We need to find a triangle in the graph (three mutually connected nodes).  
The graph is undirected, and we are guaranteed at least one triangle exists.  

A simple approach:  
- Represent the graph as an adjacency matrix (or set) for O(1) edge lookups.  
- Iterate over all triples (i, j, k) with i < j < k, and check if all three edges exist.  
- Since n ≤ 2000, checking all triples naively would be O(n³) = 8e9, too slow.  

Better:  
- For each edge (u, v), check if there is a common neighbor w such that both (u, w) and (v, w) exist.  
- We can do this by iterating over neighbors of u and checking if they are also neighbors of v.  
- This is O(m * degree) worst-case, but with m ≤ 2e5 and n ≤ 2000, it's feasible.  

We also need the lexicographically smallest triangle.  
We can iterate over nodes in increasing order and find the smallest possible triangle.  

Here’s the implementation:  

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n)]
edges = []
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].add(v)
    adj[v].add(u)
    edges.append((u, v))

# Sort edges by (u, v) to find lexicographically smallest triangle
edges.sort()

for u, v in edges:
    # Find common neighbor w > v to ensure u < v < w
    common = adj[u] & adj[v]
    for w in sorted(common):
        if w > v:
            print(u+1, v+1, w+1)
            exit()
```
