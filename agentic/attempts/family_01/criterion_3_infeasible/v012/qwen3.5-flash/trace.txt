The problem asks us to find a triplet of distinct compounds $(a, b, c)$ such that $a < b < c$ and all pairs $(a, b)$, $(b, c)$, and $(a, c)$ are incompatible. We are given $n$ compounds and $m$ incompatible pairs. We need to output the lexicographically smallest triplet. It is guaranteed that at least one such triplet exists.

Constraints:
$n \le 2000$
$m \le \min(n(n-1)/2, 2 \cdot 10^5)$
Time limit: 2 s

Let the graph of incompatible compounds be $G = (V, E)$, where $V = \{1, \dots, n\}$ and $E$ contains the given pairs. We are looking for a triangle (a $K_3$ subgraph) in $G$. Specifically, we want the lexicographically smallest triangle $(a, b, c)$ with $a < b < c$.

A brute force approach would be to iterate over all triplets $(a, b, c)$ with $a < b < c$ and check if all three edges exist.
There are $\binom{n}{3}$ triplets. With $n=2000$, $\binom{2000}{3} \approx \frac{8 \cdot 10^9}{6} \approx 1.33 \cdot 10^9$. Checking each triplet would take $O(1)$ or $O(\log m)$ time depending on storage. This is too slow given the time limit.

We need a more efficient way to find a triangle.
Since we need the lexicographically smallest triangle $(a, b, c)$, we should iterate $a$ from $1$ to $n-2$, then $b$ from $a+1$ to $n-1$, and then $c$ from $b+1$ to $n$, checking if edges $(a, b)$, $(b, c)$, and $(a, c)$ exist. If we find one, we output it and terminate.

To optimize the check:
For a fixed $a$, we need to find $b > a$ such that $(a, b) \in E$, and $c > b$ such that $(a, c) \in E$ and $(b, c) \in E$.
Essentially, for a fixed $a$, we look at its neighbors $N(a) = \{v \mid (a, v) \in E\}$. We only care about neighbors $v > a$ because we require $a < b < c$. Let $N'(a) = \{v \in N(a) \mid v > a\}$.
We need to find $b, c \in N'(a)$ such that $(b, c) \in E$ and $b < c$.
If we find such $b, c$, then $(a, b, c)$ is a triangle. To satisfy the lexicographical requirement, we iterate $a$ from $1$ to $n$, then iterate $b \in N'(a)$ in increasing order, and then iterate $c \in N'(a)$ such that $c > b$ to see if $(b, c) \in E$. The first time we find such a $c$, we are done because $a$ is fixed (smallest possible), $b$ is the smallest possible neighbor $> a$, and $c$ is the smallest possible neighbor $> b$ connected to both.

        m = int(next(iterator))

        return

    # We use 0-based indexing for nodes internally (0 to n-1)
    adj_mask = [0] * n
    
    # adj_list[u] stores the list of neighbors of u
    adj_list = [[] for _ in range(n)]

    for _ in range(m):
        u = int(next(iterator)) - 1
        v = int(next(iterator)) - 1
        
        adj_mask[u] |= (1 << v)
        adj_mask[v] |= (1 << u)
        
        adj_list[u].append(v)
        adj_list[v].append(u)

    # Sort adjacency lists to ensure we process neighbors in increasing order
    # This is crucial for finding the lexicographically smallest triplet
    for i in range(n):
        adj_list[i].sort()

    # Iterate a from 0 to n-1. Since we want lexicographically smallest (a, b, c),
    # we start with the smallest possible a.
    for a in range(n):
        # Iterate neighbors b of a. Since adj_list[a] is sorted, b will be in increasing order.
        # We only care about b > a because we want a < b < c.
        for b in adj_list[a]:
            if b <= a:
                continue

            # We want the smallest such c.
            # We can find common neighbors by bitwise AND of their masks.
            common = adj_mask[a] & adj_mask[b]
            
            # We need the smallest bit set in 'common' that is > b.

                lsb = candidates & -candidates
                c = lsb.bit_length() - 1
