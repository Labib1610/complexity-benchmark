We can solve this by checking all triples in increasing order and stopping at the first valid one.  
Since n ≤ 2000, checking all triples naively would be too slow (O(n³) ≈ 8×10⁹).  
We need a faster method.

We can use adjacency sets for O(1) edge checks, and iterate over possible `a` and `b`, then find the smallest `c > b` that is connected to both `a` and `b`.

Here’s the implementation:

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if b not in adj[a]:
                continue
            # find smallest c > b connected to both a and b
            for c in range(b + 1, n + 1):
                if c in adj[a] and c in adj[b]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
