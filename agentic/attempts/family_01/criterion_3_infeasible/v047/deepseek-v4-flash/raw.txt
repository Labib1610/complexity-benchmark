We need to find a triangle (3-clique) in an undirected graph with vertices labeled 1..n, and among all triangles, output the lexicographically smallest triple (a,b,c) with a<b<c.

### Key points:
- n up to 2000, m up to 200,000.
- Need O(n^2) or O(n^2 / word) approach.
- Lexicographically smallest triangle.

### Approach:
We can iterate over possible smallest vertex `a` from 1 to n. For each `a`, we look at its neighbors with index > a. We need to find if any two neighbors of `a` are connected. Among all such pairs, we want the smallest pair (b,c) with b<c.

To make it efficient:
- For each `a`, collect neighbors greater than `a`.
- Sort them.
- For each pair (b,c) in sorted order, check if edge (b,c) exists. The first found is the lexicographically smallest for this `a`.
- Since we iterate `a` from smallest, the first `a` that yields a triangle gives the answer.

But checking all pairs for each `a` could be O(n^3) in worst case. Need better.

### Optimization:
For each `a`, we can iterate over its neighbors in increasing order. For each neighbor `b`, we need to find the smallest `c > b` such that both `(a,c)` and `(b,c)` are edges. That is, `c` is in the intersection of neighbors of `a` and `b`, and `c > b`.

We can precompute adjacency as a bitset (Python int) for fast intersection. For each `a`, for each `b` in neighbors of `a` with b>a, compute `common = adj[a] & adj[b] & ~((1 << (b+1)) - 1)` (to keep only > b). If common != 0, take smallest set bit.

But n=2000, so bitset of 2000 bits fits in Python int. Intersection is O(1) in Python (big ints). So for each edge (a,b) we do O(1) work. Number of edges up to 200k, so fine.

We need to be careful to get lexicographically smallest triple. Since we iterate `a` from 1..n, and for each `a` we iterate its neighbors `b` in increasing order, the first triangle found is lexicographically smallest.

### Steps:
1. Read n,m.
2. Build adjacency bitset: adj[i] has bit j set if edge (i,j).
3. For a from 1 to n:
   - Get list of neighbors > a, sorted.
   - For each b in that list:
     - Compute common = adj[a] & adj[b] & ~((1 << (b+1)) - 1)
     - If common:
        - c = (common & -common).bit_length()  # smallest set bit index (1-based)
        - print(a,b,c) and exit.

But careful: bits are 0-indexed. Let's use 0-indexed internally.

### Implementation:
```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * n
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u] |= (1 << v)
        adj[v] |= (1 << u)
    
    for a in range(n):
        # neighbors of a with index > a
        neigh = []
        mask = adj[a] >> (a+1)
        while mask:
            lsb = mask & -mask
            b = (lsb.bit_length() - 1) + (a+1)
            neigh.append(b)
            mask -= lsb
        # neigh is already sorted because we go from low to high bits
        for b in neigh:
            # common neighbors of a and b that are > b
            common = adj[a] & adj[b] & ~((1 << (b+1)) - 1)
            if common:
                c = (common & -common).bit_length() - 1
                print(a+1, b+1, c+1)
                return

if __name__ == "__main__":
    main()
```
