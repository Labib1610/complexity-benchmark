We can solve this by checking each possible triple in lexicographic order and verifying if all three edges exist.  

Since n can be up to 2000, checking all triples naively would be too slow (O(n³) ≈ 8×10⁹).  
We can instead iterate over the smallest vertex `a`, then over possible `b > a`, and check for a `c > b` that is connected to both `a` and `b`.  

We can store adjacency as a set for O(1) edge lookups.  

Here’s the implementation:  

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)

    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if b not in adj[a]:
                continue
            # find smallest c > b connected to both a and b
            for c in range(b + 1, n + 1):
                if c in adj[a] and c in adj[b]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
