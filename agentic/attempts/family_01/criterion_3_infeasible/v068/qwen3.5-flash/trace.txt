The problem asks us to find the lexicographically smallest triple $(a, b, c)$ such that $1 \le a < b < c \le n$ and all three pairs $(a, b)$, $(b, c)$, and $(a, c)$ are in a given set of "unstable" pairs (edges in a graph). We are guaranteed that at least one such triple exists. The number of vertices $n$ is up to 2000, and the number of edges $m$ is up to $2 \cdot 10^5$.

This is essentially finding the lexicographically smallest triangle in a graph. The vertices are numbered $1$ to $n$. A triple $(a, b, c)$ with $a < b < c$ is a triangle if edges $(a, b)$, $(b, c)$, and $(a, c)$ exist. The lexicographical order is defined by comparing $a$ first, then $b$, then $c$. To minimize $(a, b, c)$, we need to find the smallest $a$, then for that $a$, the smallest $b$, and then for that pair $(a, b)$, the smallest $c$.

Let's represent the graph using an adjacency matrix or adjacency lists. Since $n \le 2000$, an adjacency matrix would take $O(n^2)$ space, which is roughly $4 \times 10^6$ entries. This fits well within the 256 MB memory limit. An adjacency list might be slightly more memory efficient but looking up edges would take $O(\text{degree})$. With $n=2000$, iterating over neighbors is fast enough. However, checking if an edge exists takes $O(1)$ with an adjacency matrix (or a hash set), but $O(\log n)$ or $O(\text{degree})$ with a list. Given $m$ is relatively small compared to $n(n-1)/2$ (sparse graph potentially), adjacency lists are good, but an adjacency matrix is safer for $O(1)$ checks and $n=2000$ is small enough. Let's use a boolean adjacency matrix or a set of edges. Actually, since we need to check if $(a, c)$ exists given $(a, b)$ and $(b, c)$, we need fast lookups.

The algorithm should be:
Iterate $a$ from $1$ to $n$.
  Iterate $b$ from $a+1$ to $n$.
    Check if edge $(a, b)$ exists.
      If it exists:
        Iterate $c$ from $b+1$ to $n$.
          Check if edges $(a, c)$ and $(b, c)$ exist.
            If both exist, we found the lexicographically smallest triple $(a, b, c)$. Since we iterate in increasing order of $a$, then $b$, then $c$, the first one we find is guaranteed to be the answer. Return/Print it and exit.

Complexity analysis:
The nested loops run as follows:
Outer loop $a$: $1 \dots n$
Middle loop $b$: $a+1 \dots n$
Inner loop $c$: $b+1 \dots n$
The number of triplets $(a, b, c)$ checked is $\binom{n}{3} \approx \frac{n^3}{6}$.
For $n=2000$, $n^3/6 \approx \frac{8 \cdot 10^9}{6} \approx 1.33 \cdot 10^9$.
This is too slow for a 2-second time limit. Python is slower than C++, so $10^9$ operations will definitely TLE (Time Limit Exceeded). We need a more efficient approach.

We only care about edges that exist. Let $E$ be the set of edges.
The algorithm can be optimized:
Iterate $a$ from $1$ to $n$.
  Iterate $b$ over neighbors of $a$ such that $b > a$.
    If edge $(a, b)$ exists:
      Iterate $c$ over common neighbors of $a$ and $b$ such that $c > b$.
        If edge $(a, c)$ and $(b, c)$ exist:
           Return $(a, b, c)$.

To implement "common neighbors" efficiently:
For a fixed $a$ and $b$, we want to find if there is a $c > b$ connected to both.
If we iterate over all pairs of neighbors of $a$, say $b$ and $c$, we check if $(b, c)$ exists.
This is equivalent to finding a triangle.
The complexity depends on the degrees of the vertices.
The number of operations is roughly $\sum_{(a, b) \in E} \min(\text{deg}(a), \text{deg}(b))$ or something similar if we iterate over neighbors.
Specifically, if we iterate $a$, then neighbors $b$ of $a$ (where $b > a$), then we want to find a common neighbor $c > b$.
If we iterate over neighbors of $a$ and $b$, the complexity is bounded by $\sum_{(u, v) \in E} \min(\deg(u), \deg(v))$. This is known to be $O(m \sqrt{m})$ or similar depending on the algorithm. With $m=2 \cdot 10^5$, $\sqrt{m} \approx 450$. $2 \cdot 10^5 \times 450 \approx 9 \cdot 10^7$, which is acceptable.

We want smallest $a$. Then smallest $b > a$ such that $(a, b) \in E$. Then smallest $c > b$ such that $(a, c) \in E$ and $(b, c) \in E$.
So the structure is:
For $a$ in $1 \dots n$:

    Find smallest $c$ in neighbors of $a$ with $c > b$ such that $c$ is also a neighbor of $b$.

import sys
import bisect

# Increase recursion depth just in case, though not needed here
sys.setrecursionlimit(2000)

def solve():
    # Read all input at once
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    iterator = iter(input_data)
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return
    
    adj = [[] for _ in range(n + 1)]
    # Using bytearray for adjacency matrix
    # n <= 2000, so 2000*2000 bytes = 4MB
    adj_mat = [bytearray(n + 1) for _ in range(n + 1)]
    
    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        adj[u].append(v)
        adj[v].append(u)
        adj_mat[u][v] = 1
        adj_mat[v][u] = 1
        
    # Sort adjacency lists
    for i in range(1, n + 1):
        adj[i].sort()
        
    # Iterate a from 1 to n
    for a in range(1, n + 1):
        # We need to find smallest b > a in adj[a], then smallest c > b
        # Iterate b in adj[a]
        # Since adj[a] is sorted, b will be increasing
        for idx_b, b in enumerate(adj[a]):
            if b <= a:
                continue
            
            # Now we have a pair (a, b) with a < b
            # We want to find smallest c > b such that c is connected to a and b
            # c must be in adj[a] and adj[b]
            # We check intersection, prioritizing the smaller list
            
            deg_a = len(adj[a])
            deg_b = len(adj[b])
            
            # If deg_a < deg_b, iterate adj[a]
            # We need c > b. Since b is in adj[a] at idx_b, c must be at index > idx_b
            if deg_a < deg_b:
                # Iterate c in adj[a] starting from idx_b + 1
                for idx_c in range(idx_b + 1, deg_a):
                    c = adj[a][idx_c]
                    # Check if (b, c) exists
                    if adj_mat[b][c]:
                        print(f"{a} {b} {c}")
                        return
            else:
                # If deg_b <= deg_a, iterate adj[b]
                # We need c > b.
                # Find index of first element > b in adj[b]
                # Since b is not in adj[b] (no self loops), bisect_right gives index after all <= b
                # Wait, b is not in adj[b], so all elements in adj[b] are != b.
                # So bisect_right gives index of first element > b?
                # No, bisect_right returns insertion point after all elements <= x.
                # Since no element is b, it returns index of first element > b.
                # Correct.
                start_idx = bisect.bisect_right(adj[b], b)
                for idx_c in range(start_idx, deg_b):
                    c = adj[b][idx_c]
                    # Check if (a, c) exists
                    if adj_mat[a][c]:
                        print(f"{a} {b} {c}")
                        return
