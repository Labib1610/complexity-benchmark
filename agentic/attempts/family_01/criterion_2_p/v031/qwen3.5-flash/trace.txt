The problem asks us to determine if a graph with $n$ nodes and $m$ edges is bipartite. If it is, we need to output a 2-coloring (using colors 1 and 2) that is lexicographically smallest. The nodes are numbered 1 to $n$. The output should be the colors for nodes 1, 2, ..., $n$.

A graph is bipartite if and only if it contains no odd cycles. This is equivalent to saying the graph can be 2-colored such that no two adjacent vertices have the same color.

We need to handle multiple connected components. For each connected component, we can pick a starting node and assign it a color. Since we want the lexicographically smallest sequence of assignments $s_1, s_2, \dots, s_n$, we should process nodes in increasing order of their index (1 to $n$). If a node $i$ has not been colored yet, we must assign it a color. To make the sequence lexicographically smallest, we should try to assign the smallest possible valid color to $s_i$. The colors are 1 and 2. So, for the first uncolored node in a component, we should ideally assign it color 1. However, we need to check if assigning color 1 is consistent with the rest of the component. Since the graph structure is fixed, if a component is bipartite, there are exactly two valid colorings (swapping 1 and 2). One starts with color 1 at some node, the other starts with color 2. The relative constraints within a component are fixed. Once a node is colored, the colors of all other nodes in that component are determined.

So the strategy is:
1. Initialize an array `color` of size $n+1$ with 0 (uncolored).
2. Iterate $i$ from 1 to $n$.
3. If node $i$ is not colored:
    a. Perform a BFS or DFS starting from $i$ to traverse the connected component.
    b. During traversal, assign colors. Since we want the lexicographically smallest sequence, and we are currently at node $i$ which is the *first* node in this component we encounter (because we iterate $1 \dots n$), we should assign color 1 to node $i$.
    c. Then propagate the coloring to neighbors: if $u$ has color $c$, neighbor $v$ must have color $3-c$.
    d. If we encounter a conflict (a neighbor already has the same color), then the graph is not bipartite. In this case, print "NO" and terminate.
    e. If the traversal completes successfully for this component, we continue to the next uncolored node.
4. If all nodes are processed without conflicts, print "YES" and the colors.

Wait, is it guaranteed that assigning color 1 to the first node of a component yields the lexicographically smallest result?
Let the component be $C$. Let $u \in C$ be the node with the smallest index in $C$. We encounter $u$ first because we iterate $1 \dots n$. We must assign a color to $u$. Since $s_u$ contributes to the lexicographical order, minimizing $s_u$ is the primary goal. $s_u$ can be 1 or 2. If $s_u=1$ is valid, it is strictly better than $s_u=2$. If the component is bipartite, there are exactly two valid 2-colorings. One has $u$ colored 1, the other has $u$ colored 2. Both are valid for the component. Choosing the one with $s_u=1$ makes $s_u$ minimal. Since $u$ is the first node in the component, this choice minimizes the sequence at the earliest possible position where choices exist. Thus, for every component, we should fix the color of the node with the smallest index to be 1. The rest of the component's colors are then determined by the bipartite constraints.

Algorithm details:
- Adjacency list `adj`.
- Array `colors` initialized to 0.
- Loop $i$ from 1 to $n$.
- If `colors[i]` == 0:
    - Start BFS/DFS from $i$.
    - Set `colors[i] = 1`.
    - Queue/Stack contains $i$.
    - While queue/stack not empty:
        - Pop $u$.
        - For each neighbor $v$ of $u$:
            - If `colors[v]` == 0:
                - `colors[v] = 3 - colors[u]`
                - Push $v$.
            - Else if `colors[v] == colors[u]`:
                - Return "NO".
- If loop finishes, print "YES" and `colors[1:]`.

Memory complexity: $O(N+M)$ for adjacency list and recursion/queue. Fits within 256 MB.

```python
import sys
from collections import deque

# Increase recursion depth is not needed for iterative BFS but good practice in some CP problems.
# However, we will stick to iterative BFS to be safe and efficient.

def solve():
    # Read all input from standard input
    input_data = sys.stdin.read().split()
    
    if not input_data:
        return
    
    iterator = iter(input_data)
    
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        adj[u].append(v)
        adj[v].append(u)
        
    colors = [0] * (n + 1)
    
    # Process each connected component
    # Iterating from 1 to n ensures we assign the smallest possible channel to the 
    # first node encountered in each component, satisfying the lexicographical requirement.
    for i in range(1, n + 1):
        if colors[i] == 0:
            # Assign channel 1 to the starting node of the component
            colors[i] = 1
            q = deque([i])
            
            while q:
                u = q.popleft()
                current_channel = colors[u]
                next_channel = 3 - current_channel
                
                for v in adj[u]:
                    if colors[v] == 0:
                        colors[v] = next_channel
                        q.append(v)
                    elif colors[v] != next_channel:
                        # Conflict detected: adjacent nodes have the same color
                        print("NO")
                        return
    
    print("YES")
    # Print the channels for nodes 1 through n
    sys.stdout.write(" ".join(map(str, colors[1:])) + "\n")

if __name__ == '__main__':
    solve()
```
