**Solution Explanation**

For every worker we have to choose a shift `1` or `2`.  
A constraint `u v` means *the two workers must receive different shifts*.
If we write shift `1` as colour `0` and shift `2` as colour `1`,
the constraints become exactly the edges of a graph that has to be **bipartite**  
(every edge connects vertices of different colours).

So the problem is

* check whether the given undirected graph is bipartite;
* if it is, output the lexicographically smallest 2‑colouring
  (colour `0` → shift `1`, colour `1` → shift `2`).

--------------------------------------------------------------------

#### 1.   Lexicographically smallest bipartite colouring  

A connected component of a bipartite graph has exactly two valid colourings –
they are obtained from each other by swapping the two colours.
Let `c` be the smallest vertex index inside this component.
If we colour `c` with colour `0`, the whole component is fixed,
otherwise it would start with colour `1` and the whole schedule would be larger
lexicographically (because earlier positions dominate later ones).

Therefore the following greedy rule yields the global optimum:

```
process vertices 1 … n
    if vertex i is still uncoloured:
        start a BFS/DFS from i, colour i = 0
        (the whole component gets a unique colouring)
```

When we meet a vertex that already belongs to a previously processed component,
its colour is already fixed, so the rule is consistent.

--------------------------------------------------------------------

#### 2.   Bipartite test while building the colouring  

During the BFS we assign the opposite colour to every neighbour.
If we ever try to give a neighbour a colour that it already has,
the graph is **not** bipartite → answer `NO`.

The algorithm works in `O(n + m)` time and `O(n + m)` memory,
well inside the limits (`n, m ≤ 2·10⁵`).

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `NO` iff no feasible schedule exists,
otherwise it prints `YES` and the lexicographically smallest feasible schedule.

---

##### Lemma 1  
If the algorithm reports a conflict while processing an edge `(u,v)`,
the graph is not bipartite.

**Proof.**  
During BFS we always assign opposite colours to the two ends of an edge.
A conflict means that an edge connects two vertices that already have the same
colour. Any 2‑colouring must give opposite colours to the ends of this edge,
hence no 2‑colouring exists. ∎



##### Lemma 2  
If the algorithm finishes without conflict, the produced colouring satisfies
all constraints.

**Proof.**  
The algorithm colours every vertex exactly once.
Whenever it traverses an edge `(u,v)`, it sets `colour[v] = 1 - colour[u]`.
Thus after the traversal the two ends have different colours.
All edges are traversed, therefore every constraint is satisfied. ∎



##### Lemma 3  
For each connected component the algorithm assigns colour `0` to the smallest
vertex index of that component.

**Proof.**  
Components are processed in increasing order of their smallest vertex.
When the loop reaches the smallest vertex `c` of a component,
none of its vertices has been coloured yet (otherwise `c` would belong to an
already processed component, contradiction).  
The algorithm starts the BFS with `colour[c]=0`.  
All other vertices of the component receive colours relative to `c`,
so `c` stays colour `0`. ∎



##### Lemma 4  
Among all feasible colourings, the one produced by the algorithm is
lexicographically smallest.

**Proof.**  
Consider the first position `i` where two feasible colourings differ.
`i` belongs to some component `C`.  
By Lemma&nbsp;3 the algorithm colours the smallest vertex of `C` with `0`.
If another feasible colouring gives `i` colour `1`, then its colour at the
smallest vertex of `C` is `1` as well (otherwise the two colourings would be
identical on that vertex).  
Swapping the two colours inside `C` turns that colouring into another feasible
colouring that coincides with the algorithm on all vertices ≤ `i`.  
Hence any feasible colouring that is lexicographically smaller than the
algorithm’s one cannot exist. ∎



##### Lemma 5  
If the algorithm outputs `NO`, no feasible schedule exists.

**Proof.**  
`NO` is printed only when a conflict is detected.
By Lemma&nbsp;1 a conflict implies the graph is not bipartite,
i.e. no assignment of two different shifts to the ends of every edge exists.
Thus no feasible schedule exists. ∎



##### Lemma 6  
If the algorithm outputs `YES` and a schedule, that schedule is feasible.

**Proof.**  
`YES` is printed only when the BFS finishes without conflict.
By Lemma&nbsp;2 the resulting colouring satisfies all constraints,
hence the printed schedule (colour + 1) is feasible. ∎



##### Theorem  
The algorithm is correct.

**Proof.**  

*If the algorithm prints `NO`*: by Lemma&nbsp;5 no feasible schedule exists.  

*If the algorithm prints `YES` and a schedule*: by Lemma&nbsp;6 the schedule
is feasible, and by Lemma&nbsp;4 it is the lexicographically smallest among all
feasible schedules. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency lists*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and each edge is processed once →  
`O(n + m)` time, `O(n + m)` additional memory for the queue and colour array.

Overall: **Time `O(n + m)`, Memory `O(n + m)`**.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = next(it); v = next(it)
        adj[u].append(v)
        adj[v].append(u)

    color = [-1] * (n + 1)          # -1 = uncoloured, 0 or 1 otherwise
    q = deque()

    for start in range(1, n + 1):
        if color[start] != -1:
            continue
        # start new component, give smallest vertex colour 0
        color[start] = 0
        q.append(start)
        while q:
            u = q.popleft()
            cu = color[u]
            for v in adj[u]:
                if color[v] == -1:
                    color[v] = 1 - cu
                    q.append(v)
                elif color[v] == cu:
                    # conflict -> not bipartite
                    sys.stdout.write("NO")
                    return

    # feasible, produce lexicographically smallest schedule
    sys.stdout.write("YES\n")
    # shift = colour + 1
    out = ' '.join(str(color[i] + 1) for i in range(1, n + 1))
    sys.stdout.write(out)

if __name__ == "__main__":
    solve()
```

and conforms to the required input‑output format.
