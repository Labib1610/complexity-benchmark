def solve():

    sys.setrecursionlimit(200005)
    
    input_data = sys.stdin.read().split()

        return

        u = int(next(iterator))
        v = int(next(iterator))

        adj[v].append(u)

    # The strategy is: for each connected component, we must pick the coloring 
    # that minimizes the sequence. Since the components are disjoint, we can 
    # optimize each component independently.
    # For a component, there are 2 valid colorings (if bipartite).
    # They are inverses of each other (swap 1 and 2).
    # The one that is lexicographically smaller is the one where the smallest 
    # index in the component is assigned 1 (since 1 < 2).

    # it must be the smallest index in its component.

        v = int(next(iterator))
        adj[u].append(v)
        adj[v].append(u)
        
    # Array to store colors: 0 = unvisited, 1 = color A, 2 = color B
    colors = [0] * (n + 1)
    
    # Iterate through all nodes 1 to n
    # Since we iterate in increasing order, the first time we encounter an unvisited node,
    # it is the smallest index in its connected component.
    # To achieve the lexicographically smallest sequence, we must assign the smallest
    # index in each component the value 1 (since 1 < 2).
    # This fixes the coloring for the entire component (if bipartite).
    for i in range(1, n + 1):
        if colors[i] == 0:
            colors[i] = 1
            q = deque([i])
            
            while q:
                u = q.popleft()
                current_color = colors[u]
                next_color = 3 - current_color
                
                for v in adj[u]:
                    if colors[v] == 0:
                        colors[v] = next_color
                        q.append(v)
                    else:
                        if colors[v] != next_color:
                            print("NO")
                            return

    print("YES")
    print(*(colors[1:]))

if __name__ == '__main__':
    solve()

Double check logic one last time.
Is it possible that for a component, assigning 1 to the smallest index is valid, but assigning 2 to the smallest index is ALSO valid, but somehow assigning 2 is better?
No, because the smallest index is the most significant position in the sequence for that component.
The sequence is $s_1, s_2, \dots, s_n$.
If we have a component with smallest index $u$, then $s_u$ is the value at index $u$.
If we choose $s_u=1$, the sequence has 1 at $u$.
If we choose $s_u=2$, the sequence has 2 at $u$.
All other positions $k < u$ are already fixed (either by previous components or because they are not in this component).
So we are comparing sequences that are identical up to $u-1$, and differ at $u$.
The one with 1 at $u$ is smaller.
So we MUST choose $s_u=1$.
This confirms the greedy strategy.

The code implements this exactly.
The loop iterates $i$ from 1 to $n$.
If `colors[i] == 0`, $i$ is unvisited.
This means $i$ is the smallest index in its component (since any smaller index would have been visited if it were in the same component, or if it was in a different component, it would have been processed and its component marked visited, but wait).
If $j < i$ is in the same component, then when we processed $j$, we would have visited $i$ and set `colors[i]`.
So if `colors[i] == 0`, then no $j < i$ is in the same component.
Thus $i$ is indeed the smallest index in its component.
So the logic holds.
