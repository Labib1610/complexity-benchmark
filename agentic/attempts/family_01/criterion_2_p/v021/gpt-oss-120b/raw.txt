**Solution Explanation**

For every gear we have to choose one of two directions  

```
1 – clockwise
2 – counter‑clockwise
```

If two gears are meshed they must rotate in opposite directions.
The `m` pairs of meshed gears form an undirected graph.
The task is exactly the classic *bipartite‑graph* problem:

* assign one of two colours to every vertex,
* adjacent vertices must have different colours,
* output the lexicographically smallest colour sequence
  (`1 < 2`).

If the graph is not bipartite the answer is `NO`.



--------------------------------------------------------------------

#### 1.   Observations

* In a connected component of a bipartite graph there are **exactly two**
  possible colourings – they are each other’s global swap.
* The lexicographically smallest whole sequence is obtained by the
  following greedy rule:

  Process vertices `1 … n`.  
  When we meet the first (i.e. smallest index) vertex of a still
  uncoloured component we are free to decide which of the two colourings
  we use for this component.
  To minimise the whole sequence we must give this smallest vertex colour
  `1` (the smallest possible value).  
  Afterwards the whole component is forced.

  Therefore: **in every component the vertex with the smallest index must
  obtain colour `1`.**  
  The remaining vertices receive the opposite colour automatically.

* The smallest index of a component is exactly the first vertex we start
  a BFS/DFS from while iterating `i = 1 … n`.

--------------------------------------------------------------------

#### 2.   Algorithm
```
read n, m and the adjacency lists
colour[1…n] = -1          # -1 = not visited yet, otherwise 0/1 (parity)
answer[1…n] = 0

for i = 1 … n
    if colour[i] == -1                # new component, i is its smallest vertex
        BFS starting from i
            colour[i] = 0
            store all vertices of this component in list comp
            while queue not empty
                u = pop
                for each neighbour v of u
                    if colour[v] == -1
                        colour[v] = colour[u] xor 1
                        push v, add v to comp
                    else if colour[v] == colour[u]
                        graph is not bipartite → print "NO" and exit

        # component is bipartite, decide final numbers
        # because i (the smallest vertex) has parity 0,
        # we give parity 0 → number 1, parity 1 → number 2
        for v in comp
            answer[v] = 1 if colour[v] == 0 else 2

print "YES"
print answer[1] … answer[n] separated by blanks
```

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `NO` iff no valid assignment exists,
otherwise prints `YES` and the lexicographically smallest assignment.

---

##### Lemma 1  
During BFS of a component, if the algorithm ever discovers an edge
`(u, v)` with `colour[u] == colour[v]`, the component is not bipartite.

**Proof.**  
All already visited vertices have a fixed parity (0/1) that respects
all processed edges, because we always assign the opposite parity to an
unvisited neighbour.  
If an edge connects two vertices with the same parity, any 2‑colouring
must give them different colours – impossible. ∎



##### Lemma 2  
If the algorithm finishes BFS of a component without conflict,
the component is bipartite and the array `colour` gives a correct
2‑colouring (parities 0/1).

**Proof.**  
The BFS assigns opposite parity to the two ends of every traversed edge.
Because every edge of the component is examined exactly once,
all edges connect vertices of opposite parity, i.e. a proper 2‑colouring.
∎



##### Lemma 3  
For a bipartite component the algorithm assigns number `1` to its
smallest indexed vertex.

**Proof.**  
The component is first encountered when the outer loop reaches its
smallest vertex `i`.  
The BFS starts with `colour[i] = 0`.  
Later we set `answer[v] = 1` iff `colour[v] == 0`.  
Hence `answer[i] = 1`. ∎



##### Lemma 4  
For a bipartite component the algorithm produces a valid assignment
(`1`/`2`) for all its vertices.

**Proof.**  
By Lemma&nbsp;2 the parity colouring is proper.
By construction `answer[v]` is `1` for parity `0` and `2` for parity `1`,
so adjacent vertices receive different numbers. ∎



##### Lemma 5  
Let `S` be the sequence printed by the algorithm (when it prints `YES`).
For any other valid sequence `T` we have `S` lexicographically ≤ `T`.

**Proof.**  
Consider the first index `k` where `S` and `T` differ.
All indices `< k` belong to components already processed earlier,
hence `S` and `T` are equal there.

Index `k` lies in some component `C`.  
By construction `k` is the smallest index of `C`.  
Lemma&nbsp;3 tells us `S_k = 1`.  
Any valid assignment must give either `1` or `2` to vertex `k`.  
If `T_k = 2` then `S_k < T_k` and `S` is lexicographically smaller.
If `T_k = 1` then `S_k = T_k` contradicts the definition of `k` as first
difference.  
Thus the only possible case is `S_k = 1 < T_k = 2`. ∎



##### Lemma 6  
If the algorithm prints `NO`, no valid assignment exists.

**Proof.**  
`NO` is printed only when Lemma&nbsp;1 detects a same‑parity edge,
i.e. an odd cycle. Any graph containing an odd cycle is not bipartite,
hence cannot be 2‑coloured. ∎



##### Theorem  
The algorithm

* prints `NO` **iff** the given graph has no feasible rotation assignment,
* otherwise prints `YES` and the lexicographically smallest feasible
  assignment.

**Proof.**  

*If the algorithm prints `NO`*: by Lemma&nbsp;6 the graph is not bipartite,
so no assignment exists.

*If the algorithm prints `YES`*: every component was processed without
conflict, therefore by Lemma&nbsp;2 each component is bipartite.
By Lemma&nbsp;4 the produced numbers satisfy all constraints,
so a feasible assignment exists.
By Lemma&nbsp;5 this assignment is lexicographically minimal among all
feasible ones.

Conversely, if a feasible assignment exists the graph is bipartite,
so no conflict can be found and the algorithm never prints `NO`. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency lists*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and edge is processed once →  
`O(n + m)` time, `O(n)` extra memory for queues and component lists.  

Overall  

```
Time   :  O(n + m)   ≤ 4·10⁵ operations
Memory :  O(n + m)   ≤ 4·10⁵ integers  (well below 256 MB)
```

Both satisfy the limits.

#### 5.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = next(it)
        v = next(it)
        adj[u].append(v)
        adj[v].append(u)

    parity = [-1] * (n + 1)          # -1 = unvisited, else 0/1
    answer = [0] * (n + 1)

    for start in range(1, n + 1):
        if parity[start] != -1:
            continue

        # new component, start is its smallest vertex
        q = deque([start])
        parity[start] = 0
        comp = [start]

        while q:
            u = q.popleft()
            pu = parity[u]
            for v in adj[u]:
                if parity[v] == -1:
                    parity[v] = pu ^ 1
                    q.append(v)
                    comp.append(v)
                elif parity[v] == pu:
                    # not bipartite
                    sys.stdout.write("NO")
                    return

        # assign numbers: parity 0 -> 1, parity 1 -> 2
        for v in comp:
            answer[v] = 1 if parity[v] == 0 else 2

    out = ["YES", " ".join(str(answer[i]) for i in range(1, n + 1))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
