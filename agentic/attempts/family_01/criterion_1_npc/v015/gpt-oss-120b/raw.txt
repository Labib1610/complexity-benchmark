**Solution Explanation**

The problem asks for a proper coloring of an undirected graph with at most `n = 40`
vertices using three colors (the three work blocks).  
A pair `(u , v)` is an edge – the two vertices must obtain different colors.

The graph is small, therefore a classic depth‑first search with backtracking is
fast enough.  
The only difficulty is to prune the search as much as possible, otherwise the
exponential worst case would be too slow.

--------------------------------------------------------------------

#### 1.   Data representation  

* `adj[i]` – bit mask of neighbours of vertex `i` (`0 ≤ i < n`).  
  With `n ≤ 40` a Python integer fits all bits.
* `color[i]` – current color of vertex `i` (`-1` = uncolored, otherwise `0,1,2`).

--------------------------------------------------------------------

#### 2.   Vertex ordering  

Vertices are processed in a fixed order that is *good* for backtracking:

```
order = vertices sorted by decreasing degree
```

Choosing a vertex with many already colored neighbours reduces the branching
factor early.

--------------------------------------------------------------------

#### 3.   Backtracking  

```
dfs(pos):
    if pos == n:               # all vertices colored
        return True
    v = order[pos]             # vertex to colour now
    forbidden = 0
    for each neighbour u of v that is already coloured:
        forbidden |= 1 << color[u]          # colour that cannot be used
    for c in {0,1,2}:
        if not (forbidden >> c) & 1:        # colour c is allowed
            color[v] = c
            if dfs(pos+1):
                return True
            color[v] = -1
    return False
```

`forbidden` is a 3‑bit mask, built by scanning only already coloured neighbours.
If a colour is allowed we recurse; otherwise we backtrack.

Because `n` is tiny, the recursion depth never exceeds 40, well inside Python
limits.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a valid schedule iff such a
schedule exists.

---

##### Lemma 1  
During the execution of `dfs(pos)` the partial assignment stored in `color`
is always a proper coloring of the already coloured vertices.

**Proof.**  
Initially all vertices are uncoloured – trivially proper.  
When a vertex `v` receives a colour `c`, the algorithm first computes the set
`forbidden` of colours used by coloured neighbours of `v`.  
It only assigns `c` if `c` is **not** in `forbidden`, i.e. no coloured neighbour
has colour `c`. Therefore after the assignment the property still holds. ∎



##### Lemma 2  
If `dfs(pos)` returns `True`, the array `color` after the call is a proper
3‑coloring of **all** vertices.

**Proof.**  
`True` is returned only when the base case `pos == n` is reached.
At that moment every vertex has been assigned a colour.
By Lemma&nbsp;1 the partial coloring is proper at each step, hence also after
the last step. ∎



##### Lemma 3  
If a proper 3‑coloring exists, `dfs(0)` returns `True`.

**Proof.**  
Consider any fixed proper coloring `C`.  
We show by induction on `pos` that the recursive search can follow `C`.

Induction hypothesis: after processing the first `pos` vertices of `order`,
the algorithm can reach a state where those vertices are coloured exactly as
in `C`.

*Base*: `pos = 0` – true trivially.

*Step*: assume hypothesis for `pos`.  
Vertex `v = order[pos]` is next. In `C` it has colour `c = C(v)`.  
All neighbours of `v` that appear earlier in `order` are already coloured
exactly as in `C` (induction hypothesis). Because `C` is proper, none of those
neighbours uses colour `c`. Consequently `c` is **not** forbidden and the
algorithm will try it (the loop iterates over all three colours).  
Choosing `c` leads to a recursive call satisfying the hypothesis for `pos+1`.

Thus the recursion can follow `C` all the way to `pos = n`, where it returns
`True`. ∎



##### Lemma 4  
If `dfs(0)` returns `False`, no proper 3‑coloring exists.

**Proof.**  
Assume the contrary: a proper coloring `C` exists. By Lemma&nbsp;3 the search
must be able to follow `C` and therefore would return `True`. Contradiction. ∎



##### Theorem  
The program outputs  

* `YES` and a schedule that respects all conflicts **iff** such a schedule
  exists, otherwise it outputs `NO`.

**Proof.**  

*If part*: when the program prints `YES`, it has obtained the colour array from
`dfs(0)` returning `True`. By Lemma&nbsp;2 this array is a proper 3‑coloring,
hence a valid schedule.

*Only‑if part*: when a valid schedule exists, a proper 3‑coloring exists.
By Lemma&nbsp;3 `dfs(0)` returns `True`, the program prints `YES`.  
If no schedule exists, by Lemma&nbsp;4 `dfs(0)` returns `False` and the program
prints `NO`. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Let `d` be the maximum degree of the graph.*

* Building adjacency masks: `O(m)`.
* In each recursive call we examine neighbours of the current vertex.
  Over the whole search each edge is inspected at most twice (once from each
  endpoint) per level of recursion, but the depth is at most `n = 40`.
  In practice the work is bounded by `O(3^n)` in the worst theoretical case,
  yet for `n = 40` the strong pruning makes it run far below the time limit.
* Memory consumption:  
  `adj` – `n` integers, `color` – `n` small ints → `O(n)` ≤ a few hundred bytes.

Both limits satisfy the given constraints easily.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [0] * n
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    # order vertices by decreasing degree
    order = sorted(range(n), key=lambda x: bin(adj[x]).count('1'), reverse=True)

    color = [-1] * n          # -1 = uncolored, otherwise 0,1,2

    sys.setrecursionlimit(10000)

    def dfs(pos: int) -> bool:
        if pos == n:
            return True
        v = order[pos]
        # compute which colours are forbidden by already coloured neighbours
        forb = 0
        neigh = adj[v]
        # iterate over neighbours that are already coloured
        while neigh:
            u = (neigh & -neigh).bit_length() - 1   # index of lowest set bit
            neigh &= neigh - 1
            cu = color[u]
            if cu != -1:
                forb |= 1 << cu
        for c in range(3):
            if not (forb >> c) & 1:
                color[v] = c
                if dfs(pos + 1):
                    return True
                color[v] = -1
        return False

    if dfs(0):
        out = ['YES', ' '.join(str(c + 1) for c in color)]
        sys.stdout.write('\n'.join(out))
    else:
        sys.stdout.write('NO')

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
