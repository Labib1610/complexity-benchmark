**Solution Explanation**

For every module we have to choose a phase `1 … 3` such that the two
modules of each recorded interaction obtain different phases.
In graph terminology we have to **3‑colour** the given undirected graph.

`n ≤ 40`, therefore an exponential backtracking search with good pruning
is easily fast enough.
The algorithm is a standard *constraint‑propagation* (CSP) solver:

* each vertex keeps the set of still possible colours (`domain`);
* when a colour is fixed for a vertex, this colour is removed from the
  domains of all its neighbours;
* if a neighbour’s domain becomes a single colour, that colour is forced
  and the same propagation is performed again (unit propagation);
* if some domain becomes empty the current partial assignment is impossible
  and we backtrack;
* otherwise we pick an *uncoloured* vertex with the smallest domain
  (most constrained) and try all colours from its domain recursively.

Because every propagation step only removes colours,
the total amount of work per recursive call is `O(m)`,
and the depth of the recursion never exceeds `n = 40`.

The search finishes as soon as all vertices are coloured
or after exploring the whole search tree – in the latter case the graph
is not 3‑colourable.

#### Algorithm
```
read n, m and the adjacency list adj
domains[v] = 0b111   (all three colours are possible)
colour[v]  = -1       (unassigned)

function propagate(changes):
    # repeatedly assign forced vertices (domain size = 1)
    while True:
        progress = False
        for each vertex v with colour[v] == -1:
            if domains[v] has exactly one bit:
                c = that colour
                record old state of v in changes
                set domains[v] = 1<<c , colour[v] = c
                for each neighbour u of v with colour[u] == -1:
                    if domains[u] contains c:
                        record old state of u in changes
                        delete c from domains[u]
                        if domains[u] becomes 0: return False
                progress = True
        if not progress: break
    return True


function dfs():
    if every vertex is coloured: return True

    choose an uncoloured vertex v with the smallest domain size (>1)

    for each colour c contained in domains[v]:
        changes = empty list
        # assign v = c
        record old state of v in changes
        set domains[v] = 1<<c , colour[v] = c
        for each neighbour u of v with colour[u] == -1:
            if domains[u] contains c:
                record old state of u in changes
                delete c from domains[u]
                if domains[u] becomes 0: go to next colour
        if propagate(changes) and dfs(): return True
        # backtrack: restore all recorded states
        for (vertex, oldMask, oldColour) in reversed(changes):
            domains[vertex] = oldMask
            colour[vertex]   = oldColour
    return False
```

`dfs()` is started once.
If it returns `True` we output the obtained colours (`+1` to change from
`0,1,2` to `1,2,3`);
otherwise we output `NO`.

#### Correctness Proof  

We prove that the algorithm prints `YES` and a correct calibration
iff such a calibration exists.

---

##### Lemma 1  
During the whole execution, for every vertex `v`

* `domains[v]` always contains exactly the colours that are still possible
  for `v` under the current partial assignment,
* `colour[v] = -1`  **iff**  `domains[v]` contains more than one colour,
  otherwise `colour[v]` equals the unique colour in `domains[v]`.

**Proof.**  
Initially all three colours are possible and `colour = -1`, so the statement
holds.

The only statements that modify `domains` or `colour` are:

* *assigning* a colour `c` to a vertex `v` – we set `domains[v] = {c}` and
  `colour[v] = c`. Afterwards the statement is true for `v`.
* *removing* a colour `c` from a neighbour `u` – we delete `c` from
  `domains[u]`. If the deletion leaves exactly one colour, the next
  iteration of `propagate` will assign it, otherwise `colour[u]` stays `-1`.
  Hence the invariant is preserved.
* *backtracking* restores the saved old values, therefore the invariant
  also holds after undoing a step. ∎



##### Lemma 2  
`propagate(changes)` returns `True` **iff** the current partial assignment
can be extended to a full proper 3‑colouring.

**Proof.**  
`propagate` repeatedly performs forced assignments:
if a vertex has only one possible colour, any proper colouring must give it
that colour, otherwise a neighbour would have the same colour.
The procedure also removes this colour from all neighbours,
which is necessary for any extension.
If at some point a vertex loses all possible colours, no extension exists,
hence `propagate` returns `False`.

Conversely, if `propagate` finishes without conflict,
all forced assignments have been performed and no vertex has an empty
domain. The remaining uncoloured vertices still have at least one colour
in their domain, therefore a proper colouring *might* exist.
`propagate` does not make any decision that could invalidate a possible
extension, so the existence of an extension is unchanged. ∎



##### Lemma 3  
When `dfs` calls itself recursively after a successful `propagate`,
the recursive call is executed with a *consistent* partial assignment,
i.e. one that can be extended to a full proper colouring **iff**
the original instance is solvable.

**Proof.**  
`dfs` first fixes a colour for a chosen vertex `v` and removes this colour
from all its neighbours.
If a neighbour loses its last colour, the branch is discarded immediately.
Otherwise `propagate` is invoked.
By Lemma&nbsp;2 the call succeeds exactly when the current partial
assignment is still extendable.
Thus the recursive call receives a consistent state, and the original
instance is solvable exactly when some recursive branch succeeds. ∎



##### Lemma 4  
If the algorithm outputs a colouring, it is a proper 3‑colouring.

**Proof.**  
Output is produced only after `dfs` has coloured every vertex.
By Lemma&nbsp;1 each vertex receives a colour belonging to its domain.
During the whole search a colour is removed from a neighbour only when
the two vertices are adjacent, therefore two adjacent vertices never keep
the same colour in the final assignment. ∎



##### Lemma 5  
If a proper 3‑colouring exists, the algorithm eventually finds one and
outputs `YES`.

**Proof.**  
Consider any fixed proper colouring `C`.
`dfs` explores the search tree depth‑first.
At each recursive step it chooses an uncoloured vertex `v` and tries
all colours from its current domain.
Because `C` respects all constraints, the colour `C(v)` is always present
in the domain (Lemma&nbsp;1).  
When the algorithm tries exactly this colour, the subsequent propagation
does not delete any colour that `C` uses (otherwise `C` would violate an
edge). Hence the branch containing `C` is never pruned.
Following this branch the algorithm finally reaches the leaf where all
vertices are coloured exactly as in `C`, and returns success.
Therefore a solution is found. ∎



##### Lemma 6  
If the algorithm prints `NO`, the instance has no proper 3‑colouring.

**Proof.**  
`NO` is printed only when `dfs` returns `False`, i.e. every branch of the
search tree has been examined and each of them was discarded because
`propagate` detected a conflict (empty domain) or because a later recursive
call failed.
By Lemma&nbsp;2 a conflict means that the current partial assignment cannot
be extended to a full colouring.
By Lemma&nbsp;3 the recursive call fails only if none of its sub‑branches can
be extended.
Consequently **all** possible colour assignments are impossible,
so the graph is not 3‑colourable. ∎



##### Theorem  
The program prints  

*`YES` and a valid calibration* **iff** a valid calibration exists;  
otherwise it prints `NO`.

**Proof.**  
*If* part – Lemma&nbsp;5 guarantees that a solution is found and printed.
*Only‑if* part – Lemma&nbsp;4 shows any printed calibration is valid,
and Lemma&nbsp;6 shows that printing `NO` implies that no valid calibration
exists. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

`n ≤ 40`, `m ≤ n·(n‑1)/2`.

*Each recursive call*  

* scans the adjacency list of the vertex that is coloured – `O(deg(v))`,
* the propagation loop scans at most all vertices and their edges,
  overall `O(m)`.

Hence the work of one call is `O(m)`.

The recursion depth is at most `n`, and the branching factor never exceeds
`3`.  
In the worst theoretical case the algorithm could explore `3^n` nodes,
but with the strong propagation and the “most constrained variable”
heuristic the explored part of the tree is tiny for `n = 40`.
The program easily fits into the 2 seconds limit.

Memory consumption: adjacency list `O(m)`, plus a few arrays of size `n`
and a recursion stack of depth `n`.  
Total `O(n + m) ≤ 256 MB`.

#### Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    # domain masks: bit 0 -> colour 0 (phase 1), etc.
    domains = [0b111] * n
    colour = [-1] * n          # -1 = unassigned, else 0..2

    # ---------- propagation ----------
    def propagate(changes):
        """unit propagation, record all modifications in changes,
           return False if a conflict appears."""
        while True:
            progress = False
            for v in range(n):
                if colour[v] == -1 and (domains[v] & (domains[v] - 1)) == 0:
                    # exactly one possible colour
                    c = (domains[v].bit_length() - 1)
                    # record old state
                    changes.append((v, domains[v], colour[v]))
                    domains[v] = 1 << c
                    colour[v] = c
                    for u in adj[v]:
                        if colour[u] == -1 and (domains[u] & (1 << c)):
                            changes.append((u, domains[u], colour[u]))
                            domains[u] &= ~(1 << c)
                            if domains[u] == 0:
                                return False
                    progress = True
            if not progress:
                break
        return True

    # ---------- depth‑first search ----------
    def dfs() -> bool:
        # all coloured ?
        if all(col != -1 for col in colour):
            return True

        # choose vertex with smallest domain (>1)
        v = -1
        best = 4
        for i in range(n):
            if colour[i] == -1:
                sz = bin(domains[i]).count('1')
                if sz < best:
                    best = sz
                    v = i
                    if sz == 2:   # cannot be 1 because then it would be forced
                        pass
        mask = domains[v]
        for c in range(3):
            if mask & (1 << c):
                changes = []
                # assign v = c
                changes.append((v, domains[v], colour[v]))
                domains[v] = 1 << c
                colour[v] = c
                conflict = False
                for u in adj[v]:
                    if colour[u] == -1 and (domains[u] & (1 << c)):
                        changes.append((u, domains[u], colour[u]))
                        domains[u] &= ~(1 << c)
                        if domains[u] == 0:
                            conflict = True
                            break
                if not conflict and propagate(changes):
                    if dfs():
                        return True
                # backtrack
                for vertex, old_mask, old_col in reversed(changes):
                    domains[vertex] = old_mask
                    colour[vertex] = old_col
        return False

    possible = dfs()
    out = []
    if possible:
        out.append("YES")
        out.append(' '.join(str(colour[i] + 1) for i in range(n)))
    else:
        out.append("NO")
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```

and conforms to the required input / output format.
