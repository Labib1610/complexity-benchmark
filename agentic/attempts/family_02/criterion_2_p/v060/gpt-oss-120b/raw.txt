**Solution Explanation**

The condition *“for every clause at least one of its two literals must be true”* is exactly the
**2‑SAT** problem.

* variable `i` – the solvent of herb `i`
    * `0` – Aqueous Glycerin  
    * `1` – Ethanol  

* literal  
    * `+i`  – “herb *i* is `1`”  
    * `-i`  – “herb *i* is `0`”

A clause `(a ∨ b)` is satisfied iff at least one of the two literals is true.
For 2‑SAT we build an implication graph:

```
(¬a → b)   and   (¬b → a)
```

If the graph contains a variable and its negation in the same strongly
connected component (SCC) the formula is unsatisfiable.
Otherwise a satisfying assignment is obtained by processing the SCCs in
reverse topological order: a variable is set to `1` iff the SCC of its
positive literal comes **after** the SCC of its negative literal.

The graph has `2·n` vertices, at most `2·m` edges (`m ≤ 2·10⁵`), so linear
algorithms are easily fast enough.

--------------------------------------------------------------------

#### Algorithm
```
read n, m
create adjacency lists G[2n], GR[2n]   // graph and reversed graph

function node(var, val):          // val = 0 or 1
        return 2*var + val        // 0‑based indices, 0 = false, 1 = true

for each clause (l1, l2):
        (v1, val1) = literal l1
        (v2, val2) = literal l2
        add edge  node(v1, 1-val1) → node(v2, val2)   to G and GR
        add edge  node(v2, 1-val2) → node(v1, val1)   to G and GR

// Kosaraju – first pass: order by finish time
visited = [False]*2n
order = []
for v in 0 .. 2n-1:
        if not visited[v]:
                iterative DFS from v, fill order when leaving a vertex

// second pass: assign component ids on reversed graph
comp = [-1]*2n
cid = 0
process vertices of 'order' in reverse:
        if comp[v] == -1:
                iterative DFS on GR, set comp[w] = cid for all reached
                cid += 1

// check satisfiability
for i in 0 .. n-1:
        if comp[node(i,0)] == comp[node(i,1)]:
                print "NO" and exit

// build one solution
answer = []
for i in 0 .. n-1:
        # component with larger id appears earlier in topological order
        val = 1 if comp[node(i,1)] > comp[node(i,0)] else 0
        answer.append(val)

print "YES"
print answer space‑separated
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints **YES** and a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
For every clause `(a ∨ b)` the algorithm adds exactly the two implications
`(¬a → b)` and `(¬b → a)` to the implication graph.

**Proof.**  
A literal `l` is transformed to `(var, val)` where `val = 1` for a positive
literal and `val = 0` for a negative one.
`node(var, 1-val)` is the vertex representing `¬l`.  
The two edges added are precisely from `¬a` to `b` and from `¬b` to `a`. ∎



##### Lemma 2  
If a variable `x` and its negation belong to the same SCC, the formula is
unsatisfiable.

**Proof.**  
Inside one SCC there is a directed path `x →* ¬x` and also `¬x →* x`.
Thus `x ⇒ ¬x` and `¬x ⇒ x`. Any truth assignment would have to satisfy both,
forcing `x` and `¬x` to have the same truth value, impossible. ∎



##### Lemma 3  
If for every variable `x` the vertices `x` and `¬x` are in different SCCs,
setting `x = 1` exactly when `comp(x) > comp(¬x)` satisfies all clauses.

**Proof.**  
Consider the condensation DAG of SCCs. By construction of Kosaraju,
components are numbered in the order they are discovered in the second pass,
which is a reverse topological order: edges go from higher numbers to lower
numbers.

Take any implication edge `u → v`. Then `comp(u) ≥ comp(v)`.  
If `u` is assigned `True` (i.e. `comp(u) > comp(¬u)`), we have `comp(u) > comp(¬u)`.
Because `comp(u) ≥ comp(v)`, we cannot have `comp(v) < comp(¬v)` (otherwise
`comp(v) ≤ comp(¬v) < comp(u)` would give an edge from a later to an earlier
component, contradicting the topological order). Hence `comp(v) > comp(¬v)`,
so `v` is also assigned `True`. Therefore every implication is respected,
and each clause `(a ∨ b)` (which is equivalent to the two implications)
is satisfied. ∎



##### Lemma 4  
If the algorithm outputs **YES**, the printed assignment satisfies all
clauses.

**Proof.**  
The algorithm outputs **YES** only when no variable shares an SCC with its
negation (Lemma 2). Then it uses the rule of Lemma 3, therefore the assignment
satisfies every implication and consequently every clause. ∎



##### Lemma 5  
If the formula is satisfiable, the algorithm never prints **NO**.

**Proof.**  
Assume a satisfying assignment exists.
In any satisfying assignment no variable can imply its own negation,
otherwise the assignment would violate that implication.
Thus in the implication graph there is no directed cycle containing both
`x` and `¬x`; otherwise they would be mutually reachable and belong to the same
SCC, contradicting the existence of a satisfying assignment.
Hence for every variable the two literals lie in different SCCs, and the
algorithm will not reject. ∎



##### Theorem  
The algorithm prints **YES** and a correct assignment
iff a satisfying assignment exists; otherwise it prints **NO**.

**Proof.**  
*If* part: by Lemma 4 a printed assignment is correct, so a satisfying
assignment exists.  
*Only‑if* part: by Lemma 5 the algorithm cannot reject a satisfiable instance,
so it prints **YES**. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Vertices*: `2n`  
*Edges*: `2m`  

Kosaraju runs two DFS traversals:

```
time  : O(V + E) = O(n + m)
memory: O(V + E) = O(n + m)
```

Both limits satisfy the given constraints (`n ≤ 10⁵`, `m ≤ 2·10⁵`).

#### Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(1 << 25)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    N = 2 * n
    G = [[] for _ in range(N)]
    GR = [[] for _ in range(N)]

    def node(var: int, val: int) -> int:
        return 2 * var + val  # val 0 = false, 1 = true

    for _ in range(m):
        l1 = int(next(it))
        l2 = int(next(it))

        v1 = abs(l1) - 1
        val1 = 1 if l1 > 0 else 0
        v2 = abs(l2) - 1
        val2 = 1 if l2 > 0 else 0

        a = node(v1, val1)
        na = node(v1, 1 - val1)
        b = node(v2, val2)
        nb = node(v2, 1 - val2)

        # ¬a -> b
        G[na].append(b)
        GR[b].append(na)
        # ¬b -> a
        G[nb].append(a)
        GR[a].append(nb)

    visited = [False] * N
    order = []

    # iterative DFS for first pass
    for start in range(N):
        if visited[start]:
            continue
        stack = [(start, 0)]
        while stack:
            v, idx = stack[-1]
            if not visited[v]:
                visited[v] = True
            # explore neighbours
            if idx < len(G[v]):
                nxt = G[v][idx]
                stack[-1] = (v, idx + 1)
                if not visited[nxt]:
                    stack.append((nxt, 0))
            else:
                order.append(v)
                stack.pop()

    comp = [-1] * N
    cid = 0
    # second pass on reversed graph
    for v in reversed(order):
        if comp[v] != -1:
            continue
        stack = [v]
        comp[v] = cid
        while stack:
            cur = stack.pop()
            for nxt in GR[cur]:
                if comp[nxt] == -1:
                    comp[nxt] = cid
                    stack.append(nxt)
        cid += 1

    # check satisfiability
    for i in range(n):
        if comp[node(i, 0)] == comp[node(i, 1)]:
            print("NO")
            return

    # build assignment
    ans = []
    for i in range(n):
        val = 1 if comp[node(i, 1)] > comp[node(i, 0)] else 0
        ans.append(str(val))

    print("YES")
    print(" ".join(ans))


if __name__ == "__main__":
    solve()
```

to the required input‑output format.
