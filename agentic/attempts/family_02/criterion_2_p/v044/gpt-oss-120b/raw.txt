**Solution Explanation**

For every toggle `i` we have a Boolean variable `x_i`  
`x_i = 1` – the toggle is ON, `x_i = 0` – OFF.

Each clearance criterion contains exactly two *requirements* (literals).  
A criterion is satisfied iff at least one of its two literals is true, i.e. it is a
2‑SAT clause  

```
(l1) OR (l2)
```

The whole audit is a conjunction of all clauses – a classic 2‑SAT problem.
We have to decide satisfiability and, if possible, output one satisfying
assignment.

--------------------------------------------------------------------

#### 1.   Implication graph

For a clause `(a ∨ b)` we add the two implications  

```
¬a → b
¬b → a
```

If we can reach `b` from `¬a` and also `¬b` from `a`, the clause is enforced.
The graph has `2·n` vertices – one for each literal and its negation.

Vertex numbering (0‑based)

```
variable i (1 … n)
    true  literal  →  id = 2·(i-1)
    false literal  →  id = 2·(i-1) ^ 1   (the opposite parity)
```

`neg(v) = v ^ 1`.

--------------------------------------------------------------------

#### 2.   Strongly Connected Components

In the implication graph a formula is **unsatisfiable** iff a variable and its
negation belong to the same SCC (they imply each other, forcing both true and
false).

If they are in different SCCs we can obtain a satisfying assignment:
process SCCs in reverse topological order (the order produced by Kosaraju’s
second pass).  
For a variable `i`

```
x_i = 1   if   comp[ true_literal ]  >  comp[ false_literal ]
        else 0
```

Because a component that appears later in the order cannot reach an earlier
one, the chosen value never contradicts an implication.

--------------------------------------------------------------------

#### 3.   Algorithm
```
read n, m
build adjacency list G (size 2n) and reverse list GR
for each clause (l1, l2):
        a = literal_id(l1)          # positive → true, negative → false
        b = literal_id(l2)
        add edge  neg(a) → b   to G and GR
        add edge  neg(b) → a   to G and GR

# Kosaraju
stack = []
visited = [False]*2n
for v in 0 .. 2n-1:
        if not visited[v]:
                iterative DFS from v, fill stack with finishing order

comp = [-1]*2n
cur = 0
while stack:
        v = stack.pop()
        if comp[v] == -1:
                iterative DFS on GR from v, marking all reached vertices with comp = cur
                cur += 1

# check satisfiability
for i in 0 .. n-1:
        if comp[2*i] == comp[2*i^1]:
                print "NO" and exit

# construct assignment
ans = []
for i in 0 .. n-1:
        val = 1 if comp[2*i] > comp[2*i^1] else 0
        ans.append(val)

print "YES"
print ans space separated
```

All steps are linear: `O(n + m)` time, `O(n + m)` memory.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs **YES** with a configuration exactly when a
configuration satisfying all criteria exists, otherwise outputs **NO**.

---

##### Lemma 1  
For every clause `(a ∨ b)` the added edges `¬a → b` and `¬b → a` are logically
equivalent to the clause.

**Proof.**  
If `a` is true, the clause holds regardless of `b`.  
If `a` is false (`¬a` true) then the edge forces `b` to be true, making the
clause true. Symmetrically for `b`. Hence any assignment satisfying the two
implications satisfies the clause, and any assignment violating the clause
makes at least one implication false. ∎



##### Lemma 2  
If a variable `x` and its negation `¬x` belong to the same SCC, the formula is
unsatisfiable.

**Proof.**  
Inside an SCC each vertex reaches every other, therefore `x → ¬x` and
`¬x → x`. Any assignment would have to set both `x` and `¬x` to true, which is
impossible. ∎



##### Lemma 3  
If for every variable `x` the literals `x` and `¬x` are in different SCCs, the
assignment defined by  

```
x = 1  iff  comp[x] > comp[¬x]
```

satisfies all implications of the graph.

**Proof.**  
Consider any edge `u → v`. SCC numbers respect the reverse topological order:
if there is a path from component `C_u` to `C_v` then `C_u ≤ C_v`.  
If `comp[u] > comp[v]` then `u` is assigned true and `v` false, contradicting
the edge. But `comp[u] > comp[v]` cannot happen because an edge implies a
reachability, thus `comp[u] ≤ comp[v]`.  
Two cases:

* `comp[u] = comp[v]` – both literals are in the same SCC, impossible by the
  premise (they would be a variable and its negation).
* `comp[u] < comp[v]` – then `u` is assigned false (its component appears earlier)
  and `v` true, satisfying the implication.

Hence every implication holds, and by Lemma&nbsp;1 every original clause holds. ∎



##### Lemma 4  
If the algorithm prints **YES**, the printed configuration satisfies all
criteria.

**Proof.**  
The algorithm prints **YES** only when no variable shares an SCC with its
negation, therefore Lemma&nbsp;3 applies and the constructed assignment satisfies
all implications, consequently all clauses. ∎



##### Lemma 5  
If the algorithm prints **NO**, no satisfying configuration exists.

**Proof.**  
**NO** is printed exactly when some variable `x` and `¬x` are in the same SCC.
By Lemma&nbsp;2 any assignment would require both `x` and `¬x` true, impossible.
Thus the formula is unsatisfiable. ∎



##### Theorem  
The algorithm is correct.

**Proof.**  
*If a satisfying configuration exists*: the implication graph is satisfiable,
hence no variable shares an SCC with its negation. The algorithm will not output
**NO**, proceeds to build the assignment, and by Lemma&nbsp;4 this assignment is
valid, so it outputs **YES** with a correct configuration.

*If no satisfying configuration exists*: by Lemma&nbsp;2 some variable and its
negation belong to the same SCC, the algorithm detects this and outputs **NO**.
By Lemma&nbsp;5 this is correct.

Thus the output is correct in all cases. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Building the graph*: `O(m)` edges, each added twice (forward & reverse) →  
time `O(m)`, memory `O(n + m)`.

*Kosaraju* traverses each vertex and edge a constant number of times →  
time `O(n + m)`, additional memory `O(n)` for stacks and component array.

Overall  

```
Time   : O(n + m)   ≤ 3·10^5 operations
Memory : O(n + m)   ≤ 3·10^5 integers  (well below limits)
```

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    N = 2 * n
    g = [[] for _ in range(N)]
    rg = [[] for _ in range(N)]

    def lit_id(x: int) -> int:
        v = abs(x) - 1
        if x > 0:
            return v * 2          # true
        else:
            return v * 2 ^ 1      # false (negated parity)

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        ida = lit_id(a)
        idb = lit_id(b)
        na = ida ^ 1
        nb = idb ^ 1
        # ¬a -> b
        g[na].append(idb)
        rg[idb].append(na)
        # ¬b -> a
        g[nb].append(ida)
        rg[ida].append(nb)

    sys.setrecursionlimit(1 << 25)

    visited = [False] * N
    order = []

    # iterative DFS for first pass
    for v in range(N):
        if not visited[v]:
            stack = [(v, 0)]
            while stack:
                node, state = stack.pop()
                if state == 0:
                    if visited[node]:
                        continue
                    visited[node] = True
                    stack.append((node, 1))
                    for to in g[node]:
                        if not visited[to]:
                            stack.append((to, 0))
                else:
                    order.append(node)

    comp = [-1] * N
    cur = 0
    # second pass on reversed graph
    for v in reversed(order):
        if comp[v] == -1:
            stack = [v]
            comp[v] = cur
            while stack:
                node = stack.pop()
                for to in rg[node]:
                    if comp[to] == -1:
                        comp[to] = cur
                        stack.append(to)
            cur += 1

    # check satisfiability
    for i in range(n):
        if comp[2 * i] == comp[2 * i ^ 1]:
            print("NO")
            return

    # build answer
    ans = []
    for i in range(n):
        val = 1 if comp[2 * i] > comp[2 * i ^ 1] else 0
        ans.append(str(val))

    print("YES")
    print(' '.join(ans))

if __name__ == "__main__":
    solve()
```

the required input‑output format.
