**Solution Explanation**

The problem is a classic *2‑SAT* instance.

* each valve `i` is a Boolean variable `x_i`
    * `x_i = 1` – bypass mode  
    * `x_i = 0` – radiator mode
* each safety protocol gives a clause  
  `(literal a)  OR  (literal b)`  
  where a literal is either `x_i` (positive integer) or `¬x_i` (negative integer).

A 2‑SAT formula is satisfiable iff in its implication graph no variable and its
negation belong to the same strongly connected component (SCC).  
If it is satisfiable, a concrete assignment can be obtained from the
topological order of the SCCs.

The constraints (`n ≤ 10⁵ , m ≤ 2·10⁵`) fit easily into linear‑time SCC
algorithms.



--------------------------------------------------------------------

#### 1.   Graph construction  

For every variable `i` we create two vertices  

```
id(i, true)  = 2*(i-1)          # x_i
id(i, false) = 2*(i-1) ^ 1      # ¬x_i
```

`¬v` is simply `v ^ 1`.

A clause `(a ∨ b)` is transformed into two implications  

```
¬a → b
¬b → a
```

and the corresponding directed edges are added.



--------------------------------------------------------------------

#### 2.   Kosaraju’s algorithm (iterative)

* first DFS on the original graph – store vertices in finishing order
* second DFS on the reversed graph – process vertices in reverse finishing order,
  each traversal yields one SCC and receives a component number `comp[v]`

Both passes are written iteratively (explicit stack) to avoid recursion depth
problems.



--------------------------------------------------------------------

#### 3.   Checking satisfiability  

For every variable `i`

```
if comp[id(i, true)] == comp[id(i, false)] → UNSAT
```

Otherwise the variable value is decided by the component order:

```
value(i) = 1  if comp[id(i, true)]  > comp[id(i, false)]
            0  otherwise
```

In Kosaraju the component numbers increase in the order of the second pass,
which is a reverse topological order of the condensation DAG.
Thus a component with a larger number appears earlier in any topological order,
so the rule above yields a correct assignment.



--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a valid assignment
iff such an assignment exists.

---

##### Lemma 1  
For every clause `(a ∨ b)` the added edges correctly represent the logical
implications `¬a → b` and `¬b → a`.

**Proof.**  
`a` and `b` are literals, each corresponds to a vertex `v`.  
`¬a` is the vertex `v ^ 1`. Adding an edge `v ^ 1 → w` (where `w` is the vertex of
`b`) is exactly the implication `¬a → b`. The same holds for the second edge. ∎



##### Lemma 2  
If a variable `x_i` and its negation belong to the same SCC, the formula is
unsatisfiable.

**Proof.**  
Inside an SCC each vertex reaches every other vertex.
Thus `x_i → ¬x_i` and `¬x_i → x_i`. Any truth assignment would have to satisfy
both, which is impossible. ∎



##### Lemma 3  
If for every variable `x_i` the two literals are in different SCCs, the
assignment defined by  

```
x_i = 1  iff  comp[x_i] > comp[¬x_i]
```

satisfies all clauses.

**Proof.**  
Consider the condensation DAG of SCCs. Edges go from a component to another
different component, never backwards. By construction of Kosaraju,
components are numbered in reverse topological order, i.e. all edges go from
higher numbers to lower numbers.

Take any implication edge `u → v`. Then `comp[u] ≥ comp[v]`.  
If `u` is assigned **true**, we have `comp[u] > comp[¬u]`. Because `comp[u] ≥ comp[v]`,
`comp[v]` cannot be smaller than `comp[¬u]`; therefore `v` is also assigned
**true**. Hence every implication is respected, and consequently every clause
`(a ∨ b)` (equivalent to the two implications) is satisfied. ∎



##### Lemma 4  
If the algorithm outputs `YES` and the assignment described above, all safety
protocols are satisfied.

**Proof.** Directly from Lemma&nbsp;3, because the algorithm outputs `YES` only
when Lemma&nbsp;2 does not apply. ∎



##### Lemma 5  
If the formula is satisfiable, the algorithm never declares `NO`.

**Proof.** In any satisfying assignment no variable and its negation can be
mutually reachable, otherwise Lemma&nbsp;2 would be violated. Hence they lie in
different SCCs, so the algorithm will not hit the unsat test and will output
`YES`. ∎



##### Theorem  
The program prints `NO` iff the given instance has no feasible valve
configuration; otherwise it prints `YES` followed by a configuration that
satisfies all safety protocols.

**Proof.**  
*If* the program prints `YES`, by Lemma&nbsp;4 the printed configuration is
valid, therefore a feasible configuration exists.  
*Only if* a feasible configuration exists, Lemma&nbsp;5 guarantees the program
does not output `NO`; consequently it outputs `YES` and a configuration,
which is valid by Lemma&nbsp;4. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Vertices*: `2n`  
*Edges*: `2m` (two per clause)

Both DFS passes are linear:

```
Time   : O(n + m)
Memory : O(n + m)   (adjacency lists, stacks, component array)
```

Both satisfy the limits.



--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    N = 2 * n
    g = [[] for _ in range(N)]
    rg = [[] for _ in range(N)]

    def lit_to_node(x: int) -> int:
        v = abs(x) - 1
        base = v * 2
        return base if x > 0 else base ^ 1

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        na = lit_to_node(a)
        nb = lit_to_node(b)
        na_neg = na ^ 1
        nb_neg = nb ^ 1
        # ¬a -> b
        g[na_neg].append(nb)
        rg[nb].append(na_neg)
        # ¬b -> a
        g[nb_neg].append(na)
        rg[na].append(nb_neg)

    # ---------- first pass ----------
    visited = [False] * N
    order = []

    for v in range(N):
        if not visited[v]:
            stack = [(v, 0)]  # (node, next child index)
            while stack:
                node, idx = stack[-1]
                if not visited[node]:
                    visited[node] = True
                # iterate neighbours
                if idx < len(g[node]):
                    nxt = g[node][idx]
                    stack[-1] = (node, idx + 1)
                    if not visited[nxt]:
                        stack.append((nxt, 0))
                else:
                    order.append(node)
                    stack.pop()

    # ---------- second pass ----------
    comp = [-1] * N
    cur_comp = 0
    for v in reversed(order):
        if comp[v] == -1:
            stack = [v]
            comp[v] = cur_comp
            while stack:
                node = stack.pop()
                for nxt in rg[node]:
                    if comp[nxt] == -1:
                        comp[nxt] = cur_comp
                        stack.append(nxt)
            cur_comp += 1

    # ---------- check ----------
    assignment = [0] * n
    for i in range(n):
        t = 2 * i
        f = t ^ 1
        if comp[t] == comp[f]:
            print("NO")
            return
        assignment[i] = 1 if comp[t] > comp[f] else 0

    # ---------- output ----------
    print("YES")
    print(' '.join(map(str, assignment)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
