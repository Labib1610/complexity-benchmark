**Solution Explanation**

The problem is a classic *2‑SAT* instance.

* each switch `i` is a Boolean variable  
  `xi = 1`  → switch `i` is **UP**  
  `xi = 0`  → switch `i` is **DOWN**
* a requirement `l1 l2` means “literal `l1` **or** literal `l2` must be true”.
  A literal is either `xi` (positive `i`) or `¬xi` (negative `i`).

A 2‑SAT formula is satisfiable iff its implication graph does **not**
contain a variable and its negation in the same strongly connected component
(SCC). Moreover, a satisfying assignment can be obtained from the
topological order of the SCC‑condensation graph.

The constraints are up to `10^5` variables and `2·10^5` clauses, well within
the linear‑time SCC algorithms.

--------------------------------------------------------------------

#### 1.   Graph construction  

For `n` variables we create `2·n` vertices:

```
index 2*i     → literal  ¬xi   (switch i is DOWN)
index 2*i + 1 → literal   xi   (switch i is UP)
```

For a clause `(a ∨ b)` we add the two implications

```
¬a → b
¬b → a
```

Both are edges in the directed graph.

--------------------------------------------------------------------

#### 2.   Strongly connected components  

We use **Kosaraju’s algorithm** (two depth‑first passes).  
Both passes are written iteratively with explicit stacks to avoid recursion
limits.

*First pass* – DFS on the original graph, storing vertices in finishing order.  
*Second pass* – DFS on the reversed graph, processing vertices in reverse
finishing order and assigning a component id to each visited vertex.

Both passes run in `O(V+E)` time.

--------------------------------------------------------------------

#### 3.   Checking satisfiability  

For every variable `i`

```
if comp[2*i] == comp[2*i+1] → unsatisfiable
```

--------------------------------------------------------------------

#### 4.   Building a concrete assignment  

The component ids are assigned in the order the second pass discovers SCCs.
Thus a component discovered later gets a **larger** id and is *earlier* in the
topological order of the condensation graph.

The standard rule:

```
xi = 1   if comp[2*i+1] > comp[2*i]
xi = 0   otherwise
```

produces a satisfying assignment.

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm outputs “YES” and a correct configuration
iff such a configuration exists.

---

##### Lemma 1  
For every clause `(a ∨ b)` the added edges `¬a → b` and `¬b → a`
are logically equivalent to the clause.

**Proof.**  
If `a` is true, the clause is satisfied regardless of `b`.  
If `a` is false (`¬a` true) then the edge forces `b` to be true, satisfying
the clause. Symmetrically for `b`. ∎



##### Lemma 2  
In the implication graph, if a literal `p` can reach its negation `¬p`,
then any satisfying assignment must set `p` to false.

**Proof.**  
Assume a satisfying assignment sets `p = true`. Because there is a directed
path `p → … → ¬p`, by repeatedly applying the implication rule we would
obtain `¬p = true`, contradicting `p = true`. Hence `p` cannot be true. ∎



##### Lemma 3  
If a variable `x` and its negation belong to the same SCC, the formula is
unsatisfiable.

**Proof.**  
Inside an SCC every vertex reaches every other, therefore `x` reaches `¬x`
and `¬x` reaches `x`. By Lemma&nbsp;2 both must be false, impossible. ∎



##### Lemma 4  
If for every variable `x` the two literals lie in different SCCs,
the assignment defined by `x = 1` iff `comp(x) > comp(¬x)` satisfies all
clauses.

**Proof.**  
Consider any edge `p → q` of the implication graph.
Topologically, `comp(p) ≥ comp(q)` (edges never go from a later component to an
earlier one).  
If `p` is assigned true, then `comp(p) > comp(¬p)`. Because `comp(p) ≥ comp(q)`,
we have `comp(q) ≥ comp(¬p)`. Since `comp(q)` and `comp(¬q)` are distinct,
the only way `comp(q) = comp(¬p)` is impossible, thus `comp(q) > comp(¬q)`,
so `q` is also true. Hence every implication is respected, and by Lemma&nbsp;1
all original clauses are satisfied. ∎



##### Lemma 5  
The algorithm outputs “NO” exactly when the formula is unsatisfiable.

**Proof.**  
The algorithm outputs “NO” precisely when some variable has both literals in
the same SCC. By Lemma&nbsp;3 this makes the formula unsatisfiable.
Conversely, if the formula is unsatisfiable, any assignment violates some
clause, which by Lemma&nbsp;1 yields a directed cycle containing a literal and
its negation, i.e. they belong to the same SCC. Hence the algorithm will
detect it and output “NO”. ∎



##### Lemma 6  
When the algorithm outputs “YES”, the produced assignment satisfies all
requirements.

**Proof.**  
“YES” is printed only if every variable’s literals are in different SCCs.
The assignment is built exactly as in Lemma&nbsp;4, therefore it satisfies
all clauses. ∎



##### Theorem  
The program prints

* “NO” iff no global configuration satisfies all requirements,
* otherwise “YES” followed by a configuration that satisfies all requirements.

**Proof.**  
Directly from Lemma&nbsp;5 (correctness of the “NO” case) and Lemma&nbsp;6
(correctness of the “YES” case). ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Vertices*: `2n`  
*Edges*: `2m` (two per clause)

Both DFS passes visit each vertex and edge once.

```
Time   : O(n + m)
Memory : O(n + m)   (adjacency lists, reverse lists, stacks, arrays)
```

Both respect the limits (`n ≤ 10^5`, `m ≤ 2·10^5`).

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    N = 2 * n
    g = [[] for _ in range(N)]
    rg = [[] for _ in range(N)]

    def lit_index(l: int) -> int:
        """return vertex index for literal l (positive -> xi, negative -> ¬xi)"""
        if l > 0:
            v = l - 1
            return 2 * v + 1          # xi
        else:
            v = -l - 1
            return 2 * v              # ¬xi

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        A = lit_index(a)
        B = lit_index(b)
        NA = A ^ 1          # opposite literal (toggle last bit)
        NB = B ^ 1
        # ¬a -> b
        g[NA].append(B)
        rg[B].append(NA)
        # ¬b -> a
        g[NB].append(A)
        rg[A].append(NB)

    sys.setrecursionlimit(1 << 25)

    # ---------- first pass ----------
    visited = [False] * N
    order = []

    for v in range(N):
        if not visited[v]:
            stack = [(v, 0)]
            while stack:
                node, state = stack.pop()
                if state == 0:
                    if visited[node]:
                        continue
                    visited[node] = True
                    stack.append((node, 1))
                    for to in g[node]:
                        if not visited[to]:
                            stack.append((to, 0))
                else:
                    order.append(node)

    # ---------- second pass ----------
    comp = [-1] * N
    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            stack = [v]
            comp[v] = cid
            while stack:
                node = stack.pop()
                for to in rg[node]:
                    if comp[to] == -1:
                        comp[to] = cid
                        stack.append(to)
            cid += 1

    # ---------- check satisfiability ----------
    assignment = [0] * n
    for i in range(n):
        if comp[2 * i] == comp[2 * i + 1]:
            print("NO")
            return
        assignment[i] = 1 if comp[2 * i + 1] > comp[2 * i] else 0

    # ---------- output ----------
    print("YES")
    print(' '.join(map(str, assignment)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
