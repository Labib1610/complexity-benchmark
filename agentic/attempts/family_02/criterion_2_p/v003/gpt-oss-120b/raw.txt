**Solution Explanation**

The condition “at least one of the two literals must be true” is exactly a
2‑SAT clause  

```
(l1) ∨ (l2)
```

where a literal is either a variable `xi` (switch *i* is ON) or its negation
`¬xi` (switch *i* is OFF).

A 2‑SAT instance is satisfiable iff in its implication graph no variable and its
negation belong to the same strongly connected component (SCC).  
If the instance is satisfiable, a satisfying assignment can be obtained from the
topological order of the SCCs.

The algorithm:

1. **Build the implication graph**  
   For each clause `(a ∨ b)` add the two directed edges  

   ```
   ¬a → b
   ¬b → a
   ```

   We number literals `0 … 2·n‑1` :

   * `2·(i‑1)`   – literal `xi`   (switch *i* = 1)  
   * `2·(i‑1)+1` – literal `¬xi`  (switch *i* = 0)

   The negation of a literal `v` is `v ^ 1`.

2. **Find SCCs** – Kosaraju’s algorithm (two DFS passes) works in `O(V+E)`.

3. **Check consistency** – for every variable `i`  
   if `comp[2·(i‑1)] == comp[2·(i‑1)+1]` the instance is unsatisfiable.

4. **Construct an assignment** – process SCCs in reverse topological order
   (the order produced by the second pass of Kosaraju).  
   A variable is set to `1` (ON) iff the component of its positive literal appears
   **after** the component of its negative literal.

The whole procedure is linear in the size of the input and fits easily into the
limits (`n ≤ 10⁵, m ≤ 2·10⁵`).

---

#### Correctness Proof  

We prove that the algorithm outputs “YES” and a correct assignment exactly when
the given set of rules is satisfiable.

---

##### Lemma 1  
For every clause `(a ∨ b)` the added edges `¬a → b` and `¬b → a` are logically
equivalent to the clause.

**Proof.**  
If `a` is true, the clause is satisfied regardless of `b`. The edge `¬b → a`
does not affect this case.  
If `a` is false, then `¬a` is true, and the edge `¬a → b` forces `b` to be true,
hence the clause is satisfied. Symmetrically for `b`. ∎



##### Lemma 2  
In any assignment that satisfies all clauses, every directed edge of the
implication graph is respected: if the source literal is true then the target
literal is also true.

**Proof.**  
Each edge is of the form `p → q` where `p` is the negation of some literal in a
clause. If `p` is true, then the corresponding literal of the clause is false,
so by Lemma&nbsp;1 the other literal of the clause must be true, i.e. `q` is true. ∎



##### Lemma 3  
If a variable `xi` and its negation belong to the same SCC, the instance is
unsatisfiable.

**Proof.**  
Inside an SCC there is a directed path from `xi` to `¬xi` and a path back.
By Lemma&nbsp;2, truth of `xi` forces truth of `¬xi`, and truth of `¬xi` forces
truth of `xi`. Hence both must have the same truth value, which is impossible.
∎



##### Lemma 4  
If for every variable `xi` the two literals lie in different SCCs, the assignment
produced by the algorithm satisfies all clauses.

**Proof.**  
Consider the order in which SCCs are processed: decreasing finishing times of the
first DFS, i.e. a reverse topological order of the condensation DAG.
When we assign a variable, the component of the literal that appears later in
this order is set to true, the earlier one to false.

Take any edge `p → q`. In the condensation DAG there is an edge from
`comp(p)` to `comp(q)`. Therefore `comp(p)` cannot appear later than `comp(q)`.
If `p` were assigned true, then `comp(p)` would be later than `comp(¬p)`,
hence also later than `comp(q)`, contradicting the edge direction.
Thus `p` is never true while `q` is false, i.e. the edge condition of Lemma 2
holds for every edge, and consequently every original clause is satisfied
(Lemma 1). ∎



##### Lemma 5  
If the algorithm outputs “NO”, the instance is unsatisfiable.

**Proof.**  
The algorithm outputs “NO” exactly when some variable and its negation share an
SCC. By Lemma 3 such a situation makes the instance unsatisfiable. ∎



##### Lemma 6  
If the algorithm outputs “YES” and an assignment, that assignment satisfies all
clauses.

**Proof.**  
“YES” is printed only when no variable collides with its negation, so the
precondition of Lemma 4 holds. The assignment is built exactly as described in
Lemma 4, therefore it satisfies all clauses. ∎



##### Theorem  
The algorithm prints “YES” and a valid assignment iff the given set of rules is
consistent; otherwise it prints “NO”.

**Proof.**  
*If* part: when the algorithm prints “YES”, by Lemma 6 the assignment is valid,
hence the rules are consistent.  
*Only‑if* part: when the rules are consistent, the implication graph cannot have
a variable together with its negation in the same SCC (otherwise no assignment
could exist). Hence the algorithm will not trigger the “NO” case (Lemma 5) and
will output “YES” with the assignment constructed in Lemma 4, which is valid.
∎



---

#### Complexity Analysis  

*Vertices*: `2·n`  
*Edges*: `2·m`

Both DFS passes of Kosaraju run in `O(V+E) = O(n + m)`.  
All other steps are linear as well.

Memory consumption: adjacency lists store `2·m` integers, plus a few arrays of
size `2·n` → `O(n + m)` memory, well below the 256 MB limit.

---

#### Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(1 << 25)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    N = 2 * n                     # number of literals
    g = [[] for _ in range(N)]
    rg = [[] for _ in range(N)]

    def lit(x: int) -> int:
        """map signed integer to node index"""
        v = abs(x) - 1
        if x > 0:
            return 2 * v          # xi
        else:
            return 2 * v + 1      # ¬xi

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        A = lit(a)
        B = lit(b)
        NA = A ^ 1                 # negation
        NB = B ^ 1
        # ¬a -> b
        g[NA].append(B)
        rg[B].append(NA)
        # ¬b -> a
        g[NB].append(A)
        rg[A].append(NB)

    visited = [False] * N
    order = []

    def dfs(v: int):
        stack = [(v, 0)]
        while stack:
            v, state = stack.pop()
            if state == 0:
                if visited[v]:
                    continue
                visited[v] = True
                stack.append((v, 1))
                for to in g[v]:
                    if not visited[to]:
                        stack.append((to, 0))
            else:
                order.append(v)

    for v in range(N):
        if not visited[v]:
            dfs(v)

    comp = [-1] * N
    cur = 0

    def rdfs(v: int, label: int):
        stack = [v]
        while stack:
            x = stack.pop()
            if comp[x] != -1:
                continue
            comp[x] = label
            for to in rg[x]:
                if comp[to] == -1:
                    stack.append(to)

    for v in reversed(order):
        if comp[v] == -1:
            rdfs(v, cur)
            cur += 1

    assignment = [0] * n
    for i in range(n):
        pos = 2 * i
        neg = pos + 1
        if comp[pos] == comp[neg]:
            print("NO")
            return
        # component with larger topological order (larger comp id) is earlier in reverse order
        assignment[i] = 1 if comp[pos] > comp[neg] else 0

    print("YES")
    print(' '.join(map(str, assignment)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
