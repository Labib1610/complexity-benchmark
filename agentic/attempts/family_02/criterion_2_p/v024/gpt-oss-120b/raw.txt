**Solution Explanation**

For every sensor `i` we have a Boolean variable  

```
xi = 1   → sensor i works in high‑gain
xi = 0   → sensor i works in low‑gain
```

A safety requirement contains two *literals*  

```
l =  k   (k>0)   means   xk = 1
l = -k   (k>0)   means   xk = 0
```

The requirement *“at least one of the two literals is true”* is exactly a
2‑SAT clause  

```
(l1  OR  l2)
```

The whole task is to decide whether a 2‑SAT formula is satisfiable and,
if it is, to output one satisfying assignment.



--------------------------------------------------------------------

#### 1.   Implication graph

For a clause `(a OR b)` we add the two implications  

```
¬a → b
¬b → a
```

The graph has `2·n` vertices, one for each literal `xi = 0` and `xi = 1`.

```
vertex 2·i     : xi = 0   (false)
vertex 2·i + 1 : xi = 1   (true)
```

Negation is simply `v ^ 1`.

For every requirement we translate the two given integers to vertices
and add the two directed edges described above.



--------------------------------------------------------------------

#### 2.   Strongly connected components

A 2‑SAT instance is **unsatisfiable** iff some variable and its negation belong
to the same strongly connected component (SCC).

We compute SCCs with Kosaraju’s algorithm (two depth‑first passes).
Complexities: `O(V+E) = O(n+m)` time, `O(V+E)` memory.



--------------------------------------------------------------------

#### 3.   Building a concrete assignment

Kosaraju processes vertices in *reverse* topological order of the SCC‑DAG,
assigning component numbers `0,1,2,…` in that order.
Therefore, if `comp[true] > comp[false]` the component of `true` appears **earlier**
in the topological order, i.e. it cannot reach `false`.  
Choosing the literal whose component number is larger yields a consistent
assignment.

```
xi = 1   if comp[2·i+1] > comp[2·i]
xi = 0   otherwise
```



--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints “YES” and a correct configuration
iff such a configuration exists.

---

##### Lemma 1  
For every clause `(a OR b)` the added edges `¬a → b` and `¬b → a`
are satisfied by exactly the assignments that satisfy the clause.

**Proof.**  
If the clause is satisfied, at least one of `a,b` is true.
*If `a` is true*: `¬a` is false, the edge `¬a → b` imposes no restriction.
*If `a` is false*: then `b` must be true, and the edge forces `b` true.
Symmetric for `b`. Conversely, if both edges are respected,
assume the clause is false, i.e. `a = b = false`. Then `¬a` and `¬b` are true,
so the edges would require `b` and `a` to be true – contradiction. ∎



##### Lemma 2  
If a variable `xi` and its negation belong to the same SCC,
the formula is unsatisfiable.

**Proof.**  
Inside an SCC each vertex reaches every other.
Thus `xi → ¬xi` and `¬xi → xi`. Any assignment making `xi = 1`
implies `xi = 0`, impossible; similarly for `xi = 0`. Hence no assignment
can satisfy all implications, and by Lemma&nbsp;1 no assignment can satisfy
the original formula. ∎



##### Lemma 3  
If for every `i` the two literals are in different SCCs,
the assignment defined by  

```
xi = 1  iff  comp[true] > comp[false]
```

satisfies all implications.

**Proof.**  
Consider any edge `u → v`. In the SCC‑DAG there is a directed edge from
`comp[u]` to `comp[v]`. Topological order guarantees `comp[u] ≤ comp[v]`.
If `u` is assigned true, then `comp[u] > comp[¬u]`. Because `comp[u] ≤ comp[v]`,
we also have `comp[v] > comp[¬u]`. Since `¬v` is the opposite literal of `v`,
`comp[¬v]` is either `comp[¬u]` or smaller, thus `comp[v] > comp[¬v]`,
so `v` is assigned true. Therefore every true premise forces a true
conclusion, i.e. the implication holds. ∎



##### Lemma 4  
The assignment of Lemma&nbsp;3 satisfies every original clause.

**Proof.**  
By Lemma&nbsp;1 a clause is satisfied exactly when its two implications are
satisfied. Lemma&nbsp;3 guarantees all implications are satisfied, therefore
all clauses are satisfied. ∎



##### Theorem  
The algorithm outputs  

* “NO”  **iff** the instance is unsatisfiable;  
* otherwise “YES” and a configuration that satisfies all safety requirements.

**Proof.**  

*If the algorithm prints “NO”.*  
That happens only when some variable and its negation share an SCC.
By Lemma&nbsp;2 the formula is unsatisfiable.

*If the instance is unsatisfiable.*  
Any satisfying assignment would give a consistent truth assignment to all
implications, which is impossible when a variable and its negation are in the
same SCC (Lemma&nbsp;2). Hence the algorithm will detect such a pair and print
“NO”.

*If the algorithm prints “YES”.*  
All variable/negation pairs lie in different SCCs, and the algorithm outputs
the assignment of Lemma&nbsp;3. By Lemma&nbsp;4 this assignment satisfies every
clause, i.e. all safety requirements.

Thus the output is correct in all cases. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Vertices*: `2·n`  
*Edges*: `2·m`  

Kosaraju: two DFS traversals  

```
Time   O(n + m)
Memory O(n + m)
```

Both limits satisfy the problem constraints (`n ≤ 10^5`, `m ≤ 2·10^5`).

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(1 << 25)

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    N = 2 * n
    g = [[] for _ in range(N)]
    rg = [[] for _ in range(N)]

    def lit_to_node(l: int) -> int:
        v = abs(l) - 1
        if l > 0:
            return 2 * v + 1          # true
        else:
            return 2 * v              # false

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        u = lit_to_node(a)
        v = lit_to_node(b)
        nu = u ^ 1
        nv = v ^ 1
        # ¬a -> b
        g[nu].append(v)
        rg[v].append(nu)
        # ¬b -> a
        g[nv].append(u)
        rg[u].append(nv)

    visited = [False] * N
    order = []

    sys.setrecursionlimit(1 << 25)

    def dfs(v: int):
        stack = [(v, 0)]
        while stack:
            node, idx = stack.pop()
            if idx == 0:
                if visited[node]:
                    continue
                visited[node] = True
                stack.append((node, 1))
                for to in g[node]:
                    if not visited[to]:
                        stack.append((to, 0))
            else:
                order.append(node)

    for v in range(N):
        if not visited[v]:
            dfs(v)

    comp = [-1] * N
    cur = 0

    def rdfs(v: int, label: int):
        stack = [v]
        while stack:
            node = stack.pop()
            if comp[node] != -1:
                continue
            comp[node] = label
            for to in rg[node]:
                if comp[to] == -1:
                    stack.append(to)

    for v in reversed(order):
        if comp[v] == -1:
            rdfs(v, cur)
            cur += 1

    # check satisfiability
    for i in range(n):
        if comp[2 * i] == comp[2 * i + 1]:
            print("NO")
            return

    # build assignment
    ans = [0] * n
    for i in range(n):
        ans[i] = 1 if comp[2 * i + 1] > comp[2 * i] else 0

    print("YES")
    print(' '.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
