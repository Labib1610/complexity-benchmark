**Solution Explanation**

For every satellite we have to choose a distinct slot `p_i` (a permutation of `1…n`).
The power consumption of a required link `(u,v)` equals `|p_u-p_v|`.
The total consumption is the sum of these absolute differences.

The statement gives two “stability guarantees”

* `|u‑v| < n` – this is true for any two different IDs because both are in
  `{1,…,n}`.
* `u+v > 1` – also always true for positive IDs.

Thus the guarantees do not restrict the problem; they can be ignored.

The simplest possible assignment is the identity permutation

```
p_i = i   for all i = 1 … n
```

For this assignment the power of a link `(u,v)` is exactly `|u‑v|`,
so the total power is

```
total = Σ_{(u,v) in links} |u - v|
```

If this total does not exceed the budget `B`, the identity permutation is a
valid solution.  
If it already exceeds `B`, any other permutation can only increase some
distances (because the identity already makes each vertex as close as possible
to its own index), therefore no solution exists.

Hence the algorithm is:

1. read the input,
2. compute `total = Σ |u - v|` over all given links,
3. if `total ≤ B` output `YES` and the identity permutation,
   otherwise output `NO`.

The algorithm runs in `O(m)` time and `O(1)` extra memory.

**Correctness Proof**

We prove that the algorithm outputs a correct answer.

*Lemma 1*  
For any permutation `p`, for each link `(u,v)` we have `|p_u-p_v| ≥ |u-v|`.

*Proof.*  
Consider the two numbers `u` and `v`. In the identity permutation they occupy
positions `u` and `v`. Any other permutation reorders the numbers, but the
distance between the positions of two distinct elements cannot be smaller than
the distance between their original indices, because the set `{1,…,n}` is a
line with unit spacing. Formally, the mapping `i → p_i` is a bijection of the
ordered set, therefore the order of the two elements may be swapped or their
positions moved farther apart, never closer. ∎

*Lemma 2*  
Let `total_id = Σ |u - v|` be the total power for the identity permutation.
For any permutation `p`, the total power `total_p = Σ |p_u-p_v|` satisfies
`total_p ≥ total_id`.

*Proof.*  
By Lemma&nbsp;1 each summand of `total_p` is at least the corresponding
summand of `total_id`. Summing over all links preserves the inequality. ∎

*Theorem*  
The algorithm outputs “YES” with a valid assignment exactly when a feasible
assignment exists; otherwise it outputs “NO”.

*Proof.*  
- If the algorithm prints “YES”, it has `total_id ≤ B`. Using the identity
  permutation yields total power `total_id`, which by construction does not
  exceed `B`. Hence a feasible assignment exists.
- If the algorithm prints “NO”, then `total_id > B`. By Lemma&nbsp;2 any other
  permutation has total power at least `total_id`, thus also exceeds `B`.
  Consequently no feasible assignment exists.

Therefore the algorithm’s output is correct. ∎

**Complexity Analysis**

Reading the `m` links and computing the sum needs `O(m)` time.
All other operations are `O(n)` for printing the permutation.
Memory usage is `O(1)` besides the input storage.

**Reference Implementation (Python 3)**

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    B = int(next(it))
    total = 0
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        total += abs(u - v)
    if total <= B:
        out = ["YES", " ".join(str(i) for i in range(1, n + 1))]
        sys.stdout.write("\n".join(out))
    else:
        sys.stdout.write("NO")

if __name__ == "__main__":
    solve()
```

This program follows exactly the algorithm proven correct above.
