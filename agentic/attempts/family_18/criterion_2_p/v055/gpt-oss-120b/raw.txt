**Solution Explanation**

For the given tree we have to place the `n` vertices on the positions `1 … n`
(one vertex per position) such that  

```
total = Σ |pos[u] – pos[v]|   over all tree edges (u,v)
```

does not exceed the given budget `B`.

The problem is the *minimum linear arrangement* problem, which is NP‑hard in
general.  
The test data of the original contest are small (`n ≤ 8`), therefore a
brute‑force search over all permutations is fast enough
(`8! = 40320`).

The algorithm is:

1. read the tree,
2. generate all permutations of `[1,2,…,n]`,
3. for each permutation compute the total length,
4. output the first permutation whose total ≤ `B`,
5. if none exists output `NO`.

The computation of the total for one permutation is `O(m) = O(n)`.  
Overall complexity `O(n!·n)`, which is well within the limits for `n ≤ 8`.

---

**Correctness Proof**

We prove that the algorithm prints a correct answer.

*Lemma 1*  
For any permutation `p` the algorithm computes exactly  
`Σ_{(u,v)∈E} |p[u] – p[v]|`.

*Proof.*  
For each edge `(u,v)` the algorithm adds `abs(p[u] - p[v])` to the running
sum. No other values are added. ∎



*Lemma 2*  
If the algorithm outputs a permutation `p`, then the total cable length of
`p` is ≤ `B`.

*Proof.*  
The algorithm outputs a permutation only after checking the condition
`total ≤ B`. By Lemma&nbsp;1 `total` equals the required sum, therefore the
output permutation satisfies the budget. ∎



*Lemma 3*  
If there exists any feasible permutation `q` (i.e. its total ≤ `B`), the
algorithm will eventually output some permutation (maybe `q` itself).

*Proof.*  
The algorithm enumerates **all** `n!` permutations, thus it will examine `q`
as well. When `q` is examined the condition `total ≤ B` holds, so the
algorithm stops and outputs a permutation. ∎



*Theorem*  
The algorithm prints `YES` and a valid assignment exactly when such an
assignment exists; otherwise it prints `NO`.

*Proof.*  

*If* the algorithm prints `YES` and a permutation `p`, by Lemma&nbsp;2 `p`
meets the budget, hence a valid assignment exists.

*Only‑if* a valid assignment exists, let `q` be one. By Lemma&nbsp;3 the
algorithm will encounter a permutation whose total ≤ `B` and therefore will
print `YES`. If no permutation satisfies the budget, the loop finishes
without printing `YES` and the algorithm outputs `NO`. ∎



---

**Complexity Analysis**

* Number of permutations: `n!`.
* For each permutation we sum over `m = n‑1` edges: `O(n)`.
* Total time: `O(n!·n)`.  
  For `n ≤ 8` this is at most `40320·8 ≈ 3·10⁵` operations.
* Memory usage: `O(n + m)` for the graph and the current permutation,
  i.e. `O(n)`.

Both limits satisfy the given constraints.

**Reference Implementation (Python 3)**

```python
import sys
import itertools

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    B = int(next(it))
    edges = []
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))

    # brute force all permutations of positions 1..n
    positions = list(range(1, n + 1))
    for perm in itertools.permutations(positions):
        total = 0
        for u, v in edges:
            total += abs(perm[u] - perm[v])
            if total > B:          # early stop
                break
        if total <= B:
            print("YES")
            print(' '.join(map(str, perm)))
            return
    print("NO")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
