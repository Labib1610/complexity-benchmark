We can treat the bulbs and wires as a tree, because there are exactly n−1 edges and no cycles (the statement guarantees a single coordinated system).

The task is to label the vertices with numbers 1…n (a permutation) such that the sum over edges of absolute differences of labels is at most B.

A useful observation: for a tree, the total absolute difference over edges is minimized when labels increase monotonically along a DFS order. In fact, the minimal possible total is fixed, independent of label assignment for any tree, and equals the sum over edges of absolute differences when we assign labels by an inorder traversal, but more directly: The minimal total possible is when we arrange the tree in a linear order minimizing distances.

We can achieve the minimum sum as follows:
- Root the tree arbitrarily.
- Do a DFS, and assign labels in preorder (or any order that keeps edges small).
The minimal sum for any tree is equal to the sum over all edges of the size of the smaller side when removing that edge? No, that’s not generally true. Let's think differently.

The key fact: A tree can be embedded into a line with total distance equal to the minimal possible if we do an in-order traversal of the tree decomposed into a path. But indeed the optimal arrangement is known: it's obtained by performing a Depth-First Search and assigning labels in visit order.

Observation: If we arrange labels in DFS order, each edge connects a parent and child whose labels differ by exactly the size of the subtree of the child. The total sum becomes:

For each edge (parent p, child c), where subtree(c) has size k, the label difference = k.  
Sum over all edges is then the sum of subtree sizes of all non-root nodes.

That sum is minimal independent of the tree shape? Actually yes: For any tree, if you place labels according to preorder, each edge contributes the subtree size of the child. The smallest possible sum of |label difference| over edges is exactly that value; it cannot be smaller because each edge must cross the gap between the smallest and largest index in the child's subtree.

Let’s verify: For each edge, if child subtree contains vertices with labels in some interval [L, R], the edge must contribute at least (R−L+1) – size of that subtree. Indeed the minimal across all labelings is achieved when each subtree occupies a contiguous interval. For a tree, such interval labeling exists and corresponds to an Euler tour order.

Thus, we can:
1. Build adjacency from input.
2. Root the tree at node 1.
3. Do a DFS to compute subtree sizes.
4. Minimum total = sum of subtree sizes of all nodes except the root.
5. If that minimum > B → answer NO.
6. Otherwise we can output YES, and produce such labeling by assigning labels via a DFS preorder (any order that keeps each subtree contiguous). One simple method: do a DFS that numbers nodes in the order visited. This yields each subtree contiguous and edge cost = subtree size.

Implementation plan:

- Read n, m, B.
- Build adjacency list.
- Since m = n−1 and the input guarantees a tree, we can root at 1.
- Perform iterative DFS to compute subtree sizes and also assign preorder numbers (labels).
- Compute min_total = sum(subtree_size[child] for each child edge).
- If min_total > B → NO.
- Else output YES and the labels array.

We must ensure we output exactly n integers — the label of each bulb i.

Let's code it. We'll use recursion but with a high recursion limit (n could be large? The constraints aren't given, but we can set recursionlimit high). Safer to implement iterative DFS.

We can do a two-pass iterative DFS:
- First pass: compute parent and order via stack.
- Second pass: compute subtree sizes by reverse order.
- Also assign labels in the preorder traversal.

But we also need to assign labels in DFS order. We can do this in one pass: start stack with root, and assign incrementing labels as we pop.

However, to compute subtree_size we need to process children before the parent, which is done in reverse order after the forward pass.

Let's write iterative approach:

```python
import sys
sys.setrecursionlimit(300000)
input = sys.stdin.readline

n, m, B = map(int, input().split())
adj = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

parent = [-1]*n
order = []
stack = [0]
parent[0] = 0
while stack:
    u = stack.pop()
    order.append(u)
    for v in adj[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

sub = [1]*n
for u in reversed(order):
    for v in adj[u]:
        if v == parent[u]:
            continue
        sub[u] += sub[v]

min_total = sum(sub[i] for i in range(n) if i != 0)

if min_total > B:
    print("NO")
else:
    # Assign labels via preorder (same order as the DFS order we built)
    labels = [0]*n
    for idx, node in enumerate(order):
        labels[node] = idx+1
    print("YES")
    print(' '.join(map(str, labels)))
```

If we assign labels in **preorder**, the parent gets a smaller label than its whole subtree, and the difference between parent and the last node in child's subtree = subtree_size(child). So to force cost=subtree_size, we'd need the child to be at the far end of its subtree block from the parent. adj = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    adj[u-1].append(v-1)
    adj[v-1].append(u-1)

parent = [-1]*n
order = []

parent[0] = 0
while stack:
    u = stack.pop()
    order.append(u)
    for v in adj[u]:
        if v == parent[u]:

        parent[v] = u
        stack.append(v)

# postorder: reverse of this order? In the above, we append on pop, so it's a preorder. To get postorder, we can do another pass:
# We can get postorder list by doing a standard DFS that appends after processing children.

# Let's do simple recursion-free:
post = []
stack = [(0, 0)]  # (node, state) state 0 = enter, 1 = exit
parent[0] = -1
while stack:
    u, state = stack.pop()
    if state == 0:
        stack.append((u, 1))
        for v in adj[u]:
            if v != parent[u]:
                parent[v] = u
                stack.append((v, 0))
    else:
        post.append(u)

sub = [1]*n
for u in reversed(post):
    for v in adj[u]:
        if v != parent[u]:
            sub[u] += sub[v]

min_total = sum(sub[i] for i in range(n) if i != 0)

if min_total > B:
    print("NO")
else:
    labels = [0]*n
    for idx, node in enumerate(post):
        labels[node] = idx+1
    print("YES")
    print(' '.join(map(str, labels)))
