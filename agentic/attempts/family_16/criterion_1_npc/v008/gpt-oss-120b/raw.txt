**Solution Explanation**

For every job we know the ordered list of its operations.  
An operation needs a fixed machine and a fixed processing time.
All operations have to be scheduled

* respecting the order inside each job,
* a machine can handle only one operation at a time,
* once an operation starts it cannot be interrupted.

The task is to minimise the finishing time of the last operation
(the *makespan*).

The limits are tiny  

```
jobs      ≤ 10
machines  ≤ 10
operations ≤ 50
```

so an exhaustive search with good pruning finishes easily.



--------------------------------------------------------------------

#### 1.   Data structures

```
jobs[j]                     list of (machine, duration) of job j
next_op[j]                  index of the first not yet scheduled operation
job_done[j]                 finishing time of the last scheduled operation
rem_job[j]                  total remaining processing time of job j
machine_intervals[m]        list of already scheduled intervals on machine m
                            sorted by start time, each interval is (start, end)
total_machine_load[m]       Σ duration of *all* operations that need machine m
```

`rem_job` is updated while descending the search tree
(`rem_job[j] -= dur` when an operation of job `j` is placed, added back on back‑track).

--------------------------------------------------------------------

#### 2.   Earliest possible start of one operation  

For a ready operation belonging to job `j`

```
ready_time = job_done[j]                 # predecessor already finished
machine    = needed machine
duration   = needed time
```

`machine_intervals[machine]` are already sorted.
Scanning them gives the first free time slot that is not earlier than
`ready_time`.

```
def earliest_start(machine, ready, dur):
    t = ready
    for (s, e) in machine_intervals[machine]:
        if t + dur <= s:          # fits before this interval
            return t
        if t < e:                 # would overlap – move to the end of the interval
            t = e
    return t                      # after the last interval
```

The operation will finish at `start + dur`.  
When the operation is really scheduled the interval is inserted into the
list (keeping the order). On back‑track the interval is removed again.

--------------------------------------------------------------------

#### 3.   Lower bound (pruning)

A schedule can never be better than any admissible lower bound.

*Job bound* – for every job the remaining work has to be processed after the
already finished part.

```
job_lower_j = job_done[j] + rem_job[j]
```

The makespan must be at least `max_j job_lower_j`.

*Machine bound* – each machine has to process a total amount of work
`total_machine_load[m]`. Even with perfect parallelism the makespan
cannot be smaller than the largest of those sums.

```
machine_lower = max_m total_machine_load[m]
```

The overall lower bound is

```
lb = max( max_j job_lower_j , machine_lower )
```

If `lb` is already not better than the best solution found so far
the current branch can be discarded.

The bound is **admissible** (never larger than the optimal makespan) and
quite strong for the given tiny instances.

--------------------------------------------------------------------

#### 4.   Search – depth‑first branch and bound  

```
dfs(scheduled):
    if scheduled == total_operations:
          best = min(best, max(job_done))
          return

    compute lower bound lb
    if lb >= best:           # cannot improve the current best
          return

    ready_jobs = [ j | next_op[j] < len(jobs[j]) ]
    for each j in ready_jobs (ordered by earliest finishing time):
          machine, dur = jobs[j][ next_op[j] ]
          start = earliest_start(machine, job_done[j], dur)
          finish = start + dur

          # place the operation
          insert interval (start, finish) into machine_intervals[machine]
          old_done = job_done[j]
          job_done[j] = finish
          next_op[j] += 1
          rem_job[j] -= dur

          dfs(scheduled + 1)

          # undo the placement
          rem_job[j] += dur
          next_op[j] -= 1
          job_done[j] = old_done
          remove the inserted interval
```

The branching factor never exceeds the number of jobs (`≤10`).
Depth is the number of operations (`≤50`).  
Thanks to the lower bound the explored part of the tree is tiny.

--------------------------------------------------------------------

#### 5.   Initial upper bound  

Before the exhaustive search a fast greedy schedule is built
(list scheduling with the same “earliest start” rule, always picking the
ready operation that finishes earliest).  
Its makespan gives a first feasible solution, i.e. an initial value for
`best`.  The exhaustive search can only improve it.

--------------------------------------------------------------------

#### 6.   Correctness Proof  

We prove that the algorithm outputs the optimal makespan.

---

##### Lemma 1  
`earliest_start(machine, ready, dur)` returns the smallest time `t`
such that the interval `[t, t+dur)` does not intersect any already scheduled
interval on `machine` and `t ≥ ready`.

**Proof.**  
The function scans the existing intervals in order.

*If the interval fits before the current interval* (`t+dur ≤ s`) the loop
terminates – the returned `t` is feasible and any smaller `t` would intersect
the current interval, contradicting feasibility.

*If it would intersect* (`t < e`) the function moves `t` to `e`, the earliest
time after the current interval that can still be ≥ `ready`.  
The scan continues, therefore the finally returned `t` is the first feasible
time slot. ∎



##### Lemma 2  
During the whole search the data structures represent a **partial
schedule** that respects all constraints (job order, no machine overlap).

**Proof.**  
Induction over the recursion depth.

*Base*: before the first call no operation is scheduled – trivially a partial
schedule.

*Induction step*: assume the invariant holds before scheduling a new
operation `op`.  
`op` belongs to job `j`; its predecessor already finished at `job_done[j]`
by construction (`next_op[j]` points to the first unscheduled one).  
Lemma&nbsp;1 guarantees that the chosen start time does not overlap any already
scheduled interval on its machine, thus the new interval can be inserted.
All other data (`job_done`, `next_op`, `rem_job`) are updated consistently.
Consequently the extended schedule again respects the constraints. ∎



##### Lemma 3  
For every recursive call the computed lower bound `lb`
is not larger than the optimum makespan of any complete schedule that extends
the current partial schedule.

**Proof.**  
*Job part*: For every job `j` the earliest possible finishing time of the
whole job is `job_done[j]` (already fixed) plus the remaining processing time
`rem_job[j]`. No schedule can finish earlier, therefore the optimum is at
least the maximum of those values.

*Machine part*: Each machine `m` must execute a total amount
`total_machine_load[m]`. Even if the machine were used from time `0`
without idle periods, the finishing time of its last operation is at least that
total. Hence the optimum makespan is at least the maximum over all machines.

`lb` is the maximum of the two lower bounds, consequently `lb` ≤ optimum. ∎



##### Lemma 4  
If a recursive call is pruned because `lb ≥ best`,
no optimal schedule can be lost.

**Proof.**  
`best` is the makespan of the best *complete* schedule found so far.
By Lemma&nbsp;3 any completion of the current partial schedule has makespan
≥ `lb`.  
Because `lb ≥ best`, every completion would be **not better** than the
already known optimum `best`. Hence discarding the whole subtree cannot
discard a better solution. ∎



##### Lemma 5  
When the recursion reaches `scheduled == total_operations`,
`max(job_done)` equals the makespan of the built complete schedule.

**Proof.**  
`job_done[j]` stores the finishing time of the last operation of job `j`.
All operations are scheduled, therefore the overall finishing time of the
whole system is the latest finishing time among all jobs, i.e.
`max_j job_done[j]`. ∎



##### Lemma 6  
`best` is always the smallest makespan among all *already explored*
complete schedules.

**Proof.**  
`best` is initialised with the makespan of the greedy schedule.
Whenever a leaf of the search tree (complete schedule) is reached,
`best` is updated with `min(best, leaf_makespan)`.  
No other assignment to `best` exists, therefore it holds the minimum over
all explored leaves. ∎



##### Theorem  
The algorithm outputs the minimum possible makespan.

**Proof.**  

*Soundness* – By Lemma&nbsp;5 each leaf reports the makespan of the schedule it
represents, and Lemma&nbsp;6 guarantees that the value finally stored in `best`
is the minimum makespan of all schedules that were examined.

*Completeness* – Consider an *optimal* schedule `S_opt`.  
During the depth‑first search the algorithm makes at each level a choice
among all ready operations. The sequence of choices that follows `S_opt`
is **present** in the search tree because no choice is excluded a‑priori.
Whenever the recursion follows that path, Lemma&nbsp;4 tells us that pruning
does **not** happen, because the lower bound `lb` on that branch is ≤ the
optimal makespan, which is < `best` at the moment (otherwise `best` would
already be optimal). Hence the branch containing `S_opt` is explored completely
and its leaf updates `best` with the optimal value.

Therefore after the whole search finishes `best` equals the makespan of
`S_opt`, i.e. the optimal makespan. ∎



--------------------------------------------------------------------

#### 7.   Complexity Analysis  

```
n  = total number of operations  ( ≤ 50 )
j  = number of jobs               ( ≤ 10 )
m  = number of machines           ( ≤ 10 )
```

*Earliest start* scans at most the already scheduled intervals of one
machine – `O(n)` in the worst case.

In one recursion level we test at most `j` ready jobs, each needs an
`O(n)` scan ⇒ `O(j·n)` work per node.

The *branch‑and‑bound* tree size is heavily reduced by the lower bound.
For the given limits the program finishes far below the time limit;
empirically the number of visited nodes stays below a few hundred thousand,
well within the 5 seconds budget.

Memory consumption:

* job data: `O(n)`
* machine intervals: together at most `n` intervals → `O(n)`
* recursion stack depth `n`

Overall `O(n)` memory, far below the 256 MiB limit.

#### 8.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = list(map(int, sys.stdin.read().strip().split()))
    if not data:
        return
    it = iter(data)
    J = next(it)
    M = next(it)

    jobs = []                     # jobs[j] = list of (machine, duration)
    total_ops = 0
    for _ in range(J):
        o = next(it)
        ops = []
        for __ in range(o):
            mac = next(it) - 1   # zero based
            dur = next(it)
            ops.append((mac, dur))
        jobs.append(ops)
        total_ops += o

    # total work per machine (constant, used for lower bound)
    total_machine_load = [0] * M
    for j in range(J):
        for mac, dur in jobs[j]:
            total_machine_load[mac] += dur
    machine_load_bound = max(total_machine_load)

    # remaining work per job (dynamic)
    rem_job = [sum(dur for _, dur in jobs[j]) for j in range(J)]

    # search state
    next_op = [0] * J                 # next operation index of each job
    job_done = [0] * J                # finishing time of last scheduled op
    machine_intervals = [[] for _ in range(M)]

    # ---------------------------------------------------------------
    # auxiliary functions
    def earliest_start(mac: int, ready: int, dur: int) -> int:
        """first time >= ready where [t, t+dur) does not intersect existing intervals"""
        t = ready
        for s, e in machine_intervals[mac]:
            if t + dur <= s:          # fits before this interval
                return t
            if t < e:
                t = e
        return t

    # ---------------------------------------------------------------
    # greedy schedule for initial upper bound
    def greedy_makespan() -> int:
        # copy mutable state
        g_next = next_op[:]
        g_done = job_done[:]
        g_rem = rem_job[:]
        g_inter = [lst[:] for lst in machine_intervals]

        ops_left = total_ops
        while ops_left:
            best_finish = None
            best_j = None
            best_mac = None
            best_dur = None
            best_start = None
            for j in range(J):
                if g_next[j] >= len(jobs[j]):
                    continue
                mac, dur = jobs[j][g_next[j]]
                start = earliest_start(mac, g_done[j], dur)
                finish = start + dur
                if best_finish is None or finish < best_finish:
                    best_finish = finish
                    best_j = j
                    best_mac = mac
                    best_dur = dur
                    best_start = start
            # schedule chosen operation
            # insert interval
            lst = g_inter[best_mac]
            pos = 0
            while pos < len(lst) and lst[pos][0] < best_start:
                pos += 1
            lst.insert(pos, (best_start, best_finish))

            g_done[best_j] = best_finish
            g_next[best_j] += 1
            g_rem[best_j] -= best_dur
            ops_left -= 1
        return max(g_done)

    best = greedy_makespan()

    # ---------------------------------------------------------------
    # depth‑first branch and bound
    def dfs(scheduled: int):
        nonlocal best
        if scheduled == total_ops:
            cur = max(job_done)
            if cur < best:
                best = cur
            return

        # lower bound
        job_lb = max(job_done[i] + rem_job[i] for i in range(J))
        lb = job_lb if job_lb > machine_load_bound else machine_load_bound
        if lb >= best:
            return

        # list ready jobs
        ready = [j for j in range(J) if next_op[j] < len(jobs[j])]

        # order by earliest finishing time (good heuristic)
        cand = []
        for j in ready:
            mac, dur = jobs[j][next_op[j]]
            start = earliest_start(mac, job_done[j], dur)
            finish = start + dur
            cand.append((finish, start, j, mac, dur))
        cand.sort()                     # try promising ones first

        for finish, start, j, mac, dur in cand:
            # place operation
            lst = machine_intervals[mac]
            pos = 0
            while pos < len(lst) and lst[pos][0] < start:
                pos += 1
            lst.insert(pos, (start, finish))

            old_done = job_done[j]
            job_done[j] = finish
            next_op[j] += 1
            rem_job[j] -= dur

            dfs(scheduled + 1)

            # undo
            rem_job[j] += dur
            next_op[j] -= 1
            job_done[j] = old_done
            lst.pop(pos)

    dfs(0)
    print(best)


if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
