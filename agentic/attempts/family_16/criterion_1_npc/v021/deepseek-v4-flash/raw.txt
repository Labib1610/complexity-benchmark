We can model this as a scheduling problem with precedence constraints and resource constraints.  
Since the number of potions and foci is small, we can use a search over possible orderings of phases, or a dynamic programming over states.

Here’s a possible approach:

- Each potion has a sequence of phases, each with a focus and duration.
- We need to schedule all phases respecting:
  - Order within each potion.
  - No two phases using the same focus at the same time.
  - No preemption.

We can use a priority-queue simulation with backtracking, or a DP over the set of completed phases per potion.

Because total phases ≤ 50, and j ≤ 10, we can do a DP over the vector of next phase indices for each potion.  
State: tuple of current phase index for each potion (0 = not started, o_i = done).  
Transitions: pick a potion whose next phase can start at the earliest possible time given current focus availability.

We can compute earliest start time for each possible next phase given the current schedule.  
We keep track of the finish time of the last phase on each focus.

We can use Dijkstra-like search over states, minimizing the maximum finish time.

                        rem += phases[p][k][1]

            return
        
        # Generate candidates
        candidates = []
        for p in range(j):
            if next_idx[p] < total_phases[p]:
                f, d = phases[p][next_idx[p]]
                start = max(focus_free[f], potion_free[p])
                candidates.append((start, p, f, d))
