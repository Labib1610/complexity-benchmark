We can model this as a job-shop scheduling problem with a small number of jobs (≤10) and machines (≤10), and total steps ≤50.  
Since the numbers are small, we can use a **simulation with priority queue** or **brute-force over all job orders** if we treat each job as a sequence of operations.

A simple approach:  
- Each job has a fixed sequence of (machine, time).  
- We can simulate time and assign jobs to machines as soon as both the job and the machine are free.  
- Since jobs are independent and we want to minimize makespan, we can try all permutations of job start order (10! = 3.6M, which is feasible with pruning).  
- For each permutation, simulate the schedule and take the minimum makespan.

Here’s the implementation:

```python
from itertools import permutations
import sys

def simulate(order, jobs):
    # jobs: list of list of (machine, duration)
    m = max(max(machine for machine, _ in job) for job in jobs) + 1
    machine_free = [0] * m
    job_finish = [0] * len(jobs)
    job_index = [0] * len(jobs)
    
    for job_id in order:
        for machine, dur in jobs[job_id]:
            start = max(machine_free[machine], job_finish[job_id])
            finish = start + dur
            machine_free[machine] = finish
            job_finish[job_id] = finish
    return max(job_finish)

def main():
    data = sys.stdin.read().strip().split()
    idx = 0
    j = int(data[idx]); idx += 1
    m = int(data[idx]); idx += 1
    jobs = []
    for _ in range(j):
        o = int(data[idx]); idx += 1
        job = []
        for _ in range(o):
            machine = int(data[idx]) - 1; idx += 1
            dur = int(data[idx]); idx += 1
            job.append((machine, dur))
        jobs.append(job)
    
    best = float('inf')
    for perm in permutations(range(j)):
        best = min(best, simulate(perm, jobs))
    print(best)

if __name__ == "__main__":
    main()
```
