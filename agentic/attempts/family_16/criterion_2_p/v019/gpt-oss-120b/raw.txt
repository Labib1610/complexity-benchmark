**Solution Explanation**

For every manuscript we know  

* `p1` – time the calligrapher needs to transcribe it  
* `p2` – time the bookbinder needs to bind it  

Both workers handle the manuscripts one after another **in the same order**.
The goal is to choose this order so that the moment the bookbinder finishes the
last manuscript is as early as possible (minimum makespan).

The problem is the classic **two‑machine flow shop** with permutation schedule.
For two machines the optimal order is given by **Johnson’s rule**.

--------------------------------------------------------------------

#### Johnson’s rule  

* Split the manuscripts into two groups  

```
A = {i | p1_i ≤ p2_i }          (calligrapher is not slower)
B = {i | p1_i >  p2_i }          (calligrapher is slower)
```

* Sort `A` by increasing `p1`  
* Sort `B` by decreasing `p2`  

The optimal sequence is all manuscripts of `A` (in that order) followed by all
manuscripts of `B` (in that order).

*Proof sketch* (standard, omitted for brevity) – swapping two adjacent
manuscripts that violate the rule never increases the makespan, therefore a
schedule respecting the rule is optimal.

--------------------------------------------------------------------

#### Computing the makespan of a given order  

```
time1 – moment when the calligrapher finishes the already processed manuscripts
time2 – moment when the bookbinder finishes the already processed manuscripts
initially both 0
for each manuscript (p1, p2) in the chosen order:
        time1 += p1                     # calligrapher works
        time2 = max(time2, time1) + p2  # bookbinder starts as soon as possible
```

After the loop `time2` is the required answer.

--------------------------------------------------------------------

#### Algorithm
```
read j
A = [], B = []
for each manuscript:
        read p1, p2
        if p1 <= p2:   A.append((p1,p2))
        else:          B.append((p1,p2))

sort A by p1   (ascending)
sort B by p2   (descending)

time1 = time2 = 0
process all manuscripts of A then B, updating time1, time2 as described

output time2
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the minimum possible completion time.

---

**Lemma 1**  
For any two consecutive manuscripts `i, j` in a schedule, if  

* `p1_i ≤ p2_i` and `p1_j ≤ p2_j` and `p1_i > p1_j`,  
  swapping them does not increase the makespan.

*Proof.* Both manuscripts belong to set `A`. In the schedule their
  order contributes `p1_i + p1_j` to `time1`.  
  The bookbinder can start `i` only after `time1` reaches `p1_i`,
  and `j` only after `time1` reaches `p1_i + p1_j`.  
  Because `p1_i > p1_j`, putting the smaller `p1` first can only reduce the
  idle time of the bookbinder, never increase it. ∎



**Lemma 2**  
For any two consecutive manuscripts `i, j` with `p1_i > p2_i`,
`p1_j > p2_j` and `p2_i < p2_j`, swapping them does not increase the makespan.

*Proof.* Both belong to set `B`. The same argument as Lemma&nbsp;1, now using
`p2` (the second machine times) and the decreasing order, gives the claim. ∎



**Lemma 3**  
If a schedule contains a manuscript `i` with `p1_i ≤ p2_i` placed *after*
a manuscript `j` with `p1_j > p2_j`, swapping `i` and `j` does not increase the
makespan.

*Proof.* Consider the four processing times of the two jobs.
Johnson’s original proof shows that the makespan after the swap is
`max( … )` with a value not larger than before because the earlier job
has the smaller of `{p1, p2}`. ∎



**Lemma 4** (Johnson optimality)  
A schedule that respects Johnson’s rule (all `A` sorted by increasing `p1`,
followed by all `B` sorted by decreasing `p2`) is optimal for the two‑machine
flow shop.

*Proof.* Starting from any schedule,
apply Lemma&nbsp;1 to reorder the `A` part, Lemma&nbsp;2 to reorder the `B`
part, and Lemma&nbsp;3 to move every `A` job before every `B` job.
Every step never increases the makespan, thus the final schedule obtained
by Johnson’s rule is at least as good as any other schedule. ∎



**Lemma 5**  
Given a fixed order, the algorithm’s simulation computes exactly the
completion time of the second machine.

*Proof.* By definition `time1` after processing a job equals the moment the
calligrapher finishes it. The bookbinder can start only after both it is idle
(`time2`) and the current job is ready (`time1`). Hence the start moment is
`max(time1, time2)` and the finish moment is that plus `p2`. The loop follows
this recurrence, therefore the final `time2` equals the true makespan. ∎



**Theorem**  
The algorithm outputs the minimum possible time at which the bookbinder
finishes the last manuscript.

*Proof.* By Lemma&nbsp;4 the order produced by the algorithm (Johnson’s order)
is optimal among all possible orders. By Lemma&nbsp;5 the algorithm computes the
makespan of exactly that order. Consequently the printed value is the minimal
possible makespan. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

* Partitioning and reading: `O(j)`  
* Sorting `A` and `B`: `O(j log j)` (total size `j`)  
* Simulation pass: `O(j)`  

Memory consumption: the two lists store at most `j` pairs → `O(j)`.

Both limits satisfy the given constraints (`j ≤ 200 000`).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    it = iter(data)
    n = int(next(it))

    A = []          # p1 <= p2
    B = []          # p1 >  p2
    for _ in range(n):
        p1 = int(next(it))
        p2 = int(next(it))
        if p1 <= p2:
            A.append((p1, p2))
        else:
            B.append((p1, p2))

    A.sort(key=lambda x: x[0])          # increasing p1
    B.sort(key=lambda x: -x[1])         # decreasing p2

    time1 = 0
    time2 = 0
    for p1, p2 in A:
        time1 += p1
        time2 = max(time2, time1) + p2
    for p1, p2 in B:
        time1 += p1
        time2 = max(time2, time1) + p2

    sys.stdout.write(str(time2))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required I/O format.
