**Solution Explanation**

For every junction exactly three cables meet – the graph is *cubic* (3‑regular).
We have to colour every edge by one of three colours (the three maintenance
windows) such that the three edges incident to each vertex receive three
different colours.

--------------------------------------------------------------------

#### 1.   When does a cubic graph have a 3‑edge‑colouring ?

A classical theorem of Petersen says  

*every bridgeless cubic graph contains a perfect matching*  
and after contracting the matching the remaining graph is a disjoint union of
cycles.  
Colour the matching edges by colour **1** and colour the edges of each cycle
alternately by colours **2** and **3** – this is a proper 3‑edge‑colouring.

If a cubic graph has a bridge it needs four colours, therefore it is
**impossible** to colour it with three colours.

Consequently a cubic graph is 3‑edge‑colourable **iff** it possesses a perfect
matching. (A perfect matching cannot exist when a bridge is present, but we do
not have to test bridges explicitly.)

So the whole problem reduces to

* find a perfect matching of size `n/2` in the given cubic graph,
* if it exists, construct the colouring described above,
* otherwise answer `NO`.

--------------------------------------------------------------------

#### 2.   Maximum matching – Edmonds’ blossom algorithm

`n ≤ 2000`, `m = 3n/2 ≤ 3000`.  
A general‑graph maximum matching algorithm works fast enough.
We use a compact Python implementation of Edmonds’ blossom algorithm
(`O(n³)` worst case, far below the limits for the given sizes).

The algorithm returns a list `mate[v]` (`-1` if unmatched) and the size of the
matching.

--------------------------------------------------------------------

#### 3.   Building the colouring from a perfect matching

* let `M` be the perfect matching,
* give every edge of `M` colour **1**,
* contract each matched pair `{u,v}` to a new vertex `c(u)=c(v)`.
  After contraction each original vertex loses the matched edge, therefore
  exactly two incident edges remain – they become edges between the new
  vertices.  
  Because the original graph is simple, the contracted graph is a
  **2‑regular multigraph**, i.e. a collection of cycles (parallel edges are
  possible, they form a 2‑cycle).

* traverse every cycle and colour its edges alternately **2**, **3**.
  The direction of alternation is irrelevant – any start works.

During the traversal we keep the original edge indices, therefore at the end we
output the colour of each input edge in order.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct schedule exactly when
such a schedule exists.

---

##### Lemma 1  
If the algorithm finds a perfect matching `M`, the contracted graph consists
only of vertex‑disjoint cycles.

**Proof.**  
After contracting each matched edge, every original vertex loses one incident
edge (the matched one) and keeps the other two. Hence each contracted vertex
has degree `2`. A finite graph where every vertex has degree `2` is a disjoint
union of cycles (possibly of length `2` when two parallel edges exist). ∎



##### Lemma 2  
Colouring the edges of `M` by colour 1 and the edges of each cycle of the
contracted graph alternately by colours 2 and 3 yields a proper 3‑edge‑colouring
of the original graph.

**Proof.**  
Consider any original vertex `v`. Exactly one incident edge belongs to `M`,
hence receives colour 1. The two remaining incident edges become the two
edges of the contracted vertex that `v` belongs to; they are consecutive edges
on a cycle and therefore receive different colours, namely 2 and 3.
Thus the three incident edges of `v` obtain three distinct colours.
Since this holds for every vertex, the whole edge‑colouring is proper. ∎



##### Lemma 3  
If the input graph admits a 3‑edge‑colouring, it contains a perfect matching.

**Proof.**  
Take any colour, say colour 1, in a proper 3‑edge‑colouring.
All edges of this colour are pairwise non‑adjacent (otherwise two edges of the
same colour would meet at a vertex).  
Every vertex is incident to exactly one edge of colour 1, because the three
incident edges must have three different colours.  
Hence the set of colour 1 edges is a perfect matching. ∎



##### Lemma 4  
If the algorithm outputs `NO`, the graph has no 3‑edge‑colouring.

**Proof.**  
The algorithm outputs `NO` only when the blossom algorithm fails to find a
matching of size `n/2`. By Lemma&nbsp;3 any 3‑edge‑colouring would provide a
perfect matching, contradicting maximality of the computed matching. ∎



##### Lemma 5  
If the algorithm outputs `YES` and a colour sequence, the sequence is a valid
schedule.

**Proof.**  
`YES` is printed only when a perfect matching was found.
The subsequent construction follows Lemma&nbsp;2, therefore the produced
colouring is proper, i.e. at each vertex the three incident edges have distinct
colours (windows). ∎



##### Theorem  
The algorithm prints `YES` followed by a correct assignment of windows
iff such an assignment exists; otherwise it prints `NO`.

**Proof.**  

*If the algorithm prints `YES`*: by Lemma&nbsp;5 the assignment is correct,
hence a feasible schedule exists.

*If a feasible schedule exists*: by Lemma&nbsp;3 the graph contains a perfect
matching, therefore the blossom algorithm will find one (maximum matching is
perfect). Consequently the algorithm proceeds to the colouring step and prints
`YES`.  

If the algorithm prints `NO`, by Lemma&nbsp;4 no feasible schedule exists.

Thus the output of the algorithm is correct in all cases. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Blossom matching*: `O(n³)` worst case, with `n ≤ 2000` → at most a few
seconds in Python.  
*Contraction & cycle traversal*: each edge is processed a constant number of
times → `O(m)`.

Overall time `O(n³)` ≤ `8·10⁹` elementary operations, well inside the 5 s limit
for the given size.  
Memory consumption: adjacency lists, matching arrays, colour array – all
`O(n + m)` ≤ `~5000` integers, far below 256 MB.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

# ---------- Edmonds' blossom algorithm (general graph maximum matching) ----------
def max_matching(n, adj):
    """return mate list, size of maximum matching"""
    INF = n + 5
    mate = [-1] * n
    label = [0] * n
    parent = [-1] * n
    orig = list(range(n))
    aux = [-1] * n

    def lca(v, w):
        aux_id = lca.aux_id
        aux_id += 1
        lca.aux_id = aux_id
        while True:
            if v != -1:
                if aux[v] == aux_id:
                    return v
                aux[v] = aux_id
                if mate[v] == -1:
                    v = -1
                else:
                    v = orig[parent[mate[v]]]
            v, w = w, v
    lca.aux_id = 0

    def blossom(v, w, a):
        while orig[v] != a:
            parent[v] = w
            w = mate[v]
            if label[w] == 1:
                label[w] = 0
                q.append(w)
            orig[v] = orig[w] = a
            v = parent[w]

    def augment(v):
        while v != -1:
            pv = parent[v]
            nv = mate[pv] if pv != -1 else -1
            mate[v] = pv
            mate[pv] = v
            v = nv

    for root in range(n):
        if mate[root] != -1:
            continue
        # BFS
        label = [-1] * n
        parent = [-1] * n
        orig = list(range(n))
        q = []
        label[root] = 0
        q.append(root)
        found = -1
        for qi in range(len(q)):
            v = q[qi]
            for u in adj[v]:
                if label[u] == -1:
                    label[u] = 1
                    parent[u] = v
                    if mate[u] == -1:
                        found = u
                        break
                    label[mate[u]] = 0
                    q.append(mate[u])
                elif label[u] == 0 and orig[v] != orig[u]:
                    a = lca(orig[v], orig[u])
                    blossom(v, u, a)
                    blossom(u, v, a)
            if found != -1:
                break
        if found != -1:
            augment(found)
    size = sum(1 for x in mate if x != -1) // 2
    return mate, size

# ------------------------------- Main solution ---------------------------------
def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))
        adj[u].append(v)
        adj[v].append(u)

    mate, sz = max_matching(n, adj)
    if sz * 2 != n:          # not a perfect matching
        print("NO")
        return

    # colour array, 0..2 -> output 1..3
    colour = [0] * m
    # map each vertex to its partner in the matching
    partner = mate

    # give colour 1 to matching edges
    for v in range(n):
        u = partner[v]
        if u != -1 and v < u:
            # find edge index
            for idx, (a, b) in enumerate(edges):
                if (a == v and b == u) or (a == u and b == v):
                    colour[idx] = 1
                    break

    # build contracted graph: each matched pair becomes a super vertex
    super_id = [-1] * n
    cur = 0
    for v in range(n):
        if super_id[v] == -1:
            u = partner[v]
            super_id[v] = super_id[u] = cur
            cur += 1
    super_adj = [[] for _ in range(cur)]
    # for each original edge not in matching, add to super graph
    for idx, (u, v) in enumerate(edges):
        if colour[idx] != 0:
            continue
        su = super_id[u]
        sv = super_id[v]
        super_adj[su].append((sv, idx))
        super_adj[sv].append((su, idx))

    visited = [False] * cur
    for start in range(cur):
        if visited[start]:
            continue
        # walk the cycle
        v = start
        prev_edge = -1
        cur_col = 2  # start with colour 2
        while True:
            visited[v] = True
            # find next edge not equal to prev_edge
            for (to, eidx) in super_adj[v]:
                if eidx != prev_edge:
                    break
            else:
                break  # should not happen
            colour[eidx] = cur_col
            # move
            prev_edge = eidx
            v = to
            cur_col = 5 - cur_col   # toggle between 2 and 3
            if visited[v]:
                # cycle closed
                break

    # output
    print("YES")
    print(' '.join(str(c) for c in colour))

if __name__ == "__main__":
    solve()
```
