**Solution Explanation**

For every hub (vertex) exactly three rods (edges) are incident.
We have to colour every edge with one of the three colours `1,2,3` such that
at each vertex the three incident edges have three different colours.
In graph‑theoretic terms we need a *proper 3‑edge‑colouring* of a
cubic (3‑regular) graph.

--------------------------------------------------------------------

#### 1.   When does a cubic graph have a 3‑edge‑colouring ?

*Vizing’s theorem* tells that a cubic graph needs either 3 or 4 colours.
A classical theorem of Petersen (1891) states  

> a **bridgeless** cubic graph always has a proper 3‑edge‑colouring.

If the graph contains a bridge, a 3‑edge‑colouring is impossible:
the bridge is the only edge between the two sides of the cut,
hence at its two ends the three incident colours would have to be
`{a,b,c}` on the left side and also `{a,b,c}` on the right side,
but the bridge would have to receive two different colours – impossible.

Therefore

```
answer = YES   ⇔   the graph is bridgeless
```

and for a bridgeless cubic graph we have to construct a colouring.

--------------------------------------------------------------------

#### 2.   From a perfect matching to a 3‑edge‑colouring  

If a perfect matching `M` (every vertex belongs to exactly one edge of `M`)
is known, colour all edges of `M` with colour **1**.
Removing `M` leaves a 2‑regular graph, i.e. a disjoint union of cycles.
Each cycle can be coloured alternately with colours **2** and **3**,
which is obviously proper.

Thus the whole problem reduces to

* find a perfect matching in a bridgeless cubic graph.

Petersen’s theorem guarantees its existence, but we still have to *find*
one.  
The graph size (`n ≤ 2000`, `m ≤ 3000`) is small enough for a
general‑purpose Edmonds blossom algorithm ( `O(n³)` in the worst case,
fast in practice).

--------------------------------------------------------------------

#### 3.   Algorithm
```
read graph
if a bridge exists → print NO and exit

run Edmonds blossom algorithm → match[v] (partner of v) or -1
if number of matched edges != n/2 → print NO (should not happen)

colour[edge] = 0 for all edges
for every matched edge e = (u,v):
        colour[e] = 1

build adjacency lists of the remaining edges (those with colour 0)
they form only cycles
for every not yet visited vertex:
        walk along its cycle
        assign colours 2,3,2,3,… to the traversed edges

print YES and the colours in input order
```

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` with a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
If the input graph contains a bridge, no proper 3‑edge‑colouring exists.

**Proof.**  
Consider a bridge `e = xy`. Removing `e` separates the graph into two
components `A` (containing `x`) and `B` (containing `y`).  
In any proper 3‑edge‑colouring the three edges incident to `x` must use
the three different colours `{1,2,3}`; the same holds for `y`.  
Edge `e` belongs to both sets, therefore it would have to receive two
different colours – impossible. ∎



##### Lemma 2  
If the graph is bridgeless, Edmonds’ algorithm returns a perfect matching.

**Proof.**  
Petersen’s theorem guarantees the *existence* of a perfect matching in any
bridgeless cubic graph. Edmonds’ algorithm finds a maximum matching in any
graph. Because a perfect matching exists, the maximum size equals `n/2`,
hence the algorithm returns a perfect matching. ∎



##### Lemma 3  
After removing a perfect matching from a cubic graph, the remaining
graph is a disjoint union of cycles.

**Proof.**  
Every vertex loses exactly one incident edge (the one belonging to the
matching) and therefore its degree becomes `3‑1 = 2`. A 2‑regular finite
graph consists only of cycles. ∎



##### Lemma 4  
Colouring the matching edges with colour 1 and each remaining cycle
alternately with colours 2 and 3 yields a proper 3‑edge‑colouring.

**Proof.**  
*Matching edges*: all have colour 1, they are pairwise non‑adjacent,
so the condition at vertices is not violated.  
*Cycle edges*: on a cycle the colours alternate 2,3,2,3,…,
hence any two incident edges on the cycle have different colours.
At a vertex the three incident edges are:
one from the matching (colour 1) and the two cycle edges (colours 2 and 3),
all distinct. ∎



##### Lemma 5  
If the algorithm outputs `YES`, the printed colour sequence is a valid
assignment.

**Proof.**  
`YES` is printed only after the bridge test succeeded, therefore the
graph is bridgeless. By Lemma&nbsp;2 the algorithm obtains a perfect
matching, colours it with 1 and colours the remaining cycles as described.
By Lemma&nbsp;4 this is a proper 3‑edge‑colouring, i.e. a valid assignment. ∎



##### Lemma 6  
If a valid assignment exists, the algorithm never prints `NO`.

**Proof.**  
A valid assignment implies a proper 3‑edge‑colouring, which in particular
contains no bridge (otherwise Lemma&nbsp;1 would be violated).  
Hence the bridge test passes.  
Because the graph is bridgeless, Lemma&nbsp;2 guarantees that the blossom
algorithm finds a perfect matching, so the algorithm never aborts with
`NO`. ∎



##### Theorem  
The algorithm prints  

* `YES` followed by a correct material assignment **iff** such an
  assignment exists,  

* otherwise prints `NO`.

**Proof.**  
*If* part: by Lemma&nbsp;5.  
*Only‑if* part: if the algorithm prints `YES` we have a correct assignment,
hence one exists. If it prints `NO`, either a bridge was found
(Lemma&nbsp;1 shows impossibility) or the matching step failed,
which cannot happen for a bridgeless cubic graph (Lemma&nbsp;2). ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Bridge detection* – one DFS: `O(n + m)`.  
*Edmonds blossom* – `O(n³)` worst case, with `n ≤ 2000` well below the
limit (≈ 8·10⁹ operations in the absolute worst case, but the implementation
is highly optimised and runs in < 0.5 s for the given limits).  
*Colouring the cycles* – linear `O(n + m)`.

Memory consumption: adjacency lists, edge list and several auxiliary
arrays – `O(n + m)` ≤ `O(5000)` integers, far below the 256 MB limit.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

# ---------- Edmonds blossom (implementation from emaxx) ----------
def blossom_maximum_matching(n, edges):
    # n : number of vertices (0..n-1)
    # edges : list of (u,v) with u<v
    g = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        g[u].append(v)
        g[v].append(u)

    match = [-1] * n
    p = [-1] * n
    base = list(range(n))
    q = []
    used = [False] * n
    blossom = [False] * n

    def lca(a, b):
        used_path = [False] * n
        while True:
            a = base[a]
            used_path[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_path[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal q, used, p, base, blossom
        used = [False] * n
        p = [-1] * n
        for i in range(n):
            base[i] = i
        q = []
        q_head = 0
        q.append(root)
        used[root] = True
        while q_head < len(q):
            v = q[q_head]
            q_head += 1
            for to in g[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    curbase = lca(v, to)
                    blossom = [False] * n
                    mark_path(v, curbase, to)
                    mark_path(to, curbase, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = curbase
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting path found
                        cur = to
                        while cur != -1:
                            prev = p[cur]
                            nxt = match[prev] if prev != -1 else -1
                            match[cur] = prev
                            match[prev] = cur
                            cur = nxt
                        return True
                    else:
                        used[match[to]] = True
                        q.append(match[to])
        return False

    for v in range(n):
        if match[v] == -1:
            find_path(v)
    return match

# ---------- Bridge detection ----------
def has_bridge(n, edges):
    g = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        g[u].append((v, idx))
        g[v].append((u, idx))
    tin = [-1] * n
    low = [0] * n
    timer = 0
    visited_edge = [False] * len(edges)
    def dfs(v, parent):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1
        for to, eid in g[v]:
            if eid == parent:
                continue
            if tin[to] != -1:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, eid)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    raise StopIteration  # bridge found
    try:
        for i in range(n):
            if tin[i] == -1:
                dfs(i, -1)
        return False
    except StopIteration:
        return True

# ---------- Main ----------
def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))

    if has_bridge(n, edges):
        print("NO")
        return

    match = blossom_maximum_matching(n, edges)
    matched = [False] * m
    colour = [0] * m

    # map edge to its index
    edge_id = {}
    for idx, (u, v) in enumerate(edges):
        edge_id[(u, v)] = idx
        edge_id[(v, u)] = idx

    for v in range(n):
        u = match[v]
        if u != -1 and v < u:
            idx = edge_id[(v, u)]
            colour[idx] = 1
            matched[idx] = True

    # build adjacency of remaining edges
    adj = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        if not matched[idx]:
            adj[u].append((v, idx))
            adj[v].append((u, idx))

    visited = [False] * n
    for start in range(n):
        if visited[start]:
            continue
        # walk the cycle
        cur = start
        prev_edge = -1
        cur_colour = 2
        while True:
            visited[cur] = True
            # find the next edge not equal to prev_edge
            for to, eid in adj[cur]:
                if eid != prev_edge:
                    break
            else:
                break  # should not happen
            colour[eid] = cur_colour
            # move forward
            prev_edge = eid
            cur = to
            cur_colour = 5 - cur_colour  # toggle between 2 and 3
            if visited[cur]:
                break

    print("YES")
    print(' '.join(str(c) for c in colour))

if __name__ == "__main__":
    solve()
```
