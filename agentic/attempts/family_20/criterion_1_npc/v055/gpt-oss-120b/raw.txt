**Solution Explanation**

For every chamber exactly three conduits are incident, i.e. the given graph is *cubic*
(3‑regular).  
We have to colour every edge with one of the three fluids `1,2,3` such that at each
vertex the three incident edges receive three different colours – this is exactly a
*proper 3‑edge‑colouring* of a cubic graph.

--------------------------------------------------------------------

#### 1.   When does a cubic graph have a 3‑edge‑colouring ?

A classical theorem of Petersen:

*Every bridgeless cubic graph admits a proper 3‑edge‑colouring, and a cubic graph
containing a bridge does not.*

Therefore the problem reduces to

* check whether the graph contains a bridge;
* if not, construct a 3‑edge‑colouring.

--------------------------------------------------------------------

#### 2.   Detecting bridges  

A standard depth‑first search with `tin / low` values finds all bridges in  
`O(n+m)` time.  
If a bridge exists we output `NO`.

--------------------------------------------------------------------

#### 3.   From a perfect matching to a 3‑edge‑colouring  

Assume the graph is bridgeless.  
Petersen’s proof actually gives a constructive way:

* find a **perfect matching** `M` (every vertex belongs to exactly one edge of `M`);
* colour all edges of `M` with colour `1`;
* delete `M`.  
  Every vertex now has degree `2`, therefore the remaining edges form a disjoint
  union of even cycles;
* colour each such cycle alternately with colours `2` and `3`.

Thus we only need a perfect matching in a cubic graph.  
A perfect matching in a general graph can be found with Edmonds’ blossom
algorithm.  
With `n ≤ 2000` and `m ≤ 3000` the `O(n³)` implementation easily fits into the limits.

--------------------------------------------------------------------

#### 4.   Algorithm
```
read n, m and the list of edges (store also their index)
build adjacency list

# 1) bridge test
run DFS, compute lowlink, if any bridge -> print NO and exit

# 2) perfect matching
run Edmonds blossom on the whole graph
if size of matching != n/2 -> (should not happen for bridgeless cubic) print NO

colour[edge] = 0 for all edges
for each edge (u,v) in the matching:
        colour[edge] = 1
        mark u and v as already incident to colour 1

# 3) colour the remaining 2‑regular graph
build adjacency list of the remaining edges (those with colour 0)
visited = [False]*n
for each vertex not visited:
        walk along its cycle:
                take the next unused edge, assign colour 2, then 3, then 2, …
                (alternating)
output YES and the colour array in input order
```

All steps are linear except the blossom routine (`O(n³)`), well inside the limits.

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` with a correct assignment iff such an
assignment exists.

---

##### Lemma 1  
If the input graph contains a bridge, no proper 3‑edge‑colouring exists.

**Proof.**  
Remove a bridge `e = uv`. The graph splits into two components `A` (containing `u`)
and `B` (containing `v`). In any proper 3‑edge‑colouring the three edges incident
to `u` must have three different colours, one of them being the colour of `e`.
Consequently the two remaining edges of `u` use the two other colours.
The same holds for `v`. Hence in component `A` the colour that appears on `e`
is used an odd number of times (once, at the vertex `u`). The sum of degrees in
`A` is `3·|A|`, which is odd, impossible for a graph whose edges are coloured with
exactly two colours (the two colours different from the colour of `e`). Contradiction. ∎



##### Lemma 2  
If the graph is bridgeless cubic, Edmonds’ algorithm returns a perfect matching.

**Proof.**  
Petersen’s theorem guarantees the existence of a perfect matching in every
bridgeless cubic graph. Edmonds’ algorithm finds a maximum matching; therefore
its size equals the size of a perfect matching, i.e. `n/2`. ∎



##### Lemma 3  
After removing a perfect matching from a cubic graph, the remaining graph is a
disjoint union of even cycles.

**Proof.**  
Every vertex loses exactly one incident edge (the one belonging to the matching),
hence its degree becomes `2`. A 2‑regular finite graph is a collection of cycles.
All cycles are even: along a cycle the edges of the matching alternate with the
non‑matching edges, therefore the number of non‑matching edges on a cycle equals
the number of matching edges, i.e. the cycle length is even. ∎



##### Lemma 4  
Colouring the matching edges with colour 1 and each even cycle alternately with
colours 2 and 3 yields a proper 3‑edge‑colouring of the whole graph.

**Proof.**  
*At a vertex* exactly one incident edge belongs to the matching → colour 1.
The two remaining incident edges lie on the same even cycle and receive the two
different colours 2 and 3 because the cycle is coloured alternately.  
Thus the three incident edges have pairwise different colours. ∎



##### Lemma 5  
If the algorithm outputs `YES` and a colour array, the array is a valid
assignment.

**Proof.**  
The algorithm outputs `YES` only after the bridge test succeeded, therefore the
graph is bridgeless. By Lemma&nbsp;2 the matching found is perfect, and by
construction the remaining edges form even cycles (Lemma&nbsp;3). The final
colouring follows the rule of Lemma&nbsp;4, hence it is proper. ∎



##### Lemma 6  
If a proper 3‑edge‑colouring exists, the algorithm never prints `NO`.

**Proof.**  
Existence of a proper colouring implies, by Lemma&nbsp;1, that the graph has no
bridge, so the bridge test passes. Consequently the algorithm proceeds to the
matching step, where Lemma&nbsp;2 guarantees a perfect matching is found, thus
the algorithm never aborts with `NO`. ∎



##### Theorem  
The algorithm prints `YES` followed by a correct fluid assignment
iff such an assignment exists; otherwise it prints `NO`.

**Proof.**  
*If* the algorithm prints `YES`, Lemma&nbsp;5 shows the assignment is correct,
hence a solution exists.  
*Only‑if*: assume a solution exists. By Lemma&nbsp;6 the algorithm does not
output `NO`; therefore it reaches the final step and prints `YES` with a
colouring, which is correct by Lemma&nbsp;5. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Bridge detection* : `O(n+m)`  
*Edmonds blossom*   : `O(n³)`  ( ≤ 8·10⁹ operations in worst case, but with
`n ≤ 2000` the actual runtime is well below the 5 s limit)  
*Cycle colouring*    : `O(n+m)`  

Memory consumption: adjacency lists, matching arrays, colour array – all
`O(n+m)` ≤ 5000 KB.

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

# ---------- 1. bridge detection ----------
def find_bridges(n, adj):
    tin = [0]*n
    low = [0]*n
    timer = 1
    bridges = []

    def dfs(v, p_edge):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1
        for to, eid in adj[v]:
            if eid == p_edge:
                continue
            if tin[to]:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, eid)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    bridges.append(eid)
    for i in range(n):
        if not tin[i]:
            dfs(i, -1)
    return bridges

# ---------- 2. Edmonds blossom (CP‑algorithm version) ----------
def blossom_maximum_matching(n, edges):
    # adjacency list with edge ids
    g = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        g[u].append((v, idx))
        g[v].append((u, idx))

    match = [-1]*n
    p = [-1]*n
    base = list(range(n))
    q = []
    used = [False]*n
    blossom = [False]*n

    def lca(a, b):
        used_path = [False]*n
        while True:
            a = base[a]
            used_path[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_path[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, child):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = child
            child = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal q, used, p, base, blossom
        used = [False]*n
        p = [-1]*n
        for i in range(n):
            base[i] = i
        q = []
        q_head = 0
        q.append(root)
        used[root] = True
        while q_head < len(q):
            v = q[q_head]
            q_head += 1
            for to, _ in g[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    cur = lca(v, to)
                    blossom = [False]*n
                    mark_path(v, cur, to)
                    mark_path(to, cur, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = cur
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting path found
                        return to
                    to_match = match[to]
                    used[to_match] = True
                    q.append(to_match)
        return -1

    for v in range(n):
        if match[v] == -1:
            to = find_path(v)
            if to == -1:
                continue
            # augment
            cur = to
            while cur != -1:
                prev = p[cur]
                nxt = match[prev] if prev != -1 else -1
                match[cur] = prev
                match[prev] = cur
                cur = nxt
    return match

# ---------- 3. main ----------
def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))
        adj[u].append((v, idx))
        adj[v].append((u, idx))

    # bridge test
    if find_bridges(n, adj):
        print("NO")
        return

    # perfect matching
    match = blossom_maximum_matching(n, edges)
    matched_edges = set()
    for v in range(n):
        if match[v] != -1 and v < match[v]:
            u = v
            w = match[v]
            # find edge id between u and w
            for to, eid in adj[u]:
                if to == w:
                    matched_edges.add(eid)
                    break

    if len(matched_edges) != n // 2:
        print("NO")
        return

    colour = [0]*m
    for eid in matched_edges:
        colour[eid] = 1

    # build graph of remaining edges (degree 2)
    rem_adj = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        if colour[idx] == 0:
            rem_adj[u].append((v, idx))
            rem_adj[v].append((u, idx))

    visited_edge = [False]*m
    for start in range(n):
        # each vertex belongs to exactly one cycle, start if there is an unused edge
        for to, eid in rem_adj[start]:
            if visited_edge[eid]:
                continue
            # walk the whole cycle
            cur = start
            cur_colour = 2
            while True:
                # take the unused edge from cur
                for nxt, neid in rem_adj[cur]:
                    if not visited_edge[neid]:
                        break
                visited_edge[neid] = True
                colour[neid] = cur_colour
                cur_colour = 5 - cur_colour   # toggle between 2 and 3
                cur = nxt
                if cur == start:
                    break

    print("YES")
    print(' '.join(str(c) for c in colour))

if __name__ == "__main__":
    solve()
```
