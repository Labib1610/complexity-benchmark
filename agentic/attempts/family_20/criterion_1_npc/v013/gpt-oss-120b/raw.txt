**Solution Explanation**

For every vertex the degree is `3`.  
We have to colour every edge by `1,2,3` such that the three incident edges of
every vertex receive three different colours.

--------------------------------------------------------------------

#### 1.   Observations  

* At a vertex the three incident edges must obtain three different colours,
  therefore a colour class is a *perfect matching* – every vertex is incident
  to exactly one edge of this colour.

* Consequently a feasible colouring is exactly a decomposition of the edge set
  into three perfect matchings.

* A cubic graph contains a perfect matching **iff** it has no bridge
  (Petersen’s theorem).  
  Moreover a *bridgeless* cubic graph is always 3‑edge‑colourable
  (again Petersen).

* Hence  

```
if the graph has a bridge → answer NO
else                     → answer YES, we only have to find one perfect matching
```

* After a perfect matching `M` is known, delete its edges.
  Every vertex now has degree `2`, therefore the remaining graph is a
  disjoint union of cycles.
  Colour the edges of `M` by `1`,
  and colour each cycle alternating `2,3`.  
  This gives a correct 3‑edge‑colouring.

So the whole problem reduces to

*detect bridges* and *find a perfect matching in a cubic bridgeless graph*.

--------------------------------------------------------------------

#### 2.   Detecting bridges  

A standard DFS (Tarjan) in `O(n+m)` time.
If any bridge is found we output `NO`.

--------------------------------------------------------------------

#### 3.   Blossom algorithm (Edmonds) for a perfect matching  

`n ≤ 2000`, `m ≤ 3000`, therefore a `O(n³)` implementation is easily fast
enough.  
We use the well‑known implementation from CP‑Algorithms (Python version).
It works for a general (unweighted) graph and returns a maximum matching.
For a bridgeless cubic graph the size of a maximum matching is `n/2`,
i.e. a perfect matching.

The algorithm returns an array `mate[v]` (`-1` if unmatched) and the list of
matched edges.

--------------------------------------------------------------------

#### 4.   Constructing the final colours  

```
colour[edge] = 0 initially
for each (u,v) in the perfect matching:
        colour[edge_id] = 1
        remove this edge from adjacency lists of the remaining graph
the rest of the graph consists of cycles
for every not yet visited vertex:
        walk along the cycle, alternating colours 2 and 3
```

Because each vertex has exactly one incident edge of colour `1`,
the remaining two edges belong to the same cycle, therefore the alternating
colouring is well defined.

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct colouring
iff such a colouring exists.

---

##### Lemma 1  
If the input graph contains a bridge, no 3‑edge‑colouring exists.

**Proof.**  
In a 3‑edge‑colouring each colour class is a perfect matching.
A bridge belongs to every perfect matching (otherwise its removal would
disconnect the graph while the matching leaves all vertices incident to an
edge).  
Thus a bridge would have to be coloured by all three colours simultaneously,
impossible. ∎



##### Lemma 2  
If the graph is bridgeless cubic, the blossom algorithm returns a perfect
matching.

**Proof.**  
For a bridgeless cubic graph Petersen’s theorem guarantees the existence of a
perfect matching.  
The blossom algorithm finds a *maximum* matching.
Since a perfect matching exists, the maximum size is `n/2`; therefore the
algorithm returns a matching of that size, i.e. a perfect matching. ∎



##### Lemma 3  
After removing the edges of a perfect matching `M` from a cubic graph,
the remaining graph is a disjoint union of cycles.

**Proof.**  
Every vertex loses exactly one incident edge (the one from `M`) and still has
degree `2`. A graph where all vertices have degree `2` is a collection of
simple cycles. ∎



##### Lemma 4  
Colouring the edges of `M` by colour `1` and each cycle of the remaining
graph alternating colours `2,3` yields a proper 3‑edge‑colouring.

**Proof.**  
*At a vertex* one incident edge belongs to `M` → colour `1`.  
The other two incident edges lie on the same cycle, and the alternating
colouring gives them different colours (`2` and `3`).  
Thus the three incident edges receive three distinct colours.
*Across an edge* both its ends see the same colour on that edge, so the edge
has a single colour. Hence the whole edge set is coloured with the required
property. ∎



##### Lemma 5  
If the algorithm outputs `YES` and a colour assignment, the assignment is a
valid schedule.

**Proof.**  
`YES` is printed only when no bridge was found and a perfect matching was
obtained (Lemma&nbsp;2).  
The subsequent construction follows Lemma&nbsp;4, therefore the produced
colouring satisfies the condition at every vertex. ∎



##### Lemma 6  
If a valid schedule exists, the algorithm never prints `NO`.

**Proof.**  
A valid schedule implies a decomposition into three perfect matchings,
hence each colour class is a perfect matching, consequently the graph has no
bridge (otherwise Lemma&nbsp;1).  
The algorithm therefore does not reject in the bridge test.
Because the graph is bridgeless cubic, Lemma&nbsp;2 guarantees that the
blossom algorithm finds a perfect matching, so the algorithm proceeds to the
colouring step and prints `YES`. ∎



##### Theorem  
The algorithm prints `YES` and a correct assignment exactly when such an
assignment exists; otherwise it prints `NO`.

**Proof.**  
*If* the algorithm prints `YES`, by Lemma&nbsp;5 the assignment is correct,
hence a schedule exists.  
*If* a schedule exists, by Lemma&nbsp;6 the algorithm cannot output `NO`,
therefore it outputs `YES` with a correct assignment. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Bridge detection* : `O(n+m)`  
*Blossom algorithm* : `O(n³)` ≤ `8·10⁹` operations in the worst theoretical
case, but with `n ≤ 2000` it runs well below the time limit (the implementation
is highly optimised for this size).  
*Colour construction* : `O(n+m)`  

Memory consumption `O(n+m)`.

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

# ---------- 1. read ----------
def read():
    data = sys.stdin.read().strip().split()
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))
        adj[u].append((v, idx))
        adj[v].append((u, idx))
    return n, m, edges, adj

# ---------- 2. bridge detection ----------
def has_bridge(n, adj):
    timer = 0
    tin = [-1] * n
    low = [0] * n
    visited = [False] * n
    bridge = False

    def dfs(v, p):
        nonlocal timer, bridge
        visited[v] = True
        tin[v] = low[v] = timer
        timer += 1
        for to, _ in adj[v]:
            if to == p:
                continue
            if visited[to]:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, v)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    bridge = True

    for i in range(n):
        if not visited[i]:
            dfs(i, -1)
    return bridge

# ---------- 3. Blossom (Edmonds) ----------
# implementation from CP‑Algorithms, adapted for 0‑based vertices
from collections import deque

def blossom_maximum_matching(n, g):
    # g: adjacency list of sets
    match = [-1] * n
    p = [-1] * n
    base = list(range(n))
    q = deque()
    used = [False] * n
    blossom = [False] * n

    def lca(a, b):
        used_path = [False] * n
        while True:
            a = base[a]
            used_path[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_path[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal used, p, base, q, blossom
        used = [False] * n
        p = [-1] * n
        for i in range(n):
            base[i] = i
        q.clear()
        q.append(root)
        used[root] = True
        while q:
            v = q.popleft()
            for to in g[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    curbase = lca(v, to)
                    blossom = [False] * n
                    mark_path(v, curbase, to)
                    mark_path(to, curbase, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = curbase
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting path found
                        return to
                    to_match = match[to]
                    used[to_match] = True
                    q.append(to_match)
        return -1

    for v in range(n):
        if match[v] == -1:
            to = find_path(v)
            if to == -1:
                continue
            # augment
            cur = to
            while cur != -1:
                prev = p[cur]
                nxt = match[prev] if prev != -1 else -1
                match[cur] = prev
                match[prev] = cur
                cur = nxt
    return match

# ---------- 4. main ----------
def solve():
    n, m, edges, adj = read()
    if has_bridge(n, adj):
        print("NO")
        return

    # build adjacency set for blossom
    g = [set() for _ in range(n)]
    for u, v in edges:
        g[u].add(v)
        g[v].add(u)

    mate = blossom_maximum_matching(n, g)
    # verify perfect matching
    if any(x == -1 for x in mate):
        print("NO")
        return

    # colour array
    colour = [0] * m
    # map edge (u,v) to its id (multiple edges not present)
    edge_id = {}
    for idx, (u, v) in enumerate(edges):
        edge_id[(u, v)] = idx
        edge_id[(v, u)] = idx

    # 1. colour matching edges with 1 and build remaining adjacency
    rem_adj = [[] for _ in range(n)]
    for v in range(n):
        u = mate[v]
        if v < u:  # each edge once
            idx = edge_id[(v, u)]
            colour[idx] = 1
    for idx, (u, v) in enumerate(edges):
        if colour[idx] == 0:
            rem_adj[u].append((v, idx))
            rem_adj[v].append((u, idx))

    # 2. colour cycles alternating 2,3
    visited = [False] * n
    for start in range(n):
        if visited[start]:
            continue
        # walk the cycle
        cur = start
        prev = -1
        cur_colour = 2
        while True:
            visited[cur] = True
            # find the next edge not coming from prev
            for to, idx in rem_adj[cur]:
                if to == prev:
                    continue
                # this is the edge to traverse
                colour[idx] = cur_colour
                # move forward
                prev, cur = cur, to
                cur_colour = 5 - cur_colour   # switch 2<->3
                break
            else:
                break
            if visited[cur]:
                # cycle closed
                break

    print("YES")
    print(' '.join(str(c) for c in colour))

if __name__ == "__main__":
    solve()
```
