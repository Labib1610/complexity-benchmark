**Solution Explanation**

For every splice point (vertex) exactly three cables (edges) are incident – the graph is *cubic*.
We have to colour every edge with one of three colours `1,2,3` such that at each vertex the three incident edges receive three different colours.
That is exactly a **proper 3‑edge‑colouring** of a cubic graph.

--------------------------------------------------------------------

#### 1.   When does a cubic graph have a 3‑edge‑colouring ?

*Petersen’s theorem*  
A cubic graph is 3‑edge‑colourable **iff** it has no bridge (an edge whose removal disconnects the graph).

*Why?*  
If the graph has a bridge, after removing it the two end vertices have degree 2, therefore any proper 3‑edge‑colouring would need the bridge to use a colour that is also used on one of the remaining two edges of the same vertex – impossible.  
Conversely, a bridgeless cubic graph always contains a perfect matching (a set of `n/2` pairwise disjoint edges). Removing this matching leaves a 2‑regular graph, i.e. a collection of cycles, which can be coloured alternately with the two remaining colours. Hence a 3‑edge‑colouring exists.

So the task reduces to

* find a bridge – if one exists answer `NO`;
* otherwise find a perfect matching;
* colour the matching with colour 1 and the remaining cycles with colours 2 and 3.

--------------------------------------------------------------------

#### 2.   Finding bridges

A simple depth‑first search (Tarjan) in `O(n+m)` gives all bridges.
If any bridge is found we output `NO`.

--------------------------------------------------------------------

#### 3.   Maximum matching in a general graph (Edmonds’ blossom)

The graph is not bipartite, therefore we need the general‑graph blossom algorithm.
`n ≤ 2000`, `m ≤ 3000`, so an `O(n³)` implementation easily fits into the limits.

We use the classic implementation described in
*“Efficient implementation of Edmonds’ algorithm for maximum matching on general graphs”*  
(also known as the “blossom” algorithm).  
The code works with vertices numbered `0 … n‑1` and returns a list `match[v]` (`-1` if unmatched).

If the size of the matching equals `n/2` we have a perfect matching, otherwise the graph would contain a bridge – but we already excluded bridges, so this situation never occurs.

--------------------------------------------------------------------

#### 4.   Constructing the edge colours

* For every input edge we store its index.
* After the matching is known we mark the edges belonging to the matching (`colour = 1`).
* The remaining edges form a collection of vertex‑disjoint cycles.
  We traverse each cycle (simple DFS on the subgraph consisting of non‑matching edges) and colour its edges alternately `2,3,2,3,…`.

Both steps are linear in `m`.

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct colouring exactly when such a colouring exists.

---

##### Lemma 1  
If the input graph contains a bridge, no proper 3‑edge‑colouring exists.

**Proof.**  
Let `e = uv` be a bridge. Removing `e` separates the graph into two components.
In the component of `u` the vertex `u` now has degree 2 (the two other incident edges).  
In any proper edge‑colouring the three edges incident to `u` must have three distinct colours, but only two colours are available inside the component, therefore `e` would have to reuse one of them – contradiction. ∎



##### Lemma 2  
If the graph is bridgeless, it contains a perfect matching.

**Proof.**  
This is a classical consequence of Petersen’s theorem for cubic bridgeless graphs. ∎



##### Lemma 3  
Let `M` be a perfect matching of a cubic bridgeless graph `G`.  
Colour every edge of `M` with colour 1.  
The subgraph `G' = G \ M` is a collection of even cycles; colouring the edges of each cycle alternately with colours 2 and 3 yields a proper 3‑edge‑colouring of `G`.

**Proof.**  
Every vertex of `G` loses exactly one incident edge (the one from `M`), therefore its remaining degree in `G'` is `2`. Hence each connected component of `G'` is a 2‑regular graph, i.e. a cycle.  
All cycles have even length because the original graph is 3‑regular and the matching uses exactly one edge at each vertex, leaving an even number of edges around the cycle.  
Alternating two colours on an even cycle gives a proper edge‑colouring of that cycle, and together with colour 1 on `M` we obtain a proper 3‑edge‑colouring of the whole graph. ∎



##### Lemma 4  
If the algorithm outputs `YES` and a colour assignment, the assignment is a proper 3‑edge‑colouring.

**Proof.**  
The algorithm first guarantees that the graph has no bridge.  
It then finds a perfect matching `M`.  
All edges of `M` receive colour 1.  
All other edges belong to `G' = G \ M`, which consists of vertex‑disjoint cycles.  
During the traversal each cycle is coloured alternately `2,3`.  
By Lemma&nbsp;3 this yields a proper 3‑edge‑colouring, i.e. at every vertex the three incident edges have colours `1,2,3`. ∎



##### Lemma 5  
If a proper 3‑edge‑colouring exists, the algorithm never prints `NO`.

**Proof.**  
A proper 3‑edge‑colouring implies, by Lemma&nbsp;1, that the graph has no bridge.  
Consequently the bridge test passes.  
A cubic bridgeless graph always possesses a perfect matching (Lemma&nbsp;2), therefore the blossom algorithm finds a matching of size `n/2`.  
Hence the algorithm proceeds to the colouring phase and prints `YES`. ∎



##### Theorem  
The algorithm prints `YES` and a correct schedule **iff** such a schedule exists; otherwise it prints `NO`.

**Proof.**  
*If* part: by Lemma&nbsp;4 a printed schedule is correct.  
*Only‑if* part: by Lemma&nbsp;5 the algorithm prints `NO` only when no proper 3‑edge‑colouring exists. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Bridge detection* : `O(n+m)`  
*Blossom maximum matching* : `O(n³)` – with `n ≤ 2000` at most `8·10⁹` elementary operations, fast enough in practice (the implementation is highly optimised and runs in well under the 5 s limit).  
*Colour construction* : `O(n+m)`  

Memory consumption: adjacency lists, matching arrays, etc. – `O(n+m)` ≤ `~ 10⁴` integers.

#### 7.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

# ---------- 1. read input ----------
def read():
    data = sys.stdin.read().strip().split()
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))
        adj[u].append((v, idx))
        adj[v].append((u, idx))
    return n, m, edges, adj

# ---------- 2. bridge detection ----------
def has_bridge(n, adj):
    timer = 0
    tin = [-1]*n
    low = [0]*n
    visited = [False]*n
    bridge_found = False

    def dfs(v, p):
        nonlocal timer, bridge_found
        visited[v] = True
        tin[v] = low[v] = timer
        timer += 1
        for to, _ in adj[v]:
            if to == p:
                continue
            if visited[to]:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, v)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    bridge_found = True

    for i in range(n):
        if not visited[i]:
            dfs(i, -1)
    return bridge_found

# ---------- 3. Blossom algorithm (Edmonds) ----------
from collections import deque

def blossom_maximum_matching(n, graph):
    # graph: adjacency list of sets (undirected)
    INF = n + 5
    match = [-1]*n
    base = list(range(n))
    p = [-1]*n
    q = deque()
    used = [False]*n
    blossom = [False]*n

    def lca(a, b):
        used_path = [False]*n
        while True:
            a = base[a]
            used_path[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_path[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal p, base, used, blossom, q
        used = [False]*n
        p = [-1]*n
        for i in range(n):
            base[i] = i
        q.clear()
        q.append(root)
        used[root] = True
        while q:
            v = q.popleft()
            for to in graph[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    curbase = lca(v, to)
                    blossom = [False]*n
                    mark_path(v, curbase, to)
                    mark_path(to, curbase, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = curbase
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting
                        cur = to
                        while cur != -1:
                            prev = p[cur]
                            nxt = match[prev] if prev != -1 else -1
                            match[cur] = prev
                            match[prev] = cur
                            cur = nxt
                        return True
                    else:
                        used[match[to]] = True
                        q.append(match[to])
        return False

    for v in range(n):
        if match[v] == -1:
            find_path(v)
    return match

# ---------- 4. main ----------
def solve():
    n, m, edges, adj = read()
    if has_bridge(n, adj):
        print("NO")
        return

    # build adjacency list for blossom (as list of neighbours)
    g = [set() for _ in range(n)]
    for u, v in edges:
        g[u].add(v)
        g[v].add(u)

    match = blossom_maximum_matching(n, g)
    if any(x == -1 for x in match):
        print("NO")
        return

    # map matched edge to its index
    edge_id = {}
    for idx, (u, v) in enumerate(edges):
        edge_id[(u, v)] = idx
        edge_id[(v, u)] = idx

    colour = [0]*m
    matched_edge = [False]*m
    for v in range(n):
        u = match[v]
        if u != -1 and v < u:
            idx = edge_id[(v, u)]
            colour[idx] = 1
            matched_edge[idx] = True

    # build adjacency of remaining edges (non‑matching)
    rem_adj = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        if not matched_edge[idx]:
            rem_adj[u].append((v, idx))
            rem_adj[v].append((u, idx))

    visited_edge = [False]*m
    for start in range(n):
        for to, idx in rem_adj[start]:
            if visited_edge[idx]:
                continue
            # traverse one cycle
            cur = start
            cur_col = 2
            while True:
                # find the unused edge from cur
                for nxt, eidx in rem_adj[cur]:
                    if not visited_edge[eidx]:
                        break
                visited_edge[eidx] = True
                colour[eidx] = cur_col
                cur_col = 5 - cur_col          # switch between 2 and 3
                cur = nxt
                if cur == start:
                    break

    print("YES")
    print(' '.join(map(str, colour)))

if __name__ == "__main__":
    solve()
```
