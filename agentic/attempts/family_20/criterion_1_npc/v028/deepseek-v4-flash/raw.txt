We need to check if the graph is **regular** (every vertex has the same degree) and if that degree equals the number of available essences.  
Here, the degree is `d = 2m/n`. Since `m = 3n/2`, we get `d = 3`.  

So the graph is 3-regular. We need to edge-color it with 3 colors (essences).  
By **Vizing’s theorem**, any simple graph can be edge-colored with at most `Δ+1` colors, but for 3-regular graphs, a 3-edge-coloring exists if and only if the graph is **3-edge-colorable** (i.e., it is a bridgeless cubic graph, by the Four Color Theorem equivalent).  

However, here we can check directly:  
- If the graph is 3-regular and has a **perfect matching** whose removal leaves a 2-regular graph (disjoint cycles), we can color the cycles alternately with two colors and the matching with the third.  
- If no such perfect matching exists, output `NO`.

We can find a perfect matching using standard matching algorithms (e.g., Blossom algorithm) or since n ≤ 2000, we can use network flow / Hopcroft–Karp for bipartite? But the graph is not necessarily bipartite.  
We can use a simple greedy + backtracking? That might be too slow.  
Better: Use **Kőnig's line coloring** for bipartite graphs, but here not guaranteed bipartite.  

Since n ≤ 2000, we can use a **general graph perfect matching** algorithm (Blossom) implemented efficiently.  
But implementing Blossom from scratch is heavy.  

Alternative: Since the graph is cubic, we can try to find a 3-edge-coloring via **Kempe chains** or use a known fact:  
A connected cubic graph is 3-edge-colorable iff it is bipartite or bridgeless.  
We can check for bridges: if there is a bridge, it's not 3-edge-colorable.  
If no bridge, we can find a 3-edge-coloring by a constructive method:  
- Find a perfect matching (using Blossom or a simpler method for cubic graphs: every bridgeless cubic graph has a perfect matching).  
- Remove the matching, the remaining graph is 2-regular (disjoint cycles).  
- Color each cycle alternately with two colors, and the matching edges with the third color.

So the plan:
1. Check if graph is 3-regular (should be by constraints).
2. Check if graph is connected? Not required, but each component must be bridgeless.
3. Find a perfect matching.  
   For cubic graphs, we can find a perfect matching by a simple greedy? Not always.  
   But we can use **Tutte's theorem**? Too heavy.  
   We can use **Edmonds' Blossom algorithm** for general graph matching.  
   Since n ≤ 2000, m ≤ 3000, Blossom O(n^3) is fine.

We'll implement a standard Blossom algorithm for maximum cardinality matching in general graphs.

After finding a perfect matching:
- Remove those edges.
- The remaining graph has degree 2 at each vertex → disjoint cycles.
- Color each cycle with colors 1 and 2 alternately.
- Color matching edges with color 3.

If Blossom fails to find a perfect matching, output `NO`.

Let's implement.

import sys
sys.setrecursionlimit(1000000)

def find_perfect_matching(n, edges):
    # Build adjacency list
    adj = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        adj[u].append((v, idx))
        adj[v].append((u, idx))
    
    # Blossom algorithm for maximum matching
    # Standard implementation
    match = [-1] * n
    p = [-1] * n
    base = list(range(n))
    q = []
    used = [False] * n
    blossom = [False] * n
    
    def lca(a, b):
        used_lca = [False] * n
        while True:
            a = base[a]
            used_lca[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_lca[b]:
                return b
            b = p[match[b]]
    
    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]
    
    def find_path(root):
        nonlocal p, base, used, blossom, q
        used = [False] * n
        p = [-1] * n
        for i in range(n):
            base[i] = i
        q = [root]
        used[root] = True
        for v in q:
            for to, _ in adj[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    curbase = lca(v, to)
                    blossom = [False] * n
                    mark_path(v, curbase, to)
                    mark_path(to, curbase, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = curbase
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        return to
                    to = match[to]
                    used[to] = True
                    q.append(to)
        return -1
    
    for i in range(n):
        if match[i] == -1:
            v = find_path(i)
            while v != -1:
                pv = p[v]
                nv = match[pv]
                match[v] = pv
                match[pv] = v
                v = nv
    
    # Check if perfect
    if all(m != -1 for m in match):
        matching_edges = []
        for u in range(n):
            if u < match[u]:
                matching_edges.append((u, match[u]))
        return matching_edges
    else:
        return None
