**Solution Explanation**

For every entity exactly three transfers are given, therefore the whole graph is a *cubic* (3‑regular) undirected graph with  

* `n` vertices (`n` is even)  
* `m = 3n/2` edges  

The required assignment of the three inspectors is exactly a **proper edge‑colouring with three colours** :

* each vertex is incident to the three different colours (the *per‑entity limit*),  
* each colour is used on `m/3` edges (the *balanced workload*).

A cubic graph is 3‑edge‑colourable **iff** it contains a *perfect matching* (a set of `n/2` pairwise disjoint edges covering all vertices).  
Indeed, after removing a perfect matching the remaining graph is 2‑regular, i.e. a disjoint union of cycles; every cycle can be coloured alternately with the two remaining colours.

Consequently the problem reduces to

```
find a perfect matching in the given cubic graph
```

If it exists we colour the matching with colour 1 and the two‑regular remainder with colours 2 and 3; otherwise the answer is “NO”.

The only non‑trivial part is finding a perfect matching in a general graph with up to 2000 vertices and 3000 edges.
We use Edmonds’ blossom algorithm – a classic polynomial‑time algorithm for maximum matching in general graphs.
A compact, well‑tested Python implementation (adapted from the CP‑Algorithms article) runs easily within the limits (`O(n³)` in the worst case, but far faster on these sparse inputs).

--------------------------------------------------------------------

#### Algorithm
```
read n, m and the list of edges (keep original order)
build adjacency list (0‑based vertices)

# 1. maximum matching with Edmonds’ blossom
M = blossom_maximum_matching(adj)          # M[v] = matched vertex or -1
if number of matched vertices != n:
        print "NO" and exit

# 2. colour the matching edges with colour 1
colour[edge_id] = 1   for every edge (u,v) that is in the matching

# 3. the remaining edges form a 2‑regular graph
build adjacency list of the remaining edges, each vertex now has degree 2
for every not yet coloured edge:
        walk along its cycle, alternating colours 2 and 3
        (starting colour 2 for the first traversed edge)

# 4. output
print "YES"
print colours in the original input order
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints a correct assignment iff one exists.

---

##### Lemma 1  
If the algorithm finds a perfect matching `M`, then after removing `M` the remaining graph is a disjoint union of cycles (each vertex has degree 2).

**Proof.**  
Every vertex has degree 3 in the original cubic graph.
Exactly one incident edge of each vertex belongs to the perfect matching,
so the two remaining incident edges stay in the graph.
Thus every vertex has degree 2, which is precisely a collection of cycles. ∎



##### Lemma 2  
Colouring the edges of a cycle alternately with colours 2 and 3 yields a proper edge‑colouring of that cycle (no two incident edges share a colour).

**Proof.**  
In a cycle edges appear in the order `e₁, e₂, …, e_k` (k ≥ 3) and each vertex is incident to two consecutive edges.
If we assign colour 2 to `e₁`, colour 3 to `e₂`, colour 2 to `e₃`, …, the two edges meeting at any vertex receive different colours
(because they are consecutive in the sequence and receive opposite colours). ∎



##### Lemma 3  
If the algorithm outputs a colouring, then each vertex is incident to the three different colours 1, 2, 3.

**Proof.**  
By construction each vertex is incident to exactly one edge of the perfect matching, coloured 1.
The other two incident edges belong to the same cycle (Lemma&nbsp;1) and receive colours 2 and 3 respectively (Lemma&nbsp;2). ∎



##### Lemma 4  
If the algorithm outputs a colouring, each colour is used on exactly `m/3` edges.

**Proof.**  
The perfect matching contains `n/2 = m/3` edges, all coloured 1.
All remaining edges are `m - m/3 = 2m/3` and are split equally between colours 2 and 3 because each cycle of length `ℓ` receives `⌈ℓ/2⌉` edges of colour 2 and `⌊ℓ/2⌋` of colour 3, and `ℓ` is even (every vertex has degree 2 in the remaining graph, therefore each component is an even cycle). Hence both colours appear `m/3` times. ∎



##### Lemma 5  
If the algorithm prints “YES” and the colour list, the assignment satisfies all requirements of the problem.

**Proof.**  
From Lemma&nbsp;3 the per‑entity limit holds, from Lemma&nbsp;4 the balanced workload holds, and obviously every edge receives exactly one colour. ∎



##### Lemma 6  
If the input graph admits a valid assignment, then it contains a perfect matching.

**Proof.**  
In a valid assignment each vertex is incident to exactly one edge of colour 1.
Those edges are pairwise disjoint (otherwise a vertex would have two colour 1 edges) and cover all vertices, i.e. they form a perfect matching. ∎



##### Lemma 7  
If the input graph contains a perfect matching, the algorithm finds one.

**Proof.**  
Edmonds’ blossom algorithm computes a *maximum* matching in any graph.
If a perfect matching exists, its size is `n/2`, which is the maximum possible.
Therefore the algorithm returns a matching of size `n/2`. ∎



##### Theorem  
The algorithm outputs “YES” and a correct assignment **iff** such an assignment exists; otherwise it outputs “NO”.

**Proof.**  

*If part*:  
Assume a valid assignment exists. By Lemma&nbsp;6 the graph has a perfect matching.
By Lemma&nbsp;7 the algorithm finds a perfect matching, proceeds to colour as described,
and by Lemmas&nbsp;5 the produced assignment is valid. Hence the algorithm prints “YES”.

*Only‑if part*:  
If the algorithm prints “YES”, Lemma&nbsp;5 guarantees the produced assignment is valid,
so a valid assignment exists.

If the algorithm prints “NO”, it means the blossom algorithm did not find a perfect matching,
i.e. the maximum matching size is `< n/2`. By Lemma&nbsp;6 a valid assignment would imply a perfect
matching, contradiction. Hence no valid assignment exists. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Blossom algorithm*: `O(n³)` worst case, with `n ≤ 2000` → at most about `8·10⁹` elementary operations,
but on the given sparse graphs (`m ≤ 3000`) it runs far faster (well below the 5 s limit).

*Colouring the remaining cycles*: each edge is visited once → `O(m)`.

Memory consumption: adjacency lists and a few arrays of size `O(n + m)` → ≤ ~ 50 KB.

#### Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

# ---------- Edmonds' blossom (maximum matching) ----------
def blossom_maximum_matching(adj):
    n = len(adj)
    INF = n + 5
    match = [-1] * n
    p = [-1] * n
    base = list(range(n))
    q = []
    used = [False] * n
    blossom = [False] * n

    def lca(a, b):
        used_path = [False] * n
        while True:
            a = base[a]
            used_path[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_path[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal q, used, p, base, blossom
        used = [False] * n
        p = [-1] * n
        base = list(range(n))
        q = []
        q_head = 0
        q.append(root)
        used[root] = True
        while q_head < len(q):
            v = q[q_head]
            q_head += 1
            for to in adj[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    curbase = lca(v, to)
                    blossom = [False] * n
                    mark_path(v, curbase, to)
                    mark_path(to, curbase, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = curbase
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting path found
                        cur = to
                        while cur != -1:
                            prev = p[cur]
                            nxt = match[prev] if prev != -1 else -1
                            match[cur] = prev
                            match[prev] = cur
                            cur = nxt
                        return True
                    else:
                        used[match[to]] = True
                        q.append(match[to])
        return False

    for v in range(n):
        if match[v] == -1:
            find_path(v)
    return match

# ---------- Main ----------
def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))
        adj[u].append(v)
        adj[v].append(u)

    match = blossom_maximum_matching(adj)
    matched = sum(1 for x in match if x != -1) // 2
    if matched * 2 != n:
        print("NO")
        return

    # colour array, 0 = uncoloured, 1/2/3 final colours
    colour = [0] * m
    # map edge (u,v) to its index (there may be parallel edges? not in cubic graph)
    edge_id = {}
    for idx, (u, v) in enumerate(edges):
        edge_id[(u, v)] = edge_id[(v, u)] = idx

    # colour matching edges with 1
    for v in range(n):
        u = match[v]
        if u != -1 and v < u:
            idx = edge_id[(v, u)]
            colour[idx] = 1

    # build adjacency of remaining edges (each vertex degree 2)
    rem_adj = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        if colour[idx] == 0:
            rem_adj[u].append((v, idx))
            rem_adj[v].append((u, idx))

    visited_edge = [False] * m
    for start in range(n):
        for (nbr, eid) in rem_adj[start]:
            if visited_edge[eid]:
                continue
            # walk the cycle starting from this edge
            cur = start
            cur_eid = eid
            cur_col = 2  # start colour
            while True:
                visited_edge[cur_eid] = True
                colour[cur_eid] = cur_col
                # move to the other endpoint
                u, v = edges[cur_eid]
                nxt = v if cur == u else u
                # find the next edge in the cycle (the other unused edge incident to nxt)
                for (to, ne) in rem_adj[nxt]:
                    if not visited_edge[ne]:
                        cur = nxt
                        cur_eid = ne
                        cur_col = 5 - cur_col   # toggle between 2 and 3
                        break
                else:
                    break  # cycle finished
    print("YES")
    print(' '.join(str(c) for c in colour))

if __name__ == "__main__":
    solve()
```
