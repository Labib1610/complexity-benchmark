So the problem reduces to: Does the cubic graph have a proper 3-edge-coloring? If yes, output it. If no, output NO.

A cubic graph has a proper 3-edge-coloring iff it is bridgeless (by the theorem of Tait / Four Color Theorem: every bridgeless cubic graph is 3-edge-colorable). Since n ≤ 2000, we can test for bridges.

If no bridge, we can find a proper 3-edge-coloring via backtracking or using a known linear algorithm like Kempe chains, but for n ≤ 2000, backtracking with 3 colors at each vertex is feasible.

We’ll implement:
1. Build graph.
2. Find bridges.
3. If any bridge → NO.
4. Else backtrack to assign colors to edges.

Backtracking:
- Use edge indices 0..m-1.
- At each vertex, maintain used colors for incident edges; initially none.
- Recursively pick an uncolored edge; for its two endpoints, the chosen color must be unused at both. Assign and continue.
- Since degree is 3, search space small. Use heuristic: at each step, pick vertex with most constraints (uncolored edges count = 3 - colored_count). If at any point a vertex cannot satisfy (i.e., two already colored edges have same color), backtrack.

We can also use a known recursive algorithm that matches edges in pairs — but simple backtracking works.

Let’s write the code.

```python
import sys
sys.setrecursionlimit(1000000)

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        adj[u].append((v, idx))
        adj[v].append((u, idx))
    
    # Find bridges
    tin = [-1]*n
    low = [-1]*n
    timer = [0]
    visited = [False]*n
    
    def dfs(v, p_edge):
        visited[v] = True
        tin[v] = low[v] = timer[0]
        timer[0] += 1
        for to, eidx in adj[v]:
            if eidx == p_edge:
                continue
            if visited[to]:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, eidx)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    # bridge
                    bridges.append(eidx)
    
    bridges = []
    for i in range(n):
        if not visited[i]:
            dfs(i, -1)
    if bridges:
        print("NO")
        return
    
    # Assign colors
    color = [-1]*m
    used_at = [[False]*3 for _ in range(n)]
    
    # order edges: by degree constraint
    # We'll backtrack
    def backtrack(edge_idx):
        if edge_idx == m:
            return True
        u, v = edges[edge_idx]
        for c in range(3):
            if not used_at[u][c] and not used_at[v][c]:
                color[edge_idx] = c
                used_at[u][c] = True
                used_at[v][c] = True
                if backtrack(edge_idx + 1):
                    return True
                used_at[u][c] = False
                used_at[v][c] = False
                color[edge_idx] = -1
        return False
    
    # However, naive order might cause early bad choices.
    # We can sort edges by degree of endpoints? Simple approach may work since cubic small.
    if backtrack(0):
        print("YES")
        print(" ".join(str(c+1) for c in color))
    else:
        # Should not happen if no bridges, but just in case
        print("NO")

if __name__ == "__main__":
    main()
```
