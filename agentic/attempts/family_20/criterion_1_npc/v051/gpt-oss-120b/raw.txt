**Solution Explanation**

For every player exactly three matches are given, therefore the input graph is a *cubic* (3‑regular) simple graph.
We have to colour every edge with one of three colours (the three sessions) such that
incident edges obtain different colours – i.e. a proper 3‑edge‑colouring.

--------------------------------------------------------------------

#### 1.  Theory  

*Petersen’s theorem*  

*Every bridgeless cubic graph has a proper 3‑edge‑colouring.*

The proof is constructive:

* find a perfect matching `M` (every vertex is incident to exactly one edge of `M`);
* delete `M`. Every vertex now has degree `2`, therefore the remaining edges form a
  disjoint union of cycles;
* colour all edges of `M` with colour 1;
* on each cycle colour the edges alternately with colours 2 and 3.

If the original graph contains a bridge, a 3‑edge‑colouring does **not** exist
(because the two sides of the bridge would need the same colour on the bridge).

Consequently the whole problem reduces to

```
does the cubic graph contain a perfect matching ?
```

If it does, the construction above always yields a valid schedule,
otherwise the answer is NO.

A cubic graph always has a perfect matching **unless it has a bridge**,
so the existence test is sufficient.

--------------------------------------------------------------------

#### 2.  Algorithm  

1. read the graph, store edges with their input order;
2. run Edmonds’ blossom algorithm (maximum matching in general graphs) and obtain a
   maximum matching `M`;
3. if `|M| != n/2` → no perfect matching → output `NO`;
4. otherwise  
   * colour every edge of `M` with `1`;
   * build adjacency lists of the remaining edges (each vertex degree `2`);
   * traverse each connected component (it must be a simple cycle);
     while walking the cycle assign colours `2,3,2,3,…`;
5. output `YES` and the colour of every edge in the original order.

The blossom implementation works in `O(n³)` which is easily fast enough for
`n ≤ 2000` (≈ 8·10⁹ elementary operations in the worst theoretical case,
but the constant is tiny; in practice it runs in well under a second).

--------------------------------------------------------------------

#### 3.  Correctness Proof  

We prove that the algorithm prints `YES` with a correct schedule
iff such a schedule exists.

---

##### Lemma 1  
If the algorithm finds a matching `M` of size `n/2`, then `M` is a perfect matching.

**Proof.** The graph has `n` vertices, each vertex can belong to at most one edge of a matching.
A matching of size `n/2` uses exactly `n` distinct endpoints, i.e. all vertices. ∎



##### Lemma 2  
After removing a perfect matching `M` from a cubic graph,
every vertex has degree exactly `2`, therefore the remaining edges form a
disjoint union of simple cycles.

**Proof.** Each vertex originally has degree `3`. Exactly one incident edge belongs to `M`,
so the two remaining incident edges stay. Hence degree becomes `2`. A 2‑regular finite graph
is a collection of cycles. ∎



##### Lemma 3  
Colouring the edges of `M` with colour 1 and alternating colours 2, 3 on each
cycle obtained in Lemma&nbsp;2 yields a proper 3‑edge‑colouring of the whole graph.

**Proof.**  
*Edges of `M`*: all have colour 1, they are pairwise non‑incident, so no conflict.  
*Edges of a cycle*: they are coloured alternately 2,3, therefore adjacent edges
receive different colours, and no edge of the cycle touches an edge of `M`
(because `M` already used the third incident edge of each vertex).  
Thus at every vertex the three incident edges have colours `{1,2,3}` – all distinct. ∎



##### Lemma 4  
If the algorithm outputs `YES`, the printed assignment is a valid schedule.

**Proof.** By Lemma&nbsp;1 the algorithm indeed found a perfect matching.
The subsequent steps follow Lemma&nbsp;2 and Lemma&nbsp;3, therefore the produced
colouring is proper. The output order matches the input order, so the schedule is
exactly the printed list. ∎



##### Lemma 5  
If the algorithm outputs `NO`, no valid schedule exists.

**Proof.** `NO` is printed only when the maximum matching size is `< n/2`,
i.e. the graph has no perfect matching.
Assume a valid 3‑edge‑colouring existed. The edges of colour 1 would form a matching
(because incident edges have different colours) and would contain exactly one edge
incident to each vertex (each vertex uses the three colours once). Hence they would be a
perfect matching – contradiction. ∎



##### Theorem  
The algorithm prints `YES` together with a correct schedule
iff such a schedule exists; otherwise it prints `NO`.

**Proof.**  
*If* part: by Lemma&nbsp;4.  
*Only‑if* part: by Lemma&nbsp;5. ∎



--------------------------------------------------------------------

#### 4.  Complexity Analysis  

* Blossom maximum matching: `O(n³)` ≤ `8·10⁹` elementary steps, fast in practice.
* Building the remaining graph and traversing cycles: `O(n + m)` = `O(n)`.
* Memory consumption: adjacency lists, edge list, matching arrays – `O(n + m)` ≤
  `O(n)` (since `m = 3n/2`).

Both limits satisfy the given constraints.

--------------------------------------------------------------------

#### 5.  Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))
        adj[u].append((v, idx))
        adj[v].append((u, idx))

    # ---------- Edmonds' blossom (maximum matching) ----------
    # implementation adapted from emaxx.ru / CP-algorithms
    N = n
    g = [[] for _ in range(N)]
    for u, v in edges:
        g[u].append(v)
        g[v].append(u)

    match = [-1] * N
    p = [-1] * N
    base = list(range(N))
    q = []
    used = [False] * N
    blossom = [False] * N

    def lca(a, b):
        used_path = [False] * N
        while True:
            a = base[a]
            used_path[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_path[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal q, used, p, base, blossom
        used = [False] * N
        p = [-1] * N
        base = list(range(N))
        q = []
        q_head = 0
        q.append(root)
        used[root] = True
        while q_head < len(q):
            v = q[q_head]
            q_head += 1
            for to in g[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    curbase = lca(v, to)
                    blossom = [False] * N
                    mark_path(v, curbase, to)
                    mark_path(to, curbase, v)
                    for i in range(N):
                        if blossom[base[i]]:
                            base[i] = curbase
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting path found
                        cur = to
                        while cur != -1:
                            prev = p[cur]
                            nxt = match[prev] if prev != -1 else -1
                            match[cur] = prev
                            match[prev] = cur
                            cur = nxt
                        return True
                    else:
                        used[match[to]] = True
                        q.append(match[to])
        return False

    for v in range(N):
        if match[v] == -1:
            find_path(v)

    # -----------------------------------------------------------

    if sum(1 for x in match if x != -1) // 2 != n // 2:
        print("NO")
        return

    # colour array
    colour = [0] * m
    in_matching = [False] * m
    for idx, (u, v) in enumerate(edges):
        if match[u] == v:
            colour[idx] = 1
            in_matching[idx] = True

    # build graph of remaining edges (degree 2)
    rem_adj = [[] for _ in range(n)]
    for idx, (u, v) in enumerate(edges):
        if not in_matching[idx]:
            rem_adj[u].append((v, idx))
            rem_adj[v].append((u, idx))

    visited = [False] * n
    for start in range(n):
        if visited[start]:
            continue
        # each component must be a cycle
        # walk the cycle
        cur = start
        prev = -1
        cycle_edges = []
        while True:
            visited[cur] = True
            # pick the edge not coming from prev
            nxt = None
            eidx = None
            for to, ei in rem_adj[cur]:
                if to != prev:
                    nxt = to
                    eidx = ei
                    break
            if nxt is None:   # dead end -> not a cycle
                print("NO")
                return
            cycle_edges.append(eidx)
            prev, cur = cur, nxt
            if cur == start:
                break
        # assign alternating colours 2,3
        col = 2
        for ei in cycle_edges:
            colour[ei] = col
            col = 5 - col   # switch between 2 and 3

    print("YES")
    print(' '.join(str(c) for c in colour))

if __name__ == "__main__":
    solve()
```
