**Solution Explanation**

For every junction exactly three cables meet – the graph is *cubic* (3‑regular).
We have to colour every edge by one of three colours (the maintenance windows) such that
the three incident edges of every vertex receive three different colours.
In graph theory this is exactly a **proper 3‑edge‑colouring** of a cubic graph.

--------------------------------------------------------------------

#### 1.   When does a cubic graph have a 3‑edge‑colouring ?

*If the graph contains a bridge* (an edge whose removal disconnects the graph)  
then the two sides of the bridge need the same colour on the bridge,
but each side already uses the other two colours on its three incident edges –
impossible. So a cubic graph with a bridge is **not** 3‑edge‑colourable.

*If the graph is bridgeless* then, by Petersen’s theorem,
it possesses a **perfect matching** (a set of `n/2` pairwise disjoint edges covering all vertices).
Removing this matching leaves a 2‑regular graph, i.e. a collection of disjoint cycles.
Colour the matching edges with colour 1 and colour each remaining cycle alternately
with colours 2 and 3.  
All three incident edges of every vertex now have different colours, therefore we obtain
a proper 3‑edge‑colouring.

Consequently a cubic graph is 3‑edge‑colourable **iff** it has no bridge.
Our algorithm follows exactly this constructive proof:

```
find a perfect matching M
if |M| != n/2 :   NO          (graph has a bridge)
else:
    colour edges of M with 1
    the rest of the edges form cycles → colour them 2,3 alternately
    YES and output the colours
```

The only non‑trivial part is to find a perfect matching in a general (non‑bipartite)
graph. We use Edmonds’ blossom algorithm, O(n³), fast enough for `n ≤ 2000`.

--------------------------------------------------------------------

#### 2.   Blossom algorithm (maximum matching in general graph)

We implement the classic BFS‑based Edmonds’ algorithm as described in
*“Algorithmic Graph Theory and Perfect Matching”* (Micali‑Vazirani / emaxx).
The implementation works with vertices numbered `0 … n‑1` and returns a list
`match[v] = partner of v` (`-1` if unmatched).  
Complexity `O(n³)` → ≤ 8·10⁹ elementary operations in the worst case,
but the constant is tiny and the limit `5 s` is easily met for `n = 2000`.

--------------------------------------------------------------------

#### 3.   Constructing the final colouring

* `match` gives the perfect matching `M`.  
  For every edge `i = (u,v)` (input order) we check whether `match[u] == v`.
  If yes → colour `1`.

* All other edges belong to the 2‑regular remainder.
  We build adjacency lists **only with those edges** and run a simple DFS
  to walk each cycle, alternating colours `2` and `3`.

Both steps are linear in the number of edges (`m = 3n/2 ≤ 3000`).

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` with a valid schedule
iff such a schedule exists.

---

##### Lemma 1  
If the algorithm finds a perfect matching `M` (size `n/2`) then the input graph
has no bridge.

**Proof.**  
In a cubic graph every vertex has degree 3. Removing a perfect matching leaves each
vertex with degree 2, therefore the remaining graph is a collection of cycles,
hence 2‑edge‑connected. Adding back the matching edges cannot create a bridge,
otherwise the removed edge would be the only connection between the two
components, contradicting the existence of a cycle containing it. ∎



##### Lemma 2  
If the algorithm does **not** find a perfect matching, the graph contains a bridge
and no 3‑edge‑colouring exists.

**Proof.**  
A cubic graph without a perfect matching must have a bridge (Petersen theorem’s
contrapositive). As argued in the introduction, a bridge makes a 3‑edge‑colouring
impossible. ∎



##### Lemma 3  
Assume the algorithm obtained a perfect matching `M`.  
Colouring `M` with colour 1 and the remaining edges alternating 2/3 along each
cycle yields a proper 3‑edge‑colouring.

**Proof.**  
Every vertex `v` is incident to exactly one edge of `M` (colour 1) and two edges
of the remaining graph. Those two edges lie on the same cycle, hence receive
different colours 2 and 3 by the alternating rule. Thus the three incident edges
receive three distinct colours. ∎



##### Lemma 4  
If a 3‑edge‑colouring exists, the graph has no bridge and therefore possesses a
perfect matching. The algorithm will find such a matching and output a valid
colouring.

**Proof.**  
A 3‑edge‑colouring implies the graph is bridgeless (otherwise the bridge argument
gives a contradiction). By Petersen’s theorem a bridgeless cubic graph has a
perfect matching, and Edmonds’ algorithm always finds a maximum matching,
hence a perfect one. The subsequent construction of colours is exactly the one
described in Lemma 3, therefore the output is a correct schedule. ∎



##### Theorem  
The program prints  

*`YES` and a list of colours* **iff** a feasible assignment of the three windows
exists; otherwise it prints `NO`.

**Proof.**  

*If the program prints `YES`*: it found a perfect matching, coloured as in
Lemma 3, which is a proper 3‑edge‑colouring, i.e. a feasible assignment.

*If a feasible assignment exists*: by Lemma 4 the graph is bridgeless,
has a perfect matching, the algorithm finds it and consequently prints `YES`
with a valid colouring.

If the program prints `NO`, it failed to find a perfect matching, therefore by
Lemma 2 the graph contains a bridge and no feasible assignment exists. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Blossom maximum matching*: `O(n³)` ≤ `8·10⁹` elementary steps, well below the
limit for `n = 2000`.  
*Building the remainder graph and DFS*: `O(m)` = `O(n)`.

Memory consumption: adjacency lists, matching array, a few auxiliary
arrays – `O(n + m)` ≤ `O(3000)` integers, far below the 256 MB limit.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def blossom_maximum_matching(n, adj):
    # implementation of Edmonds' blossom algorithm (O(n^3))
    INF = n + 5
    match = [-1] * n
    p = [-1] * n
    base = list(range(n))
    q = []
    used = [False] * n
    blossom = [False] * n

    def lca(a, b):
        used2 = [False] * n
        while True:
            a = base[a]
            used2[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used2[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal q, used, p, base, blossom
        used = [False] * n
        p = [-1] * n
        base = list(range(n))
        q = []
        q_head = 0
        q.append(root)
        used[root] = True
        while q_head < len(q):
            v = q[q_head]
            q_head += 1
            for to in adj[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    curbase = lca(v, to)
                    blossom = [False] * n
                    mark_path(v, curbase, to)
                    mark_path(to, curbase, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = curbase
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting path found
                        cur = to
                        while cur != -1:
                            prev = p[cur]
                            nxt = match[prev] if prev != -1 else -1
                            match[cur] = prev
                            match[prev] = cur
                            cur = nxt
                        return True
                    else:
                        used[match[to]] = True
                        q.append(match[to])
        return False

    for v in range(n):
        if match[v] == -1:
            find_path(v)
    return match

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n)]
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges.append((u, v))
        adj[u].append(v)
        adj[v].append(u)

    match = blossom_maximum_matching(n, adj)
    if any(x == -1 for x in match):
        print("NO")
        return

    # colour array
    col = [0] * m
    # mark matching edges colour 1
    in_match = set()
    for v in range(n):
        u = match[v]
        if u != -1 and v < u:
            in_match.add((v, u))
    for i, (u, v) in enumerate(edges):
        if (u, v) in in_match or (v, u) in in_match:
            col[i] = 1

    # build graph of remaining edges (2-regular)
    rem_adj = [[] for _ in range(n)]
    edge_id = {}
    for i, (u, v) in enumerate(edges):
        if col[i] == 0:
            rem_adj[u].append((v, i))
            rem_adj[v].append((u, i))
            edge_id[(u, v)] = i
            edge_id[(v, u)] = i

    visited_edge = [False] * m
    for i in range(m):
        if col[i] != 0 or visited_edge[i]:
            continue
        # walk the cycle
        u, v = edges[i]
        cur = u
        prev = -1
        cur_edge = i
        cur_color = 2
        while True:
            visited_edge[cur_edge] = True
            col[cur_edge] = cur_color
            # move to the other vertex of the edge
            nxt = edges[cur_edge][0] ^ edges[cur_edge][1] ^ cur
            # find next edge in the cycle (the one not equal to cur_edge)
            for nb, eid in rem_adj[nxt]:
                if eid != cur_edge:
                    next_edge = eid
                    break
            cur = nxt
            cur_edge = next_edge
            cur_color = 5 - cur_color  # toggle between 2 and 3
            if visited_edge[cur_edge]:
                # close the cycle
                visited_edge[cur_edge] = True
                col[cur_edge] = cur_color
                break

    print("YES")
    print(' '.join(str(c) for c in col))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
