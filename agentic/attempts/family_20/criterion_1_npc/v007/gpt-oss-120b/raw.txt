**Solution Explanation**

For every junction exactly three cables meet, therefore the whole graph is *cubic*  
(`deg(v)=3` for all vertices).  
The required schedule is exactly a **proper 3‑edge‑colouring** of this cubic
graph in which each colour is used `m/3 = n/2` times.

--------------------------------------------------------------------

#### 1.  When does a cubic graph have such a colouring ?

*If the graph is bipartite* the answer is always **YES**.

*Proof.*  
A bipartite graph is `Δ`‑edge‑colourable (`Δ` = maximum degree) – König’s
theorem.  
Our graph is `Δ = 3`, therefore its edges can be split into three
pairwise disjoint **perfect matchings** (each matching contains exactly one
incident edge of every vertex, i.e. `n/2` edges).  
Giving the three matchings the colours `1,2,3` yields a proper 3‑edge‑colouring
with the required colour frequencies. ∎



If the graph is **not** bipartite it contains an odd cycle.
In a cubic graph an odd cycle cannot be coloured with three colours while
keeping the three incident edges of each vertex different – a classic
obstruction (snarks).  
Consequently a feasible schedule does **not** exist.

Thus the whole problem reduces to

* test whether the given cubic graph is bipartite;
* if it is, decompose it into three perfect matchings.

--------------------------------------------------------------------

#### 2.  Finding three perfect matchings in a bipartite cubic graph  

The graph is bipartite, let the two sides be `L` and `R` (`|L| = |R| = n/2`).
All vertices have degree `3`, therefore the bipartite graph is **3‑regular**.

A maximum matching in a regular bipartite graph is always perfect.
We run a standard Hopcroft–Karp algorithm three times:

```
for colour = 1 .. 3
        find a maximum matching M in the current graph
        (it will have size n/2)
        assign colour to all edges of M
        delete M from the graph
```

Each run works on at most `m = 3n/2 ≤ 3000` edges, `n ≤ 2000`,
so the total complexity `O(3 * sqrt(n) * m)` is far below the limits.

--------------------------------------------------------------------

#### 3.  Correctness Proof  

We prove that the algorithm prints a correct answer iff one exists.

---

##### Lemma 1  
If the input graph is bipartite, each iteration of the algorithm finds a
perfect matching.

**Proof.**  
Before an iteration the remaining graph is still bipartite and every vertex
has degree `3‑(iteration‑1)`. After the first iteration each vertex has degree
`2`, after the second degree `1`. A `k`‑regular bipartite graph always possesses a
matching of size `|L|` (Hall’s theorem). The Hopcroft–Karp algorithm returns a
maximum matching, therefore its size is `|L| = n/2`, i.e. a perfect matching. ∎



##### Lemma 2  
After the three iterations every edge of the original graph receives exactly
one colour, and each colour is used `n/2` times.

**Proof.**  
By Lemma&nbsp;1 each iteration selects `n/2` edges, all distinct because the
selected edges are removed afterwards. The three iterations together therefore
colour `3·(n/2) = m` edges – all edges. Each colour is assigned in exactly one
iteration, hence exactly `n/2` times. ∎



##### Lemma 3  
The obtained colouring is proper: at every vertex the three incident edges
have three different colours.

**Proof.**  
At a vertex `v` the three incident edges are taken in three different
iterations, because after an iteration the edge incident to `v` is removed.
Consequently the three edges receive three different colours. ∎



##### Lemma 4  
If the input graph is bipartite, the algorithm outputs a schedule that satisfies
all requirements.

**Proof.**  
Bipartiteness is detected, the algorithm proceeds, and by Lemmas&nbsp;2 and&nbsp;3
the produced assignment is a proper 3‑edge‑colouring with exactly `n/2` edges
of each colour, i.e. a valid schedule. ∎



##### Lemma 5  
If the input graph is **not** bipartite, no feasible schedule exists.

**Proof.**  
A non‑bipartite cubic graph contains an odd cycle `C`. In any proper
3‑edge‑colouring the three edges incident to a vertex must have distinct colours,
hence along `C` the colours must repeat every three edges. Because `|C|` is odd,
this is impossible. Therefore a proper 3‑edge‑colouring does not exist, and
the required schedule cannot be built. ∎



##### Theorem  
The program prints  

* `YES` followed by a correct assignment **iff** such an assignment exists,
* otherwise prints `NO`.

**Proof.**  

*If the program prints `YES`* – it happened only when the graph was bipartite.
By Lemma&nbsp;4 the printed assignment is correct, therefore a feasible schedule
exists.

*If a feasible schedule exists* – then a proper 3‑edge‑colouring exists,
hence the graph must be bipartite (otherwise Lemma&nbsp;5 contradicts
existence). The program detects bipartiteness and, by Lemma&nbsp;4, prints a
valid assignment, i.e. `YES`.

Thus the output is correct in all cases. ∎



--------------------------------------------------------------------

#### 4.  Complexity Analysis  

*Bipartite test* – BFS: `O(n + m)`.

*Three Hopcroft–Karp runs* – each `O(√n · m)`.  
`n ≤ 2000`, `m = 3n/2 ≤ 3000`  

```
total ≤ 3 * √2000 * 3000  < 3 * 45 * 3000  ≈ 4·10^5
```

well inside the 5 s limit.  
Memory consumption: adjacency lists, matchings, auxiliary arrays – `O(n + m)`.

#### 5.  Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def bfs_bipartite(n, adj):
    color = [ -1 ] * (n + 1)
    for start in range(1, n + 1):
        if color[start] != -1:
            continue
        color[start] = 0
        q = deque([start])
        while q:
            v = q.popleft()
            for to in adj[v]:
                if color[to] == -1:
                    color[to] = color[v] ^ 1
                    q.append(to)
                elif color[to] == color[v]:
                    return None          # not bipartite
    return color

# Hopcroft–Karp for bipartite graph (left side = 1..nL)
def hopcroft_karp(nL, nR, g):
    INF = 10 ** 9
    pairU = [0] * (nL + 1)
    pairV = [0] * (nR + 1)
    dist = [0] * (nL + 1)

    def bfs():
        q = deque()
        for u in range(1, nL + 1):
            if pairU[u] == 0:
                dist[u] = 0
                q.append(u)
            else:
                dist[u] = INF
        dist[0] = INF
        while q:
            u = q.popleft()
            if dist[u] < dist[0]:
                for v in g[u]:
                    if dist[pairV[v]] == INF:
                        dist[pairV[v]] = dist[u] + 1
                        q.append(pairV[v])
        return dist[0] != INF

    def dfs(u):
        if u == 0:
            return True
        for v in g[u]:
            if dist[pairV[v]] == dist[u] + 1 and dfs(pairV[v]):
                pairU[u] = v
                pairV[v] = u
                return True
        dist[u] = INF
        return False

    matching = 0
    while bfs():
        for u in range(1, nL + 1):
            if pairU[u] == 0 and dfs(u):
                matching += 1
    return pairU, matching

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    edges = []
    adj = [[] for _ in range(n + 1)]
    for i in range(m):
        u = int(next(it)); v = int(next(it))
        edges.append((u, v))
        adj[u].append(v)
        adj[v].append(u)

    part = bfs_bipartite(n, adj)
    if part is None:
        print("NO")
        return

    # split vertices to left/right according to part (0/1)
    left_ids = {}
    right_ids = {}
    lcnt = rcnt = 0
    for v in range(1, n + 1):
        if part[v] == 0:
            lcnt += 1
            left_ids[v] = lcnt
        else:
            rcnt += 1
            right_ids[v] = rcnt

    # adjacency for current graph (will be modified)
    cur_adj = [list() for _ in range(lcnt + 1)]   # only left side needed
    edge_pos = {}   # (l,r) -> list of original indices (there is at most one)
    for idx, (u, v) in enumerate(edges):
        if part[u] == 0:
            l = left_ids[u]; r = right_ids[v]
        else:
            l = left_ids[v]; r = right_ids[u]
        cur_adj[l].append(r)
        edge_pos[(l, r)] = idx

    colour = [0] * m
    for col in range(1, 4):
        pairU, size = hopcroft_karp(lcnt, rcnt, cur_adj)
        # size must be n/2
        for u in range(1, lcnt + 1):
            v = pairU[u]
            if v == 0:
                continue
            idx = edge_pos.pop((u, v))
            colour[idx] = col
        # rebuild adjacency without used edges
        new_adj = [list() for _ in range(lcnt + 1)]
        for (u, v), idx in edge_pos.items():
            new_adj[u].append(v)
        cur_adj = new_adj

    print("YES")
    print(' '.join(map(str, colour)))

if __name__ == "__main__":
    solve()
```
