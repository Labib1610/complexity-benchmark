**Solution Explanation**

For the given wiring the `m = n‑1` links form a **tree** – between any two modules there is exactly one simple path.
For a set `C` of *critical* modules we have to activate a set of links that makes all
modules of `C` mutually reachable and the total activation cost has to be minimal.

--------------------------------------------------------------------

#### 1.   Observations  

* In a tree the unique minimal connected subgraph containing a set of vertices `C`
  is the **union of all paths between vertices of `C`**.
  No edge outside this union can help to connect the critical modules,
  therefore it never belongs to an optimal solution.

* For an edge `e = (parent, child)` let `sub` be the number of critical modules
  inside the child’s subtree (the component that would be separated from the root
  after deleting `e`).  
  After removing `e` the tree is split into two components.
  *If both components contain at least one critical module*,
  then `e` is necessary – otherwise the critical modules would become disconnected.
  Hence  

```
edge e is needed  <=>   0 < sub < |C|
```

* All edge weights are positive, therefore keeping **exactly** the needed edges
  is optimal – adding any other edge would only increase the total cost.

Consequently the answer is simply the sum of the weights of all edges whose
subtree contains a non‑empty proper subset of the critical modules.

--------------------------------------------------------------------

#### 2.   Algorithm  

1. read the tree, store adjacency list `adj`.
2. mark the critical modules (`is_term[v] = 1`).
3. root the tree at vertex `1` (any vertex works) and obtain a parent array
   with an iterative DFS/BFS – this also gives a traversal order.
4. Process the vertices **bottom‑up** (reverse of the order obtained above)  

   * `cnt[v]` – number of critical modules in the subtree of `v`  

     `cnt[v] = is_term[v] + Σ cnt[child]`
   * for the edge `(parent[v], v)` (weight `pw[v]`)  

     if `0 < cnt[v] < t` add `pw[v]` to the answer.

The algorithm touches each vertex and each edge a constant number of times.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the minimum possible total activation cost.

---

##### Lemma 1  
For any edge `e = (parent, child)` let `sub` be the number of critical modules
in the child’s subtree.  
If `0 < sub < t` then every feasible activation set must contain `e`.

**Proof.**  
Removing `e` separates the tree into two components:
*Component A* – the child’s subtree (contains `sub` critical modules)  
*Component B* – the rest of the tree (contains `t‑sub` critical modules).  
Both components contain at least one critical module, therefore any set of
active edges that keeps all critical modules mutually reachable must contain at
least one edge crossing the cut `{A,B}`. The only edge crossing this cut is `e`,
hence `e` is mandatory. ∎



##### Lemma 2  
If `sub = 0` or `sub = t` then edge `e` can be omitted while still keeping all
critical modules connected.

**Proof.**  
* `sub = 0` – the whole subtree of `child` contains no critical module.
  Deleting `e` does not separate any critical module from another, therefore
  connectivity of the critical set is preserved.
* `sub = t` – all critical modules lie inside the child’s subtree.
  The rest of the tree is irrelevant for their connectivity, again `e` can be
  removed. ∎



##### Lemma 3  
The set `E_needed` consisting of all edges with `0 < sub < t` connects all
critical modules.

**Proof.**  
Take any two critical modules `x` and `y`.  
In the original tree there is a unique path `P(x,y)`.  
Consider any edge `e` on this path. Deleting `e` separates the tree into two
components, each containing at least one of `{x,y}`; consequently each component
contains at least one critical module, i.e. `0 < sub < t`.  
Thus `e ∈ E_needed`. Since every edge of the original path belongs to `E_needed`,
the whole path is present, therefore `x` and `y` stay connected. ∎



##### Lemma 4  
`E_needed` is a feasible activation set of minimum total weight.

**Proof.**  
*Feasibility* follows from Lemma&nbsp;3.  
*Minimality*: by Lemma&nbsp;1 every feasible set must contain all edges of
`E_needed`. All edge weights are positive, therefore adding any extra edge can
only increase the total cost. Hence no feasible set can be cheaper than
`E_needed`. ∎



##### Theorem  
The algorithm outputs the minimum possible total activation cost.

**Proof.**  
During the bottom‑up traversal the algorithm computes for each vertex `v`
the exact number `cnt[v]` of critical modules in its subtree.
For the edge `(parent[v], v)` it adds its weight to the answer **iff**
`0 < cnt[v] < t`.  
Consequently the sum produced by the algorithm equals the total weight of
`E_needed`. By Lemma&nbsp;4 this weight is the optimum. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency list* – `O(n)` time, `O(n)` memory.  
*Iterative DFS to obtain order* – `O(n)` time, `O(n)` memory for stacks and
arrays.  
*Bottom‑up processing* – `O(n)` time.  

Overall  

```
Time   :  O(n)      ( ≤ 2·10^5 operations )
Memory :  O(n)
```

Both limits satisfy the problem constraints.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)          # = n-1, not used separately
    t = next(it)

    critical = [0] * (n + 1)
    for _ in range(t):
        v = next(it)
        critical[v] = 1

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = next(it)
        v = next(it)
        w = next(it)
        adj[u].append((v, w))
        adj[v].append((u, w))

    parent = [0] * (n + 1)
    pw = [0] * (n + 1)          # weight to parent
    order = []

    # iterative DFS to get parent array and traversal order
    stack = [1]
    parent[1] = -1               # mark root
    while stack:
        v = stack.pop()
        order.append(v)
        for nb, w in adj[v]:
            if nb != parent[v]:
                parent[nb] = v
                pw[nb] = w
                stack.append(nb)

    cnt = [0] * (n + 1)
    ans = 0
    # process vertices in reverse order (post‑order)
    for v in reversed(order):
        total = critical[v]
        for nb, _ in adj[v]:
            if parent[nb] == v:          # nb is a child
                total += cnt[nb]
        cnt[v] = total
        if parent[v] > 0:                # not the root
            if 0 < cnt[v] < t:
                ans += pw[v]

    print(ans)


if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
