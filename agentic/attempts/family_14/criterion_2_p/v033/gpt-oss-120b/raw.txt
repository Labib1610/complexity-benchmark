**Solution Explanation**

For a tree there is exactly one simple path between any two vertices.
If we have to connect a set `R` of required vertices, the cheapest possible
network is simply the union of all those unique paths – no edge can be
replaced by a cheaper one.

Therefore an edge `e = (parent, child)` is **necessary** iff the required
vertices are split by the cut created by removing `e` :

* at least one required vertex lies in the child’s subtree,
* at least one required vertex lies outside that subtree.

If this holds, the edge must belong to the Steiner tree, otherwise it can
be omitted.

So the answer is the sum of the weights of all necessary edges.



--------------------------------------------------------------------

#### Algorithm
```
read n, m (= n‑1), t
read list of required vertices
build adjacency list of the tree (undirected, weighted)

root the tree at vertex 1
perform an iterative DFS
    store for every vertex:
        parent[vertex]          – its parent in the rooted tree
        w_to_parent[vertex]     – weight of the edge to the parent
        order[]                 – vertices in the order they are first visited

process vertices in reverse DFS order (post‑order)
    cnt[vertex] = 1 if vertex is required else 0
    for each child c of vertex:
        cnt[vertex] += cnt[c]          # number of required vertices in its subtree
    if vertex ≠ root and 0 < cnt[vertex] < t:
        answer += w_to_parent[vertex]  # edge to its parent is necessary

output answer
```

`cnt[vertex]` is the number of required sites inside the subtree of `vertex`.
The condition `0 < cnt < t` means the required vertices are present on both
sides of the edge to the parent.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the minimum possible total cost.

---

##### Lemma 1  
For any edge `e = (p, c)` (parent `p`, child `c`) let `S_c` be the set of
required vertices in the subtree of `c`.  
Edge `e` belongs to *every* connected subgraph that contains all required
vertices **iff** `0 < |S_c| < t`.

**Proof.**  
*If* `0 < |S_c| < t` then there is at least one required vertex inside the
subtree and at least one outside (because total required vertices are `t`).
Any connected subgraph containing all required vertices must contain a path
between those two vertices, and the only possible path in a tree uses `e`.
Hence `e` is mandatory.

*Only‑if*:  
- If `|S_c| = 0`, all required vertices lie outside the subtree, so we can
  delete the whole subtree (including `e`) and still keep all required
  vertices connected – `e` is not needed.
- If `|S_c| = t`, all required vertices are inside the subtree, the rest of
  the tree is irrelevant, again `e` can be omitted. ∎



##### Lemma 2  
The algorithm adds the weight of an edge `e` to the answer **iff**
`e` satisfies the condition of Lemma&nbsp;1.

**Proof.**  
During the post‑order processing the algorithm knows `cnt[c] = |S_c|`.
It adds `w(e)` exactly when `0 < cnt[c] < t`. By Lemma&nbsp;1 this is
precisely the set of mandatory edges. ∎



##### Lemma 3  
The sum produced by the algorithm equals the total weight of the unique
minimum‑cost subgraph that connects all required vertices.

**Proof.**  
By Lemma&nbsp;2 the algorithm sums the weights of *all* mandatory edges and
no others. Any connected subgraph containing all required vertices must
contain all mandatory edges (Lemma&nbsp;1), therefore its total weight is at
least the algorithm’s sum. Conversely, the subgraph consisting exactly of
those mandatory edges is connected (removing any of them would disconnect
required vertices) and its weight equals the sum. Hence the sum is the
minimum possible. ∎



##### Theorem  
The algorithm outputs the minimum total cabling cost needed to connect all
required sites.

**Proof.**  
Directly from Lemma&nbsp;3. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency list*: `O(n)` memory and time.  
*DFS traversal*: `O(n)` time, `O(n)` additional memory for stacks and arrays.  
*Post‑order processing*: `O(n)` time.  

Total: **O(n)** time, **O(n)** memory, well within the limits (`n ≤ 200 000`).

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    it = iter(data)
    n = int(next(it))
    m = int(next(it))          # = n-1, not used separately
    t = int(next(it))

    required = [False] * (n + 1)
    for _ in range(t):
        required[int(next(it))] = True

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it)); w = int(next(it))
        adj[u].append((v, w))
        adj[v].append((u, w))

    parent = [0] * (n + 1)
    w_to_parent = [0] * (n + 1)
    order = []

    # iterative DFS to avoid recursion depth problems
    stack = [1]
    parent[1] = -1
    while stack:
        v = stack.pop()
        order.append(v)
        for to, w in adj[v]:
            if to != parent[v]:
                parent[to] = v
                w_to_parent[to] = w
                stack.append(to)

    cnt = [0] * (n + 1)
    ans = 0
    for v in reversed(order):
        cnt[v] = 1 if required[v] else 0
        for to, _ in adj[v]:
            if parent[to] == v:          # child
                cnt[v] += cnt[to]
        if v != 1 and 0 < cnt[v] < t:
            ans += w_to_parent[v]

    sys.stdout.write(str(ans))

if __name__ == "__main__":
    solve()
```
