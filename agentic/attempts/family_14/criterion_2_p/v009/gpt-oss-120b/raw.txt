**Solution Explanation**

For a tree the cheapest way to connect a set `R` of required vertices is
the *minimal subtree* that contains all vertices of `R`.  
An edge belongs to this subtree **iff** after removing the edge both
components still contain at least one required vertex.

So the answer is the sum of the weights of all edges that separate required
vertices.

--------------------------------------------------------------------

#### Algorithm
```
read input
required[v] = True  for every required vertex v
build adjacency list of the tree

root the tree at vertex 1
stack ← [1]
parent[1] ← 0
weight_to_parent[1] ← 0
order ← []                         # traversal order (pre‑order)

while stack not empty:
        v ← stack.pop()
        order.append(v)
        for (to , w) in adj[v]:
                if to == parent[v]: continue
                parent[to] = v
                weight_to_parent[to] = w
                stack.append(to)

cnt[v] = number of required vertices in the subtree of v
answer = 0

for v in reversed(order):          # children are processed before the parent
        cntv = 1 if required[v] else 0
        for (to , w) in adj[v]:
                if parent[to] == v:           # to is a child of v
                        cntv += cnt[to]
        cnt[v] = cntv
        if v != 1:                           # not the root
                if cnt[v] > 0 and  t - cnt[v] > 0:
                        answer += weight_to_parent[v]

print answer
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the weight of the minimal subtree
connecting all required sites.

---

##### Lemma 1  
For any edge `e = (p, c)` where `p` is the parent of `c`,
let `S_c` be the set of vertices in `c`'s subtree.
`e` belongs to the minimal connecting subtree **iff**
`S_c` contains at least one required vertex **and**
its complement also contains at least one required vertex.

**Proof.**  
*If*: assume both sides contain required vertices.
Any connection of all required vertices must use a path from a vertex in
`S_c` to a vertex outside `S_c`; the only such path in a tree is `e`,
therefore `e` is necessary.  

*Only‑if*: suppose `e` is in the minimal subtree.
Removing `e` would disconnect the subtree, hence at least one required vertex
must lie in each component, otherwise the subtree would still be connected.
∎



##### Lemma 2  
After the post‑order loop finishes,
`cnt[v]` equals the number of required vertices inside the subtree rooted at `v`.

**Proof.**  
Induction on the reversed traversal order.
*Base*: leaves are processed first; their subtree consists only of themselves,
so `cnt[leaf]` is correctly set to `1` if leaf is required, else `0`.  

*Induction step*: when processing an internal node `v`, all its children have
already stored correct counts (`cnt[child]`). The algorithm adds the child
counts and possibly `1` for `v` itself, therefore `cnt[v]` becomes the total
required vertices in its whole subtree. ∎



##### Lemma 3  
During the post‑order loop the algorithm adds `weight_to_parent[v]`
to the answer **iff** edge `(parent[v], v)` satisfies the condition of Lemma&nbsp;1.

**Proof.**  
When `v ≠ root`, `cnt[v]` is exactly the number of required vertices in the
subtree of `v` (Lemma&nbsp;2).  
The complement contains `t - cnt[v]` required vertices.
The algorithm adds the edge weight precisely when both numbers are positive,
i.e. exactly the condition of Lemma&nbsp;1. ∎



##### Theorem  
The algorithm outputs the total weight of the cheapest set of cabling
options that connects all required sites.

**Proof.**  
By Lemma&nbsp;3 the algorithm sums the weights of exactly those edges that
separate required vertices on both sides, i.e. the edges that belong to the
minimal subtree (Lemma&nbsp;1).  
All other edges are omitted.  
Therefore the computed sum equals the weight of the minimal subtree,
which is the optimal solution for the problem. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building the adjacency list*: `O(n)`  
*Iterative DFS (building parent array and order)*: `O(n)`  
*Post‑order processing*: each edge examined a constant number of times,
`O(n)`  

Memory consumption: adjacency list (`2·(n‑1)` entries) + a few `O(n)` integer
arrays → `O(n)`.

Both limits satisfy the constraints (`n ≤ 200 000`).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    it = iter(data)
    n = next(it)
    m = next(it)          # equals n-1
    t = next(it)

    required = [False] * (n + 1)
    for _ in range(t):
        v = next(it)
        required[v] = True

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = next(it)
        v = next(it)
        w = next(it)
        adj[u].append((v, w))
        adj[v].append((u, w))

    # iterative DFS to get parent, edge weight and order
    parent = [0] * (n + 1)
    w_parent = [0] * (n + 1)
    order = []
    stack = [1]
    parent[1] = -1          # root marker

    while stack:
        v = stack.pop()
        order.append(v)
        for to, w in adj[v]:
            if to == parent[v]:
                continue
            parent[to] = v
            w_parent[to] = w
            stack.append(to)

    cnt = [0] * (n + 1)
    ans = 0

    for v in reversed(order):
        cur = 1 if required[v] else 0
        for to, _ in adj[v]:
            if parent[to] == v:          # to is a child
                cur += cnt[to]
        cnt[v] = cur
        if v != 1:                       # skip root
            if cnt[v] > 0 and t - cnt[v] > 0:
                ans += w_parent[v]

    sys.stdout.write(str(ans))

if __name__ == "__main__":
    solve()
```
