**Solution Explanation**

For the given undirected weighted graph we have to build a set of edges of minimum total
weight such that all *t* command centres are in one connected component.
Vertices that are not command centres may be used as intermediate (Steiner) vertices.

The problem is exactly the **Steiner Tree** problem in graphs with a
small number of terminals ( *t* ≤ 10 ).
The classical exact algorithm for this situation is the
*Dreyfus‑Wagner* dynamic programming together with Dijkstra’s shortest‑path
relaxation.

--------------------------------------------------------------------

#### 1.   State

```
dp[mask][v] = minimum total weight of a tree which
              • connects all terminals whose bits are 1 in mask
              • the tree contains vertex v
```

`mask` – bitmask of size `t` ( `0 … 2^t‑1` ),  
`v`    – vertex number (`0 … n‑1`).

--------------------------------------------------------------------

#### 2.   Initialisation  

For every terminal `i` (its graph vertex is `term[i]`)

```
dp[ 1<<i ][ term[i] ] = 0          # no edge is needed, the tree is the single vertex
all other entries = INF
```

--------------------------------------------------------------------

#### 3.   Transition  

For a mask that contains at least two terminals we can split it into two
non‑empty disjoint sub‑masks `a` and `b` (`a ∪ b = mask`).

If a tree already connects the terminals of `a` **and** the terminals of `b`
and both trees contain the same vertex `v`,
we may unite the two trees at `v`.

```
dp[mask][v] = min over all proper non‑empty sub masks a of mask
              ( dp[a][v] + dp[mask ^ a][v] )
```

The split is examined only once per unordered pair (`a` , `mask^a`)  
by requiring `a < mask ^ a`.

--------------------------------------------------------------------

#### 4.   Shortest‑path relaxation  

After the merging step `dp[mask][*]` holds the cheapest cost of a tree that
**ends** in every vertex,
but the tree could be improved by adding ordinary graph edges.
Running a multi‑source Dijkstra where every vertex `v` starts with distance
`dp[mask][v]` spreads the costs through the graph and yields the true optimum
for this mask.

```
run Dijkstra with initial distances = dp[mask][*]
(the usual relaxation:  dist[to] = min( dist[to], dist[u] + w(u,to) ) )
```

For a single terminal mask this step simply produces the
shortest‑path distances from the terminal to all vertices – exactly what we need
for later merges.

--------------------------------------------------------------------

#### 5.   Result  

`full = (1<<t) - 1`   (all terminals)

```
answer = min_v dp[full][v]
```

The minimum over all possible last vertices is the weight of the cheapest
Steiner tree.

--------------------------------------------------------------------

#### 6.   Correctness Proof  

We prove that the algorithm outputs the minimum possible total weight.

---

##### Lemma 1  
For every mask and vertex `v` after the Dijkstra step  
`dp[mask][v]` equals the minimum weight of a connected subgraph that  

* contains all terminals of `mask`,
* contains vertex `v`,
* and is a tree (no cycles are required – any extra edge could be removed
  without increasing the weight).

**Proof.**  
Induction over the order in which masks are processed.

*Base –* mask with a single bit.  
Initially `dp[mask][term] = 0`, all other vertices are `INF`.  
Running Dijkstra computes the exact shortest‑path distances from that terminal,
i.e. the cheapest tree (a simple path) connecting the terminal with any vertex `v`.

*Induction step –* assume the statement true for all proper sub‑masks of `mask`.  
First the merging loop considers every partition `a , b = mask\a` and
updates `dp[mask][v]` with `dp[a][v] + dp[b][v]`.  
By induction hypothesis each summand is the optimum tree for its part that ends in `v`;
their union (they share only vertex `v`) is a tree connecting all terminals of `mask`
and also ends in `v`, therefore the minimum over all partitions is **at most**
the optimum value for `mask , v`.

After that Dijkstra is executed with exactly those values as starting distances.
Shortest‑path relaxation can only **decrease** distances and never creates cycles,
so every distance after Dijkstra is the weight of **some**
tree fulfilling the three conditions.
Consequently the obtained value is both a lower bound (cannot be larger than the optimum)
and an upper bound (realised by an explicit tree). ∎



##### Lemma 2  
For every mask the algorithm finally stores in `dp[mask][v]`
the optimal value described in Lemma&nbsp;1.

**Proof.**  
Lemma&nbsp;1 already shows that after processing a mask the stored values are optimal.
The algorithm never touches `dp[mask][*]` again (masks are processed in increasing order),
hence they remain optimal. ∎



##### Lemma 3  
`min_v dp[full][v]` equals the minimum possible total weight of a set of edges
that makes all command centres mutually reachable.

**Proof.**  
By Lemma&nbsp;2, for each vertex `v` the value `dp[full][v]` is the cheapest tree
that connects **all** terminals and contains `v`.  
Removing the requirement “contains `v`” can only lower (or keep) the cost,
therefore the minimum over all `v` is exactly the cheapest possible tree
connecting all terminals – i.e. the optimal solution of the original problem. ∎



##### Theorem  
The algorithm outputs the minimum total resource expenditure needed to build
a set of corridors that makes every command centre reachable from every other
command centre.

**Proof.**  
The algorithm outputs `min_v dp[full][v]`.  
By Lemma&nbsp;3 this quantity is precisely the optimal cost, therefore the output
is correct. ∎



--------------------------------------------------------------------

#### 7.   Complexity Analysis  

*Number of masks* : `2^t ≤ 1024`  
*Vertices*        : `n ≤ 100`  

*Merge step* – for every mask we iterate over all proper sub‑masks  
(`≤ 2^{|mask|}`) and over all vertices.

```
Σ_{mask}  (number of sub‑masks of mask) * n   =   O(3^t * n)
```

With `t ≤ 10` → at most `≈ 6·10^4 * 100 = 6·10^6` operations.

*Dijkstra* – executed once per mask.

```
2^t  * ( (n + m) log n )   ≤   1024 * ( (100 + 4950) * log 100 )
```

well below the limits.

*Memory* :

```
dp : 2^t * n  ≤ 1024 * 100  = 102 400  integers
graph adjacency list : O(m)
```

Both fit easily into the 256 MiB limit.

#### 8.   Reference Implementation  (Python 3)

```python
import sys
import heapq

INF = 10 ** 18

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    t = int(next(it))

    terminals = [int(next(it)) - 1 for _ in range(t)]

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        w = int(next(it))
        adj[u].append((v, w))
        adj[v].append((u, w))

    full = (1 << t) - 1
    dp = [[INF] * n for _ in range(full + 1)]

    # initialise single terminals
    for i, v in enumerate(terminals):
        dp[1 << i][v] = 0

    # process all masks
    for mask in range(1, full + 1):
        # combine two proper sub‑masks
        sub = (mask - 1) & mask
        while sub:
            other = mask ^ sub
            if other and sub < other:          # each unordered pair once
                dp_sub = dp[sub]
                dp_other = dp[other]
                dp_mask = dp[mask]
                for v in range(n):
                    cand = dp_sub[v] + dp_other[v]
                    if cand < dp_mask[v]:
                        dp_mask[v] = cand
            sub = (sub - 1) & mask

        # multi‑source Dijkstra to spread through edges
        heap = []
        for v in range(n):
            if dp[mask][v] < INF:
                heap.append((dp[mask][v], v))
        heapq.heapify(heap)

        while heap:
            dist, u = heapq.heappop(heap)
            if dist != dp[mask][u]:
                continue
            for to, w in adj[u]:
                nd = dist + w
                if nd < dp[mask][to]:
                    dp[mask][to] = nd
                    heapq.heappush(heap, (nd, to))

    answer = min(dp[full])
    print(answer)


if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
