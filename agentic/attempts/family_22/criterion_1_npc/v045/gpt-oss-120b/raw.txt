**Solution Explanation**

For every dish we have to choose a round (a positive integer)  

* the round number is at most `T`
* in each round at most `M` dishes can be placed
* for every requirement `a → b` we need `round[a] < round[b]`

All dishes have processing time `1`.  
The problem is exactly the feasibility of a unit‑time schedule on `M`
identical machines with precedence constraints and a given makespan `T`.

--------------------------------------------------------------------

#### 1.   Topological order, earliest and latest possible rounds  

The precedence graph is a DAG (otherwise the answer is `NO`).

*`earliest[i]`* – the smallest round in which dish `i` can be served.
```
earliest[i] = 1                     if i has no predecessor
earliest[i] = 1 + max( earliest[p] )   over all predecessors p of i
```
It is computed by a single pass over a topological order.

*`latest[i]`* – the largest round in which dish `i` can be served while still
finishing all its successors before round `T`.
Let `len_to_end[i]` be the length of the longest directed path
starting at `i` (including `i` itself).
```
len_to_end[i] = 1                     if i has no successor
len_to_end[i] = 1 + max( len_to_end[s] )   over all successors s of i
```
Again a single pass, this time on the reversed topological order.
If the longest path that contains `i` needs `len_to_end[i]` rounds,
the last possible round for `i` is

```
latest[i] = T - len_to_end[i] + 1
```

If for some dish `earliest[i] > latest[i]` the schedule is impossible.



--------------------------------------------------------------------

#### 2.   From intervals to a schedule  

Now each dish `i` is allowed to be placed in **any** round inside the
interval  

```
[ earliest[i] , latest[i] ]          (inclusive)
```

All dishes have the same processing time `1` and each round can host at most
`M` dishes.  
This is the classic “interval scheduling with resource capacity”.
A greedy algorithm works:

```
for round = 1 .. T
        insert into a min‑heap all dishes whose earliest == round
        (heap key = latest)
        take up to M dishes from the heap (the ones with smallest latest)
        assign them to the current round
        if a taken dish has latest < round -> impossible
```

Why does it work?  
It is exactly the EDF (earliest‑deadline‑first) rule for parallel machines.
If the algorithm ever fails, Hall’s condition for the bipartite
matching between dishes and round‑slots is violated, therefore no feasible
schedule exists. Conversely, if the algorithm succeeds we obtain a valid
assignment.

The algorithm runs in `O( (n+T) log n )` time and `O(n)` memory.



--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints “YES” and a correct schedule
iff such a schedule exists.

---

##### Lemma 1  
For every dish `i` any feasible schedule must place it in a round
`r` with `earliest[i] ≤ r ≤ latest[i]`.

**Proof.**  
`earliest[i]` is defined as `1 +` the length of the longest chain of
predecessors, therefore at least that many rounds are needed before `i`
can be served.  
`latest[i]` follows from the longest chain of successors: after serving `i`
we still need `len_to_end[i]-1` more rounds, all of them must be ≤ `T`. ∎



##### Lemma 2  
If the greedy EDF algorithm fails (cannot assign a dish because its
`latest` is already passed) then **no** feasible schedule exists.

**Proof.**  
Consider the first round `r` where the algorithm fails.
All dishes with `earliest ≤ r` are already in the heap.
The algorithm always picks the `M` dishes with smallest `latest`.
If a dish `x` is removed from the heap at round `r` and has `latest[x] < r`,
every schedule must place `x` no later than `latest[x]`, i.e. before round
`r`.  
But at round `r` there are already `M` other dishes (the ones the algorithm
chooses) that also need to be placed not later than `r` (their `latest`
is ≤ `latest[x] < r`).  
Thus at round `r` at least `M+1` dishes would have to be scheduled,
contradicting the capacity `M`. ∎



##### Lemma 3  
If the greedy EDF algorithm succeeds, the produced assignment satisfies
all constraints.

**Proof.**  
*Capacity*: at each round we assign at most `M` dishes by construction.  
*Precedence*: by Lemma&nbsp;1 every dish is placed inside its interval,
hence after all its predecessors (which have strictly smaller `earliest`),
so the round number is larger.  
*Bounds*: intervals are inside `[1,T]`, therefore all rounds are ≤ `T`. ∎



##### Lemma 4  
If a feasible schedule exists, the greedy EDF algorithm never fails.

**Proof.**  
Assume a feasible schedule `S` exists.
Consider the process of the algorithm round by round.
Induction hypothesis: after processing rounds `1 … r‑1` the algorithm
has assigned exactly the same set of dishes as `S` does in those rounds
(possibly different order inside a round).  
For round `r` the algorithm sees the same pool of still‑unassigned dishes
as `S` (all with `earliest ≤ r`).  
Both `S` and the algorithm must assign `M` (or fewer) of them to round `r`.
Because the algorithm always picks the dishes with smallest `latest`,
any dish that `S` puts into round `r` also has `latest ≥ r`
(otherwise `S` would violate Lemma&nbsp;1).  
Therefore the algorithm never tries to assign a dish whose `latest < r`,
so it cannot fail. ∎



##### Theorem  
The program outputs  

* “NO” iff no schedule satisfying all conditions exists;  
* otherwise “YES” and a schedule that satisfies all conditions.

**Proof.**  

*If the program prints “YES”* – it succeeded the greedy algorithm,
by Lemma&nbsp;3 the printed assignment is feasible.

*If the program prints “NO”* – there are two possible reasons  

1. The graph contains a directed cycle → obviously impossible.  
2. Some dish has `earliest > latest` → by Lemma&nbsp;1 no schedule can place it.  
3. The greedy algorithm fails → by Lemma&nbsp;2 no schedule exists.

Thus in every case “NO” is printed only when the instance is infeasible.

Conversely, if a feasible schedule exists, the graph is acyclic,
all intervals are non‑empty, and by Lemma&nbsp;4 the greedy algorithm never
fails, therefore the program prints “YES”. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Topological sorting* : `O(n + m)`  
*Computing earliest / latest* : `O(n + m)`  
*Greedy scheduling* : each dish is inserted and removed once from a heap  
`O( (n + T) log n )`  

Overall  

```
Time   : O( (n + m + T) log n )
Memory : O( n + m )
```

Both satisfy the limits easily.

#### 5.   Reference Implementation  (Python 3)

```python
import sys
import heapq

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    M = int(next(it))
    T = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    radj = [[] for _ in range(n)]
    indeg = [0] * n
    for _ in range(m):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        adj[a].append(b)
        radj[b].append(a)
        indeg[b] += 1

    # topological order
    from collections import deque
    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []
    while q:
        v = q.popleft()
        topo.append(v)
        for to in adj[v]:
            indeg[to] -= 1
            if indeg[to] == 0:
                q.append(to)
    if len(topo) != n:
        print("NO")
        return

    # earliest
    earliest = [1] * n
    for v in topo:
        for to in adj[v]:
            if earliest[to] < earliest[v] + 1:
                earliest[to] = earliest[v] + 1

    # longest path to a sink (len_to_end)
    len_to_end = [1] * n
    for v in reversed(topo):
        for pre in radj[v]:
            if len_to_end[pre] < len_to_end[v] + 1:
                len_to_end[pre] = len_to_end[v] + 1

    latest = [T - len_to_end[i] + 1 for i in range(n)]

    for i in range(n):
        if earliest[i] > latest[i] or earliest[i] > T or latest[i] < 1:
            print("NO")
            return

    # bucket dishes by earliest
    bucket = [[] for _ in range(T + 2)]
    for i in range(n):
        e = earliest[i]
        if e <= T:
            bucket[e].append(i)

    heap = []          # (latest, dish)
    assign = [0] * n
    for round_num in range(1, T + 1):
        for dish in bucket[round_num]:
            heapq.heappush(heap, (latest[dish], dish))
        cnt = 0
        while cnt < M and heap:
            dl, dish = heapq.heappop(heap)
            if dl < round_num:          # missed deadline
                print("NO")
                return
            assign[dish] = round_num
            cnt += 1

    if any(a == 0 for a in assign):
        print("NO")
        return

    print("YES")
    print(' '.join(map(str, assign)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
