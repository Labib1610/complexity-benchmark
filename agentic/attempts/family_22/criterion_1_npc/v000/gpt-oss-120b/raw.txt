**Solution Explanation**

For every job we have to choose a time slot `1 … T`

*   all precedence edges `a → b` require `slot[a] < slot[b]`
*   in each slot at most `M` jobs may be placed

The problem is exactly the feasibility problem for unit‑time jobs with
release times, deadlines and `M` identical parallel machines.
For this special case a greedy algorithm (earliest‑deadline‑first) is
optimal.



--------------------------------------------------------------------

#### 1.   From precedence to release times / deadlines  

For a job `v`

* `L[v]` – earliest slot it can be executed  
  (`release time`) – length of the longest directed path **ending** in `v`
  (counting vertices).  
  The source vertices have `L = 1`.

* `U[v]` – latest slot it may be executed  
  (`deadline`) – `T – (length of the longest directed path **starting** in v) + 1`.  
  A sink vertex has `U = T`.

Both values are obtained by a single topological order:

```
forward pass   (in topological order)   L[v] = max(L[p] + 1) over predecessors p
backward pass  (reverse topological)   R[v] = max(R[c] + 1) over successors c
U[v] = T - R[v] + 1
```

If for some vertex `L[v] > U[v]` the instance is impossible.



--------------------------------------------------------------------

#### 2.   Scheduling with release times and deadlines  

Now we have a set of jobs, each with

```
release time  = L[v]          (cannot start before this slot)
deadline      = U[v]          (must finish not later than this slot)
processing time = 1
M identical machines
```

The following algorithm is known to be optimal for this setting
(Earliest‑Deadline‑First, EDF).

```
for t = 1 .. T
        insert into a min‑heap all jobs with L == t   (key = deadline)
        repeat up to M times
                if heap empty : break
                take job with smallest deadline
                if its deadline < t : impossible
                assign this job to slot t
```

If after processing slots `1 … T` every job is assigned, we have a feasible
schedule; otherwise not.

Why does it work?  
Consider any moment `t`. All jobs that are already released (`L ≤ t`) must
be scheduled no later than their deadlines. EDF always picks the job with the
tightest deadline, therefore it never creates a situation where a job misses
its deadline while another still waiting could have been placed earlier.
For unit‑time jobs on identical parallel machines EDF is both necessary and
sufficient for feasibility.

The algorithm needs `O((n+T) log n)` time.  
`T` can be as large as `10^9`, but we never have to iterate over empty slots:
as soon as all jobs are scheduled we stop. The loop runs at most
`min(T, ceil(n/M) + max L)` iterations, well within limits.



--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the program prints a correct answer.

---

##### Lemma 1  
For every job `v` the value `L[v]` computed by the forward pass equals the
minimum possible slot of `v` in any feasible schedule.  
Analogously `U[v]` equals the maximum possible slot.

**Proof.**  
`L[v]` is defined as `1 + max length of a directed path ending in v`.  
Any schedule must respect the order of every edge, therefore all vertices
on such a path have to occupy distinct increasing slots, forcing `v` to be at
least that far from the start, i.e. `slot[v] ≥ L[v]`.  
Conversely, a schedule that puts each vertex exactly at its `L` (ignoring
capacity) respects all edges, so `L` is attainable. The argument for `U`
is symmetric, using paths that start in `v`. ∎



##### Lemma 2  
If a job is released at time `L` and has deadline `U`, then in any feasible
schedule it must be placed in a slot `t` with `L ≤ t ≤ U`.

**Proof.** Directly from Lemma&nbsp;1. ∎



##### Lemma 3 (EDF feasibility)  
Let a set of unit‑time jobs with release times `L` and deadlines `U` be given,
and let `M` identical machines be available.
The EDF algorithm described above succeeds (assigns all jobs) **iff**
there exists *any* feasible schedule.

**Proof.**  
*If part*: Assume EDF fails. The first failure happens at some slot `t`
when the algorithm extracts a job whose deadline `< t`. All jobs in the heap
have release `≤ t` (otherwise they would not be in the heap) and deadline
`< t`. At most `M·(t-1)` jobs can be placed before `t`. The heap contains at
least `M+1` such jobs (otherwise EDF would have taken at most `M` and not
failed). Hence more than `M·t` jobs would need slots `≤ t`, contradicting the
capacity `M` per slot. Therefore no feasible schedule exists.

*Only‑if part*: Suppose a feasible schedule exists.
Consider the earliest time `t` where EDF’s assignment differs from some
feasible schedule `S`. Let `j` be the job EDF puts at `t` (the one with the
smallest deadline among released jobs) and `k` the job that `S` puts at `t`
(if any). Because `j` has the smallest deadline, `deadline(j) ≤ deadline(k)`.
If `k` is not scheduled at `t` in EDF, it must be still unscheduled later,
but its deadline is not earlier than `j`’s, therefore EDF can swap `j` and `k`
without violating any deadline. Repeating this exchange yields a schedule
identical to EDF, proving EDF also succeeds. ∎



##### Lemma 4  
If the program outputs `YES` and the produced slots, they satisfy all
precedence constraints and the per‑slot capacity.

**Proof.**  
The algorithm only assigns a job after its release time `L`, therefore
`slot ≥ L`. By Lemma&nbsp;2 this guarantees all precedence constraints.
At each slot at most `M` jobs are taken from the heap, so capacity holds. ∎



##### Lemma 5  
If the program outputs `NO`, no feasible schedule exists.

**Proof.**  
`NO` is printed in two cases.

1. Some job has `L > U`. By Lemma&nbsp;2 such a job cannot be placed at any
   slot, so schedule impossible.

2. EDF fails (heap contains a job with deadline `< current slot`). By
   Lemma&nbsp;3 this implies infeasibility. ∎



##### Theorem  
The program prints `YES` and a valid assignment exactly when a feasible
schedule exists; otherwise it prints `NO`.

**Proof.**  
*If* a feasible schedule exists, Lemma&nbsp;1 gives finite `L,U` with `L≤U`.
EDF therefore succeeds (Lemma&nbsp;3) and the program outputs `YES`.  
By Lemma&nbsp;4 the printed assignment is valid.

*Only if* the program prints `YES`, Lemma&nbsp;4 shows the assignment is
valid, hence a feasible schedule exists.

If the program prints `NO`, Lemma&nbsp;5 shows no feasible schedule exists. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Topological order & longest paths* : `O(n + m)`  
*Scheduling loop* : each job is inserted once and extracted once from the
heap → `O(n log n)`.  
The loop runs at most `min(T, ceil(n/M) + max L)` iterations, never more than
`O(n/M + T)` but the heap work dominates.

Memory consumption: adjacency lists `O(n+m)`, arrays `O(n)`, heap `O(n)`.

Both limits satisfy the given constraints.



--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys
import threading
def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    M = int(next(it))
    T = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n)]
    radj = [[] for _ in range(n)]
    indeg = [0]*n
    outdeg = [0]*n
    for _ in range(m):
        a = int(next(it))-1
        b = int(next(it))-1
        adj[a].append(b)
        radj[b].append(a)
        indeg[b] += 1
        outdeg[a] += 1

    # topological order
    from collections import deque
    q = deque([i for i in range(n) if indeg[i]==0])
    topo = []
    while q:
        v = q.popleft()
        topo.append(v)
        for nb in adj[v]:
            indeg[nb] -= 1
            if indeg[nb]==0:
                q.append(nb)
    if len(topo)!=n:
        print("NO")
        return

    # forward longest path (L)
    L = [1]*n
    for v in topo:
        lv = L[v]
        for nb in adj[v]:
            if L[nb] < lv + 1:
                L[nb] = lv + 1

    # backward longest path (R)
    R = [1]*n
    for v in reversed(topo):
        rv = R[v]
        for p in radj[v]:
            if R[p] < rv + 1:
                R[p] = rv + 1

    U = [T - R[i] + 1 for i in range(n)]

    for i in range(n):
        if L[i] > U[i] or L[i] > T or U[i] < 1:
            print("NO")
            return

    # bucket jobs by release time
    buckets = [[] for _ in range(T+2)]
    for i in range(n):
        buckets[L[i]].append(i)

    import heapq
    heap = []          # (deadline, job)
    slot_of = [0]*n
    assigned = 0
    t = 1
    while t <= T and assigned < n:
        for job in buckets[t]:
            heapq.heappush(heap, (U[job], job))
        cnt = 0
        while cnt < M and heap:
            deadline, job = heapq.heappop(heap)
            if deadline < t:
                print("NO")
                return
            slot_of[job] = t
            assigned += 1
            cnt += 1
        t += 1

    if assigned < n:
        print("NO")
        return

    print("YES")
    print(' '.join(str(slot_of[i]) for i in range(n)))

if __name__ == "__main__":
    threading.Thread(target=solve).start()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
