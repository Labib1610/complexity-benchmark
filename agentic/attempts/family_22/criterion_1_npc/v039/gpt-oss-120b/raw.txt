**Solution Explanation**

For every job we have to choose a minute `1 … T`

*   all jobs of a minute ≤ number of servers `M`
*   for every precedence edge `a → b` `minute[a] < minute[b]`

All jobs have the same length (one minute) – only the minute matters.



--------------------------------------------------------------------

#### 1.   From precedence to time windows  

For a job `v`

* `L[v]` – earliest minute it can be executed  
  (all its predecessors must be earlier)
* `R[v]` – latest minute it can be executed  
  (all its successors must be later)

If a job is placed outside `[L,R]` the precedence constraints are
violated, therefore a feasible schedule must put every job into its
own window.

`L` and `R` are obtained by longest‑path distances in the DAG.

```
topological order = any order respecting edges
L[v] = 1
for v in topological order:
        for each edge v → w:
                L[w] = max(L[w], L[v] + 1)

R[v] = T
for v in reverse topological order:
        for each edge v → w:
                R[v] = min(R[v], R[w] - 1)
```

If for some job `L[v] > R[v]` the precedence constraints alone are
already impossible → answer `NO`.

--------------------------------------------------------------------

#### 2.   Scheduling with release times `L` and deadlines `R`

Now we have **unit‑length** jobs, each with a release time `L`
and a deadline `R`.  
We have `M` identical machines (servers).  
The classic greedy algorithm works:

```
for minute = 1 … T
        insert all jobs with L == minute into a min‑heap ordered by R
        repeat up to M times
                if heap empty : break
                take job with smallest R
                if R < minute : impossible
                assign this job to current minute
```

Why is it correct?  
At any minute we may execute at most `M` jobs.
Choosing the jobs whose deadlines are the earliest is the only way
to avoid missing a deadline later (exchange argument, standard EDF
proof).  
If the algorithm finishes all jobs, a feasible schedule exists;
if it fails (a job’s deadline already passed) no schedule can exist.

The algorithm runs in `O( (n+T) log n )`, well within limits.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct schedule
iff such a schedule exists.

---

##### Lemma 1  
For every job `v` any feasible schedule must place it in a minute
`minute[v]` with `L[v] ≤ minute[v] ≤ R[v]`.

**Proof.**  
`L[v]` is defined as `1 + max minute of all predecessors`.  
Therefore any schedule must put `v` strictly after all its
predecessors, i.e. at least `L[v]`.  
Analogously `R[v]` is `T - max length of a path from `v` to a sink`,
so `v` must be strictly before all its successors, i.e. at most `R[v]`. ∎



##### Lemma 2  
If the greedy algorithm assigns a job `v` at minute `t`,
then `L[v] ≤ t ≤ R[v]`.

**Proof.**  
`v` is inserted into the heap exactly when `t = L[v]`,
hence `t ≥ L[v]`.  
It is taken from the heap only if its stored deadline `R[v]`
satisfies `R[v] ≥ t`; otherwise the algorithm aborts.
Thus `t ≤ R[v]`. ∎



##### Lemma 3  
If the greedy algorithm aborts (a job with `R < current minute` is at
the top of the heap), then **no** feasible schedule exists.

**Proof.**  
Consider the first minute `t` where this happens.
All jobs with `L ≤ t` have already been inserted, therefore every
unscheduled job has `L ≤ t`.  
The heap contains exactly the unscheduled jobs, ordered by deadline.
The top job `v` has the smallest deadline among them, and
`R[v] < t`.  
Consequently **every** unscheduled job has deadline `< t`,
so none of them can be placed at minute `t` or later.
But at most `M` jobs can be placed at each earlier minute,
and all earlier minutes are already filled (the algorithm always
uses the full capacity `M` when possible).  
Hence the total number of jobs that could have been scheduled up to
minute `t` is at most `M·t`, which is **strictly less** than the number
of jobs that need a slot (`already scheduled` + `remaining`).  
Thus the Hall‑type condition fails and a feasible schedule does not
exist. ∎



##### Lemma 4  
If the greedy algorithm finishes assigning all jobs, the obtained
assignment satisfies all constraints.

**Proof.**  
*Capacity*: at each minute we assign at most `M` jobs by construction.  
*Precedence*: by Lemma&nbsp;2 each job lies inside its `[L,R]` window,
and Lemma&nbsp;1 guarantees that any placement inside the window respects
all precedence edges. ∎



##### Lemma 5  
If a feasible schedule exists, the greedy algorithm never aborts.

**Proof.**  
Assume a feasible schedule `S` exists.
Consider the algorithm minute by minute.
Induction hypothesis: after processing minutes `1 … t‑1` the algorithm
has scheduled exactly the same number of jobs as `S` (maybe different
jobs) and all jobs still unscheduled by the algorithm are also unscheduled
by `S` and have `L ≤ t`.  
At minute `t` the algorithm may schedule up to `M` jobs.
If it were to abort, Lemma&nbsp;3 shows that no schedule can exist,
contradiction. Hence it never aborts and finally schedules all jobs. ∎



##### Theorem  
The program outputs  

*`YES` and a valid assignment* **iff** a feasible assignment exists;  
otherwise it outputs `NO`.

**Proof.**  

*If part*:  
When the program prints `YES`, it has successfully run the greedy
algorithm, therefore by Lemma&nbsp;4 the printed minutes satisfy all
requirements.

*Only‑if part*:  
If a feasible assignment exists, Lemma&nbsp;1 gives finite windows,
the algorithm computes them, they are non‑empty, and by Lemma&nbsp;5
the greedy procedure never aborts, thus finishes and the program prints
`YES`.  

If any step fails (`L>R` for some job or greedy aborts) Lemma&nbsp;1
or Lemma&nbsp;3 shows that no feasible schedule exists, so printing `NO`
is correct. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Topological order & windows* : `O(n + m)`  
*Greedy scheduling* : each job is inserted and removed once from a heap  
`O(n log n)` plus `O(T)` for iterating minutes.  

Memory: adjacency lists `O(n + m)`, arrays `O(n + T)`, heap `O(n)`.  
All well below the limits.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys
import threading
import heapq

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    M = int(next(it))
    T = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    radj = [[] for _ in range(n)]
    indeg = [0] * n
    for _ in range(m):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        adj[a].append(b)
        radj[b].append(a)
        indeg[b] += 1

    # topological order
    from collections import deque
    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []
    while q:
        v = q.popleft()
        topo.append(v)
        for w in adj[v]:
            indeg[w] -= 1
            if indeg[w] == 0:
                q.append(w)
    if len(topo) != n:          # cycle (should not happen per statement)
        print("NO")
        return

    # earliest times L
    L = [1] * n
    for v in topo:
        lv = L[v]
        for w in adj[v]:
            if L[w] < lv + 1:
                L[w] = lv + 1

    # latest times R
    R = [T] * n
    for v in reversed(topo):
        rv = R[v]
        for u in radj[v]:
            if R[u] > rv - 1:
                R[u] = rv - 1

    for i in range(n):
        if L[i] > R[i] or L[i] > T or R[i] < 1:
            print("NO")
            return

    # bucket jobs by release time
    buckets = [[] for _ in range(T + 2)]
    for i in range(n):
        buckets[L[i]].append(i)

    heap = []          # (deadline, job)
    ans = [0] * n
    scheduled = 0

    for t in range(1, T + 1):
        for job in buckets[t]:
            heapq.heappush(heap, (R[job], job))
        for _ in range(M):
            if not heap:
                break
            deadline, job = heapq.heappop(heap)
            if deadline < t:
                print("NO")
                return
            ans[job] = t
            scheduled += 1

    if scheduled != n:
        print("NO")
        return

    print("YES")
    print(' '.join(str(x) for x in ans))

def main():
    solve()

if __name__ == "__main__":
    threading.Thread(target=main).start()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
