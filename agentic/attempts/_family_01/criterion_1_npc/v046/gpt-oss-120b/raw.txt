**Solution Explanation**

For every technician we have to choose one of three shifts  
(1 – Morning, 2 – Swing, 3 – Night).  
Two technicians that are *flagged* may **not** receive the same shift.
The flagged pairs form an undirected graph `G`.  
The task is exactly the classic **3‑colouring** problem:

*assign a colour 1,2,3 to every vertex so that adjacent vertices obtain
different colours.*

`n ≤ 40`, therefore an exponential back‑tracking search with good
pruning easily fits into the limits.



--------------------------------------------------------------------

#### 1.   Data representation  

* vertices are numbered `0 … n‑1`
* `adj[v]` – 64‑bit integer, bit `u` is set iff `{v,u}` is a flagged pair  
  (`n ≤ 40` → one 64‑bit integer is enough)
* `color[v]` – `0` = not coloured yet, otherwise `1,2,3`
* `allowed[v]` – 3‑bit mask, bit `c‑1` (`c = 1,2,3`) tells whether colour `c`
  is still possible for `v`.  
  Initially `allowed[v] = 0b111` for all vertices.

--------------------------------------------------------------------

#### 2.   Backtracking with forward checking  

```
dfs(coloured):
    if coloured == n:   success
    choose an uncoloured vertex v with the smallest |allowed[v]|   (MRV)
    if |allowed[v]| == 0:   dead end
    for every colour c allowed for v:
        colour v with c
        for every still uncoloured neighbour u of v:
                if c is still allowed for u:
                        delete c from allowed[u]          (forward checking)
                        remember that we changed u
        if dfs(coloured+1) succeeds → propagate success
        undo all changes (restore allowed masks, colour[v]=0)
    return failure
```

* **MRV (minimum remaining values)** – picking the vertex with the fewest
  still possible colours reduces the branching factor dramatically.
* **Forward checking** – after fixing a colour we immediately forbid this
  colour for all still uncoloured neighbours.
  If any neighbour loses its last possible colour we backtrack instantly.
* The recursion depth never exceeds `n = 40`, well below Python’s limit.

All operations are bitwise, therefore very fast.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct roster
iff a valid roster exists, otherwise prints `NO`.

---

##### Lemma 1  
During the execution of `dfs` the invariant holds:

> For every vertex `v`  
> `color[v] = 0`  **iff**  `v` is uncoloured, and  
> `allowed[v]` contains exactly the colours that can still be given to `v`
> without creating a conflict with already coloured neighbours.

**Proof.**  
*Initialization*: all vertices are uncoloured, `allowed[v]=0b111`,
which obviously satisfies the invariant.

*Induction step*: assume the invariant holds before a recursive call.
We colour a vertex `v` with colour `c`.  
For each still uncoloured neighbour `u` we delete `c` from `allowed[u]`.
No other vertex is affected.
Thus after the deletions `allowed[u]` contains precisely the colours that
do not conflict with the newly coloured neighbour `v`.  
All other vertices keep their previous `allowed` sets, which were correct
by the induction hypothesis.  
When we backtrack we restore the deleted bits, returning to the previous
state, therefore the invariant also holds after backtracking. ∎



##### Lemma 2  
If `dfs` reaches the line `if coloured == n` then the current
`color[ ]` array is a proper 3‑colouring of the whole graph.

**Proof.**  
All `n` vertices are coloured, and by Lemma&nbsp;1 each vertex’s colour
does not conflict with any already coloured neighbour.
Since every edge connects two vertices that are coloured at some moment,
the invariant guarantees that the two endpoints have different colours.
Hence the whole assignment is proper. ∎



##### Lemma 3  
If a partial assignment can be extended to a full proper colouring,
`dfs` never discards it by backtracking.

**Proof.**  
Consider a recursive call where the current partial assignment *is*
extendable.  
The algorithm chooses an uncoloured vertex `v` and iterates over all
colours still present in `allowed[v]`.  
Because the assignment is extendable, at least one of those colours
appears in some full solution; call it `c*`.  
When the algorithm tries `c*`, forward checking only removes `c*` from
neighbours that are still uncoloured. In the extendable full solution those
neighbours are coloured with a colour different from `c*`, therefore they
still have at least one allowed colour left. Consequently no neighbour
gets an empty `allowed` set, the recursive call proceeds, and the extendable
solution remains reachable.  
Thus the algorithm never backtracks *away* from every possible extension. ∎



##### Lemma 4  
If the graph is 3‑colourable, `dfs(0)` returns `True`.

**Proof.**  
Take any proper 3‑colouring `C`.  
We show by induction on the recursion depth that the algorithm can follow
choices consistent with `C` and finally reaches the success state.

*Base*: depth `0` – empty assignment, trivially consistent with `C`.

*Induction step*: assume the current recursive call’s partial assignment
coincides with `C` on the already coloured vertices.
The algorithm selects a vertex `v`.  
In `C`, `v` has colour `c = C(v)`.  
Because all already coloured neighbours keep their colours from `C`,
`c` is still present in `allowed[v]` (Lemma&nbsp;1).  
When the algorithm tries colour `c`, forward checking removes `c` only from
neighbours that are still uncoloured; in `C` those neighbours have colours
different from `c`, therefore they keep at least one allowed colour.
Thus the recursive call after fixing `c` is again consistent with `C`.
By induction we can continue until all vertices are coloured, where
Lemma&nbsp;2 yields success. ∎



##### Lemma 5  
If `dfs(0)` returns `True`, the produced assignment is a proper 3‑colouring.

**Proof.**  
`True` is returned only when the base case `coloured == n` is reached.
By Lemma&nbsp;2 the assignment at that moment is a proper colouring. ∎



##### Theorem  
The program outputs  

* `YES` and a valid roster **iff** a valid roster exists,  
* otherwise outputs `NO`.

**Proof.**  

*If part*:  
If a valid roster exists, the graph is 3‑colourable.
By Lemma&nbsp;4 `dfs(0)` returns `True`.  
The program prints `YES` and the colours stored in `color[ ]`.
By Lemma&nbsp;5 this assignment is a proper roster.

*Only‑if part*:  
If the program prints `YES`, `dfs(0)` returned `True`,
hence by Lemma&nbsp;5 the printed assignment is a proper roster,
so a valid roster exists.

If the program prints `NO`, `dfs(0)` returned `False`.  
Assume for contradiction that a proper roster existed.
Then the graph would be 3‑colourable, contradicting Lemma&nbsp;4.
Therefore no roster exists. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*`n ≤ 40`*  

Let `T` be the number of recursive calls actually performed.
Each call

* selects a vertex – `O(n)`
* iterates over at most 3 colours
* updates neighbours – each edge examined at most once per colour assignment,
  i.e. `O(deg(v))` bit operations.

Overall time `O(T · n)`.  
In practice, MRV and forward checking prune the search tree heavily;
for `n = 40` the program finishes well within the 2 s limit.

Memory consumption:

* adjacency masks: `n` integers → `O(n)`
* colour array, allowed masks: `O(n)`

Total `O(n)` ≤ a few hundred bytes, far below the 256 MB limit.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    # 0 = uncoloured, 1..3 = colour
    color = [0] * n
    # 3-bit mask, bit 0 -> colour 1, bit 1 -> colour 2, bit 2 -> colour 3
    allowed = [0b111] * n

    # pre‑compute popcount for 0..7 (optional)
    popcnt = [bin(i).count('1') for i in range(8)]

    def dfs(coloured: int) -> bool:
        if coloured == n:
            return True

        # MRV: vertex with smallest number of allowed colours
        v = -1
        best = 4
        for i in range(n):
            if color[i] == 0:
                cnt = popcnt[allowed[i]]
                if cnt < best:
                    best = cnt
                    v = i
                    if cnt == 1:
                        break
        if best == 0:          # no colour possible
            return False

        mask = allowed[v]
        # try colours 1,2,3
        for c in (1, 2, 3):
            bit = 1 << (c - 1)
            if mask & bit:
                # assign
                color[v] = c
                changed = []          # neighbours whose mask we modify
                neigh = adj[v]
                while neigh:
                    lsb = neigh & -neigh
                    u = (lsb.bit_length() - 1)
                    if color[u] == 0 and (allowed[u] & bit):
                        allowed[u] &= ~bit
                        changed.append(u)
                    neigh ^= lsb
                if dfs(coloured + 1):
                    return True
                # undo
                for u in changed:
                    allowed[u] |= bit
                color[v] = 0
        return False

    if dfs(0):
        out = ['YES', ' '.join(str(c) for c in color)]
    else:
        out = ['NO']
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
