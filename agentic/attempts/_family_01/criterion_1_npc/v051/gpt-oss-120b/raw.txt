**Solution Explanation**

For every instrument we have to choose one of three booms.
Two instruments that interfere must obtain different booms.
The problem is exactly the *graph 3‑colouring* problem:

* vertices – instruments `1 … n`
* edges    – interfering pairs  
* colour   – chosen boom (`1,2,3`)

We have to find a proper 3‑colouring or decide that none exists.



--------------------------------------------------------------------

#### 1.  Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices)
* `assigned[v]` – `-1` if not coloured yet, otherwise `0,1,2`
* `allowed[v]` – bit mask of colours still possible for `v`  
  bit `c` (`1<<c`) is set  **iff** colour `c` is still allowed.  
  Initially `allowed[v] = 0b111 = 7` for every vertex.

`n ≤ 40`, therefore all arrays are tiny.



--------------------------------------------------------------------

#### 2.  Recursive backtracking with forward checking  

The algorithm is a depth‑first search that colours vertices one after
another.

```
dfs(coloured_vertices):
    if coloured_vertices == n:   success
    choose an uncoloured vertex v with the smallest number of allowed colours
    if allowed[v] == 0:           dead end → backtrack
    for every colour c that is still allowed for v
          (and not already used by an already coloured neighbour)
          assign colour c to v
          remove colour c from the allowed‑sets of all still uncoloured neighbours
          if no neighbour lost its last possible colour
                 recurse
          undo all changes (backtrack)
    failure
```

* **MRV heuristic** – *minimum remaining values* –  
  the vertex with the fewest still possible colours is selected.
  This gives strong pruning, especially for dense graphs.

* **Forward checking** – after fixing a colour for `v` we delete this colour
  from the neighbour’s allowed sets.
  If a neighbour becomes empty we can backtrack immediately,
  without deeper recursion.

* **Undo information** – all modifications of `allowed[·]` are stored
  (`changes` list) and restored when the recursion returns.



--------------------------------------------------------------------

#### 3.  Correctness Proof  

We prove that the algorithm prints `YES` and a correct assignment
iff a feasible assignment exists.

---

##### Lemma 1  
During the execution of `dfs` the invariant holds:

*For every vertex `x`*  

* if `assigned[x] = c` then colour `c` is allowed for `x` (`allowed[x] = 1<<c`);
* if `assigned[x] = -1` then `allowed[x]` contains exactly the colours that are
  still possible for `x` respecting all already fixed colours.*

**Proof.**  
Initially all vertices are unassigned and `allowed = 0b111`, the invariant
holds.

When a colour `c` is assigned to a vertex `v` the algorithm

* sets `assigned[v]=c` and `allowed[v]=1<<c` – the first part of the invariant
  holds for `v`;
* for every still uncoloured neighbour `u` removes `c` from `allowed[u]`.
  All other colours stay possible, therefore the second part of the invariant
  stays true for those neighbours.
* No other vertex is touched.

When backtracking the algorithm restores the old masks from the saved list,
returning the data structures to the exact state before the assignment.
Thus the invariant is preserved. ∎



##### Lemma 2  
Whenever the algorithm recurses from a state `S` to a child state `S'`,
every proper 3‑colouring that extends the partial colouring of `S`
also extends the partial colouring of `S'`.

**Proof.**  
`S'` is obtained from `S` by fixing a colour `c` for a vertex `v`
that is still allowed in `S`.  
All proper colourings extending `S` may colour `v` with any colour from
`allowed_S[v]`. Choosing `c` is one of those possibilities,
hence every proper extension of `S` can be continued with the same colour
`c` and therefore also extends `S'`. ∎



##### Lemma 3  
If the algorithm reaches `coloured_vertices == n` it has produced a proper
3‑colouring.

**Proof.**  
All vertices are assigned. By Lemma&nbsp;1 each vertex has exactly the colour
stored in `assigned`.  
When a colour was assigned, the algorithm removed this colour from every
still uncoloured neighbour, therefore no edge connects two vertices with the
same colour. Hence the assignment is proper. ∎



##### Lemma 4  
If the algorithm returns *failure* from a state `S`,
no proper 3‑colouring extends the partial colouring of `S`.

**Proof.**  
Failure can happen for two reasons.

1. Some vertex has `allowed = 0`.  
   By Lemma&nbsp;1 this vertex has no colour compatible with the already fixed
   neighbours, therefore no extension exists.

2. All colour choices for the selected vertex `v` have been tried and each
   led to a recursive call that returned failure.  
   By the induction hypothesis (recursion depth is smaller) each of those
   recursive calls proves that no proper colouring exists extending the
   corresponding child state.  
   By Lemma&nbsp;2 any proper colouring extending `S` must extend one of those
   child states – contradiction. ∎



##### Lemma 5  
If a proper 3‑colouring exists, the algorithm eventually reaches the
`coloured_vertices == n` state.

**Proof.**  
Consider any proper colouring `C`.  
Starting from the initial state, follow the recursion:
whenever the algorithm chooses a vertex `v`, colour `c = C(v)` is still
allowed (otherwise `C` would already violate an edge, impossible).
Thus the branch that tries colour `c` is explored.
Because the algorithm never discards a branch that could still lead to a
proper colouring (Lemma&nbsp;4), the recursion can follow the choices of `C`
until all vertices are coloured, reaching the success state. ∎



##### Theorem  
The program outputs  

*`YES` and a valid assignment* **iff** a feasible assignment exists,  

otherwise it outputs `NO`.

**Proof.**  

*If the program prints `YES`* – it reached the success state,
by Lemma&nbsp;3 the printed assignment is a proper 3‑colouring,
hence a feasible assignment exists.

*If a feasible assignment exists* – by Lemma&nbsp;5 the algorithm will
reach the success state, therefore it will output `YES`.  
If it never reaches success, by Lemma&nbsp;4 no feasible assignment exists,
so it correctly prints `NO`. ∎



--------------------------------------------------------------------

#### 4.  Complexity Analysis  

`n ≤ 40`.

*Choosing the next vertex* – `O(n)` scan.  
*Propagation* – for a chosen vertex `v` we inspect all its neighbours,
`deg(v) ≤ n-1`.  

In each recursive level the work is `O(n + deg(v)) = O(n)`.  
The recursion depth is at most `n`.

The algorithm is exponential in the worst case (graph 3‑colourability is
NP‑complete), but the strong pruning (MRV + forward checking) makes it
fast for `n = 40`. In practice it finishes well within the 2 s limit.

#### 5.  Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        if u == v:
            continue
        adj[u].append(v)
        adj[v].append(u)

    # 0,1,2 are colours; mask 1<<c
    allowed = [0b111] * n
    assigned = [-1] * n

    # ------------------------------------------------------------
    def dfs(coloured_cnt: int) -> bool:
        if coloured_cnt == n:
            return True

        # MRV: vertex with fewest allowed colours
        v = -1
        best = 4
        for i in range(n):
            if assigned[i] == -1:
                cnt = allowed[i].bit_count()
                if cnt < best:
                    best = cnt
                    v = i
                    if cnt == 1:
                        break
        if v == -1:          # should not happen
            return True
        if best == 0:
            return False

        mask = allowed[v]
        for c in range(3):
            if not (mask & (1 << c)):
                continue
            # conflict with already coloured neighbours?
            conflict = False
            for nb in adj[v]:
                if assigned[nb] == c:
                    conflict = True
                    break
            if conflict:
                continue

            # assign colour c to v
            assigned[v] = c
            old_allowed_v = allowed[v]
            allowed[v] = 1 << c
            changes = []
            fail = False

            for nb in adj[v]:
                if assigned[nb] == -1:
                    if allowed[nb] & (1 << c):
                        old = allowed[nb]
                        allowed[nb] &= ~(1 << c)
                        changes.append((nb, old))
                        if allowed[nb] == 0:
                            fail = True
                            break

            if not fail:
                if dfs(coloured_cnt + 1):
                    return True

            # backtrack
            for nb, old in changes:
                allowed[nb] = old
            allowed[v] = old_allowed_v
            assigned[v] = -1

        return False
    # ------------------------------------------------------------

    possible = dfs(0)

    if not possible:
        print("NO")
    else:
        print("YES")
        # convert 0,1,2 -> 1,2,3
        out = [str(c + 1) for c in assigned]
        print(" ".join(out))


if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input / output format.
