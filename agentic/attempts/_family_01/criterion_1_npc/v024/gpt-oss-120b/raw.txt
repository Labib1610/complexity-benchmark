**Solution Explanation**

For every tower we have to choose one of three frequencies  
(1, 2, 3) such that adjacent towers never obtain the same frequency.
The problem is exactly the *graph 3‑coloring* problem.

`n ≤ 40`, therefore an exponential back‑tracking search is easily fast
enough if we prune wisely.

--------------------------------------------------------------------

#### 1.   Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices).  
* `order` – vertices sorted by decreasing degree, i.e. the vertex with
  most neighbours is coloured first – a classic heuristic that reduces
  the search tree.
* `color[v]` – current colour of vertex `v` (`0` = not coloured yet).

--------------------------------------------------------------------

#### 2.   Back‑tracking  

```
dfs(pos):
    if pos == n:               # all vertices coloured
        return True
    v = order[pos]             # vertex to colour now
    for c in (1,2,3):
        if no neighbour of v already has colour c:
            color[v] = c
            if dfs(pos+1):
                return True
            color[v] = 0       # undo
    return False               # none of the three colours works
```

The test *“no neighbour already has colour c”* is `O(deg(v))`.  
With `n ≤ 40` the whole search finishes far below the time limit.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints **YES** and a correct colouring
iff such a colouring exists.

---

##### Lemma 1  
During the execution of `dfs(pos)` the array `color` is a proper
partial colouring: no two already coloured adjacent vertices share the
same colour.

**Proof.**  
Initially all entries are `0`, the statement holds.
When a colour `c` is assigned to vertex `v`, the algorithm first checks
that none of its neighbours already has colour `c`. Therefore after the
assignment the property still holds. Undoing a colour obviously does
not break it. ∎



##### Lemma 2  
If `dfs(pos)` returns `True`, the final `color` array is a proper
3‑colouring of the whole graph.

**Proof.**  
`True` is returned only when `pos == n`, i.e. every vertex received a
colour. By Lemma&nbsp;1 the partial colouring is proper at every step,
hence also after the last assignment. ∎



##### Lemma 3  
If a proper 3‑colouring exists, `dfs(0)` returns `True`.

**Proof.**  
Consider any fixed proper 3‑colouring `C`.  
The recursion tries colours for the vertices in the order `order`.
When it reaches vertex `v = order[pos]`, all vertices placed earlier in
`order` are already coloured exactly as in `C` (induction hypothesis):
* if the algorithm tries the colour `C(v)`, the neighbour test succeeds,
  because `C` is proper;
* therefore the branch that follows `C(v)` is explored.
Thus the recursion can follow the whole colouring `C` and reaches the
leaf `pos == n`, where it returns `True`. ∎



##### Lemma 4  
If `dfs(0)` returns `False`, no proper 3‑colouring exists.

**Proof.**  
Assume a proper colouring existed. By Lemma&nbsp;3 the algorithm would
find it and return `True`. Contradiction. ∎



##### Theorem  
The program outputs  

* “YES” and a list of frequencies that is a valid assignment **iff**
  such an assignment exists,
* otherwise it outputs “NO”.

**Proof.**  
*If the program prints “YES”* – this happens only when `dfs(0)` returns
`True`. By Lemma&nbsp;2 the printed colours form a proper 3‑colouring,
hence a valid assignment exists.

*If a valid assignment exists* – by Lemma&nbsp;3 `dfs(0)` returns
`True`, the program prints “YES” and the colours found by the search,
which are valid by Lemma&nbsp;2.

*If the program prints “NO”* – `dfs(0)` returned `False`. By Lemma&nbsp;4
no proper 3‑colouring exists, therefore no valid assignment exists. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Let `Δ` be the maximum degree.*

* Building adjacency lists: `O(n + m)`.
* The recursion depth is `n ≤ 40`.
* At each level we try at most 3 colours and test at most `Δ` neighbours.
  In the worst case the search explores all `3^n` colourings,
  but with `n = 40` this bound is far below the time limit because
  the degree ordering prunes the tree heavily.
* Practically the running time is well under a millisecond for the given
  limits.

Memory consumption: adjacency lists `O(n + m)` plus a few arrays of size
`n` → `O(n + m) ≤ O(40^2)`, far below the 256 MB limit.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    # order vertices by decreasing degree (heuristic)
    order = sorted(range(n), key=lambda x: -len(adj[x]))
    color = [0] * n                     # 0 = uncoloured, else 1..3

    def dfs(pos: int) -> bool:
        if pos == n:
            return True
        v = order[pos]
        # try colours 1,2,3
        for c in (1, 2, 3):
            ok = True
            for nb in adj[v]:
                if color[nb] == c:
                    ok = False
                    break
            if not ok:
                continue
            color[v] = c
            if dfs(pos + 1):
                return True
            color[v] = 0
        return False

    if dfs(0):
        out = ['YES', ' '.join(str(color[i]) for i in range(n))]
        sys.stdout.write('\n'.join(out))
    else:
        sys.stdout.write('NO')

if __name__ == "__main__":
    solve()
```
