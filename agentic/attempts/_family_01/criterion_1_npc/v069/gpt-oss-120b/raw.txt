**Solution Explanation**

The assets and the “critical links” form an undirected graph `G`.
We have to colour every vertex with one of three colours
(`1,2,3`) such that adjacent vertices obtain different colours.
That is exactly the *graph 3‑colouring* problem.

`n ≤ 40`, therefore an exponential backtracking with good pruning
solves the task easily within the limits.



--------------------------------------------------------------------

#### 1.   Data representation  

* vertices are numbered `0 … n‑1`
* `adj[v]` – 64‑bit integer, bit `u` is set iff `v` is adjacent to `u`
* `col[v]` – current colour (`-1` = uncoloured)
* `avail[v]` – 3‑bit mask of still possible colours for `v`
  (`bit 0 → colour 1`, `bit 1 → colour 2`, `bit 2 → colour 3`)

Initially `avail[v] = 0b111` for every vertex.



--------------------------------------------------------------------

#### 2.   Branching rule  

At each step we pick an **uncoloured vertex with the smallest
`popcount(avail[v])`** (most constrained, DSATUR idea).  
If this number is `0` the current partial colouring is impossible.

For the chosen vertex we try every colour that is still allowed
(`avail[v]` bits).  
When a colour `c` is fixed:

```
col[v] = c
for every neighbour u of v that is still uncoloured:
        remove colour c from avail[u]
```

If after the removal some neighbour obtains `avail[u] == 0`,
the branch is dead and we backtrack immediately.

All modifications of `avail` are stored on a stack
(`(u, old_mask)`) so that they can be restored when we backtrack.



--------------------------------------------------------------------

#### 3.   Termination  

*Success* – all vertices are coloured → we output the colours.  
*Failure* – the recursion returns `False` from the initial call → answer `NO`.



--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
During the search `avail[v]` always contains exactly the colours that
can still be given to `v` without violating already fixed colours.

**Proof.**  
Initially all three colours are possible, so the statement holds.
When a vertex `x` is coloured with colour `c`,
the algorithm removes `c` from `avail` of every still uncoloured neighbour
(because `x` and that neighbour are adjacent, therefore they cannot share `c`).
No other colours are removed, and no colour is added later.
Thus after the update `avail` reflects precisely the colours compatible
with the current partial colouring. ∎



##### Lemma 2  
If the algorithm reaches a recursive call where some uncoloured vertex
has `avail == 0`, then the current partial colouring cannot be extended
to a full proper 3‑colouring.

**Proof.**  
By Lemma&nbsp;1 `avail == 0` means *no* colour can be assigned to that vertex
without creating a conflict with already coloured neighbours.
Hence any extension would violate the rule, i.e. no full proper colouring
exists extending the current partial one. ∎



##### Lemma 3  
Whenever the algorithm assigns a colour to a vertex, the partial
colouring remains proper (no adjacent vertices share a colour).

**Proof.**  
A colour `c` is assigned only if `c` is present in `avail[v]`.
By Lemma&nbsp;1 this means none of the already coloured neighbours of `v`
uses `c`. Therefore the new assignment does not create a conflict. ∎



##### Lemma 4  
If the algorithm outputs a colouring, it is a valid solution.

**Proof.**  
Output occurs only after all vertices are coloured.
By Lemma&nbsp;3 every step kept the partial colouring proper,
hence the final complete colouring is proper.
All vertices receive a colour in `{1,2,3}` by construction. ∎



##### Lemma 5  
If a proper 3‑colouring exists, the algorithm will eventually find one.

**Proof.**  
Consider any fixed proper colouring `C`.  
During the search the algorithm explores **all** possibilities that are
not pruned by Lemma&nbsp;2.
Whenever the algorithm makes a choice for a vertex, at least one of the
tried colours coincides with `C` (because `C` respects all already fixed
colours, thus its colour is still in `avail`).  
Following always that matching branch never hits a dead‑end
(Lemma&nbsp;2 would contradict the existence of `C`).  
Consequently the recursion can follow the path that exactly reproduces
`C` and will reach a leaf where all vertices are coloured, causing success. ∎



##### Lemma 6  
If the algorithm finishes with answer `NO`, no proper 3‑colouring exists.

**Proof.**  
`NO` is printed only if the initial recursive call returns `False`,
i.e. every branch was either pruned by Lemma&nbsp;2 or explored completely
without reaching a full colouring.
Assume a proper colouring existed. By Lemma&nbsp;5 the algorithm would have
found it, contradiction. Hence no proper colouring exists. ∎



##### Theorem  
The program prints  

* `YES` and a correct assignment **iff** a valid assignment exists,  
* otherwise prints `NO`.

**Proof.**  
*If* part – existence ⇒ algorithm finds it (Lemma&nbsp;5) ⇒ prints `YES`
and by Lemma&nbsp;4 the assignment is correct.  
*Only‑if* part – algorithm prints `YES` ⇒ by Lemma&nbsp;4 the assignment
is proper, therefore a valid assignment exists.  
If algorithm prints `NO`, by Lemma&nbsp;6 no valid assignment exists. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

`n ≤ 40`.  
In the worst case the algorithm explores the full 3‑ary recursion tree:
`O(3^n)`.  
The pruning (empty `avail`) and the heuristic ordering make the practical
search far smaller; for `n = 40` it easily fits into the 2 s limit.

Memory usage:

* adjacency masks – `n` integers,
* arrays `col`, `avail` – `O(n)`,
* recursion stack – depth `n`,
* change stack – at most `m` entries per level, bounded by `n·n`.

Overall `O(n^2)` ≤ a few kilobytes.



--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    col = [-1] * n               # -1 = uncoloured, else 0,1,2
    avail = [0b111] * n          # three possible colours
    change_stack = []            # (vertex, old_mask)

    # order vertices by degree for initial tie‑break
    degree = [bin(adj[i]).count('1') for i in range(n)]

    def select_vertex() -> int:
        """return uncoloured vertex with smallest popcount(avail)"""
        best = -1
        best_cnt = 4
        for v in range(n):
            if col[v] == -1:
                cnt = (avail[v] & 0b111).bit_count()
                if cnt < best_cnt:
                    best_cnt = cnt
                    best = v
                    if cnt == 1:
                        break
        return best

    def dfs(colored: int) -> bool:
        if colored == n:
            return True
        v = select_vertex()
        mask = avail[v] & 0b111
        if mask == 0:
            return False

        # try each possible colour
        for c in range(3):
            if not (mask >> c) & 1:
                continue
            # assign colour c to v
            col[v] = c
            # record changes to neighbours
            saved = []
            neigh = adj[v]
            u = 0
            while neigh:
                lsb = neigh & -neigh
                u = (lsb.bit_length() - 1)
                if col[u] == -1:
                    old = avail[u]
                    new = old & ~(1 << c)
                    if new != old:
                        saved.append((u, old))
                        avail[u] = new
                        if new == 0:
                            # dead end, revert changes of this branch
                            for uu, oo in reversed(saved):
                                avail[uu] = oo
                            col[v] = -1
                            break
                neigh ^= lsb
            else:
                # no break -> continue recursion
                if dfs(colored + 1):
                    return True
                # backtrack neighbour changes
                for uu, oo in reversed(saved):
                    avail[uu] = oo
            # backtrack colour of v
            col[v] = -1
        return False

    possible = dfs(0)
    out = []
    if possible:
        out.append("YES")
        out.append(' '.join(str(col[i] + 1) for i in range(n)))
    else:
        out.append("NO")
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```
