**Solution Explanation**

For every document we have to choose one of three vaults.
Two documents that are *incompatible* must obtain different vaults.
Thus we have to **3‑colour** the given undirected graph  
(`n ≤ 40`).  
The problem is NP‑complete in general, but with `n = 40` a
well‑pruned depth‑first search finishes easily.

--------------------------------------------------------------------

#### 1.   Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based).
* `color[v]` – `-1` if not coloured yet, otherwise `0,1,2`.
* `avail[v]` – bitmask of still possible colours for `v`
  (`1<<c` is set ⇔ colour `c` is still allowed).  
  Initially `avail[v] = 0b111` for all vertices.

During the search we need to **undo** the reductions of `avail`
that were caused by a temporary assignment.
For that we keep a stack `changes` of triples  
`(vertex, old_avail)` – the value of `avail[vertex]` *before* it was
changed.  When we backtrack we restore the saved values.

--------------------------------------------------------------------

#### 2.   Choice of the next vertex  

At each recursion step we pick an **uncoloured** vertex with the
smallest number of still possible colours
(the most constrained vertex, a classic DSATUR heuristic).
If several vertices tie we take the one with the highest degree –
another small tie‑breaker that helps.

--------------------------------------------------------------------

#### 3.   Recursive search  

```
dfs():
    if all vertices coloured:   success
    v = choose next vertex
    for each colour c allowed by avail[v]:
        assign colour c to v
        record all neighbours u that lose colour c:
            if u is uncoloured and (avail[u] contains c):
                push (u, avail[u]) on changes
                avail[u] &= ~ (1<<c)
                if avail[u] becomes 0 -> conflict, stop this colour
        if no conflict:
            if dfs(): return True
        undo all changes made for this colour
        colour[v] = -1
    return False
```

The pruning is strong:

* If a vertex loses its last possible colour, the current branch is
  impossible and we backtrack immediately.
* The ordering described above keeps the branching factor low.

With `n = 40` the recursion never exceeds a few thousand calls,
well inside the limits.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints **YES** and a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
During the search `avail[v]` always equals the set of colours that are
still feasible for `v` with respect to the colours already fixed
in the current recursion path.

**Proof.**  
Initially all three colours are feasible, so the statement holds.
When we assign colour `c` to a vertex `v`, every neighbour `u` of `v`
must not use `c`. The algorithm removes `c` from `avail[u]`.
No other vertex is affected.  
When we backtrack, the algorithm restores the previous `avail[u]`
values from the stack, exactly undoing the removal.
Thus the invariant is preserved. ∎



##### Lemma 2  
If the algorithm reaches a state where some uncoloured vertex `x`
has `avail[x] = 0`, then **no** complete proper 3‑colouring extends the
current partial assignment.

**Proof.**  
By Lemma&nbsp;1 `avail[x]` contains precisely the colours that could be
given to `x` without violating already fixed colours.
If it is empty, every colour would conflict, therefore no extension
exists. ∎



##### Lemma 3  
Whenever the recursive call `dfs()` returns `True`, the array `color`
represents a proper 3‑colouring of the whole graph.

**Proof.**  
`True` is returned only when the base case “all vertices coloured” is
reached.  
All colour assignments were performed only after checking that the
chosen colour belonged to `avail[v]`; by Lemma&nbsp;1 this guarantees
that the colour differs from every already coloured neighbour.
Hence every edge connects vertices of different colours – a proper
3‑colouring. ∎



##### Lemma 4  
If a proper 3‑colouring exists, the algorithm eventually returns `True`.

**Proof.**  
Consider any fixed proper colouring `C`.  
The search explores vertices in some order; when it reaches a vertex
`v` that is still uncoloured, `C(v)` is among the colours in
`avail[v]` (otherwise `C` would already violate a coloured neighbour,
contradiction).  
Therefore the branch that chooses colour `C(v)` is never pruned.
Inductively, the recursion can follow the sequence of choices given by
`C` and reaches the leaf where all vertices are coloured.
Consequently the algorithm will find a successful leaf and return
`True`. ∎



##### Lemma 5  
If the algorithm finishes and returns `False`, no proper 3‑colouring
exists.

**Proof.**  
Assume the contrary: a proper colouring `C` exists.
By Lemma&nbsp;4 the algorithm would have a branch that follows `C`
and would not be pruned (Lemma&nbsp;2). That branch ends in the base
case and returns `True`, contradicting the final `False`. ∎



##### Theorem  
The program outputs  

* “NO” iff the input graph is not 3‑colourable,  
* otherwise “YES” and a list of vault numbers forming a valid
  assignment.

**Proof.**  
If the program prints “YES”, it did so because `dfs()` returned `True`;
by Lemma&nbsp;3 the printed colours constitute a proper 3‑colouring.  

If it prints “NO”, `dfs()` returned `False`; by Lemma&nbsp;5 no proper
3‑colouring exists.  

Conversely, if a proper 3‑colouring exists, Lemma&nbsp;4 guarantees
`dfs()` returns `True`, so the program prints “YES”. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*`n ≤ 40`*, `m ≤ n·(n‑1)/2`.

* Pre‑processing (building adjacency lists): `O(n + m)`.
* Each recursive step touches the neighbours of the currently coloured
  vertex – at most `n‑1`.  
  The total number of performed edge inspections is bounded by the
  number of recursive calls times `n`.  
  In practice the search explores far fewer than `3^n` nodes; with the
  strong pruning the worst‑case running time is well below the limit.
* Memory: adjacency lists `O(n + m)`, colour/availability arrays
  `O(n)`, change stack `O(n·depth) ≤ O(n²)` – all far under 256 MB.

#### 6.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    color = [-1] * n               # -1 = uncoloured, else 0,1,2
    avail = [0b111] * n            # three bits set
    changes = []                   # stack of (vertex, old_avail)

    # order vertices by degree for tie‑breaking
    degree = [len(adj[i]) for i in range(n)]

    def choose_vertex() -> int:
        # pick uncoloured vertex with smallest popcount(avail)
        best = -1
        best_cnt = 4  # more than max 3
        best_deg = -1
        for v in range(n):
            if color[v] != -1:
                continue
            cnt = (avail[v] & 0b111).bit_count()
            if cnt < best_cnt or (cnt == best_cnt and degree[v] > best_deg):
                best = v
                best_cnt = cnt
                best_deg = degree[v]
        return best

    def dfs(coloured: int) -> bool:
        if coloured == n:
            return True
        v = choose_vertex()
        mask = avail[v]
        # try each colour present in mask
        for c in range(3):
            if not (mask >> c) & 1:
                continue
            # assign colour c to v
            color[v] = c
            saved = []          # local list of (u, old_avail)
            conflict = False
            for u in adj[v]:
                if color[u] == -1 and (avail[u] >> c) & 1:
                    old = avail[u]
                    new = old & ~(1 << c)
                    saved.append((u, old))
                    avail[u] = new
                    if new == 0:
                        conflict = True
                        break
            if not conflict:
                if dfs(coloured + 1):
                    return True
            # undo changes
            for u, old in reversed(saved):
                avail[u] = old
            color[v] = -1
        return False

    possible = dfs(0)
    out = []
    if not possible:
        out.append("NO")
    else:
        out.append("YES")
        out.append(' '.join(str(c + 1) for c in color))
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
