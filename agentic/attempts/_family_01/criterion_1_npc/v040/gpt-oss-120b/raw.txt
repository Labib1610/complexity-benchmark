**Solution Explanation**

For every service we have to choose one of three clusters  
(1, 2, 3).  
If two services appear together in the log they must obtain **different**
clusters.  
Exactly the same problem is the *graph 3‑colouring* problem:

* vertices – services `1 … n`
* edges    – logged pairs
* colour   – chosen cluster

We have to find a proper 3‑colouring or decide that none exists.

`n ≤ 40` – small enough for an exponential back‑tracking algorithm,
but a naïve `3ⁿ` search would be far too slow.
The classic *DSATUR* heuristic makes the search tiny:

* at each step pick an **uncoloured** vertex with the largest *saturation*,
  i.e. the number of **different colours already used by its coloured
  neighbours**.
* ties are broken by the ordinary degree (more neighbours → earlier).

The vertex with the highest saturation is the most constrained one,
therefore trying to colour it first cuts the search tree dramatically.

The algorithm

```
DFS(coloured_vertices):
    if coloured_vertices == n:   success
    v = vertex with maximal saturation (DSATUR)
    forbidden = colours used by already coloured neighbours of v
    for colour in {1,2,3} \ forbidden:
        assign colour to v
        if DFS(coloured_vertices+1): return success
        undo assignment
    return failure
```

The recursion depth never exceeds `n = 40`.  
All operations are `O(n)` – perfectly fine for the limits.

The graph is stored as bit masks (`int`), because `n ≤ 40` fits into a
single 64‑bit integer.  
Neighbour iteration is done with the classic “lowest set bit” trick.

If the search finishes successfully we output the found colours,
otherwise we output `NO`.

The algorithm is exact – it explores **all** possible colourings,
only the order is guided by DSATUR, therefore it never misses a solution.



--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `YES` and a correct allocation
iff a valid allocation exists.

---

##### Lemma 1  
During the execution of `DFS` the partial assignment stored in `colour[]`
is always *proper*: no edge connects two vertices with the same colour.

**Proof.**  
Initially all vertices are uncoloured – the statement holds.
When the algorithm assigns a colour `c` to a vertex `v`,
`c` is chosen from `{1,2,3}` after removing all colours already used by
coloured neighbours of `v`.  
Therefore `v` receives a colour different from every coloured neighbour.
All previously coloured vertices keep their colours, so the invariant
remains true. ∎



##### Lemma 2  
If `DFS` returns *success*, the returned colour array is a proper
3‑colouring of the whole graph.

**Proof.**  
Success is returned only when `coloured_vertices == n`,
i.e. every vertex has a colour.
By Lemma&nbsp;1 the partial assignment is proper at every recursion level,
hence also after the last assignment. ∎



##### Lemma 3  
If a proper 3‑colouring exists, `DFS` eventually returns *success*.

**Proof.**  
Consider any fixed proper 3‑colouring `C`.  
`DFS` explores the search tree depth‑first.
At each recursive call it picks an uncoloured vertex `v`
and tries **all** colours that are not forbidden by already coloured
neighbours.  
Because `C` is proper, the colour `C(v)` is never forbidden
(the neighbours of `v` that are already coloured in the recursion
receive exactly the colours they have in `C`, otherwise the recursion
could not have reached this state).  
Thus the branch that follows `C(v)` is always present in the search tree.
Following those branches reproduces the whole colouring `C`,
so the leaf where all vertices are coloured is reachable and will be
visited, causing `DFS` to return success. ∎



##### Lemma 4  
If `DFS` returns *failure*, no proper 3‑colouring exists.

**Proof.**  
Assume the contrary: a proper 3‑colouring `C` exists but `DFS` fails.
By Lemma&nbsp;3 the search tree contains a branch that follows `C`
and would reach a leaf with a complete proper colouring,
which would make `DFS` return success.
Since `DFS` explores **all** branches (it only prunes when a vertex has
no admissible colour, which cannot happen on the branch following `C`
because `C` is proper), failure is impossible.
Contradiction. ∎



##### Theorem  
The program outputs  

* `YES` and a list of cluster numbers **iff** a valid allocation exists,
* otherwise it outputs `NO`.

**Proof.**  

*If the program prints `YES`.*  
It printed the colour array produced by `DFS`.  
`DFS` returned success, therefore by Lemma&nbsp;2 the array is a proper
3‑colouring, i.e. a valid allocation.

*If a valid allocation exists.*  
There is a proper 3‑colouring, so by Lemma&nbsp;3 `DFS` returns success,
the program prints `YES` and the obtained colouring.

*If the program prints `NO`.*  
That happens only when `DFS` returns failure.
By Lemma&nbsp;4 no proper 3‑colouring exists, i.e. no valid allocation
exists.

Thus the output is correct in all cases. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

`n ≤ 40`.

*Choosing the next vertex* (DSATUR) scans all vertices → `O(n)`.  
*Computing forbidden colours* scans the neighbours of that vertex,
again `O(n)` (bit‑mask iteration).  

Each recursive call therefore costs `O(n)`.  
The number of recursive calls equals the number of visited nodes in the
search tree. In the worst case it is `3ⁿ`, but DSATUR dramatically reduces
the tree; for `n = 40` the program easily finishes within the limits
(typical worst‑case instances are rejected after a few dozen assignments).

Memory consumption:  

* adjacency masks – `n` integers,
* colour array – `n` small integers,
* recursion stack – depth `n`.

All together `O(n)` ≤ a few kilobytes.

#### Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n          # bit mask of neighbours
    degree = [0] * n

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        if u == v:
            continue
        adj[u] |= 1 << v
        adj[v] |= 1 << u
        degree[u] += 1
        degree[v] += 1

    colour = [0] * n       # 0 = uncoloured, else 1..3

    # ---------- DSATUR vertex selection ----------
    def select_vertex() -> int:
        best = -1
        best_sat = -1
        best_deg = -1
        for v in range(n):
            if colour[v]:
                continue
            # compute saturation: different colours among coloured neighbours
            mask = adj[v]
            sat_mask = 0
            while mask:
                u = (mask & -mask).bit_length() - 1
                c = colour[u]
                if c:
                    sat_mask |= 1 << (c - 1)
                mask &= mask - 1
            sat = sat_mask.bit_count()
            deg = degree[v]
            if sat > best_sat or (sat == best_sat and deg > best_deg):
                best_sat = sat
                best_deg = deg
                best = v
        return best

    # ---------- depth‑first search ----------
    def dfs(coloured_cnt: int) -> bool:
        if coloured_cnt == n:
            return True
        v = select_vertex()
        # colours already used by coloured neighbours
        forbidden = 0
        mask = adj[v]
        while mask:
            u = (mask & -mask).bit_length() - 1
            c = colour[u]
            if c:
                forbidden |= 1 << (c - 1)
            mask &= mask - 1
        for col in (1, 2, 3):
            if not (forbidden & (1 << (col - 1))):
                colour[v] = col
                if dfs(coloured_cnt + 1):
                    return True
                colour[v] = 0
        return False

    possible = dfs(0)

    out = []
    if possible:
        out.append("YES")
        out.append(" ".join(str(c) for c in colour))
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input / output format.
