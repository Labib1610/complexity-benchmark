**Solution Explanation**

For every worker we have to choose a shift `1` or `2`.
For each given pair `(u , v)` the two workers must obtain *different*
shifts.  
Exactly the same problem is known as **2‑colouring a graph** or
**checking bipartiteness**.

--------------------------------------------------------------------

#### 1.   Graph model
* vertices – workers `1 … n`
* undirected edges – the `m` forbidden pairs  

A schedule exists **iff** the graph is bipartite.

--------------------------------------------------------------------

#### 2.   Lexicographically smallest schedule
In a bipartite connected component there are exactly two possible
colourings – they are obtained from each other by swapping the two
colours.

The lexicographic order compares the workers from left to right.
Therefore the first (smallest index) vertex of a component decides the
order of the whole component:

*If we colour that vertex with `1`, the whole component is forced to the
corresponding orientation, otherwise it would start with `2` and any
schedule beginning with `1` would be smaller.*

Consequences  

* Process the vertices in increasing order `1 … n`.
* When we meet an unvisited vertex `i` it is the smallest index of its
  component.
* Start a BFS/DFS from `i` and give it temporary colour `0`.
  All other vertices of the component receive colour `0/1` according to
  the bipartite rule.
* Because `i` already has colour `0`, the orientation where colour `0`
  means shift `1` is exactly the lexicographically smallest one.
* Finally output `shift = colour + 1`.

If during the search we ever find an edge whose ends already have the
same temporary colour, the graph is **not** bipartite → answer `NO`.

--------------------------------------------------------------------

#### 3.   Algorithm
```
read n, m
build adjacency list G[1…n]

colour[1…n] = -1          # -1 = not visited, otherwise 0 or 1
answer[1…n] = 0

for i = 1 … n:
    if colour[i] == -1:               # new component, i is its smallest vertex
        queue ← [i]
        colour[i] = 0                 # temporary colour, will become shift 1
        while queue not empty:
            v = pop queue
            for each neighbour to in G[v]:
                if colour[to] == -1:
                    colour[to] = colour[v] ^ 1
                    push to into queue
                elif colour[to] == colour[v]:
                    print "NO" and exit   # not bipartite
        # component finished – convert temporary colours to real shifts
        for each vertex x visited in this component:
            answer[x] = colour[x] + 1

print "YES"
print answer[1] … answer[n] separated by spaces
```

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `NO` iff no feasible schedule exists,
otherwise it prints `YES` and the lexicographically smallest feasible
schedule.

---

##### Lemma 1  
During the BFS of a component the algorithm assigns temporary colours
`0/1` exactly as a proper 2‑colouring of that component would do
(if the component is bipartite).

**Proof.**  
The start vertex receives colour `0`.  
Whenever an edge `(v, to)` is processed:

* if `to` is uncoloured, we give it the opposite colour `colour[v] xor 1`,
  which is the only colour that can differ from `v`.
* if `to` is already coloured, we check that it differs from `v`.  
  If it does not, the edge connects two vertices of the same colour,
  contradicting bipartiteness.

Thus the algorithm follows the definition of a 2‑colouring. ∎



##### Lemma 2  
If the algorithm prints `NO` then the input graph is not bipartite,
hence no schedule satisfies all constraints.

**Proof.**  
`NO` is printed only when an edge is found whose ends already have the
same temporary colour. By Lemma&nbsp;1 this situation can happen only if
the component contains an odd cycle, i.e. is not bipartite.
A non‑bipartite graph cannot be 2‑coloured, therefore no schedule
exists. ∎



##### Lemma 3  
If the algorithm finishes without printing `NO`, the array `answer`
is a feasible schedule (all constraints are satisfied).

**Proof.**  
For every component the BFS succeeded, therefore by Lemma&nbsp;1 the
temporary colours form a proper 2‑colouring of that component.
`answer[x] = colour[x] + 1` maps colour `0 → 1` and `1 → 2`,
preserving the property “different colours ⇒ different shifts”.
All edges belong to some component, consequently every forbidden pair
gets different shifts. ∎



##### Lemma 4  
For each connected component the schedule produced by the algorithm is
the lexicographically smallest among the two possible colourings of that
component.

**Proof.**  
The component is first discovered at its smallest index vertex `i`.
The algorithm fixes `colour[i] = 0`, i.e. `answer[i] = 1`.  
The only other feasible colouring would give `i` colour `1` (`answer[i]=2`),
which is lexicographically larger because the first differing position
(`i`) would contain `2` instead of `1`. ∎



##### Lemma 5  
The whole schedule `answer` is the lexicographically smallest feasible
schedule for the whole graph.

**Proof.**  
Consider the first index `k` where any feasible schedule `S` differs from
`answer`.  
All vertices `< k` belong to components whose smallest vertex is `< k`,
hence by Lemma&nbsp;4 they are forced to shift `1` in every lexicographically
minimal schedule; both `answer` and `S` have shift `1` there.
Vertex `k` is the smallest vertex of its component.
By Lemma&nbsp;4 `answer[k] = 1` while any other feasible schedule must have
`S[k] = 2`.  
Thus `answer` is lexicographically smaller than any other feasible schedule. ∎



##### Theorem  
The algorithm outputs  

* `NO` **iff** no schedule satisfies all constraints;  
* otherwise `YES` and the lexicographically smallest schedule.

**Proof.**  

*If part*: By Lemma&nbsp;2, printing `NO` implies impossibility.  

*Only‑if part*: If a feasible schedule exists, the graph is bipartite,
so no conflict appears and the algorithm never prints `NO`.  
By Lemma&nbsp;3 the produced `answer` is feasible, and by Lemma&nbsp;5 it is
the lexicographically smallest one. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis
*Building adjacency list*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and edge is processed once →  
`O(n + m)` time, `O(n)` extra memory for colour/answer arrays and the queue.

Overall  

* **Time** `O(n + m)` ( ≤ 4·10⁵ operations, well inside 1 s)  
* **Memory** `O(n + m)` ( ≤ 4·10⁵ integers, < 256 MB)

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        g[u].append(v)
        g[v].append(u)

    colour = [-1] * (n + 1)          # -1 = unvisited, else 0/1
    answer = [0] * (n + 1)

    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        # start is the smallest index of its component
        dq = deque([start])
        colour[start] = 0
        component_vertices = [start]

        while dq:
            v = dq.popleft()
            cv = colour[v]
            for to in g[v]:
                if colour[to] == -1:
                    colour[to] = cv ^ 1
                    dq.append(to)
                    component_vertices.append(to)
                elif colour[to] == cv:
                    sys.stdout.write("NO")
                    return

        # orientation already makes start -> colour 0 -> shift 1
        for v in component_vertices:
            answer[v] = colour[v] + 1

    out = ["YES", " ".join(str(answer[i]) for i in range(1, n + 1))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```
