**Solution Explanation**

For every worker we have to choose one of two shifts `1` or `2`.
If two workers are a *conflict pair* they must obtain different shifts.
Thus we have to 2‑colour the conflict graph – i.e. check whether it is
* bipartite* – and output a lexicographically smallest valid colouring.

--------------------------------------------------------------------

#### 1.   Observations  

* A graph is bipartite **iff** each of its connected components can be
  coloured with two colours without contradictions.
* In one component the two colour classes can be swapped.
  Swapping changes the final shift numbers (`1` ↔ `2`) for the whole
  component.
* To obtain the lexicographically smallest whole assignment we process the
  workers in increasing order.
  When we first meet an uncoloured vertex `v` we are free to decide which
  colour class becomes shift `1`.  
  The smallest possible value for `v` is `1`, therefore we **must**
  give shift `1` to the colour class that contains `v`.

If we always do that for the first vertex of every component,
the whole sequence is lexicographically minimal:
all earlier positions are already forced to the smallest possible value,
later positions cannot influence them.

--------------------------------------------------------------------

#### 2.   Algorithm  

```
read n, m
build adjacency list G (1‑based)

colour[1..n] = -1          # -1 = not visited, 0/1 = temporary colours
answer[1..n] = 0           # final shifts (1 or 2)

for v = 1 .. n:
    if colour[v] != -1: continue

    # start a BFS for the new component, give v temporary colour 0
    queue = [v]
    colour[v] = 0
    component = [v]

    while queue not empty:
        x = pop queue
        for each neighbour y of x:
            if colour[y] == -1:
                colour[y] = colour[x] ^ 1
                push y
                component.append(y)
            elif colour[y] == colour[x]:
                print "NO" and exit   # not bipartite

    # component is bipartite, decide orientation
    # we want shift 1 for the colour class of the first vertex v
    target = colour[v]          # 0 in our construction
    for u in component:
        if colour[u] == target:
            answer[u] = 1
        else:
            answer[u] = 2

print "YES"
print answer[1] … answer[n] separated by spaces
```

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `NO` iff no valid assignment exists,
otherwise prints `YES` and the lexicographically smallest assignment.

---

##### Lemma 1  
During BFS of a component, if the algorithm detects an edge `(x,y)` with
`colour[x] == colour[y]`, the conflict graph is not bipartite.

**Proof.**  
BFS assigns colours alternating along every traversed edge, i.e. any edge
must connect vertices of different temporary colours.
If an edge connects two vertices with the same temporary colour, any
2‑colouring would have to give them the same colour, contradicting the edge
requirement. ∎



##### Lemma 2  
If the algorithm finishes BFS of a component without contradiction,
the component is bipartite and the temporary colours `0/1` form a valid
2‑colouring.

**Proof.**  
All edges examined during BFS connect vertices of opposite temporary colours
(by construction). Since every edge of the component is examined,
the obtained colouring satisfies the bipartite condition. ∎



##### Lemma 3  
For a processed component, the algorithm assigns shift `1` to exactly the
temporary colour class that contains the smallest vertex index of the
component.

**Proof.**  
The component is first encountered when iterating vertices in increasing
order, i.e. at its smallest index `v`. The BFS starts with `colour[v]=0`.
`target = colour[v]` equals the colour of `v`. Afterwards every vertex whose
temporary colour equals `target` receives shift `1`, all others shift `2`.
Thus the colour class of `v` gets shift `1`. ∎



##### Lemma 4  
The assignment produced by the algorithm (if it prints `YES`) is a valid
shift assignment for the whole graph.

**Proof.**  
By Lemma&nbsp;2 each component is bipartite, and the two temporary colour
classes are opposite for every edge inside the component.
Lemma&nbsp;3 maps one class to shift `1` and the other to shift `2`,
preserving the property that adjacent vertices obtain different shifts.
Components are disjoint, therefore the whole graph satisfies the requirement. ∎



##### Lemma 5  
Among all valid assignments, the algorithm’s assignment is lexicographically
smallest.

**Proof.**  
Consider the first position `i` where any valid assignment can differ.
`i` belongs to some component `C`. All vertices `< i` are fixed already,
hence they belong to earlier components and are identical in every valid
assignment (by induction on the processing order).

When component `C` is processed, `i` is the smallest index of `C`
(because we meet components in increasing order).
By Lemma&nbsp;3 the algorithm gives shift `1` to the colour class containing
`i`. Any valid assignment must give either `1` or `2` to `i`, but giving `2`
would make the whole sequence larger at position `i`. Therefore every
lexicographically minimal assignment must also give `1` to `i`, and the
algorithm’s choice is forced. Repeating this argument for all components
shows the whole sequence is minimal. ∎



##### Lemma 6  
If the algorithm prints `NO`, no valid assignment exists.

**Proof.**  
`NO` is printed only when Lemma&nbsp;1 detects a same‑colour edge,
i.e. the graph contains an odd cycle, which makes it non‑bipartite.
A non‑bipartite graph cannot be 2‑coloured, thus no shift assignment exists. ∎



##### Theorem  
The algorithm outputs  

* `NO` **iff** the conflict graph admits no feasible shift assignment,  
* otherwise `YES` followed by the lexicographically smallest feasible
  assignment.

**Proof.**  
*If* the algorithm prints `NO`, by Lemma&nbsp;6 no assignment exists.  
*If* it prints `YES`, Lemma&nbsp;4 guarantees the printed assignment is
feasible, and Lemma&nbsp;5 guarantees it is the lexicographically smallest
among all feasible ones. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency list*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and edge is processed once →  
`O(n + m)` time, `O(n)` additional memory for colour/queue.

Overall: **Time** `O(n + m)` ≤ `4·10⁵`, **Memory** `O(n + m)` ≤ `4·10⁵`,
well inside the limits.

#### 5.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        g[u].append(v)
        g[v].append(u)

    colour = [-1] * (n + 1)          # temporary 0/1
    ans = [0] * (n + 1)              # final shifts 1/2

    for v in range(1, n + 1):
        if colour[v] != -1:
            continue
        # start new component, give v colour 0
        q = deque([v])
        colour[v] = 0
        comp = [v]
        ok = True
        while q:
            x = q.popleft()
            cx = colour[x]
            for y in g[x]:
                if colour[y] == -1:
                    colour[y] = cx ^ 1
                    q.append(y)
                    comp.append(y)
                elif colour[y] == cx:
                    print("NO")
                    return
        # orient so that v (colour 0) gets shift 1
        target = colour[v]   # always 0 here
        for u in comp:
            ans[u] = 1 if colour[u] == target else 2

    out = ['YES', ' '.join(str(ans[i]) for i in range(1, n + 1))]
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```
