**Solution Explanation**

For the given undirected graph `G` we have to choose `k` vertices such that no two of them are
connected by an edge.
A set of vertices with this property is called an **independent set**.

The complement graph `Ĝ` contains exactly the edges that are *not* present in `G`.
In `Ĝ` a set of vertices is a **clique** (all pairwise adjacent)  
iff it is an independent set in `G`.

So the task is equivalent to

*find a clique of size `k` in the complement graph*.

`n ≤ 46`, therefore a classic exact branch‑and‑bound algorithm for the
maximum clique works easily – it is fast enough for all graphs of this size.



--------------------------------------------------------------------

#### 1.   Bitset representation  

Vertex numbers are `0 … n‑1` (the input uses `1 … n`, we subtract `1`).

```
adj[i]      – bitmask of neighbours of i in G
cadj[i]     – bitmask of neighbours of i in the complement graph Ĝ
ALL = (1<<n) - 1   – all vertices
```

All set operations are simple integer bit operations, which are very fast in
Python.



--------------------------------------------------------------------

#### 2.   Greedy coloring – upper bound  

During the search we keep a set `P` (bitmask) of *candidate* vertices that can still
be added to the current clique `R`.

A greedy coloring of the subgraph induced by `P` in `Ĝ` gives an upper bound:

*If the coloring needs `c` colours, any clique that can be built from `P`
contains at most `c` vertices* (a clique can use at most one vertex of each colour).

The greedy coloring works colour class by colour class:

```
available = P
while available != 0:
        colour += 1
        cur = available                # vertices that may obtain this colour
        while cur != 0:
                v = lowbit(cur)
                assign colour to v
                verts.append(v)        # order of processing
                col.append(colour)
                # vertices adjacent to v in Ĝ cannot share this colour
                cur &= ~ (cadj[v] | (1<<v))
        # remove all vertices coloured in this round from further consideration
        available &= ~mask_of_this_colour
```

`verts[i]` is processed later than `verts[j]` if `i > j`,
therefore the algorithm later iterates the vertices **in reverse order**
(the most promising ones first).

If at some point  

```
|R| + colour_of_current_vertex < k
```

the branch cannot reach size `k` and is pruned.



--------------------------------------------------------------------

#### 3.   Branch‑and‑bound search (Tomita style)

```
search(R_mask, P_mask, size):
        if size == k:               # clique of required size found
                store solution and return True
        # colour bound
        verts, col = greedy_colour(P_mask)
        for i from len(verts)-1 down to 0:
                if size + col[i] < k:          # impossible to reach k
                        return False
                v = verts[i]
                newR = R_mask | (1<<v)
                newP = P_mask & cadj[v]        # only vertices adjacent to v
                if size+1 == k:
                        store newR as solution and return True
                if search(newR, newP, size+1):
                        return True
                # discard v from P for the next iterations
                P_mask &= ~(1<<v)
        return False
```

The recursion stops as soon as one clique of size `k` is found.
Because of the colour bound the explored part of the search tree is tiny for
`n = 46`.



--------------------------------------------------------------------

#### 4.   Overall algorithm  

```
read n, m, k
build adj[ ] from the m edges
build cadj[ ] = ALL ^ (adj[i] | (1<<i))          # complement graph
if k == 0:   (not possible by constraints)
run search(0, ALL, 0)
if a solution was stored:
        print YES and the vertices (convert back to 1‑based)
else:
        print NO
```

The algorithm is exact, runs in well below the limits
(`n = 46` → at most a few million recursive calls, each cheap).

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the program prints `YES` and a correct committee
iff such a committee exists.

---

##### Lemma 1  
For any set of vertices `S` :

`S` is an independent set in `G` **iff** `S` is a clique in the complement graph `Ĝ`.

**Proof.**  
By definition of the complement graph, two vertices are adjacent in `Ĝ`
exactly when they are *not* adjacent in `G`.  
Thus every pair of vertices of `S` is non‑adjacent in `G`
⇔ every pair is adjacent in `Ĝ`. ∎



##### Lemma 2  
During the search, the set `R` is always a clique in `Ĝ`
and `P` always contains exactly the vertices that can be added to `R`
while keeping a clique.

**Proof.**  
Initially `R = ∅` (trivially a clique) and `P = ALL` (all vertices are possible).  
Induction step: assume the invariant holds for the current call.
When we branch on a vertex `v ∈ P` we set  

```
newR = R ∪ {v}
newP = P ∩ N_Ĝ(v)
```

All vertices of `newR` are pairwise adjacent because
* every pair inside `R` already was,
* `v` is adjacent to every vertex of `R` (otherwise `v` would not be in `P`),
* vertices of `newP` are neighbours of `v` by construction,
  and they stay neighbours of each other because they were already in `P`.

Hence the invariant holds for the recursive call. ∎



##### Lemma 3  
The greedy colouring performed on the current candidate set `P`
produces a number `c` such that any clique that can be extended from `R`
using only vertices of `P` has size at most `|R| + c`.

**Proof.**  
The greedy algorithm colours the subgraph `Ĝ[P]` so that adjacent vertices obtain
different colours. Therefore each colour class is an *independent set* in `Ĝ[P]`,
i.e. a set of vertices with no edges between them.
A clique can contain at most one vertex from each colour class,
otherwise two of its vertices would be non‑adjacent.
Consequently the size of any clique inside `P` is bounded by the number of
different colours used, which is `c`. ∎



##### Lemma 4  
If the recursive routine discards a branch because  
`size + colour_of_current_vertex < k`,
then no clique of size `k` can be obtained from that branch.

**Proof.**  
At the moment of the test the current partial clique has `size` vertices,
and the greedy colouring tells us that at most `colour_of_current_vertex`
additional vertices can be taken from the remaining candidates.
Thus any extension would have size at most `size + colour_of_current_vertex`,
which is `< k`. ∎



##### Lemma 5  
If the algorithm outputs a set `S`, then `S` is an independent set of size `k`
in the original graph `G`.

**Proof.**  
The algorithm outputs a set when the recursion reaches `size == k`.
By Lemma&nbsp;2 the set `R` at that moment is a clique in `Ĝ`.
By Lemma&nbsp;1 the same vertex set is an independent set in `G`.
Its size is exactly `k`. ∎



##### Lemma 6  
If an independent set of size `k` exists in `G`,
the algorithm will eventually find (and output) one.

**Proof.**  
Let `I` be any independent set of size `k` in `G`.  
By Lemma&nbsp;1 `I` is a clique of size `k` in `Ĝ`.
Consider the execution of the recursive search.
Whenever the current call has `R ⊆ I` and `P` still contains all vertices of
`I \ R`, the branch that *chooses* the next vertex of `I` is explored,
because the algorithm tries every vertex of `P` (unless pruned).
Lemma&nbsp;4 shows that pruning can only happen when even the optimal
extension cannot reach size `k`; this never occurs for the branch that follows
the vertices of `I`, because `I` itself is a feasible extension.
Therefore the recursion can follow the whole sequence of vertices of `I`
and will reach a call with `size = k`, where it outputs a solution.
∎



##### Theorem  
The program prints  

* `YES` and a list of `k` distinct vertex numbers **iff**
  there exists a set of `k` vertices with no edge between any two of them;

* otherwise it prints `NO`.

**Proof.**  

*If the program prints `YES`*: by Lemma&nbsp;5 the printed vertices form an
independent set of size `k`. Hence such a set exists.

*If such a set exists*: by Lemma&nbsp;6 the search will eventually find a
clique of size `k` in `Ĝ` and output it, therefore the program prints `YES`.

If the program prints `NO`, the search has exhausted all branches without
finding a clique of size `k`. By Lemma&nbsp;4 every pruned branch cannot
contain a size‑`k` clique, and the unpruned branches were explored completely.
Thus no clique of size `k` exists in `Ĝ`, and by Lemma&nbsp;1 no independent
set of size `k` exists in `G`. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

`n ≤ 46`.

*Bit operations* are `O(1)`.

The algorithm is exponential in the worst case, but the colour bound makes the
search tree tiny for this size.  
In practice the number of recursive calls is far below `10⁶`.

Memory consumption: a few integer masks and recursion depth ≤ `k ≤ n`,
so `O(n)` integers → well under the 256 MiB limit.



--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    k = int(next(it))

    adj = [0] * n
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    ALL = (1 << n) - 1
    # complement adjacency (including self‑loops removed)
    cadj = [ALL ^ (adj[i] | (1 << i)) for i in range(n)]

    solution_mask = 0
    found = False

    # ---------- greedy coloring, returns (verts, colours) ----------
    def greedy_color(P_mask: int):
        verts = []
        colours = []
        available = P_mask
        colour = 0
        while available:
            colour += 1
            cur = available
            colour_mask = 0
            while cur:
                v = (cur & -cur).bit_length() - 1
                cur &= cur - 1
                verts.append(v)
                colours.append(colour)
                colour_mask |= 1 << v
                # remove neighbours of v (in complement) from cur
                cur &= ~ (cadj[v] | (1 << v))
            # vertices coloured this round are removed from further rounds
            available &= ~colour_mask
        return verts, colours

    # ---------- recursive search ----------
    def dfs(R_mask: int, P_mask: int, size: int):
        nonlocal solution_mask, found
        if found:
            return True
        if size == k:
            solution_mask = R_mask
            found = True
            return True

        verts, colours = greedy_color(P_mask)
        # iterate in reverse order (most promising first)
        for i in range(len(verts) - 1, -1, -1):
            if size + colours[i] < k:          # bound, cannot reach k
                return False
            v = verts[i]
            newR = R_mask | (1 << v)
            newP = P_mask & cadj[v]
            if size + 1 == k:
                solution_mask = newR
                found = True
                return True
            if dfs(newR, newP, size + 1):
                return True
            # discard v from P for the next iterations
            P_mask &= ~(1 << v)
        return False

    dfs(0, ALL, 0)

    out = []
    if found:
        out.append("YES")
        ans = [str(i + 1) for i in range(n) if (solution_mask >> i) & 1]
        out.append(" ".join(ans))
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
