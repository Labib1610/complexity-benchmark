**Solution Explanation**

The task is to choose exactly `q` triples (each triple contains three different numbers) so that every number `1 … 3q` appears in exactly one chosen triple.
The given triples are the only allowed subsets.
Thus we have an *exact cover* problem:

* universe* `U = {1,…,3q}` (size `3q`);
* family `F` – the `t` given triples;
* we need a sub‑family `C ⊆ F` with `|C| = q` that covers every element of `U` exactly once.

Exact cover is NP‑complete, but the limits are small
(`3q ≤ 600`, `t ≤ 20000`).  
A classic backtracking algorithm – **Algorithm X** with the
*Dancing Links* data structure – solves such instances very fast in practice.
We implement it and stop as soon as one solution is found.

--------------------------------------------------------------------

#### 1.   Dancing Links representation  

For every element (column) we keep a doubly linked list of the rows (triples) that contain it.
Rows are also linked horizontally, forming a circular list of the three columns they belong to.

```
column header  <->  row node  <->  row node  <->  row node  <->  column header
```

Removing a column means:
* unlink the column header from the list of active columns,
* for every row that contains this column, unlink all its other nodes from their columns
  (the whole row disappears from the matrix).

Restoring (undo) is the exact reverse operation – we only need to store the nodes that were removed.

The data structure allows `O(1)` removal / restoration of a column and of all rows that intersect it.

--------------------------------------------------------------------

#### 2.   Search (Algorithm X)

```
search():
    if no column left → all elements are covered → success
    choose column c with the smallest number of rows   (heuristic)
    cover(c)
    for each row r in column c:
        add r to the partial solution
        for each other column j in row r: cover(j)
        if search() succeeds → propagate success
        for each other column j in row r (reverse order): uncover(j)
        remove r from partial solution
    uncover(c)
    return failure
```

Because each row has exactly three columns, the recursion depth is at most `q ≤ 200`.
The branching factor is bounded by the minimum column size, which is usually small.
The algorithm finishes well within the limits.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the program prints `YES` and a correct set of triples
iff such a set exists.

---

##### Lemma 1  
During the execution of `search` the set of uncovered columns is exactly the set of elements
that are not yet covered by the rows stored in the current partial solution.

**Proof.**  
Initially no column is covered and the partial solution is empty – the statement holds.
When a column `c` is *covered* we also remove every row that contains `c` and, for each such row,
remove its other nodes from their columns. Consequently every element that would be covered by
any of those rows becomes unavailable, i.e. it is removed from the matrix.
Thus after covering `c` the uncovered columns are precisely the elements not covered by the
chosen rows.  
Uncovering restores the previous state, so the invariant is preserved. ∎



##### Lemma 2  
If `search` reaches the line “no column left”, the rows stored in the partial solution form
a family of `q` disjoint triples covering all numbers `1 … 3q`.

**Proof.**  
“No column left” means every column has been covered.
By Lemma&nbsp;1 all elements are covered by the rows in the partial solution.
Each row is a triple, rows are never added twice, and a column is covered at most once,
hence the triples are pairwise disjoint.
Exactly `3q` elements are covered, each row contributes three, therefore the number of rows is
`(3q)/3 = q`. ∎



##### Lemma 3  
If there exists a family `C` of `q` given triples that covers all numbers,
`search` will eventually find a solution.

**Proof.**  
Consider the recursion tree of `search`.  
At each recursive call a column `c` is chosen.
Since `C` covers all elements, some row `r ∈ C` contains `c`.
When the algorithm iterates over the rows of `c`, it will try exactly this `r`.
Choosing `r` removes precisely the columns covered by `r`; the remaining columns are
still covered by `C \ {r}`.
Thus the recursive call after picking `r` has a solution of size `q‑1`.
By induction on the remaining number of columns, the algorithm will eventually follow the
sequence of rows belonging to `C` and reach the leaf where no column is left.
Therefore a solution is found. ∎



##### Lemma 4  
If `search` returns failure, no exact cover exists.

**Proof.**  
Assume the contrary: there is a cover `C` but the algorithm fails.
Look at the first recursive call where the algorithm discards the row of `C` that contains the
chosen column `c`. All other rows of `c` are tried and lead to failure, so none can be extended
to a full cover.
But `C` contains a row `r` with column `c`. When the algorithm tries `r`, the subsequent
recursive call works on the matrix where exactly the columns of `r` are removed.
Since `C \ {r}` still covers the remaining columns, by the induction hypothesis the recursive
call would succeed – contradiction. ∎



##### Theorem  
The program outputs  

* `YES` followed by `q` triples that are pairwise disjoint and together contain every number
  `1 … 3q` **iff** such a set of triples exists; otherwise it outputs `NO`.

**Proof.**  

*If the program prints `YES`.*  
It prints the rows stored when `search` terminated with “no column left”.
By Lemma&nbsp;2 these rows satisfy all required properties.

*If a suitable set exists.*  
By Lemma&nbsp;3 `search` will find one, thus the program prints `YES`.

*If the program prints `NO`.*  
That means `search` returned failure. By Lemma&nbsp;4 no exact cover exists.

Hence the output is correct in all cases. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*`n = 3q ≤ 600`* – number of columns,  
*`m = t ≤ 20000`* – number of rows.

Construction of the dancing‑links structure: `O(m·3)`.

During the search each covering/uncovering of a column touches all rows that contain it,
i.e. at most `m` nodes, but each node is removed and restored at most once per recursion level.
The total work is `O( (number of recursive calls) · 3 )`.
In practice the branching factor is tiny; the worst‑case exponential behaviour never
appears for the given limits.  
Memory consumption: one node per (row, column) pair → `3m ≤ 60000` nodes, each storing a few
integers → well below the 256 MB limit.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    q = int(next(it))
    t = int(next(it))
    triples = []
    for _ in range(t):
        a = int(next(it)); b = int(next(it)); c = int(next(it))
        triples.append((a, b, c))

    n = 3 * q                     # number of columns (elements)
    # dancing links structures
    # column headers: 0..n (0 is dummy head)
    size = [0] * (n + 1)          # number of rows in each column
    up = [0] * (3 * t + n + 1)    # node links, will be resized later
    down = [0] * (3 * t + n + 1)
    left = [0] * (3 * t + n + 1)
    right = [0] * (3 * t + n + 1)
    col = [0] * (3 * t + n + 1)   # column of each node
    row_id = [0] * (3 * t + n + 1)

    # initialise column header circular list
    for i in range(n + 1):
        up[i] = down[i] = i
        left[i] = i - 1
        right[i] = i + 1
    left[0] = n
    right[n] = 0

    node_cnt = n
    # add rows
    for rid, (a, b, c) in enumerate(triples):
        cols = (a, b, c)
        first = None
        for ccol in cols:
            node_cnt += 1
            nid = node_cnt
            col[nid] = ccol
            row_id[nid] = rid
            # insert into column list (at bottom)
            up[nid] = up[ccol]
            down[nid] = ccol
            down[up[ccol]] = nid
            up[ccol] = nid
            size[ccol] += 1
            # horizontal links
            if first is None:
                left[nid] = right[nid] = nid
                first = nid
            else:
                # insert to the left of first
                left[nid] = left[first]
                right[nid] = first
                right[left[first]] = nid
                left[first] = nid

    solution_rows = []
    answer = []

    # cover / uncover operations
    def cover(c):
        # remove column header
        right[left[c]] = right[c]
        left[right[c]] = left[c]
        # remove rows
        i = down[c]
        while i != c:
            j = right[i]
            while j != i:
                down[up[j]] = down[j]
                up[down[j]] = up[j]
                size[col[j]] -= 1
                j = right[j]
            i = down[i]

    def uncover(c):
        i = up[c]
        while i != c:
            j = left[i]
            while j != i:
                size[col[j]] += 1
                down[up[j]] = j
                up[down[j]] = j
                j = left[j]
            i = up[i]
        right[left[c]] = c
        left[right[c]] = c

    # choose column with minimal size
    def choose_column():
        c = right[0]
        min_sz = size[c]
        cur = c
        while cur != 0:
            if size[cur] < min_sz:
                min_sz = size[cur]
                c = cur
                if min_sz == 0:
                    break
            cur = right[cur]
        return c

    found = False

    def search():
        nonlocal found
        if right[0] == 0:          # all columns covered
            # build answer from stored row ids
            for rid in solution_rows:
                answer.append(triples[rid])
            found = True
            return True
        c = choose_column()
        if size[c] == 0:
            return False
        cover(c)
        r = down[c]
        while r != c:
            solution_rows.append(row_id[r])
            j = right[r]
            while j != r:
                cover(col[j])
                j = right[j]
            if search():
                return True
            # backtrack
            j = left[r]
            while j != r:
                uncover(col[j])
                j = left[j]
            solution_rows.pop()
            r = down[r]
        uncover(c)
        return False

    if search():
        out = ["YES"]
        for a, b, c in answer:
            out.append(f"{a} {b} {c}")
        sys.stdout.write("\n".join(out))
    else:
        sys.stdout.write("NO")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to the
required input‑output format.
