**Solution Explanation**

The problem asks for a set of `q` triples that

* uses every number `1 … 3q` exactly once,
* each triple must be one of the given `t` triples.

That is exactly the *exact cover* problem with

* one column for every element `1 … 3q`,
* one row for every given triple, containing the three columns of the triple.

We have to decide whether an exact cover exists and output one if it does.

The classic algorithm for exact cover is **Algorithm X** (Donald Knuth) together with the
*Dancing Links* data structure.  
The instance size is modest (`3q ≤ 600`, `t ≤ 20000`), therefore a plain recursive
implementation with the usual heuristic “choose the column with the smallest
remaining row count” solves the problem easily within the limits.



--------------------------------------------------------------------

#### Data structures

* `n = 3*q` – number of columns.
* For each column we keep a doubly linked list of the rows that contain it.
* For each row we keep the three column indices it covers.

The dancing‑links structure is stored in plain Python lists:

```
U, D, L, R : int arrays (size = max_nodes)
C          : column of a node
S[col]     : current size of column (how many rows still available)
row_of[node] : which row the node belongs to
```

`head` is a special column header.  
All nodes are created once at the beginning (no dynamic insertion/deletion).

--------------------------------------------------------------------

#### Algorithm X (recursive search)

```
search(k):
    if head.right == head:               # no column left → all covered
         solution of size k found
    choose column c with minimal S[c]
    cover(c)
    for each row r in column c:
         add r to current answer
         for each column j in row r (except c):
                cover(j)
         if search(k+1) succeeds: return success
         for each column j in row r (in reverse order):
                uncover(j)
    uncover(c)
    return failure
```

`cover` removes a column and all rows that intersect it from the structure,
`uncover` restores them – both are O(number of removed nodes) and are implemented
by pointer manipulations only.

Because each recursive level fixes one triple, the recursion depth never exceeds `q ≤ 200`.
The heuristic guarantees a very small search tree for the given limits; in the worst
case the program still finishes well inside the time limit.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints “YES” and a correct schedule iff such a schedule
exists.

---

##### Lemma 1  
At any moment of the execution, the dancing‑links structure represents exactly the
set of rows (triples) that are still compatible with the already chosen rows.

**Proof.**  
`cover(c)` removes column `c` and all rows that contain `c`. Those rows would reuse a
vial already taken, therefore they are no longer compatible. No other rows are
affected. `uncover(c)` restores precisely those rows and the column, undoing the
removal. All other operations only traverse the structure without modification.
∎



##### Lemma 2  
When `search` reaches the line `if head.right == head` all columns are covered and
the rows stored in the current answer form a set of triples that uses every element
exactly once.

**Proof.**  
`head.right == head` means no column header remains, i.e. every column has been
covered by some earlier `cover` operation. By Lemma&nbsp;1 a column is covered only
when a row containing it has been selected and all other rows containing that column
have been removed, therefore the selected rows are pairwise disjoint on columns.
Since there are `n = 3q` columns and each selected row contributes exactly three new
columns, the number of selected rows is `n/3 = q`. Hence the rows constitute a
valid schedule. ∎



##### Lemma 3  
If a valid schedule exists, `search` will eventually find it.

**Proof.**  
Consider any valid schedule `S`. The first recursive call chooses a column `c`.
Because `S` covers all columns, it contains a row `r∈S` that also covers `c`.
During the loop over rows of column `c` the algorithm will iterate over `r`.
When `r` is processed, all other columns of `r` are covered, which exactly removes
all rows conflicting with `r`. The remaining instance is precisely the original
instance restricted to the columns not in `r` and rows not conflicting with `r`,
and `S \ {r}` is a valid schedule for this reduced instance.
By induction on the number of remaining columns the recursive call will eventually
select the rest of `S`. Hence the algorithm can follow a path that leads to a
solution. ∎



##### Lemma 4  
If `search` returns failure, no valid schedule exists.

**Proof.**  
`search` explores **all** possibilities: for the chosen column `c` it tries every
row that contains `c`. For each such row it recursively explores all completions.
If none succeed, then there is no row covering `c` that can be extended to a full
cover, i.e. no exact cover exists for the current instance. By Lemma&nbsp;1 the
instance at each recursion level is exactly the set of rows compatible with the
already fixed rows, therefore failure at the top level means no set of rows covers
all columns – no valid schedule exists. ∎



##### Theorem  
The program outputs

* “YES” followed by `q` triples that use every vial exactly once **iff**
  such a set of triples exists,
* otherwise it outputs “NO”.

**Proof.**  
*If* the program prints “YES”, it did so after `search` reached the empty‑column
condition. By Lemma&nbsp;2 the printed triples form a valid schedule.

*Only‑if*: assume a valid schedule exists. By Lemma&nbsp;3 `search` will find one,
hence will reach the empty‑column condition and the program prints “YES”.  
If `search` fails, by Lemma&nbsp;4 no schedule exists, and the program prints “NO”. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Construction* creates `3·t` nodes → `O(t)` time and memory.

During the search each node is removed and restored at most once per recursion
level, therefore the total work is `O(number_of_nodes × recursion_depth)`.
In the worst case `O(t·q) ≤ 20000·200 = 4·10⁶` elementary operations, easily inside
the limits. Memory consumption is `O(t)` nodes ≈ `3·20000 = 60000` integers,
well below 256 MB.

#### Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    q = int(next(it))
    t = int(next(it))
    n = 3 * q                     # number of columns
    rows = []                     # list of triples (0‑based column indices)
    for _ in range(t):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        c = int(next(it)) - 1
        rows.append((a, b, c))

    # ---------- build dancing links ----------
    max_nodes = t * 3 + n + 1      # +1 for head
    U = [0] * max_nodes
    D = [0] * max_nodes
    L = [0] * max_nodes
    R = [0] * max_nodes
    C = [0] * max_nodes            # column of node
    row_of = [0] * max_nodes

    S = [0] * (n + 1)              # column sizes, column 0 is head
    head = 0

    # initialise column headers (0 is head, 1..n are real columns)
    for i in range(n + 1):
        U[i] = D[i] = i
        L[i] = i - 1
        R[i] = i + 1
    L[0] = n
    R[n] = 0

    node_id = n + 1                # next free node index
    for r_idx, (a, b, c) in enumerate(rows):
        first = None
        for col in (a + 1, b + 1, c + 1):   # columns are 1‑based in DLX
            nid = node_id
            node_id += 1
            C[nid] = col
            row_of[nid] = r_idx

            # insert into column list (at bottom)
            U[nid] = U[col]
            D[nid] = col
            D[U[col]] = nid
            U[col] = nid
            S[col] += 1

            # link row horizontally
            if first is None:
                first = nid
                L[nid] = R[nid] = nid
            else:
                L[nid] = L[first]
                R[nid] = first
                R[L[first]] = nid
                L[first] = nid

    # ---------- DLX operations ----------
    def cover(col: int) -> None:
        # remove column header
        L[R[col]] = L[col]
        R[L[col]] = R[col]
        # remove rows
        i = D[col]
        while i != col:
            j = R[i]
            while j != i:
                U[D[j]] = U[j]
                D[U[j]] = D[j]
                S[C[j]] -= 1
                j = R[j]
            i = D[i]

    def uncover(col: int) -> None:
        i = U[col]
        while i != col:
            j = L[i]
            while j != i:
                S[C[j]] += 1
                U[D[j]] = j
                D[U[j]] = j
                j = L[j]
            i = U[i]
        L[R[col]] = col
        R[L[col]] = col

    answer_rows = []

    def search(k: int) -> bool:
        if R[head] == head:          # all columns covered
            return True
        # choose column with minimal size
        c = R[head]
        min_s = S[c]
        j = R[c]
        while j != head:
            if S[j] < min_s:
                c = j
                min_s = S[j]
                if min_s == 0:
                    break
            j = R[j]
        if min_s == 0:
            return False
        cover(c)
        r = D[c]
        while r != c:
            answer_rows.append(row_of[r])
            j = R[r]
            while j != r:
                cover(C[j])
                j = R[j]
            if search(k + 1):
                return True
            # backtrack
            j = L[r]
            while j != r:
                uncover(C[j])
                j = L[j]
            answer_rows.pop()
            r = D[r]
        uncover(c)
        return False

    possible = search(0)

    out = []
    if possible:
        out.append("YES")
        # translate stored row indices back to original triples (1‑based)
        for rid in answer_rows:
            a, b, c = rows[rid]
            out.append(f"{a+1} {b+1} {c+1}")
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to the
required input‑output format.
