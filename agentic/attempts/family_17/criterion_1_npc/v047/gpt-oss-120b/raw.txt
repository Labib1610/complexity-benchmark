**Solution Explanation**

The task is to choose `q` triples among the given `t` triples so that every number
`1 … 3q` occurs in exactly one chosen triple.
It is an *exact cover* problem:

* columns – the `3q` numbers (each must be covered once)
* rows    – the given triples (each row covers the three columns of its numbers)

We have to find a set of rows that covers every column exactly once.
`3q ≤ 600`, `t ≤ 20000`.  
The classic algorithm for exact cover is **Algorithm X** with the
*Dancing Links* (DLX) data structure.  
With the heuristic “choose the column with the smallest number of rows”
the search tree is usually tiny for the given limits, and the implementation
fits easily into the time and memory limits.

--------------------------------------------------------------------

#### Data structures

* `head` – dummy column header.
* For each column `c` (number `1 … 3q`) we store
  * `size[c]` – how many rows currently contain this column.
  * doubly linked list of column headers (`L`, `R`) to allow O(1) removal.
* For each node (intersection of a row and a column) we store
  * `U, D, L, R` – four directional links (the dancing links).
  * `col[node]` – the column of the node.
* For each row we keep the index of one of its nodes (`row_head[row]`);
  from there we can traverse the whole row.

All arrays are plain Python lists of integers; the total number of nodes is
`3 * t ≤ 60000`.

--------------------------------------------------------------------

#### Core operations (standard DLX)

* **cover(c)** – removes column `c` and all rows that contain `c` from the
  structure.
* **uncover(c)** – restores everything removed by the last `cover(c)`.
* **search(k)** – recursive backtracking.
  * If no column remains (`R[head] == head`) we have found a solution;
    the current list `solution` (row indices) contains exactly `q` rows.
  * Choose column `c` with minimal `size[c]`.
  * For each row `r` that contains `c`
        * add `r` to `solution`
        * cover all other columns of `r`
        * recurse
        * on backtrack, uncover those columns and remove `r` from `solution`.

The recursion depth never exceeds `q ≤ 200`.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `YES` and a correct family of triples
iff such a family exists.

---

##### Lemma 1  
During execution of `search`, the dancing‑links structure always represents
the set of rows that are still *available* (i.e. not yet excluded by previous
choices) and the set of columns that are still *uncovered*.

**Proof.**  
Initially all rows and columns are present.  
`cover(c)` removes column `c` and, for every row `r` that contains `c`,
removes the whole row `r` (by unlinking all its nodes from their columns).
Thus after `cover(c)` the structure contains exactly the rows that do **not**
use column `c`, and all other columns stay.  
`uncover(c)` performs the inverse operations in reverse order, restoring the
previous state. ∎



##### Lemma 2  
When `search` reaches the line `if R[head] == head` (no column left),
the rows stored in `solution` form a set of pairwise disjoint triples that
covers every number `1 … 3q` exactly once.

**Proof.**  
No column left means every column has been covered by some earlier `cover`
operation. A column is covered only when a row containing it is selected
(and all its other columns are covered as well). Because a column is removed
once it is covered, it can never be covered again, therefore two selected rows
cannot share a column. The set of selected rows therefore consists of disjoint
triples. Since all columns are removed, each column appears in exactly one of
those triples. ∎



##### Lemma 3  
If there exists a family `F` of `q` disjoint triples covering all numbers,
`search` will eventually find a solution.

**Proof.**  
Consider the recursion tree of `search`.  
At each level a column `c` is chosen. Because `F` covers all columns,
some row `r ∈ F` contains `c`. The algorithm iterates over **all** rows that
contain `c`; therefore the branch that picks this particular `r` is explored.
When that branch is taken, all other columns of `r` are covered, exactly as in
`F`. Repeating the argument for the next level shows that there is a path
that successively picks the rows of `F`. When the last row of `F` is chosen,
all columns are covered, the base case is reached and the algorithm reports
success. ∎



##### Lemma 4  
If `search` reports failure (returns `False`), no family of `q` disjoint
triples covering all numbers exists.

**Proof.**  
Assume a family `F` existed. By Lemma&nbsp;3 there is a path in the recursion
tree that selects exactly the rows of `F` and reaches the success base case.
Therefore the algorithm would have returned `True`. Contradiction. ∎



##### Theorem  
The program outputs  

* `YES` followed by `q` triples that partition `{1,…,3q}`  
  **iff** such a partition exists in the input,
* otherwise it outputs `NO`.

**Proof.**  

*If the program prints `YES`.*  
It printed the rows stored in `solution` when the base case was reached.
By Lemma&nbsp;2 these rows are disjoint triples covering all numbers, i.e. a
valid deployment.

*If a valid deployment exists.*  
By Lemma&nbsp;3 the search will find it and return `True`; the program then
prints `YES` and the found triples.

*If the program prints `NO`.*  
That happens only when `search` returns `False`. By Lemma&nbsp;4 no valid
deployment exists. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Let* `n = 3q ≤ 600`, `m = t ≤ 20000`.

* Building the DLX structure: `O(3m)` time, `O(3m + n)` memory.
* Each recursive step covers at most three columns and removes at most
  `size` rows; the total work over the whole search is proportional to the
  number of nodes that are temporarily removed and restored.
  In the worst case this is `O( (q) * 3m )`, but in practice the heuristic
  keeps the explored tree tiny.  
  With the given limits the program easily runs within the 5 s limit.

Memory consumption: at most about `4 * 3m` integers ≈ 240 KB, well below the
256 MB limit.

#### Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    q = int(next(it))
    t = int(next(it))
    n = 3 * q                     # number of columns
    triples = []
    for _ in range(t):
        a = int(next(it))
        b = int(next(it))
        c = int(next(it))
        triples.append((a, b, c))

    # ---------- DLX construction ----------
    max_nodes = 3 * t + n + 1      # plus column headers and head
    U = [0] * max_nodes
    D = [0] * max_nodes
    L = [0] * max_nodes
    R = [0] * max_nodes
    C = [0] * max_nodes           # column of node
    size = [0] * (n + 1)          # size[0] unused, columns 1..n
    row_head = [0] * t            # one node index per row

    head = 0
    # link column headers horizontally
    for i in range(n + 1):
        L[i] = i - 1
        R[i] = i + 1
        U[i] = D[i] = i
    L[0] = n
    R[n] = 0

    node_cnt = n + 1  # next free index

    for r, (a, b, c) in enumerate(triples):
        first = 0
        for col in (a, b, c):
            node = node_cnt
            node_cnt += 1
            C[node] = col
            # vertical link
            U[node] = U[col]
            D[node] = col
            D[U[col]] = node
            U[col] = node
            size[col] += 1
            # horizontal link within the row
            if first == 0:
                L[node] = R[node] = node
                first = node
            else:
                L[node] = L[first]
                R[node] = first
                R[L[first]] = node
                L[first] = node
        row_head[r] = first

    # ---------- DLX operations ----------
    def cover(col: int) -> None:
        # remove column header
        L[R[col]] = L[col]
        R[L[col]] = R[col]
        # remove rows
        i = D[col]
        while i != col:
            j = R[i]
            while j != i:
                U[D[j]] = U[j]
                D[U[j]] = D[j]
                size[C[j]] -= 1
                j = R[j]
            i = D[i]

    def uncover(col: int) -> None:
        i = U[col]
        while i != col:
            j = L[i]
            while j != i:
                size[C[j]] += 1
                U[D[j]] = j
                D[U[j]] = j
                j = L[j]
            i = U[i]
        L[R[col]] = col
        R[L[col]] = col

    solution = []

    def search(k: int) -> bool:
        if R[head] == head:          # all columns covered
            return True
        # choose column with minimal size
        c = R[head]
        min_sz = size[c]
        col = c
        j = R[c]
        while j != head:
            if size[j] < min_sz:
                min_sz = size[j]
                col = j
                if min_sz == 0:
                    break
            j = R[j]
        if min_sz == 0:
            return False
        cover(col)
        r = D[col]
        while r != col:
            solution.append(r)       # store a node belonging to the row
            j = R[r]
            while j != r:
                cover(C[j])
                j = R[j]
            if search(k + 1):
                return True
            # backtrack
            solution.pop()
            j = L[r]
            while j != r:
                uncover(C[j])
                j = L[j]
            r = D[r]
        uncover(col)
        return False

    ok = search(0)

    out = []
    if ok:
        out.append("YES")
        # translate stored nodes back to triples
        for node in solution:
            cols = []
            x = node
            while True:
                cols.append(C[x])
                x = R[x]
                if x == node:
                    break
            out.append(" ".join(map(str, sorted(cols))))
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
