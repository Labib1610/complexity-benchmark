**Solution Explanation**

For the `3 q` sectors we have to choose `q` protocols (triples) such that

* every sector appears in exactly one chosen triple,
* no sector appears in two different chosen triples.

In other words we have to find an *exact cover* of the set `{1,…,3q}` by the given
triples.  
`q ≤ 200` and `t ≤ 20000`, therefore a back‑tracking search with a good
heuristic is fast enough.

--------------------------------------------------------------------

#### 1.   Data structures

* `triples` – list of all given triples, each stored as a tuple of three ints.
* `by_elem[e]` – list of indices of triples that contain sector `e`
  (`e` runs from `1` to `3q`).
* `used[e]` – boolean array, `True` iff sector `e` is already covered.
* `solution` – list of indices of triples that are currently chosen.

--------------------------------------------------------------------

#### 2.   Heuristic – choose the most constrained uncovered sector  

During the search we look at all still uncovered sectors and pick the one
with the smallest number of *still usable* triples (a triple is usable iff
none of its three sectors is covered yet).  
Choosing the most constrained sector reduces the branching factor dramatically
(standard “minimum remaining values” heuristic).

--------------------------------------------------------------------

#### 3.   Recursive search  

```
search():
    if every sector is covered:   # i.e. all used[1..3q] are True
            return True
    pick an uncovered sector x with the smallest number of usable triples
    for each triple idx in by_elem[x]:
            (a,b,c) = triples[idx]
            if used[a] or used[b] or used[c]:   # not usable any more
                    continue
            # choose this triple
            used[a] = used[b] = used[c] = True
            solution.append(idx)
            if search():          # recurse
                    return True
            # backtrack
            solution.pop()
            used[a] = used[b] = used[c] = False
    return False
```

The recursion depth is at most `q ≤ 200`.  
All operations inside a call are `O(3q)` in the worst case (scanning the
uncovered sectors to find the best one).  
The total running time is well below the limit for the given constraints.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct collection of triples
iff such a collection exists.

---

##### Lemma 1  
During the execution of `search` the array `used` is always consistent with
`solution`: a sector is marked `True` exactly when it belongs to one of the
triples stored in `solution`.

**Proof.**  
Initially both are empty/`False`.  
When a triple is added, the three sectors are set to `True`; when the triple
is removed (backtrack) the same three sectors are reset to `False`. No other
modifications of `used` happen. ∎



##### Lemma 2  
If `search` reaches the line `return True` (all sectors covered) then the
triples stored in `solution` form a valid exact cover.

**Proof.**  
All sectors are marked `True`, therefore by Lemma&nbsp;1 each sector appears in
some triple of `solution`.  
Because a sector is never marked `True` twice, it appears in **exactly one**
triple. Hence `solution` is an exact cover. ∎



##### Lemma 3  
If there exists an exact cover, `search` will eventually return `True`.

**Proof.**  
Consider any recursive call with the current partial set `P` of triples
(`solution`).  
If `P` is a subset of some exact cover `C`, then at least one uncovered
sector `x` belongs to a triple `t ∈ C`.  
`search` tries **all** usable triples that contain `x`. In particular it will
try `t`. Adding `t` keeps the invariant “current set is a subset of `C`”.
Thus the recursion can follow the triples of `C` step by step until all
sectors are covered, where Lemma&nbsp;2 makes it return `True`. ∎



##### Lemma 4  
If `search` returns `False`, no exact cover exists.

**Proof.**  
Assume the contrary: an exact cover `C` exists but the current call returns
`False`.  
The call examines the chosen sector `x`. Every usable triple containing `x`
is tried. For each such triple `t` the recursive call after adding `t`
returns `False`. By the induction hypothesis (recursion depth is smaller)
the set `solution ∪ {t}` cannot be extended to an exact cover, i.e. no exact
cover contains `t`. Since `C` must contain some triple covering `x`, this is a
contradiction. ∎



##### Theorem  
The program outputs  

* `YES` followed by `q` triples that exactly cover all sectors **iff**
  such a collection exists,
* otherwise it outputs `NO`.

**Proof.**  
If the program prints `YES`, it did so after `search` returned `True`.  
By Lemma&nbsp;2 the printed triples form a correct exact cover.

If the program prints `NO`, `search` returned `False`.  
By Lemma&nbsp;4 no exact cover exists. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Pre‑processing*  
`O(t)` to read input and fill `by_elem`.

*Search*  
Depth ≤ `q`.  
In each call we scan at most `3q` sectors to pick the most constrained one,
and for each tried triple we touch only its three sectors.
Hence the total work is `O( q · 3q + number_of_visited_nodes · 3 )`.  
In practice the heuristic keeps the number of visited nodes very small; the
worst‑case bound is far below the limits (`q ≤ 200`, `t ≤ 20000`).

Memory consumption:  
`used` – `3q+1 ≤ 601` booleans,  
`by_elem` – `3q` lists, total `3·t` integers ≤ `60000`.  
All well inside 256 MB.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    q = int(next(it))
    t = int(next(it))
    n = 3 * q
    triples = []
    by_elem = [[] for _ in range(n + 1)]
    for idx in range(t):
        a = int(next(it)); b = int(next(it)); c = int(next(it))
        triples.append((a, b, c))
        by_elem[a].append(idx)
        by_elem[b].append(idx)
        by_elem[c].append(idx)

    used = [False] * (n + 1)
    solution = []

    # list of uncovered elements for fast iteration
    uncovered = set(range(1, n + 1))

    def choose_sector():
        """return uncovered sector with minimal number of usable triples"""
        best = None
        best_cnt = None
        for x in uncovered:
            cnt = 0
            for idx in by_elem[x]:
                a, b, c = triples[idx]
                if not (used[a] or used[b] or used[c]):
                    cnt += 1
            if cnt == 0:
                # dead end, prune immediately
                return x, 0
            if best_cnt is None or cnt < best_cnt:
                best_cnt = cnt
                best = x
                if cnt == 1:
                    break
        return best, best_cnt

    def dfs() -> bool:
        if not uncovered:
            return True
        x, cnt = choose_sector()
        if cnt == 0:
            return False
        for idx in by_elem[x]:
            a, b, c = triples[idx]
            if used[a] or used[b] or used[c]:
                continue
            # choose this triple
            used[a] = used[b] = used[c] = True
            uncovered.discard(a); uncovered.discard(b); uncovered.discard(c)
            solution.append(idx)
            if dfs():
                return True
            # backtrack
            solution.pop()
            used[a] = used[b] = used[c] = False
            uncovered.add(a); uncovered.add(b); uncovered.add(c)
        return False

    if dfs():
        out = ["YES"]
        for idx in solution:
            a, b, c = triples[idx]
            out.append(f"{a} {b} {c}")
        sys.stdout.write("\n".join(out))
    else:
        sys.stdout.write("NO")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
