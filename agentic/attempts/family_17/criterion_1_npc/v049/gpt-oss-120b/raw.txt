**Solution Explanation**

The problem asks for a *perfect* packing of the numbers `1 … 3q` with triples taken from a given list.
Every number has to appear in exactly one chosen triple – this is the classic *exact‑cover*
problem.  
We solve it with Donald Knuth’s **Algorithm X** together with the
*Dancing Links* data structure (DLX).  
The universe has at most `3·200 = 600` elements, the number of triples is at most `20000`,
so DLX easily fits into the limits.

--------------------------------------------------------------------

#### 1.   DLX data structure  

*Columns* – one for each element `1 … 3q`.  
*Rows* – one for each given triple.  
A node belongs to a row and a column; the four neighbour pointers (`L,R,U,D`)
form circular doubly linked lists horizontally (row) and vertically (column).

Additional arrays  

* `size[c]` – number of nodes still present in column `c` (used for the heuristic).  
* `row_id[node]` – which input triple the node belongs to (needed to output the answer).  

The header node `head` links all still‑alive columns.

All operations are *O(1)*:

* **cover(c)** – removes column `c` and all rows that contain `c`.  
* **uncover(c)** – restores them (exact inverse).

--------------------------------------------------------------------

#### 2.   Algorithm X (recursive search)

```
search():
    if no column left → all elements covered → success
    choose column c with minimal size
    cover(c)
    for each row r in column c:
        add r to partial solution
        for each node j in row r (except c):
            cover(column_of(j))
        if search() succeeds → propagate success
        for each node j in row r (reverse order):
            uncover(column_of(j))
        remove r from partial solution
    uncover(c)
    return failure
```

Because every chosen row removes exactly three columns, the recursion depth is at most `q`
(≤ 200). The heuristic “column with smallest size” keeps the branching factor tiny in practice.

--------------------------------------------------------------------

#### 3.   Building the structure

* Columns are numbered `1 … 3q`.  
* For each input triple `(a,b,c)` we create three nodes, link them horizontally,
  and insert each into the bottom of its column’s vertical list.
* While inserting we store the index of the triple (`0‑based`) in `row_id`.

--------------------------------------------------------------------

#### 4.   Output  

If the search succeeds we have a list of row indices (the chosen triples).
We print

```
YES
triple_1
triple_2
...
triple_q
```

otherwise we print `NO`.

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` with a valid schedule iff such a schedule
exists.

---

##### Lemma 1  
At any moment of the search, the set of uncovered columns is exactly the set of
elements that are not yet covered by the rows stored in the current partial solution.

**Proof.**  
Initially all columns are uncovered, no element is covered – true.  
When a row `r` is added, `cover` is called for each column appearing in `r`.  
`cover` removes the column and all rows that intersect it, i.e. it marks the
corresponding element as covered and forbids any later row that would reuse it.
Thus after processing `r` the uncovered columns are precisely the still‑uncovered
elements. The reverse operation `uncover` restores the previous state.
∎



##### Lemma 2  
`search` returns success **iff** the rows stored in the partial solution form a
perfect packing of all `3q` elements.

**Proof.**  
*If* `search` reaches the base case “no column left”, by Lemma&nbsp;1 every element
is covered, and because a column is removed only together with all rows that contain
it, no element can be covered twice. Hence the stored rows are a perfect packing.

*Only‑if* assume a perfect packing `S` exists. Consider the recursion tree.
At each level the algorithm chooses a column `c`. Since `S` covers all elements,
some row `r∈S` contains `c`. That row is among the rows iterated in the `for` loop.
When the algorithm tries exactly this `r`, it covers all columns of `r`,
which are also covered by `S`. The remaining uncovered columns are exactly those
covered by `S \ {r}` (Lemma&nbsp;1). By induction the recursive call can follow the
remaining rows of `S` and finally reaches the empty‑column base case, thus returns
success. ∎



##### Lemma 3  
If a perfect packing exists, `search` will eventually explore the branch that
chooses exactly the rows of that packing.

**Proof.**  
From Lemma&nbsp;2 we know that at each recursion level there is at least one row of the
desired packing that contains the selected column. The algorithm iterates **all**
rows of that column, therefore the branch that picks the correct row is present in
the search tree. ∎



##### Theorem  
The program outputs `YES` followed by a set of `q` triples that partition
`{1,…,3q}` **iff** such a set exists; otherwise it outputs `NO`.

**Proof.**  

*Soundness.*  
If the program prints `YES`, it has obtained a successful return from `search`.
By Lemma&nbsp;2 the stored rows form a perfect packing, i.e. a valid schedule.

*Completeness.*  
If a valid schedule exists, Lemma&nbsp;3 guarantees that the recursive search contains
a branch that exactly follows its rows, and Lemma&nbsp;2 shows that this branch leads
to success. Consequently `search` returns success and the program prints `YES`.

If no schedule exists, no branch can satisfy the base case, therefore `search`
fails and the program prints `NO`. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Let* `n = 3q ≤ 600`, `m = t ≤ 20000`.

* Building the DLX structure: `O(m·3)` = `O(m)`.
* Each recursive step covers at most three columns and iterates over the rows of the
  chosen column. Because of the minimal‑size heuristic the total number of node
  operations is bounded by `O(m·q)` in the worst case, which is far below the limits
  (`200·20000 = 4·10⁶`).

Memory consumption: one node per matrix entry → `3·m ≤ 60000` nodes,
each node stores four integers → well under the 256 MiB limit.

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    q = int(next(it))
    t = int(next(it))
    triples = []
    for _ in range(t):
        a = int(next(it)); b = int(next(it)); c = int(next(it))
        triples.append((a, b, c))

    n = 3 * q                     # number of columns (elements)
    max_nodes = 3 * t + n + 1     # plus column headers and head

    # DLX arrays
    L = [0] * max_nodes
    R = [0] * max_nodes
    U = [0] * max_nodes
    D = [0] * max_nodes
    C = [0] * max_nodes           # column of node
    row_id = [0] * max_nodes      # which triple this node belongs to
    size = [0] * (n + 1)          # column sizes, 1..n

    head = 0
    # initialise header list of columns
    for i in range(n + 1):
        L[i] = i - 1
        R[i] = i + 1
        U[i] = D[i] = i
    L[0] = n
    R[n] = 0

    node_cnt = n + 1  # next free index

    # add rows
    for idx, (a, b, c) in enumerate(triples):
        cols = [a, b, c]
        first = -1
        for col in cols:
            node = node_cnt
            node_cnt += 1
            C[node] = col
            row_id[node] = idx

            # vertical link (insert at bottom of column)
            U[node] = U[col]
            D[node] = col
            D[U[col]] = node
            U[col] = node
            size[col] += 1

            # horizontal link
            if first == -1:
                first = node
                L[node] = R[node] = node
            else:
                # insert to the right of first
                L[node] = L[first]
                R[node] = first
                R[L[first]] = node
                L[first] = node

    solution_rows = []

    def cover(col: int) -> None:
        # remove column header
        L[R[col]] = L[col]
        R[L[col]] = R[col]
        # remove rows
        i = D[col]
        while i != col:
            j = R[i]
            while j != i:
                U[D[j]] = U[j]
                D[U[j]] = D[j]
                size[C[j]] -= 1
                j = R[j]
            i = D[i]

    def uncover(col: int) -> None:
        i = U[col]
        while i != col:
            j = L[i]
            while j != i:
                size[C[j]] += 1
                U[D[j]] = j
                D[U[j]] = j
                j = L[j]
            i = U[i]
        L[R[col]] = col
        R[L[col]] = col

    def search(k: int) -> bool:
        if R[head] == head:          # all columns covered
            return True
        # choose column with minimal size
        c = R[head]
        min_sz = size[c]
        col = c
        j = R[c]
        while j != head:
            if size[j] < min_sz:
                min_sz = size[j]
                col = j
                if min_sz == 0:
                    break
            j = R[j]
        if min_sz == 0:
            return False
        cover(col)
        r = D[col]
        while r != col:
            solution_rows.append(row_id[r])
            j = R[r]
            while j != r:
                cover(C[j])
                j = R[j]
            if search(k + 1):
                return True
            # backtrack
            j = L[r]
            while j != r:
                uncover(C[j])
                j = L[j]
            solution_rows.pop()
            r = D[r]
        uncover(col)
        return False

    ok = search(0)
    out = []
    if ok:
        out.append("YES")
        for idx in solution_rows:
            a, b, c = triples[idx]
            out.append(f"{a} {b} {c}")
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to the
required input‑output format.
