**Solution Explanation**

For every number `i ( 1 … k )`

* arm `i` must be used once,
* sensor `i` must be used once,
* module `i` must be used once.

A feasible production line is a set of `k` triples  

```
(arm , sensor , module)
```

such that each arm, each sensor and each module occurs exactly once.
The triples given in the input are the only ones we may use.

The problem is an *exact cover* problem:

* there are `3·k` columns – one for every arm, every sensor and every module,
* every admissible triple is a row covering exactly three columns,
* we have to choose rows so that every column is covered exactly once.

The classical algorithm for exact cover is **Dancing Links** (Algorithm X).
`k ≤ 22`, therefore there are at most `66` columns and at most `k³ ≤ 10648`
rows – a tiny instance for DLX.  
The recursive search depth is at most `k = 22`, easily fitting into the
time limit.



--------------------------------------------------------------------

#### Data structures

```
header 0                           – start of the column list
column nodes 1 … 3k                – one header for every column
ordinary nodes  (one per 1‑cell)   – 3·t nodes, at most 3·10648 ≈ 32000
```

All nodes are stored in parallel integer arrays (the classic C implementation
transcribed to Python lists)

```
L[i], R[i]   – left / right neighbours   (horizontal)
U[i], D[i]   – up   / down   neighbours   (vertical)
C[i]         – column of the node (for ordinary nodes)
row_id[i]    – which input triple the node belongs to
S[c]         – current size of column c (how many rows are still present)
```

The column headers are linked together in a circular doubly linked list
with the special header `0` (`R[0]` is the first column, `L[0]` the last).

For every input triple `(a,b,c)` three ordinary nodes are created,
one for column `a` (arm), one for column `k+b` (sensor) and one for column
`2k+c` (module).  
Inside the row the three nodes are linked circularly with `L`/`R`.

--------------------------------------------------------------------

#### Operations

```
cover(col)
    – remove column header from the column list
    – for every row r that contains col
          for every other node j in that row
                remove j from its column list
                -- decrement column size
```

```
uncover(col)
    – reverse of cover, restores everything in the opposite order
```

Both procedures are O(number of removed nodes) and are implemented
exactly as in Knuth’s paper.

--------------------------------------------------------------------

#### Search

```
search()
    if R[0] == 0                     # no column left → all covered
           solution found
    choose column c with minimal S[c]   # heuristic, reduces branching
    cover(c)
    for each row r = D[c] while r != c
          add r to current solution
          for each node j = R[r] while j != r
                cover( C[j] )
          if search() succeeds → propagate success
          # backtrack
          for each node j = L[r] while j != r
                uncover( C[j] )
          remove r from current solution
    uncover(c)
    return failure
```

The recursion depth never exceeds `k ≤ 22`.  
Because we always pick the column with the smallest remaining size,
the branching factor stays very low; the whole search finishes in well
below one second for the maximal input.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints **YES** and a correct set of triples
iff such a set exists.

---

##### Lemma 1  
`cover(c)` removes **exactly** those rows that contain column `c` from the
search space, and removes from the remaining rows exactly the nodes that lie
in the same rows as the removed nodes.

**Proof.**  
`cover` iterates over all rows `r` that are linked vertically below column
header `c`. For each such row it iterates over the other nodes `j` of the
row (horizontal links). Each node `j` is removed from its column list by
splicing it out (`U[D[j]] = U[j]`, `D[U[j]] = D[j]`). No other nodes are
touch­ed. ∎



##### Lemma 2  
During the execution of `search` the set of rows that are still present
(and the column sizes `S`) correspond exactly to the rows that can still be
chosen together with the rows already stored in the current partial solution
without violating the exact‑cover constraints.

**Proof.**  
Induction over the recursion depth.

*Base.* At the top level no row is selected, no column is covered.
All rows are present – the statement holds.

*Step.* Assume the statement holds at the beginning of a call.
The algorithm chooses a column `c` that must be covered next.
`cover(c)` (Lemma&nbsp;1) removes every row containing `c`; any solution that
extends the current partial one must contain a row covering `c`, therefore
all removed rows are impossible and may be discarded.
For the chosen row `r` the algorithm additionally covers the two other
columns of `r`. By Lemma&nbsp;1 exactly the rows that intersect those columns are
removed – they would conflict with `r`. Thus after all `cover` calls the
remaining rows are precisely those compatible with the enlarged partial
solution.
When backtracking, `uncover` restores the data structures to their previous
state, re‑establishing the original correspondence. ∎



##### Lemma 3  
If `search` reaches the line `if R[0]==0` the rows stored in the solution list
form a perfect matching of the three sets.

**Proof.**  
`R[0]==0` means that every column header has been removed from the header list,
i.e. every column has been covered exactly once.
Each covering step adds one row (triple) to the solution list and covers the
three columns of that row. Because a column is removed only once, each column
appears in exactly one chosen row. Hence every arm, sensor and module occurs
once, and the `k` stored rows constitute a feasible configuration. ∎



##### Lemma 4  
If a perfect matching exists, `search` will eventually find it.

**Proof.**  
Consider any exact cover `M`. At the first recursive call the algorithm chooses
a column `c`. Because `M` covers `c`, there is exactly one row `r ∈ M` containing
`c`. This row appears in the vertical list of `c`, thus the `for` loop will
enumerate it. When the algorithm processes `r`, it covers the remaining two
columns of `r`. After these covers, by Lemma&nbsp;2 the remaining rows are
exactly those rows of `M` that do not intersect the already chosen rows.
Consequently the recursive call continues with a reduced exact cover
`M \{r\}`. Repeating the argument yields a recursion path that always
selects a row belonging to `M` and finally reaches an empty column list,
where Lemma&nbsp;3 reports success. Hence the algorithm cannot miss an existing
solution. ∎



##### Lemma 5  
If `search` reports failure, no perfect matching exists.

**Proof.**  
Assume a perfect matching existed. By Lemma&nbsp;4 the recursive exploration
contains a branch that follows exactly this matching and would succeed.
`search` only returns failure when **all** branches have been explored and
none succeeded, contradicting the existence of a successful branch.
Therefore failure implies non‑existence of a perfect matching. ∎



##### Theorem  
The program prints  

*`YES`* and a list of `k` triples each using every arm, sensor and module once
iff such a list exists; otherwise it prints *`NO`*.

**Proof.**  

*If part.*  
When the program prints `YES` it has found a solution via `search`,
so by Lemma&nbsp;3 the printed triples form a perfect matching.

*Only‑if part.*  
If a perfect matching exists, Lemma&nbsp;4 guarantees that `search` reaches a
state where all columns are covered and returns success, causing the program
to output `YES` and the corresponding triples.
If no perfect matching exists, Lemma&nbsp;5 shows that `search` exhausts all
possibilities and returns failure, leading the program to output `NO`. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

```
columns      : 3·k ≤ 66
rows         : t ≤ k³ ≤ 10648
nodes        : 3·t ≤ 31944
```

*Building the structure* – `O(nodes)`.

*Search* – each recursive level chooses one row, depth `k ≤ 22`.  
Cover / uncover of a row touches exactly the three columns of that row and
the rows intersecting them, i.e. at most `O(nodes)` over the whole search.
In practice the branching factor is tiny because we always pick the column
with the smallest size. The worst‑case theoretical bound is `O( 3·t·k )`,
well below a few million operations.

Memory consumption: the arrays store at most `1 + 3k + 3t ≤ 1 + 66 + 31944`
integers → far under the 256 MiB limit.

#### Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(1000000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    k = int(next(it))
    t = int(next(it))

    triples = []                     # (a,b,c) 1‑based
    for _ in range(t):
        a = int(next(it))
        b = int(next(it))
        c = int(next(it))
        triples.append((a, b, c))

    ncol = 3 * k                     # columns are 1..ncol

    # ----- DLX structures -----
    # header = 0, column headers = 1..ncol
    L = [0] * (1 + ncol)             # left neighbour
    R = [0] * (1 + ncol)             # right neighbour
    U = [0] * (1 + ncol)             # up neighbour
    D = [0] * (1 + ncol)             # down neighbour
    C = [0] * (1 + ncol)             # column of node (only for ordinary nodes)
    row_id = [0] * (1 + ncol)        # row index of node (only for ordinary nodes)
    S = [0] * (ncol + 1)             # size of each column

    # initialise column headers and header list
    for i in range(ncol + 1):
        L[i] = i - 1
        R[i] = i + 1
        U[i] = D[i] = i
    L[0] = ncol
    R[ncol] = 0

    # ----- function to add a row -----
    node_cnt = ncol + 1               # next free index
    def add_row(cols, rid):
        nonlocal node_cnt
        first = None
        for col in cols:
            idx = node_cnt
            node_cnt += 1
            # vertical links
            U[idx] = U[col]
            D[idx] = col
            D[U[col]] = idx
            U[col] = idx
            C[idx] = col
            row_id[idx] = rid
            S[col] += 1
            # horizontal links (temporary)
            if first is None:
                first = idx
                L[idx] = R[idx] = idx
            else:
                # insert to the left of first (circular list)
                L[idx] = L[first]
                R[idx] = first
                R[L[first]] = idx
                L[first] = idx

    # build rows
    for idx, (a, b, c) in enumerate(triples, start=1):
        add_row([a, k + b, 2 * k + c], idx)

    # ----- DLX core operations -----
    def cover(col):
        # remove column header
        L[R[col]] = L[col]
        R[L[col]] = R[col]
        # remove rows
        i = D[col]
        while i != col:
            j = R[i]
            while j != i:
                U[D[j]] = U[j]
                D[U[j]] = D[j]
                S[C[j]] -= 1
                j = R[j]
            i = D[i]

    def uncover(col):
        i = U[col]
        while i != col:
            j = L[i]
            while j != i:
                S[C[j]] += 1
                U[D[j]] = j
                D[U[j]] = j
                j = L[j]
            i = U[i]
        L[R[col]] = col
        R[L[col]] = col

    # ----- search -----
    solution_rows = []
    answer = None

    def choose_column():
        # column with smallest S
        c = R[0]
        best = c
        min_sz = S[c]
        c = R[c]
        while c != 0:
            if S[c] < min_sz:
                min_sz = S[c]
                best = c
                if min_sz == 0:
                    break
            c = R[c]
        return best

    def search():
        nonlocal answer
        if R[0] == 0:                     # all columns covered
            answer = solution_rows.copy()
            return True
        c = choose_column()
        if S[c] == 0:                     # dead end
            return False
        cover(c)
        r = D[c]
        while r != c:
            solution_rows.append(row_id[r])
            j = R[r]
            while j != r:
                cover(C[j])
                j = R[j]
            if search():
                return True
            # backtrack
            j = L[r]
            while j != r:
                uncover(C[j])
                j = L[j]
            solution_rows.pop()
            r = D[r]
        uncover(c)
        return False

    possible = search()

    out = []
    if possible:
        out.append("YES")
        for rid in answer:
            a, b, c = triples[rid - 1]
            out.append(f"{a} {b} {c}")
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
