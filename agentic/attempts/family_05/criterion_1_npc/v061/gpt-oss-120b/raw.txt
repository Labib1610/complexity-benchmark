**Solution Explanation**

For every recipe we have exactly one copy.
A progression `(x , y , z)` consumes the three copies  
`(phase‑1 , x) , (phase‑2 , y) , (phase‑3 , z)`.
We have to choose `k` progressions so that every copy is used once.
That is exactly the *exact cover* problem:

* columns – one for every copy ( `3·k` columns )  
* rows    – one for every allowed progression ( at most `k³` rows )  
* a row contains three `1`s, the columns of the three copies it uses  

We have to find a set of rows covering every column exactly once.

`k ≤ 22`, therefore `3·k ≤ 66`.  
The number of rows is at most `22³ = 10648`.  
For such sizes Donald Knuth’s **Algorithm X** with dancing links (DLX) solves the
exact cover problem instantly.

--------------------------------------------------------------------

#### 1.   Data structures (DLX)

* `L,R,U,D` – four doubly linked lists (arrays of integers).  
  `0` is the header node, columns are numbered `1 … C` (`C = 3·k`).
* `S[c]` – number of rows still containing column `c`.
* `row_id[node]` – which original progression a node belongs to.
* `col[node]` – column of a node.

For each row we create three nodes and link them vertically into their column
list and horizontally into a circular list of the row.

Maximum number of nodes  

```
max_nodes = C                # column headers
          + t * 3            # three nodes per row
          + 1                # header
```

All arrays are sized a little larger.

--------------------------------------------------------------------

#### 2.   Algorithm X (recursive search)

```
search():
    if header.R == 0               # no uncovered column → solution found
        return True
    choose column c with minimal S[c]   (heuristic)
    cover(c)
    for each row r in column c (downwards):
        add r to current solution
        for each node j in row r (rightwards):
            cover( col[j] )
        if search(): return True
        # backtrack
        for each node j in row r (leftwards):
            uncover( col[j] )
        remove r from solution
    uncover(c)
    return False
```

`cover(c)` removes column `c` and all rows that contain it from the matrix,
`uncover(c)` restores them – both are pure pointer manipulations, `O(number of
1‑entries removed)`.

The recursion depth never exceeds `k` because each chosen row consumes exactly
one column of each phase, i.e. three columns, and we have `3·k` columns.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints “YES” and a correct set of progressions
iff such a set exists.

---

##### Lemma 1  
During the execution of `search` the matrix represented by the dancing links
contains exactly the rows that are still *compatible* with the rows already
chosen in the current recursion path.

**Proof.**  
`cover(c)` removes column `c` and every row that contains `c`.  
All those rows would use a copy already taken by the chosen row that covered
`c`, therefore they are incompatible and must be discarded.
`uncover(c)` restores exactly those rows and the column, i.e. the matrix returns
to the previous state. ∎



##### Lemma 2  
When `search` reaches the line `if header.R == 0` all columns are covered and
the rows stored in the current solution use each copy exactly once.

**Proof.**  
`header.R == 0` means no column header is linked to the header → every column
has been covered by a previous `cover`.  
Each `cover` is performed only for a column that belongs to a row that has been
added to the solution, therefore each column is covered by exactly one chosen
row. ∎



##### Lemma 3  
If there exists a set `S` of `k` progressions covering all copies, `search`
will eventually find a solution.

**Proof.**  
Consider the recursion tree of `search`.  
At each level it chooses a column `c`. Because `S` covers all columns,
some row `r ∈ S` contains `c`. That row is present in the column list of `c`
(Lemma&nbsp;1). The algorithm iterates over **all** rows of `c`, therefore it
will try `r`. After choosing `r` all columns of `r` are covered, and the
remaining rows of `S` are still present (they do not intersect `r` on any
column). Repeating the argument for the next level shows that there is a path
following exactly the rows of `S`. When the last row is chosen, all columns are
covered, the base case is reached and the algorithm returns success. ∎



##### Lemma 4  
If `search` returns a solution, the printed progressions form a valid answer.

**Proof.**  
By Lemma&nbsp;2 the returned set of rows covers every column exactly once.
Each row corresponds to one allowed progression, therefore the printed
progressions are allowed and each copy of each recipe appears in exactly one
progression. The number of rows is `k` because `3·k` columns are covered and each
row covers three columns. ∎



##### Lemma 5  
If no set of `k` progressions covering all copies exists, `search` returns
`False`.

**Proof.**  
Assume the contrary: `search` would return `True`. By Lemma&nbsp;4 the returned
set would be a valid covering, contradicting the assumption. ∎



##### Theorem  
The program outputs  

* “YES” and a list of `k` progressions **iff** such a list exists,  
* otherwise “NO”.

**Proof.**  
*If part*: existence ⇒ by Lemma&nbsp;3 `search` finds a solution,
by Lemma&nbsp;4 the printed list is valid, program prints “YES”.

*Only‑if part*: program prints “YES” ⇒ `search` succeeded ⇒ by Lemma&nbsp;4
the printed list is a valid covering ⇒ such a list exists.

If the program prints “NO”, `search` returned `False`; by Lemma&nbsp;5 no
valid covering exists. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Let* `C = 3·k ≤ 66`, `R = t ≤ k³ ≤ 10648`.

* Building the structure: `O(C + 3·R)` time, `O(C + 3·R)` memory.
* Each recursive step covers one column and at most `R` rows, but the total
  work of all `cover`/`uncover` operations over the whole search is
  `O(number of 1‑entries) = O(3·R)`.
* The recursion depth is at most `k ≤ 22`.

Hence the worst‑case time is well below a few million elementary operations,
comfortably inside the limits. Memory consumption is below
`(C + 3·R) * 4 * 4 bytes ≈ 0.5 MiB`.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    k = int(next(it))
    t = int(next(it))

    triples = []
    for _ in range(t):
        x = int(next(it)) - 1
        y = int(next(it)) - 1
        z = int(next(it)) - 1
        triples.append((x, y, z))

    C = 3 * k                     # number of columns
    max_nodes = 1 + C + 3 * t + 5

    # dancing links arrays
    L = [0] * max_nodes
    R = [0] * max_nodes
    U = [0] * max_nodes
    D = [0] * max_nodes
    col = [0] * max_nodes
    row_id = [0] * max_nodes
    S = [0] * (C + 1)             # column sizes, 1‑based

    # header = 0, column headers 1..C
    for i in range(C + 1):
        L[i] = i - 1
        R[i] = i + 1
        U[i] = D[i] = i
    L[0] = C
    R[C] = 0

    node_cnt = C + 1              # next free index

    # add rows
    for idx, (x, y, z) in enumerate(triples):
        cols = [x + 1, k + y + 1, 2 * k + z + 1]   # 1‑based column numbers
        first = -1
        for c in cols:
            nd = node_cnt
            node_cnt += 1
            col[nd] = c
            row_id[nd] = idx

            # vertical link
            U[nd] = U[c]
            D[nd] = c
            D[U[c]] = nd
            U[c] = nd
            S[c] += 1

            # horizontal link
            if first == -1:
                first = nd
                L[nd] = R[nd] = nd
            else:
                L[nd] = L[first]
                R[nd] = first
                R[L[first]] = nd
                L[first] = nd

    solution_rows = []

    sys.setrecursionlimit(10000)

    def cover(c):
        # remove column header
        L[R[c]] = L[c]
        R[L[c]] = R[c]
        # remove rows
        i = D[c]
        while i != c:
            j = R[i]
            while j != i:
                U[D[j]] = U[j]
                D[U[j]] = D[j]
                S[col[j]] -= 1
                j = R[j]
            i = D[i]

    def uncover(c):
        i = U[c]
        while i != c:
            j = L[i]
            while j != i:
                S[col[j]] += 1
                U[D[j]] = j
                D[U[j]] = j
                j = L[j]
            i = U[i]
        L[R[c]] = c
        R[L[c]] = c

    def choose_column():
        # heuristic: column with smallest S
        c = R[0]
        min_s = S[c]
        cur = R[c]
        while cur != 0:
            if S[cur] < min_s:
                min_s = S[cur]
                c = cur
                if min_s == 0:
                    break
            cur = R[cur]
        return c

    found = False

    def search():
        nonlocal found
        if R[0] == 0:          # all columns covered
            found = True
            return True
        c = choose_column()
        if S[c] == 0:          # dead end
            return False
        cover(c)
        r = D[c]
        while r != c:
            solution_rows.append(row_id[r])
            j = R[r]
            while j != r:
                cover(col[j])
                j = R[j]
            if search():
                return True
            # backtrack
            j = L[r]
            while j != r:
                uncover(col[j])
                j = L[j]
            solution_rows.pop()
            r = D[r]
        uncover(c)
        return False

    if search():
        out = ["YES"]
        for idx in solution_rows:
            x, y, z = triples[idx]
            out.append(f"{x+1} {y+1} {z+1}")
        sys.stdout.write("\n".join(out))
    else:
        sys.stdout.write("NO")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
