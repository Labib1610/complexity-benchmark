**Solution Explanation**

We have a directed graph with `n` vertices and `m` edges.
Each edge `i` has capacity `cap[i]` and we must send a **non‑negative integer**
amount `f[i] ≤ cap[i]`.

All vertices except the source `s` and the sink `t` must satisfy flow
conservation, i.e. total incoming flow = total outgoing flow.
The required net flow from `s` to `t` is exactly `d`.

This is exactly the classic **maximum s‑t flow** problem with a demand `d`.
If the maximum possible flow from `s` to `t` is at least `d`,
any flow of value `d` is a feasible plan.
Otherwise the plan is impossible.

So we:

1. Build a flow network with the given capacities.
2. Run a fast max‑flow algorithm (Dinic, `O(E·√V)` in practice, easily fast enough).
3. If `max_flow < d` → output `NO`.
4. Otherwise we have a flow of value `max_flow`.  
   Reduce it to exactly `d` by simply **ignoring the excess**:
   the algorithm already stores the flow on each edge; we keep the first `d`
   units that were sent (the flow values themselves already respect capacities,
   and decreasing the total flow by `max_flow‑d` on any s‑t path keeps all
   constraints satisfied).  
   The simplest way: after the algorithm finishes, the stored flow on each
   edge already equals some feasible flow of value `max_flow`.  
   If `max_flow > d`, we can run a second DFS from `s` to `t` that pushes back
   `max_flow‑d` units along the residual graph, effectively reducing the flow
   to exactly `d`.  
   Implementation wise we just call the same `max_flow` routine a second time
   with a **negative** additional demand `max_flow‑d` (i.e. we try to send
   `max_flow‑d` more flow from `t` to `s`).  
   After that the stored edge flows represent a flow of value `d`.

5. Output `YES` and the flow values for the original `m` edges in input order.

The algorithm runs in `O(m·√n)` which is far below the limits
(`n,m ≤ 2·10⁵` typical, 2 s, 256 MB).

---

**Correctness Proof**

We prove that the algorithm outputs `YES` with a feasible allocation
iff such an allocation exists.

*Lemma 1*  
For any integer `k`, there exists a feasible allocation with net flow `k`
from `s` to `t` **iff** the maximum s‑t flow in the network is at least `k`.

*Proof.*  
- (⇒) A feasible allocation with net flow `k` is a flow of value `k`,
  therefore the maximum flow value is ≥ `k`.
- (⇐) If the maximum flow value `F_max ≥ k`, the definition of maximum flow
  guarantees a flow of value `k` (just take a flow of value `F_max` and
  reduce it by `F_max‑k` along any s‑t path, which preserves all constraints).
∎

*Lemma 2*  
After the first Dinic run we obtain a flow `f` of value `F_max`.
Running Dinic again on the residual graph with source `t` and sink `s`
and demand `F_max‑d` reduces the stored edge flows to a flow of value `d`.

*Proof.*  
The residual graph represents all ways to augment or cancel flow.
Sending `F_max‑d` units from `t` to `s` in the residual graph is equivalent to
decreasing the original s‑t flow by the same amount, because each unit sent
from `t` to `s` traverses a reverse edge of some original s‑t path and
cancels one unit of flow on that path. Capacities are never violated,
and flow conservation still holds for all intermediate vertices.
Thus the resulting stored flows have value `d`. ∎

*Lemma 3*  
The final stored flows satisfy all problem constraints.

*Proof.*  
- Non‑negativity and capacity: Dinic never exceeds capacities; cancelling flow
  only reduces values, never makes them negative.
- Conservation for all vertices except `s,t`: Dinic maintains conservation,
  and cancelling flow along a reverse s‑t path preserves conservation at every
  intermediate vertex.
- Net departure from `s` equals `d` by construction (Lemma 2).  
  Consequently net arrival at `t` also equals `d`. ∎

*Theorem*  
The algorithm outputs `YES` and a list of edge allocations exactly when a
feasible allocation exists; otherwise it outputs `NO`.

*Proof.*  
- If the algorithm outputs `YES`, then `F_max ≥ d` (otherwise it would have
  printed `NO`). By Lemma 2 we produce a flow of value `d` that satisfies all
  constraints (Lemma 3). Hence a feasible allocation exists.
- If a feasible allocation exists, by Lemma 1 the maximum flow is at least `d`,
  so the first Dinic run yields `F_max ≥ d` and the algorithm does not output
  `NO`. It proceeds to adjust the flow to value `d` and outputs `YES`. ∎



---

**Complexity Analysis**

Let `V = n`, `E = m`.

Dinic runs in `O(E·√V)` time in practice; two runs keep the same bound.
Memory consumption: adjacency list with forward and reverse edges → `O(E)`.

Both fit easily into the limits.

**Reference Implementation (Python 3)**

```python
import sys
sys.setrecursionlimit(1 << 25)

class Dinic:
    __slots__ = ('n', 'g', 'level', 'it')
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, idx=-1):
        # forward edge
        fwd = [to, cap, None, idx]   # to, cap, rev, original index
        # backward edge
        rev = [fr, 0, fwd, -1]
        fwd[2] = rev
        self.g[fr].append(fwd)
        self.g[to].append(rev)

    def bfs(self, s, t):
        level = [-1] * self.n
        q = [s]
        level[s] = 0
        for v in q:
            for to, cap, rev, _ in self.g[v]:
                if cap and level[to] < 0:
                    level[to] = level[v] + 1
                    q.append(to)
        self.level = level
        return level[t] >= 0

    def dfs(self, v, t, f):
        if v == t:
            return f
        for i in range(self.it[v], len(self.g[v])):
            self.it[v] = i
            to, cap, rev, _ = self.g[v][i]
            if cap and self.level[v] + 1 == self.level[to]:
                ret = self.dfs(to, t, min(f, cap))
                if ret:
                    self.g[v][i][1] -= ret
                    rev[1] += ret
                    return ret
        return 0

    def max_flow(self, s, t, limit=None):
        flow = 0
        INF = 10**18
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF if limit is None else limit - flow)
                if not pushed:
                    break
                flow += pushed
                if limit is not None and flow >= limit:
                    return flow
        return flow

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it)); m = int(next(it)); _ = int(next(it))  # the third number is always 1, ignore
    s = int(next(it)) - 1
    t = int(next(it)) - 1
    d = int(next(it))
    edges = []
    dinic = Dinic(n)
    for idx in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        cap = int(next(it))
        edges.append((u, v, cap))
        dinic.add_edge(u, v, cap, idx)

    maxflow = dinic.max_flow(s, t)
    if maxflow < d:
        print("NO")
        return

    # Reduce flow to exactly d if needed
    if maxflow > d:
        # send (maxflow - d) from t to s in residual graph
        dinic.max_flow(t, s, maxflow - d)

    # collect flows for original edges
    ans = [0] * m
    for u in range(n):
        for to, cap, rev, idx in dinic.g[u]:
            if idx >= 0:  # original edge
                # original capacity - remaining capacity = flow sent
                original_cap = edges[idx][2]
                flow_sent = original_cap - cap
                ans[idx] = flow_sent

    print("YES")
    print(' '.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
