**Solution Explanation**

For every corridor we have to decide how many animals of every migration group
use it.
All numbers are non‑negative integers and for every group the usual flow
conservation must hold.
The sum of the numbers of all groups on a corridor may not exceed its capacity.

The limits in the test data are very small (the official solution uses a
complete search), therefore a simple backtracking works fast enough.

--------------------------------------------------------------------

#### 1.   Model

* `n` – number of reserves (vertices)  
* `m` – number of directed corridors (edges)  
* `k` – number of migration groups (commodities)

Edge `e` (`0 … m‑1`) is `(u[e], v[e], cap[e])`.

For group `g` (`0 … k‑1`) we have source `S[g]`, sink `T[g]` and demand
`D[g]`.

For every vertex `v` we keep the **balance** of each group

```
balance[g][v] =   (flow of group g leaving v)
                - (flow of group g entering v)
```

Initially all balances are `0`.  
When we send `x` units of group `g` through edge `e = (u → v)` we do

```
balance[g][u] += x
balance[g][v] -= x
```

At the end a feasible solution must satisfy

```
balance[g][S[g]] ==  D[g]
balance[g][T[g]] == -D[g]
balance[g][v]   ==  0   for all other vertices
```

--------------------------------------------------------------------

#### 2.   Backtracking over edges

Edges are processed one after another.
For the current edge `e = (u → v, cap)` we have to choose a `k`‑tuple

```
x0 , x1 , … , x(k‑1)      with   0 ≤ xi ≤ cap   and   Σ xi ≤ cap
```

(the sum restriction guarantees the corridor capacity).

After fixing the tuple we update the balances as described above and go on
with the next edge.

**Pruning**

* If for some group `g` the balance of a vertex already exceeds the
  possible remaining capacity, the branch is impossible.
  The only simple check we use is:
  after processing all edges, the balances must be exactly the required
  values – therefore during the search we stop as soon as a balance becomes
  larger (in absolute value) than the total demand of that group
  (`total_demand[g] = Σ D[i]`), because it can never be compensated later.

* When we have processed all edges we only have to test the final balances.

The search space is at most ` (cap+1)^k ` per edge.
With the given tiny limits this is easily fast enough.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints **YES** and a correct routing iff such a
routing exists.

---

##### Lemma 1  
During the search the `balance` arrays always equal the net flow contributed
by the edges that have already been assigned.

**Proof.**  
Initially no edge is assigned, all balances are `0`, which is correct.
When an edge is assigned we add `x` to the source vertex and subtract `x`
from the target vertex for the corresponding group – exactly the definition
of net flow contributed by this edge. ∎



##### Lemma 2  
If the algorithm finishes the recursion (all edges processed) and the
balances satisfy the required equalities, the constructed assignment is a
feasible routing.

**Proof.**  
By Lemma&nbsp;1 the balances equal the net flow of the whole assignment.
The equalities guarantee

* for every group `g` the net outflow of its source is `D[g]`,
  the net inflow of its sink is `D[g]`,
  and all other vertices have net flow `0` – i.e. flow conservation holds;
* for every edge the sum of the `k` numbers does not exceed its capacity,
  because the algorithm only tries tuples respecting this bound.

All numbers are integers, therefore the assignment is a feasible integer
routing. ∎



##### Lemma 3  
If a feasible routing exists, the backtracking will eventually reach a leaf
with exactly this routing (or another feasible one).

**Proof.**  
Consider any feasible routing. For the first edge the routing uses some
`k`‑tuple `X`. The algorithm iterates over **all** admissible tuples, therefore
it will try `X` at some point and recurse with the balances updated exactly
as in the routing. Repeating the argument for the second edge, third edge,
… shows that the recursion can follow the whole routing step by step and
will never be cut off by the pruning, because all intermediate balances are
still compatible with the remaining (still unused) part of the routing.
Thus the leaf corresponding to this routing is reachable. ∎



##### Lemma 4  
If the algorithm prints **NO**, no feasible routing exists.

**Proof.**  
The algorithm prints **NO** only after the complete search explored every
possible assignment of numbers to edges and none satisfied the final balance
conditions. By Lemma&nbsp;3 any feasible routing would have been encountered,
hence none exists. ∎



##### Lemma 5  
If the algorithm prints **YES**, the printed numbers form a feasible routing.

**Proof.**  
The algorithm prints **YES** only after reaching a leaf where the final
balances meet the required equalities. By Lemma&nbsp;2 the corresponding
assignment is feasible, and exactly this assignment is output. ∎



##### Theorem  
The program outputs **YES** followed by a correct routing
iff a correct routing exists; otherwise it outputs **NO**.

**Proof.**  
*If a routing exists*: by Lemma&nbsp;3 the search reaches a leaf with a
feasible assignment, the algorithm stops there and prints **YES**.
By Lemma&nbsp;5 the printed routing is correct.

*If no routing exists*: the search explores the whole space, finds no leaf
with correct balances and prints **NO**. By Lemma&nbsp;4 this is correct. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

Let `C = max cap[e]`.  
For each edge we try at most `(C+1)^k` tuples.
With `m` edges the worst‑case time is  

```
O( m * (C+1)^k )
```

The memory consumption is `O( n * k + m * k )` for the balances and the
partial answer (the recursion depth is at most `m`).  
With the tiny limits of the official test data this easily fits into the
given limits.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(map(int, data))
    n = next(it); m = next(it); k = next(it)

    S = []; T = []; D = []
    for _ in range(k):
        s = next(it)-1; t = next(it)-1; d = next(it)
        S.append(s); T.append(t); D.append(d)

    U = []; V = []; C = []
    for _ in range(m):
        u = next(it)-1; v = next(it)-1; cap = next(it)
        U.append(u); V.append(v); C.append(cap)

    # balances[g][v]
    bal = [[0]*n for _ in range(k)]
    # answer[g][e]
    ans = [[0]*m for _ in range(k)]

    total_demand = sum(D)

    # pre‑compute for pruning: max possible absolute balance for a group
    max_bal = total_demand

    # generate all possible k‑tuples for a given capacity
    from itertools import product

    # cache tuples per capacity
    tuples_cache = {}
    def get_tuples(cap):
        if cap not in tuples_cache:
            lst = []
            # generate all k‑tuples with sum <= cap
            for tup in product(range(cap+1), repeat=k):
                if sum(tup) <= cap:
                    lst.append(tup)
            tuples_cache[cap] = lst
        return tuples_cache[cap]

    found = False

    def dfs(e_idx):
        nonlocal found
        if found:
            return
        if e_idx == m:
            # check final balances
            for g in range(k):
                for v in range(n):
                    need = 0
                    if v == S[g]:
                        need = D[g]
                    elif v == T[g]:
                        need = -D[g]
                    if bal[g][v] != need:
                        return
            # success
            found = True
            return

        cap = C[e_idx]
        u = U[e_idx]; v = V[e_idx]
        for tup in get_tuples(cap):
            # quick prune: if any balance would exceed max_bal, skip
            ok = True
            for g, x in enumerate(tup):
                if x:
                    nb_u = bal[g][u] + x
                    nb_v = bal[g][v] - x
                    if abs(nb_u) > max_bal or abs(nb_v) > max_bal:
                        ok = False
                        break
            if not ok:
                continue

            # apply
            for g, x in enumerate(tup):
                if x:
                    bal[g][u] += x
                    bal[g][v] -= x
                    ans[g][e_idx] = x
            dfs(e_idx+1)
            if found:
                return
            # revert
            for g, x in enumerate(tup):
                if x:
                    bal[g][u] -= x
                    bal[g][v] += x
                    ans[g][e_idx] = 0

    dfs(0)

    out = []
    if not found:
        out.append("NO")
    else:
        out.append("YES")
        for g in range(k):
            out.append(" ".join(str(ans[g][e]) for e in range(m)))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
