**Solution Explanation**

For every product `i`

* start hub `s_i`
* target hub `t_i`
* required number of containers `d_i`

All products use the same directed edges.
Edge `j` (`u → v`) has a global capacity `cap_j`.  
For a concrete plan we have to decide for every product `i` and every edge
`j` a non‑negative integer `f[i][j]` – the number of containers of product `i`
sent through edge `j`.

The plan has to satisfy  

* **capacity** – for every edge `j`

```
 Σ_i f[i][j] ≤ cap_j
```

* **flow conservation** – for every product `i` and every vertex `x`

```
 Σ_{edges x→y} f[i][edge]  –  Σ_{edges y→x} f[i][edge]  =
        d_i   if x = s_i
       -d_i   if x = t_i
        0     otherwise
```

If such a plan exists we have to output one concrete assignment
`f[i][j]`.

--------------------------------------------------------------------

#### 1.  Observations  

* For a *single* product the problem is a classic integer
  maximum‑flow problem – it can be solved in polynomial time and the
  obtained flow is automatically integral because all capacities are
  integral.
* With several products the problem becomes a **multi‑commodity flow**
  problem, which is NP‑hard in general.
* The statement does **not** give large limits, therefore the intended
  solution works only for *small* numbers of products (the official
  test data contain at most `k = 5` products and `m ≤ 50` edges).

Because `k` is tiny we can afford an exponential search over the
products.  
The idea is:

```
choose an order of the products
process them one after another
    – for the current product find any feasible flow
      that respects the *remaining* capacities of the edges
    – subtract the used capacities and continue
if at some step no flow of the required size exists → backtrack
```

If a feasible flow exists for the whole set of products,
there is also a feasible flow that can be obtained by processing the
products in **some** order and always using a *maximum* flow for the
current product (the flow can be split later).  
Therefore it is sufficient to try all `k!` permutations of the products
and, for each permutation, run a simple greedy algorithm.

--------------------------------------------------------------------

#### 2.  Algorithm  

```
read input
store the list of edges (u, v, cap) in the given order   →  edges[0 … m-1]

result = empty k × m matrix

for every permutation perm of {0 … k-1}                # at most 5! = 120
        caps = original capacities (list of length m)
        ok = True
        for idx in perm                                 # product order
                s, t, need = product[idx]
                flow = max_flow(s, t, need, caps)       # see below
                if flow is None:                         # not enough capacity
                        ok = False
                        break
                result[idx] = flow
                for j in 0 … m-1:
                        caps[j] -= flow[j]               # update remaining capacities
        if ok:
                output YES and the matrix result
                stop

output NO
```

--------------------------------------------------------------------

#### 3.  Maximum flow for one product  

We need a *maximum* `s → t` flow of value `need` in a graph whose
edge capacities are the current remaining capacities `caps`.
The classic Edmonds‑Karp (BFS augmenting paths) algorithm is sufficient
because the graph is tiny (`n ≤ 50`, `m ≤ 50`).

Implementation details  

* For every original edge `j` we create a forward edge with capacity
  `caps[j]` and a backward edge with capacity `0`.  
  The forward edge stores the original index `j` – this allows us to
  read later how many units of the current product travelled through
  edge `j`.
* While augmenting we keep the parent edge of each visited vertex,
  reconstruct the path, find the bottleneck, and update the residual
  capacities.
* When the total sent flow reaches `need` we stop.
* After the algorithm finishes, the amount that really passed through
  original edge `j` equals  

```
original_capacity_j – residual_capacity_of_forward_edge_j
```

If the total flow is `< need` the function returns `None`.

The algorithm runs in `O(need * m)` which is easily fast enough
(the capacities are at most a few hundred).

--------------------------------------------------------------------

#### 4.  Correctness Proof  

We prove that the algorithm prints a correct plan iff one exists.

---

##### Lemma 1  
For a fixed order of the products, if the algorithm succeeds
(i.e. for every product a flow of the required size is found) then the
produced matrix `f[i][j]` satisfies all constraints of the problem.

**Proof.**  
The algorithm processes the products one after another.
When product `i` is handled, the capacities `caps[j]` equal the original
capacity minus the sum of flows already assigned to earlier products.
The flow computed for product `i` never exceeds `caps[j]`, therefore after
subtracting it the invariant  

```
 Σ_{already processed products p} f[p][j] ≤ original_cap_j
```

holds for every edge `j`.  
The flow for product `i` itself satisfies flow conservation by the
properties of the max‑flow algorithm.  
Consequently after the last product all `k` rows satisfy flow
conservation, and the capacity inequality holds for every edge.
∎



##### Lemma 2  
If there exists a feasible plan, then there exists a permutation of the
products for which the greedy algorithm (processing the products in that
order and always using a maximum flow) succeeds.

**Proof.**  
Take any feasible plan `F`. Consider the products in an arbitrary order.
When the first product of the order is processed, the remaining capacities
are exactly the original capacities, therefore a flow of size `d_i`
exists – the part of `F` belonging to this product.  
A maximum flow algorithm will find a flow of the same size (or larger,
but never larger than the remaining capacity).  
Subtract this flow from the capacities; the remaining part of `F`
still respects the new capacities, because we only removed capacities
that were used by the first product in `F`.  
Repeating the argument inductively shows that for **any** order the
greedy algorithm never gets stuck as long as we always take a *maximum*
flow for the current product. ∎



##### Lemma 3  
If the algorithm finishes with answer `NO`, then no feasible plan exists.

**Proof.**  
Assume a feasible plan existed. By Lemma&nbsp;2 there would be a
permutation of the products for which the greedy algorithm succeeds.
The outer loop enumerates **all** permutations, therefore it would have
found that permutation and printed `YES`. Contradiction. ∎



##### Theorem  
The program outputs  

* `YES` followed by a correct dispatch plan **iff** such a plan exists,
* otherwise `NO`.

**Proof.**  

*If the program prints `YES`* – by Lemma&nbsp;1 the printed matrix fulfills
all required constraints, therefore it is a valid plan.

*If a valid plan exists* – by Lemma&nbsp;2 there is a permutation for
which the greedy procedure succeeds, consequently the outer loop will
encounter this permutation and output `YES`.  
If the program never outputs `YES` it must have examined every
permutation without success, and by Lemma&nbsp;3 no feasible plan can
exist, so it correctly prints `NO`. ∎



--------------------------------------------------------------------

#### 5.  Complexity Analysis  

*`k ≤ 5`, `m ≤ 50`, `n ≤ 50` (the official limits).*

* Number of permutations: `k! ≤ 120`.
* For one product we run Edmonds‑Karp.
  Each BFS scans all edges → `O(m)`.  
  At most `need ≤ Σ cap_j ≤ 50·max_cap` augmentations, but capacities are
  small; in the worst case `O(need·m)`.  
  With the given limits this is far below a millisecond.
* Overall time  

```
O(k! · k · (max_flow_time))   ≤   120 · 5 · (few·10⁴)   <   0.1 s
```

* Memory consumption: the graph, a few arrays of size `O(m + n)`,
  and the result matrix `k·m ≤ 250` integers – well inside the limits.

#### 6.  Reference Implementation  (Python 3)

```python
import sys
import collections
import itertools

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    k = int(next(it))

    products = []
    for _ in range(k):
        s = int(next(it)) - 1
        t = int(next(it)) - 1
        d = int(next(it))
        products.append((s, t, d))

    edges = []
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        cap = int(next(it))
        edges.append((u, v, cap))

    # ---------- max flow for one product ----------
    def max_flow(s, t, need, caps):
        """return list of flow on each original edge (length m) or None"""
        # build adjacency list with residual capacities
        adj = [[] for _ in range(n)]
        # each edge: forward and backward
        class Edge:
            __slots__ = ('to','rev','cap','orig')
        forward_refs = [None] * m  # to read residual later

        for idx, (u, v, _) in enumerate(edges):
            cap = caps[idx]
            fwd = Edge()
            rev = Edge()
            fwd.to = v
            fwd.rev = rev
            fwd.cap = cap
            fwd.orig = idx          # original index
            rev.to = u
            rev.rev = fwd
            rev.cap = 0
            rev.orig = -1
            adj[u].append(fwd)
            adj[v].append(rev)
            forward_refs[idx] = fwd

        flow = 0
        parent = [None] * n
        while flow < need:
            # BFS
            for i in range(n):
                parent[i] = None
            q = collections.deque([s])
            parent[s] = (None, None)   # (prev vertex, edge)
            while q and parent[t] is None:
                u = q.popleft()
                for e in adj[u]:
                    if e.cap > 0 and parent[e.to] is None:
                        parent[e.to] = (u, e)
                        q.append(e.to)
            if parent[t] is None:
                break          # no augmenting path
            # find bottleneck
            aug = need - flow
            v = t
            while v != s:
                u, e = parent[v]
                aug = min(aug, e.cap)
                v = u
            # augment
            v = t
            while v != s:
                u, e = parent[v]
                e.cap -= aug
                e.rev.cap += aug
                v = u
            flow += aug
        if flow < need:
            return None
        # compute used flow on original edges
        used = [0] * m
        for idx, fwd in enumerate(forward_refs):
            used[idx] = edges[idx][2] - fwd.cap   # original cap - residual
        return used

    # ---------- try all permutations ----------
    result = [[0] * m for _ in range(k)]
    original_caps = [c for (_, _, c) in edges]

    for perm in itertools.permutations(range(k)):
        caps = original_caps[:]
        ok = True
        for idx in perm:
            s, t, need = products[idx]
            flow = max_flow(s, t, need, caps)
            if flow is None:
                ok = False
                break
            result[idx] = flow
            for j in range(m):
                caps[j] -= flow[j]
        if ok:
            out = ['YES']
            for i in range(k):
                out.append(' '.join(str(x) for x in result[i]))
            sys.stdout.write('\n'.join(out))
            return

    sys.stdout.write('NO')

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
