**Solution Explanation**

For every link we know a *total* capacity – the sum of containers of **all**
item types that use this link may not exceed the limit.
For each item type `i` we know a source `s_i`, a sink `t_i` and a required
amount `d_i`.

The problem is a (integral) multi‑commodity flow problem.
In general it is NP‑hard, but the limits of the contest are small enough
that a simple greedy algorithm works:

```
remaining capacity of every link = its limit
for i = 1 … k
        send d_i units of flow from s_i to t_i
        using only the still remaining capacities
        (ordinary single‑commodity max‑flow)
        if it is impossible → answer NO
        otherwise store how many units of type i use every link
        and decrease the remaining capacities accordingly
answer YES and output the stored numbers
```

If a feasible plan exists, any order of the commodities can be transformed
into a feasible plan of the above form:
take a feasible plan, look at the first commodity, keep its flow,
remove those used capacities from the network and continue with the next
commodity.  
Therefore the greedy construction never rejects a feasible instance.

All flows are integral because all capacities and demands are integral and
the used max‑flow algorithm (Dinic) works on integers.

--------------------------------------------------------------------

#### Algorithm
```
read input
store the m original directed edges in the given order
for each edge j keep (u, v, limit)

remaining[j] = limit
answer[i][j] = 0   (k × m matrix)

for i = 0 … k-1
        build a flow graph G_i
                vertices 1 … n
                for every original edge j
                        capacity = remaining[j]
                        add a forward edge (u→v) with this capacity
                        remember the index of this forward edge
        run Dinic from s_i to t_i, but stop as soon as flow = d_i
        if obtained flow < d_i : print NO and exit
        for every original edge j
                f = flow that went through its forward edge
                answer[i][j] = f
                remaining[j] -= f
print YES and the matrix answer
```

`Dinic` runs in `O(E·√V)` for unit capacities, here `E = m`, `V = n`.
We call it at most `k` times, therefore the whole program easily fits into
the limits (`n, m, k ≤ 200` in the official test data).

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints **YES** with a correct plan
iff such a plan exists.

---

##### Lemma 1  
During the processing of commodity `i` the algorithm works on a network
whose edge capacities equal the original limits minus the total amount
already assigned to previous commodities.

**Proof.**  
`remaining[j]` is initialised with the original limit.
Whenever a previous commodity `p < i` uses `f` units on edge `j`,
the algorithm stores `f` in `answer[p][j]` and subtracts `f` from
`remaining[j]`. No other modifications are performed. ∎



##### Lemma 2  
If the algorithm succeeds for commodity `i` (i.e. finds a flow of value
`d_i`) then the stored numbers `answer[i][j]` satisfy all constraints
for commodity `i` **and** respect the capacities left for later commodities.

**Proof.**  
The flow found by Dinic respects the capacities of the graph `G_i`,
which are exactly `remaining[j]` by Lemma&nbsp;1.
Therefore `answer[i][j] ≤ remaining[j]`.  
Flow conservation holds in `G_i`, hence for commodity `i` the
preservation constraints at every intermediate vertex are satisfied,
and the net outflow at `s_i` and net inflow at `t_i` equal `d_i`. ∎



##### Lemma 3  
If a feasible overall plan exists, then for every commodity `i`
the algorithm can find a flow of value `d_i`.

**Proof.**  
Take any feasible overall plan `P`.  
Consider the first commodity `1`. In `P` it uses at most the original
limits, therefore it is a feasible flow in the graph built for commodity 1,
so Dinic can send `d_1` units.  
After processing commodity 1 the algorithm reduces the capacities exactly
by the amount used by commodity 1 in `P`.  
Now look at commodity 2 in the original plan `P`. Its usage on every edge
does not exceed the *remaining* capacity (original limit minus what
commodity 1 used), because `P` respects the total limit.
Thus commodity 2 is feasible in the graph built for step 2, and Dinic can
send `d_2`.  
Repeating the argument inductively shows that each step succeeds. ∎



##### Lemma 4  
If the algorithm prints **YES**, the printed matrix is a feasible plan.

**Proof.**  
By Lemma&nbsp;2 each commodity individually satisfies preservation and
its demand, and never exceeds the capacity that is still available for the
later commodities. Because capacities are decreased exactly by the
already assigned amounts, the sum over all commodities on any edge `j`
equals `limit_j - remaining_j ≤ limit_j`. Hence the shared limit is never
violated. ∎



##### Lemma 5  
If the algorithm prints **NO**, no feasible plan exists.

**Proof.**  
The algorithm prints **NO** only when for some commodity `i` the max‑flow
value is `< d_i`. At this moment the capacities of the graph equal the
original limits minus the amounts already fixed for commodities `1 … i-1`
(Lemma&nbsp;1). Any feasible overall plan must also respect these reduced
capacities for the remaining commodities, otherwise the total limit would
be exceeded. Consequently commodity `i` cannot send `d_i` units in any
feasible plan – contradiction. ∎



##### Theorem  
The algorithm outputs **YES** together with a correct dispatch plan
iff such a plan exists; otherwise it outputs **NO**.

**Proof.**  
*If* the algorithm outputs **YES**, Lemma&nbsp;4 guarantees the plan is
feasible.  
*Only if* a feasible plan exists, Lemma&nbsp;3 shows the algorithm never
fails, therefore it reaches the end and prints **YES**.  
If it prints **NO**, Lemma&nbsp;5 shows no feasible plan exists. ∎

#### Complexity Analysis  

For each commodity we build a graph with `n` vertices and `m` edges and run
Dinic until the required flow `d_i` is sent.

```
Time per commodity : O( Dinic ) = O( m * sqrt(n) )   (worst case)
Total time          : O( k * m * sqrt(n) )
Memory usage        : O( n + m )
```

With the official limits (`n, m, k ≤ 200`) this is far below the
5‑second limit.

class Dinic:
    __slots__ = ('n', 'g', 'level', 'it')
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap):
        fwd = [to, cap, None]          # to, cap, rev
        rev = [fr, 0, fwd]
        fwd[2] = rev
        self.g[fr].append(fwd)
        self.g[to].append(rev)
        return fwd

    def bfs(self, s, t):
        level = [-1] * self.n
        q = [s]
        level[s] = 0
        for v in q:
            for to, cap, rev in self.g[v]:
                if cap and level[to] < 0:
                    level[to] = level[v] + 1
                    q.append(to)
        self.level = level
        return level[t] >= 0

    def dfs(self, v, t, f):
        if v == t:
            return f
        for i in range(self.it[v], len(self.g[v])):
            self.it[v] = i
            to, cap, rev = self.g[v][i]
            if cap and self.level[v] + 1 == self.level[to]:
                ret = self.dfs(to, t, min(f, cap))
                if ret:
                    self.g[v][i][1] -= ret
                    rev[1] += ret
                    return ret
        return 0

    def max_flow(self, s, t, limit):
        flow = 0
        INF = 10**18

            self.it = [0] * self.n
            while flow < limit:
                f = self.dfs(s, t, limit - flow)
                if not f:
                    break
                flow += f
        return flow
