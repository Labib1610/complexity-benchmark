**Solution Explanation**

For every chute (directed edge) we only have to respect the *total* number of parcels that use it.
The different categories (commodities) are indistinguishable for this restriction, therefore
the whole system can be described by a *single* flow with several sources and sinks:

* at a station `v` let  

```
supply(v) = Σ d_i   (over all categories i with source s_i = v)
demand(v) = Σ d_i   (over all categories i with sink   t_i = v)
```

All other stations have supply = demand = 0.
A feasible routing exists **iff** there is a feasible circulation that satisfies all
supplies/demands and never exceeds the chute capacities.

The circulation problem is transformed to a usual max‑flow problem:

* add a super source `S` and a super sink `T`
* for every station `v` with `supply(v) > 0` add edge `S → v` of capacity `supply(v)`
* for every station `v` with `demand(v) > 0` add edge `v → T` of capacity `demand(v)`

If the maximum flow from `S` to `T` equals the total demand
`D = Σ_i d_i`, a feasible circulation exists.

--------------------------------------------------------------------

### From a feasible circulation to per‑category flows
The circulation gives us the *total* amount of parcels that travel through each chute,
but not how they are split among the categories.
Because the total flow respects all capacities, we can now route the categories one after
another, each time using the **remaining** capacity of every chute.

Algorithm for the second phase

```
remaining[e] = original capacity of chute e
for i = 1 … k
        run a max‑flow from s_i to t_i using only edges with capacity = remaining
        if flow < d_i : impossible
        store the obtained flow of every chute as answer[i][e]
        remaining[e] -= answer[i][e]
```

The sum of all `d_i` equals the total flow found in the first phase,
hence the loop never fails when the first phase succeeded.

Both phases use Dinic’s algorithm (`O(E·√V)` in practice, easily fast enough).

--------------------------------------------------------------------

### Correctness Proof  

We prove that the algorithm prints “YES” and a correct routing
iff such a routing exists.

---

#### Lemma 1  
A routing satisfying all category requirements exists **iff**
there is a feasible circulation that satisfies the aggregated supplies
` supply(v) ` and demands ` demand(v) ` and respects the chute capacities.

*Proof.*  
*If* a routing exists, sum the flows of all categories edge‑wise.
At every non‑source/non‑sink station the inflow equals outflow for each
category, therefore also for the sum.  
At a source station the total outflow minus inflow equals the sum of its
category demands, i.e. `supply(v)`. The same holds for sinks.
All edge capacities are respected because each category respects them
individually. Hence the summed flow is a feasible circulation.

*Only‑if* a feasible circulation exists, split its total flow arbitrarily
into the required amounts for each category (possible because capacities
are only on the sum). The split yields a routing that satisfies all
category constraints. ∎



#### Lemma 2  
The max‑flow from `S` to `T` in the transformed network equals the total
demand `D` **iff** a feasible circulation of Lemma&nbsp;1 exists.

*Proof.*  
Adding `S` and `T` exactly enforces the supplies and demands:
any `S→v` edge must send `supply(v)` units into the network,
any `v→T` edge must absorb `demand(v)` units.
A flow of value `D` therefore corresponds to a circulation that fulfills
all supplies/demands and respects all original capacities.
Conversely, any feasible circulation can be extended by sending the
supplies through the `S` edges and the demands into `T`, giving a flow of
value `D`. ∎



#### Lemma 3  
Assume the first phase succeeded, i.e. we have a feasible circulation.
Then the sequential routing of the `k` categories using the remaining‑capacity
procedure succeeds for every category.

*Proof.*  
Let `F` be the total flow of the circulation, `F(e)` its amount on chute `e`.
Initially `remaining(e)=capacity(e)`. After processing some categories,
the sum of already assigned flows on `e` equals the amount already taken from
`remaining(e)`, therefore `remaining(e)=capacity(e)-used(e)`.
Because the circulation uses at most `capacity(e)`, we always have
`remaining(e) ≥ 0`.

Consider the moment before routing category `i`. The sum of demands of the
still unprocessed categories equals the total flow that still has to be sent
through the network (the circulation minus what has already been assigned).
Thus there exists a flow of value `d_i` from `s_i` to `t_i` that fits into the
current `remaining` capacities (just take the part of the original circulation
that belongs to category `i`). Dinic finds a flow of at least that value,
hence exactly `d_i`. ∎



#### Lemma 4  
The flows recorded for each category satisfy all problem constraints.

*Proof.*  
*Non‑negativity* – Dinic only produces non‑negative flows.  
*Flow conservation* – each per‑category max‑flow respects the usual
conservation, therefore the required equalities at intermediate stations hold.  
*Source / sink condition* – each max‑flow sends exactly `d_i` units from
`s_i` to `t_i`, giving the required net out‑/in‑flow.  
*Capacity* – after processing category `i` we subtract its flow from `remaining`,
so the sum of all recorded flows on any chute never exceeds the original capacity. ∎



#### Lemma 5  
If the algorithm prints “NO”, no feasible routing exists.

*Proof.*  
The algorithm prints “NO” only in two cases:

1. The first phase max‑flow value `< D`.  
   By Lemma&nbsp;2 no feasible circulation exists, hence by Lemma&nbsp;1
   no routing exists.

2. During the second phase a category cannot send its demand.  
   At that moment the remaining capacities are exactly the capacities that
   any routing would have to respect (all previously assigned flows are
   unavoidable). If even a single‑commodity flow of value `d_i` does not exist,
   no overall routing can exist. ∎



#### Theorem  
The algorithm outputs “YES” together with a correct per‑category routing
iff such a routing exists; otherwise it outputs “NO”.

*Proof.*  
*If* the algorithm outputs “YES”, Lemma&nbsp;3 guarantees the second phase
succeeds, and Lemma&nbsp;4 shows the produced flows satisfy all constraints,
hence a valid routing exists.

*Only‑if* a valid routing exists, Lemma&nbsp;1 gives a feasible circulation,
so by Lemma&nbsp;2 the first phase succeeds. Then Lemma&nbsp;3 ensures the
second phase also succeeds, therefore the algorithm prints “YES”. ∎



--------------------------------------------------------------------

### Complexity Analysis  

*First phase* – one Dinic run on a graph with `n+2` vertices and `m + n` edges:  
`O( (m+n) √(n) )` in practice, well below the limits.

*Second phase* – `k` independent Dinic runs on the original graph
(`n` vertices, `m` edges) with capacities decreasing over time.  
Total time `O( k · (m √n) )`.

Memory consumption: adjacency lists for the graph plus a `k × m` array for the
answers – at most `O(mk)` integers, fitting into the 256 MiB limit for the given
constraints.

--------------------------------------------------------------------

### Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(1 << 25)

class Dinic:
    __slots__ = ('n', 'g', 'level', 'it')
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, idx=-1):
        # idx is the original edge index, -1 for auxiliary edges
        f = [to, cap, None, idx]
        b = [fr, 0, f, -1]
        f[2] = b
        self.g[fr].append(f)
        self.g[to].append(b)

    def bfs(self, s, t):
        level = [-1]*self.n
        q = [s]
        level[s] = 0
        for v in q:
            for to, cap, rev, _ in self.g[v]:
                if cap and level[to] < 0:
                    level[to] = level[v]+1
                    q.append(to)
        self.level = level
        return level[t] >= 0

    def dfs(self, v, t, f):
        if v == t:
            return f
        for i in range(self.it[v], len(self.g[v])):
            self.it[v] = i
            to, cap, rev, _ = self.g[v][i]
            if cap and self.level[v]+1 == self.level[to]:
                ret = self.dfs(to, t, min(f, cap))
                if ret:
                    self.g[v][i][1] -= ret
                    rev[1] += ret
                    return ret
        return 0

    def max_flow(self, s, t):
        flow = 0
        INF = 10**18
        while self.bfs(s, t):
            self.it = [0]*self.n
            while True:
                f = self.dfs(s, t, INF)
                if not f:
                    break
                flow += f
        return flow

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it)); m = int(next(it)); k = int(next(it))
    cats = []
    supply = [0]*n
    demand = [0]*n
    for _ in range(k):
        s = int(next(it))-1
        t = int(next(it))-1
        d = int(next(it))
        cats.append((s, t, d))
        supply[s] += d
        demand[t] += d
    edges = []
    for _ in range(m):
        u = int(next(it))-1
        v = int(next(it))-1
        cap = int(next(it))
        edges.append((u, v, cap))

    # ---------- Phase 1 ----------
    S = n
    T = n+1
    dinic = Dinic(n+2)
    for idx, (u, v, cap) in enumerate(edges):
        dinic.add_edge(u, v, cap, idx)
    total_demand = 0
    for v in range(n):
        if supply[v]:
            dinic.add_edge(S, v, supply[v])
        if demand[v]:
            dinic.add_edge(v, T, demand[v])
            total_demand += demand[v]
    flow = dinic.max_flow(S, T)
    if flow != total_demand:
        print("NO")
        return

    # retrieve total used capacity on each original edge
    used_total = [0]*m
    for u in range(n):
        for to, cap, rev, idx in dinic.g[u]:
            if idx >= 0:  # original edge
                used = rev[1]  # flow sent forward = reverse edge capacity
                used_total[idx] = used

    # ---------- Phase 2 ----------
    remaining = [edges[i][2] for i in range(m)]
    answer = [[0]*m for _ in range(k)]

    for ci, (src, dst, need) in enumerate(cats):
        din = Dinic(n)
        for idx, (u, v, _) in enumerate(edges):
            if remaining[idx]:
                din.add_edge(u, v, remaining[idx], idx)
        got = din.max_flow(src, dst)
        if got != need:
            print("NO")
            return
        # extract flows
        for u in range(n):
            for to, cap, rev, idx in din.g[u]:
                if idx >= 0:
                    f = rev[1]  # flow sent forward
                    if f:
                        answer[ci][idx] = f
                        remaining[idx] -= f

    # ---------- Output ----------
    print("YES")
    out_lines = []
    for i in range(k):
        out_lines.append(' '.join(str(x) for x in answer[i]))
    sys.stdout.write('\n'.join(out_lines))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
