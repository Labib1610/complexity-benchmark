**Solution Explanation**

For every comparator (edge) the two linked fields must not have the same
position, otherwise a halt occurs.
Therefore we have to colour the vertices of the given undirected graph with
two colours `1` and `2` such that adjacent vertices receive different colours.
Exactly this is the definition of a *bipartite* graph.

If the graph is not bipartite no safe configuration exists.

If it is bipartite there are two possible colourings for each connected
component – the two colour classes can be swapped.
Among all global colourings we need the lexicographically smallest
sequence  

```
s1 s2 … sn   (si ∈ {1,2})
```

--------------------------------------------------------------------

#### Lemma  
For a fixed connected component the lexicographically smallest colouring
assigns colour `1` to the vertex with the smallest index inside this component.

*Proof.*  
Inside one component the two colourings differ only by swapping the two
colour classes.
All vertices outside the component keep the same colour in both colourings,
so the first position where the two global strings can differ is the smallest
index belonging to the component.
If that vertex receives colour `1` the whole string is not larger than the
string where it receives colour `2`. ∎



Consequences  

* we can treat each component independently,
* after a usual BFS/DFS that produces a temporary 2‑colouring (`0/1`),
  we look at the smallest vertex `vmin` of the component.
  If `temp_colour[vmin] == 0` we keep the colours,
  otherwise we flip all colours of the component.

After fixing the orientation we output `1` for temporary colour `0`
and `2` for temporary colour `1`.

--------------------------------------------------------------------

#### Algorithm
```
read n, m
build adjacency list
colour[1…n] = -1   // -1 = unvisited, 0/1 = temporary colour
answer[1…n]

for each vertex v = 1 … n
    if colour[v] == -1
        // start new component
        queue ← [v]
        colour[v] = 0
        component_vertices = []
        min_vertex = v
        while queue not empty
            x = pop queue
            component_vertices.append(x)
            if x < min_vertex: min_vertex = x
            for each neighbour y of x
                if colour[y] == -1
                    colour[y] = colour[x] ^ 1
                    push y
                else if colour[y] == colour[x]
                    print "NO" and exit   // not bipartite
        // decide orientation
        if colour[min_vertex] == 1          // needs flipping
            for each u in component_vertices
                colour[u] ^= 1
        // write final answer values
        for each u in component_vertices
            answer[u] = 1 if colour[u] == 0 else 2

print "YES"
print answer[1] … answer[n]
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `NO` iff no stable configuration exists,
otherwise prints `YES` and the lexicographically smallest stable configuration.

---

##### Lemma 1  
If the algorithm prints `NO` then the graph is not bipartite.

*Proof.*  
`NO` is printed only when during BFS an edge `(x,y)` with `colour[x]==colour[y]`
is found. The BFS colours neighbours with opposite temporary colour,
so such an equality can happen only if there exists an odd cycle,
i.e. the component is not bipartite. ∎



##### Lemma 2  
If the graph is not bipartite the algorithm prints `NO`.

*Proof.*  
A non‑bipartite graph contains a component with an odd cycle.
During BFS of that component the first edge of the cycle that closes the
cycle connects two already coloured vertices with the same colour,
triggering the condition of Lemma&nbsp;1. Hence `NO` is printed. ∎



##### Lemma 3  
Assume the graph is bipartite.
After processing a component the algorithm assigns colour `1` to its smallest
index vertex.

*Proof.*  
The BFS produces a temporary 2‑colouring (`0/1`).  
If the smallest vertex `vmin` already has temporary colour `0`,
the algorithm keeps the colours, therefore `vmin` receives final colour `1`.  
Otherwise it flips all temporary colours, turning `vmin` into `0`,
hence again final colour `1`. ∎



##### Lemma 4  
Assume the graph is bipartite.
The sequence `answer[1…n]` produced by the algorithm is a stable configuration.

*Proof.*  
For every edge both endpoints belong to the same component.
Inside a component the algorithm either keeps the BFS colouring or flips it,
both of which are proper 2‑colourings (adjacent vertices have opposite
temporary colours).  
Mapping `0 → 1` and `1 → 2` preserves inequality, therefore no edge has equal
final values. ∎



##### Lemma 5  
Assume the graph is bipartite.
The produced configuration is lexicographically minimal among all stable
configurations.

*Proof.*  
Consider the components ordered by their smallest vertex.
By Lemma&nbsp;3 the algorithm gives colour `1` to that smallest vertex,
which is the smallest possible value for that position.
All earlier positions (belonging to previous components) are already fixed
and equal to the minimum achievable values (induction on the order).
Thus no other stable configuration can be lexicographically smaller. ∎



##### Theorem  
The algorithm outputs  

* `NO` iff no stable configuration exists,  
* otherwise `YES` and the lexicographically smallest stable configuration.

*Proof.*  
If the algorithm prints `NO`, by Lemma&nbsp;1 the graph is not bipartite,
hence no stable configuration exists.  
If the graph is not bipartite, Lemma&nbsp;2 guarantees the algorithm prints
`NO`.  
If the graph is bipartite, the algorithm reaches the end, prints `YES`,
and by Lemma&nbsp;4 the printed assignment is stable.
Lemma&nbsp;5 shows it is the lexicographically smallest among all stable
assignments. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency list*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and edge is processed once → `O(n + m)`.  
*Additional loops* over component vertices are linear in total size → `O(n)`.

Total time `O(n + m)` ≤ `4·10⁵`, well inside the limit.  
Memory consumption `O(n + m)` ≤ about 3 MB for adjacency plus arrays,
well below 256 MB.

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        adj[u].append(v)
        adj[v].append(u)

    colour = [-1] * (n + 1)          # temporary 0/1
    answer = [0] * (n + 1)

    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        # BFS of a new component
        q = deque([start])
        colour[start] = 0
        comp = []
        min_vertex = start
        while q:
            x = q.popleft()
            comp.append(x)
            if x < min_vertex:
                min_vertex = x
            cx = colour[x]
            for y in adj[x]:
                if colour[y] == -1:
                    colour[y] = cx ^ 1
                    q.append(y)
                elif colour[y] == cx:
                    sys.stdout.write("NO")
                    return
        # orient so that min_vertex gets colour 0 (=> final 1)
        if colour[min_vertex] == 1:
            for v in comp:
                colour[v] ^= 1
        for v in comp:
            answer[v] = 1 if colour[v] == 0 else 2

    out = ["YES", " ".join(str(answer[i]) for i in range(1, n + 1))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```
