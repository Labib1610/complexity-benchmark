# Shift Scheduling

Time limit: 1 s   Memory limit: 256 MB

A manufacturing facility operates continuously by dividing its workforce across two daily shifts, designated as shift 1 and shift 2. The facility's payroll system supports a maximum headcount of two hundred thousand technicians. The current headcount is $n$, with each technician assigned a sequential ID from 1 to $n$. 

A safety ledger, which has a storage limit of two hundred thousand entries, contains $m$ records. Each record specifies a pair of technicians who require access to the same specialized tool. To prevent access conflicts, any two technicians listed in a single record must be assigned such that exactly one of them works shift 1 and the other works shift 2. 

Your task is to determine a valid shift designation for all $n$ technicians that satisfies all $m$ safety records. To respect seniority, if there are multiple ways to configure the workforce, you must choose the configuration that assigns shift 1 to the lowest-ID technician possible. If ties remain, you must assign shift 1 to the next lowest-ID technician possible, and so on, effectively finding the configuration that evaluates to the lexicographically smallest sequence of shift numbers. If no configuration can satisfy all safety records, you must report that it is impossible.

## Input
The first line contains the headcount $n$ and the number of safety records $m$. The values of $n$ and $m$ are guaranteed to respect the payroll and ledger limits described above, and there is always at least one technician employed.
Each of the subsequent $m$ lines provides two integers $u$ and $v$ — the IDs of the technicians involved in that specific safety record.

## Output
If no valid configuration can be formed, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $s_1 \dots s_n$ (where each $s_i$ is either 1 or 2), representing the valid configuration that respects the seniority rule.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

This forces the model to derive the bounds from context and recognize the bipartite requirement from the distribution logic rather than relying on standard "incompatible pairs" phrase matching.
</RATIONALE>
