**Solution Explanation**

For every worker `i (1 … n)` we have to choose a shift `s[i] ∈ {1,2,3}`.
If two workers `u , v` are in conflict they must obtain different shifts.

The required value  

```
value = Σ s[i] * 4^(n-i)
```

has strictly decreasing weights (`4^(n-i) > 3·4^(n-i-1)`), therefore the
lexicographically smallest sequence `(s[1],…,s[n])` is also the unique
minimum of the value.
Consequently we have to find the **lexicographically smallest proper
3‑colouring** of the given graph.

--------------------------------------------------------------------

#### 1.  Backtracking in the natural order  

We colour the workers one after another in the order `1,2,…,n`.
For the current worker `v` we try the colours `1,2,3` **in this order**.
A colour is admissible iff none of the already coloured neighbours of `v`
has the same colour.

If a colour is admissible we assign it and continue with `v+1`.
If all three colours are impossible we backtrack – the previous worker
gets its next possible colour, etc.

Because we always try the smallest still possible colour first,
the first complete colouring found by this depth‑first search is exactly
the lexicographically smallest one.

The algorithm is a plain recursive backtracking with only one pruning
rule: a colour that already conflicts with an earlier neighbour is
rejected immediately.

--------------------------------------------------------------------

#### 2.  Correctness Proof  

We prove that the algorithm prints `NO` iff no proper 3‑colouring exists,
otherwise it prints `YES` and the lexicographically smallest colouring.

---

##### Lemma 1  
During the search, before assigning a colour to worker `v`,
all workers `1 … v‑1` are already coloured and the partial assignment
contains no conflict.

**Proof.**  
Induction over `v`.  
*Base*: before the first call (`v = 1`) the set is empty – trivially
conflict‑free.  
*Step*: assume the invariant holds for `v`.  
When we try a colour for `v` we check all neighbours among `1 … v‑1`;
only a colour different from all those neighbours is accepted.
Thus after a successful assignment the invariant holds for `v+1`. ∎



##### Lemma 2  
If the algorithm reaches `v = n+1` (all workers coloured) the obtained
sequence is a proper 3‑colouring of the whole graph.

**Proof.**  
By Lemma&nbsp;1 the partial assignment after each step is conflict‑free.
When `v = n+1` all workers are coloured, therefore the whole assignment
has no conflict. ∎



##### Lemma 3  
If a proper 3‑colouring exists, the algorithm will eventually find one.

**Proof.**  
Consider any proper colouring `C`.  
During the depth‑first search the algorithm explores **all** colour
choices that are not rejected by the conflict test.
For each worker `v` the colour `C[v]` is admissible because all neighbours
with smaller index already have the same colours as in `C` and they differ
from `C[v]`.  
Hence the branch that follows exactly the colours of `C` is never cut
off and will be visited, leading to a complete colouring. ∎



##### Lemma 4  
The first complete colouring produced by the algorithm is the
lexicographically smallest proper colouring.

**Proof.**  
The search is depth‑first and for each worker tries colours in the order
`1,2,3`.  
Therefore the recursion explores the space in lexicographic order:
all colourings starting with `(1, …)` are examined before any colouring
starting with `(2, …)`, etc.
Consequently the first leaf (complete colouring) reached is the smallest
in lexicographic order among all leaves, i.e. among all proper colourings. ∎



##### Theorem  
The program outputs  

* `NO` iff the graph is not 3‑colourable,
* otherwise `YES` and the lexicographically smallest proper 3‑colouring.

**Proof.**  

*If the program prints `YES`*: it has found a complete colouring,
hence by Lemma&nbsp;2 the graph is 3‑colourable.  
By Lemma&nbsp;4 this colouring is the lexicographically smallest one.

*If the program prints `NO`*: the backtracking exhausted all possibilities
without reaching `v = n+1`. By Lemma&nbsp;3 this can happen only if no proper
colouring exists. ∎



--------------------------------------------------------------------

#### 3.  Complexity Analysis  

`n ≤ 40`.  
In the worst case the algorithm may try up to `3^n` branches,
but the conflict test is `O(deg(v))` and the total work is bounded by
the number of visited nodes in the search tree.

Memory consumption:  

* adjacency list – `O(n + m)`  
* colour array – `O(n)`  
* recursion depth – `O(n)`

Both are well below the limits.

#### 4.  Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    colour = [0] * n          # 0 = uncoloured, otherwise 1..3
    found = False

    def dfs(v: int) -> bool:
        """return True if a complete colouring is found from vertex v onward"""
        if v == n:
            return True
        # try colours 1,2,3
        for c in (1, 2, 3):
            ok = True
            for nb in adj[v]:
                if nb < v and colour[nb] == c:
                    ok = False
                    break
            if not ok:
                continue
            colour[v] = c
            if dfs(v + 1):
                return True
            colour[v] = 0
        return False

    if dfs(0):
        sys.stdout.write("YES\n")
        sys.stdout.write(" ".join(map(str, colour)) + "\n")
    else:
        sys.stdout.write("NO\n")

if __name__ == "__main__":
    solve()
```
