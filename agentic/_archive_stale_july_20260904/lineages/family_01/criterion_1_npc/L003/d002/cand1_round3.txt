# Problem A — Tier Allocation

Time limit: 2 s
Memory limit: 256 MB

A facility employs $n$ staff members. To maintain continuous operations, the facility uses three distinct tiers of service per day, labeled 1, 2, and 3. Each staff member must be allocated to exactly one of these three service tiers.

Due to historical friction, certain pairs of staff members cannot be placed in the same tier. You are given a log of these pairwise incompatibilities.

Your task is to determine whether it is possible to allocate a tier to all $n$ staff members without placing any incompatible pair in the same tier. 

Please note: the testing environment contains adversarial incompatibility configurations designed to degrade simple fixed-order backtracking search. Algorithms that merely process staff members sequentially and try tiers in fixed ascending order will encounter worst-case exponential branches and exceed the time limit on these $n=40$ configurations.

## Input
The first line contains two integers $n$ and $m$. The headcount $n$ is bounded by a minimum of 1 and the facility's maximum capacity of 40. The number of incompatibility records $m$ ranges from 0 up to the maximum possible number of distinct pairs among the staff, which evaluates to $n(n-1)/2$.
Each of the subsequent $m$ lines contains two integers $u$ and $v$ — representing a pair of distinct staff members who cannot share the same tier.

## Output
If there is no valid way to allocate the tiers, output a single line containing `NO`.
If a valid allocation is possible, output `YES` on the first line. On the second line, output $n$ integers $s_1, s_2, \dots, s_n$ ($s_i \in \{1, 2, 3\}$), where $s_i$ is the tier allocated to staff member $i$. If multiple valid allocations exist, output the one that produces the lexicographically smallest sequence $s_1, s_2, \dots, s_n$ (i.e., compare $s_1$ first, then $s_2$, and so on).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
