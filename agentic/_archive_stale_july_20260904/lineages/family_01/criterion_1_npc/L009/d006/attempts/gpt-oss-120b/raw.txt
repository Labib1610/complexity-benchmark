**Solution Explanation**

For every index `i` we have to choose a value `c[i] ∈ {1,2,3}`.
For each given pair `(u,v)` the three points  

```
P = (c[u] , c[u]²) ,   Q = (c[v] , c[v]²) ,   R = (4 , 16)
```

must **not** be collinear.

--------------------------------------------------------------------

#### 1.   When are the three points collinear ?

If `c[u] = c[v]` the points `P` and `Q` coincide, the triangle is degenerate,
so this is forbidden.

Otherwise the line through `P` and `Q` has slope  

```
(c[v]² – c[u]²) / (c[v] – c[u]) = c[u] + c[v]                (1)
```

Using point‑slope form with point `P`

```
y – c[u]² = (c[u] + c[v])·(x – c[u])
```

Plug `x = 4` :

```
y = c[u]² + (c[u] + c[v])·(4 – c[u])                        (2)
```

The three points are collinear **iff** the right hand side equals `16`.

So for a pair of values `(a,b)` (`a,b ∈ {1,2,3}`) the pair is **allowed**
iff

```
a ≠ b                     and
a*a + (a+b)*(4-a) ≠ 16
```

The condition is symmetric, therefore we can pre‑compute a 4×4 boolean table
`ok[a][b]` (indices `1..3`) telling whether the ordered pair `(a,b)` satisfies
the constraint.

--------------------------------------------------------------------

#### 2.   The problem becomes a CSP

We have a graph `G` with `n ≤ 40` vertices, edges are the given constraints.
For every edge `{u,v}` the assignment must respect `ok[c[u]][c[v]]`.

We have to output the **lexicographically smallest** feasible assignment.
Because the domain size is only `3`, a simple depth‑first search that tries
values `1,2,3` in this order for the vertices `1,2,…,n` already yields the
lexicographically smallest solution – the first complete assignment found is
the answer.

During the search we only have to check already assigned neighbours,
nothing more is needed for correctness, but we add a tiny forward‑checking
pruning: if a vertex gets a value, we verify that each still unassigned
neighbour still has at least one possible value left (by scanning the three
values). With `n ≤ 40` this is more than fast enough.

The recursion depth is at most `40`, well inside Python limits.

--------------------------------------------------------------------

#### 3.   Algorithm
```
pre‑compute ok[a][b] for a,b = 1..3
read n,m and the edges
build adjacency list adj[1..n]

c[1..n] = 0   // 0 = unassigned

function dfs(pos):
    if pos == n+1:               // all vertices assigned
        return True
    for val in 1,2,3:            // try in increasing order
        ok_for_all = True
        for each neighbour w of pos with c[w] != 0:
            if not ok[val][c[w]]:   // edge (pos,w) would be illegal
                ok_for_all = False
                break
        if not ok_for_all: continue

        // forward checking: every still unassigned neighbour must keep at least one possible colour
        saved = []               // remember neighbours that lose a colour
        feasible = True
        for each neighbour w of pos with c[w] == 0:
            possible = False
            for cand in 1,2,3:
                if ok[cand][val]:
                    possible = True
                    break
            if not possible:
                feasible = False
                break
        if not feasible: continue

        c[pos] = val
        if dfs(pos+1): return True
        c[pos] = 0               // backtrack
    return False

if dfs(1):
    print "YES" and the array c
else:
    print "NO"
```

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and the lexicographically smallest
valid sequence iff such a sequence exists, otherwise prints `NO`.

---

##### Lemma 1  
For any two values `a,b ∈ {1,2,3}` the table entry `ok[a][b]` is `True`
iff the constraint for the pair of indices with those values is satisfied.

**Proof.**  
The definition of `ok[a][b]` is exactly the logical negation of the two
necessary conditions for collinearity derived in (1)–(2):
* `a ≠ b` (otherwise `P = Q`);
* `a*a + (a+b)*(4-a) ≠ 16` (otherwise `R` lies on the line through `P,Q`).
∎



##### Lemma 2  
During the depth‑first search, when a value `val` is assigned to vertex `v`,
all already assigned neighbours satisfy the constraint.

**Proof.**  
Before assigning, the algorithm checks every neighbour `w` with `c[w] ≠ 0`
and requires `ok[val][c[w]]` to be `True`. By Lemma&nbsp;1 this is exactly the
required condition for the edge `{v,w}`. ∎



##### Lemma 3  
If the algorithm reaches recursion depth `pos = n+1`, the whole assignment
`c[1..n]` satisfies every constraint.

**Proof.**  
All edges connect two vertices. For each edge `{u,v}` the later of the two
vertices (larger index) was assigned after the earlier one, and at that moment
the check of Lemma&nbsp;2 guaranteed `ok[c[u]][c[v]] = True`. Hence every edge
satisfies the constraint. ∎



##### Lemma 4  
If a partial assignment can be extended to a full solution, the algorithm
never discards it because of the forward‑checking test.

**Proof.**  
Assume a partial assignment `A` can be extended to a full solution `S`.
Consider an unassigned neighbour `w` of the vertex we are about to assign
value `val`. In `S` the final colour of `w` is some `c_w`. Since `S` is a
solution, `ok[c_w][val]` holds. Therefore `c_w` is a colour that passes the
forward‑checking test, so the test finds at least one possible colour and
does not reject `val`. ∎



##### Lemma 5  
If a full solution exists, the recursive search eventually finds one.

**Proof.**  
We proceed by induction on the recursion depth.
At depth `k` the algorithm tries the three colours in order.
If the colour chosen is the one used by some existing solution `S`,
Lemma&nbsp;2 and Lemma&nbsp;4 guarantee that the recursive call continues with a
partial assignment still extendable to a solution.
Thus the branch following the colours of `S` is never cut off and reaches
depth `n+1`, where Lemma&nbsp;3 yields a full solution. ∎



##### Lemma 6  
The first complete assignment found by the search is the lexicographically
smallest feasible assignment.

**Proof.**  
The search processes vertices in increasing index order and, for each vertex,
tries colours `1,2,3` in that order. This is exactly a depth‑first traversal of
the lexicographic tree of all assignments. Because the algorithm stops at the
first leaf that is a solution, that leaf is the smallest leaf (lexicographically)
among all solution leaves. ∎



##### Theorem  
The program outputs  

* `YES` and the lexicographically smallest sequence satisfying all constraints
  iff such a sequence exists;
* `NO` otherwise.

**Proof.**  

*If a solution exists.*  
By Lemma&nbsp;5 the DFS reaches a leaf that is a solution, therefore returns
`True`. The program prints `YES` and the stored assignment. By Lemma&nbsp;6
this assignment is the lexicographically smallest one.

*If no solution exists.*  
All branches are explored; none reaches depth `n+1`, so the DFS returns
`False`. The program prints `NO`.

Both cases are exhaustive, completing the proof. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

`ok` table: constant work.

DFS:
* At each vertex we try at most 3 colours.
* For each trial we inspect all neighbours (at most `n-1 ≤ 39`) twice
  (once for already assigned neighbours, once for forward checking).

Worst‑case time `O(3^n · n)` is astronomically large, but the strong pruning
(the graph is dense only for `n=40`, still the domain is tiny) makes the
practical search tiny. In the worst theoretical case (`n=40`, no edges) the
algorithm simply tries `1` for every vertex and finishes instantly.

Memory usage: adjacency list `O(n²)` in the worst case (`≈1600` integers) and
the colour array `O(n)`. Well below the limits.

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        adj[u].append(v)
        adj[v].append(u)

    # pre‑compute allowed ordered pairs
    ok = [[False] * 4 for _ in range(4)]   # 1..3
    for a in range(1, 4):
        for b in range(1, 4):
            if a == b:
                continue
            if a * a + (a + b) * (4 - a) != 16:
                ok[a][b] = True

    c = [0] * (n + 1)   # 1‑based

    sys.setrecursionlimit(10000)

    def dfs(pos: int) -> bool:
        if pos == n + 1:
            return True
        for val in (1, 2, 3):
            # check already assigned neighbours
            good = True
            for nb in adj[pos]:
                if c[nb] != 0 and not ok[val][c[nb]]:
                    good = False
                    break
            if not good:
                continue

            # forward checking: each unassigned neighbour must keep at least one colour
            feasible = True
            for nb in adj[pos]:
                if c[nb] == 0:
                    possible = False
                    for cand in (1, 2, 3):
                        if ok[cand][val]:
                            possible = True
                            break
                    if not possible:
                        feasible = False
                        break
            if not feasible:
                continue

            c[pos] = val
            if dfs(pos + 1):
                return True
            c[pos] = 0
        return False

    if dfs(1):
        out = ['YES', ' '.join(str(c[i]) for i in range(1, n + 1))]
        sys.stdout.write('\n'.join(out))
    else:
        sys.stdout.write('NO')

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
