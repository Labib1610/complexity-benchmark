<METHOD_NAME>Isomorphic Constraint Obfuscation via Orthogonal Matrices</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit inequality constraint (c_u != c_v) with an isomorphic algebraic condition (the product of two chosen diagonal matrices must be the zero matrix). Models relying on surface pattern-matching will fail to recognize the underlying graph coloring structure and fall back to naive simulation of matrix multiplication within their search, leading to a Time Limit Exceeded (TLE) on the NP-complete search space. Models that genuinely reason will deduce that the matrix product is zero if and only if the chosen options are distinct, thus recovering the standard graph coloring model.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem A — Orthogonal Configuration

Time limit: 2 s   Memory limit: 256 MB

You are configuring a network of $n$ nodes. Each node $i$ ($1 \le i \le n$) must be assigned a configuration matrix $M_i$. You must choose exactly one of the following three options for each node:

- Option 1: $M_i$ is a $3 \times 3$ matrix with a $1$ at row 1, column 1, and $0$ everywhere else.
- Option 2: $M_i$ is a $3 \times 3$ matrix with a $1$ at row 2, column 2, and $0$ everywhere else.
- Option 3: $M_i$ is a $3 \times 3$ matrix with a $1$ at row 3, column 3, and $0$ everywhere else.

You are provided with $m$ interference constraints. Each constraint is a pair of distinct nodes $u$ and $v$. For the network to operate correctly, every constrained pair must satisfy the following condition: the standard matrix product $M_u \times M_v$ must be the $3 \times 3$ zero matrix (a matrix where all nine elements are $0$).

Determine a valid sequence of choices $c_1, c_2, \dots, c_n$ (where each $c_i \in \{1, 2, 3\}$ is the option number chosen for node $i$). If multiple valid sequences exist, you must provide the one that is lexicographically smallest (comparing the option for node 1 first, then node 2, and so on). If it is impossible to assign matrices without violating the constraints, you must report it.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$) — the number of nodes and the number of interference constraints. 
Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$) — indicating that node $u$ and node $v$ share an interference constraint. The two endpoints of a constraint are always distinct nodes.

## Output
If no valid assignment of configuration matrices exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $c_1, c_2, \dots, c_n$ (where each $c_i \in \{1, 2, 3\}$), representing the option number assigned to each node. If there is more than one valid sequence, output the lexicographically smallest one.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
I replaced the explicit "cannot share the same rating" inequality with an isomorphic algebraic condition: the standard matrix product of the assigned matrices must be the zero matrix. This forces models to algebraically deduce that the condition is strictly equivalent to distinct assignments; models that rely on surface pattern matching will fail to recognize the graph coloring structure and will likely TLE by naively simulating matrix multiplication inside their search space.
</RATIONALE>
<PRESERVED_ANSWER>
The matrix product $M_u \times M_v$ is the zero matrix if and only if $M_u$ and $M_v$ are different options, which is mathematically equivalent to the original constraint $c_u \neq c_v$, ensuring identical valid assignments for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core logic remains exactly equivalent to finding a valid 3-coloring of a graph, keeping the problem in the NP-complete complexity class.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "standard matrix product" as element-wise multiplication, though in the specific case of these diagonal matrices, both operations yield the exact same result, mitigating any risk of incorrect logic.
</RISK>
