# Problem A — Reactive Storage

Time limit: 2 s   Memory limit: 256 MB

A research facility utilizes three distinct storage units, designated by the digits 1, 2, and 3. The laboratory houses $n$ chemical specimens, which are sequentially numbered starting from 1. Due to their reactive properties, specific pairs of these specimens are highly volatile when combined and must strictly be kept in separate storage units. Your objective is to distribute every specimen into exactly one of the three units such that no volatile pair shares the same unit, or to conclude that no valid distribution exists.

The facility's full-capacity scenarios are explicitly adversarial; exhaustive enumeration of all possible unit assignments will exceed the time limit.

## Input
The first line contains two integers $n$ and $m$ — the total count of specimens and the number of volatile pairs, respectively. The specimen count $n$ is at least 1, and its maximum limit is exactly the number of thieves in the classic tale of Ali Baba. The pair count $m$ ranges from zero up to the maximum possible number of unique pairs that can be formed from the $n$ specimens.
Each of the subsequent $m$ lines provides two integers $u$ and $v$, identifying a pair of specimens that are volatile together.

## Output
If a safe distribution is impossible, output a single line containing `NO`.
If a safe distribution can be achieved, output `YES` on the first line. On the second line, output $n$ integers $s_1, s_2, \dots, s_n$ (each selected from {1, 2, 3}), where $s_i$ indicates the unit assigned to the $i$-th specimen. In cases where multiple valid distributions are possible, you must resolve ties by selecting the distribution that assigns the lowest possible unit number to specimen 1; if a tie persists, select the one with the lowest possible unit number for specimen 2, and proceed with this tie-breaking logic sequentially up to specimen $n$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
Added a mutable scenario sentence warning that exhaustive enumeration will exceed the time limit, which removes the affordance of blindly relying on the problem's small constraints to justify naive recursion. The bounds were also made indirect, using a literary constant (40 thieves) and a combinatorial definition ($n(n-1)/2$), forcing the model to explicitly derive the constraint sizes rather than pattern-match on bare numbers.
</RATIONALE>

</PRESERVED_ANSWER>
