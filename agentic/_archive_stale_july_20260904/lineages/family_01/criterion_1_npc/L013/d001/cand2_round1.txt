# Problem A — Scheduling Pipeline: Phase 2

Time limit: 2 s   Memory limit: 256 MB

A factory's automated management software operates in three phases. 
In Phase 1, the HR module collects data on the workers and identifies pairs of workers who have interpersonal conflicts. The factory floor is physically divided into exactly 8 sectors, each containing exactly 5 individual workstations. The facility employs at least one worker, and every worker is assigned to their own dedicated workstation, meaning the total worker headcount never exceeds the total number of workstations. The number of conflict pairs can be anything from zero up to the theoretical maximum where every worker conflicts with every other worker.

Your task is to implement Phase 2: the shift assignment module. The factory runs three shifts labeled 1, 2, and 3. You must assign every worker to exactly one of the three shifts so that no conflicting pair shares a shift. The test data may contain arbitrary adversarial configurations, including worst-case feasible and infeasible instances intended to defeat naive trial-and-error approaches; solutions must meet the time limit on those instances.

In Phase 3, the payroll module will take your assignment and generate the daily timetables. To ensure Phase 3 behaves predictably, if multiple valid assignments exist, you must provide the lexicographically smallest sequence of shift assignments (comparing the shift of worker 1 first, then worker 2, and so on). If no valid assignment is possible, Phase 2 must report that it is impossible so the software can alert management.

## Input
The first line contains two integers $n$ and $m$ — the number of workers and the number of conflict pairs identified in Phase 1. 
Each of the next $m$ lines contains two integers $u$ and $v$ — a conflicting pair.
(The values of $n$ and $m$ are guaranteed to strictly adhere to the facility limits described above.)

## Output
If no valid assignment exists, print a single line NO.
Otherwise print YES on the first line. On the second line print $n$ integers $s_1, s_2, \dots, s_n$ (each in {1,2,3}), where $s_i$ is the shift of worker $i$. Among all valid assignments output the lexicographically smallest sequence.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I removed the explicit numeric constraints and replaced them with physical facility limits (8 sectors of 5 workstations) that unambiguously multiply to 40. I also added a warning about adversarial configurations and worst-case instances. This forces models to actively derive the bounds from the text rather than matching on `n <= 40`, and deters them from assuming that simple constraints automatically justify unoptimized brute-force logic.
</RATIONALE>
<PRESERVED_ANSWER>
The core requirement of finding a valid, conflict-free shift assignment across 3 shifts and returning the lexicographically smallest one remains exactly the same, ensuring identical outputs for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem is still equivalent to finding the lexicographically smallest 3-coloring of a graph, keeping it in the NP-complete complexity class.
</PRESERVED_CLASS>
<RISK>
Models might fail to parse the implicit bound of $n \le 40$ from the physical description and assume $n$ could be large, which could trick them into attempting incorrect polynomial-time heuristics.
</RISK>
