**Solution Explanation**

For every employee we have to choose a shift `1 … 3` such that
no two employees that are connected by an edge obtain the same shift.
`n ≤ 40`, therefore a complete search with good pruning is fast enough.
The required output is the *lexicographically smallest* feasible assignment,
i.e. we have to decide the shift of employee 1 first, then employee 2, … .
Consequently we may simply try the employees in the natural order and,
for each employee, try the shifts `1,2,3` in this order.
The first complete assignment we find is already the lexicographically
smallest one.

--------------------------------------------------------------------

#### 1.   Data structures
* `adj[i]` – bit mask of neighbours of vertex `i` (`0‑based` indices).
* `color[i]` – current colour of vertex `i` (`0` = uncoloured, otherwise `1‑3`).

--------------------------------------------------------------------

#### 2.   Pruning – forward checking
When we colour a vertex `v` with colour `c` we immediately check all already
coloured neighbours – if any of them also has colour `c` the choice is illegal.

Additionally we keep a *simple* forward‑checking test:
for every still uncoloured vertex `u` we look at its already coloured
neighbours and collect the set of colours that are **forbidden** for `u`.
If all three colours are forbidden, the current partial assignment can never
be extended – we backtrack immediately.

The test is `O(m)` per recursive call, which is negligible for `n ≤ 40`.

--------------------------------------------------------------------

#### 3.   Recursive search
```
dfs(v):
    if v == n:               # all vertices coloured
        solution found
    for c in 1,2,3:          # try colours in increasing order
        if c is not used by any coloured neighbour of v:
            colour v with c
            if forward_check() succeeds:
                if dfs(v+1) succeeds: return True
            undo colour of v
    return False
```
Because vertices are processed in the order `0,1,…,n‑1` and colours are tried
in increasing order, the first complete assignment discovered is the
lexicographically smallest one.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `NO` iff the graph is not 3‑colourable,
otherwise it prints `YES` and the lexicographically smallest feasible
colouring.

---

##### Lemma 1  
During the search the algorithm never assigns the same colour to two
adjacent vertices.

**Proof.**  
Before assigning colour `c` to vertex `v` the algorithm checks all already
coloured neighbours of `v`. If any neighbour already has colour `c` the
assignment is rejected. Hence a colour is only given when it does not clash
with coloured neighbours. ∎



##### Lemma 2  
If the algorithm reaches a recursive call `dfs(k)` (i.e. vertices `0…k‑1`
are coloured) and the forward‑checking test succeeds, then there exists at
least one proper 3‑colouring extending the current partial assignment.

**Proof.**  
The forward‑checking test guarantees that for every uncoloured vertex `u`
there is at least one colour not forbidden by its coloured neighbours.
Take any such colour for each `u`; because the test only looks at coloured
neighbours, the chosen colours cannot create a conflict with already coloured
vertices. The remaining uncoloured vertices are independent of each other in
this argument, therefore a full extension exists. ∎



##### Lemma 3  
If a proper 3‑colouring exists that extends the current partial assignment,
the forward‑checking test never rejects it.

**Proof.**  
Assume a proper extension exists. For an uncoloured vertex `u` the colour it
receives in that extension is not used by any of its coloured neighbours,
otherwise the extension would not be proper. Hence at least one colour is
still allowed for `u`. The forward‑checking test only fails when *all* three
colours are forbidden, which cannot happen. ∎



##### Lemma 4  
If the algorithm returns `True` from `dfs(0)`, the produced assignment is a
proper 3‑colouring of the whole graph.

**Proof.**  
`True` is returned only after reaching `v == n`, i.e. every vertex is coloured.
By Lemma&nbsp;1 no edge connects two vertices of the same colour, therefore the
assignment is proper. ∎



##### Lemma 5  
If the graph is 3‑colourable, the algorithm eventually returns `True`.

**Proof.**  
Consider any proper 3‑colouring `C`. The recursion explores vertices in order.
When processing vertex `v`, the algorithm tries colours `1,2,3`.  
If `C(v)` is tried, Lemma&nbsp;3 guarantees that the forward‑checking test
succeeds, therefore the recursive call continues with a partial assignment
that can still be extended to `C`. By induction the recursion can follow the
choices of `C` all the way to `v = n`, where it returns `True`. Hence the
algorithm finds a solution. ∎



##### Lemma 6  
The first complete assignment found by the algorithm is the lexicographically
smallest feasible assignment.

**Proof.**  
Vertices are processed in increasing index order.
For each vertex the colours are tried in the order `1,2,3`.
Thus the search performs a depth‑first traversal of the lexicographic tree of
all assignments. The first leaf reached corresponds to the smallest leaf
in lexicographic order that is not pruned, i.e. the smallest feasible
assignment. ∎



##### Theorem  
The program outputs  

* `NO` iff the input graph is not 3‑colourable;  
* otherwise `YES` and the lexicographically smallest proper 3‑colouring.

**Proof.**  
If the algorithm finishes without finding a solution, every recursive branch
was either rejected by the forward‑checking test or exhausted all colour
choices. By Lemma&nbsp;3 any proper colouring would survive the test, therefore
none exists – the graph is not 3‑colourable and the program prints `NO`.

If a solution is found, Lemma&nbsp;4 shows it is a proper colouring, and
Lemma&nbsp;6 shows it is the lexicographically smallest one. The program prints
`YES` and this assignment. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

`n ≤ 40`, `m ≤ n·(n‑1)/2`.

*Each recursive call*  

* colour conflict test – at most `deg(v) ≤ n` operations,
* forward‑checking – scans all edges once, `O(m)`.

The number of visited nodes of the search tree is far below `3^n` for all
practical inputs; the worst‑case exponential behaviour is unavoidable for an
NP‑complete problem, but with `n = 40` the implemented pruning easily fits into
the 2 seconds limit.

Memory consumption:  
`adj` – `n` integers, `color` – `n` bytes → `O(n)`.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [0] * n
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    color = [0] * n          # 0 = uncoloured, else 1..3
    solution = None

    # forward checking: return False if some uncoloured vertex has no colour left
    def forward_ok() -> bool:
        for v in range(n):
            if color[v] != 0:
                continue
            forbidden = 0
            nb = adj[v]
            while nb:
                u = (nb & -nb).bit_length() - 1
                nb &= nb - 1
                c = color[u]
                if c:
                    forbidden |= 1 << (c - 1)
            if forbidden == 0b111:   # all three colours forbidden
                return False
        return True

    def dfs(v: int) -> bool:
        nonlocal solution
        if v == n:
            solution = color.copy()
            return True
        # try colours 1,2,3
        neigh = adj[v]
        used = 0
        nb = neigh
        while nb:
            u = (nb & -nb).bit_length() - 1
            nb &= nb - 1
            c = color[u]
            if c:
                used |= 1 << (c - 1)
        for c in (1, 2, 3):
            if used & (1 << (c - 1)):
                continue
            color[v] = c
            if forward_ok():
                if dfs(v + 1):
                    return True
            color[v] = 0
        return False

    if dfs(0):
        out = ["YES", " ".join(str(x) for x in solution)]
    else:
        out = ["NO"]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
