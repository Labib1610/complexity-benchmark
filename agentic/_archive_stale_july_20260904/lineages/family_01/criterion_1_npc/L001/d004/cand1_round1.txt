# Problem A — Distributed Ledger Shard Allocation

Time limit: 2 s   Memory limit: 256 MB

A decentralized network is allocating $n$ data shards, numbered $1$ through $n$, across three highly specialized storage tiers: Tier 1, Tier 2, and Tier 3. Every shard must be assigned to exactly one of these three tiers.

To prevent data corruption during simultaneous accesses, the network's spatial analyzer has identified $m$ pairs of shards that share volatile memory dependencies. If any two shards in an identified pair are assigned to the identical storage tier, a critical collision will occur. Thus, they must be placed in strictly different tiers.

The overall allocation is represented as a sequence of $n$ integers, where the $i$-th integer is the tier (1, 2, or 3) assigned to shard $i$. The network must select the valid allocation that is lexicographically smallest. This means that when comparing two collision-free allocations, the system reads the sequences from shard 1 to $n$ and prefers the one with a strictly smaller tier number at the earliest shard index where the two sequences differ.

If no collision-free allocation exists across the three tiers, the process must be aborted.

**Performance Note:** The dependency structures in the test suite include highly adversarial configurations. The connectivity topologies contain dense localized structures, and the shard numbering is deliberately arranged to force fixed-order sequential assignment to evaluate an astronomical number of dead-end configurations. Implementations relying on naive sequential trial-and-error (e.g., strictly iterating through shards in numerical order without lookahead) will encounter catastrophic slowdowns and exceed the time limit. To succeed within the 2-second limit, your approach must incorporate robust state pruning, dynamic variable selection heuristics (such as dynamically selecting the most constrained shard next), or equivalent advanced optimization strategies.

## Input
The first line contains two integers $n$ and $m$ — the number of data shards and the number of dependency pairs ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$).
Each of the following $m$ lines contains two integers $u$ and $v$ — denoting a pair of shards that share a dependency and must be assigned to different tiers.

## Output
If no valid allocation is possible, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $t_1, t_2, \dots, t_n$ ($t_i \in \{1, 2, 3\}$), representing the storage tier assigned to each shard. This sequence must be the lexicographically smallest valid allocation.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
