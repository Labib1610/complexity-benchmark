<METHOD_NAME>Algebraic Constraint Disguise</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit inequality constraint (x != y) with an algebraic equivalent over the domain {1,2,3}: the product x*y must not be a perfect square. This prevents models from immediately recognizing the 3-coloring graph constraint.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Problem A — Network Tier Provisioning

Time limit: 2 s   Memory limit: 256 MB

You are provisioning a cloud architecture consisting of $n$ microservices, numbered sequentially from $1$ to $n$. Each microservice must be assigned exactly one security tier from the available options: $1$, $2$, or $3$.

The architecture contains $m$ critical data pipelines, each linking a pair of microservices. Due to legacy cryptographic constraints, if two microservices are linked by a pipeline, the product of their assigned security tiers must not be a perfect square. If the product is a perfect square, the pipeline will fail to initialize. 

Your task is to find a valid tier assignment for all $n$ microservices. If multiple valid assignments exist, you must select the one that assigns the smallest possible tier to microservice $1$. If there are still multiple candidates, choose the one that minimizes the tier for microservice $2$, and so forth, checking microservice by microservice up to microservice $n$. If no valid assignment can be found, you must state that it is impossible.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — the number of microservices and the number of pipelines.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), representing a pipeline linking microservice $u$ and microservice $v$.

## Output
If no valid assignment exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the security tiers for microservices $1$ through $n$, adhering to the specified tie-breaking rule (minimizing the tier of microservice 1, then microservice 2, and so forth).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The explicit "must be different" constraint is replaced by the algebraic rule "product must not be a perfect square". Over the domain {1, 2, 3}, the product of two values is a perfect square if and only if the values are identical, making the constraints mathematically equivalent while heavily disguising the standard graph coloring structure. The tie-breaking rule is restored to the exact phrasing of the seed to ensure strict compliance.
</RATIONALE>
<PRESERVED_ANSWER>
For values in {1, 2, 3}, x*y is a perfect square exactly when x = y, meaning pipelines simply enforce the original inequality constraint, preserving all valid configurations and the exact lexicographically smallest solution.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to finding the lexicographically smallest 3-coloring of a graph, which is NP-complete.
</PRESERVED_CLASS>
