# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You are conducting a regulatory review on a sequential ledger of financial operations. The ledger consists of a total of $n$ operations, numbered sequentially from $1$ up to $n$. Your task is to classify each operation $i$ by assigning it a security level $c_i$. The allowable security levels are restricted to exactly the first three positive integers.

The audit data includes $m$ regulatory constraints between specific pairs of operations. To maintain strict compliance, no two operations connected by a constraint can share the same security level. In other words, for any constrained pair of operations, the set containing their assigned security levels must have a cardinality of exactly two. A violation of this condition constitutes an immediate audit failure.

You must find a fully compliant security level classification for all $n$ operations. Should multiple valid classifications exist, regulations dictate that you must provide the one that strictly minimizes the weighted risk coefficient $C$, defined mathematically as:

$C = \sum_{i=1}^n c_i \cdot 4^{-i}$

Due to the length of the ledger, you must evaluate this coefficient exactly; approximate floating-point representations will lead to incorrect comparisons.

If it is impossible to classify all operations without violating at least one constraint, you must declare the audit impossible.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — representing the total number of operations and the number of regulatory constraints, respectively.
Following this, there are $m$ lines. Each line provides two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), which indicates a regulatory constraint between operation $u$ and operation $v$.

## Output
If no compliant classification can be formed, output exactly one line containing the word `NO`.
If a valid classification exists, output `YES` on the first line. On the second line, output $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the security levels assigned to operations $1$ through $n$ in the classification that minimizes the weighted risk coefficient.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<METHOD_NAME>Floating-Point Objective Disguise</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit "lexicographically smallest" tie-break rule with an exact mathematical equivalent: minimizing the sum of c_i * 4^(-i). Models that fail to recognize this equivalence will likely attempt to compute it using floating-point arithmetic (leading to precision errors on n=40) or evaluate all valid configurations without early termination (leading to Time Limit Exceeded).</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>
<RATIONALE>
The explicit "lexicographically smallest" requirement was replaced with its mathematical equivalent: minimizing a base-4 fractional polynomial. This forces models to either genuinely recognize the equivalence and implement early-exit DFS, or fall into the trap of computing the sum naively, which leads to precision failures or time limit exceeded.
</RATIONALE>
<PRESERVED_ANSWER>
Because 4 is strictly greater than the maximum difference between any two valid assignments (3 - 1 = 2), minimizing the sum of c_i * 4^(-i) is mathematically identical to finding the lexicographically smallest sequence.
</PRESERVED_ANSWER>
