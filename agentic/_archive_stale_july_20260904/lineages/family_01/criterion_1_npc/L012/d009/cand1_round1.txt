<METHOD_NAME>
Polynomial Root Constraint Obfuscation
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces the standard graph coloring inequality constraint (u != v) with an algebraically equivalent property: the absolute difference of the assigned values must be a root of x^2 - 3x + 2 = 0. This masks the recognizable "coloring" pattern and forces the model to reason algebraically about the validity of states.
</METHOD_DESCRIPTION>

yes

<STATEMENT>
# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You are auditing a ledger of sequential financial transactions. The ledger contains $n$ transactions, indexed from $1$ to $n$. For each transaction $i$, you must assign a risk tier $c_i$. There are exactly three risk tiers available, represented by the values $1$, $2$, and $3$.

The ledger also specifies $m$ dependency links between certain transactions. Due to regulatory rules, any two transactions connected by a dependency link must satisfy a strict numerical condition to avoid a compliance violation: the absolute difference between their assigned risk tiers, $x = |c_u - c_v|$, must be a valid root of the polynomial equation $x^2 - 3x + 2 = 0$. If the absolute difference of their assigned tiers does not satisfy this equation, the configuration is invalid.

Your objective is to determine a compliant risk configuration for the entire ledger. If there is more than one compliant configuration, you must output the one that is lexicographically smallest. A configuration sequence $A = (a_1, a_2, \dots, a_n)$ is lexicographically smaller than sequence $B = (b_1, b_2, \dots, b_n)$ if, at the first index $i$ where they differ, $a_i < b_i$.

If there is no way to assign the risk tiers without a compliance violation, you must report that the configuration is impossible.

*System Note:* The automated test cases include dependency structures specifically constructed so that many partial assignments of tiers to a prefix of transactions are locally valid but possess no fully compliant extension to the entire ledger. The largest allowed inputs are deliberately worst-case instances, including cases whose lexicographically first solution appears only after essentially all earlier assignment prefixes have been disproved, and cases where impossibility is established only after exhaustive search.

## Input
The first line provides two integers $n$ and $m$. The number of transactions $n$ is an integer between $1$ and the value of $5! / 3$. The number of dependency links $m$ is an integer between $0$ and the maximum number of distinct unordered pairs that can be chosen from $n$ items.
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating that a dependency link connects transaction $u$ and transaction $v$.

## Output
If a compliant configuration is impossible, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the assigned risk tiers for transactions $1$ through $n$ in the lexicographically smallest compliant configuration.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I applied Strategy S07 by stating the bounds indirectly using basic combinatorics and factorials ($5! / 3$ for 40, and 'maximum distinct unordered pairs' for $n(n-1)/2$). To defeat the remaining models in Aggressive Mode, I introduced 'Polynomial Root Constraint Obfuscation'. Instead of plainly stating that linked transactions must have different tiers, I require that the absolute difference of their tiers is a root of $x^2 - 3x + 2 = 0$. I also updated the System Note to warn that the largest inputs are worst-case instances requiring exhaustive search, directly removing the backtracking affordance without using banned terminology.
</RATIONALE>
<PRESERVED_ANSWER>
The roots of $x^2 - 3x + 2 = 0$ are exactly 1 and 2, meaning the absolute difference between the linked tiers (which are chosen from {1, 2, 3}) must be 1 or 2; this is mathematically identical to requiring that the linked tiers are strictly unequal, preserving all valid configurations exactly.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains identical to 3-COLORING on a graph, as the variables, domain, and binary inequality constraints are logically completely unchanged.
</PRESERVED_CLASS>
<RISK>
Models might theoretically struggle to evaluate $5! / 3$ or factor the simple quadratic, though both are standard operations that shouldn't introduce linguistic ambiguity.
</RISK>
