# Problem A — Deployment Tiers

Time limit: 2 s   Memory limit: 256 MB

You are configuring a software architecture comprising $n$ microservices, labeled from 1 up to $n$. Your task is to allocate a security tier to each microservice. Every tier must be a positive integer strictly less than 4.

Diagnostic checks have uncovered parallel execution vulnerabilities between specific microservices. Whenever two microservices involved in a vulnerability operate at the exact same security tier, the entire architecture becomes unstable. Consequently, you must ensure that any such pair is allocated to differing tiers. Note that the two microservices in a vulnerability report are not required to be distinct: a report might list a microservice alongside itself. Any such self-pair makes the answer NO because a service always has the same tier as itself, preventing any valid configuration.

Your goal is to find a stable tier allocation for all $n$ microservices. Should multiple stable allocations exist, you must select the one that grants the lowest possible tier to microservice 1. Any remaining ties must be resolved by minimizing the tier given to microservice 2, and so on, checking element by element up to microservice $n$. If no stable allocation can be found, you must output a failure notice.

## Input
The first line contains $n$ and $m$ — the total number of microservices and the number of vulnerability reports ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$).
Each of the subsequent $m$ lines provides two integers $u$ and $v$, indicating a vulnerability between microservice $u$ and microservice $v$. As noted, a line may contain $u = v$.

## Output
If a stable architecture cannot be achieved, print NO on a single line.
Otherwise, print YES on the initial line. On the next line, print $n$ space-separated integers corresponding to the tiers for microservices 1 through $n$, adhering to the tie-breaking rules.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

This prevents models from blindly applying standard backtracking templates that only validate against previously assigned, strictly distinct neighbors.
</RATIONALE>

The logical requirements for a valid assignment remain exactly the same; the explicit mention of self-pairs merely clarifies an edge case that already mathematically invalidates any assignment under the original rules.
</PRESERVED_ANSWER>

</PRESERVED_CLASS>
