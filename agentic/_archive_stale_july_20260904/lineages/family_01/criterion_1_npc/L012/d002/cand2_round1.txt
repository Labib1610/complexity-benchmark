# Problem A — Deployment Tiers

Time limit: 2 s   Memory limit: 256 MB

You are configuring a software architecture containing $n$ distinct microservices, numbered 1 through $n$. Each microservice requires an assigned security tier, which must be chosen from exactly three available levels: 1, 2, or 3.

Through diagnostic runs, specific pairs of microservices have been found to trigger parallel execution faults. Whenever two such microservices are allocated the exact same security tier, the architecture destabilizes. Your configuration must ensure that no such pair shares a tier.

Your objective is to find a stable allocation for all $n$ microservices. When multiple stable allocations exist, you must select the one that assigns the lowest numerical tier to microservice 1. Any remaining ties are resolved by minimizing the tier for microservice 2, and so on, evaluating element by element sequentially up to microservice $n$. If achieving a stable architecture is impossible, you must output a failure indicator.

The evaluation suite contains test cases with up to 40 microservices arranged in specific fault patterns. Certain configurations are structured such that a process which sequentially guesses tier assignments will traverse a vast number of invalid states before terminating, both in scenarios where a stable architecture exists and where it does not.

## Input
The first line provides two integers, $n$ and $m$, representing the total number of microservices and the number of fault-prone pairs ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$).
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), specifying that microservice $u$ and microservice $v$ will destabilize the architecture if assigned the same tier.

## Output
If no stable configuration can be formed, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, provide $n$ space-separated integers (each 1, 2, or 3) indicating the security tiers for microservices 1 through $n$, adhering to the tie-breaking rules.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
