<STATEMENT>
# Problem A — Deployment Tiers

Time limit: 2 s   Memory limit: 256 MB

A software system consists of $n$ microservices. You must assign each microservice a security tier. A tier must be exactly one of the values 1, 2, or 3.

Extensive testing has revealed that certain distinct pairs of microservices exhibit parallel execution flaws. If a pair with this flaw operates at the exact same security tier, the system becomes unstable. To guarantee stability, the two microservices in any such pair must be assigned to different tiers.

You must determine a valid tier assignment for all $n$ microservices. If there are several valid ways to assign the tiers, the deployment policy requires ranking the complete configurations to select the best one. A complete configuration is represented as a sequence of $n$ tiers. When comparing two different valid configuration sequences, the preferred sequence is the one that contains a smaller tier value at the lowest-indexed microservice where the two sequences differ. You must output the single most preferred valid configuration under this strict ranking policy. If no such configuration is possible, you must report this failure.

## Input
The first line provides $n$ and $m$ — the number of microservices and the number of flawed pairs. The deployment scale implies that $n$ is at least 1, but capped by a physical limit of 40. The count of flaws $m$ ranges from a minimum of 0 up to the maximum capacity where every possible pair of distinct microservices is flawed.
The following $m$ lines each contain two integers $u$ and $v$, indicating that microservice $u$ and microservice $v$ share a parallel execution flaw. The indices $u$ and $v$ are guaranteed to be at least 1 and at most $n$, and they will never be equal to each other.

## Output
If the system cannot be stabilized, output a single line with the word NO.
Otherwise, output YES on the first line. On the second line, output $n$ integers separated by spaces, where each integer is 1, 2, or 3, representing the tiers assigned to microservices 1 through $n$ respectively, following the configuration ranking policy described above.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The tie-break rule was rewritten from a successive per-microservice minimization into a whole-configuration ranking policy. This forces the model to synthesize the lexicographic requirement from the sequence comparison rule, defeating simple pattern matching on "minimize element-by-element". Numeric bounds were converted to prose descriptions of physical constraints (S07), ensuring exact numbers like 1, 40, and 0 are present but the algebraic inequalities are removed.
</RATIONALE>
<PRESERVED_ANSWER>
The problem still requires an assignment of values {1, 2, 3} to $n$ variables such that specified pairs differ, and the tie-break rule mathematically identical to lexicographical ordering is preserved.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to 3-COLORING with a lexicographical tie-break, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the upper bound on $m$ if they fail to recognize "every possible pair of distinct microservices" as $n(n-1)/2$, though this is a standard combinatorial concept.
</RISK>
