# Problem A — Deployment Tiers

Time limit: 2 s   Memory limit: 256 MB

A software system consists of microservices, identified by integers starting from 1 up to the total count. You must assign each microservice a security tier. A tier must be exactly one of the values 1, 2, or 3.

Extensive testing has revealed that certain distinct pairs of microservices exhibit parallel execution flaws. If a pair with this flaw operates at the exact same security tier, the system becomes unstable. To guarantee stability, the two microservices in any such pair must be assigned to different tiers.

You must determine a valid tier assignment for all microservices. Configurations are evaluated as a complete sequence of tier values from the first microservice to the last. When multiple valid configurations exist, they are ranked by comparing these sequences: between any two valid configurations, the one that contains a smaller tier value at the earliest point where their sequences differ is considered the strictly better deployment policy. You must output the absolute best valid configuration according to this ranking. If no such configuration is possible, you must report this failure.

Be aware that the system configurations can be highly deceptive. In many cases, a very large number of partial tier assignments that successfully resolve conflicts among the first several microservices will ultimately fail due to structural restrictions appearing only at the final few microservices.

## Input
The first line provides $n$ and $m$ — the number of microservices and the number of flawed pairs. The physical hardware limits the deployment to a chassis with a maximum capacity of 40 microservices, and there is always at least one. The number of flawed pairs ranges from zero up to the theoretical maximum where every distinct pair is flawed.

The following $m$ lines each contain two distinct integers $u$ and $v$ representing valid microservice identifiers, indicating that microservice $u$ and microservice $v$ share a parallel execution flaw.

## Output
If the system cannot be stabilized, output a single line with the word NO.
Otherwise, output YES on the first line. On the second line, output $n$ integers separated by spaces, where each integer is 1, 2, or 3, representing the tiers assigned to microservices 1 through $n$ respectively, following the ranking rules described above.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
