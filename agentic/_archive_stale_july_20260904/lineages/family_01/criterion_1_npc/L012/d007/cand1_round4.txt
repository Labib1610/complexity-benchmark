<STATEMENT>
# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You are auditing a ledger of sequential financial transactions. The ledger contains $n$ transactions, indexed from $1$ to $n$. For each transaction $i$, you must assign a risk tier $c_i$. There are exactly three risk tiers available, represented by the scalar values $1$, $2$, and $3$.

The ledger also specifies $m$ dependency links between certain transactions. Each link connects a pair of transactions $u$ and $v$. Due to regulatory rules, the risk tiers assigned to any linked pair must be linearly independent when combined with a unit vector. Specifically, for every dependency link between transaction $u$ and transaction $v$, their assigned tiers $c_u$ and $c_v$ must satisfy the determinant condition:
$$ \det \begin{pmatrix} c_u & c_v \\ 1 & 1 \end{pmatrix} \ne 0 $$
If this condition fails for any link, it triggers a compliance violation.

Your objective is to determine a compliant risk configuration for the entire ledger. If there is more than one compliant configuration, you must output the one that yields the minimum possible value for the final audit hash. The audit hash is computed sequentially through the ledger. Let the audit state at step $i$ be represented by a column vector $V_i = \begin{pmatrix} H_i \\ 1 \end{pmatrix}$. Starting with an initial state $V_0 = \begin{pmatrix} 0 \\ 1 \end{pmatrix}$, each transaction $i$ (from $1$ to $n$) updates the state via the transformation matrix:
$$ V_i = \begin{pmatrix} 4 & c_i \\ 0 & 1 \end{pmatrix} V_{i-1} $$
You must output the configuration that minimizes the top element of the final state vector $V_n$. (Note: this top element evaluates exactly to the standard audit hash formula $\sum_{i=1}^{n} c_i \cdot 2^{2n - 2i}$). 
If there is no way to assign the risk tiers without a compliance violation, you must report that the configuration is impossible.

## Input
The first line provides two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — the number of transactions and the number of dependency links.
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating that a dependency link connects transaction $u$ and transaction $v$.

## Output
If a compliant configuration is impossible, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the risk tiers for transactions $1$ through $n$ that minimize the audit hash.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
The problem is mathematically identical to the seed but heavily disguised using linear algebra. The inequality constraint `c_u != c_v` is rewritten as a non-zero matrix determinant, and the lexicographical tie-breaker is rewritten as a sequence of affine transformations using matrix multiplication. This prevents models from recognizing the problem as standard graph 3-coloring, forcing them to reason through the matrix operations rather than deploying pre-memorized index-order backtracking templates.
</RATIONALE>
<PRESERVED_ANSWER>
The determinant condition simplifies exactly to `c_u - c_v != 0`, and the top element of the final matrix state mathematically expands to exactly the original audit hash formula, ensuring all valid configurations and the chosen minimum remain identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly Graph 3-Coloring with a lexicographical tie-breaker, keeping it in NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the matrix transformation as requiring floating-point arithmetic rather than exact integer state updates, though the inputs and matrix elements are all strict integers.
</RISK>
