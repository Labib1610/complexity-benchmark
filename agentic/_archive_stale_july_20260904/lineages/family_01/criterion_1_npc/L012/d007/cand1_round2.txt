# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You have been tasked with auditing a ledger containing $n$ sequential financial transactions, which are indexed from $1$ up to $n$. Every transaction $i$ must be assigned a specific risk tier $c_i$. The system only supports three risk tiers, which are strictly represented by the integers $1$, $2$, and $3$.

Additionally, the ledger defines $m$ dependency links between pairs of transactions. To comply with strict regulatory rules, the two transactions connected by any dependency link cannot share the same risk tier. In other words, the set of risk tiers assigned to the two endpoints of a link must contain exactly two distinct values. Any violation of this rule renders the entire configuration invalid.

Your goal is to find a risk tier configuration for all $n$ transactions that satisfies every dependency link. If multiple valid configurations exist, you must select the one that produces the minimum possible audit hash. The audit hash is computed using the following formula:
$$ \sum_{i=1}^{n} c_i \cdot 2^{2n - 2i} $$

If no such valid configuration can be formed, you must declare it impossible.

*Performance Warning:* The hidden test suite contains adversarial ledgers specifically engineered to cause Time Limit Exceeded (TLE) for naive solvers. Evaluating transactions strictly in their default index order ($1, 2, \dots, n$) without intelligent variable ordering or pruning will result in an exponentially large search tree on these worst-case instances.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — the total number of transactions and the total number of dependency links.
Each of the following $m$ lines provides two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating a dependency link between transaction $u$ and transaction $v$.

## Output
If it is impossible to find a compliant risk configuration, print a single line containing `NO`.
If a compliant configuration is possible, print `YES` on the first line. On the second line, print $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the optimal risk tiers for transactions $1$ through $n$ that minimize the audit hash.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
