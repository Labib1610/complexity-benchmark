<STATEMENT>
# Problem A — Security Clearance Resolution

Time limit: 2 s
Memory limit: 256 MB

In a secure distributed architecture, permissions must be carefully allocated across a network of $n$ processing terminals. The facility is physically limited to exactly 40 terminal bays, meaning the number of active terminals $n$ is at least 1 and at most the facility's total bay capacity. You must assign exactly one clearance level to each terminal, choosing from the available levels $\{1, 2, 3\}$.

The system's integrity is maintained by $m$ strict separation protocols. The number of protocols $m$ can be anything from 0 up to the theoretical maximum where every distinct pair of terminals is restricted. Each protocol dictates that a specific pair of terminals, $u$ and $v$, cannot share the same clearance level. While a single protocol only limits two terminals, the overlapping nature of these rules creates complex, system-wide dependencies.

Be warned: the evaluation scenarios contain explicit adversarial instances. The test suite includes maximum-size configurations deliberately constructed so that a simple trial-and-error approach assigning terminals in increasing index order and trying clearance levels 1, 2, and 3 sequentially will explore an astronomical number of dead ends and exceed the time limit before finding a solution or proving NO. You must employ more robust pruning techniques or intelligent orderings during your search, even though the final output must still be the lexicographically smallest valid configuration.

You must determine whether a complete clearance level assignment exists that satisfies every separation protocol. If such an assignment is possible, you must find the one that is lexicographically smallest.

## Input
The first line contains two integers $n$ and $m$. The value of $n$ represents the active terminals (ranging from 1 up to the 40-bay capacity), and $m$ represents the number of separation protocols (from 0 up to the maximum possible number of distinct terminal pairs).
Each of the next $m$ lines contains two integers $u$ and $v$ (ranging from 1 to $n$, with $u \neq v$), representing a protocol that prevents terminal $u$ and terminal $v$ from operating at the same clearance level.

## Output
If it is impossible to assign levels without breaking a protocol, output `NO` on a single line.
If a valid assignment can be made, output `YES` on the first line. On the second line, output $n$ integers $c_1, c_2, \dots, c_n$ (where $c_i \in \{1, 2, 3\}$) to represent the assigned clearance level for each terminal. This sequence of levels must be the lexicographically smallest valid configuration (comparing the level of terminal 1 first, then terminal 2, and so on).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The numeric bounds have been reframed as physical capacities and theoretical maximums within the scenario (a 40-bay facility, maximum distinct pairs) instead of bare inequalities. The specific affordance that led models to use a naive index-ordered search has been directly countered by explicitly warning them that such a sequence of assignments will time out on adversarial inputs, forcing them to reason about dynamic variable ordering and pruning before validating the lexicographically smallest requirement.
</RATIONALE>
<PRESERVED_ANSWER>
The solution space remains identical because the available clearance levels, the separation constraints, and the lexicographical tie-breaking rule are mathematically unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-COLORING on a graph with up to 40 vertices, keeping it firmly NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "maximum possible number of distinct terminal pairs" if they do not correctly recall the formula for combinations, but this is a standard concept so the risk is low.
</RISK>
