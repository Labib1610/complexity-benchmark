# Problem A — Security Clearance Resolution

Time limit: 2 s   Memory limit: 256 MB

In a secure distributed architecture, permissions must be carefully allocated across a network of $n$ modules. You must assign exactly one security tier to each module, choosing from the available tiers $\{1, 2, 3\}$.

The system's integrity is maintained by $m$ strict isolation policies. Each policy dictates that a specific pair of modules, $u$ and $v$, cannot share the same security tier. While a single policy only limits two modules, the overlapping nature of these rules creates complex, system-wide dependencies. 

Be warned: the evaluation scenarios contain explicit adversarial instances. The module numbering is an adversarial permutation. Maximum-size inputs are selected so that sequentially committing modules in increasing numerical index order (from 1 to $n$) will explore an astronomical number of partial configurations before finding a solution or proving NO. To avoid exceeding the time limit, your approach should process the modules using a dynamic or structural ordering strategy (for example, prioritizing heavily-constrained modules) rather than naive index-based prefix enumeration.

You must determine whether a complete security tier assignment exists that satisfies every isolation policy. If such an assignment is possible, you must find the specific valid assignment that minimizes the system's total risk footprint. 
The risk footprint $R$ of an assignment $c_1, c_2, \dots, c_n$ is defined as:
$$R = \sum_{i=1}^n c_i \cdot 4^{n-i}$$
where $c_i \in \{1, 2, 3\}$ is the tier assigned to module $i$.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$), denoting the number of modules and the number of isolation policies.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing a policy that prevents module $u$ and module $v$ from operating at the same security tier.

## Output
If it is impossible to assign tiers without breaking a policy, output `NO` on a single line.
If a valid assignment can be made, output `YES` on the first line. On the second line, output $n$ integers $c_1, c_2, \dots, c_n$ (where $c_i \in \{1, 2, 3\}$) to represent the assigned security tier for each module that minimizes the risk footprint $R$. (Do not output $R$ itself).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2

```
4 6

1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
The problem's tie-break rule ("lexicographically smallest") naturally aligns with the first solution found by a naive index-ordered DFS, allowing models to short-circuit their search without proving optimality. By mathematically disguising this tie-break rule as an exponentially-weighted objective function and explicitly warning models against using index-ordered processing, models are manipulated into using dynamic variable ordering (e.g., largest degree first). Because this dynamic search order is completely orthogonal to the index-weighted objective function, their branch-and-bound implementations will fail to prune effectively and will explore the entire search space to prove optimality, leading to a Time Limit Exceeded.
</RATIONALE>
