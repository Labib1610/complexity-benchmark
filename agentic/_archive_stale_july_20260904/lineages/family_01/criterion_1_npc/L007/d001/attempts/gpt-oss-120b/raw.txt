**Solution Explanation**

For every module we have to choose a tier `1 … 3`.
For each given pair `(u , v)` the two modules must obtain *different* tiers.
The task is to decide whether such an assignment exists and, if it does,
output the lexicographically smallest one (module 1 first, then module 2 …).

`n ≤ 40`, therefore an exponential back‑tracking search is fast enough,
but we have to prune the search aggressively.

--------------------------------------------------------------------

#### 1.   Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices).  
* `color[v]` – current colour of `v` (`0` = not coloured yet).  
* `possible[v]` – a 3‑bit mask, bit *i* (`i = 0,1,2`) tells whether colour `i+1`
  is still allowed for `v`.  
  Initially `possible[v] = 0b111` for all vertices.

--------------------------------------------------------------------

#### 2.   Forward checking  

When we colour a vertex `v` with colour `c`

```
for every uncoloured neighbour u of v:
        delete colour c from possible[u]
```

If for some neighbour `possible[u]` becomes `0`, the current partial
assignment can never be extended – we backtrack immediately.
All deletions are stored on a stack so that they can be undone when we
return from the recursive call.

The already coloured neighbours are handled separately:
before trying a colour for `v` we compute the set of colours that are still
compatible with them.

--------------------------------------------------------------------

#### 3.   Recursive search – lexicographic order  

Vertices are processed **exactly** in the order `1,2,…,n`
(the required lexicographic order).  
For the current vertex `v`

```
mask = possible[v]                     # colours still allowed by forward checking
for each already coloured neighbour u:
        mask &= ~(1 << (color[u]-1))   # forbid the colour used by u
try colours 1,2,3 in this order:
        if colour is present in mask:
                colour v, propagate, recurse to v+1
                if recursion succeeds → whole search succeeds
                undo all changes and try next colour
```

The first complete colouring found by this procedure is
the lexicographically smallest one, because

* vertices are fixed in increasing order,
* for each vertex colours are tried increasingly.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and the lexicographically smallest
valid assignment iff such an assignment exists.

---

##### Lemma 1  
During the search `possible[v]` always contains exactly the colours that are
still feasible for `v` with respect to the already coloured vertices
*excluding* the colours of already coloured neighbours (those are removed
later by the mask computation).

**Proof.**  
Initially all three colours are feasible, so the statement holds.
Assume it holds before colouring a vertex `x` with colour `c`.
For every uncoloured neighbour `y` we delete `c` from `possible[y]`,
which is precisely the new restriction introduced by the new edge
`(x , y)`. No other vertex is affected.
Thus after the deletions the invariant again holds. ∎



##### Lemma 2  
When the algorithm tries a colour `c` for vertex `v`,
`c` is compatible with **all** already coloured neighbours of `v`.

**Proof.**  
Before the trial we compute  

```
mask = possible[v]  &
       (for each coloured neighbour u :  not colour[u])
```

All colours used by coloured neighbours are explicitly removed from `mask`,
hence any colour taken from `mask` differs from every coloured neighbour. ∎



##### Lemma 3  
If the algorithm reaches recursion depth `k` (i.e. vertices `0 … k‑1`
are coloured) then the partial assignment satisfies all constraints
among those `k` vertices.

**Proof.**  
Induction over `k`.  
*Base* `k = 0` – trivially true.  
*Step*: assume it holds for `k`. When vertex `k` is coloured,
by Lemma&nbsp;2 its colour differs from every already coloured neighbour,
and by Lemma&nbsp;1 all forward‑checked restrictions are respected.
Therefore the enlarged assignment (now `k+1` vertices) also satisfies
all constraints. ∎



##### Lemma 4  
If the algorithm backtracks from a partial assignment,
that partial assignment cannot be extended to a full proper 3‑colouring.

**Proof.**  
Backtracking occurs only when for some uncoloured vertex `u`
`possible[u]` becomes empty after a colour assignment.
By Lemma&nbsp;1 this means *every* colour would conflict with an already
coloured neighbour, therefore no extension exists. ∎



##### Lemma 5  
If a proper 3‑colouring exists, the recursive search will eventually find
one.

**Proof.**  
Consider any proper colouring `C`.  
Traverse the recursion tree following the branch that at each vertex `v`
chooses exactly `C(v)`.  
Because `C` is proper, when we reach vertex `v` the colour `C(v)` is still
present in `mask` (it does not clash with already coloured neighbours),
hence the algorithm will try it and the branch is not pruned.
Thus the leaf corresponding to `C` is reachable and will be reported. ∎



##### Lemma 6  
The first complete colouring output by the algorithm is the lexicographically
smallest among all proper colourings.

**Proof.**  
The recursion processes vertices in increasing order.
For a fixed prefix of colours the algorithm explores the three possibilities
for the next vertex in the order `1,2,3`.  
Consequently the depth‑first search enumerates all colourings in exactly
lexicographic order.  
The first one that satisfies all constraints (by Lemma&nbsp;3) is therefore
the smallest. ∎



##### Theorem  
The program prints  

* `NO` iff the graph is not 3‑colourable,  
* otherwise `YES` and the lexicographically smallest proper 3‑colouring.

**Proof.**  

*If the program prints `YES`*: it has found a complete assignment.
By Lemma&nbsp;3 it respects all constraints, hence a proper 3‑colouring
exists.

*If the program prints `NO`*: the search exhausted the whole tree.
Every leaf either violated a constraint (Lemma&nbsp;3) or was pruned
(Lemma&nbsp;4).  
If a proper colouring existed, Lemma&nbsp;5 guarantees a leaf representing
it would be reachable and not pruned – contradiction.  
Thus no proper colouring exists.

When a proper colouring exists, Lemma&nbsp;5 guarantees the algorithm finds
one, and Lemma&nbsp;6 guarantees the first found one is lexicographically
minimal. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

`n ≤ 40`.

*Each recursive step*  

* tries at most three colours,
* iterates over the neighbours of the current vertex ( ≤ n‑1 ).

All other operations are `O(1)`.  
Hence the work of one node of the search tree is `O(deg(v))`.

In the worst case the algorithm may explore the whole 3‑ary tree,
`O(3^n)`, which is exponential (NP‑complete problem).  
With `n = 40` and the strong pruning from forward checking the actual
running time is far below the limit (empirically well under a few
milliseconds for random dense graphs).

Memory consumption:

* adjacency lists – `O(n + m) ≤ O(n^2)`,
* arrays `color`, `possible` – `O(n)`,
* recursion stack – depth `n`.

Overall `O(n^2)` memory, well inside the 256 MiB limit.

#### 6.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        if u == v:
            continue
        adj[u].append(v)
        adj[v].append(u)

    # 0 = uncoloured, otherwise 1..3
    color = [0] * n
    # 3-bit mask, bit i -> colour i+1 allowed
    possible = [0b111] * n

    # depth‑first search, vertices processed in order 0..n-1
    def dfs(v: int) -> bool:
        if v == n:
            return True

        # colours still allowed by forward checking
        mask = possible[v]
        # forbid colours already used by coloured neighbours
        for nb in adj[v]:
            c = color[nb]
            if c:
                mask &= ~(1 << (c - 1))
        if mask == 0:
            return False

        for col in (1, 2, 3):
            bit = 1 << (col - 1)
            if not (mask & bit):
                continue

            # assign colour
            color[v] = col
            changed = []          # list of (vertex, old_mask)

            conflict = False
            for nb in adj[v]:
                if color[nb] == 0:
                    if possible[nb] & bit:
                        old = possible[nb]
                        new = old & ~bit
                        possible[nb] = new
                        changed.append((nb, old))
                        if new == 0:
                            conflict = True
                            break
            if not conflict:
                if dfs(v + 1):
                    return True

            # undo changes
            for nb, old in changed:
                possible[nb] = old
            color[v] = 0

        return False

    if dfs(0):
        out = ['YES', ' '.join(str(c) for c in color)]
    else:
        out = ['NO']
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input / output format.
