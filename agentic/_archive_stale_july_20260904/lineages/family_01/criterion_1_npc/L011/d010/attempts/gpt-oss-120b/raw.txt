**Solution Explanation**

For every task we have to choose one of the three profiles  

```
1 : (1,2,3)
2 : (2,3,1)
3 : (3,1,2)
```

For a pair of simultaneous tasks `u , v` the three steps must use
different resources, i.e. for every step `k`

```
profile_u[k] != profile_v[k]
```

Looking at the three profiles we see that two *different* profiles are
always different in every step, while a profile is equal to itself.
Therefore the condition for an edge `(u,v)` is simply

```
profile_u != profile_v
```

So the problem is exactly a **proper 3‑colouring** of the given undirected
graph, and we have to output the lexicographically smallest colour
sequence `c1 … cn`.

`n ≤ 40`, therefore a depth‑first search with backtracking is easily fast
enough.  
We colour the vertices **in the natural order 1 … n**.
When we reach vertex `i` we try the colours `1,2,3` in this order;
the first complete colouring we find is automatically the lexicographically
smallest one.

The algorithm:

```
DFS(i):
    if i > n:   # all vertices coloured
        solution found
    for colour in 1..3:
        if colour is different from every already coloured neighbour of i:
            assign colour to i
            DFS(i+1)
            if solution found: return
    undo assignment of i   # backtrack
```

If the search finishes without finding a solution we output `NO`,
otherwise `YES` and the stored colour array.

The search explores at most `3^n` states, but with the neighbour checks
the branching factor is much smaller; for `n = 40` it runs far below the
time limit.

---

#### Correctness Proof  

We prove that the algorithm outputs `YES` and the lexicographically
smallest valid configuration iff such a configuration exists.

---

**Lemma 1**  
During the search, a partial assignment never violates any edge constraint.

*Proof.*  
When a colour is assigned to vertex `i` we check all already coloured
neighbours `j < i`. The colour is accepted only if it differs from each
neighbour’s colour. Hence every edge whose both ends are already coloured
has different colours. ∎



**Lemma 2**  
If the algorithm reaches `i = n+1`, the built colour array is a valid
configuration.

*Proof.*  
All vertices `1 … n` are coloured. By Lemma&nbsp;1 every edge with both ends
coloured (i.e. all edges) has different colours on its ends, which is
exactly the required condition. ∎



**Lemma 3**  
If a valid configuration exists, the DFS will eventually find one.

*Proof.*  
Consider any valid configuration `C`. The DFS explores colours for vertex
`1` in order `1,2,3`. Since `C[1]` is one of them, the branch that chooses
`C[1]` is taken. Inductively, assume the DFS has followed the branch that
matches `C` on vertices `1 … i‑1`. When processing vertex `i`, colour
`C[i]` is allowed because all neighbours among `1 … i‑1` have colours
different from `C[i]` (otherwise `C` would be invalid). Therefore the DFS
will also take the branch with colour `C[i]`. By induction the whole
configuration `C` is reachable, so the search will find a solution. ∎



**Lemma 4**  
The first complete colouring found by the DFS is the lexicographically
smallest among all valid colourings.

*Proof.*  
The DFS processes vertices in increasing index order and, for each vertex,
tries colours `1,2,3` in increasing order.
Thus the search tree is ordered lexicographically: any colouring that
differs first at position `p` with a smaller colour at `p` appears earlier
in a pre‑order traversal. The algorithm stops at the first leaf (complete
colouring), therefore this leaf is the lexicographically smallest
colouring. ∎



**Theorem**  
The algorithm outputs  

* `NO` iff no valid configuration exists;  
* otherwise `YES` and the lexicographically smallest valid configuration.

*Proof.*  

*If part*:  
If the algorithm outputs `YES`, it has reached `i = n+1`. By Lemma&nbsp;2
the produced array is a valid configuration.

*Only‑if part*:  
If a valid configuration exists, Lemma&nbsp;3 guarantees the DFS will
reach a leaf, so the algorithm will output `YES`. If none exists, the
DFS explores the whole search space without reaching a leaf and finally
outputs `NO`.

When a solution is found, Lemma&nbsp;4 shows it is the lexicographically
smallest one. ∎



---

#### Complexity Analysis  

`n ≤ 40`, `m ≤ n(n‑1)/2`.

For each vertex we test at most three colours, each test scans its
adjacent edges (degree ≤ n‑1).  
Worst‑case time: `O(3^n * n)` – far below the limit for `n = 40`.  
Memory usage: adjacency list `O(n + m)` plus the colour array `O(n)`,
well within 256 MB.

#### Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    colour = [0] * n
    found = False

    def dfs(v: int):
        nonlocal found
        if found:
            return
        if v == n:
            found = True
            return
        for c in (1, 2, 3):
            ok = True
            for nb in adj[v]:
                if nb < v and colour[nb] == c:
                    ok = False
                    break
            if not ok:
                continue
            colour[v] = c
            dfs(v + 1)
            if found:
                return
            colour[v] = 0  # backtrack

    dfs(0)

    out = []
    if not found:
        out.append("NO")
    else:
        out.append("YES")
        out.append(" ".join(map(str, colour)))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

conforms to the required input‑output format.
