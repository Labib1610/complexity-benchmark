# Phase II: Team Segregation Module

Time limit: 1 s   Memory limit: 256 MB

Our automated resource management pipeline consists of three sequential phases. In Phase I, the system ingests feedback surveys and compiles a list of $m$ incompatible worker pairs among the $n$ total employees (numbered 1 through $n$). We are currently implementing Phase II. Later, in Phase III, the payroll daemon will take the generated schedules and apply team-specific tax codes.

Your task is to build the core logic for Phase II. The module receives the $n$ employees and the $m$ incompatible pairs from Phase I. It must determine if the employees can be divided into exactly two distinct operational groups, Group 1 and Group 2, such that no two employees in the same group are flagged as incompatible.

The module must either reject the configuration or output a valid group assignment. Since Phase III's caching mechanism requires deterministic inputs, if multiple valid assignments exist, you must output the one that is lexicographically smallest (comparing the sequence of group numbers assigned to employee 1, then employee 2, and so on up to employee $n$).

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2 \cdot 10^5$, $0 \le m \le 2 \cdot 10^5$), representing the number of employees and the number of incompatible pairs generated by Phase I.
Each of the following $m$ lines contains two integers $u$ and $v$ — an incompatible pair.

## Output
If Phase II cannot find any valid group assignment, print a single line containing NO.
Otherwise, print YES on the first line. On the second line, print $n$ integers separated by spaces, where the $i$-th integer is either 1 or 2, representing the group assigned to employee $i$. This sequence must be the lexicographically smallest valid assignment.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
