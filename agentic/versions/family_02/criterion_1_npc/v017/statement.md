# Problem A — Pipeline Configuration Synthesis

Time limit: 2 s   Memory limit: 256 MB

## Description
You are implementing the configuration synthesis phase of an automated integration pipeline.

In the preceding phase, the telemetry parser scans the hardware and produces a list of *m* operational constraints over *n* binary toggles. Each toggle must be assigned exactly one state: active or inactive. The constraints generated by the parser always take a specific form: each constraint identifies three toggle conditions (a condition being a specific toggle and its required state, either active or inactive). A constraint is considered resolved if at least one of its three conditions is met by the global configuration.

Your module receives these constraints. Its job is to determine if there exists a single, comprehensive configuration for all *n* toggles that resolves every constraint simultaneously. The same toggle may be referenced across many constraints, and may be required to be active in some and inactive in others.

If your module successfully synthesizes a valid configuration, it passes it to the deployment engine, which flashes it to the hardware for the next run. If the constraints contradict each other such that no valid configuration is possible, your module must signal a failure so the pipeline can halt and trigger a manual engineering review.

## Input
The first line contains two integers *n* and *m* (1 ≤ *n* ≤ 90, 0 ≤ *m* ≤ 400), representing the number of toggles and the number of constraints generated by the parser.
The next *m* lines each contain three non-zero integers *l1*, *l2*, *l3* (with absolute values between 1 and *n*, inclusive). An integer *x* represents a condition: if *x > 0*, it means toggle *x* must be active; if *x < 0*, it means toggle *|x|* must be inactive. Each line represents a constraint where at least one of the three conditions must be satisfied.

## Output
If the pipeline must halt because no valid configuration exists, output a single line with `NO`.
Otherwise, output `YES` on the first line. On the second line, output *n* space-separated integers *s1*, *s2*, ..., *sn*, where *si* is `1` if toggle *i* is active, and `0` if it is inactive. If multiple valid configurations exist, any of them will be accepted by the deployment engine.

## Example 1
Input:
```
3 2
1 2 3
-1 2 -3
```
Output:
```
YES
0 0 1
```

## Example 2
Input:
```
1 2
1 1 1
-1 -1 -1
```
Output:
```
NO
```

## Note
Each constraint provided by the parser has exactly three entries. The same toggle index may appear more than once in a single constraint.
