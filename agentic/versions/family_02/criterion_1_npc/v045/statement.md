# Problem A — Configuration Pipeline: Phase 2

Time limit: 2 s   Memory limit: 256 MB

## Description

The configuration of a high-security facility involves a three-phase pipeline. In Phase 1, an automated audit generates a list of safety constraints based on the states of **n** two-state toggles. Each toggle must be firmly set to either engaged or disengaged before operations begin; there is no neutral position.

Every safety constraint generated by the audit specifies exactly three requirements. A requirement refers to a specific toggle and a mandatory state (engaged or disengaged) for that toggle. A safety constraint is considered fulfilled if at least one of its three requirements is met. A constraint where none of the three requirements are met is violated. The same toggle might be referenced across multiple safety constraints, sometimes required to be engaged and other times disengaged. The constraints may overlap heavily or barely at all — the only thing that matters is the exact requirements each constraint lists.

In Phase 2, your software must process the output of Phase 1 and determine if there exists a single, comprehensive configuration for all **n** toggles such that every safety constraint is fulfilled simultaneously. If such a configuration exists, it must report one; otherwise, it must report that the constraints are contradictory. Fulfilling the constraints one by one is simple — the challenge is finding one assignment consistent with all of them at once.

In Phase 3, the facility either deploys your reported configuration to the physical hardware, or initiates a manual override if the constraints were contradictory.

Your task is to implement Phase 2.

## Input
The first line contains two integers, n and m. The number of toggles n is at least 1, and cannot exceed the 90 available physical slots on the control board. The number of constraints m can be as few as zero, and goes up to the maximum 400 entries permitted by the audit log.

Each of the following m lines contains three non-zero signed integers l1, l2, l3. The absolute value of each integer corresponds to a valid toggle index on the board. A positive integer indicates a requirement that the corresponding toggle be engaged, while a negative integer indicates a requirement that it be disengaged. For a constraint to be fulfilled, at least one of its three stated requirements must be met.

## Output
If no valid configuration exists that fulfills all constraints, print a single line containing NO.
Otherwise, print YES on the first line. On the second line, print n integers s1 s2 … sn (each in {0, 1}), where si is 1 if toggle i is engaged and 0 if it is disengaged. Any valid configuration is accepted.

## Example 1
Input:
```
3 2
1 2 3
-1 2 -3
```
Output:
```
YES
0 0 1
```

## Example 2
Input:
```
1 2
1 1 1
-1 -1 -1
```
Output:
```
NO
```

## Note
Each constraint always lists exactly three requirements. The same toggle index might be specified multiple times within a single constraint.
