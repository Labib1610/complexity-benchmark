# Problem A — Treatment Pipeline Integration

Time limit: 5 s
Memory limit: 256 MB

## Description

A medical center manages its operations through a four-stage treatment pipeline:
1. **Intake and Triage**: Incoming cases are evaluated and assigned unique dossier ID numbers.
2. **Compatibility Screening**: An automated system evaluates medical requirements and generates a catalog of medically sound treatment profiles. Each profile is a specific triad consisting of one specialist, one facility, and one dossier.
3. **Daily Roster Generation**: This is the stage your software must handle.
4. **Post-Operative Allocation**: The recovery wards are prepared based on the finalized daily roster.

You are responsible for implementing the third stage. You will receive the catalog of viable treatment profiles generated by the second stage. For the current shift, there are exactly **k** specialists, **k** facilities, and **k** dossiers, each numbered from 1 to **k**.

Your task is to select exactly **k** treatment profiles from the catalog to form the daily roster. To ensure the pipeline functions correctly for the fourth stage, the roster must satisfy a strict requirement: every specialist must be activated exactly once, every facility must be booked exactly once, and every dossier must be resolved exactly once.

Determine whether a valid roster can be constructed. If it is possible, report one such roster so the pipeline can proceed.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k). These represent the size of each resource pool (specialists, facilities, dossiers) and the total number of approved treatment profiles from the screening stage.
Each of the following **t** lines contains three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), describing a single treatment profile composed of specialist **x**, facility **y**, and dossier **z**. No profile is duplicated in the catalog.

## Output

If a valid daily roster can be formed, print `YES` on the first line. Then, output **k** lines, each containing the three integers `x y z` of a selected treatment profile. Any roster that uses every specialist, facility, and dossier exactly once is acceptable. The profiles may be printed in any order.

If it is impossible to form a valid daily roster, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both approved treatment profiles require facility 1. Consequently, facility 2 can never be booked, making it impossible to complete the roster.
