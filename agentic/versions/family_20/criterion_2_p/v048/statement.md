# Factory Pipeline Phase 2: QA Synchronization

Time limit: 2 s   Memory limit: 256 MB

## Description
The security factory pipeline operates in three distinct phases to produce and verify its components.

**Phase 1 (Manufacturing & Test Generation):** Automated lathes produce a batch of locks and a batch of keys. The QA system then determines a set of mandatory interaction tests, each requiring exactly one lock and exactly one key to be physically engaged. The system calculates the "peak load"—the maximum number of tests that any single physical item (whether a lock or a key) is required for—and passes the complete list of tests to the next phase.

**Phase 2 (Synchronization & Scheduling - Your Task):** The robotic testing bay operates in discrete time slots. Your task is to process the list of tests from Phase 1 and assign each test to a time slot. Because an item cannot be in two places at once, no two tests that share the same lock or the same key may be assigned to the same time slot. Furthermore, to keep the pipeline moving, the QA bay is strictly allocated exactly *peak load* time slots for the entire batch. You must assign every test a slot numbered from 1 to *peak load* such that no item is double-booked. (Due to the strict separation of components into locks and keys, achieving this optimal schedule is always physically possible).

**Phase 3 (Execution & Shipping):** The robotic bay reads your schedule, executes all independent tests simultaneously within each time slot, logs the results, and clears the bay for the next batch.

Your program is responsible solely for executing Phase 2.

## Input
The first line contains three integers `nL`, `nR`, and `m` (1 ≤ `nL`, `nR` ≤ 100000, 0 ≤ `m` ≤ 400000), representing the number of locks, the number of keys, and the total number of tests generated by Phase 1.
The next `m` lines each contain two integers `u` and `v` (1 ≤ `u` ≤ `nL`, 1 ≤ `v` ≤ `nR`), indicating a test required between lock `u` and key `v`.

## Output
First, print `YES` to acknowledge the pipeline stage.
Then, print a single line containing `m` integers, each between 1 and the *peak load* inclusive. The `i`-th integer represents the time slot assigned to the `i`-th test in the input sequence. If multiple valid schedules exist, any one is acceptable.

## Example

### Input
```text
3 3 4
1 1
1 2
2 2
3 3
```

### Output
```text
YES
1 2 1 1
```
