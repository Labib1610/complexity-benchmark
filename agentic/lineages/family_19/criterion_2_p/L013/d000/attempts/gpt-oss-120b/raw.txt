**Solution Explanation**

For every corridor we know a *capacity* – the maximal number of containers that may be sent through it.
We have to decide how many containers to send through every corridor so that

* the amount sent through a corridor never exceeds its capacity,
* at every hub except the origin `s` and the destination `t` the total incoming
  equals the total outgoing amount,
* exactly `d` containers leave `s` and arrive at `t`.

That is exactly the definition of a **feasible flow of value `d`** in a directed
network with capacities.

The classic way to test feasibility and to construct a concrete flow is a
maximum‑flow algorithm.

--------------------------------------------------------------------

#### 1.   Max‑flow from `s` to `t`

* Build a flow network with the given capacities.
* Run Dinic’s algorithm ( `O(E·√V)` in practice, easily fast enough ).
* Let `f` be the obtained maximum flow value.

*If `f < d`* – even the best possible flow is not enough → answer `NO`.

Otherwise we already have a flow of value `f ≥ d`.  
We still have to **reduce it to exactly `d`** while keeping all constraints.

--------------------------------------------------------------------

#### 2.   Reducing a flow

A flow of value `f` can be decreased by sending flow **backwards** from the
sink to the source.
In the residual network (the graph that Dinic works with) an edge
`u → v` with remaining capacity `c` means we may still increase the flow
through `u → v` by at most `c`.  
Conversely, the reverse edge `v → u` with capacity equal to the current flow
means we may *decrease* the flow on `u → v` by sending flow from `v` to `u`.

Therefore we run a second max‑flow computation

```
source = t ,   sink = s
required reduction = f - d
```

on the **current residual graph**.
The algorithm will push at most `f-d` units back; because the original flow
has value `f`, we can always push exactly `f-d` (just follow any `s‑t` path
used before, but in reverse).  
After this second run the net flow from `s` to `t` becomes `d`.

--------------------------------------------------------------------

#### 3.   Extracting the answer

For every original corridor we stored its initial capacity `cap0`.
During the algorithm the forward edge’s remaining capacity `cap` changes.
The amount actually sent through that corridor is

```
flow = cap0 - cap
```

These numbers are printed in the order of the input.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
After the first Dinic run the obtained flow `F₁` is a feasible flow
with value `f = |F₁|` (the maximum possible flow value).

**Proof.** Dinic is a correct maximum‑flow algorithm. It respects capacities,
conserves flow at intermediate vertices and returns a flow of maximal value.
∎



##### Lemma 2  
If `f ≥ d` then there exists a feasible flow of value exactly `d`.

**Proof.** Take the maximum flow `F₁` of value `f`.  
Consider the residual network `R₁`.  
Sending one unit of flow from `t` to `s` in `R₁` corresponds to decreasing the
value of the original flow by one (the unit travels backwards along some
`s‑t` path of `F₁`).  
Repeating this `f-d` times yields a flow of value `d`.  
All capacity and conservation constraints stay satisfied because we only
decrease flow on edges that currently carry flow. ∎



##### Lemma 3  
Running a second max‑flow from `t` to `s` on the residual graph `R₁`
pushes exactly `f-d` units of flow back, producing a flow `F₂` of value `d`.

**Proof.** The source‑sink pair is swapped, therefore any augmenting path
found in `R₁` sends flow opposite to the original direction, i.e. reduces the
original flow value.  
The total possible amount that can be sent back equals the current flow value
`f` (the whole flow could be cancelled).  
Since we request at most `f-d ≤ f`, the algorithm will succeed in sending the
full requested amount (standard max‑flow property: it finds a flow of maximal
possible value, which is at least the request).  
Consequently the resulting flow value is `f-(f-d)=d`. ∎



##### Lemma 4  
After both runs, for every corridor the stored number `cap0 - cap`
equals the amount of flow assigned to that corridor in the final flow `F₂`.

**Proof.** The forward edge’s remaining capacity `cap` is always
`cap0 - (current flow on that edge)`.  
Both Dinic runs only modify capacities via the usual augment/undo operations,
so the invariant holds throughout. ∎



##### Lemma 5  
If the algorithm outputs `YES` and the list of numbers, they satisfy all
requirements of the problem.

**Proof.** By Lemma&nbsp;3 the final flow has value `d`.  
By Lemma&nbsp;4 the printed numbers are exactly the flow on each corridor,
hence they respect capacities (never exceed `cap0`).  
Flow conservation holds for all intermediate vertices because the algorithm
always maintains a feasible flow. ∎



##### Lemma 6  
If the algorithm outputs `NO` then no feasible assignment exists.

**Proof.** `NO` is printed only when the first max‑flow value `f` is smaller
than `d`. By Lemma&nbsp;1 `f` is the maximum possible flow value, therefore no
flow of value `d` can exist. ∎



##### Theorem  
The algorithm prints `YES` followed by a correct allocation
iff such an allocation exists; otherwise it prints `NO`.

**Proof.**  
*If* the algorithm prints `YES`, Lemma&nbsp;5 guarantees the allocation is
valid.  
*Only if* a valid allocation exists, its value is `d`; thus the maximum flow
value `f` is at least `d`. The algorithm will not output `NO` (Lemma&nbsp;6)
and will produce a flow of value `d` (Lemmas&nbsp;2–4), hence prints `YES`. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*First Dinic*: `O(E·√V)` (practically ≤ `O(E·V)` ), with `V = n`, `E = m`.  
*Second Dinic*: same bound, but the amount of flow to push is at most `f-d`,
still `O(E·√V)`.  

Overall time `O(E·√V)` ≤ `2·10⁵` operations for typical limits, well inside 2 s.  

Memory consumption: adjacency lists store for each edge a forward and a reverse
edge → `O(E)` objects, each constant size → ≤ `O(E)` ≤ 256 MB.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(1 << 25)

class Dinic:
    __slots__ = ('n', 'g', 'level', 'it')
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, idx=-1):
        # forward edge
        fwd = [to, cap, None, idx]   # to, cap, rev, idx
        # backward edge
        rev = [fr, 0, fwd, -1]
        fwd[2] = rev
        self.g[fr].append(fwd)
        self.g[to].append(rev)

    def bfs(self, s, t):
        level = [-1] * self.n
        q = [s]
        level[s] = 0
        for v in q:
            for to, cap, rev, _ in self.g[v]:
                if cap and level[to] < 0:
                    level[to] = level[v] + 1
                    q.append(to)
        self.level = level
        return level[t] >= 0

    def dfs(self, v, t, f):
        if v == t:
            return f
        for i in range(self.it[v], len(self.g[v])):
            self.it[v] = i
            to, cap, rev, _ = self.g[v][i]
            if cap and self.level[v] + 1 == self.level[to]:
                ret = self.dfs(to, t, min(f, cap))
                if ret:
                    self.g[v][i][1] -= ret
                    rev[1] += ret
                    return ret
        return 0

    def max_flow(self, s, t, limit=None):
        flow = 0
        INF = 10**18
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF if limit is None else limit - flow)
                if not pushed:
                    break
                flow += pushed
                if limit is not None and flow >= limit:
                    return flow
        return flow

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it)); m = int(next(it)); _ = next(it)  # the 1 is irrelevant
    s = int(next(it)) - 1
    t = int(next(it)) - 1
    d = int(next(it))

    dinic = Dinic(n)
    edge_refs = []          # store forward edge reference for each original edge
    caps0 = []              # original capacities

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        cap = int(next(it))
        caps0.append(cap)
        # store reference to forward edge list element
        dinic.add_edge(u, v, cap, len(edge_refs))
        edge_refs.append((u, len(dinic.g[u]) - 1))   # (from, index in adjacency)

    maxf = dinic.max_flow(s, t)
    if maxf < d:
        print("NO")
        return

    # Reduce flow from f to d by sending back (maxf - d) from t to s
    need = maxf - d
    if need > 0:
        dinic.max_flow(t, s, need)

    # Extract flows
    ans = [0] * m
    for idx, (u, pos) in enumerate(edge_refs):
        edge = dinic.g[u][pos]
        flow = caps0[idx] - edge[1]   # original cap - remaining cap
        ans[idx] = flow

    print("YES")
    print(' '.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```
