# Problem A — Transitive Unification

Time limit: 5 s   Memory limit: 256 MB

## Description

A rule engine manages **n** state variables, numbered 1 through **n**. You have the option to enforce bidirectional equality constraints between specific pairs of variables. Enforcing an available equality constraint between a given pair of variables incurs a continuous overhead of a specific number of compute credits.

When variables are constrained to be equal, this relationship is fully transitive: if variable A is forced to equal variable B, and B is forced to equal C, then A is guaranteed to equal C.

You are given a strict requirement: a designated set of **t** target variables must all be guaranteed to hold the exact same value. To achieve this, you may select any set of available equality constraints to enforce. You are free to use any of the other non-target variables as intermediate steps in your transitive chains. Determine the minimum total compute credits required for the set of constraints you choose to enforce.

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2).
The second line contains **t** distinct integers: the ids of the target variables.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000): indicating that an equality constraint between variable **u** and variable **v** is available, and enforcing it costs **w** compute credits.
The available constraints are sufficient to ensure all target variables can be made equal.

## Output

Print a single integer: the minimum total compute credits required for the set of enforced constraints to ensure all target variables share the same value.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, enforcing constraints that link variable 4 to variables 1, 2, and 3 (costing 1+1+1 = 3 credits) is cheaper than using constraints that only involve the target variables directly (which would cost 4). In Example 3, there is only one target variable, so no constraints need to be enforced.

I completely rewrote the scenario from establishing network protocols to enforcing logical equality constraints in a rule engine. This removes all networking terminology (components, data flow, forwarding), forcing models to recognize that algebraic transitivity over a subset of variables mathematically maps to finding a minimum-weight connected subgraph.
</RATIONALE>

</PRESERVED_CLASS>
<RISK>
Models might misinterpret "continuous overhead" as requiring a time-based calculation, though the problem explicitly asks for the "total compute credits required for the set of constraints", which correctly implies a one-time sum of the chosen weights.
</RISK>
