<STATEMENT>
# Secure Data Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

A distributed system manages a set of isolated cryptographic key stores, numbered sequentially starting from 1. 
To enable cross-platform communication, the system can compute bidirectional equivalence mappings between specific pairs of key stores. Computing a mapping between a specific pair incurs a known computational overhead. 

Once an equivalence mapping is computed between two stores, they seamlessly share decryption privileges. This sharing is fully transitive: if store A shares privileges with store B, and store B shares with store C, then A and C can also decrypt each other's data. 

A select group of these stores are classified as root authorities. Because root authorities require intensive manual auditing, corporate policy strictly limits their number to at most ten (and at least one) in any deployed system. 
The system's security protocol dictates that all root authorities must be able to share decryption privileges with one another. You may compute mappings between any pairs of stores—including those that are not root authorities—if doing so provides a more efficient chain of equivalence.

Calculate the minimum possible sum of computational overheads required to compute a valid set of mappings that guarantees all root authorities share decryption privileges.

## Input

The first line contains three integers: the total number of key stores, the number of potential mappings, and the number of root authorities. The total number of stores is between 1 and 100, and the number of potential mappings is between 0 and the maximum possible for that number of stores.
The second line contains a list of distinct integers identifying each of the root authorities.
Each of the subsequent lines describes one potential equivalence mapping using three integers: the identifiers of the two distinct stores it connects, followed by its computational overhead (between 1 and 1,000,000).
It is guaranteed that a valid set of mappings exists to satisfy the protocol.

## Output

Print a single integer: the minimum total overhead needed.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, computing mappings through the non-root store 4 (overhead 1+1+1 = 3) is more efficient than directly linking the three root authorities (which would require an overhead of 2+2 = 4). In Example 3, there is only a single root authority, so no mappings need to be computed.

Removed the explicit `t <= 10` inequality from the input specification and instead expressed this bound naturally within the scenario description. I also replaced standard graph/network terminology with a cryptographic key equivalence scenario. This forces the model to actually read and reason about the scenario constraints to discover that this is a small-terminal Steiner Tree problem, rather than pattern-matching bare inequalities in the input bounds to instantly select an exponential-time bitmask DP.
