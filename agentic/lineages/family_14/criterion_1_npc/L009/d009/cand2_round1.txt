<STATEMENT>
# Problem A — Subspace Basis Procurement

Time limit: 5 s   Memory limit: 256 MB

## Description

You are analyzing an $n$-dimensional vector space over the finite field GF(2). Let $b_1, b_2, \ldots, b_n$ denote the standard basis vectors of this space, represented as $1 \times n$ row vectors. Within this domain, a specific set of $t$ indices are designated as priority coordinates.

You are tasked with procuring a subset of vectors from a provided catalog. Each catalog entry allows you to add a specific vector of the form $b_u + b_v$ to your chosen subset for a specified procurement expense. Note that since the field is GF(2), addition is commutative and $b_u + b_v$ is identical to $b_v + b_u$.

Your goal is to select a subset of the available catalog entries. Let $k$ be the number of vectors you procure, and let $M$ be the $k \times n$ matrix over GF(2) whose rows are these chosen vectors. You must ensure that for every pair of priority coordinates $x$ and $y$, the vector $b_x + b_y$ belongs to the row space of $M$. Equivalently, there must exist a row vector $c \in \text{GF}(2)^k$ such that $c M = b_x + b_y$. 

Calculate the minimum total expense required to procure a subset of catalog entries that satisfies this condition.

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2, 1 ≤ t ≤ 10). The integer **t** is the number of priority coordinates.
The second line provides **t** distinct integers representing the identities of these priority coordinates.
The subsequent **m** lines each contain three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), describing a catalog entry that provides the vector $b_u + b_v$ for a procurement expense of **w**.
It is guaranteed that the available catalog options are sufficient to construct a matrix $M$ satisfying $c M = b_x + b_y$ for all pairs of priority coordinates $x$ and $y$.

## Output

Print a single integer: the minimum total expense to satisfy the condition for all priority coordinates.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, procuring the vectors $b_1 + b_4$, $b_2 + b_4$, and $b_3 + b_4$ incurs a total expense of 1+1+1 = 3. Let these three vectors form the rows of the $3 \times 4$ matrix $M$. For the priority coordinates 1 and 2, the vector $c = [1, 1, 0]$ yields $c M = (b_1 + b_4) + (b_2 + b_4) = b_1 + b_2$. Similar row vectors $c$ exist for $b_2 + b_3$ and $b_1 + b_3$. Consequently, the condition is fulfilled for the priority coordinates 1, 2, and 3. This is more economical than selecting a subset of catalog entries that do not involve coordinate 4 (which would cost at least 4).

In Example 3, there is only a single priority coordinate. The condition that for every pair of priority coordinates $x$ and $y$, there exists a vector $c$ such that $c M = b_x + b_y$ is vacuously satisfied by an empty subset of vectors (where $M$ has 0 rows), resulting in a cost of 0.
</STATEMENT>
<RATIONALE>
I removed the explicit permission to use non-priority coordinates as "intermediate components" and replaced the subset span condition with an equivalent GF(2) matrix row-space formulation ($c M = b_x + b_y$). This forces the model to algebraically deduce that linear combinations of $b_u + b_v$ correspond to path connectivity in a graph, rather than relying on familiar graph-like phrasing to trigger a Steiner tree template.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that $b_x + b_y$ is in the row space of $M$ over GF(2) is mathematically identical to it being in the subspace spanned by the selected vectors, so the valid subsets and their costs remain exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem is still isomorphic to the Steiner tree problem on a graph where priority coordinates act as terminals, so the complexity class remains NP-complete.
</PRESERVED_CLASS>
