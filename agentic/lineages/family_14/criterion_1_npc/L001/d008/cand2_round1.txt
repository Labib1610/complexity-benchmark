# Problem A — Microservice Unification

Time limit: 5 s   Memory limit: 256 MB

## Description

You are managing a distributed backend system consisting of **n** microservices, indexed 1 through **n**.
Your specific objective is to ensure the robust unification of a set of **t** critical microservices: $c_1, c_2, \dots, c_t$.

To achieve this, you can deploy bidirectional communication channels.
You are provided with a list of **m** possible channels. Deploying a channel between microservice $u$ and microservice $v$ incurs a one-time setup cost of $w$. 
You only pay the setup cost for each deployed channel once.

The system of critical microservices is considered **unified** if it satisfies the following cross-environment condition:
Imagine assigning every one of the **n** microservices to either a 'Primary' zone or a 'Secondary' zone. 
If a zone assignment results in the Primary zone containing at least one critical microservice AND the Secondary zone containing at least one critical microservice, then there must be at least one deployed channel that connects *some* microservice in the Primary zone to *some* microservice in the Secondary zone (the connected microservices do not themselves need to be critical). 
This requirement must hold true for *every* possible zone assignment that splits the critical microservices.

You must choose a subset of channels to deploy such that the critical microservices are unified, while minimizing the total setup cost.

(Note: If $t=1$, it is impossible to split the critical microservices between zones. Thus, the condition is trivially satisfied by deploying 0 channels for a total cost of 0.)

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2), representing the total number of microservices, the number of available channels, and the number of critical microservices.
The second line contains **t** distinct integers $c_1, c_2, \dots, c_t$: the indices of the critical microservices.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), indicating that a bidirectional channel between microservice u and microservice v can be deployed for a cost of w.
It is guaranteed that a valid set of channels exists to satisfy the requirement.

## Output

Print a single integer: the minimum total setup cost.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, the critical microservices are 1, 2, and 3. You can deploy channels between (1,4), (2,4), and (3,4) for a total cost of 1+1+1 = 3. 
To verify this satisfies the condition, consider any zone assignment. For instance, if microservices 1 and 2 are in the Primary zone, and 3 and 4 are in the Secondary zone, the Primary zone contains critical microservices 1 and 2, and the Secondary zone contains critical microservice 3. The deployed channel (1,4) connects microservice 1 (Primary) to 4 (Secondary), satisfying the requirement. Any other valid zone assignment that splits the critical microservices will similarly be bridged by at least one of these three deployed channels. 
Alternatively, you could deploy channels (1,2) and (2,3) for a total cost of 2+2 = 4. The minimum cost is 3.

In Example 3, there is only one critical microservice ($t=1$). No partition can place a critical microservice in both zones. The condition is trivially met with 0 channels, and the minimum cost is 0.
