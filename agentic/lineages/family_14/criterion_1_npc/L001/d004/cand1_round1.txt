# Problem A — Memory Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

You are configuring a system with **n** memory banks (numbered 1 to **n**). You have a list of potential two-way state-links that can be activated between specific pairs of banks. Activating a link incurs a known hardware cost.

The system relies on a sequence of **t** core banks: $c_1, c_2, \dots, c_t$. 
To verify system stability, a synchronization token must complete a sequential routing test. The token begins at $c_1$. It must then be routed to $c_2$, then to $c_3$, and so on, reaching each target core bank in the specified order until it finally arrives at $c_t$. 

A configuration consists of a chosen subset of the available links to activate. The token is only permitted to pass between two banks if the link connecting them is included in your activated subset. The total cost of a configuration is the sum of the hardware costs of the links in the chosen subset.

Determine the minimum total activation cost of a configuration that makes this sequential routing test possible. (If $t=1$, the test requires no movements and the minimum cost is 0).

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2), representing the total number of memory banks, the number of available state-links, and the number of core banks.
The second line contains **t** distinct integers $c_1, c_2, \dots, c_t$: the identifiers of the core banks in their specified sequence.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000): indicating that a state-link can be activated between bank u and bank v at a cost of w.
It is guaranteed that the available links are sufficient to satisfy the routing test.

## Output

Print a single integer: the minimum total activation cost of a configuration that allows the token to complete its journey.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, the core banks are 1, 2, and 3. The token must travel from 1 to 2, and then from 2 to 3. A valid configuration is to activate the links (1,4), (2,4), and (3,4) for a total cost of 1+1+1 = 3. Under this configuration, the token can travel from 1 to 4 to 2 (reaching bank 2), and then from 2 to 4 to 3 (reaching bank 3). Alternatively, activating links (1,2) and (2,3) directly would cost 2+2 = 4. The minimum cost is 3. 

In Example 3, there is only one core bank ($t=1$), so the token requires no movements to complete the test and no links need to be activated.

<METHOD_NAME>Sequential Routing Masquerade</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit requirement for a shared network connecting a chain of nodes with a dynamic narrative of a single token sequentially visiting the nodes. This obscures the underlying equivalence relation (connectivity) and strongly baits sequential shortest-path heuristics, while mathematically still demanding a minimum-weight connected subgraph (Steiner Tree) spanning the core banks.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>
<RATIONALE>
Removed the explicit sentences explaining that links can be reused across multiple paths to form an arbitrary network structure. Instead, the connectivity requirement is framed as a single token that must sequentially traverse the core banks using only the activated links. This forces the model to independently deduce that a continuous walk visiting a set of nodes is equivalent to finding a connected subgraph containing those nodes, without the problem text directly hinting at a shared Steiner network.
</RATIONALE>
<PRESERVED_ANSWER>
The minimum cost subset of edges that allows a valid walk to visit all specified nodes in order is exactly the minimum cost connected subgraph containing all those nodes (the Steiner Tree), so the optimal cost is identical for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core requirement is still to find a minimum-weight subgraph connecting a subset of terminal vertices, which remains the NP-complete Steiner Tree problem.
</PRESERVED_CLASS>
<RISK>
A reader might wonder if the token is forbidden from passing through a later core bank (e.g., passing through $c_3$ while en route to $c_2$), but since the optimal Steiner tree is just a connected component, the presence or absence of such a restriction does not change the valid edge subsets or the optimal answer.
</RISK>
