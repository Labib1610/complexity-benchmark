<STATEMENT>
# Problem A — Memory Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

You are configuring a system with **n** memory banks (numbered 1 to **n**). You can permanently install two-way state-links between specific pairs of banks. Installing a link incurs a known one-time hardware cost. 

To initialize the system, a synchronization token must be routed sequentially through a workload of **t** core banks, provided in a specific order: $c_1, c_2, \dots, c_t$. 

The token is initially injected at $c_1$. The initialization process consists of $t-1$ consecutive phases. In phase $i$ (for $1 \le i \le t-1$), the token must be routed from its current location $c_i$ to its next destination $c_{i+1}$. 

The token can only travel between banks that are directly connected by an installed link. You must purchase and install a single set of links before the initialization begins. Because the links are permanent, any link you install is available for use during any and all phases, and the token may traverse an installed link any number of times in either direction.

Your task is to select a set of links to install such that the token can successfully complete all $t-1$ phases of its routing sequence. Determine the minimum total cost of the installed links required. (If $t=1$, the token does not need to move and the minimum cost is 0).

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2), representing the total number of memory banks, the number of available state-links, and the number of core banks.
The second line contains **t** distinct integers $c_1, c_2, \dots, c_t$: the identifiers of the core banks in their specified sequence.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000): indicating that a state-link can be installed between bank u and bank v at a cost of w.
It is guaranteed that the available links are sufficient to allow the token to complete the sequence.

## Output

Print a single integer: the minimum total cost of a set of installed links that allows the token to complete all phases.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, the core banks are 1, 2, and 3. The token must be routed from 1 to 2 in phase 1, and from 2 to 3 in phase 2. This can be achieved by installing links between (1,4), (2,4), and (3,4) for a total cost of 1+1+1 = 3. In phase 1, the token routes from 1 to 2 via bank 4. In phase 2, it routes from 2 to 3, again via bank 4. Alternatively, installing links (1,2) and (2,3) directly would cost 2+2 = 4. The minimum cost is 3. 

In Example 3, there is only one core bank ($t=1$), so the token has no phases to complete and no links are needed.

<RATIONALE>
I changed the problem from satisfying a set of static path requirements to routing a single token through the core banks in a strict sequence. This forces the model to realize that the sequential routing constraint is a red herring and that the problem still only requires finding a single connected component containing all core banks.
</RATIONALE>
<PRESERVED_ANSWER>
Any set of links that allows the token to sequentially visit all core banks must contain a connected component spanning all core banks, and any such component allows the token to complete the sequence, meaning the optimal set of links is exactly the same minimum-cost Steiner tree.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the Steiner Tree problem on graphs, which is NP-complete, as the sequential token routing is mathematically equivalent to connecting a subset of vertices.
</PRESERVED_CLASS>
<RISK>
Models might interpret "sequential token routing" as requiring the token to visit the banks without revisiting them (a simple path), but the text explicitly states "the token may traverse an installed link any number of times", mitigating this risk.
</RISK>
