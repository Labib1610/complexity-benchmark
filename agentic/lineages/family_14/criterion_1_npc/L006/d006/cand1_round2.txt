<STATEMENT>
# Problem A — Orbital Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

A set $X$ consists of $n$ distinct items, labeled $1$ to $n$. A specific subset $T$ of $t$ items is designated as the core subset.

You are provided with a list of $m$ available transposition operators. The $i$-th transposition operator in the list, when activated, can swap the items at positions $u_i$ and $v_i$. Activating this specific operator incurs a one-time cost of $w_i$.

You may choose to activate any selection of these listed operators. Let $G$ be the permutation group generated by your selected operators. The group $G$ naturally acts on the set $X$, partitioning the items into disjoint orbits. Two items $a$ and $b$ are in the same orbit if there exists some element in the group $G$ that maps $a$ to $b$.

Your objective is to ensure that all $t$ items in the core subset $T$ belong to a single orbit under the action of $G$. Items not in $T$ may also be part of this orbit if their inclusion helps minimize the total cost.

Calculate the minimum total cost of a selection of operators that achieves this objective. The total cost is the sum of the activation costs of the specific operators you choose to activate from the list.

## Input

The first line provides three integers $n$, $m$, and $t$ (1 ≤ $t$ ≤ 10, 1 ≤ $n$ ≤ 100, 0 ≤ $m$ ≤ $n \cdot (n−1)/2$).
The second line lists $t$ distinct integers representing the indices of the core items.
Each of the subsequent $m$ lines specifies an available transposition operator using three integers $u$, $v$, and $w$ (1 ≤ $u, v$ ≤ $n$, $u \neq v$, 1 ≤ $w$ ≤ 1000000). This indicates an operator that swaps items $u$ and $v$ with an activation cost of $w$.
It is guaranteed that activating all $m$ available operators is sufficient to place all core items into a single orbit.

## Output

Print a single integer: the minimum total activation cost required to ensure all core items belong to the same orbit.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, activating the operators that involve item 4 (which require costs of 1, 1, and 1; total cost = 3) is more efficient than activating the operators directly involving only the three core items (which would result in a total cost of 4). The group generated by the transpositions (1, 4), (2, 4), and (3, 4) places items 1, 2, 3, and 4 into a single orbit. Thus, item 4 acts as an effective intermediary. 
In Example 3, there is only a single core item, so it trivially belongs to its own orbit without needing to activate any operators, resulting in a total cost of 0.
</STATEMENT>
<RATIONALE>
The problem was rewritten to use the language of permutation groups and group actions. The algebraic concept of "orbits" of a permutation group generated by a set of transpositions is mathematically isomorphic to the connected components of a graph formed by those transpositions as edges. This hides the Steiner Tree structure behind group theory, forcing models to deduce the equivalence instead of pattern-matching graph terminology.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that all target items lie in a single orbit of the generated group is strictly equivalent to requiring that all target vertices lie in the same connected component of the selected edges, preserving the minimum-weight objective perfectly.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem requires selecting a minimum-cost subset of edges (transpositions) to connect a specific subset of vertices (core items), which is exactly the NP-complete Minimum Steiner Tree problem.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the problem as requiring the generated group to be the full symmetric group $S_t$ on the core elements, but the text explicitly states the requirement is only that they "belong to a single orbit", which precisely specifies connectivity rather than full permutation capability.
</RISK>
