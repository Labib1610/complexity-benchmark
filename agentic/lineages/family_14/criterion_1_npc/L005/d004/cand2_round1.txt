Semantic Bait-and-Switch (Graph to Disjoint Sets)
</METHOD_NAME>
<METHOD_DESCRIPTION>
Reframed the Steiner Tree problem (connecting a subset of nodes in a graph) as a corporate merger process. By using terminology strongly associated with Disjoint Set Union and Minimum Spanning Tree (merging departments, consolidated divisions, integration costs), models relying on semantic similarity will be lured into applying Kruskal's or Prim's algorithms, which fail to correctly optimize the non-terminal (Steiner) nodes. Additionally, the inherent symmetry of a "merger" eliminates the explicit "free reverse pathway" rule that previously served as a structural hint for reducing the problem to an undirected graph.
</METHOD_DESCRIPTION>
<METHOD_NOVEL>
yes
</METHOD_NOVEL>
<STATEMENT>
# Problem A — Corporate Consolidation Strategy

Time limit: 5 s   Memory limit: 256 MB

## Description

You are managing a corporate restructuring for a company with one or more departments (numbered starting from 1). The office building has exactly one hundred floors, and each department occupies at least one dedicated floor, imposing a strict maximum on the total department count.

You have a portfolio of proposed department mergers. The portfolio might be empty, but it is strictly deduplicated, meaning there is never more than one proposal for any unique pair of departments. Each proposal specifies a lead department **u**, a partner department **v**, and an integration cost **w**. Executing the proposal merges the two departments into a single consolidated division. This process unites them completely, meaning they exist in the same division regardless of which was listed as the lead or partner. The integration cost **w** is a positive integer amount paid from a discretionary fund capped at one million dollars.

A specific subset of the departments are designated as *core*. There is always at least one core department, and each is sponsored by a distinct member of the ten-person board of directors, strictly bounding their maximum number. 

Your objective is to ensure that all core departments are eventually absorbed into the exact same consolidated division. You are not required to consolidate the entire company; you may merge core departments directly with each other, or merge them with non-core departments if doing so yields a cheaper overall structure.

Find the minimum total integration cost required to achieve a single division containing all core departments.

## Input

The first line provides three integers: the number of departments, the number of proposed mergers in the portfolio, and the number of core departments.
The second line lists the identifiers of the core departments.
Each of the subsequent lines describes one proposal using three integers: the lead department, the partner department, and the integration cost.
It is guaranteed that the portfolio contains sufficient proposals to achieve the objective.

## Output

Output a single integer representing the minimum total integration cost to consolidate all core departments into one division.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, executing the proposals involving department 4 (total cost 1+1+1 = 3) merges departments 1, 2, and 3 into a single division. This is cheaper than executing proposals to merge the three core departments directly (which would cost 4). In Example 3 there is only one core department, so no proposals need to be executed.
</STATEMENT>
<RATIONALE>
I removed the explicit "free reverse pathway" rule that models were using as a shortcut to build an undirected graph. By substituting it with a "corporate merger" framing, the connections become inherently symmetric without needing a special rule. Furthermore, the vocabulary of "mergers" and "consolidated divisions" baits models into misclassifying the problem as a Minimum Spanning Tree or Disjoint Set Union task, forcing them to genuinely reason about the subset-optimization requirement to arrive at the correct Steiner Tree approach. Numeric bounds were also embedded into the scenario via physical limits and capacities.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical structure is identical: finding the minimum cost set of edges (proposals) to ensure a specific subset of vertices (core departments) are in the same connected component (consolidated division).
</PRESERVED_ANSWER>

The problem remains the classic NP-Complete Steiner Tree problem on graphs, just described using the mechanics of set merging.
