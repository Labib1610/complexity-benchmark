<METHOD_NAME>Parity Subspace Obfuscation</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the requirement to reach "all pairs of critical elements" (which trivially maps to paths and graph connectivity) with the mathematically equivalent requirement to reach "all even-parity subsets of critical elements". This shifts the semantic framing from graph theory (Steiner Tree) to linear algebra over GF(2), forcing the model to either rediscover the graph equivalence or fail by attempting an intractable basis-spanning algorithm over the subset space.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>
<STATEMENT>
# Problem A — Database Flag Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

You are managing a legacy database system containing **n** configuration flags. All flags are initially set to `FALSE`.

You can purchase synchronization scripts to manipulate these flags. Each script is hardwired to exactly two distinct flags, $u$ and $v$. When executed, the script simultaneously toggles the boolean state of both flag $u$ and flag $v$ (changing `FALSE` to `TRUE`, or `TRUE` to `FALSE`). 

Once a script is purchased, it is permanently unlocked. You may execute your purchased scripts in any order, and you may execute the same script multiple times. 

A specific subset of **t** flags are designated as *critical*. Your task is to purchase a subset of available scripts such that the following condition is satisfied: 
For *every* possible target state of the database that satisfies BOTH of the criteria below, there must exist some sequence of executions of your purchased scripts that transitions the database from its initial state (all flags `FALSE`) to that target state. 

The criteria for the target states are:
1. The number of critical flags that are `TRUE` is an **even** integer (e.g., 0, 2, 4, ...).
2. All **non-critical** flags are `FALSE`.

The specific sequence of executions may be different for each valid target state, but every sequence may only use scripts from the subset you purchased.

You are given a list of **m** available scripts, each with a one-time purchase cost **w**. Determine the minimum total cost of a subset of scripts that satisfies this requirement.

## Input

The first line provides three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2).
The second line lists **t** distinct integers representing the indices of the critical flags (1-indexed).
The following **m** lines each contain three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1,000,000). These represent an available script wired to flags **u** and **v** that can be purchased for a cost of **w**. (Note that the order of $u$ and $v$ does not matter, as the script toggles both simultaneously).
It is guaranteed that it is possible to satisfy the requirement using the available scripts.

## Output

Output a single integer representing the minimum total cost of a subset of scripts that allows reaching all required target states.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, the critical flags are 1, 2, and 3. The target states we must be able to reach (where an even number of critical flags are `TRUE` and all non-critical flags are `FALSE`) are:
- 0 critical flags `TRUE`: All flags `FALSE` (requires 0 executions).
- 2 critical flags `TRUE`: 
  - Exactly 1 and 2 are `TRUE` (and 4 is `FALSE`)
  - Exactly 2 and 3 are `TRUE` (and 4 is `FALSE`)
  - Exactly 1 and 3 are `TRUE` (and 4 is `FALSE`)

By purchasing the three scripts wired to (1, 4), (2, 4), and (3, 4) for a total cost of 1+1+1 = 3, we can satisfy the requirement. For instance, to reach the state where exactly 1 and 2 are `TRUE`, we can execute the script (1, 4) and then the script (2, 4). Flag 4 is toggled twice (returning to `FALSE`), while flags 1 and 2 are each toggled once (becoming `TRUE`). This is cheaper than purchasing the scripts (1, 2) and (2, 3) directly, which would cost 2+2=4.

In Example 3, there is only one critical flag. The only state with an even number of critical flags `TRUE` and all non-critical flags `FALSE` is the all-`FALSE` state (0 is an even number). Since the database is already in this state, no scripts need to be purchased, resulting in a cost of 0.
</STATEMENT>
<RATIONALE>
The previous version allowed models to trivially map "reach a state where exactly flag i and flag j are TRUE" to "find a path between vertex i and vertex j", instantly transforming the problem into a standard graph connectivity/Steiner Tree format. By mathematically extending the target condition to "all states with an even number of TRUE critical flags", the problem is reframed as spanning a specific parity subspace over GF(2). This forces the model to either deduce that spanning the even-parity subspace is exactly equivalent to connecting a set of terminals in a graph, or fail by attempting an intractable subset-sum or basis-finding algorithm.
</RATIONALE>
<PRESERVED_ANSWER>
In the cycle space of a graph over GF(2), a subset of edges can form all even-parity assignments on a set of vertices if and only if all those vertices belong to the same connected component, meaning the required optimal subsets of scripts (and their costs) are exactly identical to the original Steiner Tree formulation.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying mathematical requirement remains finding a minimum-weight subgraph that connects all critical vertices, preserving its identity as the NP-complete Steiner Tree problem.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "every possible target state" as only requiring the ability to reach *one* state that satisfies the criteria, though the explicit phrasing "For *every* possible target state... there must exist some sequence" strongly guards against this.
</RISK>
