# Problem A — Network Provisioning

Time limit: 5 s   Memory limit: 256 MB

## Description

A distributed computing system contains **n** processing nodes, numbered 1 through **n**. Physical chassis limitations restrict the node count to a maximum of 100, and there is always at least 1 active node. A designated group of **t** core controllers is installed. The architecture provides exactly 10 dedicated priority slots for these controllers, meaning **t** is at most 10, though at least 1 must be present. These core controllers must be fully interconnected to exchange telemetry data.

You can provision bidirectional communication channels between certain pairs of nodes. There are **m** available channels. Depending on the physical wiring, **m** can be as low as 0 or as high as **n**·(**n**−1)/2. Each available channel requires a specific amount of power to maintain, which is bounded by hardware capabilities between 1 and 1000000 units inclusive.

Data exchange operates across the provisioned channels: telemetry can be transmitted directly between two nodes if a channel is provisioned between them. Telemetry transmission is transitive: if data can be transmitted between node A and node B, and between node B and node C, then it can be transmitted between node A and node C.

Your objective is to select a subset of the available channels to provision such that telemetry can be exchanged among all core controllers. Find the minimum total power required to provision these channels.

## Input

The first line contains three integers **n**, **m**, and **t**.
The second line contains **t** distinct integers: the identifiers of the core controllers.
Each of the next **m** lines contains three integers **u**, **v**, and **w**, representing an available bidirectional channel between node **u** and node **v** (where **u** ≠ **v** and both are between 1 and **n** inclusive) that requires **w** units of power to maintain.
It is guaranteed that there exists at least one set of channels that allows all core controllers to exchange telemetry data.

## Output

Print a single integer: the minimum total power required to provision a valid set of channels.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

The explicit bounds from the input section were integrated into the narrative as physical constraints of the system (e.g., "chassis limitations" and "priority slots") to fulfill the S07 strategy while preserving exact numeric values for the checker. Additionally, the explicit hint that standard processing nodes can be used as intermediaries (and the associated explanatory Note) was removed. This forces the model to deduce from the objective and Example 1 that non-core nodes can be included in the selected channels to minimize power, preventing simple pattern matching to Steiner Tree templates.
</RATIONALE>

The objective remains to find the minimum weight subset of edges that connects a specific subset of vertices, keeping the mathematical graph problem identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem is still exactly the Minimum Steiner Tree problem on graphs, which is NP-complete.
</PRESERVED_CLASS>

Models might misinterpret the lack of explicit permission to use non-core nodes as a restriction to only use edges between core controllers, though Example 1's output of 3 directly contradicts this and resolves the ambiguity for any model that checks its understanding against the examples.
