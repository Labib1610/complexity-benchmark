<STATEMENT>
# Subsystem Boot Sequence

Time limit: 2 s   Memory limit: 256 MB

## Description

A mainframe computer consists of $n$ processing modules, numbered $1$ to $n$. These modules are linked by $m$ bidirectional data buses. The architecture guarantees that all modules are interlinked in a single contiguous network. The total number of buses $m$ is strictly fixed at exactly $n - 1$, meaning there is exactly one unique sequence of buses between any two modules.

A specific subset of $t$ modules are designated as core modules. To initialize the system, a boot signal must successfully reach all $t$ of these core modules.

You may choose any single module in the mainframe to act as the primary bootloader, from which the boot signal will originate (it does not need to be one of the core modules). However, all data buses are initially uncalibrated and cannot transmit the signal. Before initialization, you must select a set of buses to calibrate. Calibrating the bus between module $u$ and module $v$ requires $w$ microseconds of processing time. Once a bus is calibrated, it can transmit the boot signal in either direction, allowing the signal to propagate freely across any sequence of calibrated buses. Uncalibrated buses cannot transmit the signal.

Your task is to determine the minimum possible total processing time required to calibrate a set of buses such that the boot signal can successfully reach all $t$ core modules from your chosen primary bootloader.

## Input

The first line contains three integers: $n$, $m$, and $t$ ($1 \le n \le 200000$, $m = n - 1$, $1 \le t \le n$).

The second line contains $t$ distinct integers, representing the IDs of the core modules.

Following this are $m$ lines, each describing a single data bus with three integers: $u$, $v$, and $w$ ($1 \le u, v \le n$, $u \neq v$, $1 \le w \le 1000000$).

## Output

Print a single integer: the minimum total processing time required.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the core modules are 1 and 4. You could choose module 2 as the primary bootloader. To ensure the signal reaches module 1, the bus between 1 and 2 must be calibrated (time 5). To reach module 4, the buses between 2 and 3, and 3 and 4 must be calibrated (times 1 and 2). The signal propagates from 2 to 1, and from 2 to 3 to 4. The total time is 5 + 1 + 2 = 8. Alternatively, choosing module 3 as the bootloader would require calibrating exactly the same buses. The minimum possible total time is 8.
In Example 2, there is only one core module (module 3). You can simply choose module 3 as the primary bootloader. Since the signal originates at the required core module, no buses need to be calibrated. The minimum possible total time is 0.
</STATEMENT>
<RATIONALE>
The framing has been shifted from a physical inspector touring a network to a boot signal propagating from an arbitrary starting module to target core modules. This obscures the "minimal subtree" structure by making it sound like a directed broadcast or source-selection problem. It forces the model to deduce that the optimal solution is still exactly the minimal connecting subgraph, regardless of which node within it is chosen as the source.
</RATIONALE>
<PRESERVED_ANSWER>
The cost to ensure reachability from a chosen start node to a set of targets in a tree is identical to the cost of traversing a connected subgraph containing them; the minimal such subgraph is unique and has the exact same edge sum as the original problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying graph is still explicitly a tree ($m = n - 1$, connected), meaning the unique minimal connecting subgraph logic still applies, keeping the solution in O(n) time.
</PRESERVED_CLASS>
