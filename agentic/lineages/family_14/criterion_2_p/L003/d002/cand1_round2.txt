<STATEMENT>
# Problem B — Module Integration Fabric

Time limit: 2 s   Memory limit: 256 MB

## Description

You are tasked with designing a routing sub-network for a distributed system. The system contains **n** system modules, numbered 1 through **n**. You are given a list of **m** potential bidirectional data links that can be deployed. Deploying a data link between a specific pair of modules incurs a given installation cost.

There are **t** modules designated as priority modules. Your goal is to select a subset of the potential data links to deploy so that all priority modules can transmit data to one another. Data can be relayed through non-priority modules if necessary.

Determine the minimum total installation cost required to achieve full connectivity among all priority modules.

*System Note: The available data links form a precisely connected architecture (as specified in the Input section). Consequently, achieving connectivity at the minimum cost is equivalent to deploying exactly the indispensable data links. A data link is indispensable if and only if its absence from the full set of **m** links would leave at least one pair of priority modules unable to communicate. Evaluating the network to identify these indispensable links will yield the correct minimum-cost subset.*

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ n, 1 ≤ n ≤ 200000, m = n − 1).
The second line contains **t** distinct integers: the ID numbers of the priority modules.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), representing a potential data link between module **u** and module **v** with an installation cost of **w**. The system architecture guarantees that deploying all **m** data links would successfully connect all **n** modules into a single network.

## Output

Print a single integer representing the minimum total cost to deploy data links such that all priority modules can communicate with each other.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the priority modules 1 and 4 can only communicate if the data passes through modules 2 and 3. Therefore, all three available data links (costs 5, 1, and 2) are indispensable and must be deployed, giving a total cost of 8.
In Example 2, there is only one priority module, so no data links need to be deployed and the total cost is 0.

<RATIONALE>
I preserved the original optimization objective precisely, but added a "System Note" that highlights a mathematical equivalence: in this specific architecture, the minimum-cost subset consists exactly of those links whose removal would disconnect a pair of priority modules. This baits models into implementing a naive O(N^2) edge-removal check (which will fail the time limit) rather than recognizing the underlying tree structure that allows O(N) leaf pruning. All numeric bounds, including `m = n - 1`, have been strictly restored to satisfy the exact original contract.
</RATIONALE>
<PRESERVED_ANSWER>
Because the graph is a tree, any valid network connecting the priority modules must include all edges on the unique paths between them, making the minimal connected subgraph unique and identical to the set of indispensable links.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains finding the minimum weight connected subgraph containing a subset of required vertices on a tree (Steiner Tree on trees), which is solvable in O(N) time.
</PRESERVED_CLASS>

Models might misinterpret the note as changing the problem to finding bridges in a general graph, but since the primary task explicitly asks for the minimum cost to achieve full connectivity, the mathematical goal remains unambiguous.
