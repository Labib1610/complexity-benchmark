<STATEMENT>
# Establishing the Secure Comm-Link

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital command manages a planetary grid of outposts. Certain pairs of outposts can be bridged by a secure conduit, which requires a specific energy cost to activate. Among the outposts, a specific subset are designated as **primary hubs**. You must activate a collection of conduits so that all primary hubs can synchronize data with each other (either directly or by relaying through other outposts, which do not need to be primary hubs themselves).

The engineers deployed the conduits to form a minimal contiguous framework. This means that if all available conduits were powered, data could successfully propagate between any two outposts in the grid. However, removing even a single conduit from this complete set would divide the grid into isolated segments that cannot communicate.

Your objective is to activate a set of conduits that minimizes the total energy cost while ensuring all primary hubs are interconnected. Output this minimum total energy cost.

## Input

The first line of the manifest provides three integers: $n$, $m$, and $t$.
- $n$ represents the total count of outposts. The sector's territorial grid comprises exactly 400 regions, each containing up to 500 individual sites. The total outpost count cannot exceed the total number of sites across all regions, and there will always be at least a single outpost.
- $m$ represents the number of available conduits. The entire grid is designed with exactly enough conduits to ensure no outpost is isolated, but without a single redundant connection, meaning the total conduit count is always exactly the outpost count minus one.
- $t$ represents the count of primary hubs. This count starts from a minimum of one and can scale up to encompass every outpost.

The second line contains $t$ distinct integers: the identifiers of the primary hubs.

Each of the next $m$ lines details a possible conduit with three integers: $u$, $v$, and $w$.
- $u$ and $v$ are distinct outpost identifiers (from 1 to $n$) bridged by this conduit.
- $w$ represents the energy cost to activate this conduit. The hardware requires a minimum of one unit of energy, and its maximum safety threshold is capped at exactly the square of one thousand units.

The available conduits strictly form the non-redundant contiguous framework described above.

## Output

Print a single integer: the minimum total energy cost required to interconnect all primary hubs.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the primary hubs 1 and 4 can only synchronize data by relaying through outposts 2 and 3, so all three conduits (5 + 1 + 2 = 8) must be activated. In Example 2, there is only one primary hub, so no conduits need to be activated.

<RATIONALE>
The explicit "exactly one possible route" guarantee was removed, which allowed models to skip structural reasoning and instantly treat the input as a tree. It has been replaced with the equivalent but less direct property that the network is contiguous but every edge is a bridge that would disconnect the grid if removed. Furthermore, direct numeric bounds were replaced with physical scenarios (e.g., 400 regions of 500 sites for 200,000 max outposts) forcing the model to calculate the limits.
</RATIONALE>

The problem still requires finding the minimum-weight subgraph connecting a specific subset of vertices in what is fundamentally a tree, meaning the identical unique minimal subtree is always chosen.
</PRESERVED_ANSWER>
