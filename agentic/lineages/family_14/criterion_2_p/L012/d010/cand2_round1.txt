<METHOD_NAME>Dual Cut-Space Framing</METHOD_NAME>
<METHOD_DESCRIPTION>Instead of asking the model to find a minimal set of edges to connect a subset of vertices (a path-based Steiner tree framing), this method asks the model to find the minimal set of edges whose individual removal would separate the subset (a cut-based framing). In a tree, the set of edges that separate a subset is exactly the minimal subtree connecting that subset. By framing the problem around "preventing separation by a single cut" rather than "establishing connectivity", models relying on pattern-matching will fail to recognize the Steiner tree structure and will likely attempt incorrect minimum-cut or articulation-point algorithms.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Legacy GC Sweep Audit

Time limit: 2 s   Memory limit: 256 MB

## Description

You are auditing a legacy database system that allocates up to a fifth of a million distinct memory sectors (with at least one sector always present).

The system features a set of predefined 'garbage collection (GC) sweeps'. Each sweep evaluates the reference link between two specific sectors, $u$ and $v$. The system's architecture guarantees that the total number of defined sweeps is exactly one less than the number of sectors. Furthermore, the sweeps form a minimally contiguous structure: assuming no sweeps are bypassed, executing ANY single GC sweep will sever the link it evaluates, permanently partitioning the entire memory space into exactly two disjoint reference pools. Sector $u$ will anchor one pool and sector $v$ will anchor the other, with all remaining sectors distributed between them according to their indirect links.

You are given a list of $t$ 'protected sectors' (the volume of this list ranges from a single sector up to the entire memory space).

You can choose to bypass certain GC sweeps. Bypassing the sweep between $u$ and $v$ consumes a specific number of micro-cycles, which is a positive integer never exceeding one million. When a sweep is bypassed, it is neutralized and will not partition the memory space even if triggered.

Your objective is to bypass a subset of sweeps such that: if the database subsequently triggers any SINGLE non-bypassed sweep, all $t$ protected sectors are guaranteed to remain together in the SAME reference pool.

Find the minimum total micro-cycles required to bypass the necessary sweeps. (If there is only 1 protected sector, it can never be separated from itself, requiring 0 micro-cycles).

## Input

The first line contains three integers: $n$, $m$, and $t$.
- $n$ is the number of distinct memory sectors.
- $m$ is the number of defined GC sweeps.
- $t$ is the number of protected sectors.

The second line contains $t$ distinct integers: the indices of the protected sectors (from 1 to $n$).

Each of the next $m$ lines details a GC sweep with three integers: $u$, $v$, and $w$.
- $u$ and $v$ are the distinct sectors (from 1 to $n$) evaluated by the sweep.
- $w$ is the micro-cycle cost to bypass this sweep.

## Output

Print a single integer: the minimum total micro-cycles required to bypass the necessary sweeps so that no single active sweep can separate the protected sectors.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the protected sectors are 1 and 4.
- If sweep (1,2) is executed, it partitions the sectors into {1} and {2,3,4}, separating the protected sectors. It must be bypassed (cost 5).
- If sweep (2,3) is executed, it partitions the sectors into {1,2} and {3,4}, separating the protected sectors. It must be bypassed (cost 1).
- If sweep (3,4) is executed, it partitions the sectors into {1,2,3} and {4}, separating the protected sectors. It must be bypassed (cost 2).
All three sweeps must be bypassed to guarantee sectors 1 and 4 remain in the same pool. The minimum total micro-cycles required is 5 + 1 + 2 = 8.

In Example 2, there is only one protected sector. Since a single sector can never be separated from itself, no sweeps need to be bypassed, resulting in a minimum cost of 0 micro-cycles.
</STATEMENT>
<RATIONALE>
The problem was completely reframed from a path-based construction ("connect these nodes") to a cut-based prevention ("prevent these nodes from being separated by a single cut"). In a tree, the set of edges whose individual removal separates a subset of vertices is mathematically identical to the minimal subtree connecting them. This dual framing forces the model to deduce the relationship between cut-sets and subtrees, bypassing simple pattern matching for Steiner tree problems. Additionally, all explicit numeric bounds were removed from the Input section and embedded dynamically into the scenario text (Strategy S07).
</RATIONALE>
<PRESERVED_ANSWER>
In a tree, an edge separates a subset of vertices if and only if it lies on the minimal subtree connecting that subset; therefore, the exact same subset of edges must be selected and their summed cost remains identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying structure remains finding the weight of the minimal subtree containing the target vertices in a given tree, which operates in O(n) time and remains in P.
</PRESERVED_CLASS>
<RISK>
A reader might misinterpret the condition as needing to protect against MULTIPLE sweeps being executed simultaneously, but the text explicitly emphasizes "any SINGLE non-bypassed sweep" to eliminate this ambiguity.
</RISK>
