# Entity Unification

Time limit: 2 s   Memory limit: 256 MB

## Description

You are managing a database of $n$ isolated entities. Exactly $t$ of these entities are marked as **Core Entities**.

You are provided with a list of $m$ potential unification procedures. Each procedure merges two specific entities, $u$ and $v$, into a single unified group. Executing a procedure requires a computational cost of $w$. 

The list contains exactly $m = n - 1$ procedures. It is guaranteed that if you were to execute all $m$ procedures, all $n$ entities would be merged into a single comprehensive group.

Your objective is to select a subset of these procedures to execute such that all $t$ Core Entities end up in the same unified group (either by direct merger or through a chain of intermediate mergers). (If $t=1$, no procedures need to be executed).

Determine the minimum total computational cost required to achieve this.

## Input

The first line contains three integers: $n$, $m$, and $t$.
- $1 \le n \le 200000$ is the total number of entities.
- $m = n - 1$ is the number of available procedures.
- $1 \le t \le n$ is the number of Core Entities.

The second line contains $t$ distinct integers: the indices of the Core Entities (from $1$ to $n$).

Each of the next $m$ lines details an available procedure with three integers: $u$, $v$, and $w$.
- $1 \le u, v \le n$ ($u \ne v$) are the indices of the entities merged by the procedure.
- $1 \le w \le 1000000$ is the computational cost of the procedure.

## Output

Print a single integer: the minimum total cost of a subset of procedures that unifies all Core Entities into the same group.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, Core Entities 1 and 4 can only be unified into the same group by executing all three procedures (costs 5 + 1 + 2 = 8). In Example 2, there is only one Core Entity. Since a single entity is always considered its own group, no procedures need to be executed, resulting in a minimum cost of 0.

I completely changed the algebraic/quadratic-penalty framing to an "Entity Unification" framing. This semantic shift strongly activates the "Disjoint Set Union (DSU) / Kruskal's" concepts in LLMs, tempting them to sort procedures by cost and merge greedily. However, applying Kruskal's to connect a subset of targets in a tree yields the wrong answer (it includes cheap unnecessary edges). To succeed, models must resist the DSU trap, recognize that the $m = n - 1$ guarantee implies a tree, and implement the correct subtree DFS pruning.
