# Federated Query Optimization

Time limit: 2 s   Memory limit: 256 MB

## Description

A distributed database system consists of **N** distinct data shards, numbered 1 through **N**.

There are **E** predefined bidirectional relational joins available. Each join associates records between shard **u** and shard **v** and incurs a computational overhead of **w**. 

The full collection of available joins provides complete relational continuity: if all **E** joins were executed, a single comprehensive view linking any two shards in the system would be established.

A specific query requires retrieving correlated information from a subset of **F** *critical* shards. You must choose a single subset of the available joins to permanently execute so that the records from any two critical shards are relationally linked using exclusively the executed joins. (The linkage may transitively incorporate non-critical shards, provided the joins along the linkage are also executed).

Determine the minimum total computational overhead required to link all critical shards in this manner. (If **F** = 1, exactly 0 joins need to be executed, so the minimum total overhead is 0.)

## Input

The first line contains three integers **N**, **E**, and **F** (1 ≤ F ≤ N, 1 ≤ N ≤ 200000, E = N − 1).
The second line contains **F** distinct integers: the labels of the critical shards.
Each of the following **E** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ N, u ≠ v, 1 ≤ w ≤ 1000000), representing an available join between shard **u** and shard **v** with a computational overhead of **w**.

## Output

Print a single integer: the minimum total computational overhead required to ensure all critical shards are relationally linked.

## Examples

```
8
```


**Output**
```
9
```
