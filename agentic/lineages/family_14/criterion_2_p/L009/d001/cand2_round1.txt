# Freight Hub Upgrades

Time limit: 2 s   Memory limit: 256 MB

## Description

A regional railway network consists of **n** stations. The region assigns exactly one inspector per station, and the total inspector headcount across the region is between 1 and 200,000, which defines the possible number of stations. 

The network was designed so that every station can be reached from any other. To minimize initial construction costs, it was built with the absolute minimum number of track segments necessary to achieve this full connectivity. The total number of track segments is **m**.

The transport authority has designated **t** of these stations as freight hubs. The number of hubs ranges from a single station up to the entire network. 

To support heavy cargo, the authority must upgrade a selection of track segments. The upgrades must ensure that every freight hub can route trains to every other freight hub using exclusively upgraded track segments. 

Each track segment has an associated upgrade cost **w**. The upgrade machinery requires at least 1 unit of material per segment, and its physical capacity limits the maximum material cost to 1,000,000 units. 

Determine the minimum total cost required to upgrade the necessary track segments.

## Input

The first line contains three integers **n**, **m**, and **t**. Their valid ranges and exact values are determined by the inspector headcount, the minimal connectivity design, and the hub designation rules described above.

The second line contains **t** distinct integers: the identifiers of the freight hubs.

Each of the following **m** lines contains three integers **u**, **v**, and **w**, representing a direct track segment between distinct valid stations **u** and **v** (where both are between 1 and **n**) with an upgrade cost of **w**. The range of **w** is dictated by the machinery limits.

## Output

Print a single integer: the minimum total cost to upgrade track segments such that all freight hubs are connected to each other via upgraded tracks.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

<RATIONALE>
I removed the explicit statement that there is "exactly one sequence of direct track segments connecting any pair", replacing it with the condition that the network achieves full connectivity using the "absolute minimum number of track segments". This forces the model to logically deduce that the network is a tree (and $m = n - 1$) rather than relying on a direct description of unique paths. I also rewrote all numeric bounds as physical or administrative limits within the scenario to prevent simple pattern matching on bare inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
The structural requirement of minimal full connectivity still strictly defines a tree, meaning the unique paths between freight hubs and the required edges to upgrade remain identical for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying graph is still a tree, so the task remains solvable in $O(n)$ time by rooting the network and including edges based on subtree hub counts.
</PRESERVED_CLASS>
<RISK>
Models might struggle to confidently extract the exact numerical bounds from the text, though the phrasing "between 1 and 200,000" and "at least 1... limits... to 1,000,000" is highly unambiguous.
</RISK>
