# Ledger Reconciliation

Time limit: 2 s
Memory limit: 256 MB

## Description

You are auditing a ledger consisting of exactly **n** distinct account balances, numbered from 1 to **n**.

You are provided with a pool of **m** optional reconciliation rules. Each rule can be applied to synchronize two specific accounts **u** and **v** (meaning their balances are forced to be equal), and has an associated implementation cost **w**.

The pool of available reconciliation rules is minimal and complete: there are exactly **m** = **n** - 1 rules available, and together they are capable of synchronizing all **n** accounts. Because of this minimal completeness, for any two accounts, there is exactly one sequence of available rules that can be chained together to force them to be equal.

Your objective is to select a subset of these rules to implement. You must ensure that, whether directly or through intermediate accounts, a specific list of **t** critical accounts are all forced to be equal to each other. The synchronization status of the remaining non-critical accounts does not matter.

What is the minimum total cost of the reconciliation rules you must select to satisfy this critical account condition?

## Input

The first line contains three integers **n**, **m**, and **t**. The number of accounts is **n** (1 ≤ **n** ≤ 200000). The number of available rules **m** is always exactly **n** − 1. The number of critical accounts is **t** (1 ≤ **t** ≤ **n**).
The second line contains **t** distinct integers: the identifiers of the critical accounts.
Each of the next **m** lines contains three integers **u**, **v**, and **w**. These denote an optional rule synchronizing accounts **u** and **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), which costs **w** to implement (1 ≤ **w** ≤ 1000000).

## Output

Print a single integer: the minimum total cost required.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

</RATIONALE>

The required subset of rules still corresponds exactly to the edges of the minimal subtree spanning the critical vertices, keeping the minimum cost identical for all inputs.
</PRESERVED_ANSWER>

The underlying graph formed by the rules is a tree, meaning the problem remains solvable in polynomial time via a linear-time tree traversal to identify edges on paths between critical vertices.
</PRESERVED_CLASS>
