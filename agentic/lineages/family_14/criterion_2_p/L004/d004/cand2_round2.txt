<STATEMENT>
# Constraint Selection

Time limit: 2 s
Memory limit: 256 MB

## Description

You are given a system of **n** integer variables (numbered 1 to **n**). Initially, they can take any independent values.

You have a list of **m** possible equality constraints. Each constraint can enforce that variable **u** must equal variable **v**. Activating a constraint incurs a specific cost, **w**. The list of constraints is minimal and complete: there are exactly **m** = **n** − 1 constraints available, and if you were to activate all of them, all **n** variables would be forced to take the exact same value.

System requirements have identified **t** target variables that must be synchronized. Your task is to select a subset of the available constraints such that, for any valid assignment of values that satisfies the activated constraints, all **t** target variables are guaranteed to hold the same value. You do not care about the other variables, though they may end up sharing this value as a byproduct.

What is the minimum total cost (the sum of the costs of the activated constraints) required to achieve this?

## Input

The first line contains three integers **n**, **m**, and **t**. The number of variables **n** (1 ≤ **n** ≤ 200000). The number of available constraints **m** is always exactly **n** − 1. The number of target variables **t** (1 ≤ **t** ≤ **n**).
The second line contains **t** distinct integers: the indices of the target variables.
Each of the next **m** lines contains three integers **u**, **v**, and **w**. These denote a potential constraint between variables **u** and **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**) requiring a cost of **w** (1 ≤ **w** ≤ 1000000).

## Output

Print a single integer: the minimum total cost required.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

<METHOD_DESCRIPTION>
I mapped the graph connectivity problem to a system of variables and equality constraints. Finding a minimal connected component translates to finding a minimal subset of equality constraints that forces a target subset of variables to be equal. By removing all spatial and graph-theoretic terminology ("components", "merged", "parts"), models relying on keyword association are less likely to recognize the underlying tree structure and apply the optimal DFS/subtree algorithm, instead getting confused by equivalence relations or attempting generic optimization.
</METHOD_DESCRIPTION>
<METHOD_NOVEL>
yes
</METHOD_NOVEL>
<RATIONALE>
I changed the domain from physical parts merging to activating mathematical equality constraints on variables. The underlying structure (a tree of n nodes and n-1 edges) and the objective (find the minimal subtree connecting t specific nodes) remain identical. By stripping away graph-theoretic and assembly terminology, models are forced to independently deduce that the equality constraints form a tree and that the minimal subset to enforce equality among targets is the Steiner tree, breaking pattern-matching shortcuts.
</RATIONALE>
<PRESERVED_ANSWER>
The problem is mathematically isomorphic to the original: variables are nodes, constraints are edges, and forcing variables to be equal requires a path of constraints between them, ensuring the minimal cost subset is exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding the minimal subtree connecting t given nodes in a tree, which can be solved optimally in O(n) time using a single depth-first search, keeping it firmly in P.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "for any valid assignment of values" as implying a boolean satisfiability or general algebraic problem rather than simple equivalence classes, though the phrase "enforce that variable u must equal variable v" keeps the equivalence relation straightforward.
</RISK>
