We are given a graph with \( n \) vertices and \( m = n-1 \) edges, so it’s a tree.  
The condition says: for every subset \( S \) that intersects \( T \) but doesn’t contain all of \( T \), there must be an edge crossing the cut \((S, U \setminus S)\).

This is equivalent to saying: in the chosen edge set, every connected component must either contain all of \( T \) or none of \( T \).  
Because if a component contains some but not all of \( T \), then taking \( S \) as that component would violate the condition.

So the problem reduces to:  
We have a tree. We must remove some edges (i.e., not activate them) so that each resulting connected component contains either all of \( T \) or none of \( T \).  
We want to minimize the total cost of the edges we keep (activate).  
Equivalently, maximize the total cost of edges we remove, subject to the constraint.

This is a classic tree DP:  
- Root the tree arbitrarily.  
- For each node, compute the minimum cost to make its subtree valid, given whether the component containing the root of the subtree contains any priority elements.

Let’s define:
- `dp0[u]`: minimum cost to make the subtree of `u` valid, assuming the component containing `u` has **no** priority elements.
- `dp1[u]`: minimum cost to make the subtree of `u` valid, assuming the component containing `u` has **all** priority elements in the subtree (or at least, it contains some priority elements and will eventually connect to the rest).

But since the condition is about whole components, we can think in terms of cutting edges.

Better approach:  
We want to remove edges so that no component contains a proper non-empty subset of \( T \).  
That means:  
- If a component contains at least one priority element, it must contain all of them.  
So the only allowed components are:  
1. Components with no priority elements.  
2. The single component that contains all priority elements.

Thus, we must cut all edges that connect a priority-containing part to a non-priority part, except we can keep edges inside the priority set and inside the non-priority set.

So the problem becomes:  
Find the minimum cost to keep a connected subgraph that contains all priority vertices, and we can optionally keep some non-priority vertices connected to it, but we must cut edges that would separate priority vertices from each other.

Actually, since the graph is a tree, the minimal way to connect all priority vertices is the minimal Steiner tree connecting them.  
All other edges can be removed (cost saved).  
So the answer = total cost of all edges − cost of the minimal Steiner tree connecting all priority vertices.

But wait: we can also keep some non-priority vertices connected to the Steiner tree if it’s cheaper than cutting them?  
No — if we keep a non-priority vertex connected to the priority component, that’s fine, it doesn’t violate the condition.  
But we don’t need to keep any non-priority edges unless they are on the path between priority vertices.  
So the minimal cost is exactly the cost of the minimal subtree that connects all priority vertices.

Thus:  
Answer = sum of all edge weights − weight of minimal Steiner tree connecting all \( t \) priority vertices.

Since the graph is a tree, the minimal Steiner tree connecting a set of vertices is simply the union of all edges on paths between them.  
We can compute it by:  
- Mark all priority vertices.  
- Do a DFS from any priority vertex, and keep edges that lead to a priority vertex in the subtree.

Implementation:  
1. Read input.  
2. Build adjacency list.  
3. Total cost = sum of all w.  
4. DFS from any node (say 1), compute for each node whether its subtree contains a priority vertex.  
5. If an edge connects a node to a child whose subtree contains a priority vertex, then that edge is part of the Steiner tree.  
6. Sum those edge weights.  
7. Answer = total − Steiner cost.

Edge case: if t = 1, Steiner tree cost = 0, answer = total cost? Wait, if t=1, we only need one priority vertex, so we can remove all edges, cost = 0.  
But our formula: total − Steiner cost. Steiner cost = 0, so answer = total. That’s wrong.  
So we must be careful: If t=1, we don’t need to keep any edges, so answer = 0.  
If t=n, we need all vertices connected, so Steiner tree is the whole tree, answer = total cost.

So the correct logic:  
We need to keep a connected subgraph that contains all priority vertices.  
If t=1, we can keep just that vertex, cost 0.  
If t>1, we need the minimal subtree connecting them.

Thus:  
If t == 1: answer = 0.  
Else: answer = total − cost_of_minimal_connecting_subtree.

Let’s implement.

```python
import sys
sys.setrecursionlimit(300000)

def solve():
    input = sys.stdin.readline
    n, m, t = map(int, input().split())
    T = set(map(int, input().split()))
    edges = []
    adj = [[] for _ in range(n+1)]
    total = 0
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
        total += w
    
    if t == 1:
        print(0)
        return
    
    # DFS to find edges that are part of Steiner tree
    parent = [0]*(n+1)
    parent_w = [0]*(n+1)
    visited = [False]*(n+1)
    stack = [1]
    visited[1] = True
    order = []
    while stack:
        u = stack.pop()
        order.append(u)
        for v, w in adj[u]:
            if not visited[v]:
                visited[v] = True
                parent[v] = u
                parent_w[v] = w
                stack.append(v)
    
    has_priority = [False]*(n+1)
    for u in range(1, n+1):
        if u in T:
            has_priority[u] = True
    
    steiner_cost = 0
    # Process in reverse order (post-order)
    for u in reversed(order):
        if u == 1:
            continue
        if has_priority[u]:
            steiner_cost += parent_w[u]
            # propagate up
            p = parent[u]
            while p != 0 and not has_priority[p]:
                has_priority[p] = True
                steiner_cost += parent_w[p]
                p = parent[p]
    
    print(total - steiner_cost)

if __name__ == "__main__":
    solve()
```
