# Orbital Station Power Grid

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital station consists of **n** modules (numbered 1 to **n**) and **m** structural corridors. The network of corridors is fully connected, ensuring any module can be reached from any other.

During a low-power emergency, the station commander must minimize power consumption. There are **t** specific modules that contain vital life-support systems. To safely reduce power, the commander follows a strict iterative shutdown protocol:

1. Initially, all **m** corridors are pressurized and active.
2. A corridor is evaluated as *redundant* if deactivating it (while leaving the rest of the currently active network unchanged) would still allow every vital module to reach every other vital module (if **t** ≥ 2) exclusively through the remaining active corridors.
3. The commander selects exactly one redundant corridor and permanently deactivates it.
4. This process is repeated one corridor at a time until no single remaining active corridor can be deactivated without isolating at least one vital module from the others.

Each corridor requires a certain amount of power to remain pressurized. Determine the total power required to maintain the corridors that remain active at the exact end of this protocol. (The station's architecture mathematically guarantees that the final set of active corridors—and therefore the total required power—is unique and entirely independent of the order in which redundant corridors are chosen for deactivation).

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ **t** ≤ **n**, 1 ≤ **n** ≤ 200000, **m** = **n** − 1).
The second line contains **t** distinct integers: the identifiers of the vital modules.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**, 1 ≤ **w** ≤ 1000000), representing a corridor linking module **u** and module **v** that requires **w** units of power to pressurize.

## Output

Print a single integer: the total power required to keep the final set of active corridors pressurized.

## Examples

### Example 1

**Input**
```

```

**Output**
```
8
```

```

```

**Output**
```
9
```

<RATIONALE>
I reframed the problem from an optimization task ("find the minimum connected subset") to a procedural simulation ("execute this iterative shutdown protocol"). This forces models to genuinely analyze the graph's structural properties—recognizing that the input is a tree and the protocol deterministically yields the minimal Steiner tree—to arrive at the required $O(n)$ DFS, rather than relying on surface-level keyword matching to trigger a tree algorithm. Models that blindly translate the protocol into a simulation will fail due to Time Limit Exceeded.
</RATIONALE>
<PRESERVED_ANSWER>
The iterative removal of redundant edges in a tree perfectly isolates the minimal subtree spanning the vital modules, meaning the final set of active corridors and their total weight is mathematically identical to the original formulation.
</PRESERVED_ANSWER>

The problem still asks for the sum of weights of the minimal Steiner tree on an input tree, which remains solvable in $O(n)$ time using a single DFS, keeping it in class P.
