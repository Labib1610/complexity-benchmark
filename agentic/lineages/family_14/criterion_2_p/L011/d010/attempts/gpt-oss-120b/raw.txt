**Solution Explanation**

For the given `n` reservoirs and `n‑1` pipes the graph is a **tree**.
A set of vertices is *fully mixable* **iff** it induces a connected sub‑tree.

During the process we may delete a vertex only while it is a leaf of the
current induced tree and it is not critical.
Thus we can delete any non‑critical leaf, after that new leaves appear,
and continue – exactly the usual “prune leaves” operation.

If we prune all possible non‑critical leaves, the remaining vertices are
precisely the smallest connected sub‑tree that contains **all critical
vertices**.
No extra vertex can lower the total pipe weight, because every extra vertex
adds at least one pipe.  
Consequently the optimal final system is the *minimal Steiner tree* for the
critical vertices in a tree – a uniquely defined sub‑tree:
the union of all paths between critical vertices, i.e. the tree that remains
after repeatedly removing non‑critical leaves.

--------------------------------------------------------------------

#### When is an edge necessary?

Remove an edge `e = (u, v)`. The tree splits into two components.
If **both** components contain at least one critical vertex,
the edge is needed to keep the whole set connected.
Otherwise the component without a critical vertex can be completely pruned
away, so the edge can be discarded.

Therefore the answer equals the sum of the weights of all edges whose two
sides each contain at least one critical vertex.

--------------------------------------------------------------------

#### Computing the answer

Root the tree arbitrarily (vertex `1`).  
For every vertex `x` we compute  

```
cnt[x] = number of critical vertices inside the subtree of x
```

by a single DFS (iterative to avoid recursion limits) and a bottom‑up pass.

Let `total = t` be the total number of critical vertices.
For a tree edge connecting a child `c` with its parent `p`

```
sub = cnt[c]                         # critical vertices in child's side
other = total - sub                  # critical vertices in the rest
edge is needed  <=>  sub > 0 and other > 0
```

Add its weight to the answer in that case.

The whole algorithm is linear `O(n)` time and `O(n)` memory, well within the
limits (`n ≤ 2·10⁵`).

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the minimum possible total maintenance
cost.

---

##### Lemma 1  
During the sealing process a vertex can be sealed **iff** it is a leaf of the
current induced tree and it is not critical.

**Proof.**  
If a vertex is a leaf, removing it does not disconnect the remaining vertices,
so the connectivity condition stays satisfied.
If it is not a leaf, it has degree ≥ 2 inside the induced tree. Deleting it would
separate its neighbours into different components, breaking connectivity –
forbidden. Critical vertices are never allowed to be sealed. ∎



##### Lemma 2  
The set of vertices that can remain after any valid sealing sequence is
exactly the smallest connected sub‑tree containing all critical vertices
(the *critical Steiner tree*).

**Proof.**  

*Containment.*  
All critical vertices must stay, so any final set contains them.
By Lemma&nbsp;1 only leaves can be removed, therefore the remaining vertices
form a connected induced sub‑tree.

*Minimality.*  
Take the critical Steiner tree **T\*** (the unique minimal connected sub‑tree
spanning all critical vertices).  
Every vertex of **T\*** is either critical or lies on a path between two
critical vertices.
If such a vertex were not in the final set, the two critical vertices would be
separated – contradicting connectivity. Hence every vertex of **T\*** must be
present in any valid final set.

Thus any achievable final set equals **T\***. ∎



##### Lemma 3  
An edge `e` belongs to the critical Steiner tree **iff**
both sides of `e` contain at least one critical vertex.

**Proof.**  
Remove `e`; the tree splits into components `A` and `B`.

*If* both contain a critical vertex, any connected sub‑graph spanning all
critical vertices must contain a path between those two vertices, and the only
such path in the original tree is `e`. Hence `e` is necessary.

*If* one side, say `A`, has no critical vertex, all critical vertices lie in `B`.
Then the sub‑tree consisting of `B` (without `e`) already spans all critical
vertices, so `e` is not needed. ∎



##### Lemma 4  
The algorithm adds exactly the weights of the edges of the critical Steiner
tree.

**Proof.**  
Rooting the tree, for a child `c` the subtree of `c` is exactly one of the two
components obtained by cutting the edge to its parent.
`cnt[c]` equals the number of critical vertices in that component.
The algorithm adds the edge weight precisely when `cnt[c] > 0` and
`total - cnt[c] > 0`, i.e. when both components contain a critical vertex.
By Lemma&nbsp;3 this condition is equivalent to the edge belonging to the
critical Steiner tree. ∎



##### Lemma 5  
The total weight computed by the algorithm equals the minimum possible total
maintenance cost after sealing.

**Proof.**  
By Lemma&nbsp;2 any admissible final system must be exactly the critical
Steiner tree, whose total edge weight is the sum of its edges.
By Lemma&nbsp;4 the algorithm outputs exactly this sum. ∎



##### Theorem  
`solve` prints the minimum possible total maintenance cost of the remaining
mixing pipes.

**Proof.**  
The algorithm outputs the sum of the weights of the critical Steiner tree
(Lemmas&nbsp;4 and&nbsp;5).  
No other final configuration can have smaller total cost (Lemma&nbsp;2), and
this configuration is reachable by repeatedly sealing non‑critical leaves
(Lemma&nbsp;1). Therefore the printed value is the optimum. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency list* : `O(n)` time, `O(n)` memory.  
*Iterative DFS* : `O(n)` time, `O(n)` memory for stack and arrays.  
*Bottom‑up aggregation* : `O(n)` time.  

Total time `O(n)`, total memory `O(n)` (≤ ~2·10⁶ integers – well below 256 MB).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    it = iter(data)

    n = int(next(it))
    m = int(next(it))          # = n-1
    t = int(next(it))

    critical = [False] * (n + 1)
    for _ in range(t):
        critical[int(next(it))] = True

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        w = int(next(it))
        adj[u].append((v, w))
        adj[v].append((u, w))

    # iterative DFS to obtain parent, edge weight to parent and order
    parent = [0] * (n + 1)
    pw = [0] * (n + 1)          # weight of edge to parent
    order = []
    stack = [1]
    parent[1] = -1              # root marker

    while stack:
        u = stack.pop()
        order.append(u)
        for v, w in adj[u]:
            if v != parent[u]:
                parent[v] = u
                pw[v] = w
                stack.append(v)

    # bottom‑up: count critical vertices in each subtree
    cnt = [0] * (n + 1)
    for u in reversed(order):
        total = 1 if critical[u] else 0
        for v, _ in adj[u]:
            if parent[v] == u:          # v is a child of u
                total += cnt[v]
        cnt[u] = total

    total_crit = t
    ans = 0
    for v in range(2, n + 1):           # all vertices except the root
        sub = cnt[v]
        if sub > 0 and total_crit - sub > 0:
            ans += pw[v]

    print(ans)

if __name__ == "__main__":
    solve()
```
