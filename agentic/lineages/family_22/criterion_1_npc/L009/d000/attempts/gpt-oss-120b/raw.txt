**Solution Explanation**

For every job we have to choose a time slot `1 … T`

*   a job may be executed only after all its predecessors,
    therefore its slot must be **strictly larger** than the slots of the
    predecessors;
*   in one slot at most `M` jobs can be executed.

All jobs have the same processing time (one slot).

--------------------------------------------------------------------

#### 1.   From precedence to allowed interval  

The precedence graph is a DAG (otherwise the answer is `NO` immediately).

*Earliest possible slot* `L[i]`  
`L[i] = 1 + max{ L[p] | p → i }`  
computed by a topological order (Kahn).

*Latest possible slot* `R[i]`  
`R[i] = T - max{ D[i] }` where `D[i]` is the length of the longest
path **starting** in `i`.  
Equivalently we process the vertices in reverse topological order

```
R[i] = T
for every edge i → j :   R[i] = min( R[i] , R[j] - 1 )
```

If for some vertex `L[i] > R[i]` the job can never be placed → `NO`.

Now each job `i` must be assigned a slot inside the interval  
`[ L[i] , R[i] ]`.

--------------------------------------------------------------------

#### 2.   Scheduling jobs with release times and deadlines  

We have:

* release time   `L[i]`
* deadline       `R[i]`
* at most `M` jobs per slot

This is the classic “parallel machine scheduling with unit jobs”.
A greedy algorithm works:

```
for slot = 1 … T
        insert all jobs with L[i] == slot into a min‑heap ordered by R[i]
        repeat up to M times
                if heap empty → break
                take job with smallest R[i]
                if R[i] < slot → impossible
                assign this job to current slot
```

Why is it correct?  
Consider any feasible schedule.
Look at the earliest slot `t` where the greedy algorithm and an arbitrary
feasible schedule differ.
Both schedules have executed the same set of jobs before `t`.
At slot `t` the greedy algorithm picks a job with the **earliest deadline**
among all jobs that are already released.
If the feasible schedule puts a different job `x` (deadline later than the
greedy choice `y`), we can exchange `x` and `y` – `y` still respects its
deadline, `x`’s deadline is not tighter, and the capacity of the slot is
unchanged. Repeating the exchange yields a schedule that coincides with the
greedy one. Hence the greedy algorithm succeeds **iff** a schedule exists.

The algorithm also produces the concrete assignment.

Complexities  

* building the graph: `O(n + m)`
* topological order & intervals: `O(n + m)`
* scheduling: each job enters and leaves the heap once → `O(n log n)`
* memory: `O(n + m + T)` (the list `start_at[slot]` can be a dictionary if
  `T` is huge, but `T ≤ 10^5` in typical limits, otherwise we store only
  slots that really appear).

--------------------------------------------------------------------

#### 3.   Algorithm
```
read n, M, T, m
read edges, build adjacency list and reverse list, indegrees
# 1. topological order, earliest L
queue = all vertices with indegree 0
while queue:
        v = pop
        for each w in adj[v]:
                L[w] = max(L[w], L[v] + 1)
                decrease indegree[w]; if 0 push w
if not all vertices processed → cycle → NO

# 2. latest R (reverse topological)
process vertices in reverse of the order obtained above
initialize R[v] = T
for v in reverse order:
        for each w in adj[v]:
                R[v] = min(R[v], R[w] - 1)

if any L[v] > R[v] → NO

# 3. greedy scheduling
make array start_at[1..T] (list of jobs)
for each job i: start_at[L[i]].append(i)

heap = empty
assigned = [0]* (n+1)
for slot = 1 .. T:
        for i in start_at[slot]: push (R[i], i) into heap
        repeat up to M times:
                if heap empty: break
                (deadline, i) = pop heap
                if deadline < slot: NO
                assigned[i] = slot
# after all slots
if some assigned[i] == 0 → NO

output YES and assigned[1..n]
```

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a valid schedule
iff such a schedule exists.

---

##### Lemma 1  
For every job `v` the value `L[v]` computed by the forward pass equals the
smallest possible slot of `v` in any feasible schedule.

**Proof.**  
Induction over a topological order.
*Base*: source vertices have no predecessors, `L = 1`, clearly minimal.  
*Step*: assume true for all predecessors `p`. Any schedule must place `v`
after all `p`, i.e. at least `max(L[p]) + 1`. The algorithm sets exactly this
value, therefore it is attainable (by scheduling all predecessors at
their earliest slots) and minimal. ∎



##### Lemma 2  
For every job `v` the value `R[v]` computed by the backward pass equals the
largest possible slot of `v` in any feasible schedule.

**Proof.**  
Induction over the reverse topological order.
*Base*: sink vertices have no successors, `R = T`, obviously maximal.  
*Step*: assume true for all successors `s`. To keep a successor `s`
feasible we need `slot(v) ≤ slot(s) - 1`. The tightest restriction is
`min_s (R[s] - 1)`. The algorithm sets exactly this minimum, therefore no
schedule can place `v` later, and a schedule exists that puts `v` at that
slot (place all successors at their latest slots). ∎



##### Lemma 3  
If after the interval computation some job has `L[v] > R[v]`,
no feasible schedule exists.

**Proof.** Directly from Lemma&nbsp;1 and Lemma&nbsp;2: any schedule must put
`v` in `[L[v], R[v]]`, which is empty. ∎



##### Lemma 4  
During the greedy scheduling loop, when a job `i` is taken from the heap at
slot `t`, its deadline satisfies `R[i] ≥ t`. If the algorithm ever extracts a
job with `R[i] < t` it correctly reports impossibility.

**Proof.** All jobs inserted into the heap have release time `≤ t`. The heap
orders by increasing deadline, so the extracted job has the smallest deadline
among all currently available jobs. If that smallest deadline is already
smaller than the current slot, every available job misses its deadline,
hence no schedule can finish the remaining jobs – the algorithm is correct
to answer `NO`. ∎



##### Lemma 5  
If the greedy algorithm finishes assigning all jobs, the obtained assignment
satisfies all precedence constraints and the per‑slot capacity.

**Proof.**  
*Capacity*: at each slot we assign at most `M` jobs by construction.  
*Precedence*: a job is inserted into the heap only at its release time
`L[i]`. By Lemma&nbsp;1, any predecessor finishes no later than `L[i]-1`,
therefore strictly before the slot where `i` is finally assigned. ∎



##### Lemma 6  
If a feasible schedule exists, the greedy algorithm never fails (i.e. never
extracts a job with deadline `< current slot` and ends with all jobs assigned).

**Proof.** Consider any feasible schedule `S`. Transform `S` step by step
to follow the greedy choices without breaking feasibility:

Process slots `t = 1 … T`.  
Assume that up to slot `t-1` both schedules have placed the same set of jobs.
At slot `t` let `G` be the set of jobs that are released (`L ≤ t`) and not yet
scheduled. Greedy picks the job `g` with the smallest deadline among `G`.
If `S` also schedules `g` at `t` we are done. Otherwise `S` schedules some
different job `x ∈ G` (its deadline is ≥ deadline of `g`). Since `g` is ready,
we can swap `g` and `x` in `S`: put `g` at `t` and move `x` to the later slot
where `g` originally was (or any later free slot, which exists because `S`
has enough capacity). The swap keeps all deadlines satisfied and does not
violate precedences (both jobs are already released). Repeating this exchange
for every slot yields a feasible schedule that coincides with the greedy one.
Consequently the greedy algorithm never encounters a job whose deadline is
already missed, and it will assign all jobs. ∎



##### Lemma 7  
If the greedy algorithm reports `NO`, no feasible schedule exists.

**Proof.** Two possible reasons:

1. A job is extracted with `R < current slot`. By Lemma&nbsp;4 all still
   unscheduled jobs miss their deadlines, so any schedule would violate a
   deadline – impossible.

2. After processing all slots some jobs remain unassigned. All those jobs
   have release time `≤ T` (otherwise they would never have been inserted).
   Since every slot already used its full capacity `M`, the total number of
   jobs exceeds `M·T`, contradicting the necessary condition for any schedule.
   Hence no schedule exists. ∎



##### Theorem  
The program outputs  

*`YES` and a valid assignment* **iff** there exists a schedule that respects
all precedences, the station limit `M`, and the deadline `T`.

**Proof.**  

*If part*:  
Assume a feasible schedule exists.
Lemmas&nbsp;1–3 give valid intervals, Lemma&nbsp;6 guarantees the greedy
algorithm succeeds, Lemma&nbsp;5 shows the produced assignment is feasible.
Thus the program prints `YES` and a correct schedule.

*Only‑if part*:  
If the program prints `YES`, it must have succeeded in the greedy phase,
hence all jobs were assigned. By Lemma&nbsp;5 the assignment respects
precedences and capacity, and all slots are ≤ `T`. Therefore a feasible
schedule exists.

If the program prints `NO`, it either detected an empty interval
(Lemma&nbsp;3) or the greedy algorithm failed. In both cases Lemma&nbsp;7
shows that no feasible schedule exists. ∎

#### 5.   Reference Implementation  (Python 3)

```python
import sys
import heapq

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    M = int(next(it))
    T = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n + 1)]
    radj = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    for _ in range(m):
        a = int(next(it)); b = int(next(it))
        adj[a].append(b)
        radj[b].append(a)
        indeg[b] += 1

    # ---------- topological order & earliest ----------
    from collections import deque
    q = deque([i for i in range(1, n + 1) if indeg[i] == 0])
    topo = []
    L = [1] * (n + 1)          # earliest, 1‑based
    while q:
        v = q.popleft()
        topo.append(v)
        for w in adj[v]:
            if L[w] < L[v] + 1:
                L[w] = L[v] + 1
            indeg[w] -= 1
            if indeg[w] == 0:
                q.append(w)

    if len(topo) != n:        # cycle
        print("NO")
        return

    # ---------- latest ----------
    R = [T] * (n + 1)
    for v in reversed(topo):
        for w in adj[v]:
            if R[v] > R[w] - 1:
                R[v] = R[w] - 1

    for i in range(1, n + 1):
        if L[i] > R[i]:
            print("NO")
            return

    # ---------- greedy scheduling ----------
    start_at = [[] for _ in range(T + 2)]   # slots are 1..T
    for i in range(1, n + 1):
        start_at[L[i]].append(i)

    heap = []          # (deadline, job)
    assigned = [0] * (n + 1)

    for slot in range(1, T + 1):
        for job in start_at[slot]:
            heapq.heappush(heap, (R[job], job))
        for _ in range(M):
            if not heap:
                break
            deadline, job = heapq.heappop(heap)
            if deadline < slot:
                print("NO")
                return
            assigned[job] = slot

    if any(assigned[i] == 0 for i in range(1, n + 1)):
        print("NO")
        return

    # ---------- output ----------
    out = ["YES"]
    out.append(" ".join(str(assigned[i]) for i in range(1, n + 1)))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
