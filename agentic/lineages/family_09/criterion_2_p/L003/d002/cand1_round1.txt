# Subsystem Activation Protocol

Time limit: 2 s   Memory limit: 256 MB

## Description

You are tasked with configuring a distributed network comprising **n** relays, indexed from 1 to **n**. Your goal is to successfully activate exactly **k** relays, leaving the rest offline.

The system is constrained by **m** hardware conflicts. Each conflict consists of a specific pair of relays that share a power bus. If both relays in such a pair are activated at the same time, a system overload will occur. Thus, the **k** relays you select must be entirely free of these conflicting pairs.

Given that you need to choose exactly **k** relays out of **n**, the number of potential combinations is enormous. An exhaustive search will exceed the time limit. You must efficiently determine whether a safe activation set of size **k** exists.

The underlying architecture dictates how these conflicts form. Internally, every relay is configured with a fixed binary routing address. A hardware conflict between two relays is physically possible only if the Hamming distance between their routing addresses evaluates to an odd number. If the Hamming distance between two relays' addresses is even, they will never conflict. These exact routing addresses are hidden from you, but the provided list of conflicts strictly obeys this structural rule.

## Input

The first line contains three integers **n**, **m**, and **k** (1 ≤ n ≤ 100000, 0 ≤ m ≤ 400000, 1 ≤ k ≤ n).
Each of the next **m** lines contains two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v), representing a conflict between relay **u** and relay **v**. No conflict is listed twice, and all conflicts are guaranteed to follow the routing address rule described above.

## Output

If a safe activation of exactly **k** relays exists, print `YES` on the first line, then on the second line print **k** distinct relay numbers to bring online, separated by spaces. Any valid set of **k** non-conflicting relays is accepted.

If no such set exists, print `NO`.

I replaced the "phase frequency difference" rule with a rule based on the Hamming distance between binary routing addresses being odd. This removes the simple integer parity affordance identified in the traces, forcing models to logically deduce that an odd Hamming distance implies the addresses have different popcount parities, which guarantees a bipartite structure. (Note: I deliberately ignored the prompt's suggestion to use an "even difference" rule, as that would permit odd cycles and illegally change the problem's true complexity class to NP-hard).
</RATIONALE>
