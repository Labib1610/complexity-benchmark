**Solution Explanation**

For every vertex `v` look at all vertices that can be reached from `v` by a walk
with an **even** number of edges.
The statement guarantees that inside this set there is no edge.
Exactly this property characterises *bipartite* graphs:

* a graph is bipartite ⇔ its vertices can be coloured with two colours
  (`0` and `1`) such that every edge connects vertices of different colours;
* for a fixed vertex `v` all vertices having the same colour as `v`
  are reachable from `v` by an even‑length walk,
  vertices of the other colour by an odd‑length walk;
* vertices of the same colour are never adjacent.

So the given graph is bipartite.  
In each connected component we obtain two colour classes

```
C0 : vertices coloured 0
C1 : vertices coloured 1
```

Both `C0` and `C1` are independent sets, and there are **no edges between
different components**.  
From every component we have to choose **either** all vertices of `C0`
**or** all vertices of `C1`.  
The whole problem becomes:

```
For every component i we have two numbers
    a[i] = |C0| ,   b[i] = |C1|
Choose one number from each pair so that the total sum equals k.
```

That is a classic “two‑choice knapsack” (subset‑sum) problem.



--------------------------------------------------------------------

#### 1.   Computing the bipartition

Breadth‑first search (or DFS) colours each component.
During the search we store the two lists of vertices of the component
(`list0[i]`, `list1[i]`) and their sizes `a[i] , b[i]`.

Complexity: `O(n+m)`.



--------------------------------------------------------------------

#### 2.   Feasibility – bitset DP

`k ≤ n ≤ 100 000`, therefore a bitset of length `k+1` fits easily into a
Python integer (`int` has arbitrary length).

```
dp  – integer, bit s is 1  ⇔  sum s is reachable using already processed components
initially dp = 1   (only sum 0)
for each component i:
        dp = (dp << a[i]) | (dp << b[i])
```

After all components `dp` tells us whether `k` is reachable.

Complexity: `O(number_of_components * (k/word_size))`,
in practice far below the time limit.



--------------------------------------------------------------------

#### 3.   Reconstructing one solution

During the DP we store the intermediate bitsets in a list
`pref[0] … pref[t]` (`t = number of components`).

```
pref[0] = 1
for i = 1 … t:
        pref[i] = (pref[i-1] << a[i-1]) | (pref[i-1] << b[i-1])
```

`pref[i]` is the set of sums reachable after the first `i` components.
Memory consumption:

```
t ≤ n ≤ 100 000
each bitset ≤ k+1 ≤ 100 001 bits  →  about 12.5 KiB
total ≤ 1.3 GiB   (worst case)
```

The official limits are 256 MiB, therefore we must reduce the memory.
We keep the bitsets **only for every 64‑th component** (a checkpoint).
Between two checkpoints we recompute the needed bitsets on the fly;
the recomputation costs at most `64 * (k/word_size)` operations,
still easily fast enough.

Reconstruction algorithm

```
need = k
answer = empty list
i = t-1 … 0 (going backwards)
    # decide whether we took a[i] or b[i] in the optimal solution
    if need >= a[i] and bit (need-a[i]) is set in pref_before_i :
            take colour 0 of component i
            need -= a[i]
            add all vertices of list0[i] to answer
    else:
            take colour 1
            need -= b[i]
            add all vertices of list1[i] to answer
```

`pref_before_i` is the bitset of sums reachable **before** component `i`.
It is obtained either from a stored checkpoint or by recomputing from the
nearest earlier checkpoint.

The loop finishes with `need = 0` and `|answer| = k`.



--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints “YES” and a correct set iff such a set
exists.

---

##### Lemma 1  
The input graph is bipartite.

**Proof.**  
The statement of the problem is exactly the definition of a bipartite
graph (no edge inside the set of vertices reachable by an even walk from a
fixed vertex). ∎



##### Lemma 2  
For every connected component `i` the two colour classes `C0[i]` and `C1[i]`
are independent sets, and any independent set of the whole graph contains
either a subset of `C0[i]` **or** a subset of `C1[i]`, never vertices from
both colour classes of the same component.

**Proof.**  
Inside a component all edges go between the two colour classes, therefore
each class is independent.
If an independent set contained vertices of both colours of the same
component, those two vertices would be adjacent – contradiction. ∎



##### Lemma 3  
A set of exactly `k` vertices satisfying the condition exists  
iff there is a choice, for every component `i`, of either `a[i]` or `b[i]`
such that the sum of the chosen numbers equals `k`.

**Proof.**  
*If* such a choice exists, take for each component the whole colour class
that corresponds to the chosen number; by Lemma&nbsp;2 the union is an
independent set of size `k`.

*Only‑if*: let `S` be a feasible independent set of size `k`.  
By Lemma&nbsp;2, for each component `i` the intersection `S ∩ component i`
lies completely inside one colour class, therefore its size is either
`a[i]` or `b[i]`. Summation over all components gives `k`. ∎



##### Lemma 4  
After processing the first `p` components the bitset `pref[p]`
has exactly the sums that can be obtained by a valid choice for those
`p` components.

**Proof.** By induction over `p`.  
`p = 0` : only sum `0` is possible, `pref[0] = 1`.  
Induction step: assume the statement for `p`.  
For component `p` we may add `a[p]` **or** `b[p]`.  
Shifting `pref[p]` left by `a[p]` (resp. `b[p]`) marks precisely the sums
that arise from adding that value. The bitwise OR of the two shifted
bitsets therefore marks exactly all sums reachable after component `p`. ∎



##### Lemma 5  
During the backward reconstruction the test  

```
need >= a[i]  and  (need-a[i]) ∈ pref_before_i
```

is true exactly when there exists a feasible overall solution that
chooses colour 0 for component `i`.

**Proof.**  
`pref_before_i` contains all sums achievable by the first `i` components.
If `need-a[i]` belongs to it, we can realise the sum `need-a[i]` before
component `i`; adding `a[i]` (i.e. taking colour 0) yields `need`.  
Conversely, if a global solution uses colour 0 for component `i`,
the partial sum before `i` must be `need-a[i]`, which therefore belongs to
`pref_before_i`. ∎



##### Lemma 6  
The reconstruction algorithm produces a set of exactly `k` vertices that
is independent.

**Proof.**  
We start with `need = k`.  
At step `i` we choose a colour according to Lemma&nbsp;5, which guarantees
that a feasible solution for the remaining components still exists.
We subtract the size of the chosen colour, therefore after processing all
components `need` becomes `0`.  
The collected vertices are exactly the whole colour class chosen for each
component, hence by Lemma&nbsp;2 they form an independent set.
Its size is the sum of the chosen class sizes, i.e. `k`. ∎



##### Lemma 7  
If the algorithm prints “NO”, no feasible set of size `k` exists.

**Proof.**  
“NO” is printed only when the final bitset `pref[t]` does **not** contain
bit `k`. By Lemma&nbsp;4 this means that no selection of colour classes of
all components yields total size `k`. By Lemma&nbsp;3 such a selection is
equivalent to a feasible independent set of size `k`. ∎



##### Theorem  
The program outputs

* “YES” and a correct set of `k` vertices **iff** such a set exists,
* otherwise “NO”.

**Proof.**  
*If* the program prints “YES”, Lemma&nbsp;6 guarantees that the printed
set is independent and has size `k`.  

*Only‑if*: when a feasible set exists, Lemma&nbsp;3 gives a suitable
choice of colour classes, therefore by Lemma&nbsp;4 bit `k` is set in the
final DP bitset and the program does not output “NO”. Consequently it
enters the reconstruction phase and, by Lemma&nbsp;6, outputs a correct
set. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Bipartition* : `O(n+m)` time, `O(n+m)` memory.  
*DP* (with checkpoints) : `O(t * k / 64)` time,  
`O(t/64 * k/8)` memory ≤ about **2 MiB**.  
*Reconstruction* : same order as DP.  

Overall well inside the limits (`n,m ≤ 4·10⁵`, `k ≤ 10⁵`).

#### 6.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it)); m = int(next(it)); k = int(next(it))
    g = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        g[u].append(v)
        g[v].append(u)

    colour = [-1] * n
    comps0 = []          # list of vertices of colour 0 per component
    comps1 = []          # list of vertices of colour 1 per component
    a = []               # sizes
    b = []

    for start in range(n):
        if colour[start] != -1:
            continue
        q = deque([start])
        colour[start] = 0
        cur0 = []
        cur1 = []
        while q:
            v = q.popleft()
            if colour[v] == 0:
                cur0.append(v)
            else:
                cur1.append(v)
            for to in g[v]:
                if colour[to] == -1:
                    colour[to] = colour[v] ^ 1
                    q.append(to)
        comps0.append(cur0)
        comps1.append(cur1)
        a.append(len(cur0))
        b.append(len(cur1))

    t = len(a)

    # ----- DP with checkpoints (every 64 components) -----
    STEP = 64
    checkpoints = []          # (index, bitset)
    dp = 1                    # only sum 0 reachable
    checkpoints.append((0, dp))
    for i in range(t):
        dp = (dp << a[i]) | (dp << b[i])
        if (i + 1) % STEP == 0:
            checkpoints.append((i + 1, dp))
    final_dp = dp

    if (final_dp >> k) & 1 == 0:
        print("NO")
        return

    # function to obtain pref bitset before component idx (0‑based)
    # recompute from nearest earlier checkpoint
    def pref_before(idx: int) -> int:
        # find checkpoint with index <= idx
        cp_idx = (idx // STEP) * STEP
        # locate stored bitset
        for j in range(len(checkpoints)-1, -1, -1):
            if checkpoints[j][0] == cp_idx:
                base = checkpoints[j][1]
                break
        else:
            base = 1  # should not happen
        # recompute forward from cp_idx to idx
        for i in range(cp_idx, idx):
            base = (base << a[i]) | (base << b[i])
        return base

    need = k
    answer = []
    # walk backwards
    for i in range(t - 1, -1, -1):
        pref = pref_before(i)          # sums reachable before component i
        take0 = False
        if need >= a[i] and ((pref >> (need - a[i])) & 1):
            take0 = True
        if take0:
            answer.extend(v + 1 for v in comps0[i])
            need -= a[i]
        else:
            answer.extend(v + 1 for v in comps1[i])
            need -= b[i]

    # need must be zero now
    print("YES")
    print(' '.join(map(str, answer[:k])))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
