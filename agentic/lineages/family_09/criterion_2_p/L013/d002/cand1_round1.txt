<STATEMENT>
# Problem B — Component Activation

Time limit: 2 s
Memory limit: 256 MB

## Description

You are in charge of bringing a distributed sensor array online. The array contains **n** modules, indexed from 1 to **n**. The system requires exactly **k** modules to be powered on to reach its operational threshold.

Some modules cannot be active at the same time due to destructive resonance. You have a diagnostic report detailing **m** pairs of modules that will resonate destructively if both are powered on. An acceptable configuration must strictly avoid activating any two modules that appear together in this report.

The modules were engineered to run on various integer frequency bands, which are hidden from you. Destructive resonance pairs may have arbitrary integer frequency differences, with no parity guarantee. However, the system's physical constraints guarantee that destructive resonance is only possible between two modules if one module's hidden internal temperature offset is strictly positive and the other's is strictly negative.

Because **n** can be as large as 100,000, the number of ways to choose **k** modules is astronomically large (upwards of $10^{5000}$). Exhaustive search is completely unfeasible. You must establish whether a safe configuration of exactly **k** modules exists and, if so, identify one.

## Input

The first line contains three integers **n**, **m**, and **k** (1 ≤ n ≤ 100000, 0 ≤ m ≤ 400000, 1 ≤ k ≤ n), representing the number of modules, the number of resonance links, and the target number of modules to power on.

Each of the following **m** lines provides two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v), meaning that module **u** and module **v** will resonate destructively. No pair is repeated. The resonance links strictly follow the temperature offset rule described above.

## Output

If a safe configuration of exactly **k** modules is possible, print `YES` on the first line. On the second line, print **k** distinct integers separated by spaces, denoting the modules to power on. If multiple such configurations exist, you may output any single one.

If no such configuration is possible, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 2
1 3
1 4
2 3
2 4
```

**Output**
```
YES
1 2
```

### Example 2

**Input**
```
5 0 5
```

**Output**
```
YES
1 2 3 4 5
```

### Example 3

**Input**
```
4 4 3
1 3
1 4
2 3
2 4
```

**Output**
```
NO
```
</STATEMENT>
<RATIONALE>
The previous version used the parity of frequency differences (odd integer difference) to guarantee the conflict graph was bipartite, which models easily pattern-matched to 2-coloring. I explicitly neutralized this shortcut by stating that frequency differences have no parity guarantee, and instead introduced a hidden temperature offset rule (one strictly positive, one strictly negative). This forces models to deduce that the positive/negative constraint inherently partitions the graph into two independent sets.
</RATIONALE>
<PRESERVED_ANSWER>
The structural constraints on the input graphs remain identical (they are always bipartite), so the valid independent sets of size k for any given input are exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The positive and negative temperature offsets enforce that edges can only exist between two disjoint sets, preserving the guarantee that the input is a bipartite graph and thus the problem remains solvable in polynomial time via Maximum Independent Set on bipartite graphs.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the explicit denial of the parity guarantee as a statement that the graph can be general, ignoring the subsequent temperature offset constraint, though a careful reading resolves this.
</RISK>
