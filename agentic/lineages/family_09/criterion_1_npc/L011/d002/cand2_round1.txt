# Problem A — Panel Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

A social platform maintains **n** member profiles (numbered 1 to **n**). Over time, the platform has logged **m** bilateral interaction events. Each event involves exactly two distinct members.

A research study aims to designate exactly **k** members to form a focus panel, while the unselected members form a control group. To guarantee independent perspectives, the panel must be formed under the following restriction:
- No two members who share a logged interaction event can both be selected for the focus panel.

Determine whether it is possible to successfully form a valid focus panel of exactly **k** members, and if so, report the members assigned to the panel.

## Input

The first line provides three integers: **n**, **m**, and **k**. The platform's legacy database allocates exactly 46 memory slots for member profiles, restricting the total member count **n** to a positive integer up to this slot capacity. The interaction log count **m** ranges from zero up to the theoretical maximum where every distinct pair of members has interacted exactly once. The requested panel size **k** requires at least one participant and cannot exceed the total member count **n**.

Each of the following **m** lines contains two integers **u** and **v**. These represent the distinct member numbers (from 1 to **n**) involved in a bilateral interaction event. The log never lists the same interaction event more than once.

## Output

If a valid focus panel of **k** members can be successfully formed, print `YES` on the first line. On the second line, print the **k** distinct member numbers that make up the panel, separated by spaces. If multiple valid panels exist, any one is accepted.

If no such panel can be formed, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

<RATIONALE>
Changed the constraint wording from a 2-SAT-like clause ("at least one... must be assigned to the control group") to an exclusion clause ("No two members... can both be selected"), removing a known pattern-matching affordance. Additionally, stated the variable bounds indirectly via a database slot limit and theoretical pair maximums, forcing the model to parse constraints from the scenario rather than relying on explicit inequality strings.
</RATIONALE>

The answers are identical because the exclusion clause logically requires exactly the same assignments as the original control group requirement, preserving the valid sets of members.
