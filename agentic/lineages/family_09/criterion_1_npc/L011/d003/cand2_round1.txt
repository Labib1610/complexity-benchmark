<STATEMENT>
# Problem A — Panel Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

A social network tracks **n** member profiles, identified by numbers from 1 to **n**. The system has recorded **m** bilateral interaction events, each representing an exchange between two distinct members.

For auditing purposes, an event allocation assigns each of the **m** interaction events to exactly one of the two members involved in it. This chosen member is designated as the primary respondent for that specific event. A single member may be designated as the primary respondent for any number of events, provided they were a participant in each of them.

A research initiative requires selecting exactly **k** distinct members to form a focus panel. A selection of **k** members is considered valid if and only if there exists at least one event allocation for all **m** events such that absolutely zero events are assigned to any member of the focus panel.

Your objective is to evaluate whether it is possible to choose a valid focus panel of exactly **k** members. If such a panel can be formed, you must also provide a list of its members.

## Input

The first line provides three integers **n**, **m**, and **k** (1 ≤ n ≤ 46, 0 ≤ m ≤ n·(n−1)/2, 1 ≤ k ≤ n).
Following this are **m** lines, each containing two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v). These indicate an interaction event between member **u** and member **v**. Each interaction event is listed at most once.

## Output

If a valid focus panel of exactly **k** members can be formed, output `YES` on the first line. On the next line, output the **k** distinct member numbers that constitute the panel, separated by spaces. Any valid panel will be accepted if more than one exists.

If forming such a panel is impossible, output `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```
</STATEMENT>
<RATIONALE>
The seed problem explicitly stated that the unselected members must "include at least one participant from every single recorded interaction event", which models trivially mapped to Vertex Cover and its dual, Independent Set. I removed this direct structural cue by introducing an "event allocation" framing, where each event must be assigned to one of its participants. The requirement is now an existential condition: there must exist an assignment where panel members are assigned zero events. This masks the Independent Set constraint behind what appears to be a bipartite matching or network flow problem, forcing the model to deduce that such an assignment exists if and only if no two panel members share an event.
</RATIONALE>
<PRESERVED_ANSWER>
An event allocation that assigns zero events to the focus panel exists if and only if every event has at least one participant outside the panel (who can then take the assignment), which is exactly the Independent Set condition from the seed problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the NP-complete Independent Set problem, simply presented through an equivalent logical condition on the edges.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "event allocation" as a requirement to output the actual assignment of events, though the Output section explicitly only asks for the focus panel members.
</RISK>
