# Problem A — Secure Audit Scheduling

Time limit: 5 s   Memory limit: 256 MB

## Description

A financial institution maintains **n** accounts, numbered 1 through **n**. An auditing team is tasked with isolating exactly **k** distinct accounts for a comprehensive daily review.

The accounts are linked by **m** bilateral reconciliation channels. Each channel establishes a continuous data sync between a specific pair of accounts. During the review process, a strict isolation protocol must be enforced to avoid data corruption: for any given reconciliation channel, at least one of its two linked accounts must remain outside the review. If both accounts linked by a channel are simultaneously isolated for the review, the system will enter a deadlock state.

The evaluation data includes configurations specifically designed with densely interlocking channel structures. These arrangements maximize the number of partial account groupings that appear to follow the isolation protocol but ultimately cannot reach the required size **k**. To process these dense structures within the time limits, your approach must actively bound the search space and evaluate structural limits, as unguided sequential generation of valid subsets will be insufficient.

Given the total accounts and the layout of the reconciliation channels, determine if exactly **k** accounts can be safely isolated. If such an arrangement is possible, output one valid grouping.

## Input

The first line of the input contains three integers **n**, **m**, and **k** (1 ≤ **n** ≤ 46, 0 ≤ **m** ≤ **n**·(**n**−1)/2, 1 ≤ **k** ≤ **n**).
The next **m** lines each provide two integers **u** and **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), identifying the two accounts linked by a reconciliation channel.
The order of the two accounts on a line is irrelevant, and no pair of accounts is given more than once.

## Output

If a safe review of exactly **k** accounts is possible, output `YES` on the first line. On the second line, output **k** distinct integers representing the selected accounts, separated by spaces. If multiple valid groupings exist, any one is acceptable.

If no valid grouping can be formed, output `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```
