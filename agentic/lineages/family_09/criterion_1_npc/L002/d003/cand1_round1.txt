# Problem A — Data Center Workload Allocation

Time limit: 5 s   Memory limit: 256 MB

## Description

You are configuring a data center. The facility occupies a single room with 46 physical server bays. The number of deployed servers, **n**, is a positive integer that fits within these bays. The servers are identified by integers 1 through **n**.

Your objective is to designate a target headcount of **k** servers to run a new high-intensity workload. This target **k** must be at least one server, up to the entire deployed fleet of **n** servers.

The facility's cooling infrastructure includes **m** specialized liquid-cooling loops. The number of cooling loops, **m**, is a non-negative integer. Since each loop connects a unique pair of servers, the maximum number of loops is simply the number of possible server pairs. Each loop plumbs exactly two distinct servers together.

Each cooling loop can safely dissipate a maximum of 100 kilowatts (kW) of excess heat. A server running in standard mode injects 0 kW of excess heat into the loop. A server designated for the high-intensity workload injects exactly 100 kW of excess heat into *each* individual cooling loop it is connected to. 

If the combined excess heat from the two servers connected to a single cooling loop strictly exceeds the loop's 100 kW capacity, the loop will boil and fail.

You must determine whether it is possible to select exactly **k** servers for the high-intensity workload such that no cooling loop fails. Given the layout of the cooling loops, find a valid set of **k** servers, or determine that no such set exists.

## Input

The first line provides three integers: **n**, **m**, and **k**. The values respect the physical bounds described above.
The following **m** lines each contain two integers **u** and **v**, representing a cooling loop connecting server **u** and server **v**.

## Output

If it is possible to safely allocate the workload to exactly **k** servers, output `YES` on the first line. On the second line, output the **k** distinct server identifiers that should be selected, separated by spaces. If multiple valid configurations exist, any one is acceptable.

If no safe allocation of exactly **k** servers is possible, output `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

```

```

```

```

<RATIONALE>
The previous wording allowed models to directly pattern-match the constraint "designated servers must not exceed standard servers on the edge" as an Independent Set condition. I reframed the constraint into a physical capacity limit (100 kW max, where each active server injects 100 kW). This forces the model to read the physical rules and deduce that two active servers on the same loop will exceed the limit (200 kW > 100 kW), while one active server is safe (100 kW), which mathematically reduces to an Independent Set. Furthermore, I applied Strategy S07 (Indirect Bounds) to express all numeric limits through the physical constraints of the data center rather than explicit inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that a loop fails if its excess heat strictly exceeds 100 kW means it fails if and only if both of its connected servers are designated for the high-intensity workload (100 kW + 100 kW = 200 kW > 100 kW). This perfectly maintains the original requirement that no two connected servers can both be selected.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the Independent Set problem (finding a set of k vertices such that no two are adjacent), which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "strictly exceeds" and assume 100 kW is already a failure, though "strictly exceeds 100 kW" mathematically guarantees 100 kW is safe.
</RISK>
