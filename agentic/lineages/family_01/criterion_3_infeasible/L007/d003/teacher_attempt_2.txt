# Acoustic Resonance

Time limit: 2 s   Memory limit: 256 MB

An acoustic testing chamber evaluates a set of tuning forks. During testing, specific pairs of forks were found to produce a harsh interference pattern when struck together. 

The engineers need to identify a destructive triad to calibrate the dampening fields. A triad is formed by evaluating a group of three distinct tuning forks; it is considered destructive if every possible pair chosen from within this group produces the harsh interference pattern.

The testing chamber requires a minimum of three tuning forks to run a valid test, up to a strict physical capacity of two thousand forks. The data logging system will always capture at least three interference events, up to a maximum storage limit of two hundred thousand events (or the total possible number of distinct pairs for the given forks, whichever is smaller). It is guaranteed that at least one destructive triad is present in the test data. You must process the records to find it.

## Input
The first line contains two integers $n$ and $m$, representing the number of tuning forks and the number of interference records, respectively. Their minimum and maximum values adhere exactly to the chamber capacity and storage limits described above.
Each of the next $m$ lines contains two integers $u$ and $v$, indicating that fork $u$ and fork $v$ produce a harsh interference pattern. 
It is guaranteed that at least one destructive triad exists.

## Output
Print three integers on one line, ordered from lowest to highest, representing the identifiers of the forks in the destructive triad. 
If multiple such groups exist, output the one whose lowest identifier is as small as possible; if there is a tie, minimize the middle identifier; and if still tied, minimize the highest identifier.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
Replaced the explicit algorithmic definition of a triad (involving $a < b < c$ and their direct pairwise connections) with a purely set-based description ("every possible pair chosen from within this group"). The bounds were moved out of the input section and stated indirectly as physical capacities and storage limits, forcing the model to read and comprehend the scenario text rather than pattern-matching the constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The condition "every possible pair chosen from within this group" is logically identical to checking the three edges $(a,b), (b,c), (a,c)$, and the explicit tie-breaking rules strictly enforce the original lexicographical requirement.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core task remains finding three mutually interacting items, which is exactly the Triangle Finding problem, maintaining the original computational complexity and feasibility constraints.
</PRESERVED_CLASS>
<RISK>
Models might theoretically struggle to reconstruct the exact formula $n(n-1)/2$ from "total possible number of distinct pairs", but this is a standard combinatorial concept and should not be ambiguous to a competent reader.
</RISK>
