# Problem C — Fatal Configuration

Time limit: 2 s
Memory limit: 256 MB

A complex system contains $n$ modules. During stress testing, specific two-module combinations were flagged as incompatible when operated simultaneously. 

The system administrator needs to isolate a fatal configuration to diagnose a persistent crash. A fatal configuration is a set of exactly three distinct modules $a$, $b$, and $c$ such that the logs contain an incompatibility record between $a$ and $b$, a record between $b$ and $c$, and a record between $a$ and $c$. 

You must process the logs to find a fatal configuration. The system is known to be flawed, so it is guaranteed that at least one such set of three modules exists.

## Input
The first line contains two integers $n$ and $m$. The number of modules $n$ is bounded by a minimum operational requirement of $3$ and a maximum chassis capacity of $2000$. The number of recorded conflicts $m$ is at least $3$, and is limited by the system memory to at most $200000$, or the theoretical maximum of $n(n-1)/2$ unique pairs, whichever is smaller.

Each of the next $m$ lines contains two distinct integers $u$ and $v$, indicating that module $u$ and module $v$ are incompatible. Each unordered pair of modules is recorded at most once in the logs.
It is guaranteed that at least one fatal configuration exists.

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$, representing the IDs of the modules in a fatal configuration. 
If multiple fatal configurations exist, output the one with the smallest value for $a$; if there is a tie, choose the one with the smallest value for $b$; and if still tied, the smallest value for $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
