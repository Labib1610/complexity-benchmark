# Problem C — Fatal Configuration

Time limit: 2 s   Memory limit: 256 MB

A complex system contains $n$ modules. The system architecture mandates a minimum of 3 modules, while the physical chassis capacity strictly limits the total to 2000. During stress testing, $m$ specific combinations of two modules were flagged as interfering with each other when operated simultaneously. The diagnostic log must contain a minimum of 3 flagged entries. Due to storage limits, the log records at most 200,000 entries, or the total number of possible distinct module pairs for the given $n$, whichever is strictly smaller.

The system administrator needs to isolate a fatal configuration. To do this, you must select exactly three distinct modules from the $n$ available. A selection of three distinct modules forms a fatal configuration if the logs demonstrate that none of the three can operate with any other module in the selection. In other words, each module in the chosen trio must have a recorded interference with the remaining two modules of that trio.

You must search this space to find a fatal selection.

## Input
The first line contains two integers $n$ and $m$, representing the module count and the number of log entries, respectively.
Each of the next $m$ lines contains two integers $u$ and $v$, indicating that module $u$ and module $v$ interfere with each other. 
It is guaranteed that at least one fatal selection of three modules exists.

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$ such that the pairs $\{a, b\}$, $\{a, c\}$, and $\{b, c\}$ are all listed as interfering in the input. 
If multiple fatal selections exist, output the one with the smallest value for $a$; if there is a tie, choose the one with the smallest value for $b$; and if still tied, the smallest value for $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
