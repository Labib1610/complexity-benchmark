**Solution Explanation**

For every unordered pair `{u,v}` we are given that the two frequency bands interfere.
A *tri‑resonance* is a set `{a,b,c}` of three different bands such that all three
pairs `{a,b}`, `{a,c}`, `{b,c}` are present – i.e. a triangle in the undirected graph.

The task is to output the lexicographically smallest triangle
(`a < b < c`, minimal `a`, then minimal `b`, then minimal `c`).
It is guaranteed that at least one triangle exists.



--------------------------------------------------------------------

#### 1.   Data structure – bitset per vertex  

`n ≤ 2000`, therefore a vertex can be represented by a bitset of length `n`.
In Python an arbitrary length integer works as a bitset:

```
mask[v]  – integer whose i‑th bit (1‑based) is 1  ⇔  edge (v,i) exists
```

Construction is `O(m)`.

--------------------------------------------------------------------

#### 2.   Searching triangles in lexicographic order  

We iterate `a` from `1` to `n`.
For a fixed `a` we iterate `b` from `a+1` to `n` **only if the edge (a,b) exists**.
All possible `c` that close a triangle with `{a,b}` are exactly the vertices that are
neighbors of both `a` and `b` :

```
common = mask[a] & mask[b]          # vertices adjacent to both a and b
```

We still have to respect the ordering `c > b`.  
All bits `≤ b` are cleared by a mask:

```
higher = ((1 << (n+1)) - (1 << (b+1)))   # bits b+1 … n are 1
candidates = common & higher
```

If `candidates` is non‑zero, the smallest `c` is the index of the least significant
set bit. In Python:

```
c = (candidates & -candidates).bit_length()   # position of lowest 1‑bit
```

The first triple found during the described loops is exactly the required
lexicographically smallest triangle, because we increase `a` first, then `b`,
and finally pick the smallest possible `c`.

The total work:

* outer loop over `a` – `n` iterations,
* inner loop over `b` – only over existing edges, i.e. `O(m)`,
* each iteration does a constant‑time integer `&` and a few bit operations.

With `n ≤ 2000` and `m ≤ 2·10⁵` this easily fits into the limits.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triangle.

---

##### Lemma 1  
For any pair of vertices `a < b`, the set `candidates` computed by the algorithm
contains exactly the vertices `c` such that `{a,b,c}` is a triangle and `c > b`.

**Proof.**  
`common = mask[a] & mask[b]` contains precisely the vertices adjacent to both `a`
and `b`. Intersecting with `higher` removes all vertices `≤ b`. Hence `candidates`
contains exactly those vertices adjacent to both `a` and `b` and larger than `b`. ∎



##### Lemma 2  
If `candidates` is non‑empty, the algorithm chooses the smallest possible `c`.

**Proof.**  
`candidates & -candidates` isolates the lowest set bit. Its position (obtained by
`.bit_length()`) is the smallest index present in `candidates`. ∎



##### Lemma 3  
When the algorithm outputs a triple `(a,b,c)`, it is a triangle.

**Proof.**  
The algorithm reaches the output only if edge `(a,b)` exists (checked before the
inner loop) and `candidates` is non‑empty. By Lemma&nbsp;1 any `c` in `candidates`
is adjacent to both `a` and `b`. Therefore all three edges are present. ∎



##### Lemma 4  
The first triple output by the algorithm is the lexicographically smallest
triangle in the graph.

**Proof.**  
The outer loop enumerates `a` in increasing order.
For a fixed `a`, the inner loop enumerates `b` in increasing order **among those
with edge (a,b)**.
For each such pair the algorithm, by Lemma&nbsp;2, picks the smallest feasible `c`.
Consequently, any triangle with a smaller `a` would have been examined earlier.
If two triangles share the same `a` but have different `b`, the one with the
smaller `b` is examined first.
If they also share `b`, the algorithm chooses the smallest possible `c`.
Thus the first found triangle is exactly the lexicographically minimal one. ∎



##### Theorem  
The algorithm always terminates and prints the required answer.

**Proof.**  
The loops iterate over a finite set of vertices and edges, therefore terminate.
Because the input guarantees at least one triangle, there exists a pair `(a,b)`
for which `candidates` is non‑empty, so the algorithm will eventually output a
triple. By Lemma&nbsp;3 the output is a triangle, and by Lemma&nbsp;4 it is the
lexicographically smallest one. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building masks*: `O(m)` time, `O(n)` integers (≈ 2000 bits each) → `O(n)` memory.  

*Search*: each existing edge `(a,b)` is processed once.
For each edge we perform a constant‑time bitwise `&` and a few integer operations.
Hence time `O(m)`.  

Overall:

* **Time** `O(m)`  ( ≤ 2·10⁵ operations, well within 2 s )
* **Memory** `O(n)`  (≈ 2000·(2000/8) bytes ≈ 0.5 MB)

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # adjacency bitsets, 1‑based indexing, bit i corresponds to vertex i
    mask = [0] * (n + 1)
    edges = []          # store edges for iteration
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        mask[u] |= 1 << v
        mask[v] |= 1 << u
        if u < v:
            edges.append((u, v))
        else:
            edges.append((v, u))

    # pre‑compute a mask that has bits > b set, for each b
    # higher_mask[b] = bits (b+1 .. n) = ((1 << (n+1)) - (1 << (b+1)))
    higher_mask = [0] * (n + 1)
    full = (1 << (n + 1)) - 2   # bits 1..n set
    for b in range(1, n + 1):
        higher_mask[b] = full ^ ((1 << (b + 1)) - 2)   # clear bits <= b

    # search in lexicographic order
    for a in range(1, n + 1):
        # iterate b > a where edge exists
        # we can scan all b, but using mask speeds up a bit
        neigh = mask[a]
        b = a + 1
        while b <= n:
            if (neigh >> b) & 1:
                # edge (a,b) exists
                common = mask[a] & mask[b] & higher_mask[b]
                if common:
                    # smallest c = position of lowest set bit
                    low = common & -common
                    c = low.bit_length()
                    print(a, b, c)
                    return
            b += 1

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
