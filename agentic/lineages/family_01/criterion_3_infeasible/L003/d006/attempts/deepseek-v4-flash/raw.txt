We can solve this by checking all triples, but that would be too slow for \( n = 2000 \).  
Instead, we can use the fact that a valid triple exists and we want the lexicographically smallest one.

A triple \((a,b,c)\) is valid if each vertex is connected to the other two.  
That means the three vertices form a triangle in the graph.

We can iterate over the smallest vertex \( a \) from 1 to \( n \), then over the second smallest \( b > a \), and check if there is a common neighbor \( c > b \) that is connected to both \( a \) and \( b \).  
To do this efficiently, we can store adjacency as sets.

For each pair \((a,b)\) that are connected, we look for the smallest \( c > b \) that is in both adjacency sets of \( a \) and \( b \).  
If found, we output \((a,b,c)\) and stop.

Complexity:  
- We iterate over all edges \((a,b)\) — at most \( m \).  
- For each, we check intersection of two sets — can be done by iterating over the smaller set, which is at most \( n \).  
- Worst case \( O(m \cdot n) \) = \( 2 \cdot 10^5 \cdot 2000 = 4 \cdot 10^8 \) — might be borderline but often fine in Python with optimizations.

We can optimize by using bitsets (Python integers as bitmasks) for adjacency, then intersection is a bitwise AND, and finding the smallest set bit is fast.

Let's implement with bitmasks.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * (n + 1)
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if (adj[a] >> b) & 1:
                common = adj[a] & adj[b]
                # remove bits <= b
                common &= ~((1 << (b + 1)) - 1)
                if common:
                    c = (common & -common).bit_length() - 1
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
