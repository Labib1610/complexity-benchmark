We need to find a triangle (a triple of mutually connected nodes) in an undirected graph.

Because the graph has up to \(n = 2000\) nodes and \(m = 200000\) edges, even an \(O(n^3)\) brute-force is too heavy.  
We can use an adjacency set or bitset to check edges in \(O(1)\) via hash lookups.

The plan:
- Read the graph.
- Iterate over possible smallest vertex `a` from 1 to n.
- For each `a`, iterate `b` greater than `a` that is connected to `a`.
- For each such `b`, iterate `c` greater than `b` that is connected to `b`.
- Check if `(a, c)` is also an edge; if yes, that's our smallest triple because we iterate in sorted order.

To speed up and avoid scanning all nodes for inner loops unnecessarily, we can intersect neighbor sets, but here the constraint m ≤ 2e5 makes the above efficient enough.

Let’s implement with adjacency sets.

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)

    for a in range(1, n + 1):
        for b in adj[a]:
            if b <= a:
                continue
            for c in adj[b]:
                if c <= b:
                    continue
                if c in adj[a]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    solve()
```
