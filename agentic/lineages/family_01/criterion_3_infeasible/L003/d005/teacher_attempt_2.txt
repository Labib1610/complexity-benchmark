<STATEMENT>
# Planetary Core Assembly

Time limit: 2 s   Memory limit: 256 MB

A mechanical engineering team is evaluating $n$ distinct gear designs, labeled with integer IDs from 1 to $n$. Through extensive prototyping, they have confirmed $m$ specific meshing compatibilities, each indicating that two particular gears can run together continuously without jamming.

The testing facility has exactly 2000 testing bays, meaning the number of gear designs $n$ will never exceed this capacity. A minimum of 3 designs is required to initiate the project. The central database is allocated to store up to 200,000 compatibility records. The number of confirmed records $m$ is bounded by this storage limit, as well as by the total number of distinct pairs that can be formed from the $n$ available designs. At least 3 records are always present.

The engineers need to construct a "planetary core". The assembly procedure requires forming a trio of distinct gear designs. A trio is considered structurally sound if its components can be assembled sequentially: a base gear is placed, a secondary gear is added which has a confirmed compatibility with the base gear, and finally a tertiary gear completes the core, provided it has a confirmed compatibility with both previously placed gears.

Physical constraints guarantee that at least one valid planetary core can be constructed. Your task is to process the compatibility records and identify one such assembly.

## Input
The first line contains two integers $n$ and $m$. Their minimum and maximum possible values are dictated by the facility and database capacities described above.
Each of the next $m$ lines contains two integers $u$ and $v$ — a pair of gears that have a confirmed meshing compatibility.
It is guaranteed that at least one planetary core exists.

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$ representing the gears in the planetary core. Output the lexicographically smallest such set (smallest $a$; ties broken by smallest $b$; then smallest $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
The description of the three-component assembly was rewritten from a static requirement ("any two gears must be compatible") to a sequential one ("base, secondary compatible with base, tertiary compatible with both"). This removes the direct "pairwise-compatible trio" phrasing that triggers triangle-finding templates, forcing the model to deduce that the sequential dependencies form a 3-clique. Numeric bounds were also moved into the scenario text as physical limits (S07).
</RATIONALE>
<PRESERVED_ANSWER>
The sequential assembly conditions (first and second are compatible, third is compatible with both) identically demand that all three pairs among the chosen trio are compatible, leaving the set of valid outputs unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the detection of a 3-clique (triangle) in an undirected graph, maintaining the O(nm/64) bitset or O(m sqrt m) complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the sequential assembly as requiring a specific ordered output, but the output section explicitly asks for the set of gears sorted by ID, mitigating this risk.
</RISK>
