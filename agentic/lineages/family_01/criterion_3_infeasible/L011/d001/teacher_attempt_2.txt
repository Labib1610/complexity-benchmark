# Production Line Diagnostics

Time limit: 2 s   Memory limit: 256 MB

A manufacturing facility operates continuously using exactly two production lines. Certain pairs of manufacturing steps require a shared specialized calibration tool and therefore cannot be assigned to the same production line. The current batch of manufacturing steps cannot be distributed across the two lines without causing at least one tool collision.

Your diagnostic software must isolate a root cause of this allocation failure by identifying three distinct steps that form a closed dependency loop: the first step shares a tool with the second, the second shares a tool with the third, and the third shares a tool with the first. Such a trio forms an unresolvable bottleneck, as no two of these three steps can be placed on the same line.

To ensure deterministic logging, if multiple such unresolvable trios exist, the system must output the one whose step identifiers are sequentially lowest.

## Input
The first line contains two integers $n$ and $m$. The number of manufacturing steps $n$ is limited by the facility's maximum batch capacity of two thousand steps, and is always at least large enough to form the three-step bottleneck. Steps are numbered from $1$ to $n$. The number of tool collision pairs $m$ requires a minimum of three entries to run the diagnostic, and is capped by the system's logging limit of two hundred thousand pairs (or the maximum possible number of distinct pairs for $n$, whichever is smaller).

Each of the following $m$ lines contains two distinct integers $u$ and $v$ representing step numbers, indicating that step $u$ and step $v$ cannot be assigned to the same production line.
It is guaranteed that at least one such three-step bottleneck exists in the provided data.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, with $a < b < c$, representing the identifiers of the three steps forming the bottleneck. Output the combination that is sequentially lowest (the smallest possible value for $a$; in case of a tie, the smallest possible value for $b$; and finally the smallest possible value for $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

The description of the three steps was changed from a "set where every pair requires a shared tool" to a "closed dependency loop" of three steps. This forces the model to realize that a 3-step dependency loop in a symmetric relation is structurally identical to a mutually connected trio (a triangle/3-clique). Numeric bounds were additionally translated into narrative constraints (e.g., maximum batch capacity) to fulfill the S07 strategy.
</RATIONALE>
