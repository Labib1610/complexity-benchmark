<STATEMENT>
# Production Line Diagnostics

Time limit: 2 s   Memory limit: 256 MB

A manufacturing facility operates continuously using exactly two production lines. Certain pairs of manufacturing steps require a shared specialized calibration tool. A tool collision occurs if both steps of such a pair are assigned to the same production line. Currently, the entire batch of manufacturing steps cannot be distributed across the two lines without causing at least one tool collision.

Your diagnostic software must isolate a root cause of this allocation failure by identifying a group of exactly three steps that form an unresolvable bottleneck. 

A subset of exactly three steps $\{a, b, c\}$ is considered an unresolvable bottleneck if no valid configuration exists for them. A configuration assigns each of these three specific steps to either Line 1 or Line 2 (yielding exactly 8 possible configurations for the subset). A configuration is invalid if two steps assigned to the same line require a shared calibration tool. If all 8 configurations are invalid, the subset $\{a, b, c\}$ is an unresolvable bottleneck.

To ensure deterministic logging, if multiple such groups exist, the system must output the one whose step identifiers are sequentially lowest.

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2 \cdot 10^5)$), representing the total number of manufacturing steps and the number of tool collision pairs. Steps are numbered from $1$ to $n$.

Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), indicating that step $u$ and step $v$ require a shared calibration tool.

It is guaranteed that at least one unresolvable bottleneck of three steps exists in the provided data.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, with $a < b < c$, representing the identifiers of the three steps. Output the combination that is sequentially lowest (the smallest possible value for $a$; in case of a tie, the smallest possible value for $b$; and finally the smallest possible value for $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
I changed the definition of the bottleneck from 'no two steps are independent' to 'all 8 possible assignments of the three steps to two lines are invalid'. This removes the explicit pairwise connection (triangle) and presents it as a subset property. To pass within the 2-second time limit, models can no longer just translate the text into code; they must mathematically deduce that 'all 8 configurations fail' is exactly equivalent to 'all 3 pairs conflict' in order to prune their search or use bitsets, otherwise their O(N^3) simulation will TLE.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that all 8 assignments of a 3-step subset to 2 lines fail is logically equivalent to all 3 pairs within the subset conflicting, so the exact same combinations qualify as bottlenecks.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still reduces to finding a triangle (K3) in an unweighted graph, preserving its computational complexity class and the intended O(N*M/64) bitset algorithm.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret 'yielding exactly 8 possible configurations for the subset' as implying the configuration applies to the entire set of N steps, though the text explicitly says 'assigns each of these three specific steps'.
</RISK>
