<STATEMENT>
# Distributed Cluster Synchronization

Time limit: 2 s   Memory limit: 256 MB

A distributed computing cluster consists of multiple microservices. Certain pairs of microservices are connected by a bidirectional data synchronization channel.

Your task is to identify a "Critical Deadlock" in the cluster. A Critical Deadlock is a group of exactly three distinct microservices that exhibit a specific structural dependency, defined as follows.

Let $T$ be any group of exactly three distinct microservices. We can select a non-empty subset $A \subseteq T$ to form an "audit group". 
For any microservice $v$ in $T$ (regardless of whether $v$ is in $A$ or not), we define its *exposure* to the audit group as the number of distinct microservices in $A$ that share a synchronization channel with $v$. 
An audit group $A$ is considered *balanced* if the exposure of every microservice in $T$ is an even number (e.g., 0 or 2).

A group of three microservices $T$ forms a Critical Deadlock if and only if the **only** non-empty subset $A \subseteq T$ that is balanced is the entire group itself ($A = T$).

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2 \cdot 10^5)$), representing the total number of microservices and the number of synchronization channels. Microservices are numbered from $1$ to $n$.

Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), indicating that microservice $u$ and microservice $v$ share a bidirectional synchronization channel.

It is guaranteed that at least one Critical Deadlock exists in the provided data.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, with $a < b < c$, representing the identifiers of the three microservices that form a Critical Deadlock. If multiple such groups exist, output the combination that is sequentially lowest: the one with the smallest possible value for $a$; in case of a tie, the smallest possible value for $b$; and finally the smallest possible value for $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

I replaced the linear independence condition with an equivalent parity-based subset condition. Mathematically, this corresponds to finding a 3-vertex subgraph whose adjacency matrix over GF(2) has a null space containing only the all-ones vector and the zero vector. This property is uniquely satisfied by a triangle (3-clique). This forces the model to either deduce this non-obvious algebraic property or write a brute-force simulation that will exceed the time limit.
</RATIONALE>
<PRESERVED_ANSWER>
The parity condition is uniquely satisfied by a set of three mutually connected vertices (a triangle), which is exactly the same structural requirement as the original linear independence condition over the reals.
</PRESERVED_ANSWER>

The problem remains exactly the problem of finding a triangle (3-clique) in an undirected graph, keeping it in the same complexity class.
</PRESERVED_CLASS>
