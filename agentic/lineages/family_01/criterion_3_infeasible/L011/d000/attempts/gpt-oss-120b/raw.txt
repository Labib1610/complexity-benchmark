**Solution Explanation**

For every pair of steps we are given whether they *conflict* (cannot be placed on the same
production line).  
A set of three steps `{a,b,c}` is a *bad trio* iff all three pairs conflict,
i.e. the three vertices form a triangle in the undirected graph defined by the
conflict pairs.

The task is to output the lexicographically smallest triangle
(`a < b < c`, smallest possible `a`, then `b`, then `c`).

`n ≤ 2000`, therefore a vertex can be represented by a single bit inside a
Python integer (which can hold arbitrarily many bits).  
With a bit‑mask we can test adjacency and intersect neighbour sets in **O(1)**
time.



--------------------------------------------------------------------

#### Data structure

`adj[v]` – integer mask, bit `i‑1` (`i` from `1` to `n`) is `1` iff
there is an edge `v – i`.

Construction: for each input edge `u v`

```
adj[u] |= 1 << (v-1)
adj[v] |= 1 << (u-1)
```

--------------------------------------------------------------------

#### Finding the smallest triangle

All edges are stored as ordered pairs `(a,b)` with `a < b` and sorted
lexicographically.  
Processing them in this order guarantees that the first triangle we discover
has the smallest possible `a` and, for that `a`, the smallest possible `b`.

For a fixed edge `(a,b)` a vertex `c` completes a triangle iff it is adjacent
to **both** `a` and `b`.  
The set of such vertices is the intersection of the neighbour masks:

```
common = adj[a] & adj[b]
```

Only vertices with index larger than `b` are allowed (otherwise the ordering
`a < b < c` would be violated).  
We discard smaller indices by shifting the mask right by `b` positions:

```
cand = common >> b          # bit 0 now corresponds to vertex b+1
```

If `cand` is non‑zero, the least significant set bit gives the smallest possible
`c` for this `(a,b)` pair.

```
lsb = cand & -cand                     # isolate lowest set bit
offset = lsb.bit_length() - 1          # its index (0‑based)
c = b + offset + 1
```

Because edges are examined in increasing `(a,b)` order and we always pick the
lowest possible `c`, the first triangle we output is exactly the required
lexicographically smallest one.

The algorithm stops immediately after printing the answer.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triangle.

---

**Lemma 1**  
For a fixed edge `(a,b)` (`a<b`) the algorithm, if it finds a vertex `c`,
outputs the smallest `c` such that `{a,b,c}` is a triangle.

*Proof.*  
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to both `a`
and `b`. After shifting right by `b`, bit `k` of `cand` corresponds to vertex
`b+1+k`. The least significant set bit of `cand` therefore corresponds to the
minimum vertex index larger than `b` that belongs to `common`. ∎



**Lemma 2**  
If the algorithm outputs triangle `(a,b,c)`, then `{a,b,c}` is a triangle in the
graph.

*Proof.*  
`c` is obtained from `common = adj[a] & adj[b]`, hence `c` is adjacent to both
`a` and `b`. By construction `a<b<c`. The edge `a‑b` is the current processed
edge, therefore all three edges exist. ∎



**Lemma 3**  
Let `T* = (a*,b*,c*)` be the lexicographically smallest triangle of the graph.
When the algorithm processes edge `(a*,b*)` it will output `T*`.

*Proof.*  
All edges are sorted lexicographically, so every edge `(a,b)` with
`a<a*` or (`a=a*` and `b<b*`) is processed earlier. None of those edges can be
part of a triangle lexicographically smaller than `T*`, otherwise `T*` would not
be minimal. Hence none of them yields a triangle, and the algorithm continues.

When edge `(a*,b*)` is processed, `common` contains `c*` because `c*` is adjacent
to both `a*` and `b*`. By Lemma&nbsp;1 the algorithm selects the smallest such
`c`, which is exactly `c*` (any smaller `c` would give a triangle lexicographically
smaller than `T*`). Therefore the algorithm outputs `T*`. ∎



**Theorem**  
The algorithm prints the lexicographically smallest triple of vertices that
form a triangle.

*Proof.*  
By Lemma&nbsp;2 any printed triple is a triangle.  
By Lemma&nbsp;3 the first triangle printed is exactly the minimal one.
Since the algorithm stops after printing the first triangle, the output is the
required lexicographically smallest triangle. ∎



--------------------------------------------------------------------

#### Complexity Analysis

*Building masks*: `O(m)`  
*Sorting edges*: `O(m log m)` ( `m ≤ 2·10⁵` )  
*Processing edges*: each edge needs a constant‑time bit operation,
so `O(m)`.

Overall time: `O(m log m)` ≤ `O(2·10⁵ log 2·10⁵)` – well within the limit.  
Memory: `n` integer masks, each ≤ 2000 bits → negligible, plus the edge list:
`O(n + m)` integers → ≤ a few MB.

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    edges = []

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u > v:
            u, v = v, u
        edges.append((u, v))
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    edges.sort()                # lexicographic order

    for a, b in edges:
        common = adj[a] & adj[b]
        cand = common >> b       # keep only vertices > b
        if cand:
            lsb = cand & -cand
            offset = lsb.bit_length() - 1
            c = b + offset + 1
            # a < b < c holds automatically
            sys.stdout.write(f"{a} {b} {c}")
            return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
