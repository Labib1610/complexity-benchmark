 We need to find a triangle in the graph, and among all triangles, output the one with the smallest lexicographic order of its vertices.

A brute-force check of all triples would be O(n³), which is too slow for n up to 2000.  
We can instead iterate over each edge and check for a common neighbor, but we need to be careful about efficiency.

A common approach:  
- For each vertex `u` from 1 to n, check its neighbors in increasing order.  
- For each neighbor `v` (with `v > u`), check if there is a common neighbor `w` (with `w > v`) that is connected to both `u` and `v`.  
- The first such triple found in this order will be the lexicographically smallest.

We can use adjacency sets for O(1) neighbor checks.

Here’s the implementation:

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    adj[u].add(v)
    adj[v].add(u)

found = False
for u in range(1, n + 1):
    for v in sorted(adj[u]):
        if v > u:
            for w in sorted(adj[v]):
                if w > v and w in adj[u]:
                    print(u, v, w)
                    found = True
                    break
            if found:
                break
    if found:
        break
```
