# Facility Scheduling Diagnostics

Time limit: 2 s   Memory limit: 256 MB

A facility operates using exactly two concurrent execution environments. Certain pairs of tasks have mutual interference and cannot be executed in the same environment. The overall schedule cannot be distributed across the two environments without a critical allocation failure.

Your diagnostic software must isolate a root cause of this failure by identifying a bottleneck trio. A bottleneck trio consists of exactly three distinct tasks where, for any two tasks chosen from the trio, there is an interference record between them. Because all three tasks are mutually incompatible, they cannot be distributed across only two execution environments.

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2 \cdot 10^5)$), representing the total number of tasks and the number of interference records. Tasks are numbered from $1$ to $n$.

Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), indicating that an interference record exists between task $u$ and task $v$, meaning they cannot be assigned to the same environment.

It is guaranteed that at least one bottleneck trio exists in the provided data.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, with $a < b < c$, representing the identifiers of the three tasks in the bottleneck trio. Output the combination that is sequentially lowest (the smallest possible value for $a$; in case of a tie, the smallest possible value for $b$; and finally the smallest possible value for $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
