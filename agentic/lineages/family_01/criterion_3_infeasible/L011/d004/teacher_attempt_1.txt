<STATEMENT>
# Dual-Core Scheduling Conflict

Time limit: 2 s   Memory limit: 256 MB

A software system contains $n$ concurrent processes. You need to map these processes onto a dual-core processor (Core 0 and Core 1). Certain pairs of processes are resource-incompatible and cannot execute on the same core.

The system is currently failing to schedule because a complete separation into two cores is impossible. Diagnostics indicate this failure is driven by a "concurrency deadlock" involving a set of exactly three processes. Within such a set, assigning one of the processes to Core 0 forces another to Core 1 due to a resource incompatibility. This placement of the second process then forces the remaining third process to Core 0 due to another incompatibility. However, the schedule fails because this third process also has a recorded incompatibility with the first process, meaning they cannot both share Core 0.

Your task is to isolate a concurrency deadlock. If there are multiple such sets of three processes, you must isolate the one with the lowest hardware trace. For a deadlock consisting of process IDs $a, b,$ and $c$ (ordered so that $a < b < c$), the hardware trace is defined by the formula: $a \cdot 10^8 + b \cdot 10^4 + c$.

## Input
The first line of the input contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2 \cdot 10^5)$), representing the number of processes and the number of recorded resource incompatibilities. The processes are assigned integer IDs from $1$ to $n$.

Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), indicating that process $u$ and process $v$ are resource-incompatible. 

The provided records are guaranteed to contain at least one concurrency deadlock (a set of three processes exhibiting the failure chain described above).

## Output
Output a single line containing three space-separated integers $a$, $b$, and $c$ ($a < b < c$) representing the IDs of the three processes in the concurrency deadlock. You must output the set that yields the minimum hardware trace as described.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
The phrase explicitly stating that "each process is resource-incompatible with both of the other two" was removed, as it acted as a direct keyword trigger for identifying cliques/triangles. Instead, the mutual incompatibility is described mechanically as a chain of forced assignments that results in a contradiction, forcing models to deduce the underlying pairwise relationship structure themselves.
</RATIONALE>
<PRESERVED_ANSWER>
The chain of incompatibilities described (1 forces 2, 2 forces 3, 3 conflicts with 1) exactly defines a set of three mutually incompatible processes, meaning the target structure and tie-breaker logic are identical to the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a cycle of length 3 (a triangle) in an undirected graph, preserving the O(n*m/w) bitset intersection time complexity.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the "first", "second", and "third" process as implying that the set itself is ordered, but the tie-breaker rule explicitly clarifies that the IDs are sorted mathematically for the trace formula regardless of their conceptual position in the deadlock chain.
</RISK>
