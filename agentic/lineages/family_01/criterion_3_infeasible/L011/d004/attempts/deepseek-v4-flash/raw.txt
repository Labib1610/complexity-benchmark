 We need to find the lexicographically smallest triple of vertices that forms a triangle in the graph (i.e., a 3-clique).  

The problem states:  
- We have `n` steps and `m` edges representing pairs that cannot be on the same line.  
- A triple is a bottleneck if all 8 possible assignments of the 3 steps to 2 lines cause at least one collision.  
- That means every pair among the 3 must be an edge (i.e., they form a triangle).  

So we just need to find the smallest triple `(a, b, c)` with `a < b < c` such that edges `(a,b)`, `(a,c)`, and `(b,c)` all exist.  

We can do this efficiently:  
- For each `a` from 1 to n,  
  - For each `b > a` that is connected to `a`,  
    - For each `c > b` that is connected to both `a` and `b`,  
      - If found, print and exit.  

Since `n ≤ 2000`, an O(n³) check might be too slow in the worst case, but we can optimize using adjacency sets.  

We can iterate `a` and `b`, then check intersection of adjacency sets of `a` and `b` for a `c > b`.  

Here’s the implementation:  

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].add(v)
    adj[v].add(u)

for a in range(n):
    for b in range(a+1, n):
        if b in adj[a]:
            # find common neighbors > b
            common = adj[a] & adj[b]
            for c in sorted(common):
                if c > b:
                    print(a+1, b+1, c+1)
                    exit()
```
