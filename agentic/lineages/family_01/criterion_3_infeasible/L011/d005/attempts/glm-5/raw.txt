Looking at this problem, I need to find three steps where every pair requires a shared calibration tool (i.e., forms an edge in the input graph). This is finding a triangle in the graph, specifically the lexicographically smallest one.

**Approach:**
1. Build adjacency sets for each vertex
2. For each vertex `a` from 1 to n, for each neighbor `b` > a, check if any common neighbor `c` > b exists in both adjacency sets
3. The first such triangle found is the lexicographically smallest

**Optimization considerations:**
- With n up to 2000 and m up to 2·10^5, the naive O(n·m) approach could be slow in Python
- Using bitsets (Python integers) for adjacency representation makes intersection fast
- For each edge (a, b) with a < b, intersect adj[a] and adj[b], then find the lowest set bit that's > b

**Implementation:**
- Store adjacency as bitmasks (integers where bit i represents vertex i)
- For each edge (u, v) with u < v, compute intersection and find smallest vertex > v in the intersection
- Track the best (smallest) triangle found

The key insight: iterate edges in sorted order (by u, then v), and for each edge find the smallest valid third vertex. The first complete triangle found this way is the answer.

Let me verify with examples:
- Example 1: Edge (1,2), common neighbors include 3 → triangle (1,2,3) ✓
- Example 2: Edge (1,2), common neighbors include 4 → triangle (1,2,4) ✓

```python
import sys

def solve():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [0] * (n + 1)
    edges = []
    
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        adj[u] |= (1 << v)
        adj[v] |= (1 << u)
        if u < v:
            edges.append((u, v))
        else:
            edges.append((v, u))
    
    # Sort edges by (u, v)
    edges.sort()
    
    best = None
    
    for u, v in edges:
        # Find common neighbors > v
        common = adj[u] & adj[v]
        # Mask out vertices <= v
        mask = ~((1 << (v + 1)) - 1)
        common &= mask
        
        if common:
            # Find lowest set bit
            c = (common & -common).bit_length() - 1
            candidate = (u, v, c)
            if best is None or candidate < best:
                best = candidate
                # Since edges are sorted, first found is smallest (u,v)
                # But c might not be smallest possible for this (u,v)... 
                # Actually we want smallest c > v, which is what we found
                # And since we process edges in order, first triangle is answer
                print(f"{u} {v} {c}")
                return
    
    # Shouldn't reach here per problem statement
    if best:
        print(f"{best[0]} {best[1]} {best[2]}")

solve()
```

Let me double-check the bit manipulation:
- `1 << (v+1)` creates a bit at position v+1
- Subtracting 1 gives bits 0 through v set
- `~` inverts (but Python integers are arbitrary precision, so this needs care)

Actually, `~` in Python gives negative numbers due to infinite precision. Let me fix this:

```python
import sys

def solve():
    input_data = sys.stdin.buffer.read().split()

        if u < v:
            edges.append((u, v))
        else:
            edges.append((v, u))
    
    edges.sort()
    
    for u, v in edges:
        common = adj[u] & adj[v]
        # Keep only bits > v (positions v+1, v+2, ...)
        # Clear bits 0 through v
        common >>= (v + 1)
        
        if common:
            c = (common & -common).bit_length() - 1 + v + 1
            print(f"{u} {v} {c}")
            return

solve()
```

This is cleaner. Shifting right by v+1 removes bits 0 through v, then finding the lowest set bit and adding back v+1 gives us the actual vertex number.
