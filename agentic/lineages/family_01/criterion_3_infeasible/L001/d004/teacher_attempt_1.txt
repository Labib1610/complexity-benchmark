<STATEMENT>
# Problem C — Tri-Region Junction

Time limit: 2 s
Memory limit: 256 MB

A cartographer is analyzing a complex conceptual map divided into distinct territories. The mapping system requires a minimum of 3 territories to be defined in order to form any junctions, and its memory architecture caps the total number of distinct territories at exactly 2,000. 

The map's layout is documented by a list of boundary records. Each record indicates that two specific territories share a direct border. The archive storing these records must contain at least 3 entries. The maximum capacity of the archive is exactly 200,000 records, though the actual number of records will naturally never exceed the total number of unique pairs among the defined territories.

The cartographer needs to locate a "tri-junction" — a location where exactly three territories meet. According to the topological rules of this map, three distinct territories meet at a single point if and only if the records confirm that none of the three possible pairs among these three territories lacks a shared border.

You are provided with the complete list of boundary records. It is guaranteed that the map contains the necessary borders to form at least one tri-junction. Your task is to identify the three territories that meet at this junction.

## Input
The first line contains two integers $n$ and $m$, representing the number of territories and the number of boundary records, respectively. Territories are assigned ID numbers from $1$ to $n$.

Each of the following $m$ lines contains two distinct integers $u$ and $v$ representing valid territory IDs, indicating that territory $u$ and territory $v$ share a border.

It is guaranteed that at least one tri-junction can be identified.

## Output
Output a single line containing three space-separated integers $a$, $b$, and $c$, which are the ID numbers of the three territories meeting at the junction. These IDs must be arranged in strictly ascending order ($a < b < c$).

If there is more than one valid tri-junction, select the one that is lexicographically earliest (that is, choose the one with the smallest $a$; if there is a tie, minimize $b$; and if a tie persists, minimize $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
The numeric inequalities were removed from the Input section and integrated into the scenario as system capacities and minimum requirements (Strategy S07). To prevent immediate pattern matching to graph triangles, the explicit pairwise-border phrasing was replaced with a double-negative consistency condition ("none of the three possible pairs... lacks a shared border"), forcing models to reason about the logical requirement rather than matching the standard definition of a 3-clique.
</RATIONALE>
<PRESERVED_ANSWER>
The logical requirement that none of the three pairs lacks a shared border is strictly equivalent to all three pairs having a shared border, so exactly the same sets of three territories are valid tri-junctions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying graph structure and the task of finding a 3-clique (triangle) are completely unchanged, meaning the time and space complexity requirements remain identical.
</PRESERVED_CLASS>
<RISK>
The double-negative phrasing ("none of the three possible pairs... lacks a shared border") might be misread by a careless reader, though it is logically unambiguous.
</RISK>
