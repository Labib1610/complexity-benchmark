**Solution Explanation**

For a triple `u < v < w` let  

```
Iuv = 1  if edge (u,v) exists, else 0
Iuw = 1  if edge (u,w) exists, else 0
Ivw = 1  if edge (v,w) exists, else 0
```

For any real numbers `x1 , x2 , x3` with  

```
x1 + x2 + x3 = 0
x1² + x2² + x3² = 1
```

the interference energy is  

```
E = x1·x2·Iuv + x1·x3·Iuw + x2·x3·Ivw
```

A well‑known identity (expand `(x1+x2+x3)²`) gives

```
x1·x2 + x1·x3 + x2·x3 = ( (x1+x2+x3)² – (x1²+x2²+x3²) ) / 2
                     = ( 0 – 1 ) / 2 = –0.5
```

Hence, **if all three edges are present** (`Iuv = Iuw = Ivw = 1`) we obtain

```
E = x1·x2 + x1·x3 + x2·x3 = –0.5
```

independently of the concrete admissible `x`.  
If at least one of the three edges is missing, the corresponding term is
zero, therefore `E` cannot be `‑0.5` for *all* admissible triples.
Consequently a *critically flawed* triple is exactly a **triangle** of the
graph.

The task reduces to:  

*find the lexicographically smallest triangle* (three vertices all pairwise
connected).

--------------------------------------------------------------------

#### Finding the smallest triangle

`n ≤ 2000`, therefore we can store the adjacency of each vertex as a
bitset of length `n`. In Python an integer works as such a bitset
(`bit i` = 1 ⇔ edge to vertex `i` exists).

For every ordered pair `a < b` that is an edge we compute

```
common = adjacency[a] & adjacency[b]          # vertices adjacent to both a and b
common >>= (b+1)                               # keep only vertices > b
```

If `common` is non‑zero, its least significant set bit gives the smallest
`c > b` that together with `a,b` forms a triangle.
Because we iterate `a` increasingly, then `b` increasingly,
the first triangle we encounter is exactly the required one.

Complexities  

* building adjacency: `O(m)`
* main loops: at most `O(n² / wordsize)` bit operations – well below the
  limit (`n = 2000` → about 2 M operations)
* memory: `n` integers, each ≤ `2ⁿ`, i.e. < 256 KB.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest
critically flawed triple.

---

##### Lemma 1  
A triple of vertices is critically flawed **iff** the three vertices form a
triangle (all three edges are present).

**Proof.**  
*If* the three edges exist, the identity shown above gives `E = –0.5` for
every admissible `(x1,x2,x3)`.  
*Only if*: suppose at least one edge, say `(u,v)`, is missing.
Choose admissible coefficients with `x_u = 1/√2 , x_v = –1/√2 , x_w = 0`.
They satisfy the constraints, and the term `x_u·x_v·I_uv` equals
`±½·0 = 0`. The other two terms are bounded by `|x_i·x_j| ≤ ½`,
so the total energy cannot be constantly `–0.5`. ∎



##### Lemma 2  
When the algorithm examines a pair `a<b` that is an edge,
`common` after the shift contains exactly the vertices `c` such that
`a<b<c` and edges `(a,c)` and `(b,c)` exist.

**Proof.**  
`adjacency[a] & adjacency[b]` keeps precisely the vertices adjacent to both
`a` and `b`. Shifting right by `b+1` discards bits `0 … b`, i.e. vertices
`≤ b`. The remaining bits correspond exactly to vertices `c>b` adjacent to
both `a` and `b`. ∎



##### Lemma 3  
If the algorithm finds a triangle `(a,b,c)` it is the lexicographically
smallest triangle of the graph.

**Proof.**  
The outer loop enumerates `a` from `1` to `n`. For a fixed `a` the inner
loop enumerates `b` from `a+1` upwards, but only those `b` that are
adjacent to `a`. For each such pair the algorithm picks the smallest
`c>b` (least set bit of `common`). Therefore the first triangle discovered
has the smallest possible `a`; among those with that `a` it has the smallest
`b`; and for that pair the smallest possible `c`. This is exactly the
lexicographic order required. ∎



##### Lemma 4  
If the graph contains at least one triangle, the algorithm will find one.

**Proof.**  
Take the lexicographically smallest triangle `(a,b,c)`. The edge `(a,b)`
appears in the inner loop when `a` is processed, because `b>a` and the edge
exists. At that moment `c` is adjacent to both `a` and `b`, hence its bit is
set in `common`. Since `c>b`, after the shift it remains set, and because
`c` is the smallest such vertex, it is the least significant set bit.
Thus the algorithm discovers this triangle. ∎



##### Theorem  
The algorithm outputs three integers `a<b<c` that form a critically flawed
triple, and among all such triples it is the lexicographically smallest.

**Proof.**  
By Lemma&nbsp;4 a triangle is found; by Lemma&nbsp;2 the three vertices are
pairwise adjacent, i.e. a triangle. Lemma&nbsp;1 shows that any triangle is
critically flawed. Lemma&nbsp;3 guarantees that the first triangle found is
lexicographically minimal. The algorithm prints exactly this triple. ∎

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [0] * n          # bitset adjacency
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(n):
        mask_a = adj[a]
        # iterate b > a where edge exists
        b_bits = mask_a >> (a + 1)
        while b_bits:
            lsb = b_bits & -b_bits
            b = (a + 1) + (lsb.bit_length() - 1)
            # common neighbours > b
            common = (adj[a] & adj[b]) >> (b + 1)
            if common:
                lsb_c = common & -common
                c = (b + 1) + (lsb_c.bit_length() - 1)
                print(a + 1, b + 1, c + 1)
                return
            b_bits ^= lsb  # remove this b

if __name__ == "__main__":
    solve()
```
