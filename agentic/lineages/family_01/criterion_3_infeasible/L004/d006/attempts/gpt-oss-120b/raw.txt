**Solution Explanation**

For three vertices `a < b < c` let  

*`E(a,b,c)`* – the set of edges among them (at most three edges).

For a subset `S ⊆ {a,b,c}` the number `k(S)` is the amount of edges of `E`
that are completely inside `S`.  
The required value for the triple is  

```
F(a,b,c) = Σ_{S ⊆ {a,b,c}} 2^{k(S)}                (1)
```

--------------------------------------------------------------------
### 1.  What triples give value 18 ?

Only three vertices exist, therefore the possible edge‑sets are

* 0 edges
* 1 edge
* 2 edges (they must share a vertex, because only three vertices exist)
* 3 edges – a triangle

Evaluating (1) for each case (enumerating the 8 subsets) gives  

| #edges | value |
|--------|-------|
| 0      | 8 |
| 1      | 10 |
| 2      | 13 |
| 3      | **18** |

So `F(a,b,c) = 18` **iff** the three vertices form a triangle
(all three possible edges are present).

The whole task is therefore:

*find the lexicographically smallest triangle in the given undirected graph.*

--------------------------------------------------------------------
### 2.  Finding the smallest triangle

`n ≤ 2000`, therefore an `n × n` adjacency matrix fits easily into memory.
A Python `int` works as a bitset of length `n` – bit `v‑1` is `1`
iff the vertex `v` is adjacent.

```
adj[v]  – integer, bit i (0‑based) = 1  ⇔  edge (v , i+1) exists
```

*Building the matrix* – `O(m)`.

*Searching* – iterate vertices `a` and `b` in increasing order,
check whether edge `(a,b)` exists, then intersect the neighbour sets:

```
common = adj[a] & adj[b]          # vertices adjacent to both a and b
```

All vertices `c` with `c > b` that close a triangle are exactly the set bits
of `common` whose index is at least `b` (because `c` must be larger than `b`
to keep the order `a < b < c`).  
Mask the lower bits away, take the least significant remaining bit –
that gives the smallest possible `c`.

The first triple found during the double loop is already the lexicographically
smallest one, because the loops increase `a` first, then `b`, then `c`.

Complexities  

*Time* : `O(n²)`   ( ≤ 2·10⁶ iterations, each only a few integer operations)  
*Memory*: `O(n)`   ( `n` integers of at most 2000 bits → < 1 MiB)

Both are far below the limits.

--------------------------------------------------------------------
### 3.  Correctness Proof  

We prove that the algorithm outputs exactly the required triple.

---

#### Lemma 1  
For any three distinct vertices `a,b,c` the value `F(a,b,c)` defined in (1)
equals 18 **iff** the three edges `{ab,ac,bc}` are all present.

*Proof.*  
The table in Section&nbsp;1 enumerates all possible edge‑sets among three
vertices and the corresponding sums (direct computation over the 8 subsets).
Only the case of three edges yields 18. ∎



#### Lemma 2  
During the execution, when the algorithm reaches a pair `(a,b)` with
`a < b` and edge `(a,b)` present, the variable  

```
common = adj[a] & adj[b] & mask(b)
```

contains exactly the vertices `c` such that `c > b` and the three edges
`ab, ac, bc` are present.

*Proof.*  
`adj[a] & adj[b]` keeps a vertex `x` iff both edges `(a,x)` and `(b,x)` exist.
`mask(b)` has bits `1` for indices `≥ b` and `0` otherwise, therefore the
additional `&` removes all `x ≤ b`.  Consequently the remaining set bits are
precisely the vertices `c` with `c > b` that together with `a,b` form a triangle. ∎



#### Lemma 3  
If the algorithm prints a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

*Proof.*  
The algorithm prints only after confirming that edge `(a,b)` exists
(`(adj[a]>> (b-1)) & 1 == 1`) and after finding a set bit `c` in `common`
as defined in Lemma&nbsp;2.  
By Lemma&nbsp;2 this bit guarantees edges `(a,c)` and `(b,c)`.  
Thus all three edges are present – the vertices form a triangle. ∎



#### Lemma 4  
The first printed triple is the lexicographically smallest triangle
in the graph.

*Proof.*  
The outer loop enumerates `a = 1 … n-2` in increasing order.
For a fixed `a` the inner loop enumerates `b = a+1 … n-1` in increasing order.
When a pair `(a,b)` is processed, the algorithm chooses the smallest possible
`c > b` (least significant set bit).  
Therefore triples are examined in the exact order of the lexicographic
comparison `(a,b,c)`.  
The first triple that satisfies the triangle condition is consequently the
minimum one. ∎



#### Lemma 5  
If the graph contains at least one triangle, the algorithm will print a
triple.

*Proof.*  
Take the lexicographically smallest triangle `{a,b,c}`.
When the outer loops reach this pair `(a,b)`, edge `(a,b)` is present,
so the algorithm computes `common`.  
Because `c` is adjacent to both `a` and `b` and `c > b`,
bit `c` belongs to `common` (Lemma&nbsp;2).  
Thus `common` is non‑empty and the algorithm prints a triple (possibly the
same `{a,b,c}` or an even smaller one, but a triangle exists). ∎



#### Theorem  
The algorithm always outputs three vertex numbers in increasing order that
form a triangle, and among all such triples it outputs the one with the
smallest first vertex, then smallest second, then smallest third.

*Proof.*  
Existence of a triangle is guaranteed, so by Lemma&nbsp;5 the algorithm
outputs a triple.  
By Lemma&nbsp;3 the output triple is a triangle, therefore its capacity is
exactly 18 (Lemma&nbsp;1).  
Lemma&nbsp;4 shows that the first printed triple is the lexicographically
smallest triangle, which is exactly the required tie‑breaking rule. ∎

### 4.  Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # adjacency as bitsets, 1‑based vertex numbers, bits 0..n-1
    adj = [0] * (n + 1)
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    full_mask = (1 << n) - 1          # bits 0 .. n-1 set

    for a in range(1, n - 1):
        a_adj = adj[a]
        for b in range(a + 1, n):
            # edge (a,b) must exist
            if not ((a_adj >> (b - 1)) & 1):
                continue
            # vertices adjacent to both a and b
            common = a_adj & adj[b]
            # keep only vertices with index >= b  (i.e. vertex number > b)
            mask = full_mask ^ ((1 << b) - 1)   # bits b .. n-1 are 1
            common &= mask
            if common:
                # smallest c : least significant set bit
                lsb = common & -common
                c = lsb.bit_length()          # gives index+1
                # c is already 1‑based because bit 0 -> vertex 1
                print(a, b, c)
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
