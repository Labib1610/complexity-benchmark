# Environment Allocation

Time limit: 2 s
Memory limit: 256 MB

A system administrator is trying to deploy $n$ software modules (numbered 1 through $n$) across two isolated virtual environments. The system's compatibility registry contains $m$ records of module pairs that will cause a critical system panic if installed in the same environment.

The administrator suspects it is impossible to deploy all modules using only two environments. To formally justify the creation of a third environment, you must output a minimal proof of this impossibility. You need to find a set of exactly three distinct modules which, if considered in isolation from the rest of the system, cannot be distributed across two environments without triggering a registered panic. 

This requirement ensures that no matter how you might assign these three specific modules to the two environments, at least one pair placed in the same environment will be a registered conflict.

## Input
The first line contains two integers $n$ and $m$. The deployment requires a minimum of three modules, and the system architecture imposes a maximum capacity of 2000 modules. The number of conflict records $m$ is at least 3, and cannot exceed the registry's storage quota of 200,000 entries (or the total number of possible distinct module pairs, whichever is smaller).

Each of the next $m$ lines contains two integers $u$ and $v$ — a pair of modules that conflict with each other. 
It is guaranteed that at least one such required set of three modules exists.

## Output
Print the three integer identifiers of these modules on one line, sorted in ascending order. 
If there are multiple valid sets, output the one that is lexicographically smallest (the one with the lowest first identifier; resolving ties by the second identifier, then the third).

## Example 1
### Input
```
4 5
1 2
1 3
2 3
2 4
3 4
```
### Output
```
1 2 3
```

## Example 2
### Input
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
### Output
```
1 2 4
```
