**Solution Explanation**

For three different transceivers `a<b<c`

```
Zii = 1                              (i = 1,2,3)
Zij = 0   if (ui , uj) is an interference link
Zij = 1   otherwise
```

`Z = I + B` where `B` has `0` on the diagonal and `Bij = 1` iff the pair
`(ui , uj)` is **not** an interference link.

*If the three transceivers form a triangle of interference links*  
all three off‑diagonal entries of `Z` are `0`, therefore `Z = I` and

```
Z⁵ = I ,   trace(Z⁵) = 3 .
```

If at least one of the three possible links is missing, `Z` contains a
`1` outside the diagonal.  
All entries of `Z` are non‑negative, consequently every power of `Z`
has non‑negative entries and every diagonal entry of `Z⁵` is at least `1`.
Having a `1` outside the diagonal makes at least one diagonal entry of
`Z⁵` larger than `1`, therefore the trace becomes larger than `3`.

Hence

> **The required triple is exactly a triangle (three pairwise
> interfering transceivers).**

The task is reduced to: *find the lexicographically smallest triangle*.

--------------------------------------------------------------------

#### 1.   Data structure – bitsets

`n ≤ 2000`, therefore a 2000‑bit integer fits easily into a Python `int`.
For every vertex `v` we store

```
adj[v] : integer, bit i is 1  ⇔  (v , i) is an interference link
```

All operations on a whole row are then a single integer operation
(`&`, `>>`, …) and are O(1).

We also keep for each vertex a **sorted list** of its neighbours
(`nbr[v]`) – needed to iterate over edges in increasing order.

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle

```
for a = 0 … n-1:
        for each b in nbr[a] with b > a (in increasing order):
                common = adj[a] & adj[b]          # vertices adjacent to both a and b
                # we need a vertex c > b
                common >>= (b+1)                  # delete bits ≤ b
                if common != 0:
                        # lowest set bit = smallest possible c
                        low = common & -common
                        c = (low.bit_length() - 1) + b + 1
                        answer = (a+1, b+1, c+1)   # back to 1‑based labels
                        output and finish
```

*Why does this give the lexicographically smallest triangle?*

* the outer loop increases `a` – the smallest label of the answer is minimal;
* for a fixed `a` the inner loop increases `b` – the second label is minimal;
* for a fixed pair `(a,b)` we take the smallest possible `c>b` – the third
  label is minimal.

All three conditions together are exactly the required ordering.

The algorithm touches every edge once, each step performs only a few
integer operations → **`O(m)` time**, `m ≤ 2·10⁵`.  
Memory consumption: `n` integers (`≈ 2000·2000/8 ≈ 0.5 MiB`) plus neighbour
lists – well below the limit.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest
triangle.

---

##### Lemma 1  
For any three distinct vertices `x<y<z` the trace of `Z⁵` equals `3`
iff `{x,y,z}` is a triangle (all three edges are present).

**Proof.**  
If the three edges are present, all off‑diagonal entries of `Z` are `0`,
so `Z = I` and `Z⁵ = I`, trace `=3`.

Otherwise at least one off‑diagonal entry of `Z` equals `1`.  
All entries of `Z` are non‑negative, therefore every entry of `Z⁵` is
non‑negative and each diagonal entry of `Z⁵` is at least `1`.  
Having a `1` outside the diagonal makes at least one walk of length `5`
from a vertex to itself that uses this `1`, increasing the corresponding
diagonal entry above `1`. Consequently the sum of the three diagonal
entries is larger than `3`. ∎



##### Lemma 2  
During the execution, when the algorithm reaches a pair `(a,b)` with
`a<b` and edge `(a,b)` exists, `common = adj[a] & adj[b]` contains exactly
the vertices adjacent to **both** `a` and `b`.

**Proof.**  
`adj[a]` has a `1` at position `v` iff `(a,v)` is an edge.
`adj[b]` has a `1` at position `v` iff `(b,v)` is an edge.
Bitwise `&` keeps a `1` only when both bits are `1`, i.e. when both edges
exist. ∎



##### Lemma 3  
If after shifting `common >>= (b+1)` the result is non‑zero, the vertex
`c` reconstructed by the algorithm satisfies `c>b` and forms a triangle
`(a,b,c)`.

**Proof.**  
Shifting removes all bits `≤ b`; any remaining set bit corresponds to a
vertex `c>b`. Because the bit was present in the original `common`,
by Lemma&nbsp;2 both edges `(a,c)` and `(b,c)` exist.
Edge `(a,b)` exists by the outer loops, therefore the three edges of the
triple are present – it is a triangle. ∎



##### Lemma 4  
The first triangle found by the algorithm is the lexicographically
smallest triangle in the graph.

**Proof.**  
Consider any triangle `{x,y,z}` with `x<y<z`.

* The outer loop iterates `a` in increasing order.
  The first `a` for which a triangle exists is `x`, because for any
  `a<x` no triangle can contain `a` as its smallest vertex.
* For this `a=x` the inner loop iterates `b` in increasing order among
  neighbours `>a`. The smallest possible `b` belonging to a triangle with
  `a` is `y`; all `b<y` cannot be part of a triangle with `a` (otherwise
  `y` would not be minimal).
* For the pair `(a,b) = (x,y)` the algorithm selects the smallest
  `c>b` that is adjacent to both – that is exactly `z`.

Thus the algorithm discovers `{x,y,z}` before any other triangle,
hence it is the lexicographically smallest. ∎



##### Lemma 5  
If the algorithm outputs a triple `(a,b,c)`, it satisfies the required
stability characteristic (trace `=3`).

**Proof.**  
By Lemma&nbsp;3 the three edges `(a,b) , (a,c) , (b,c)` are present,
so `{a,b,c}` is a triangle. Lemma&nbsp;1 then gives trace `=3`. ∎



##### Theorem  
The program always prints three transceiver labels forming a subset
with stability characteristic `3`, and among all such subsets prints the
one with minimal lexicographic order.

**Proof.**  
Existence of at least one suitable subset is guaranteed, i.e. the graph
contains a triangle. The algorithm scans all edges; when it meets the
first triangle it stops and outputs it. By Lemma&nbsp;5 the output has
trace `3`. By Lemma&nbsp;4 this triangle is the lexicographically smallest
among all triangles, which are exactly the subsets with trace `3`
(Lemma&nbsp;1). ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets* : `O(m)` time, `O(n)` integers memory.  
*Scanning edges* : each edge examined once, each step `O(1)` → `O(m)` time.  

```
Time   :  O(m)   ≤ 2·10⁵   (well below 2 s)
Memory :  O(n)   ≤ 2000 integers  ≈ 0.5 MiB
```

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n               # bitset of neighbours
    nbr = [[] for _ in range(n)]

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        # set bits
        adj[u] |= 1 << v
        adj[v] |= 1 << u
        # store for ordered iteration
        if u < v:
            nbr[u].append(v)
            nbr[v].append(u)
        else:
            nbr[v].append(u)
            nbr[u].append(v)

    # sort neighbour lists (they are already increasing because we added in order,
    # but sorting guarantees)
    for lst in nbr:
        lst.sort()

    for a in range(n):
        for b in nbr[a]:
            if b <= a:
                continue
            common = adj[a] & adj[b]
            # keep only vertices > b
            common >>= (b + 1)
            if common:
                # lowest set bit
                low = common & -common
                c = (low.bit_length() - 1) + b + 1
                # output 1‑based
                print(a + 1, b + 1, c + 1)
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
