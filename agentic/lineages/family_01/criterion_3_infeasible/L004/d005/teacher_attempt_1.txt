# Integration Audit

Time limit: 2 s
Memory limit: 256 MB

A system administrator is auditing software modules (numbered consecutively starting from 1) for compatibility. The system's compatibility registry contains records of module pairs. If both modules from a record are deployed together, they will trigger a critical system panic.

The administrator needs to demonstrate a severe integration failure by finding exactly three distinct modules that are completely mutually incompatible. You must provide a minimal configuration that proves this: a set of exactly three modules where all three possible pairs among them appear in the registry.

## Input
The first line provides two integers $n$ and $m$, representing the actual number of modules and the actual number of records. The system requires at least enough modules to form a target group of three, while the maximum possible value for $n$ is dictated by the data center's limit of exactly 40 racks, each holding exactly 50 modules. The registry must contain at least three records, and the maximum possible value for $m$ is limited by a database allocation of exactly 400 memory pages, each storing exactly 500 records (or the maximum number of unique pairs possible among the $n$ modules, whichever is smaller).

Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing a pair of modules that trigger a panic if deployed together. 
It is guaranteed that the registry contains at least one such group of three modules.

## Output
Output the three integer identifiers of your chosen group on a single line, ordered from lowest to highest. 
If more than one such group exists, evaluate them by their sorted identifiers. Choose the group that minimizes the first (lowest) identifier. If there is a tie, choose the one that minimizes the second (middle) identifier. If a tie still remains, minimize the third (highest) identifier.

## Example 1
### Input
```
4 5
1 2
1 3
2 3
2 4
3 4
```
### Output
```
1 2 3
```

## Example 2
### Input
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
### Output
```
1 2 4
```

<RATIONALE>
I removed the scenario about distributing modules across two environments, which previously acted as an explicit hint (via the pigeonhole principle) pointing towards 2-coloring impossibility and triangle detection. Instead, I directly asked for a triad of mutually incompatible modules. I also replaced the explicit numeric bounds with physical storage limits (racks, memory pages) that require simple arithmetic to recover, forcing the model to read and derive the constraints rather than pattern-matching standard competitive programming bounds.
</RATIONALE>

</PRESERVED_ANSWER>
