**Solution Explanation**

For every unordered pair `{u , v}` we are given a *directed* edge

```
min(u,v)  →  max(u,v)
```

So the direction is completely determined by the node numbers.
For a triple `a < b < c` we need the three directed edges

```
a → b ,   a → c ,   b → c
```

i.e. the three undirected edges `{a,b}`, `{a,c}`, `{b,c}` must all be present.
The task is to output the lexicographically smallest such triple
(the smallest possible `a`, then the smallest possible `b`, then `c`).

--------------------------------------------------------------------

#### 1.   Observations  

* `a` is the smallest vertex of the triple.  
  If we fix `a`, the other two vertices must be neighbours of `a`
  and also be connected with each other.

* `n ≤ 2000`.  
  An `n × n` boolean matrix (≈ 4 · 10⁶ entries) easily fits into memory.
  In Python an `int` can be used as a bitset of length `n+1`
  (bit *i* tells whether vertex *i* is a neighbour).

* For a fixed `a` we need **any edge inside the neighbour set of `a`**
  (restricted to vertices larger than `a`).  
  If we can test “does vertex `b` have a neighbour among the set `S`?”
  quickly, we obtain the required triple.

--------------------------------------------------------------------

#### 2.   Data structures  

* `adj_bits[i]` – an integer, bit *j* (`j>0`) is `1` iff `{i,j}` is an edge.
* `higher_mask[i]` – bits `i+1 … n` are `1`, lower bits are `0`.  
  `higher_mask[i] = ((1 << (n+1)) - 1) ^ ((1 << (i+1)) - 1)`

Both arrays have size `n+1` (index `0` unused).

--------------------------------------------------------------------

#### 3.   Algorithm  

```
for a = 1 … n-2                         # increasing → lexicographic a
        N = adj_bits[a] & higher_mask[a]   # neighbours larger than a
        while N is not empty:              # iterate b in increasing order
                b = lowest set bit of N
                N ^= (1 << b)               # remove b from N
                # vertices > b that are neighbours of both a and b
                cand = adj_bits[b] & (adj_bits[a] & higher_mask[a]) & higher_mask[b]
                if cand != 0:
                        c = lowest set bit of cand
                        output a, b, c and finish
```

*The inner `cand` expression*  
`adj_bits[a] & higher_mask[a]` is exactly the set `N` we already computed.
Intersecting it with `adj_bits[b]` keeps only vertices adjacent to `b`,
and `higher_mask[b]` discards vertices `≤ b`.  
If the intersection is non‑empty, its lowest bit gives the smallest possible
`c` for the current `a` and `b`. Because we scan `a` and `b` in increasing
order, the first triple we output is the lexicographically smallest one.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triple
`a < b < c` with all three required edges.

---

##### Lemma 1  
For a fixed `a`, the algorithm examines the neighbours `b` of `a`
in strictly increasing order.

**Proof.**  
`N` is the bitset of neighbours larger than `a`.  
In each loop iteration the lowest set bit of `N` is taken as `b`
(`b = lowbit(N)`) and then cleared (`N ^= 1<<b`).  
Therefore the sequence of extracted `b` values is increasing. ∎



##### Lemma 2  
For a fixed pair `a < b` (both neighbours of each other),
`cand` is non‑empty **iff** there exists a vertex `c` with  
`b < c` and edges `a–c` and `b–c`.

**Proof.**  
`cand` = `adj_bits[b]` ∧ `adj_bits[a]` ∧ `higher_mask[b]`.

* `adj_bits[a]` guarantees `c` is adjacent to `a`.
* `adj_bits[b]` guarantees `c` is adjacent to `b`.
* `higher_mask[b]` guarantees `c > b`.

Thus any bit set in `cand` corresponds exactly to a vertex `c`
satisfying the three conditions, and conversely any such `c`
appears in the intersection. ∎



##### Lemma 3  
If the algorithm outputs a triple `(a,b,c)`, then it satisfies all
required edges.

**Proof.**  
`b` is taken from `N`, i.e. `b` is a neighbour of `a` and `b>a`.  
`c` is taken from `cand`, which by Lemma&nbsp;2 is a neighbour of both
`a` and `b` and larger than `b`.  
Hence edges `a→b`, `a→c`, `b→c` exist. ∎



##### Lemma 4  
Let `T* = (a*,b*,c*)` be the lexicographically smallest feasible triple.
When the outer loop reaches `a = a*`, the inner loop will eventually
output exactly `T*`.

**Proof.**  
All neighbours of `a*` larger than `a*` are examined in increasing order
(Lemma&nbsp;1).  
Consider the first neighbour `b` examined that belongs to `T*` (i.e. `b = b*`).
All earlier neighbours `b' < b*` cannot form a valid triple with `a*`,
otherwise `(a*,b',c')` would be lexicographically smaller than `T*`.
For `b = b*`, Lemma&nbsp;2 tells us that `cand` contains at least `c*`,
so it is non‑empty and the algorithm picks the smallest such `c`,
which is exactly `c*` (otherwise a smaller `c` would give a smaller triple).
Thus the algorithm outputs `(a*,b*,c*)`. ∎



##### Lemma 5  
The algorithm never outputs a triple that is lexicographically larger
than the smallest feasible triple.

**Proof.**  
If it outputs a triple, the outer loop has already fixed the smallest
possible `a` for which a feasible triple exists (otherwise a smaller `a`
would have produced an output earlier).  
For this `a`, by Lemma&nbsp;1 the first `b` that leads to a non‑empty `cand`
is the smallest `b` that can be part of any feasible triple with this `a`.
Finally the smallest possible `c` for this pair is chosen.
Hence the produced triple is the lexicographically smallest among all
feasible triples. ∎



##### Theorem  
The algorithm terminates and prints the lexicographically smallest
triple `a < b < c` such that edges `a→b`, `a→c`, `b→c` exist.

**Proof.**  
Existence of at least one feasible triple is guaranteed, therefore the
outer loop will eventually reach its smallest `a` and, by Lemma&nbsp;4,
output a triple. By Lemma&nbsp;3 the output is valid, and by Lemma&nbsp;5
it is the lexicographically smallest one. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Building adjacency bitsets* – `O(m)`.

For each vertex `a` we iterate over its neighbours larger than `a`
once (each neighbour is removed from `N` after processing).  
Inside the loop we perform only constant‑time bit operations on integers
of length ≤ 2000 bits (Python `int` handles them in word‑size chunks).

Hence the total work is `O( Σ deg(a) ) = O(m)`.

Memory consumption: `n+1` integers of at most `n+1` bits → `O(n² / wordsize)`
≈ 2000 · 2000 / 64 ≈ 62 KB, well below the limit.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # bitsets, bit i means edge to i
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    # masks with bits > i set
    full_mask = (1 << (n + 1)) - 1
    higher_mask = [0] * (n + 1)
    for i in range(n + 1):
        higher_mask[i] = full_mask ^ ((1 << (i + 1)) - 1)

    # helper: index of lowest set bit (bit 0 is unused)
    def lowbit_index(x: int) -> int:
        return (x & -x).bit_length() - 1

    for a in range(1, n - 1):
        N = adj[a] & higher_mask[a]          # neighbours > a
        while N:
            b = lowbit_index(N)
            N ^= 1 << b                       # remove b
            # vertices > b that are neighbours of both a and b
            cand = adj[b] & (adj[a] & higher_mask[a]) & higher_mask[b]
            if cand:
                c = lowbit_index(cand)
                print(a, b, c)
                return

if __name__ == "__main__":
    solve()
```

and conforms to the required input‑output format.
