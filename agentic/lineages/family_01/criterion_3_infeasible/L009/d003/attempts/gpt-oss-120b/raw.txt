**Solution Explanation**

For three vertices `a < b < c` the induced subgraph is *not* 2‑colourable
iff it contains an odd cycle.
With only three vertices the only odd cycle is a triangle,
so we have to output a triangle.
The required triangle is the lexicographically smallest one
(`a` minimal, then `b`, then `c`).

`n ≤ 2000`, therefore an adjacency matrix (or a bitset) of size `n·n`
fits easily into memory and allows `O(1)` edge tests.



--------------------------------------------------------------------

#### Data structure – bitset adjacency

For every vertex `v` we store a Python integer `adj[v]`.
Bit `i` (0‑based) of `adj[v]` is `1` iff the edge `v – i` exists.

```
adj[v] = Σ (1 << i)   over all neighbours i of v
```

With this representation

* test “edge (x , y) exists” → `(adj[x] >> y) & 1`
* intersection of neighbour sets → `adj[x] & adj[y]` (also an integer)

All operations are bitwise and run in O(1) for `n = 2000`.

--------------------------------------------------------------------

#### Searching the lexicographically smallest triangle

We iterate vertices in increasing order – this already guarantees the
smallest possible `a`.

```
for a = 0 … n-1:
    for each neighbour b of a with b > a (sorted increasingly):
        common = adj[a] & adj[b]          # vertices adjacent to both a and b
        # we need a vertex c > b
        mask = common >> (b+1)            # discard bits ≤ b
        if mask != 0:
            # lowest set bit of mask → smallest possible c
            low = mask & -mask
            offset = low.bit_length() - 1
            c = b + 1 + offset
            output (a+1, b+1, c+1) and stop
```

*Why does this give the lexicographically smallest triangle?*

* `a` grows from `1` upwards – the first found triangle uses the smallest
  possible `a`.
* For a fixed `a`, neighbours `b` are examined in increasing order,
  therefore the first triangle found for this `a` has the smallest possible
  `b`.
* For a fixed pair `(a,b)` we look for the smallest `c > b`
  (the lowest set bit of `common` after position `b`).

Thus the first triangle discovered by the algorithm is exactly the
lexicographically minimal one.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest
triangle.

---

##### Lemma 1  
For any vertices `a < b` the expression `common = adj[a] & adj[b]`
contains exactly the vertices adjacent to **both** `a` and `b`.

**Proof.**  
Bit `i` of `adj[a]` is `1` iff edge `(a,i)` exists, similarly for `adj[b]`.
Bitwise AND keeps a `1` only when both bits are `1`, i.e. when both edges
exist. ∎



##### Lemma 2  
`mask = common >> (b+1)` has a set bit at position `k` (0‑based)  
iff vertex `c = b+1+k` satisfies `c > b` and is adjacent to both `a` and `b`.

**Proof.**  
Shifting right by `b+1` discards bits `0 … b`.  
A remaining set bit at position `k` corresponds to original bit
`b+1+k`, i.e. vertex `c = b+1+k`. By Lemma&nbsp;1 this vertex is adjacent to
both `a` and `b`. The shift guarantees `c > b`. ∎



##### Lemma 3  
If `mask ≠ 0` then `c = b+1+offset` computed by the algorithm is the
smallest vertex `> b` adjacent to both `a` and `b`.

**Proof.**  
`mask & -mask` isolates the lowest set bit of `mask`. Its index `offset`
is the smallest `k` with a set bit, therefore `c = b+1+offset` is the
smallest vertex satisfying Lemma&nbsp;2. ∎



##### Lemma 4  
When the algorithm prints a triple `(a,b,c)` it is a triangle.

**Proof.**  
`b` is a neighbour of `a` by the outer loop.
By Lemma&nbsp;3, `c` is a neighbour of both `a` and `b`.  
Thus edges `(a,b)`, `(a,c)`, `(b,c)` all exist – a triangle. ∎



##### Lemma 5  
Let `T` be the triangle printed by the algorithm.
For any triangle `T' = (a',b',c')` with `a' < b' < c'`,
we have `(a,b,c) ≤_lex (a',b',c')`.

**Proof.**  
The outermost loop scans `a` increasingly.
The algorithm stops at the first `a` for which a triangle exists,
hence `a` is the smallest possible first vertex among all triangles,
so `a ≤ a'`.

If `a = a'`, the inner loop scans neighbours `b` of `a` in increasing order.
The algorithm stops at the first `b` that can be extended to a triangle,
therefore `b` is the smallest possible second vertex for this `a`,
so `b ≤ b'`.

If also `b = b'`, Lemma&nbsp;3 chooses the smallest feasible `c`,
hence `c ≤ c'`. ∎



##### Lemma 6  
A triangle exists (guaranteed by the statement), therefore the algorithm
will eventually find one and terminate.

**Proof.**  
All edges are stored, loops enumerate every ordered pair `(a,b)` with an
edge and `a<b`. For a triangle `(x,y,z)` with `x<y<z`,
when the outer loops reach `a=x`, `b=y` the common neighbours contain `z`,
so `mask ≠ 0` and the algorithm prints a triangle. ∎



##### Theorem  
The algorithm outputs the lexicographically smallest triple of vertices
that forms a triangle.

**Proof.**  
By Lemma&nbsp;6 the algorithm outputs some triangle.
By Lemma&nbsp;4 the output is indeed a triangle.
By Lemma&nbsp;5 no other triangle is lexicographically smaller.
Thus the printed triple is exactly the required answer. ∎



--------------------------------------------------------------------

#### Complexity Analysis

*Building adjacency bitsets* – `O(m)` time, `O(n)` integers (≈ 2000·8 bytes).

*Search* – For each edge `(a,b)` we perform constant‑time bit operations.
The number of examined pairs is at most `m`.  
Hence total time `O(m) ≤ 2·10⁵`.  
Memory consumption `O(n²/wordsize) ≈ 2000·2000 / 8 bytes ≈ 0.5 MB`.

Both limits satisfy the problem constraints.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n          # bitset adjacency
    neigh = [[] for _ in range(n)]   # neighbour lists (sorted later)

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u
        neigh[u].append(v)
        neigh[v].append(u)

    for i in range(n):
        neigh[i].sort()

    for a in range(n):
        for b in neigh[a]:
            if b <= a:
                continue
            common = adj[a] & adj[b]
            # keep only vertices > b
            mask = common >> (b + 1)
            if mask:
                low = mask & -mask          # lowest set bit
                offset = low.bit_length() - 1
                c = b + 1 + offset
                # output 1‑based, sorted
                print(a + 1, b + 1, c + 1)
                return

if __name__ == "__main__":
    solve()
```

and conforms to the required input‑output format.
