# Problem C — Economic Cores

Time limit: 2 s
Memory limit: 256 MB

In a sprawling galaxy, there are $n$ star systems and $m$ established hyperspace trade routes. Each trade route is bidirectional and allows commerce between two different star systems. 

Each star system maintains a registry of its direct trade partners. An "Economic Core" is formed by a triplet of distinct systems $a, b, c$ (sorted such that $a < b < c$) if they satisfy the following mutual registry conditions:
- System $b$ is listed in the registry of system $a$.
- System $c$ is listed in both the registry of system $a$ and the registry of system $b$.

Your task is to identify such a triplet. The galaxy's routing data is complex, but the hyperspace registry confirms that the current configuration guarantees the presence of at least one qualifying triplet.

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2 \cdot 10^5)$), representing the number of star systems and the number of trade routes. Star systems are numbered from $1$ to $n$.

Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating a bidirectional trade route between star system $u$ and star system $v$. It is guaranteed that at most one route exists between any specific pair of star systems, and that at least one Economic Core exists in the network.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, representing the star systems in the Economic Core. You must list them in ascending order ($a < b < c$).

If there are multiple valid triplets, output the lexicographically smallest one. A triplet $(a_1, b_1, c_1)$ is lexicographically smaller than $(a_2, b_2, c_2)$ if $a_1 < a_2$; or if $a_1 = a_2$ and $b_1 < b_2$; or if $a_1 = a_2$, $b_1 = b_2$, and $c_1 < c_2$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
I removed the framing of "three systems connected to each other" which models mapped directly to standard "triangle enumeration" templates. Instead, I defined the target structure as a sorted triplet satisfying specific adjacency inclusions ($b \in adj[a]$ and $c \in adj[a] \cap adj[b]$). This forces the model to construct the intersection logic from the text rather than relying on a pre-packaged graph concept.
</RATIONALE>
<PRESERVED_ANSWER>
Because the graph is undirected, any three mutually connected nodes will satisfy the registry inclusion conditions when sorted, and any triplet satisfying the conditions forms a mutually connected triangle, meaning the exact same outputs remain correct.
</PRESERVED_ANSWER>
