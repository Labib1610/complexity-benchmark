# Triple-Factor Security Profile

Time limit: 2 s   Memory limit: 256 MB

You are configuring a high-security access system that relies on a database of distinct biometric sensors, identified by integers starting from 1. During calibration, the system generated a compatibility log containing specific pairs of sensors that can operate concurrently without mutual interference.

Your task is to establish a valid security profile, which must incorporate exactly three distinct sensors. For the authentication process to execute flawlessly, each sensor in your selected trio must be confirmed by the log to operate concurrently with both of the other two sensors in the trio.

You must determine a valid combination of three sensors for this profile. If multiple valid combinations are possible, you must choose the one that is lexicographically first.

## Input
The first line provides two integers $n$ and $m$, representing the total number of biometric sensors and the number of recorded concurrent pairs. A basic configuration needs 3 sensors, and the mainboard supports up to 2000 physical connections, defining the valid range for $n$. The calibration phase always logs at least 3 successful pairings. The firmware restricts the log capacity to 200,000 entries—meaning $m$ is bounded by this capacity, or by the theoretical maximum of unique pairs among the installed sensors, whichever is smaller.

Each of the subsequent $m$ lines contains two integers $u$ and $v$, indicating that sensor $u$ and sensor $v$ can operate concurrently.
It is guaranteed that at least one valid security profile can be established.

## Output
Print three integers $a$, $b$, and $c$ on a single line, ordered such that $a < b < c$. These must represent three sensors where the log confirms $a$ can operate concurrently with $b$, $b$ can operate concurrently with $c$, and $c$ can operate concurrently with $a$. If there are multiple valid profiles, output the one with the smallest $a$; if there is a tie, the smallest $b$; and finally the smallest $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

</RATIONALE>

The condition that a, b, and c must all be able to operate concurrently with each other defines exactly the same 3-clique requirement as the original problem, preserving all valid combinations and the lexicographical tie-breaker.
</PRESERVED_ANSWER>

The problem still requires finding a triangle (a 3-clique) in an undirected graph, which maintains the identical computational complexity and expected O(n*m/64) bitset algorithm.
</PRESERVED_CLASS>

Models might misinterpret the indirect bounds if they fail to parse "theoretical maximum of unique pairs" as n*(n-1)/2, though this is a standard concept and shouldn't cause algorithmic ambiguity.
