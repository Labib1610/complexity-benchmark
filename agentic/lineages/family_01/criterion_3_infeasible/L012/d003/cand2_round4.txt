<STATEMENT>
# Problem C — Resource Contention

Time limit: 2 s
Memory limit: 256 MB

You are configuring a system with $n$ parallel processes. The system has a set of binary contention rules. Each rule specifies two processes that share a critical resource, meaning they cannot both be in the ACTIVE state at the same time.

Your task is to identify a "contention bottleneck" in the current configuration. A contention bottleneck is a group of exactly three distinct processes such that you cannot select any pair of processes from this group and make them both ACTIVE simultaneously. Because of this property, these three processes are severely restricted. 

It is guaranteed that the provided configuration contains at least one such group of three processes. Your task is to find and report one.

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2 \cdot 10^5)$), representing the number of processes and the number of contention rules, respectively. Processes are numbered from $1$ to $n$.

Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$), indicating a contention rule between process $u$ and process $v$. The rules apply in both directions. It is guaranteed that at least one contention bottleneck of three processes exists.

## Output
Print three integers $a$, $b$, and $c$ on a single line, representing the identifiers of the three processes that form the contention bottleneck. 

The identifiers must be printed in ascending order ($a < b < c$). If there are multiple valid groups of three processes, you must output the one that is lexicographically smallest. This means you should first minimize $a$; if there are ties, minimize $b$ among those ties; and if there are still ties, minimize $c$.

## Example 1
**Input:**
```
4 5
1 2
1 3
2 3
2 4
3 4
```
**Output:**
```
1 2 3
```

## Example 2
**Input:**
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
**Output:**
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I removed the explicit graph framing ("linked by an interlock", "forms a flaw") that allowed models to pattern-match "triangle" or "3-clique". Instead, I framed it as a resource contention problem where a group of three processes cannot have any pair active simultaneously. This forces the model to logically deduce that every pair in the group must be restricted by a rule, which translates to a 3-clique, without giving away the graph structure directly. I also removed the explicit input guarantees about self-links and duplicates to strictly satisfy the Gate Feedback.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that no pair in the group of three can be active simultaneously means that all three possible pairs in the group must have a contention rule, which is mathematically identical to finding a 3-clique, preserving all answers.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a 3-clique in the given relation, maintaining the identical $O(n \cdot m / 64)$ bitset intersection complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "cannot select any pair" as applying to the whole system rather than just being a property of the three chosen processes, though the phrase "from this group" makes it highly precise.
</RISK>
