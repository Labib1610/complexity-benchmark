We need to find the lexicographically smallest triple of distinct processes that cannot be split into two groups without violating a mutual exclusion constraint.

A triple fails if every possible 2-coloring of its three vertices has at least one edge within the same color.  
For three vertices, this happens exactly when the triple forms a triangle (all three edges present).  
If any edge is missing, we can put the two non-adjacent vertices in one group and the third in the other.

So the problem reduces to: find the lexicographically smallest triangle in the graph.

We can do this by iterating over possible smallest vertex `a` from 1 to n, then over possible second vertex `b` from `a+1` to n, and check if there is a `c > b` such that all three edges exist.  
To make it efficient, we can store adjacency as sets for O(1) edge checks.

Complexity: O(n^2) in the worst case, which is fine for n ≤ 2000.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if b not in adj[a]:
                continue
            # Find smallest c > b such that c is connected to both a and b
            # Intersection of neighbors of a and b, but only those > b
            common = adj[a] & adj[b]
            for c in sorted(common):
                if c > b:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
