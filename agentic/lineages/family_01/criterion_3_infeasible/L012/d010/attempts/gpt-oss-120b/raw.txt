**Solution Explanation**

For a triple of distinct vertices `{a,b,c}` the three equilibrium equations are  

```
E(a,b)·Pb + E(a,c)·Pc = 0
E(b,a)·Pa + E(b,c)·Pc = 0
E(c,a)·Pa + E(c,b)·Pb = 0
```

`E(x,y)` is `1` if the edge `xy` exists, otherwise `0`.  
Writing them as a homogeneous linear system `M·P = 0`

```
          | 0  Eab  Eac |   |Pa|
M =       |Eab   0  Ebc| · |Pb| = 0
          |Eac Ebc   0 |   |Pc|
```

A non‑trivial solution exists **iff** `det(M) = 0`.  
For a symmetric matrix with zero diagonal

```
|0 a b|
|a 0 c|   det = 2·a·b·c
|b c 0|
```

Here `a = Eab , b = Eac , c = Ebc` are `0` or `1`.  
Therefore  

```
det(M) = 2   if   Eab = Eac = Ebc = 1   (the three edges are present)
det(M) = 0   otherwise
```

So a triple is *unresolvable* exactly when the three vertices form a **triangle**
(3‑cycle) in the given graph.

The task becomes:

*find the lexicographically smallest triangle* `a < b < c`.

--------------------------------------------------------------------

#### Finding the smallest triangle

`n ≤ 2000`, therefore a bitset of length `n` fits into a single Python integer
(`2000` bits ≈ 250 bytes).  
For every vertex `v` we store

```
adj[v] : integer, bit i is 1 ⇔ edge v‑i exists
nbr[v] : sorted list of neighbours of v   (for iteration)
```

For a fixed edge `a‑b` (`a < b`) the vertices that together with `a` and `b`
form a triangle are exactly the common neighbours:

```
common = adj[a] & adj[b]
```

We need a third vertex `c` larger than `b` (to keep `a<b<c`).  
Mask away all bits `≤ b`:

```
mask = ((1 << n) - 1) ^ ((1 << (b+1)) - 1)   # bits b+1 … n-1 are 1
common &= mask
```

If `common` is non‑zero, the least set bit gives the smallest possible `c`.
The first triangle discovered while iterating

```
a = 0 … n-1
    b = neighbours of a with b > a   (in increasing order)
        test common neighbours > b
```

is exactly the lexicographically smallest one, because `a` grows first,
then `b`, then the smallest possible `c`.

All operations on the bitsets are O(1) (single integer `&`), therefore the whole
algorithm runs in `O(m)` time and `O(n)` memory.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest unresolvable
(triangle) triple.

---

##### Lemma 1  
A triple `{a,b,c}` is unresolvable **iff** the three edges
`ab , ac , bc` are all present (i.e. `{a,b,c}` is a triangle).

**Proof.**  
From the discussion above the coefficient matrix of the system is

```
M = [[0, Eab, Eac],
     [Eab, 0, Ebc],
     [Eac, Ebc, 0]]
```

Its determinant equals `2·Eab·Eac·Ebc`.  
If all three edges exist, the determinant is `2 ≠ 0`, the only solution of
`M·P = 0` is the trivial one, therefore the triple is unresolvable.
If at least one edge is missing, the product is `0`, the determinant is `0`,
and a non‑trivial solution exists, so the triple is resolvable. ∎



##### Lemma 2  
During the execution, when the algorithm examines an edge `a‑b` (`a<b`),
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to **both**
`a` and `b`.

**Proof.**  
`adj[a]` has a `1`‑bit precisely for vertices adjacent to `a`.  
Bitwise `&` keeps a bit `1` only if it is `1` in both operands, i.e. the vertex
is adjacent to `a` **and** to `b`. ∎



##### Lemma 3  
After masking `common` with `mask`, the remaining set bits correspond exactly
to vertices `c` such that `c > b` and `{a,b,c}` is a triangle.

**Proof.**  
`mask` has `1`‑bits for indices `b+1 … n-1` and `0` elsewhere.
Thus `common & mask` removes all vertices `≤ b`.  
By Lemma&nbsp;2 the bits before masking are precisely the common neighbours of
`a` and `b`; after masking we keep those common neighbours that are larger than
`b`. ∎



##### Lemma 4  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The algorithm outputs only when `common & mask` is non‑zero.
By Lemma&nbsp;3 any vertex represented by a set bit after masking is a common
neighbour of `a` and `b` and larger than `b`.  
Hence edges `ab , ac , bc` all exist, i.e. `{a,b,c}` is a triangle. ∎



##### Lemma 5  
The first triangle output by the algorithm is the lexicographically smallest
triangle in the graph.

**Proof.**  
The outer loop enumerates `a` in increasing order.
For a fixed `a`, the inner loop enumerates neighbours `b` with `b>a` in increasing
order (the neighbour list is sorted).  
For a fixed pair `(a,b)` the algorithm chooses the smallest possible `c>b`
present in `common & mask` (the least set bit).  

Consider any triangle `{x,y,z}` with `x<y<z`.  
When the outer loop reaches `a = x`, the inner loop will eventually examine
`b = y` (since `y` is a neighbour of `x`). At that moment `c = z` is present in
`common & mask`, therefore the algorithm will output a triangle no later than
this point. Because all earlier `(a,b)` pairs are lexicographically smaller,
the first output triangle cannot be larger than `{x,y,z}`. ∎



##### Lemma 6  
The algorithm always outputs a triangle (the input guarantees at least one).

**Proof.**  
Since at least one triangle exists, let `{a₀,b₀,c₀}` be the lexicographically
smallest one. By Lemma&nbsp;5 the algorithm will output a triangle no later than
when it processes the pair `(a₀,b₀)`. Hence it certainly outputs a triangle. ∎



##### Theorem  
The algorithm prints three integers `a b c` (in increasing order) that form the
lexicographically smallest unresolvable triplet of modules.

**Proof.**  
By Lemma&nbsp;4 the printed triple is a triangle, therefore by Lemma&nbsp;1 it
is an unresolvable triplet.  
By Lemma&nbsp;5 it is the lexicographically smallest triangle, and consequently
the lexicographically smallest unresolvable triplet. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Memory*  
`adj` – `n` integers, each ≤ `2ⁿ` → `O(n)` bits (≈ 250 KB for `n=2000`).  
Neighbour lists – `2m` integers → `O(m)`.

*Time*  

```
building structures : O(m)
outer loop over edges : each edge examined once → O(m) bitwise ANDs
finding least set bit: O(1) using (x & -x).bit_length()
```

Overall `O(m)` ≤ `2·10⁵`, well inside the limits.  

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n                 # bitset adjacency
    nbr = [[] for _ in range(n)]  # neighbour lists

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u
        nbr[u].append(v)
        nbr[v].append(u)

    for lst in nbr:
        lst.sort()

    full_mask = (1 << n) - 1

    for a in range(n):
        for b in nbr[a]:
            if b <= a:
                continue
            common = adj[a] & adj[b]
            # keep only vertices with index > b
            mask = full_mask ^ ((1 << (b + 1)) - 1)
            common &= mask
            if common:
                # least set bit -> smallest c
                c_bit = common & -common
                c = c_bit.bit_length() - 1   # zero‑based index
                # output in 1‑based, already a<b<c
                print(a + 1, b + 1, c + 1)
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
