 We need to find a triplet of vertices such that the only solution to the given linear system is the zero vector.  

The equations for a triplet \( \{a,b,c\} \) are:

1. \( E(a,b) P_b + E(a,c) P_c = 0 \)  
2. \( E(b,a) P_a + E(b,c) P_c = 0 \)  
3. \( E(c,a) P_a + E(c,b) P_b = 0 \)  

Since the graph is undirected, \( E(u,v) = E(v,u) \).  
So the system becomes:

\[
\begin{cases}
E_{ab} P_b + E_{ac} P_c = 0 \\
E_{ab} P_a + E_{bc} P_c = 0 \\
E_{ac} P_a + E_{bc} P_b = 0
\end{cases}
\]

This is a homogeneous linear system in \( P_a, P_b, P_c \).  
It has only the trivial solution if and only if the determinant of the coefficient matrix is non-zero.

The coefficient matrix (with columns for \(P_a, P_b, P_c\)) is:

\[
\begin{pmatrix}
0 & E_{ab} & E_{ac} \\
E_{ab} & 0 & E_{bc} \\
E_{ac} & E_{bc} & 0
\end{pmatrix}
\]

The determinant is:

\[
0 \cdot (0 \cdot 0 - E_{bc} \cdot E_{bc}) - E_{ab} \cdot (E_{ab} \cdot 0 - E_{bc} \cdot E_{ac}) + E_{ac} \cdot (E_{ab} \cdot E_{bc} - 0 \cdot E_{ac})
\]

Simplify:

\[
= -E_{ab} \cdot (-E_{bc} E_{ac}) + E_{ac} \cdot (E_{ab} E_{bc})
= E_{ab} E_{bc} E_{ac} + E_{ac} E_{ab} E_{bc}
= 2 E_{ab} E_{bc} E_{ac}
\]

So the determinant is \( 2 E_{ab} E_{bc} E_{ac} \).  
This is non-zero if and only if all three edges exist in the triangle.  

Thus, the triplet is unresolvable exactly when the three vertices form a triangle in the graph.

So the problem reduces to: find the lexicographically smallest triangle in the graph.

We can do this by iterating over all triples \( (a,b,c) \) with \( a < b < c \) and checking if all three edges exist. Since \( n \le 2000 \), we can use an adjacency matrix for O(1) edge checks.

Complexity: \( O(n^3) \) worst-case, but with \( n=2000 \) that's \( 8 \times 10^9 \) which is too slow.  
We need a better approach.

We can instead iterate over each edge \( (a,b) \) and try to find a common neighbor \( c \) that is larger than both \( a \) and \( b \) to get the smallest triangle.  
We can store adjacency lists as sets for fast intersection.

Algorithm:
- Build adjacency sets.
- For each pair \( (a,b) \) with \( a < b \), if they are connected, find the smallest \( c > b \) such that \( c \) is connected to both \( a \) and \( b \).  
- Keep the smallest such triplet.

We can do this by iterating over all edges and checking neighbors.

Implementation:

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n)]
edges = []
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].add(v)
    adj[v].add(u)
    edges.append((u, v))

best = None
for a in range(n):
    for b in adj[a]:
        if b > a:
            # find smallest c > b connected to both
            for c in adj[a]:
                if c > b and c in adj[b]:
                    if best is None or (a, b, c) < best:
                        best = (a, b, c)
                    break  # since adj[a] is a set, iteration order not sorted, so we need to check all
            # Actually we need to find the smallest c, so we should iterate sorted
            # Let's do sorted intersection
            common = sorted(adj[a] & adj[b])
            for c in common:
                if c > b:
                    if best is None or (a, b, c) < best:
                        best = (a, b, c)
                    break

# Output 1-based
a, b, c = best
print(a+1, b+1, c+1)
```

But this still might be slow if we do it for every edge.  
We can optimize: iterate over a from 0 to n-1, then b from a+1 to n-1, check if edge exists, then find smallest c > b in intersection.

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].add(v)
    adj[v].add(u)

found = False
for a in range(n):
    for b in range(a+1, n):
        if b in adj[a]:
            # find smallest c > b connected to both
            for c in range(b+1, n):
                if c in adj[a] and c in adj[b]:
                    print(a+1, b+1, c+1)
                    found = True
                    break
            if found:
                break
    if found:
        break
```

This is \(O(n^3)\) but with early exit. Worst-case if no triangle until the very end, but the problem guarantees at least one triangle exists.  
Given \(n=2000\), worst-case \(8 \times 10^9\) is too much. But we can improve by using bitsets.

We can represent adjacency as bitsets (Python integers) and use bit operations to find common neighbors quickly.

```python
n, m = map(int, input().split())
adj_bits = [0] * n
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj_bits[u] |= 1 << v
    adj_bits[v] |= 1 << u

for a in range(n):
    for b in range(a+1, n):
        if (adj_bits[a] >> b) & 1:
            common = adj_bits[a] & adj_bits[b]
            # find smallest c > b
            mask = common & ~((1 << (b+1)) - 1)
            if mask:
                c = (mask & -mask).bit_length() - 1
                print(a+1, b+1, c+1)
                exit()
```

This is much faster: \(O(n^2)\) with bit operations.  
This will find the lexicographically smallest triangle because we iterate a and b in increasing order and pick the smallest c.

Final code:
