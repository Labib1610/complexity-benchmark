**Solution Explanation**

For three sensors `a < b < c` the rule *“no matter how you colour them with two colours,
some edge has both ends of the same colour”* is equivalent to saying that the
induced sub‑graph on `{a,b,c}` is **not bipartite**.
A graph with three vertices is non‑bipartite **iff it contains a triangle**
(the three edges `(a,b) , (a,c) , (b,c)`).

So we only have to find a triangle and output the lexicographically smallest
one.

--------------------------------------------------------------------

#### 1.   Data structures  

* `mask[v]` – an integer whose binary representation has a `1` at position `u`
  iff there is an edge `v – u`.  
  With `n ≤ 2000` the whole adjacency matrix fits into a 2000‑bit integer.
* `adj[v]` – list of neighbours of `v` (kept sorted).

Both structures are built while reading the input.

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle  

We iterate over the first vertex `a` in increasing order.
For a fixed `a` we look at its neighbours `b` with `b > a` (again in
increasing order).

```
common = mask[a] & mask[b]          # vertices adjacent to both a and b
common &= ~((1 << (b+1)) - 1)        # keep only vertices > b
```

If `common` is non‑zero, there exists a vertex `c > b` adjacent to both
`a` and `b`.  
The lowest set bit of `common` gives the smallest such `c`:

```
low = common & -common               # lowest 1‑bit
c   = low.bit_length() - 1
```

The first triple found in this order is exactly the lexicographically
smallest triangle, because we increase `a`, then `b`, then `c`.

The whole work per edge is a few bit operations → **O(m)** time,
`m ≤ 2·10⁵`.  
Memory consumption: `n` integers of at most 2000 bits → **O(n)**.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triple
`(a,b,c)` that forms a triangle.

---

##### Lemma 1  
For any three distinct vertices `x<y<z` the subgraph on `{x,y,z}` is not
2‑colourable **iff** the three edges `(x,y) , (x,z) , (y,z)` are present
(i.e. they form a triangle).

**Proof.**  
A graph on three vertices is bipartite unless it contains an odd cycle.
The only possible odd cycle is a 3‑cycle, which is exactly the triangle.
∎



##### Lemma 2  
When the algorithm processes a pair `(a,b)` (`a<b`) it finds the smallest
`c>b` such that `{a,b,c}` is a triangle, if such a `c` exists.

**Proof.**  
`common = mask[a] & mask[b]` contains precisely the vertices adjacent to
both `a` and `b`.  
After clearing bits `≤ b` only vertices `>b` remain.
If the resulting set is non‑empty, its lowest set bit corresponds to the
minimum vertex `c>b` belonging to the set. ∎



##### Lemma 3  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The triple is produced only when `common` (as defined above) is non‑empty.
Thus `c` is adjacent to `a` (because `c ∈ mask[a]`) and to `b`
(because `c ∈ mask[b]`).  
The outer loops guarantee that `b` is a neighbour of `a`.  
Hence all three edges are present – a triangle. ∎



##### Lemma 4  
Let `T* = (a*,b*,c*)` be the lexicographically smallest triangle in the
graph. The algorithm will output `T*`.

**Proof.**  
The outermost loop enumerates `a = 1,2,…`.  
All triangles with first vertex `< a*` are examined before any triangle
with first vertex `a*`. Since none exist, the first time a triangle can be
found is when `a = a*`.

For this fixed `a*`, the second loop enumerates neighbours `b>a*` in
increasing order. All triangles with the same `a*` and a smaller second
vertex than `b*` would have been discovered earlier, contradicting the
minimality of `b*`. Hence the first triangle found for `a*` uses `b = b*`.

Finally, by Lemma&nbsp;2 the algorithm chooses the smallest possible `c>b*`
that closes the triangle, i.e. `c = c*`. ∎



##### Theorem  
The algorithm always prints three integers `a<b<c` that form a triangle,
and among all such triples it prints the lexicographically smallest one.

**Proof.**  
Existence of at least one triangle is guaranteed by the statement of the
problem, therefore the algorithm will eventually encounter a pair `(a,b)`
with a non‑empty `common` and terminate.

By Lemma&nbsp;3 the printed triple is a triangle.
By Lemma&nbsp;4 it is the lexicographically smallest triangle.
∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building masks and adjacency lists* : `O(m)` time, `O(n+m)` memory.  

*Search* : each edge `(a,b)` with `a<b` is examined once, constant‑time
bit operations → `O(m)` time.  

Overall  

* **Time** `O(m)`  ( ≤ 2·10⁵, well inside the limit)  
* **Memory** `O(n)` (≈ 2000·2000 bits ≈ 0.5 MiB)

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    masks = [0] * n               # adjacency bitsets
    adj = [[] for _ in range(n)]  # neighbour lists

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        masks[u] |= 1 << v
        masks[v] |= 1 << u
        adj[u].append(v)
        adj[v].append(u)

    for lst in adj:
        lst.sort()

    for a in range(n):
        ma = masks[a]
        for b in adj[a]:
            if b <= a:
                continue
            # vertices adjacent to both a and b
            common = ma & masks[b]
            # keep only vertices > b
            common &= ~((1 << (b + 1)) - 1)
            if common:
                low = common & -common          # lowest set bit
                c = low.bit_length() - 1
                # output in 1‑based, sorted order
                print(a + 1, b + 1, c + 1)
                return

if __name__ == "__main__":
    solve()
```

to the required input‑output format.
