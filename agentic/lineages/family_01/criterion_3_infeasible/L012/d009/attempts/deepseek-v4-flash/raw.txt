We need to find a triplet of vertices such that for every 2-coloring of its three vertices, at least one edge inside the triplet has both endpoints the same color.  

This is equivalent to: the induced subgraph on the three vertices is **not** bipartite. Because a graph is bipartite if and only if it can be 2-colored with no monochromatic edge. So an unresolvable triplet is exactly a triangle (3-cycle) in the graph.  

Thus the problem reduces to: find the lexicographically smallest triangle in an undirected graph with up to 2000 vertices and 2e5 edges.  

We can iterate over all possible first vertex a from 1 to n, then over all possible second vertex b > a that is adjacent to a, and then check if there exists c > b adjacent to both a and b. To make this efficient, we can store adjacency as sets or boolean matrix.  

Since n ≤ 2000, a boolean adjacency matrix of size 2000×2000 is fine (4 million booleans). memory ~4 MB if using bitset or list of sets). We can use a list of sets for adjacency, and for each pair (a,b) check intersection of adjacency sets.  

We need lexicographically smallest triplet: iterate a in increasing order, then b in increasing order, then c in increasing order. The first found triangle is the answer.  

Complexity: O(n^2) in worst case if we check all pairs, but each check is O(degree) if using set intersection. With n=2000, worst-case O(n^3) if dense, but we can optimize: for each a, iterate over b in adj[a] with b>a, then iterate over c in adj[a] with c>b and check if c in adj[b]. That is O(sum over edges of degree) which can be O(n^3) in dense graph (2000^3 = 8e9 too large)..  

Better: Use bitsets. Represent adjacency as Python integers bitmask (n bits). Then for each a, for each b in adj[a] with b>a, compute common = adj[a] & adj[b] & mask_greater_than_b. If common != 0, pick smallest bit set. This is O(n^2) bit operations, each on 2000-bit integers (fast in Python).. n=2000 → ~4 million iterations, each with a few bit ops, feasible.  

We need to output the smallest c > b in common. We can find lowest set bit using (common & -common).bit_length()-1 or use bit_length on common.  

Let's implement.  

Edge case: graph may have multiple triangles; we need lexicographically smallest. Our iteration order ensures that.  

Let's write the code.```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * (n + 1)
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(1, n + 1):
        # b must be > a and adjacent to a
        bmask = adj[a] & ~((1 << (a + 1)) - 1)
        while bmask:
            low = bmask & -bmask
            b = low.bit_length() - 1
            bmask ^= low

            # c must be > b and adjacent to both a and b
            cmask = adj[a] & adj[b] & ~((1 << (b + 1)) - 1)
            if cmask:
                lowc = cmask & -cmask
                c = lowc.bit_length() - 1
                print(a, b, c)
                return

if __name__ == "__main__":
    main()
