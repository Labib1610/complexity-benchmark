Looking at this problem, I need to find a triangle (3-clique) in an undirected graph, and output the lexicographically smallest one.

**Key insight:** For the lexicographically smallest triangle, I want to minimize `a` first. So I should iterate `a` from 1 to n, and for each `a`, check if there's a triangle containing `a` where `a` is the smallest vertex. If found, among all such triangles, pick the one with smallest `b`, then smallest `c`.

**Algorithm:**
1. For each vertex `a` from 1 to n:
   - Let `S` be the set of neighbors of `a` that are greater than `a`
   - For each `b` in `S` (in increasing order):
     - For each `c` in `S` where `c > b` and edge `(b,c)` exists:
       - Return `a b c` (first found is lexicographically smallest for this `a`)
   - If any triangle found for this `a`, return immediately (since we iterate `a` in increasing order)

**Complexity analysis:**
- For each `a`, we iterate over pairs of neighbors. The total work is bounded by summing over all edges `(a,b)` where `a < b`, the degree of `a` (restricted to neighbors > `a`).
- This is at most O(m * d_max) where d_max ≤ n. With m ≤ 2×10^5 and n ≤ 2000, worst case is 4×10^8, but in practice much less since we stop early and the constraint m ≤ n(n-1)/2 with the triangle guarantee limits dense subgraphs.

To optimize, I'll use bitsets for adjacency to make the edge check O(1) and potentially use bit operations for finding common neighbors.

Let me use Python integers as bitsets for adjacency rows - this gives fast intersection operations.

```python
import sys

def solve():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [0] * (n + 1)  # adj[v] is a bitmask of neighbors
    
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        adj[u] |= (1 << v)
        adj[v] |= (1 << u)
    
    for a in range(1, n + 1):
        # neighbors of a that are > a
        mask_a = adj[a] & ~((1 << (a + 1)) - 1)  # bits > a
        # iterate b in increasing order
        b = a + 1
        while b <= n and mask_a:
            if not (mask_a >> b) & 1:
                b += 1
                continue
            # look for c > b in mask_a that is also neighbor of b
            mask_b = adj[b] & mask_a & ~((1 << (b + 1)) - 1)
            if mask_b:
                # find lowest set bit = smallest c
                c = (mask_b & -mask_b).bit_length() - 1
                print(f"{a} {b} {c}")
                return
            b += 1
    
    # Should not reach here per problem guarantee
    print("-1 -1 -1")

solve()
```

Wait, there's an issue: when n=2000, `1 << 2000` is a huge number but Python handles big integers fine. However, the `~((1 << (a+1)) - 1)` creates negative numbers in Python. Let me fix this by using a different masking approach.

Actually in Python, `~` on integers gives negative numbers due to two's complement with infinite bits. I should use `& ((1 << (n+1)) - 1)` to mask to valid range, and use subtraction instead of `~`.

Let me reconsider: to get bits > a, I can compute `adj[a] >> (a+1)` then shift back, or use `adj[a] & (((1 << (n+1)) - 1) ^ ((1 << (a+1)) - 1))`.

```python
import sys

def solve():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [0] * (n + 1)
    
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        adj[u] |= (1 << v)
        adj[v] |= (1 << u)
    
    full_mask = (1 << (n + 1)) - 1
    
    for a in range(1, n + 1):
        # neighbors of a that are > a
        mask_a = adj[a] & (full_mask ^ ((1 << (a + 1)) - 1))
        b = a + 1
        while b <= n and mask_a:
            if not (mask_a >> b) & 1:
                b += 1
                continue
            mask_b = adj[b] & mask_a & (full_mask ^ ((1 << (b + 1)) - 1))
            if mask_b:
                c = (mask_b & -mask_b).bit_length() - 1
                print(f"{a} {b} {c}")
                return
            b += 1
    
    print("-1 -1 -1")

solve()
```

This should work. The bit operations make finding the smallest `c` for a given `(a,b)` O(1). The overall complexity is O(n * d_max) for the outer loops plus bit operations, which should be efficient enough.

Let me verify with the examples:
- Example 1: a=1, mask_a has bits 2,3 (neighbors >1). b=2: mask_b = adj[2] & mask_a & (>2) = {1,3,4} & {2,3} & {3,4,...} = {3}. c=3. Output: 1 2 3 ✓
- Example 2: a=1, mask_a = {2,4}. b=2: mask_b = adj[2] & {2,4} & (>2) = {1,4} & {2,4} & {3,4,5} = {4}. c=4. Output: 1 2 4 ✓
