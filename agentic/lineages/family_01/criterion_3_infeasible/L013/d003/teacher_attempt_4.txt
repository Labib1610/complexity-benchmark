# Problem C — Triple Redundancy Fault

Time limit: 2 s   Memory limit: 256 MB

A distributed database system consists of $n$ storage clusters, numbered 1 through $n$. To ensure high availability, the architecture relies on $m$ active peer-to-peer data pipes. Each pipe connects a specific pair of clusters, allowing them to mirror their records in real time.

The system's consensus algorithm is robust, except for one critical vulnerability: a "triple redundancy fault". This fault occurs whenever there is a group of exactly three clusters where each cluster in the group has a direct data pipe to the other two. When this happens, update packets circulate endlessly among the three clusters, degrading overall performance. Diagnostics confirm that the current configuration suffers from at least one such fault.

To resolve the issue, you must identify a set of three clusters causing this fault.

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n(n-1)/2, 2 \cdot 10^5)$).
The following $m$ lines each contain two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), representing an active data pipe between cluster $u$ and cluster $v$. Each data pipe is listed at most once.
It is guaranteed that at least one triple redundancy fault exists in the system.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, representing the cluster numbers involved in a triple redundancy fault. The cluster numbers must be printed in ascending order ($a < b < c$).
If there are multiple such faults, you must output the one that is lexicographically smallest. That is, minimize $a$; if there is a tie, minimize $b$; and if there is still a tie, minimize $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
