We need to find the lexicographically smallest triangle in an undirected graph.  
A direct brute force over all triples would be too slow for \( n = 2000 \), but we can do it efficiently by iterating over edges and checking common neighbors.

Here’s the approach:

- Represent the graph as an adjacency set for fast lookups.
- Iterate over all edges `(u, v)` with `u < v`.
- For each such edge, check all neighbors `w` of `u` where `w > v` and check if `(v, w)` is also an edge.
- Keep track of the smallest triple found.

Since we iterate edges and for each check neighbors, the worst-case is \( O(m \cdot \Delta) \), which is acceptable for the given limits.

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
        if u > v:
            u, v = v, u
        edges.append((u, v))
    
    edges.sort()
    
    for u, v in edges:
        for w in adj[u]:
            if w > v and w in adj[v]:
                print(u, v, w)
                return

if __name__ == "__main__":
    solve()
```
