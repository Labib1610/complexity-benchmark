We can solve this by checking each possible smallest vertex `a` in increasing order, then looking for a triangle that includes `a` and has the smallest possible `b` and `c`.

A direct approach:  
For each `a` from 1 to n, check all pairs `(b, c)` where `b > a`, `c > b`, and edges exist `(a,b)`, `(b,c)`, `(c,a)`.  
But that would be too slow if done naively.

We can optimize:  
For each `a`, we only need to check neighbors of `a` that are greater than `a`.  
For each such neighbor `b`, we look for a neighbor `c` of `b` that is also a neighbor of `a` and greater than `b`.  
We can store adjacency in sets for O(1) lookups.

Since `n ≤ 2000`, we can afford O(n * degree(a) * degree(b)) in the worst case, but we can break early once we find the lexicographically smallest triangle.

Here’s the implementation:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in sorted(adj[a]):
            if b <= a:
                continue
            for c in sorted(adj[b]):
                if c <= b:
                    continue
                if c in adj[a]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    solve()
```
