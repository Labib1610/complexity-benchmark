**Solution Explanation**

For every worker we store the set of his conflicts as a bitset.
`bit i` (0‑based) is `1` iff the worker conflicts with worker `i+1`.

```
adj[v]   – integer, bitset of neighbours of vertex v (0‑based)
neigh[v] – sorted list of neighbours of v (1‑based values)
```

A triangle `a < b < c` exists iff for some edge `a‑b`

```
c ∈ neighbours(a) ∩ neighbours(b)   and   c > b
```

Because we scan `a` from `1 … n` and for each `a` scan `b` in increasing
order, the first triangle we meet is the lexicographically smallest one.

Finding the smallest `c` :

```
common = adj[a] & adj[b]                # all common neighbours (0‑based)
# keep only vertices with index > b-1
mask   = common >> (b)                  # shift away bits 0 … b-1
if mask != 0:
        # lowest set bit of mask
        low   = mask & -mask
        pos   = low.bit_length() - 1    # position inside mask
        c = b + 1 + pos                 # back to 1‑based numbering
```

The whole algorithm:

```
for a = 1 … n:
        for b in neigh[a] with b > a:
                common = adj[a-1] & adj[b-1]
                mask   = common >> b
                if mask:
                        c = b + 1 + (mask & -mask).bit_length() - 1
                        output a, b, c and stop
```

`n ≤ 2000`, therefore each bitset fits into a Python `int`
(2000 bits ≈ 250 bytes).  
The loop processes each undirected edge once → `O(m)` time,
`O(n + m)` memory.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triangle.

---

**Lemma 1**  
For any vertices `a < b`, `mask` computed above is non‑zero
iff there exists a vertex `c > b` such that edges `a‑c` and `b‑c` are present.

*Proof.*  
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to both
`a` and `b`. Shifting right by `b` removes bits for vertices `≤ b`.
Thus `mask` contains a `1` exactly for vertices `c` with `c > b`
that are common neighbours. ∎



**Lemma 2**  
If `mask` is non‑zero, the algorithm computes `c` equal to the smallest
vertex `c > b` that together with `a,b` forms a triangle.

*Proof.*  
`mask & -mask` isolates the lowest set bit of `mask`. Its position `pos`
(0‑based) is the smallest index inside `mask`. Adding back the shift amount `b`
gives vertex index `c = b + 1 + pos`, which is the smallest `c > b`
present in `mask`. By Lemma&nbsp;1 such a `c` is a common neighbour,
hence `(a,b,c)` is a triangle, and no smaller `c` works. ∎



**Lemma 3**  
When the algorithm outputs a triple `(a,b,c)`, it is a triangle
(`a‑b`, `a‑c`, `b‑c` are edges) and satisfies `a < b < c`.

*Proof.*  
`b` is taken from `neigh[a]` with `b > a`, so `a‑b` is an edge and `a<b`.  
By Lemma&nbsp;2 the computed `c` is a common neighbour of `a` and `b`,
hence edges `a‑c` and `b‑c` exist, and `c > b`. ∎



**Lemma 4**  
Let `(a₀,b₀,c₀)` be the first triangle output by the algorithm.
For any triangle `(a,b,c)` we have `(a₀,b₀,c₀)` ≤lex `(a,b,c)`.

*Proof.*  
The outer loop enumerates `a` in increasing order.
The inner loop enumerates, for this `a`, all `b>a` in increasing order.
Thus the algorithm examines all candidate pairs `(a,b)` in lexicographic order.
For a fixed `(a,b)` it chooses the smallest possible `c` (Lemma&nbsp;2).
Consequently the first triple found is lexicographically minimal among all
triangles. ∎



**Theorem**  
The algorithm always terminates and prints the lexicographically smallest
triple of workers that are pairwise in conflict.

*Proof.*  
The input guarantees at least one triangle, so some iteration will satisfy
`mask != 0`. At that moment the algorithm outputs a triple and stops,
hence it terminates. By Lemma&nbsp;3 the printed triple is a triangle,
and by Lemma&nbsp;4 it is the lexicographically smallest one. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building structures* : `O(m)` time, `O(n + m)` memory.  
*Main loops* : each undirected edge `(a,b)` with `a<b` is processed once,
constant‑time bit operations → `O(m)` time.  

Overall  

```
Time   : O(m)   ( ≤ 2·10^5 )
Memory : O(n + m)  ( ≤ about 3·10^5 integers )
```

Both satisfy the limits.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # adjacency as bitsets (0‑based)
    adj = [0] * n
    # neighbour lists for ordered iteration
    neigh = [[] for _ in range(n)]

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        if u == v:
            continue
        # set bits
        adj[u] |= 1 << v
        adj[v] |= 1 << u
        # store for later ordered traversal
        if u < v:
            neigh[u].append(v + 1)   # store 1‑based for easy output
        else:
            neigh[v].append(u + 1)

    # sort neighbour lists (they are already increasing because we added only when u<v)
    # but to be safe:
    for lst in neigh:
        lst.sort()

    for a in range(1, n + 1):
        a_idx = a - 1
        for b in neigh[a_idx]:
            if b <= a:
                continue
            b_idx = b - 1
            common = adj[a_idx] & adj[b_idx]
            # keep only vertices with index > b_idx
            mask = common >> b
            if mask:
                # lowest set bit
                low = mask & -mask
                pos = low.bit_length() - 1
                c = b + 1 + pos
                # output in increasing order
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```
