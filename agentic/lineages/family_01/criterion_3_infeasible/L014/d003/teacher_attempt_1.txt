# Problem C — Concurrency Fallback Trigger

Time limit: 2 s   Memory limit: 256 MB

A database system is attempting to process a batch of concurrent transactions. Certain pairs of transactions have overlapping write requests and cannot be executed in the same batch processing thread.

The current set of transactions cannot be scheduled using the standard two-thread pool. To trigger the fallback execution mode, you must provide a minimal proof of this scheduling impossibility. You do not need to attempt a safe schedule yourself.

Specifically, you must identify a subset of exactly three distinct transactions which are completely mutually incompatible. Whenever any two transactions are chosen from this subset of three, there must be a recorded overlap between them. Because no two transactions in such a subset can share a thread, they prove that at least three threads are required.

## Input
The first line contains two integers $n$ and $m$, representing the number of transactions and the number of overlapping pairs. A batch always contains at least three transactions to justify processing, up to a maximum capacity of two thousand transactions. The logging system records at least three overlaps and is physically limited to storing two hundred thousand records (or the total possible number of transaction pairs, if that is smaller). Transactions are numbered from $1$ to $n$.

Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating that an overlap exists between transaction $u$ and transaction $v$.

It is guaranteed that the batch contains at least one subset of three transactions satisfying the fallback criteria.

## Output
Print three integers $a$, $b$, and $c$ on a single line with $a < b < c$, representing the IDs of the three transactions that form the proof.
If there are multiple valid sets of three transactions, output the one that is lexicographically smallest (i.e., smallest $a$; ties broken by smallest $b$; then smallest $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
