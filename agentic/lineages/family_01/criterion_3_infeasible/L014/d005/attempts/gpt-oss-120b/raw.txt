**Solution Explanation**

For three different vertices `a < b < c` we have to decide whether they form a
*deadlock*.

For a vertex `x` the condition  

*“the other two vertices have the same prohibition status with respect to `x`”*  

means that `x` is either connected to **both** of the other vertices or to **none**
of them.
Therefore for the whole triple the only possible adjacency patterns are

* no edges – forbidden because a deadlock must contain at least one prohibited
  pair,
* all three edges – a **triangle**,
* any other pattern – violates the “same status” rule for at least one vertex.

Consequently a deadlock is exactly a triangle in the given graph.
The task becomes:

> find the lexicographically smallest triangle `(a,b,c)` (`a<b<c`).

--------------------------------------------------------------------

#### 1.   Data structure – bitsets

`n ≤ 2000`, therefore an `int` (unlimited length in Python) can store the whole
neighbour set of a vertex:

```
mask[v]  – integer, bit (u‑1) is 1  ⇔  (v,u) is a prohibited pair
```

All masks are built in `O(m)`.

Checking whether an edge `(x,y)` exists is a single bit test:

```
(mask[x] >> (y-1)) & 1
```

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle

We iterate over all ordered pairs `(a,b)` with `a < b`.
If the edge `(a,b)` is present we look for a common neighbour `c` that is larger
than `b`.

```
common = mask[a] & mask[b]          # vertices adjacent to both a and b
common >>= b                        # discard vertices ≤ b
if common != 0:
        # the least set bit gives the smallest possible c
        lsb = (common & -common).bit_length() - 1
        c = b + 1 + lsb
        answer = (a,b,c)   # this is the lexicographically first triangle
        stop
```

Why does this give the lexicographically first triangle?

* The outer loops increase `a` first, then `b`.  
  The first time we find a suitable `c` we have the smallest possible `a`,
  and for this `a` the smallest possible `b`.
* Inside the pair we take the *smallest* `c > b` (the least set bit).

Thus the produced triple is exactly the required minimum.

Complexity
* building masks: `O(m)`
* outer loops: at most `m` pairs (only edges are processed)
* each pair: bitwise `&` and a shift on an integer of at most 2000 bits  
  → `O(1)` in practice (≈ 32 machine words)
* total time `O(m)`  ( ≤ 2·10⁵ )
* memory: `n` integers, each ≤ 2ⁿ → `O(n)` (≈ 2000·256 bytes)

Both limits are far below the given constraints.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest deadlock
(triangle).

---

##### Lemma 1  
A triple of vertices satisfies the deadlock conditions **iff** it is a triangle
(all three edges are present).

**Proof.**  
For any vertex `x` of the triple the other two vertices must have identical
adjacency status to `x`. Hence `x` is either adjacent to both of them or to none.
If any edge is missing, the endpoint of that missing edge is adjacent to exactly
one of the other two vertices, contradicting the rule.  
Conversely, in a triangle each vertex is adjacent to the other two, satisfying
the rule, and at least one edge exists. ∎



##### Lemma 2  
When the algorithm examines a pair `(a,b)` with `a<b` and finds a vertex `c`
as described, the triple `(a,b,c)` is a triangle.

**Proof.**  
`common = mask[a] & mask[b]` contains exactly the vertices adjacent to **both**
`a` and `b`. After shifting away vertices `≤ b`, any remaining set bit corresponds
to a vertex `c > b` that is adjacent to `a` **and** to `b`. Therefore edges
`(a,c)` and `(b,c)` exist, and we already know `(a,b)` exists (the pair is
processed only if that edge is present). All three edges are present, i.e. a
triangle. ∎



##### Lemma 3  
If the algorithm outputs `(a,b,c)`, no triangle `(a',b',c')` with
lexicographically smaller order exists.

**Proof.**  
The outer loops enumerate pairs `(a,b)` in increasing lexicographic order:
first by `a`, then by `b`. The algorithm stops at the first pair for which a
suitable `c` is found. Hence for any earlier pair `(a',b')` either the edge
`(a',b')` is absent or there is **no** common neighbour larger than `b'`. In the
first case no triangle can start with `(a',b')`; in the second case any triangle
containing `(a',b')` would need a third vertex `c' ≤ b'`, contradicting the
required ordering `a'<b'<c'`. Therefore no triangle precedes `(a,b,c)` lexicographically. ∎



##### Lemma 4  
If a triangle exists, the algorithm will find one.

**Proof.**  
Take the lexicographically smallest triangle `(a\*,b\*,c\*)`. Its edge `(a\*,b\*)`
appears in the enumeration, because the algorithm iterates over **all** edges.
When processing this pair, `c\*` is a common neighbour of `a\*` and `b\*` and
`c\* > b\*`. Hence after the shift `common` still contains the bit of `c\*`,
so the algorithm will detect a non‑zero `common` and output a triangle (maybe
with an even smaller `c`, but still ≥ `b\*+1`). Thus it never fails to output. ∎



##### Theorem  
The algorithm always outputs the lexicographically smallest deadlock
(triangle) of the given graph.

**Proof.**  
By Lemma&nbsp;1 deadlocks are exactly triangles.  
Lemma&nbsp;4 guarantees the algorithm outputs some triangle.  
Lemma&nbsp;2 shows the produced triple is indeed a triangle.  
Lemma&nbsp;3 proves that this triangle is lexicographically minimal among all
triangles. Therefore it is the required answer. ∎

#### 4.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    masks = [0] * (n + 1)          # 1‑based
    edges = []                     # list of (u,v) with u<v

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u > v:
            u, v = v, u
        masks[u] |= 1 << (v - 1)
        masks[v] |= 1 << (u - 1)
        edges.append((u, v))

    # sort edges to guarantee lexicographic order of (a,b)
    edges.sort()

    for a, b in edges:
        # common neighbours of a and b
        common = masks[a] & masks[b]
        # discard vertices <= b
        common >>= b
        if common:
            # least significant set bit
            lsb = (common & -common).bit_length() - 1
            c = b + 1 + lsb
            sys.stdout.write(f"{a} {b} {c}\n")
            return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
