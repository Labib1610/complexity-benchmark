We need to find the lexicographically smallest triple \((a,b,c)\) with \(a<b<c\) such that:

1. At least one edge exists among the three.
2. For any two of them, their adjacency to the third is the same.

That means for triple \((a,b,c)\):

- \( \text{adj}(a,b) = \text{adj}(a,c) \)  
- \( \text{adj}(b,a) = \text{adj}(b,c) \)  
- \( \text{adj}(c,a) = \text{adj}(c,b) \)

Where adjacency is symmetric.

We can brute force over all triples in increasing order and check the condition.  
Since \(n \le 2000\), \(O(n^3)\) is too slow. We need a smarter approach.

---

**Observation:**  
For a triple \((a,b,c)\) to satisfy condition 2, the three vertices must have identical adjacency patterns to each other.  
That means the induced subgraph on \(\{a,b,c\}\) is either:

- A triangle (all edges present)
- An independent set (no edges)
- A star with one vertex connected to the other two, but the two leaves are not connected.

But condition 1 says at least one edge must exist, so the triple cannot be an independent set.

So the valid triples are either:

- A triangle (all 3 edges)
- A "V" shape: one vertex connected to the other two, but the two others not connected.

We need the lexicographically smallest such triple.

---

**Approach:**  
We can iterate over possible smallest vertex \(a\) from 1 to n.  
For each \(a\), we look at its neighbors and non-neighbors.

If \(a\) has at least two neighbors \(b,c\) such that \(b\) and \(c\) are not connected, then \((a,b,c)\) is a valid V-shape.  
If \(a\) has two neighbors \(b,c\) that are connected, then \((a,b,c)\) is a triangle.

We want the lexicographically smallest triple overall.  
So we can iterate \(a\) from 1 to n, and for each \(a\), try to find the smallest possible \(b\) and \(c\) that satisfy the condition.

---

**Algorithm:**

1. Read graph as adjacency matrix (boolean) for O(1) edge checks.
2. For \(a\) from 1 to n:
   - Let neighbors = sorted list of neighbors of \(a\).
   - For each pair \((b,c)\) with \(b<c\) from neighbors:
     - If edge(b,c) exists → triangle found.  
       Check if \((a,b,c)\) is lexicographically smaller than current best.
     - Else → V-shape found.  
       Check if \((a,b,c)\) is lexicographically smaller.
   - Also consider non-neighbors:  
     For V-shape, the center could be \(b\) or \(c\) instead of \(a\).  
     But since we iterate \(a\) as smallest, we only need to check cases where \(a\) is the smallest vertex.  
     So we only need to check triples where \(a\) is smallest.  
     That means we only need to consider \(a\) as the smallest vertex in the triple.  
     So we only check triples where \(a\) is connected to both \(b\) and \(c\) (since if \(a\) is smallest and not connected to one of them, then the triple would be independent or have the edge elsewhere, but we can still check all possibilities).

Actually, to be safe, we can check all triples with \(a\) smallest by iterating \(b\) and \(c\) from \(a+1\) to n, but that's \(O(n^3)\) again.

Better:  
For each \(a\), we only need to consider \(b\) and \(c\) that are neighbors of \(a\) (for triangle or V with center \(a\)).  
But what if the triple is a V with center \(b\) (where \(b>a\))?  
Then \(a\) and \(c\) are both neighbors of \(b\), but \(a\) and \(c\) are not connected.  
In that case, \(a\) is not necessarily connected to \(c\).  
So we must also check triples where \(a\) is not connected to one of the others.

---

**Better approach:**  
We can iterate over all pairs \((a,b)\) with \(a<b\) and check if there exists a \(c\) such that the triple is valid.  
But we need lexicographically smallest, so we can break early.

We can do:

For \(a\) from 1 to n:
  For \(b\) from \(a+1\) to n:
    For \(c\) from \(b+1\) to n:
      Check condition.  
But that's \(O(n^3)\) — too slow for n=2000.

---

**Optimization:**  
We can precompute for each pair \((a,b)\) the set of common neighbors and common non-neighbors.

For a triple \((a,b,c)\) to be valid:

- If edge(a,b) exists:
  - Then we need edge(a,c) == edge(b,c) (both true or both false).
- If edge(a,b) does not exist:
  - Then we need edge(a,c) == edge(b,c) as well.

So the condition is:  
For all pairs among the three, the adjacency to the third is the same.

That means:  
For triple \((a,b,c)\), we need:
- adj(a,b) == adj(a,c)
- adj(b,a) == adj(b,c)
- adj(c,a) == adj(c,b)

Since adjacency is symmetric, this is equivalent to:
- adj(a,b) == adj(a,c)
- adj(a,b) == adj(b,c)

So the three edges among the triple are either all present or all absent, or exactly one is present and the other two absent?  
Wait, let's check:

If adj(a,b) = 1, adj(a,c) = 1, then adj(b,c) must be 1 (from second condition). So triangle.

If adj(a,b) = 0, adj(a,c) = 0, then adj(b,c) must be 0. So independent set.

If adj(a,b) = 1, adj(a,c) = 0, then from first condition adj(b,c) must be 0 (since adj(a,b) == adj(b,c)).  
So we have exactly one edge (a,b) and the other two absent. That's a V with center a.

Similarly, if adj(a,b) = 0, adj(a,c) = 1, then adj(b,c) = 1? Wait:  
From adj(a,b) == adj(a,c) → 0 == 1 false, so invalid.  
So the only valid patterns are:
- All edges present (triangle)
- No edges (independent set) — but condition 1 says at least one edge, so invalid.
- Exactly one edge present (V shape).

So valid triples are either triangles or V-shapes.

---

**Plan:**  
We can iterate over all pairs \((a,b)\) with \(a<b\).  
For each pair, we know if they are connected.  
We need to find the smallest \(c > b\) such that the triple is valid.

If edge(a,b) exists:
- We need c such that edge(a,c) == 1 and edge(b,c) == 1 (triangle)  
  OR edge(a,c) == 0 and edge(b,c) == 0 (but that would be independent set, invalid because at least one edge exists — but we already have edge(a,b), so that's fine? Wait, if edge(a,b)=1, and edge(a,c)=0, edge(b,c)=0, then we have exactly one edge, which is valid V-shape with center a or b?  
  Let's check:  
  If edge(a,b)=1, edge(a,c)=0, edge(b,c)=0 →  
  Condition: adj(a,b)=1, adj(a,c)=0 → must be equal? No, they are not equal, so invalid.  
  So for edge(a,b)=1, we must have adj(a,c) == adj(b,c).  
  So either both 1 (triangle) or both 0 (but then adj(a,b)=1, adj(a,c)=0 → not equal, so invalid).  
  So only triangle works when edge(a,b)=1.

If edge(a,b)=0:
- We need adj(a,c) == adj(b,c).  
  If both 0 → independent set (invalid).  
  If both 1 → then we have edges (a,c) and (b,c), but not (a,b) → V-shape with center c. Valid.

So:

- If edge(a,b)=1: need c such that edge(a,c)=1 and edge(b,c)=1.
- If edge(a,b)=0: need c such that edge(a,c)=1 and edge(b,c)=1.

So in both cases, we need a common neighbor c of both a and b!  
And c must be > b for lexicographic order.

So the problem reduces to:  
Find the smallest triple (a,b,c) with a<b<c such that a and b have a common neighbor c, and the triple is not an independent set (which it won't be because c is connected to both).

Wait, but if a and b are connected, and c is common neighbor, then triangle.  
If a and b are not connected, and c is common neighbor, then V-shape with center c.  
Both are valid.

So we just need to find the lexicographically smallest triple where a and b have a common neighbor c > b.

---

**Algorithm:**

1. Read graph as adjacency matrix (boolean).
2. For a from 1 to n:
   - For b from a+1 to n:
     - Find the smallest c > b such that edge(a,c) and edge(b,c) are both true.
     - If found, output (a,b,c) and exit.

We need to do this efficiently.  
For each pair (a,b), finding smallest common neighbor > b can be done by precomputing adjacency lists sorted.

We can precompute for each vertex a sorted list of neighbors.  
Then for pair (a,b), we can merge their neighbor lists to find smallest common > b.

Complexity:  
There are O(n^2) pairs, each merge O(deg(a)+deg(b)) worst-case O(n).  
n=2000 → O(n^3) worst-case ~8e9 too slow.

We need better.

---

**Optimization:**  
We can iterate a from 1 to n, and for each a, we want to find smallest b>a and c>b such that a,b,c form valid triple.

We can precompute for each a the list of neighbors sorted.  
For each a, we can iterate b from a+1 to n, and check if there is a common neighbor > b.

We can precompute for each pair (a,b) the smallest common neighbor > b using bitsets.

Since n ≤ 2000, we can use Python integers as bitsets for adjacency.  
For each vertex, store an integer bitmask of neighbors.  
Then for pair (a,b), common neighbors = adj[a] & adj[b].  
We need the smallest bit > b.

We can precompute for each pair (a,b) the smallest common neighbor > b by scanning bits, but that's O(n^3) again.

But we can do:  
For each a, for each b>a, compute common = adj[a] & adj[b].  
Then find smallest set bit > b.  
We can do this by masking out bits ≤ b: common &= ~((1 << (b+1)) - 1).  
Then find lowest set bit.

Since n=2000, we can use Python's int bit operations which are fast.  
Number of pairs ~2 million, each operation O(1) on 2000-bit ints (which is ~32 machine words).  
That's feasible.

---

**Implementation steps:**

1. Read n, m.
2. Initialize adj as list of ints of length n+1, all 0.
3. For each edge (u,v): set bit v in adj[u], bit u in adj[v].
4. For a from 1 to n:
   - For b from a+1 to n:
     - common = adj[a] & adj[b]
     - mask = (1 << (b+1)) - 1  # bits 0..b
     - common &= ~mask
     - if common != 0:
         c = (common & -common).bit_length() - 1  # lowest set bit index
         # c is > b
         print(a,b,c)
         exit

We need to be careful with 1-based indexing: we'll use bits 1..n.

This works and is efficient.

Let's write the code.```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * (n + 1)
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u] |= (1 << v)
        adj[v] |= (1 << u)
    
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            common = adj[a] & adj[b]
            # keep only bits > b
            mask = (1 << (b + 1)) - 1
            common &= ~mask
            if common:
                # lowest set bit
                c = (common & -common).bit_length() - 1
                print(a, b, c)
                return

if __name__ == "__main__":
    main()
```
