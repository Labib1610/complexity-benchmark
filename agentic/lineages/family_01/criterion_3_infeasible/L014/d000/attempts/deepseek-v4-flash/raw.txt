We can solve this by checking all triples, but that would be too slow for large n.  
Instead, we can use the fact that if the graph is not bipartite, it contains a triangle in the complement? Actually, we need a triangle in the original graph.

A more efficient approach:  
We can find a triangle in an undirected graph in O(n + m) time using BFS or DFS with parent tracking.  
But here we need the lexicographically smallest triangle.

We can iterate over the first vertex `a` from 1 to n, then for each neighbor `b > a`, check if there is a common neighbor `c > b`.  
To make this fast, we can store adjacency as sets and check intersections.

Since n ≤ 2000, we can do:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(n):
        for b in adj[a]:
            if b > a:
                common = adj[a] & adj[b]
                for c in common:
                    if c > b:
                        print(a+1, b+1, c+1)
                        return

if __name__ == "__main__":
    solve()
```
