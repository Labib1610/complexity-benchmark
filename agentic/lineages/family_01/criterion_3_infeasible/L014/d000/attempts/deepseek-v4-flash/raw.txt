We can solve this by checking each triple in lexicographic order and verifying if it forms a triangle in the graph.

Since \( n \) can be up to 2000, checking all triples naively would be \( O(n^3) \), which is too slow.  
We can instead use adjacency sets and iterate over edges to find triangles efficiently.

Here’s the approach:

- Store the graph as an adjacency set for fast lookups.
- Iterate over all edges \((u, v)\).
- For each edge, check all common neighbors \( w \) such that \( w > v \) to ensure lexicographic order and avoid duplicates.
- The first triangle found in this order will be lexicographically smallest.

We can sort the edges by their endpoints to ensure we check in lexicographic order.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        if u > v:
            u, v = v, u
        edges.append((u, v))
        adj[u].add(v)
        adj[v].add(u)
    
    edges.sort()
    
    for u, v in edges:
        # Find common neighbors w > v
        common = adj[u] & adj[v]
        for w in sorted(common):
            if w > v:
                print(u, v, w)
                return

if __name__ == "__main__":
    main()
```
