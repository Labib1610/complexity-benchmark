# Problem C — Cargo Prohibition Protocol

Time limit: 2 s   Memory limit: 256 MB

A logistics firm operates a shipping route for hazardous materials. Certain pairs of these materials are highly reactive and are strictly prohibited from sharing a vessel.

The proposed loading schedule is structurally impossible to fulfill. You must produce a definitive proof of this impossibility to trigger an automatic schedule rejection.

To establish this proof, you are required to isolate a "deadlock" configuration consisting of exactly three distinct materials. A configuration of three materials is deemed a deadlock if and only if they cannot be safely transported by a standard dual-hold cargo ship. Specifically, if you were to consider just those three materials, it must be impossible to assign each of them to either Hold A or Hold B such that neither hold ends up containing a prohibited pair.

Because the automated auditing system requires deterministic reporting, it will not accept an arbitrary deadlock configuration. The system demands the canonical proof, meaning you must systematically ensure no earlier configuration could have been reported.

## Input
The first line provides two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n(n-1)/2, 2 \cdot 10^5)$), indicating the number of hazardous materials and the number of prohibited pairs. The materials are identified by integers from $1$ to $n$.
Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$) — a pair of materials that are prohibited from sharing a vessel. 
It is guaranteed that the input contains at least one deadlock configuration of three materials.

## Output
Output a single line containing three integers $a$, $b$, and $c$ ($a < b < c$), representing the identifiers of the materials in the deadlock configuration.
To satisfy the deterministic auditing system, if more than one such configuration exists, you must output the lexicographically earliest one among all valid configurations. This means you must minimize $a$; if there is a tie, minimize $b$; and if still tied, minimize $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
The previous version used an "equal prohibition status" condition that models easily translated into an adjacency equality check, immediately exposing that the target structure was a triangle. This rewrite removes that affordance by replacing the explicit edge-status rules with a constraint satisfaction scenario (distributing 3 items into 2 holds without conflicts). To succeed, the model must now independently deduce the Pigeonhole Principle application: that a 2-partition of 3 vertices avoids monochromatic edges if and only if the subgraph is not a triangle. Models failing this deduction will likely attempt a naive $O(n^3)$ partition-checking search that times out.
</RATIONALE>
<PRESERVED_ANSWER>
By the Pigeonhole Principle, distributing 3 items into 2 holds guarantees at least one hold contains 2 items; thus, it is impossible to avoid a prohibited pair if and only if all 3 possible pairs among the items are prohibited (a triangle), preserving the exact same valid configurations.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core computational task remains finding a triangle (K3) in an undirected graph, which requires an algorithm faster than naive $O(n^3)$ (e.g., bitset intersection or common-neighbor search) to pass within the time limit.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "assign each of them to either Hold A or Hold B" as requiring both holds to be non-empty, though mathematically the impossibility holds true regardless of whether 3-0 splits are permitted, making this risk harmless to the logic.
</RISK>

Pigeonhole Partition Obfuscation
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces explicit subgraph edge counts or neighbor-equality conditions with a bipartite-partition constraint on a fixed-size subset. It forces the model to mathematically prove to itself that "impossible to 2-color a 3-vertex graph" is strictly equivalent to "is a K3 clique" before it can write an efficient algorithm, defeating models that rely on direct translation of problem rules into code.
</METHOD_DESCRIPTION>
