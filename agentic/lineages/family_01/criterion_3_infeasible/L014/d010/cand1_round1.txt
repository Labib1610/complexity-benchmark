<STATEMENT>
# Problem C — Cargo Prohibition Protocol

Time limit: 2 s   Memory limit: 256 MB

A logistics firm operates a shipping route for hazardous materials. Certain pairs of these materials are highly reactive and are explicitly prohibited from sharing a single cargo vessel.

The proposed loading schedule is structurally impossible to fulfill. You must produce a definitive proof of this impossibility to trigger an automatic schedule rejection.

To establish this proof, you are required to isolate a "deadlock configuration". A deadlock configuration is a set of exactly three distinct materials. To verify a deadlock, the auditing system attempts to arrange the three materials into a linear sequence containing a first, a second, and a third material. A sequence is considered 'compliant' if the first material is permitted to share a vessel with the second (meaning they do not form a prohibited pair), OR if the second material is permitted to share a vessel with the third. A deadlock configuration is one where it is impossible to form a compliant sequence, no matter which of the six possible orderings of the three materials is evaluated.

Because the automated auditing system requires deterministic reporting, it will not accept an arbitrary deadlock configuration. The system demands the canonical proof, meaning you must systematically ensure no earlier configuration could have been reported.

## Input
The first line provides two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n(n-1)/2, 2 \cdot 10^5)$), indicating the number of hazardous materials and the number of prohibited pairs. The materials are identified by integers from $1$ to $n$.
Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$) — a pair of materials that are prohibited from sharing a vessel. 
It is guaranteed that the input contains at least one deadlock configuration of three materials.

## Output
Output a single line containing three integers $a$, $b$, and $c$ ($a < b < c$), representing the identifiers of the materials in the deadlock configuration.
To satisfy the deterministic auditing system, if more than one such configuration exists, you must output the lexicographically earliest one among all valid configurations. This means you must minimize $a$; if there is a tie, minimize $b$; and if still tied, minimize $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I changed the definition of a deadlock configuration from an impossible 2-vessel assignment (which maps directly to the Pigeonhole Principle and clique detection) to a condition requiring all permutations of the three materials to fail a logical compliance check. This forces the model to either blindly simulate the permutations (resulting in a Time Limit Exceeded due to the $O(N^3)$ overhead) or perform a multi-step logical deduction using De Morgan's laws to realize the condition simplifies to a 3-clique.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that all 6 permutations fail the compliance check is logically equivalent to all 3 pairs in the triplet being prohibited, which is exactly a triangle (3-clique), so the valid configurations remain identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still asks for the lexicographically earliest 3-clique in an undirected graph, preserving the $O(NM/64)$ bitset complexity class.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "first material" and "second material" as referring to the materials' numeric IDs rather than their structural positions within the evaluated sequence, though the phrase "no matter which of the six possible orderings... is evaluated" strongly clarifies it.
</RISK>

Universal Permutation Obfuscation
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces a static structural property (all pairs prohibited) with a universal quantification over all permutations, where each permutation is subjected to a Boolean logic check. This defeats models that rely on pattern-matching the Pigeonhole Principle or clique definitions, forcing them to either write a naive simulation that TLEs or perform explicit Boolean algebraic simplification.
</METHOD_DESCRIPTION>
