We need to find the lexicographically smallest triple \((a,b,c)\) with \(a < b < c\) such that:

- \((a,b)\) is an edge (prohibited pair).
- Both \((a,c)\) and \((b,c)\) are also edges.

That means we need a triangle in the graph, and we want the smallest triangle in lexicographic order.

Since \(n \leq 2000\), we can afford an \(O(n^2)\) or \(O(n^2 \log n)\) approach.

**Approach:**

1. Read the graph as an adjacency matrix (boolean) for fast lookups.
2. Iterate over all possible \(a\) from 1 to \(n\).
3. For each \(a\), iterate over all possible \(b > a\) such that \((a,b)\) is an edge.
4. For each such pair, iterate over all possible \(c > b\) and check if \((a,c)\) and \((b,c)\) are edges.
5. The first found triple in this order is the lexicographically smallest.

Since \(m \leq 2\cdot 10^5\), the number of edges is manageable. The triple loop might be heavy if done naively, but we can optimize:

- For each \(a\), collect neighbors \(N(a)\).
- For each \(b \in N(a)\) with \(b > a\), we need to find a \(c > b\) such that \(c \in N(a) \cap N(b)\).
- We can check intersection by iterating over the smaller neighbor list.

Given \(n=2000\), even \(O(n^3)\) in worst case is \(8 \times 10^9\) which is too much. But we can do better:

For each \(a\), we can iterate over pairs \((b,c)\) from its neighbor list. Since the graph is sparse (max 2e5 edges), the neighbor lists are small on average. Worst-case dense graph would be \(n=2000\), \(m \approx 2e6\) but here \(m \leq 2e5\), so average degree ≤ 200.

So for each \(a\), we can:

- Let neighbors = sorted list of neighbors of \(a\).
- For each pair \((b,c)\) in neighbors with \(b < c\), check if \((b,c)\) is an edge.
- If yes, we have a triangle \((a,b,c)\). Since we iterate \(a\) from smallest, and within that \(b,c\) in increasing order, the first found is lexicographically smallest.

Complexity: For each \(a\), checking all pairs in its neighbor list is \(O(\deg(a)^2)\). Sum over all \(a\) of \(\deg(a)^2\) is at most \(O(n \cdot \text{maxdeg}^2)\). With maxdeg ≤ 2000 but m ≤ 2e5, worst-case sum of squares is bounded by \(O(m \cdot \text{maxdeg})\) which is fine.

Let's implement.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [[False] * (n + 1) for _ in range(n + 1)]
    neighbors = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u][v] = adj[v][u] = True
        neighbors[u].append(v)
        neighbors[v].append(u)
    
    for a in range(1, n + 1):
        neigh = sorted(neighbors[a])
        L = len(neigh)
        for i in range(L):
            b = neigh[i]
            if b <= a:
                continue
            for j in range(i + 1, L):
                c = neigh[j]
                if c <= b:
                    continue
                if adj[b][c]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
