Looking at this problem, I need to find a triangle (3-clique) in an undirected graph, specifically the lexicographically smallest one.

**Approach:**
- For each vertex `a` (in increasing order), check all pairs of its neighbors `(b, c)` where `b < c`.
- If `b` and `c` are connected by an edge, then `(a, b, c)` forms a triangle.
- Since we iterate `a` in increasing order, and for each `a` we iterate `b` in increasing order then `c` in increasing order, the first triangle found is the lexicographically smallest.

**Optimization:**
- Store the graph as adjacency sets for O(1) edge lookups.
- For each vertex `a`, iterate through its neighbors in sorted order. For each pair `(b, c)` of neighbors with `b < c`, check if edge `(b, c)` exists.
- To avoid redundant checks, only consider neighbors `b, c > a` (since we want `a < b < c` and we process `a` in increasing order).

The complexity is O(n + sum over all vertices of d(v)^2) where d(v) is the degree. In the worst case this could be O(n^3), but with the constraint that a triangle exists and we stop early, plus the degree sum being bounded by 2m, this should be efficient enough for the given constraints.

```python
import sys

def solve():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        neighbors_a = sorted(adj[a])
        # Filter neighbors > a
        neighbors_a = [x for x in neighbors_a if x > a]
        len_na = len(neighbors_a)
        for i in range(len_na):
            b = neighbors_a[i]
            adj_b = adj[b]
            for j in range(i + 1, len_na):
                c = neighbors_a[j]
                if c in adj_b:
                    print(f"{a} {b} {c}")
                    return

solve()
```
