We need to find a triangle in the conflict graph (a 3-cycle) and output the lexicographically smallest one.

A direct check of all triples is too slow for \( n \) up to 2000 and \( m \) up to \( 2 \cdot 10^5 \).  
We can instead iterate over each edge and check for a common neighbor, but we must be careful to get the lexicographically smallest triangle.

A practical approach:

- Sort adjacency lists for each vertex.
- For each edge \((u, v)\) with \( u < v \), check all neighbors \( w \) of \( u \) that are greater than \( v \). If \( w \) is also a neighbor of \( v \), we found a triangle \((u, v, w)\).
- Since we iterate edges in sorted order and neighbors in sorted order, the first triangle found will be lexicographically smallest.

We can use sets for fast neighbor checks.

Here’s the implementation:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    edges = []
    edge_set = set()

    for _ in range(m):
        u, v = map(int, input().split())
        if u > v:
            u, v = v, u
        edges.append((u, v))
        edge_set.add((u, v))
        adj[u].append(v)
        adj[v].append(u)

    for i in range(1, n + 1):
        adj[i].sort()

    # Iterate edges in sorted order
    edges.sort()
    for u, v in edges:
        for w in adj[u]:
            if w > v and (v, w) in edge_set:
                print(u, v, w)
                return

if __name__ == "__main__":
    solve()
```
