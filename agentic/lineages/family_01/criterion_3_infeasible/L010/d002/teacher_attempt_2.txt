<STATEMENT>
# Signature Meal Selection

Time limit: 2 s
Memory limit: 256 MB

A prestigious culinary academy is designing a new tasting menu from a repertoire of $n$ distinct recipes. Through extensive taste-testing, the academy has compiled a catalog of $m$ harmonious pairings. An entry in the catalog indicates that two specific recipes complement each other perfectly (this relationship is mutual).

The academy's graduation requirement dictates that a student must present a "signature meal" consisting of exactly three distinct recipes. A meal is considered perfectly balanced if and only if there are exactly three distinct pairings in the catalog for which both recipes belong to the meal.

Given the sheer number of possible combinations, your task is to automate the search for a perfectly balanced signature meal. It is guaranteed that the catalog contains at least one such valid trio of recipes.

The academy's repertoire contains $n$ recipes, where $n$ is at least the number of recipes required for a single meal, up to a maximum capacity of 2000 (established in the academy's founding charter). The catalog contains $m$ pairings, with a minimum of 3 and a maximum limit of two hundred thousand. Naturally, $m$ cannot exceed the total number of distinct pairs that can be formed from the $n$ recipes.

## Input
The first line contains two integers $n$ and $m$.
Each of the next $m$ lines contains two integers $u$ and $v$ — the identifiers of two recipes that form a harmonious pairing.
It is guaranteed that at least one perfectly balanced signature meal can be formed.

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$ representing the identifiers of the three recipes in the signature meal. If multiple such meals can be formed, output the one that minimizes $a$; if there is a tie, minimize $b$; and if still tied, minimize $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
The problem was rewritten to state all numeric bounds indirectly within the text, removing them from the Input section. The description of a valid meal was changed from "every recipe complements every other" (which directly maps to the definition of a clique) to counting the number of valid pairings within the chosen subset (requiring exactly three). This forces the model to deduce the constraints and to realize that three edges among three vertices mathematically implies a triangle, rather than relying on structural buzzwords.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement of selecting three recipes that have exactly three pairings among them is equivalent to finding a 3-clique (triangle), which matches the original problem's definition exactly.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a triangle (K3) in a graph, preserving the certificate-style infeasibility complexity class.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "exactly three distinct pairings in the catalog for which both recipes belong to the meal" as meaning there must be no *other* pairings in the catalog involving those recipes, though "for which both recipes belong to the meal" strictly limits the condition to the internal edges of the subset.
</RISK>
