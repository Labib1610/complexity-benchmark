# Ternary Mixture Viability

Time limit: 2 s   Memory limit: 256 MB

A chemical manufacturing plant operates with $n$ base compounds. The safety board maintains a registry of $m$ safe binary mixtures. Each entry in the registry certifies that two specific compounds can safely dissolve into each other. This physical property is inherently symmetric.

The plant needs to formulate a new 'ternary mixture' which requires combining exactly three distinct base compounds. According to safety regulations, a mixture of three compounds is viable if and only if the compounds can be designated as a primary, a secondary, and a tertiary component such that:
- The secondary component is certified to dissolve safely with the primary component.
- The tertiary component is certified to dissolve safely with both the primary and secondary components.

Given the registry of safe binary mixtures, your task is to automate the search for a viable ternary mixture. It is guaranteed that the registry allows for at least one such mixture.

## Input
The first line contains two integers $n$ and $m$ (3 ≤ n ≤ 2000, 3 ≤ m ≤ min(n·(n−1)/2, 2·10⁵)).
Each of the next $m$ lines contains two integers $u$ and $v$ — the identifiers of two base compounds that form a certified safe binary mixture.
It is guaranteed that at least one viable ternary mixture can be formulated.

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$ representing the identifiers of the three compounds in the ternary mixture. If multiple viable mixtures can be formed, output the one whose identifiers are lexicographically smallest (smallest $a$; ties broken by smallest $b$; then smallest $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

This forces the model to logically deduce that all three pairs must exist, disabling surface-level pattern matching for graph cliques while actually providing a subtle structural hint toward the intended intersection algorithm.
</RATIONALE>
