<STATEMENT>
# Problem C — Proof of Impossibility

Time limit: 2 s   Memory limit: 256 MB

The factory still has only two shifts, 1 and 2, but the roster is known to be hopeless. Your job is not to schedule — it is to search the conflict data to certify the impossibility. 

A deadlock is defined as a subset of exactly three conflict records that, across their six total positions, contain exactly three distinct worker IDs. Furthermore, each of these three IDs must appear in exactly two of the three records. Such a configuration provides an undeniable certificate that two shifts cannot suffice. Finding such a deadlock can appear daunting given the sheer number of possible subsets to check.

It is guaranteed that the conflict data contains at least one such deadlock. Output the worker IDs involved in one such deadlock.

## Input
The first line contains two integers n and m (3 ≤ n ≤ 2000, 3 ≤ m ≤ min(n·(n−1)/2, 2·10⁵)).
Each of the next m lines contains two integers u v — a conflict record representing a pair of workers who cannot work together.
It is guaranteed that at least one deadlock exists.

## Output
Print three integers a b c on one line with a < b < c representing the three distinct workers involved in the deadlock. Output the lexicographically smallest such group of workers (smallest a; ties by smallest b; then smallest c).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
The previous wording ("one worker cannot work with a second, the second cannot work with a third...") allowed models to directly pattern-match the problem to finding an undirected 3-cycle (triangle). I replaced this with a set-theoretic definition of a deadlock (a subset of 3 records containing exactly 3 distinct IDs, each appearing exactly twice). This forces models to logically deduce that this configuration is structurally identical to a triangle, defeating superficial text-matching.
</RATIONALE>
<PRESERVED_ANSWER>
The only way to select 3 records (edges) that contain exactly 3 worker IDs (vertices) such that each ID appears in exactly 2 records is if the records form a triangle, making the mathematical condition identical to the original.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a triangle in a graph, preserving the O(n*m/64) or O(m*sqrt(m)) complexity class.
</PRESERVED_CLASS>
<RISK>
Models might simulate the subset definition literally and write an O(m^3) brute-force search over all triples of records, which would fail the time limit, though this is a failure of algorithmic reasoning rather than ambiguity.
</RISK>
