We can solve this by checking each triple `(a, b, c)` in increasing order and verifying whether the number of edges among them equals exactly 3. However, iterating all triples naively is too slow for large n.

We can iterate over **each edge** and try to find a third vertex that connects to both endpointsaint, in a way that **exactly matches** 3 edges including the current one dropped.

Since exactly 3 edges among the triple means the triple forms a triangle in the graph, we can:

1. Sort the vertices for lexicographic ordering.
2. For each possible smallest vertex `a`:
   - For each vertex `b > a` where edge exists:
     - For each vertex `c > b`:
       - If all three edges exist, that is a valid triple.
       - Check edges: `(a,b)`, `(a,c)`, `(b,c)` — if all are in the adjacency set, it works.

We can speed this up: Instead of iterating all triples, for each edge `(u,v)` with `u < v`, we try each `w > v` and check if both `(u,w)` and `(v,w)` are edgescars. Since we already have `(u,v)`, that gives exactly 3 edges.

We search in sorted order and stop at first found.

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    edges = set()
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        if u > v:
            u, v = v, u
        edges.add((u, v))
        adj[u].append(v)
        adj[v].append(u)
    
    for u in range(1, n + 1):
        adj[u].sort()
    
    for u in range(1, n + 1):
        for v in adj[u]:
            if v <= u:
                continue
            for w in adj[v]:
                if w <= v:
                    continue
                if (u, w) in edges:
                    print(u, v, w)
                    return

if __name__ == "__main__":
    solve()
```
