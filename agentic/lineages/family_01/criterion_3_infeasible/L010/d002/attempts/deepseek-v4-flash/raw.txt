We need to find a set of three distinct workers such that there are exactly three conflict edges among them, forming a triangle.  
That is, we need to find a triangle in the graph.  

The problem guarantees at least one triangle exists.  
We need the lexicographically smallest triangle (by sorted vertex IDs).  

A direct approach:  
- Store edges in an adjacency set for O(1) lookups.  
- Iterate over all possible triples in sorted order and check if all three edges exist.  
- Since n ≤ 2000, checking all triples naively is O(n³) = 8e9, too slow.  

Better:  
- Iterate over each edge (u, v) with u < v.  
- For each w > v, check if edges (u, w) and (v, w) exist.  
- This is O(m * n) worst-case, but m ≤ 2e5 and n ≤ 2000 → 4e8 worst-case, still borderline but likely okay in Python with optimizations.  

We can optimize by only checking w that are neighbors of u and v.  
But simpler: iterate over u from 1 to n, v from u+1 to n, and if edge exists, check w > v.  

We can break early when we find the first triangle because we iterate in lexicographic order.  

Implementation:  

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if b not in adj[a]:
                continue
            for c in range(b + 1, n + 1):
                if c in adj[a] and c in adj[b]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
