**Solution Explanation**

For three reports (edges) to give each of three workers exactly two
appearances, the three edges must be the three sides of a triangle:

```
workers a , b , c
edges : (a,b) , (b,c) , (c,a)
```

Each vertex of the triangle is incident to the two other edges, therefore
its count is 2, and all other vertices have count 0.
The task is exactly:

*find the lexicographically smallest triangle*  
(`a < b < c`, minimal `a`, then `b`, then `c`).

--------------------------------------------------------------------

#### 1.   Data structure – bitsets

`n ≤ 2000`, therefore a 2000‑bit integer fits easily into a Python
`int`.  
For every vertex `v` we store a bit mask `adj[v]` :

```
bit i (0‑based) is 1  ⇔  edge (v , i+1) exists
```

Construction is `O(m)`.

--------------------------------------------------------------------

#### 2.   Searching triangles

We iterate over all ordered vertex pairs `(a,b)` with `a < b`.

```
if edge (a,b) exists:
        common = adj[a] & adj[b]          # vertices adjacent to both a and b
        # we need a vertex c > b
        common >>= b                      # delete bits 0 … b‑1
        if common != 0:
                c = b + 1 + index_of_lowest_set_bit(common)
                output a,b,c
                stop
```

* `common` contains exactly the vertices that together with `a` and `b`
  form a triangle.
* Shifting right by `b` removes all vertices `≤ b`; the lowest remaining
  set bit is the smallest possible `c`.
* Because the outer loops run with increasing `a` and, for a fixed `a`,
  increasing `b`, the first triangle we encounter is the lexicographically
  smallest one.

The loops examine at most `n·(n‑1)/2 ≤ 2·10⁶` pairs, each in `O(1)`,
so the total time is `O(n²)` (≈ 4 · 10⁶ operations for `n = 2000`).

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints exactly the required triple.

---

##### Lemma 1  
For any pair of vertices `a<b` with an edge between them,
`common = adj[a] & adj[b]` contains precisely the vertices that are
adjacent to **both** `a` and `b`.

**Proof.**  
Bit `i` of `adj[a]` is 1 iff `(a,i+1)` is an edge, similarly for `adj[b]`.
The bitwise AND is 1 exactly when both bits are 1, i.e. when both edges
exist. ∎



##### Lemma 2  
After `common >>= b`, the lowest set bit (if any) corresponds to the
smallest vertex `c` such that `c > b` and edges `(a,c)` and `(b,c)` exist.

**Proof.**  
Shifting right by `b` discards bits `0 … b‑1`, i.e. vertices `1 … b`.
All remaining bits keep their relative order, now starting at position 0.
Thus the least‑significant 1‑bit represents the smallest remaining vertex,
which is exactly the smallest `c > b` adjacent to both `a` and `b`. ∎



##### Lemma 3  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The algorithm outputs only after confirming that edge `(a,b)` exists
(the outer test) and that `c` is a set bit of `common` after the shift.
By Lemma&nbsp;1, `c` is adjacent to both `a` and `b`, i.e. edges
`(a,c)` and `(b,c)` exist. Hence the three edges form a triangle. ∎



##### Lemma 4  
Let `T = (a₀,b₀,c₀)` be the lexicographically smallest triangle
(`a₀<b₀<c₀`). The algorithm will output `T`.

**Proof.**  
Consider the iteration when `a = a₀` and `b = b₀`.  
Since `(a₀,b₀)` is an edge of triangle `T`, the algorithm reaches the
inner block. By Lemma&nbsp;1, `common` contains `c₀`.  
All vertices ≤ `b₀` are removed; `c₀ > b₀`, so after the shift `c₀`
remains set. By Lemma&nbsp;2 it is the lowest set bit, therefore the
algorithm chooses `c = c₀` and outputs `(a₀,b₀,c₀)`. ∎



##### Lemma 5  
No triangle lexicographically smaller than the output can exist.

**Proof.**  
The algorithm scans pairs `(a,b)` in increasing lexicographic order.
When it first finds a triangle, it stops. Any triangle with a smaller
`a` would have been examined earlier; with the same `a` but smaller `b`
also earlier; with the same `a,b` but smaller `c` would have been chosen
by Lemma&nbsp;2. Hence none exists. ∎



##### Theorem  
The program prints three integers `a<b<c` that are exactly the
lexicographically smallest triple of workers forming a triangle in the
given graph.

**Proof.**  
By Lemma&nbsp;3 the printed triple is a triangle.
By Lemma&nbsp;4 the smallest triangle is printed.
By Lemma&nbsp;5 no smaller triangle exists.
Thus the output satisfies the specification. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets* : `O(m)` time, `O(n)` memory  
*Searching* : at most `n·(n‑1)/2` iterations, each `O(1)` → `O(n²)` time  
For `n ≤ 2000` this is ≤ 4 · 10⁶ operations, well inside limits.  
Memory usage: `n+1` integers of ≤ 2000 bits → < 0.5 MiB.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # adjacency as bitsets, vertices are 1‑based, bits are 0‑based
    adj = [0] * (n + 1)
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    for a in range(1, n + 1):
        mask_a = adj[a]
        for b in range(a + 1, n + 1):
            # edge (a,b) must exist
            if not ((mask_a >> (b - 1)) & 1):
                continue
            common = mask_a & adj[b]          # neighbours of both a and b
            common >>= b                      # keep only vertices > b
            if common:
                # lowest set bit gives smallest c
                low = common & -common
                pos = low.bit_length() - 1    # position inside shifted bits
                c = b + 1 + pos
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
