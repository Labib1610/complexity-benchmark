We can solve this by checking each triple of elements in increasing order and verifying if all three pairs are present in the set of stable binary alloys.  

Since \( n \) can be up to 2000, checking all triples naively would be \( O(n^3) \), which is too slow.  
Instead, we can iterate over each edge \((u, v)\) and look for a third element \( w \) such that both \((u, w)\) and \((v, w)\) are edges.  

We can store edges in an adjacency set for fast lookup.  
To get the lexicographically smallest triple, we iterate \( a \) from 1 to \( n \), then \( b \) from \( a+1 \) to \( n \), and check if \((a, b)\) is an edge. If yes, we look for the smallest \( c > b \) such that \((a, c)\) and \((b, c)\) are edges.  

This is efficient because for each edge we only scan possible \( c \) values, and the total work is bounded by \( O(n^2) \) in the worst case, which is fine for \( n \leq 2000 \).

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    edges = set()
    adj = [set() for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        edges.add((u, v))
        edges.add((v, u))
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if (a, b) not in edges:
                continue
            # Find smallest c > b such that (a,c) and (b,c) are edges
            for c in range(b + 1, n + 1):
                if (a, c) in edges and (b, c) in edges:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    solve()
```
