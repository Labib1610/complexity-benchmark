**Solution Explanation**

For three different workers `a < b < c` the three incident files

```
(a , b) , (a , c) , (b , c)
```

must all be present.  
So we have to find a *triangle* in the undirected graph whose vertices are the
workers and whose edges are the incident files.

The required answer is the lexicographically smallest triple
`(a , b , c)`.  
If we examine the vertices in increasing order

```
for a = 1 .. n
    for b = a+1 .. n
        if edge (a , b) exists
            look for the smallest c > b that is adjacent to both a and b
```

the first triangle we meet is exactly the wanted one.

--------------------------------------------------------------------

#### Data structure – bitsets  

`n ≤ 2000`, therefore a vertex can be represented by a bit in a Python
integer (≈ 2000 bits ≈ 250 bytes).  
For every vertex `v` we store

```
adj[v]  – integer, bit i (0‑based) is 1  ⇔  edge (v , i+1) exists
```

All operations we need are:

* test whether an edge `(x , y)` exists – one bit test,
* intersection of neighbour sets – bitwise `&`,
* find the smallest vertex in a set – isolate the lowest set bit.

All of them are O(1) on the size of the integer (the whole integer is handled
by the CPU at once).

--------------------------------------------------------------------

#### Algorithm
```
read n , m
adj[1..n] = 0
for each edge (u , v):
        adj[u] |= 1 << (v-1)
        adj[v] |= 1 << (u-1)

fullMask = (1 << n) - 1          # bits 0 … n-1 are 1

for a = 1 … n:
        for b = a+1 … n:
                # does edge (a , b) exist ?
                if ((adj[a] >> (b-1)) & 1) == 0:   continue

                common = adj[a] & adj[b]            # neighbours of both a and b
                # keep only vertices > b
                mask   = fullMask ^ ((1 << b) - 1)   # bits b … n-1 are 1
                cand   = common & mask

                if cand != 0:                       # at least one c exists
                        low = cand & -cand            # lowest set bit
                        c   = low.bit_length()       # index+1, because bit_length gives position of highest 1‑bit (1‑based)
                        print a, b, c
                        exit
```

The loops run at most `n·(n-1)/2 ≤ 2·10⁶` iterations, each iteration does only a
few integer operations – easily fast enough.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

##### Lemma 1  
For any vertices `a < b`, after the test `if ((adj[a] >> (b-1)) & 1) == 0`
the algorithm proceeds **iff** the edge `(a , b)` is present in the graph.

**Proof.**  
`adj[a]` has bit `b-1` set exactly when `(a , b)` is an edge.
Shifting right by `b-1` moves that bit to position 0, masking with `1` extracts
its value. ∎



##### Lemma 2  
For fixed `a < b` with edge `(a , b)` present, the variable `cand`
contains exactly the vertices `c` such that

* `c > b`,
* edges `(a , c)` and `(b , c)` are present.

**Proof.**  

* `common = adj[a] & adj[b]` – a vertex `v` is in `common` iff it is adjacent
  to **both** `a` and `b`.
* `mask` has bits `b … n-1` set and lower bits cleared, therefore
  `cand = common & mask` keeps precisely those vertices of `common`
  whose index `v-1 ≥ b`, i.e. `v > b`. ∎



##### Lemma 3  
If `cand ≠ 0`, the vertex `c` computed by the algorithm is the smallest
vertex `> b` that together with `a , b` forms a triangle.

**Proof.**  
`cand` is a non‑empty set of candidate vertices (Lemma&nbsp;2).  
`low = cand & -cand` isolates the lowest set bit of `cand`.  
`low.bit_length()` returns the position (1‑based) of that bit, i.e.
`c = index+1`. Hence `c` is the smallest vertex contained in `cand`,
therefore the smallest vertex `> b` completing the triangle. ∎



##### Lemma 4  
When the algorithm prints a triple `(a , b , c)`, it is a triangle
(`(a , b) , (a , c) , (b , c)` are all edges) and `a < b < c`.

**Proof.**  
`a < b` by loop order.  
Edge `(a , b)` exists by Lemma&nbsp;1.  
`c` is taken from `cand`, therefore `c > b` (Lemma&nbsp;2) and edges
`(a , c)` and `(b , c)` exist (again Lemma&nbsp;2). ∎



##### Lemma 5  
Let `T` be the lexicographically smallest triangle in the whole graph.
The algorithm prints `T`.

**Proof.**  
Consider the outer loops. They enumerate all ordered pairs `(a , b)` with
`a < b` in lexicographic order.  
When the pair `(a_T , b_T)` of triangle `T` is reached, edge `(a_T , b_T)`
exists, so the inner part is executed.
By Lemma&nbsp;2 the set `cand` consists exactly of the third vertices of all
triangles whose first two vertices are `(a_T , b_T)`.  
Since `T` is the smallest triangle, its third vertex `c_T` is the smallest
element of `cand`. Lemma&nbsp;3 shows the algorithm will pick exactly `c_T`
and output `(a_T , b_T , c_T)`. ∎



##### Lemma 6  
The algorithm never prints a triangle that is lexicographically larger than
the first triangle it could have printed.

**Proof.**  
The loops stop immediately after the first successful `print`.  
Thus the printed triangle is the first one encountered in the enumeration
order described in Lemma&nbsp;5, i.e. the smallest one. ∎



##### Theorem  
The algorithm always terminates and outputs the lexicographically smallest
triple `a < b < c` such that the three edges among them are present
(i.e. a triangle).

**Proof.**  

*Termination*: the double loop has finitely many iterations; inside it we
either continue or `exit` after printing, so the program ends.

*Existence*: the statement guarantees at least one triangle, therefore some
iteration will satisfy the condition `cand != 0` and the algorithm will
print.

*Correctness*: By Lemma&nbsp;4 the printed triple is a triangle.
By Lemma&nbsp;5 it is the smallest possible triangle.
By Lemma&nbsp;6 no earlier triangle could have been missed.
Hence the output fulfills the specification. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency bitsets* – `O(m)` operations.  
*Main loops* – at most `n·(n-1)/2 ≤ 2·10⁶` iterations, each does a constant
number of integer bit operations (`>> , & , | , - , bit_length`).  
Therefore  

```
Time   :  O(n² + m)   ≤  about 2·10⁶ elementary operations
Memory :  O(n) bits for adjacency = n·(n) ≤ 2000·2000 ≈ 4·10⁶ bits ≈ 0.5 MiB
          plus a few integers → well below the 256 MiB limit.
```

Both limits are easily satisfied.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    full_mask = (1 << n) - 1     # bits 0 .. n-1 are 1

    for a in range(1, n + 1):
        a_adj = adj[a]
        for b in range(a + 1, n + 1):
            # edge (a,b) ?
            if ((a_adj >> (b - 1)) & 1) == 0:
                continue
            common = a_adj & adj[b]
            # keep only vertices > b
            mask = full_mask ^ ((1 << b) - 1)   # bits b .. n-1 are 1
            cand = common & mask
            if cand:
                low = cand & -cand               # lowest set bit
                c = low.bit_length()            # vertex number (since bit_length is index+1)
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
