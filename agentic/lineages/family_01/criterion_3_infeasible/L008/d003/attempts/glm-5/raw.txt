Looking at this problem, I need to find three workers such that all three pairs between them appear in the incident list. This is finding a triangle in the graph.

**Key insight:** The problem guarantees a triangle exists. I need to find the lexicographically smallest one.

**Approach:**
1. For each vertex `a` (in increasing order), I want to find the smallest `b > a` and `c > b` such that edges (a,b), (a,c), (b,c) all exist.
2. For a fixed `a`, I look at its neighbors. Among neighbors `> a`, I need two that are connected to each other.
3. To find this efficiently: for each `a`, iterate through pairs of its neighbors. But this could be O(d²) per vertex.

**Optimization:** If I process `a` from 1 to n, and for each `a` only consider neighbors `> a`, the first triangle found is the answer (since we want smallest `a`, then smallest `b`, then smallest `c`).

For a fixed `a`, to get smallest `b`: iterate neighbors in sorted order. For each neighbor `b`, check if any subsequent neighbor `c` is connected to `b`. To make this fast, I can mark all neighbors of `a` in a set, then for each `b` (in sorted order), iterate through `b`'s neighbors and check if they're in `a`'s neighbor set and `> b`.

The complexity: For each `a`, we iterate through `b`'s adjacency list. Total work is bounded by sum over all edges (a,b) of degree(b). In the worst case this could be large, but with the constraint that a triangle exists and we stop early, plus the degree sum being bounded by m·max_degree...

Actually, a cleaner bound: the total work is at most O(m·√m) using the standard triangle-finding technique, but since we stop at the first triangle found and process in sorted order, it should be fast enough.

Let me use a simpler approach: for each `a` from 1 to n, collect neighbors > a, sort them. Then for each pair (b, c) with b < c in this list, check if (b,c) is an edge. Use a hash set for edge lookups. Return first found.

To optimize the pair checking: for each `b` in sorted neighbors, iterate through `b`'s neighbors that are > b and check if they're in `a`'s neighbor set. This avoids checking all pairs.

```python
import sys

def solve():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [set() for _ in range(n+1)]
    edges = set()
    
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        adj[u].add(v)
        adj[v].add(u)
        edges.add((u, v) if u < v else (v, u))
    
    for a in range(1, n+1):
        neighbors_a = sorted([x for x in adj[a] if x > a])
        if len(neighbors_a) < 2:
            continue
        neighbor_set = set(neighbors_a)
        for b in neighbors_a:
            for c in adj[b]:
                if c > b and c in neighbor_set:
                    print(f"{a} {b} {c}")
                    return
```
