Looking at this problem, I need to find a triangle (3-cycle) in an undirected graph, and among all triangles, output the one with minimum lexicographic order (a, b, c).

**Approach:**
1. For each vertex `v` in increasing order, check if any two of its neighbors form an edge.
2. To efficiently check this, for each vertex `v`, I iterate through pairs of its neighbors and check if they're connected.
3. To optimize, I use a hash set for adjacency lookups and process vertices in order.

**Optimization for efficiency:**
- For each vertex `v`, iterate through its neighbors in sorted order.
- For each pair of neighbors (u, w) where u < w, check if edge (u, w) exists.
- The first triangle found when processing vertex `v` (smallest first) with the smallest pair gives the answer.

But checking all pairs could be O(n²) per vertex. With n=2000 and m=2×10⁵, worst case could be expensive.

**Better approach:** Process vertices in order. For vertex `v`, look at all pairs of its neighbors. Since we want minimum (a,b,c), and `v` would be the smallest element `a`, we process `v` from 1 to n. For each `v`, we want the minimum (b,c) pair where both are neighbors of `v` and edge(b,c) exists.

To find minimum (b,c): iterate b through sorted neighbors of v (b > v), then for each b, iterate c through sorted neighbors of v (c > b), check if edge exists. Return first found.

This is still potentially O(degree²) per vertex. But total edges is bounded by 2×10⁵, so sum of degrees is 4×10⁵. The worst case for pairs is when one vertex has high degree.
