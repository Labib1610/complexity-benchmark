# Problem C — Proof of Impossibility

Time limit: 2 s
Memory limit: 256 MB

Management insists on dividing the workforce into exactly two non-overlapping shifts. However, the HR department knows this plan is doomed. You must provide undeniable proof of this failure.

HR has a collection of incident files. Each file lists two specific workers who cannot be placed on the same shift.

Management's plan can be proven impossible if you can find a 'deadlock' in the records. A deadlock is defined by a set of exactly three distinct workers. If you examine the entire collection of incident files and count how many of them have both of their listed workers belonging to this specific trio, the count must be exactly 3.

It is guaranteed that at least one such deadlock exists. Your task is to identify the three workers involved in such a deadlock and report them to HR.

## Input
The first line provides the workforce size $n$ and the total incident count $m$. The workforce size $n$ is bounded below by 3 and bounded above by the facility capacity of 2000. The incident count $m$ is at least 3, and is capped by either the theoretical maximum of $n(n-1)/2$ distinct combinations, or the archival capacity of $2 \cdot 10^5$, whichever is smaller. Workers are identified by integers from 1 to $n$.

Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), identifying the two workers involved in a single incident. No two incident files list the exact same pair of workers.

It is guaranteed that at least one valid deadlock exists.

## Output
Output three space-separated integers $a$, $b$, and $c$ representing the IDs of the three workers involved. They must be printed such that $a < b < c$.

To ensure a unique valid response when multiple such deadlocks exist, you must select the one that minimizes the value of $a$. If there is a tie, minimize the value of $b$ among the tied triplets, and if a tie still persists, minimize $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
I replaced the graph-theoretic deadlock definition with a set-based counting condition. This forces the model to either deduce the mathematical equivalence to a 3-clique (which allows an efficient graph algorithm) or fall back to a literal implementation that checks all subsets of 3 workers against all incident files, which will fail the time limit.
</RATIONALE>
<PRESERVED_ANSWER>
Because there are no duplicate files, the maximum number of incident files involving only workers from a specific trio is 3; requiring exactly 3 such files is mathematically identical to requiring all three pairs to be present, preserving all valid deadlocks and original answers.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying task remains identifying a 3-chromatic subgraph (a triangle) as a certificate of 2-coloring infeasibility, maintaining the same complexity class and intended O(n*m/64) solution.
</PRESERVED_CLASS>
<RISK>
A reader might misinterpret "both of their listed workers belonging to this specific trio" as checking if the file contains all three workers, but "both" explicitly refers to the two workers in the file, making it unambiguous.
</RISK>
