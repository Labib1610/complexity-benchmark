**Solution Explanation**

For every worker we store the set of workers he/she cannot work with.
The set is stored as a bitset – a Python integer whose *i*-th bit (0‑based)
represents worker `i+1`.

```
adj[i]  – integer, bit j is 1  ⇔  workers (i+1) and (j+1) cannot work together
```

A triangle `a < b < c` exists iff

```
edge a‑b   is present   (bit b‑1 set in adj[a‑1])
edge a‑c   is present   (bit c‑1 set in adj[a‑1])
edge b‑c   is present   (bit c‑1 set in adj[b‑1])
```

For a fixed pair `(a,b)` the workers that are adjacent to **both**
are exactly the bits of `adj[a] & adj[b]`.
Among them we need the smallest `c` that is larger than `b`
(because we require `a<b<c`).

The algorithm enumerates all possible `(a,b)` in lexicographic order:

```
for a = 1 … n
    for b = a+1 … n
        if edge a‑b exists:
            common = adj[a] & adj[b]                # workers adjacent to both
            mask   = bits higher than b               # keep only c > b
            cand   = common & mask
            if cand != 0:
                c = index of lowest set bit in cand
                output a b c   (the first found is lexicographically minimal)
```

Finding the lowest set bit of an integer `x` is done by
`x & -x` (isolates the lowest 1‑bit) and `bit_length()`.

`n ≤ 2000`, therefore each adjacency integer fits into a few machine words.
The double loop runs at most `n·(n‑1)/2 ≈ 2·10⁶` iterations,
each performing only a few integer operations – easily fast enough.

---

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triple
`(a,b,c)` such that all three edges exist.

*Lemma 1*  
For any workers `a<b`, `common = adj[a] & adj[b]` contains exactly the workers
that are adjacent to **both** `a` and `b`.

*Proof.*  
Bit `k` of `adj[a]` is 1 iff edge `a‑(k+1)` exists, similarly for `adj[b]`.
Bitwise AND keeps a bit 1 only when it is 1 in both operands,
hence bit `k` of `common` is 1 iff both edges `a‑(k+1)` and `b‑(k+1)` exist. ∎



*Lemma 2*  
`cand = common & mask` (where `mask` has 1‑bits only for indices `> b`) contains
exactly the workers `c` with `c>b` that together with `a,b` form a triangle.

*Proof.*  
By Lemma&nbsp;1, `common` contains all workers adjacent to both `a` and `b`.
Masking removes those with index ≤ `b`; the remaining bits correspond precisely
to workers `c>b` that are adjacent to both `a` and `b`. ∎



*Lemma 3*  
If `cand ≠ 0`, the algorithm computes `c` as the smallest index `>b` such that
`(a,b,c)` is a triangle.

*Proof.*  
`cand`’s lowest set bit is the smallest index satisfying the condition.
`cand & -cand` isolates that bit; `bit_length()-1` returns its index.
Thus the obtained `c` is the minimal possible. ∎



*Lemma 4*  
When the algorithm outputs a triple `(a,b,c)`, it is a triangle.

*Proof.*  
The algorithm outputs only after confirming edge `a‑b` exists
(`adj[a]` has bit `b` set) and after finding `c` from `cand`.
By Lemma&nbsp;2, `c` is adjacent to both `a` and `b`; together with the
already known edge `a‑b` all three edges exist. ∎



*Lemma 5*  
The first triple output by the algorithm is the lexicographically smallest
triangle in the graph.

*Proof.*  
The outer loops enumerate pairs `(a,b)` in increasing `a`, then increasing `b`.
For a fixed `(a,b)`, Lemma&nbsp;3 yields the smallest possible `c>b`.
Therefore any triangle with a smaller `a` would have been examined earlier.
If another triangle has the same `a` but smaller `b`, it would also be examined
earlier. If `a` and `b` are equal, the algorithm chooses the smallest feasible
`c`. Hence the first found triangle is lexicographically minimal. ∎



*Theorem*  
The algorithm always outputs three integers `a<b<c` such that all three pairs
are present in the input, and the triple is the lexicographically smallest
among all such triples.

*Proof.*  
Existence of at least one triangle is guaranteed by the problem statement,
so the loops will eventually encounter a pair `(a,b)` belonging to some
triangle. By Lemma&nbsp;4 the algorithm outputs a valid triangle.
By Lemma&nbsp;5 this triangle is the lexicographically smallest one.
∎



---

#### Complexity Analysis  

*Building adjacency*: `O(m)`  
*Main loops*: at most `n·(n‑1)/2 ≤ 2·10⁶` iterations, each doing a constant number
of bitwise operations on integers of size ≤ 2000 bits → `O(1)` per iteration.

Total time: `O(n² + m)` ≤ about 2 · 10⁶ operations, well within 2 seconds.  
Memory: `n` integers, each ≤ 2ⁿ → `O(n)` ≈ 2000 · 8 bytes ≈ 16 KB.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [0] * n  # 0‑based
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(n):
        a_adj = adj[a]
        for b in range(a + 1, n):
            if (a_adj >> b) & 1 == 0:
                continue          # edge a‑b not present
            common = a_adj & adj[b]
            # keep only bits with index > b
            mask = (~0) << (b + 1)
            cand = common & mask
            if cand:
                # lowest set bit
                low = cand & -cand
                c = low.bit_length() - 1
                # output 1‑based
                sys.stdout.write(f"{a+1} {b+1} {c+1}")
                return

if __name__ == "__main__":
    solve()
```

to the required input‑output format.
