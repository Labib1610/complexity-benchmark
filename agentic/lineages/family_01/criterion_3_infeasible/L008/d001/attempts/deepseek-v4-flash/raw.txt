We can solve this by representing the graph with an adjacency matrix (or set) and then checking all triplets in sorted order until we find one that forms a triangle.  

Since \( n \le 2000 \), a naive triple loop would be \( O(n^3) \), which is too slow.  
Instead, we can iterate over edges and check for a common neighbor, which is more efficient.

Here’s the implementation:

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
        edges.append((u, v))
    
    # Sort edges by (u, v) to ensure we find the smallest triplet
    edges.sort()
    
    for u, v in edges:
        # Find common neighbors of u and v
        common = adj[u] & adj[v]
        if common:
            w = min(common)
            a, b, c = sorted((u, v, w))
            print(a, b, c)
            return

if __name__ == "__main__":
    main()
```
