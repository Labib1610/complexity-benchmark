<METHOD_NAME>Polynomial Objective Disguise</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit "lexicographically smallest" tie-break rule with an equivalent mathematical objective function, P = sum(a_i * 4^{n-i}). Because a_i is bounded in {1, 2, 3}, this polynomial evaluated at base 4 is strictly monotonic with respect to lexicographical order, preserving the exact same unique minimum. However, models that fail to mathematically deduce this equivalence will attempt to evaluate all valid configurations (causing TLE on loose constraints) or overflow standard 64-bit integer types in languages like C++ when computing 4^40 (causing WA), rather than using the intended early-exit DFS.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You are conducting a regulatory review on a sequential ledger of financial operations. The ledger consists of a total of $n$ operations, numbered sequentially from $1$ up to $n$. Your task is to classify each operation $i$ by assigning it a security tier $a_i$. The allowable security tiers are restricted to exactly the first three positive integers: $a_i \in \{1, 2, 3\}$.

The audit data includes $m$ regulatory dependencies between specific pairs of operations. To maintain strict compliance, for any dependent pair of operations, their assigned security tiers must be strictly distinct. A violation of this condition constitutes an immediate audit failure.

You must find a fully compliant security tier classification for all $n$ operations. Should multiple valid classifications exist, regulations dictate that you must provide the one that minimizes the total systemic risk penalty $P$. The risk penalty for a classification sequence $A = (a_1, a_2, \dots, a_n)$ is defined by the following evaluation:

$$P(A) = \sum_{i=1}^{n} a_i \cdot 4^{n-i}$$

If it is impossible to classify all operations without violating at least one dependency, you must declare the audit impossible.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — representing the total number of operations and the number of regulatory dependencies, respectively.
Following this, there are $m$ lines. Each line provides two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), which indicates a regulatory dependency between operation $u$ and operation $v$.

## Output
If no compliant classification can be formed, output exactly one line containing the word `NO`.
If a valid classification exists, output `YES` on the first line. On the second line, output $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the security tiers assigned to operations $1$ through $n$ in the classification that minimizes the risk penalty $P$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
Changed the explicit description of the lexicographical tie-breaker to an equivalent mathematical objective function $P(A)$. This forces the model to either mathematically prove that this objective is exactly minimized by the lexicographically first valid assignment (to allow early-exit backtracking), or naively search all valid assignments to find the minimum. Naive searches will trigger a Time Limit Exceeded error on instances with many valid assignments, or cause integer overflow in C++ since $4^{40}$ exceeds standard 64-bit limits.
</RATIONALE>
<PRESERVED_ANSWER>
Because $a_i \in \{1, 2, 3\}$ and the base is 4, the difference between any two assignments is dominated by the most significant differing position, meaning the assignment that minimizes $P(A)$ is mathematically guaranteed to be exactly the lexicographically smallest valid assignment.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core problem remains finding a valid 3-coloring of a graph with a specific tie-breaking rule, keeping it in NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might fail to realize that $4^{n-i}$ can exceed standard 64-bit integer limits and produce overflow bugs if they attempt to compute it directly instead of reasoning about the order, but the problem statement itself is mathematically unambiguous.
</RISK>
