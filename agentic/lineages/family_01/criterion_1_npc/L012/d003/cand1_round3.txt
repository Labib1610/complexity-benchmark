<STATEMENT>
# Problem A — Deployment Tiers

Time limit: 2 s   Memory limit: 256 MB

A software system consists of $n$ microservices, identified by integers from 1 to $n$. You must assign each microservice a security tier. A tier must be exactly one of the values 1, 2, or 3.

Extensive testing has revealed that certain distinct pairs of microservices exhibit parallel execution flaws. If a pair with this flaw operates at the exact same security tier, the system becomes unstable. To guarantee stability, the two microservices in any such pair must be assigned to different tiers.

You must determine a valid tier assignment for all $n$ microservices. If there are several valid complete assignments, the deployment policy requires ranking them as complete configurations. Represent each valid assignment as an $n$-element sequence formed by the assigned tiers for microservices 1 through $n$ in order. You must select the valid configuration whose sequence is lexicographically smallest. If no valid configuration is possible, you must report this failure.

Be aware that the system configurations can be highly deceptive. In many cases, a very large number of partial tier assignments that successfully resolve conflicts among the first several microservices will ultimately fail due to structural restrictions appearing only at the final few microservices.

## Input
The first line provides $n$ and $m$ — the number of microservices and the number of flawed pairs.
The system requires at least one microservice, and a strict hardware constraint limits the maximum number of microservices to exactly 40. The number of flawed pairs can be as low as zero, up to the maximum possible number of unique unordered pairs of distinct microservices.
The following $m$ lines each contain two integers $u$ and $v$ (where $u$ and $v$ are distinct integers between 1 and $n$), indicating that microservice $u$ and microservice $v$ share a parallel execution flaw.

## Output
If the system cannot be stabilized, output a single line with the word NO.
Otherwise, output YES on the first line. On the second line, output $n$ integers separated by spaces, where each integer $s_i \in \{1, 2, 3\}$ represents the tier assigned to microservice $i$.
Among all valid assignments, you must output the sequence $s_1, s_2, \dots, s_n$ that is lexicographically smallest (i.e., sequence $A$ is smaller than sequence $B$ if $A$ contains a smaller tier at the first microservice index where the two configurations differ).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The tie-break rule was re-presented as a whole-sequence lexicographical ranking rather than a greedy step-by-step minimization instruction, removing the direct affordance that leads models to use ascending-order DFS. The exact numeric bounds were rewritten indirectly as physical system constraints (S07), forcing the model to infer the standard limits (1 ≤ n ≤ 40, 0 ≤ m ≤ n(n-1)/2) from the prose.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement to output the lexicographically smallest sequence of tiers is mathematically identical to minimizing the tier of microservice 1, then 2, etc., ensuring the exact same output is produced for all inputs.
</PRESERVED_ANSWER>

The core problem remains assigning 3 colors to vertices in a graph such that no adjacent vertices share the same color, which is exactly the NP-complete 3-COLORING problem.
</PRESERVED_CLASS>
