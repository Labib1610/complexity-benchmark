# Problem A — Deployment Tiers

Time limit: 2 s   Memory limit: 256 MB

A software system consists of $n$ microservices, identified by integers from 1 to $n$. You must assign each microservice a security tier. A tier must be exactly one of the values 1, 2, or 3.

Extensive testing has revealed that certain distinct pairs of microservices exhibit parallel execution flaws. If a pair with this flaw operates at the exact same security tier, the system becomes unstable. To guarantee stability, the two microservices in any such pair must be assigned to different tiers.

You must determine a valid tier assignment for all $n$ microservices. If multiple valid tier configurations exist, you must resolve the ambiguity by comparing full configurations. Treat each valid configuration as a sequence of $n$ numbers (the tiers for microservices 1 through $n$ in order). You must select the sequence that is strictly smaller than all other valid sequences when compared lexicographically. If no such configuration is possible, you must report this failure.

## Input
The first line provides $n$ and $m$ — the number of microservices and the number of flawed pairs. The registry limit bounds the microservices ($1 \le n \le 40$), and the flaw count ranges from none to all possible combinations ($0 \le m \le n(n-1)/2$).
The following $m$ lines each contain two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating that microservice $u$ and microservice $v$ share a parallel execution flaw.

## Output
If the system cannot be stabilized, output a single line with the word NO.
Otherwise, output YES on the first line. On the second line, output $n$ integers separated by spaces, where each integer is 1, 2, or 3, representing the tiers assigned to microservices 1 through $n$ respectively, following the full-sequence ranking rule described above.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

I rewrote the lexicographic tie-breaking rule to describe a comparison of complete configurations rather than an element-by-element minimization process. This forces models to recognize that finding the lexicographically smallest sequence can still be done via ordered backtracking, rather than being explicitly instructed to minimize each assignment successively. I also integrated the constraint bounds into the scenario description while preserving their exact mathematical forms to satisfy strict validation.
</RATIONALE>
