<METHOD_DESCRIPTION>Rewrites the graph coloring inequality $c_u \neq c_v$ as a set cardinality constraint $|\{c_u, c_v\}| = 2$ and obfuscates the base-4 lexicographical objective function $\sum c_i 4^{n-i}$ using its base-2 equivalent $\sum c_i 2^{2n-2i}$. This prevents models from immediately recognizing that they can optimize the search by stopping at the first valid leaf in an index-order DFS, forcing a full state space exploration (TLE) for pattern-matching models.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You are auditing a ledger of $n$ sequential financial transactions, indexed from $1$ to $n$. For each transaction $i$, you must assign a risk tier $c_i$. There are exactly three risk tiers available, represented by the values $1$, $2$, and $3$.

The ledger contains $m$ dependency links. Each link specifies a pair of transactions. Due to regulatory rules, for every such pair, the set of risk tiers assigned to the two transactions must contain exactly two distinct values. If this condition fails for any link, it triggers a compliance violation.

Your objective is to determine a compliant risk configuration for the entire ledger. If there is more than one compliant configuration, you must output the one that yields the minimum possible value for the audit hash, which is calculated using the formula:
$$ \sum_{i=1}^{n} c_i \cdot 2^{2n - 2i} $$
If there is no way to assign the risk tiers without a compliance violation, you must report that the configuration is impossible.

## Input
The first line provides two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — the number of transactions and the number of dependency links.
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating that a dependency link connects transaction $u$ and transaction $v$.

## Output
If a compliant configuration is impossible, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the risk tiers for transactions $1$ through $n$ that minimize the audit hash.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I changed the thematic framing from structural engineering to financial auditing to prevent surface-level pattern matching to graph coloring. I reformulated the inequality constraint $c_u \neq c_v$ as a set cardinality condition ($|\{c_u, c_v\}| = 2$) to bypass simple AST-based constraint recognition. Most importantly, I mathematically obfuscated the tie-break objective formula from $\sum c_i 4^{n-i}$ to $\sum c_i 2^{2n-2i}$. This preserves the exact objective value but obscures the base-4 positional nature of the sum, forcing models that rely on shallow pattern matching to evaluate the full search space (resulting in Time Limit Exceeded) rather than correctly deducing that they can stop at the first valid assignment in an index-order DFS.
</RATIONALE>
<PRESERVED_ANSWER>
The set cardinality constraint is strictly mathematically identical to $c_u \neq c_v$, and the objective formula $2^{2n-2i}$ is algebraically identical to $4^{n-i}$, ensuring the exact same configurations are valid and the exact same unique minimum is chosen for every input.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to finding a valid 3-coloring of a graph, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the set cardinality constraint if they do not recognize that the set of risk tiers for two transactions can only ever have size 1 or 2, though the wording "contain exactly two distinct values" is standard and unambiguous.
</RISK>
