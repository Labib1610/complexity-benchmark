# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You are auditing a ledger of $n$ sequential financial transactions, indexed from $1$ to $n$. Because a single auditor processes exactly one transaction per hour, a standard 40-hour work week strictly limits the ledger to a maximum of 40 transactions. A ledger will always contain at least one transaction. For each transaction $i$, you must assign a risk tier $c_i$. There are exactly three risk tiers available, represented by the values $1$, $2$, and $3$.

The ledger contains $m$ dependency links. A ledger can have no links at all, or it can be fully interconnected, meaning $m$ can reach the maximum possible number of distinct pairs among the $n$ transactions. Each link specifies a pair of transactions. Due to regulatory rules, for every such pair, the set of risk tiers assigned to the two transactions must contain exactly two distinct values. If this condition fails for any link, it triggers a compliance violation.

Your objective is to determine a compliant risk configuration for the entire ledger. If there is more than one compliant configuration, you must output the one that yields the minimum possible value for the audit hash, which is calculated using the formula:
$$ \sum_{i=1}^{n} c_i \cdot 2^{2n - 2i} $$
If there is no way to assign the risk tiers without a compliance violation, you must report that the configuration is impossible.

Please note: the testing data includes deeply interconnected ledgers specifically engineered to cause severe execution delays for approaches that merely resolve the transactions in their sequential index order. Careful consideration of how transactions are evaluated is necessary to complete the audit within the time limit.

## Input
The first line provides two integers $n$ and $m$ — the number of transactions and the number of dependency links.
Each of the subsequent $m$ lines contains two integers $u$ and $v$ (where $1 \le u, v \le n$ and $u \ne v$), indicating that a dependency link connects transaction $u$ and transaction $v$.

## Output
If a compliant configuration is impossible, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ space-separated integers from the set $\{1, 2, 3\}$, representing the risk tiers for transactions $1$ through $n$ that minimize the audit hash.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
