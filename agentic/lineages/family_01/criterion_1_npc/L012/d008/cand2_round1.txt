# Problem A — Risk Audit

Time limit: 2 s
Memory limit: 256 MB

You are auditing a ledger of sequential financial transactions. The ledger contains a sequence of transactions, indexed starting from $1$. For each transaction $i$, you must assign a risk tier $c_i$. There are exactly three risk tiers available, represented by the scalar values $1$, $2$, and $3$.

The ledger also specifies dependency links between certain transactions. Each link connects a pair of transactions $u$ and $v$. Due to regulatory rules, the risk tiers assigned to any linked pair must be linearly independent when combined with a unit vector. Specifically, for every dependency link between transaction $u$ and transaction $v$, their assigned tiers $c_u$ and $c_v$ must satisfy the determinant condition:
$$ \det \begin{pmatrix} c_u & c_v \\ 1 & 1 \end{pmatrix} \ne 0 $$
If this condition fails for any link, it triggers a compliance violation.

Your objective is to determine a compliant risk configuration for the entire ledger. If there is more than one compliant configuration, you must output the one that yields the minimum possible value for the final audit hash. The audit hash is computed sequentially through the ledger. Let the audit state at step $i$ be represented by a column vector $V_i = \begin{pmatrix} H_i \\ 1 \end{pmatrix}$. Starting with an initial state $V_0 = \begin{pmatrix} 0 \\ 1 \end{pmatrix}$, each transaction $i$ (from $1$ up to the total number of transactions) updates the state via the transformation matrix:
$$ V_i = \begin{pmatrix} 4 & c_i \\ 0 & 1 \end{pmatrix} V_{i-1} $$
You must output the configuration that minimizes the top element of the final state vector. If there is no way to assign the risk tiers without a compliance violation, you must report that the configuration is impossible.

*Performance Warning:* The audit logs in the test data include adversarial dependency structures specifically constructed to force exhaustive fixed-order evaluation to explore an exponential number of states. Your implementation must employ dynamic evaluation ordering or advanced pruning to avoid exceeding the time limit.

## Input
The first line provides two integers: the number of transactions and the number of dependency links. The number of transactions is at least $1$ and at most the regulatory batch limit of $40$. The number of dependency links is at least $0$ and at most the maximum possible number of unique unordered pairs of distinct transactions.
Each of the subsequent lines contains two integers $u$ and $v$ (where $u \ne v$), indicating that a dependency link connects transaction $u$ and transaction $v$. Transactions are indexed starting from $1$.

## Output
If a compliant configuration is impossible, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output the space-separated sequence of chosen scalar values from the set $\{1, 2, 3\}$, representing the risk tiers for all transactions in index order that minimize the audit hash.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
I removed the explicit numeric inequalities for the bounds and replaced them with descriptive text ("regulatory batch limit of 40", "maximum possible number of unique unordered pairs"). I also introduced an explicit "Performance Warning" suggesting that fixed-order evaluation will TLE on adversarial test cases. This forces models to reconsider their standard index-order backtracking; if they switch to dynamic vertex ordering (like MRV) to save time, they will lose the lexicographical guarantee and fail the test.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical definition of the final state vector's top element exactly matches the base-4 polynomial from the seed, ensuring the lexicographically smallest valid assignment is still the only correct answer.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core requirement remains assigning values from {1, 2, 3} such that adjacent nodes have different values (enforced by the determinant condition), which is exactly 3-coloring and inherently NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "maximum possible number of unique unordered pairs" if they don't recognize it as $n(n-1)/2$, but this is standard mathematical phrasing and unambiguous.
</RISK>
