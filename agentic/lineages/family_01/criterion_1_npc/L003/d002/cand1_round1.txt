# Acoustic Levitation Arrays

Time limit: 2 s   Memory limit: 256 MB

You are calibrating a network of acoustic levitation emitters. The central power supply provides exactly 400 Watts, and each active emitter draws exactly 10 Watts. Consequently, the total number of emitters in the array, $n$, can be anywhere from a single emitter up to a maximum of forty. Emitters are numbered from 1 to $n$.

Each emitter must be tuned to one of exactly three available phase offsets, denoted by the configuration codes 1, 2, and 3.

Due to the spatial layout, $m$ specific pairs of emitters have overlapping focal regions. The number of such overlaps $m$ ranges from zero up to the theoretical limit where every possible pair of emitters overlaps. When two emitters share a focal region, their waves interact. If the product of their assigned phase configuration codes evaluates to a perfect square, the waves will perfectly synchronize, doubling the local pressure and shattering the levitated sample. To guarantee safe and stable levitation, the product of the configuration codes assigned to any two emitters with a shared focal region must never equal a perfect square.

Be aware that the evaluation suite contains intensely interconnected, adversarial layouts specifically engineered to defeat greedy heuristics. A robust, systematic exploration of the configuration space is strictly required to process these inputs successfully.

Given the list of emitter pairs that share a focal region, determine if a safe phase configuration exists for all $n$ emitters.

## Input
The first line contains the two integers $n$ and $m$.
This is followed by $m$ lines, each containing two integers $u$ and $v$, indicating that emitter $u$ and emitter $v$ share a focal region.

## Output
If it is impossible to safely configure the array, print NO on a single line.
Otherwise, print YES on the first line. On the second line, output $n$ integers $p_1, p_2, \dots, p_n$ (each chosen from $\{1, 2, 3\}$), where $p_i$ is the phase configuration code for emitter $i$. If there are multiple valid configurations, any of them is accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
