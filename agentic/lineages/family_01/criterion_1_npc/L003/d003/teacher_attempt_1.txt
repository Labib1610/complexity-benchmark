# Facility Automation Control: Module Execution Scheduling

Time limit: 2 s   Memory limit: 256 MB

## Description
A central controller manages $n$ processing modules numbered from $1$ to $n$. Each module must be assigned to operate in one of three available execution phases, indexed as 1, 2, or 3.

Certain pairs of modules cause bus contention if they operate in the exact same execution phase simultaneously. You are given a list of $m$ pairs of mutually incompatible modules. An assignment of phases to modules is valid if no incompatible pair shares the same phase index.

To maintain system stability and deterministic startup order, if multiple valid phase assignments exist, the controller chooses the unique configuration that prioritizes earlier-indexed modules. Specifically, it breaks ties by preferring a smaller phase number at module 1; if a tie persists, it prefers a smaller phase number at module 2, continuing sequentially through module $n$. If it is impossible to assign phases 1, 2, or 3 to all modules without causing bus contention, the system cannot initialize.

Determine if a valid phase assignment exists. If so, output `YES` along with the phase sequence selected by the controller. Otherwise, report `NO`.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le \frac{n(n-1)}{2}$) — the number of modules and the number of contention constraints.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n, u \neq v$), indicating that module $u$ and module $v$ cannot share the same execution phase.

## Output
If no valid phase configuration exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ space-separated integers $s_1, s_2, \dots, s_n$ where $s_i \in \{1, 2, 3\}$ represents the phase assigned to module $i$. If multiple valid assignments exist, output the one selected by the controller's tie-breaking rule described above.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
The key textual trigger "lexicographically smallest sequence" was rephrased into an explicit step-by-step priority rule for resolving ties module by module. This prevents models from immediately matching standard keyword shortcuts and forces them to parse the operational tie-breaker rule to deduce the equivalent greedy search strategy.
</RATIONALE>
<PRESERVED_ANSWER>
The outputs remain identical for all inputs because prioritizing smaller phase numbers sequentially from module 1 to module $n$ is the exact definition of lexicographical ordering.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem remains 3-coloring on graphs with $n \le 40$, which is NP-complete.
</PRESERVED_CLASS>
