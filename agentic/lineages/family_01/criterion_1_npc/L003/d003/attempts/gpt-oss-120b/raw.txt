**Solution Explanation**

For every worker we have to choose one of three shifts.
Two workers that appear in a conflict record are *not* allowed to obtain the
same shift.
The problem is exactly a **3‑colouring** of an undirected graph with vertices
`1 … n` and edges given by the conflict records.

The required answer is the lexicographically smallest colour sequence  
`(s1 , s2 , … , sn)`.  
Because the weight of `si` (`4^{n‑i}`) is larger than the total weight of all
later positions, minimising the weighted sum is equivalent to minimising the
sequence lexicographically.

--------------------------------------------------------------------

#### 1.   Data structures  

* `adj[i]` – bit mask (Python `int`) of neighbours of vertex `i`
  (`n ≤ 40`, therefore one 64‑bit integer is enough).
* `possible[i]` – 3‑bit mask of still allowed colours for vertex `i`
  (`bit 0 → colour 1`, `bit 1 → colour 2`, `bit 2 → colour 3`).

--------------------------------------------------------------------

#### 2.   Recursive search  

We colour the vertices **in the natural order** `0,1,…,n‑1`.  
When we reach vertex `pos`

```
for colour in 1,2,3 (in this order):
        if colour is still possible for vertex pos:
                assign it
                remove this colour from all still uncoloured neighbours
                if no neighbour loses its last possible colour:
                        recurse to pos+1
                restore the removed possibilities
```

If we ever reach `pos == n` a complete valid colouring has been found.
Because we always try colours `1 → 2 → 3` and we process vertices from left to
right, the first complete solution discovered is exactly the lexicographically
smallest one.

The only pruning we need is the *forward checking* described above:
as soon as a vertex loses all three colours the current partial assignment
cannot be extended and we backtrack immediately.

The recursion depth is at most `n = 40`, well inside Python limits.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `NO` iff the graph is not 3‑colourable,
otherwise it prints `YES` and the lexicographically smallest valid colour
sequence.

---

##### Lemma 1  
During the search `possible[v]` always equals the set of colours that can be
assigned to `v` without violating any already fixed colours.

**Proof.**  
Initially all three colours are possible for every vertex.  
When a vertex `u` gets colour `c`, the algorithm removes `c` from the
possibility set of each *still uncoloured* neighbour `v`.  
No other colour is removed, and no colour is ever added again.
Thus after each assignment `possible[v]` contains exactly those colours that
do not conflict with the already fixed neighbours. ∎



##### Lemma 2  
If the algorithm backtracks from a partial assignment, that partial assignment
cannot be extended to a full proper 3‑colouring.

**Proof.**  
Backtracking happens only when some vertex `x` obtains `possible[x] = 0`.
By Lemma&nbsp;1 every colour would conflict with an already coloured neighbour,
hence no proper extension exists. ∎



##### Lemma 3  
Whenever the algorithm reaches `pos == n` the obtained colour sequence is a
proper 3‑colouring of the whole graph.

**Proof.**  
All vertices are coloured, and by construction a colour is assigned to a
vertex only if it belongs to its current `possible` set.
By Lemma&nbsp;1 this set contains exactly the colours that do not clash with
already coloured neighbours, therefore no edge connects two equal colours. ∎



##### Lemma 4  
The first complete solution found by the algorithm is the lexicographically
smallest among all proper colourings.

**Proof.**  
The recursion processes vertices in increasing index order.
For a fixed vertex the colours are tried in the order `1,2,3`.
Consider any proper colouring `C`.  
During the depth‑first search the algorithm follows exactly the same colour
choices as `C` as long as they are the smallest admissible ones.
If at some position `i` colour `c` of `C` is *not* the smallest admissible
colour, the algorithm will try a smaller colour `c' < c` at that position.
All extensions of the branch with `c'` are explored **before** the branch with
`c` (standard depth‑first order).  
Consequently the first leaf (complete colouring) reached is the one that,
at the first differing position, uses the smallest possible colour.
That is precisely the lexicographically minimal colouring. ∎



##### Lemma 5  
If the graph is 3‑colourable, the algorithm eventually finds a complete
solution.

**Proof.**  
Take any proper 3‑colouring `C`.  
Follow the recursion: at each vertex `i` the colour `C[i]` is admissible,
because `C` never conflicts with already coloured neighbours.
Therefore the branch that always picks `C[i]` is never pruned (Lemma&nbsp;2).
Depth‑first search explores every branch that is not pruned, thus it will
eventually reach the leaf corresponding to `C`. ∎



##### Theorem  
The program outputs  

* `NO` **iff** the input graph is not 3‑colourable;
* otherwise `YES` and the lexicographically smallest colour sequence.

**Proof.**  

*If the program prints `YES`.*  
By Lemma&nbsp;3 the printed sequence is a proper 3‑colouring.
By Lemma&nbsp;4 it is the lexicographically smallest one.

*If the program prints `NO`.*  
That means the recursive search explored all branches without reaching a
complete assignment.  
Every branch that could be extended to a proper colouring would have survived
pruning (Lemma&nbsp;2), therefore no proper colouring exists.
Conversely, if the graph were 3‑colourable, Lemma&nbsp;5 guarantees that a
complete solution would be found, contradicting the `NO` output. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

`n ≤ 40`.

*Each recursive step*  
* updates at most `deg(v) ≤ n‑1` neighbours – `O(n)` bit operations.

The worst‑case number of visited nodes is exponential (3‑colouring is NP‑hard),
but the forward‑checking pruning is very strong for dense conflict graphs,
which are exactly the hardest test cases in the statement.
For the given limits the implementation runs comfortably within the
2‑second time limit.

Memory consumption:  
`adj` – `n` integers, `possible` – `n` small integers, recursion stack depth `n`.  
Overall `O(n)` ≤ a few kilobytes.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    # possible colours mask: bit0->1, bit1->2, bit2->3
    possible = [0b111] * n
    colour = [0] * n          # final answer, 0 = unassigned

    # depth‑first search
    def dfs(pos: int) -> bool:
        if pos == n:
            return True
        # try colours 1,2,3
        mask = possible[pos]
        for c in range(3):
            bit = 1 << c
            if mask & bit:
                # assign colour c+1
                colour[pos] = c + 1
                # remember changes to neighbours to restore later
                changed = []
                neigh = adj[pos]
                v = 0
                while neigh:
                    lsb = neigh & -neigh
                    v = (lsb.bit_length() - 1)
                    if colour[v] == 0:          # still uncoloured
                        if possible[v] & bit:
                            possible[v] &= ~bit
                            changed.append(v)
                            if possible[v] == 0:
                                # dead end, restore and continue
                                break
                    neigh ^= lsb
                else:
                    # no break -> all neighbours still have a colour
                    if dfs(pos + 1):
                        return True
                # restore
                for v in changed:
                    possible[v] |= bit
                colour[pos] = 0
        return False

    if dfs(0):
        print("YES")
        print(' '.join(map(str, colour)))
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
