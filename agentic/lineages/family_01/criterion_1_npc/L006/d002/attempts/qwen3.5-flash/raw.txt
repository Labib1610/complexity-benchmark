The problem asks for the lexicographically smallest valid assignment of 3 security clearance tiers to $n$ personnel members, subject to $m$ constraints (pairs that cannot have the same tier). If no valid assignment exists, output `NO`. Otherwise, output `YES` and the assignment.

Constraints: $n \le 40$, $m \le n(n-1)/2$. Time limit: 2s.

This is a graph 3-coloring problem. We need to find a valid 3-coloring that is lexicographically smallest. Since $n$ is small (up to 40), we can use backtracking with pruning. To ensure lexicographical order, we must try assigning colors $1, 2, 3$ to personnel $1, 2, \dots, n$ in that order. Specifically, we fix $s_1$, then $s_2$, and so on. The first valid full assignment found by this DFS will be the lexicographically smallest.

To make the backtracking efficient enough for $n=40$, we should use forward checking. Forward checking maintains the set of available colors for each unassigned node. When a node is assigned a color, we remove that color from the available colors of its unassigned neighbors. If any neighbor's available colors become empty, we prune that branch immediately.

Since we need to backtrack efficiently, we need to restore the state of available colors when backtracking. Since $n$ is small, we can maintain the `avail` array globally and update it during the recursion.

Algorithm:
1. Parse input $n, m$ and the edges. Build an adjacency list.
2. Initialize `avail` array where each entry is a bitmask representing available colors. Initially, all colors $\{1, 2, 3\}$ are available for all nodes (bitmask `7` i.e., `111` in binary).
3. Initialize `assignment` array to store the chosen colors.
4. Call a recursive function `solve(u)` where `u` is the current personnel index (0-indexed, from 0 to $n-1$).
5. In `solve(u)`:
   - Iterate `c` from 1 to 3.
   - Check if `c` is available for `u` (bit check on `avail[u]`).
   - Check forward checking: if assigning `c` to `u` would make any unassigned neighbor `v > u` have no available colors. This happens if `avail[v]` becomes 0 after removing `c`.
   - If valid:
     - Assign `c` to `u` (update `assignment[u]`).
     - Update `avail` for neighbors `v > u`: remove `c` from `avail[v]`.
     - Recurse: `if solve(u + 1): return True`.
     - Backtrack:
       - Restore `avail` for neighbors `v > u`: add `c` back to `avail[v]`.
       - (Optionally clear `assignment[u]`, not strictly needed).
   - If loop finishes without returning True, return False.
6. If `solve(0)` returns True, print `YES` and the assignment. Else print `NO`.

Optimization:
- Use bitwise operations for speed.
- Use `sys.setrecursionlimit` to avoid recursion depth issues (though 40 is small).
- Use fast I/O.

Corner cases:
- $n=1$: Always YES 1.
- $m=0$: Always YES 1...1.
- Disconnected components: Handled naturally.
- No solution: Handled by returning False.

Complexity:
- In worst case, this is still exponential, but forward checking prunes significantly. For $n=40$, typical 3-coloring instances are solvable within 2s with this approach.

Implementation details:
- Nodes are 1-indexed in input, convert to 0-indexed.
- `avail` is a list of integers.
- `adj` is a list of lists.

```python
import sys

# Increase recursion depth just in case
sys.setrecursionlimit(5000)

def solve():
    input = sys.stdin.read
    data = input().split()
    
    if not data:
        return

    iterator = iter(data)
    n = int(next(iterator))
    m = int(next(iterator))
    
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(iterator)) - 1
        v = int(next(iterator)) - 1
        adj[u].append(v)
        adj[v].append(u)
    
    # avail[u] is a bitmask of available colors for node u
    # Colors are 1, 2, 3 mapped to bits 0, 1, 2
    # Initially all 3 colors available: 111 binary = 7
    avail = [7] * n
    assignment = [0] * n
    
    # To optimize, we can check if the graph is 3-colorable quickly?
    # For N=40, forward checking is usually sufficient.
    
    def backtrack(u):
        if u == n:
            return True
        
        # Try colors 1, 2, 3 in order
        for c in range(1, 4):
            # Check if color c is available for u
            # c=1 -> bit 0 (1), c=2 -> bit 1 (2), c=3 -> bit 2 (4)
            bit = 1 << (c - 1)
            
            if not (avail[u] & bit):
                continue
            
            # Forward checking: Check if assigning c to u makes any neighbor v > u have 0 options
            # We only need to check neighbors v > u because neighbors v < u are already assigned
            # and their constraints are already reflected in avail[u].
            # For v > u, we need to check if removing c from avail[v] makes it 0.
            # This happens if avail[v] == bit exactly.
            
            can_assign = True
            affected_neighbors = []
            
            for v in adj[u]:
                if v > u:
                    if avail[v] == bit:
                        can_assign = False
                        break
                    else:
                        affected_neighbors.append(v)
            
            if not can_assign:
                continue
            
            # Assign
            assignment[u] = c
            for v in affected_neighbors:
                avail[v] &= ~bit
            
            if backtrack(u + 1):
                return True
            
            # Backtrack
            for v in affected_neighbors:
                avail[v] |= bit
            assignment[u] = 0
            
        return False

    if backtrack(0):
        print("YES")
        print(*(assignment))
    else:
        print("NO")

if __name__ == '__main__':
    solve()
```
