# Bounded Sequence Synthesis

Time limit: 2 s   Memory limit: 256 MB

You are tasked with synthesizing an integer sequence $C$ of length $n$. Every element in the sequence must be chosen from the discrete domain $\{1, 2, 3\}$.

The sequence must satisfy a set of global bounds and pairwise interference relations. 

First, the sequence must conform to the following global baseline bounds:
1. The sum of the squares of all elements in $C$ must be strictly less than $10 \cdot n^2 + 42$.
2. For any valid index $i$, the natural logarithm of $C[i]$ must be strictly less than 1.5.
3. The harmonic sum of the sequence must satisfy: $\sum_{i=1}^n \frac{1}{C[i]} \ge \frac{n}{4}$.
4. The total variation must be bounded: $\sum_{i=1}^{n-1} |C[i+1] - C[i]| < 1000 \cdot n$.

Second, the sequence must satisfy $m$ specific pairwise interference conditions. Each condition is defined by a pair of 1-based indices $u$ and $v$. 
For each given pair $(u, v)$, the elements at those indices must satisfy the following trigonometric threshold:
$$ \cos\left( \frac{\pi}{2} (C[u] - C[v]) \right) \le 0.5 $$

Your objective is to determine if at least one such sequence $C$ can be constructed that satisfies all the global baseline bounds and all $m$ pairwise interference conditions simultaneously.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$). 
The following $m$ lines each contain two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), indicating a pairwise interference condition applied to the elements at index $u$ and index $v$.

## Output
If no such sequence can be constructed, output `NO` on a single line.
If a valid sequence exists, output `YES` on the first line. On the second line, output $n$ integers representing the valid sequence $C[1], C[2], \dots, C[n]$. If there are multiple valid sequences, any of them will be accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
The models were bypassing the intended difficulty by recognizing the local condition as `C[u] != C[v]` and immediately applying an optimized graph coloring template (e.g., degree-ordered backtracking). To defeat this, I wrapped the pairwise condition in a trigonometric function and introduced four "fake" global constraints that look numerically complex but are mathematically guaranteed to be true for any sequence of 1s, 2s, and 3s. This forces the model to perceive the task as a generic Constraint Satisfaction Problem rather than a pure graph problem, pushing it to use naive backtracking which will time out for $n=40$.
</RATIONALE>
<PRESERVED_ANSWER>
The global bounds are algebraically true for any sequence restricted to {1, 2, 3}, and the cosine inequality evaluates to true if and only if C[u] ≠ C[v], making the valid sequences exactly identical to the valid 3-colorings of the seed graph.
</PRESERVED_ANSWER>

The problem remains equivalent to checking if a graph is 3-colorable, preserving its NP-completeness, as the added global bounds can be verified in O(n) time and do not restrict the solution space.
