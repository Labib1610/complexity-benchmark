# Problem A — Quantum Resonance Tiers

Time limit: 2 s
Memory limit: 256 MB

You are configuring a quantum key distribution network consisting of $n$ repeater nodes, numbered 1 through $n$. Each node must be assigned a discrete resonance tier of 1, 2, or 3.

The network contains entanglement links between certain pairs of nodes. For a link to remain stable, its harmonic product—defined strictly as the product of the resonance tiers of the two nodes it connects—must not be a perfect square. If this product is a perfect square (an integer that is the square of another integer), the link will experience destructive resonance and fail. 

Note that the test data includes configurations specifically structured such that evaluation approaches which process nodes in numerical order, or sort them solely by their number of connections, will explore too many invalid states.

You are given the total number of nodes and the specific pairs that are connected by entanglement links. Determine a valid resonance tier assignment for all $n$ nodes that ensures every link remains stable, or report that no such assignment exists.

## Input
The first line contains two integers $n$ and $m$ — the number of repeater nodes and the number of entanglement links ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$).
Each of the following $m$ lines contains two distinct integers $u$ and $w$ ($1 \le u, w \le n$, $u \neq w$), representing a pair of nodes connected by an entanglement link. It is guaranteed that each unordered pair of nodes appears at most once in the input.

## Output
If no valid resonance tier assignment can be found, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $a_1, a_2, \dots, a_n$ (where each $a_i \in \{1, 2, 3\}$), representing the resonance tier assigned to node $i$. Any valid assignment will be accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I changed the scenario to a quantum network configuration and replaced the explicit inequality constraint with a mathematically equivalent condition: the product of the two assigned values must not be a perfect square. This prevents models from immediately pattern-matching the problem to Graph 3-Coloring, forcing them to either deduce the mathematical equivalence to inequality or implement an advanced constraint-satisfaction heuristic (like MRV) from scratch rather than relying on standard graph templates.
</RATIONALE>
<PRESERVED_ANSWER>
Since the domain of values is restricted to {1, 2, 3}, the pairwise product of any two values is a perfect square (1, 4, or 9) if and only if the two values are identical, making the new constraint logically perfectly equivalent to the original inequality constraint.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly Graph 3-Coloring (NP-Complete), as the vertices, edges, and domain of colors are completely unchanged, and the new rule is isomorphic to standard vertex coloring.
</PRESERVED_CLASS>
<RISK>
Models might theoretically misinterpret "perfect square" if they consider non-integer roots, but the explicit parenthetical "(an integer that is the square of another integer)" strictly eliminates this ambiguity.
</RISK>
