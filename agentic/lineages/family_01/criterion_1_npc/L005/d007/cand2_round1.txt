Non-Commutative Algebraic Masking
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces a simple arithmetic equality check with a commutativity check over a specifically chosen set of non-commuting 2x2 matrices. Because the matrices only commute with themselves, the condition remains exactly equivalent to equality. Models relying on surface pattern matching will fail to recognize the equivalence to standard graph 3-coloring, forcing them to either symbolically evaluate the matrix products or implement a custom backtracking solver that executes matrix multiplication at each step.
</METHOD_DESCRIPTION>

<STATEMENT>
# Problem A — Distributed Shard Routing

Time limit: 2 s   Memory limit: 256 MB

You are configuring a distributed database with $n$ storage nodes. The hardware chassis is arranged as a 5 by 8 grid of slots, meaning the number of storage nodes $n$ is at least 1 and cannot exceed the total number of slots in this grid. To ensure optimal load distribution, each node must be assigned to exactly one of 3 available data shards. The shards are identified by the integer IDs 1, 2, and 3.

You are given a list of $m$ high-frequency query patterns. The number of these patterns $m$ can be zero, up to a maximum of one pattern for every possible distinct pair of nodes present in the chassis. Each pattern involves a specific pair of nodes $(u, v)$ that are frequently accessed together.

To prevent routing bottlenecks, the hash-based router must never produce a collision for any of these high-frequency pairs. The router evaluates a pair of nodes by taking their assigned shard IDs, $c_u$ and $c_v$. Each shard ID is associated with a specific $2 \times 2$ transformation matrix:
- Shard 1 uses matrix $M_1 = \begin{pmatrix} 0 & 1 \\ 1 & 0 \end{pmatrix}$
- Shard 2 uses matrix $M_2 = \begin{pmatrix} 1 & 1 \\ 0 & 1 \end{pmatrix}$
- Shard 3 uses matrix $M_3 = \begin{pmatrix} 1 & 0 \\ 1 & 1 \end{pmatrix}$

A routing collision occurs if and only if the transformations commute. Specifically, if $M_{c_u} \times M_{c_v} = M_{c_v} \times M_{c_u}$, then the pair $(u, v)$ produces a collision. 

To maintain system stability, you must assign a shard ID (1, 2, or 3) to each of the $n$ nodes such that strictly zero collisions occur among all $m$ given query patterns.

## Input
The first line contains two integers $n$ and $m$ — the number of storage nodes and the number of high-frequency query patterns. The values of $n$ and $m$ are guaranteed to respect the physical limits of the chassis described above.
Each of the subsequent $m$ lines contains two integers $u$ and $v$, representing a pair of nodes involved in a high-frequency query pattern. Nodes are indexed from 1 to $n$.

## Output
If no such assignment is possible, output NO on a single line.
Otherwise, output YES on the first line. On the second line, output $n$ integers $c_1 \ c_2 \dots c_n$ (each being 1, 2, or 3), where $c_i$ is the shard ID assigned to node $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
Removed the direct arithmetic divisibility check that allowed models to easily deduce the equality condition. Replaced it with a matrix commutativity check using three distinct non-commuting 2x2 matrices. Additionally, applied Strategy S07 to remove bare numeric bounds, replacing them with a physical grid description ("5 by 8 grid") and pair combinations. This forces models to either perform symbolic matrix algebra to rediscover the equality constraint or to run a custom search that evaluates matrix products natively.
</RATIONALE>
<PRESERVED_ANSWER>
The chosen matrices M_1, M_2, and M_3 only commute with themselves, meaning M_a * M_b = M_b * M_a if and only if a = b; thus, a collision still occurs exactly when the two nodes are assigned the identical shard ID.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains fundamentally equivalent to determining if a graph (where nodes are vertices and query patterns are edges) can be strictly 3-colored, which is NP-complete.
</PRESERVED_CLASS>
