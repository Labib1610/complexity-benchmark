<METHOD_NAME>Global Polynomial Product Trap</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the pairwise divisibility condition with a global product of cubic polynomials evaluated on each edge. The polynomial $c_u^3 + c_v^3 - c_u^2 c_v - c_u c_v^2$ factors to $(c_u+c_v)(c_u-c_v)^2$, which is non-zero iff $c_u \neq c_v$. Framing it as a global product $P \neq 0$ forces the model to either mathematically deduce the pairwise inequality and apply graph coloring with degree heuristics, or fall into the trap of writing a naive CSP/backtracking solver that evaluates the product at the leaves (or fails to prune early), which will time out on $N=40$. Furthermore, naive C++ solvers might overflow the product to exactly zero, failing the test case unless they reason about the structure.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem A — Distributed Shard Routing

Time limit: 2 s   Memory limit: 256 MB

You are configuring a distributed database with $n$ storage nodes. To ensure optimal load distribution, each node must be assigned to exactly one of 3 available data shards. The shards are identified by the integer IDs 1, 2, and 3.

You are given a list of $m$ high-frequency query patterns. Each pattern involves a specific pair of nodes $(u, v)$ that are frequently accessed together.

To prevent routing bottlenecks, the system evaluates the stability of the entire network using a global routing product $P$. For every high-frequency query pattern involving a pair of nodes $(u, v)$, the router computes a pattern score $S$ based on their assigned shard IDs $c_u$ and $c_v$:

$$S = c_u^3 + c_v^3 - c_u^2 \cdot c_v - c_u \cdot c_v^2$$

The global routing product $P$ is defined as the product of the pattern scores $S$ across all $m$ given patterns. (If $m = 0$, $P$ is defined as 1).

To maintain system stability, you must assign a shard ID (1, 2, or 3) to each of the $n$ nodes such that the global routing product $P$ is strictly non-zero.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$) — the number of storage nodes and the number of high-frequency query patterns.
Each of the subsequent $m$ lines contains two integers $u$ and $v$, representing a pair of nodes involved in a high-frequency query pattern. Nodes are indexed from 1 to $n$.

## Output
If no such assignment is possible, output NO on a single line.
Otherwise, output YES on the first line. On the second line, output $n$ integers $c_1 \ c_2 \dots c_n$ (each being 1, 2, or 3), where $c_i$ is the shard ID assigned to node $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The pairwise collision condition has been replaced with a global product of cubic polynomials. The polynomial algebraically factors to $(c_u + c_v)(c_u - c_v)^2$, meaning a score of zero occurs if and only if $c_u = c_v$. By framing the requirement as a global product $P \neq 0$, models that rely on surface pattern matching will likely implement a naive global constraint check that fails to prune the search tree early, leading to a Time Limit Exceeded on $N=40$. Models that genuinely reason will deduce that $P \neq 0 \iff \forall (u,v), c_u \neq c_v$ and apply an efficient 3-coloring algorithm.
</RATIONALE>
<PRESERVED_ANSWER>
The polynomial score $S$ for any pair evaluates to 0 if and only if the two assigned shard IDs are identical; therefore, the global product $P$ is non-zero exactly when no two paired nodes share the same shard ID, which is mathematically identical to the collision condition in the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly Graph 3-Coloring, which is NP-complete, as the underlying combinatorial requirement (assigning 3 states such that no specified pair shares the same state) is unchanged.
</PRESERVED_CLASS>
<RISK>
A rigid interpretation might argue that computing the exact global product $P$ could exceed a 64-bit integer for large $m$, but since the task mathematically only requires ensuring $P \neq 0$ (which equates to ensuring no factor is zero), the mathematical definition is unambiguous and standard for algorithmic problem solving.
</RISK>
