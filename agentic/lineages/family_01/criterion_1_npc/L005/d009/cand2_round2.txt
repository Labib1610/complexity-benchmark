<STATEMENT>
# Problem A — Distributed Shard Routing

Time limit: 2 s   Memory limit: 256 MB

You are configuring a distributed database with $n$ storage nodes. To ensure stable load distribution, each node must be assigned to exactly one of 3 available data shards. The shards are identified by the integer IDs 1, 2, and 3.

You are given a list of $m$ high-frequency query patterns. Each pattern involves an unordered pair of nodes that are frequently accessed together.

To prevent routing bottlenecks, the hash-based router evaluates these pairs using a permutation checksum. Each shard ID corresponds to a specific swapping operation on a 3-element array:
- Shard 1 swaps the elements at the 1st and 2nd positions.
- Shard 2 swaps the elements at the 2nd and 3rd positions.
- Shard 3 swaps the elements at the 1st and 3rd positions.

For each high-frequency pair of nodes, the router evaluates their assigned shards by taking a fresh array `[X, Y, Z]` and applying both nodes' swapping operations to it in sequence. A routing collision occurs if the final array is identical to the starting array `[X, Y, Z]`. Because of the nature of these specific operations, applying them in either order yields the exact same collision result; the evaluation is completely symmetric.

To maintain system stability, you must assign a shard ID (1, 2, or 3) to each of the $n$ nodes such that strictly zero collisions occur among all $m$ given query patterns. 

## Input
The first line contains two integers $n$ and $m$ — the number of storage nodes and the number of high-frequency query patterns ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$).
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing an unordered pair of nodes involved in a high-frequency query pattern. Nodes are indexed from 1 to $n$. Each unordered pair appears at most once in the input. The order of $u$ and $v$ within a line, and the order of the lines themselves, is irrelevant.

## Output
If no such assignment is possible, output NO on a single line.
Otherwise, output YES on the first line. On the second line, output $n$ integers $c_1 \ c_2 \dots c_n$ (each being 1, 2, or 3), where $c_i$ is the shard ID assigned to node $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
The previous attempt failed because it introduced directional semantics to an inherently undirected problem. This rewrite fixes that by explicitly stating the pairs are unordered and the operations are symmetric, while enforcing the $c_u \neq c_v$ constraint via group-theoretic involutions (transpositions on an array). This completely masks the 3-coloring equivalence, forcing the model to deduce the mathematical property without relying on surface-level graph heuristics like DSATUR.
</RATIONALE>
<PRESERVED_ANSWER>
The product of two transpositions is the identity if and only if they are the exact same transposition; thus, the final array equals the starting array if and only if the two assigned shard IDs are identical, preserving the exact same valid assignments as the seed.
</PRESERVED_ANSWER>
