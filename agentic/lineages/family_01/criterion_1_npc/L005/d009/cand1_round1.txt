# Problem A — Distributed Shard Routing

Time limit: 2 s   Memory limit: 256 MB

You are configuring a distributed database with $n$ storage nodes. To ensure stable load distribution, each node must be assigned to exactly one of 3 available data shards. The shards are identified by the integer IDs 1, 2, and 3.

You are given a list of $m$ high-frequency query patterns. Each pattern involves a specific pair of nodes $(u, v)$ that are frequently accessed together.

To prevent routing bottlenecks, the hash-based router evaluates these pairs using a signature-matching protocol. First, each node $i$ (for $1 \le i \le n$) is classified into one of three Sectors based on its index:
- Sector 1: $i \bmod 3 = 1$
- Sector 2: $i \bmod 3 = 2$
- Sector 3: $i \bmod 3 = 0$

When a node is assigned a Shard ID, it emits a specific Signature (X, Y, or Z) according to its Sector:
- For a Sector 1 node: Shard 1 emits X, Shard 2 emits Y, Shard 3 emits Z.
- For a Sector 2 node: Shard 1 emits Y, Shard 2 emits Z, Shard 3 emits X.
- For a Sector 3 node: Shard 1 emits Z, Shard 2 emits X, Shard 3 emits Y.

A routing collision occurs if a high-frequency query pattern between two nodes results in an incompatible pair of signatures. Since the query patterns are bidirectional, the order of the two nodes in the input does not matter. The incompatibility rules are:

1. If the two nodes belong to the SAME Sector, they collide if they emit the SAME Signature (i.e., both emit X, both emit Y, or both emit Z).
2. If the pattern involves one node from Sector 1 and one node from Sector 2, they collide if the Sector 1 node emits X and the Sector 2 node emits Y; or if the Sector 1 node emits Y and the Sector 2 node emits Z; or if the Sector 1 node emits Z and the Sector 2 node emits X.
3. If the pattern involves one node from Sector 2 and one node from Sector 3, they collide if the Sector 2 node emits X and the Sector 3 node emits Y; or if the Sector 2 node emits Y and the Sector 3 node emits Z; or if the Sector 2 node emits Z and the Sector 3 node emits X.
4. If the pattern involves one node from Sector 3 and one node from Sector 1, they collide if the Sector 3 node emits X and the Sector 1 node emits Y; or if the Sector 3 node emits Y and the Sector 1 node emits Z; or if the Sector 3 node emits Z and the Sector 1 node emits X.

To maintain system stability, you must assign a Shard ID (1, 2, or 3) to each of the $n$ nodes such that strictly zero collisions occur among all $m$ given query patterns. 

## Input
The first line contains two integers $n$ and $m$ — the number of storage nodes and the number of high-frequency query patterns ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$).
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing a pair of nodes involved in a high-frequency query pattern. Nodes are indexed from 1 to $n$.

## Output
If no such assignment is possible, output NO on a single line.
Otherwise, output YES on the first line. On the second line, output $n$ integers $c_1 \ c_2 \dots c_n$ (each being 1, 2, or 3), where $c_i$ is the shard ID assigned to node $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
I replaced the simple algebraic condition with a node-index-dependent state mapping. Nodes are classified into Sectors, and their Shard IDs are mapped to Signatures using a sector-specific permutation. The collision rules are then defined as a complex set of asymmetric incompatibilities between Signatures across different Sectors. Mathematically, these rules perfectly evaluate to exactly `c_u == c_v`, but their presentation prevents models from algebraically simplifying the constraint to a simple equality check. This forces them to treat the problem as a generic CSP with edge-specific constraints, preventing the use of standard 3-coloring heuristics like DSATUR and causing generic backtracking solutions to fail or time out.
</RATIONALE>
<PRESERVED_ANSWER>
The sector-based signature incompatibility rules are carefully constructed such that for any two nodes $u$ and $v$, their signatures collide if and only if they are assigned the exact same Shard ID, keeping all valid assignments identical to the seed problem.
</PRESERVED_ANSWER>

The problem remains exactly equivalent to Graph 3-Coloring, preserving its NP-Complete complexity class.
</PRESERVED_CLASS>
