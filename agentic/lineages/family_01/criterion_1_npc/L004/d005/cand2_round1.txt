<STATEMENT>
# Signal Transformation Pathways

**Time limit:** 2 s  
**Memory limit:** 256 MB  

You manage an array of $n$ signal processors, numbered from $1$ to $n$. Each processor must be configured with exactly one of three available transformation modes, denoted by the integers $1$, $2$, and $3$. 

When a signal carrying an integer value $x \in \{0, 1, 2\}$ passes through a processor, its value is transformed depending on the processor's configured mode:
- Mode 1: $T_1(x) = (2x + 1) \bmod 3$
- Mode 2: $T_2(x) = (2x + 2) \bmod 3$
- Mode 3: $T_3(x) = (2x) \bmod 3$

You are provided with a list of $m$ critical operational links between pairs of processors. For each critical link connecting processor $u$ and processor $v$, the system strictly requires that routing a signal sequentially through processor $v$ and then processor $u$ MUST alter the signal's value for at least one possible input. 

Mathematically, the composite transformation $T_u(T_v(x))$ must not equal $x$ for all $x \in \{0, 1, 2\}$. The critical links can connect any subsets of processors in arbitrary arrangements, and all $m$ routing requirements must be simultaneously fulfilled. (Note that because of the specific functions used, if $T_u(T_v(x)) \neq x$ for at least one $x$, it holds true for all $x$).

Your task is to determine if a complete, valid mode configuration can be established for all $n$ processors such that no critical link violates this transformation rule.

## Input
The first line consists of two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$), which represent the total number of processors and the total number of critical links.
Each of the following $m$ lines provides two integers $u$ and $v$ (indices from $1$ to $n$), identifying a pair of processors connected by a critical link.

## Output
If there is no way to configure the processors without violating the rules, output `NO` on a single line.
If a valid assignment is achievable, output `YES` on the first line. On the second line, provide a sequence of $n$ integers $c_1, c_2, \dots, c_n$ (where each $c_i \in \{1, 2, 3\}$) representing the transformation mode for each processor $i$. If more than one valid sequence exists, you must output the lexicographically smallest sequence (comparing the mode for processor $1$ first, then processor $2$, and so on up to processor $n$).

## Example 1
**Input:**
```
4 5
1 2
1 3
2 3
1 4
2 4
```
**Output:**
```
YES
1 2 3 3
```

## Example 2
**Input:**
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
**Output:**
```
NO
```
</STATEMENT>
<RATIONALE>
The problem of assigning 3 colors to nodes such that adjacent nodes have different colors has been isomorphicly mapped to assigning 3 linear modular functions such that their composition is not the identity function. Models that rely on recognizing "different values for adjacent entities" to trigger their optimized 3-coloring templates will instead see a function composition problem, forcing them to reason through the algebra or write heavier, unoptimized state-space searches.
</RATIONALE>
<PRESERVED_ANSWER>
Algebraically, $T_a(T_b(x)) = (4x + 2c_b + c_a) \bmod 3 = (x + 2c_b + c_a) \bmod 3$, which equals $x$ if and only if $2c_b + c_a \equiv 0 \pmod 3$, which strictly occurs if and only if $a = b$; thus the constraint perfectly preserves the requirement that $c_u \neq c_v$.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-coloring, which is NP-Complete, and the constraints and variables map 1:1 to the original formulation.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the order of function application, but the statement explicitly provides the mathematical notation $T_u(T_v(x))$ to eliminate any ambiguity.
</RISK>
