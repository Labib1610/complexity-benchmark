**Solution Explanation**

For every emitter we have to choose a frequency `1 , 2 , 3`.
For each critical pair `(u , v)` the two frequencies must be different,
i.e. `|f_u – f_v| ≥ 1`.  
The problem is exactly the *graph 3‑colouring* problem:

* vertices – emitters  
* edges   – critical pairs  
* colours – the three frequencies  

We have to decide whether the given graph is 3‑colourable and, if it is,
output the lexicographically smallest colour sequence
(`f₁` first, then `f₂`, …).

`n ≤ 40`, therefore an exponential backtracking search with good pruning
fits easily into the limits.



--------------------------------------------------------------------

#### 1.   Data structures

* `adj[i]` – 64‑bit integer, bit *j* is `1` iff there is an edge `i – j`
  (`0 ≤ i , j < n`).  
  With `n ≤ 40` a single integer is enough and neighbour iteration is fast.

* `allowed[i]` – 3‑bit mask, bit `c‑1` (`c = 1,2,3`) tells whether colour `c`
  is still possible for vertex `i`.  
  Initially `allowed[i] = 0b111`.

* `col[i]` – currently chosen colour (`0` = not chosen yet).

--------------------------------------------------------------------

#### 2.   Backtracking (depth‑first search)

Vertices are processed **in the natural order** `0 … n‑1`.  
For the current vertex `v`

```
for colour c = 1,2,3 (in this order)
        if c is still allowed for v
                assign c to v
                delete colour c from the allowed‑sets of all still
                uncoloured neighbours of v
                if no neighbour lost its last possible colour
                        recurse to vertex v+1
                undo all deletions (restore the masks)
                unassign v
```

*Why does this work?*  
When a neighbour `u` receives a colour `c`, the colour `c` can never be
used for `u` again, therefore we delete it from `allowed[u]`.  
If after a deletion `allowed[u]` becomes `0`, the partial assignment can
never be extended to a full solution – we backtrack immediately.

Because we always try colours `1 → 3` and vertices `1 → n`,
the first complete assignment found is the lexicographically smallest one.

The recursion depth is at most `n = 40`, well inside Python limits.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct lexicographically
smallest colouring **iff** such a colouring exists.

---

##### Lemma 1  
During the search `allowed[v]` always contains exactly the colours that
are still possible for vertex `v` respecting all already fixed colours.

**Proof.**  
Initially all three colours are possible, so the statement holds.
Assume it holds before assigning colour `c` to vertex `v`.
For every uncoloured neighbour `u` we delete `c` from `allowed[u]`,
because `u` may not receive the same colour as `v`.  
No other vertex is affected, therefore after the deletions the statement
still holds.  
When we backtrack we restore the deleted bits, returning to the previous
state, so the invariant is preserved throughout the whole execution. ∎



##### Lemma 2  
If the algorithm reaches recursion level `k` (`k` vertices already coloured)
then the partial assignment can be extended to a full proper 3‑colouring
**iff** the recursive call returns `True`.

**Proof.**  
*If* the call returns `True`, a full colouring was found in the deeper
recursion, therefore the current partial assignment is extendable.

*Only‑if*: suppose the current partial assignment is extendable.
Consider the first vertex `v` (the next one to colour) in the extension.
Its colour `c` is allowed for `v` (Lemma&nbsp;1), therefore the algorithm
will try `c`.  
All deletions performed by the algorithm are also performed in the
extension, so the recursive call after assigning `c` still has a feasible
extension and will eventually return `True`. ∎



##### Lemma 3  
When the algorithm finishes, the produced colour sequence (if any) is a
proper 3‑colouring of the whole graph.

**Proof.**  
A sequence is output only after the recursion has assigned colours to all
`n` vertices and returned `True`.  
By Lemma&nbsp;2 the assignment is extendable – but there are no vertices left,
hence it is a complete proper colouring. ∎



##### Lemma 4  
If a proper 3‑colouring exists, the algorithm finds one.

**Proof.**  
Take any proper 3‑colouring `C`.  
Proceed by induction over the recursion depth.
Assume the algorithm has already coloured the first `i` vertices exactly as
in `C`.  
Vertex `i+1` has colour `C[i+1]`, which is allowed (Lemma&nbsp;1), therefore
the algorithm will try this colour among the three possibilities.
Choosing it does not create a conflict, so the recursive call continues
with the first `i+1` vertices matching `C`.  
Thus the algorithm can follow `C` all the way to `i = n` and finally returns
`True`. ∎



##### Lemma 5  
The first complete colouring found by the algorithm is the lexicographically
smallest among all proper colourings.

**Proof.**  
The search order is a depth‑first traversal of a 3‑ary tree:
at each vertex we try colours `1,2,3` in this order, and vertices are processed
in increasing index.  
Depth‑first search explores the tree in *lexicographic* order of the leaf
labels (the colour sequences).  
Consequently the first leaf that corresponds to a proper colouring is the
lexicographically smallest one. ∎



##### Theorem  
The program prints  

* `NO`  **iff** the input graph is not 3‑colourable;  
* `YES` and a colour sequence otherwise, and this sequence is the
  lexicographically smallest proper 3‑colouring.

**Proof.**  

*If part*:  
If the program prints `YES`, by Lemma&nbsp;3 the printed sequence is a proper
3‑colouring, therefore the graph is 3‑colourable.

*Only‑if part*:  
If the graph is 3‑colourable, Lemma&nbsp;4 guarantees that the algorithm
finds a colouring, thus it prints `YES`.  
If the graph is not 3‑colourable, Lemma&nbsp;2 shows that every recursive
call returns `False`, the whole search fails and the program prints `NO`.

Finally, Lemma&nbsp;5 gives the lexicographically smallest property. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

`n ≤ 40`.

*Neighbour iteration* for a vertex touches each incident edge once,
therefore over the whole search each edge is examined at most twice
(once from each endpoint).  

Let `T` be the number of visited nodes of the search tree.
The work per node is `O(deg(v))`, so the total running time is `O(T·n)`.
In the worst case `T = 3^n`, but for `n = 40` the strong pruning
(`allowed` becoming empty) makes the explored part tiny for all practical
inputs; the program easily fits into the 2 seconds limit.

Memory consumption:

* adjacency masks – `n` integers  
* allowed masks – `n` integers  
* colour array – `n` integers  
* recursion stack – depth `n`

Overall `O(n)` ≤ a few kilobytes, far below the 256 MB limit.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n               # bitmask of neighbours
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    # 3 bits: colour 1 -> bit 0, colour 2 -> bit 1, colour 3 -> bit 2
    allowed = [0b111] * n
    col = [0] * n               # 0 = not coloured yet

    # depth‑first search, vertices are processed in order 0 .. n-1
    def dfs(v: int) -> bool:
        if v == n:
            return True

        mask = allowed[v]
        for c in (1, 2, 3):
            bit = 1 << (c - 1)
            if not (mask & bit):
                continue

            # assign colour c to vertex v
            col[v] = c
            changed = []          # neighbours whose mask lost this bit
            conflict = False

            neigh = adj[v]
            while neigh:
                lsb = neigh & -neigh
                u = (lsb.bit_length() - 1)
                neigh ^= lsb
                if col[u] == 0:    # neighbour not coloured yet
                    if allowed[u] & bit:
                        allowed[u] ^= bit   # delete the bit
                        changed.append(u)
                        if allowed[u] == 0:
                            conflict = True
                            # no need to continue deleting, but we still
                            # have to finish the loop to keep neighbour mask
                # already coloured neighbours are already consistent
                # because their colour was removed from allowed[v] earlier

            if not conflict:
                if dfs(v + 1):
                    return True

            # undo the deletions
            for u in changed:
                allowed[u] |= bit
            col[v] = 0

        return False

    if dfs(0):
        out = "YES\n" + " ".join(str(c) for c in col)
        sys.stdout.write(out)
    else:
        sys.stdout.write("NO\n")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
