**Solution Explanation**

For every sensor we have to choose one of three channels  
`1 , 2 , 3`.  
For each given interfering pair `(u , v)` the two sensors must obtain
different channels.

The task is a *3‑colouring* of an undirected graph with at most `40`
vertices.
We also have to output the lexicographically smallest colour sequence,
i.e. colour sensor `1` as small as possible, then sensor `2`, …



--------------------------------------------------------------------

#### 1.  Observations  

* `n ≤ 40` – the whole graph fits easily into memory.
* The required order of the output forces us to colour the vertices
  **exactly in the order `1 … n`**.
  While searching we may try the colours `1,2,3` for a vertex in this
  order – the first complete colouring we find is already the
  lexicographically smallest one.
* While colouring we can keep, for every still uncoloured vertex,
  the set of colours that are still possible for it.
  When we colour a vertex `v` with colour `c`,
  colour `c` becomes impossible for all still uncoloured neighbours of `v`.
  If for some neighbour the set becomes empty, the current partial
  colouring can never be extended – we have to backtrack immediately.
  This is the classic *forward checking* technique and prunes the search
  dramatically.

The whole search is a depth‑first recursion of depth `n ≤ 40`,
each step touches at most `n‑1 ≤ 39` neighbours – easily fast enough.



--------------------------------------------------------------------

#### 2.  Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices).
* `col[v]` – current colour of `v` (`0` = not coloured yet).
* `allow[v]` – bit mask of still possible colours for `v`  
  bit `0` → colour `1`, bit `1` → colour `2`, bit `2` → colour `3`.  
  Initially `allow[v] = 0b111 = 7`.

During recursion we have to undo the changes of `allow[·]`.
For that we store a *stack* of modifications:

```
changes = []          # list of (vertex, previous_mask)
```

When we remove a colour from a neighbour we push the old mask,
later we restore it by popping the stack.



--------------------------------------------------------------------

#### 3.  Algorithm  

```
DFS(idx):
    # idx = next vertex to colour (0 … n-1)
    if idx == n:                # all vertices coloured
        return True

    for colour in 1,2,3 (in this order):
        mask = 1 << (colour-1)
        if allow[idx] does NOT contain mask:   # colour already forbidden
            continue

        # try to colour vertex idx with 'colour'
        col[idx] = colour
        changes = []            # local list of modifications

        ok = True
        for each neighbour u of idx:
            if col[u] != 0:                 # already coloured → no effect
                continue
            old = allow[u]
            new = old & ~mask               # forbid this colour
            if new != old:
                changes.append((u, old))
                allow[u] = new
                if new == 0:                # neighbour has no colour left
                    ok = False
                    break

        if ok and DFS(idx+1):               # recurse
            return True                     # solution found

        # ----- backtrack -----
        for (u, old) in reversed(changes):
            allow[u] = old
        col[idx] = 0

    return False            # no colour works for vertex idx
```

The outer driver calls `DFS(0)`.  
If it returns `True` we output the colours stored in `col[·]`,
otherwise we output `NO`.

Because colours are tried in increasing order and vertices are processed
in the required order, the first complete solution is the lexicographically
smallest one.



--------------------------------------------------------------------

#### 4.  Correctness Proof  

We prove that the algorithm prints `NO` iff the graph is not 3‑colourable,
and otherwise prints `YES` followed by the lexicographically smallest
valid colouring.

---

##### Lemma 1  
During the execution of `DFS(idx)` the invariant holds:

*For every vertex `v` with `col[v] = 0` the set represented by `allow[v]`
contains exactly the colours that are still possible for `v`
with respect to the already coloured vertices `0 … idx‑1`.*

**Proof.**  
Initially (`idx = 0`) all vertices are uncoloured and `allow[v] = 0b111`,
which indeed contains all three colours.

Assume the invariant holds at the beginning of a call `DFS(idx)`.
When we try a colour `c` for vertex `idx` we remove `c` from the
`allow`‑set of each still uncoloured neighbour `u`.  
All other vertices keep their previous `allow`‑sets.
Because the only new restriction is “neighbour `idx` already uses colour `c`”,
the updated `allow[u]` is precisely the set of colours still possible for `u`.
All other vertices keep the correct set by the induction hypothesis.
Thus the invariant holds after the update.
When we backtrack we restore the old masks, returning to the previous
state where the invariant also held. ∎



##### Lemma 2  
If `DFS(idx)` returns `True`, the array `col` is a proper 3‑colouring of the
whole graph.

**Proof.**  
`DFS` returns `True` only after a recursive call `DFS(n)` succeeds.
That call is reached only after colours have been assigned to vertices
`0 … n‑1` without ever encountering a conflict:
* a colour is assigned to a vertex only if it is still allowed
  (checked by `allow[idx]`);
* after each assignment the algorithm aborts the branch immediately
  if some neighbour loses its last possible colour (i.e. `allow` becomes
  `0`).  
Therefore no edge ever connects two vertices with the same colour.
All vertices are coloured, so `col` is a proper 3‑colouring. ∎



##### Lemma 3  
If the graph admits a proper 3‑colouring, `DFS(0)` returns `True`.

**Proof.**  
Consider any proper 3‑colouring `C`.  
We show by induction on `idx` that the recursive search never discards the
partial assignment `C[0 … idx‑1]`.

*Base `idx = 0`*: trivially true.

*Induction step*: assume the search reaches the call `DFS(idx)` with
`col[0 … idx‑1] = C[0 … idx‑1]`.  
Because `C` is proper, colour `C[idx]` is still allowed for vertex `idx`
(the neighbours coloured earlier use different colours).  
Consequently the loop in `DFS(idx)` will try colour `C[idx]`
(at the latest when it reaches that colour in the order `1,2,3`).
When this colour is tried, the forward‑checking updates exactly the
restrictions imposed by `C[idx]`; they are compatible with the rest of
`C` (again because `C` is proper).  
Thus the recursive call `DFS(idx+1)` is entered with
`col[0 … idx] = C[0 … idx]`.  
By the induction hypothesis the branch following colour `C[idx]`
will finally succeed, so `DFS(idx)` returns `True`. ∎



##### Lemma 4  
If `DFS(0)` returns `True`, the produced colouring is the lexicographically
smallest among all proper 3‑colourings.

**Proof.**  
The algorithm processes vertices in the fixed order `1 … n`
and, for each vertex, tries colours in the increasing order `1,2,3`.
Depth‑first search explores the first colour completely before trying the
next colour for the same vertex.
Therefore the first complete colouring found is the one that
*uses the smallest possible colour for vertex 1*;
among those, the smallest possible colour for vertex 2; and so on.
Consequently it is exactly the lexicographically smallest proper
colouring. ∎



##### Lemma 5  
If the graph is not 3‑colourable, `DFS(0)` returns `False`.

**Proof.**  
Assume the contrary: `DFS(0)` returns `True`.  
By Lemma&nbsp;2 the algorithm would then have produced a proper 3‑colouring,
contradicting the assumption that none exists. ∎



##### Theorem  
The program prints  

* `NO` **iff** the given graph is not 3‑colourable;  

* otherwise `YES` followed by the lexicographically smallest proper
  3‑colouring.

**Proof.**  
*If part*:  
If the program prints `YES`, `DFS(0)` returned `True`.  
By Lemma&nbsp;2 the printed colours form a proper 3‑colouring,
and by Lemma&nbsp;4 they are the lexicographically smallest one.

*Only‑if part*:  
If the program prints `NO`, `DFS(0)` returned `False`.  
By Lemma&nbsp;5 the graph cannot be 3‑colourable. ∎



--------------------------------------------------------------------

#### 5.  Complexity Analysis  

*`n ≤ 40`, `m ≤ n·(n‑1)/2`.*

* **Memory**  
  * adjacency lists: `O(n + m)` ≤ `O(n²)` ≤ `1600` integers  
  * arrays `col`, `allow`: `O(n)`  
  * recursion stack depth `n`.  
  Total well below the 256 MiB limit.

* **Time**  
  In the worst case the algorithm may explore many branches,
  but each recursive step touches at most `deg(v) ≤ n‑1` neighbours,
  performing only constant‑time bit operations.
  Hence the work per visited node of the search tree is `O(n)`.  
  For the given limits (`n = 40`) the program easily fits into the
  2 seconds time limit; typical instances finish after exploring only a
  tiny fraction of the theoretical `3ⁿ` possibilities.

#### 6.  Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # adjacency lists
    neigh = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        neigh[u].append(v)
        neigh[v].append(u)

    # 0 = uncoloured, otherwise 1..3
    col = [0] * n
    # bitmask of allowed colours, bit 0 -> colour 1, etc.
    allow = [0b111] * n   # all three colours possible initially

    # depth‑first search with forward checking
    def dfs(idx: int) -> bool:
        if idx == n:
            return True

        cur_allowed = allow[idx]
        for colour in (1, 2, 3):
            mask = 1 << (colour - 1)
            if not (cur_allowed & mask):
                continue

            # assign colour
            col[idx] = colour
            changes = []          # (vertex, previous_mask)
            ok = True

            for u in neigh[idx]:
                if col[u] != 0:
                    continue
                old = allow[u]
                new = old & ~mask
                if new != old:
                    changes.append((u, old))
                    allow[u] = new
                    if new == 0:
                        ok = False
                        break

            if ok and dfs(idx + 1):
                return True

            # backtrack
            for u, old in reversed(changes):
                allow[u] = old
            col[idx] = 0

        return False

    if dfs(0):
        out = ['YES', ' '.join(str(c) for c in col)]
    else:
        out = ['NO']
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
