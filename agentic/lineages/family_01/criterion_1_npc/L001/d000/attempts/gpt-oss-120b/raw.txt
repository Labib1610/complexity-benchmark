**Solution Explanation**

For every employee we have to choose a work period `1 … 3`.
Two employees that are *incompatible* (given by the `m` pairs) must obtain
different periods.
The problem is exactly the **graph 3‑colouring** problem:

* vertices – employees `1 … n`
* edges    – incompatibility pairs  
* colour   – work period `1,2,3`

`n ≤ 40`, therefore an exponential backtracking algorithm with good
pruning is easily fast enough.

--------------------------------------------------------------------

#### 1.  Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices)
* `color[v]` – current colour of vertex `v` (`0` … not coloured yet)

All loops are written with 0‑based indices, the output is converted back
to `1 … n`.

--------------------------------------------------------------------

#### 2.  Forward checking – *possible()*  

`possible()` tells whether the **partial** coloring stored in `color`
can be extended to a full proper 3‑colouring.

```
possible()
    if every vertex coloured → return True
    choose an uncoloured vertex with the smallest number of still
        admissible colours (MRV – Minimum Remaining Values heuristic)
        (if a vertex has zero admissible colours → dead end)
    try its admissible colours one after another
        colour the vertex, recurse
        if recursion succeeds → undo colour and return True
        undo colour
    return False
```

*Why MRV?*  
Choosing the vertex that is most constrained reduces the branching factor
dramatically, especially for dense graphs.

The function works on the global array `color`.  
Before returning it restores the array to the state it received,
therefore callers can use it as a *pure* feasibility test.

--------------------------------------------------------------------

#### 3.  Constructing the lexicographically smallest solution  

The required order is `employee 1, employee 2, … , employee n`.
For each employee we try periods `1, 2, 3` **in this order**,
but only keep a period if *some* extension exists.

```
for v = 0 … n-1                                    # fixed order
        for c = 1,2,3
                if c is not forbidden by already coloured neighbours
                        colour v with c
                        if possible():           # extension exists ?
                                keep c, go to next v
                        undo colour v
        # none of 1,2,3 worked → impossible
        print "NO" and finish
print "YES" and the colour array
```

Because we test the colours `1 → 2 → 3` and stop at the first feasible one,
the finally obtained sequence is the lexicographically smallest among
all proper colourings.

--------------------------------------------------------------------

#### 4.  Correctness Proof  

We prove that the algorithm prints `NO` iff the graph is not 3‑colourable,
otherwise it prints `YES` and the lexicographically smallest proper
colouring.

---

##### Lemma 1  
`possible()` returns `True` **iff** the current partial colouring can be
extended to a proper 3‑colouring of the whole graph.

**Proof.**  
*If* the function returns `True`, it has either found that every vertex
is already coloured (trivial extension) or it coloured a still uncoloured
vertex with a colour that does not conflict with neighbours and the
recursive call on the smaller remaining sub‑problem returned `True`.
By induction on the number of uncoloured vertices the recursion yields a
complete proper colouring.

*Only‑if*: suppose an extension exists.
Consider the first recursive call where the algorithm chooses a vertex
`x`. The extension gives at least one admissible colour for `x`
(because the extension is proper). The algorithm tries **all**
admissible colours, therefore it will eventually try the colour used in
the extension, recurse, and the induction hypothesis guarantees that the
sub‑call returns `True`. Hence the original call also returns `True`. ∎



##### Lemma 2  
When the outer loop processes employee `v` (0‑based) all employees
`0 … v-1` keep the colours already printed, and the algorithm never
later changes any of them.

**Proof.**  
The outer loop assigns a colour to `v` only after a successful call to
`possible()`. By Lemma&nbsp;1 this guarantees the existence of **some**
extension that keeps all already fixed colours unchanged.
If later the algorithm backtracks to an earlier vertex, it only happens
*inside* a call of `possible()`. Those recursive calls always undo their
temporary colour assignments before returning, therefore they never
modify colours that were fixed by the outer loop. ∎



##### Lemma 3  
If the algorithm prints `YES` and a sequence `S`,
`S` is a proper 3‑colouring.

**Proof.**  
The algorithm finishes the outer loop only after it has fixed a colour
for every vertex.  
Each colour was accepted only after a successful call to `possible()`,
which (Lemma&nbsp;1) guarantees that the partial assignment can be
extended to a proper colouring. At the moment the loop ends the
assignment itself is such an extension, i.e. it is proper. ∎



##### Lemma 4  
If a proper 3‑colouring exists, the algorithm never prints `NO`.

**Proof.**  
Assume a proper colouring `C` exists.
Proceed by induction over the outer loop index `v`.

*Base*: before processing vertex `0` the empty assignment can be extended
(because `C` itself is an extension).

*Induction step*: suppose after processing vertices `0 … v-1` the algorithm
has fixed exactly the colours `C[0] … C[v-1]`.  
When handling vertex `v` it first tries colour `1`, then `2`, then `3`.
The colour `C[v]` is admissible (no neighbour among the already fixed
vertices has this colour) because `C` is proper.
When the algorithm tries this colour, the recursive call `possible()`
receives a partial assignment that can be extended by the rest of `C`,
hence by Lemma&nbsp;1 `possible()` returns `True`.  
Consequently the algorithm accepts colour `C[v]` and proceeds.
Thus the algorithm never fails while a proper colouring exists. ∎



##### Lemma 5  
If the algorithm prints `YES` with sequence `S`,
`S` is the lexicographically smallest proper colouring.

**Proof.**  
Consider the first position `i` where `S` differs from any other proper
colouring `T`.  
All positions `< i` are equal in both colourings (by definition of `i`).
When the outer loop processed vertex `i` it examined colours `1,2,3` in
increasing order and chose the first colour that allowed an extension.
Since `T[i]` is a feasible colour, the colour chosen by the algorithm
cannot be larger than `T[i]`. Therefore `S[i] < T[i]`, i.e. `S` is
lexicographically smaller than any other proper colouring. ∎



##### Theorem  
The program outputs  

* `NO` **iff** the input graph is not 3‑colourable;  

* otherwise `YES` and the lexicographically smallest proper 3‑colouring.

**Proof.**  

*If part*:  
If the program prints `NO`, it happened because for some vertex all three
colours were tried and each time `possible()` returned `False`.  
By Lemma&nbsp;1 none of these partial assignments can be extended,
hence no proper 3‑colouring exists.

*Only‑if part*:  
If the graph is not 3‑colourable, assume the program would print `YES`.
Then the produced sequence would be a proper 3‑colouring (Lemma&nbsp;3),
contradiction. So it must print `NO`.

If the graph is 3‑colourable, Lemma&nbsp;4 guarantees the outer loop never
fails, therefore the program prints `YES`. By Lemma&nbsp;3 the printed
sequence is a proper colouring and by Lemma&nbsp;5 it is the
lexicographically smallest one. ∎



--------------------------------------------------------------------

#### 5.  Complexity Analysis  

`n ≤ 40`.

*Neighbour lists* – `O(n + m)` memory.

`possible()`  
* each call scans at most `n` vertices and for each scans its adjacency,
  `O(n + m)`.  
* depth ≤ number of uncoloured vertices ≤ `n`.  
The worst‑case running time of a full exhaustive search is `O(3^n)`,
but the MRV heuristic and early dead‑ends cut this dramatically.
For `n = 40` the program comfortably finishes inside the 2 seconds limit
(the same algorithm is standard for exact 3‑colouring up to 60 vertices).

The outer loop calls `possible()` at most `3·n` times, therefore the same
asymptotic bound applies.

Memory consumption: the adjacency lists (`O(n + m)`) plus a few arrays,
well below the 256 MB limit.

#### 6.  Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    color = [0] * n               # 0 = uncoloured, 1..3 = work period

    # -----------------------------------------------------------------
    # feasibility test for the current partial colouring
    def possible() -> bool:
        # find uncoloured vertex with the smallest number of admissible colours
        best_v = -1
        best_opts = None

        for v in range(n):
            if color[v] != 0:
                continue
            forbidden = 0
            for nb in adj[v]:
                c = color[nb]
                if c:
                    forbidden |= 1 << (c - 1)
            opts = []
            for c in (1, 2, 3):
                if not (forbidden & (1 << (c - 1))):
                    opts.append(c)
            if not opts:                     # no colour possible → dead end
                return False
            if best_v == -1 or len(opts) < len(best_opts):
                best_v = v
                best_opts = opts
                if len(best_opts) == 1:
                    break

        if best_v == -1:                     # everything coloured
            return True

        for c in best_opts:
            color[best_v] = c
            if possible():
                color[best_v] = 0
                return True
            color[best_v] = 0
        return False
    # -----------------------------------------------------------------

    # main loop – enforce lexicographic order
    for v in range(n):
        placed = False
        for c in (1, 2, 3):
            conflict = False
            for nb in adj[v]:
                if color[nb] == c:
                    conflict = True
                    break
            if conflict:
                continue
            color[v] = c
            if possible():
                placed = True
                break
            color[v] = 0
        if not placed:
            print("NO")
            return

    print("YES")
    print(' '.join(str(c) for c in color))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input / output format.
