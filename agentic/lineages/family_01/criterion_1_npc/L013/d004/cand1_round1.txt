# Module Isolation Protocols

Time limit: 2 s   Memory limit: 256 MB

A distributed application is composed of a collection of software modules. To ensure fault tolerance, the application relies on three separate execution environments. These environments are referenced using the integer labels 1, 2, and 3.

Each module $i$ must be deployed to exactly one environment, denoted by $e_i \in \{1, 2, 3\}$.

During integration testing, engineers discovered that certain pairs of modules cause critical race conditions if they share the same environment. To mitigate this, a list of operational constraints has been compiled. Each constraint identifies two specific modules, $u$ and $v$, which must be isolated from one another. This isolation is mathematically enforced by the requirement:
$(e_u - e_v)^2 \ge 1$

These isolation requirements can form deeply interconnected dependency structures. Your task is to evaluate whether there exists a global deployment configuration that satisfies every isolation constraint simultaneously. If such a configuration exists, you must output it. Any valid deployment configuration is acceptable if multiple exist.

*Performance Warning:* The evaluation dataset contains intentionally adversarial, highly interwoven constraint configurations specifically chosen to defeat fixed-order and simple degree-ordered search strategies. Your implementation must be sufficiently robust to handle these dense structures within the time limit.

## Input
The first line provides two integers, $n$ and $m$. The integer $n$ represents the total number of modules, bounded such that $1 \le n \le 4! + 4^2$. The integer $m$ represents the number of isolation constraints, which is non-negative and will not exceed the maximum possible number of unique unordered pairs of $n$ modules.

Each of the following $m$ lines contains two integers $u$ and $v$. This indicates that module $u$ and module $v$ are subject to an isolation constraint and must satisfy $(e_u - e_v)^2 \ge 1$.

## Output
If no valid deployment configuration exists that satisfies all constraints, output a single line containing `NO`.
If a valid deployment is possible, output `YES` on the first line. On the second line, output $n$ space-separated integers $e_1, e_2, \dots, e_n$, where each $e_i \in \{1, 2, 3\}$ represents the environment label assigned to module $i$. Any valid configuration will be accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
