# Problem B — Market Reconciliation

Time limit: 1 s   Memory limit: 256 MB

A commodities exchange is auditing a group of market participants. The exchange's mainframe has a hard limit of 200,000 participant profiles per audit, though it will always process at least one. The transaction ledger's capacity allows it to store up to 200,000 bilateral contracts, and it may sometimes be completely empty.

To reconcile the ledger, the exchange must assign each participant a compliance status for the entire audit period. A status is an integer value, restricted to either 1 or 2. 

For a bilateral contract to be deemed valid by the audit system, the product of the compliance statuses of the two participants involved must be exactly 2. You must find a status assignment for all participants that validates every recorded contract. If the ledger cannot be reconciled under these rules, indicate that it is impossible.

## Input
The first line provides $n$ and $m$, the number of participants and bilateral contracts, respectively. The bounds on these values correspond to the mainframe and ledger capacities described above.
The following $m$ lines each contain two integers $u$ and $v$ — a pair of participants who entered into a bilateral contract.

## Output
If the ledger cannot be reconciled, output NO on a single line.
If it can, output YES on the first line. On the second line, output $n$ integers $r_1 \dots r_n$ (each in {1,2}), representing the lexicographically smallest valid sequence of statuses for participants $1$ through $n$.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
Removed the explicit "buyer and seller" opposite-role framing and the "sum to 3" hint, which strongly triggered bipartite graph pattern matching. Replaced it with a mathematical constraint (the product of statuses in {1,2} must equal 2), forcing the model to deduce that adjacent nodes must take different values. Moved the numeric limits out of the Input section into the scenario description as physical capacities to fulfill Strategy S07.
</RATIONALE>
<PRESERVED_ANSWER>
Since the statuses are restricted to {1, 2}, the only way their product can be exactly 2 is if one is 1 and the other is 2, which is logically identical to the original "sum to 3" constraint and preserves all valid assignments.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to finding a valid 2-coloring of a graph (or detecting an odd cycle), which is solved in linear time using BFS/DFS.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the bounds if they fail to parse the capacities from the description, though the phrasing is highly explicit.
</RISK>
