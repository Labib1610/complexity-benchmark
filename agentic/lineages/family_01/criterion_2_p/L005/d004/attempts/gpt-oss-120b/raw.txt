**Solution Explanation**

For every machine we have to choose a power `1` or `2`.
For a flagged pair `{u,v}` the product of the two powers must be `2`.

```
1·1 = 1      2·2 = 4      not allowed
1·2 = 2      2·1 = 2      allowed
```

So the two machines of every pair must receive **different** powers.
The whole problem is therefore exactly the problem of 2‑colouring a graph
(bipartite checking).

--------------------------------------------------------------------

#### 1.   Graph model
* vertices – machines `1 … n`
* undirected edges – the `m` flagged pairs  

A feasible configuration exists **iff** the graph is bipartite.

--------------------------------------------------------------------

#### 2.   Lexicographically smallest configuration
If a component is bipartite there are two possible colourings
(the two colour classes can be swapped).
All components are independent, we may decide the swap for each component
separately.

Lexicographic order compares the sequence from left to right.
When we first meet a vertex of a component we can freely decide which colour
class becomes power `1`.  
Choosing the colour of this first vertex to be `1` makes the whole sequence
as small as possible, because any later decision cannot change an earlier
position.

Therefore:

```
process vertices 1 … n
    if the component of the current vertex has not been oriented yet
          orient it so that this vertex receives power 1
    output the power according to the orientation
```

Isolated vertices have no edges, they belong to a component of size `1`.
The rule above also gives them power `1`.

--------------------------------------------------------------------

#### 3.   Algorithm
```
read n, m
build adjacency list

comp_id[1…n] = -1          # component number, -1 = unvisited
col[1…n]      = -1          # 0 / 1 inside the component
components = []            # list of vertex lists, one per component

for each vertex v (1 … n)
    if comp_id[v] == -1
        start new component id = len(components)
        bfs/dfs from v
            assign col (alternating 0/1)
            if an edge connects two vertices with the same col -> NOT bipartite
            store all visited vertices in a list
        add the list to components

if any component was not bipartite
        print "NO" and finish

orientation = [ -1 ] * number_of_components   # which colour (0/1) becomes power 1

answer = [0] * n
for i = 1 … n
        c = comp_id[i]
        if orientation[c] == -1
                orientation[c] = col[i]          # give this vertex power 1
        answer[i] = 1 if col[i] == orientation[c] else 2

print "YES"
print answer
```

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `"NO"` iff no feasible configuration
exists, otherwise prints `"YES"` and the lexicographically smallest
feasible configuration.

---

##### Lemma 1  
During the BFS/DFS of a component the algorithm detects a conflict
iff the component contains an odd cycle, i.e. is not bipartite.

**Proof.**  
The BFS colours the start vertex `0` and always gives a neighbour the
opposite colour.  
If an edge connects two already coloured vertices with the same colour,
the two vertices are at even distance from the start, therefore the edge
closes an odd cycle. Conversely, any odd cycle forces two adjacent vertices
to obtain the same colour by this rule. ∎



##### Lemma 2  
If the algorithm finishes the BFS/DFS phase without reporting a conflict,
the whole graph is bipartite and the arrays `col` and `comp_id` describe a
valid 2‑colouring of every component.

**Proof.**  
By Lemma&nbsp;1 each component contains no odd cycle, therefore it is bipartite.
The BFS construction gives opposite colours to the ends of every edge,
hence the obtained colouring is valid. ∎



##### Lemma 3  
For a bipartite component `C` let `c0` be the colour class that the
algorithm finally maps to power `1`.  
All vertices of `C` receive power `1` exactly when their colour equals `c0`,
otherwise power `2`. This assignment satisfies the product‑2 condition for
every edge of `C`.

**Proof.**  
Edges of `C` always connect vertices of different colours.
If one endpoint has colour `c0` (power 1) the other has colour `1‑c0`
(power 2). Their product is `1·2 = 2`. ∎



##### Lemma 4  
When the algorithm processes vertices in increasing order,
the first vertex of each component receives power `1`.

**Proof.**  
The first time a vertex `v` of component `C` is visited, `orientation[C]` is
still `-1`. The algorithm sets `orientation[C] = col[v]`. Consequently
`col[v] == orientation[C]` and by Lemma&nbsp;3 `v` gets power `1`. ∎



##### Lemma 5  
The produced sequence `answer[1…n]` is the lexicographically smallest among
all feasible power assignments.

**Proof.**  
Consider any feasible assignment `A`.  
Traverse indices `i = 1 … n`.  
Let `C` be the component of the first index where `answer` and `A` differ.
By Lemma&nbsp;4, `answer[i] = 1`.  
In any feasible assignment the two colour classes of `C` must be assigned
the values `{1,2}` (Lemma&nbsp;3). Since `answer[i] = 1`, the only way for `A`
to differ at position `i` is to assign `2` to this vertex, i.e. `A[i] = 2`.
Thus `answer[i] < A[i]`. Therefore `answer` is lexicographically smaller
than any other feasible assignment. ∎



##### Lemma 6  
If the algorithm prints `"NO"` then no feasible configuration exists.

**Proof.**  
`"NO"` is printed only when a conflict is detected during BFS.
By Lemma&nbsp;1 this means some component is not bipartite, i.e. contains an
odd cycle. In any assignment of `1`/`2` values two adjacent vertices of an odd
cycle cannot all be different, so the product‑2 condition cannot hold.
Hence no feasible configuration exists. ∎



##### Lemma 7  
If the algorithm prints `"YES"` then the printed assignment satisfies the
product‑2 condition for every edge.

**Proof.**  
`"YES"` is printed only if no conflict was found, therefore by Lemma&nbsp;2
the graph is bipartite and the colours are valid.
By Lemma&nbsp;3 the final mapping of colours to powers makes every edge
connect a `1` and a `2`, i.e. product `2`. ∎



##### Theorem  
The algorithm outputs  

* `"NO"` **iff** the instance has no feasible power configuration,  
* otherwise `"YES"` and the lexicographically smallest feasible configuration.

**Proof.**  
*If part*: by Lemma&nbsp;6.  
*Only‑if part*: if a feasible configuration exists, the graph must be
bipartite, otherwise Lemma&nbsp;1 would give a conflict. Hence the algorithm
does not output `"NO"` and proceeds to construct an assignment.
By Lemma&nbsp;7 this assignment is feasible, and by Lemma&nbsp;5 it is the
lexicographically smallest one. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis
*Building adjacency list* – `O(n + m)` memory and time.  
*BFS over all components* – each vertex and edge examined once: `O(n + m)`.  
*Final pass for orientation* – `O(n)`.  

Total time `O(n + m)` ≤ `4·10⁵`, well inside the 1 s limit.  
Memory consumption `O(n + m)` ≤ about 3 MB for the adjacency list plus
arrays, far below 256 MB.

#### 6.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    comp_id = [-1] * n          # component number
    col = [-1] * n              # 0 / 1 inside component
    components = []              # list of vertex lists per component
    ok = True

    for start in range(n):
        if comp_id[start] != -1:
            continue
        # new component
        cid = len(components)
        q = deque([start])
        comp_id[start] = cid
        col[start] = 0
        verts = [start]

        while q and ok:
            v = q.popleft()
            cv = col[v]
            for nb in adj[v]:
                if comp_id[nb] == -1:
                    comp_id[nb] = cid
                    col[nb] = cv ^ 1
                    q.append(nb)
                    verts.append(nb)
                else:
                    if col[nb] == cv:
                        ok = False
                        break
        if not ok:
            break
        components.append(verts)

    if not ok:
        sys.stdout.write("NO")
        return

    # orientation[c] = colour (0/1) that gets power 1
    orientation = [-1] * len(components)
    ans = [0] * n

    for i in range(n):
        cid = comp_id[i]
        if orientation[cid] == -1:
            orientation[cid] = col[i]          # give this vertex power 1
        ans[i] = 1 if col[i] == orientation[cid] else 2

    out = ["YES", " ".join(map(str, ans))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
