<STATEMENT>
# Problem B — Network Token Configuration

Time limit: 1 s
Memory limit: 256 MB

You are configuring a network of $n$ routing nodes. Each node $i$ must be assigned a configuration state $h_i$, which must be exactly either `1` or `2`.

You must satisfy $m$ routing constraints. Each constraint is given as a pair of indices $u$ and $v$, representing a directed routing check from node $u$ to node $v$. 
For each check, a token bucket is used to validate the connection between the two assigned states:
1. The bucket starts empty.
2. The source node $u$ adds exactly $h_u$ tokens to the bucket.
3. The destination node $v$ then processes the bucket by performing exactly $h_v$ sequential actions. For each action: if the bucket contains at least one token, it removes one token; if the bucket is empty, it adds one penalty token to the bucket.
4. The constraint is satisfied if and only if the bucket contains exactly 1 token after node $v$ has finished all of its actions.

Your task is to determine if there exists a valid configuration for all $n$ nodes such that every routing constraint is satisfied. 
If multiple valid configurations exist, you must output the one that is lexicographically smallest when represented as a sequence of integers $h_1, h_2, \dots, h_n$. A sequence $A$ is lexicographically smaller than sequence $B$ if, at the first index $i$ where they differ, the value in $A$ is strictly less than the value in $B$.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2 \cdot 10^5$, $0 \le m \le 2 \cdot 10^5$).
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$), representing a routing constraint from node $u$ to node $v$.

## Output
If there is no valid configuration, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ space-separated integers $h_1, h_2, \dots, h_n$ (each either `1` or `2`), representing the lexicographically smallest valid configuration.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<METHOD_NAME>Asymmetric State-Machine Trap</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces a symmetric boolean constraint with an asymmetric state-machine procedure (a token bucket) that evaluates to the exact same truth table. The procedure is framed as a directed operation from u to v. Models relying on surface-level reading will build a directed graph and fail to correctly propagate components, while models that genuinely analyze the state machine will discover the underlying symmetry and correctly build an undirected graph.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>
<RATIONALE>
Removed the explicit boolean clauses that enabled models to instantly recognize symmetric graph coloring. Replaced them with a token bucket state machine that evaluates to `True` if and only if $h_u \neq h_v$. The framing strongly implies a directed relationship, forcing the model to either blindly implement a directed graph (which will fail to color connected components correctly) or genuinely analyze the state machine to discover that the constraint is mathematically symmetric and requires an undirected graph.
</RATIONALE>
<PRESERVED_ANSWER>
The token bucket ends with exactly 1 token if and only if $h_u \neq h_v$ (for $h_i \in \{1, 2\}$), which is logically identical to the original problem's requirement that the two variables have opposite boolean values.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 2-coloring an undirected graph (bipartiteness testing), keeping the time complexity at O(n+m) and the class in P.
</PRESERVED_CLASS>
