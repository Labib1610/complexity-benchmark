# Secure Relay Configuration

Time limit: 1 s   Memory limit: 256 MB

A telecommunications network consists of $n$ data relays, numbered 1 to $n$. The network is housed in a facility that accommodates up to 20 server racks, each capable of holding exactly 10,000 relays. Thus, the network must contain at least one relay and cannot exceed the facility's total relay capacity.

To initialize the network, each relay must be assigned a base encryption key of either 1 or 2.

The network contains $m$ synchronization channels, each establishing a direct link between a specific pair of relays. The total number of channels $m$ can range from zero up to a maximum limit that is exactly equal to the facility's total relay capacity. For a channel to successfully authenticate its endpoints, the product of the encryption keys assigned to the two connected relays must evaluate to exactly 2.

You need to determine if there is a valid key assignment for all $n$ relays that successfully authenticates all $m$ channels. If a valid assignment exists, you must output it. In cases where multiple valid assignments satisfy all requirements, you must output the assignment that forms the lexicographically smallest sequence of keys.

## Input
The first line contains two integers $n$ and $m$, representing the number of relays and the number of channels, respectively. The bounds for $n$ and $m$ are defined by the facility constraints described above.
Each of the next $m$ lines contains two integers $u$ and $v$ — the numbers of two relays connected by a synchronization channel.

## Output
If no valid assignment exists, print a single line `NO`.
Otherwise print `YES`, followed by a second line containing $n$ integers $s_1 \dots s_n$ (each being 1 or 2), representing the lexicographically smallest valid sequence of encryption keys.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
Replaced the explicit bitwise XOR condition with a multiplicative condition (product equals 2) to remove the surface-level pattern that models associate with bitwise operations and 2-coloring. Replaced the direct numeric inequalities for $n$ and $m$ with an indirect derivation based on server rack capacities, forcing the model to carefully read and compute the bounds instead of scanning for inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
Since the only allowed keys are 1 and 2, their product is exactly 2 if and only if one key is 1 and the other is 2, which exactly matches the truth table of the original XOR condition ($1 \oplus 2 = 3$).
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to finding a valid 2-coloring of a graph (determining bipartiteness) and selecting the lexicographically first valid assignment, which is solvable in linear time using BFS or DFS.
</PRESERVED_CLASS>
<RISK>
Models might fail to correctly parse or multiply the rack capacity (20 * 10,000) to find the bounds, though the arithmetic is completely unambiguous.
</RISK>
