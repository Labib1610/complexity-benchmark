# Problem B — Day and Night

Time limit: 1 s
Memory limit: 256 MB

The factory planning process requires assigning each employee to a specific work period. The personnel database tracks $n$ active employees. The system requires at least one employee and has a strict architectural limit of $200,000$ employee records. The HR department's incompatibility registry contains $m$ logged pairs. This registry might be completely empty, and its hardware storage caps out at $200,000$ pairs.

Your task is to assign each employee a shift token, which must be either the integer 1 or the integer 2. To ensure smooth operations without supervision, for every pair of employees logged in the HR registry, the sum of their assigned shift tokens must evaluate to exactly 3. If no such token assignment is possible across the entire workforce, the plan must be rejected.

Once assigned, this schedule will be sent to the payroll department for final processing.

## Input
The first line contains two integers: the headcount $n$ and the registry size $m$.
Each of the next $m$ lines contains two integers $u$ and $v$ (between 1 and $n$) — the identifiers of a pair of employees logged in the incompatibility registry.

## Output
If no valid token assignment exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On a second line, print $n$ integers $s_1 \dots s_n$ (each being 1 or 2), representing the lexicographically smallest valid assignment.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<RATIONALE>
I replaced the explicit graph-coloring constraint ("no conflicting pair shares a shift") with a mathematical equivalent: the sum of the two assigned shift tokens (which must be 1 or 2) must equal 3. This forces the model to realize that $x+y=3$ for $x,y \in \{1,2\}$ is simply an inequality constraint $x \neq y$, demanding an abstraction step before applying standard bipartite checking. I also implemented Strategy S07 by describing the numeric bounds as database capacity limits rather than bare inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
The constraint that two variables from the set {1, 2} sum to 3 is logically identical to requiring that they take different values, which perfectly preserves the original non-sharing condition.
</PRESERVED_ANSWER>
