**Solution Explanation**

For every dampener (edge) `{u,v}` we need  

```
grade[u] + grade[v] = 3 ,   grade[i] ∈ {1,2}
```

Therefore the two ends must receive *different* grades, i.e. the graph must be
**bipartite**.  
If the graph is bipartite we have two possible colourings for each connected
component – we may exchange the two colour classes.
Among all feasible colourings we have to output the lexicographically smallest
sequence `c1 … cn`.

--------------------------------------------------------------------

#### 1.   Observations  

* `grade = 1` is smaller than `grade = 2`.  
  To minimise the whole sequence we want the smallest possible index to obtain
  grade `1`.  
* Components are independent: flipping colours inside one component does not
  influence any other component.
* Consequently we can decide the orientation of each component **independently**
  and greedily:
  *look at the smallest vertex index belonging to the component – give it grade
  `1`*.
  This yields the globally lexicographically smallest sequence, because any
  later decision cannot change an earlier position.

--------------------------------------------------------------------

#### 2.   Algorithm  

```
read n,m
build adjacency list

colour[1..n] = -1          # 0 / 1 for the two sides, -1 = unvisited
answer[1..n] = 0

for v = 1 .. n:
    if colour[v] == -1:
        # start a new component
        queue = [v]; colour[v] = 0
        component_vertices = [v]

        while queue not empty:
            x = pop queue
            for each neighbour y of x:
                if colour[y] == -1:
                    colour[y] = colour[x] ^ 1
                    push y to queue
                    component_vertices.append(y)
                elif colour[y] == colour[x]:
                    print "NO" and exit   # not bipartite

        # component is bipartite, decide orientation
        smallest = min(component_vertices)
        # if smallest currently has colour 0 we keep mapping 0→1,1→2,
        # otherwise we flip the mapping
        flip = (colour[smallest] == 1)

        for u in component_vertices:
            if flip:
                answer[u] = 1 if colour[u] == 1 else 2
            else:
                answer[u] = 1 if colour[u] == 0 else 2

# all components processed without conflict
print "YES"
print answer[1] … answer[n]
```

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `NO` iff no feasible assignment exists,
otherwise prints the lexicographically smallest feasible assignment.

---

##### Lemma 1  
If the algorithm prints `NO`, the input graph is not bipartite, therefore no
assignment satisfies all edges.

**Proof.** `NO` is printed only when during BFS an edge `{x,y}` with
`colour[x] == colour[y]` is found. This is exactly the definition of a graph
that is not bipartite. In any feasible assignment adjacent vertices must have
different grades, i.e. different colours, so a non‑bipartite graph cannot be
satisfied. ∎



##### Lemma 2  
If the algorithm finishes without printing `NO`, the produced `answer`
satisfies every edge.

**Proof.** For each component BFS assigned a proper 2‑colouring
(`colour` values differ on every edge). Afterwards we possibly flip the whole
colouring, which still keeps the two colour classes distinct.
Mapping colour `0 → 1, 1 → 2` (or the flipped version) gives grades `1` and `2`
that differ on every edge, hence sum `3`. ∎



##### Lemma 3  
For a fixed connected component, among the two possible grade assignments the
algorithm chooses the lexicographically smaller one restricted to the indices
of that component.

**Proof.** Let `s` be the smallest vertex index of the component.
The algorithm forces `grade[s] = 1`. The only other feasible assignment would
give `grade[s] = 2` (the opposite orientation). Since `1 < 2`, the chosen
orientation is lexicographically smaller on the component’s index set. ∎



##### Lemma 4  
Let the components be processed in increasing order of their smallest vertex.
After processing the first `k` components, the partial sequence of the first
`p` vertices (where `p` is the largest index among those components) is the
lexicographically smallest possible among all feasible global assignments.

**Proof.** Induction over `k`.

*Base `k=1`*: By Lemma&nbsp;3 the orientation of the first component is the
smallest among the two possibilities, therefore the prefix up to its largest
index is minimal.

*Induction step*: Assume the claim holds after `k-1` components.
Component `k` contains the smallest index not yet fixed; all earlier indices
are already at their minimal possible values.
Choosing the orientation that gives grade `1` to the smallest vertex of this
component (Lemma&nbsp;3) cannot worsen any earlier position and makes the new
prefix (up to the largest index of component `k`) minimal. ∎



##### Lemma 5  
The complete sequence `answer` output by the algorithm is the lexicographically
smallest feasible assignment.

**Proof.** After the last component all vertices are processed, so Lemma&nbsp;4
applies to the whole index set `{1,…,n}`. Hence no other feasible assignment
has a smaller prefix, i.e. the whole sequence is minimal. ∎



##### Theorem  
The algorithm outputs  

* `NO` iff no feasible assignment exists;  
* otherwise `YES` and the lexicographically smallest feasible assignment.

**Proof.**  
*If part*: By Lemma&nbsp;1, `NO` implies impossibility.  
*Only‑if part*: If a feasible assignment exists, the graph is bipartite,
so BFS never encounters a conflict and the algorithm does not print `NO`.  
By Lemma&nbsp;2 the produced assignment is feasible, and by Lemma&nbsp;5 it is
the lexicographically smallest one. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency list*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and edge is visited once → `O(n + m)`.  
*Additional work* (finding minima, filling answer) is linear in the component
size, overall `O(n)`.

Total time `O(n + m)` ≤ `4·10⁵`, well inside the limits.  
Memory consumption `O(n + m)` for adjacency list and arrays.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        adj[u].append(v)
        adj[v].append(u)

    colour = [-1] * (n + 1)          # 0 / 1
    answer = [0] * (n + 1)

    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        # BFS for this component
        q = deque([start])
        colour[start] = 0
        comp = [start]

        while q:
            x = q.popleft()
            cx = colour[x]
            for y in adj[x]:
                if colour[y] == -1:
                    colour[y] = cx ^ 1
                    q.append(y)
                    comp.append(y)
                elif colour[y] == cx:
                    sys.stdout.write("NO")
                    return

        # decide orientation: smallest vertex gets grade 1
        smallest = min(comp)
        flip = (colour[smallest] == 1)   # need to swap if smallest is colour 1
        if not flip:
            for v in comp:
                answer[v] = 1 if colour[v] == 0 else 2
        else:
            for v in comp:
                answer[v] = 1 if colour[v] == 1 else 2

    out = ["YES", " ".join(str(answer[i]) for i in range(1, n + 1))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```
