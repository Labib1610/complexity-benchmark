We can model each sensor’s basis as a binary variable and each link as a constraint.  

Let’s check the transformations:

- \( f_1(x) = (2x + 1) \bmod 5 \)  
- \( f_2(x) = (3x + 2) \bmod 5 \)  

For a link between \(u\) and \(v\), we need \( f_{b_v}(f_{b_u}(x)) = x \) for all \(x\).  

We can test all four combinations of bases:

- (1,1): \( f_1(f_1(x)) = 2(2x+1)+1 = 4x+3 \), not identity.  
- (1,2): \( f_2(f_1(x)) = 3(2x+1)+2 = 6x+5 \equiv x \pmod 5 \) → works.  
- (2,1): \( f_1(f_2(x)) = 2(3x+2)+1 = 6x+5 \equiv x \pmod 5 \) → works.  
- (2,2): \( f_2(f_2(x)) = 3(3x+2)+2 = 9x+8 \equiv 4x+3 \), not identity.

So the constraint is:  
**The two sensors on a link must have different bases.**

Thus, the problem reduces to:  
Given an undirected graph, can we 2-color it (bipartite check)? If yes, output the coloring that minimizes the base-3 integer.

To minimize the base-3 integer with digits 1 and 2 (where 1 < 2), we want as many leading 1’s as possible.  
So we do BFS/DFS, assign 1 to the first node, then alternate. If a conflict occurs → NO.

Here’s the implementation:

```python
import sys
from collections import deque

input = sys.stdin.readline

n, m = map(int, input().split())
adj = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

color = [-1] * n
possible = True

for i in range(n):
    if color[i] == -1:
        color[i] = 0
        q = deque([i])
        while q:
            u = q.popleft()
            for v in adj[u]:
                if color[v] == -1:
                    color[v] = 1 - color[u]
                    q.append(v)
                elif color[v] == color[u]:
                    possible = False
                    break
            if not possible:
                break
    if not possible:
        break

if not possible:
    print("NO")
else:
    print("YES")
    # color 0 -> basis 1, color 1 -> basis 2
    print(' '.join(str(c + 1) for c in color))
```
