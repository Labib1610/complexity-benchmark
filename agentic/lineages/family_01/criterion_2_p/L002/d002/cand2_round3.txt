# Module 2: Clearance Allocation

Time limit: 1 s   Memory limit: 256 MB

The HR analytics engine has compiled a list of personnel interactions that require strict oversight. 

Your task is to implement the clearance allocation processor. This processor receives the list of interactions and must assign each of the $n$ personnel a security clearance level of either `1` or `2`. To maintain operational safety, for each interaction between personnel $u$ and $v$ flagged by the HR engine, the bitwise XOR of the clearance level assigned to $u$ and the clearance level assigned to $v$ must evaluate to exactly 3.

If it is impossible to assign clearance levels in this manner, the processor must abort the workflow. Furthermore, whenever multiple valid assignments are possible, the compliance protocol requires the processor to output the one that yields the lexicographically smallest sequence of clearance levels (where the sequence is formed by the levels assigned to personnel 1 through $n$).

## Input
The first line contains two integers $n$ and $m$, representing the number of personnel and the number of flagged interactions. The headcount $n$ implies a physical capacity constraint where $1 \le n \le 2\cdot 10^5$. The interactions $m$ can be absent entirely or reach up to the system limit, meaning $0 \le m \le 2\cdot 10^5$.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$) — a pair of personnel whose clearance levels must satisfy the bitwise XOR requirement.

## Output
If the clearance allocation processor cannot find any valid assignment, output a single line with `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $s_1 \dots s_n$ (each either `1` or `2`), representing the clearance level assigned to each person from $1$ to $n$. This sequence must be the lexicographically smallest valid assignment.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The affordance "the product of the clearance level assigned to u and the clearance level assigned to v must be exactly 2" was heavily relied upon by models to instantly recognize the bipartite 2-coloring structure. This has been replaced with the condition that the bitwise XOR of the two levels evaluates to 3. Since the domain is restricted to {1, 2}, `1 XOR 2 = 3` while `1 XOR 1 = 0` and `2 XOR 2 = 0`, making the condition mathematically identical but forcing models to reason through the bitwise operation rather than relying on surface pattern matching.
</RATIONALE>
<PRESERVED_ANSWER>
The condition `u XOR v == 3` for values restricted to {1, 2} strictly enforces that one value is 1 and the other is 2, which is exactly mathematically equivalent to the original condition `u * v == 2`, meaning all valid and invalid assignments remain perfectly identical for every input.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem remains 2-coloring (bipartiteness testing) on an undirected graph, which is solvable in O(n+m) time using Breadth-First Search or Depth-First Search, keeping it firmly in the P complexity class.
</PRESERVED_CLASS>
