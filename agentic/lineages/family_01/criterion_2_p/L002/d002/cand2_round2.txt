# Module 2: Clearance Allocation

Time limit: 1 s
Memory limit: 256 MB

The annual company review process consists of three distinct modules executed in sequence. First, the HR analytics engine scans past incident reports to compile a list of personnel interactions that require strict oversight. 

Your task is to implement the second module: the clearance allocation processor. This processor receives the list of interactions and must assign each of the $n$ personnel a security clearance tier of either `1` or `2`. To maintain operational safety, for each interaction between personnel $u$ and $v$ flagged by the HR engine, the bitwise XOR of the clearance tier assigned to $u$ and the clearance tier assigned to $v$ must evaluate to exactly 3.

If it is impossible to assign clearance tiers in this manner, the processor must abort the workflow. Furthermore, whenever multiple valid assignments are possible, the compliance protocol requires the processor to output the one that yields the lexicographically smallest sequence of clearance tiers (where the sequence is formed by the tiers assigned to personnel 1 through $n$).

Finally, the output of your module is fed into the third module, the payroll system, which uses these clearance designations to apply shift differentials and finalize the weekly pay schedule.

## Input
The first line contains two integers $n$ and $m$. The corporate facility has a maximum headcount constraint, so the workforce size $n$ is guaranteed to be at least 1 and at most 200000. The HR engine's incident log capacity limits the number of flagged interactions $m$ to range from 0 up to 200000.
Each of the next $m$ lines contains two integers $u$ and $v$ (where $u$ and $v$ are valid personnel IDs from 1 to $n$ inclusive) — a pair of personnel whose clearance tiers must satisfy the bitwise XOR condition described above.

## Output
If the clearance allocation processor cannot find any valid assignment, output a single line with `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $s_1 \dots s_n$ (each either `1` or `2`), representing the clearance tier assigned to each person from 1 to $n$. This sequence must be the lexicographically smallest valid assignment.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<RATIONALE>
Changed the condition "product must be exactly 2" to "bitwise XOR must evaluate to exactly 3". Because the only allowed tier values are 1 and 2, 1 XOR 2 = 3 while equal tiers XOR to 0, which logically preserves the requirement that interacting pairs must receive differently valued tiers. Implemented S07 by expressing the numeric bounds dynamically through operational capacities (headcount and log limits) rather than as bare inequalities, while retaining the exact machine-checkable digits.
</RATIONALE>
<PRESERVED_ANSWER>
Since the only allowed values are 1 and 2, the requirement that their bitwise XOR evaluates to 3 is uniquely satisfied by the pairs (1, 2) and (2, 1), which is fundamentally identical to the seed's product requirement; thus all valid assignments remain precisely the same.
</PRESERVED_ANSWER>
