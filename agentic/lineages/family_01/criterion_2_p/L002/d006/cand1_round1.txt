<STATEMENT>
# Tiered Settlement Obligations

Time limit: 1 s   Memory limit: 256 MB

A financial clearinghouse is migrating $n$ institutional accounts to a new regulatory framework. Under this framework, each account must be assigned a compliance tier, strictly designated as either `1` or `2`.

The clearinghouse has identified $m$ reciprocal obligations between specific pairs of accounts. To satisfy risk-margin requirements, any two accounts $u$ and $v$ involved in a reciprocal obligation must form a joint supervisory committee. The protocol dictates that the committee is only valid if the assigned tiers $t_u$ and $t_v$ satisfy a specific cryptographic parity check: the sum of their squares ($t_u^2 + t_v^2$) must be an exact multiple of 5.

If there is no way to assign tiers to all $n$ accounts such that every reciprocal obligation satisfies this parity check, the migration must be halted. 

If multiple valid tier assignments are possible for the entire network, the compliance protocol mandates a strict sequential locking procedure to ensure a deterministic audit trail. You must determine the final sequence of tiers exactly as if you simulated the following procedure:
1. Initialize an empty locked sequence.
2. For each account $i$ from 1 to $n$ in increasing order:
   a. Check if there exists AT LEAST ONE fully valid global assignment for all $n$ accounts that matches all previously locked tiers for accounts $1 \dots i-1$, and also assigns tier `1` to account $i$.
   b. If such a global assignment exists, permanently lock account $i$ to tier `1`.
   c. If no such global assignment exists, permanently lock account $i$ to tier `2`.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2\cdot 10^5$, $0 \le m \le 2\cdot 10^5$), representing the number of accounts and the number of reciprocal obligations.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$) — a pair of accounts that share a reciprocal obligation.

## Output
If no valid tier assignment can be found, print `NO` on a single line.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1 \dots s_n$ (each either `1` or `2`), denoting the compliance tier for accounts 1 through $n$ that is produced by the sequential locking protocol.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<RATIONALE>
The edge condition was obfuscated into a modular arithmetic check on the sum of squares, which evaluates to True for {1, 2} and False for {1, 1} and {2, 2}. The "lexicographically smallest" tie-breaker was replaced with an explicit, step-by-step operational procedure that mathematically constructs the exact same sequence. This forces the model to either blindly implement the O(N^2) simulation and fail the time limit, or genuinely recognize that the procedure is functionally identical to the natural output of an O(N+M) BFS traversal.
</RATIONALE>
<PRESERVED_ANSWER>
The condition (t_u^2 + t_v^2) % 5 == 0 over the domain {1, 2} is mathematically identical to t_u != t_v, and the sequential locking procedure is the exact constructive definition of lexicographical minimization.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 2-coloring (bipartiteness testing), solvable in O(N+M) time using a standard Breadth-First Search.
</PRESERVED_CLASS>
