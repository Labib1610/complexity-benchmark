<STATEMENT>
# Problem B — System Configuration

Time limit: 1 s
Memory limit: 256 MB

A cloud provider must configure the operation mode for $n$ database instances. The total number of instances $n$ is strictly bounded by the maximum capacity of 200 server racks, each supporting exactly 1000 instances. At least one instance must be configured.

Certain pairs of instances share a dedicated backup storage array. The number of shared backup arrays $m$ is limited by a central switch that handles 2000 modules, each providing exactly 100 array connections. It is possible to have no shared arrays, or any number up to the switch's full capacity.

The configuration requires assigning each instance $i$ an operation mode $s_i$, which must be chosen from the set $\{1, 2\}$.

To maintain system stability, the synchronization protocol for any shared backup array requires that the operation mode assigned to one of its connected instances is exactly twice the operation mode assigned to the other.

You must assign a mode to each instance to satisfy all stability constraints, or determine that no such configuration exists. If multiple valid configurations exist, the automated deployment system requires the configuration whose sequence of mode assignments $s_1 \dots s_n$ is lexicographically smallest.

## Input
The first line contains two integers $n$ and $m$, representing the number of database instances and the number of shared backup arrays (whose maximum values are derived from the hardware limits described above).
Each of the next $m$ lines contains two integers $u$ and $v$, indicating that instances $u$ and $v$ share a backup array.

## Output
If no valid configuration exists, print a single line NO.
Otherwise print YES, then a second line with $n$ integers $s_1 \dots s_n$ (each in {1,2}), representing the lexicographically smallest valid configuration.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I applied strategy S07 by replacing the explicit numeric bounds for $n$ and $m$ with physical hardware capacities (200 racks of 1000 instances, 2000 modules of 100 connections) that multiply to exactly $2 \cdot 10^5$. To remove the identified affordance, I replaced the explicit absolute-difference equation with the requirement that one mode must be exactly twice the other, forcing the model to independently deduce the opposite-color requirement without relying on standard inequality phrasing.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that one mode is exactly twice the other, given the domain $\{1, 2\}$, restricts valid assignments for any shared array strictly to $\{1, 2\}$ and $\{2, 1\}$, which is identically the same set of valid assignments as the original absolute difference equation.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a valid 2-coloring (or detecting an odd cycle) and choosing the lexicographically first valid assignment, which remains solvable in $O(n+m)$ time using BFS or DFS, keeping it in P.
</PRESERVED_CLASS>
<RISK>
The physical capacity descriptions could be misinterpreted as implying $n$ and $m$ must be exact multiples of 1000 or 100, though the phrasing "strictly bounded by the maximum capacity" and "any number up to" is intended to clearly indicate an upper limit rather than a step size.
</RISK>
