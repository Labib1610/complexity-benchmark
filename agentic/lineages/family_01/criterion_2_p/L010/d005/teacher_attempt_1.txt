# Multi-Phase Deployment Orchestration

Time limit: 1 s   Memory limit: 256 MB

A cloud architect is configuring $n$ software modules, numbered 1 through $n$. Each module must be assigned to one of two execution phases, identified as Phase 1 and Phase 2.

Certain pairs of modules manipulate the same legacy data structures. If they operate during the same phase, they will cause a race condition. The architect has isolated $m$ such pairs. To prevent data corruption, the two modules in any identified pair must be assigned to distinct phases.

Your task is to determine whether all $n$ modules can be successfully configured without any race conditions.

If a valid configuration exists, you must provide the specific phase assignment for each module. The configuration engine standardizes deployments by favoring Phase 1, breaking ties by prioritizing lower-numbered modules for Phase 1. Formally, you must output the lexicographically smallest valid sequence of phase assignments. A sequence of assignments $s_1, \dots, s_n$ is lexicographically smaller than another valid sequence $t_1, \dots, t_n$ if, at the first module index $i$ where they differ, $s_i < t_i$.

## Input
The first line contains two integers $n$ and $m$, representing the number of modules and the number of race condition pairs. The environment guarantees at least one module will be deployed, while the infrastructure's maximum capacity imposes a hard upper limit of 200,000 modules for $n$. The monitoring system's log size dictates that the number of pairs $m$ can range from an empty log (0) up to a maximum of 200,000 entries.

Each of the following $m$ lines contains two integers $u$ and $v$ — a pair of modules that cannot operate in the same phase.

## Output
If it is impossible to configure all modules without race conditions, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1 \dots s_n$ (each in $\{1,2\}$), representing the lexicographically smallest valid phase assignment.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
