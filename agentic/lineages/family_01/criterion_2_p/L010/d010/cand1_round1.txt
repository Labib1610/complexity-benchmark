# Harmonized Frequencies

Time limit: 1 s
Memory limit: 256 MB

A manufacturing plant operates $n$ robotic assembly arms. Each arm must be configured to an integer operational mode $s_i$, which must be chosen from the set $\{1, 2\}$.

The facility has identified $m$ instances of workspace overlap. To avoid collisions, the entire network of arms must pass an aggregate safety check. For any arm $u$, let $k_u$ be the number of overlaps involving arm $u$, and let $C_u$ be the collection of the $k_u$ operational modes assigned to the other arm in each of these overlaps. 

A configuration is considered safe if and only if, for every arm $u$ from $1$ to $n$, the sum of the modes in $C_u$ plus the product of the modes in $C_u$ is exactly equal to:

$k_u (3 - s_u) + (3 - s_u)^{k_u}$

*(Note: If an arm has no overlaps, $k_u = 0$. The sum of an empty collection is 0 and its product is 1, so the condition evaluates to $0 + 1 = 0 \cdot (3 - s_u) + 1$, which is automatically satisfied.)*

Determine a valid operational mode for each assembly arm so that the safety check is passed for all arms. If no such configuration exists, you must report it.

The plant requires the operational modes to be standardized. If multiple valid configurations exist, you must output the lexicographically smallest sequence $s_1, \dots, s_n$.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2\cdot 10^5$, $0 \le m \le 2\cdot 10^5$), representing the number of assembly arms and the number of overlaps, respectively.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$) — indicating that the workspace of arm $u$ overlaps with the workspace of arm $v$.

## Output
If no valid configuration exists, print a single line NO.
Otherwise print YES, followed by a second line containing $n$ integers $s_1 \dots s_n$ (where each $s_i \in \{1,2\}$), representing the operational mode assigned to each arm. If multiple valid configurations exist, output the lexicographically smallest sequence $s_1 \dots s_n$.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<RATIONALE>
The problem was modified to replace the explicit local pairwise edge condition with a global neighborhood condition. Instead of checking a polynomial for each pair, the new condition requires the sum and product of all neighboring modes for a vertex $u$ to equal exactly $k_u(3-s_u) + (3-s_u)^{k_u}$. This forces the models to use algebraic extreme-value bounding to deduce that all neighbors must have the opposite mode, preventing them from simply evaluating the 4 possible pairs of an edge to bypass the reasoning step.
</RATIONALE>
<PRESERVED_ANSWER>
The condition equals the theoretical maximum of the sum+product when $s_u=1$ (forcing all neighbors to be 2) and the theoretical minimum when $s_u=2$ (forcing all neighbors to be 1), making it mathematically identical to the original requirement that every edge connects opposite modes.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying graph constraint remains strictly equivalent to proper 2-coloring, which is solvable in linear time using BFS/DFS, thus preserving the problem's membership in P.
</PRESERVED_CLASS>
<RISK>
Models might interpret the product of a large number of 2s as causing integer overflow if they attempt to simulate the condition directly in a low-level language, though the problem statement presents it purely as a mathematical property.
</RISK>
