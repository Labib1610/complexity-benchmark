**Solution Explanation**

For every edge `{u , v}` we need  

```
value[u] * value[v] = 2 ,   value[x] ∈ {1 , 2}
```

The only way to obtain the product `2` with numbers `1` and `2` is that the
two endpoints are different:

```
value[u] = 1 , value[v] = 2   or   value[u] = 2 , value[v] = 1
```

So the graph must be *bipartite* – its vertices can be coloured with two
colours such that adjacent vertices have different colours.
If the graph is not bipartite the answer is `NO`.

If it is bipartite, each connected component has exactly two possible
assignments:

* colour 0 → `1`, colour 1 → `2`
* colour 0 → `2`, colour 1 → `1`

We have to output the **lexicographically smallest** valid sequence.
Lexicographic order compares the first position where the two sequences differ,
preferring the smaller number (`1`).

Consider a component `C`.  
Let `p` be the smallest vertex index belonging to `C`.
Whatever we decide for the rest of the component, the value at position `p`
is the first place where this component can influence the whole answer.
Therefore we must give vertex `p` the value `1`.  
All other vertices of `C` are forced then:
the colour of `p` receives `1`, the opposite colour receives `2`.

Thus the optimal strategy is:

* run a BFS/DFS, colour the graph (0/1) and collect the vertices of each
  component,
* for each component remember its smallest vertex `p`,
* assign `1` to the colour of `p`, `2` to the other colour.

The whole algorithm is linear.



--------------------------------------------------------------------

#### Algorithm
```
read n , m
build adjacency list

comp_id = -1
colour[1..n] = undefined
component_of[1..n] = -1
list_of_vertices = []          # list per component
min_vertex = []                # smallest vertex per component

for v = 1 .. n
    if colour[v] is undefined
        start new component
        comp_id += 1
        queue = [v]
        colour[v] = 0
        component_of[v] = comp_id
        cur_vertices = []
        cur_min = v

        while queue not empty
            x = pop queue
            cur_vertices.append(x)
            cur_min = min(cur_min, x)

            for each neighbour y of x
                if colour[y] is undefined
                    colour[y] = colour[x] ^ 1
                    component_of[y] = comp_id
                    push y into queue
                else if colour[y] == colour[x]
                    print "NO" and exit   # not bipartite

        store cur_vertices into list_of_vertices[comp_id]
        store cur_min into min_vertex[comp_id]

# construct answer
answer[1..n]

for each component c
    p = min_vertex[c]
    colour_of_p = colour[p]          # 0 or 1 gets value 1
    for each vertex x in list_of_vertices[c]
        if colour[x] == colour_of_p
            answer[x] = 1
        else
            answer[x] = 2

print "YES"
print answer[1] … answer[n]
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `NO` iff no valid assignment exists,
otherwise it prints the lexicographically smallest valid assignment.

---

##### Lemma 1  
If the algorithm prints `NO`, the graph is not bipartite, therefore no
assignment satisfies all edges.

**Proof.** `NO` is printed only when during BFS an edge `{x,y}` with
`colour[x] == colour[y]` is found. This is exactly the definition of a
non‑bipartite graph. For such a graph any 2‑colouring (hence any assignment of
`1`/`2`) would give two equal values on that edge, product `1` or `4`, never `2`.
∎



##### Lemma 2  
If the graph is bipartite, the algorithm produces a sequence that satisfies
all edges.

**Proof.** For each component the BFS colours vertices with two colours
`0` and `1` such that adjacent vertices have opposite colours – this is the
definition of a bipartite colouring.  
The algorithm assigns value `1` to all vertices of the colour of the smallest
vertex `p` of the component and value `2` to the opposite colour.
Hence any edge connects a vertex of colour `0` and a vertex of colour `1`,
so its endpoints receive values `1` and `2`. Their product is `2`. ∎



##### Lemma 3  
For a bipartite component `C` let `p` be its smallest vertex.
Among all valid assignments for `C` the one that gives `p` the value `1`
is lexicographically smallest when considering only positions belonging to `C`.

**Proof.** Any valid assignment must give `p` either `1` or `2`.  
If it gives `2`, replace the whole component by swapping the two colours:
`p` becomes `1` and all other vertices keep the property of being different
along edges. The new sequence is identical to the old one at every earlier
position (none, because `p` is the smallest index of the component) and is
strictly smaller at position `p`. Hence any assignment with `p = 2` is
lexicographically larger than the one with `p = 1`. ∎



##### Lemma 4  
The sequence output by the algorithm is the lexicographically smallest
among all valid assignments for the whole graph.

**Proof.** Process vertices from `1` to `n`.  
When the first vertex `i` of a component `C` is encountered, `i` is exactly the
smallest vertex of `C`. By Lemma&nbsp;3 the algorithm chooses the only optimal
value for `i` (`1`). All later decisions are inside already fixed components
or in components whose smallest vertex is larger than `i`, therefore cannot
change the already minimal prefix. By induction over `i` the whole sequence is
lexicographically minimal. ∎



##### Theorem  
The algorithm

* prints `NO` iff no valid assignment exists,
* otherwise prints `YES` and the lexicographically smallest valid assignment.

**Proof.**  
*If the algorithm prints `NO`*: by Lemma&nbsp;1 no assignment exists.  

*If the algorithm prints `YES`*: the graph is bipartite, Lemma&nbsp;2 shows the
produced sequence is valid, and Lemma&nbsp;4 shows it is the lexicographically
smallest among all valid ones.  

Conversely, if a valid assignment exists, the graph is bipartite, the BFS
never encounters a conflict, so the algorithm does not print `NO`. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency list*: `O(n + m)` memory and time.  
*BFS over all vertices*: each vertex and edge is processed once → `O(n + m)`.  
*Constructing the answer*: each vertex once → `O(n)`.

Total time `O(n + m)` ≤ `4·10⁵`, well inside the limit.  
Memory usage `O(n + m)` ≤ about 3 MB for the adjacency list plus arrays,
well below 256 MB.

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        adj[u].append(v)
        adj[v].append(u)

    colour = [-1] * (n + 1)          # -1 = unvisited, else 0/1
    comp_id = -1
    comp_vertices = []               # list of lists
    comp_min = []                    # smallest vertex per component

    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        comp_id += 1
        q = deque([start])
        colour[start] = 0
        cur_vertices = []
        cur_min = start

        while q:
            x = q.popleft()
            cur_vertices.append(x)
            if x < cur_min:
                cur_min = x
            for y in adj[x]:
                if colour[y] == -1:
                    colour[y] = colour[x] ^ 1
                    q.append(y)
                elif colour[y] == colour[x]:
                    print("NO")
                    return
        comp_vertices.append(cur_vertices)
        comp_min.append(cur_min)

    # build answer
    ans = [0] * (n + 1)
    for cid, verts in enumerate(comp_vertices):
        p = comp_min[cid]
        col_of_p = colour[p]
        for v in verts:
            ans[v] = 1 if colour[v] == col_of_p else 2

    out = ["YES", " ".join(str(ans[i]) for i in range(1, n + 1))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```
