**Solution Explanation**

For an edge `u – v`

```
M = | xu  1 |
    | -1 xv |
det(M) = xu·xv – (‑1) = xu·xv + 1
```

`xu , xv` can only be `1` or `2`.

```
xu xv + 1 = 2   (1,1)   not a power of 3
xu xv + 1 = 3   (1,2) or (2,1)   OK
xu xv + 1 = 5   (2,2)   not a power of 3
```

So for every edge the two endpoints must have **different** values.
The whole graph therefore has to be *bipartite*.
If it is bipartite, we can colour the vertices with two colours `0 / 1`
and set

```
colour 0 -> 1 , colour 1 -> 2          (or the opposite)
```

For each edge the factor becomes `3`, the product over `m` edges is `3^m`
exactly as required.

Thus the problem reduces to

* check whether the given graph is bipartite,
* if it is, choose the orientation of every connected component
  (which colour gets value `1`) so that the whole sequence
  `x1 … xn` is lexicographically minimal.

--------------------------------------------------------------------

#### Lexicographically minimal orientation

Consider one connected component.
All its vertices are forced to have opposite values,
but we may flip the whole component.
Let `vmin` be the smallest index inside the component.
If we give `vmin` the value `1`, the whole sequence becomes
lexicographically smaller than giving it the value `2`
(because `vmin` is the first position where this component appears).

Therefore for each component we simply

```
if colour[vmin] == 0 :   colour 0 -> 1 , colour 1 -> 2
else                     colour 0 -> 2 , colour 1 -> 1
```

Processing vertices from `1` to `n` guarantees that the first still
uncoloured vertex of a component is exactly `vmin`.

--------------------------------------------------------------------

#### Algorithm
```
read n , m
build adjacency list
ans[1..n] = 0
colour[1..n] = -1          # -1 = unvisited, 0/1 = bipartite colour

for each vertex i = 1 .. n
    if colour[i] == -1
        # new component, BFS
        queue = [i]; colour[i] = 0
        component_vertices = []
        while queue not empty
            v = pop
            component_vertices.append(v)
            for each neighbour to
                if colour[to] == -1
                    colour[to] = colour[v] ^ 1
                    push to
                elif colour[to] == colour[v]
                    print "NO" and exit   # odd cycle
        # orientation for this component
        vmin = min(component_vertices)
        if colour[vmin] == 0
            for v in component_vertices
                ans[v] = 1 if colour[v]==0 else 2
        else
            for v in component_vertices
                ans[v] = 2 if colour[v]==0 else 1

print "YES"
print ans[1] … ans[n]
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `YES` and a lexicographically smallest
valid assignment iff such an assignment exists.

---

##### Lemma 1  
For any edge `u‑v` the condition `xu·xv+1 = 3` holds **iff**
`xu` and `xv` are different (one is `1`, the other `2`).

*Proof.* Direct enumeration of the four possibilities shown above. ∎



##### Lemma 2  
If the algorithm finishes without printing `NO`, the graph is bipartite
and the produced assignment satisfies `xu·xv+1 = 3` for every edge.

*Proof.*  
During BFS we assign colours `0/1` to neighbours, i.e. we enforce that
adjacent vertices have opposite colours.
If we ever meet an edge whose ends already have the same colour,
the algorithm prints `NO`. Hence when it finishes, no such edge exists,
so the colouring is a proper 2‑colouring → the graph is bipartite.

Later we map the two colours to the values `{1,2}` (maybe flipped).
Thus adjacent vertices receive different values, and by Lemma&nbsp;1
each edge contributes factor `3`. ∎



##### Lemma 3  
For a bipartite connected component the algorithm assigns the value `1`
to its smallest indexed vertex.

*Proof.*  
`vmin` is defined as the minimum index in the component.
If its colour is `0` we map colour `0 → 1`; otherwise we flip the mapping,
so colour `1 → 1`. In both cases `vmin` receives value `1`. ∎



##### Lemma 4  
Let `A` be the assignment output by the algorithm and `B` any other
valid assignment (i.e. all edges have different endpoint values).
Then `A` is lexicographically not larger than `B`.

*Proof.*  
Consider the first position `p` where `A` and `B` differ.
All vertices `1 … p‑1` belong to components whose smallest index is
already fixed to `1` by Lemma&nbsp;3, therefore they have the same value
in every valid assignment.  
Vertex `p` is the smallest index of its component `C`.  
By Lemma&nbsp;3, `A[p] = 1`.  
In any valid assignment the two colours of `C` must be opposite,
so the smallest index of `C` can be either `1` or `2`.  
If `B[p] = 2` then `A[p] < B[p]` and `A` is lexicographically smaller.
If `B[p] = 1` then `A[p] = B[p]`, contradicting the choice of `p`.
Thus the case `B[p]=2` is the only possible one, and `A ≤ B`. ∎



##### Lemma 5  
If the graph is not bipartite, no assignment satisfies the requirement.

*Proof.*  
Assume a valid assignment existed. By Lemma&nbsp;1 every edge forces its
endpoints to have different values, i.e. the graph would be 2‑colourable,
hence bipartite – contradiction. ∎



##### Theorem  
The algorithm outputs  

* `NO` iff no assignment of `{1,2}` makes the overall resonance equal
  to `3^m`;
* otherwise `YES` and the lexicographically smallest such assignment.

*Proof.*  

*If part.*  
If the algorithm prints `NO`, it discovered an edge whose ends received
the same colour, i.e. an odd cycle, so the graph is not bipartite.
By Lemma&nbsp;5 no valid assignment exists.

*Only‑if part.*  
If the algorithm finishes with `YES`, by Lemma&nbsp;2 the produced
assignment is valid. By Lemma&nbsp;4 it is lexicographically minimal
among all valid assignments.

Thus the theorem holds. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency list*: `O(n + m)`  
*BFS over all components*: each vertex and edge is processed once → `O(n + m)`  
*Memory*: adjacency list `O(n + m)`, plus a few `O(n)` arrays.

Both limits satisfy the constraints (`n, m ≤ 2·10⁵`).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        adj[u].append(v)
        adj[v].append(u)

    colour = [-1] * (n + 1)          # -1 unvisited, 0/1 bipartite colour
    ans = [0] * (n + 1)

    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        # BFS this component
        q = deque([start])
        colour[start] = 0
        comp = []
        while q:
            v = q.popleft()
            comp.append(v)
            cv = colour[v]
            for to in adj[v]:
                if colour[to] == -1:
                    colour[to] = cv ^ 1
                    q.append(to)
                elif colour[to] == cv:
                    print("NO")
                    return
        # orientation: smallest index gets value 1
        vmin = min(comp)
        if colour[vmin] == 0:
            for v in comp:
                ans[v] = 1 if colour[v] == 0 else 2
        else:
            for v in comp:
                ans[v] = 2 if colour[v] == 0 else 1

    # all done
    print("YES")
    print(' '.join(str(ans[i]) for i in range(1, n + 1)))

if __name__ == "__main__":
    solve()
```
