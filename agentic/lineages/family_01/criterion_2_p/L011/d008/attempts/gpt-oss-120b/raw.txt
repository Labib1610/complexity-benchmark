**Solution Explanation**

For every transmitter we have to choose one of the two intervals  

* `A = [0,1]` (right end = **1**)  
* `B = [1,2]` (right end = **2**)

For a pair `(u , v)` the union of the two chosen intervals must be an
interval of length `2`.  
The only way two length‑1 intervals give a length‑2 interval is that one
is `A` and the other is `B`.  
Therefore for every given pair the two transmitters must receive **different**
intervals.

So the whole problem is exactly the classic *graph bipartition* problem:

* vertices – transmitters `1 … n`
* edges – the `m` given pairs
* we have to colour the vertices with two colours `1` and `2`
  such that adjacent vertices have different colours.

If the graph is not bipartite the answer is `NO`.

If it is bipartite there are two possible colourings for each connected
component (they are each other's colour swap).  
We have to output the lexicographically smallest sequence of right ends.
Lexicographic order is decided by the first position where two sequences differ.
Hence we want the smallest possible colour for vertex `1`, then for vertex `2`,
and so on.

Processing vertices in increasing order and, when we meet a new component,
forcing the first (smallest‑index) vertex of this component to colour `1`
gives the optimal lexicographic result:

* the component’s other vertices are forced automatically,
* swapping the whole component would make that first vertex colour `2`,
  which is larger lexicographically,
* isolated vertices are also coloured `1`.

Thus a simple BFS/DFS that always starts a new component with colour `1`
produces the required answer, or discovers a conflict → `NO`.

--------------------------------------------------------------------

#### Algorithm
```
read n, m
build adjacency list G
colour[1…n] = 0          # 0 = uncoloured, 1 or 2 otherwise
for v = 1 … n:
    if colour[v] == 0:
        colour[v] = 1
        queue = [v]
        while queue not empty:
            x = pop queue
            for each neighbour y of x:
                if colour[y] == 0:
                    colour[y] = 3 - colour[x]      # opposite colour
                    push y
                elif colour[y] == colour[x]:
                    print "NO" and exit
print "YES"
print colour[1] … colour[n]   # they are exactly the right ends
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `YES` and a lexicographically smallest
valid sequence iff such a sequence exists.

---

##### Lemma 1  
During BFS, whenever an edge `(a,b)` is processed, the algorithm assigns
different colours to `a` and `b`.

**Proof.**  
If `b` is uncoloured, it receives `3‑colour[a]`, the opposite colour.
If `b` is already coloured, the algorithm checks `colour[b] == colour[a]`;
if they are equal it aborts with `NO`. Otherwise they are different. ∎



##### Lemma 2  
If the algorithm finishes without aborting, the produced colouring satisfies
the requirement for every given pair.

**Proof.**  
By Lemma&nbsp;1 each edge connects vertices of different colours, i.e. one
gets interval `[0,1]` (right end 1) and the other `[1,2]` (right end 2).  
Their union is `[0,2]`, an interval of length 2, exactly the required condition. ∎



##### Lemma 3  
If the input graph is not bipartite, the algorithm aborts and prints `NO`.

**Proof.**  
A non‑bipartite graph contains an odd cycle. While BFS traverses this cycle,
the first vertex receives colour 1, the next colour 2, and so on.
Because the cycle length is odd, the last edge connects two vertices that
already have the same colour, triggering the conflict test and causing the
algorithm to output `NO`. ∎



##### Lemma 4  
If the input graph is bipartite, the algorithm never aborts.

**Proof.**  
A bipartite graph admits a 2‑colouring. BFS starts a component with colour 1;
the opposite colour is forced on every neighbour, and so on.
Since a proper 2‑colouring exists, no edge ever connects two vertices of the
same colour, therefore the conflict test never fails. ∎



##### Lemma 5  
For each connected component the algorithm chooses the lexicographically
smallest possible colour assignment among the two feasible assignments.

**Proof.**  
Consider a component `C`. Let `p` be the smallest vertex index in `C`.
When the outer loop reaches `p`, it is still uncoloured, so the algorithm
starts BFS with `colour[p]=1`. The only other feasible assignment for `C`
is the colour swap, which would give `colour[p]=2`. Since `1 < 2`,
the algorithm’s choice is lexicographically smaller for the whole array,
independently of colours of later vertices. ∎



##### Lemma 6  
The whole colour array output by the algorithm is the lexicographically
smallest among all valid colourings.

**Proof.**  
Proceed by induction over vertex indices.
Assume the algorithm and any optimal colouring coincide on vertices `1…k‑1`.
If vertex `k` is already coloured, both colourings agree (by induction).
Otherwise `k` is the smallest index of its component.
By Lemma&nbsp;5 the algorithm gives `colour[k]=1`, which is the smallest
possible value for any valid colouring (the alternative would be `2`).
Thus any optimal colouring must also have `colour[k]=1`.  
Hence the algorithm’s prefix up to `k` is lexicographically minimal.
Induction completes the claim for the whole array. ∎



##### Theorem  
The algorithm outputs  

* `NO` iff no valid assignment exists,  
* otherwise `YES` and the lexicographically smallest sequence of right ends.

**Proof.**  
*If the algorithm prints `NO`*: by Lemma&nbsp;3 the graph is non‑bipartite,
hence no valid assignment exists.

*If a valid assignment exists*: the graph is bipartite.
By Lemma&nbsp;4 the algorithm does not abort, thus prints `YES`.
By Lemma&nbsp;2 the produced colouring is valid.
By Lemma&nbsp;6 it is the lexicographically smallest among all valid
colourings. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency list*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and edge is processed once → `O(n + m)` time.  

Total: **Time `O(n + m)`**, **Memory `O(n + m)`**, well within the limits
(`n, m ≤ 200 000`).

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        g[u].append(v)
        g[v].append(u)

    colour = [0] * (n + 1)          # 0 = uncoloured, 1 or 2 otherwise

    for start in range(1, n + 1):
        if colour[start]:
            continue
        colour[start] = 1
        q = deque([start])
        while q:
            x = q.popleft()
            cx = colour[x]
            nx = 3 - cx               # opposite colour
            for y in g[x]:
                if colour[y] == 0:
                    colour[y] = nx
                    q.append(y)
                elif colour[y] == cx:
                    sys.stdout.write("NO")
                    return

    # all good
    out = ["YES\n"]
    out.append(' '.join(str(colour[i]) for i in range(1, n + 1)))
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```
