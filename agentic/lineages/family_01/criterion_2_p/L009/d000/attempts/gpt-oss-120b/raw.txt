**Solution Explanation**

For every worker we have to choose one of two shifts.
A pair `(u , v)` is a *conflict*: `u` and `v` must obtain different shifts.
Thus we have to 2‑colour the undirected graph whose vertices are the workers
and whose edges are the conflict pairs.

The graph must be *bipartite*.
If it is not, no assignment exists.

If it is bipartite there are two possible colourings for each connected
component – the two colour classes can be swapped.
Among all global colourings we have to output the **lexicographically smallest**
sequence `s1 … sn` (`1 < 2`).

--------------------------------------------------------------------

#### Lemma  
Consider one connected component `C`.  
Let `vmin` be the smallest vertex index inside `C`.  
Among the two possible colourings of `C` the lexicographically smaller one
is the one that gives `vmin` colour `1`.

*Proof.*  
All vertices with index `< vmin` belong to other components, therefore their
colours are already fixed when we decide the orientation of `C`.  
The first position where the two colourings of `C` differ is exactly `vmin`,
where they have opposite colours.  
Since `1 < 2`, the colouring with colour `1` at `vmin` is lexicographically
smaller, and no later decision can change this. ∎



Consequences  

* we can treat each component independently;
* for a component we run a BFS/DFS, colour vertices with temporary colours
  `0` and `1`;
* if a conflict is found → graph not bipartite → answer `NO`;
* otherwise, if the temporary colour of `vmin` is `1` we **flip** all colours
  of this component (swap `0 ↔ 1`);
* finally output `colour + 1` (`0 → 1`, `1 → 2`).

The whole algorithm is linear.

--------------------------------------------------------------------

#### Algorithm
```
read n, m
build adjacency list G[1…n]

colour = [-1] * (n+1)          # -1 = unvisited, 0/1 = temporary colour
answer = [0] * (n+1)

for each vertex start = 1 … n:
    if colour[start] != -1: continue
    # new component
    queue = [start]
    colour[start] = 0
    component_vertices = [start]
    ok = True
    while queue not empty:
        v = pop queue
        for each neighbour to in G[v]:
            if colour[to] == -1:
                colour[to] = colour[v] ^ 1
                queue.append(to)
                component_vertices.append(to)
            elif colour[to] == colour[v]:
                print "NO" and exit
    # decide orientation
    vmin = min(component_vertices)
    if colour[vmin] == 1:          # need to flip
        for v in component_vertices:
            colour[v] ^= 1

# build final answer
for i = 1 … n:
    answer[i] = colour[i] + 1

print "YES"
print answer[1] … answer[n] separated by spaces
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `NO` iff no feasible assignment exists,
otherwise prints `YES` and the lexicographically smallest feasible assignment.

---

##### Lemma 1  
If the algorithm prints `NO`, the conflict graph is not bipartite.

*Proof.*  
`NO` is printed only when during BFS an edge `(v,to)` with
`colour[v] == colour[to]` is discovered.
All previously visited vertices have been coloured consistently with the rule
“adjacent vertices have opposite colours”.  
Thus the discovered edge creates an odd cycle, proving the component (hence the
graph) is not bipartite. ∎



##### Lemma 2  
If the conflict graph is not bipartite, the algorithm prints `NO`.

*Proof.*  
A non‑bipartite graph contains an odd cycle.
During the BFS of the component containing that cycle, vertices are coloured
alternately along the walk. When the last edge of the odd cycle is examined,
its two ends already have the same colour, triggering the `NO` output. ∎



##### Lemma 3  
Assume the graph is bipartite. After processing a component `C`,
the temporary colours satisfy:
* they are a proper 2‑colouring of `C`;
* the smallest vertex `vmin` of `C` has colour `0`.

*Proof.*  
The BFS colours every visited vertex opposite to its predecessor, therefore
adjacent vertices receive different colours – a proper 2‑colouring.
If after BFS `colour[vmin] == 1`, the algorithm flips all colours of `C`,
changing every `0` to `1` and vice‑versa. Flipping preserves the property
“adjacent vertices have opposite colours”. After a possible flip,
`vmin` has colour `0`. ∎



##### Lemma 4  
The final sequence `s_i = colour[i] + 1` is a feasible assignment.

*Proof.*  
By Lemma&nbsp;3 each component is properly 2‑coloured, i.e. any edge connects
vertices of different temporary colours. Adding `1` maps `{0,1}` to `{1,2}`
without changing equality/inequality, therefore every conflict pair receives
different shifts. ∎



##### Lemma 5  
Among all feasible assignments, the algorithm’s assignment is lexicographically
smallest.

*Proof.*  
Consider components ordered by their minimal vertex index.
Processing components in increasing order of that index, Lemma&nbsp;3 guarantees
that for each component its minimal vertex receives colour `1`
(the smallest possible value).  
By Lemma&nbsp;the earlier components cannot be altered by later decisions.
Hence at the first position where any feasible assignment could differ from
the algorithm’s one, the algorithm already has the smallest possible value `1`.
Thus no other feasible assignment is lexicographically smaller. ∎



##### Theorem  
The algorithm outputs  

* `NO` iff no assignment satisfying all conflicts exists;  
* otherwise `YES` and the lexicographically smallest valid assignment.

*Proof.*  
If the algorithm prints `NO`, by Lemma&nbsp;1 the graph is not bipartite,
hence no assignment exists.  
If the graph is not bipartite, Lemma&nbsp;2 shows the algorithm prints `NO`.  
If the graph is bipartite, the algorithm finishes the BFSs, never prints `NO`,
and by Lemma&nbsp;4 the produced assignment is feasible.
Lemma&nbsp;5 shows it is the lexicographically smallest among all feasible
assignments. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency list*: `O(n + m)` memory and time.  
*BFS over all components*: each vertex and edge is processed once → `O(n + m)`.  
*Flipping colours*: total work proportional to the number of vertices, also
`O(n)`.  

Overall time `O(n + m)` ≤ `4·10⁵`, well inside the 1 s limit.  
Memory: adjacency list (`2m` integers) + a few arrays of size `n` → `O(n + m)`  
≤ 2 · 10⁵ · (4 bytes) ≈ 1.6 MB, far below 256 MB.

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        g[u].append(v)
        g[v].append(u)

    colour = [-1] * (n + 1)          # 0 / 1 temporary colours
    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        # BFS this component
        q = deque([start])
        colour[start] = 0
        comp = [start]
        while q:
            v = q.popleft()
            cv = colour[v]
            for to in g[v]:
                if colour[to] == -1:
                    colour[to] = cv ^ 1
                    q.append(to)
                    comp.append(to)
                elif colour[to] == cv:
                    sys.stdout.write("NO")
                    return
        # orient so that minimal vertex gets colour 0
        vmin = min(comp)
        if colour[vmin] == 1:
            for v in comp:
                colour[v] ^= 1

    # build answer
    out = ['YES\n']
    out.append(' '.join(str(colour[i] + 1) for i in range(1, n + 1)))
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```
