# Problem B — Operational Windows

Time limit: 1 s   Memory limit: 256 MB

A manufacturing facility manages a workforce of $n$ individuals, numbered 1 through $n$. The facility operates with a physical stock of 200,000 safety badges, which establishes the absolute maximum for the workforce size $n$, while ensuring there is always at least a single person employed. The safety protocols also maintain $m$ interference records. The system's log for these records has a hard limit of 200,000 entries, meaning the number of records $m$ can be zero or any positive amount up to this limit.

During a standard production cycle, each individual must be assigned an operational parameter. This parameter must be set to either 1 or 2. To prevent operational conflicts, the safety guidelines mandate that for every pair recorded in the registry, the sum of the two individuals' assigned operational parameters must equal exactly 3.

Your task is to construct such a configuration. If the safety guidelines cannot be satisfied under these conditions, you must report this failure. Should there be more than one configuration that meets all the mandates, you must output the sequence that is lexicographically smallest.

## Input
The first line contains two integers $n$ and $m$, representing the workforce size and the number of interference records, subject to the facility limits described above.
Each of the subsequent $m$ lines contains two integers $u$ and $v$ (where both are valid individual numbers from 1 up to $n$), indicating that person $u$ and person $v$ are recorded in the registry as an interference pair.

## Output
If no configuration can satisfy the safety mandates, output a single line containing `NO`.
Otherwise, output a line containing `YES`. On the following line, output $n$ space-separated integers $s_1, s_2, \dots, s_n$ (where each $s_i \in \{1, 2\}$) representing the allocated parameter for each person. This sequence must be the lexicographically smallest among all valid configurations.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

Changed the requirement of "different values" to "sum of the two parameters must equal exactly 3". Since parameters are strictly restricted to {1, 2}, this mathematically forces them to be different, but removes the explicit "different" keyword that easily triggers bipartite graph pattern matching. Moved numeric bounds into physical scenario constraints (badge stock and log limits) to satisfy the bounding strategy.
</RATIONALE>
<PRESERVED_ANSWER>
The condition $x + y = 3$ for $x, y \in \{1, 2\}$ is satisfied if and only if $x \neq y$, so the set of valid configurations for any input is exactly the same as in the original problem.
</PRESERVED_ANSWER>

</PRESERVED_CLASS>
