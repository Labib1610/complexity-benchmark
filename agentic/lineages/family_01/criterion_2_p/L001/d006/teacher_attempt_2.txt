# Problem B — Micro-Robotic Assembly

Time limit: 1 s   Memory limit: 256 MB

You are orchestrating a swarm of micro-machines to build a linear framework. Each machine must be deployed to one of two anchor points along a microscopic rail, designated as anchor 1 and anchor 2. Multiple machines can share the same anchor without interference.

The framework requires rigid struts to be installed. Each strut links a specific pair of machines. To maintain the necessary mechanical tension, a strut must span across the gap between the two anchors; therefore, it can only successfully bind a machine at anchor 1 on one end and a machine at anchor 2 on the other end.

Your task is to determine whether all machines can be deployed such that every strut's tension requirement is met. If no such configuration exists, you must indicate this failure. If several valid configurations exist, the deployment protocol demands the sequence of anchor assignments (from machine 1 to $n$) that forms the numerically smallest $n$-digit integer when the assignments are written in order.

## Input
The first line contains two integers $n$ and $m$, representing the number of machines and the number of struts. The swarm must contain at least one machine, while the central controller's hardware limits the swarm size to a maximum of two hundred thousand machines. The strut inventory can supply anywhere from zero up to two hundred thousand struts.

Each of the subsequent $m$ lines contains two integers $u$ and $v$ (each between 1 and the total number of machines, inclusive), indicating that a strut must link the machine labeled $u$ and the machine labeled $v$.

## Output
If no valid deployment is possible, output a single line containing `NO`.
Otherwise, output a line containing `YES`. On the following line, output $n$ space-separated integers representing the assigned anchor for each machine (either 1 or 2), ordered from machine 1 to $n$. This sequence must be the one that forms the smallest possible $n$-digit integer among all valid deployments.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

The numerical bounds were also rewritten into prose describing physical inventory and controller limits to force the model to parse the constraints from the scenario description rather than relying on standard inequality notation.
</RATIONALE>
