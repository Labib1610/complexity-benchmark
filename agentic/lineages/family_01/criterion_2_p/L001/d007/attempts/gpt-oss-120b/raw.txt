**Solution Explanation**

For every monomer we have to choose one of the two intervals  

* `1` – interval `[0,1]`  
* `2` – interval `[1,2]`

For a recorded bond `{u,v}` the two intervals must intersect **in exactly one point**.
The only way two of the given intervals intersect in a single point is

```
[0,1]  ∩  [1,2] = {1}
```

All other pairs intersect in a whole segment (length > 0).  
Therefore a bond forces its ends to have **different** labels.

So the whole problem is exactly the classical *bipartite graph* test:

* vertices = monomers  
* edges = recorded bonds  
* we need a 2‑colouring such that adjacent vertices have opposite colours.

Additional constraints  

* a self‑loop `{u,u}` would require the interval of a vertex to intersect
  itself in a single point – impossible.  
  → answer `NO` immediately.
* many edges between the same pair are harmless – they repeat the same
  “different colour” requirement.

If the graph is bipartite we must output the **lexicographically smallest**
colour sequence `r1 … rn` (`1` < `2`).  
Consider the first vertex (smallest index) that belongs to a not yet coloured
connected component.  
Setting its colour to `1` gives a sequence that is strictly smaller than any
sequence where this vertex is coloured `2`, because the first differing
position is this vertex itself.
Thus the greedy rule

```
process vertices 1 … n
   if vertex i is still uncoloured:
        start BFS from i, colour i = 1
        propagate colours (neighbour gets the opposite colour)
```

produces the lexicographically minimal feasible colouring.
If during BFS we ever need to give a vertex a colour that contradicts an
already assigned colour, the component (hence the whole graph) is not bipartite
→ answer `NO`.

The algorithm is linear:

* building adjacency lists – `O(n + m)`
* one BFS per component – each edge examined twice – `O(n + m)`
* memory – adjacency lists + colour array – `O(n + m)`

Both limits (`2·10⁵`) are easily satisfied.



--------------------------------------------------------------------

#### Algorithm
```
read n, m
create adjacency list G[1…n] as empty lists
for each of the m edges (u, v):
        if u == v:               # self‑loop
                print "NO" and exit
        add v to G[u], add u to G[v]

colour[1…n] = 0          # 0 = uncoloured, 1 or 2 afterwards
for i = 1 … n:
        if colour[i] == 0:
                colour[i] = 1
                queue = [i]
                while queue not empty:
                        v = pop front
                        for each w in G[v]:
                                if colour[w] == 0:
                                        colour[w] = 3 - colour[v]   # opposite
                                        push w
                                elif colour[w] == colour[v]:
                                        print "NO" and exit
# all vertices coloured successfully
print "YES"
print colour[1] … colour[n] separated by spaces
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `YES` and a lexicographically minimal
valid sequence iff such a sequence exists.

---

##### Lemma 1  
If the algorithm ever prints `NO`, no valid configuration exists.

**Proof.**  
Two possible reasons:

1. A self‑loop `(u,u)` is present.  
   Any interval intersected with itself is the whole interval, not a single
   point, so the condition cannot be satisfied.

2. During BFS an edge `{v,w}` is found with `colour[v] == colour[w]`.  
   The algorithm assigns colours exactly according to the rule
   “adjacent vertices must have opposite colours”.  
   If an edge forces equal colours, the graph contains an odd cycle
   (standard property of bipartite testing) – the graph is not bipartite,
   therefore no 2‑colouring respecting the “different colour” condition exists.
∎



##### Lemma 2  
If the algorithm finishes without conflict, the produced colouring satisfies
the condition for every bond.

**Proof.**  
The algorithm colours vertices only by the rule
`colour[neighbour] = opposite(colour[current])`.  
Thus for every processed edge `{u,v}` we have `colour[u] ≠ colour[v]`.  
All edges are processed (they belong to some component’s BFS), therefore the
condition holds for every bond. ∎



##### Lemma 3  
For each connected component the algorithm assigns the colour `1` to the
smallest‑index vertex of that component.

**Proof.**  
Components are discovered in the outer loop over `i = 1 … n`.  
When the first vertex `i` of a component is encountered, it is still uncoloured,
so the algorithm starts BFS from `i` and explicitly sets `colour[i] = 1`. ∎



##### Lemma 4  
Let `C` be a connected component.
Among all valid colourings of `C`, the algorithm’s colouring is
lexicographically smallest when restricted to the vertices of `C`
(in the order of their indices).

**Proof.**  
By Lemma&nbsp;3 the smallest index in `C` receives colour `1`.  
Any other valid colouring of `C` must give this vertex either colour `1` or
colour `2`.  
If it gives colour `2`, its sequence is already larger at this first
position, hence not smaller.  
If it also gives colour `1`, the rest of the component is forced uniquely
(bipartite colouring is determined by the colour of a single vertex).  
Thus the algorithm’s choice coincides with every other optimal colouring,
so it is lexicographically minimal for `C`. ∎



##### Lemma 5  
The whole sequence output by the algorithm is lexicographically minimal
among all valid sequences.

**Proof.**  
Consider the first index `p` where an arbitrary valid sequence `S`
differs from the algorithm’s sequence `A`.  
Vertex `p` belongs to some component `C`.  
All earlier vertices belong to components already processed, and by Lemma 4
they are coloured identically in every optimal colouring, therefore `A` and
`S` coincide on them.  

In component `C`, by Lemma 4 the algorithm gives the smallest possible colour
to its smallest index, which is exactly `p` (because all earlier vertices of `C`
are ≤ `p` and already fixed).  
Hence `A[p] = 1` and any other valid colouring must have `S[p] ∈ {1,2}` with
`S[p] ≥ A[p]`.  
If `S[p] = 2` then `S` is lexicographically larger; if `S[p] = 1` then the
first difference occurs later, contradicting the choice of `p`.  
Thus no valid sequence is lexicographically smaller than `A`. ∎



##### Lemma 6  
If a valid configuration exists, the algorithm never prints `NO`.

**Proof.**  
Assume a valid configuration exists.  
Then the graph has no self‑loops (otherwise impossible) and is bipartite,
otherwise a 2‑colouring with opposite colours on each edge could not exist.
During BFS the algorithm would never encounter an edge whose ends already have
the same colour, because such a situation would create an odd cycle, contradicting
bipartiteness.  
Therefore no conflict arises and the algorithm finishes with `YES`. ∎



##### Theorem  
The algorithm outputs  

* `NO` iff no valid tuning configuration exists,  
* otherwise `YES` and the lexicographically smallest valid sequence.

**Proof.**  
*If the algorithm outputs `NO`*: by Lemma 1 no configuration exists.  

*If a configuration exists*: by Lemma 6 the algorithm outputs `YES`.  
Lemma 2 guarantees the produced sequence is valid.  
Lemma 5 shows it is the lexicographically smallest among all valid ones. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency lists*: `O(n + m)` time, `O(n + m)` memory.  
*BFS over all components*: each vertex enqueued once, each edge examined twice →  
`O(n + m)` time, `O(n)` extra memory for colour array and queue.  

Total: **`O(n + m)` time**, **`O(n + m)` memory**, well within limits.

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u == v:                     # self‑loop – impossible
            sys.stdout.write("NO")
            return
        g[u].append(v)
        g[v].append(u)

    colour = [0] * (n + 1)             # 0 = uncoloured, 1 or 2

    for start in range(1, n + 1):
        if colour[start] != 0:
            continue
        colour[start] = 1
        q = deque([start])
        while q:
            v = q.popleft()
            cv = colour[v]
            opp = 3 - cv                # opposite colour
            for w in g[v]:
                if colour[w] == 0:
                    colour[w] = opp
                    q.append(w)
                elif colour[w] == cv:
                    sys.stdout.write("NO")
                    return

    # all good
    out = ["YES\n"]
    out.append(' '.join(str(colour[i]) for i in range(1, n + 1)))
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input / output format.
