**Solution Explanation**

For every given pair `(u , v)` the two assets must belong to different
portfolios.
The problem is exactly the *2‑coloring* (bipartite) problem:

* vertices – assets `1 … n`
* edges – given pairs  
* we have to colour the vertices with colours `1` and `2`
  such that the ends of every edge have different colours.

If a component of the graph is bipartite, it has **exactly two**
valid colourings – they differ only by swapping the two colours.
Among all global colourings we need the lexicographically smallest
sequence  

`c1 c2 … cn`  (`1 < 2`).

--------------------------------------------------------------------

#### 1.  Observations

* The graph may be disconnected.  
  Components are independent – we may flip colours inside a component
  without affecting another component.

* In a component let `vmin` be the smallest numbered vertex.
  Any two global colourings differ first (if at all) at `vmin`,
  because all vertices with a smaller index belong to already processed
  components.

* Therefore, to obtain the lexicographically smallest whole sequence we
  **must colour `vmin` with `1`**.
  After fixing the colour of `vmin`, the colours of all other vertices
  of the component are forced (they are the opposite colour on each edge).

* While scanning vertices from `1` to `n`,
  the first uncoloured vertex we meet is exactly `vmin` of its component.
  If we start a BFS/DFS from it and give it the internal colour `0`,
  after mapping `0 → 1 , 1 → 2` the vertex receives colour `1` – the
  optimal choice.

Hence a *single* BFS/DFS for every component, always starting with colour
`0` for the first vertex, yields the required lexicographically smallest
colouring, **if the graph is bipartite**.

--------------------------------------------------------------------

#### 2.  Algorithm
```
read n, m
build adjacency list G (1‑based)

colour[1…n] = -1          # -1 = not visited, 0/1 = internal colours
queue = empty

for v = 1 … n:
    if colour[v] != -1: continue          # already processed component

    colour[v] = 0                         # v is the smallest vertex of its component
    push v into queue
    while queue not empty:
        x = pop queue
        for each neighbour y of x:
            if colour[y] == -1:
                colour[y] = colour[x] ^ 1 # opposite colour
                push y
            elif colour[y] == colour[x]:
                print "NO" and exit        # odd cycle → not bipartite

# all components processed without conflict
print "YES"
output = [ colour[i] + 1 for i = 1 … n ]   # map 0→1, 1→2
print output
```

--------------------------------------------------------------------

#### 3.  Correctness Proof  

We prove that the algorithm prints `NO` iff no feasible allocation exists,
otherwise it prints `YES` and the lexicographically smallest allocation.

---

##### Lemma 1  
During the BFS of a component the algorithm assigns opposite internal
colours to the endpoints of every traversed edge.

**Proof.**  
The start vertex receives colour `0`.  
Whenever an edge `(x, y)` is examined,
* if `y` is uncoloured we set `colour[y] = colour[x] xor 1`,
  i.e. the opposite colour.
* if `y` is already coloured, the algorithm checks whether the colours are
  equal; if they are, it aborts (see Lemma&nbsp;2). ∎



##### Lemma 2  
If the algorithm prints `NO`, the input graph is not bipartite,
hence no valid allocation exists.

**Proof.**  
`NO` is printed only when an examined edge `(x, y)` has
`colour[x] == colour[y]`.  
By Lemma&nbsp;1 all previously processed edges respect opposite colours,
so the current edge creates an odd‑length cycle, which is a well‑known
characterisation of a non‑bipartite graph.  
Thus no 2‑colouring exists. ∎



##### Lemma 3  
If the algorithm finishes without aborting, the produced colour array
`c[i] = colour[i] + 1` satisfies all constraints.

**Proof.**  
For every edge both endpoints were examined either when the later endpoint
was first discovered (Lemma&nbsp;1) or later during the adjacency scan.
In both cases Lemma&nbsp;1 guarantees opposite internal colours,
hence opposite final colours `1` and `2`. ∎



##### Lemma 4  
For each connected component the algorithm assigns colour `1`
to its smallest‑index vertex.

**Proof.**  
When the outer loop reaches the smallest vertex `vmin` of a component,
it is still uncoloured, becomes the BFS start vertex and receives internal
colour `0`. The final mapping adds `1`, therefore `c[vmin] = 1`. ∎



##### Lemma 5  
Among all feasible allocations the algorithm’s allocation is
lexicographically smallest.

**Proof.**  
Consider any feasible allocation `d[1…n]`.
Process vertices in increasing order.
Let `k` be the first index where `c` (algorithm’s output) and `d` differ.
Vertex `k` belongs to some component `C`.  
All vertices `< k` lie in components already processed earlier, thus they are
identical in both colourings (the algorithm never changes a finished component).

By Lemma&nbsp;4, `c[k] = 1` because `k` is the smallest index of `C`.
Since `d` is a valid colouring of `C`, its colour of vertex `k` must be either
`1` or `2`.  
If `d[k] = 2`, then `c[k] < d[k]` and `c` is lexicographically smaller.
If `d[k] = 1`, the two colourings coincide at `k`, contradicting the choice
of `k` as the first differing position.
Therefore `d[k]` cannot be `1`; the only possibility is `d[k] = 2`,
and `c` is strictly lexicographically smaller than any other feasible
allocation. ∎



##### Theorem  
The algorithm outputs  

* `NO`  **iff**  no allocation satisfies all mandates,  

* otherwise `YES` and the lexicographically smallest feasible allocation.

**Proof.**  

*If part:*  
If the algorithm outputs `NO`, by Lemma&nbsp;2 the graph is not bipartite,
hence no allocation exists.

*Only‑if part:*  
If the graph is not bipartite, any 2‑colouring attempt must encounter an
edge whose endpoints receive the same colour, exactly the situation where
the algorithm prints `NO`.  

If the graph is bipartite, the algorithm never aborts, Lemma&nbsp;3 shows
that its output satisfies all constraints, and Lemma&nbsp;5 proves
lexicographic optimality. ∎



--------------------------------------------------------------------

#### 4.  Complexity Analysis  

*Building adjacency list*: `O(n + m)` memory and time.  

*BFS over all components*: each vertex and each edge is processed once.  
Time `O(n + m)`, memory `O(n + m)` for the graph and the colour array.

Both limits satisfy the given constraints (`n, m ≤ 2·10⁵`).

#### 5.  Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = next(it)
        v = next(it)
        g[u].append(v)
        g[v].append(u)

    colour = [-1] * (n + 1)          # -1 = unvisited, 0/1 = internal colour
    q = deque()

    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        colour[start] = 0            # smallest vertex of this component gets 0
        q.append(start)
        while q:
            v = q.popleft()
            cv = colour[v]
            for to in g[v]:
                if colour[to] == -1:
                    colour[to] = cv ^ 1
                    q.append(to)
                elif colour[to] == cv:
                    sys.stdout.write("NO")
                    return

    # successful colouring
    sys.stdout.write("YES\n")
    out = ' '.join(str(colour[i] + 1) for i in range(1, n + 1))
    sys.stdout.write(out)

if __name__ == "__main__":
    solve()
```
