**Solution Explanation**

For a tube connecting lenses `u , v` with assigned values `x , y ∈ {1,2}` the instrument
computes  

```
f(x,y) = x² + y² – x·y
```

The required total product over all `m` tubes is `3^m`.  
Therefore every single factor must be `3`, otherwise the product would contain a
different prime factor.

```
x y | f
1 1 | 1
1 2 | 3
2 1 | 3
2 2 | 4
```

Only the mixed pair `(1,2)` (or `(2,1)`) gives `3`.  
Consequently **every tube must connect lenses with different values**.
So we have to colour the given graph with two colours `1` and `2` such that
adjacent vertices have different colours – exactly the definition of a
*bipartite* graph.

If the graph is not bipartite the answer is `NO`.  
If it is bipartite we have to output the lexicographically smallest
`1/2` sequence among all proper colourings.

--------------------------------------------------------------------

#### Lexicographically smallest proper 2‑colouring

Each connected component of a bipartite graph has exactly two proper
colourings – they are each other’s colour swap.
Let  

* `par[v] ∈ {0,1}` – colour obtained by a BFS/DFS (arbitrary start vertex gets `0`);
* `comp` – list of vertices of the current component;
* `minv` – the smallest vertex index inside this component.

If we keep the mapping `0 → 1 , 1 → 2` then vertex `minv` receives colour  
`1` iff `par[minv] = 0`.  
If `par[minv] = 1` we can swap the mapping (`0 → 2 , 1 → 1`) and obtain colour
`1` for `minv`.  
Choosing the orientation that gives colour `1` to the smallest index of the
component makes the whole sequence lexicographically minimal, because earlier
positions dominate later ones and components are independent.

Thus the algorithm is:

```
for every not yet visited vertex:
        BFS, fill par[ ] and detect odd cycle (non‑bipartite)
        remember all vertices of this component and its minimum index
        if par[min] == 0:   mapping = (0→1, 1→2)
        else:               mapping = (0→2, 1→1)
        write the final colours into answer[ ]
```

If `m = 0` there are no edges, the graph is trivially bipartite and the
lexicographically smallest assignment is all `1`s.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `YES` and a lexicographically smallest
valid assignment iff such an assignment exists.

---

##### Lemma 1  
For any edge `{u,v}` the value `x_u² + x_v² – x_u·x_v` equals `3`
iff `{x_u , x_v} = {1,2}`.

*Proof.* Direct computation of the four possibilities (shown in the table)
gives the claim. ∎



##### Lemma 2  
A labeling of the lenses satisfies the required product `3^m`
iff it is a proper 2‑colouring of the graph (adjacent vertices have different
labels).

*Proof.* By Lemma&nbsp;1 each edge contributes `3` exactly when its endpoints have
different labels, otherwise the contribution is `1` or `4` and the total
product cannot be `3^m`. ∎



##### Lemma 3  
If the algorithm reports `NO` then no valid labeling exists.

*Proof.* The algorithm reports `NO` only when during BFS an edge connects two
vertices with the same parity `par`. That means the graph contains an odd
cycle, i.e. it is not bipartite. By Lemma&nbsp;2 a valid labeling would be a
proper 2‑colouring, which is impossible for a non‑bipartite graph. ∎



##### Lemma 4  
If the algorithm finishes without conflict, the produced array `ans`
is a proper 2‑colouring.

*Proof.* Within each component BFS assigns parity `par` such that every edge
joins vertices of opposite parity (otherwise a conflict would have been
detected). Afterwards we possibly swap the mapping `0↔1` globally for the
component, which does not change the fact that adjacent vertices receive
different final colours. Hence all edges connect different numbers. ∎



##### Lemma 5  
For a bipartite component the algorithm chooses the orientation that yields
the smallest possible subsequence of that component in any proper colouring.

*Proof.* The component has exactly two proper colourings, differing only by a
global swap of the two colours. Let `v₀` be the smallest index in the component.
If in one orientation `v₀` receives `1` and in the other it receives `2`,
any full sequence beginning with the first orientation is lexicographically
smaller, because the first differing position is `v₀`.  
If both orientations give the same colour to `v₀` (impossible, they are opposite),
the subsequences are identical. The algorithm selects the orientation with
`ans[v₀]=1`, therefore it is optimal for the component. ∎



##### Lemma 6  
The whole array `ans` is the lexicographically smallest proper colouring of the
graph.

*Proof.* Consider the vertices in increasing order.
Let `c` be the first vertex where the algorithm’s answer could differ from any
other proper colouring `b`. Vertex `c` belongs to some component `C`.  
All vertices `< c` are identical in both colourings, therefore they are fixed.
By Lemma&nbsp;5 the algorithm’s choice for component `C` gives the smallest
possible colour for its smallest vertex, which is exactly `c` (otherwise a
smaller vertex of `C` would appear earlier). Hence `ans[c] = 1` whenever any
proper colouring can have `1` there; otherwise all colourings have `2`. Thus
`ans` is not larger than `b` at the first differing position, i.e. it is
lexicographically minimal. ∎



##### Theorem  
The algorithm outputs  

* `NO` iff no assignment of `{1,2}` to the lenses makes the product equal to
  `3^m`;
* otherwise `YES` and the lexicographically smallest such assignment.

*Proof.*  
- If the algorithm prints `NO`, by Lemma&nbsp;3 no valid assignment exists.  
- If it prints `YES`, Lemma&nbsp;4 guarantees the assignment is proper, hence
  by Lemma&nbsp;2 it satisfies the product condition. Lemma&nbsp;6 shows it is
  the lexicographically smallest among all valid assignments.  

Conversely, if a valid assignment exists, the graph is bipartite, so the
algorithm never encounters a conflict and therefore prints `YES`. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

`BFS` visits each vertex once and each edge twice.

```
Time   :  O(n + m)   ≤ 4·10⁵
Memory :  O(n + m)   adjacency lists + a few arrays
```

Both fit easily into the limits.

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        adj[u].append(v)
        adj[v].append(u)

    # special case: no edges -> all 1s
    if m == 0:
        print("YES")
        print(" ".join(["1"] * n))
        return

    color = [ -1 ] * (n + 1)          # parity 0/1, -1 = unvisited
    answer = [0] * (n + 1)

    for start in range(1, n + 1):
        if color[start] != -1:
            continue
        # BFS this component
        q = deque([start])
        color[start] = 0
        comp = [start]
        minv = start
        ok = True
        while q:
            v = q.popleft()
            for to in adj[v]:
                if color[to] == -1:
                    color[to] = color[v] ^ 1
                    q.append(to)
                    comp.append(to)
                    if to < minv:
                        minv = to
                elif color[to] == color[v]:
                    # odd cycle
                    print("NO")
                    return
        # decide orientation
        if color[minv] == 0:
            # 0 -> 1, 1 -> 2
            for v in comp:
                answer[v] = 1 if color[v] == 0 else 2
        else:
            # swap
            for v in comp:
                answer[v] = 2 if color[v] == 0 else 1

    # output
    print("YES")
    print(" ".join(str(answer[i]) for i in range(1, n + 1)))

if __name__ == "__main__":
    solve()
```

to the required input‑output format.
