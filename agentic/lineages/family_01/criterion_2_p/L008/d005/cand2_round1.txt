# Problem B — Storage Tier Isolation

Time limit: 1 s   Memory limit: 256 MB

An enterprise architecture contains $n$ microservices. Each microservice must be assigned to a storage tier, which must be represented by an integer value of either 1 or 2.

- Tier 1 utilizes a block of 1000 memory addresses: from 0 to 999.
- Tier 2 utilizes a block of 1000 memory addresses: from 1000 to 1999.

When a microservice is assigned to a tier, it is granted access to that tier's entire memory block.

The architecture includes $m$ integration testing pipelines. Each pipeline connects a specific pair of microservices. During an integration test between two microservices, the testing environment isolates the memory blocks accessible to them. The environment calculates the *footprint* of the test as the total number of unique memory addresses accessible to at least one of the two microservices.

To ensure sufficient memory isolation across the system, the aggregate footprint—calculated by summing the individual footprints of all $m$ integration tests—must be exactly $2000 \cdot m$ addresses.

Determine an assignment of storage tiers for all $n$ microservices that satisfies this aggregate footprint requirement, or report that the architecture makes this impossible.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2\cdot 10^5$, $0 \le m \le 2\cdot 10^5$).
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$) — the two microservices connected by an integration pipeline.

## Output
If no valid assignment exists, print a single line containing `NO`.
Otherwise, print `YES`, followed by a second line with $n$ integers $c_1 \dots c_n$ (each in $\{1,2\}$). This sequence must represent a valid tier assignment. If multiple valid assignments exist, output the sequence that is lexicographically smallest.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<METHOD_NAME>
Set-Union Maximization Constraint
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces the algebraic constraint (product of sums is exactly $3^m$) with a set-theoretic one (the sum of the sizes of memory block unions equals $2000m$). This forces the model to deduce that each union must achieve its maximum possible size of 2000, which only happens when the two nodes are assigned disjoint memory blocks (different tiers). This defeats models that rely on simple algebraic cues like 'XOR 3' or 'sum is 3' to blindly trigger a bipartite graph coloring template.
</METHOD_DESCRIPTION>
<METHOD_NOVEL>
yes
</METHOD_NOVEL>
<RATIONALE>
I completely removed the mathematical operations (addition and multiplication) that models were using as shortcuts to identify the problem as 2-coloring. By reframing the edge constraint as the cardinality of a set union needing to reach its theoretical maximum across all edges, models must now genuinely reason about the properties of the sets to realize that adjacent nodes must possess different values.
</RATIONALE>
<PRESERVED_ANSWER>
Since the maximum footprint of any single test is 2000, achieving a total aggregate footprint of $2000m$ requires every single test to have a footprint of exactly 2000, which strictly enforces that connected microservices must be assigned different tiers, perfectly mirroring the seed's bipartite constraint.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to finding the lexicographically smallest 2-coloring of a graph (or determining if it contains an odd cycle), which is solvable in O(n+m) time using Breadth-First Search.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret 'accessible to at least one' as a simple arithmetic sum of sizes rather than a set union, though the phrase 'unique memory addresses' explicitly clarifies that it evaluates cardinality without double-counting overlaps.
</RISK>
