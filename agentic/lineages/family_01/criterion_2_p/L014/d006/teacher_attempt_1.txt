# Portfolio Diversification Strategy

Time limit: 1 s   Memory limit: 256 MB

You are a quantitative analyst constructing a portfolio from a pool of $n$ distinct financial assets, numbered 1 through $n$. Each asset must be assigned to one of two operational modes: Mode A or Mode B.

Risk analysis has flagged $m$ structural dependencies between certain pairs of assets. To maintain balanced exposure, regulatory rules evaluate these dependencies using a strict compatibility matrix. For any two assets linked by a dependency, the combination of their assigned modes must yield a 'Permitted' status:
- Both assets assigned to Mode A: Forbidden
- One asset in Mode A and the other in Mode B: Permitted
- Both assets assigned to Mode B: Forbidden

The firm's automated trading system demands a strictly deterministic portfolio configuration. If multiple valid configurations satisfy all regulatory rules, the system filters them sequentially: it evaluates the assets in ascending order from 1 to $n$. For each asset $i$, if the pool of remaining valid configurations contains both assignments (Mode A and Mode B) for asset $i$, the system permanently discards all configurations where asset $i$ is assigned to Mode B. This filtering proceeds through all $n$ assets until a single definitive configuration remains.

If the dependencies make it impossible to assign modes without violating a rule, you must reject the pool entirely.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2\cdot 10^5$, $0 \le m \le 2\cdot 10^5$) — the number of assets and the number of structural dependencies.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$), indicating a dependency between asset $u$ and asset $v$.

## Output
If no valid configuration is possible, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers separated by spaces, representing the definitive configuration. Print `1` if the asset is assigned to Mode A, and `2` if it is assigned to Mode B.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<RATIONALE>
The explicit numeric constraint "indices sum to exactly 3" was removed, as it served as a direct trigger for models to recognize the problem as bipartite graph 2-coloring. It was replaced with abstract states (Mode A and Mode B) and a descriptive compatibility matrix, forcing models to infer the mutual-exclusion logic from the rules rather than pattern-matching a well-known arithmetic shortcut.
</RATIONALE>
<PRESERVED_ANSWER>
The compatibility rules strictly enforce that linked assets must have different modes (Mode A and Mode B), which perfectly maps to the original requirement that their indices (1 and 2) must sum to 3, and the tie-breaking logic identically prefers Mode A (mapped to 1) over Mode B (mapped to 2).
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to finding a valid 2-coloring (checking bipartiteness) of an undirected graph, which is in P and solvable in O(n+m) time using BFS/DFS.
</PRESERVED_CLASS>
