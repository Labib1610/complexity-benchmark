# Problem B — Pipeline Segregation Phase

Time limit: 1 s
Memory limit: 256 MB

In the automated deployment pipeline for the Aegis distributed architecture, the deployment process is divided into three distinct phases: telemetry gathering, module segregation, and binary distribution. You are responsible for implementing the module segregation phase.

During the initial telemetry phase, the system monitors independent service modules and generates a list of interference warnings. Each warning specifies a pair of modules that compete for identical hardware resources. The system's module registry allocates a fixed block of exactly $800,000$ bytes, where each active module requires exactly $4$ bytes of tracking data. The architecture mandates that at least one module is always active, up to the maximum that fits in the registry block. Meanwhile, the telemetry warning log is allocated exactly $1,600,000$ bytes, with each recorded warning occupying $8$ bytes. The log may be completely empty, or it may contain any number of warnings up to its full capacity.

In your segregation phase, you must configure every module to run in exactly one of two distinct operating modes, identified as mode 1 and mode 2. To prevent resource conflicts, any pair of modules listed together in an interference warning must be configured to run in different modes.

The final binary distribution phase requires a strictly deterministic configuration to route requests. Because there may be multiple valid ways to assign the modes, the distribution phase expects the configuration that is lexicographically smallest. (A configuration is represented as a sequence of integers, where the $i$-th integer is the mode chosen for module $i$. One sequence is lexicographically smaller than another if it has a smaller value at the first position where they differ).

If the telemetry constraints are inherently contradictory and no valid configuration is possible, your phase must halt the pipeline by rejecting the setup.

## Input
The first line contains two integers $n$ and $m$, representing the number of modules and the number of interference warnings, respectively. (Their possible minimum and maximum values are dictated by the registry and log capacities described above).
Each of the following $m$ lines contains two integers $u$ and $v$ (valid module identifiers from $1$ to $n$), representing a pair of modules that must not share an operating mode.

## Output
If no valid configuration exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers (each either 1 or 2)—the lexicographically smallest valid configuration for the modules.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
