<STATEMENT>
# Problem A — Protocol Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

A secure network requires establishing exactly **k** simultaneous communication channels. You are provided with a catalog of **t** authorized port configurations.

Each configuration is defined by a triplet of integers `(x, y, z)`, corresponding to the initialization vectors.

To ensure there is no cross-channel interference, the set of **k** chosen configurations must be completely mutually disjoint across all three parameters. This means that for any two distinct chosen configurations `(x1, y1, z1)` and `(x2, y2, z2)`, they must satisfy all three of the following conditions:
- `x1 ≠ x2`
- `y1 ≠ y2`
- `z1 ≠ z2`

Determine whether it is possible to select exactly **k** configurations from the catalog that satisfy this non-interference property. If it is possible, output one such valid selection of **k** configurations.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the required number of channels, and the total number of authorized configurations in the catalog.
Each of the following **t** lines contains three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), representing an authorized configuration. No configuration is listed more than once.

## Output

If a valid selection of **k** configurations exists, print `YES` on the first line. Then, print **k** lines, each containing the three integers `x y z` of a chosen configuration. The configurations may be printed in any order.

If no such selection exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both authorized configurations have y = 1. Therefore, it is impossible to select two configurations without them sharing the same y value.
</STATEMENT>
<RATIONALE>
I replaced the explicit "exact cover" framing ("every component... is utilized exactly once") with an "independent set" framing ("no two chosen configurations share any parameter"). Because exactly k configurations are chosen and the values are bounded by k, this is mathematically identical, but it forces models to either deduce the permutation property themselves or fall back to much slower pairwise-conflict searches instead of immediately using efficient bitmask state pruning.
</RATIONALE>
<PRESERVED_ANSWER>
Choosing k items from a set where each parameter is in 1..k such that no two items share any parameter mathematically guarantees that every parameter value from 1 to k is used exactly once, matching the original requirement.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, asking for a subset of size k from a collection of triplets such that all elements in each dimension are distinct.
</PRESERVED_CLASS>
<RISK>
Models might quickly skim "mutually disjoint" and mistakenly think a single configuration cannot have x=y or y=z, but the explicit pairwise mathematical formulas provided directly after remove this ambiguity.
</RISK>
