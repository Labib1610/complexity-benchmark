# Problem A — Signal Routing

Time limit: 5 s   Memory limit: 256 MB

## Description

You are configuring a network of **k** communication relays. Each relay requires a dedicated transceiver module.

The system scale factor is given by an integer **k**. Due to the hardware capacity of the main signal multiplexer, this scale factor **k** is capped at exactly 22. All available frequencies in the system are assigned an integer ID from 1 to **k**.

You are provided with a catalog of **t** available transceiver modules. Each module is hardwired to operate on a specific triplet of frequencies: an `uplink` frequency, a `downlink` frequency, and a `sideband` frequency. No two available modules in the catalog use the exact same triplet of frequencies.

Your task is to select exactly **k** modules from the catalog to equip the **k** relays. To prevent signal interference across the network, the selection must satisfy the following strict condition:
- Every frequency ID from 1 to **k** must be assigned exactly once as an `uplink` frequency among the chosen modules.
- Every frequency ID from 1 to **k** must be assigned exactly once as a `downlink` frequency among the chosen modules.
- Every frequency ID from 1 to **k** must be assigned exactly once as a `sideband` frequency among the chosen modules.

Determine whether it is possible to select exactly **k** valid modules from the catalog, and if so, report one valid selection.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the system scale factor, and the number of available transceiver modules. 
Each of the next **t** lines contains three integers `uplink`, `downlink`, `sideband` (1 ≤ uplink, downlink, sideband ≤ k), representing the frequencies of an available module. No module's frequency triplet is listed more than once.

## Output

If a valid configuration of **k** modules exists, print `YES` on the first line, then print **k** lines, each containing the three integers `uplink downlink sideband` of one chosen module. Any selection meeting the conditions is accepted; the modules may be printed in any order.

If no valid configuration exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both available modules share the same `downlink` frequency (1). Choosing both would mean the frequency ID 1 is assigned twice as a `downlink`, violating the interference condition, so it is impossible to configure 2 valid relays.

<RATIONALE>
The problem was completely reframed from a 3D spatial grid (with x, y, z coordinates and structural non-alignment) to a communication network configuration (with uplink, downlink, sideband frequencies). This removes any semantic triggers for "3D matching" that models might rely on. The exact numeric bounds were restored to the Input section to satisfy strict I/O formatting constraints, while the limit of 22 was also integrated into the narrative as a hardware multiplexer limit. The non-alignment condition was rephrased positively ("every ID from 1 to k must be assigned exactly once") which is mathematically equivalent for k choices but requires the model to recognize the permutation structure rather than just matching a "no two may share" pattern.
</RATIONALE>

</PRESERVED_ANSWER>
