<METHOD_NAME>Constraint Inversion via Pairwise Mutual Exclusion</METHOD_NAME>
<METHOD_DESCRIPTION>I replaced the global "use every resource exactly once" exact-cover constraint with a local pairwise constraint: "select exactly W items such that no two share the same resource". Mathematically, selecting W items from W possible values with no collisions forces a bijection (exact cover), but phrasing it as pairwise mutual exclusion pushes LLMs to model the problem as Maximum Clique or Independent Set on a conflict graph. Because standard clique algorithms scale poorly on dense graphs without exploiting the specific multipartite structure, this reframing is expected to induce TLE or suboptimal search strategies from models relying on surface-level pattern matching.</METHOD_DESCRIPTION>

# Problem A — Quantum State Entanglement

Time limit: 5 s   Memory limit: 256 MB

## Description

You are configuring a quantum computing system that requires a core of exactly **W** entangled states.

The system uses **W** distinct particle types, **W** distinct spin orientations, and **W** distinct energy levels. Each of these properties is identified by an integer from 1 to **W**.

You are provided with a list of **N** stable configurations. Each configuration is defined by exactly one particle type (**p**), one spin orientation (**s**), and one energy level (**e**). 

You must select a subset of exactly **W** configurations from the provided list to form a valid core. To maintain quantum stability and prevent interference, the selected subset must satisfy the following strict conditions:
- No two configurations in the chosen subset may share the same particle type.
- No two configurations in the chosen subset may share the same spin orientation.
- No two configurations in the chosen subset may share the same energy level.

Determine whether it is possible to select such a subset of configurations to form a valid core, and if so, report one such selection.

## Input

The first line contains two integers **W** and **N** (1 ≤ W ≤ 22, 0 ≤ N ≤ W·W·W): the required number of states for the core and the number of stable configurations available. 

Each of the next **N** lines contains three integers **p**, **s**, and **e** (1 ≤ p, s, e ≤ W), representing a stable configuration with particle type **p**, spin orientation **s**, and energy level **e**. No configuration is listed more than once.

## Output

If a valid core can be formed, print `YES` on the first line, then print **W** lines, each containing the three integers `p s e` of one chosen configuration. Any valid selection is accepted; the configurations may be printed in any order.

If no such core can be formed, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both stable configurations share the same spin orientation (1). Choosing both would violate the condition that no two selected configurations may share the same spin orientation, so it is impossible to form a valid core.

<RATIONALE>
The problem was rewritten to describe the exact cover condition as a pairwise mutual exclusion constraint ("no two configurations may share the same...") over a fixed subset size, rather than a global completeness constraint ("utilize every... exactly once"). This mathematically identical formulation encourages solvers to approach it as an Independent Set or Maximum Clique problem on a conflict graph, which is highly likely to cause TLE for standard exponential search templates that fail to exploit the underlying 3D matching structure.
</RATIONALE>
