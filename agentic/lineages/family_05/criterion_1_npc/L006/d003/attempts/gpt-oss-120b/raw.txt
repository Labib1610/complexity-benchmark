**Solution Explanation**

For every integer `k (1 ≤ k ≤ 22)` we have three sets  

* bases `M = {1 … k}`
* reagents `C = {1 … k}`
* temperatures `F = {1 … k}`  

and `t` different triples `(m , c , f)` (`m∈M , c∈C , f∈F`).  
We have to choose **exactly `k` triples** so that each element of the three
sets occurs **once** in the chosen triples.

The problem is the *exact‑cover* problem for a 3‑partite 3‑uniform hypergraph.
Because `k ≤ 22` a simple depth‑first search with bit masks is fast enough.



--------------------------------------------------------------------

#### 1.   Data structures

* `triples_by_base[b]` – list of all triples whose base is `b`
  (0‑based indices are used inside the program).
* three integer bit masks  

```
usedM … bases already taken
usedC … reagents already taken
usedF … temperatures already taken
```

`usedM` always has exactly the same number of set bits as the recursion depth,
therefore the recursion depth never exceeds `k`.

* `answer` – list of the triples already chosen (size ≤ k).

All masks fit into a normal Python `int` because `k ≤ 22`.

--------------------------------------------------------------------

#### 2.   Recursive search

```
search(usedM, usedC, usedF):
    if usedM has k bits set:               # all bases are used
            success → store answer
    choose the first base b that is still free
    for each (b, c, f) in triples_by_base[b]:
            if c and f are still free:
                    mark them used, add triple to answer
                    recurse
                    undo the changes
    if none works → backtrack (return False)
```

*Choosing the first free base* is a very good heuristic: every solution must
contain exactly one triple for this base, therefore the branching factor is
the number of triples that contain it and respect the already used `c` and `f`.

The recursion depth is at most `k = 22`.  
Even in the worst case the total number of visited nodes is far below the
limit (`5 s`) because each level discards many triples by the mask test.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct schedule
iff such a schedule exists.

---

##### Lemma 1  
During the execution of `search` the three masks always represent the set of
bases, reagents and temperatures that appear in `answer`.

**Proof.**  
Initially all masks are `0` and `answer` is empty – the statement holds.
When the algorithm adds a triple `(b,c,f)` it sets the three corresponding bits
and appends the triple to `answer`. When it backtracks it clears the same bits
and removes the triple. No other modifications are performed. ∎



##### Lemma 2  
If `search` reaches the line `if usedM has k bits set` then `answer`
contains exactly `k` triples and each element of `M, C, F` occurs exactly once
in them.

**Proof.**  
`usedM` has `k` bits ⇒ every base is used.  
By Lemma&nbsp;1 the masks describe the elements occurring in `answer`.  
Because a bit is set only when the corresponding element is added and never
cleared while the recursion continues, each element appears at most once.
Since there are `k` bases and each triple contains one base, `answer` has
exactly `k` triples, consequently also `k` distinct reagents and `k` distinct
temperatures. ∎



##### Lemma 3  
If a valid schedule exists, `search` eventually returns `True`.

**Proof.**  
Consider any fixed valid schedule `S`.  
At the first recursive call the algorithm picks the smallest free base `b`.
`S` contains a triple `(b, c, f)`. Because `c` and `f` are still free
(the schedule uses each element only once), this triple is among the
enumerated candidates, therefore the recursive call that chooses it is
explored.

Inductively, assume the algorithm has already followed the triples of `S`
for the first `d` recursion levels (`0 ≤ d < k`).  
All elements of those `d` triples are marked used, all other elements are still
free, thus the `(d+1)`‑st triple of `S` is again a candidate and the algorithm
will explore the branch that picks it.

Consequently the recursion can follow the whole schedule `S` and reaches the
success test, returning `True`. ∎



##### Lemma 4  
If `search` returns `True`, the printed triples form a valid schedule.

**Proof.**  
`True` is returned only when the success test is satisfied.
By Lemma&nbsp;2 the current `answer` then contains `k` triples covering each
element of the three sets exactly once. The algorithm outputs exactly this
`answer`. ∎



##### Lemma 5  
If `search` returns `False`, no valid schedule exists.

**Proof.**  
Assume a schedule existed. By Lemma&nbsp;3 the recursion would have a branch
that follows this schedule and would therefore reach the success test,
returning `True`. This contradicts the assumption that the whole search
returns `False`. Hence no schedule exists. ∎



##### Theorem  
The program prints  

* `YES` followed by a correct schedule **iff** such a schedule exists,
* otherwise prints `NO`.

**Proof.**  
The program calls `search`.  
*If it returns `True`* – by Lemma&nbsp;4 the printed triples are a valid
schedule, and the program prints `YES`.  
*If it returns `False`* – by Lemma&nbsp;5 no schedule exists, and the program
prints `NO`. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*`k ≤ 22`, `t ≤ k³ ≤ 10648`.*

* Pre‑processing: `O(t)` to fill the lists.
* In the recursion each level scans all triples of the currently chosen base,
  at most `k²` (worst case `22·22 = 484`).  
  The depth is `k`, therefore the total work is bounded by  
  `O(k · k²) = O(k³) ≤ 10648` in the worst case, far below the limits.
* Memory consumption: the lists store all `t` triples → `O(t)` integers,
  plus a few masks – well under the 256 MiB limit.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    k = int(next(it))
    t = int(next(it))

    triples_by_base = [[] for _ in range(k)]          # 0‑based
    for _ in range(t):
        m = int(next(it)) - 1
        c = int(next(it)) - 1
        f = int(next(it)) - 1
        triples_by_base[m].append((m, c, f))

    answer = []
    full_mask = (1 << k) - 1

    # depth‑first search
    def dfs(usedM: int, usedC: int, usedF: int) -> bool:
        if usedM == full_mask:          # all bases are used
            return True

        # pick first free base
        b = (usedM ^ full_mask).bit_length() - 1   # index of highest zero bit
        # iterate over its triples
        for (bm, rc, ft) in triples_by_base[b]:
            if (usedC >> rc) & 1:      # reagent already used
                continue
            if (usedF >> ft) & 1:      # temperature already used
                continue
            # choose this triple
            answer.append((bm, rc, ft))
            if dfs(usedM | (1 << bm), usedC | (1 << rc), usedF | (1 << ft)):
                return True
            answer.pop()
        return False

    possible = dfs(0, 0, 0)

    out_lines = []
    if possible:
        out_lines.append("YES")
        for (m, c, f) in answer:
            out_lines.append(f"{m+1} {c+1} {f+1}")
    else:
        out_lines.append("NO")
    sys.stdout.write("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
