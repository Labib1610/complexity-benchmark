<STATEMENT>
# Planetary System Blueprint

Time limit: 5 s   Memory limit: 256 MB

## Description

You are an architect designing an artificial planetary system consisting of exactly **k** planets. 
The planetary engineering database contains a pool of **t** stable planet blueprints.

Each blueprint is defined by three structural parameters:
- Core density index (**x**)
- Atmospheric composition index (**y**)
- Orbital resonance index (**z**)

All index values are integers from 1 to **k**.

Your task is to select a subset of exactly **k** blueprints from this database to form your system. To ensure the system's gravitational and thermodynamic stability, the chosen set of blueprints must satisfy a strict diversity threshold. 

Specifically, you must evaluate your selection by:
1. Counting the number of distinct Core density indices present among the selected blueprints.
2. Counting the number of distinct Atmospheric composition indices present.
3. Counting the number of distinct Orbital resonance indices present.

For the system to be stable, the sum of these three counts must be **at least 3k**.

Determine if such a planetary system can be formed.

## Input

The first line provides two integers, **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k³). Here, **k** represents both the maximum index value and the exact number of blueprints required for the system, and **t** is the total number of blueprints available in the database.
The next **t** lines each contain three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), representing a blueprint in the pool. Every blueprint in the input is distinct.

## Output

If a valid system can be formed, output `YES` on the initial line. Following this, output **k** lines each containing three integers `x y z`, specifying the blueprints used for your system. If several valid selections exist, supplying any one of them is sufficient. The blueprints may be printed in any sequence.

If it is impossible to find **k** blueprints satisfying the condition, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```

```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, the only possible selection of 2 blueprints is `1 1 1` and `2 1 2`. 
- The distinct Core density indices present are 1 and 2 (a count of 2).
- The distinct Atmospheric composition indices present is only 1 (a count of 1).
- The distinct Orbital resonance indices present are 1 and 2 (a count of 2).
The sum of these counts is 2 + 1 + 2 = 5. Since the required sum is at least 3 × 2 = 6, this selection is invalid. With only 2 blueprints available, it is impossible to form a valid system.

This deduction is required to implement the early pruning / Exact Cover logic that makes the search tractable.
