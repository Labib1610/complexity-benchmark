# Archway Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

A historical restoration project involves rebuilding a ruined colonnade. The finished colonnade must consist of exactly **k** distinct arches.

To build a single arch, three components are required: one left pillar, one right pillar, and one keystone. The excavation site has yielded exactly **k** left pillars, **k** right pillars, and **k** keystones. For each component category, the recovered stones are identified by integers from 1 to **k**.

Due to the irregular weathering of the ancient stones over centuries, they cannot be mixed and matched arbitrarily. The restoration engineers have physically tested the stones and compiled a list of structurally sound combinations. An arch can only support itself if its specific combination of (left pillar, right pillar, keystone) is explicitly listed as a sound configuration. 

Your objective is to rebuild exactly **k** independent arches. To achieve this, you must select **k** configurations from the engineers' list such that every individual left pillar, every individual right pillar, and every individual keystone is incorporated into exactly one arch.

Given the quantity **k** and the list of sound configurations, determine if the stones can be successfully grouped to rebuild the entire colonnade. If so, output the configurations to be used.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k), where **k** is the quantity of stones in each category, and **t** is the number of sound configurations available.
Then, **t** lines follow. Each line consists of three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), indicating that left pillar **x**, right pillar **y**, and keystone **z** can form a sound arch. All listed configurations are unique.

## Output

If all stones can be successfully partitioned into **k** arches, print `YES` on the first line. On the following **k** lines, print three integers `x y z` per line, representing the stones used in each rebuilt arch. Any valid partition where each stone appears in exactly one arch will be accepted. You may print the chosen arches in any order.

If there is no way to group all stones into **k** arches, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both sound configurations require right pillar 1. This means right pillar 2 cannot be utilized, making it impossible to form 2 valid arches.

<RATIONALE>
The problem was completely reframed from a manufacturing pipeline to an architectural restoration project involving pillars and keystones. This removes any domain-specific heuristics associated with "tracks" or "equipment synchronization" that might have triggered specific exact-cover or matching templates, forcing the model to recognize the core 3-dimensional matching structure from first principles.
</RATIONALE>
<PRESERVED_ANSWER>
The structural requirements—selecting exactly k triples such that each item from 1 to k in all three categories is used exactly once—are mathematically identical to the seed problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains 3-Dimensional Matching, a classic NP-complete exact cover problem, as the combinatorial constraints and bounds are unchanged.
</PRESERVED_CLASS>
