# Archway Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

The archaeological team is restoring an ancient colonnade. The goal is to successfully assemble exactly **k** standalone monuments from the recovered ruins.

The ruins consist of foundation blocks, column shafts, and decorative capitals. Each of these three categories of components has pieces labeled with integer identifiers.

Due to centuries of wear, not all pieces fit together. The architectural team has analyzed the stonework and produced a catalog of viable configurations. A configuration consists of a foundation block, a column shaft, and a decorative capital that can successfully form a single monument.

You must choose exactly **k** configurations from this catalog. The selection of **k** configurations is structurally sound if and only if it satisfies the following sequence requirements:
- Extract the foundation block identifiers from the **k** chosen configurations. When you sort this collection of **k** integers in ascending numerical order, the value at the 1-indexed **i**-th position (for all 1 ≤ **i** ≤ **k**) must be exactly **i**.
- Extract the column shaft identifiers from the **k** chosen configurations. When you sort this collection in ascending numerical order, the value at the 1-indexed **j**-th position (for all 1 ≤ **j** ≤ **k**) must be exactly **j**.
- Extract the decorative capital identifiers from the **k** chosen configurations. When you sort this collection in ascending numerical order, the value at the 1-indexed **m**-th position (for all 1 ≤ **m** ≤ **k**) must be exactly **m**.

## Input

The first line provides two integers, **k** and **t**. Here, **k** represents the target number of monuments to assemble, and **t** is the total number of viable configurations in the catalog.
The value of **k** must be at least the first positive integer, and is bounded by the site's transport capacity, which accommodates a maximum of 22 monuments. The catalog size **t** can be as low as absolute zero and is bounded above by the volume of a cube with side length **k**.
The next **t** lines each contain three integers **x**, **y**, and **z**. This denotes that foundation block **x**, column shaft **y**, and decorative capital **z** can successfully form a monument. Every configuration in the input is distinct. The identifiers **x**, **y**, and **z** begin at the first positive integer and never exceed **k**.

## Output

If a sound selection is possible, output `YES` on the initial line. Following this, output **k** lines each containing three integers `x y z`, specifying the pieces used for each of the **k** monuments. If several sound selections exist, supplying any one of them is sufficient. The monuments may be printed in any sequence.

If it is impossible to find **k** configurations that meet all sequence requirements, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, any attempt to choose 2 configurations will result in a collection of column shaft identifiers that, when sorted, is `1, 1`. The value at the 1-indexed 2nd position is 1, which does not equal 2. Therefore, no sound selection can be formed.

<RATIONALE>
The explicit exact-cover constraint ("no two chosen configurations share...") has been replaced with a sorting property, and the bounds are stated indirectly via physical limits (Strategy S07). Models can no longer trigger their DLX/exact-cover templates via simple keyword or pattern matching. To succeed, the model must logically deduce that a sorted sequence of `k` bounded integers equaling `1..k` is mathematically identical to each item being used exactly once, and then apply standard exact-cover backtracking.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that `k` integers bounded by `k` sort to `1, 2, ..., k` is satisfied if and only if the integers are a permutation of `1..k`, meaning no two configurations share any component, exactly as in the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching; the constraints are mathematically identical to an exact cover, keeping it in NP-Complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the sorting rule as implying the configurations themselves must be output in sorted order, though the Output section explicitly states "The monuments may be printed in any sequence."
</RISK>
