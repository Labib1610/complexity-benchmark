# Quantum Resonance Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

You are designing a quantum resonance core. The core requires exactly **k** modules to function.

You are provided with a catalog of **t** available modules. Each module is characterized by exactly 3 parameters: Frequency, Amplitude, and Phase. 

To achieve perfect stability, you must select exactly **k** modules from the catalog such that all the following conditions are met:
1. No two selected modules may share the same Frequency parameter.
2. No two selected modules may share the same Amplitude parameter.
3. No two selected modules may share the same Phase parameter.

Determine if such a stable core can be formed by selecting exactly **k** modules from the catalog.

## Input

The first line provides two integers, **k** and **t**. The core size **k** is bounded below by a single module and bounded above by the containment vessel's maximum capacity of twenty-two modules. The catalog size **t** can be empty (zero) or contain up to every possible combination of parameters, which corresponds to the volume of a cube with side length **k**.

The next **t** lines each contain three integers **x**, **y**, and **z**, representing the Frequency, Amplitude, and Phase parameters of a module in the catalog. Each parameter value is an integer that is at least one and cannot exceed the core size **k**. Every module listed in the input is distinct. You may choose only among these listed modules, and each module from the catalog may be selected at most once.

## Output

If a perfectly stable core can be formed, output `YES` on the initial line. Following this, output **k** lines each containing three integers `x y z`, specifying the modules used for your core. If several valid selections exist, supplying any one of them is sufficient. The modules may be printed in any sequence.

If it is impossible to find **k** modules satisfying the condition, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, the two available modules are `1 1 1` and `2 1 2`. To form a core of size 2, both modules must be selected. However, both of these modules have an Amplitude of 1. This violates the rule that no two selected modules may share the same Amplitude parameter. Thus, it is impossible to form a stable core.
</STATEMENT>
<RATIONALE>
I removed the explicit stage-to-frequency mapping, instead presenting all three parameters symmetrically as requiring uniqueness among the selected modules. I also applied S07 by expressing all numeric bounds through physical limits of the containment vessel and catalog volume. This forces models to independently discover the permutation property of the constraints rather than relying on the explicit stage assignment to partition the search space.
</RATIONALE>
<PRESERVED_ANSWER>
Since exactly k modules are selected and all parameter values are bounded between 1 and k, requiring uniqueness for each parameter logically forces each parameter to form a complete permutation of 1 to k, which is mathematically identical to the original problem's requirements.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, as it still requires selecting k triples from a given set such that no two triples share a value in any of the three coordinates.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret 'no two selected modules may share the same Frequency' as applying only to Frequency and not realizing it forces a 1..k permutation, though the math is strictly unambiguous.
</RISK>
