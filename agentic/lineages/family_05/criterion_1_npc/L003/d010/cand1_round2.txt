<STATEMENT>
# Quantum Resonance Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

You are designing a quantum resonance core. You are provided with a catalog of **t** available modules. Each module is characterized by exactly 3 parameters: Frequency, Amplitude, and Phase. All parameter values are integers between 1 and **k**.

To achieve perfect stability, you must select exactly **k** modules from the catalog such that all the following conditions are met:
1. The chosen modules must cover every Frequency value from 1 to **k** exactly once (i.e., no two selected modules share the same Frequency).
2. The chosen modules must cover every Amplitude value from 1 to **k** exactly once (i.e., no two selected modules share the same Amplitude).
3. The chosen modules must cover every Phase value from 1 to **k** exactly once (i.e., no two selected modules share the same Phase).

Determine if such a stable core can be formed by selecting exactly **k** modules from the catalog.

## Input

The first line provides two integers, **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k³). Here, **k** represents the number of modules required for the core, and **t** is the total number of available modules in the catalog.

The next **t** lines each contain three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), representing the Frequency, Amplitude, and Phase parameters of a module in the catalog. Every module listed in the input is distinct. You may choose only among these listed modules, and each module from the catalog may be selected at most once.

## Output

If a perfectly stable core can be formed, output `YES` on the initial line. Following this, output **k** lines each containing three integers `x y z`, specifying the modules used for your core. If several valid selections exist, supplying any one of them is sufficient. The modules may be printed in any sequence.

If it is impossible to find **k** modules satisfying the condition, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, the two available modules are `1 1 1` and `2 1 2`. To select exactly 2 modules that cover every Frequency from 1 to 2, we must choose both of them. However, both of these modules have an Amplitude of 1. This violates the rule that no two selected modules may share the same Amplitude parameter (or equivalently, that every Amplitude from 1 to 2 must be covered exactly once). Thus, it is impossible to form a stable core.
</STATEMENT>
<RATIONALE>
The seed problem masked its symmetric 3-Dimensional Matching nature by phrasing one dimension (Frequency) as an assignment to sequential "stages". This asymmetry provided a strong heuristic hint, leading models to automatically group modules by Frequency and backtrack stage-by-stage. By removing the "stages" and presenting the requirement symmetrically across all three parameters, models can no longer rely on the surface text to structure their search space, forcing them to reason about the underlying exact cover structure directly.
</RATIONALE>
<PRESERVED_ANSWER>
Because selecting exactly k modules with parameters in the range 1..k requires each parameter value to appear exactly once if no two share a value, the set of valid module selections remains mathematically identical to the seed's stage-assignment formulation, preserving all outputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, an NP-complete problem, as the requirement to select k triples covering all elements in three disjoint sets of size k is the canonical definition of 3DM.
</PRESERVED_CLASS>
