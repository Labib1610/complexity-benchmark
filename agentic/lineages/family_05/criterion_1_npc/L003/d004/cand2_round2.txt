<METHOD_NAME>
Collision-Free Subset Framing
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces the textbook "exact cover" wording ("utilized exactly once") with an "independent set" wording ("subset of exactly k profiles", "mutually collision-free"). Since the identifiers are bounded by k, choosing k collision-free profiles mathematically implies an exact cover, but models relying on pattern-matching will likely attempt a generic backtracking search over the t profiles (which TLEs) rather than branching optimally on the k dimensions.
</METHOD_DESCRIPTION>
<METHOD_NOVEL>
yes
</METHOD_NOVEL>
<STATEMENT>
# Distributed Query Routing

Time limit: 5 s   Memory limit: 256 MB

## Description

A distributed system is being configured to handle a new workload. The system utilizes queries, databases, and indexes, all of which are assigned integer identifiers from 1 up to **k**.

You are given a catalog of **t** authorized execution profiles. Each profile is a triplet consisting of a query, a database, and an index that can successfully operate together without causing a system timeout.

You must determine whether it is possible to construct a complete routing plan. A complete routing plan is defined as a subset of exactly **k** profiles chosen from the catalog. To prevent resource conflicts, the chosen profiles must be mutually collision-free:
* No two selected profiles may share the same query identifier.
* No two selected profiles may share the same database identifier.
* No two selected profiles may share the same index identifier.

## Input

The first line provides two integers, **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k³). Here, **k** defines the maximum identifier value for any query, database, or index, and **t** is the total number of authorized profiles in the catalog.
The next **t** lines each contain three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k). This denotes that query **x**, database **y**, and index **z** form an authorized execution profile. Every profile in the input is distinct; no configuration `(x, y, z)` appears more than once.

## Output

If a complete routing plan is possible, output `YES` on the first line. Following this, output **k** lines each containing three integers `x y z`, specifying the profiles used for the plan. If multiple valid plans exist, supplying any one complete plan is sufficient. The profiles may be printed in any sequence.

If it is impossible to find a set of exactly **k** collision-free profiles, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both authorized profiles use database 1. Consequently, they would cause a database collision if both were selected. It is impossible to select 2 collision-free profiles from the catalog.
</STATEMENT>
<RATIONALE>
The rewrite changes the problem description from an "exact cover" framing (each item utilized exactly once) to an "independent set" framing (find exactly k items with no collisions). This forces the model to mathematically deduce that selecting k collision-free items from a domain of size k is equivalent to an exact cover, preventing reliance on surface-level keyword triggers for DLX or specialized DP algorithms. The formal bounds are restored verbatim to satisfy the gate checker's exact-match requirements.
</RATIONALE>
<PRESERVED_ANSWER>
Selecting exactly k profiles such that no two share an identifier from a domain of size k means every identifier from 1 to k must be used exactly once, which is mathematically identical to the original requirement of using every piece exactly once.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, which is NP-complete, as the underlying combinatorial structure and constraints are strictly identical.
</PRESERVED_CLASS>
