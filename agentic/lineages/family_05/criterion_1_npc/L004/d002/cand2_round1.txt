<STATEMENT>
# Problem A — Configuration Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

A system must execute a batch of operations. Each operation is defined by a configuration of three distinct parameters. For each parameter, the assigned value must be an integer from 1 up to the system scale.

Only certain configurations of the three parameters are stable. You are given a list of these stable configurations.

You must select a subset of the given stable configurations to form your execution schedule. A schedule is valid if and only if the collection of first parameters from your chosen configurations contains every integer from 1 up to the system scale exactly once. This identical requirement must also be met independently by the collection of second parameters, and by the collection of third parameters.

Determine whether a valid schedule can be formed, and if so, report one valid set of configurations.

## Input

The first line contains two integers: the system scale and the number of known stable configurations. The system scale is at least 1 and capped at 22 due to hardware limits. The number of stable configurations is non-negative and will not exceed the total number of theoretically possible combinations for the given scale.

Each of the following lines describes one stable configuration using three integers. Each integer is between 1 and the system scale, inclusive. No configuration is listed more than once.

## Output

If a valid selection of configurations exists, print `YES` on the first line, then print the chosen configurations, one per line. Each line must contain the three values of the configuration. Any selection meeting the requirement is accepted, and the configurations may be printed in any order.

If no valid selection exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, any selection meeting the requirement would have to include both stable configurations to cover the system scale of 2. However, they both use the value 1 for the second parameter, which means the collection of second parameters from the chosen subset would be `1, 1`, failing to contain every integer from 1 to 2 exactly once.
</STATEMENT>
<RATIONALE>
The description was rewritten to require the collection of each parameter's chosen values to contain all integers from 1 to the system scale exactly once, rather than explicitly asking to select exactly k configurations where no two share a parameter. The numeric bounds for k and t were expressed indirectly through physical hardware limits and the theoretical maximum of combinations (k³). This forces the model to deduce the subset size and recognize the exact-cover structure from the "exactly once" property rather than relying on explicit pairwise distinctness cues.
</RATIONALE>
<PRESERVED_ANSWER>
Any valid schedule must select exactly k configurations to cover the k required values for each parameter exactly once, which mathematically restricts the solution space to exactly the same valid selections as the original problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core task is still finding a perfect 3-dimensional matching on a k by k by k tripartite hypergraph, keeping it in the NP-complete class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "collection of first parameters" as the mathematical set of unique values rather than a multiset, but the phrase "contains every integer ... exactly once" clarifies that duplicates would violate the rule, removing potential ambiguity.
</RISK>
