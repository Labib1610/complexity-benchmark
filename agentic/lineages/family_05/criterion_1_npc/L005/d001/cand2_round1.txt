# Problem A — Cloud Provisioning

Time limit: 5 s   Memory limit: 256 MB

## Description

A cloud infrastructure team is tasked with initializing a batch of **k** isolated virtual instances. Constructing a single instance demands exactly three distinct components: one compute node, one container image, and one database shard. The team's total available inventory holds exactly **k** compute nodes, **k** container images, and **k** database shards.

Due to strict network policies and architectural constraints, only specific complete combinations of these three resources will successfully boot. You will be provided with a comprehensive log of all viable assemblies. A deployment is valid only when every selected compute node, container image, and database shard triad appears explicitly in the log as a single verified assembly. The compatibility of any two components does not imply that they will function alongside a given third component, and the setup cannot be validated by pairing resource types independently.

Your objective is to pick exactly **k** assemblies from the log such that every single compute node, container image, and database shard from the inventory is incorporated into exactly one instance. Determine whether it is possible to achieve this complete utilization, and if so, output one valid configuration.

## Input

The first line provides two integers **k** and **t**. The inventory size **k** for each resource type is at least 1, and because the data center rack has exactly 22 physical slots, **k** will never exceed this capacity. The number of viable assemblies **t** is at least 0 and at most the theoretical maximum where every item is universally compatible (the cube of **k**).

Each of the subsequent **t** lines contains three integers **x**, **y**, and **z**. Each identifier is a positive integer no greater than the inventory size **k**. These three integers specify a viable assembly consisting of compute node **x**, container image **y**, and database shard **z**. No assembly is documented more than once.

## Output

If a full deployment of **k** instances is achievable, print `YES` on the first line. Following that, print **k** lines, each containing three integers `x y z` to describe the compute node, container image, and database shard of one initialized instance. Any configuration where every resource is utilized exactly once is acceptable; the instances may be listed in any order.

If no such deployment is achievable, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable assemblies require container image 1, meaning container image 2 can never be deployed.

<RATIONALE>
The problem description was rewritten to explicitly state that the three-part assemblies cannot be decomposed or validated by pairing resource types independently, neutralizing the affordance that previously allowed models to apply a bipartite matching heuristic. Numeric bounds were also replaced with indirect scenario constraints (e.g., a 22-slot physical rack capacity and the cube of k) to require derivation rather than simple parsing.
</RATIONALE>
<PRESERVED_ANSWER>
The core requirement of finding a subset of exact size k from the given triples such that every element appears exactly once remains identical, so all valid assignments are preserved.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching (3DM), which is NP-complete, as it asks to find a perfect matching in a 3-uniform hypergraph.
