<STATEMENT>
# Problem A — Grand Potion Synthesis

Time limit: 5 s   Memory limit: 256 MB

## Description

You are participating in the Grand Synthesis, an alchemical trial where you must simultaneously brew a specific number of distinct elixirs. The trial provides you with three sets of ingredients: base liquids, rare catalysts, and elemental essences. The ingredients in each set are numbered sequentially starting from 1 up to the number of elixirs you must brew. The alchemy guild's brewing rack has exactly twenty-two slots, so the number of elixirs you must brew is at least one and at most the number of slots on the rack.

An elixir can only be brewed by combining one base liquid, one rare catalyst, and one elemental essence. However, only certain combinations are chemically stable. You have transcribed a list of stable recipes from an ancient grimoire. The grimoire might contain no stable recipes at all, or it might contain every possible combination up to the theoretical maximum.

Your objective is to select recipes from your list to brew the elixirs. A successful Grand Synthesis requires you to select a number of recipes exactly equal to the number of elixirs to be brewed. To maintain alchemical stability among the simultaneous brews, no two selected recipes may share the same base liquid, no two may share the same rare catalyst, and no two may share the same elemental essence.

Determine if it is possible to achieve a successful Grand Synthesis, and if so, report the recipes you have chosen.

## Input

The first line contains two integers: the number of elixirs to be brewed, and the number of stable recipes. The number of stable recipes is non-negative and will not exceed the total number of ways to form an elixir using one ingredient from each of the three sets.
Each of the following lines contains three integers, describing a stable recipe that combines a base liquid, a rare catalyst, and an elemental essence, respectively. No recipe appears more than once in the list.

## Output

If a successful Grand Synthesis is possible, output `YES` on the first line. Then, output one line for each chosen recipe, containing the three integers of that recipe. Any valid selection of recipes that meets the stability requirements is accepted. The chosen recipes can be printed in any order.

If no such selection of recipes exists, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both stable recipes require rare catalyst 1. Since no two selected recipes may share the same rare catalyst, it is impossible to select the required number of recipes.

<RATIONALE>
I replaced the explicit exact-cover phrasing ("consumed in exactly one chosen recipe") with a matching constraint ("no two selected recipes may share..."). I also applied Strategy S07 by moving the numeric bounds into the scenario description (e.g., bounding the number of elixirs by the capacity of a 22-slot brewing rack). This forces the model to recognize that a collision-free selection of size k over sets of size k is equivalent to an exact cover, defeating surface-level pattern matching for Dancing Links.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement to select k recipes with no shared ingredients across sets of size k is mathematically identical to requiring that every ingredient is used exactly once, preserving all valid selections.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, which is NP-complete, only rephrased from an exact cover perspective to a packing perspective.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "the total number of ways to form an elixir using one ingredient from each of the three sets" as something other than k^3, though it is the standard combinatorial definition.
</RISK>
