# Problem A — Balanced Route Deployment

Time limit: 5 s   Memory limit: 256 MB

## Description

You are tasked with deploying a data processing network. The architecture routes continuous data streams from **k** data sources, through **k** transformer nodes, into **k** storage destinations. The components within each of these three layers are indexed starting from 1 up to **k**. The number of components per layer, **k**, is a positive integer capped at a maximum hardware limit of twenty-two. 

Data must be routed in unbroken triplets of `(source, transformer, destination)`. You are provided a list of **t** supported routes that have been verified for compatibility. The number of such routes, **t**, ranges from zero up to the maximum possible number of distinct routes formed by choosing one component from each layer.

Your objective is to establish a steady-state network configuration. A configuration consists of a chosen subset of the supported routes. For the system to remain stable, the hardware utilization must be absolutely uniform: any component—whether a source, a transformer, or a destination—can sustain at most one active routing path. Furthermore, the protocol demands full hardware participation, meaning no component can be left inactive. You must find a subset of the supported routes that satisfies these operational limits for all components simultaneously.

Determine if such a steady-state configuration is achievable, and if so, report the routes to activate.

## Input

The first line contains two integers **k** and **t**: the number of components per layer, and the number of supported routes. The bounds for **k** and **t** are defined by the hardware limits and theoretical maximums described above.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), representing a supported route consisting of source **x**, transformer **y**, and destination **z**. No route is listed more than once.

## Output

If a steady-state configuration exists, print `YES` on the first line, then print the selected routes, one per line, each containing the three integers `x y z`. Any configuration that satisfies the operational limits is accepted; the routes may be printed in any order.

If no such configuration exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both supported routes require transformer node 1, meaning transformer node 2 can never participate in an active route.

<RATIONALE>
The explicit bounds `1 ≤ k ≤ 22` and `0 ≤ t ≤ k·k·k` were removed from the Input section and replaced with descriptive physical limits in the text, forcing the model to infer the numeric bounds from the scenario. Additionally, the phrase "selecting exactly k routes... without omission or duplication" was replaced by two simultaneous conditions: "at most one active routing path" and "no component can be left inactive", which forces the model to deduce that this is an exact cover problem rather than relying on surface pattern matching.
</RATIONALE>
