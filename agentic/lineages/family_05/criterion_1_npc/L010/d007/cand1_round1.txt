<STATEMENT>
# Problem A — Deep Space Relays

Time limit: 5 s   Memory limit: 256 MB

## Description

You are designing a communication array and must select exactly $k$ relay configurations from a provided catalog.

You are given a log of $t$ candidate relays. Each candidate is specified by a triplet of positive integers $(a, b, c)$.

To prevent signal interference, the $k$ chosen relays must satisfy a strict global isolation metric. For each parameter position $j \in \{1, 2, 3\}$ (corresponding to the first, second, and third parameters respectively), and for each integer $v$ from $1$ to $k$, let $c_{j,v}$ be the number of chosen relays that have the value $v$ at position $j$. 

The selection is valid if and only if the sum of the squares of all these $3k$ counts evaluates to exactly $3k$:

$$ \sum_{j=1}^{3} \sum_{v=1}^{k} (c_{j,v})^2 = 3k $$

Determine whether it is possible to select exactly $k$ valid relays from the log. If it is, output the $k$ chosen relays.

## Input

The first line contains two integers $k$ and $t$. The first integer $k$ is the required deployment size (a positive integer capped by the 22 available orbital zones). The second integer $t$ is the total number of candidate relays in the log (a non-negative integer bounded by the deployment size cubed).

The next $t$ lines each contain three integers $a$, $b$, and $c$, detailing a candidate relay. Each parameter of a candidate relay is a positive integer that does not exceed the deployment size $k$. No relay appears more than once in the log.

## Output

If a valid selection of $k$ relays is possible, print `YES` on the first line. Then, print $k$ lines, each containing the three integers $a$ $b$ $c$ of a chosen relay. The chosen relays can be printed in any order. Any valid selection will be accepted.

If no such selection is possible, print `NO`.


**Output**
```
YES

```

### Example 2


**Output**


## Note

In Example 2, the deployment size is $k=2$. The two candidate relays are $(1, 1, 1)$ and $(2, 1, 2)$. If we select both of them, we evaluate the counts $c_{j,v}$ for each position $j \in \{1, 2, 3\}$ and each value $v \in \{1, 2\}$:

- For the first position ($j=1$): the values are $1$ and $2$. So $c_{1,1} = 1$ and $c_{1,2} = 1$. The sum of squares is $1^2 + 1^2 = 2$.
- For the second position ($j=2$): the values are $1$ and $1$. So $c_{2,1} = 2$ and $c_{2,2} = 0$. The sum of squares is $2^2 + 0^2 = 4$.
- For the third position ($j=3$): the values are $1$ and $2$. So $c_{3,1} = 1$ and $c_{3,2} = 1$. The sum of squares is $1^2 + 1^2 = 2$.

The total sum of squares is $2 + 4 + 2 = 8$. Since $8$ is not equal to $3k = 6$, they do not satisfy the isolation condition. It is impossible to select 2 relays that satisfy the requirement.
</STATEMENT>
<RATIONALE>
The explicit cardinalities and unique-element product condition have been replaced with a sum-of-squares formulation over parameter frequencies. To solve this efficiently, the model must mathematically deduce that since the sum of frequencies per position is $k$, the sum of their squares can only equal $3k$ if every frequency is exactly 1 (which precisely defines a 3-Dimensional Matching). This forces genuine reasoning about the algebraic minimum instead of matching keywords like "unique elements" to exact cover algorithms.
</RATIONALE>
<PRESERVED_ANSWER>
The sum of squares of $k$ non-negative integers that sum to $k$ is minimized at $k$ (when all are 1), so the total sum over 3 positions is $\ge 3k$; equality holds if and only if all parameters in each position are distinct, perfectly preserving the 3D matching requirement.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem remains exactly 3-Dimensional Matching, which is NP-complete, simply represented through an algebraic identity rather than set cardinalities.
</PRESERVED_CLASS>
