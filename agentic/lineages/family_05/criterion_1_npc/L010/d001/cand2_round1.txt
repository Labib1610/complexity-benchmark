<STATEMENT>
# Problem A — Crew Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

A project requires the formation of complete work crews. There are three distinct resources available, each containing the exact same number of members, **k**:

- specialists (group X), labeled 1 through **k**,
- machines (group Y), labeled 1 through **k**,
- time slots (group Z), labeled 1 through **k**.

You are provided a catalog of viable deployments `(x, y, z)`. A deployment pairs one specialist with one machine during one time slot. 

The objective is to execute a comprehensive schedule where every single specialist is deployed, every single machine is operated, and every single time slot is utilized. A deployment consumes exactly one of each resource, and no specialist, machine, or time slot can participate in more than one scheduled deployment.

Determine if such a comprehensive schedule is achievable, and if so, list the deployments that form it.

## Input

The first line contains two integers **k** and **t**. The group size **k** is at least 1, and is strictly limited by the facility's maximum capacity of 22 active crews. The number of viable deployments **t** can be as low as 0 and as high as the total number of theoretical combinations of one specialist, one machine, and one time slot.
Each of the following **t** lines contains three integers **x**, **y**, **z** corresponding to valid labels in their respective groups, representing a viable deployment. No deployment is listed more than once.

## Output

If a comprehensive schedule exists, print `YES` on the first line, then print **k** lines, each containing the three members `x y z` of one scheduled deployment. Any schedule that utilizes every specialist, machine, and time slot exactly once is accepted; the deployments may be printed in any order.

If no such schedule exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable deployments require machine 1, meaning machine 2 can never be operated without violating the rule against reusing resources.
</STATEMENT>
<RATIONALE>
The explicit instruction to "choose exactly k allowed combinations" was removed, forcing models to deduce that fully utilizing all resources without reuse inherently requires selecting exactly k non-overlapping triples. The numeric bounds for `k` and `t` were also rewritten as physical limits and theoretical maximums rather than bare inequalities, requiring the model to parse the scenario to extract the constraints.
</RATIONALE>
