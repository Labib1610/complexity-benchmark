<STATEMENT>
# Problem A — Operation Mobilization

Time limit: 5 s   Memory limit: 256 MB

## Description

You are organizing a complex operation requiring $k$ supervisors, $k$ facilities, and $k$ shifts. Each category has its resources numbered from $1$ to $k$.

To form a complete operational unit, you must combine exactly one supervisor, one facility, and one shift. Due to operational constraints, not all combinations are viable. You are given a roster of $t$ certified configurations, each represented as a sequence $(x, y, z)$, meaning supervisor $x$, facility $y$, and shift $z$ can successfully operate together.

Your objective is to mobilize exactly $k$ units from the provided roster. A mobilization is only valid if it utilizes every single resource perfectly—meaning each of the $k$ supervisors, each of the $k$ facilities, and each of the $k$ shifts is assigned to exactly one of the $k$ mobilized units.

Note that the provided roster can be dense, and the configurations may be ordered arbitrarily. The test cases are designed such that simple constrained-first branching strategies may encounter worst-case scenarios, maximizing the required exploration.

Determine if a valid mobilization is possible. If it is, output the configurations that form the units.

## Input

The first line contains two integers $k$ and $t$ ($1 \le k \le 22$, $0 \le t \le k^3$), denoting the number of resources in each category and the total number of certified configurations.
The next $t$ lines each contain three integers $x$, $y$, and $z$ ($1 \le x, y, z \le k$), defining a certified configuration. No configuration appears more than once in the roster.

## Output

If exactly $k$ units can be mobilized satisfying the conditions, print `YES` on the first line. Then, print $k$ lines, each containing the identifiers $x$ $y$ $z$ of a chosen unit. The units can be printed in any order. Any valid mobilization will be accepted.

If no valid mobilization is possible, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable configurations require facility 1. As a result, it is impossible to assign facility 2 to any unit, meaning a perfectly comprehensive mobilization cannot be achieved.
