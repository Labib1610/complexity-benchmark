We need to find a perfect matching in a 3-partite hypergraph, which is NP-hard in general.  
But here \( k \le 22 \), so we can use a meet-in-the-middle or bitmask DP approach.

We can model it as: choose exactly one triplet for each technician, such that hardware and shifts are all used exactly once.

We can do DP over subsets of hardware and shifts, but that’s \( 2^{2k} \) states — too large for \( k=22 \).  
Instead, we can use a **backtracking with pruning** or **DLX (Dancing Links)** style exact cover.

We’ll implement exact cover using Algorithm X with bitmasks for speed.

We have \( k \) technicians, each must be matched to exactly one configuration.  
We can treat each configuration as a row covering three columns: technician, hardware, shift.  
We need to cover all \( 3k \) columns exactly once.

We’ll use bitmask representation for columns:  
- technicians: bits 0..k-1  
- hardware: bits k..2k-1  
- shifts: bits 2k..3k-1  

We’ll use Algorithm X with bit operations.
