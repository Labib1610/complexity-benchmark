<STATEMENT>
# Problem A — Crew Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

Regulatory standards mandate that any concurrent operation must not exceed 22 active certification slots per critical domain. You are tasked with assembling a fully compliant operation plan for a scenario with exactly **k** slots per domain.

An operation requires the synchronization of three domains: personnel, equipment, and scheduling. Within your plan, personnel badges, equipment tags, and schedule blocks are each issued as consecutive integers starting from 1 up to **k**.

A deployment protocol defines a specific synchronization between one personnel badge, one equipment tag, and one schedule block. You will be provided with a registry of all approved protocols.

Your objective is to activate a subset of these protocols to form the operation plan. To meet compliance, the active protocols must be perfectly balanced: across all activated protocols, each personnel badge from 1 to **k**, each equipment tag from 1 to **k**, and each schedule block from 1 to **k** must be utilized exactly once.

Determine if a compliant operation plan can be constructed. If it can, detail the protocols that form it.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k). The value **k** represents the number of certification slots per domain, and **t** is the total number of approved protocols in the registry.

The following **t** lines each contain three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), describing an approved protocol that synchronizes personnel badge **x**, equipment tag **y**, and schedule block **z**. No protocol is listed more than once.

## Output

If a compliant operation plan can be constructed, output `YES` on the first line. Following this, output **k** lines, each containing three integers `x y z` corresponding to an activated protocol. If multiple compliant plans exist, any of them is acceptable. The protocols may be printed in any order.

If no compliant plan can be constructed, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both approved protocols synchronize equipment tag 1. A plan cannot be constructed without reusing equipment tag 1, which violates the requirement that each tag is utilized exactly once.
</STATEMENT>
<RATIONALE>
Removed explicit framing of "distinct pools of resources" and "mutually exclusive" combinations which act as strong keywords for 3D matching and exact cover. The upper bound `k <= 22` was integrated into the scenario's regulatory lore rather than presented purely as an algorithmic limit, forcing models to deduce the exact-cover structure from the "utilized exactly once" constraint rather than relying on surface pattern matching.
</RATIONALE>
<PRESERVED_ANSWER>
Selecting a subset of protocols where each item from 1 to k across three sets is used exactly once is mathematically identical to selecting k mutually exclusive combinations, preserving all valid outputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, asking for a perfect matching in a 3-uniform hypergraph, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "utilized exactly once" as meaning all items must be used in a single protocol, but the phrase "across all activated protocols" resolves this ambiguity.
</RISK>
