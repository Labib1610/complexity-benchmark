# Problem A — Subspace Signals

Time limit: 5 s   Memory limit: 256 MB

## Description

You are designing a signal constellation for a high-frequency subspace communication system. The system requires exactly **k** distinct signal templates to form a complete basis. You are provided with a catalog of **t** candidate signal templates.

Each template is defined by a vector of three integer parameters: frequency band, phase shift, and amplitude level. For each candidate, these three parameters are integers between 1 and **k** inclusive.

To ensure that the **k** selected templates do not interfere with each other, the system dictates that the Hamming distance between any two distinct selected templates in the basis must be exactly 3. 

The Hamming distance between two signal templates is defined as the number of parameters (out of the three) at which their values differ.

Determine if it is possible to select exactly **k** signal templates from the catalog to form a complete basis. If it is, output the parameters of the chosen templates.

## Input

The first line specifies the basis size **k** and the catalog size **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k).

The following **t** lines each contain three integers representing the frequency band, phase shift, and amplitude level of a candidate template. All parameter values are between 1 and **k**. No two templates in the catalog have the exact same combination of all three parameters.

## Output

If a successful selection of exactly **k** templates is possible, print `YES` on the first line. Following this, print **k** lines, each containing the three parameters of a selected template. If multiple valid selections exist, any of them is acceptable, and the templates may be printed in any order.

If no such selection is possible, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, there are only two candidate templates: `1 1 1` and `2 1 2`. The Hamming distance between them is 2, because they differ in the first parameter (1 vs 2) and the third parameter (1 vs 2), but share the same second parameter (1 = 1). Since the required Hamming distance for any pair of distinct selected templates is 3, these two cannot be selected together. As **k** = 2 templates are needed, a successful selection is impossible.
</STATEMENT>
<RATIONALE>
I replaced the global exact-cover constraint (sum of unique parameter values equals 3k) with a pairwise local constraint (the Hamming distance between any two selected templates must be exactly 3). Models that pattern-match will map this to Maximum Clique or Independent Set and write generic graph backtracking algorithms (like Bron-Kerbosch) that TLE on the dense conflict graph. Models that genuinely reason will deduce that a k-clique in this space implies a permutation over each coordinate, allowing them to reformulate it back to Exact Cover and use efficient coordinate-branching.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that $k$ items have a pairwise Hamming distance of 3 means no two items can share any of their three parameters; since parameters are bounded by $k$, this is mathematically identical to requiring that all $k$ items together cover every parameter value exactly once.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching (NP-complete), merely described through the equivalent condition of finding a $k$-clique in the conflict graph of the matching instance.
</PRESERVED_CLASS>
