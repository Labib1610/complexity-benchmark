<STATEMENT>
# Problem A — Resonant Waveforms

Time limit: 5 s   Memory limit: 256 MB

## Description

A quantum communications array operates at a system scale **k**. 
For a given scale **k**, we define a $3 \times 3$ transformation matrix $M$ as follows:

$$M = \begin{pmatrix} k+1 & 1 & 0 \\ 0 & k+1 & 1 \\ 0 & 0 & k+1 \end{pmatrix}$$

You are provided with a catalog of **t** potential signal paths. Each path is characterized by a triplet of integers `(x, y, z)`. 
For any path, its signature matrix $S(x, y, z)$ is generated by raising $M$ to specific powers derived from its triplet:

$$S(x, y, z) = M^x + M^{k+y} + M^{2k+z}$$

*(Here, $M^p$ denotes the matrix $M$ multiplied by itself $p$ times).*

Your objective is to stabilize the array by activating exactly **k** paths from the catalog. The array reaches a stable state if and only if the matrix sum of the signatures of the chosen paths exactly equals the target matrix $T$, which is the sum of all powers of $M$ from $1$ to $3k$:

$$T = \sum_{i=1}^{3k} M^i$$

Determine whether there is a subset of exactly **k** paths that achieves this stable configuration. If a valid configuration exists, output one such valid set.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the scale of the system and the number of available signal paths in the catalog.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), representing an available path. No path is listed more than once.

## Output

If a valid stable configuration of exactly **k** paths exists, print `YES` on the first line, then print **k** lines, each containing the three parameters `x y z` of one chosen path. Any valid configuration is accepted; the paths may be printed in any order.

If no valid configuration exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, **k** = 2. The transformation matrix is:
$$M = \begin{pmatrix} 3 & 1 & 0 \\ 0 & 3 & 1 \\ 0 & 0 & 3 \end{pmatrix}$$

The target matrix $T = \sum_{i=1}^6 M^i$ calculates to:
$$T = \begin{pmatrix} 1092 & 2005 & 1549 \\ 0 & 1092 & 2005 \\ 0 & 0 & 1092 \end{pmatrix}$$

If we select the two available paths:
- The path `1 1 1` has the signature $S(1, 1, 1) = M^1 + M^3 + M^5 = \begin{pmatrix} 273 & 433 & 279 \\ 0 & 273 & 433 \\ 0 & 0 & 273 \end{pmatrix}$.
- The path `2 1 2` has the signature $S(2, 1, 2) = M^2 + M^3 + M^6 = \begin{pmatrix} 765 & 1491 & 1225 \\ 0 & 765 & 1491 \\ 0 & 0 & 765 \end{pmatrix}$.

The matrix sum of these two signatures is:
$$\begin{pmatrix} 1038 & 1924 & 1504 \\ 0 & 1038 & 1924 \\ 0 & 0 & 1038 \end{pmatrix}$$

Since this sum does not exactly equal the target matrix $T$, this configuration is invalid, making it impossible to form a stable configuration.

<RATIONALE>
I replaced the explicit mention of "levels" and the superincreasing capacity sum with a mathematically equivalent matrix equation using a Jordan block. The top-left element of the matrix powers implicitly enforces the base-$(k+1)$ no-carry condition, completely hiding the 3D matching structure. This forces the model to either algebraically deduce the exact cover from matrix powers or implement a matrix-based backtracking search, defeating the shortcut of immediately mapping explicit coordinates to a DLX solver.
</RATIONALE>
