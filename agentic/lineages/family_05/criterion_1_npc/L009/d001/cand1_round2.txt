<STATEMENT>
# Problem A — Crew Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

A facility needs to launch a deployment plan involving three categories of assets:
- operators, identified by integers 1 through **k**,
- apparatuses, identified by integers 1 through **k**,
- shifts, identified by integers 1 through **k**.

A deployment unit consists of one operator, one apparatus, and one shift. You are provided with a catalog of allowed combinations `(x, y, z)`.

Your task is to select exactly **k** of these allowed combinations to form the final deployment plan. The plan is considered fully operational if and only if, across all **k** selected combinations, every operator from 1 to **k** appears at least once, every apparatus from 1 to **k** appears at least once, and every shift from 1 to **k** appears at least once. 

Determine whether such a plan can be formed, and if so, report one valid set of **k** combinations.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the group size and the number of allowed combinations.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), representing an allowed combination. No combination is listed more than once.

## Output

If a valid deployment plan of **k** combinations exists, print `YES` on the first line, then print **k** lines, each containing the three members `x y z` of one chosen combination. Any valid plan is accepted; the combinations may be printed in any order.

If no valid plan exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both allowed combinations use apparatus 1. Since exactly 2 combinations must be selected and they must together ensure that both apparatus 1 and apparatus 2 appear at least once, it is impossible to form a valid plan.
</STATEMENT>
<RATIONALE>
The explicit "no two share" constraint was replaced with a requirement that every element must appear at least once across exactly `k` selections. This indirectly forces the exact cover bound (frequency = 1) via the Pigeonhole Principle, requiring models to derive the non-overlapping property rather than recognizing standard exact-cover boilerplate.
</RATIONALE>
<PRESERVED_ANSWER>
Any set of `k` triplets that covers all `k` elements of each type must necessarily be disjoint, making the new coverage condition logically identical to the original non-sharing condition.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, mapping identically to the standard NP-complete formulation.
</PRESERVED_CLASS>
