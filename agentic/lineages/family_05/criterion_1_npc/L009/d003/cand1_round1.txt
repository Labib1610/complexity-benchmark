<STATEMENT>
# Problem A — Station Tethering

Time limit: 5 s   Memory limit: 256 MB

## Description

A space station features three independent docking rings: the Alpha ring, the Beta ring, and the Gamma ring. Each ring is equipped with a sequence of docking ports. The capacity of a ring is **k** ports, referenced by their sequential position from 1 up to **k**.

A tethering configuration connects exactly one port from the Alpha ring, one port from the Beta ring, and one port from the Gamma ring. You are provided with a catalog of allowed tethering configurations, each given as a triplet `(x, y, z)`.

Your objective is to activate a subset of these configurations to fully secure the station. A valid activation plan must ensure that no port is left unconnected, and no port is subjected to multiple connections. Consequently, every individual port across all three rings must participate in precisely one active configuration.

Determine whether such a valid activation plan can be formed, and if so, report one valid set of configurations.

## Input

The first line contains two integers **k** and **t**: the capacity of each ring and the number of allowed configurations. The capacity **k** is at least 1 and is bounded above by the total number of starting players on the pitch in a standard association football match. The quantity **t** is non-negative and will not exceed the volume of a cube with edge length **k**.

Each of the next **t** lines contains three integers **x**, **y**, **z**, representing an allowed configuration connecting the **x**-th port of the Alpha ring, the **y**-th port of the Beta ring, and the **z**-th port of the Gamma ring. No configuration is listed more than once.

## Output

If a valid activation plan exists, print `YES` on the first line, then print **k** lines, each containing the three ports `x y z` of one chosen configuration. Any valid plan is accepted; the configurations may be printed in any order.

If no valid plan exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both allowed configurations require the 1st port of the Beta ring. Thus, they cannot be activated simultaneously without subjecting that port to multiple connections. Since every port must be used exactly once, and only 2 configurations are available in total, it is impossible to form a valid plan.
</STATEMENT>
<RATIONALE>
I removed the explicit instruction to "select exactly k combinations" and the definition of "interference", replacing them with the systemic requirement that every port across all three rings must be used exactly once. I also replaced the bare inequalities in the input with indirect physical and geometric bounds (e.g., the number of players on a football pitch), forcing the model to deduce the mathematical constraints rather than pattern-matching on them.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement to use every port exactly once across three rings of size k necessitates picking exactly k disjoint triples, which is mathematically identical to the original exact-k non-interfering combinations task.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core task is still to find a subset of triples that perfectly covers a 3k-element set without overlaps, which remains the NP-complete 3-Dimensional Matching problem.
</PRESERVED_CLASS>
<RISK>
Models might fail to correctly identify the number of starting players in a standard association football match (22), though this is globally standard knowledge.
</RISK>
