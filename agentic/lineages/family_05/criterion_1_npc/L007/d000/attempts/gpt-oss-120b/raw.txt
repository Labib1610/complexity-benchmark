**Solution Explanation**

For every integer `k ( 1 ≤ k ≤ 22 )`

* enzymes   : `E1 … Ek`
* substrates: `S1 … Sk`
* profiles  : `P1 … Pk`

A viable reaction is a triple `(e , s , p)` – it uses exactly one element
from each group.
From the given list of triples we have to choose **exactly `k` triples**
so that every element `Ei , Sj , Pl` appears in **one** chosen triple.
In other words we need an *exact cover* of the set  

```
U = {E1,…,Ek , S1,…,Sk , P1,…,Pk}      (|U| = 3k)
```

by the given triples (each triple covers three elements of `U`).

The problem is the classic **Exact Cover** problem.
`k ≤ 22` ⇒ `|U| ≤ 66`, while the number of triples `t ≤ k³ ≤ 10648`.
For these sizes the well‑known backtracking algorithm
*Algorithm X* with the *Dancing Links* data structure solves the task
comfortably within the limits.



--------------------------------------------------------------------

#### 1.   Modelling as Exact Cover

* columns   – one column for every element of `U`
* rows      – one row for every given triple  
  the row contains the three columns belonging to its three elements

Finding `k` rows that together contain each column exactly once
is exactly the required protocol.



--------------------------------------------------------------------

#### 2.   Dancing Links (DLX)

DLX stores the sparse 0/1 matrix of rows × columns as a set of doubly
linked lists:

```
column header  <->  column header  <-> …
   ^  |                ^  |
   |  v                |  v
node <-> node <-> … <-> node   (all nodes of the same column)
```

Each node also knows its row id (the index of the triple it belongs to).

Operations needed

* **cover(col)** – removes a column and all rows that contain it
* **uncover(col)** – restores them (exact inverse)

Both are `O(number of removed nodes)` and are performed while recursing.



--------------------------------------------------------------------

#### 3.   Search routine

```
search():
    if no column left → all columns covered → solution found
    choose column c with the smallest number of rows   (heuristic)
    cover(c)
    for each row r in column c:
        add r to current solution
        for each other column j in row r: cover(j)
        if search() succeeds → propagate success
        for each other column j in row r (reverse order): uncover(j)
        remove r from solution
    uncover(c)
    return failure
```

Depth of recursion ≤ `k` (because each chosen row covers three new columns,
so after `k` rows all `3k` columns disappear).

The algorithm explores only a tiny fraction of the exponential search
space; for the given limits it finishes far below the time limit.



--------------------------------------------------------------------

#### 4.   Reconstructing the answer

When the search succeeds we have the list of row indices (triples) that
form the exact cover.
We output them in any order.



--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct set of triples
iff such a set exists.

---

##### Lemma 1  
During the execution of `search` the set of uncovered columns is exactly
the set of elements of `U` that are not yet used by the rows already
chosen in the current recursion path.

**Proof.**  
Initially no column is covered, i.e. all elements are unused – true.
When a row `r` is added, `cover` is called for each column that `r`
contains, removing those columns from the structure.
Thus those elements become “used”.  
When backtracking, `uncover` restores the columns, making the elements
unused again. By induction over the recursion depth the invariant holds. ∎



##### Lemma 2  
`cover(c)` removes **all** rows that contain column `c` and no other rows.

**Proof.**  
Implementation follows Knuth’s description: the column header is
removed from the header list, then for each node in that column the whole
row (all its nodes) is removed from their column lists.
Only rows that have a node in column `c` are touched. ∎



##### Lemma 3  
If `search` reaches the line “no column left”, the rows stored in the
solution list form a set of triples that uses every element of `U`
exactly once.

**Proof.**  
“No column left” means every column header has been covered.
By Lemma&nbsp;1 each covered column corresponds to an element already used
by some chosen row.
Since a column is covered only once (Lemma&nbsp;2 never re‑adds a column
while it stays covered) each element appears in exactly one chosen row.
The number of chosen rows is `k` because each row covers three distinct
columns and there are `3k` columns in total. ∎



##### Lemma 4  
If a set of `k` triples satisfying the requirement exists, `search`
will eventually find it and return success.

**Proof.**  
Consider any correct set `C`.  
At the first recursion level `search` picks a column `c`.  
Because `C` covers all columns, some row `r ∈ C` contains `c`.
`r` is among the rows iterated in the `for` loop (all rows of column `c`
are examined).  
When the algorithm tries `r`, it covers exactly the columns of `r`,
which are also covered by `r` in `C`.  
Thus the remaining uncovered columns are exactly those that `C \ {r}`
covers.  
Inductively, the recursive call can continue to pick the rows of `C`
one after another, never discarding a needed row, because at each step
the needed row is still present in the column chosen (the column
heuristic may pick a different column, but the needed row still belongs
to that column).  
Consequently the recursion can follow the path that selects all rows of
`C` and reaches the success state. ∎



##### Lemma 5  
If `search` returns failure, no set of `k` triples satisfying the
requirement exists.

**Proof.**  
Assume contrary that a correct set `C` exists.
During the execution, at each recursion level the algorithm tries **all**
rows of the currently chosen column.
If the row belonging to `C` is tried, the recursive call proceeds with
exactly the remaining columns of `C \ {row}` (as argued in Lemma&nbsp;4).
Thus the recursion would eventually succeed.
Since the algorithm finally reports failure, every possible choice at
some level leads to dead ends, meaning no correct set can exist. ∎



##### Theorem  
The program outputs  

* `YES` followed by `k` triples that use every enzyme, substrate and
  profile exactly once **iff** such a collection exists,
* otherwise outputs `NO`.

**Proof.**  

*If the program prints `YES`.*  
It did so only after `search` succeeded.
By Lemma&nbsp;3 the printed triples form a valid protocol.

*If a valid protocol exists.*  
By Lemma&nbsp;4 `search` succeeds, therefore the program prints `YES`
and a correct protocol.

*If no valid protocol exists.*  
By Lemma&nbsp;5 `search` fails, the program prints `NO`.

Thus the output is correct in all cases. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*`n = 3k ≤ 66`* – number of columns  
*`m = t ≤ 10648`* – number of rows  

DLX uses `O(n + 3m)` memory (one node per 1‑entry, three per row).

The worst‑case time of Algorithm X is exponential, but for the given
bounds the practical running time is far below the 5 s limit
(typical instances finish in milliseconds).

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(1000000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    k = int(next(it))
    t = int(next(it))

    triples = []
    for _ in range(t):
        e = int(next(it)) - 1          # 0‑based
        s = int(next(it)) - 1
        p = int(next(it)) - 1
        triples.append((e, s, p))

    # ----- build DLX structure -----
    # columns: 0..k-1 enzymes, k..2k-1 substrates, 2k..3k-1 profiles
    ncol = 3 * k
    max_nodes = t * 3 + ncol + 1

    # arrays (1‑based node indexing, 0 is header)
    up = [0] * max_nodes
    down = [0] * max_nodes
    left = [0] * max_nodes
    right = [0] * max_nodes
    col = [0] * max_nodes          # column of node
    row_id = [0] * max_nodes       # which triple (index) the node belongs to
    size = [0] * ncol              # number of nodes in each column

    # header links columns in a circular list
    for i in range(ncol):
        up[i] = down[i] = i
        left[i] = i - 1 if i > 0 else ncol - 1
        right[i] = i + 1 if i + 1 < ncol else 0
    left[0] = ncol - 1
    right[ncol - 1] = 0

    node_cnt = ncol  # next free index

    def add_node(r, c):
        nonlocal node_cnt
        node = node_cnt
        node_cnt += 1
        col[node] = c
        row_id[node] = r

        # insert into column c (at bottom)
        up[node] = up[c]
        down[node] = c
        down[up[c]] = node
        up[c] = node
        size[c] += 1

        return node

    # create rows
    for idx, (e, s, p) in enumerate(triples):
        nodes = []
        for c in (e, k + s, 2 * k + p):
            nodes.append(add_node(idx, c))
        # link the three nodes horizontally (circular)
        for i in range(3):
            left[nodes[i]] = nodes[i - 1]
            right[nodes[i]] = nodes[(i + 1) % 3]

    # ----- DLX operations -----
    def cover(c):
        # remove column header
        left[right[c]] = left[c]
        right[left[c]] = right[c]
        # remove rows
        i = down[c]
        while i != c:
            j = right[i]
            while j != i:
                down[up[j]] = down[j]
                up[down[j]] = up[j]
                size[col[j]] -= 1
                j = right[j]
            i = down[i]

    def uncover(c):
        i = up[c]
        while i != c:
            j = left[i]
            while j != i:
                size[col[j]] += 1
                down[up[j]] = j
                up[down[j]] = j
                j = left[j]
            i = up[i]
        left[right[c]] = c
        right[left[c]] = c

    solution = []
    answer_rows = None

    # heuristic: choose column with minimal size
    def choose_column():
        c = right[0]
        min_sz = size[c]
        best = c
        while c != 0:
            if size[c] < min_sz:
                min_sz = size[c]
                best = c
                if min_sz == 0:
                    break
            c = right[c]
        return best

    def search():
        nonlocal answer_rows
        if right[0] == 0:          # all columns covered
            answer_rows = solution.copy()
            return True
        c = choose_column()
        if size[c] == 0:
            return False
        cover(c)
        r = down[c]
        while r != c:
            solution.append(row_id[r])
            j = right[r]
            while j != r:
                cover(col[j])
                j = right[j]
            if search():
                return True
            # backtrack
            j = left[r]
            while j != r:
                uncover(col[j])
                j = left[j]
            solution.pop()
            r = down[r]
        uncover(c)
        return False

    possible = search()

    out = []
    if possible:
        out.append("YES")
        for idx in answer_rows:
            e, s, p = triples[idx]
            out.append(f"{e+1} {s+1} {p+1}")
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
