<STATEMENT>
# Problem A — Resonance Calibration

Time limit: 5 s   Memory limit: 256 MB

## Description

A geological scanner operates in a subterranean grid of dimensions **k** × **k** × **k**. Every location in the grid is defined by a depth **x**, a latitude **y**, and a longitude **z**, each taking an integer value from 1 to **k**.

The scanner has identified **t** resonance pockets at specific `(x, y, z)` locations. 

To calibrate the scanning array, you must select a subset of exactly **k** resonance pockets from the identified list. The calibration is successful if and only if the selected pockets do not interfere with each other. 

Interference between any two selected pockets occurs if the 3D straight-line distance between them is exactly equal to the 2D straight-line distance between their projections onto the depth-latitude (xy) plane, the depth-longitude (xz) plane, or the latitude-longitude (yz) plane. 

Determine whether a successful calibration is possible, and if so, report one valid selection of resonance pockets.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the grid dimension and the number of identified resonance pockets.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), the coordinates of a resonance pocket. No location is listed more than once.

## Output

If a non-interfering selection of exactly **k** pockets exists, print `YES` on the first line. Then, print **k** lines, each containing the three coordinates `x y z` of one selected pocket. Any valid selection is accepted, and the pockets may be printed in any order.

If no valid selection exists, print `NO`.

## Examples

### Example 1

**Input**
```text
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```text
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```text
2 2
1 1 1
2 1 2
```

**Output**
```text
NO
```

### Example 3

**Input**
```text
1 1
1 1 1
```

**Output**
```text
YES
1 1 1
```

## Note

In Example 2, the two identified resonance pockets are `(1, 1, 1)` and `(2, 1, 2)`. The 3D straight-line distance between them is √2. Their projections onto the depth-longitude (xz) plane are `(1, 1)` and `(2, 2)`, which also have a 2D straight-line distance of √2. Because these distances are equal, selecting both would cause interference, making a successful calibration impossible.
</STATEMENT>
<RATIONALE>
I replaced the explicit "same depth, latitude, or longitude" interference rule with a geometric equivalence: 3D distance equaling 2D projected distance. This forces the model to mathematically deduce that the condition simplifies to coordinate equality ($z_1 = z_2$, etc.). Without this deduction, the model cannot recognize the 3D Matching structure or optimize its backtracking by grouping by a coordinate, leading to a Time Limit Exceeded on generic search.
</RATIONALE>
<PRESERVED_ANSWER>
The 3D Euclidean distance between two points equals the 2D distance of their projection onto an axis-aligned plane if and only if their difference in the omitted third coordinate is exactly zero, making the new interference condition mathematically identical to sharing a coordinate.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, requiring the selection of $k$ disjoint triplets from a given set, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might interpret "projection onto the depth-latitude (xy) plane" incorrectly if they lack basic geometric knowledge, though the explicit inclusion of the axis labels (xy, xz, yz) makes the intended mathematical operation unambiguous.
</RISK>
