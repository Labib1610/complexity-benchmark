# Tensor Factorization Core

Time limit: 5 s   Memory limit: 256 MB

## Description

You are optimizing a sparse tensor operation for a machine learning compiler. The operation involves a 3-dimensional tensor of size **k** × **k** × **k**. The dimensions correspond to batch index **x**, spatial index **y**, and channel index **z**.

The sparsity analysis has identified **t** non-zero elements in the tensor. Each non-zero element is given as a triplet `(x, y, z)`, indicating a value exists at batch **x**, spatial **y**, and channel **z**. All indices are 1-based (from 1 to **k**). The tensor size **k** is at most 22.

To pipeline the computation efficiently, the compiler needs to extract exactly **k** non-zero elements from the identified list to form a "computational core". 
Let the chosen **k** elements be used to construct two 2-dimensional binary matrices, **M_xy** and **M_yz**, both of size **k** × **k**:
- **M_xy**[u][v] = 1 if there is at least one chosen element with batch index **u** and spatial index **v**, and 0 otherwise.
- **M_yz**[v][w] = 1 if there is at least one chosen element with spatial index **v** and channel index **w**, and 0 otherwise.

A computational core is considered valid if and only if both **M_xy** and **M_yz** are strict permutation matrices. A **k** × **k** binary matrix is a strict permutation matrix if it contains exactly one '1' in every row and exactly one '1' in every column.

Determine whether it is possible to extract a valid computational core of exactly **k** elements. If a valid core exists, provide the elements that compose it.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the size of the tensor dimensions and the total number of non-zero elements.
Each of the following **t** lines provides three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), representing a non-zero element at batch **x**, spatial **y**, and channel **z**. All listed elements are distinct.

## Output

If a valid computational core of **k** elements can be formed, print `YES` on the first line. Then, output **k** lines, each containing the three integers `x y z` of one selected element. Any valid core of **k** elements is accepted; the chosen elements may be printed in any order.

If no such core is possible, print `NO`.

## Examples

### Example 1

**Input**
```

1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```

1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```

```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, any selection of 2 elements must include both (1, 1, 1) and (2, 1, 2). The resulting **M_xy** matrix would have ones at (1, 1) and (2, 1), meaning column 1 contains two '1's. This is not a valid permutation matrix, so a valid core is impossible.

<RATIONALE>
The problem is reframed from selecting mutually exclusive configurations to extracting elements that form two coupled permutation matrices. To achieve the required time efficiency, the model must deduce mathematically that the permutation matrix constraints on exactly $k$ elements force the $x$, $y$, and $z$ coordinates to all be distinct permutations, allowing for dimension-grouped backtracking. A model that relies on surface pattern matching will likely attempt a naive subset search over the elements with matrix validation, resulting in a Time Limit Exceeded error.
</RATIONALE>
<PRESERVED_ANSWER>
Because exactly $k$ elements are chosen, the only way for $M_{xy}$ to be a $k \times k$ permutation matrix (which requires exactly $k$ ones) is if all chosen elements have distinct $x$ and distinct $y$ coordinates; similarly, $M_{yz}$ forces distinct $y$ and distinct $z$, making it mathematically identical to the seed's exclusivity constraint.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, as selecting $k$ triplets such that each coordinate appears exactly once is the defining property of 3DM.
</PRESERVED_CLASS>
