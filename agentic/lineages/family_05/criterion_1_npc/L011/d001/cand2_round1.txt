<STATEMENT>
# Problem A — Processor Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

A manufacturing plant produces tri-core processors. Each processor requires three distinct components: an alpha core, a beta core, and a gamma core. For a given production run, the plant has exactly **k** alpha cores, **k** beta cores, and **k** gamma cores available. Within each category, the cores are uniquely identified by integers starting from 1 up to **k**.

The plant relies on a fixed number of testing chambers, which imposes a strict ceiling on the production scale. Specifically, there are 22 testing chambers, meaning the batch size **k** can be as large as the number of available chambers, and is always at least 1.

Not all cores can work together. You are supplied with **t** certified blueprints. Each blueprint is a specific combination of one alpha core, one beta core, and one gamma core that are known to synchronize perfectly. The number of blueprints **t** can be zero, and at most it encompasses every conceivable combination of the three core types for the given **k**.

Your objective is to execute a complete production run. This requires assembling exactly **k** processors using the certified blueprints such that no core is left unused or reused. In other words, every single alpha, beta, and gamma core must be incorporated into exactly one processor.

Determine if it is possible to achieve this complete assembly. If it is, provide one valid set of **k** blueprints that accomplishes the goal.

## Input

The first line specifies the batch size **k** and the number of certified blueprints **t**.
Each of the next **t** lines contains three integers **x**, **y**, and **z**. These represent a certified blueprint consisting of alpha core **x**, beta core **y**, and gamma core **z**. All provided blueprints are unique.

## Output

If a complete assembly of **k** processors is feasible, print `YES` on the first line. Following this, output **k** lines, each containing the three integers `x y z` of a selected blueprint. You may list the selected blueprints in any order.

If no such assembly is possible, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both certified blueprints require beta core 1, meaning beta core 2 can never be utilized.

Removed the explicit bare inequalities for the bounds of `k` and `t`. The limits are now embedded in the scenario description (e.g., the 22 testing chambers and the maximum conceivable combinations), forcing models to read and interpret the text to realize that `k` is small enough to permit an exponential backtracking search.
</RATIONALE>

The structural requirement to select exactly `k` non-overlapping triples from a given list remains identical, ensuring the same configurations are valid.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, which is NP-complete, as it still asks for an exact cover of three equinumerous sets by a subset of given triples.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "every conceivable combination" as a different mathematical bound than $k^3$, though the context of three core types makes it standard.
</RISK>
