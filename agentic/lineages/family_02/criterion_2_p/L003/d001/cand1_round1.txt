<STATEMENT>
# Phase 3: Deployment Planner

Time limit: 1 s   Memory limit: 256 MB

## Description

The continuous integration pipeline for our cloud infrastructure coordinates the deployment of microservices. Each microservice must be assigned to exactly one of two environments: Zone 1 or Zone 0. 

During the aggregation phase, developers submit routing overrides to handle failover scenarios. To guarantee high availability, the orchestrator must establish a global deployment plan where every override is actively supported. 

An override specifies two fallback endpoints. An endpoint is defined by a microservice and its assigned environment. The failover mechanism dictates a strict fallback relationship: if the global deployment plan does not include the first endpoint, it must include the second endpoint to maintain connectivity. Because failover is symmetric, if the deployment lacks the second endpoint, it must include the first. 

Your task is to process these overrides and determine if there exists a global configuration—assigning exactly one environment to each of the $n$ microservices—that supports every override simultaneously. If such a configuration exists, you must output it so the pipeline can proceed. Otherwise, you must halt the pipeline.

## Input
The first line contains two integers $n$ and $m$, representing the number of microservices and the number of overrides. The catalog size $n$ ranges from a single service up to the system capacity of $100,000$. The batch size $m$ can be empty (zero) or contain up to $200,000$ overrides.

Each of the following $m$ lines details a single override using two non-zero integers. The absolute value of an integer identifies a valid microservice ID (a number from $1$ up to $n$). A positive integer specifies that the endpoint expects the microservice in Zone 1, whereas a negative integer specifies it expects the microservice in Zone 0.

## Output
If no valid global configuration exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ separated by spaces. Print $s_i = 1$ if microservice $i$ is deployed to Zone 1, and $s_i = 0$ if it is deployed to Zone 0, forming any valid configuration.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid configurations may exist; any one is accepted. The same microservice ID may appear in multiple overrides.
</STATEMENT>
<RATIONALE>
Changed the presentation of the binary choices from explicit "at least one of two states" clauses into mutual dependency implications ("if the deployment lacks the first endpoint, it must include the second"). Translated the bare inequalities into narrative system limits (e.g., catalog size capacity, batch size). This forces the model to construct the implication graph from the logical rules rather than relying on surface-level 2-SAT literal pattern matching.
</RATIONALE>
<PRESERVED_ANSWER>
The logical condition "if not A then B, and if not B then A" is strictly equivalent to the boolean OR of A and B, meaning the set of valid configurations for any input is exactly the same as in the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 2-SAT, solvable in linear time using strongly connected components on the implication graph.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the implication as exclusive OR (meaning exactly one endpoint must be present), though the phrasing "if the deployment lacks the first... it must include the second" strictly defines inclusive OR.
</RISK>
