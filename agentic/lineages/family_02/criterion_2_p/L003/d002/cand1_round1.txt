<STATEMENT>
# Phase 3: Deployment Planner

Time limit: 1 s   Memory limit: 256 MB

## Description
You are configuring a network of $n$ microservices. Each microservice must be assigned to exactly one of two routing paths: Route 1 or Route 0.

The system is governed by $m$ compatibility rules. Each rule is defined by two non-zero integers, which specify a pair of routing assignments that are mutually incompatible.

For any non-zero integer $v$, define its *restricted assignment* as follows: it occurs if microservice $|v|$ is assigned to Route 0 when $v$ is positive, or assigned to Route 1 when $v$ is negative. 

Each rule consists of two integers $l_1$ and $l_2$. The rule dictates that the restricted assignment for $l_1$ and the restricted assignment for $l_2$ must not occur simultaneously. In other words, a valid global configuration must ensure that for each of the $m$ rules, it does not simultaneously trigger the restricted assignment of $l_1$ and the restricted assignment of $l_2$.

Your task is to determine if there exists a global configuration—assigning every microservice to either Route 1 or Route 0—that respects all $m$ compatibility rules.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 10^5$, $0 \le m \le 2 \cdot 10^5$), representing the number of microservices and the number of compatibility rules.

Each of the following $m$ lines provides a rule as two non-zero integers $l_1$ and $l_2$ ($|l_i| \le n$). The absolute value $|l_i|$ identifies the microservice. The sign of $l_i$ defines its restricted assignment: if $l_i$ is positive, its restricted assignment is Route 0; if $l_i$ is negative, its restricted assignment is Route 1.

## Output
If no valid global configuration exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ separated by spaces. Print $s_i = 1$ if microservice $i$ is assigned to Route 1, and $s_i = 0$ if it is assigned to Route 0. Any valid configuration is accepted.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid configurations may exist; any one is accepted. The same microservice ID may appear in multiple rules, and even within the same rule.
</STATEMENT>
<RATIONALE>
The previous wording used the standard DIMACS literal formulation ("at least one of its two linked targets"). To break this pattern match, the rule logic was rewritten using De Morgan's laws. Instead of requiring $l_1 \lor l_2$, the problem now defines a "restricted assignment" equivalent to $\neg l_i$, and forbids the simultaneous occurrence of both restricted assignments ($\neg (\neg l_1 \land \neg l_2)$). This forces models to genuinely reason about the logical implications rather than blindly translating input pairs into 2-SAT clauses.
</RATIONALE>
<PRESERVED_ANSWER>
The logical constraint forbidding the simultaneous occurrence of the inverted assignments ($\neg (\neg l_1 \land \neg l_2)$) is mathematically identical to requiring at least one of the original targets ($l_1 \lor l_2$), so all valid configurations remain exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 2-SAT, solvable in $O(n+m)$ time by building an implication graph from the incompatibility constraints and finding strongly connected components.
</PRESERVED_CLASS>
