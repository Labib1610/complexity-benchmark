<STATEMENT>
# Phase 3: Deployment Planner

Time limit: 1 s   Memory limit: 256 MB

## Description

You are configuring a network of $n$ microservices. Each microservice must be assigned to exactly one of two routing paths: Route 1 or Route 0.

The system is governed by $m$ compatibility rules. Each rule links two potential routing targets to ensure network stability. A target is represented by a non-zero integer. The absolute value of the integer identifies the microservice. A positive integer designates Route 1 as the target for that service, while a negative integer designates Route 0. 

To maintain stability, each rule specifies a fallback mechanism between its two targets: if the final global configuration fails to implement the first target, the system is strictly required to implement the second target. Because the rules are symmetric, failing to implement the second target similarly requires the first target to be implemented. Your task is to determine if there exists a global configuration—assigning every microservice to either Route 1 or Route 0—that properly supports all $m$ fallback mechanisms.

## Input
The first line contains two integers $n$ and $m$. The number of microservices $n$ is at least one and will not exceed the fifth power of ten. The number of rules $m$ is non-negative and is bounded by twice the maximum possible limit for $n$.

Each of the following $m$ lines provides a rule as two non-zero integers $l_1$ and $l_2$ (whose absolute values are between $1$ and $n$, inclusive). The absolute value $|l_i|$ identifies the microservice. A positive $l_i$ designates Route 1 as the target for microservice $|l_i|$; a negative $l_i$ designates Route 0 as the target for microservice $|l_i|$.

## Output
If no valid global configuration exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ separated by spaces. Print $s_i = 1$ if microservice $i$ is assigned to Route 1, and $s_i = 0$ if it is assigned to Route 0. Any valid configuration is accepted.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid configurations may exist; any one is accepted. The same microservice ID may appear in multiple rules, and even within the same rule.
</STATEMENT>
<RATIONALE>
Changed the description of rule satisfaction from "at least one of its two linked targets" to a symmetric fallback condition ("if it fails to implement the first, it is strictly required to implement the second"). This removes the explicit OR-clause framing that models blindly map to DIMACS 2-SAT, forcing them to derive the logical equivalence or build the implication graph directly from the operational constraints. Also applied S07 by describing bounds using text like "fifth power of ten" and "twice the maximum possible limit for n".
</RATIONALE>
<PRESERVED_ANSWER>
The condition "if not A then B" and its symmetric counterpart "if not B then A" are logically identical to "A OR B", meaning any configuration valid in the seed is valid here.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 2-SAT, solvable in O(n+m) time by constructing an implication graph and finding strongly connected components.
</PRESERVED_CLASS>
