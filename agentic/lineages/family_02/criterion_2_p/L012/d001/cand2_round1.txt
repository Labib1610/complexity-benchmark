# Problem B — Paired Window Constraints

Time limit: 1 s   Memory limit: 256 MB

## Description

The system configuration pipeline operates in three stages. First, a parser transforms complex user requirements into a standardized intermediate format concerning **n** binary switches, each to be set ON or OFF before the run. This format consists of **m** acceptance rules. Every rule specifies exactly two acceptable switch states (each state being a specific switch and its required ON/OFF position). For the system to pass verification, every rule must have at least one of its two specified states actively matching the global configuration.

In the second stage—which your program must implement—you evaluate this intermediate format. Decide whether a single global ON/OFF setting of all n switches satisfies every rule simultaneously. If such a configuration exists, report one; otherwise, report that the rules are mutually contradictory.

Finally, in the third stage, a downstream controller will read your output and physically actuate the switches.

## Input
The first line contains two integers n and m (1 ≤ n ≤ 10^5, 0 ≤ m ≤ 2·10^5).
Each of the next m lines contains two non-zero signed integers l1 l2, with |li| ≤ n. A positive integer *i* indicates that switch *i* is expected to be ON, while a negative integer *-i* indicates that switch *i* is expected to be OFF. For each line, at least one of the two stated conditions must be met.

## Output
If no valid assignment exists, print a single line NO.
Otherwise print YES on the first line. On the second line print n integers s1 s2 … sn (each in {0, 1}) forming any valid assignment, where 1 denotes ON and 0 denotes OFF.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid assignments may exist; any one is accepted. The same switch index may appear in multiple rules.
