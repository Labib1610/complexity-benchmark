**Solution Explanation**

The condition of a rule is a *literal* – a variable together with a required
value (ON = 1, OFF = 0).  
A rule contains two literals `a , b` and is satisfied iff at least one of them
holds, i.e. the clause  

```
a  OR  b
```

All rules have to hold simultaneously → we have a **2‑SAT** instance.
`n ≤ 10^5 , m ≤ 2·10^5`, therefore a linear‑time algorithm is required.

--------------------------------------------------------------------

#### 1.   Implication graph

For every variable `x (1 … n)` we create two vertices  

* `x`   – meaning “x = 1” (true)  
* `¬x` – meaning “x = 0” (false)

Numbering  

```
idx(x = true)  = x-1                (0 … n-1)
idx(x = false) = x-1 + n            (n … 2n-1)
```

Negation:

```
neg(v) = v + n   if v < n
neg(v) = v - n   otherwise
```

A clause `(a ∨ b)` is equivalent to the two implications  

```
¬a → b
¬b → a
```

We add both directed edges to the graph.  
The graph has `2·n` vertices and `2·m` edges – linear size.

--------------------------------------------------------------------

#### 2.   Strongly connected components (SCC)

If a variable and its negation belong to the same SCC, the instance is
unsatisfiable (they imply each other, so both must be true and false).

Otherwise the SCCs form a DAG.  
A classic way to obtain a satisfying assignment is:

*process SCCs in reverse topological order*  
(the order produced by Kosaraju’s second pass).  
Give a variable the value **true** iff its SCC appears **after** the SCC of its
negation.

Implementation: Kosaraju (two DFS passes, iterative to avoid recursion depth).

--------------------------------------------------------------------

#### 3.   Algorithm
```
read n, m
build adjacency lists G (forward) and GR (reversed)
for each clause (l1, l2):
        a = literal_to_index(l1)
        b = literal_to_index(l2)
        add edge  neg(a) → b   to G,   b → neg(a) to GR
        add edge  neg(b) → a   to G,   a → neg(b) to GR

first pass: iterative DFS on G, store vertices by finishing time
second pass: process vertices in reverse finishing order on GR,
            assign component id comp[v]

for each variable i:
        if comp[i] == comp[i+n]:  print "NO" and exit

assignment[i] = 1 if comp[i] > comp[i+n] else 0   (true after false)

print "YES" and the assignment
```

All steps are `O(n + m)` time and memory.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints “YES” and a correct assignment iff such an
assignment exists.

---

##### Lemma 1  
For every clause `(a ∨ b)` the added edges `¬a → b` and `¬b → a` are logically
equivalent to the clause.

**Proof.**  
If `a` is true, the clause holds, and the implication `¬b → a` is satisfied
because the consequent `a` is true.  
If `a` is false, then `¬a` is true, so the edge forces `b` to be true.
Thus at least one literal is true. The converse direction is identical. ∎



##### Lemma 2  
If a variable `x` and its negation `¬x` belong to the same SCC, the formula is
unsatisfiable.

**Proof.**  
Inside an SCC each vertex reaches every other, therefore `x → ¬x` and
`¬x → x`. Any assignment that makes `x` true forces `¬x` true, contradiction.
Similarly for `x` false. Hence no assignment satisfies all implications,
and by Lemma&nbsp;1 no assignment satisfies the original formula. ∎



##### Lemma 3  
Assume no variable shares an SCC with its negation.
Let `order(v)` be the component number assigned by the second Kosaraju pass
(the order in which components are discovered).  
Setting a variable `x` to true iff `order(x) > order(¬x)` satisfies all
implications.

**Proof.**  
Consider any implication `p → q`. If `order(p) < order(q)`, then `p` is placed
in a component that is processed **earlier** (i.e. lower order) than `q`.  
Two cases:

* `p` is assigned false. Then the implication is vacuously true.
* `p` is true. Then `order(p) > order(¬p)`. Because `p → q`, there is a path
  from `p` to `q`, therefore `order(p) ≥ order(q)`. The only possibility with
  `order(p) > order(¬p)` is `order(q) > order(¬q)`, i.e. `q` is also true.

Thus every implication holds, and by Lemma&nbsp;1 every original clause holds. ∎



##### Lemma 4  
The assignment produced by the algorithm satisfies all clauses.

**Proof.**  
The algorithm uses exactly the rule of Lemma&nbsp;3, therefore all
implications (and consequently all clauses) are satisfied. ∎



##### Lemma 5  
If the algorithm outputs “NO”, the formula is unsatisfiable.

**Proof.**  
“NO” is printed only when some variable `x` and `¬x` lie in the same SCC.
By Lemma&nbsp;2 the formula cannot be satisfied. ∎



##### Lemma 6  
If the formula is satisfiable, the algorithm outputs “YES”.

**Proof.**  
A satisfiable 2‑SAT instance has a model, which implies that no variable can be
mutually reachable with its negation (otherwise Lemma&nbsp;2 would contradict
satisfiability). Hence the SCC test passes and the algorithm proceeds to
output “YES”. ∎



##### Theorem  
The algorithm prints “YES” and a valid assignment exactly when such an
assignment exists; otherwise it prints “NO”.

**Proof.**  
*If* the algorithm prints “YES”, by Lemma&nbsp;4 the printed assignment is
valid.  
*If* it prints “NO”, by Lemma&nbsp;5 the instance is unsatisfiable.  
Conversely, if the instance is satisfiable, Lemma&nbsp;6 guarantees the
algorithm does not reject and therefore prints “YES”. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Building the graph*: `O(m)` edges, `O(n + m)` memory.  
*First DFS pass*: each vertex/edge visited once → `O(n + m)`.  
*Second pass*: same → `O(n + m)`.  
*Final check & assignment*: `O(n)`.

Total time `O(n + m)` ≤ `3·10^5`, well inside the limits.  
Memory: adjacency lists store `2·m` integers plus arrays of size `2·n` →  
`O(n + m)` ≤ about 3·10^5 integers → < 10 MB.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    N = 2 * n
    G = [[] for _ in range(N)]
    GR = [[] for _ in range(N)]

    def lit_index(l: int) -> int:
        v = abs(l) - 1
        return v if l > 0 else v + n

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        ia = lit_index(a)
        ib = lit_index(b)
        na = ia + n if ia < n else ia - n
        nb = ib + n if ib < n else ib - n
        # ¬a -> b
        G[na].append(ib)
        GR[ib].append(na)
        # ¬b -> a
        G[nb].append(ia)
        GR[ia].append(nb)

    sys.setrecursionlimit(1 << 25)

    visited = [False] * N
    order = []

    # iterative DFS for first pass
    for v in range(N):
        if not visited[v]:
            stack = [(v, 0)]
            while stack:
                node, state = stack.pop()
                if state == 0:
                    if visited[node]:
                        continue
                    visited[node] = True
                    stack.append((node, 1))
                    for to in G[node]:
                        if not visited[to]:
                            stack.append((to, 0))
                else:
                    order.append(node)

    comp = [-1] * N
    cid = 0
    # second pass
    for v in reversed(order):
        if comp[v] == -1:
            stack = [v]
            comp[v] = cid
            while stack:
                node = stack.pop()
                for to in GR[node]:
                    if comp[to] == -1:
                        comp[to] = cid
                        stack.append(to)
            cid += 1

    # check satisfiability
    for i in range(n):
        if comp[i] == comp[i + n]:
            sys.stdout.write("NO")
            return

    # build assignment
    assign = [0] * n
    for i in range(n):
        assign[i] = 1 if comp[i] > comp[i + n] else 0

    out = ["YES", " ".join(map(str, assign))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
