**Solution Explanation**

For every machine `i` we have a Boolean variable  

```
xi = 1   ⇔   machine i is in mode 1
xi = 0   ⇔   machine i is in mode 0
```

A reference condition is a literal

* `+i`  – the literal `xi` (machine i must be 1)
* `-i`  – the literal `¬xi` (machine i must be 0)

For an interlock we are given two literals `a , b`.  
The interlock trips **only** when *both* literals are false, therefore a safe
configuration must satisfy

```
a  OR  b
```

Thus the whole problem is exactly a **2‑SAT** instance with `n` variables and
`m` clauses of the form `(a ∨ b)`.

--------------------------------------------------------------------

#### 1.   Implication graph

For a clause `(a ∨ b)` we add the two implications

```
¬a → b
¬b → a
```

The graph has `2·n` vertices – one for each literal `xi` and `¬xi`.

Vertex numbering (0‑based)

```
id(i, true)  = 2·(i-1)       # literal xi
id(i, false) = 2·(i-1) + 1   # literal ¬xi
```

`neg(v) = v ^ 1` flips the last bit, i.e. gives the opposite literal.

--------------------------------------------------------------------

#### 2.   Strongly Connected Components

A 2‑SAT formula is satisfiable **iff** no variable and its negation belong to the
same SCC of the implication graph.

We compute SCCs with Kosaraju’s algorithm (two DFS passes).  
Complexities: `O(V+E) = O(n+m)` time, `O(V+E)` memory.

--------------------------------------------------------------------

#### 3.   Constructing a solution

Kosaraju returns components in reverse topological order.
If `comp[v] > comp[neg(v)]` we set the variable to **true**, otherwise **false**.
(This works because a component that appears later in the order cannot reach an
earlier one, therefore its literals can be forced to true.)

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs “YES” and a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
For every clause `(a ∨ b)` the added implications are logically equivalent to
the clause.

**Proof.**  
`(a ∨ b)` is false exactly when `a` is false **and** `b` is false, i.e.
when `¬a` holds and `¬b` holds.  
The implications `¬a → b` and `¬b → a` forbid this situation:
if `¬a` were true, `b` must be true; if `¬b` were true, `a` must be true.
Thus the only assignments that satisfy both implications are precisely those
satisfying `(a ∨ b)`. ∎



##### Lemma 2  
If a variable `x` and its negation `¬x` belong to the same SCC, the formula is
unsatisfiable.

**Proof.**  
Inside an SCC every vertex reaches every other vertex.
Hence `x → ¬x` and `¬x → x` are both implied.
If we set `x = 1`, the first implication forces `¬x = 1`, contradiction.
If we set `x = 0`, the second forces `x = 1`, contradiction.
Thus no assignment can satisfy all implications, and by Lemma&nbsp;1 no
assignment can satisfy the original formula. ∎



##### Lemma 3  
If for every variable `x` the literals `x` and `¬x` are in different SCCs,
the assignment defined by  

```
x = 1  iff  comp[x] > comp[¬x]
```

satisfies all implications.

**Proof.**  
Consider any implication `p → q`.  
In the condensation DAG of SCCs there is an edge from `comp[p]` to
`comp[q]`. Topological order guarantees `comp[p] ≤ comp[q]`.  
Two cases:

* `comp[p] = comp[q]` – impossible because then `p` and `q` would be in the
  same SCC, contradicting the premise that `p` and `¬p` are separate (but
  `p` may equal `q` – then the implication is trivial).

* `comp[p] < comp[q]`.  
  By construction, if `comp[p] < comp[q]` then `p` is assigned **false**
  (otherwise `comp[p] > comp[¬p]` would hold, implying `comp[¬p] < comp[p]`,
  impossible because `¬p` reaches `p` via the edge).  
  Hence the premise of the implication (`p` true) never occurs, so the
  implication is satisfied.

Thus every implication holds, and by Lemma&nbsp;1 every original clause holds. ∎



##### Lemma 4  
If the algorithm outputs “YES” and the assignment described above,
the assignment satisfies all interlocks.

**Proof.** Directly from Lemma&nbsp;3 and Lemma&nbsp;1. ∎



##### Lemma 5  
If the algorithm outputs “NO”, the formula is unsatisfiable.

**Proof.** “NO” is printed exactly when some variable and its negation share an
SCC. By Lemma&nbsp;2 the formula cannot be satisfied. ∎



##### Theorem  
The algorithm prints “YES” and a valid configuration of the `n` machines
iff such a configuration exists; otherwise it prints “NO”.

**Proof.**  

*If the algorithm prints “YES”* – by Lemma&nbsp;4 the produced assignment is
valid, therefore a configuration exists.

*If a valid configuration exists* – the corresponding assignment satisfies all
implications, thus no variable can reach its negation, i.e. no variable and its
negation lie in the same SCC. The algorithm therefore will not output “NO”.
Consequently it reaches the assignment step and prints “YES”. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis

*Vertices*: `2n`  
*Edges*: `2m` (two per clause)

```
Time   : O(n + m)
Memory : O(n + m)
```

Both respect the limits (`n ≤ 10^5`, `m ≤ 2·10^5`).

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(1 << 25)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    N = 2 * n
    g = [[] for _ in range(N)]
    rg = [[] for _ in range(N)]

    def var_id(x: int) -> int:
        """return vertex id for literal x (positive -> true, negative -> false)"""
        v = abs(x) - 1
        if x > 0:
            return 2 * v          # xi
        else:
            return 2 * v + 1      # ¬xi

    def add_imp(u: int, v: int) -> None:
        g[u].append(v)
        rg[v].append(u)

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        A = var_id(a)
        B = var_id(b)
        NA = A ^ 1
        NB = B ^ 1
        # ¬A -> B
        add_imp(NA, B)
        # ¬B -> A
        add_imp(NB, A)

    visited = [False] * N
    order = []

    def dfs(v: int):
        stack = [(v, 0)]
        while stack:
            node, state = stack.pop()
            if state == 0:
                if visited[node]:
                    continue
                visited[node] = True
                stack.append((node, 1))
                for to in g[node]:
                    if not visited[to]:
                        stack.append((to, 0))
            else:
                order.append(node)

    for v in range(N):
        if not visited[v]:
            dfs(v)

    comp = [-1] * N
    cur = 0
    def rdfs(v: int, label: int):
        stack = [v]
        while stack:
            node = stack.pop()
            if comp[node] != -1:
                continue
            comp[node] = label
            for to in rg[node]:
                if comp[to] == -1:
                    stack.append(to)

    for v in reversed(order):
        if comp[v] == -1:
            rdfs(v, cur)
            cur += 1

    assignment = [0] * n
    for i in range(n):
        if comp[2*i] == comp[2*i+1]:
            print("NO")
            return
        assignment[i] = 1 if comp[2*i] > comp[2*i+1] else 0

    print("YES")
    print(' '.join(map(str, assignment)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
