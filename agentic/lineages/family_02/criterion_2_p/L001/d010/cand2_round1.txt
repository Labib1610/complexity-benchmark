Conditional Additive Load Capacity
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces independent boolean clauses with an additive resource-routing mechanic. Parameters target 'sinks' and conditionally deposit 'load' based on state matching. Failure occurs when cumulative load reaches 2. This masks the logical NAND structure behind arithmetic sum and flow terminology, tricking the model into perceiving a capacity-constraint problem rather than 2-SAT.
</METHOD_DESCRIPTION>

yes

<STATEMENT>
# Problem B — Logistics Safeguards

Time limit: 1 s   Memory limit: 256 MB

## Description
Management of a logistics network must finalize the operational schedule for its $n$ transit hubs. Every hub $i$ must be assigned a configuration state $s_i \in \{0, 1\}$.

Safety inspectors have completed $m$ vulnerability assessments. Each assessment provides two non-zero integer parameters $l_1$ and $l_2$. 

These assessments act as stress conduits that attempt to route load into the network's two structural sinks: Sink 0 and Sink 1.
- For any parameter $x$, its internal routing targets Sink 0 if $x > 0$, and Sink 1 if $x < 0$.
- The hub $|x|$ acts as a directional valve for this parameter. If hub $|x|$ is assigned configuration state $s_{|x|}$, it opens the pathway to Sink $s_{|x|}$ while closing the pathway to the other sink.

Consequently, a parameter $x$ successfully deposits 1 unit of load into its targeted sink if and only if the valve at hub $|x|$ is configured to match the targeted sink. 

An assessment raises a critical failure if its two parameters collectively deposit a total of 2 units of load into the sinks. 

Your task is to determine whether it is possible to assign a configuration state $s_i \in \{0, 1\}$ to every hub such that zero critical failures occur across all $m$ assessments. If such a schedule can be formed, you must provide one.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 10^5$, $0 \le m \le 2 \cdot 10^5$).

Each of the following $m$ lines provides two non-zero integers $l_1$ and $l_2$ ($1 \le |l_i| \le n$), representing the two parameters of a vulnerability assessment. 

Note that $l_1$ and $l_2$ in an assessment may refer to the same hub, with the same or opposite signs. A hub may appear in any number of assessments, and identical assessments may repeat.

## Output
If no safe schedule is possible, print a single line NO.

Otherwise, print YES on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ (each being 0 or 1, representing the configuration state $s_i$ for hub $i$) that form a valid schedule. Multiple valid schedules may exist; any one is accepted.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The explicit boolean logic ("fails if both fail to be aligned") was replaced with an additive resource-routing mechanic. The model must now deduce that a capacity of 2 across two parameters means both parameters must successfully deposit load, and translate the valve/sink routing rules back into forbidden state combinations, breaking direct pattern matching to 2-SAT.
</RATIONALE>
<PRESERVED_ANSWER>
A parameter deposits load exactly when it is in the forbidden state of the original problem ($s=0$ for $x>0$, $s=1$ for $x<0$), and the total load reaches 2 exactly when both parameters are in their forbidden states, making the failure conditions mathematically identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 2-SAT, as each assessment still defines a forbidden pair of boolean assignments, allowing it to be solved in O(n+m) via an implication graph.
</PRESERVED_CLASS>
<RISK>
The phrase "collectively deposit a total of 2 units" could theoretically be misread as allowing one parameter to deposit 2 units, but the text explicitly states a parameter "successfully deposits 1 unit", making 1+1=2 the only mathematical possibility.
</RISK>
