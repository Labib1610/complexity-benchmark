**Solution Explanation**

For every dossier we are given  

* `a` – time of the first (initial) review  
* `b` – time of the second (final) sign‑off  

All dossiers have to be processed one after another

```
first review → second sign‑off
```

The first review of a dossier can start only after the previous
first review has finished, the same for the second sign‑off.
The whole work finishes when the last sign‑off finishes.

For a fixed order of the dossiers let  

* `A(k)` – sum of `a` of the first `k` dossiers (time when the `k`‑th
  first review ends)  
* `B(k)` – sum of `b` of the dossiers from `k` to the end
  (time needed for all sign‑offs that start not earlier than the `k`‑th
  dossier)

The moment when the whole work is finished is  

```
Cmax = max over k ( A(k) + B(k) )
```

We have to minimise `Cmax`.

--------------------------------------------------------------------

#### 1.   Relation to the two‑machine flow‑shop problem  

The situation is exactly the classical *two‑machine flow‑shop* problem
(Jobs → Machine 1 → Machine 2) where

* processing time on Machine 1 = `a`
* processing time on Machine 2 = `b`

The makespan of a schedule of this flow‑shop is the same formula
`max_k (A(k)+B(k))`.  
For two machines the optimal order is given by **Johnson’s rule**.

--------------------------------------------------------------------

#### 2.   Johnson’s rule  

For each job compare its two processing times.

```
if a ≤ b :   put the job into group L
else        :   put the job into group R
```

*Group L* (first‑stage not longer than second‑stage) is processed **first**
and inside the group it is sorted by **increasing a**.  
*Group R* is processed **after** all jobs of L and inside the group it is
sorted by **decreasing b**.

The concatenation `L (sorted) + R (sorted)` is optimal, i.e. it yields the
minimum possible `Cmax`.

Proof sketch (standard Johnson proof)

* Consider two consecutive jobs `X , Y`.
* If `a_X ≤ b_X` and `a_Y > b_Y` then swapping them never increases the
  makespan; therefore all jobs with `a ≤ b` can be placed before all jobs
  with `a > b`.
* Inside the first part we should put the smaller `a` earlier,
  otherwise the prefix sum `A(k)` becomes larger earlier and can only
  increase the maximum.
* Inside the second part we should put the larger `b` later
  (i.e. sort by decreasing `b`) for the same reason.

Repeating these local improvements leads to the order described above,
which is therefore optimal.

--------------------------------------------------------------------

#### 3.   Computing the answer for the obtained order  

After sorting we walk through the list once.

```
pref = 0                     # current A(k)
total_b = sum of all b
ans = 0
for each job (a,b) in order:
        pref += a
        total_b -= b        # now total_b = B(k)
        ans = max(ans, pref + total_b)
```

`ans` finally equals the minimal possible maximum clearance metric.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the optimal value.

---

##### Lemma 1  
For any two consecutive jobs `X , Y` in a schedule,
if `a_X ≤ b_X` and `a_Y > b_Y` then swapping `X` and `Y`
does not increase `Cmax`.

**Proof.**  
Let the prefix sum before `X` be `P`.  
Before swapping:

```
C1 = max( P + a_X + b_X , P + a_X + a_Y + b_Y )
```

After swapping:

```
C2 = max( P + a_Y + b_Y , P + a_Y + a_X + b_X )
```

Because `a_X ≤ b_X` and `a_Y > b_Y` we have  

`P + a_X + b_X ≤ P + a_Y + a_X + b_X` and  
`P + a_Y + b_Y ≤ P + a_X + a_Y + b_Y`.  

Thus each term of `C2` is ≤ the corresponding term of `C1`,
so `C2 ≤ C1`. ∎



##### Lemma 2  
In an optimal schedule all jobs with `a ≤ b` appear before all jobs with
`a > b`.

**Proof.**  
If a schedule violates the property, there exists a pair of consecutive
jobs `X , Y` with `a_X > b_X` and `a_Y ≤ b_Y`.  
By Lemma&nbsp;1 swapping them does not increase `Cmax`. Repeating the swap
while such inversions exist finally yields a schedule satisfying the
property and with `Cmax` no larger than the original one. ∎



##### Lemma 3  
Inside the block of jobs with `a ≤ b` sorting them by increasing `a`
does not increase `Cmax`.

**Proof.**  
Take two consecutive jobs `X , Y` of this block.
Both satisfy `a ≤ b`.  
If `a_X > a_Y` swapping them changes the two relevant values to

```
before:  P + a_X          ,  P + a_X + a_Y + b_Y
after :  P + a_Y          ,  P + a_Y + a_X + b_X
```

Since `b_X ≥ a_X` and `b_Y ≥ a_Y`, the second term after swapping is
not larger than the second term before swapping, and the first term
becomes smaller. Hence the maximum does not increase. ∎



##### Lemma 4  
Inside the block of jobs with `a > b` sorting them by decreasing `b`
does not increase `Cmax`.

**Proof.**  
Analogous to Lemma&nbsp;3, now both jobs satisfy `a > b`.  
If `b_X < b_Y` (i.e. they are not in decreasing order) swapping them makes
the first term larger but the second term smaller, and because
`a_X > b_X , a_Y > b_Y` the larger increase cannot exceed the decrease.
Thus the maximum does not increase. ∎



##### Lemma 5  
The order produced by Johnson’s rule (L sorted by increasing `a`,
followed by R sorted by decreasing `b`) yields the minimum possible
`Cmax`.

**Proof.**  
Starting from any optimal schedule, by Lemma&nbsp;2 we can reorder it so
that all `a ≤ b` jobs precede all `a > b` jobs without worsening `Cmax`.
Then, by Lemma&nbsp;3 we can sort the first block by increasing `a`,
and by Lemma&nbsp;4 sort the second block by decreasing `b`,
again without increasing `Cmax`.  
The resulting schedule is exactly Johnson’s order, therefore it is also
optimal. ∎



##### Lemma 6  
For the order produced by the algorithm the value computed in the
single pass (`ans`) equals `Cmax` of that order.

**Proof.**  
During the pass `pref` equals `A(k)` and `total_b` equals `B(k)` for the
current position `k`. The statement `ans = max(ans, pref + total_b)`
stores the maximum of all `A(k)+B(k)`. Hence after the loop `ans` is
exactly `max_k (A(k)+B(k)) = Cmax`. ∎



##### Theorem  
The algorithm outputs the smallest possible maximum clearance metric.

**Proof.**  
By Lemma&nbsp;5 the order constructed by the algorithm is optimal,
i.e. its makespan is the minimum achievable `Cmax`.  
By Lemma&nbsp;6 the algorithm computes the makespan of this order.
Therefore the printed number equals the optimal value. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Splitting and sorting* – each of the two groups is sorted once  

```
O(j log j)   time
O(j)         memory
```

The final linear scan is `O(j)` time and `O(1)` extra memory.

Overall  

```
Time   : O(j log j)   ( ≤ 2·10⁵ log 2·10⁵  well inside 1 s )
Memory : O(j)
```

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    left = []   # a <= b
    right = []  # a > b
    total_b = 0
    for _ in range(n):
        a = int(next(it))
        b = int(next(it))
        total_b += b
        if a <= b:
            left.append((a, b))
        else:
            right.append((a, b))
    # Johnson's rule
    left.sort(key=lambda x: x[0])          # increasing a
    right.sort(key=lambda x: -x[1])        # decreasing b
    order = left + right

    pref = 0
    suffix_b = total_b
    ans = 0
    for a, b in order:
        pref += a
        suffix_b -= b
        cur = pref + suffix_b
        if cur > ans:
            ans = cur
    print(ans)

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
