**Solution Explanation**

For every order we have two operations

* mixing – time `p1` on machine **M1**
* frosting – time `p2` on machine **M2**

Both machines work one order at a time, the second machine always takes the order
that has been waiting the longest (FIFO on the buffer).  
The problem is the classical *two‑machine flow shop* with unlimited buffer.
The optimal order of the jobs is given by **Johnson’s rule**.

--------------------------------------------------------------------

#### Johnson’s rule  

For each job compare its two processing times.

* If `p1 ≤ p2` the job should be placed **as early as possible**.
  Among those jobs we sort by increasing `p1`.
* If `p1 > p2` the job should be placed **as late as possible**.
  Among those jobs we sort by decreasing `p2`.

The concatenation of the two sorted groups yields an optimal schedule,
i.e. the smallest possible finishing time of the last job.

*Proof sketch* (standard, omitted for brevity)  
Consider any two consecutive jobs `A , B`.  
If `min(p1A, p2B) ≤ min(p1B, p2A)` swapping them never increases the makespan.
Repeatedly applying this exchange argument leads exactly to the order described
above, therefore it is optimal. ∎



--------------------------------------------------------------------

#### Computing the makespan of a given order  

```
t1 = 0          # finishing time of the mixer
t2 = 0          # finishing time of the froster
for each job (p1, p2) in the order:
        t1 += p1                 # mixer finishes this job
        t2 = max(t2, t1) + p2    # froster can start only after both are ready
answer = t2
```

Both times are monotone, the loop is `O(j)`.

--------------------------------------------------------------------

#### Algorithm
```
read all jobs
group1 = jobs with p1 <= p2
group2 = jobs with p1 >  p2
sort group1 by p1 ascending
sort group2 by p2 descending
order = group1 + group2
simulate the two machines as described, obtain makespan
output makespan
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the minimal possible completion time.

---

**Lemma 1**  
For any two jobs `A, B` the schedule `A,B` is not worse than `B,A`
iff `min(p1A, p2B) ≤ min(p1B, p2A)`.

*Proof.*  
Consider the two‑machine flow shop with only these two jobs.
The makespan of `A,B` is `max(p1A + p1B, p1A + p2A, p1A + p1B + p2B)`.
Similarly for `B,A`. Comparing the two expressions yields exactly the stated
inequality. ∎



**Lemma 2** (Johnson)  
Starting from any permutation, repeatedly swapping adjacent jobs that violate
`min(p1A, p2B) ≤ min(p1B, p2A)` strictly reduces (or keeps) the makespan and
terminates at the order produced by the algorithm.

*Proof.*  
A violating pair satisfies `min(p1A, p2B) > min(p1B, p2A)`. By Lemma&nbsp;1 swapping
them does not increase the makespan. The swap moves a job with larger `p1`
to the right or a job with larger `p2` to the left, therefore the process
converges. The final permutation has no violating adjacent pair, which is
exactly the condition “all jobs with `p1 ≤ p2` are before all jobs with
`p1 > p2`, sorted as described”. ∎



**Lemma 3**  
The order constructed by the algorithm contains no violating adjacent pair.

*Proof.*  
* In the first block (`p1 ≤ p2`) jobs are sorted by increasing `p1`.  
  For any two consecutive jobs `A,B` we have `p1A ≤ p1B`. Because both satisfy
  `p1 ≤ p2`, `min(p1A, p2B) = p1A ≤ p1B = min(p1B, p2A)`. No violation.
* In the second block (`p1 > p2`) jobs are sorted by decreasing `p2`.  
  Analogously `p2A ≥ p2B` gives `min(p1A, p2B)=p2B ≤ p2A = min(p1B, p2A)`.
* The boundary between the blocks has `p1 ≤ p2` on the left and `p1 > p2` on
  the right, therefore `min(p1_left, p2_right)=p1_left ≤ p2_left = min(p1_right,
  p2_left)`. No violation. ∎



**Lemma 4**  
The makespan of the schedule produced by the algorithm is minimal.

*Proof.*  
Take an optimal schedule `OPT`. By repeatedly applying the swaps from
Lemma&nbsp;2 we can transform `OPT` into the algorithm’s order without increasing
the makespan. Hence the algorithm’s makespan is ≤ optimal makespan, i.e. it is
optimal. ∎



**Theorem**  
The program outputs the smallest possible time at which all orders are
completed.

*Proof.*  
The program builds exactly the order described in Lemma&nbsp;3 (Johnson’s rule)
and computes its makespan by the simulation, which is correct for any fixed
order. By Lemma&nbsp;4 this makespan is minimal among all possible orders.
Therefore the printed value is the required answer. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Sorting*: `O(j log j)`  
*Simulation*: `O(j)`  

Memory consumption: storing all jobs – `O(j)`.

Both limits satisfy the constraints (`j ≤ 200 000`).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    early = []   # p1 <= p2
    late = []    # p1 >  p2
    for _ in range(n):
        p1 = int(next(it)); p2 = int(next(it))
        if p1 <= p2:
            early.append((p1, p2))
        else:
            late.append((p1, p2))
    early.sort(key=lambda x: x[0])          # increasing p1
    late.sort(key=lambda x: -x[1])          # decreasing p2
    order = early + late

    t1 = 0  # mixer finish time
    t2 = 0  # froster finish time
    for p1, p2 in order:
        t1 += p1
        if t2 < t1:
            t2 = t1
        t2 += p2
    sys.stdout.write(str(t2))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
