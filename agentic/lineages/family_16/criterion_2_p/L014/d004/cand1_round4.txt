<STATEMENT>
# Problem B — Packet Sequence Evaluation

Time limit: 1 s
Memory limit: 256 MB

## Description

A network router must process and transmit **j** data packets. 

To determine the total processing time for any given transmission sequence, the router's simulation software maintains two timers: $T_{A}$ and $T_{B}$, both initially set to 0.

You must choose a single permutation of all **j** packets. For each packet in your chosen sequence, using its given primary duration **p1** and secondary duration **p2**, the software updates the timers in the following exact order:
1. $T_{A}$ is increased by **p1**.
2. $T_{B}$ is updated to be the maximum of its current value and $T_{A}$.
3. $T_{B}$ is increased by **p2**.

Your objective is to find a permutation of the **j** packets that minimizes the final value of $T_{B}$ after all packets in the sequence have been processed. Report this minimum possible final value.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the primary duration and the secondary duration of a packet.

## Output

Print a single integer: the smallest possible final value of $T_{B}$ among all permutations.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one packet with primary duration 5 and secondary duration 3.
Initially, $T_A = 0$ and $T_B = 0$.
Processing the only packet:
1. $T_A$ increases by 5, so $T_A = 5$.
2. $T_B$ is updated to $\max(0, 5) = 5$.
3. $T_B$ increases by 3, so $T_B = 8$.
The final value of $T_B$ is 8.
</STATEMENT>
<RATIONALE>
The previous version failed because framing the problem as finding a path through a grid introduced false semantic choices (a "path-choice" story) that independent solvers misinterpreted. To fix this while still defeating pattern-matching models, I restored the exact deterministic sequence evaluation from the seed. However, instead of describing it through the physical analogy of "segments processing one packet at a time," I presented the mathematically identical recurrence relation as a deterministic procedural update of two trackers. This removes the "two-machine flow-shop" keywords (uplink, downlink, segments, waiting) while perfectly preserving the mathematical task.
</RATIONALE>
<PRESERVED_ANSWER>
The procedural updates exactly mirror the $T_{up}$ and $T_{down}$ recurrence formulas from the original problem, ensuring the final value of $T_B$ is identical to the original makespan for any permutation.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the 2-machine flow-shop scheduling problem, which is optimally solvable in O(j log j) using Johnson's rule.
</PRESERVED_CLASS>
