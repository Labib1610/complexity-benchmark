<STATEMENT>
# Problem B — Two-Tier Level Design

Time limit: 1 s   Memory limit: 256 MB

## Description

You are designing a two-tier level consisting of **j** segments. Each segment has two values: a top-tier score **p1** and a bottom-tier score **p2**.

You must arrange all **j** segments in a sequence from left to right to form a grid with 2 rows and **j** columns. The top row is formed by the top-tier scores, and the bottom row is formed by the bottom-tier scores.

Once you choose the order of the segments, consider all valid paths from the top-left cell (row 1, column 1) to the bottom-right cell (row 2, column **j**). A valid path can only move right (to the next column in the same row) or down (from row 1 to row 2 in the same column). Because there are only two rows, any valid path moves right along row 1 up to some column **k** (1 ≤ **k** ≤ **j**), moves down to row 2 at column **k**, and then moves right along row 2 until column **j**. 

The "cost" of a path is the sum of the values of all cells it visits. Notice that the path will include both the top-tier and bottom-tier values of the segment at the column **k** where it moves down.

The "score" of your chosen arrangement is the maximum cost among all valid paths through it.

Your goal is to choose an arrangement (a permutation of the **j** segments) that minimizes this score. What is the minimum possible score?

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the top-tier and bottom-tier values of a segment, respectively.

## Output

Print a single integer: the minimum possible score (the minimized maximum path cost) achievable by optimally ordering the segments.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one segment. The only valid path visits the top-tier cell (value 5) and then the bottom-tier cell (value 3). The cost is 5 + 3 = 8.

In Example 1, one optimal arrangement of the segments (identified by their original input order) is segment 3, then segment 2, then segment 1. 
The grid values from left to right are:
Row 1: 1, 2, 3
Row 2: 3, 4, 2
The possible paths are:
- Move down at column 1: cost = 1 (top) + 3 (bottom) + 4 (bottom) + 2 (bottom) = 10.
- Move down at column 2: cost = 1 (top) + 2 (top) + 4 (bottom) + 2 (bottom) = 9.
- Move down at column 3: cost = 1 (top) + 2 (top) + 3 (top) + 2 (bottom) = 8.
The maximum path cost for this arrangement is 10. No other arrangement yields a lower maximum path cost.

<RATIONALE>
Transformed the scheduling mechanics into an exact mathematical equivalent: finding a permutation of columns in a 2xN grid to minimize the maximum path sum from top-left to bottom-right. This forces models to independently recognize the structural equivalence to the two-machine flow-shop problem rather than pattern-matching on scheduling keywords.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum path sum in the 2xN grid for a given permutation is mathematically identical to the makespan of that permutation in a two-machine flow-shop, so the minimum possible value remains exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains solvable in O(j log j) time using Johnson's rule, as the underlying optimization objective (min-max of prefix/suffix sums) is completely unchanged.
</PRESERVED_CLASS>
<RISK>
Models might attempt to solve it using generic dynamic programming or path-finding algorithms which will result in Time Limit Exceeded due to the large bounds.
</RISK>
