<STATEMENT>
# Problem B — Data Buffer Optimization

Time limit: 1 s   Memory limit: 256 MB

## Description

You are optimizing the memory utilization of a data processing pipeline that must process exactly $j$ data blocks. Each block must be processed exactly once, and you must choose the sequence in which they are processed.

Each block $k$ is characterized by two values:
- $p_1$: the number of bytes written to the buffer when the block is loaded.
- $p_2$: the number of bytes removed from the buffer after the block is compressed.

The pipeline operates on a single continuous buffer. To ensure all compression dictionaries are available, the buffer is initialized with a pre-loaded dictionary block. The size of this initial data is exactly equal to the sum of the $p_2$ values of all $j$ blocks.

Let $V$ be the current number of bytes in the buffer. Initially, $V = \sum_{k=1}^j p_2$.
When the $i$-th block in your chosen sequence is processed:
1. First, its uncompressed data is loaded. The buffer size increases by its $p_1$ value. The system records the buffer's size at this moment as the "peak usage" for this step, denoted $P_i = V + p_1$.
2. Then, the block is compressed. The buffer size decreases by its $p_2$ value. The new buffer size becomes $V = V + p_1 - p_2$.

This process repeats sequentially for all $j$ blocks in the order you selected. 

Your objective is to find an ordering of the $j$ blocks that minimizes the maximum peak usage recorded across all $j$ processing steps (i.e., minimize $\max(P_1, P_2, \dots, P_j)$).

What is the minimum possible value of this maximum peak usage?

## Input

The first line contains a single integer $j$ ($1 \le j \le 200000$).
Each of the following $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$), representing the load size and compression reduction for each block, respectively.

## Output

Print a single integer: the minimum possible maximum peak usage.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, the sum of all $p_2$ values is $2 + 4 + 3 = 9$. The buffer starts at $V = 9$.
One optimal sequence is to process the 3rd input block, then the 2nd input block, then the 1st input block.
- For the first block in sequence (input block 3): $p_1 = 1$, $p_2 = 3$. 
  Peak usage $P_1 = 9 + 1 = 10$. 
  New buffer size $V = 9 + 1 - 3 = 7$.
- For the second block in sequence (input block 2): $p_1 = 2$, $p_2 = 4$. 
  Peak usage $P_2 = 7 + 2 = 9$. 
  New buffer size $V = 7 + 2 - 4 = 5$.
- For the third block in sequence (input block 1): $p_1 = 3$, $p_2 = 2$. 
  Peak usage $P_3 = 5 + 3 = 8$. 
  New buffer size $V = 5 + 3 - 2 = 6$.

The maximum peak usage across all steps is $\max(10, 9, 8) = 10$. This is the minimum possible maximum peak usage across all valid sequences.

<RATIONALE>
The models were succeeding by recognizing the explicit two-stage, same-sequence structure and immediately applying Johnson's rule. I used an algebraic identity to transform the two-machine makespan objective into a mathematically equivalent single-machine peak tracking problem. By factoring out the sum of the second stage times as a constant initial value, the problem now appears to be a standard greedy resource scheduling problem, forcing models to either derive the correct strict weak ordering comparator from scratch (which frequently fails in Python) or fail to recognize the underlying structure entirely.
</RATIONALE>
<PRESERVED_ANSWER>
The makespan of a 2-machine flow shop is exactly equal to the sum of all second-stage times plus the maximum over all steps of the accumulated difference between first-stage and second-stage times, which is exactly the peak formula calculated by this new process.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
Because the mathematical objective is algebraically identical to the original makespan objective, the exact same optimal permutations apply, meaning it remains optimally solvable in O(j log j) using Johnson's rule.
</PRESERVED_CLASS>
