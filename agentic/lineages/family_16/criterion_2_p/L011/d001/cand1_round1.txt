# Problem B — Protocol Synchronization

Time limit: 1 s   Memory limit: 256 MB

## Description

A synchronization protocol requires allocating two uninterrupted time intervals for each of **j** distinct requests. For each request, you must assign an activation interval of duration **p1** and a resolution interval of duration **p2**.

The allocation of these intervals on the timeline (starting from time 0) must satisfy the following strict conditions:

- **Mutual Exclusion**: No two activation intervals may overlap in time. Similarly, no two resolution intervals may overlap.
- **Causality**: For every request, its resolution interval cannot begin until its activation interval has completely finished.
- **Order Preservation**: The requests must be resolved in the same sequence they are activated. If the activation interval for request A is scheduled before the activation interval for request B, then the resolution interval for request A must also be scheduled before the resolution interval for request B.

Because the activation and resolution of different requests can overlap in time, the total time depends heavily on how the intervals are packed. Determine the absolute minimum time required for the final resolution interval to conclude, assuming an optimal sequence is chosen.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the required duration for the activation interval and the resolution interval of the request, respectively.

## Output

Print a single integer: the minimum possible time at which all resolution intervals are completely finished.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, the single request's activation interval occupies 5 time units, and its resolution interval occupies 3 time units. The resolution finishes at time 8.

<RATIONALE>
I replaced the explicit "two-stage primary/secondary processors" framing with an abstract interval-scheduling scenario ("Protocol Synchronization"). By defining the mechanics through logical constraints (mutual exclusion, causality, order preservation) rather than a recognizable factory metaphor, models can no longer rely on surface pattern matching to immediately identify a "two-machine permutation flow shop", forcing them to deduce the structural equivalence from the constraints themselves.
</RATIONALE>
<PRESERVED_ANSWER>
The problem still requires finding the minimum makespan for two sequential tasks with a shared order, so the optimal schedule length remains exactly the same for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The mathematical constraints directly encode a two-machine permutation flow shop, meaning it is still optimally solvable in O(j log j) time using Johnson's algorithm.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "overlap in time" in the description as allowing a single request's activation and resolution to overlap, but the "Causality" rule explicitly forbids this, making the constraints unambiguous.
</RISK>
