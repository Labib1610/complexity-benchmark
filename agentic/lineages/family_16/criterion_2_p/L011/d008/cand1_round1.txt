# Problem B — Grid Path Game

Time limit: 1 s   Memory limit: 256 MB

## Description

You are given **j** rectangular tiles. Each tile has a top integer and a bottom integer.

You must arrange all **j** tiles in a single sequence from left to right. This creates a grid with 2 rows and **j** columns. The top row consists of the top integers of the tiles in your chosen order, and the bottom row consists of the bottom integers.

An adversary will trace a path through this grid starting at the top-left cell (row 1, column 1) and ending at the bottom-right cell (row 2, column **j**). At each step, the adversary can either move one cell to the right (to the same row, next column) or one cell down (to the next row, same column). The adversary cannot move left or up, and cannot leave the grid.

The cost of a path is the sum of the integers in all the cells it visits, including the starting and ending cells. The adversary will evaluate all valid paths and choose one that **maximizes** this cost.

Your objective is to find an ordering of the **j** tiles that **minimizes** the cost of the adversary's chosen path.

What is the minimum possible cost you can force the adversary to accept?

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the top integer and the bottom integer of a tile, respectively.

## Output

Print a single integer: the minimum possible cost of the adversary's path, assuming you arrange the tiles optimally.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, if we order the tiles as the 3rd tile, then the 2nd tile, then the 1st tile from the input, the grid is:
Row 1: 1, 2, 3
Row 2: 3, 4, 2

The adversary can choose from three valid paths:
- Move down at column 1: visits (1,1) → (2,1) → (2,2) → (2,3). Cost = 1 + 3 + 4 + 2 = 10.
- Move down at column 2: visits (1,1) → (1,2) → (2,2) → (2,3). Cost = 1 + 2 + 4 + 2 = 9.
- Move down at column 3: visits (1,1) → (1,2) → (1,3) → (2,3). Cost = 1 + 2 + 3 + 2 = 8.

The adversary maximizes the cost, so the adversary will choose the first path, resulting in a cost of 10. This is the minimum possible maximum cost across all valid tile orderings.

<RATIONALE>
The problem was completely rewritten to frame it as a minimax path-finding game on a 2xN grid rather than a two-stage scheduling process. This removes all scheduling terminology, recurrence relations, and flow-shop framing that models used to pattern-match Johnson's rule, forcing them to independently deduce that the maximum grid path is mathematically identical to the flow shop makespan.
</RATIONALE>
<PRESERVED_ANSWER>
The cost of a path that moves down at column i is exactly the sum of top integers up to i and bottom integers from i onwards, making the maximum path cost identical to the completion time of a 2-machine flow shop, meaning the optimal permutation and minimum cost remain unchanged.
</PRESERVED_ANSWER>

The problem remains exactly equivalent to the two-machine flow shop makespan problem, which is solvable optimally in O(N log N) time using Johnson's rule.
