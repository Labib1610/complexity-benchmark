# Problem B — Sequential Validation Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

You are configuring a sequential validation pipeline for a batch of **j** data artifacts. Each artifact must first clear the Primary Validator and then the Secondary Validator.

You must establish a single processing permutation of the **j** artifacts. Both validators will process the artifacts strictly according to this identical permutation.

The pipeline's timeline is governed by the following precise rules:
1. The Primary Validator processes artifacts continuously, one after another in your chosen permutation, starting at timestamp 0.
2. The Secondary Validator also processes artifacts one after another in the exact same permutation.
3. The Secondary Validator can only process one artifact at a time.
4. For any given artifact, the Secondary Validator cannot begin processing it until two conditions are met:
   - The Primary Validator has completely finished processing that specific artifact.
   - The Secondary Validator has completely finished processing the previous artifact in your permutation (this applies to all artifacts after the first).
5. The Secondary Validator always begins processing an artifact at the earliest possible timestamp that satisfies both conditions above.

Because the Secondary Validator must sometimes wait for the Primary Validator to finish an artifact, it may experience periods of idle time. The Primary Validator, however, operates continuously and never experiences idle time. 

Your objective is to find an ordering of the **j** artifacts that minimizes the final timestamp—specifically, the exact timestamp when the Secondary Validator completely finishes processing the final artifact in your permutation. (Note that because the sum of all Secondary Validator processing times is constant, minimizing this final timestamp is mathematically equivalent to minimizing the total accumulated idle time of the Secondary Validator).

What is the minimum possible final timestamp?

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the following **j** lines contains two integers **v1** and **v2** (1 ≤ v1, v2 ≤ 1000000), representing the duration required for the artifact's Primary Validator processing and Secondary Validator processing, respectively.

## Output

Print a single integer: the minimum possible final timestamp when the Secondary Validator finishes the last artifact.

## Examples


**Output**
```
10
```

### Example 2


### Example 3


## Note

In Example 1, if we select the permutation: 3rd artifact, then 2nd artifact, then 1st artifact from the input:
- **3rd artifact**: Primary Validator takes 1 (finishes at timestamp 1). Secondary Validator takes 3. It starts at 1 and finishes at 4. (The Secondary Validator was idle from timestamp 0 to 1).
- **2nd artifact**: Primary Validator takes 2 (finishes at 1+2=3). Secondary Validator takes 4. It must wait for its Primary Validator phase (timestamp 3) and the previous Secondary Validator phase (timestamp 4). It starts at 4 and finishes at 4+4=8. (No idle time here).
- **1st artifact**: Primary Validator takes 3 (finishes at 3+3=6). Secondary Validator takes 2. It must wait for its Primary Validator phase (timestamp 6) and the previous Secondary Validator phase (timestamp 8). It starts at 8 and finishes at 8+2=10. (No idle time here).

The final timestamp is 10. The total idle time for the Secondary Validator was 1. This is the minimum possible final timestamp across all valid permutations.

In Example 2, there is only one artifact. The Primary Validator finishes at 5. The Secondary Validator starts at 5 and finishes at 5 + 3 = 8.
