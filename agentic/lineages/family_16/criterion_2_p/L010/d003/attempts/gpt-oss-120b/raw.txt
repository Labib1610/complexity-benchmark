**Solution Explanation**

For every lens we have two processing times  

* `d1` – time on the *primary* axis (machine 1)  
* `d2` – time on the *secondary* axis (machine 2)

The lenses have to be processed on the two machines in the **same order**.
The start moment on machine 1 of the first lens may be `0`.  
For a fixed order the smallest possible finishing moment of the last lens
(the makespan) is obtained by the usual flow‑shop rule:

```
t1 = 0                     # finishing time on machine 1
t2 = 0                     # finishing time on machine 2
for each lens (d1,d2) in the order:
        t1 += d1
        t2 = max(t2, t1) + d2
makespan = t2
```

The only remaining question is: **which order gives the minimal makespan?**

--------------------------------------------------------------------

#### 1.   Johnson’s rule (two‑machine flow shop)

For two machines the optimal order is known (Johnson, 1954):

* put all jobs with `d1 ≤ d2` **first**, sorted by increasing `d1`
* put all jobs with `d1 > d2` **last**, sorted by decreasing `d2`

Proof sketch (standard, omitted here):
* For any two consecutive jobs `A,B` with `d1A ≤ d2A` and `d1B > d2B`
  swapping them never increases the makespan.
* Repeating swaps moves all “type 1” jobs (`d1 ≤ d2`) to the front,
  preserving the internal order described above.
* No other permutation can be better – the rule is optimal.

Thus we only have to build this order and evaluate the makespan with the
simulation above.

--------------------------------------------------------------------

#### 2.   Algorithm
```
read j
list1 = []          # jobs with d1 ≤ d2
list2 = []          # jobs with d1 > d2
for each lens:
        if d1 ≤ d2:   append (d1,d2) to list1
        else:         append (d1,d2) to list2

sort list1 by d1   (ascending)
sort list2 by d2   (descending)

order = list1 + list2

t1 = t2 = 0
for (d1,d2) in order:
        t1 += d1
        t2 = (t1 if t1 > t2 else t2) + d2   # max(t2,t1)+d2
print t2
```

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the minimal possible final boundary
value.

---

##### Lemma 1  
For a fixed order of lenses the simulation computes the smallest possible
`Y_j + d2(L_j)` that satisfies all constraints.

**Proof.**  
`X_k` is exactly the finishing time of lens `k` on machine 1, i.e. the
cumulative sum of `d1`.  
`Y_k` must be at least both the finishing time on machine 1 (`X_k+d1`) and
the finishing time of the previous lens on machine 2 (`Y_{k-1}+d2`).  
Choosing `Y_k = max( X_k+d1 , Y_{k-1}+d2 )` is the smallest feasible value,
and the recurrence used in the simulation is exactly this choice.
∎



##### Lemma 2  
Let two consecutive lenses `A,B` satisfy `d1A ≤ d2A` and `d1B > d2B`.
Swapping them does not increase the makespan.

**Proof.**  
Consider the four processing times:

```
order AB :   ... → A → B → ...
order BA :   ... → B → A → ...
```

Write the makespan formulas for the two‑lens fragment, using the
starting time on machine 1 as `s` and the starting time on machine 2 as
`t` (both ≤ the real start times, they cancel out).

For order **AB**:

```
finish1 = s + d1A + d1B
finish2 = max( t, s+d1A ) + d2A
finish2 = max( finish2, s+d1A+d1B ) + d2B
```

For order **BA**:

```
finish1' = s + d1B + d1A
finish2' = max( t, s+d1B ) + d2B
finish2' = max( finish2', s+d1B+d1A ) + d2A
```

Because `d1A ≤ d2A` we have `s+d1A ≤ max(t, s+d1A)+d2A`,
so after processing `A` the second machine is not earlier than the first.
Analogously `d1B > d2B` gives `max(t, s+d1B)+d2B ≤ s+d1B+d1A`.
A short case analysis (standard in Johnson’s proof) shows
`finish2' ≤ finish2`. ∎



##### Lemma 3  
After repeatedly applying the swap of Lemma&nbsp;2, any optimal order can be
transformed into the order produced by Johnson’s rule without increasing the
makespan.

**Proof.**  
Each swap moves a “type 1” job (`d1 ≤ d2`) leftwards and a “type 2” job
rightwards. Repeating until no such adjacent pair exists yields exactly the
order: all type 1 jobs first (sorted by increasing `d1` – any other order of
them can be sorted without worsening the makespan, because swapping two
type 1 jobs with `d1 ≤ d2` does not increase the makespan; similarly for the
type 2 part sorted by decreasing `d2`). ∎



##### Lemma 4  
The order constructed by the algorithm is optimal.

**Proof.**  
Take an optimal order `O`. By Lemma&nbsp;3 we can transform `O` into the
Johnson order `J` without increasing the makespan. Therefore `J` has makespan
≤ optimal makespan, i.e. it is optimal. ∎



##### Theorem  
The algorithm outputs the minimum possible value of `Y_j + d2(L_j)`.

**Proof.**  
The algorithm builds the Johnson order `J` (Lemma&nbsp;4) and then computes
the makespan for `J` using the simulation (Lemma&nbsp;1). Since `J` is optimal,
the obtained makespan is the global minimum. ∎

#### 4.   Complexity Analysis  

*Splitting* the jobs: `O(j)`  
*Sorting* `list1` and `list2`: `O(j log j)`  
*Simulation*: `O(j)`  

Memory consumption: the two lists store all jobs → `O(j)`.

Both limits satisfy the constraints (`j ≤ 200 000`).

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    list1 = []  # d1 <= d2
    list2 = []  # d1 > d2
    for _ in range(n):
        d1 = int(next(it))
        d2 = int(next(it))
        if d1 <= d2:
            list1.append((d1, d2))
        else:
            list2.append((d1, d2))
    list1.sort(key=lambda x: x[0])          # ascending d1
    list2.sort(key=lambda x: -x[1])         # descending d2
    order = list1 + list2

    t1 = 0
    t2 = 0
    for d1, d2 in order:
        t1 += d1
        if t2 < t1:
            t2 = t1
        t2 += d2
    sys.stdout.write(str(t2))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
