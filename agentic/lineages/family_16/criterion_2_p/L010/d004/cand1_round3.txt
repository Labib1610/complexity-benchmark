<STATEMENT>
# Problem B — Path Optimization on a Permuted Grid

Time limit: 1 s   Memory limit: 256 MB

## Description

You are given a collection of $j$ distinct columns, where each column consists of exactly two cells: a top cell and a bottom cell. For the $i$-th given column, the top cell has a weight of $d_1$ and the bottom cell has a weight of $d_2$. (Duplicate pairs of weights may exist, but each input line represents a distinct column that must be used exactly once).

You must arrange all $j$ columns into a single sequence from left to right. Let this chosen sequence of columns be indexed $1, 2, \dots, j$. Let $T_k$ and $B_k$ denote the weight of the top cell and the bottom cell, respectively, of the column placed at position $k$ in your sequence.

Consider a path that starts at the top cell of the first column (position 1) and ends at the bottom cell of the last column (position $j$). The path can only move to the right (to the next cell in the same row) or down (from the top cell to the bottom cell of the same column). A valid path will move right along the top row until some column $k$ ($1 \le k \le j$), move down at column $k$, and then move right along the bottom row until column $j$.

The cost of such a path moving down at column $k$ is the sum of the weights of all cells it visits:
$$ \text{Cost}(k) = \sum_{i=1}^{k} T_i + \sum_{i=k}^{j} B_i $$

For any fixed arrangement of the $j$ columns, its **grid score** is defined as the maximum path cost among all $j$ possible valid paths. That is, you do **not** choose a path to minimize cost; rather, the score of an arrangement is determined by its worst-case path (the maximum over all valid down-columns $k$):
$$ \text{Score} = \max_{1 \le k \le j} \text{Cost}(k) $$

Your goal is to find an arrangement (permutation) of the $j$ columns that minimizes this grid score. Report the smallest possible grid score.

Note: The answer may exceed the range of a 32-bit signed integer.

## Input

The first line contains a single integer $j$ ($1 \le j \le 200000$).
Each of the next $j$ lines contains two integers $d_1$ and $d_2$ ($1 \le d_1, d_2 \le 1000000$): the weights of the top and bottom cells for that column.

## Output

Print a single integer: the smallest possible grid score.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, if we place the columns in the order (1 3), (2 4), (3 2), meaning $T = [1, 2, 3]$ and $B = [3, 4, 2]$:
- Path down at $k=1$: $\text{Cost} = T_1 + B_1 + B_2 + B_3 = 1 + 3 + 4 + 2 = 10$.
- Path down at $k=2$: $\text{Cost} = T_1 + T_2 + B_2 + B_3 = 1 + 2 + 4 + 2 = 9$.
- Path down at $k=3$: $\text{Cost} = T_1 + T_2 + T_3 + B_3 = 1 + 2 + 3 + 2 = 8$.
The grid score for this arrangement is $\max(10, 9, 8) = 10$. No arrangement yields a score strictly less than 10.

I replaced the dual-axis scheduling scenario with a grid-path optimization problem. This forces the model to mathematically analyze the minimax objective over the path sums to rediscover the equivalent two-machine flow-shop structure, rather than relying on standard scheduling keywords.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum path cost in the 2xN grid is mathematically identical to the makespan in a two-machine permutation flow shop, so the optimal permutation yields the exact same minimum cost.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains solvable in O(n log n) using Johnson's algorithm, as the underlying mathematical structure is identical to a two-machine flow shop.
</PRESERVED_CLASS>
