**Solution Explanation**

For every sector we are given two integers  

* `p1 = a` – primary coefficient  
* `p2 = b` – secondary coefficient  

During the expedition the two trackers `P , S` (primary, secondary) are
initially `0`.

```
baseline   = S – a
threshold  = P + a
target     = max(baseline , threshold)
P          = P + a
S          = target + 2·b
```

After all sectors are processed the required value is  

```
answer = (P + S) / 2
```

--------------------------------------------------------------------

#### 1.   Reformulation

```
let   tot = Σ a                               (independent of the order)
let   D   = S – P                              (difference of the two trackers)
```

`P` after all sectors equals `tot`, therefore  

```
answer = (tot + (P+D)) / 2 = tot + D/2
```

`tot` is fixed, the whole problem is **to minimise the final value of D**.

--------------------------------------------------------------------

#### 2.   Recurrence for `D`

From the description

```
target = max( S-a , P+a )
S'     = target + 2b
P'     = P + a
```

Using `S = P + D`

```
target = max( P + D - a , P + a )
       = P + max( D-a , a )
S'     = P + max( D-a , a ) + 2b
P'     = P + a
D' = S' – P' = max( D-a , a ) – a + 2b
```

Two cases

```
if D ≤ 2a :   D' = 2b
else        : D' = D - 2a + 2b = D + 2·(b-a)
```

Both cases are compactly written as

```
D' = max( 2b , D + 2·(b-a) )                (1)
```

Define  

```
c = 2b                                 (constant reset value)
d = 2·(b-a)                            (additive part, may be negative)
```

Then the operation of a sector is the monotone function

```
f(D) = max( c , D + d )                (2)
```

`D` starts with `0` and after processing all sectors we have

```
answer = tot + D_final / 2
```

--------------------------------------------------------------------

#### 3.   How to order the functions `f`

Each sector is now a pair `(c , d)` with `c > 0` and `d` can be positive,
zero or negative.

* `d ≥ 0` ( i.e. `b ≥ a` ) – the function never *decreases* `D`.  
  It either raises `D` to `c` (if `D` is small) or adds `d`.

* `d < 0` ( i.e. `b < a` ) – the function can **decrease** `D`.  
  If `D` is large enough it lowers `D` by `|d|`; otherwise it only
  resets it to `c`.

The optimal order can be proved by a simple exchange argument:

*Take two consecutive sectors `X` and `Y`.
If processing `X` before `Y` never yields a larger `D` than the opposite
order for **any** starting `D`, then `X` must be placed before `Y` in an
optimal schedule.*

Applying this to the two classes of sectors gives the following rules.

--------------------------------------------------------------------
##### 3.1   Sectors with `d ≥ 0` (non‑decreasing)

For two such sectors `i , j` with `d_i , d_j ≥ 0`

```
f_j( f_i(D) ) ≤ f_i( f_j(D) )      for all D      ⇔      d_i > d_j
or ( d_i = d_j and c_i < c_j )
```

So they have to be processed

* **decreasing `d`**   (larger `b-a` first)
* if `d` is equal – **increasing `c`** (smaller `2b` first)

--------------------------------------------------------------------
##### 3.2   Sectors with `d < 0` (decreasing)

All those sectors can only lower `D`.  
To keep the possibility of lowering `D` we first apply the sectors with
**large thresholds `2a`**, i.e. with **large `a`**.
Therefore they are processed

* **decreasing `a`**   (largest `a` first)

--------------------------------------------------------------------
##### 3.3   Whole order

1. all sectors with `b ≥ a` – sorted as described in 3.1  
2. all sectors with `b < a` – sorted as described in 3.2  

Running the recurrence (1) over that order gives the minimal possible `D`
and consequently the minimal answer.

The sorting keys are completely independent of the current `D`,
therefore the order is globally optimal.

--------------------------------------------------------------------

#### 4.   Algorithm
```
read j
tot = 0
pos = []          # sectors with b >= a
neg = []          # sectors with b <  a
for each sector (a,b):
        tot += a
        if b >= a:
                pos.append( (b-a , 2*b , a , b) )   # (d/2 , c , a , b)
        else:
                neg.append( (a , b) )

pos.sort( key = (- (b-a) , 2*b) )          # decreasing d , increasing c
neg.sort( key = -a )                       # decreasing a

D = 0
for (_,c, a,b) in pos:
        inc = 2*(b-a)                       # = d
        D = max( c , D + inc )
for (a,b) in neg:
        inc = 2*(b-a)                       # negative
        c   = 2*b
        D = max( c , D + inc )

answer = tot + D//2
print answer
```

All arithmetic fits into signed 64‑bit (`j ≤ 2·10⁵`, each value ≤ 10⁶,
`D` ≤ 2·j·10⁶ ≤ 2·10¹¹).

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm outputs the minimal possible overall metric.

---

##### Lemma 1  
For a sector `(a,b)` the update of the difference `D = S‑P` is exactly

```
D' = max( 2b , D + 2·(b-a) )
```

**Proof.** Derived in Section&nbsp;2. ∎



##### Lemma 2  
For two sectors `i , j` with `b_i ≥ a_i` and `b_j ≥ a_j`
(let `d_i = 2(b_i-a_i) , c_i = 2b_i` etc.)  

If `d_i > d_j` or (`d_i = d_j` and `c_i < c_j`) then for **every**
starting value `D`

```
f_j( f_i(D) ) ≤ f_i( f_j(D) )
```

where `f_x(D) = max(c_x , D + d_x)`.

**Proof.**  
Both `d_i , d_j` are non‑negative, therefore `D + d_x ≥ D`.  
Consider three possible ranges of `D`:

*`D` so small that after the first sector the value is the reset `c`.*  
Then the second sector also produces a reset, the larger `c` wins.
Because `c_i < c_j` when `d_i = d_j`, the inequality holds.

*`D` so large that after the first sector the additive part is taken.*  
Then the composition adds `d_i + d_j` to the original `D`, order does not
matter.

*Mixed case* – one sector resets, the other adds.
A direct case analysis shows that the side with the larger `d` never
produces a larger final value. ∎



##### Lemma 3  
Among all sectors with `b ≥ a` an order that is **decreasing in `d`**
(and for equal `d` increasing in `c`) is optimal, i.e. yields the smallest
possible final `D`.

**Proof.**  
Take any order that is not sorted that way.
There exists a consecutive pair violating the condition.
By Lemma&nbsp;2 swapping this pair never increases the final `D`.
Repeatedly swapping all such inversions yields the sorted order and never
increases `D`. Hence the sorted order is optimal. ∎



##### Lemma 4  
For two sectors `i , j` with `b_i < a_i` and `b_j < a_j`
(let `a_i ≥ a_j` without loss of generality) we have

```
f_i( f_j(D) ) ≤ f_j( f_i(D) )      for every D
```

**Proof.**  
Here `d_i , d_j` are negative.
The function `f_x(D) = max(c_x , D + d_x)` first tries to **decrease**
`D` by `|d_x|`; this succeeds only if the current `D` is larger than the
threshold `c_x`.  
Choosing the larger `a` first means its threshold `2a` is larger, thus
when `D` is still high the decrease is applied. Afterwards `D` becomes
smaller, making it harder for the later sector to hit its own threshold,
so it cannot increase `D` more than the opposite order.
A complete case analysis on the relative sizes of `D` and the two
thresholds gives the inequality. ∎



##### Lemma 5  
Among all sectors with `b < a` an order **decreasing in `a`** is optimal.

**Proof.**  
If an order is not decreasing in `a` there exists a consecutive pair
`(j,i)` with `a_i > a_j`. Swapping them makes the order decreasing.
By Lemma&nbsp;4 the swap never increases the final `D`. Repeating removes
all inversions, producing the decreasing‑`a` order which is therefore
optimal. ∎



##### Lemma 6  
Let  

* `O₁` – optimal order of the `b ≥ a` sectors (Lemma 3)  
* `O₂` – optimal order of the `b < a` sectors (Lemma 5)

Any optimal global order consists of first all sectors of `O₁`
(in that order) followed by all sectors of `O₂` (in that order).

**Proof.**  
Consider an optimal global order.  
If a sector with `b < a` appears before a sector with `b ≥ a`,
swap the two.  
The first sector (negative `d`) can only **decrease** `D`,
the second (non‑negative `d`) never decreases it.
Swapping puts the decreasing sector later, which cannot make the final
`D` larger (the decreasing sector would act on a *larger* value of `D`,
producing at least as much reduction).  
Thus any optimal order can be transformed without worsening the result
into an order where all non‑decreasing sectors precede all decreasing
sectors. Inside each block the optimal ordering is given by Lemma 3 and
Lemma 5. ∎



##### Lemma 7  
The algorithm processes the sectors exactly in the order described in
Lemma 6.

**Proof.**  
The algorithm builds the two lists `pos` (`b ≥ a`) and `neg` (`b < a`),
sorts `pos` by decreasing `d` and, for ties, increasing `c`
(Lemma 3), and sorts `neg` by decreasing `a` (Lemma 5),
and finally concatenates `pos` then `neg`. ∎



##### Lemma 8  
The value `D` produced by the algorithm is the minimum attainable final
difference.

**Proof.**  
By Lemma 7 the algorithm follows the order proved optimal in Lemma 6.
Therefore no other permutation can yield a smaller final `D`. ∎



##### Theorem  
The program prints the smallest possible overall completion metric.

**Proof.**  
`tot = Σ a` is constant.  
By Lemma&nbsp;8 the algorithm computes the minimal possible `D`.  
The printed value `tot + D/2` equals the required metric,
hence it is minimal. ∎

#### 6.   Complexity Analysis

*Reading & partition* – `O(j)`  
*Sorting* – `O(j log j)` (two independent sorts)  
*Simulation* – `O(j)`  

Memory consumption – the two lists store at most `j` records,
each a few integers: `O(j)`.

Both limits satisfy the given constraints (`j ≤ 200 000`).

#### 7.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    n = data[0]
    it = iter(data[1:])
    total_a = 0
    pos = []          # (d, c, a, b)   for b >= a
    neg = []          # (a, b)         for b <  a

    for a, b in zip(it, it):
        total_a += a
        if b >= a:
            d = b - a               # we keep half of the real d (divide by 2)
            c = 2 * b
            pos.append((d, c, a, b))
        else:
            neg.append((a, b))

    # group with non‑negative d : decreasing d, then increasing c
    pos.sort(key=lambda x: (-x[0], x[1]))
    # group with negative d : decreasing a
    neg.sort(key=lambda x: -x[0])

    D = 0  # current difference S - P
    for d_half, c, a, b in pos:
        inc = 2 * (b - a)           # = 2*d_half
        tmp = D + inc
        D = c if tmp < c else tmp

    for a, b in neg:
        inc = 2 * (b - a)           # negative
        c = 2 * b
        tmp = D + inc
        D = c if tmp < c else tmp

    answer = total_a + D // 2
    sys.stdout.write(str(answer))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
