<METHOD_NAME>
Algebraic Metric Substitution
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces the explicit flow-shop makespan formulation (idle delay + sum of machine 2 times) with a mathematically identical but conceptually disjoint metric (final buffer + sum of machine 1 times). This breaks the LLM's pattern matching for Johnson's rule, forcing it to analyze the new metric from scratch, which typically leads to incorrect greedy heuristics.
</METHOD_DESCRIPTION>
<METHOD_NOVEL>
yes
</METHOD_NOVEL>
<STATEMENT>
# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given a surface scan parameter **p1** and a deep core extraction parameter **p2**.

You must arrange the **j** sectors into a single linear sequence. As the expedition processes your sequence sector by sector, it maintains an `active reserve` (initially 0).

For each sector in your sequence, the following steps occur in this exact order:
1. The sector's surface scan parameter **p1** is subtracted from the `active reserve`.
2. If the `active reserve` is now strictly negative, it is immediately reset to 0.
3. The sector's deep core extraction parameter **p2** is then added to the `active reserve`.

After all **j** sectors have been processed, the expedition's overall completion metric is calculated as the final `active reserve` plus the sum of the **p1** parameters of all **j** sectors.

Determine the sequence of sectors that minimizes this overall completion metric. Report that smallest possible metric.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the surface scan parameter and deep core extraction parameter for a sector, respectively.

## Output

Print a single integer: the smallest possible overall completion metric.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
- Processing the third sector (1, 3): The `active reserve` becomes 0 - 1 = -1. Since it is negative, it resets to 0. Then **p2** (3) is added, making the reserve 3.
- Processing the second sector (2, 4): The `active reserve` becomes 3 - 2 = 1. It is not negative, so it does not reset. Then **p2** (4) is added, making the reserve 5.
- Processing the first sector (3, 2): The `active reserve` becomes 5 - 3 = 2. It is not negative, so it does not reset. Then **p2** (2) is added, making the reserve 4.
The final `active reserve` is 4. The sum of all **p1** parameters is 1 + 2 + 3 = 6. The overall completion metric is 4 + 6 = 10.

In Example 2, processing the single sector (5, 3):
- The `active reserve` becomes 0 - 5 = -5. It resets to 0. Then **p2** (3) is added, making the reserve 3.
The final `active reserve` is 3. The sum of all **p1** parameters is 5. The overall completion metric is 3 + 5 = 8.
</STATEMENT>
<RATIONALE>
The models previously recognized the problem as a 2-machine flow shop because the metric was explicitly defined as the total `idle delay` plus the sum of all `p2` parameters, which perfectly matches the standard definition of makespan. By mathematically substituting this with an equivalent metric (`final reserve` plus the sum of all `p1` parameters), the problem no longer resembles the standard flow shop formulation. This forces models to derive the optimal sequence from first principles, which usually results in incorrect greedy heuristics.
</RATIONALE>
<PRESERVED_ANSWER>
The new metric (final reserve + sum of p1) is mathematically identical to the original metric (idle delay + sum of p2) for all possible sequences, meaning the optimal sequence and the minimum metric value are unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
Because the metric and the optimal sequence are identical, the problem is still solvable by Johnson's rule in O(n log n) time, preserving its P complexity class.
</PRESERVED_CLASS>
