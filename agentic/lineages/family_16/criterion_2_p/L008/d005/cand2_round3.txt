# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given a surface scan parameter **p1** and a deep core extraction parameter **p2**.

You must arrange the **j** sectors into a single linear sequence from position 1 to position **j**.

Once the sequence is chosen, we evaluate its effectiveness by considering all possible "transition points". A transition point **k** (where 1 ≤ **k** ≤ **j**) represents a hypothetical moment where the expedition finishes surface scans and switches to deep core extractions. 

Specifically, for a chosen transition point **k**, the `path score` is calculated as:
- The sum of the **p1** parameters of all sectors from position 1 to position **k** (inclusive).
- PLUS the sum of the **p2** parameters of all sectors from position **k** to position **j** (inclusive).

Notice that the sector at the transition point **k** contributes BOTH its **p1** and **p2** parameters to the `path score`.

The `peak score` of your chosen sequence is defined as the maximum `path score` among all **j** possible transition points.

Your objective is to find an arrangement of the **j** sectors that minimizes this `peak score`. Report that smallest possible `peak score`.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the surface scan parameter and deep core extraction parameter for a sector, respectively.

## Output

Print a single integer: the smallest possible `peak score` achievable by any valid sequence.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
This corresponds to the sequence of pairs: (1, 3), (2, 4), (3, 2).
We evaluate all possible transition points **k** from 1 to 3:
- For **k** = 1:
  The **p1** sum from position 1 to 1 is 1.
  The **p2** sum from position 1 to 3 is 3 + 4 + 2 = 9.
  The `path score` is 1 + 9 = 10.
- For **k** = 2:
  The **p1** sum from position 1 to 2 is 1 + 2 = 3.
  The **p2** sum from position 2 to 3 is 4 + 2 = 6.
  The `path score` is 3 + 6 = 9.
- For **k** = 3:
  The **p1** sum from position 1 to 3 is 1 + 2 + 3 = 6.
  The **p2** sum from position 3 to 3 is 2.
  The `path score` is 6 + 2 = 8.
The `peak score` is the maximum of these path scores: max(10, 9, 8) = 10.
This is the smallest possible `peak score` among all arrangements.

In Example 2, there is only one sector (5, 3), so **k** can only be 1.
- For **k** = 1:
  The **p1** sum from position 1 to 1 is 5.
  The **p2** sum from position 1 to 1 is 3.
  The `path score` is 5 + 3 = 8.
The `peak score` is 8.

Transformed the sequential buffer simulation into its mathematically equivalent static form: minimizing the maximum path sum (prefix of p1 + suffix of p2) over all split points. This removes the iterative "idle time" accumulation that models map to flow-shop makespan, forcing them to reason about the minimax objective directly rather than pattern-matching the wait-time recurrence.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum prefix-p1 plus suffix-p2 sum over all split points is mathematically identical to the makespan of a 2-machine flow shop, which is identically equal to the seed's idle-delay plus sum-of-p2 metric for every possible sequence.
</PRESERVED_ANSWER>
