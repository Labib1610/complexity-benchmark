# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given a surface scan parameter **p1** and a deep core extraction parameter **p2**.

You must arrange the **j** sectors into a single linear sequence. As the expedition processes your sequence sector by sector, it maintains a `reserve` (initially 0) and tracks the `total cost` (initially 0).

For each sector in your sequence, the following steps occur in this exact order:
1. A `shortfall` is calculated for the sector, defined as `max(0, p1 - reserve)`.
2. The `total cost` is increased by `shortfall + p2`.
3. The `reserve` is updated to `max(0, reserve - p1) + p2`.

Determine the sequence of sectors that minimizes the final `total cost`. Report that smallest possible `total cost`.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the surface scan parameter and deep core extraction parameter for a sector, respectively.

## Output

Print a single integer: the smallest possible final `total cost`.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
- Processing the third sector (1, 3): The `shortfall` is `max(0, 1 - 0) = 1`. The `total cost` increases by 1 + 3 = 4 (becoming 4). The `reserve` is updated to `max(0, 0 - 1) + 3 = 3`.
- Processing the second sector (2, 4): The `shortfall` is `max(0, 2 - 3) = 0`. The `total cost` increases by 0 + 4 = 4 (becoming 8). The `reserve` is updated to `max(0, 3 - 2) + 4 = 5`.
- Processing the first sector (3, 2): The `shortfall` is `max(0, 3 - 5) = 0`. The `total cost` increases by 0 + 2 = 2 (becoming 10). The `reserve` is updated to `max(0, 5 - 3) + 2 = 4`.
The final `total cost` is 10.

In Example 2, processing the single sector (5, 3):
- The `shortfall` is `max(0, 5 - 0) = 5`. The `total cost` increases by 5 + 3 = 8 (becoming 8). The `reserve` is updated to `max(0, 0 - 5) + 3 = 3`.
The final `total cost` is 8.

<METHOD_NAME>Merged Metric Increment</METHOD_NAME>
<METHOD_DESCRIPTION>Combined the separate order-dependent idle delay and order-independent sum(p2) components into a single step-by-step cost increment formula. This prevents models from immediately pattern-matching the objective as a 2-machine flow shop makespan, forcing them to either derive the equivalence algebraically or attempt adjacent-exchange derivations from scratch.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<RATIONALE>
The models previously recognized the problem as a standard 2-machine flow shop (Johnson's rule) because the metric explicitly separated an order-independent sum (`sum(p2)`) from the order-dependent idle delay. By merging these into a single incremental `total cost` update (`shortfall + p2`), the standard objective is obscured. The underlying mechanics remain identical, but the affordance for superficial pattern-matching is removed.
</RATIONALE>
<PRESERVED_ANSWER>
The `reserve` perfectly mirrors the original `buffer`, and the step-by-step addition of `shortfall + p2` mathematically equals the original final `idle delay` plus the sum of all `p2` values for every possible sequence.
</PRESERVED_ANSWER>

The problem remains solvable in O(j log j) using exactly the same greedy sorting logic (Johnson's rule), keeping it firmly in P.
</PRESERVED_CLASS>
