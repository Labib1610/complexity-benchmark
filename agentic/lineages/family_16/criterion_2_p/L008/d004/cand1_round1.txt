# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given a surface scan parameter **p1** and a deep core extraction parameter **p2**.

You must arrange the **j** sectors into a single linear sequence. As the expedition processes your sequence sector by sector, it maintains a `scanned buffer` (initially 0) and tracks the total `idle delay` (initially 0).

For each sector in your sequence, the following steps occur in this exact order:
1. The sector's surface scan parameter **p1** is subtracted from the `scanned buffer`.
2. If the `scanned buffer` is now strictly negative, the expedition experiences a delay. The absolute value of the `scanned buffer` is added to the total `idle delay`, and the `scanned buffer` is immediately reset to 0.
3. The sector's deep core extraction parameter **p2** is then added to the `scanned buffer`.

After all **j** sectors have been processed, the expedition's overall completion metric is calculated as the final total `idle delay` plus the sum of the **p2** parameters of all **j** sectors.

Determine the sequence of sectors that minimizes this overall completion metric. Report that smallest possible metric.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the surface scan parameter and deep core extraction parameter for a sector, respectively.

## Output

Print a single integer: the smallest possible overall completion metric.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
- Processing the third sector (1, 3): The buffer becomes 0 - 1 = -1. Since it is negative, the `idle delay` increases by 1 (becoming 1), and the buffer resets to 0. Then `p2` (3) is added, making the buffer 3.
- Processing the second sector (2, 4): The buffer becomes 3 - 2 = 1. It is not negative, so the `idle delay` remains 1. Then `p2` (4) is added, making the buffer 5.
- Processing the first sector (3, 2): The buffer becomes 5 - 3 = 2. It is not negative, so the `idle delay` remains 1. Then `p2` (2) is added, making the buffer 4.
The final `idle delay` is 1. The sum of all `p2` parameters is 3 + 4 + 2 = 9. The overall completion metric is 1 + 9 = 10.

In Example 2, processing the single sector (5, 3):
- The buffer becomes 0 - 5 = -5. The `idle delay` increases by 5 (becoming 5), and the buffer resets to 0. Then `p2` (3) is added, making the buffer 3.
The overall completion metric is 5 + 3 = 8.

<RATIONALE>
The problem was previously solved by models that instantly recognized the classic "two-machine flow shop" terminology (parallel tracks, sequence synchronization, prerequisites). To defeat this shortcut, the problem has been mathematically transformed into a sequential state machine tracking a "buffer" and "idle delay". This relies on the invariant that the makespan of a two-machine flow shop equals the total idle time of the second machine plus the sum of its processing times. Models can only solve this by genuinely deriving the optimal adjacent-swap condition (which yields Johnson's rule) rather than pattern-matching NLP scheduling templates.
