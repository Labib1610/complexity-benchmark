# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given the duration required for its surface scan and the duration required for its deep core extraction.

You must arrange the **j** sectors into a single linear sequence. For your chosen sequence, let Sector $k$ denote the $k$-th sector in the sequence (where $1 \le k \le j$). The timeline of the expedition is determined by assigning a surface scan start time and a deep core extraction start time to each Sector $k$, adhering to the following structural dependencies:

- The surface scan of Sector 1 starts at time 0.
- For each $k > 1$, the surface scan of Sector $k$ starts exactly when the surface scan of Sector $k-1$ ends.
- For each $k \ge 1$, the deep core extraction of Sector $k$ cannot start until the surface scan of Sector $k$ has ended.
- For each $k > 1$, the deep core extraction of Sector $k$ cannot start until the deep core extraction of Sector $k-1$ has ended.
- Each start time is set to the earliest possible moment that satisfies all dependencies.
- The end time of any operation is strictly its start time plus its required duration.

Because these dependencies form a constrained network, the overall completion time is dictated by the longest chain of operations. Your objective is to determine the sequence of sectors that minimizes the end time of the deep core extraction of Sector **j**. Report that smallest possible end time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations for a sector's surface scan and deep core extraction, respectively.

## Output

Print a single integer: the smallest possible end time of the final sector's deep core extraction.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, the single sector's surface scan occupies the time interval [0, 5]. Its deep core extraction must wait for the scan to end, so it occupies the time interval [5, 8]. The final end time is 8.

<RATIONALE>
I replaced the explicit "two parallel tracks" and "machine pipeline" language with a formal system of start-time assignment rules based on structural dependencies. By stating that the timeline forms a "constrained network" dictated by the "longest chain of operations", I encourage models to frame this as a general DAG or critical path optimization problem, which typically leads to dynamic programming or generic search approaches, rather than recognizing the specific two-machine flow-shop structure that permits Johnson's optimal sorting rule.
</RATIONALE>
<PRESERVED_ANSWER>
The dependency rules strictly enforce that surface scans occur sequentially without gaps, and deep core extractions occur sequentially while waiting for their respective surface scans, which is mathematically identical to the seed's synchronization rules.
</PRESERVED_ANSWER>

The problem remains exactly the two-machine permutation flow-shop scheduling problem to minimize makespan, which is solvable optimally in O(N log N) time using Johnson's rule.
</PRESERVED_CLASS>

Models might interpret "longest chain of operations" as implying they need to output the length of a specific path rather than optimizing the sequence, though the objective sentence strictly clarifies they must minimize the overall end time of the final extraction.
</RISK>
