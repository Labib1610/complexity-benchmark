# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to process **j** sectors. For each sector, you are given an energy requirement **p1** and an energy yield **p2**.

You must arrange the **j** sectors into a single linear sequence. As the expedition processes your sequence sector by sector, it maintains a `battery charge` (initially 0) and an `accumulated cost` (initially 0).

For each sector in your sequence, the following steps occur in this exact order:
1. The sector requires **p1** units of energy. The expedition draws energy from the battery to meet this requirement. If the current `battery charge` is strictly less than **p1**, the battery is fully depleted (dropping to 0), and an unmetered auxiliary grid supplies the shortfall. Otherwise, the `battery charge` is simply decreased by **p1**.
2. The sector then yields **p2** units of energy, which is added entirely to the `battery charge`.
3. The `accumulated cost` is updated. It increases by the sector's requirement **p1**, is further increased by the `battery charge` at the end of step 2, and is decreased by the `battery charge` from the start of step 1.

After all **j** sectors have been processed, the overall completion metric is the final `accumulated cost`.

Determine the sequence of sectors that minimizes this overall completion metric. Report that smallest possible metric.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the energy requirement and energy yield for a sector, respectively.

## Output

Print a single integer: the smallest possible overall completion metric.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
- Processing the third sector (1, 3): The starting charge is 0. In step 1, requirement p1 is 1. Since charge is 0, it drops to 0. In step 2, p2 (3) is added, making the charge 3. In step 3, the `accumulated cost` increases by p1 (1) + end charge (3) - start charge (0) = 4. The cost becomes 4.
- Processing the second sector (2, 4): The starting charge is 3. In step 1, requirement p1 is 2. The charge is sufficient, so it decreases by 2, becoming 1. In step 2, p2 (4) is added, making the charge 5. In step 3, the `accumulated cost` increases by p1 (2) + end charge (5) - start charge (3) = 4. The cost becomes 8.
- Processing the first sector (3, 2): The starting charge is 5. In step 1, requirement p1 is 3. The charge is sufficient, so it decreases by 3, becoming 2. In step 2, p2 (2) is added, making the charge 4. In step 3, the `accumulated cost` increases by p1 (3) + end charge (4) - start charge (5) = 2. The cost becomes 10.
The final `accumulated cost` is 10, which is the overall completion metric.

In Example 2, processing the single sector (5, 3):
- The starting charge is 0. In step 1, requirement p1 is 5. The charge drops to 0. In step 2, p2 (3) is added, making the charge 3. In step 3, the `accumulated cost` increases by p1 (5) + end charge (3) - start charge (0) = 8. The cost becomes 8.
The overall completion metric is 8.

<RATIONALE>
The models were succeeding by noticing that `p2` was directly added to the cost at every step, allowing them to instantly factor out `sum(p2)` as a constant and focus purely on minimizing the grid draw. I removed this affordance by reformulating the cost increment as a telescoping sum: `cost += p1 + battery_new - battery_old`. This is mathematically identical step-by-step to `cost += grid_draw + p2`, but it completely hides the constant `p2` contribution. Models must now algebraically prove that the total cost simplifies to `sum(p1) + battery_final`, and then deduce that minimizing the final battery charge is equivalent to minimizing the grid draw (the flow-shop makespan).
</RATIONALE>
<PRESERVED_ANSWER>
The step-by-step cost increment `p1 + B_new - B_old` algebraically simplifies to exactly `grid_draw + p2` for every possible state, meaning the accumulated cost tracks identical values at every single step for any sequence.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
Since the mathematical function being evaluated and minimized is exactly identical for all permutations, the problem remains a 2-machine flow shop solvable by Johnson's rule in O(N log N) time.
</PRESERVED_CLASS>
