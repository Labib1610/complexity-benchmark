**Solution Explanation**

For every commission we have two processing times  

* `a` – time of Artist **A** (first machine)  
* `b` – time of Artist **B** (second machine)

All commissions must be processed in the same order on both machines.
A commission may start on machine 2 only after it has finished on machine 1
and after machine 2 has finished the previous commission.

The problem is the classic *two‑machine flow shop* makespan minimisation.
The optimal order is given by **Johnson’s rule**.

--------------------------------------------------------------------

#### Johnson’s rule for two machines  

*Split the jobs into two groups*

* `G1` – jobs with `a ≤ b`
* `G2` – jobs with `a > b`

*Sort*

* `G1` by increasing `a`
* `G2` by decreasing `b`

*Schedule* all jobs of `G1` first (in that order) and then all jobs of `G2`.

The rule is optimal; a short proof can be found in any scheduling textbook.
For this problem we only have to implement it.

--------------------------------------------------------------------

#### Computing the finishing time of a given order  

```
timeA = 0          # moment when A finishes the current job
timeB = 0          # moment when B finishes the current job
for (a,b) in order:
    timeA += a                     # A works continuously
    timeB = max(timeB, timeA) + b # B may have to wait for A
answer = timeB
```

Both variables fit into 64‑bit signed integers
(`j ≤ 2·10⁵`, each duration ≤ 10⁶ → total ≤ 2·10¹¹).

--------------------------------------------------------------------

#### Algorithm
```
read j
read all (a,b) pairs
G1 = [(a,b) for (a,b) if a <= b]
G2 = [(a,b) for (a,b) if a >  b]

sort G1 by a   (ascending)
sort G2 by b   (descending)

order = G1 + G2

simulate the schedule (formula above) → answer
print answer
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the minimal possible finishing time.

---

##### Lemma 1 (Johnson’s rule optimality)  
For a two‑machine flow shop, the schedule obtained by Johnson’s rule
minimises the makespan (completion time of the last job).

*Proof Sketch.*  
Consider any optimal schedule.  
If there exists a pair of consecutive jobs `X, Y` such that

* `a_X > b_X` and `a_Y ≤ b_Y`  

then swapping `X` and `Y` does not increase the makespan.
Repeatedly applying such swaps moves all jobs with `a ≤ b` to the front,
ordered by non‑decreasing `a`, and all jobs with `a > b` to the back,
ordered by non‑increasing `b`.  
Thus an optimal schedule can be transformed into the Johnson order,
so Johnson’s order is optimal. ∎



##### Lemma 2  
Given a fixed order of jobs, the simulation described above computes the
exact makespan of that order.

*Proof.*  
`timeA` is the sum of all `a` of processed jobs, i.e. the moment when A
finishes the current job – correct because A never idles.  
When the current job reaches B, B can start only after both
* it has finished the previous job (`timeB` before the update) and
* A has finished this job (`timeA`).  
Hence the start moment is `max(timeB, timeA)`, and after processing `b`
the new `timeB` is `max(timeB, timeA) + b`.  
Induction over the jobs shows the invariant holds, therefore the final
`timeB` equals the makespan. ∎



##### Lemma 3  
The algorithm outputs the makespan of the Johnson order.

*Proof.*  
The algorithm builds exactly the order described in Lemma&nbsp;1
(first `G1` sorted by `a`, then `G2` sorted by `b` descending) and then
applies the simulation of Lemma&nbsp;2, whose result is printed. ∎



##### Theorem  
The algorithm prints the smallest possible finishing time of all
commissions.

*Proof.*  
By Lemma&nbsp;1 the Johnson order is optimal, i.e. no other order yields a
smaller makespan.  
By Lemma&nbsp;3 the algorithm computes the makespan of that order.
Therefore the printed value is the minimum achievable finishing time. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

* Splitting into two groups: `O(j)`
* Sorting `G1` and `G2`: `O(j log j)` (dominant term)
* Simulation: `O(j)`

Memory consumption: the two lists store all jobs → `O(j)` pairs.

Both limits satisfy the given constraints (`j ≤ 200 000`).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    n = data[0]
    jobs = [(data[i], data[i + 1]) for i in range(1, 2 * n, 2)]

    g1 = []  # a <= b
    g2 = []  # a >  b
    for a, b in jobs:
        if a <= b:
            g1.append((a, b))
        else:
            g2.append((a, b))

    g1.sort(key=lambda x: x[0])          # increasing a
    g2.sort(key=lambda x: x[1], reverse=True)  # decreasing b

    order = g1 + g2

    time_a = 0
    time_b = 0
    for a, b in order:
        time_a += a
        if time_b < time_a:
            time_b = time_a
        time_b += b

    sys.stdout.write(str(time_b))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
