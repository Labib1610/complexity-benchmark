We have \( j \) packets, each with a synchronization cost \( p1_i \) and an update cost \( p2_i \).  
We need to order them to minimize:

\[
\max_{k=1..j} \left( \sum_{i=1}^k p1_i + \sum_{i=k}^j p2_i \right)
\]

Let’s denote:
- \( S1_k = \sum_{i=1}^k p1_i \)
- \( S2_k = \sum_{i=k}^j p2_i \)

We want to minimize \(\max_k (S1_k + S2_k)\).

---

### Key observation
For a given order, the expression for position \(k\) is:

\[
S1_k + S2_k = S1_k + (TotalP2 - \text{sum of p2 before k})
\]

If we define:
- \( A_k = S1_k - \text{sum of p2 before k} \)

Then:
\[
S1_k + S2_k = A_k + TotalP2
\]

So minimizing \(\max_k (S1_k + S2_k)\) is equivalent to minimizing \(\max_k A_k\).

Where:
\[
A_k = \sum_{i=1}^k p1_i - \sum_{i=1}^{k-1} p2_i
\]
(Note: for \(k=1\), the second sum is 0.)

---

### Reformulation
We can think of each packet as having a "cost" when placed at position \(k\):
- When placed at position \(k\), it contributes \(p1\) to the prefix sum, and also contributes \(p2\) to the "penalty" for later positions.

We can rewrite:
\[
A_k = \sum_{i=1}^k (p1_i - p2_i) + p2_k
\]
Wait, let's check:

For \(k\):
\[
A_k = \sum_{i=1}^k p1_i - \sum_{i=1}^{k-1} p2_i
= \sum_{i=1}^k p1_i - \left( \sum_{i=1}^k p2_i - p2_k \right)
= \sum_{i=1}^k (p1_i - p2_i) + p2_k
\]

So:
\[
A_k = \left( \sum_{i=1}^k (p1_i - p2_i) \right) + p2_k
\]

---

### Greedy strategy
We want to minimize the maximum of these \(A_k\).  
This is similar to a scheduling problem: we can sort by some criterion.

If we sort by \(p1 - p2\) in **decreasing** order, the prefix sums of \(p1 - p2\) will be as small as possible early on, which helps reduce the maximum.

Let’s test with example 1:
Packets: (3,2), (2,4), (1,3)  
Differences: 1, -2, -2  
Sort descending: (3,2) diff=1, then (2,4) diff=-2, then (1,3) diff=-2.

Compute:
k=1: sum diff = 1, +p2=2 → A=3  
k=2: sum diff = -1, +p2=4 → A=3  
k=3: sum diff = -3, +p2=3 → A=0  
Max = 3, plus TotalP2 = 2+4+3=9 → total = 12. But expected answer is 10. So this isn't optimal.

---

### Better approach
We can binary search on the answer \(X\).  
For a given \(X\), can we order packets so that for all \(k\):

\[
\sum_{i=1}^k p1_i + \sum_{i=k}^j p2_i \le X
\]

This is equivalent to:
\[
\sum_{i=1}^k p1_i - \sum_{i=1}^{k-1} p2_i \le X - TotalP2
\]

Let \(C = X - TotalP2\).  
We need to order so that for all \(k\):
\[
\sum_{i=1}^k p1_i - \sum_{i=1}^{k-1} p2_i \le C
\]

This is a known scheduling feasibility: we can place packets in order of \(p1\) ascending? Let's think.

We can use a greedy:  
At each step, among remaining packets, pick one with smallest \(p1\) that doesn't violate the constraint.  
But we also need to consider \(p2\) effect on future.

Actually, this is similar to "minimize maximum prefix sum" with two types of costs.  
We can sort by \(p1\) ascending, then check if feasible.

---

### Feasibility check for given C
We maintain current sum \(S = 0\).  
We iterate packets in some order.  
For each packet, before adding, we check:  
If we place it now, the new \(A_k = S + p1_i\) must be ≤ C.  
After placing, we update \(S = S + p1_i - p2_i\).

We need to find an order that keeps all \(S + p1_i \le C\).

This is like: we have items with "entry cost" p1 and "exit cost" p2.  
We can sort by p1 ascending, and if at any point the constraint fails, it's impossible.

Let's test with example 1, C = X - TotalP2.  
TotalP2 = 9.  
If X=10, C=1.  
Sort by p1: (1,3), (2,4), (3,2).  
Start S=0.  
Place (1,3): check S+p1=1 ≤1 OK, S=0+1-3=-2.  
Place (2,4): check S+p1=-2+2=0 ≤1 OK, S=-2+2-4=-4.  
Place (3,2): check S+p1=-4+3=-1 ≤1 OK.  
Feasible → X=10 works.

So binary search works.

---

### Implementation
We binary search X from max(p1)+max(p2) to sum(p1)+sum(p2).  
Feasibility: sort by p1 ascending, simulate.

---

```python
def can(X, packets, total_p2):
    C = X - total_p2
    if C < 0:
        return False
    S = 0
    for p1, p2 in sorted(packets):
        if S + p1 > C:
            return False
        S += p1 - p2
    return True

def solve():
    import sys
    input = sys.stdin.readline
    j = int(input())
    packets = [tuple(map(int, input().split())) for _ in range(j)]
    total_p2 = sum(p2 for _, p2 in packets)
    lo = max(p1 for p1, _ in packets) + max(p2 for _, p2 in packets)
    hi = sum(p1 for p1, _ in packets) + total_p2
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, packets, total_p2):
            hi = mid
        else:
            lo = mid + 1
    print(lo)

if __name__ == "__main__":
    solve()
```
