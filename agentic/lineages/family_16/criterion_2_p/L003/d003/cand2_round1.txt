# Problem B — Event Synchronization

Time limit: 1 s   Memory limit: 256 MB

## Description

A communications protocol transmits a batch of **j** data packets. You must choose the exact sequence in which these packets are arranged. Each packet requires a specific preparation duration **p1** and a resolution duration **p2**.

For any chosen sequence, an observer logs a critical event for each position **k** in the sequence (where 1 ≤ **k** ≤ **j**). The timestamp of the **k**-th critical event is calculated by adding the preparation durations of all packets from position 1 up to position **k** inclusive, and then adding the resolution durations of all packets from position **k** up to position **j** inclusive.

The overall latency of the sequence is defined as the maximum timestamp among all **j** critical events.

Given the durations **p1** and **p2** for each packet, determine the optimal arrangement of the packets that minimizes the overall latency. Output this minimum possible latency.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the preparation duration and the resolution duration for a packet, respectively.

## Output

Print a single integer: the smallest possible overall latency.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one packet. The single critical event timestamp is calculated as its preparation duration (5) plus its resolution duration (3), yielding 8.

This forces models to either independently recognize the mathematical equivalence between this max-sum formula and the flow-shop makespan, or to derive the optimal sorting comparator from scratch using exchange arguments.

The maximum over all k of the sum of the first k elements' preparation durations and the remaining elements' resolution durations is mathematically identical to the makespan of a two-machine permutation flow shop, ensuring identical outputs for all sequences.
