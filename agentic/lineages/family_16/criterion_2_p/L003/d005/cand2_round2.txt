# Problem B — The Tile Grid

Time limit: 1 s   Memory limit: 256 MB

## Description

You are given a set of **j** tiles. Each tile has a top value and a bottom value. You cannot rotate or flip the tiles.

You must arrange all **j** tiles in a single sequence from left to right to form a grid with 2 rows and **j** columns. The top values of the tiles form the top row of the grid, and the bottom values form the bottom row. Each tile must be used exactly once, and both rows follow the exact same left-to-right tile order you choose.

Consider a token that starts at the top-left cell of this grid and must reach the bottom-right cell. The token can only move to the right (to the next column in the same row) or down (to the bottom cell in the same column). Because the grid has exactly 2 rows and moves are only right or down, any valid path is uniquely determined by the single column where the token moves down.

The cost of a path is the sum of the values in all the cells the token visits, including the start and end cells. 

The maximum path cost of an arrangement is the highest total cost among all valid paths the token could take. Your task is to choose an arrangement of the tiles that minimizes this maximum path cost. You do **not** need to output the arrangement itself; output only the minimum achievable maximum path cost.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the top value and the bottom value of a tile, respectively.

## Output

Print a single integer: the smallest possible maximum path cost among all valid arrangements of the tiles.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, if you arrange the tiles in the order `(1, 3)`, `(2, 4)`, and `(3, 2)`, the top row is `[1, 2, 3]` and the bottom row is `[3, 4, 2]`.
The three possible paths are:
- Move down in column 1: cost is 1 (top) + 3 (bottom) + 4 (bottom) + 2 (bottom) = 10.
- Move down in column 2: cost is 1 (top) + 2 (top) + 4 (bottom) + 2 (bottom) = 9.
- Move down in column 3: cost is 1 (top) + 2 (top) + 3 (top) + 2 (bottom) = 8.
The maximum path cost for this arrangement is 10. No other arrangement yields a smaller maximum path cost.

<RATIONALE>
Replaced the factory machinery and queueing scenario with a 2xN grid path optimization. The completion time of the last job in a 2-machine flow shop is mathematically identical to the maximum path cost in a 2xN grid where top/bottom rows represent the processing times. This removes all scheduling vocabulary, forcing the model to recognize the algebraic equivalence to Johnson's rule rather than triggering it via keywords.
</RATIONALE>

The maximum path cost in the 2xN grid exactly calculates the makespan of the corresponding 2-machine permutation flow shop, so the optimal arrangement and its value are identical.
</PRESERVED_ANSWER>
