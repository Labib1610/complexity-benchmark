# Problem B — Pipeline Optimization

Time limit: 1 s   Memory limit: 256 MB

## Description

You are optimizing a data pipeline that processes a batch of **j** datasets. You must arrange the datasets by loading them into the pipeline's Initial Queue in a specific order of your choosing.

The pipeline consists of an Extractor unit, a Transfer Queue, and a Transformer unit, operating under the following mechanics:
- The Initial Queue holds the datasets in your chosen order.
- The Extractor unit begins operating at time 0. It continuously dequeues the next dataset from the front of the Initial Queue, spends **p1** time processing it, and immediately enqueues it at the back of the Transfer Queue. The Extractor processes exactly one dataset at a time and never pauses as long as the Initial Queue is not empty.
- The Transfer Queue is a strict First-In-First-Out (FIFO) buffer.
- The Transformer unit processes exactly one dataset at a time. It continuously monitors the Transfer Queue. Whenever the Transformer is idle and the Transfer Queue is not empty, it dequeues the next dataset from the front, spends **p2** time processing it, and then outputs it. If the Transfer Queue is empty, the Transformer remains idle until a dataset arrives.

For each dataset, you are given the time **p1** it requires in the Extractor, and the time **p2** it requires in the Transformer.

Determine the optimal initial order of datasets in the Initial Queue to minimize the time at which the Transformer finishes processing the final dataset. Output this minimum possible time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the time required for a dataset in the Extractor and the Transformer, respectively.

## Output

Print a single integer: the smallest possible time at which the final dataset finishes its processing in the Transformer.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1

```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal arrangement is to place the 3rd dataset at the front of the Initial Queue, followed by the 2nd, and then the 1st at the back.
- **3rd dataset:** Extractor dequeues it at time 0, takes 1 (finishes at 1), and enqueues it to the Transfer Queue. The Transformer immediately dequeues it at time 1 and takes 3 (finishes at 4).
- **2nd dataset:** Extractor dequeues it at time 1, takes 2 (finishes at 3), and enqueues it. The Transformer is busy until time 4. At time 4, the Transformer dequeues the 2nd dataset and takes 4 (finishes at 8).
- **1st dataset:** Extractor dequeues it at time 3, takes 3 (finishes at 6), and enqueues it. The Transformer is busy until time 8. At time 8, the Transformer dequeues the 1st dataset and takes 2 (finishes at 10).
The final dataset finishes at time 10.

In Example 2, the single dataset takes 5 for the Extractor. It enters the Transfer Queue at time 5, and the Transformer takes 3, finishing at time 8.
