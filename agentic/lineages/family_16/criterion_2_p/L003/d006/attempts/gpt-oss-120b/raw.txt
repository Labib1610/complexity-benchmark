**Solution Explanation**

For a fixed order of the `j` tiles let  

* `a[i]` – value in the top cell of the *i*-th column,
* `b[i]` – value in the bottom cell of the *i*-th column.

The adversary starts at `(1,1)` and must finish at `(2,j)`.  
He can move only **right** or **down**, therefore his path is completely
determined by the column `k` where he moves down:

```
(1,1) → … → (1,k) → (2,k) → … → (2,j)
```

The cost of this path is  

```
prefTop(k) = a[1] + … + a[k]          (top cells up to k)
suffBot(k) = b[k] + … + b[j]          (bottom cells from k)
cost(k)   = prefTop(k) + suffBot(k)
```

The adversary chooses `k` that maximises `cost(k)`.
For a given ordering the worst‑case cost is  

```
worst = max_{k=1..j} ( prefTop(k) + suffBot(k) )
```

Our task: **choose an ordering that minimises this worst value**.



--------------------------------------------------------------------

#### 1.  Key observation – ordering by `a[i] - b[i]`

Consider two consecutive columns `X` then `Y`.

```
top :  aX , aY
bot :  bX , bY
```

If we swap them, only the two possible down‑positions `k = X` and `k = Y`
change their costs:

```
costX before swap = (prefTop up to X) + (bX + bY + rest)
costY before swap = (prefTop up to Y) + (bY + rest)
```

All other `k` keep the same cost because the set of visited cells is
identical.

The difference between the two costs after the swap is

```
Δ = (aY - bY) - (aX - bX)
```

*If* `aX - bX ≥ aY - bY` then `Δ ≤ 0`, i.e. swapping would **not decrease**
the larger of the two costs.
Therefore an optimal order never puts a column with larger `a-b`
*after* a column with smaller `a-b`.

Consequently, sorting the columns **in non‑increasing order of
`a[i] - b[i]`** yields an optimal arrangement.

--------------------------------------------------------------------

#### 2.  Computing the answer for the sorted order

After sorting we scan once, maintaining

* `prefTop` – sum of `a` of processed columns,
* `prefBotPrev` – sum of `b` of columns **before** the current one.

Let `totalBot = Σ b[i]`.  
For the current column `k` (1‑based)

```
suffBot(k) = totalBot - prefBotPrev
cost(k)    = prefTop + suffBot(k)
```

Update the maximum over all `k`.  
Complexities: `O(j log j)` time for sorting, `O(j)` memory.

--------------------------------------------------------------------

#### 3.  Correctness Proof  

We prove that the algorithm outputs the minimal possible maximum path cost.

---

##### Lemma 1  
For any two adjacent columns `X, Y` with `aX - bX ≥ aY - bY`,
swapping them does not decrease `max_k cost(k)`.

**Proof.**  
Only the costs for down‑positions `k = X` and `k = Y` are affected.
Let `P` be the sum of top cells before column `X`,
`Q` the sum of bottom cells after column `Y`.

Before swap  

```
costX = P + aX + (bX + bY) + Q
costY = P + aX + aY + bY + Q
```

After swap  

```
costX' = P + aY + (bY + bX) + Q
costY' = P + aY + aX + bX + Q
```

The larger of the two values after swapping is at most the larger before
because  

```
costX' - costY = (aY - bY) - (aX - bX) ≤ 0
costY' - costX = (aX - bX) - (aY - bY) ≥ 0
```

Thus the maximum does not get smaller. ∎



##### Lemma 2  
There exists an optimal ordering that is sorted by non‑increasing
`a[i] - b[i]`.

**Proof.**  
Take any optimal ordering. While there is a pair of adjacent columns that
violates the order (`aX - bX < aY - bY`), swap them.
By Lemma&nbsp;1 the maximum cost never increases, therefore after finitely
many swaps we obtain an optimal ordering that is fully sorted. ∎



##### Lemma 3  
For the sorted ordering the algorithm computes  
`M = max_k (prefTop(k) + suffBot(k))`.

**Proof.**  
During the left‑to‑right scan, after processing column `k`

* `prefTop` equals `Σ_{i=1..k} a[i]`,
* `prefBotPrev` equals `Σ_{i=1..k-1} b[i]`.

Hence `totalBot - prefBotPrev = Σ_{i=k..j} b[i] = suffBot(k)`.
The algorithm evaluates `prefTop + suffBot(k)` for this `k` and keeps the
maximum over all `k`. ∎



##### Lemma 4  
The value `M` output by the algorithm equals the minimal possible maximum
path cost.

**Proof.**  
*Upper bound*: By Lemma&nbsp;2 there exists an optimal ordering that is
sorted. For that ordering the worst path cost is exactly `M`
(Lemma&nbsp;3). Hence the optimal value ≤ `M`.

*Lower bound*: For any ordering, its worst path cost is at least the
maximum over `k` of `prefTop(k)+suffBot(k)`. The sorted ordering minimises
this maximum (Lemma&nbsp;2), therefore no ordering can achieve a value
smaller than `M`. Hence the optimal value ≥ `M`.

Both bounds give equality. ∎



##### Theorem  
The program prints the smallest possible maximum cost the adversary can
obtain.

**Proof.**  
The program sorts the tiles by decreasing `a-b`, computes `M` as described,
and outputs it. By Lemma&nbsp;4 this `M` is exactly the optimal value. ∎



--------------------------------------------------------------------

#### 4.  Complexity Analysis

*Sorting*: `O(j log j)` time, `O(j)` memory.  
*Scanning*: `O(j)` time, `O(1)` extra memory.  

Overall: `O(j log j)` time, `O(j)` memory, well within limits (`j ≤ 2·10^5`).

#### 5.  Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    tiles = []
    total_bot = 0
    for _ in range(n):
        a = int(next(it))
        b = int(next(it))
        tiles.append((a, b, a - b))
        total_bot += b

    # sort by decreasing (a - b)
    tiles.sort(key=lambda x: -x[2])

    pref_top = 0
    pref_bot_prev = 0
    best = 0
    for a, b, _ in tiles:
        pref_top += a
        # suffix bottom includes current b
        suff_bot = total_bot - pref_bot_prev
        cost = pref_top + suff_bot
        if cost > best:
            best = cost
        pref_bot_prev += b

    print(best)

if __name__ == "__main__":
    solve()
```
