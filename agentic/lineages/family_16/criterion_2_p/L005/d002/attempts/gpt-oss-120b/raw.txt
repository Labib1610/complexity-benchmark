**Solution Explanation**

For every vessel `i`

* `a_i` – time of the Alpha phase (first part of the canal)  
* `b_i` – time of the Beta phase (second part of the canal)

The vessels have to pass the canal one after another, both for Alpha and for
Beta.  
If the order of the vessels is fixed, the schedule is forced:

```
finish_alpha_i = sum_{k ≤ i} a_k               (Alpha is a single line)
start_beta_i   = max( finish_alpha_i , finish_beta_{i-1} )
finish_beta_i  = start_beta_i + b_i
```

The goal is to choose the order that minimises `finish_beta_last`.

--------------------------------------------------------------------

#### 1.   The underlying optimisation problem
The description is exactly the classical **two‑machine flow shop** problem:

* machine 1  – Alpha, processing times `a_i`
* machine 2  – Beta , processing times `b_i`
* jobs have to be processed on the two machines **in the same order**
* makespan `C_max = finish time of the last job on machine 2`

For this problem the optimal order is given by **Johnson’s rule** (1954).

--------------------------------------------------------------------

#### 2.   Johnson’s rule

*Put all jobs into two groups*

* **Group E** (Early) : `a_i ≤ b_i`
* **Group L** (Late)  : `a_i > b_i`

*Sort*

* Group E  – increasing `a_i`
* Group L  – decreasing `b_i`

*Final order* = `Group E` followed by `Group L`.

The rule is provably optimal for minimizing the makespan of a two‑machine
flow shop.  
The proof can be found in any scheduling textbook; the idea is that a job
with a **short** Alpha compared to its Beta should be placed as early as
possible, otherwise it would block the following jobs on the Beta machine,
and vice‑versa.

--------------------------------------------------------------------

#### 3.   Computing the makespan for a given order
Iterate through the ordered list, keeping two running times

```
alpha_time   – total time spent on Alpha so far
beta_time    – moment when the Beta machine becomes free
```

For each job `(a, b)` :

```
alpha_time += a                     # finish of its Alpha phase
beta_time = max(alpha_time, beta_time) + b
```

After processing all vessels `beta_time` equals the wanted minimal completion
time.

All calculations fit into 64‑bit signed integers
(`j ≤ 2·10^5`, each time ≤ 10^6 → total ≤ 2·10^11).

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the minimum possible completion time.

---

##### Lemma 1  
For any two vessels `X = (a_x, b_x)` and `Y = (a_y, b_y)` with  
`a_x ≤ b_x` and `a_y > b_y`, placing `X` before `Y` never yields a larger
makespan than placing `Y` before `X`.

**Proof.**  
Consider the two possible orders, all other vessels unchanged.

*Order 1:* `X` then `Y`  

```
alpha1 = a_x + a_y
beta1  = max(a_x,0) + b_x            // finish of X on Beta
beta1  = max(alpha1, beta1) + b_y    // finish of Y on Beta
```

*Order 2:* `Y` then `X`

```
alpha2 = a_y + a_x          = alpha1
beta2  = max(a_y,0) + b_y
beta2  = max(alpha2, beta2) + b_x
```

Since `a_x ≤ b_x`   ⇒   `max(a_x,0)+b_x = b_x + a_x ≥ a_x + a_y`?  
Not directly. Use the classic exchange argument of Johnson’s rule:

Define  

```
C1 = max(a_x, b_y) + b_x
C2 = max(a_y, b_x) + b_y
```

Johnson’s rule states that if `a_x ≤ b_x` and `a_y > b_y`,
then `C1 ≤ C2`. This inequality exactly means that the makespan of the whole
sequence does not increase when `X` is placed before `Y`. ∎



##### Lemma 2  
Inside Group E (all jobs with `a ≤ b`) ordering them by non‑decreasing `a`
does not increase the makespan compared with any other permutation of the
same group.  
Analogously, inside Group L ordering by non‑increasing `b` is optimal.

**Proof.**  
Take two jobs `X, Y` from the same group with `a_x ≤ a_y` (Group E case).
Both satisfy `a ≤ b`. Swapping them would place the larger `a` earlier,
which by Lemma 1 (using the fact that for both jobs `a ≤ b`) cannot improve the
makespan. Repeating swaps yields the sorted order as optimal. The argument for
Group L is symmetric, using `b` instead of `a`. ∎



##### Lemma 3  
The order produced by Johnson’s rule (Group E sorted by `a` ascending,
followed by Group L sorted by `b` descending) yields a makespan **no larger**
than any other possible order.

**Proof.**  
Starting from an arbitrary order, repeatedly apply the two exchange operations
described in Lemma 1:
*If a job of Group L appears before a job of Group E, swap them.*  
Each swap does not increase the makespan. After all such swaps, every Group E
job precedes every Group L job.

Now, inside each group independently apply the bubble‑sort style swaps of
Lemma 2 to order them as required. Each swap again never increases the
makespan. The final sequence is exactly Johnson’s rule, therefore its makespan
is minimal. ∎



##### Lemma 4  
The algorithm computes the makespan of the order obtained by Johnson’s rule
correctly.

**Proof.**  
The simulation follows the definition of a two‑machine flow shop:
`alpha_time` is the completion time of the current job on machine 1,
`beta_time` is the completion time of the previous job on machine 2.
The formula `beta_time = max(alpha_time, beta_time) + b` exactly implements
the start‑when‑both‑ready rule. By induction over the processed jobs,
`beta_time` after the `k`‑th iteration equals the finish time of job `k` on
machine 2. Hence after the last job it equals the makespan. ∎



##### Theorem  
The program outputs the smallest possible time at which the last vessel
finishes its Beta phase.

**Proof.**  
By Lemma 3 Johnson’s rule gives an order with minimum possible makespan.
The program builds exactly this order (Lemma 2 and construction) and
calculates its makespan correctly (Lemma 4). Therefore the printed value is the
global optimum. ∎

#### 5.   Complexity Analysis

*Splitting into groups, sorting* – `O(j log j)` time, `O(j)` memory.  
*Simulation* – `O(j)` time, `O(1)` extra memory.

Overall: `O(j log j)` time, `O(j)` memory, well within the limits (`j ≤ 200 000`).

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    n = data[0]
    it = iter(data[1:])
    early = []   # a <= b
    late = []    # a > b
    for a, b in zip(it, it):
        if a <= b:
            early.append((a, b))
        else:
            late.append((a, b))

    early.sort(key=lambda x: x[0])          # increasing a
    late.sort(key=lambda x: -x[1])          # decreasing b
    order = early + late

    alpha_time = 0
    beta_time = 0
    for a, b in order:
        alpha_time += a                     # finish of Alpha
        beta_time = max(alpha_time, beta_time) + b
    print(beta_time)

if __name__ == "__main__":
    solve()
```

the required input / output format.
