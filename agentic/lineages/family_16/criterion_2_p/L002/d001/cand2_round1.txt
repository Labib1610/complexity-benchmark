# Problem B — Canal Sequence

Time limit: 1 s   Memory limit: 256 MB

## Description

A canal authority needs to schedule a fleet of **j** ships through a waterway that features two consecutive narrow locks: the Upper Lock and the Lower Lock. Every ship must traverse the Upper Lock first, and then the Lower Lock. You are provided with the time each ship requires to clear the Upper Lock, followed by the time it requires to clear the Lower Lock.

The navigation rules are as follows:
- A lock can accommodate only one ship at a time.
- After a ship clears the Upper Lock, it waits in an intermediate basin until the Lower Lock is available. The Upper Lock is immediately free to accept the next ship.
- A ship can only begin its transit through the Lower Lock after it has completely finished its transit through the Upper Lock.
- The intermediate basin has enough space for any number of waiting ships, but it is too narrow for ships to pass one another. Consequently, the fleet must enter the Lower Lock in the exact same sequence that they entered the Upper Lock.

You must decide the initial sequence in which the fleet enters the canal. Choose the sequence that minimizes the time at which the **last** ship finishes clearing the Lower Lock. Report that smallest possible finish time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the time required for a ship to clear the Upper Lock and the Lower Lock, respectively.

## Output

Print a single integer: the smallest possible time at which all ships have completely cleared the Lower Lock.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, the single ship takes 5 to clear the Upper Lock and then 3 to clear the Lower Lock, finishing at time 8.

<RATIONALE>
Removed the explicit "two operations" and "processed" terminology that strongly hinted at a factory or machine scheduling problem. Replaced it with a physical canal-routing scenario where the flow-shop constraints (no passing, sequential bottlenecks, infinite buffer) emerge from the physical properties of the locks and basins, forcing the model to deduce the mathematical structure rather than pattern-match the classical problem description.
</RATIONALE>
<PRESERVED_ANSWER>
The physical constraints perfectly mirror a 2-machine permutation flow-shop, so the minimum makespan and the optimal sequence remain mathematically identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to a 2-machine flow-shop makespan minimization, which is solvable in O(n log n) time using Johnson's rule.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the intermediate basin as adding a transit delay, but the phrasing "waits ... until available" and omitting any mention of transit time between locks should prevent this.
</RISK>
