We need to arrange the manuscripts to minimize the maximum possible total time, where the reviewer chooses the transition point to maximize the sum.

Let’s restate the problem:

We have `j` manuscripts, each with `p1` (physical time) and `p2` (digital time).  
We arrange them in some order.  
The reviewer picks a `k` (1 ≤ k ≤ j) and computes:

\[
T(k) = \sum_{i=1}^{k} p1_i + \sum_{i=k}^{j} p2_i
\]

The reviewer will pick the `k` that maximizes `T(k)`.  
We want to arrange the manuscripts to minimize that maximum.

---

### Key observation

For a given arrangement, the maximum over `k` is:

\[
\max_{1 \le k \le j} \left( \sum_{i=1}^{k} p1_i + \sum_{i=k}^{j} p2_i \right)
\]

We can rewrite:

\[
\sum_{i=1}^{k} p1_i + \sum_{i=k}^{j} p2_i
= \left( \sum_{i=1}^{j} p2_i \right) + \sum_{i=1}^{k} (p1_i - p2_i)
\]

Let `S = sum(p2)` and `d_i = p1_i - p2_i`.  
Then:

\[
T(k) = S + \sum_{i=1}^{k} d_i
\]

The maximum over `k` is:

\[
S + \max_{1 \le k \le j} \left( \sum_{i=1}^{k} d_i \right)
\]

We want to minimize this maximum prefix sum of `d_i`.

---

### Strategy

We can arrange the `d_i` values in any order.  
The maximum prefix sum is minimized when we sort `d_i` in **non-decreasing** order (i.e., smallest first).  
Why? Because putting negative numbers first reduces the prefix sum early, and putting large positives later keeps the maximum prefix sum as low as possible.

So:

- Compute `d_i = p1_i - p2_i` for each manuscript.
- Sort `d_i` ascending.
- Compute prefix sums, find the maximum prefix sum.
- Answer = `S + max_prefix_sum`.

---

---

### Correct derivation

We have:

\[
T(k) = \sum_{i=1}^{k} p1_i + \sum_{i=k}^{j} p2_i
\]

Note: The second sum includes `p2_k` as well.  
So:

\[
T(k) = \sum_{i=1}^{k} p1_i + \sum_{i=k}^{j} p2_i
= \sum_{i=1}^{k} p1_i + \sum_{i=1}^{j} p2_i - \sum_{i=1}^{k-1} p2_i
\]

Wait, careful:  
\(\sum_{i=k}^{j} p2_i = \sum_{i=1}^{j} p2_i - \sum_{i=1}^{k-1} p2_i\)

So:

\[
T(k) = \sum_{i=1}^{k} p1_i + S - \sum_{i=1}^{k-1} p2_i
= S + \sum_{i=1}^{k} p1_i - \sum_{i=1}^{k-1} p2_i
\]

That is:

\[
T(k) = S + p1_k + \sum_{i=1}^{k-1} (p1_i - p2_i)
\]

So:

\[
T(k) = S + p1_k + \sum_{i=1}^{k-1} d_i
\]

Where \(d_i = p1_i - p2_i\).

Now the maximum over k is:

\[
\max_{1 \le k \le j} \left( S + p1_k + \sum_{i=1}^{k-1} d_i \right)
\]

We want to minimize this.

---

### Rearrangement

We can think of each manuscript as having two values: `p1` and `d = p1 - p2`.  
The expression for a given k is:

\[
S + \left( p1_k + \sum_{i=1}^{k-1} d_i \right)
\]

We can choose the order.

This is similar to a scheduling problem: we want to minimize the maximum of (prefix sum of d up to k-1) + p1_k.

---

### Known approach

This is a classic problem: minimize the maximum of (prefix sum of d) + p1 of the next item.  
The optimal order is to sort by `p1` descending? Or by `d`? Let's test.

We can try sorting by `p1` descending:  
Example: (3,2) p1=3, d=1; (2,4) p1=2, d=-2; (1,3) p1=1, d=-2  
Sort by p1 desc: (3,2), (2,4), (1,3)  
k=1: S + p1_1 = 9+3=12  
k=2: S + p1_2 + d_1 = 9+2+1=12  
k=3: S + p1_3 + d_1+d_2 = 9+1+1-2=9  
Max=12.

Sort by d ascending: (1,3), (2,4), (3,2)  
k=1: 9+1=10  
k=2: 9+2+(-2)=9  
k=3: 9+3+(-2-2)=8  
Max=10. That works.

So sorting by d ascending works here.

But earlier we tried (1,3), (3,2), (2,4) also gave 10.  
Let's check if sorting by d ascending always works.

---

### Proof sketch

We want to minimize \(\max_k (p1_k + \sum_{i<k} d_i)\).  
This is like: we have items with "cost" d_i and "final" p1_i.  
The maximum is minimized when we put items with smaller d first, because that keeps the prefix sum low.  
But we also need to consider p1_k.  
If we sort by d ascending, the prefix sum of d is minimized at every step, but p1_k might be large.  
However, the maximum is over all k, so we need to balance.

Actually, the optimal strategy is to sort by `d` ascending, and if there's a tie, sort by `p1` descending? Let's test.

Example:  
(5,1) d=4, p1=5  
(1,5) d=-4, p1=1  
S = 1+5=6  
Sort by d asc: (1,5), (5,1)  
k=1: 6+1=7  
k=2: 6+5+(-4)=7  
Max=7.

If we swap: (5,1), (1,5)  
k=1: 6+5=11  
k=2: 6+1+4=11  
Max=11. So d asc is better.

Another:  
(10,1) d=9, p1=10  
(1,10) d=-9, p1=1  
S=11  
d asc: (1,10), (10,1)  
k=1: 11+1=12  
k=2: 11+10-9=12  
Max=12.

If we swap: (10,1), (1,10)  
k=1: 11+10=21  
k=2: 11+1+9=21  
Max=21. So d asc better.

So sorting by d ascending seems optimal.

### Implementation

- Read j
- Read pairs
- Compute S = sum(p2)
- Compute d = p1 - p2 for each
- Sort by d ascending (if tie, maybe by p1 descending? But not needed for correctness? Let's check tie case.)

Tie case:  
(3,1) d=2, p1=3  
(2,0) d=2, p1=2  
S=1+0=1  
Sort by d asc (both 2): order doesn't matter?  
If (3,1) first: k=1: 1+3=4; k=2: 1+2+2=5 → max=5  
If (2,0) first: k=1: 1+2=3; k=2: 1+3+2=6 → max=6  
So we should put larger p1 later when d equal? Actually we want to minimize max, so we want smaller p1 early? Let's see:  
If d equal, the prefix sum of d is same, but p1_k matters.  
We want to minimize max(p1_k + prefix_d).  
If d equal, prefix_d is same for all positions, so we want to put smaller p1 early? Actually p1_k is added at position k, so we want to put larger p1 later? Let's test:  
d=2 for both, prefix_d before k:  
If order A: p1=3 first, p1=2 second:  
k=1: p1=3 + 0 = 3  
k=2: p1=2 + 2 = 4 → max=4  
If order B: p1=2 first, p1=3 second:  
k=1: 2+0=2  
k=2: 3+2=5 → max=5  
So order A (larger p1 first) gives max=4, which is better.  
So when d equal, we should put larger p1 first? Wait, that seems counterintuitive but works because the prefix sum of d is same, so the later p1 gets added to a larger prefix sum, so we want the larger p1 earlier? Actually in order A, the larger p1 is at k=1, so it gets added to prefix 0, giving 3. The smaller p1 at k=2 gets added to prefix 2, giving 4. Max=4.  
In order B, smaller p1 at k=1 gives 2, larger p1 at k=2 gives 3+2=5, max=5.  
So we want larger p1 earlier when d equal? That seems to reduce the max because the larger p1 is added to a smaller prefix sum.  
So sort by d ascending, and if tie, sort by p1 descending.

---

### Final algorithm

1. Read j
2. Read pairs, compute S = sum(p2)
3. Create list of (d, p1) where d = p1 - p2
4. Sort by d ascending, then by p1 descending
5. Compute prefix sum of d, and for each k compute S + p1_k + prefix_d_before_k
6. Take max over k
7. Output that max

---

### Complexity

O(j log j) for sorting, fine for j ≤ 200000.

---

### Code

```python
def solve():
    import sys
    input = sys.stdin.readline
    j = int(input())
    items = []
    S = 0
    for _ in range(j):
        p1, p2 = map(int, input().split())
        S += p2
        d = p1 - p2
        items.append((d, p1))
    # sort by d ascending, then p1 descending
    items.sort(key=lambda x: (x[0], -x[1]))
    prefix_d = 0
    ans = 0
    for d, p1 in items:
        ans = max(ans, S + p1 + prefix_d)
        prefix_d += d
    print(ans)

if __name__ == "__main__":
    solve()
```
