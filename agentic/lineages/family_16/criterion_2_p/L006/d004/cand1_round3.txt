<METHOD_NAME>Grid Path Equivalence</METHOD_NAME>
<METHOD_DESCRIPTION>Transforms the two-machine flow shop makespan problem into its exact mathematical dual: minimizing the maximum path sum in a 2-by-j grid where rows can be permuted. This removes all scheduling terminology while preserving the exact recurrence relation.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Problem B — Grid Stack

Time limit: 1 s   Memory limit: 256 MB

## Description

You are given **j** tiles. Each tile has two values printed on it: a left value (**p1**) and a right value (**p2**).

You must arrange all **j** tiles into a single vertical column, placing them into positions $1, 2, \dots, j$ from top to bottom. Let $p1_i$ and $p2_i$ be the left and right values of the tile assigned to position $i$.

Once the tiles are arranged, consider all possible paths from the top-left value to the bottom-right value. A valid path starts at the left value of the tile in position 1. From any left value at position $i$, a path can either move DOWN to the left value at position $i+1$, or move RIGHT to the right value at position $i$. From any right value at position $i$, a path can only move DOWN to the right value at position $i+1$. The path ends when it reaches the right value of the tile in position $j$.

In other words, a valid path moves down the left side up to some chosen tile $k$ ($1 \le k \le j$), moves across to the right side of tile $k$, and then continues down the right side until tile $j$. The cost of a path is the sum of all values visited along the path, including the start and end values.

The *weight* of your chosen arrangement is the maximum cost among all valid paths through it.

Find an ordering of the **j** tiles that makes the weight of the arrangement as small as possible, and report this smallest possible weight.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the left value and the right value of a tile.

## Output

Print a single integer: the smallest possible weight.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, an optimal arrangement places the tiles in the order of the 3rd, 2nd, and 1st from the input.
- The 1st tile in the column is the 3rd input tile (left 1, right 3).
- The 2nd tile in the column is the 2nd input tile (left 2, right 4).
- The 3rd tile in the column is the 1st input tile (left 3, right 2).

There are three valid paths through this arrangement:
- Cross at tile 1: 1 (left) + 3 (right) + 4 (right) + 2 (right) = 10.
- Cross at tile 2: 1 (left) + 2 (left) + 4 (right) + 2 (right) = 9.
- Cross at tile 3: 1 (left) + 2 (left) + 3 (left) + 2 (right) = 8.
The maximum cost among these paths is 10. Thus, the weight of this arrangement is 10.
</STATEMENT>
<RATIONALE>
The problem was completely reframed from a scheduling task (two-machine flow shop) to a geometric/combinatorial task (minimizing the maximum path sum in a permutable 2-by-j grid). This forces the model to mathematically map the grid path recurrence to the flow-shop completion time recurrence, preventing it from blindly triggering Johnson's rule via scheduling keywords.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum path sum in a 2-by-j grid is mathematically identical to the makespan of a two-machine flow shop where row i corresponds to job i, the left column is machine 1, and the right column is machine 2.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly solvable in O(j log j) time using Johnson's rule, because the mathematical structure and objective function are strictly isomorphic to the original task.
</PRESERVED_CLASS>
