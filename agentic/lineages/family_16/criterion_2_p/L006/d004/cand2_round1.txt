<STATEMENT>
# Problem B — Tile Path Burden

Time limit: 1 s   Memory limit: 256 MB

## Description

You are given **j** rectangular tiles. Each tile has an upper value (**U**) and a lower value (**L**).

You must arrange all **j** tiles into a single horizontal sequence from left to right. This creates a grid with 2 rows and **j** columns, where the first row consists of the upper values and the second row consists of the lower values.

A valid path through this grid must start at the upper value of the leftmost tile and end at the lower value of the rightmost tile. From any cell, a path can only proceed in two directions:
- **Right**: moving to the cell in the exact same row in the adjacent tile to the right.
- **Down**: moving from the upper value to the lower value of the exact same tile.

The cost of a path is the sum of the values in all the cells it visits. 

Because of the movement rules, any valid path will travel rightwards along the upper row up to some tile $k$, move down at tile $k$, and then travel rightwards along the lower row from tile $k$ to the end.

The *burden* of a specific arrangement of tiles is defined as the maximum cost among all valid paths through it. 

Your objective is to find an arrangement of the **j** tiles that makes its burden as small as possible, and report this minimum possible burden.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **U** and **L** (1 ≤ U, L ≤ 1000000): the upper and lower values of a tile.

## Output

Print a single integer: the smallest possible burden.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, an optimal arrangement places the tiles in the order of the 3rd, 2nd, and 1st from the input.
The upper row is `1, 2, 3` and the lower row is `3, 4, 2`.
There are exactly three valid paths:
- Moving down at the 1st tile (visiting upper 1st, then lower 1st, lower 2nd, lower 3rd): cost is 1 + 3 + 4 + 2 = 10.
- Moving down at the 2nd tile (visiting upper 1st, upper 2nd, then lower 2nd, lower 3rd): cost is 1 + 2 + 4 + 2 = 9.
- Moving down at the 3rd tile (visiting upper 1st, upper 2nd, upper 3rd, then lower 3rd): cost is 1 + 2 + 3 + 2 = 8.
The burden of this arrangement is the maximum of these costs, which is 10. No arrangement has a burden less than 10.
</STATEMENT>
<RATIONALE>
Changed the domain from scheduling (2-machine flow shop) to a grid path problem. A sequence of 2-step jobs maps perfectly to finding a column permutation of a 2xN grid that minimizes the maximum right-down path sum. This forces the model to either mathematically prove the isomorphism to Johnson's rule or derive the sorting comparator from scratch.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum right-down path sum in a 2xN grid is exactly the makespan of a 2-machine flow shop with the same values, so the minimum possible maximum path sum is identical to the minimum makespan.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains solvable in O(j log j) time using Johnson's rule by sorting the columns based on the same conditions as the original problem.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "cost of a path is the sum of the values in all the cells it visits" if they think moving right and moving down somehow skips cells, but the note explicitly lists the cells visited to prevent this.
</RISK>
