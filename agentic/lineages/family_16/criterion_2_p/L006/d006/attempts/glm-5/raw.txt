Let me analyze the formula: V' = max(p2, V - p1 + p2)

The sum of p1 is constant regardless of order, so I need to minimize the final V.

Let me think about when V "grows" vs "stays at p2":
- If V - p1 + p2 > p2, i.e., V > p1, then V' = V - p1 + p2 (V grows by p2 - p1)
- If V ≤ p1, then V' = p2 (V resets to p2)

So stages where p2 > p1 are "positive" (they increase V when V > p1), and stages where p2 ≤ p1 are "non-positive".

**Key insight**: Once V exceeds some threshold, positive stages keep increasing V. The final V depends on:
1. The last "reset" stage (where V ≤ p1, so V becomes p2)
2. All subsequent positive stages that keep growing V

For the optimal strategy:
- Process non-positive stages (p2 ≤ p1) first, sorted by p1 ascending (to minimize resets)
- Then process positive stages (p2 > p1), sorted by p1 ascending (to trigger growth early)

import sys

def solve():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    j = int(input_data[idx]); idx += 1
    
    total_p1 = 0
    positive = []  # p2 > p1
    non_positive = []  # p2 <= p1
    
    for _ in range(j):
        p1 = int(input_data[idx]); idx += 1
        p2 = int(input_data[idx]); idx += 1
        total_p1 += p1
        if p2 > p1:
            positive.append((p1, p2))
        else:
            non_positive.append((p1, p2))
    
    # Sort positive by p1 ascending (so V stays above p1 once it exceeds)
    positive.sort(key=lambda x: x[0])
    # Sort non-positive by p1 ascending (minimize resets)
    non_positive.sort(key=lambda x: x[0])
    
    V = 0
    for p1, p2 in positive:
        if V > p1:
            V = V - p1 + p2
        else:
            V = p2
    
    for p1, p2 in non_positive:
        if V > p1:
            V = V - p1 + p2
        else:
            V = p2
    
    print(total_p1 + V)

solve()
