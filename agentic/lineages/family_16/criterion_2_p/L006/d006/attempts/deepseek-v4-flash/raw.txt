We can solve this by noticing that the update rule  
\( V' = \max(p2, V - p1 + p2) \)  
can be rewritten as:  
\( V' = \max(p2, V + (p2 - p1)) \).  

If we define \( d = p2 - p1 \), then each stage either:
- Raises the signal by \( d \) if \( d > 0 \) and \( V \) is high enough,
- Or sets it to at least \( p2 \).

The key is to sort stages so that we minimize the final \( V \).  
It turns out the optimal order is to sort by \( p2 \) descending, and if equal, by \( p1 \) descending.  

Here’s the implementation:  

```python
import sys

def solve():
    data = sys.stdin.buffer.read().split()
    j = int(data[0])
    stages = []
    idx = 1
    for _ in range(j):
        p1 = int(data[idx])
        p2 = int(data[idx+1])
        idx += 2
        stages.append((p1, p2))
    
    # Sort by p2 descending, then p1 descending
    stages.sort(key=lambda x: (-x[1], -x[0]))
    
    V = 0
    sum_p1 = 0
    for p1, p2 in stages:
        sum_p1 += p1
        V = max(p2, V - p1 + p2)
    
    print(sum_p1 + V)

if __name__ == "__main__":
    solve()
```
