**Solution Explanation**

For every vat (vertex) exactly three tubes (edges) are incident.
We have to colour every edge with one of the three colours `1,2,3` such that
the three incident edges of every vertex have three different colours.
In graph‑theoretic terms we need a *proper 3‑edge‑colouring* of a
cubic (3‑regular) graph.

--------------------------------------------------------------------

#### 1.   Observations  

* A cubic graph that contains a bridge can never be 3‑edge‑coloured.
  In a bridge the two incident vertices would need three different colours
  but only one edge connects the two parts – impossible.

* A **bridgeless** cubic graph is always 3‑edge‑colourable
  (Petersen’s theorem).  
  A constructive proof is:
  1. find a *perfect matching* `M` (every vertex belongs to exactly one edge of `M`);
  2. delete `M`.  
     Every vertex now has degree `2`, therefore the remaining graph is a
     disjoint union of cycles;
  3. colour all edges of `M` with colour `1`;
  4. on each cycle colour edges alternately `2,3`.

  The obtained colouring is proper, because at each vertex the three
  incident edges are exactly one from `M` (colour 1) and the two neighbours
  on the cycle (colours 2 and 3).

Consequently the whole task reduces to

```
if the graph has a bridge → answer NO
else
        find a perfect matching
        colour as described → answer YES
```

--------------------------------------------------------------------

#### 2.   Finding bridges  

A standard depth‑first search computes low‑link values in `O(n+m)`.
If an edge `(u,v)` (`u` is the DFS parent of `v`) satisfies  
`low[v] > tin[u]` it is a bridge.

--------------------------------------------------------------------

#### 3.   Perfect matching in a general graph  

The graph is not bipartite, therefore we need Edmonds’ blossom algorithm.
The implementation below follows the well‑known `O(n³)` version
(also known as “Gabow‑Edmonds”).
With `n ≤ 2000` and `m = 3n/2 ≤ 3000` it easily fits into the limits
(about a few million elementary operations).

The algorithm returns a list `mate[v]` (`mate[v] = u` if `v` is matched with `u`,
`-1` otherwise).  
Because the graph is cubic and has no bridges, a perfect matching is guaranteed
to exist; we nevertheless check that every vertex is matched.

--------------------------------------------------------------------

#### 4.   Constructing the final colouring  

* For every edge `i` (input order) we store its ends `a[i], b[i]`.
* If `mate[a[i]] == b[i]` the edge belongs to the perfect matching → colour `1`.
* All other edges form a 2‑regular graph.
  We traverse each connected component (simple cycle) with a DFS,
  alternating colours `2` and `3`.

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct colouring
iff such a colouring exists.

---

##### Lemma 1  
If the input graph contains a bridge, no proper 3‑edge‑colouring exists.

**Proof.**  
Consider a bridge `e = (x,y)`. Removing `e` disconnects the graph.
In any proper 3‑edge‑colouring the three edges incident to `x` must have
different colours, the same for `y`.  
All three colours already appear on the three edges incident to `x`;
the only edge that can give a colour to `y` from the side of `x` is `e`,
hence `y` would receive the same colour twice – contradiction. ∎



##### Lemma 2  
If the graph is bridgeless cubic, the blossom algorithm returns a perfect
matching.

**Proof.**  
Petersen’s theorem states that every bridgeless cubic graph has a perfect
matching. The blossom algorithm is exact: it finds a maximum matching in any
graph. Because a perfect matching exists, the maximum size is `n/2`,
hence the algorithm returns a perfect matching. ∎



##### Lemma 3  
After removing a perfect matching `M` from a cubic graph, the remaining
graph is a disjoint union of cycles.

**Proof.**  
Every vertex loses exactly one incident edge (the one belonging to `M`);
its degree drops from `3` to `2`. A graph where every vertex has degree `2`
is a collection of cycles (possibly a single cycle). ∎



##### Lemma 4  
Colouring all edges of `M` with colour 1 and, on each cycle of the
remaining graph, alternating colours 2 and 3 yields a proper 3‑edge‑colouring.

**Proof.**  
Take any vertex `v`.  
Exactly one incident edge of `v` lies in `M` → colour 1.  
The other two incident edges are consecutive edges of the unique cycle that
contains `v`; by construction they receive different colours (`2` and `3`).
Thus the three incident edges of `v` have three distinct colours.
Since this holds for every vertex, the edge colouring is proper. ∎



##### Lemma 5  
If the algorithm outputs `YES` and a colour sequence, this sequence is a
valid solution.

**Proof.**  
`YES` is printed only when
* no bridge was found, and
* a perfect matching covering all vertices was obtained.

The subsequent construction follows Lemma&nbsp;4, therefore the produced
colouring is proper. ∎



##### Lemma 6  
If a proper 3‑edge‑colouring exists, the algorithm never prints `NO`.

**Proof.**  
A proper 3‑edge‑colouring implies, in particular, that the graph has no bridge
(Lemma&nbsp;1). Hence the bridge test passes.
For a bridgeless cubic graph a perfect matching exists (Lemma&nbsp;2), so the
blossom algorithm finds one and the matching covers all vertices.
Consequently the algorithm reaches the colouring phase and prints `YES`. ∎



##### Theorem  
The algorithm prints `YES` followed by a correct assignment
iff such an assignment exists; otherwise it prints `NO`.

**Proof.**  
*If the algorithm prints `YES`* – by Lemma&nbsp;5 the assignment is correct,
hence a solution exists.

*If a solution exists* – by Lemma&nbsp;1 the graph has no bridge,
the bridge test succeeds; by Lemma&nbsp;2 a perfect matching is found,
so the algorithm proceeds to the colouring step and prints `YES`.
Thus it never prints `NO`. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Bridge detection* : `O(n + m)`  
*Blossom maximum matching* : `O(n³)` → with `n ≤ 2000` at most `8·10⁹`
operations in the worst theoretical bound, but the practical constant is
tiny; for the given sparse graphs it runs well below the time limit.  

*Cycle traversal & colouring* : `O(n + m)`  

Memory consumption: adjacency lists, matching arrays, etc. – `O(n + m)`  
( ≤ 5000 integers ), far below the 256 MiB limit.

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(10000)

# ------------------------------------------------------------
# 1. read input
data = sys.stdin.read().strip().split()
if not data:
    sys.exit()
it = iter(data)
n = int(next(it))
m = int(next(it))
edges = []
adj = [[] for _ in range(n)]
for idx in range(m):
    u = int(next(it)) - 1
    v = int(next(it)) - 1
    edges.append((u, v))
    adj[u].append((v, idx))
    adj[v].append((u, idx))

# ------------------------------------------------------------
# 2. bridge detection
tin = [-1] * n
low = [0] * n
timer = 0
has_bridge = False

def dfs(v, p):
    global timer, has_bridge
    tin[v] = low[v] = timer
    timer += 1
    for to, _ in adj[v]:
        if to == p:
            continue
        if tin[to] != -1:
            low[v] = min(low[v], tin[to])
        else:
            dfs(to, v)
            low[v] = min(low[v], low[to])
            if low[to] > tin[v]:
                has_bridge = True

dfs(0, -1)
if has_bridge:
    print("NO")
    sys.exit()

# ------------------------------------------------------------
# 3. Edmonds' blossom algorithm (maximum matching)
from collections import deque

def blossom_maximum_matching(n, g):
    # g: adjacency list of vertices (list of lists)
    INF = n + 5
    match = [-1] * n
    base = list(range(n))
    p = [-1] * n
    q = deque()
    used = [False] * n
    blossom = [False] * n

    def lca(a, b):
        used_path = [False] * n
        while True:
            a = base[a]
            used_path[a] = True
            if match[a] == -1:
                break
            a = p[match[a]]
        while True:
            b = base[b]
            if used_path[b]:
                return b
            b = p[match[b]]

    def mark_path(v, b, children):
        while base[v] != b:
            blossom[base[v]] = blossom[base[match[v]]] = True
            p[v] = children
            children = match[v]
            v = p[match[v]]

    def find_path(root):
        nonlocal used, p, base, q, blossom
        used = [False] * n
        p = [-1] * n
        for i in range(n):
            base[i] = i
        q.clear()
        q.append(root)
        used[root] = True
        while q:
            v = q.popleft()
            for to in g[v]:
                if base[v] == base[to] or match[v] == to:
                    continue
                if to == root or (match[to] != -1 and p[match[to]] != -1):
                    cur = lca(v, to)
                    blossom[:] = [False] * n
                    mark_path(v, cur, to)
                    mark_path(to, cur, v)
                    for i in range(n):
                        if blossom[base[i]]:
                            base[i] = cur
                            if not used[i]:
                                used[i] = True
                                q.append(i)
                elif p[to] == -1:
                    p[to] = v
                    if match[to] == -1:
                        # augmenting
                        v = to
                        while v != -1:
                            pv = p[v]
                            nv = match[pv] if pv != -1 else -1
                            match[v] = pv
                            match[pv] = v
                            v = nv
                        return True
                    else:
                        used[match[to]] = True
                        q.append(match[to])
        return False

    for v in range(n):
        if match[v] == -1:
            find_path(v)
    return match

# build simple adjacency list for blossom (no edge indices needed)
g = [[] for _ in range(n)]
for u, v in edges:
    g[u].append(v)
    g[v].append(u)

mate = blossom_maximum_matching(n, g)

if any(x == -1 for x in mate):
    print("NO")
    sys.exit()

# ------------------------------------------------------------
# 4. colour edges
color = [0] * m
# colour 1 for matching edges
for idx, (u, v) in enumerate(edges):
    if mate[u] == v:
        color[idx] = 1

# build adjacency of remaining edges (those not coloured yet)
rem_adj = [[] for _ in range(n)]
for idx, (u, v) in enumerate(edges):
    if color[idx] == 0:
        rem_adj[u].append((v, idx))
        rem_adj[v].append((u, idx))

visited_edge = [False] * m

for start in range(n):
    for to, eid in rem_adj[start]:
        if visited_edge[eid]:
            continue
        # walk the whole cycle
        cycle = []
        cur = start
        prev = -1
        while True:
            # find the unused edge from cur that is not the edge we came from
            for nxt, neid in rem_adj[cur]:
                if visited_edge[neid]:
                    continue
                if nxt == prev:
                    continue
                # this is the next edge
                visited_edge[neid] = True
                cycle.append(neid)
                prev, cur = cur, nxt
                break
            else:
                # should not happen
                break
            if cur == start:
                break
        # colour alternately 2,3
        for i, eid in enumerate(cycle):
            color[eid] = 2 if i % 2 == 0 else 3

print("YES")
print(' '.join(str(c) for c in color))
```
