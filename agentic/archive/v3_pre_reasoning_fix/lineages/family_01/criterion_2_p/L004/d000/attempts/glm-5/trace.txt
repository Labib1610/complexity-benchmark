Now, about the lexicographically smallest: Is there any case where the greedy assignment of 1 to the first unvisited vertex is not optimal because the graph is not bipartite? No, if not bipartite, we output NO.

But wait: What if the graph is bipartite but there are multiple valid colorings that are not just flips of each other? For a connected bipartite graph, there are exactly two colorings. For a disconnected graph, the number of colorings is 2^(number of components). The lexicographically smallest is obtained by choosing for each component the coloring that minimizes the sequence. Since the components are independent, we can decide the color of the first vertex of each component. But is it always optimal to set the first vertex of each component to 1? Let's test with a tricky example.

Suppose we have two components:
Component A: vertices {1, 3} with edge 1-3.
Component B: vertices {2, 4} with edge 2-4.
Possible colorings:
A: 1=1,3=2 or 1=2,3=1
B: 2=1,4=2 or 2=2,4=1
Sequences:
A1,B1: 1,1,2,2
A1,B2: 1,2,2,1
A2,B1: 2,1,1,2
A2,B2: 2,2,1,1
Lexicographically smallest: 1,1,2,2 (A1,B1). Greedy: i=1: A1 (1=1,3=2). i=2: B1 (2=1,4=2). So 1,1,2,2. Correct.

What if Component A: vertices {1, 4} edge 1-4. Component B: vertices {2, 3} edge 2-3.
A1: 1=1,4=2; A2: 1=2,4=1
B1: 2=1,3=2; B2: 2=2,3=1
Sequences:
A1,B1: 1,1,2,2
A1,B2: 1,2,1,2? Wait: A1: 1=1,4=2; B2: 2=2,3=1 -> seq: 1,2,1,2? Actually indices: 1:1, 2:2, 3:1, 4:2 -> 1,2,1,2.
A2,B1: 2,1,2,1? 1:2, 2:1, 3:2, 4:1 -> 2,1,2,1.
A2,B2: 2,2,1,1.
Smallest is 1,1,2,2. Greedy gives that.

Now consider a case where the first vertex of a component is not the one that would be 1 in the lexicographically smallest if we consider the whole sequence? Actually, for a given component, the two colorings are complements. The first vertex of that component (by index) will have color 1 in one and 2 in the other. The one with 1 is smaller at that index. So we must choose the one with 1. There's no scenario where choosing 2 for that vertex could lead to a smaller sequence overall, because at that index, 2 > 1, so any sequence with 2 at that index is lexicographically larger than one with 1, regardless of later indices. So we must set the first vertex of each component to 1. That is exactly what greedy does.

But wait: What if the component has only one vertex? Then the two "colorings" are 1 and 2. We choose 1. That's optimal.

So the greedy algorithm is correct.

Now, let's think about the implementation. We need to handle up to 2e5 vertices and 2e5 edges. Python's recursion limit might be hit if we use recursive DFS. So we use iterative BFS with deque. Or we can use a stack for DFS. BFS is fine.

We need to output "YES" and then the sequence. The sequence should be space-separated. The problem says "a second line with n integers s_1 ... s_n". So we print "YES" on first line, then the numbers on second line.

Now, check the example:
Example 1:
4 4
1 2
2 3
3 4
1 4
Graph: 1-2, 2-3, 3-4, 1-4. This is a cycle of length 4. Bipartite. Greedy: i=1: color[1]=1. BFS: 1->2 (color 2), 2->3 (color 1), 3->4 (color 2), 4->1 (already 1, ok). Sequence: 1,2,1,2. Output matches.

Example 2:
3 3
1 2
1 3
2 3
Triangle, not bipartite. Output NO.

Now, consider edge cases:
- n=1, m=0: Output YES, then 1.
- n=1, m=1 with self-loop? But m lines contain pairs of workers, likely u!=v. If u=v, it's impossible. We should handle it.
- Large n, m=0: all isolated vertices. Greedy assigns 1 to all. Output YES and n ones.
- Disconnected graph with multiple components.
- Graph with multiple edges: e.g., 1-2 appears twice. BFS will just see the edge again, color already set, no conflict. So fine.

Now, is there any case where the greedy assignment of 1 to the first unvisited vertex is not lexicographically smallest because of the order we traverse? No, as argued.

But wait: There is a known problem: "Bipartite graph coloring, lexicographically smallest". Sometimes, if the graph is not connected, the lexicographically smallest coloring might not be obtained by simply setting the first vertex of each component to 1. Why? Because the components are interleaved. For example, consider a graph with two components: Component A: vertices {1, 4} with edge 1-4. Component B: vertices {2, 3} with edge 2-3. We already saw greedy gives 1,1,2,2. But what if we have Component A: vertices {1, 3} with edge 1-3. Component B: vertices {2, 4} with edge 2-4. Greedy: i=1: A: 1=1,3=2. i=2: B: 2=1,4=2. Seq: 1,1,2,2. Is there a better? If we flip B: 2=2,4=1 -> seq: 1,2,2,1. Compare: 1,1,2,2 vs 1,2,2,1: at index 2, 1<2, so greedy is better. So greedy is correct.
