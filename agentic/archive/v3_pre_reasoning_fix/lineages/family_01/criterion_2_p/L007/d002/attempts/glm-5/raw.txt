Since we can always choose 1 for the smallest index in a component (by flipping the whole component), we should do so. For vertex 2, if it's in the same component as 1, its color is already determined by the choice for vertex 1. If we chose 1 for vertex 1, vertex 2's color is forced. Could we have chosen 2 for vertex 1 to make vertex 2 be 1? That would make vertex 1=2, which is worse than vertex 1=1, because lexicographic order cares more about earlier positions. So we should not. If vertex 2 is in a different component, we can independently choose its color. We should choose 1 if possible. So the greedy algorithm is optimal.

But wait: what if the graph is bipartite, but for some component, the smallest index vertex cannot be 1 because of some global constraint? There is no global constraint; components are independent. So it can always be 1.

- Read n, m.
- Build adjacency list for n vertices (1-indexed).
- For each edge, if u == v: impossible (but we can just let BFS detect it: if we process, a self-loop would mean when we try to color, we see neighbor same color? Actually, if u==v, then when we process u, we look at neighbors. If we assign u=1, then neighbor u should be 2, but it's 1, conflict. So BFS will detect it. But we can also early exit.)
- Initialize color array of size n+1 with 0.
- For i in 1..n:
    if color[i] == 0:
        color[i] = 1
        queue = deque([i])
        while queue:
            u = queue.popleft()
            for v in adj[u]:
                if color[v] == 0:
                    color[v] = 3 - color[u]  # 1->2, 2->1
                    queue.append(v)
                elif color[v] == color[u]:
                    print("NO")
                    return
- If we finish without conflict, print "YES" and the colors from 1 to n.

But wait: is this BFS guaranteed to produce the lexicographically smallest? Let's test a tricky case. Suppose we have a component with vertices 1,2,3,4 and edges: 1-2, 2-3, 3-4, 4-1 (cycle of 4). Smallest index 1 gets 1. Then 2 gets 2, 3 gets 1, 4 gets 2. Sequence: 1,2,1,2. What if we had a different component? It's fine.

But consider a component that is a tree: 1-2, 1-3. Smallest index 1 gets 1. Then 2 and 3 get 2. Sequence: 1,2,2. Is there a valid sequence with 1=1 that gives 1,1,2? No, because 1-2 edge requires different. So 1,2,2 is the only one with 1=1. What if we set 1=2? Then 2=1, 3=1. Sequence: 2,1,1. 1,2,2 is smaller. So correct.

Now, what if the graph has multiple components and we process in order. Suppose we have component A: vertices {2,3} with edge 2-3. Component B: vertex 1 isolated. Process 1: assign 1=1. Process 2: assign 2=1, 3=2. Sequence: 1,1,2. Is there a better? What if we assign 1=1, and for component A, we assign 2=2, 3=1? Sequence: 1,2,1. Compare: at index 2, 1 vs 2: 1 is smaller. So 1,1,2 is smaller. So greedy is correct.

But wait: what if the component's smallest index is not the first we encounter because we process in order? Actually, we process in order 1..n. So the first uncolored vertex we encounter is the smallest index among all uncolored vertices. That vertex is the smallest index in its component. So we assign it 1. That is optimal for that component. But could it be that by assigning 1 to that vertex, we force some other vertex in the same component to be 2, but if we had assigned 2 to that vertex, that other vertex would be 1, and since that other vertex has a smaller index than some vertex in a different component? No, because the other vertex in the same component has a larger index than the smallest index (since the smallest index is the first we encountered). So making the smallest index 1 is always better than making it 2, regardless of later vertices. So the greedy approach is correct.

But there is a catch: what if the graph is not connected, and we have a component where the smallest index is, say, 5. But we process vertices 1..4 first, which belong to other components. We assign them optimally. Then at 5, we assign 1. That's fine. But what if a component has vertices {2,4} and another has {1,3}? Process 1: assign 1=1, 3=2. Process 2: assign 2=1, 4=2. Sequence: 1,1,2,2. Is there a better sequence? What if we colored component {1,3} with 1=2, 3=1? Then sequence: 2,?,1,?. For component {2,4}, if we color 2=1, 4=2, sequence: 2,1,1,2. Compare 1,1,2,2 vs 2,1,1,2: at index 1, 1<2, so 1,1,2,2 is smaller. So greedy is correct.

But wait: what if the graph is bipartite, but for some component, the smallest index vertex cannot be 1 because of some global constraint? There is no global constraint; components are independent. So it can always be 1.

- For each edge, if u == v: impossible (but we can just let BFS detect it: if we process, a self-loop would mean when we try to color, we see neighbor same color? So 1,1,2 is smaller. So greedy is correct.

But wait: what if the component's smallest index is not the first we encounter because we process in order? Actually, we process in order 1..n. Smallest index 1 gets 1. Then 2 gets 2, 3 gets 1, 4 gets 2. Sequence: 1,2,1,2. What if we had a different component? It's fine.

But consider a component that is a tree: 1-2, 1-3. Smallest index 1 gets 1. Then 2 and 3 get 2. Sequence: 1,2,2. Is there a valid sequence with 1=1 that gives 1,1,2? No, because 1-2 edge requires different. So 1,2,2 is the only one with 1=1. What if we set 1=2? Then 2=1, 3=1. Sequence: 2,1,1. 1,2,2 is smaller. So correct.

Now, what if the graph has multiple components and we process in order. Suppose we have component A: vertices {2,3} with edge 2-3. Component B: vertex 1 isolated. Process 1: assign 1=1. Process 2: assign 2=1, 3=2. Sequence: 1,1,2. Is there a better? What if we assign 1=1, and for component A, we assign 2=2, 3=1? Sequence: 1,2,1. Compare: at index 2, 1 vs 2: 1 is smaller. So 1,1,2 is smaller. So greedy is correct.

But wait: what if the component's smallest index is not the first we encounter because we process in order? Actually, we process in order 1..n. So the first uncolored vertex we encounter is the smallest index among all uncolored vertices. That vertex is the smallest index in its component. So we assign it 1. That is optimal for that component. But could it be that by assigning 1 to that vertex, we force some other vertex in the same component to be 2, but if we had assigned 2 to that vertex, that other vertex would be 1, and since that other vertex has a smaller index than some vertex in a different component? No, because the other vertex in the same component has a larger index than the smallest index (since the smallest index is the first we encountered). So making the smallest index 1 is always better than making it 2, regardless of later vertices. So the greedy approach is correct.

But there is a catch: what if the graph is not connected, and we have a component where the smallest index is, say, 5. But we process vertices 1..4 first, which belong to other components. We assign them optimally. Then at 5, we assign 1. That's fine. But what if a component has vertices {2,4} and another has {1,3}? Process 1: assign 1=1, 3=2. Process 2: assign 2=1, 4=2. Compare 1,1,2,2 vs 2,1,1,2: at index 1, 1<2, so 1,1,2,2 is smaller. So greedy is correct.
