# Problem B — Pipeline Isolation Phase

Time limit: 1 s
Memory limit: 256 MB

In the automated deployment pipeline for the Aegis distributed architecture, the deployment process is divided into three distinct phases: telemetry acquisition, environment isolation, and payload routing. You are responsible for implementing the environment isolation phase.

During the telemetry acquisition phase, the system monitors $n$ service modules (numbered 1 through $n$) and generates a list of $m$ hardware conflicts. Each conflict specifies a pair of modules that compete for identical hardware resources.

In the isolation phase, you must allocate each of the $n$ modules to exactly one of two physical host environments, designated as Environment 1 and Environment 2. To guarantee stability, you must ensure that no two modules flagged in the same hardware conflict are allocated to the same environment.

The final payload routing phase requires a strictly deterministic configuration. Because there may be multiple valid ways to allocate the modules, the routing phase applies a sequential resolution rule to find the definitive plan. It evaluates the modules in order from 1 to $n$. For each module $i$ in turn, if there exists at least one valid overall allocation plan (which satisfies all hardware conflicts and respects all environment choices locked in for modules $1$ to $i-1$) where module $i$ is placed in Environment 1, then module $i$ is permanently locked to Environment 1. If no such valid overall plan exists, module $i$ is permanently locked to Environment 2.

If the telemetry constraints are inherently contradictory and no valid allocation exists at all, your phase must halt the pipeline by rejecting the configuration.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2\cdot 10^5$, $0 \le m \le 2\cdot 10^5$), representing the number of modules and the number of hardware conflicts, respectively.
Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$), representing a pair of modules that must not be assigned to the same environment.

## Output
If no valid allocation plan exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers (each either 1 or 2)—the final deterministic allocation plan for the modules.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I replaced the explicit request for the "lexicographically smallest" allocation with a sequential locking process that evaluates modules from 1 to $n$. This forces the model to deduce that this global sequential constraint satisfaction process is mathematically identical to finding the lexicographically smallest valid assignment, and that it can still be optimized by exploiting the independence of disconnected components rather than simulating the expensive validity check at each step.
</RATIONALE>
<PRESERVED_ANSWER>
The sequential locking rule evaluates modules in index order and prefers Environment 1 whenever it remains part of a valid overall assignment, which is the exact constructive definition of a lexicographically smallest sequence.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains solvable in $O(n+m)$ time by identifying connected components and assigning Environment 1 to the lowest-indexed module in each component, which is standard 2-coloring.
</PRESERVED_CLASS>
<RISK>
Some readers might misinterpret the sequential rule as a local greedy algorithm that ignores future constraints, though the text explicitly requires it to be part of a "valid overall allocation plan".
</RISK>
