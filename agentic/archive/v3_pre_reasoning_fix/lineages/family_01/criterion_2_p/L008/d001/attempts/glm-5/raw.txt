But wait: is there a case where setting the smallest index of a component to 1 forces a later vertex in that component to be 2, but if we set the smallest index to 2, that later vertex becomes 1, and that later vertex is smaller than some vertex in another component that we haven't processed yet? But the later vertex is in the same component, so its index is greater than the smallest index of that component. The other component's vertices might have indices between the smallest and that later vertex. For example: Component A: vertices {1, 4} edge 1-4. Component B: vertices {2, 3} edge 2-3. Smallest of A is 1, smallest of B is 2. Greedy: A: 1=1,4=2; B: 2=1,3=2. Sequence: 1,1,2,2. What if we chose A: 1=2,4=1; B: 2=1,3=2? Sequence: 2,1,2,1. At index 1, 1<2, so greedy better. What if we chose A: 1=1,4=2; B: 2=2,3=1? Sequence: 1,2,2,1. At index 2, 1<2, so greedy better. So greedy is best.

But is there any situation where the greedy choice for a component (setting its smallest index to 1) is not globally optimal because it forces a vertex in that component to be 2, and that vertex is smaller than some vertex in a component we haven't processed yet? No, because the smallest index of that component is the smallest in that component. Any other vertex in that component is larger. The components we haven't processed yet have smallest indices larger than the current vertex? Actually, we process in increasing order. When we are at vertex i, all vertices < i are already colored. Let's outline the algorithm:
- Read n, m.
- adj = [[] for _ in range(n+1)]
- For each edge: read u, v. If u == v: we can immediately mark as impossible? But we can just add to adj and let the BFS detect. However, if u==v, adding to adj will cause self-loop. - For i in 1..n:

    - color[i] = 1
    - queue = deque([i])
    - while queue:
        - u = queue.popleft()

            - if color[v] == 0:
                - color[v] = 3 - color[u]
                - queue.append(v)
            - elif color[v] != 3 - color[u]:
                - print("NO")
                - return
- If we finish without conflict:
  - print("YES")
  - print(" ".join(str(color[i]) for i in 1..n))
