# Problem B — Interfacing Thickness

Time limit: 1 s   Memory limit: 256 MB

A fashion designer is creating a complex garment made of $n$ fabric panels, numbered 1 to $n$. Each panel must be padded with either 1 or 2 layers of interfacing.

The cutting facility allocates exactly 100 hours per design, and can process a maximum of 2,000 panels per hour, which caps the total number of panels $n$ in the garment. The garment requires at least a single panel. The assembly instructions specify $m$ seams. The sewing machine receives instructions from a digital queue that can hold up to two hundred thousand seam commands, though a design might require no seams at all.

Each seam joins two specific panels together. To ensure the stitching needle passes through cleanly without breaking or leaving loose threads, any seam must pass through exactly 3 layers of interfacing in total between the two joined panels.

Your task is to determine if it is possible to choose the padding thickness for all $n$ panels such that every seam constraint is satisfied. Because the automated cutting machine processes panels in numerical order, if multiple valid configurations exist, you must output the one whose sequence of padding layers is lexicographically smallest.

## Input
The first line contains two integers $n$ and $m$ — the number of fabric panels and the number of seams, respectively. Their possible values are constrained by the facility limits mentioned above.
Each of the next $m$ lines contains two integers $u$ and $v$ indicating that a seam connects panel $u$ and panel $v$.

## Output
If no valid padding thickness sequence exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ (where each $s_i \in \{1, 2\}$), representing the lexicographically smallest valid sequence of padding layers.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```

<RATIONALE>
I removed the "opposite finishes" phrasing, replacing it with a requirement that the sum of layers on joined panels must be exactly 3, where each panel has 1 or 2 layers. This forces the model to deduce the mutual exclusion constraint rather than matching the "opposite" keyword to graph coloring. I also embedded the numeric bounds into the scenario description (e.g., 100 hours at 2,000 panels per hour) so the model must read and derive the constraints rather than extracting bare inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that the two layers $x, y \in \{1, 2\}$ sum to exactly 3 is mathematically identical to requiring $x \neq y$, preserving the exact same valid configurations and lexicographical tie-breaking.
</PRESERVED_ANSWER>

The problem remains a 2-SAT / bipartite graph checking problem, solvable in linear time using BFS or DFS to color each connected component.
</PRESERVED_CLASS>
