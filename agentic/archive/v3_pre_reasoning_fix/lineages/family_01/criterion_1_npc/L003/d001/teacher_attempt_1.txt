# Problem A — Factory Access Provisioning

Time limit: 2 s   Memory limit: 256 MB

A manufacturing plant is updating its employee onboarding workflow, which consists of four sequential stages:

1. **Recruitment:** Human resources finalizes the hiring of $n$ new employees, assigning each an ID from $1$ to $n$. The number of hires $n$ is at least 1 and reaches at most the physical limit of the orientation room (exactly 40 seats).
2. **Vetting:** The security team conducts background checks and generates $m$ risk reports. Each report identifies a pair of employees who have prior disputes. The number of reports $m$ is non-negative and reaches at most the theoretical maximum where every employee has a risk report with every other employee.
3. **Clearance:** The operations department must assign each employee a single shift token. The available tokens are stamped with the integer values 1, 2, and 3. To comply with safety regulations, whenever a risk report lists two employees, the system must ensure that the absolute difference between their assigned token values is strictly greater than zero.
4. **Badge Generation:** The IT department generates access badges based on the token assignments. If valid assignments exist, the system requires an ordered sequence of token values for employees $1$ through $n$. To maintain a deterministic database, if multiple valid configurations are possible, the system mandates the sequence that is lexicographically smallest. If no valid configuration can be formed without violating safety regulations, the HR system must be notified to halt the process.

Your task is to implement the software module that bridges Stage 2 and Stage 4. Given the number of employees and the risk reports, determine the token assignments required for Stage 4, or determine that the workflow must be halted.

## Input
The first line contains two integers $n$ and $m$ — the number of employees and the number of risk reports, constrained by the physical limits described above.
Each of the next $m$ lines contains two integers $u$ and $v$ — representing the IDs of the two employees listed in a single risk report.

## Output
If the workflow must halt because no valid token assignment is possible, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ (where each $s_i \in \{1, 2, 3\}$), representing the token value for employee $i$. Among all valid configurations, output the lexicographically smallest sequence (compare $s_1$ first, then $s_2$, and so on).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
Removed the direct inequalities in the Input section and instead embedded the limits within the scenario descriptions (e.g., orientation room capacity, theoretical maximum of unique pairs). Replaced the obvious "cannot be assigned the same work period" with a mathematical equivalent ("absolute difference ... is strictly greater than zero") to prevent keyword-based mapping to the 3-coloring problem. Models must now symbolically process the condition $|s_u - s_v| > 0$ to deduce the $s_u \neq s_v$ inequality.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that the absolute difference between token values must be strictly greater than zero is mathematically identical to requiring that the two values are not equal, preserving the exact same valid configurations and lexicographical tie-breaking rule.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to finding the lexicographically smallest 3-coloring of a graph, maintaining its NP-complete complexity.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "absolute difference is strictly greater than zero" as implying a difference of at least 2 if it forgets that token values are adjacent integers, but the clear token set {1, 2, 3} and the unambiguous mathematical phrasing mitigate this risk.
</RISK>
