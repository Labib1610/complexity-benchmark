# Problem A — RTOS Stage Allocation

Time limit: 2 s   Memory limit: 256 MB

A real-time operating system (RTOS) is being configured to run $n$ concurrent tasks, numbered $1$ to $n$. The system allocates task control blocks from a fixed 320-byte memory pool, where each task requires exactly an 8-byte block. Each task must be assigned exactly one execution stage: 1, 2, or 3.

During static analysis, the compiler identifies $m$ pairs of tasks that read and write to the same shared memory registers. To guarantee deterministic preemption and prevent race conditions, the RTOS arbiter enforces a non-linear separation rule. For any two tasks $u$ and $v$ that share memory registers, the arbiter computes a collision metric equal to $2^{s_u} + 2^{s_v}$, where $s_u$ and $s_v$ are their assigned execution stages. To avoid triggering a system fault, this metric must not be an exact power of two.

The configuration file requires the stage assignment to be listed as a sequence of $n$ integers, where the $i$-th integer is the stage of task $i$. To ensure the configuration is reproducible, if there are multiple valid assignments that satisfy all arbiter rules, the compiler must generate the sequence that is lexicographically smallest.

If it is impossible to assign stages to all tasks without violating the arbiter's rules, the compiler must abort the build.

## Input
The first line contains two integers $n$ and $m$ — the number of tasks and the number of pairs sharing memory registers. The value of $n$ is at least 1 and will not exceed the maximum number of tasks that can fit in the task control block pool. The value of $m$ is non-negative and will not exceed the total number of possible distinct pairs among the $n$ tasks.
Each of the next $m$ lines contains two integers $u$ and $v$ — representing a pair of tasks that share memory registers and therefore must satisfy the separation condition.

## Output
If no valid stage assignment is possible, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ (where each $s_i \in \{1, 2, 3\}$), representing the stage assigned to task $i$. Among all valid assignments, output the sequence that is lexicographically smallest (compare $s_1$ first, then $s_2$, and so on).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I replaced the "product is not a square" rule with the condition that "$2^{s_u} + 2^{s_v}$ must not be an exact power of two". This completely removes the affordance that allowed models to instantly pattern-match to a proper 3-coloring, forcing them to manually evaluate the new metric to discover that it merely enforces $s_u \neq s_v$. I also replaced the bare numerical bounds for $n$ and $m$ with physical memory pool limits and combinatoric descriptions to require indirect derivation.
</RATIONALE>
<PRESERVED_ANSWER>
The new collision metric $2^{s_u} + 2^{s_v}$ evaluates to a power of two if and only if $s_u = s_v$, perfectly matching the original "product is a square" rule for values in {1, 2, 3}, ensuring all valid assignments remain identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core problem remains exactly equivalent to finding a lexicographically smallest valid 3-coloring of a graph, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "exact power of two" to mean specifically $2^2$ or some other specific power, though standard mathematical terminology makes this unlikely.
</RISK>
