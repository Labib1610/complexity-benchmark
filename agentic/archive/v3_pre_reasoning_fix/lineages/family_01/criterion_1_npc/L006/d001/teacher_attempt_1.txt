<STATEMENT>
# Problem A — Deployment Tiers

Time limit: 2 s   Memory limit: 256 MB

A software system consists of $n$ microservices, identified by integers from 1 to $n$. You must assign each microservice to a security tier. The architecture supports a limited number of security tiers, identified by positive integers. The highest available tier number is restricted by the number of independent security protocols licensed by the system: Alpha, Beta, and Gamma. Therefore, the maximum valid tier integer exactly equals the total count of these licensed protocols.

Extensive testing has revealed that certain pairs of microservices exhibit parallel execution flaws. If a pair with this flaw operates at the exact same security tier, the system becomes unstable. To guarantee stability, the two microservices in any such pair must be assigned to different tiers.

You must determine a valid tier assignment for all $n$ microservices. If there are several valid ways to assign the tiers, you must prefer the configuration that assigns the lowest possible tier integer to microservice 1. If ties remain, you must break them by minimizing the tier integer assigned to microservice 2, continuing this element-by-element comparison up to microservice $n$. If no such configuration is possible, you must report this failure.

## Input
The first line provides $n$ and $m$ — the number of microservices and the number of flawed pairs. The number of microservices is at least one and does not exceed the mainframe's hardware limit of forty concurrent service slots. The number of flawed pairs $m$ ranges from zero up to the maximum number of unique pairs that can be formed from $n$ microservices.
The following $m$ lines each contain two integers $u$ and $v$, indicating that microservice $u$ and microservice $v$ share a parallel execution flaw.

## Output
If the system cannot be stabilized, output a single line with the word NO.
Otherwise, output YES on the first line. On the second line, output $n$ integers separated by spaces, representing the tiers assigned to microservices 1 through $n$ respectively, following the tie-breaking rules described above.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The explicit numeric bound "strictly less than 4" was replaced with a derived bound based on the count of three named security protocols (Alpha, Beta, Gamma). The explicit inequality bounds for $n$ and $m$ were also rewritten as physical limits and combinatorial maximums. This prevents models from using regex-like pattern matching on small integers to instantly classify the problem, forcing them to parse the scenario to deduce that exactly 3 states are available.
</RATIONALE>
<PRESERVED_ANSWER>
The valid tier identifiers (positive integers up to 3, meaning 1, 2, and 3), the conflict constraints, and the element-by-element minimization rule are logically identical to the seed, so the optimal assignment remains exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires assigning one of three distinct values to each element such that no two conflicting elements share a value, preserving its identity as the NP-complete 3-Coloring problem.
</PRESERVED_CLASS>
<RISK>
A model might fail to realize that "positive integers" up to a maximum of 3 strictly implies the set {1, 2, 3}, perhaps incorrectly including 0 if it ignores the word positive.
</RISK>
