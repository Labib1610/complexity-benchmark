The problem asks us to find the lexicographically smallest set of three vertices $\{a, b, c\}$ such that $a < b < c$ and there is an edge between $a$ and $b$, between $b$ and $c$, and between $a$ and $c$. In graph theory terms, we are looking for the lexicographically smallest 3-clique (triangle) in a given undirected graph.

Input constraints:
$n \le 2000$
$m \le 200,000$
A solution is guaranteed to exist.

The graph is undirected. The vertices are labeled $1$ to $n$.
We need to output $a, b, c$ such that $a < b < c$ and edges $(a, b), (b, c), (a, c)$ exist.
The lexicographically smallest condition means we want to minimize $a$, then minimize $b$, then minimize $c$.

Since $n$ is up to 2000, an $O(n^2)$ algorithm might be acceptable. $2000^2 = 4 \times 10^6$, which is well within the time limit of 2 seconds.
However, the number of edges $m$ is up to $2 \cdot 10^5$. A standard adjacency matrix would take $2000 \times 2000$ integers, which is fine for memory. Checking if an edge exists would be $O(1)$.

Let's consider the approach to find the lexicographically smallest triangle $(a, b, c)$ with $a < b < c$.
To minimize $a$, we should iterate $a$ from $1$ to $n$.
For a fixed $a$, we need to find the smallest $b > a$ such that there is an edge between $a$ and $b$.
Then, for that fixed pair $(a, b)$, we need to find the smallest $c > b$ such that there are edges between $(a, c)$ and $(b, c)$.

Algorithm:
1. Store the graph. Since we want to check edge existence quickly, an adjacency matrix `adj[n+1][n+1]` is suitable given $n \le 2000$. Or we can use adjacency lists `adj[u]` containing neighbors of `u`. Since we need to check intersection of neighbors, adjacency lists are good, but checking intersection efficiently depends on how we do it. An adjacency matrix allows $O(1)$ check. Given $N=2000$, a boolean matrix is small enough ($4 \times 10^6$ bytes $\approx 4$ MB).
2. Iterate $a$ from $1$ to $n-2$.
3. Iterate $b$ from $a+1$ to $n-1$.
4. Check if edge $(a, b)$ exists. If not, continue.
5. If edge $(a, b)$ exists, we need to find the smallest $c > b$ such that $c$ is connected to both $a$ and $b$.
   - We can iterate $c$ from $b+1$ to $n$.
   - Check if edges $(a, c)$ and $(b, c)$ exist.
   - If they do, we found our answer. Since we iterate $a$ then $b$ then $c$ in increasing order, the first one we find is guaranteed to be the lexicographically smallest.
   - Return/Print $a, b, c$ and terminate.
