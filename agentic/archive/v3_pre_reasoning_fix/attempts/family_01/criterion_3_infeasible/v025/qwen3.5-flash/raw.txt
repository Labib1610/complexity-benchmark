The problem asks us to find the lexicographically smallest triple of servers $(a, b, c)$ such that $1 \le a < b < c \le n$ and there are direct links between $(a, b)$, $(b, c)$, and $(a, c)$. We are given $n$ servers and $m$ edges. It is guaranteed that at least one such triple exists. The constraints are $n \le 2000$ and $m \le 2 \cdot 10^5$.

The problem is essentially finding a triangle in a graph. Since we need the lexicographically smallest triple $(a, b, c)$, we should iterate through possible values of $a$, then $b$, then $c$.

Let's consider the constraints. $N$ is up to 2000. A brute-force check of all triples $(a, b, c)$ would take $O(N^3)$ time, which is roughly $8 \cdot 10^9$ operations, too slow for a 2-second time limit. We need something more efficient, likely $O(N^2)$ or $O(M \sqrt{M})$ or similar.

Since we want the lexicographically smallest triple, we should iterate $a$ from $1$ to $n$. For a fixed $a$, we iterate $b$ from $a+1$ to $n$. If there is an edge between $a$ and $b$, we then look for a $c$ such that $b < c \le n$ and edges $(a, c)$ and $(b, c)$ exist. If we find such a $c$, then $(a, b, c)$ is a valid triple. Since we iterate $a$ and $b$ in increasing order, the first valid $c$ we find for a specific pair $(a, b)$ will be the smallest $c$ for that pair, and since $a$ and $b$ are minimized first, this will be the lexicographically smallest triple overall.

So the algorithm would be:
1. Store the graph. Since we need to check for edge existence efficiently, an adjacency matrix or adjacency sets would work. Given $N \le 2000$, an adjacency matrix `adj[N+1][N+1]` of booleans takes $2000^2$ bytes $\approx 4$ MB, which is well within the memory limit.
2. Iterate $a$ from $1$ to $n$.
3. Iterate $b$ from $a+1$ to $n$.
4. If there is an edge between $a$ and $b$:
    5. Iterate $c$ from $b+1$ to $n$.
    6. If there are edges between $(a, c)$ and $(b, c)$, then we found our answer $(a, b, c)$. Since we iterate in order, this is the lexicographically smallest. Return/Print and exit.

    # Fast I/O
    input_data = sys.stdin.read().split()

        n = int(next(iterator))
        m = int(next(iterator))

        for idx_b, b in enumerate(adj[a]):

import sys
from bisect import bisect_right

def solve():
    # Read all input from standard input efficiently
    input_data = sys.stdin.read().split()
    if not input_data:
        return

    iterator = iter(input_data)
    
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    # Adjacency list to store neighbors
    adj = [[] for _ in range(n + 1)]
    # Adjacency matrix using bytearray for O(1) edge check and memory efficiency
    # adj_mat[u][v] == 1 if edge exists, 0 otherwise
    adj_mat = [bytearray(n + 1) for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        adj[u].append(v)
        adj[v].append(u)
        adj_mat[u][v] = 1
        adj_mat[v][u] = 1

    # Sort adjacency lists to allow for ordered iteration and efficient slicing/indexing
    for i in range(1, n + 1):
        adj[i].sort()

    # Iterate through all possible vertices for 'a'
    for a in range(1, n + 1):
        # Iterate through neighbors of 'a' for 'b'
        # We use enumerate to keep track of the index in adj[a]
        for idx_b, b in enumerate(adj[a]):
            # We require a < b < c, so b must be greater than a
            if b <= a:
                continue
            
            # We need to find a vertex c such that c > b and edges (a, c) and (b, c) exist.
            # This means c must be in the intersection of adj[a] and adj[b].
            # To minimize the number of checks, we iterate over the smaller adjacency list.
            # The condition is: find smallest c > b in intersection.
            
            # If adj[a] is smaller or equal in size to adj[b]
            if len(adj[a]) <= len(adj[b]):
                # Iterate over neighbors of a that are strictly greater than b.
                # Since adj[a] is sorted and b is at index idx_b, the elements after idx_b are > b.
                # We iterate from idx_b + 1 to the end of adj[a].
                # This avoids using bisect_right on adj[a] and slicing, saving overhead.
                for idx_c in range(idx_b + 1, len(adj[a])):
                    c = adj[a][idx_c]
                    # Check if c is connected to b
                    if adj_mat[b][c]:
                        # Found the lexicographically smallest triple (a, b, c)
                        print(f"{a} {b} {c}")
                        return
            else:
                # If adj[b] is smaller, iterate over neighbors of b.
                # We need c > b. Since adj[b] is sorted, we find the first element > b using bisect_right.
                idx_c = bisect_right(adj[b], b)
                for k in range(idx_c, len(adj[b])):
                    c = adj[b][k]
                    # Check if c is connected to a
                    if adj_mat[a][c]:
                        print(f"{a} {b} {c}")
                        return
