The problem asks us to find the lexicographically smallest triplet of machine indices $(a, b, c)$ such that $a < b < c$ and all pairs $(a, b)$, $(a, c)$, and $(b, c)$ exist in the given list of interfering pairs. We are given $n$ machines and $m$ pairs. The constraints are $n \le 2000$ and $m \le 2 \cdot 10^5$. We are guaranteed that at least one such triplet exists.

This problem is essentially finding the lexicographically smallest triangle in a graph where vertices are machines and edges represent interference.

Since we need the lexicographically smallest triplet $(a, b, c)$ with $a < b < c$, we should iterate through possible values of $a$, then $b$, then $c$.
However, simply iterating through all triplets would take $O(n^3)$, which is too slow for $n=2000$ ($2000^3 = 8 \cdot 10^9$).
The number of edges $m$ is up to $2 \cdot 10^5$, which suggests an algorithm with complexity related to $m$ or $m \cdot n$ or $m \sqrt{m}$ might be acceptable, though $n \le 2000$ allows for $O(n^2)$ algorithms potentially.

Let's store the graph using an adjacency matrix or adjacency lists. Since we need to check existence of edges efficiently, an adjacency matrix `adj[n+1][n+1]` (boolean) allows $O(1)$ lookups. Given $n=2000$, an $2000 \times 2000$ boolean array takes about 4 MB, which is well within the 256 MB limit.

The strategy to find the lexicographically smallest triplet $(a, b, c)$ with $a < b < c$:
1. Iterate $a$ from $1$ to $n-2$.
2. Iterate $b$ from $a+1$ to $n-1$.
3. Iterate $c$ from $b+1$ to $n$.
4. Check if edges $(a, b)$, $(a, c)$, and $(b, c)$ exist.
5. If they do, return $(a, b, c)$.

The complexity of this naive approach is $O(n^3)$.

import sys

# Increase recursion depth just in case, though not used here
sys.setrecursionlimit(20000)

def solve():
    # Read all input from stdin
    input_data = sys.stdin.read().split()
    
    if not input_data:
        return
    
    iterator = iter(input_data)
    
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return
    
    # adj_mask[i] will store a bitmask of neighbors of machine i
    # bit j corresponds to machine j+1
    adj_mask = [0] * (n + 1)
    
    # adj_list[i] will store a sorted list of neighbors of i that are greater than i
    # This helps in iterating b > a efficiently
    adj_list = [[] for _ in range(n + 1)]
    
    # We also need to ensure adj_mask is fully populated for intersection checks
    # and adj_list is sorted for lexicographical order
    
    for _ in range(m):
        try:
            u = int(next(iterator))
            v = int(next(iterator))
            
            # Update adjacency mask
            # Machine u corresponds to bit u-1, Machine v to bit v-1
            adj_mask[u] |= (1 << (v - 1))
            adj_mask[v] |= (1 << (u - 1))
            
            # Populate adj_list
            # We only store neighbors > u in adj_list[u]
            # and neighbors > v in adj_list[v]
            if u < v:
                adj_list[u].append(v)
            else:
                adj_list[v].append(u)
                
        except StopIteration:
            break
            
    # Sort the neighbor lists to ensure we check b in increasing order
    # This is crucial for finding the lexicographically smallest triplet
    for i in range(1, n + 1):
        adj_list[i].sort()
        
    # Iterate through each machine 'a'
    for a in range(1, n + 1):
        # Optimization: If 'a' has no neighbors greater than 'a', we can't form a triangle with a < b < c
        # We can check this by checking if adj_mask[a] has any bit >= a set
        # adj_mask[a] has bit k set if machine k+1 is a neighbor
        # We need neighbors with index > a, i.e., machine index >= a+1, bit index >= a
        if (adj_mask[a] >> a) == 0:
            continue
            
        # Iterate through neighbors b of a such that b > a
        # adj_list[a] contains exactly these neighbors in sorted order
        for b in adj_list[a]:
            # We have established a < b and edge (a, b) exists.
            # Now we need to find the smallest c > b such that (a, c) and (b, c) exist.
            # c corresponds to a bit in adj_mask[a] and adj_mask[b].
            # We need smallest bit index k in common = adj_mask[a] & adj_mask[b] such that k >= b.
            # Note: bit index k corresponds to machine k+1.
            # Condition c > b means machine index c >= b+1, so bit index c-1 >= b.
            # So we need smallest bit index k >= b in common.
            
            common = adj_mask[a] & adj_mask[b]
            
            # Shift right by b to bring bit b to position 0.
            # Bits 0..b-1 are discarded.
            shifted = common >> b
            
            if shifted:
                # Find the lowest set bit in shifted
                lsb = shifted & -shifted
                
                # lsb is a power of 2, say 2^k.
                # The bit index in shifted is k.
                # The bit index in common is k + b.
                # The machine index c is (k + b) + 1 = k + b + 1.
                # lsb.bit_length() returns k + 1.
                # So c = (lsb.bit_length() - 1) + b + 1 = lsb.bit_length() + b.
                c = lsb.bit_length() + b
                
                # We found the lexicographically smallest triplet (a, b, c)
                print(f"{a} {b} {c}")
                return

    solve()
