The problem asks us to find the lexicographically smallest triple $(a, b, c)$ such that $1 \le a < b < c \le n$ and $a, b, c$ form a triangle (mutually conflicting). A triangle in this context means that the pairs $(a, b)$, $(b, c)$, and $(a, c)$ are all present in the input list of conflicts. We are guaranteed that at least one such triangle exists.

The constraints are:
$n \le 2000$
$m \le 2 \cdot 10^5$

Since we need to find the lexicographically smallest triple $(a, b, c)$, we should iterate through possible values of $a$, then $b$, then $c$.
The condition $a < b < c$ suggests we can fix $a$ first. To minimize $a$, we can iterate $a$ from $1$ to $n$.
For a fixed $a$, we want to find the smallest valid $b > a$ such that there exists a valid $c > b$ where $a, b, c$ form a triangle.
For a fixed $a$ and $b$, we need to check if there is a $c$ such that $(a, c)$ is an edge, $(b, c)$ is an edge, and $c > b$. Actually, the order condition is $a < b < c$. If we iterate $a$ from $1$ to $n$ and $b$ from $a+1$ to $n$, we just need to check if there exists any $c$ such that $c > b$ and edges $(a, c)$ and $(b, c)$ exist. Wait, if we find *any* such $c$, since we want the lexicographically smallest triple, for a fixed pair $(a, b)$, the smallest valid $c$ is the best one. So we should check for the existence of such $c$ and pick the smallest one. However, since we want the overall lexicographically smallest $(a, b, c)$, we just need to find the first pair $(a, b)$ (in lexicographical order) that completes a triangle, and then the smallest $c$ that completes it.
Actually, if we iterate $a$ from $1$ to $n$, and for each $a$, iterate $b$ from $a+1$ to $n$, the first time we find a pair $(a, b)$ that can be part of a triangle, the smallest valid $c$ for that pair will give the lexicographically smallest triple starting with $a, b$. Since we iterate $a$ in increasing order, and then $b$ in increasing order, the first such triple found is indeed the answer.

Let's refine the algorithm.
1. Store the graph. Since $n$ is up to 2000, an adjacency matrix or adjacency sets/lists would work. $O(n^2)$ space is roughly $4 \cdot 10^6$ integers, which is fine (a few MBs). Adjacency matrix is $O(1)$ lookup. Adjacency lists are more space-efficient but lookup is $O(deg)$. Given $m$ can be up to $2 \cdot 10^5$, the graph is relatively sparse compared to $n^2$ (max edges $\approx 2 \cdot 10^6$). An adjacency list or adjacency sets would be appropriate.
   Let's use an adjacency matrix `adj` of size $(n+1) \times (n+1)$ or simply a set of edges. With $N=2000$, a boolean matrix `is_adj[2005][2005]` is $2000^2 = 4 \times 10^6$ bytes $\approx 4$ MB, which is very small. This allows $O(1)$ check for existence of edge $(u, v)$.

2. Iterate $a$ from $1$ to $n$.
3. Iterate $b$ from $a+1$ to $n$.
   - If edge $(a, b)$ exists:
     - We need to find smallest $c > b$ such that $(a, c)$ and $(b, c)$ exist.
     - Iterate $c$ from $b+1$ to $n$.
       - If `is_adj[a][c]` and `is_adj[b][c]`:
         - Found the answer: print $a, b, c$ and exit.

Complexity analysis:
The loops are:
$a$ from $1$ to $n$
  $b$ from $a+1$ to $n$
    $c$ from $b+1$ to $n$
This is effectively iterating over all triples, $O(n^3)$.
With $n=2000$, $n^3 = 8 \cdot 10^9$, which is too slow for 2 seconds. We need a faster approach.

Optimization:
Instead of iterating $c$ for every pair $(a, b)$, notice that we only care about neighbors.
For a fixed $a$, we iterate through its neighbors $u$ such that $u > a$. Let's call these candidates for $b$.
For each such neighbor $b$, we need to find a common neighbor $c$ such that $c > b$.
So the algorithm becomes:
1. Build adjacency matrix `adj` (or adjacency lists).
2. Iterate $a$ from $1$ to $n$.
3. Iterate through neighbors $b$ of $a$ such that $b > a$.
   - We want to find the smallest $c$ such that $c > b$ and $c$ is a neighbor of both $a$ and $b$.
   - If we iterate neighbors, we can intersect the neighbor lists of $a$ and $b$.
   - Specifically, we need $c \in \text{neighbors}(a) \cap \text{neighbors}(b)$ and $c > b$.
   - To minimize $c$, we can just look at the intersection.
   - However, finding the intersection naively might still be slow if we do it inside the loops.
   - Also, we want to find the smallest $a$, then smallest $b$, then smallest $c$.
   
Let's restructure the loops.

    We need to find the smallest $c > b$ in neighbors($a$) $\cap$ neighbors($b$).
    Note that neighbors($a$) are the candidates for $c$ as well.
    So we are looking for $c \in \text{neighbors}(a)$ such that $c > b$ and $c$ is connected to $b$.
    Since we iterate $a$ in increasing order, and $b$ in increasing order (neighbors of $a$ sorted), the first valid triple we find will be the lexicographically smallest.

    Does iterating $a$, then $b$ (sorted), then finding smallest $c$ guarantee the global optimum?
    Yes.
    Suppose the optimal triple is $(a^*, b^*, c^*)$.
    Since we iterate $a$ from $1$ upwards, we will hit $a^*$ before any $a > a^*$.
    For a fixed $a$, if we iterate $b$ from smallest valid neighbor upwards, we will hit $b^*$ before any $b > b^*$.
    For fixed $a, b$, if we pick smallest valid $c$, we get $c^*$.
    So yes, the structure is:
      For $a = 1 \dots n$:
        Sort neighbors of $a$ that are $> a$.
        For $b$ in sorted neighbors of $a$ ($b > a$):
           Find smallest $c$ such that $c > b$, $c$ is neighbor of $a$, $c$ is neighbor of $b$.

```python
import sys

# Set recursion depth just in case, though not used.
sys.setrecursionlimit(2000)

def main():
    # Read all input from stdin
    input_data = sys.stdin.read().split()
    
    if not input_data:
        return

    iterator = iter(input_data)
    
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    # Adjacency list and adjacency masks
    # IDs are 1-based, so we use size n + 1
    adj = [[] for _ in range(n + 1)]
    adj_mask = [0] * (n + 1)

    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        
        adj[u].append(v)
        adj[v].append(u)
        
        # Set bit v in mask of u, and bit u in mask of v
        adj_mask[u] |= (1 << v)
        adj_mask[v] |= (1 << u)
        
    # Sort adjacency lists to ensure we iterate neighbors in increasing order
    for i in range(1, n + 1):
        adj[i].sort()
        
    # Iterate to find the lexicographically smallest triple (a, b, c)
    # We want to minimize a, then b, then c.
    # Iterate a from 1 to n
    for a in range(1, n + 1):
        # Iterate neighbors b of a
        # We only care about b > a to maintain a < b < c condition
        # and to avoid duplicate checks.
        # Since adj[a] is sorted, we encounter smaller b first.
        for b in adj[a]:

            # Common neighbors of a and b are given by the intersection of their adjacency masks.
            common = adj_mask[a] & adj_mask[b]
```

```python
import sys

def main():
    # Read all input from standard input
    input_data = sys.stdin.read().split()
    
    if not input_data:
        return

    iterator = iter(input_data)
    
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    # Adjacency list and adjacency masks
    # IDs are 1-based, so we use size n + 1
    adj = [[] for _ in range(n + 1)]
    adj_mask = [0] * (n + 1)
    
    # Read m edges
    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        
        adj[u].append(v)
        adj[v].append(u)
        
        # Set bit v in mask of u, and bit u in mask of v
        adj_mask[u] |= (1 << v)
        adj_mask[v] |= (1 << u)
        
    # Sort adjacency lists to ensure we iterate neighbors in increasing order
    for i in range(1, n + 1):
        adj[i].sort()
        
    # Iterate to find the lexicographically smallest triple (a, b, c)
    # We want to minimize a, then b, then c.
    # Iterate a from 1 to n
    for a in range(1, n + 1):
        # Iterate neighbors b of a
        # We only care about b > a to maintain a < b < c condition
        # and to avoid duplicate checks.
        # Since adj[a] is sorted, we encounter smaller b first.
        for b in adj[a]:
            if b <= a:
                continue
            
            # Check if there exists a c > b such that c is connected to both a and b.
            # Common neighbors of a and b are given by the intersection of their adjacency masks.
            common = adj_mask[a] & adj_mask[b]
            
            # We need c > b.
            # Create a mask that has 0s at positions 0 to b, and 1s elsewhere.
            # (1 << (b + 1)) - 1 creates a mask with 1s at 0..b.
            # ~((1 << (b + 1)) - 1) inverts it.
            # Note: Python integers are arbitrary precision, so ~x is -x-1 which behaves like infinite 1s.
            # ANDing with common (which is positive and finite) works correctly.
            
            c_mask = common & ~((1 << (b + 1)) - 1)
            
            if c_mask:
                # If c_mask is non-zero, there is at least one common neighbor > b.
                # We need the smallest such c.
                # The smallest set bit corresponds to the smallest c.
                # (c_mask & -c_mask) isolates the lowest set bit.
                # .bit_length() - 1 gives the index of that bit.
                c = (c_mask & -c_mask).bit_length() - 1
                print(f"{a} {b} {c}")
                return

if __name__ == '__main__':
    main()
```
