We need find lexicographically smallest triangle in undirected graph. n up to 2000, m up to 2e5. Brute force O(n^3) too high. Approach: adjacency sets. For lexicographically smallest triple (a,b,c), with a<b<c. Iterate a from 1..n. For each a, get neighbors > a. For each pair of neighbors (b,c) with b<c, check if edge between b and c exists. Need efficient.

We can for each a, list neighbors > a, sort them. Then for each pair (b,c) in that list, check adjacency matrix or hash. Since n max 2000, adjacency matrix 2000x2000 bits -> 4 million bools, ok. Use list of bitsets or Python set. Use adjacency list plus bitset via Python's built-in set for membership O(1). Approach: adjacency list as set for each node.

For each a: neighbors = [v for v in adj[a] if v>a]. Sort. For i in range(len(neighbors)): for j in range(i+1,len(neighbors)): b=neighbors[i]; c=neighbors[j]; if c in adj[b]: output a,b,c. Since we iterate a ascending, and neighbors sorted ascending, this yields lexicographically smallest. Complexity: For each a, we examine pairs of its higher neighbors. Worst-case degree ~ n. That's O(n^3). But n=2000, worst-case m=2e5, average degree 200. In worst-case dense graph, m ~ n^2/2 ~ 2e6 > limit, but m limited to 2e5, so average degree ~200. For a with 200 neighbors, pairs ~20k. For all a, sum over a of d_a^2 ~? In worst-case, one node has 2000 neighbors? Can't because m=200k. Suppose one node with degree 2000, others small. pairs for that node ~2M. That's okay? 2000 choose 2 = 1999000. That's near 2M. That's fine within 2s.

Thus algorithm fine.

Implementation details: read n,m. Build adjacency list as list of sets. Then main loop.

Edge case: ensure a<b<c. We only consider neighbors > a. So b> a and c> a. But we also need b<c. Our loops guarantee that.
