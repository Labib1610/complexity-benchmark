The problem asks us to find the lexicographically smallest triangle $(a, b, c)$ in a graph with $n$ nodes and $m$ edges, where $a < b < c$. The graph is guaranteed to have at least one triangle. The constraints are $n \le 2000$ and $m \le 2 \cdot 10^5$.

A triangle consists of three vertices $a, b, c$ such that edges $(a, b)$, $(b, c)$, and $(c, a)$ exist.
We need to find $a, b, c$ such that $a < b < c$ and the edges exist, minimizing $a$ first, then $b$, then $c$.

Let's represent the graph using an adjacency list or an adjacency matrix. Since $n \le 2000$, an adjacency matrix would take $2000^2$ integers/booleans, which is about 4 million entries, well within memory limits (256 MB). An adjacency matrix allows $O(1)$ edge lookups. However, iterating over all triplets would be $O(n^3)$, which is roughly $8 \cdot 10^9$ operations, too slow for a 2-second time limit.

We need a more efficient approach.
Since we want the lexicographically smallest triangle $(a, b, c)$, we should iterate through possible values of $a$, then $b$, then $c$.
The outer loops will be:
Iterate $a$ from $1$ to $n$.
  Iterate $b$ from $a+1$ to $n$.
    If edge $(a, b)$ exists:
      Iterate $c$ from $b+1$ to $n$.
        If edge $(a, c)$ exists AND edge $(b, c)$ exists:
          Found the answer $(a, b, c)$. Return it.

The complexity of this naive approach depends on the number of edges.
Let $d(v)$ be the degree of vertex $v$.
The number of pairs $(a, b)$ such that $(a, b)$ is an edge is $m$. For each such pair, we iterate $c$.
If we check for $c$ in the range $b+1 \dots n$, it takes $O(n)$ time per edge. Total time $O(m \cdot n)$.
Given $n=2000$ and $m=2 \cdot 10^5$, $m \cdot n = 4 \cdot 10^8$. This might be a bit tight for 2 seconds in Python, but maybe acceptable if the constant factor is small. However, we can optimize.

import sys

# Increase recursion depth just in case, though not used here
sys.setrecursionlimit(2000)

def solve():
    # Read all input from standard input
    input_data = sys.stdin.read().split()
    
    if not input_data:
        return

    iterator = iter(input_data)
    
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    # Adjacency masks for fast intersection checks
    # We use 1-based indexing for vertices to avoid confusion
    adj_mask = [0] * (n + 1)
    
    # Adjacency lists to iterate neighbors in sorted order
    adj_list = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        
        # Set bits in masks
        adj_mask[u] |= (1 << v)
        adj_mask[v] |= (1 << u)
        
        # Add to adjacency lists
        adj_list[u].append(v)
        adj_list[v].append(u)
    
    # Sort adjacency lists to ensure we check b in increasing order
    for i in range(1, n + 1):
        adj_list[i].sort()
        
    # Iterate through each vertex a
    for a in range(1, n + 1):
        # Iterate through neighbors b of a
        # Since we want a < b < c, we only care about b > a
        for b in adj_list[a]:
            if b <= a:
                continue
            
            # Check for common neighbors c > b
            # common neighbors are in (adj_mask[a] & adj_mask[b])
            common = adj_mask[a] & adj_mask[b]
            
            # We need the smallest c such that c > b.
            # In common, bits represent vertices. We want smallest set bit index > b.
            # Shift common right by (b + 1) to discard bits <= b.
            # The lowest set bit of the result corresponds to the smallest valid c.
            cand = common >> (b + 1)
            
            if cand > 0:
                # Find the index of the lowest set bit of cand
                # (cand & -cand) isolates the lowest set bit
                lsb = cand & -cand
                # bit_length() returns the number of bits required to represent an integer
                # For a power of 2, it returns the index + 1
                k = lsb.bit_length() - 1
                
                # The actual vertex index c
                c = b + 1 + k
                
                # We found the lexicographically smallest triangle (a, b, c)
                print(f"{a} {b} {c}")
                return

The problem asks us to find the lexicographically smallest triangle $(a, b, c)$ in a graph with $n$ vertices and $m$ edges, where $a < b < c$. The constraints are $n \le 2000$ and $m \le 2 \cdot 10^5$.

A brute-force approach checking all triplets would take $O(n^3)$, which is too slow ($8 \cdot 10^9$ operations). Even checking all pairs of vertices and their common neighbors naively takes $O(m \cdot n)$, which might be too slow in Python ($4 \cdot 10^8$ operations). We can optimize this using bitsets (Python's arbitrary-precision integers) to perform intersection checks efficiently.

### Algorithm
1.  **Representation**: Store the graph using an adjacency list for iteration and an adjacency mask (integer bitmask) for fast edge lookups and intersection. Since $n \le 2000$, an integer with 2000 bits fits well in memory and bitwise operations are efficient ($O(n/64)$).
2.  **Construction**: For each edge $(u, v)$, update `adj_mask[u]` and `adj_mask[v]` by setting the $v$-th and $u$-th bits respectively. Also populate `adj_list[u]` and `adj_list[v]`.
3.  **Iteration**: To find the lexicographically smallest triangle $(a, b, c)$ with $a < b < c$, we iterate:
    *   $a$ from $1$ to $n$.
    *   $b$ from the neighbors of $a$ such that $b > a$. We must iterate $b$ in increasing order to ensure lexicographical minimality.
    *   For each pair $(a, b)$, we look for a common neighbor $c$ such that $c > b$.
4.  **Finding $c$**: The common neighbors of $a$ and $b$ are given by the bitwise AND of their masks: `common = adj_mask[a] & adj_mask[b]`. We need the smallest bit set in `common` at an index greater than $b$. We can achieve this by shifting `common` right by $b+1$ positions (`cand = common >> (b + 1)`). If the result is non-zero, the lowest set bit of `cand` corresponds to the smallest valid $c$.
5.  **Termination**: The first triangle $(a, b, c)$ found using this ordered iteration is guaranteed to be the lexicographically smallest. We print it and terminate.

### Complexity
*   **Time**: Building the graph takes $O(m)$. Sorting adjacency lists takes $O(m \log n)$. The main loop iterates over edges $(a, b)$ and performs bitwise operations. The number of such pairs is $m$. Each bitwise operation on 2000-bit integers takes roughly $O(n/64)$. Total time complexity is approximately $O(m \cdot n / 64)$, which is well within the 2-second limit for $n=2000, m=2\cdot 10^5$.
*   **Space**: We store $n$ integers of size $n$ bits and $m$ edges, which is negligible ($< 10$ MB).
