**Solution Explanation**

For every vertex one of the colours `1 , 2 , 3` has to be chosen

* two adjacent vertices may **not** get the same colour  
  (simple 3‑colouring)

The order of the vertices is fixed – vertex `1` must be coloured first,
then vertex `2`, …, vertex `n`.  
The answer has to be the lexicographically smallest assignment, i.e. the
first assignment in the order

```
vertex 1 : colour 1 , 2 , 3
vertex 2 : colour 1 , 2 , 3
...
```

If the graph is not 3‑colourable we have to output **NO**.



--------------------------------------------------------------------

#### 1.  Representation

`n ≤ 40`, therefore a Python integer is a perfect bit mask

```
bit i  = 1   <=>   vertex i is present
```

For every vertex

* `neigh[i]` – bit mask of all neighbours of `i`
* `adj[i]`   – plain list of neighbour indices (needed for forward
  checking)

The current colouring

```
colour[v]  (0 = not coloured, 1/2/3 = chosen colour)
```

and a bit mask of all vertices having a certain colour

```
colourMask[1], colourMask[2], colourMask[3]
```

`usedMask[v]` – bit mask of colours already used by the **already coloured**
neighbours of `v`.  
If `usedMask[v] == 0b111` vertex `v` cannot obtain any colour later – the
current partial colouring is impossible and can be abandoned.



--------------------------------------------------------------------

#### 2.  Forward checking

When a vertex `x` receives colour `c`

```
for every not yet coloured neighbour u of x
        old = usedMask[u]
        usedMask[u] |= 1 << c
        record (u, old)   # to restore it later
        if usedMask[u] == 0b111   ->   impossible → prune
```

During backtracking we restore all recorded masks.



--------------------------------------------------------------------

#### 3.  Depth‑first search

```
dfs(idx)   # idx = next vertex to colour (0 … n-1)
    if idx == n
            solution found
            return True

    for colour c = 1,2,3
            if colour c does not clash with already coloured neighbours
                    (colourMask[c] & neigh[idx]) == 0
                    assign colour
                    forward checking
                    if no contradiction
                            if dfs(idx+1)  ->  return True
                    undo everything
    return False
```

The recursion depth is at most `n (≤ 40)`.  
Because vertices are processed in the fixed order and colours are tried in
ascending order, the **first** found solution is automatically the
lexicographically smallest one.



--------------------------------------------------------------------

#### 4.  Correctness Proof  

We prove that the algorithm prints a correct answer.

---

##### Lemma 1  
During the search, a vertex is coloured only with a colour that is not
used by any already coloured neighbour.

**Proof.**

When trying colour `c` for vertex `v`

```
colourMask[c] & neigh[v] == 0
```

holds, i.e. none of the neighbours of `v` already has colour `c`.  
∎



##### Lemma 2  
After colouring a vertex `x` with colour `c`, the forward checking step
detects a *definitely impossible* partial colouring iff some
still uncoloured vertex has all three colours already used by its coloured
neighbours.

**Proof.**

`usedMask[u]` contains exactly the colours that are already used by the
coloured neighbours of `u`.  
The algorithm sets

```
usedMask[u] := usedMask[u] ∪ {c}
```

for every uncoloured neighbour `u` of `x`.  
If afterwards `usedMask[u] == 0b111`, every colour is already used by a
coloured neighbour of `u`; thus `u` can never obtain a colour – the
current partial colouring is impossible.  
Conversely, if `usedMask[u] != 0b111` no immediate impossibility is
detectable from the coloured neighbours only.  
∎



##### Lemma 3  
If the algorithm backtracks from a vertex, every colouring that was
examined before the backtrack is still a valid partial colouring of the
graph induced by the already coloured vertices.

**Proof.**

The only modifications made when a colour is tried are

* setting `colour[v]` and the corresponding bit in `colourMask[c]`
* adding the colour to `usedMask[nb]` for every uncoloured neighbour
  `nb` (only if the bit was not already present)

When backtracking, the algorithm restores

* `colour[v]` to `0`
* the bit in `colourMask[c]` is cleared
* all `usedMask[nb]` are reverted to their old values

Thus after backtracking the state is exactly as it was before the colour
was tried – a valid partial colouring. ∎



##### Lemma 4  
If the algorithm returns `True`, the produced colouring is a proper
3‑colouring of the whole graph.

**Proof.**

The algorithm stops only when `idx == n`, i.e. all vertices have been
assigned a colour.  
By Lemma&nbsp;1 every vertex receives a colour that differs from all its
coloured neighbours, therefore all edges connect vertices of distinct
colours – the colouring is proper.  
Only colours `1,2,3` are used, hence it is a 3‑colouring. ∎



##### Lemma 5  
If the algorithm returns `False`, the graph is not 3‑colourable.

**Proof.**

Assume the contrary – the graph admits a 3‑colouring `C`.  
Consider the first vertex `v` whose colour in `C` is **not** the first
colour tried by the algorithm at its recursion level.
For every earlier vertex the algorithm already used the smallest colour
possible in all valid partial colourings; thus all earlier vertices of
`C` have the same colours as in the partial colouring produced by the
algorithm when it reaches `v`.  
Therefore the colour of `v` in `C` is compatible with all coloured
neighbours – the algorithm will try this colour at vertex `v`.  
Because the algorithm explores all possible colour choices for a vertex
until a solution is found, it will eventually follow the path that
reproduces colouring `C` and will return `True`.  
Contradiction.  
Hence no 3‑colouring exists. ∎



##### Lemma 6  
The first colouring found by the algorithm is the lexicographically
smallest proper 3‑colouring.

**Proof.**

Vertices are processed in the fixed order `1 … n`.  
For each vertex colours are tried in the order `1 , 2 , 3`.  
Therefore the first complete assignment found has

* for every vertex the smallest possible colour that still allows a
  solution for the remaining vertices,

which is exactly the definition of the lexicographically smallest
colouring. ∎



##### Theorem  
The algorithm prints

* `NO` iff the graph is not 3‑colourable,
* otherwise it prints `YES` followed by the lexicographically smallest
  proper 3‑colouring of the graph.

**Proof.**

*If the algorithm prints `YES`* – by Lemma&nbsp;4 the printed colours
form a proper 3‑colouring; by Lemma&nbsp;6 it is the lexicographically
smallest one.

*If the algorithm prints `NO`* – it never returned `True`.  
By Lemma&nbsp;5 the graph is not 3‑colourable.

Thus the output of the algorithm satisfies the specification. ∎



--------------------------------------------------------------------

#### 5.  Complexity Analysis

Let `T(n)` be the worst‑case number of recursive calls.
Because of forward checking many dead ends are pruned immediately
(`K₄₀` for example).
The search is exponential in the worst case – as expected for graph
colouring – but for all practical instances with `n ≤ 40` it finishes in
well below a second.

All operations inside one call are `O(degree(v))` bit operations on
integers of at most `40` bits, therefore they are `O(1)`.

Memory usage:

```
neigh[ ] , adj[ ] , colour[ ] , colourMask[ ] , usedMask[ ]   :  O(n)
```

--------------------------------------------------------------------

#### 6.  Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(1 << 20)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # adjacency lists, as sets first (no multiple edges)
    g = [set() for _ in range(n)]
    for _ in range(m):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        g[a].add(b)
        g[b].add(a)

    neigh = [0] * n          # bit masks of neighbours
    adj  = [list() for _ in range(n)]  # plain lists for forward check
    for i in range(n):
        mask = 0
        for j in g[i]:
            mask |= 1 << j
            adj[i].append(j)
        neigh[i] = mask

    colour = [0] * n                 # 0 = not coloured
    colourMask = [0, 0, 0, 0]        # 1‑based indexing
    usedMask = [0] * n               # colours already used by coloured neighbours
    answer = None                    # to store the final colouring

    def dfs(idx: int) -> bool:
        """returns True iff a full proper colouring was found"""
        nonlocal answer
        if idx == n:
            answer = colour[:]       # copy
            return True

        v = idx
        for c in (1, 2, 3):
            # check clash with already coloured neighbours
            if colourMask[c] & neigh[v]:
                continue            # colour c already used by a neighbour

            # assign colour
            colour[v] = c
            colourMask[c] |= 1 << v

            # forward checking
            bad = False
            changes = []              # list of (vertex, oldMask)
            for u in adj[v]:
                if colour[u] == 0:    # still uncoloured
                    old = usedMask[u]
                    new = old | (1 << c)
                    if new != old:
                        changes.append((u, old))
                        usedMask[u] = new
                        if usedMask[u] == 0b111:
                            bad = True
                            break

            if not bad:
                if dfs(idx + 1):
                    return True

            # undo everything
            for u, old in changes:
                usedMask[u] = old
            colourMask[c] &= ~(1 << v)
            colour[v] = 0

        return False

    possible = dfs(0)

    out = sys.stdout
    if not possible:
        out.write("NO\n")
    else:
        out.write("YES\n")
        out.write(" ".join(str(x) for x in answer) + "\n")


if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input/output format.
