            color[u] = c
            ans[u] = c
            
            # Update forbidden states for next neighbors (unassigned)
            mask = 1 << (c - 1)
            changed_next = []
            conflict_found = False
            
            for v in next_neighbors[u]:
                old_val = forbidden[v]
                forbidden[v] |= mask
                if old_val != forbidden[v]:
                    changed_next.append(v)
                
                if forbidden[v] == 7: # All 3 colors forbidden
                    conflict_found = True
                    break
            
            if conflict_found:
                # Backtrack: revert changes
                for v in changed_next:
                    forbidden[v] &= ~mask
                color[u] = 0
                ans[u] = 0
                continue
            
            # Recurse
            if backtrack(u + 1):
                return True
            
            # Backtrack: revert changes
            for v in changed_next:
                forbidden[v] &= ~mask
            color[u] = 0
            ans[u] = 0
            
        return False

    if backtrack(1):
        print("YES")
        print(*(ans[1:]))
    else:
        print("NO")

    solve()

One detail: `changed_next` logic.
If `forbidden[v]` was already 7 (impossible state), `old_val` is 7. `forbidden[v]` remains 7. `changed_next` not appended.
Then `conflict_found` is True (since `forbidden[v] == 7`).
We revert `forbidden[v] &= ~mask`.
If `forbidden[v]` was 7, clearing a bit makes it 6.
This is wrong!
If `forbidden[v]` was 7, it means it was already impossible.
But as discussed, `forbidden[v]` should not be 7 before we assign `u`.
Because if it was 7, we would have backtracked at the step that made it 7.
So `forbidden[v]` is always $< 7$ when entering `backtrack(u)`.
So `old_val` is always $< 7$.
So `forbidden[v]` becomes 7 only if it was 6 (binary 110) and we add 1 (001).
Or 5 (101) and add 2 (010).
Or 3 (011) and add 4 (100).
In all cases `old_val != forbidden[v]`.
So `changed_next` is correctly populated.
And reverting `&= ~mask` restores `old_val`.
So the logic is safe.
