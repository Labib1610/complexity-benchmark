The problem asks us to assign one of two work periods (1 or 2) to each of $n$ personnel such that for every pair of mutually exclusive personnel, they are assigned to different periods. We need to find if such an assignment exists. If it does, we need to find the one that is lexicographically smallest. The assignment is represented as a sequence $s_1, s_2, \dots, s_n$, where $s_i$ is the work period of person $i$.

The constraint that mutually exclusive pairs must be in different periods is essentially the definition of a bipartite graph coloring problem with 2 colors. Each personnel is a node in a graph, and each mutual exclusivity constraint is an edge. We need to color the graph with 2 colors (say 1 and 2) such that no two adjacent nodes have the same color. If the graph is not bipartite, no such assignment exists.

The graph consists of up to $n$ nodes and $m$ edges. Since the constraints are pairwise, the problem reduces to checking if the graph is bipartite. If it is bipartite, we need to find the lexicographically smallest valid coloring. The coloring is defined by the sequence $s_1, s_2, \dots, s_n$. We want to minimize $s_1$, then $s_2$, and so on. Since $s_i \in \{1, 2\}$, minimizing $s_1$ means we prefer 1 over 2. If $s_1$ is fixed, we prefer 1 for $s_2$ over 2, etc.

Let's consider the connected components of the graph. The constraints apply independently within each connected component. However, the goal is lexicographical order for the global sequence $s$. This suggests we should process nodes $1, 2, \dots, n$ in order.

Wait, if we have a connected component, once we fix the color of one node in that component, the colors of all other nodes in that component are determined (up to swapping 1 and 2). Specifically, if we fix node $u$'s color to $c$, then all neighbors must have color $3-c$, their neighbors must have color $c$, and so on. Since the graph must be bipartite, this assignment is consistent if and only if there are no odd cycles. If there is an odd cycle, we output NO.

To achieve the lexicographically smallest sequence $s_1, s_2, \dots, s_n$, we should iterate through nodes $i$ from 1 to $n$. If node $i$ has not been assigned a color yet, we start a traversal (BFS or DFS) to color the connected component containing $i$. To minimize the sequence lexicographically, when we start coloring a new component, we should assign the current node $i$ the value 1. Why? Because $s_i$ is the first time this component appears in the sequence. If we assign $s_i = 1$, then $s_i$ is smaller than if we assigned $s_i = 2$. Since all nodes in the component are determined once $s_i$ is chosen, choosing $s_i=1$ is locally optimal for index $i$. Does it affect previous choices? No, because previous nodes $1, \dots, i-1$ are already processed. If $i$ was already processed, it belongs to a component that was already colored. If $i$ is not processed, it belongs to a new component. The choice for this component only affects nodes $\ge i$. To make the sequence lexicographically smallest, we want the earliest possible indices to have the smallest possible values. Since $i$ is the first uncolored node we encounter (assuming we iterate 1 to $n$), we greedily assign it 1. Then the rest of the component is determined relative to this choice.

Let's double check this logic.
Suppose we have nodes 1 and 2 connected.
If we process 1, we assign $s_1 = 1$. Then $s_2$ must be 2. Sequence: 1, 2.
If we assigned $s_1 = 2$, then $s_2$ must be 1. Sequence: 2, 1.
1, 2 is lexicographically smaller than 2, 1. So for the first node in a component, we pick 1.
Suppose we have nodes 1, 2, 3 forming a path 1-2-3.
Processing 1: $s_1=1$. Then $s_2=2$ (neighbor of 1). Then $s_3=1$ (neighbor of 2). Sequence: 1, 2, 1.
Is it possible to have a different valid assignment? The only other valid assignment is swapping 1 and 2 everywhere in the component. That would be 2, 1, 2.
Comparing 1, 2, 1 and 2, 1, 2. Clearly 1, 2, 1 is smaller.
So the strategy is: iterate $i$ from 1 to $n$. If $i$ is not colored, start BFS/DFS from $i$. Assign $color[i] = 1$. Propagate constraints. If a conflict is found (adjacent nodes have same color), output NO. If we finish and all nodes are colored, output YES and the colors.

Wait, is it always optimal to start with 1?
Suppose the component involves nodes $\{2, 3\}$ and we are at step $i=2$. Node 1 is already colored (say component $\{1\}$ colored with 1).
We process node 2. It's uncolored. We assign $s_2=1$. Then $s_3=2$. Sequence so far: $s_1=1, s_2=1, s_3=2$.
Alternative: $s_2=2, s_3=1$. Sequence: $1, 2, 1$.
Comparing $(1, 1, 2)$ and $(1, 2, 1)$, the first one is smaller.
So yes, whenever we encounter an uncolored node $i$ in the loop $1 \dots n$, it means $i$ is the "root" of a new component in the order of indices. To minimize the sequence at index $i$, we must set $s_i = 1$. Any other valid assignment for this component would require $s_i = 2$ (since the component has 2 valid colorings, and we chose the one starting with 1). Since $1 < 2$, this choice is locally optimal for the index $i$. Since previous indices $j < i$ are already fixed and don't depend on the coloring of this component (because $i$ is the first node of this component in $1 \dots n$), this greedy choice is globally optimal.

Algorithm:
1. Initialize an array `color` of size $n+1$ with 0 (unvisited).
2. Construct the adjacency list for the graph.
3. Iterate $i$ from 1 to $n$:
    a. If `color[i]` is 0:
        i. Perform BFS/DFS starting from $i$.
        ii. Set `color[i] = 1`.
        iii. Queue/Stack contains $i$.
        iv. While queue is not empty:
            - Pop $u$.
            - For each neighbor $v$ of $u$:
                - If `color[v]` is 0:
                    - Set `color[v] = 3 - color[u]`.
                    - Push $v$ to queue/stack.
                - Else if `color[v] == color[u]`:
                    - Return "NO".
4. If loop finishes without conflict, print "YES" and the `color` array from 1 to $n$.

Since $i$ is the first node of the component, $C[i]=1$ and $C'[i]=2$. Thus $C$ is lexicographically smaller.

import sys
from collections import deque

# Increase recursion depth just in case, though we use BFS
sys.setrecursionlimit(200005)

def solve():
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    iterator = iter(input_data)
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        adj[u].append(v)
        adj[v].append(u)
        
    colors = [0] * (n + 1)
    
    # To handle the lexicographical requirement
    # We iterate 1 to n. If uncolored, color it 1 and propagate.
    # If conflict, print NO and exit.
    
    for i in range(1, n + 1):
        if colors[i] == 0:
            # Start BFS/DFS for this component
            colors[i] = 1
            q = deque([i])
            
            while q:
                u = q.popleft()
                c = colors[u]
                next_c = 3 - c # 1 -> 2, 2 -> 1
                
                for v in adj[u]:
                    if colors[v] == 0:
                        colors[v] = next_c
                        q.append(v)
                    elif colors[v] == c:
                        print("NO")
                        return

    print("YES")
    print(*(colors[1:]))

if __name__ == '__main__':
    solve()

Final check of the code logic.
The problem asks for lexicographically smallest $s_1, \dots, s_n$.
My logic:
1. Iterate $i$ from 1 to $n$.
2. If $i$ uncolored, it is the first node of a new component in the sequence.
3. Assign $s_i = 1$. This is the smallest possible value for $s_i$.
4. Propagate constraints. If conflict, impossible -> NO.
5. If successful, all $s_i$ are determined.
Since $s_i$ is determined at step $i$ (or earlier if it was part of a component started by $j < i$), and we always choose the smallest valid option for the first node of a component, the resulting sequence is lexicographically minimal.
Specifically, for any two valid assignments $A$ and $B$, let $k$ be the first index where they differ.
If $k$ is part of a component where the root was $r \le k$.
Since $r$ was processed at step $r$, and we chose $s_r=1$ (min value), $A$ must have $s_r=1$.
If $B$ had $s_r=2$, then $B$ would differ from $A$ at $r$.
Since $r \le k$, if $r < k$, then $A$ and $B$ differ at $r$, contradiction to $k$ being first difference.
If $r = k$, then $A$ has 1, $B$ has 2. $A < B$.
So my construction yields the minimal assignment.

One edge case: Is it possible that for a component, picking 1 for the root is valid, but picking 2 for the root is also valid (always true for bipartite), but picking 1 forces a choice later that is suboptimal?
No. Once the root is fixed, the rest of the component is fixed (because the graph is connected and bipartite, there is a unique coloring relative to the root). There are no other degrees of freedom within the component.
Wait, if the component was not connected?
We process components one by one. The choice for one component does not affect the coloring of another component (no edges between them).
So we can optimize each component independently.
Within a component, the only freedom is swapping 1 and 2.
So the greedy choice at the root is globally optimal.
