The problem asks us to find a triangle (a set of 3 vertices where every pair is connected by an edge) in a given graph with $n$ vertices and $m$ edges. We are guaranteed that such a triangle exists. We need to output the lexicographically smallest triple $(a, b, c)$ with $a < b < c$.

The constraints are $n \le 2000$ and $m \le 2 \cdot 10^5$. The time limit is 2 seconds. Since we need to find the lexicographically smallest triangle, we should iterate through possible candidates for $a$, then $b$, then $c$.

Let the vertices be numbered $1$ to $n$. A triangle consists of vertices $u, v, w$ such that $(u, v)$, $(v, w)$, and $(u, w)$ are all edges. We want to minimize $a$, then $b$, then $c$ where $a < b < c$ are the vertices of the triangle.

A brute-force approach would check all triples $(u, v, w)$ and see if they form a triangle. There are $O(n^3)$ triples, which is too slow for $n=2000$ ($8 \cdot 10^9$ operations).

Since we need the lexicographically smallest one, we can iterate $a$ from $1$ to $n$. For a fixed $a$, we iterate $b$ from $a+1$ to $n$. If $(a, b)$ is an edge, we look for a $c > b$ such that $(a, c)$ and $(b, c)$ are edges. The first such $c$ we find (in increasing order) will give the smallest $c$ for the fixed $a, b$. The first time we find such a $a, b, c$ across all loops, that will be the lexicographically smallest triple.

To optimize finding $c$, we can pre-process the graph into an adjacency structure. An adjacency matrix would take $O(n^2)$ memory, which is $4 \cdot 10^6$ bytes (4MB), perfectly fine. An adjacency list would take $O(m)$ memory. Since $m$ can be up to $2 \cdot 10^5$, an adjacency list is also fine, but checking edge existence takes $O(\text{degree})$ or $O(1)$ with a matrix. Given $n=2000$, an adjacency matrix is very fast to check if an edge exists.
