The problem asks us to find the lexicographically smallest triplet $(a, b, c)$ such that $1 \le a < b < c \le n$ and there is an edge between $a$ and $b$, $b$ and $c$, and $a$ and $c$ in a given graph with $n$ vertices and $m$ edges. The edges represent restricted pairs. We are guaranteed that at least one such triplet (a triangle) exists. We need to minimize $a$, then $b$, then $c$.

The constraints are $n \le 2000$ and $m \le 2 \cdot 10^5$. The time limit is 2 seconds.
Since we need the lexicographically smallest triangle $(a, b, c)$ with $a < b < c$, we can iterate through possible values of $a$ from $1$ to $n$, then possible values of $b$ from $a+1$ to $n$, and finally check if there exists a $c > b$ such that $(a, c)$ and $(b, c)$ are edges. However, simply checking all triplets would be $O(n^3)$ or $O(m \cdot n)$, which might be too slow if $n=2000$. $2000^3 = 8 \cdot 10^9$, definitely too slow. $m \cdot n$ is $2 \cdot 10^5 \cdot 2000 = 4 \cdot 10^8$, which is borderline but likely too slow for Python within 2 seconds. We need a more efficient approach.

def solve():

    adj = [[] for _ in range(n + 1)]
    # Adjacency matrix for O(1) edge existence checks
    is_edge = [[False] * (n + 1) for _ in range(n + 1)]
    
    for _ in range(m):

        v = int(next(iterator))
        adj[u].append(v)
        adj[v].append(u)
        is_edge[u][v] = True
        is_edge[v][u] = True

    # Sort adjacency lists to facilitate lexicographical search and binary search
    for i in range(1, n + 1):
        adj[i].sort()

    for a in range(1, n + 1):
        # Iterate through neighbors 'b' of 'a'
        # Since adj[a] is sorted, we encounter b in increasing order
        for b in adj[a]:
            if b <= a:

            # To optimize, we iterate over the adjacency list of the vertex with the smaller degree
