The user wants a Python 3 solution for the "Network Security Audit: Triad Detection" problem.

**Problem Analysis:**
- We are given a graph with $n$ nodes and $m$ edges.
- We need to find a triangle (3-cycle), which is a set of three distinct nodes $\{a, b, c\}$ such that edges $(a, b)$, $(b, c)$, and $(c, a)$ all exist.
- We need to find the lexicographically smallest triple $(a, b, c)$ where $a < b < c$.
- Constraints: $n \le 2000$, $m \le 2 \cdot 10^5$.
- Time limit: 2 seconds.

**Algorithm:**
To find the lexicographically smallest triangle $(a, b, c)$ with $a < b < c$, we can iterate through possible values of $a$ from $1$ to $n-2$. For a fixed $a$, we iterate through possible values of $b$ from $a+1$ to $n-1$. If there is an edge between $a$ and $b$, we then look for a node $c$ such that $c > b$ and edges $(a, c)$ and $(b, c)$ exist.

Since we want the lexicographically smallest, the first one we find using this order will be the answer.

**Optimization:**
A naive check for every pair $(a, b)$ and iterating over all $c$ would take $O(n^2 \cdot n) = O(n^3)$ or checking neighbors would be $O(m \cdot n)$.
Given $n=2000$, $n^3$ is too slow ($8 \cdot 10^9$). $m \cdot n$ is $4 \cdot 10^8$, which might be too slow for 2 seconds, but let's check the structure.

A better approach is to iterate over edges or adjacency lists.
Let's represent the graph using adjacency lists. Since we need to check existence of edges efficiently, an adjacency matrix or a set of neighbors for each node is good. Since $n$ is up to 2000, an adjacency matrix (boolean array `adj[2001][2001]`) is feasible in terms of memory ($2000 \times 2000$ booleans/bytes is roughly 4MB, which is well within 256MB).

**Proposed Algorithm:**
1. Construct an adjacency matrix `adj` of size $(n+1) \times (n+1)$ where `adj[u][v] = 1` if there is an edge, `0` otherwise.
2. Iterate $a$ from $1$ to $n-2$.
3.   Iterate $b$ from $a+1$ to $n-1$.
4.     If `adj[a][b]` is true:
5.       Iterate $c$ from $b+1$ to $n$.
6.         If `adj[a][c]` and `adj[b][c]` are true:
7.           Return $(a, b, c)$.

def solve():
    # Read all input from standard input
    input_data = sys.stdin.read().split()
    
    if not input_data:
        return

    iterator = iter(input_data)
    
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    # Adjacency masks for bitset operations
    # adj_mask[i] is an integer where the j-th bit is set if there is an edge between i and j
    adj_mask = [0] * (n + 1)
    
    # Adjacency lists to iterate over neighbors efficiently
    adj_list = [[] for _ in range(n + 1)]

    for _ in range(m):
        try:
            u = int(next(iterator))
            v = int(next(iterator))
        except StopIteration:
            break
            
        # Update adjacency masks
        adj_mask[u] |= (1 << v)
        adj_mask[v] |= (1 << u)
        
        # Update adjacency lists
        adj_list[u].append(v)
        adj_list[v].append(u)

    # Sort adjacency lists to ensure we process neighbors in increasing order
    # This is crucial for finding the lexicographically smallest triple
    for i in range(1, n + 1):
        adj_list[i].sort()

    # We want the lexicographically smallest triple (a, b, c) with a < b < c.
    # We iterate 'a' from 1 to n-2.
    # For each 'a', we iterate 'b' (neighbor of 'a' with b > a) in increasing order.
    # For each pair (a, b), we find the smallest 'c' (neighbor of both a and b with c > b).
    
    for a in range(1, n - 1):
        mask_a = adj_mask[a]
        
        # Iterate over neighbors b of a
        for b in adj_list[a]:
            if b <= a:
                continue
            
            # Check if there exists a common neighbor c > b
            # common represents bits set for nodes connected to both a and b
            common = mask_a & adj_mask[b]
            
            # We need to find the smallest bit index in 'common' that is strictly greater than 'b'.
            # Shifting 'common' right by (b + 1) effectively removes bits <= b
            # and shifts the remaining bits down.
            # The lowest set bit in the shifted value corresponds to the smallest c > b.
            
            common_shifted = common >> (b + 1)
            
            if common_shifted > 0:
                # Extract the lowest set bit
                low_bit = common_shifted & -common_shifted
                
                # Calculate the index of this bit. 
                # low_bit is 2^k for some k. bit_length() returns k + 1.
                # So the index relative to the shift start is k = bit_length() - 1.
                # The actual index c is k + (b + 1).
                
                c = low_bit.bit_length() - 1 + b + 1
                
                # We found the lexicographically smallest triple
                print(f"{a} {b} {c}")
                return
