The problem asks us to find a triangle in a graph where nodes represent technicians and edges represent incompatibilities. Specifically, we need to find three distinct vertices $a, b, c$ such that edges $(a, b)$, $(b, c)$, and $(a, c)$ exist. We need to output the lexicographically smallest triple $(a, b, c)$ with $1 \le a < b < c \le n$. We are guaranteed that at least one such triangle exists. The constraints are $n \le 2000$ and $m \le 2 \cdot 10^5$. The time limit is 2 seconds.

This is the "triangle finding" problem. Since we need the lexicographically smallest triangle, we should iterate through possible values of $a$ from 1 to $n$, then $b$ from $a+1$ to $n$, and check if there exists a $c$ such that $b < c \le n$ and edges $(a, b)$, $(b, c)$, $(a, c)$ exist.

A naive algorithm would iterate over all triples $(a, b, c)$, checking if they form a triangle. This takes $O(n^3)$ time, which is too slow for $n=2000$ (approx $8 \cdot 10^9$ operations).
We can optimize this. We can iterate over edges $(u, v)$ and check if there is a $w$ connected to both $u$ and $v$. Or, we can iterate over vertices $u$, then iterate over neighbors $v$ of $u$, then iterate over neighbors $w$ of $v$ and check if $(u, w)$ exists.

Given that we need the lexicographically smallest solution, we should iterate $a$ from 1 to $n$. For a fixed $a$, we need to find the smallest $b > a$ such that there exists $c > b$ with edges $(a, b)$, $(a, c)$, $(b, c)$.
To check this efficiently, we can represent the graph using an adjacency matrix or adjacency lists. Since $n=2000$, an adjacency matrix $O(n^2)$ is feasible in terms of memory ($2000^2$ booleans/ints is roughly 4MB) and initialization.
However, $O(n^3)$ is definitely out.
Let's consider iterating $a$ from 1 to $n$. Then we look for neighbors of $a$. Let the neighbors be $v_1, v_2, \dots$. We need to find two neighbors $u, v$ of $a$ such that $u$ and $v$ are connected. To minimize lexicographically, we want smallest $a$. Then for that $a$, we want smallest $b$. So we should iterate neighbors $b$ of $a$ in increasing order. Then we need to find a neighbor $c$ of $a$ such that $c > b$ and $c$ is also a neighbor of $b$. To minimize $c$, we should iterate neighbors $c$ of $a$ in increasing order.

Algorithm idea:
1. Store graph as an adjacency matrix `adj` where `adj[u][v]` is true if $u$ and $v$ are incompatible. Since we need fast lookups, a boolean matrix or bitset is good. With $N=2000$, a 2D array `adj[2001][2001]` is fine.
2. Iterate $a$ from 1 to $n$.
3. Iterate $b$ from $a+1$ to $n$.
   - If `adj[a][b]` is true (edge exists):
     - Iterate $c$ from $b+1$ to $n$.
       - If `adj[a][c]` is true and `adj[b][c]` is true:
         - We found the triangle $(a, b, c)$.
         - Since we iterate $a$, then $b$, then $c$ in increasing order, the first one we find is guaranteed to be the lexicographically smallest.
         - Print $a, b, c$ and exit.

import sys

# Standard competitive programming setup
input = sys.stdin.read

def solve():
    data = input().split()
    if not data:
        return
    
    iterator = iter(data)
    try:
        n = int(next(iterator))
        m = int(next(iterator))
    except StopIteration:
        return

    adj_mask = [0] * (n + 1)
    adj_list = [set() for _ in range(n + 1)]
    
    # Read edges
    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        adj_mask[u] |= (1 << v)
        adj_mask[v] |= (1 << u)
        adj_list[u].add(v)
        adj_list[v].add(u)
        
    # Sort adjacency lists for lexicographical order
    for i in range(1, n + 1):
        adj_list[i] = sorted(list(adj_list[i]))
        
    # Find lexicographically smallest triangle
    for a in range(1, n + 1):
        for b in adj_list[a]:
            if b <= a:
                continue
            
            # Intersection of neighbors
            common = adj_mask[a] & adj_mask[b]
            
            # Filter neighbors > b
            # We want to keep bits corresponding to nodes > b
            # Nodes are 1..n. Bits 1..n.
            # We need to clear bits 1..b.
            # Mask (1 << (b + 1)) - 1 sets bits 0..b.

            common &= ~((1 << (b + 1)) - 1)

            # Find lowest set bit
            lsb = common & -common
            # bit_length of 2^k is k+1.
            # If bit k is set (node k), value is 2^k.
            # c = k.
            c = lsb.bit_length() - 1
            
            print(f"{a} {b} {c}")
            return
