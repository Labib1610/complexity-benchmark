The problem asks us to find the lexicographically smallest triangle (a group of three mutually connected vertices) in a given undirected graph. We are given $n$ vertices and $m$ edges. $n \le 2000$ and $m \le 200,000$. We are guaranteed that at least one triangle exists.

A triangle consists of three vertices $a, b, c$ such that edges $(a, b)$, $(b, c)$, and $(c, a)$ exist. We need to output $a, b, c$ such that $a < b < c$, and this triple is lexicographically smallest. This means we want to minimize $a$, then minimize $b$, then minimize $c$.

Let's denote the adjacency list of the graph as $G$. Since the edges are undirected, if there is an edge between $u$ and $v$, then $v$ is in $G[u]$ and $u$ is in $G[v]$. To efficiently check if an edge exists, we can store the graph as an adjacency list where each list is sorted or use an adjacency matrix (but $N=2000$ implies $N^2 = 4 \times 10^6$, which is acceptable for memory, but iterating over all pairs is $O(N^3)$ which is too slow if done naively). However, checking existence in an adjacency list can be done faster if we sort the lists or use a hash set. Since we are in Python, `set` lookups are $O(1)$ on average.

Among all such pairs for a fixed $a$, we want the one that minimizes $b$, and then $c$.
