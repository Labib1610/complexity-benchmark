We need find lexicographically smallest triangle in undirected graph with up to n=2000, m up to 2e5. Brute O(m^1.5) maybe okay. Since n small 2000, we can maintain adjacency bitsets or sets.

Goal: find smallest a<b<c where edges exist among all pairs.

Lexicographically smallest: minimize a, then b, then c. So iterate a from 1..n, for each a we need to find smallest b > a such that edge a-b exists, and then find smallest c > b such that both edges a-c and b-c exist. So we can iterate a ascending, then iterate over neighbors b> a ascending, then search for c> b that connects to both. We need efficient intersection of adjacency sets.

We can have adjacency lists sorted. For each a,b, we need intersection of neighbors of a and b that are > b. Since n <=2000, we can use bitsets of length n, operations O(n/word). 2000 bits ~ 32 longs. So intersection quickly. Or simpler: use boolean array visited. But we must find min c. Approach: for each a, precompute bitset of adjacency of a (size n). Then for each b in neighbors of a with b>a, compute intersection bitset = adj[a] & adj[b], then find first set bit > b. Since bitset is small, we can iterate from b+1 to n, check if intersection has bit. That's O(n) per pair worst-case. But number of pairs a,b edges m <= 2e5, times n=2000 gives 4e8 too large.

Better: use bitsets and find first set bit quickly: we can use Python's int as bitset. Represent adjacency of each node as integer with bits 1..n. Then intersection = adj[a] & adj[b]. Then we need to find least bit > b. We can shift right by (b) bits? Actually bits indexing from 1. We can compute mask = (~((1 << (b)) - 1)) to zero bits <= b. Then intersection & mask, then find lowest set bit using bit_length? For integer x>0, lowest set bit index can be (x & -x). Then index = bit_length - 1? For example: lsb = x & -x, index = lsb.bit_length() - 1 (0-based). If bits start at 0 for node 1? Let's define bit i corresponds to node i+1? Let's shift accordingly.

Simpler: use python bitarray? But built-in int works.
