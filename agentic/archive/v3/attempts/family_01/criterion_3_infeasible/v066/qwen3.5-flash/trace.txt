The problem asks us to find the lexicographically smallest triple of facilities $(a, b, c)$ such that $1 \le a < b < c \le n$ and there are edges $(a, b)$, $(b, c)$, and $(a, c)$ in the given graph. The graph is undirected. We are guaranteed that at least one such triangle exists. We need to output $a, b, c$.

Constraints:
$n \le 2000$
$m \le \min(n(n-1)/2, 2 \cdot 10^5)$
Time limit: 2 seconds.

Since we need the lexicographically smallest triple, we should iterate through possible values of $a$, then $b$, then $c$.
Specifically, we want the smallest $a$. For that $a$, the smallest $b > a$. For that pair $(a, b)$, the smallest $c > b$.
The condition is that edges $(a, b)$, $(b, c)$, and $(a, c)$ must exist.

Let's consider an algorithm.
A naive approach would be to iterate over all triples $(a, b, c)$ and check if they form a triangle. This takes $O(n^3)$ time. With $n=2000$, $n^3 = 8 \cdot 10^9$, which is too slow.
We can optimize this.
We iterate $a$ from $1$ to $n$.
  We iterate $b$ from $a+1$ to $n$.
    If edge $(a, b)$ exists:
      We iterate $c$ from $b+1$ to $n$.
        If edges $(a, c)$ and $(b, c)$ exist:
          We found the answer $(a, b, c)$. Since we iterate in increasing order, this is the lexicographically smallest.
          Return/Print and exit.

The check "If edge $(a, c)$ and $(b, c)$ exist" needs to be fast.
We can use an adjacency matrix or adjacency lists.

However, constructing the matrix takes $O(n^2)$ space and time. With $n=2000$, $n^2 = 4 \cdot 10^6$, which fits easily in memory and time.

    for _ in range(m):
        u = int(next(iterator))
        v = int(next(iterator))
        
        adj[u].append(v)
        adj[v].append(u)
        adj_mask[u] |= (1 << v)
        adj_mask[v] |= (1 << u)
    
    for i in range(1, n + 1):
        adj[i].sort()
    
    for a in range(1, n + 1):
        for b in adj[a]:
            if b <= a:
                continue
            
            # Check intersection
            common = adj_mask[a] & adj_mask[b]
            
            # We need c > b
            # Shift to remove bits <= b
            # bit b+1 becomes bit 0
            shifted = common >> (b + 1)
            
            if shifted > 0:
                # Get lowest set bit index
                lsb = shifted & -shifted
                offset = lsb.bit_length() - 1
                c = b + 1 + offset
                
                print(f"{a} {b} {c}")
                return

  Wait, `adj_mask` construction loop:
  `adj_mask[u] |= (1 << v)`
  This creates a new integer.
  Since $m$ is up to $2 \cdot 10^5$, and each op is fast, it's fine.
  
  One potential issue:
  `1 << v` creates a new integer object every time.
  With $m$ edges, we do $2m$ such creations.
  $4 \cdot 10^5$ objects.
  This is fine.
  Python's integer allocator is efficient.
  
  Final check:
  Is `adj` list needed if we use `adj_mask`?
  We need `adj` to iterate $b$ in increasing order efficiently.
  Iterating $b$ from $a+1$ to $n$ and checking `if (adj_mask[a] >> b) & 1` would be $O(n^2)$ which is $4 \cdot 10^6$ checks.
  Inside check: bitwise AND of size $n$.
  Total $O(n^3/64)$.
  With $m$ small, iterating `adj` is better ($O(m \cdot n/64)$).
  With $m$ large (dense), $O(n^2)$ iterations is same as $O(m)$ (since $m \approx n^2$).
  So `adj` list is good for both cases.
  Wait, if $m$ is small, $O(n^2)$ loop is slow?
  $n^2 = 4 \cdot 10^6$.
  $4 \cdot 10^6 \times 30 \approx 1.2 \cdot 10^8$.
  This is acceptable too.
  But `adj` list makes it $O(m \cdot n/64) = 6 \cdot 10^6$.
  So `adj` list is definitely better.
