We need to find the lexicographically smallest triangle (clique of size 3) in an undirected graph.

Given the constraints \( n \leq 2000 \), \( m \leq 2 \cdot 10^5 \), a direct triple loop over all triples is \( O(n^3) \) which is too slow.

We can use an adjacency bitmask approach: represent neighbors as bitmasks using Python integers. For each edge \((u, v)\), we want to find a vertex \( w > v \) that is a neighbor of both.

To get the lexicographically smallest triple, we iterate over vertices in increasing order, and for each edge \((u, v)\) with \( u < v \), check for the smallest \( w > v \) that is connected to both.

Here's the implementation:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * (n + 1)
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u] |= (1 << v)
        adj[v] |= (1 << u)

    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if not (adj[a] >> b) & 1:
                continue
            common = adj[a] & adj[b]
            # Clear bits ≤ b, find smallest > b
            common &= ~((1 << (b + 1)) - 1)
            if common:
                c = (common & -common).bit_length() - 1
                print(a, b, c)
                return

if __name__ == "__main__":
    solve()
```
