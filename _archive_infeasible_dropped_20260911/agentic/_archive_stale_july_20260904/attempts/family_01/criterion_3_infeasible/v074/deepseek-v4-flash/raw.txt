We need to find a triangle (3-clique) in an undirected graph with up to 2000 nodes and 200k edges, and output the lexicographically smallest triangle.

A direct O(n^3) check is too slow. But we can do it efficiently by iterating over the first vertex in sorted order, then checking pairs among its neighbors.

**Approach:**
- Store adjacency as sets for fast intersection checks.
- Iterate `a` from 1 to n.
- For each `a`, consider its neighbors sorted.
- For each pair of neighbors `(b, c)` with `b < c`, check if `b` and `c` are connected.
- The first found triangle (in this order) is the lexicographically smallest.

Since we iterate `a` in increasing order, and for each `a` we check neighbors in increasing order, the first triangle found is lexicographically smallest.

**Complexity:**  
Worst case: for each `a`, we check all pairs of its neighbors. In dense graphs this could be O(n^3) in theory, but with n=2000 and m=200k, the number of neighbor pairs is bounded by sum of deg^2, which is at most ~2m * max_deg. In practice it's fine.

Let's implement:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        neighbors = sorted(adj[a])
        for i in range(len(neighbors)):
            b = neighbors[i]
            if b <= a:
                continue
            for j in range(i + 1, len(neighbors)):
                c = neighbors[j]
                if c <= a:
                    continue
                if c in adj[b]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    solve()
```
