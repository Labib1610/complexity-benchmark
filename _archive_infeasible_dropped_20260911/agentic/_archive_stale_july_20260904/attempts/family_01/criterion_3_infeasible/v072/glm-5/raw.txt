To solve this problem, we need to find a volatile triad (a triangle in the graph) with the lexicographically smallest triple (a, b, c) where a < b < c. The challenge is to do this efficiently given the constraints (n up to 2000 and m up to 200,000).

### Approach
1. **Graph Representation**: Represent the graph using an adjacency list where each node points to its neighbors. Additionally, use a set or a boolean matrix to quickly check if an edge exists between any two nodes.
2. **Finding the Lexicographically Smallest Triangle**: The lexicographically smallest triangle will have the smallest possible a, then the smallest possible b, and then the smallest possible c. To find this:
   - Iterate through each node a from 1 to n. For each a, iterate through its neighbors b where b > a. For each such pair (a, b), check if there exists a common neighbor c such that c > b and both (a, c) and (b, c) are edges. The first such c found will give the lexicographically smallest triangle for the current (a, b) pair.
   - The first valid triangle found in this manner will be the lexicographically smallest overall because we are checking nodes in increasing order of a, then b, then c.

### Solution Code
```python
import sys

def solve():
    input = sys.stdin.read().split()
    ptr = 0
    n = int(input[ptr])
    ptr += 1
    m = int(input[ptr])
    ptr += 1
    
    adj = [[] for _ in range(n+1)]
    # Using a set for O(1) lookups
    edge_set = [set() for _ in range(n+1)]
    
    for _ in range(m):
        u = int(input[ptr])
        v = int(input[ptr+1])
        ptr += 2
        adj[u].append(v)
        adj[v].append(u)
        edge_set[u].add(v)
        edge_set[v].add(u)
    
    # Sort adjacency lists for each node to process in order
    for i in range(1, n+1):
        adj[i].sort()
    
    # Iterate a from 1 to n
    for a in range(1, n+1):
        # Iterate b in adj[a] where b > a
        for b in adj[a]:
            if b <= a:
                continue
            # Now check for c in adj[b] where c > b and c is in adj[a]
            # Since adj[b] is sorted, we can iterate in order
            for c in adj[b]:
                if c <= b:
                    continue
                if c in edge_set[a]:
                    print(a, b, c)
                    return
    # Shouldn't reach here as per problem statement
    print(-1, -1, -1)

solve()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the constraints.
2. **Graph Representation**: The graph is stored using an adjacency list (`adj`) and a set of edges (`edge_set`) for each node to allow O(1) edge existence checks.
3. **Finding the Triangle**: The algorithm iterates through each node `a` in ascending order. For each `a`, it checks all neighbors `b` greater than `a`. For each such `b`, it checks all neighbors `c` of `b` that are greater than `b` and also neighbors of `a`. The first such `c` found forms the lexicographically smallest triangle (a, b, c) and is printed immediately.
4. **Efficiency**: The algorithm efficiently checks for triangles by leveraging sorted adjacency lists and set lookups, ensuring optimal performance. The worst-case time complexity is O(n^2) in the worst scenario, but with the constraints (n up to 2000), this approach is feasible.
