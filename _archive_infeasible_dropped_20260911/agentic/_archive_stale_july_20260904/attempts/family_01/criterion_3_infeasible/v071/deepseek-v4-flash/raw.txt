We can solve this by checking all triples, but with n up to 2000, that would be too slow. Instead, we can use adjacency sets and iterate over edges to find a triangle with the smallest lexicographic order.

Here’s the approach:

1. Read n, m and build an adjacency set for each node.
2. Iterate over all edges (u, v) with u < v.
3. For each such edge, find the smallest w > v such that w is connected to both u and v.
4. Keep track of the best (smallest lexicographic) triple found.

Since we iterate over edges and for each we check neighbors, the complexity is O(m * degree) in the worst case, but with m up to 2e5 and n up to 2000, this is acceptable.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        if u > v:
            u, v = v, u
        adj[u].add(v)
        adj[v].add(u)
        edges.append((u, v))
    
    best = None
    for u, v in edges:
        # find smallest w > v connected to both u and v
        # iterate over neighbors of u that are > v
        for w in sorted(adj[u]):
            if w > v and w in adj[v]:
                if best is None or (u, v, w) < best:
                    best = (u, v, w)
                break  # since sorted, first found is smallest for this edge
        if best is not None and u > best[0]:
            # can't improve x anymore
            break
    
    print(*best)

if __name__ == "__main__":
    main()
```
