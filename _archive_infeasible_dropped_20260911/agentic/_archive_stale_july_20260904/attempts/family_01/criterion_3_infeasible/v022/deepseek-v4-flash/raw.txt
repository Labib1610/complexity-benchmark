We can solve this by checking each possible triple, but that would be too slow for large \( n \).  
Instead, we can use the fact that if the graph is not bipartite, there is a triangle in the complement of a maximum matching, but here we just need any triangle in the original graph.

A more efficient approach:  
- For each vertex \( u \), check its neighbors.  
- For each neighbor \( v \) of \( u \), check if any neighbor of \( v \) is also a neighbor of \( u \).  
- To keep it fast, we can use adjacency sets and iterate smartly.

Since \( n \leq 2000 \) and \( m \leq 2\cdot 10^5 \), we can afford an \( O(n^2) \) approach with bitsets.

Here’s the implementation:

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
    
    # Try to find lexicographically smallest triangle
    for a in range(n):
        for b in adj[a]:
            if b <= a:
                continue
            for c in adj[a]:
                if c <= b:
                    continue
                if c in adj[b]:
                    print(a+1, b+1, c+1)
                    return

if __name__ == "__main__":
    main()
```
