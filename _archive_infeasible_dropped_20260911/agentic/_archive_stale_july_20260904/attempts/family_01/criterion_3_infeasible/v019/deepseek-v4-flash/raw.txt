We need to find a triangle (three mutually connected nodes) in the graph, and among all triangles, pick the lexicographically smallest triplet.

Since the graph is undirected and we need the lexicographically smallest triplet, we can iterate over all possible triplets in increasing order and check if they form a triangle.

Given constraints (n up to 2000, m up to 2e5), an O(n^3) check is too slow. But we can do it more efficiently:

- For each node `a` from 1 to n:
  - For each neighbor `b` of `a` with `b > a`:
    - For each neighbor `c` of `a` with `c > b`:
      - Check if `b` and `c` are connected.

This is still potentially O(n * deg^2), but since we stop at the first found triangle (which is lexicographically smallest because we iterate `a` in increasing order, then `b`, then `c`), it will be fast in practice.

We can store adjacency as a set for O(1) edge lookup.

Here’s the implementation:

```python
import sys

def main():
    data = sys.stdin.read().strip().split()
    n = int(data[0])
    m = int(data[1])
    adj = [set() for _ in range(n + 1)]
    idx = 2
    for _ in range(m):
        u = int(data[idx])
        v = int(data[idx + 1])
        idx += 2
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in sorted(adj[a]):
            if b <= a:
                continue
            for c in sorted(adj[a]):
                if c <= b:
                    continue
                if c in adj[b]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
