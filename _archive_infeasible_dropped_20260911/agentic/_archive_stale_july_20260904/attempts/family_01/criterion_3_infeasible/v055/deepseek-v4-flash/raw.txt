We can solve this by checking all triples, but with n up to 2000 that’s too slow (O(n³)). Instead, we can use the fact that the graph is bipartite (since tasks are split into two streams, and restrictive pairs are between different streams).  

A critical cluster is a triangle in the graph. We need the lexicographically smallest triangle.  

We can iterate over the first vertex `a` from 1 to n, then over `b > a` that is connected to `a`, and then check for `c > b` connected to both `a` and `b`. Using adjacency sets for O(1) lookups, this is efficient enough because m ≤ 2e5.

Here’s the implementation:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(n):
        for b in adj[a]:
            if b <= a:
                continue
            for c in adj[a]:
                if c <= b:
                    continue
                if c in adj[b]:
                    print(a+1, b+1, c+1)
                    return

if __name__ == "__main__":
    solve()
```
