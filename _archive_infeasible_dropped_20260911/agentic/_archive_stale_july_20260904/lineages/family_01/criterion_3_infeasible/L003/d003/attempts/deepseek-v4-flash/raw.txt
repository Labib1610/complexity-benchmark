 We need to find a triangle in an undirected graph.  
The graph is given by edges, and we need to output the lexicographically smallest triangle (a < b < c).  

A direct approach:  
- Store edges in an adjacency set for O(1) lookups.  
- Iterate over all possible triples (a, b, c) in increasing order, and check if all three edges exist.  
- Since n ≤ 2000, O(n³) is too slow (8e9 operations).  

We can do better:  
- For each edge (u, v), check if there is a common neighbor w such that u < v < w (or any order) and all edges exist.  
- We can iterate over all edges, and for each edge, check all neighbors of the smaller endpoint to find a common neighbor.  

Complexity: O(m * degree) worst-case, but with n=2000 and m=2e5, it's feasible if we use sets.  

We also need the lexicographically smallest triangle.  
We can iterate over a from 1 to n, then b from a+1 to n, then c from b+1 to n, but that’s O(n³).  
Instead, we can collect all triangles and pick the smallest.  

But we can also do:  
- For each a from 1 to n:  
  - For each b > a that is connected to a:  
    - For each c > b that is connected to both a and b:  
      - If found, that’s the smallest because we iterate in sorted order.  

This is O(n * m) worst-case, but with early exit it's fine.  

Let's implement that.  

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n + 1)]
for _ in range(m):
    u, v = map(int, input().split())
    adj[u].add(v)
    adj[v].add(u)

for a in range(1, n + 1):
    for b in sorted(adj[a]):
        if b <= a:
            continue
        for c in sorted(adj[b]):
            if c <= b:
                continue
            if c in adj[a]:
                print(a, b, c)
                exit()
```
