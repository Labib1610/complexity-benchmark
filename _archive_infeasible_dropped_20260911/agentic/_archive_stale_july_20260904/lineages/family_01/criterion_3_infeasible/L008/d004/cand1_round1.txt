<STATEMENT>
# Problem C — Proof of Impossibility

Time limit: 2 s
Memory limit: 256 MB

Management insists on dividing the workforce into exactly two non-overlapping shifts. However, the HR department knows this plan is doomed. You must provide undeniable proof of this failure.

HR has a collection of incident files, where each file lists two specific workers who cannot be placed on the same shift. 

Management's plan can be proven impossible if you can find a 'deadlock' in the records. A deadlock consists of a subset of exactly three incident files such that every worker mentioned in this subset appears in exactly two of the three files.

It is guaranteed that at least one such deadlock exists. Your task is to identify the three distinct workers involved in such a deadlock and report them to HR.

## Input
The first line provides the workforce size n and the total incident count m. The workforce size n is bounded below by 3 and bounded above by the facility capacity of 2000. The incident count m is at least 3, and is capped by either the theoretical maximum of n·(n−1)/2 distinct combinations, or the archival capacity of 2·10⁵, whichever is smaller. Workers are identified by integers from 1 to n.

Each of the next m lines contains two integers u and v (1 ≤ u, v ≤ n, u ≠ v), identifying the two workers involved in a single incident. No two incident files list the exact same pair of workers.

It is guaranteed that at least one valid deadlock exists.

## Output
Output three space-separated integers a, b, and c representing the IDs of the three workers involved. They must be printed such that a < b < c.

To ensure a unique valid response when multiple such deadlocks exist, you must select the one that minimizes the value of a. If there is a tie, minimize the value of b among the tied triplets, and if a tie still persists, minimize c.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I removed the explicit mention of "three distinct workers" from the structural definition of the configuration. By defining a deadlock purely as three files where every mentioned worker appears exactly twice, models that rely on surface pattern matching may try to iterate over files (which will TLE) or fail to map the problem to a standard graph triangle. Models that genuinely reason will deduce that 3 files with 2 workers each, where every worker appears twice, mathematically necessitates exactly 3 workers mutually connected.
</RATIONALE>
<PRESERVED_ANSWER>
Since each of the 3 files contains 2 workers (6 total mentions), and every worker in the subset appears exactly twice, there must be exactly 3 distinct workers involved; in a simple graph, this uniquely describes a triangle, which is exactly the same structure as the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem remains finding a triangle (K3) in an undirected graph, keeping it in the same complexity class (solvable in O(n*m/64) using bitsets).
</PRESERVED_CLASS>
<RISK>
A reader might initially be confused about how many workers are in a deadlock, but simple arithmetic (3 files * 2 workers / 2 appearances) unambiguously resolves to exactly 3 workers.
</RISK>
