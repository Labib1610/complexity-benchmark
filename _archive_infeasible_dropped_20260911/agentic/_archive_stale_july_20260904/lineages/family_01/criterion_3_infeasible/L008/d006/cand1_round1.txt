<METHOD_DESCRIPTION>Replaces the explicit edge-by-edge construction of a triangle with a set-theoretic property: three edges (files) whose union of vertices (workers) has a size of exactly 3. Models that pattern-match will literally translate this into an O(m^3) file-combination loop and TLE, while models that reason mathematically will deduce it describes a triangle and use the O(n*m/64) adjacency bitset algorithm.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem C — Proof of Impossibility

Time limit: 2 s
Memory limit: 256 MB

Management insists on dividing the workforce into exactly two non-overlapping shifts. However, the HR department knows this plan is doomed. You must provide undeniable proof of this failure.

HR has a collection of incident files, where each file lists two specific workers who cannot be placed on the same shift. 

Management's plan can be proven impossible if you can find a 'deadlock' in the records. A deadlock is defined as a set of exactly three incident files that, when considered together, involve exactly three distinct workers in total. 

It is guaranteed that at least one such deadlock exists. Your task is to identify the three distinct workers involved in such a deadlock and report them to HR.

## Input
The first line provides the workforce size n and the total incident count m. The workforce size n is bounded below by 3 and bounded above by the facility capacity of 2000. The incident count m is at least 3, and is capped by either the theoretical maximum of n·(n−1)/2 distinct combinations, or the archival capacity of 2·10⁵, whichever is smaller. Workers are identified by integers from 1 to n.

Each of the next m lines contains two integers u and v (1 ≤ u, v ≤ n, u ≠ v), identifying the two workers involved in a single incident. No two incident files list the exact same pair of workers.

It is guaranteed that at least one valid deadlock exists.

## Output
Output three space-separated integers a, b, and c representing the IDs of the three workers involved. They must be printed such that a < b < c.

To ensure a unique valid response when multiple such deadlocks exist, you must select the one that minimizes the value of a. If there is a tie, minimize the value of b among the tied triplets, and if a tie still persists, minimize c.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I changed the definition of a deadlock from an explicit step-by-step connection of three files to a global set-theoretic property: three files that collectively involve exactly three distinct workers. This forces the model to mathematically deduce that three distinct 2-element sets with a union of size 3 must form a triangle. If it fails this reasoning step and relies on a literal translation of the text, it will generate an O(m^3) loop over file combinations and fail due to Time Limit Exceeded.
</RATIONALE>
<PRESERVED_ANSWER>
Because the input guarantees no duplicate files, the only way three distinct 2-worker files can involve exactly three workers in total is if they represent all three possible pairs between those workers, perfectly matching the original triangle definition.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The condition still describes finding a triangle in an undirected graph, which remains in the same polynomial complexity class (solvable in O(n*m/64) using bitsets).
</PRESERVED_CLASS>
<RISK>
A model might briefly misinterpret "involve exactly three distinct workers in total" as meaning each file must individually involve 3 workers, but the phrasing "when considered together" and "in total" strongly clarifies it refers to the union of the files.
</RISK>
