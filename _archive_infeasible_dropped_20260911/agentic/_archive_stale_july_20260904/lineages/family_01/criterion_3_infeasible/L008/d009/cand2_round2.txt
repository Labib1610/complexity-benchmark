<METHOD_NAME>Subset Inclusion Counting</METHOD_NAME>
<METHOD_DESCRIPTION>Instead of asking for three specific records that share exactly three workers, the task asks for a 3-element subset of workers that fully contains exactly 3 records. By framing the search target as the workers rather than the records, and using subset inclusion rather than pairwise adjacency, models that pattern-match for "finding a triangle of edges" or "intersecting neighbors of an edge" will fail to align the set-theoretic condition with their graph heuristics.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Problem C — Proof of Impossibility

Time limit: 2 s
Memory limit: 256 MB

Management insists on dividing the workforce into exactly two non-overlapping shifts. However, the HR department knows this plan is doomed. You must provide undeniable proof of this failure.

HR has a collection of incident files. Each file is a record containing exactly two workers who cannot be placed on the same shift. 

You can prove the plan is impossible by identifying a specific group of workers. Specifically, you must find a set of exactly three distinct workers $W = \{a, b, c\}$ such that the number of incident files entirely contained within $W$ is exactly 3. An incident file is considered entirely contained within $W$ if both workers listed in the file are members of $W$.

It is guaranteed that at least one such set of three workers exists. Your task is to deduce which three workers form this set and report their IDs to HR.

## Input
The first line provides the workforce size $n$ and the total incident count $m$. The workforce size $n$ is at least 3 and is bounded by the facility capacity ($3 \le n \le 2000$). The incident count $m$ is at least 3, and is capped by either the theoretical maximum of distinct pairs or the archival capacity ($3 \le m \le \min(n(n-1)/2, 2 \cdot 10^5)$). Workers are identified by integers from $1$ to $n$.

Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), identifying the two workers involved in a single incident file. No two incident files list the exact same pair of workers.

It is guaranteed that at least one valid set of three workers exists.

## Output
Output three space-separated integers $a$, $b$, and $c$ representing the IDs of the three workers in the set. They must be printed such that $a < b < c$.

To ensure a unique valid response when multiple such groups of workers exist, you must select the group that minimizes the value of $a$. If there is a tie, minimize the value of $b$ among the tied groups, and if a tie still persists, minimize $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
The problem was reframed from finding three records that share three workers, to finding a 3-element subset of workers that fully contains exactly 3 records. This algebraic/set-theoretic phrasing avoids the "common neighbor" or "triangle of edges" pattern matching that models rely on to apply bitset adjacency algorithms, forcing them to reason about the equivalence of subset containment and clique presence.
</RATIONALE>
<PRESERVED_ANSWER>
Because duplicate records are forbidden, a 3-worker set can contain at most 3 records; containing exactly 3 records means all three pairwise combinations are present, which is identical to the original triangle requirement.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to finding a triangle (K3) in an undirected graph, keeping it in the same complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "entirely contained within W" if it wasn't explicitly defined, but the definition "if both workers listed in the file are members of W" removes this ambiguity.
</RISK>
