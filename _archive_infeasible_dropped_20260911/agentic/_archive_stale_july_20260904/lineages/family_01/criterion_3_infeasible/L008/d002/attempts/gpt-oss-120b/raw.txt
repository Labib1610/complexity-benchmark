**Solution Explanation**

For every worker we store the set of workers he/she cannot share a shift with.
The input gives an undirected graph  

* vertices – workers `1 … n`  
* edges – incident files (pairs that must be on different shifts)

A *bad* set of three workers is exactly a **triangle** (3‑clique) in this graph.
The task is to output the lexicographically smallest triangle  
`a < b < c`.

--------------------------------------------------------------------

#### 1.   Data structure – bitset

`n ≤ 2000`, therefore a 2000‑bit integer fits easily into a Python `int`.
For a vertex `v`

```
adj[v]  – integer whose bit u (1 ≤ u ≤ n) is 1  ⇔  edge (v,u) exists
```

Setting a bit: `adj[u] |= 1 << v`.

All operations we need (`&`, test a single bit) are O(1) on such integers.

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle

We try the first vertex `a` in increasing order.
For a fixed `a` we try the second vertex `b` (`b > a`) that is adjacent to `a`.
If `(a,b)` is an edge, the possible third vertices are the common neighbours
of `a` and `b`.

```
common = adj[a] & adj[b]          # vertices adjacent to both a and b
```

Only vertices larger than `b` may be used, otherwise the ordering `a<b<c`
would be violated.  
We delete all bits `≤ b`:

```
mask   = (1 << (b+1)) - 1          # bits 0 … b are 1
common &= ~mask
```

If `common` is non‑zero, the lowest set bit gives the smallest possible `c`,
hence the lexicographically smallest triangle for the current `(a,b)`.
Because we iterate `a` then `b` increasingly, the first triangle we find is
the required answer.

Finding the index of the lowest set bit:

```
low   = common & -common          # isolates lowest 1‑bit
c     = low.bit_length() - 1      # its position
```

The whole algorithm runs in `O(n²)` time (at most `~2·10⁶` iterations) and
`O(n)` memory.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

##### Lemma 1  
For any vertices `a < b`, after the statement  

```
common = adj[a] & adj[b]
common &= ~((1 << (b+1)) - 1)
```

`common` contains exactly the vertices `c` such that  

* `c > b`
* edges `(a,c)` and `(b,c)` exist.

**Proof.**  
`adj[a] & adj[b]` keeps precisely the vertices adjacent to *both* `a` and `b`.  
The mask `((1 << (b+1)) - 1)` has bits `0 … b` set to 1, all higher bits 0.
Negating it clears bits `≤ b` and leaves higher bits unchanged.
Therefore after the `&=`, only vertices `c > b` remain. ∎



##### Lemma 2  
If `common` is non‑zero, `c = (common & -common).bit_length() - 1`
is the smallest vertex `c` satisfying the conditions of Lemma&nbsp;1.

**Proof.**  
`common & -common` isolates the least significant 1‑bit of `common`,
i.e. the smallest index whose bit is set.
`bit_length()` returns the position of the highest 1‑bit plus one,
so for a power of two it yields exactly that index + 1.
Subtracting one gives the vertex number. ∎



##### Lemma 3  
When the algorithm prints a triple `(a,b,c)`, it is a triangle
(`a<b<c` and all three edges exist).

**Proof.**  
`b` is chosen only if edge `(a,b)` exists (explicit test).  
By Lemma&nbsp;1, `c` is taken from `common`, therefore `c>b` and edges
`(a,c)` and `(b,c)` exist. Hence all three edges are present. ∎



##### Lemma 4  
Let `T` be the set of all triangles in the graph.
The algorithm outputs the triangle with the smallest lexicographic
order `(a,b,c)` among `T`.

**Proof.**  
The outer loop enumerates `a = 1,2,…`.  
For a fixed `a`, the inner loop enumerates `b = a+1, a+2,…`.  
Thus triangles are examined in increasing order of `(a,b)`.
For a given pair `(a,b)` Lemma&nbsp;2 yields the smallest possible `c`.
Consequently the first triangle encountered during the enumeration is the
lexicographically smallest triangle overall. ∎



##### Theorem  
The program always prints three integers `a<b<c` that form a triangle,
and among all such triples it is the lexicographically minimal one.

**Proof.**  
Existence: the statement guarantees at least one triangle, so the loops will
eventually find a non‑empty `common` and output a triple.  
By Lemma&nbsp;3 the printed triple is a triangle.  
By Lemma&nbsp;4 it is the lexicographically smallest triangle. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Memory* : `adj` – `n+1` integers, each ≤ `2ⁿ` → `O(n)`.

*Time* :

```
for a = 1 … n-2:
    for b = a+1 … n:
        constant work (bit tests, &, mask)
```

Number of iterations ≤ `n·(n-1)/2 ≤ 2·10⁶` for `n = 2000`.  
All operations inside are O(1).  
Hence total time `O(n²)` ≤ `2·10⁶` elementary operations, well inside limits.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # bitset, 1‑based vertices
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(1, n - 1):
        a_adj = adj[a]
        for b in range(a + 1, n + 1):
            if (a_adj >> b) & 1:          # edge (a,b) exists
                common = a_adj & adj[b]    # neighbours of both
                # keep only vertices > b
                mask = (1 << (b + 1)) - 1
                common &= ~mask
                if common:
                    low = common & -common
                    c = low.bit_length() - 1
                    sys.stdout.write(f"{a} {b} {c}")
                    return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
