# Problem C — Proof of Impossibility

Time limit: 2 s
Memory limit: 256 MB

Management insists on dividing the workforce into exactly two non-overlapping shifts. However, the HR department knows this plan is doomed. You must provide undeniable proof of this failure.

HR has a collection of incident files, where each file lists two specific workers who cannot be placed on the same shift. 

It is a known fact that the archives contain a set of exactly three distinct incident files which, when the workers listed in these three files are pooled together, feature exactly three distinct workers in total. The existence of such a configuration mathematically guarantees that two shifts are inadequate. Your task is to identify the three workers involved in one such configuration and report them to HR.

## Input
The first line of the log provides the workforce size n and the total incident count m. The workforce size n is bounded below by 3 and bounded above by the facility capacity of 2000. The incident count m is at least 3, and is capped by either the theoretical maximum of n·(n−1)/2 distinct combinations, or the archival capacity of 2·10⁵, whichever is smaller. Workers are identified by integers from 1 to n.

Each of the next m lines contains two integers u and v (1 ≤ u, v ≤ n, u ≠ v), identifying the two workers involved in a single incident. No two incident files list the exact same pair of workers.

It is guaranteed that at least one valid configuration of three workers exists.

## Output
Output three space-separated integers a, b, and c representing the IDs of the three workers involved. They must be printed such that a < b < c.

To ensure a unique valid response when multiple such triplets of workers exist, you must select the triplet that minimizes the value of a. If there is a tie, minimize the value of b among the tied triplets, and if a tie still persists, minimize c.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
Changed the description from a vertex-centric definition ("a set of three workers where every two-person combination within that set is documented") to an edge-centric one ("exactly three distinct incident files which... feature exactly three distinct workers in total"). This removes the explicit prompt to check all pairs between three workers, forcing the model to mathematically deduce that three simple edges spanning exactly three vertices is equivalent to a triangle (3-clique) before it can apply the intended common-neighbor heuristic.
</RATIONALE>
<PRESERVED_ANSWER>
Because the graph is simple (no multi-edges or self-loops), any set of exactly 3 edges that collectively span exactly 3 vertices must form a cycle of length 3 (a triangle), meaning the valid sets of workers and the tie-breaking logic are mathematically identical to the seed.
</PRESERVED_ANSWER>

The problem still asks to find a triangle (K3) in an undirected graph, maintaining its status as a certificate of 2-colorability infeasibility and requiring the exact same time complexity.
</PRESERVED_CLASS>

Models might misinterpret "feature exactly three distinct workers in total" as a global property of the entire dataset rather than the union of the three selected files, though the phrase "when the workers listed in these three files are pooled together" is designed to heavily scope it.
