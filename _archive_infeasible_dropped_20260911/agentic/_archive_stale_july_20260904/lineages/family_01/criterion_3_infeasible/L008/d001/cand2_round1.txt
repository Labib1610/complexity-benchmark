<STATEMENT>
# Promotional Synergy

Time limit: 2 s
Memory limit: 256 MB

Description:
You are building an analytics pipeline for a retail database that tracks $n$ distinct products.
The database contains $m$ 'co-purchased' records. Each record pairs two distinct products that have been bought together.
Marketing wants to identify a "Synergy Group" to run a special promotion. To form a Synergy Group, you must select exactly three distinct products—designated as the anchor, the complement, and the booster—that satisfy the following three conditions:
- A co-purchased record exists between the anchor and the complement.
- A co-purchased record exists between the anchor and the booster.
- A co-purchased record exists between the complement and the booster.

Because the promotional engine requires a deterministic choice, you must output the IDs of the three selected products sorted in ascending order. If multiple valid Synergy Groups can be formed, you must output the one that is lexicographically smallest. (This means you first minimize the smallest of the three IDs; if there is a tie, you minimize the middle ID; and if still tied, you minimize the largest ID).

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2 \cdot 10^5)$).
Each of the next $m$ lines contains two integers $u$ and $v$, indicating a co-purchased record between product $u$ and product $v$.
It is guaranteed that the records allow the formation of at least one Synergy Group.

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$, representing the sorted product IDs of the chosen Synergy Group.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
The original problem framed the task as finding a hopeless roster to certify the impossibility of a 2-shift schedule, which easily triggers pattern matching for "certify non-bipartite" or "find a triangle". This was removed entirely and replaced with a retail analytics scenario. Additionally, the symmetric description ("every possible pair drawn from these three") was replaced with an asymmetric listing of three roles (anchor, complement, booster) and their specific pairwise interactions. This forces the model to synthesize the three independent rules into a single structural requirement (a 3-clique) rather than relying on surface-level keyword matching.
</RATIONALE>
<PRESERVED_ANSWER>
The problem still requires finding a set of three items where all three possible pairwise relationships exist in the input, and outputting the lexicographically smallest such triplet sorted in ascending order, mathematically identical to the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying task remains finding a 3-clique (triangle) in an undirected graph, preserving the original computational complexity and the viability of the intended bitset intersection algorithm.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret the asymmetric roles (anchor, complement, booster) as requiring the output to be ordered by those roles rather than ascending by ID, though the instructions explicitly state to "output the IDs of the three selected products sorted in ascending order" to mitigate this.
</RISK>
