**Solution Explanation**

For three conflict records to contain exactly three different workers and each
worker to appear in exactly two records, the three records must be the three
edges of a triangle:

```
workers a , b , c          records (a,b) , (a,c) , (b,c)
```

So we only have to find a triangle in the given undirected graph and output the
lexicographically smallest triple `(a,b,c)` (`a<b<c`).

--------------------------------------------------------------------

#### Data structures  

* `adj[i]` – an integer whose binary representation is a bitset of the
  neighbours of vertex `i` (bit `j` is `1` iff edge `i‑j` exists).  
  `n ≤ 2000`, therefore one integer (≈ 2000 bits) is enough.

* The graph is undirected, we store each edge in both bitsets.

--------------------------------------------------------------------

#### Algorithm  

```
read n , m
adj[1..n] = 0
for each edge (u,v):
        set bit v-1 in adj[u]
        set bit u-1 in adj[v]

for a = 1 .. n:
        for b = a+1 .. n:
                if edge a‑b does not exist: continue
                common = adj[a] & adj[b]          # vertices adjacent to both a and b
                # we need a vertex c > b
                mask = common >> b                # discard bits 0..b-1
                if mask != 0:
                        # lowest set bit gives the smallest possible c
                        low = mask & -mask
                        idx = low.bit_length() - 1          # 0‑based inside mask
                        c = idx + b + 1
                        output a b c and finish
```

*The loops enumerate triples in lexicographic order* (`a` increasing,
inside it `b` increasing, and for a fixed `(a,b)` we take the smallest possible
`c`).  
The first triangle found is therefore the required answer.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triple of workers that forms a deadlock (triangle).

---

##### Lemma 1  
If the algorithm outputs a triple `(a,b,c)`, then edges `(a,b)`, `(a,c)`,
`(b,c)` are all present in the input.

**Proof.**  
The outer loops guarantee `a<b`. The inner `if` checks that edge `a‑b` exists.
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to **both**
`a` and `b`. `c` is taken from `common`, therefore `c` is adjacent to `a`
and to `b`. ∎



##### Lemma 2  
The algorithm outputs a triple only if it is a deadlock.

**Proof.**  
By Lemma&nbsp;1 the three edges exist, and the three vertices are distinct
(`a<b<c`). The three edges involve exactly the three vertices, each appearing in
two edges, which matches the definition of a deadlock. ∎



##### Lemma 3  
If a deadlock (triangle) `{x,y,z}` exists, the algorithm will eventually
consider the ordered pair `(a,b) = (min(x,y), max(x,y))` and will find the third
vertex `c = the remaining one`.

**Proof.**  
All vertices are iterated, so the pair `(a,b)` equal to the two smallest
numbers of the triangle appears. Since the edge between them exists,
the algorithm reaches the line `common = adj[a] & adj[b]`.  
The third vertex of the triangle is adjacent to both `a` and `b`, therefore it
belongs to `common`. After shifting by `b`, it is still present, so `mask≠0`
and the algorithm extracts it as `c`. ∎



##### Lemma 4  
The first triple output by the algorithm is the lexicographically smallest
triangle.

**Proof.**  
The outer loops enumerate all ordered pairs `(a,b)` with `a<b` in increasing
lexicographic order. For a fixed pair, the algorithm chooses the smallest
possible `c>b` (the lowest set bit after the shift). Hence triples are examined
in the exact order required for lexicographic comparison. The first one that
forms a triangle is therefore the smallest. ∎



##### Theorem  
The algorithm always outputs three integers `a<b<c` that form a deadlock, and
they are the lexicographically smallest such triple.

**Proof.**  
Existence: the statement guarantees at least one deadlock, i.e. a triangle.
By Lemma&nbsp;3 the algorithm will find it, thus it will output some triple.
By Lemma&nbsp;2 any output triple is a deadlock.  
Minimality: by Lemma&nbsp;4 the first (and only) output is the lexicographically
smallest triangle. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building bitsets*: `O(m)` operations.  
*Main loops*: at most `n·(n-1)/2 ≤ 2·10⁶` iterations (since `n ≤ 2000`).  
All operations inside are O(1) bitwise integer ops.  
Hence total time `O(n² + m) ≤ 2·10⁶ + 2·10⁵`, well below the limit.  

Memory: `n+1` integers, each ≤ 2ⁿ, i.e. about `n·n/8 ≤ 0.5 MB`.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        bit_v = 1 << (v - 1)
        bit_u = 1 << (u - 1)
        adj[u] |= bit_v
        adj[v] |= bit_u

    for a in range(1, n + 1):
        mask_a = adj[a]
        for b in range(a + 1, n + 1):
            # edge a‑b ?
            if not (mask_a >> (b - 1)) & 1:
                continue
            common = mask_a & adj[b]          # neighbours of both a and b
            # keep only vertices > b
            mask = common >> b
            if mask:
                low = mask & -mask
                idx = low.bit_length() - 1    # 0‑based inside shifted mask
                c = idx + b + 1
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
