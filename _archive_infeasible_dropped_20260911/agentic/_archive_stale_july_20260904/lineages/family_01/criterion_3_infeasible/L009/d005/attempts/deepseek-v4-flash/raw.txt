 We need to find three vertices that form a triangle in the complement graph.  
That is, three materials such that no two are connected by an edge in the original graph.  

The problem guarantees at least one such triple exists.  

We can solve it by checking all triples in increasing order and stopping at the first valid one.  
Since n ≤ 2000, O(n³) is too slow (8e9 operations).  
We need a smarter approach.

We can use the fact that if a triple exists, we can find it by checking each vertex as the smallest in the triple.  
For each vertex `a`, we look at all vertices not connected to `a` (non-neighbors).  
Among those, we need two that are not connected to each other.  

We can do this by:
- For each `a`, collect all non-neighbors (excluding `a` itself).
- For each pair among those non-neighbors, check if they are not connected.  
But that could still be O(n³) in worst case.

Better:  
We can use the complement graph idea:  
We need a triangle in the complement graph.  
We can find a triangle in a graph in O(n²) using a simple algorithm:  
For each vertex `u`, check all pairs of its neighbors in the complement graph.  
If any two neighbors are also connected in the complement, we have a triangle.

But we need the lexicographically smallest triple.  
We can iterate `a` from 1 to n, then `b` from a+1 to n, then `c` from b+1 to n, and stop at first valid.  
But that's O(n³) worst-case.

However, we can optimize:  
For each `a`, we only need to check `b` and `c` among non-neighbors of `a`.  
If the number of non-neighbors is small, it's fast.  
In the worst case, if the graph is sparse, non-neighbors are many, but then we can find a triangle quickly.

We can use the following approach:  
For each `a`, collect non-neighbors.  
If there are at least 2 non-neighbors, check all pairs among them.  
If we find a pair not connected, we have our triple.  
If not, move to next `a`.

This is still O(n³) in worst case if many non-neighbors and no triangle early.  
But we can break early because the problem guarantees a triangle exists.

Given n ≤ 2000, we can do O(n²) by using adjacency matrix and checking all triples in a smart order:  
We can iterate `a` from 1 to n, then `b` from a+1 to n, and for each `b`, we check if `a` and `b` are not connected.  
If not, we then look for `c` > b such that `a` and `c` are not connected and `b` and `c` are not connected.  
We can precompute for each pair (a,b) the set of common non-neighbors.  
But that's O(n³) memory.

Simpler:  
We can use the fact that if we find any triangle in the complement, we can then find the lexicographically smallest by checking all triples in order and stopping at first valid.  
But that's O(n³) time.

Given n=2000, O(n³) = 8e9, too slow.

We need O(n²) or O(n² log n).

We can do:  
For each `a`, find all non-neighbors.  
If there are at least 2, we check if any two are not connected.  
If yes, we have a triple.  
We can do this by:  
- For each `a`, get list L of non-neighbors.  
- For each i in L, for each j in L with j>i, check if not connected.  
This is O(deg_complement²) per a.  
In worst case, if graph is empty (no edges), then complement is complete, so non-neighbors of a are all other vertices, and we will find a triangle immediately (first three vertices).  
If graph is dense, non-neighbors are few, so fast.

Worst case is when graph is such that each vertex has about n/2 non-neighbors, and no triangle until late.  
But we can still bound:  
For each a, we check pairs among non-neighbors.  
If we find a triangle, we stop.  
Since we iterate a from 1 upward, we will find the lexicographically smallest triple.

We can implement with adjacency matrix for O(1) edge checks.

Let's code it.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [[False]*n for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u][v] = adj[v][u] = True
    
    for a in range(n):
        non_neighbors = [i for i in range(n) if i != a and not adj[a][i]]
        if len(non_neighbors) < 2:
            continue
        # Check pairs
        for idx1 in range(len(non_neighbors)):
            b = non_neighbors[idx1]
            if b <= a:
                continue
            for idx2 in range(idx1+1, len(non_neighbors)):
                c = non_neighbors[idx2]
                if c <= b:
                    continue
                if not adj[b][c]:
                    print(a+1, b+1, c+1)
                    return

if __name__ == "__main__":
    main()
```
