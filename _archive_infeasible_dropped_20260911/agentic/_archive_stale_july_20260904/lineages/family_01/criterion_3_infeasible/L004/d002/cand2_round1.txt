# Critical Interference

Time limit: 2 s
Memory limit: 256 MB

A proposed security protocol attempts to assign $n$ communication nodes (numbered 1 to $n$) to one of two distinct channels. The network requires a minimum of 3 nodes to be active, and a primary routing hub limits the total node count to a maximum of 2000. 

There are $m$ specific connections between nodes that cause mutual severe interference. The total number of connections is at least 3. It will never exceed the theoretical maximum number of unique pairs among the $n$ nodes, nor will it exceed the system's hard limit of 200,000 connections. 

The protocol's requirements are known to be fundamentally impossible to satisfy. Your task is to certify this impossibility. You must identify a sequence of three distinct nodes $a$, $b$, and $c$, with $a < b < c$, such that:
- Node $a$ and node $b$ share a connection causing severe interference.
- Node $a$ and node $c$ share a connection causing severe interference.
- Node $b$ and node $c$ share a connection causing severe interference.

Any such sequence of three nodes demonstrates that two channels are insufficient. It is guaranteed that at least one such sequence exists.

## Input
The first line contains the two integers $n$ and $m$.
Each of the next $m$ lines contains two integers $u$ and $v$ — representing a mutual interference connection between these two nodes. 

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$, representing the identifiers of the three nodes. 
Output the lexicographically smallest such sequence (smallest $a$; ties broken by smallest $b$; then smallest $c$).

## Example 1
### Input
```
4 5
1 2
1 3
2 3
2 4
3 4
```
### Output
```
1 2 3
```

## Example 2
### Input
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
### Output
```
1 2 4
```
