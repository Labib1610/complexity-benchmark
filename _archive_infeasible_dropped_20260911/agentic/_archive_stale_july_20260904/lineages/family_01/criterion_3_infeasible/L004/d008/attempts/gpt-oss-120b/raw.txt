**Solution Explanation**

For three vertices `u < v < w` let  

* `x = 1` if edge `u‑v` exists, otherwise `0`
* `y = 1` if edge `u‑w` exists, otherwise `0`
* `z = 1` if edge `v‑w` exists, otherwise `0`

The matrix described in the statement is  

```
[-1  x  y]
[ x -1  z]
[ y  z -1]
```

Its determinant is

```
-1 + x² + y² + z² + 2·x·y·z
```

Because `x , y , z` are `0` or `1`

```
det = -1 + (x+y+z) + 2·x·y·z
```

`det = 4`  ⇔  `x+y+z + 2·x·y·z = 5`.

If any of `x , y , z` is `0` the left side is at most `3`.  
Therefore `x = y = z = 1` – the three vertices must form a **triangle**
(all three edges are present).  
For a triangle the determinant is exactly `4`.

So the problem reduces to:

*find the lexicographically smallest triangle in the given undirected graph.*

--------------------------------------------------------------------

#### 1.   Data structure – bitsets

`n ≤ 2000`, therefore a 2000‑bit integer fits easily in Python.
For every vertex `i` we store an integer `adj[i]` whose `j`‑th bit is `1`
iff edge `i‑j` exists.

All operations we need are:

* test whether an edge `(i , j)` exists – one bit test,
* intersect the neighbour sets of two vertices – bitwise **AND**,
* find the smallest vertex larger than a given index in a bitset –  
  shift right and take the lowest set bit.

All of them are `O(1)` on the size of the integer (the whole bitset is
handled by the CPU in a few machine words).

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle

We iterate vertices in increasing order, guaranteeing the smallest `a`.

```
for a = 0 … n-1:
    for b = a+1 … n-1,  if edge a‑b exists:
        common = adj[a] & adj[b]          # vertices adjacent to both a and b
        # we need a vertex c > b
        mask = common >> (b+1)
        if mask != 0:
            c = (mask & -mask).bit_length() - 1 + (b+1)
            output (a,b,c)   # first found is the answer
```

* `common` contains all vertices that together with `a` and `b` would
  close a triangle.
* Shifting by `b+1` discards vertices `≤ b`; the lowest set bit of the
  remaining number is the smallest possible `c`.
* Because the outer loops increase `a` first, then `b`, the first
  triangle we encounter is exactly the lexicographically smallest one.

The number of iterations of the inner loop equals the number of edges
(`m ≤ 2·10⁵`). Each iteration performs a few integer operations – well
within the limits.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the required triple.

---

##### Lemma 1  
For any three distinct vertices `u < v < w` the determinant of the
matrix defined in the statement equals `4` **iff** the three edges
`(u,v) , (u,w) , (v,w)` are all present.

**Proof.**  
From the computation in the analysis part  

```
det = -1 + (x+y+z) + 2·x·y·z
```

with `x,y,z ∈ {0,1}`.
If any of `x,y,z` is `0`, the right side ≤ `-1+3 = 2`.  
If all are `1`, the right side = `-1+3+2 = 4`. ∎



##### Lemma 2  
When the algorithm examines a pair `(a,b)` (`a<b`) it finds the
smallest vertex `c>b` such that `{a,b,c}` is a triangle, if such a `c`
exists.

**Proof.**  
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to **both**
`a` and `b`.  
Shifting right by `b+1` removes all vertices `≤ b`.  
If the resulting number `mask` is non‑zero, its lowest set bit corresponds
to the smallest remaining vertex `c`. By construction `c` is adjacent to
both `a` and `b`, therefore `{a,b,c}` is a triangle, and no smaller
`c>b` can satisfy this. ∎



##### Lemma 3  
If the algorithm outputs a triple `(a,b,c)`, it is a triangle and
`a<b<c`.

**Proof.**  
The triple is produced only after the test `mask != 0`, i.e. after
Lemma&nbsp;2 guarantees existence of a vertex `c>b` adjacent to both `a`
and `b`. Edge `a‑b` is known to exist because the inner loop iterates
only over such edges. Hence all three edges are present – a triangle.
Indices are taken from the loops (`a<b`) and from Lemma&nbsp;2 (`c>b`),
so `a<b<c`. ∎



##### Lemma 4  
Let `T` be the lexicographically smallest triangle in the graph.
The algorithm outputs `T`.

**Proof.**  
Consider the outer loop iteration with `a = T₁` (the smallest vertex of
`T`). All earlier values of `a` are `< T₁` and cannot start a triangle
lexicographically smaller than `T`.  

During this iteration the inner loop scans `b = T₂, T₂+1, …`.  
When `b = T₂` the edge `a‑b` exists (by definition of `T`).  
By Lemma&nbsp;2 the algorithm finds the smallest `c>b` that together with
`a,b` forms a triangle. Since `T₃` is such a vertex and any smaller
`c` would give a triangle `(a,b,c)` lexicographically smaller than `T`,
the algorithm must obtain `c = T₃`.  

Thus the first triangle discovered is exactly `T`, and the algorithm
terminates with it. ∎



##### Theorem  
The program prints three integers `a<b<c` that form a triangle and among
all such triples it is the lexicographically smallest one.

**Proof.**  
By Lemma&nbsp;3 any printed triple is a triangle.  
By Lemma&nbsp;4 the first triangle found (and printed) is the smallest
lexicographically. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets* : `O(m)`  
*Main loops* : one iteration per edge → `O(m)`  
All operations inside are constant‑time on 2000‑bit integers.

```
Time   :  O(m)   ≤ 2·10⁵
Memory :  n integers of ≤ 2000 bits  →  O(n)  ≤ 2000·256 bytes ≈ 0.5 MiB
```

Both limits satisfy the problem constraints.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n          # bitset for each vertex, 0‑based
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(n):
        a_adj = adj[a]
        # iterate b > a where edge a‑b exists
        # we can scan all b, checking the bit
        for b in range(a + 1, n):
            if (a_adj >> b) & 1 == 0:
                continue
            common = a_adj & adj[b]          # neighbours of both a and b
            # need c > b
            mask = common >> (b + 1)
            if mask:
                # lowest set bit
                low = mask & -mask
                c = low.bit_length() - 1 + (b + 1)
                # output 1‑based
                print(a + 1, b + 1, c + 1)
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
