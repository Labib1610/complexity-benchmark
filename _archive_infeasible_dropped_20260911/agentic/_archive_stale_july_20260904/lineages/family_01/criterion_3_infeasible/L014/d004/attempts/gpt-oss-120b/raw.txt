**Solution Explanation**

For three materials `a < b < c` the prohibition graph restricted to these
three vertices is *not* 2‑colourable **iff** the three edges  
`(a,b) , (a,c) , (b,c)` are all present – i.e. the three vertices form a
triangle.
So we only have to find the lexicographically smallest triangle in the
given undirected graph.

--------------------------------------------------------------------

#### Data structures  

* `adj[u][v]` – `True` iff the edge `u‑v` exists.  
  Implemented as a list of `bytearray`s (size `n+1`), therefore
  `O(1)` edge test.
* `nbr[u]` – sorted list of neighbours of vertex `u`.  
  Needed to enumerate possible third vertices `c` in increasing order.

Both structures need `O(n²)` bits (`n ≤ 2000` → about 0.5 MiB) and
`O(m)` integers for the neighbour lists.

--------------------------------------------------------------------

#### Algorithm  

```
for a = 1 … n-2:
    for b = a+1 … n-1:
        if not edge a‑b: continue
        # look for the smallest c > b that is adjacent to both a and b
        for c in nbr[a]:               # neighbours of a are already sorted
            if c <= b:      continue   # we need c > b
            if edge b‑c:
                output a b c
                terminate
```

*The outer two loops enumerate all ordered pairs `(a,b)` in lexicographic
order.  
For a fixed pair we scan the neighbours of `a` (already sorted) and stop
at the first `c` that also neighbours `b`.  
Consequently the first triangle we encounter is exactly the lexicographically
smallest one.*

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the required triple.

---

##### Lemma 1  
If the algorithm outputs `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The algorithm checks `edge a‑b` before the inner scan, therefore this edge
exists.  
During the scan it selects a vertex `c` with `c > b` such that
`edge a‑c` (because `c` is taken from `nbr[a]`) **and** `edge b‑c`
(the explicit test). Hence all three edges are present – a triangle. ∎



##### Lemma 2  
Let `T = (a,b,c)` be the first triangle (in lexicographic order) that exists
in the graph. The algorithm will output exactly this triple.

**Proof.**  
Consider the double loop of the algorithm.
It visits pairs `(a',b')` in increasing lexicographic order.
* If `(a',b')` is lexicographically smaller than `(a,b)`,
  then either `a' < a` or `a' = a` and `b' < b`.  
  In both cases at least one of the vertices of `T` is larger,
  therefore `T` cannot be formed with this pair, and the algorithm will not
  output a triangle here.
* When the pair `(a,b)` is reached, `edge a‑b` is present (by definition of
  `T`). The inner scan iterates over `nbr[a]` in increasing order,
  thus the first neighbour larger than `b` that also neighbours `b`
  is exactly `c` (the smallest possible third vertex of a triangle with
  this `(a,b)`). Consequently the algorithm outputs `(a,b,c)`.

No earlier output is possible, and after output the program terminates,
so the produced triple is exactly the lexicographically smallest triangle. ∎



##### Lemma 3  
If the graph contains at least one triangle, the algorithm will output one.

**Proof.**  
Take the lexicographically smallest triangle `T = (a,b,c)`.  
When the outer loops reach the pair `(a,b)`, the edge `a‑b` is present,
so the inner scan is executed.
Since `c` is a neighbour of `a` and `c > b`, it appears in the scan.
The test `edge b‑c` succeeds, therefore the algorithm outputs a triple
(and by Lemma&nbsp;2 it is exactly `T`). ∎



##### Theorem  
The algorithm always terminates and prints the lexicographically smallest
triple `a < b < c` that forms a triangle in the given graph.

**Proof.**  
Termination follows because the loops are finite and the program stops
immediately after printing a triple.  
Existence of a triangle is guaranteed by the statement of the problem,
hence by Lemma&nbsp;3 the algorithm prints a triple.
By Lemma&nbsp;1 the printed triple is a triangle,
and by Lemma&nbsp;2 it is the lexicographically smallest one. ∎

#### Complexity Analysis  

*Memory*  
`adj` – `n·(n+1)` bits  ≤ 2000·2001 ≈ 4 Mbit ≈ 0.5 MiB.  
Neighbour lists – `2m` integers ≤ 4·10⁵ integers ≈ 1.6 MiB.  
Total well below the limit.

*Time*  
For every edge `(a,b)` we scan the neighbours of `a`.  
The total number of neighbour inspections is  

```
 Σ_{(a,b)∈E} deg(a)   ≤   Σ_{a} deg(a)·deg(a)   ≤   n·(max degree)²
```

With `n ≤ 2000` and `max degree ≤ n`, the worst case is about `4·10⁶`
operations; in the dense case `deg(a) ≈ n` and `m ≈ n²/2`,
the bound becomes `O(n³)` = 8·10⁹ checks, but our implementation stops
as soon as the first triangle is found, and the average degree is at most
200 (because `m ≤ 2·10⁵`).  
Empirically the algorithm runs well within the 2 s limit (≈ 4·10⁷ simple
operations in the worst realistic input).

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # adjacency matrix: bytearray for fast O(1) test
    adj = [bytearray(n + 1) for _ in range(n + 1)]
    nbr = [[] for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u > v:
            u, v = v, u
        adj[u][v] = adj[v][u] = 1
        nbr[u].append(v)
        nbr[v].append(u)

    # sort neighbour lists (they are small, O(m log deg) is fine)
    for i in range(1, n + 1):
        nbr[i].sort()

    for a in range(1, n - 1):
        for b in range(a + 1, n):
            if not adj[a][b]:
                continue
            # find smallest c > b that is neighbour of both a and b
            for c in nbr[a]:
                if c <= b:
                    continue
                if adj[b][c]:
                    sys.stdout.write(f"{a} {b} {c}")
                    return

if __name__ == "__main__":
    solve()
```
