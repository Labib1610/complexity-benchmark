# Production Line Diagnostics

Time limit: 2 s   Memory limit: 256 MB

A manufacturing facility distributes tasks between a primary and a secondary assembly track. Certain tasks cannot run on the same track because they both need access to a specific single-use jig. This means if you pick any two such tasks, they must be separated across the two tracks. 

The current task list cannot be scheduled across the two tracks without a delay. The diagnostic protocol requires finding a core conflict: a group of three distinct tasks where every possible pair drawn from this group has a recorded jig-sharing restriction. Because there are only two tracks, these three tasks can never be scheduled simultaneously.

The facility handles a minimum of three tasks to form a valid batch, and due to the memory constraints of the legacy controller, it can process up to a maximum of two thousand tasks per batch. The number of jig-sharing restrictions recorded in the system is at least three, and is capped by the system's log capacity at two hundred thousand (or the theoretical maximum of all possible distinct pairs among the tasks, whichever is less). 

If multiple such core conflicts exist, the system logs the one whose task identifiers sort earliest.

## Input
The first line contains two integers $n$ and $m$, representing the total number of tasks and the number of jig-sharing restrictions. The values of $n$ and $m$ conform to the physical and system limits described above. Tasks are numbered sequentially starting from $1$ up to $n$.
Each of the following $m$ lines contains two distinct integers $u$ and $v$ representing valid task identifiers, indicating that task $u$ and task $v$ cannot be assigned to the same track.
It is guaranteed that at least one core conflict exists in the provided data.

## Output
Print three integers on a single line, separated by spaces, sorted in ascending order, representing the identifiers of the three tasks forming the core conflict. Output the combination that sorts earliest (the smallest possible first identifier; in case of a tie, the smallest second; and finally the smallest third).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
