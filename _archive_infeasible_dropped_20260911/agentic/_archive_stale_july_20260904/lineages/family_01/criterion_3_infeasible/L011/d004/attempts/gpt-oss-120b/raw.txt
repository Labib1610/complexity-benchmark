**Solution Explanation**

For every pair of steps `u , v` we are given that they **must not** be placed on the same
production line.
If three steps `a < b < c` are taken, the 8 possible assignments of the three steps to
the two lines are exactly the 2‑colourings of the induced subgraph on `{a,b,c}`.
All 8 colourings contain a conflict **iff** the induced subgraph is a triangle
(`a‑b , a‑c , b‑c` are all edges).  
Indeed, if one of the three edges is missing we can colour its two ends differently
and the third vertex with any colour – no edge has equal colours.

So the required “unresolvable bottleneck’’ is simply a **triangle** in the given
graph.
We have to output the lexicographically smallest triple
`a < b < c` that forms a triangle.

--------------------------------------------------------------------

#### 1.   Data structure – bitsets

`n ≤ 2000`, therefore a 2000‑bit set fits into a Python integer.
For every vertex `v` we store

```
adj[v] : integer, bit i (0‑based) is 1  ⇔  vertex (i+1) is adjacent to v
```

All operations on such bitsets are O(1) (single machine word operations).

--------------------------------------------------------------------

#### 2.   Finding the smallest triangle

* iterate over all edges `(a,b)` with `a < b` **in lexicographic order**  
  (first by `a`, then by `b`);
* the vertices that are adjacent to **both** `a` and `b` are

```
common = adj[a] & adj[b]          # bitset of common neighbours
```

* we need a common neighbour `c` that is larger than `b`.
  Bits `0 … b‑1` correspond to vertices `1 … b`.  
  By shifting right by `b` we discard them:

```
tmp = common >> b                 # bit 0 now corresponds to vertex b+1
```

* if `tmp` is non‑zero, its least significant set bit gives the smallest possible
  `c`:

```
lsb = (tmp & -tmp)                # isolates lowest 1‑bit
pos = lsb.bit_length() - 1        # position of that bit (0‑based)
c   = b + 1 + pos                  # vertex number
```

* the first triangle found in this loop is the answer, because edges are processed
  in increasing `(a,b)` order and for a fixed `(a,b)` we pick the smallest possible
  `c`.

The whole algorithm is `O(m)` big‑integer operations, easily fast enough
(`m ≤ 2·10⁵`).

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

##### Lemma 1  
A set of three vertices `{a,b,c}` is an “unresolvable bottleneck’’
iff the three edges `ab , ac , bc` are all present (i.e. they form a triangle).

**Proof.**  
If the three edges are present, any 2‑colouring gives two vertices of the same
colour that are adjacent, therefore a conflict – all 8 assignments fail.

Conversely, assume at least one of the three edges is missing, say `ac` is not an
edge. Colour `a` red, `c` blue, and colour `b` arbitrarily (red).  
Edge `ab` connects red–red only if it exists, but we can choose the colour of `b`
blue instead, making both existing edges (`ab` and `bc`) connect different colours.
Thus a conflict‑free assignment exists, contradicting the definition. ∎



##### Lemma 2  
When the algorithm processes an edge `(a,b)` (with `a<b`) it finds the smallest
vertex `c>b` such that `{a,b,c}` is a triangle, if such a vertex exists.

**Proof.**  
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to **both**
`a` and `b`.  
Shifting right by `b` removes all vertices `≤ b`.  
If the resulting integer `tmp` is non‑zero, its least significant set bit corresponds
to the smallest remaining vertex, i.e. the smallest `c>b` belonging to `common`. ∎



##### Lemma 3  
The first triangle output by the algorithm is the lexicographically smallest
triangle of the whole graph.

**Proof.**  
Edges are examined in increasing order of `(a,b)`.  
Consider any triangle `{x,y,z}` with `x<y<z`. Its edge `(x,y)` will be examined
when the algorithm reaches `(a,b) = (x,y)`.  
By Lemma&nbsp;2 the algorithm will then discover `c = z` (or a smaller `c` if the
triangle had a smaller third vertex).  
Therefore the algorithm outputs a triangle whose first two vertices are not larger
than those of any other triangle.  
If several triangles share the same `(a,b)`, Lemma&nbsp;2 guarantees the smallest
possible `c` is chosen. Hence the output is lexicographically minimal. ∎



##### Theorem  
The algorithm always prints three integers `a<b<c` that form an unresolvable
bottleneck, and among all such triples it prints the lexicographically smallest
one.

**Proof.**  
Existence of at least one required triple is guaranteed, i.e. at least one
triangle exists. While iterating over edges the algorithm will eventually
process an edge belonging to a triangle; by Lemma&nbsp;2 it will then output that
triangle and terminate. By Lemma&nbsp;1 the printed triple is indeed an
unresolvable bottleneck. Lemma&nbsp;3 shows that the printed triple is the
lexicographically smallest possible. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets* : `O(m)`  
*Sorting edges*            : `O(m log m)` ( `m ≤ 2·10⁵` )  
*Main loop*               : each edge → one big‑integer `&` and shift → `O(1)`  
Overall time   `O(m log m)` ≤ `~2·10⁵ log 2·10⁵` – well below the 2 s limit.  

Memory: `n` integers of at most 2000 bits → `n·256 bytes` ≈ 0.5 MB, plus edge list –
far below 256 MB.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    edges = []

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u == v:
            continue
        if u > v:
            u, v = v, u
        # set bits
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)
        edges.append((u, v))

    edges.sort()                 # lexicographic order

    for a, b in edges:
        common = adj[a] & adj[b]          # vertices adjacent to both
        # keep only vertices > b
        tmp = common >> b                  # drop bits 0..b-1 (indices)
        if tmp:
            # isolate lowest set bit
            lsb = tmp & -tmp
            pos = lsb.bit_length() - 1    # position inside tmp
            c = b + 1 + pos                # real vertex number
            # output
            sys.stdout.write(f"{a} {b} {c}")
            return

if __name__ == "__main__":
    solve()
```
