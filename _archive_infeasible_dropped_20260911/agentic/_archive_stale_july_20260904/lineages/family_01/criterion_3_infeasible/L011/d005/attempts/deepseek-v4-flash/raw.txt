 We need to find a triangle in the graph, and among all triangles, pick the one with the smallest lexicographic order of its vertices.

A triangle is a set of three vertices where each pair is connected by an edge.  
We can iterate over all triples in increasing order and check if they form a triangle.  
Since \( n \) can be up to 2000, checking all triples naively would be \( O(n^3) \), which is too slow.

We can instead iterate over edges and check for a common neighbor.  
For each edge \((u, v)\) with \( u < v \), we look for a vertex \( w > v \) such that both \((u, w)\) and \((v, w)\) are edges.  
The first such found will be the lexicographically smallest triangle because we iterate edges in increasing order of \( u \), then \( v \), and then \( w \).

We can store the graph as an adjacency matrix (boolean) for fast lookup.

Here’s the implementation:

```python
n, m = map(int, input().split())
adj = [[False] * (n + 1) for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    adj[u][v] = adj[v][u] = True

# Iterate over all edges in increasing order
for u in range(1, n + 1):
    for v in range(u + 1, n + 1):
        if adj[u][v]:
            for w in range(v + 1, n + 1):
                if adj[u][w] and adj[v][w]:
                    print(u, v, w)
                    exit()
```
