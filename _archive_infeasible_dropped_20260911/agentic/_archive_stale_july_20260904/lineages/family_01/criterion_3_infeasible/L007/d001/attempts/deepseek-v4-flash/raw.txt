We need an efficient way to find a triangle in an undirected graph where all three edges are present.  
The brute-force check over all triples is \( O(n^3) \), which is too slow for \( n = 2000 \).  

Here, since \( m \) can be up to \( 200,000 \), we can use an adjacency list and iterate over edges, combining with neighbor lists.  

Idea:
- Store adjacency sets for O(1) edge lookup.
- Loop over all edges \((u, v)\). For each common neighbor \( w \) of both \( u \) and \( v \), we found a triangle.
- Track the best triangle by lexicographical order.

Complexity is about \( O(m \cdot \text{deg})\) in the worst case, but acceptable given constraints (average deg is low in practice).

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
        edges.append((u, v))
    
    best = None
    # Sort edges for deterministic order if needed, but we'll just compare lexicographically
    for u, v in edges:
        # find common neighbors
        if len(adj[u]) > len(adj[v]):
            u, v = v, u
        for w in adj[u]:
            if w in adj[v]:
                # triangle found
                triple = sorted([u, v, w])
                if best is None or triple < best:
                    best = triple
    # Output 1-based indexing
    print(best[0]+1, best[1]+1, best[2]+1)

if __name__ == "__main__":
    main()
```
