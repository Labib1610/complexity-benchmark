<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform processes a sequence of $j$ client requests. Each request requires processing on machine 1 and then on machine 2. Let $p_{1,k}$ and $p_{2,k}$ be the given processing times for request $k$ ($1 \le k \le j$) on machine 1 and machine 2, respectively.

The standard schedule evaluation framework tracks the completion times using two accumulators, $X_k$ and $Y_k$, representing the progress on machine 1 and machine 2 respectively. Given a configuration of which operations are enabled, the framework computes the final completion time as follows:

- Initially, $X_0 = 0$ and $Y_0 = 0$.
- For each step $k$ from $1$ to $j$:
  1. Determine the active times $u_k$ and $v_k$. If request $k$ is enabled for machine 1, $u_k = p_{1,k}$; otherwise $u_k = 0$. If request $k$ is enabled for machine 2, $v_k = p_{2,k}$; otherwise $v_k = 0$.
  2. Update the first accumulator: $X_k = X_{k-1} + u_k$.
  3. Calculate the synchronization delay: $D_k = X_k - Y_{k-1}$. If $D_k < 0$, set $D_k = 0$.
  4. Update the second accumulator: $Y_k = Y_{k-1} + D_k + v_k$.

The final completion time of the entire configuration is $Y_j$. The client requires $Y_j \le T$ when all requests are enabled for both machines.

For every input provided, this requirement is impossible to meet. The input guarantees that exactly one of the two following limitation categories applies. You must print a short rejection certificate from the applicable category:

- **Isolated Job Obstruction:** There is a request $i$ ($1 \le i \le j$) such that if we evaluate a configuration where *only* request $i$ is enabled for both machines (i.e., for all $k \neq i$, neither machine is enabled), the resulting $Y_j$ strictly exceeds $T$. If this category applies, print `JOB i`. If multiple requests satisfy this, printing any one of them is acceptable.

- **Continuous Utilization Exhaustion:** There is a machine $c \in \{1, 2\}$ such that if we evaluate a configuration where *all* requests are enabled for machine $c$, but *no* requests are enabled for the other machine, the resulting $Y_j$ strictly exceeds $T$. If this category applies, print `LOAD c`. If both machines satisfy this, printing either is acceptable.

Output must be consistent with the unique applicable limitation category guaranteed by the input.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the processing times of a request on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` or `LOAD c`. The output must be consistent with the unique applicable limitation category guaranteed by the input.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, consider the configuration for the isolated job obstruction of request 1.
For $k=1$, $u_1 = 70, v_1 = 60$.
$X_1 = 0 + 70 = 70$.
$D_1 = 70 - 0 = 70$. (Since $70 \ge 0$, $D_1 = 70$)
$Y_1 = 0 + 70 + 60 = 130$.
For $k=2$, $u_2 = 0, v_2 = 0$.
$X_2 = 70 + 0 = 70$.
$D_2 = 70 - 130 = -60$. Since $-60 < 0$, $D_2 = 0$.
$Y_2 = 130 + 0 + 0 = 130$.
For $k=3$, $u_3 = 0, v_3 = 0$.
$X_3 = 70 + 0 = 70$.
$D_3 = 70 - 130 = -60$. Since $-60 < 0$, $D_3 = 0$.
$Y_3 = 130 + 0 + 0 = 130$.
The final completion time $Y_3$ is 130, which strictly exceeds $T=100$. Thus, `JOB 1` is a valid rejection certificate.

In Example 2, consider the configuration for the continuous utilization exhaustion of machine 1.
For all $k$, $u_k = 50$ and $v_k = 0$.
$k=1: X_1 = 50, D_1 = 50 - 0 = 50, Y_1 = 0 + 50 + 0 = 50$.
$k=2: X_2 = 100, D_2 = 100 - 50 = 50, Y_2 = 50 + 50 + 0 = 100$.
$k=3: X_3 = 150, D_3 = 150 - 100 = 50, Y_3 = 100 + 50 + 0 = 150$.
$k=4: X_4 = 200, D_4 = 200 - 150 = 50, Y_4 = 150 + 50 + 0 = 200$.
The final completion time $Y_4$ is 200, which strictly exceeds $T=150$. Thus, `LOAD 1` is a valid rejection certificate.

<RATIONALE>
The explicit flow-shop recurrence with `max` and `sum` was replaced by an equivalent state accumulator with a synchronization delay $D_k$. The direct zero-substitution wording was replaced by enabling/disabling configurations. This forces the model to either algebraically deduce that the recurrence still collapses to $p_{1,i} + p_{2,i}$ and $\sum p_{c,k}$, or attempt to simulate the rules directly, which will fail with a Time Limit Exceeded verdict on the $O(N^2)$ job evaluations.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical identity $Y_{k-1} + \max(0, X_k - Y_{k-1}) = \max(Y_{k-1}, X_k)$ ensures the $Y_k$ accumulator perfectly mirrors the original $B_k$ recurrence, keeping all certificate conditions identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying simplified checks remain $O(N)$ overall (finding a job where $p_{1,i} + p_{2,i} > T$ or checking if $\sum p_{c,k} > T$), maintaining the identical $O(N)$ time complexity bounds as the original problem.
</PRESERVED_CLASS>
