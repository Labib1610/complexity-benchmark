<STATEMENT>
# Deadline Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud cluster receives a batch of $j$ jobs. Each job $k$ requires processing time $p_{1,k}$ on the front-end server and $p_{2,k}$ on the back-end server. The jobs must be processed in the given sequence.

To analyze why a batch fails to meet a target deadline $T$, the system uses a diagnostic function $E(S_1, S_2)$, where $S_1$ and $S_2$ are subsets of the job indices $\{1, 2, \dots, j\}$. $E(S_1, S_2)$ computes a projected completion time using two accumulators, $X$ and $Y$. 

The function initializes $X_0 = 0$ and $Y_0 = 0$. Then, for each job $k$ from $1$ to $j$, it updates the accumulators as follows:
- $X_k = X_{k-1} + \begin{cases} p_{1,k} & \text{if } k \in S_1 \\ 0 & \text{otherwise} \end{cases}$
- $Y_k = \max(X_k, Y_{k-1}) + \begin{cases} p_{2,k} & \text{if } k \in S_2 \\ 0 & \text{otherwise} \end{cases}$

The final projected completion time is $Y_j$.

For every input provided, the full sequence cannot meet the deadline $T$. You must output a certificate proving the impossibility. The input guarantees exactly one of the following certificate categories is valid:

- **Single Job Bottleneck:** There is a job $i$ such that $E(\{i\}, \{i\}) > T$. If this applies, output `JOB i`. (If multiple jobs satisfy this, printing any one of them is acceptable).
- **Server Overload:** There is a server $c \in \{1, 2\}$ such that isolating its workload still exceeds the deadline. Specifically, for server 1, the condition is $E(\{1, 2, \dots, j\}, \emptyset) > T$. For server 2, the condition is $E(\emptyset, \{1, 2, \dots, j\}) > T$. If this applies, output `LOAD c`. (If both servers satisfy this, printing either is acceptable).

Output the single valid certificate category for the given input.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_{1,k}$ and $p_{2,k}$ ($1 \le p_{1,k}, p_{2,k} \le 1000000$), representing the processing times of job $k$ on the front-end and back-end servers, respectively.

## Output

Print a single line containing either `JOB i` or `LOAD c`, consistent with the unique applicable certificate category guaranteed by the input.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, evaluating $E(\{1\}, \{1\})$ means the subsets only contain job $1$.
For $k=1$, the accumulators reach $X_1 = 70$ and $Y_1 = \max(70, 0) + 60 = 130$.
For the remaining jobs $k=2$ and $k=3$, neither $X$ nor $Y$ increase since they are not in the subsets. The final projected time $Y_3 = 130$ exceeds $T=100$. Thus, `JOB 1` is a valid certificate.

In Example 2, evaluating $E(\{1, 2, 3, 4\}, \emptyset)$ means $S_1$ contains all jobs and $S_2$ is empty.
The front-end accumulator adds all $p_1$ times, reaching $X_4 = 200$.
Since $S_2$ is empty, the back-end accumulator adds $0$ for every job, resulting in $Y_k = \max(X_k, Y_{k-1})$. The final projected time $Y_4 = 200$ exceeds $T=150$, making `LOAD 1` a valid certificate.

<RATIONALE>
The explicit phrasing "replaced with 0" allowed models to instantly pattern-match the reductions to `sum(p1)` and `p1[i] + p2[i]` without engaging with the recurrence. By reformulating the problem using a formal diagnostic function evaluated over subsets of job indices, models must now symbolically evaluate the recurrence to discover these $O(1)$ and $O(N)$ simplifications, or else they will attempt a naive $O(N^2)$ simulation and fail via Time Limit Exceeded.
</RATIONALE>
