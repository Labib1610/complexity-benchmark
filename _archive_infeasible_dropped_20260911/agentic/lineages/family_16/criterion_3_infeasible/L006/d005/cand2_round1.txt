<METHOD_NAME>Interval Subset Reformulation</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces explicit inequalities ("strictly exceeds T") with set-theoretic interval subset conditions. This forces models to translate the physical span of processing into mathematical intervals and deduce the correct threshold condition (X > T), rather than relying on surface-level pattern matching of "exceeds T".</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform uses a two-stage pipeline to process client requests. A batch of **j** jobs has been submitted. Every job must be processed on machine 1 and then on machine 2. Each machine processes one job at a time without preemption. A job can only begin on machine 2 after it has completely finished on machine 1.

The client requires all **j** jobs to be completely finished by a strict Service Level Agreement (SLA) deadline of **T** milliseconds. We define the SLA window as the closed interval of time `[0, T]`.

For every input provided, it is impossible to meet this deadline, regardless of how the jobs are scheduled. Your task is to output a short rejection certificate proving the deadline cannot be met. 

A certificate highlights a specific physical limitation that makes the deadline unachievable. For every input, at least one such limitation will be present. You must print one valid certificate that applies:

- **Sequential Bottleneck:** A job cannot begin on machine 2 until it has completely finished on machine 1. Suppose job **i** starts at time 0 and experiences no delays between machines. Its total processing will span a continuous time interval. If this interval is not a subset of the SLA window, print `JOB i` (where **i** is the 1-based index). If multiple jobs qualify, any one is acceptable.

- **Machine Capacity Limit:** Each machine processes one job at a time without preemption. Suppose machine **c** runs continuously from time 0 to clear all its assigned tasks. Its active period will form a continuous time interval. If this interval is not a subset of the SLA window, print `LOAD c` (where **c** is the machine number, 1 or 2). If both machines qualify, either is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` (for a job qualifying under the Sequential Bottleneck) or `LOAD c` (for a machine qualifying under the Machine Capacity Limit).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under the Sequential Bottleneck for job 1, it requires 70 milliseconds on machine 1 and 60 milliseconds on machine 2. Running sequentially from time 0, its processing spans the interval `[0, 130]`. Because `[0, 130]` is not a subset of the SLA window `[0, 100]`, `JOB 1` is a valid rejection certificate.

In Example 2, no single job's interval violates the SLA window. However, under the Machine Capacity Limit for machine 1, the machine must process four jobs taking 50 milliseconds each. Running continuously from time 0, its active period spans the interval `[0, 200]`. Because `[0, 200]` is not a subset of the SLA window `[0, 150]`, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
The explicit mention of "strictly exceeds T" was replaced with a set-theoretic interval subset condition. By framing the processing duration as a continuous time interval `[0, X]` and testing if it is a subset of the SLA window `[0, T]`, models are forced to reason about interval inclusion to deduce the correct `X > T` threshold, defeating simple pattern matching on the inequality.
</RATIONALE>
<PRESERVED_ANSWER>
The interval `[0, X]` is not a subset of `[0, T]` if and only if `X > T`, which is perfectly mathematically equivalent to the original "strictly exceeds T" condition.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires a linear scan to check if any job's sum or any machine's total load exceeds T, keeping it in the same O(N) infeasibility certification class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the interval definitions, but the explicit Note walkthrough of `[0, 130]` not being a subset of `[0, 100]` makes the subset logic completely unambiguous.
</RISK>
