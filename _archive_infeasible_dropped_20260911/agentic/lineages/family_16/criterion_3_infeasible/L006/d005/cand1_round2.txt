<METHOD_NAME>Slack Budget Inversion</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces direct accumulation and `>` comparisons with a strictly negative slack budget subtraction, breaking the AST pattern of `p1 + p2 > T` and introducing a domain-specific 'slack' term.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform uses a two-stage pipeline to process client requests. A batch of **j** jobs has been submitted. Every job must be processed on machine 1 and then on machine 2. Each machine processes one job at a time without preemption. A job can only begin on machine 2 after it has completely finished on machine 1.

The client requires all **j** jobs to be completely finished by a strict Service Level Agreement (SLA) deadline of **T** milliseconds. 

For every input provided, it is impossible to meet this deadline, regardless of how the jobs are scheduled. Your task is to output a short rejection certificate proving the deadline cannot be met. 

Exactly one of the two listed reason categories below is guaranteed to hold for every input. You must print the certificate for the applicable category:

- **Sequential Bottleneck:** A job cannot begin on machine 2 until it has completely finished on machine 1. Define the sequential slack of job **i** as the SLA deadline **T** minus its processing time on machine 1. If this slack is strictly less than its required processing time on machine 2, print `JOB i` (where **i** is the 1-based index). If multiple jobs qualify within this applicable category, any one is acceptable.

- **Machine Capacity Limit:** Each machine processes one job at a time without preemption. Define the capacity slack of machine **c** as the SLA deadline **T** minus the total processing time of all **j** jobs on machine **c**. If this slack is strictly less than zero, print `LOAD c` (where **c** is the machine number, 1 or 2). If both machines qualify within this applicable category, either is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` or `LOAD c` according to the guaranteed applicable reason.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for job 1, the sequential slack is the 100-millisecond SLA minus its machine 1 time (70), which equals 30 milliseconds. This slack is strictly less than its required machine 2 time (60). Therefore, `JOB 1` is the applicable certificate.

In Example 2, no single job satisfies the sequential bottleneck condition. However, for machine 1, the capacity slack is the 150-millisecond SLA minus the total processing time of all four jobs (50 each, totaling 200), which equals -50. Since this slack is strictly less than zero, `LOAD 1` is the applicable certificate.
</STATEMENT>
<RATIONALE>
The explicit `p1 + p2 > T` and `sum > T` conditions have been inverted into a slack budget subtraction (`T - p1 < p2` and `T - sum < 0`). This breaks the direct AST pattern matching observed in the surviving models while addressing the expert critique by restoring the exact exclusivity guarantee and direct sum criterion of the seed.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions `T - p1 < p2` and `T - sum < 0` are mathematically identical to the seed's `p1 + p2 > T` and `sum > T`, ensuring the exact same certificates apply to every input.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires exactly the same O(N) linear scan and sum operations, preserving its original complexity class.
</PRESERVED_CLASS>
