<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform uses a two-stage pipeline to process client requests. A batch of **j** jobs has been submitted. Every job must be processed on machine 1 and then on machine 2. Each machine processes one job at a time without preemption. A job can only begin on machine 2 after it has completely finished on machine 1.

The client requires all **j** jobs to be completely finished by a strict Service Level Agreement (SLA) deadline of **T** milliseconds. 

For every input provided, it is impossible to meet this deadline, regardless of how the jobs are scheduled. Your task is to output a short rejection certificate proving the deadline cannot be met. 

A certificate highlights a specific physical limitation that makes the deadline unachievable. For every input, at least one such limitation will be present. You must print one valid certificate that applies:

- **Sequential Bottleneck:** A job cannot begin on machine 2 until it has completely finished on machine 1. Consequently, the SLA deadline **T** must be split into two non-negative integers **t1** and **t2** (such that **t1** + **t2** = **T**) where the job's machine 1 processing time is at most **t1** and its machine 2 processing time is at most **t2**. If there is NO such valid split for job **i**, print `JOB i` (where **i** is the 1-based index). If multiple jobs qualify, any one is acceptable.

- **Machine Capacity Limit:** Each machine processes one job at a time without preemption. Consequently, the SLA deadline **T** must be sufficient to accommodate any subset of jobs running sequentially on that machine. If there exists ANY subset of jobs whose combined processing time on machine **c** strictly exceeds **T**, print `LOAD c` (where **c** is the machine number, 1 or 2). If both machines qualify, either is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` (for a job qualifying under the Sequential Bottleneck) or `LOAD c` (for a machine qualifying under the Machine Capacity Limit).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for job 1, there is no way to partition the 100-millisecond SLA into two non-negative integers **t1** and **t2** (**t1** + **t2** = 100) such that **t1** accommodates the 70-millisecond machine 1 time and **t2** accommodates the 60-millisecond machine 2 time. For instance, if **t1** = 70, **t2** is only 30 (which is < 60). If **t1** = 40, **t2** is 60, but **t1** is < 70. Exhausting all partitions from (0, 100) to (100, 0) reveals no valid split. Therefore, `JOB 1` is a valid rejection certificate.

In Example 2, no single job violates the sequential division rule. However, for machine 1, if we evaluate subsets of jobs, we find that the subset containing jobs 1, 2, 3, and 4 has a combined processing time of 200 on machine 1. Since 200 strictly exceeds the 150-millisecond SLA, a violating subset exists. Therefore, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
I replaced the explicit $O(1)$ and $O(N)$ inequality checks with logically equivalent conditions framed as existential and universal quantifiers over sets (subsets and integer partitions). This forces the model to mathematically deduce that "no valid split exists" implies $p1+p2 > T$ and "any subset exceeds T" implies $\sum p > T$. Models relying on literal text-to-code translation will write loops or subset-generators that result in Time Limit Exceeded.
</RATIONALE>
<PRESERVED_ANSWER>
The condition for `JOB i` is mathematically identical because $p1+p2 \le T$ if and only if there exist non-negative integers $t1, t2$ summing to $T$ with $p1 \le t1$ and $p2 \le t2$; similarly, the maximum subset sum of positive integers is exactly the sum of all elements, preserving the `LOAD c` condition.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying verification algorithm remains a linear scan computing sums and pairwise additions, keeping the problem firmly in the same complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the subset condition as requiring a search for a specific strict subset rather than realizing the full set is the maximal subset, but the phrase "ANY subset" unambiguously includes the full set.
</RISK>
