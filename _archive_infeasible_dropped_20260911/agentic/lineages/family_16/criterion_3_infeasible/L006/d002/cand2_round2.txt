# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform provides a two-stage pipeline for processing client requests. A batch of **j** jobs has been submitted, which must pass through exactly **two** machines. To maintain data integrity, every job must be processed on machine 1 first and then on machine 2. Each machine can only process one job at a time, and a job can only arrive at machine 2 after it has completely finished on machine 1.

The client has requested a strict Service Level Agreement (SLA) deadline of **T** milliseconds: all **j** jobs must be completely finished by time **T**.

For every input in this problem, the requested SLA is guaranteed to be impossible to meet, regardless of how the jobs are scheduled. Your task is to generate a short rejection certificate that proves the deadline is impossible, which is verifiable directly against the input.

The inputs are rigorously constructed such that exactly one of the following two categories of bottleneck is responsible for the SLA failure, guaranteeing at least one valid certificate always exists. You must output the corresponding certificate for the unique bottleneck category that applies:

- **Machine Capacity Bottleneck:** The cumulative active time required by a single machine to process its entire queue of tasks strictly surpasses the SLA.
  Print: `LOAD c` — where **c** is 1 or 2, representing the specific machine whose total workload exceeds the deadline.

- **Individual Job Bottleneck:** A single job **i** requires at least its processing time on machine 1 plus its processing time on machine 2 across the two stages, and this sequential total strictly surpasses the SLA.
  Print: `JOB i` — where **i** (1-based index) is such a job.

If multiple witnesses exist within the valid category, any one of them is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `LOAD c` (if machine **c**'s cumulative active time exceeds **T**) or `JOB i` (if job **i** requires at least **p1** + **p2** time across machine 1 then machine 2, and this sum exceeds **T**). If multiple valid indices within the applicable category exist, any one is acceptable.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the first job requires 70 milliseconds on machine 1 and 60 milliseconds on machine 2. Its total sequential duration is 130 milliseconds, which is strictly greater than the 100-millisecond SLA. Therefore, `JOB 1` is a correct rejection certificate.

In Example 2, no single job exceeds the 150-millisecond SLA. However, machine 1 has a cumulative active time of 50 + 50 + 50 + 50 = 200 milliseconds, which exceeds the 150-millisecond SLA. Therefore, `LOAD 1` is a correct rejection certificate.
