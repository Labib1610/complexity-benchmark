**Solution Explanation**

For a request `k`

* on machine 1 it needs `p1[k]`
* on machine 2 it needs `p2[k]`

The real schedule is

```
A0 = B0 = 0
Ak = A(k‑1) + p1[k]
Bk = max(Ak , B(k‑1)) + p2[k]
```

`Bj` is the finishing time of the whole batch.

The statement guarantees that the deadline `T` cannot be met and that **exactly one**
of the two following reasons is true.

--------------------------------------------------------------------

#### 1.  Isolated Job Obstruction  

All jobs except one `i` are set to zero processing time.
Only job `i` keeps its original times.

* `Ak` before `i` is `0`, after `i` it stays `p1[i]`.
* `Bi = max(p1[i],0) + p2[i] = p1[i] + p2[i]`.
* Afterwards `Bk = max(p1[i], B(k‑1)) = B(k‑1)` because `B(k‑1) ≥ p1[i]+p2[i]`.

So the final finishing time is simply  

```
Bj = p1[i] + p2[i]
```

Therefore **JOB i** is a valid certificate **iff** `p1[i] + p2[i] > T`.

--------------------------------------------------------------------

#### 2.  Continuous Utilization Exhaustion  

All processing times on the *other* machine are set to zero.

*If the other machine is 2* (`c = 1`): `p2[k] = 0`

```
Ak = sum_{t≤k} p1[t]          (non‑decreasing)
Bk = max(Ak , B(k‑1))         (no extra time)
```

Thus `Bk` is always the larger of the two, i.e. the current `Ak`.  
Finally `Bj = sum_{k=1..j} p1[k]`.

*If the other machine is 1* (`c = 2`): `p1[k] = 0`

```
Ak = 0
Bk = max(0 , B(k‑1)) + p2[k] = B(k‑1) + p2[k]
```

Hence `Bj = sum_{k=1..j} p2[k]`.

So **LOAD 1** is a certificate **iff** `Σ p1 > T`,
and **LOAD 2** is a certificate **iff** `Σ p2 > T`.

--------------------------------------------------------------------

Because the input guarantees that exactly one of the two categories applies,
the decision is straightforward:

```
if there exists i with p1[i] + p2[i] > T:
        output "JOB i"   (any such i)
else if sum(p1) > T:
        output "LOAD 1"
else:
        output "LOAD 2"
```

All operations are linear in the number of requests (`j ≤ 2·10⁵`).

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm always prints a correct certificate.

---

**Lemma 1**  
For any request `i`, when all other requests have processing time `0`,
the final completion time equals `p1[i] + p2[i]`.

*Proof.* As shown in the analysis of category 1, after job `i` the
completion time on machine 1 stays `p1[i]`, and on machine 2 becomes
`p1[i] + p2[i]`. Later steps cannot increase it because the max
always selects this larger value. ∎



**Lemma 2**  
If all `p2` are set to `0`, the final completion time equals `Σ p1`.

*Proof.* With `p2 = 0` we have `Bk = max(Ak , B(k‑1))`.  
Since `Ak` is the cumulative sum of `p1` and is non‑decreasing,
`Bk` follows the same non‑decreasing sequence, ending at `Σ p1`. ∎



**Lemma 3**  
If all `p1` are set to `0`, the final completion time equals `Σ p2`.

*Proof.* With `p1 = 0` we get `Ak = 0` and `Bk = B(k‑1) + p2[k]`,
so `Bk` is exactly the prefix sum of `p2`, ending at `Σ p2`. ∎



**Theorem**  
The algorithm outputs a line that satisfies the definition of the
unique applicable limitation category.

*Proof.*  
The algorithm first checks for an index `i` with `p1[i] + p2[i] > T`.
By Lemma&nbsp;1 this means that the hypothetical schedule where only job `i`
keeps its times finishes after `T`; therefore the *Isolated Job
Obstruction* category holds and printing `JOB i` is correct.

If no such job exists, then for every `i` we have `p1[i] + p2[i] ≤ T`.
Consequently the *JOB* category cannot be the applicable one
(the input guarantees exactly one category).  
The algorithm then checks `Σ p1 > T`. By Lemma&nbsp;2 this is precisely the
condition for *Continuous Utilization Exhaustion* on machine 1,
so printing `LOAD 1` is correct.  
Otherwise `Σ p1 ≤ T`. Since the overall deadline is impossible,
the remaining possibility is `Σ p2 > T`. Lemma&nbsp;3 shows this is the
condition for *Continuous Utilization Exhaustion* on machine 2,
hence printing `LOAD 2` is correct.

Thus in all cases the algorithm outputs a valid certificate belonging to
the unique applicable category. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Reading input* – `O(j)`  
*Scanning for a violating job* – `O(j)`  
*Computing the two sums* – `O(j)`  

Total time `O(j)` ≤ `2·10⁵` operations, well within limits.  
Memory usage is `O(1)` besides the input stream.

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    j = int(next(it))
    T = int(next(it))

    sum1 = 0
    sum2 = 0
    job_idx = -1

    for idx in range(1, j + 1):
        p1 = int(next(it))
        p2 = int(next(it))
        if job_idx == -1 and p1 + p2 > T:
            job_idx = idx          # first job that violates alone
        sum1 += p1
        sum2 += p2

    if job_idx != -1:
        sys.stdout.write(f"JOB {job_idx}")
    elif sum1 > T:
        sys.stdout.write("LOAD 1")
    else:
        sys.stdout.write("LOAD 2")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above.
