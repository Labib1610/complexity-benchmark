<METHOD_NAME>Recurrence Relation Embedding</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the intuitive definitions of the certificates with an equivalent recurrence relation over hypothetical modified inputs, forcing the model to algebraically simplify the recurrence to avoid an O(N^2) simulation that would TLE.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform processes a sequence of $j$ client requests. Every request must be processed on machine 1 and then on machine 2. The completion times of the requests are defined by the following recurrences:

Let $A_k$ be the completion time of request $k$ on machine 1, and $B_k$ be its completion time on machine 2.
- $A_0 = 0$ and $B_0 = 0$
- $A_k = A_{k-1} + p_{1, k}$ for $k = 1, 2, \dots, j$
- $B_k = \max(A_k, B_{k-1}) + p_{2, k}$ for $k = 1, 2, \dots, j$

The final completion time of the entire batch is $B_j$. The client requires $B_j \le T$.

For every input provided, it is impossible to meet this deadline. The input guarantees that exactly one of the two following limitation categories applies. You must print a short rejection certificate from the applicable category:

- **Isolated Job Obstruction:** There is a request $i$ ($1 \le i \le j$) such that if we were to construct a hypothetical sequence where the processing times of all requests *except* $i$ are replaced with $0$ (i.e., $p_{1, k} = 0$ and $p_{2, k} = 0$ for all $k \neq i$), the final completion time $B_j$ of this hypothetical sequence would strictly exceed $T$. If this category applies, print `JOB i`. If multiple requests satisfy this, printing any one of them is acceptable.

- **Continuous Utilization Exhaustion:** There is a machine $c \in \{1, 2\}$ such that if we were to construct a hypothetical sequence where the processing times on the *other* machine are replaced with $0$ (i.e., if $c=1$, then $p_{2, k} = 0$ for all $k$; if $c=2$, then $p_{1, k} = 0$ for all $k$), the final completion time $B_j$ of this hypothetical sequence would strictly exceed $T$. If this category applies, print `LOAD c`. If both machines satisfy this, printing either is acceptable.

Output must be consistent with the unique applicable limitation category guaranteed by the input.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the processing times of a request on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` or `LOAD c`. The output must be consistent with the unique applicable limitation category guaranteed by the input.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, consider the hypothetical sequence for request 1 where requests 2 and 3 take 0 time:
$p_1 = [70, 0, 0]$ and $p_2 = [60, 0, 0]$.
$A_1 = 70$, $B_1 = \max(70, 0) + 60 = 130$.
$A_2 = 70 + 0 = 70$, $B_2 = \max(70, 130) + 0 = 130$.
$A_3 = 70 + 0 = 70$, $B_3 = \max(70, 130) + 0 = 130$.
The final completion time $B_3$ is 130, which exceeds $T=100$. Thus, `JOB 1` is a valid rejection certificate.

In Example 2, consider the hypothetical sequence for machine 1 where all machine 2 times are 0:
$p_1 = [50, 50, 50, 50]$ and $p_2 = [0, 0, 0, 0]$.
$A_1 = 50$, $B_1 = \max(50, 0) + 0 = 50$.
$A_2 = 100$, $B_2 = \max(100, 50) + 0 = 100$.
$A_3 = 150$, $B_3 = \max(150, 100) + 0 = 150$.
$A_4 = 200$, $B_4 = \max(200, 150) + 0 = 200$.
The final completion time $B_4$ is 200, which exceeds $T=150$. Thus, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
Removed the intuitive descriptions ("zero wait time", "never experienced any idle time") that models were pattern-matching directly to simple arithmetic checks (`p1 + p2 > T` and `sum > T`). Replaced them with the formal completion time recurrence evaluated on hypothetical modified inputs. Models must now algebraically simplify the recurrence mathematically to deduce the $O(N)$ checks; if they merely write code to simulate the described procedure directly, the $O(N^2)$ evaluation will exceed the time limit.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical simplification of the recurrence for the modified inputs exactly reduces to $B_j = p_{1,i} + p_{2,i}$ for the JOB certificate and $B_j = \sum p_{c,k}$ for the LOAD certificate, meaning the identical certificates are required.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains unchanged (INFEASIBLE/linear time checking) because evaluating the simplified conditions still takes exactly $O(N)$ time.
</PRESERVED_CLASS>
