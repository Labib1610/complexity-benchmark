<METHOD_NAME>Measure-Theoretic Reformulation</METHOD_NAME>
<METHOD_DESCRIPTION>Transforms operational scheduling constraints (completion times, continuous utilization) into abstract measure-theoretic properties (Lebesgue measure, disjoint sets, supremum bounds). This prevents models from matching the scenario to standard job-shop arithmetic shortcuts, forcing them to mathematically deduce that the supremum bounds correspond to the sum of sequence measures and the sum of disjoint measures.</METHOD_DESCRIPTION>

<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform schedules a batch of $j$ requests. A valid schedule maps each request $k$ ($1 \le k \le j$) to two measurable sets of time points, $S_{k,1} \subset \mathbb{R}_{\ge 0}$ for machine 1 and $S_{k,2} \subset \mathbb{R}_{\ge 0}$ for machine 2.

A valid schedule must satisfy the following conditions:
1. **Duration:** The Lebesgue measure of $S_{k,1}$ is exactly $p_{k,1}$ and the measure of $S_{k,2}$ is exactly $p_{k,2}$, for all $k$.
2. **Precedence:** For every request $k$, all time points in $S_{k,1}$ strictly precede all time points in $S_{k,2}$. That is, for any $x \in S_{k,1}$ and any $y \in S_{k,2}$, it must be that $x < y$.
3. **Exclusivity:** A machine can only process one request at a time. For any two distinct requests $k$ and $m$, their sets must be disjoint: $S_{k,1} \cap S_{m,1} = \emptyset$ and $S_{k,2} \cap S_{m,2} = \emptyset$.
4. **Deadline:** All processing for all requests must be completed by a strict deadline $T$. Thus, the supremum of all sets across both machines must be at most $T$.

The client has provided inputs for which it is impossible to meet the deadline. The input guarantees that exactly one of the following two structural rejection certificates applies. You must print a short certificate from the applicable category:

- **Pointwise Supremum Certificate:** There is a request $i$ such that any sets $S_{i,1}$ and $S_{i,2}$ satisfying the Duration and Precedence conditions for this individual request will inevitably have $\sup(S_{i,1} \cup S_{i,2}) > T$. If this category applies, print `JOB i` (where $i$ is the 1-based index of the request). If multiple requests satisfy this, printing any one of them is acceptable.

- **Measure Bound Certificate:** There is a machine $c \in \{1, 2\}$ such that any disjoint sets $S_{1,c}, S_{2,c}, \dots, S_{j,c}$ satisfying the Duration and Exclusivity conditions for this machine will inevitably have $\sup(\bigcup_{k=1}^j S_{k,c}) > T$. If this category applies, print `LOAD c` (where $c$ is the machine number). If both machines satisfy this, printing either is acceptable.

Output must be consistent with the unique applicable limitation category guaranteed by the input.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the required measures for a request on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` or `LOAD c`. The output must be consistent with the unique applicable limitation category guaranteed by the input.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, request 1 requires sets $S_{1,1}$ and $S_{1,2}$ with measures 70 and 60. By the Precedence condition, all elements of $S_{1,2}$ must be strictly greater than all elements of $S_{1,1}$. Since $S_{1,1} \subset \mathbb{R}_{\ge 0}$, any such assignment will force $\sup(S_{1,2}) \ge 130$. This inevitably exceeds the deadline $T=100$. The Pointwise Supremum Certificate applies, making `JOB 1` a valid output.

In Example 2, machine 1 must be assigned four disjoint sets $S_{1,1}, S_{2,1}, S_{3,1}, S_{4,1}$, each with measure 50. By the Exclusivity condition, their union must have a measure of 200. Any subset of $\mathbb{R}_{\ge 0}$ with measure 200 must have a supremum of at least 200, which inevitably exceeds the deadline $T=150$. The Measure Bound Certificate applies, making `LOAD 1` a valid output.
</STATEMENT>
<RATIONALE>
The problem was reformulated using measure theory to obscure the simple arithmetic checks (`p1 + p2 > T` and `sum(p) > T`). By defining the schedule as mappings to measurable sets and bounding their supremums, models can no longer pattern-match to standard "zero wait time" or "continuous utilization" phrases. They must instead mathematically deduce that the supremum of sequentially dependent sets equals the sum of their measures, and the supremum of disjoint sets equals the sum of their measures.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical lower bound for the supremum of two sequentially dependent sets in $\mathbb{R}_{\ge 0}$ is exactly $p_1 + p_2$, and for disjoint sets is exactly $\sum p$, meaning the certificates still trigger under the exact same arithmetic conditions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an $O(N)$ impossibility certification, simply checking if any job's sequential measure sum or any machine's total measure exceeds $T$.
</PRESERVED_CLASS>
<RISK>
Models might struggle with the continuous set terminology and assume the problem requires complex integral calculus or interval packing algorithms, but the note explicitly demonstrates how the measure bounds reduce to simple arithmetic addition.
</RISK>
