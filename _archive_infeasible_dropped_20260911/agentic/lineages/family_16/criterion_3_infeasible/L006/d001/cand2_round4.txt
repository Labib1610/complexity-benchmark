# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A data processing center runs a two-phase pipeline. A batch of $j$ tasks has been scheduled to run through Phase 1 and then Phase 2. The pipeline operates under the following constraints:
- Phase 1 and Phase 2 run on separate, dedicated processors.
- A processor can only handle one task at a given moment.
- A task can only begin Phase 2 after it has fully completed Phase 1.

A client has submitted these $j$ tasks with a strict Service Level Agreement (SLA) deadline of $T$ time units. They require that the entire batch of tasks finishes processing by time $T$.

However, the requested deadline $T$ is mathematically impossible to satisfy, no matter how the tasks are scheduled. Your objective is to evaluate the tasks and output a rejection certificate that proves the deadline cannot be met.

It is guaranteed that for every test case, **exactly one** of the following two proof categories will be valid:

- **Cumulative Capacity Breach:** A single processor is asked to do more total work than the deadline allows. Since a processor handles tasks serially, the sum of the durations of all tasks on that processor cannot exceed $T$. If this proves the failure, output `LOAD c`, where `c` is the phase number (1 or 2) that exceeds the limit.
- **Sequential Bottleneck:** A single task requires too much time to complete its phases. Since a task must complete Phase 1 and then Phase 2 in order, the sum of its durations across both phases cannot exceed $T$. If this proves the failure, output `JOB i`, where `i` is the 1-based index of the task.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
The following $j$ lines each contain two integers, $x_k$ and $y_k$ ($1 \le x_k, y_k \le 1000000$), representing the duration of task $k$ in Phase 1 and Phase 2, respectively.

## Output

Print a single line containing the applicable rejection certificate: `LOAD c` (for a phase with total load $> T$) or `JOB i` (for a task with total duration $> T$).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, task 1 needs 70 + 60 = 130 time units sequentially. Since 130 > 100, `JOB 1` proves the SLA is impossible. 
In Example 2, no single task exceeds 150 time units sequentially. However, Phase 1 must process 50 + 50 + 50 + 50 = 200 units of work in total. Since 200 > 150, `LOAD 1` is the rejection certificate.
