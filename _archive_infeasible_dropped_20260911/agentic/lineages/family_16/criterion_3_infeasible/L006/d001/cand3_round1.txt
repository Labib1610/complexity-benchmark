<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud processing facility operates a two-stage pipeline for client data. A batch of **j** jobs has been submitted. Each job must be processed on machine 1, and only after it has completely finished on machine 1 can it be processed on machine 2. Each machine processes one job at a time.

The client requires all **j** jobs to be fully completed within a strict Service Level Agreement (SLA) deadline of **T** milliseconds.

For every batch submitted to this endpoint, the SLA is impossible to meet. Your task is to output a rejection certificate proving the deadline cannot be met. The certificate must be easily verifiable against the input.

To maintain standardized compliance logs, it is possible for multiple rejection reasons to apply to the same batch. When this happens, you must evaluate the rejection reasons in a strict priority order. Print the first one that applies:

1. **Machine 1 is overloaded:** Because a machine processes jobs one at a time, it requires a time span at least equal to the sum of all its processing times. If the total processing time required on machine 1 exceeds **T**, print `LOAD 1`.
2. **Machine 2 is overloaded:** If the total processing time required on machine 2 exceeds **T**, print `LOAD 2`.
3. **A single job is too long:** If a specific job's processing times on both machines add up to more than **T**, that job alone (running on machine 1 then machine 2, in sequence) cannot finish by **T**. Print `JOB i` — where **i** (1-based index) is the first such job in the input.

## Input

The first line contains two integers **j** and **T**.
- **j** is the number of jobs. It is at least 1. The maximum batch size corresponds to the system's maximum connection limit, which is exactly the number of seconds equivalent to a continuous duration of 55 hours, 33 minutes, and 20 seconds.
- **T** is the SLA deadline in milliseconds. It is at least 1. The maximum possible deadline is limited by the billing cycle length, which is exactly the number of milliseconds equivalent to a continuous duration of 11 days, 13 hours, 46 minutes, and 40 seconds.

Each of the next **j** lines contains two integers **p1** and **p2**: the processing times in milliseconds of a job on machine 1 and machine 2, respectively.
- The processing times are at least 1. A hardware timeout ensures no individual processing step can exceed the number of milliseconds equivalent to a continuous duration of 16 minutes and 40 seconds.

## Output

Print a single line containing the rejection certificate according to the priority rules above: either `LOAD 1`, `LOAD 2`, or `JOB i`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the total load on machine 1 is 75 and on machine 2 is 66, neither of which exceeds 100. However, job 1 needs 70 + 60 = 130 > 100 milliseconds in sequence. Since no higher-priority load condition is met, `JOB 1` proves the SLA is impossible.

In Example 2, no single job exceeds 150, but machine 1 must process 50+50+50+50 = 200 > 150 milliseconds of work in total. Thus, `LOAD 1` is the rejection certificate.
</STATEMENT>
<RATIONALE>
Replaced the "exactly one reason applies" guarantee with a strict priority order that forces models to check the machine loads before falling back to a single-job certificate. This removes the affordance of immediately exiting upon finding a long job, forcing the model to compute all conditions to satisfy the priority rule. Additionally, applied strategy S07 to express the numeric bounds indirectly as equivalent time durations.
</RATIONALE>
<PRESERVED_ANSWER>
Since the original test cases were generated under the constraint that exactly one rejection reason applies, the new priority rules will never alter the output for any valid test case, as only one condition will evaluate to true.
</PRESERVED_ANSWER>
