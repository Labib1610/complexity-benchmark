# SLA Rejection Notice

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform provides a two-stage pipeline for processing client requests. A batch of **j** jobs has been submitted, which must pass through exactly two machines. To maintain data integrity, every job must be processed on machine 1 first and then on machine 2. Each machine can only process one job at a time, and a job can only arrive at machine 2 after it has completely finished on machine 1.

The client has requested a strict Service Level Agreement (SLA) deadline of **T** milliseconds: all **j** jobs must be completely finished by time **T**.

For every input in this problem, the requested SLA is guaranteed to be impossible to meet. Your task is to generate a short rejection notice that explains why the deadline is impossible.

Multiple rejection conditions might be true for a given batch. You must evaluate them and print exactly one rejection notice, strictly following this priority order:

1. **Machine 1 is overloaded.** Because machine 1 processes jobs one at a time, it requires a time span at least equal to the sum of all its processing times. If the total processing time required on machine 1 strictly exceeds **T**, print: `LOAD 1`
2. **Machine 2 is overloaded.** Similarly, if the total processing time required on machine 2 strictly exceeds **T**, print: `LOAD 2`
3. **A single job is too long.** If a specific job's processing times on both machines add up to strictly more than **T**, that job alone (running on machine 1 then machine 2, in sequence) cannot finish by **T**. Print: `JOB i` — where **i** (1-based index) is the first such job in the input.

You must only output a `JOB` notice if neither machine's total load exceeds **T**.

## Input

The first line contains two integers **j** and **T**.
The number of jobs **j** is at least 1, and its upper limit is the platform's maximum batch capacity (the number of bytes in 200 kilobytes, where 1 kilobyte is 1000 bytes).
The deadline **T** is at least 1, and caps at the system's maximum configurable deadline (the number of nanoseconds in one second).

Each of the next **j** lines contains two integers **p1** and **p2**: the processing times of a job on machine 1 and machine 2, respectively.
Each processing time is at least 1, and is bounded by a maximum duration equal to the number of milligrams in one kilogram.

## Output

Print a single line containing the appropriate rejection notice (`LOAD 1`, `LOAD 2`, or `JOB i`), determined by the priority rules above.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the total load on machine 1 is 75, and on machine 2 is 66, neither of which exceeds 100. However, job 1 needs 70 + 60 = 130 > 100 milliseconds in sequence. Since no machine is overloaded, the correct notice is `JOB 1`.
In Example 2, no single job exceeds 150, but machine 1 must process 50+50+50+50 = 200 milliseconds of work in total. Since 200 > 150, machine 1 is overloaded. Based on the priority rules, the notice `LOAD 1` must be printed.
</STATEMENT>
<RATIONALE>
The problem was modified to remove the guarantee that exactly one rejection condition applies, explicitly introducing an overlapping-case rule. It now enforces a strict evaluation priority (LOAD 1, then LOAD 2, then JOB) preventing models from returning early upon finding a single valid JOB condition without first evaluating both machine loads. Additionally, numeric constraints have been replaced with equivalent indirect physical/unit derivations (e.g., nanoseconds in a second) to circumvent rote bound parsing.
</RATIONALE>
<PRESERVED_ANSWER>
Because the original problem guaranteed that exactly one rejection condition would apply per valid test case, the new priority rules will always select the identical correct answer since there are no true overlaps in the underlying dataset.
</PRESERVED_ANSWER>
