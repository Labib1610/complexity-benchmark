<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s
Memory limit: 256 MB

## Description

A cloud computing platform provides a two-stage pipeline for processing client requests. A batch of **j** jobs has been submitted, which must pass through exactly **two** machines. To maintain data integrity, every job must be processed on machine 1 first and then on machine 2. Each machine can only process one job at a time, and a job can only arrive at machine 2 after it has completely finished on machine 1.

The client has requested a strict Service Level Agreement (SLA) deadline of **T** milliseconds: all **j** jobs must be completely finished by time **T**.

For every input in this problem, the requested SLA is guaranteed to be impossible to meet, regardless of how the jobs are scheduled. Your task is to generate a short rejection certificate that proves the deadline is impossible, which is verifiable directly against the input.

Exactly one of the following reasons always applies. Print the one that holds:

- **Sequential Bottleneck:** A job must traverse the pipeline serially. If a specific job's end-to-end processing requirement (the time it spends actively running on both machines) exceeds **T**, it cannot finish in time even if it never waits in a queue.
  Print: `JOB i` — where **i** (1-based index) is such a job.

- **Throughput Bottleneck:** A machine processes jobs strictly one at a time. If the cumulative active time required by all jobs on a single machine exceeds **T**, that machine cannot clear its queue before the deadline, even with zero idle time.
  Print: `LOAD c` — where **c** is 1 or 2, representing the machine whose cumulative requirement exceeds **T**.

## Input

The first line provides the batch size and the SLA deadline, given as two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000). The batch size is limited by the system's queue capacity of 200000, and the deadline timer cannot exceed 1000000000 milliseconds.
The subsequent **j** lines detail the jobs. Each line contains two integers (1 ≤ A, B ≤ 1000000): the time required on machine 1 (**A**), followed by the time required on machine 2 (**B**). The hardware enforces a maximum of 1000000 milliseconds per operation.

## Output

Print a single line: `JOB i` (where **i** is the 1-based index of the job causing a sequential bottleneck) or `LOAD c` (where **c** is the machine number causing a throughput bottleneck).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the first job requires 70 + 60 = 130 milliseconds end-to-end. Since this exceeds the 100 millisecond deadline, `JOB 1` proves the SLA is impossible. 
In Example 2, no single job exceeds 150 milliseconds sequentially. However, the first machine must process 50+50+50+50 = 200 milliseconds of work cumulatively. Since this exceeds the 150 millisecond deadline, `LOAD 1` is the rejection certificate.

<RATIONALE>
Removed the explicit formulas `p1 + p2 > T` and replaced them with conceptual descriptions ("end-to-end processing requirement" and "cumulative active time"). Variable names in the input were generalized to A and B to prevent simple pattern matching. S07 strategy was applied by describing the numeric bounds as physical system limits in the text, while strictly maintaining the required mathematical bounds in parentheses to satisfy the parser and expert constraints. The exclusivity guarantee is preserved as mandated by the expert to prevent semantic drift.
</RATIONALE>
<PRESERVED_ANSWER>
The logic for selecting a certificate remains identical: a sequential bottleneck corresponds to a single job's total time exceeding T, and a throughput bottleneck corresponds to a machine's total load exceeding T.
</PRESERVED_ANSWER>

</PRESERVED_CLASS>
