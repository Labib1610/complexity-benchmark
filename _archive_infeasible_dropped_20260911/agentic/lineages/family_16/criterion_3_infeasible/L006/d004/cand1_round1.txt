<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

We are analyzing an allocation system for $j$ entities. Each entity $k \in \{1, \dots, j\}$ has two fixed scalar parameters, $X_k$ and $Y_k$.

A valid allocation consists of two mappings, $f: \{1, \dots, j\} \to \mathbb{R}_{\ge 0}$ and $g: \{1, \dots, j\} \to \mathbb{R}_{\ge 0}$, that satisfy three axioms:
- **A1 (Precedence):** For all $k$, $g(k) \ge f(k) + X_k$.
- **A2 (Exclusivity X):** For any distinct $k, m$, the open-right intervals $[f(k), f(k) + X_k)$ and $[f(m), f(m) + X_m)$ are disjoint.
- **A3 (Exclusivity Y):** For any distinct $k, m$, the open-right intervals $[g(k), g(k) + Y_k)$ and $[g(m), g(m) + Y_m)$ are disjoint.

The *span* of an allocation is defined as $\max_{k} (g(k) + Y_k)$. 

You are given a strict upper bound $T$. It is mathematically guaranteed that no valid allocation exists with a span less than or equal to $T$. Your objective is to output a formal certificate proving this impossibility. A valid certificate must be one of the following two types:

- **JOB Certificate:** Consider a subsystem restricted to a single entity $i$. The mappings $f$ and $g$ are only defined for $i$, meaning A2 and A3 are vacuously satisfied, while A1 must still hold. If the minimum possible span of all valid allocations for this single-entity subsystem is strictly greater than $T$, then the string `JOB i` (where $i$ is the 1-based input index) is a valid certificate. If multiple entities qualify, any one is acceptable.

- **LOAD Certificate:** Consider a relaxed system containing all $j$ entities, but with modified axioms.
  - **LOAD 1:** We force $Y_k = 0$ for all $k$, and remove axiom A3 entirely. Axioms A1 and A2 remain fully enforced. If the minimum possible span of all valid allocations in this relaxed system is strictly greater than $T$, then `LOAD 1` is a valid certificate.
  - **LOAD 2:** We force $X_k = 0$ for all $k$, and remove axiom A2 entirely. Axioms A1 and A3 remain fully enforced. If the minimum possible span of all valid allocations in this relaxed system is strictly greater than $T$, then `LOAD 2` is a valid certificate.

If both `LOAD 1` and `LOAD 2` qualify, either is acceptable. For every input, at least one valid `JOB` or `LOAD` certificate is guaranteed to exist.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $X_k$ and $Y_k$ ($1 \le X_k, Y_k \le 1000000$).

## Output

Print a single line containing either a valid `JOB i` certificate or a valid `LOAD c` certificate.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for the `JOB 1` subsystem, any valid allocation must satisfy $g(1) \ge f(1) + 70$. Since $f(1) \ge 0$, $g(1) \ge 70$. The span is $g(1) + Y_1 \ge 70 + 60 = 130$. Since $130 > 100$, `JOB 1` is a valid certificate.

In Example 2, no single entity has a minimum span exceeding 150. However, consider the `LOAD 1` relaxation. The four entities each have $X_k = 50$. Due to axiom A2, their $f$-intervals must be disjoint, meaning they cannot overlap in $\mathbb{R}_{\ge 0}$. Consequently, the maximum value of $f(k) + X_k$ across all four entities must be at least 200. By axiom A1, this forces the span $\max_k (g(k) + 0)$ to be at least 200. Since $200 > 150$, `LOAD 1` is a valid certificate.
