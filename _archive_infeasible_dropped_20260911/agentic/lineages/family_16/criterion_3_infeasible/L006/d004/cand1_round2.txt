<METHOD_NAME>Formal Axiomatic Mapping</METHOD_NAME>
<METHOD_DESCRIPTION>Abstracts the physical scheduling problem into a mathematical problem of mapping elements to intervals on the real line subject to topological/measure-theoretic axioms. <STATEMENT>
# Axiomatic Mapping Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

We are given a discrete set of **j** elements and a target scalar **T**. Each element **i** is characterized by two scalar parameters, **p1** and **p2**.

We wish to define two mapping functions, $A$ and $B$, which assign each element **i** to a closed interval $A(i)$ and a closed interval $B(i)$ on the real line. A mapping is considered valid if it satisfies all of the following axioms:
1. **Span:** For every element **i**, the length of $A(i)$ is exactly **p1**, and the length of $B(i)$ is exactly **p2**.
2. **Containment:** For every element **i**, both $A(i)$ and $B(i)$ are subsets of the interval $[0, T]$.
3. **Ordering:** For every element **i**, the maximum value in $A(i)$ is less than or equal to the minimum value in $B(i)$.
4. **Exclusivity:** For any two distinct elements **i** and **k**, the intersection of $A(i)$ and $A(k)$ has a length of 0. Similarly, the intersection of $B(i)$ and $B(k)$ has a length of 0.

For every provided input, no valid mapping exists. Your task is to output a short rejection certificate proving this impossibility. A certificate is formed by defining a relaxed set of axioms that is strictly easier to satisfy, yet still admits no valid mapping. You must output a certificate for any impossible relaxed scenario:

- **Singleton Domain Certificate:** The set of elements is reduced to contain only a single element **i**. The mapping must satisfy all four axioms for this single element. If no valid mapping exists under these conditions, print `JOB i` (where **i** is the 1-based index of the element). If multiple elements qualify, any one is acceptable.

- **Uncoupled Phase Certificate:** The Ordering axiom is completely eliminated. Furthermore, the Span axiom is modified such that for one specific phase (either phase 1 for function $A$, or phase 2 for function $B$), the required interval lengths for all elements are reduced to 0. The other phase **c** (where **c** is strictly 1 or 2) requires the original lengths and must still satisfy the Exclusivity and Containment axioms. If no valid mapping exists under these relaxed conditions, print `LOAD c` (where **c** is exactly 1 or 2). If both phases qualify, either is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the two scalar parameters for the **i**-th element.

## Output

Print a single line containing either a valid `JOB i` certificate (where **i** is the 1-based index) or a valid `LOAD c` certificate (where **c** is 1 or 2).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under the Singleton Domain Certificate for element 1, $A(1)$ must have length 70 and $B(1)$ must have length 60. By the Ordering axiom, $A(1)$ must strictly precede $B(1)$. The union of their spans requires a minimal interval of length 130, which strictly exceeds the 100 bound of the Containment axiom. Therefore, `JOB 1` is a valid rejection certificate.

In Example 2, no single element violates the containment when isolated. However, under the Uncoupled Phase Certificate for phase 1, we must assign intervals $A(i)$ for four elements, each of length 50. By the Exclusivity axiom, they cannot overlap, requiring a disjoint placement across an interval of length at least 200. This strictly exceeds the 150 bound of the Containment axiom. Therefore, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
The physical scheduling concepts (jobs, machines, processing times) have been replaced with a formal mathematical task of mapping elements to intervals. This removes the intuitive cues that lead models to simply sum "durations" or "workloads," forcing them to deduce that the topological disjointness and ordering constraints imply additive lower bounds on the required interval span.
</RATIONALE>
<PRESERVED_ANSWER>
The interval mapping constraints are mathematically isomorphic to the original scheduling rules, so exactly the same elements and phases violate the relaxed scenarios.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an impossible certification task solvable by checking single-element interval sums and total-phase interval sums, keeping it in the same complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "the intersection has a length of 0" as allowing intervals to overlap at a single point, but this is exactly equivalent to jobs starting immediately as the previous one finishes, so it accurately models the original non-preemptive scheduling constraint without introducing ambiguity.
</RISK>
