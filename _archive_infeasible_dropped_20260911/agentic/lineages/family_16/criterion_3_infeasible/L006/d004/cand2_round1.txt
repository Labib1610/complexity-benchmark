<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform uses a two-stage pipeline to process client requests. A batch of **j** jobs has been submitted. Every job must be processed on machine 1 and then on machine 2. Each machine processes one job at a time without preemption. A job can only begin on machine 2 after it has completely finished on machine 1.

The client requires all **j** jobs to be completely finished by a strict Service Level Agreement (SLA) deadline of **T** milliseconds. 

For every input provided, it is impossible to meet this deadline, regardless of the order in which the jobs are scheduled. Your task is to output a short rejection certificate proving the deadline cannot be met. 

A certificate is formed by proposing a hypothetical modification to the processing times that makes the batch strictly faster to complete, yet the minimum possible completion time for the entire batch still strictly exceeds the SLA deadline. For every input, at least one such hypothetical modification will remain impossible to complete by the deadline. You must output a certificate for any impossible modification:

- **Isolated Job Scenario:** The processing times of all jobs except job **i** are reduced to 0 on both machines. Job **i** retains its original processing times. If the minimum possible time to completely finish all **j** jobs under these modified times strictly exceeds **T**, print `JOB i` (where **i** is the 1-based index). If multiple jobs qualify, any one is acceptable.

- **Independent Machine Scenario:** The processing times of all **j** jobs on the other machine (machine 2 if **c** is 1, or machine 1 if **c** is 2) are reduced to 0. Their processing times on machine **c** remain unchanged. If the minimum possible time to completely finish all **j** jobs under these modified times strictly exceeds **T**, print `LOAD c` (where **c** is the machine number, 1 or 2). If both machines qualify, either is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` (for a job qualifying under the isolated job scenario) or `LOAD c` (for a machine qualifying under the independent machine scenario).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under the Isolated Job Scenario for job 1, the processing times for jobs 2 and 3 become 0 on both machines. Regardless of the scheduling order, the minimum possible time to finish all three jobs is 130 milliseconds (since job 1 requires 70 milliseconds on machine 1 and then 60 milliseconds on machine 2, while the other jobs take 0 time). This strictly exceeds the 100-millisecond SLA. Therefore, `JOB 1` is a valid rejection certificate.

In Example 2, no single job exceeds the 150-millisecond SLA in an Isolated Job Scenario. However, under the Independent Machine Scenario for machine 1, the processing times for all jobs on machine 2 become 0. The minimum possible time to finish all four jobs requires machine 1 to process them one by one, taking 200 milliseconds total, after which they instantly finish on machine 2. This strictly exceeds the 150-millisecond SLA. Therefore, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
I removed the explicit instructions to "completely remove" jobs or "eliminate sequential dependency", which models were using to trivially sum the variables without understanding the flow shop mechanics. Instead, the certificates are defined as modified flow shop scheduling problems where certain processing times are set to 0. This forces the model to algorithmically deduce that the optimal makespan of these specifically modified flow shops is mathematically invariant to the job schedule and identically equals the simple additive bounds from the seed; models that fail to deduce this will attempt to simulate the schedules or apply Johnson's rule, resulting in a Time Limit Exceeded.
</RATIONALE>
<PRESERVED_ANSWER>
Setting $n-1$ jobs to 0 time results in a flow shop makespan exactly equal to $p1_i + p2_i$, and setting one machine to 0 time results in a makespan exactly equal to the sum of the other machine's times, preserving the exact certificate threshold conditions from the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an $O(N)$ certificate verification check because the invariant makespans can still be computed using the exact same simple additions as the seed, bypassing any need for actual simulation.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "minimum possible time" as requiring them to find the optimal schedule for the original unaltered jobs before evaluating the scenarios, but the text explicitly qualifies it as "under these modified times".
</RISK>
