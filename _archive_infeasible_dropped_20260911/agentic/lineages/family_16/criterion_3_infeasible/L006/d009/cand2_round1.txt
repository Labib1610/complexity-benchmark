<METHOD_NAME>State Machine Unrolling</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces explicit algebraic parameter substitution (e.g., $u=0, v=0$) with procedural step-skipping in an unrolled state machine. Models that rely on shallow pattern matching to derive the $O(N)$ closed forms ($\sum p_1$, $\sum p_2$, $p_{1,i} + p_{2,i}$) will fail to map the skipped steps to the corresponding mathematical simplifications, forcing them to either simulate the process or reason deeply about the state invariants.</METHOD_DESCRIPTION>

<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform processes a sequence of $j$ client requests. The system tracks its data using two counters: `secured_data` and `exposed_data`. Initially, both counters are exactly 0.

Each request provides two parameters, $p_1$ and $p_2$, and is processed in three sequential steps:
1. The system adds $p_1$ to `secured_data`.
2. The system encrypts up to $p_1$ units of exposed data. That is, it decreases `exposed_data` by $p_1$. Since `exposed_data` cannot become negative, if it is currently less than $p_1$, it simply drops to 0.
3. The system adds $p_2$ units of new data to `exposed_data`.

After all $j$ requests are processed in order, the final evaluation metric of the sequence is the sum of `secured_data` and `exposed_data`. The client requires this final metric to be at most $T$.

For every input provided, it is impossible to meet this deadline. The input guarantees that exactly one of the two following limitation categories applies. You must print a short rejection certificate from the applicable category:

- **Isolated Job Obstruction:** There is a request $i$ ($1 \le i \le j$) such that if we were to construct a hypothetical sequence where all requests except $i$ are completely skipped (meaning steps 1, 2, and 3 are ignored for all $k \neq i$), the final metric of this $j$-step sequence would strictly exceed $T$. If this category applies, print `JOB i`. (If multiple requests satisfy this, printing any one of them is acceptable).

- **Continuous Utilization Exhaustion:** There is a component $c \in \{1, 2\}$ such that if we were to construct a hypothetical sequence where one type of operation is systematically suppressed across all requests, the final metric would strictly exceed $T$. Specifically:
  - If $c = 1$, we simulate the sequence such that step 3 (ingesting new exposed data) is skipped for all requests. Steps 1 and 2 operate normally using $p_1$.
  - If $c = 2$, we simulate the sequence such that steps 1 and 2 are skipped for all requests. Only step 3 operates normally using $p_2$.
  If this category applies, print `LOAD c`. (If both satisfy this, either is acceptable).

Output must be consistent with the unique applicable limitation category guaranteed by the input.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the parameters for a request.

## Output

Print a single line containing either `JOB i` or `LOAD c`. The output must be consistent with the unique applicable limitation category guaranteed by the input.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, consider the hypothetical sequence for request 1 where requests 2 and 3 are completely skipped (steps 1, 2, and 3 are ignored).
Starting at `secured_data` = 0, `exposed_data` = 0:
Request 1:
Step 1: `secured_data` increases by 70. `secured_data` = 70.
Step 2: `exposed_data` decreases by 70 (bounded at 0). `exposed_data` = 0.
Step 3: `exposed_data` increases by 60. `exposed_data` = 60.
Requests 2 and 3 are skipped, so the state remains `secured_data` = 70, `exposed_data` = 60.
The final metric is 70 + 60 = 130. Since 130 > 100, `JOB 1` is a valid rejection certificate.

In Example 2, consider the hypothetical sequence for component 1 where step 3 is skipped for all requests.
Starting at `secured_data` = 0, `exposed_data` = 0:
Request 1:
Step 1: `secured_data` = 50.
Step 2: `exposed_data` decreases by 50 (bounded at 0). `exposed_data` = 0.
Step 3: skipped.
Request 2:
Step 1: `secured_data` = 100.
Step 2: `exposed_data` decreases by 50 (bounded at 0). `exposed_data` = 0.
Step 3: skipped.
Request 3:
Step 1: `secured_data` = 150.
Step 2: `exposed_data` decreases by 50 (bounded at 0). `exposed_data` = 0.
Step 3: skipped.
Request 4:
Step 1: `secured_data` = 200.
Step 2: `exposed_data` decreases by 50 (bounded at 0). `exposed_data` = 0.
Step 3: skipped.
The final metric is 200 + 0 = 200. Since 200 > 150, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
The explicit zeroing out of parameters (e.g., $u=0, v=0$) acts as a strong semantic trigger for LLMs to generate algebraic closed forms ($p_1+p_2$, $\sum p_1$, $\sum p_2$). By unrolling the state update into three distinct procedural steps and describing the hypothetical sequences as skipping specific steps rather than substituting zeroes, the problem forces the model to trace the state machine to deduce the same invariants.
</RATIONALE>
<PRESERVED_ANSWER>
Skipping all steps for a request is mathematically identical to processing $u=0, v=0$; skipping step 3 is identical to $u=p_1, v=0$; and skipping steps 1 and 2 is identical to $u=0, v=p_2$, ensuring all certificate conditions evaluate to the exact same totals.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still asks for the identical co-NP style impossibility certificates evaluated over $O(N)$ linear scans, preserving the INFEASIBLE complexity class.
</PRESERVED_CLASS>
