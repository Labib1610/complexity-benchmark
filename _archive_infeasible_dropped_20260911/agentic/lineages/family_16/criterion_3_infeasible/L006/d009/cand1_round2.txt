<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description
A data processing pipeline processes a sequence of $j$ jobs. Each job $k$ (for $1 \le k \le j$) requires $p_{1,k}$ milliseconds on machine 1 and then $p_{2,k}$ milliseconds on machine 2.

The pipeline tracks two timestamps for each job $k$:
- $E_k$: the time when the job completes on machine 1.
- $T_k$: the time when the job completes on machine 2.

Initially, at step 0 (before any jobs are processed), $E_0 = 0$ and $T_0 = 0$. For each job $k$ from $1$ to $j$, the timestamps are calculated sequentially:
- Machine 1 processes one job at a time, so job $k$ starts on machine 1 exactly when the previous job finishes on machine 1:
  $E_k = E_{k-1} + p_{1,k}$
- Machine 2 also processes one job at a time, but job $k$ cannot start on machine 2 until BOTH its own processing on machine 1 is finished AND the previous job's processing on machine 2 is finished:
  $T_k = \max(E_k, T_{k-1}) + p_{2,k}$

The final evaluation metric for the entire sequence is the completion time of the last job on machine 2, which is $T_j$. The system requires $T_j \le T$.

For every input provided, it is impossible to meet this deadline. The input guarantees that exactly one of the two failure families below is the reason. You must print a short rejection certificate identifying a valid witness from the applicable family.

- **Isolated Job Bottleneck:** There is a job $i$ ($1 \le i \le j$) such that if we construct a hypothetical sequence where job $i$ retains its actual parameters $p_{1,i}$ and $p_{2,i}$, but every other job $k \neq i$ is instantaneous (replaced with $p_{1,k} = 0$ and $p_{2,k} = 0$), the final metric $T_j$ of this hypothetical sequence strictly exceeds $T$.
  If this family applies, print `JOB i`.

- **Machine Saturation:** There is a machine $c \in \{1, 2\}$ such that if we construct a hypothetical sequence where the *other* machine takes 0 time for all jobs, the final metric $T_j$ strictly exceeds $T$.
  - If $c = 1$, we simulate using $p_{1,k}$ as given, but $p_{2,k} = 0$ for all $k$.
  - If $c = 2$, we simulate using $p_{1,k} = 0$, but $p_{2,k}$ as given for all $k$.
  If this family applies, print `LOAD c`.

**Uniqueness and Multiplicity:** For every input, exactly one of the two failure families is guaranteed to hold. However, within the applicable family, there may be multiple valid witnesses (e.g., multiple jobs $i$ that individually exceed $T$, or both machines exceeding $T$). Outputting any one valid witness from the applicable family is acceptable.

## Input
The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the time required on machine 1 and machine 2 for a job, respectively.

## Output
Print a single line containing either `JOB i` or `LOAD c`. The output must be a valid witness from the unique applicable failure family guaranteed by the input.

## Examples

### Example 1
**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2
**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note
In Example 1, consider the hypothetical sequence for job 1 where jobs 2 and 3 take 0 time:
The modified parameters are $(70, 60)$, $(0, 0)$, $(0, 0)$.
Step 1: $E_1 = 0 + 70 = 70$. $T_1 = \max(70, 0) + 60 = 130$.
Step 2: $E_2 = 70 + 0 = 70$. $T_2 = \max(70, 130) + 0 = 130$.
Step 3: $E_3 = 70 + 0 = 70$. $T_3 = \max(70, 130) + 0 = 130$.
The final metric $T_3 = 130$. Since $130 > 100$, `JOB 1` is a valid rejection certificate.

In Example 2, consider the hypothetical sequence for machine 1 where all machine 2 parameters are 0:
The modified parameters use the given machine 1 times and 0 machine 2 times.
Step 1: $E_1 = 50$, $T_1 = \max(50, 0) + 0 = 50$.
Step 2: $E_2 = 100$, $T_2 = \max(100, 50) + 0 = 100$.
Step 3: $E_3 = 150$, $T_3 = \max(150, 100) + 0 = 150$.
Step 4: $E_4 = 200$, $T_4 = \max(200, 150) + 0 = 200$.
The final metric $T_4 = 200$. Since $200 > 150$, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
I changed the state update equations from an artificial load/backlog system (tracking S and D, with metric S+D) to the mathematically isomorphic standard flow-shop completion times (tracking E and T, with metric T). This removes the explicit addition of the two state variables at the end, forcing models to symbolically evaluate the new max-based recurrence to prove that the zeroed-out hypothetical sequences still collapse to the closed forms `p1+p2`, `sum(p1)`, and `sum(p2)`.
</RATIONALE>
<PRESERVED_ANSWER>
The new state variables E_k and T_k maintain the exact invariant T_k = S_k + D_k, meaning the final metric T_j is mathematically identical to S_j + D_j for all possible inputs, preserving all certificate conditions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires a single linear pass over the sequence to check the isolated job sums and the total machine sums, keeping the time complexity at O(N).
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "every other job is instantaneous" as removing them from the sequence entirely rather than setting their parameters to 0, though the parenthesis "(replaced with p1=0 and p2=0)" explicitly prevents this.
</RISK>
