This forces the model to map the domain concepts back to the mathematical operations required to evaluate them.</METHOD_DESCRIPTION>

<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform uses a two-stage pipeline to process client requests. A batch of $j$ jobs has been submitted. Every job must be processed on machine 1 and then on machine 2. Each machine processes one job at a time without preemption. A job can only begin on machine 2 after it has completely finished on machine 1.

The client requires all $j$ jobs to be completely finished by a deadline of $T$ milliseconds. 

For every input provided, it is impossible to meet this deadline. The input guarantees that exactly one of the two following limitations is the reason the schedule must fail. You must print a short rejection certificate identifying the applicable limitation:

- **Sequential Bottleneck:** A job's minimum possible transit time through both stages is strictly greater than the deadline. If this applies, print `JOB i` (where $i$ is the 1-based index of any such job).

- **Machine Capacity Limit:** A machine's total required active running time for the batch is strictly greater than the deadline. If this applies, print `LOAD c` (where $c$ is the machine number, 1 or 2).

Output must be consistent with the unique applicable limitation guaranteed by the input.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` (for a job qualifying under the Sequential Bottleneck) or `LOAD c` (for a machine qualifying under the Machine Capacity Limit). The output must be consistent with the unique applicable limitation guaranteed by the input.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for job 1, its minimum transit time is $70 + 60 = 130$ milliseconds. This is strictly greater than the 100 millisecond deadline. The Sequential Bottleneck applies, making `JOB 1` a valid rejection certificate.

In Example 2, no job has a transit time exceeding 150 milliseconds. However, machine 1 has a total required active running time of $50 + 50 + 50 + 50 = 200$ milliseconds. This is strictly greater than the 150 millisecond deadline. The Machine Capacity Limit applies, making `LOAD 1` a valid rejection certificate.
</STATEMENT>
<RATIONALE>
Removed the closed-form inequalities (`T - p1 < p2` and `T < sum`) and replaced them with descriptive scheduling concepts ("minimum possible transit time" and "total required active running time"). This forces models to derive the mathematical bounds from the operational requirements rather than pattern-matching the explicit formulas.
</RATIONALE>
<PRESERVED_ANSWER>
The logical conditions for the two certificates remain mathematically identical to the seed problem ($p_{1,i} + p_{2,i} > T$ and $\sum p_{c,i} > T$), maintaining exactly the same outputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class is unchanged (O(N) impossibility certification) because the conditions that need to be checked and the logic required to find a valid certificate remain identical.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "minimum possible transit time" as involving wait times between stages, though "minimum possible" strongly implies continuous execution.
</RISK>
