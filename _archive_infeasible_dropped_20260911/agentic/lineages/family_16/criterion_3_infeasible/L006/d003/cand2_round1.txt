<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform uses a two-stage pipeline to process client requests. A batch of **j** jobs has been submitted. Every job must be processed on machine 1 and then on machine 2. Each machine processes one job at a time without preemption. A job can only begin on machine 2 after it has completely finished on machine 1.

The client requires all **j** jobs to be completely finished by a strict Service Level Agreement (SLA) deadline of **T** milliseconds. 

For every input provided, it is impossible to meet this deadline, regardless of how the jobs are scheduled. Your task is to output a short rejection certificate proving the deadline cannot be met. 

A certificate is formed by proposing a simplified, hypothetical scenario that is strictly easier to schedule than the original problem, yet still impossible to complete by the deadline. For every input, at least one such hypothetical scenario will remain impossible to schedule. You must output a certificate for any impossible scenario:

- **Isolated Job Scenario:** All jobs except job **i** are completely removed from the system. Job **i** must still be processed on machine 1 and then machine 2. If this scenario cannot be completed by the deadline, print `JOB i` (where **i** is the 1-based index). If multiple jobs qualify, any one is acceptable.

- **Independent Machine Scenario:** The sequential dependency between machines is completely eliminated. Furthermore, one of the machines is replaced with an infinitely fast processor that takes 0 time for all jobs. Only machine **c** operates at its normal speed, processing its assigned tasks one at a time. If this scenario cannot be completed by the deadline, print `LOAD c` (where **c** is the machine number, 1 or 2). If both machines qualify, either is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` (for a job qualifying under the isolated job scenario) or `LOAD c` (for a machine qualifying under the independent machine scenario).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under the Isolated Job Scenario for job 1, it requires 70 milliseconds on machine 1 and 60 milliseconds on machine 2. Since it must run sequentially, it takes 130 milliseconds, which strictly exceeds the 100-millisecond SLA. Therefore, `JOB 1` is a valid rejection certificate.

In Example 2, no single job exceeds the 150-millisecond SLA in an Isolated Job Scenario. However, under the Independent Machine Scenario for machine 1, the machine must process four jobs taking 50 milliseconds each. Running them one at a time requires 200 milliseconds, which strictly exceeds the 150-millisecond SLA. Therefore, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
Removed the explicit inequality checks (`p1 + p2 > T` and total workload `> T`) that allowed models to pattern-match the solution without understanding the scheduling constraints. Replaced them with schedule-dependent bottleneck certificates defined through relaxed hypothetical scenarios, forcing the model to deduce that the isolated job scenario requires `p1 + p2` time and the independent machine scenario requires `sum(pc)` time.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions for an impossible isolated job (`p1 + p2 > T`) and an impossible independent machine (`sum(pc) > T`) are exactly equivalent to the original sequential job limit and total machine workload conditions, ensuring all valid outputs remain strictly identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an INFEASIBLE certificate generation task requiring linear-time checks of sums and single-element bounds, preserving the original O(N) complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the "Independent Machine Scenario" as allowing jobs to be processed in parallel on the same machine, but the instruction "processing its assigned tasks one at a time" directly prevents this ambiguity.
</RISK>
