<STATEMENT>
# SLA Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud computing platform uses a two-stage pipeline to process client requests. A batch of **j** jobs has been submitted. Every job must be processed on machine 1 and then on machine 2. Each machine processes one job at a time. A job can only begin on machine 2 after it has completely finished on machine 1.

The client requires all **j** jobs to be completely finished by a strict Service Level Agreement (SLA) deadline of **T** milliseconds. 

For every input provided, it is impossible to meet this deadline, regardless of how the jobs are scheduled. Your task is to output a short rejection certificate proving the deadline cannot be met. 

A rejection certificate identifies a specific simplified scenario that still fails to meet the deadline. Consider the following two hypothetical scenarios:

- **Scenario A (Infinite Capacity):** Assume both machines can process an unlimited number of jobs simultaneously, meaning jobs never wait for other jobs. However, each job's machine 2 operation must still wait for its own machine 1 operation to finish. If the earliest time by which all jobs can complete under this scenario strictly exceeds **T**, print `JOB i`, where **i** is the 1-based index of any job that completes after time **T**.

- **Scenario B (Independent Stages):** Assume each job's machine 2 operation no longer needs to wait for its machine 1 operation to finish, meaning machine 2 can start processing jobs at time 0. However, each machine can still only process one job at a time, meaning operations on the same machine cannot overlap. If the earliest time by which all jobs can complete under this scenario strictly exceeds **T**, print `LOAD c`, where **c** is the machine number (1 or 2) that finishes its assigned operations after time **T**.

The inputs are rigorously constructed such that exactly one of these two scenarios will result in an earliest completion time that strictly exceeds **T**. You must output the certificate corresponding to the single applicable scenario.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` or `LOAD c`, consistent with the guaranteed single applicable scenario that exceeds the SLA.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under Scenario A, the first job requires 70 milliseconds on machine 1 and then 60 milliseconds on machine 2, completing at 130 milliseconds. Since this strictly exceeds the 100-millisecond SLA, `JOB 1` is a valid rejection certificate. Under Scenario B, both machines would finish all their assigned operations within 75 milliseconds, which does not exceed the SLA.

In Example 2, under Scenario A, no single job takes more than 51 milliseconds, which is well within the 150-millisecond SLA. However, under Scenario B, machine 1 must process four 50-millisecond operations sequentially, taking 200 milliseconds. Since this strictly exceeds the 150-millisecond SLA, `LOAD 1` is a valid rejection certificate.
</STATEMENT>
<RATIONALE>
Changed the explicit sum and inequality definitions of the rejection certificates into schedule-dependent bottleneck scenarios (infinite capacity vs independent stages). This forces the model to determine the optimal pipeline behavior under these relaxations and logically derive the corresponding formulas itself, rather than pattern-matching explicit inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
The earliest completion time under the infinite capacity scenario evaluates exactly to the maximum sequential job time, and under the independent stages scenario evaluates exactly to the maximum total machine workload, preserving all conditions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The required check remains a linear scan to find a single job exceeding the limit or to sum the workloads for each machine, keeping it an O(N) impossibility certification.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "earliest time by which all jobs can complete" as requiring them to compute an actual optimal schedule for the original unrelaxed problem, though the explicit relaxations should prevent this.
</RISK>
