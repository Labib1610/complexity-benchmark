 We need to check two possible reasons for infeasibility:

1. **JOB i**: Even ignoring the non-overlap constraints, a single job cannot finish by `T+1`.  
   For job `i`, the earliest possible completion time on stage 2 is `p1[i] + p2[i]` (since stage 1 must finish before stage 2 starts, and both start at time ≥ 1).  
   So if `p1[i] + p2[i] > T + 1`, then `JOB i` is a valid certificate.

2. **LOAD c**: Even ignoring the other facility and the precedence constraints, the total processing time on facility `c` must fit within the time window from 1 to `T+1`.  
   Since jobs on the same machine cannot overlap, the sum of processing times on that machine must be ≤ `T+1`.  
   If `sum(p1) > T+1`, then `LOAD 1` is valid.  
   If `sum(p2) > T+1`, then `LOAD 2` is valid.

We check `JOB` first, then `LOAD`. If both are possible, we can output either, but the problem says exactly one will apply.  

Let's implement:

```python
j, T = map(int, input().split())
p1 = []
p2 = []
for _ in range(j):
    a, b = map(int, input().split())
    p1.append(a)
    p2.append(b)

# Check JOB condition
for i in range(j):
    if p1[i] + p2[i] > T + 1:
        print(f"JOB {i+1}")
        exit()

# Check LOAD condition
if sum(p1) > T + 1:
    print("LOAD 1")
    exit()
if sum(p2) > T + 1:
    print("LOAD 2")
    exit()
```
