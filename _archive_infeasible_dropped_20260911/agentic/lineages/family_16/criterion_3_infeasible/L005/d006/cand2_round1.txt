<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must process **j** items through two sequential stages. Every item must fully complete stage 1 at the first facility before it can advance to stage 2 at the second facility. The required processing duration for each item at stage 1 and stage 2 is provided. A facility can process only a single item at any given moment.

The input provides an integer parameter **T**. The absolute deadline for the production run is time `t = T + 1`. Note that the plant powers on and begins its schedule exactly at time `t = 1`.

For any processing sequence $\pi$ (a permutation of the **j** items), the plant operates as follows:
- Facility 1 begins processing the first item in $\pi$ at `t = 1` and processes all items in the order $\pi$ continuously back-to-back.
- Facility 2 processes items in the same order $\pi$. It begins an item as soon as facility 1 completes it, provided facility 2 is not currently busy with a previous item.

For a given sequence $\pi$, we can measure three specific bottleneck metrics:
1. For each item **i**, its **transit span**: the elapsed time from the exact moment item **i** begins at facility 1 until the exact moment it completes at facility 2.
2. The **stage 1 span**: the elapsed time from when facility 1 starts its first item until it completes its last item.
3. The **stage 2 span**: the elapsed time from when facility 2 starts its first item until it completes its last item, MINUS any time during this period that facility 2 spends idle.

For every given input, no sequence $\pi$ can meet the deadline `T + 1`. Exactly one of the following two underlying bottlenecks is responsible, and you must output the corresponding certificate:

- **Routing Delay:** There exists an item **i** (1-based index) such that its transit span strictly exceeds **T** for EVERY possible sequence $\pi$. If this is the cause, output `JOB i`. If multiple items fit this description, you may output any one of them.
- **Throughput Saturation:** There exists a facility **c** (1 or 2) such that its corresponding stage span (stage 1 span for facility 1, or stage 2 span for facility 2) strictly exceeds **T** for EVERY possible sequence $\pi$. If this is the cause, output `LOAD c`. If both facilities fit this description, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing duration of an item at stage 1 and stage 2, respectively.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, **T** = 100. The absolute deadline is `t = 101`. Consider item 1. For any sequence $\pi$, it must spend 70 time units at facility 1 and 60 time units at facility 2. Since it cannot be processed at both simultaneously, its transit span is at least 130. Since 130 strictly exceeds 100, its transit span exceeds **T** for every possible sequence $\pi$. Thus, a routing delay certificate `JOB 1` is printed. (The stage 1 span is 75, and the stage 2 span is 66, both of which are ≤ 100).

In Example 2, **T** = 150. The absolute deadline is `t = 151`. No single item has a transit span exceeding 150 for all sequences (for instance, in the sequence `[1, 2, 3, 4]`, item 1's transit span is exactly 50 + 1 = 51). However, the stage 1 span is the time facility 1 takes to process all items back-to-back. This is 50 + 50 + 50 + 50 = 200. Since 200 strictly exceeds 150, the stage 1 span exceeds **T** for every possible sequence $\pi$. Thus, a saturation certificate `LOAD 1` is printed.
