# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory processes **j** orders through exactly two sequential stages. Every order must be processed on stage 1 first, and then on stage 2. For each order, you are given its required processing duration on stage 1 and on stage 2. Each stage processes only one order at a time without interruption, and an order reaches stage 2 only after its stage 1 processing is complete.

A schedule assigns a start time $S_{i,c}$ and end time $E_{i,c}$ for each order $i$ on each stage $c$. For any valid schedule, we define the following metrics:
- The *residence time* of order $i$ is $E_{i,2} - S_{i,1}$.
- The *delay time* of order $i$ is $S_{i,2} - E_{i,1}$.
- The *completion time* of a stage $c$ is the maximum $E_{k,c}$ over all orders $k$.
- The *idle time* of a stage $c$ is the total duration between time $0$ and its completion time during which the stage is not processing any order.

A diagnostic tool evaluates the configuration against a deadline **T**. Exactly one of the following structural bottlenecks will be present in the input. Print the one that holds:

- **An order is too long.** If there is an order $i$ such that its residence time minus its delay time strictly exceeds **T**, print `JOB i` (where $i$ is the 1-based index of the order).
- **A stage is overloaded.** If there is a stage $c$ (1 or 2) such that its completion time minus its idle time strictly exceeds **T**, print `LOAD c`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of an order on stage 1 and stage 2.

## Output

Print a single line: `JOB i` (an order whose residence time minus delay time exceeds T) or `LOAD c` (a stage c whose completion time minus idle time exceeds T).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for order 1, its residence time minus its delay time is 70 + 60 = 130 > 100, so `JOB 1` is the identified bottleneck. In Example 2, no single order exceeds 150, but the completion time minus idle time for stage 1 is 50+50+50+50 = 200 > 150, so `LOAD 1` is the bottleneck.
