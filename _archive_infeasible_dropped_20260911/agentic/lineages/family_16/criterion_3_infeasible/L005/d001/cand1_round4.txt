<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must route **j** jobs through two sequential processing stations. Every job must be fully processed at station 1 before it can be transferred to station 2. The required processing duration for each job at station 1 and station 2 is provided. A station can process only a single job at any given moment.

The plant operates under a strict completion deadline **T**. For a production run to be successful, all jobs must clear station 2 by time **T**.

For every given configuration, no valid schedule exists that can meet the deadline. You must provide a structural certificate proving this impossibility. Exactly one of the following two proof categories will apply to the configuration, and you must output the certificate for the uniquely applicable category:

- **Routing Delay:** A specific job cannot complete its required sequence within the timeframe. Because its processing at station 1 and station 2 must occur sequentially, its own minimum sequential duration strictly exceeds **T**. 
  Output format: `JOB i`, where **i** (1-based index) is the failing job. If multiple jobs fail this way, you may output any one of them.

- **Throughput Saturation:** A specific station requires more total active time than the timeframe allows. Because a station processes jobs serially, its required continuous operation to clear all jobs strictly exceeds **T**.
  Output format: `LOAD c`, where **c** is the station number (1 or 2) that is saturated. If both stations are saturated, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing duration of a job at station 1 and station 2, respectively.

## Output

Print a single line containing the exact certificate for the uniquely applicable category: either `JOB i` for a routing delay or `LOAD c` for throughput saturation.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 time units at station 1 and then 60 at station 2. Its minimum sequential duration is 130, which strictly exceeds the deadline of 100. Thus, a routing delay certificate `JOB 1` is printed. 
In Example 2, no single job's sequential duration exceeds 150. However, station 1 must remain continuously active for 50+50+50+50 = 200 time units to process all jobs serially. This strictly exceeds the 150 deadline, so a throughput saturation certificate `LOAD 1` is printed.
</STATEMENT>
<RATIONALE>
The rewrite removes the explicit mathematical formulas (`p1+p2 > T` and `sum > T`) that models were pattern-matching against, replacing them with mechanically descriptive phrases ("minimum sequential duration" and "required continuous operation to clear all jobs"). It restores the exact logical guarantee from the seed (that exactly one category applies) to satisfy the gate critique while maintaining the structural proof framing.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions "minimum sequential duration strictly exceeds T" and "required continuous operation strictly exceeds T" are mathematically identical to `p1+p2 > T` and `sum(p) > T`, so the identical output logic applies.
</PRESERVED_ANSWER>

The complexity remains O(j) since it still involves checking a linear number of independent conditions and sums, preserving the impossibility certification nature.
</PRESERVED_CLASS>
