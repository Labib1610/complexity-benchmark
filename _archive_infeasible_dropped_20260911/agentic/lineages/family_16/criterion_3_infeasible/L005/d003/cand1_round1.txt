# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must route **j** jobs through two sequential processing stations. Every job must be fully processed at station 1 before it can be transferred to station 2. The required processing duration for each job at station 1 and station 2 is provided. A station can process only a single job at any given moment.

The plant operates under a strict completion deadline **T**. For a production run to be successful, all jobs must clear station 2 by time **T**.

For every given configuration, no valid schedule exists that can meet the deadline. You must provide a structural certificate proving this impossibility. Exactly one of the following two proof categories will apply to the configuration, and you must output the certificate for the uniquely applicable category:

- **Routing Delay:** Output `JOB i`, where **i** (1-based index) is a job that is guaranteed to breach the deadline in isolation. This applies if the plant would fail to finish by time **T** even in a hypothetical scenario where all jobs except job **i** are cancelled. If multiple jobs qualify, you may output any one of them.

- **Throughput Saturation:** Output `LOAD c`, where **c** is the station number (1 or 2) that is guaranteed to breach the deadline in isolation. This applies if the plant would fail to finish by time **T** even in a hypothetical scenario where the *other* station requires exactly zero time to process any job. If both stations qualify, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing duration of a job at station 1 and station 2, respectively.

## Output

Print a single line containing the exact certificate for the uniquely applicable category: either `JOB i` for a routing delay or `LOAD c` for throughput saturation.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 time units at station 1 and then 60 at station 2. Even if all other jobs are cancelled, job 1 finishes at time 130, missing the deadline of 100. Thus, a routing delay certificate `JOB 1` is printed. 
In Example 2, no single job breaches the 150 deadline in isolation. However, if station 2 required zero time, station 1 would still need to process four tasks of 50 time units each. This takes 200 time units, missing the deadline, so a throughput saturation certificate `LOAD 1` is printed.
</STATEMENT>
<RATIONALE>
I replaced the explicit descriptions of additive bounds ("zero wait time", "processed all its assigned tasks back-to-back") with hypothetical relaxed scenarios (cancelling all other jobs, or making the other station instantaneous). This forces the model to deduce the mathematical implications of these relaxations—specifically that they correspond to `p1 + p2 > T` and `sum(p1) > T` or `sum(p2) > T`—rather than relying on surface-level keyword matching. The suggested addition of a 1-unit delay was explicitly rejected because it would alter correct outputs for boundary cases (e.g., `p1 + p2 = T`), violating the identical answers constraint.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for the certificates mathematically evaluate to exactly `p1 + p2 > T` and `sum > T` as in the original problem, ensuring the reference solution remains perfectly correct.
</PRESERVED_ANSWER>

</PRESERVED_CLASS>
<RISK>
Models might misinterpret "cancelled" or "zero time" as altering the definition of the actual scheduling problem rather than merely defining the condition for the certificate, though "hypothetical scenario" should clarify this.
</RISK>
