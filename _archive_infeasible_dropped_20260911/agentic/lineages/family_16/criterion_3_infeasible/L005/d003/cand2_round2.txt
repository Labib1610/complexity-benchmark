<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must process **j** items through two sequential stages. Every item must fully complete stage 1 at the first facility before it can advance to stage 2 at the second facility. The required processing duration for each item at stage 1 and stage 2 is provided. A facility can process only a single item at any given moment.

The plant operates under a strict completion deadline **T**. For a production run to be successful, all items must clear stage 2 by time **T**.

For every given input, no valid schedule exists that can meet the deadline. You must provide a short certificate proving this impossibility. You are not asked to construct a schedule; only output a certificate that can be checked directly from the input. Exactly one of the following two reasons will apply, and you must output the corresponding certificate:

- **Routing Delay:** A single item is inherently too long. Output `JOB i`, where **i** (1-based index) is an item whose minimal possible completion time from time 0, constrained only by its own sequential processing requirements, strictly exceeds **T**. If multiple items qualify, you may output any one of them.

- **Throughput Saturation:** A facility is assigned too much work. Output `LOAD c`, where **c** is the facility number (1 or 2) whose minimal possible time to clear its entire queue from time 0, constrained only by its total assigned processing volume, strictly exceeds **T**. If both facilities qualify, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing duration of an item at stage 1 and stage 2, respectively.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, item 1 requires 70 time units at stage 1 and then needs 60 at stage 2. Its absolute minimum completion time from time 0 is 130, missing the deadline of 100. Thus, a routing delay certificate `JOB 1` is printed. 
In Example 2, no single item is inherently too long for the 150 deadline. However, facility 1 has to complete four tasks of 50 time units each. Its absolute minimum time to finish all tasks from time 0 is 200. This misses the deadline, so a throughput saturation certificate `LOAD 1` is printed.
</STATEMENT>
<RATIONALE>
I removed the explicit additive lower bounds by describing the conditions as the "minimal possible completion time from time 0" dictated by sequential constraints or total volume. I did not add the suggested one-unit transfer delay because doing so would alter the mathematical condition (e.g., p1 + p2 + 1 > T), which risks changing the uniquely applicable certificate for existing test cases where p1 + p2 = T, violating the identical answers constraint. This forces models to logically derive the sums from the minimal time constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The definitions for both certificates remain mathematically identical to p1 + p2 > T and sum > T, ensuring the reference solution's outputs remain perfectly correct.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an impossibility certification task where the solver must check individual job lengths and total machine loads against a deadline.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "minimal possible completion time from time 0" as requiring them to simulate a schedule, though the text explicitly tells them not to construct a schedule.
</RISK>
