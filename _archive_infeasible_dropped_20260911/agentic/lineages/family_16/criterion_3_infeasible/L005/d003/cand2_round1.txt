<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must route **j** jobs through two sequential processing stations. Every job must be fully processed at station 1 before it can be transferred to station 2. The required processing duration for each job at station 1 and station 2 is provided. A station can process only a single job at any given moment.

The plant operates under a strict completion deadline **T**. For a production run to be successful, all jobs must clear station 2 by time **T**.

For every given configuration, no valid schedule exists that can meet the deadline. You must provide a structural certificate proving this impossibility. Exactly one of the following two proof categories will apply to the configuration, and you must output the certificate for the uniquely applicable category.

Imagine a timeline interval extending from time 0 to the deadline **T**:

- **Routing Delay:** Job **i** (1-based index) requires a continuous block of time at station 1 and a continuous block at station 2. Because a job cannot be at both stations simultaneously, its two blocks cannot overlap. Output `JOB i` if it is impossible to place both of job **i**'s blocks within the timeline interval such that they do not overlap. If multiple jobs qualify, you may output any one of them.

- **Throughput Saturation:** Station **c** (station 1 or 2) requires a continuous block of time for each of the **j** jobs. Because a station can process only one job at a time, its **j** blocks cannot overlap. Output `LOAD c` if it is impossible to place all **j** of station **c**'s blocks within the timeline interval such that none of them overlap. If both stations qualify, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing duration of a job at station 1 and station 2, respectively.

## Output

Print a single line containing the exact certificate for the uniquely applicable category: either `JOB i` for a routing delay or `LOAD c` for throughput saturation.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires a block of 70 time units at station 1 and a block of 60 at station 2. It is impossible to place both blocks into the [0, 100] timeline interval without them overlapping. Thus, a routing delay certificate `JOB 1` is printed. 
In Example 2, no single job's two blocks are too large to fit into the [0, 150] timeline interval. However, station 1 must allocate four blocks of 50 time units each. It is impossible to place all four blocks into the [0, 150] timeline interval without overlap, so a throughput saturation certificate `LOAD 1` is printed.
</STATEMENT>
<RATIONALE>
I removed the explicit wording that acted as a direct affordance for additive lower bounds (e.g., "if it never sat idle"). Instead, I reframed both conditions as geometric packing problems on a timeline. Models must now deduce that placing continuous blocks into an interval without overlap is impossible if and only if the sum of their lengths strictly exceeds the interval's length.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that blocks cannot be placed in an interval of length T without overlap is mathematically identical to their sum being strictly greater than T, preserving all original logic and answers perfectly.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains INFEASIBLE (co-NP style certification) because the algorithm still just requires checking sums of processing times against the constant T.
</PRESERVED_CLASS>
<RISK>
Models or readers might misinterpret "place within the timeline interval" as requiring the blocks to be contiguous with each other, though the phrase "such that they do not overlap" implies they can be placed anywhere.
</RISK>
