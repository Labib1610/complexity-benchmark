<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must process **j** items through two sequential stages. Every item must fully complete stage 1 at the first facility before it can advance to stage 2 at the second facility. A facility can process only a single item at any given moment.

The plant operates under a strict completion deadline **T**. For a production run to be successful, all items must clear stage 2 by time **T** (meaning all processing must occur within the operational window $[0, T]$).

For every given input, it is guaranteed that no valid schedule exists that can meet the deadline. You must provide a short certificate identifying the root cause of this impossibility. You are not asked to construct a schedule; only output a certificate that can be verified directly from the input. Exactly one of the following two scenarios will apply, and you must output the corresponding certificate:

- **Internal Overlap:** Output `JOB i`, where **i** (1-based index) is an item for which any attempt to place a continuous block of length equal to its stage 1 requirement and a continuous block of length equal to its stage 2 requirement entirely within the window $[0, T]$ inevitably results in the two blocks overlapping by a strictly positive duration. If multiple items exhibit this property, you may output any one of them.

- **Resource Overlap:** Output `LOAD c`, where **c** is the facility number (1 or 2) for which, even when ignoring all stage dependencies and focusing solely on this single facility, any attempt to place a continuous block for every item's stage **c** requirement entirely within the window $[0, T]$ inevitably results in at least two items' blocks overlapping by a strictly positive duration. If both facilities exhibit this property, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required continuous processing duration of the item at stage 1 and stage 2, respectively.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, item 1 requires a block of length 70 at stage 1 and a block of length 60 at stage 2. It is impossible to place both blocks entirely within the $[0, 100]$ operational window without them overlapping by a strictly positive duration. Thus, an internal overlap certificate `JOB 1` is printed. 
In Example 2, no single item forces an internal overlap within the 150 window. However, facility 1 must accommodate four separate blocks of length 50. Placing all four blocks within the $[0, 150]$ window inevitably forces at least two of them to overlap by a strictly positive duration. Thus, a resource overlap certificate `LOAD 1` is printed.
</STATEMENT>
<RATIONALE>
Removed explicit references to minimal completion times and total processing volumes, which models easily mapped to `p1 + p2` and column sums. By redefining the certificates as 1D geometric packing problems (fitting blocks into a window of size T without overlap), models must now mathematically deduce that "inevitably overlapping" is identical to the sum of lengths exceeding T.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that 1D blocks cannot be packed into an interval of length T without positive-duration overlap is mathematically identical to their sum strictly exceeding T, preserving the exact `p1+p2 > T` and `sum(p) > T` logic.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly solvable in O(N) time by checking the single-item sums and total-column sums.
</PRESERVED_CLASS>
<RISK>
Models might attempt to actually simulate placing blocks instead of reducing it to a sum, leading to overly complex or inefficient code, though the wording "inevitably results in" strongly points toward an analytical inequality.
</RISK>
