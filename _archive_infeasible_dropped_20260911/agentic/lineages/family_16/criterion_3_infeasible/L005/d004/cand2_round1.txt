<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must process **j** items through two sequential stages. Every item must fully complete stage 1 at the first facility before it can advance to stage 2 at the second facility. The required processing duration for each item at stage 1 and stage 2 is provided. A facility can process only a single item at any given moment.

The plant operates under a strict completion deadline **T**. For a production run to be successful, all items must clear stage 2 by time **T**.

For every given input, no valid schedule exists that can meet the deadline. You must provide a short certificate proving this impossibility. You are not asked to construct a schedule; only output a certificate that can be checked directly from the input. Exactly one of the following two reasons will apply, and you must output the corresponding certificate:

- **Routing Delay:** Imagine a hypothetical scenario where all items except item **i** (1-based index) are cancelled. If the plant still cannot process item **i** through both stages by time **T**, output `JOB i`. If multiple items fit this description, you may output any one of them.

- **Throughput Saturation:** Imagine a hypothetical scenario where the sequential dependency between stages is removed, such that facility **c** (1 or 2) always has all **j** items immediately available to process back-to-back without any waiting. If facility **c** still cannot finish its work by time **T**, output `LOAD c`. If both facilities fit this description, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing duration of an item at stage 1 and stage 2, respectively.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, if all items except item 1 are cancelled, it requires 70 time units at stage 1 and then needs 60 at stage 2. It would finish at time 130, missing the deadline of 100. Thus, a routing delay certificate `JOB 1` is printed. 
In Example 2, no single item would miss the deadline if run alone. However, if facility 1 could process all tasks back-to-back without waiting for any prerequisites, it would still need to complete four tasks of 50 time units each. It would finish at time 200, which misses the deadline, so a throughput saturation certificate `LOAD 1` is printed.
</STATEMENT>
<RATIONALE>
Replaced explicit descriptions of additive bounds (minimal time constrained by sequential requirements or total volume) with purely operational counterfactuals. Models must now deduce that "cancelling all other items" implies $p_1 + p_2 > T$, and "removing sequential dependencies" implies $\sum p_c > T$, forcing genuine reasoning about the scenario rather than pattern-matching summation shortcuts.
</RATIONALE>
<PRESERVED_ANSWER>
The first counterfactual exactly describes $p_1+p_2 > T$ and the second exactly describes $\sum p_c > T$, which uniquely define the original certificates `JOB i` and `LOAD c`.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires an $O(n)$ check of individual job sums and total machine loads to output an impossibility certificate, keeping it in the same complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "cannot finish its work" for the facility as something other than the sum of its processing times, though "process back-to-back without any waiting" strongly constrains the meaning.
</RISK>
