# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must process **j** items through two sequential stages. Every item must fully complete stage 1 at the first facility before it can advance to stage 2 at the second facility. The required processing duration (in discrete cycles) for each item at stage 1 and stage 2 is provided. A facility can process only a single item at any given moment.

Time is measured in discrete intervals called cycles, starting from cycle 0. The plant operates under a strict completion deadline: all items must fully clear stage 2 before the start of cycle **T**. 

For every given input, no valid schedule exists that can meet the deadline. You must provide a short certificate proving this impossibility. Exactly one of the following two reasons will apply, and you must output the corresponding certificate:

- **Routing Delay:** Imagine a hypothetical scenario where all items except item **i** (1-based index) are cancelled. If item **i** is processed as early as possible, and the final cycle of its processing is cycle **T** or greater, output `JOB i`. If multiple items fit this description, you may output any one of them.

- **Throughput Saturation:** Imagine a hypothetical scenario where the sequential dependency between stages is removed, such that facility **c** (1 or 2) processes all **j** items back-to-back without any idle cycles. If the final cycle of facility **c**'s processing is cycle **T** or greater, output `LOAD c`. If both facilities fit this description, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing duration of an item at stage 1 and stage 2, respectively.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, if all items except item 1 are cancelled, it requires 70 cycles at stage 1 and 60 cycles at stage 2, for a total of 130 cycles. Starting at cycle 0, its processing occupies cycles 0 through 129. The final cycle of its processing is cycle 129. Since 129 is **T** or greater (129 ≥ 100), a routing delay certificate `JOB 1` is printed. 

In Example 2, no single item would have a final cycle of 150 or greater if run alone. However, if facility 1 processes all tasks back-to-back starting at cycle 0, it requires 200 cycles in total. Its processing occupies cycles 0 through 199. The final cycle of its processing is cycle 199. Since 199 is 150 or greater (199 ≥ 150), a throughput saturation certificate `LOAD 1` is printed.

<METHOD_NAME>Zero-Indexed Final Cycle Trap</METHOD_NAME>
<METHOD_DESCRIPTION>We define time in 0-indexed cycles so that a process of length X ends on cycle X - 1. The failure condition is framed as "the final cycle is T or greater" (i.e. X - 1 >= T), which is mathematically identical to the original X > T. Models relying on surface pattern matching will likely translate "is T or greater" directly into `X >= T` (missing the -1 offset) and fail on boundary cases.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>
<RATIONALE>
Changed the deadline framing to use 0-indexed discrete cycles and defined the failure threshold based on the index of the final occupied cycle (`X - 1 >= T`) rather than the total duration (`X > T`). This forces the model to carefully track the off-by-one shift instead of blindly applying a `>` or `>=` operator to the total sum.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical condition for a certificate remains exactly total duration > T (since total - 1 >= T is equivalent to total > T for integers), ensuring output is identical for all inputs.
</PRESERVED_ANSWER>

The underlying logic of identifying a single job or single machine that independently exceeds the time limit remains unchanged, preserving the INFEASIBLE certification class.
