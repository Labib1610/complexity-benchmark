<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

You are given a domain boundary parameter $T$, and a set of $j$ elements. For each element $k \in \{1, \dots, j\}$, you must define two half-open intervals of real numbers: $X_k = [a_{1,k}, b_{1,k})$ and $Y_k = [a_{2,k}, b_{2,k})$.
The required lengths of these intervals are given: the length of $X_k$ must be exactly $p_{1,k}$, and the length of $Y_k$ must be exactly $p_{2,k}$.

A configuration of these intervals is called *valid* if it satisfies all four of the following axioms:
1. **Domain:** For all $k$, $X_k \subset [1, T+1]$ and $Y_k \subset [1, T+1]$.
2. **Precedence:** For all $k$, every real number in $X_k$ is strictly less than every real number in $Y_k$.
3. **Disjoint X:** For all distinct $m$ and $n$, $X_m \cap X_n = \emptyset$.
4. **Disjoint Y:** For all distinct $m$ and $n$, $Y_m \cap Y_n = \emptyset$.

For every given input, it is guaranteed that no valid configuration exists. You must provide a short certificate proving this impossibility. Exactly one of the following two reasons will apply, and you must output the corresponding certificate:

- `JOB i` (where $i$ is the 1-based index of the element): Axioms 1 and 2 alone are logically inconsistent for a specific element $i$. That is, it is mathematically impossible to define intervals $X_i$ and $Y_i$ of their required lengths that satisfy Axioms 1 and 2, even if Axioms 3 and 4 are completely ignored. If multiple elements fit this description, you may output any one of them.
- `LOAD c` (where $c$ is 1 or 2): Axioms 1 and the corresponding disjointness axiom are logically inconsistent. 
  - If $c = 1$, it is mathematically impossible to define the collection of intervals $X_1, X_2, \dots, X_j$ of their required lengths to satisfy Axioms 1 and 3, even if Axioms 2 and 4 are completely ignored.
  - If $c = 2$, it is mathematically impossible to define the collection of intervals $Y_1, Y_2, \dots, Y_j$ of their required lengths to satisfy Axioms 1 and 4, even if Axioms 2 and 3 are completely ignored.
  
  If both $c=1$ and $c=2$ fit this description, you may output either one.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the following $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the required lengths for $X_k$ and $Y_k$, respectively, for the $k$-th element.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, $T = 100$. For element 1, $p_{1,1} = 70$ and $p_{2,1} = 60$. Because of Axiom 2, the intervals cannot overlap and $X_1$ must strictly precede $Y_1$. This requires a combined span of at least 130 within the domain $[1, 101]$, which only has a length of 100. This is mathematically impossible. Thus, `JOB 1` is printed. 

In Example 2, $T = 150$. For each element $k$, $p_{1,k} = 50$. To satisfy Axioms 1 and 3, four mutually disjoint intervals of length 50 must be placed within the domain $[1, 151]$. This requires a total domain length of 200, which exceeds the available length of 150. Thus, `LOAD 1` is printed.
</STATEMENT>
<RATIONALE>
The scheduling terminology (facilities, processing times, deadlines, items) has been entirely replaced with formal mathematical definitions of half-open intervals and set-theoretic axioms. This breaks the pattern-matching affordance that allowed models to immediately recognise the problem as a "machine load and job duration" check. To succeed, models must now genuinely reason about the geometric implications of interval disjointness and precedence to derive the arithmetic bounds.
</RATIONALE>
<PRESERVED_ANSWER>
The condition for `JOB i` remains exactly $p_{1,i} + p_{2,i} > T$, and the condition for `LOAD c` remains exactly $\sum p_{c,k} > T$, because the geometric constraints on the intervals perfectly map to the original scheduling constraints.
</PRESERVED_ANSWER>

The complexity class is unchanged (INFEASIBLE/linear time verification) because the required checks are still simple arithmetic sums over the input arrays.
