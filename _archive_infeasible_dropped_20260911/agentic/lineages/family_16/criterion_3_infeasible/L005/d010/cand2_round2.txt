# Problem C — Grid Layout Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A software application needs to render a set of $n$ UI widgets on a canvas grid. The canvas provides an available horizontal coordinate window $[1, W+1]$ and is divided into two rows (bottom and top).
Each widget $k \in \{1, 2, \dots, n\}$ consists of two components: a bottom-row element and a top-row element.

A valid layout assigns each element to a half-open horizontal interval $[x_{start}, x_{end})$ such that:
1. **Bounds:** For all widgets $k$, both intervals must be sub-intervals of the available coordinate window $[1, W+1]$.
2. **Dimensions:** For all widgets $k$, the bottom-row interval has length exactly $w_{1,k}$ (i.e., $x_{end} - x_{start} = w_{1,k}$), and the top-row interval has length exactly $w_{2,k}$.
3. **Relative Positioning:** For all widgets $k$, the top-row interval must be positioned entirely at or after the bottom-row interval (specifically, the starting x-coordinate of the top-row interval must be greater than or equal to the ending x-coordinate of the bottom-row interval).
4. **Bottom Row Isolation:** For any two distinct widgets, their bottom-row intervals do not intersect.
5. **Top Row Isolation:** For any two distinct widgets, their top-row intervals do not intersect.

For every given input, it is guaranteed that no valid layout exists. You must provide a short certificate proving this impossibility. Exactly one of the following two structural bottlenecks will apply, and you must output the corresponding certificate:

- `JOB i` (where $i \in \{1, 2, \dots, n\}$): The system of constraints formed by rules 1, 2, and 3 is intrinsically inconsistent when restricted to the single widget $i$. If multiple widgets fit this description, you may output any one of them. (The prefix `JOB` stands for *Joint Object Bounds*).
- `LOAD c` (where $c \in \{1, 2\}$): The system of constraints formed by rules 1, 2, and the isolation rule for row $c$ (rule 4 for the bottom row $c=1$, rule 5 for the top row $c=2$) is intrinsically inconsistent when applied to the entire set of $n$ widgets. If both rows fit this description, you may output either one. (The prefix `LOAD` stands for *Layer Overlap And Dimensions*).

## Input

The first line contains two integers **n** and **W** (1 ≤ n ≤ 200000, 1 ≤ W ≤ 1000000000).
Each of the following **n** lines contains two integers **w1** and **w2** (1 ≤ w1, w2 ≤ 1000000): the width of the bottom-row element and the top-row element for a widget, respectively. Widgets are implicitly numbered 1 to **n**.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, **W** = 100. For widget 1, the domain is $[1, 101]$. The relative positioning constraint forces the top-row interval to be placed at or after the end of the bottom-row interval. Given their lengths of 70 and 60, satisfying this ordering within the allowed domain is mathematically impossible. Thus, `JOB 1` proves the inconsistency.

In Example 2, **W** = 150. The domain is $[1, 151]$. For the bottom row, the isolation constraint requires the bottom-row intervals of widgets 1, 2, 3, and 4 to be mutually disjoint. Since each has a length of 50, no arrangement of these disjoint sub-intervals can exist entirely within a domain of measure 150. Thus, `LOAD 1` proves the inconsistency.
