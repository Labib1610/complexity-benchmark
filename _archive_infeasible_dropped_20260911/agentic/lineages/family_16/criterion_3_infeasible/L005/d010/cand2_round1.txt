<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

Consider a finite universe of integers $U = \{1, 2, \dots, T\}$. 
You are given $j$ specifications. Each specification $k \in \{1, \dots, j\}$ provides two integers $p_{1,k}$ and $p_{2,k}$.

A valid mathematical model must assign to each specification $k$ two sets of integers, $A_k$ and $B_k$, satisfying the following axioms:
1. **Domain:** For all $k$, $A_k \subseteq U$ and $B_k \subseteq U$.
2. **Measure:** For all $k$, the number of elements in $A_k$ is exactly $p_{1,k}$, and the number of elements in $B_k$ is exactly $p_{2,k}$.
3. **Ordering:** For all $k$, $A_k$ is a set of consecutive integers, $B_k$ is a set of consecutive integers, and every integer in $B_k$ is strictly greater than every integer in $A_k$.
4. **Primary Orthogonality:** For any two distinct indices $k \neq m$, $A_k \cap A_m = \emptyset$.
5. **Secondary Orthogonality:** For any two distinct indices $k \neq m$, $B_k \cap B_m = \emptyset$.

For every given input, it is guaranteed that no mathematical model can satisfy all 5 axioms simultaneously. You must provide a short certificate proving this impossibility. Exactly one of the following two structural bottlenecks will apply, and you must output the corresponding certificate:

- `JOB i` (where $i \in \{1, \dots, j\}$): The system of axioms 1, 2, and 3 is intrinsically inconsistent when restricted to the single specification $i$. If multiple specifications fit this description, you may output any one of them.
- `LOAD c` (where $c \in \{1, 2\}$): The system of axioms 1, 2, and the orthogonality axiom corresponding to $c$ (Axiom 4 for $c=1$, covering the $A_k$ sets; Axiom 5 for $c=2$, covering the $B_k$ sets) is intrinsically inconsistent when applied to the entire collection of $j$ specifications. If both $c=1$ and $c=2$ fit this description, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of elements for the sets $A_k$ and $B_k$, respectively. Specifications are implicitly numbered 1 to **j**.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, **T** = 100, so $U = \{1, \dots, 100\}$. For specification 1, $p_{1,1} = 70$ and $p_{2,1} = 60$. Axiom 3 requires $A_1$ and $B_1$ to be sets of consecutive integers where all elements of $B_1$ are strictly greater than all elements of $A_1$. The smallest possible union $A_1 \cup B_1$ satisfying this would span exactly $70 + 60 = 130$ consecutive integers. Axiom 1 requires both sets to be subsets of $U$, which only contains 100 elements. This is mathematically impossible. Thus, `JOB 1` proves the inconsistency.

In Example 2, **T** = 150. For type 1 sets ($A_1, A_2, A_3, A_4$), each must contain 50 elements (Axiom 2) and they must be mutually disjoint (Axiom 4). Their union would require exactly $4 \times 50 = 200$ distinct integers. However, Axiom 1 restricts them to $U$, which only has 150 elements. Thus, `LOAD 1` proves the inconsistency.
</STATEMENT>
<RATIONALE>
Replaced the interval scheduling narrative entirely with an abstract set-theoretic framework. "Jobs" are now "specifications", sequential processing is "set ordering", and isolation is "orthogonality". This forces models to engage with the mathematical axioms to deduce that `JOB i` equates to `p1 + p2 > T` and `LOAD c` equates to `sum(p_c) > T`, rather than relying on standard scheduling keywords.
</RATIONALE>
