<STATEMENT>
# Problem C — Set Assignment Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A combinatorial process must assign integer sets to a collection of items $J = \{1, 2, \dots, j\}$. An assignment gives each item $k \in J$ a primary block $A_k$ and a secondary block $B_k$.

Any valid assignment must satisfy the following constraints:
1. **Domain:** For all $k \in J$, both blocks $A_k$ and $B_k$ must be subsets of the universe $U = \{1, 2, \dots, T\}$ consisting of consecutive integers.
2. **Cardinality:** For all $k \in J$, the number of elements in $A_k$ is exactly $p_{1,k}$ (i.e., $|A_k| = p_{1,k}$), and the number of elements in $B_k$ is exactly $p_{2,k}$.
3. **Element-wise Dominance:** For all $k \in J$, every integer in $B_k$ must be strictly greater than every integer in $A_k$ (specifically, $\min(B_k) > \max(A_k)$).
4. **Primary Isolation:** For any two distinct items $k, m \in J$, their primary blocks do not intersect ($A_k \cap A_m = \emptyset$).
5. **Secondary Isolation:** For any two distinct items $k, m \in J$, their secondary blocks do not intersect ($B_k \cap B_m = \emptyset$).

For every given input, it is guaranteed that no valid assignment exists. You must provide a short certificate proving this impossibility. Exactly one of the following two structural bottlenecks will apply, and you must output the corresponding certificate:

- `JOB i` (where $i \in J$): The system of constraints formed by rules 1, 2, and 3 is intrinsically inconsistent when restricted to the single item $i$. If multiple items fit this description, you may output any one of them.
- `LOAD c` (where $c \in \{1, 2\}$): The system of constraints formed by rules 1, 2, and the isolation rule for block type $c$ (rule 4 for $c=1$, rule 5 for $c=2$) is intrinsically inconsistent when applied to the entire set $J$. If both block types fit this description, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required cardinality of the primary block and the secondary block, respectively. Items are implicitly numbered 1 to **j**.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, **T** = 100. The universe of available integers is $U = \{1, 2, \dots, 100\}$. For item 1, the element-wise dominance constraint requires all integers in $B_1$ to be strictly greater than all integers in $A_1$. Given the required cardinalities of 70 and 60, satisfying this ordering within a universe of 100 elements is mathematically impossible. Thus, `JOB 1` proves the inconsistency.

In Example 2, **T** = 150. The universe is $U = \{1, 2, \dots, 150\}$. For the primary blocks, the isolation constraint requires $A_1, A_2, A_3, A_4$ to be mutually disjoint subsets. Since each requires a cardinality of 50, no arrangement of these disjoint subsets can exist entirely within a universe of 150 elements. Thus, `LOAD 1` proves the inconsistency.

<RATIONALE>
The problem was reframed from a continuous time-interval scheduling scenario to a discrete integer set-assignment problem. By replacing intervals with sets of consecutive integers and sequential flow with element-wise dominance, all semantic clues pointing to "job processing times" and "machine loads" are removed. Models must now independently deduce that `min(B) > max(A)` implies $|A| + |B| \le T$ and that disjoint subsets imply $\sum |A| \le T$, rather than falling back on memorized scheduling heuristics. The exact wording of the exclusive-reason promise and certificate conditions was preserved verbatim from the seed to ensure perfect alignment with the original logic.
</RATIONALE>
