<METHOD_NAME>Set-Theoretic Mapping Formulation</METHOD_NAME>
<METHOD_DESCRIPTION>Transforms the scheduling domain into a formal mathematical mapping of time steps to jobs, defining the impossibility certificates strictly in terms of the non-existence of valid pre-images under specific cardinality and span constraints. This avoids typical scheduling interval keywords that trigger the LLM's heuristic sum-checks.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Problem C — Schedule Diagnostics

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must process a set of jobs $J = \{1, 2, \dots, j\}$. You are analyzing the theoretical feasibility of completing all jobs within a strict deadline. 
A schedule is defined by two machine-state functions, $M_1$ and $M_2$. Each function maps a discrete time step $t$ to either a job $k \in J$ or to $0$ (indicating the machine is idle).

Any valid schedule must satisfy the following constraints:
1. **Domain:** The schedule is restricted to the available time window $\{1, 2, \dots, T\}$. Thus, both $M_1$ and $M_2$ are functions with domain $\{1, 2, \dots, T\}$.
2. **Measure and Span:** For all $k \in J$, the set of time steps assigned to job $k$ on machine 1, denoted by the pre-image $M_1^{-1}(k) = \{t \mid M_1(t) = k\}$, must have a cardinality of exactly $p_{1,k}$, and the difference between its maximum and minimum elements must be exactly $p_{1,k} - 1$. Similarly, $M_2^{-1}(k)$ must have a cardinality of exactly $p_{2,k}$, and the difference between its maximum and minimum elements must be exactly $p_{2,k} - 1$.
3. **Sequential Flow:** For all $k \in J$, every time step in $M_2^{-1}(k)$ must be strictly greater than every time step in $M_1^{-1}(k)$.
4. **Machine 1 Isolation:** By the mathematical definition of a function, $M_1$ maps each time step to at most one job. Consequently, for any two distinct jobs $k, m \in J$, their pre-images are disjoint ($M_1^{-1}(k) \cap M_1^{-1}(m) = \emptyset$).
5. **Machine 2 Isolation:** By the mathematical definition of a function, $M_2$ maps each time step to at most one job. Consequently, for any two distinct jobs $k, m \in J$, their pre-images are disjoint ($M_2^{-1}(k) \cap M_2^{-1}(m) = \emptyset$).

For every given input, it is guaranteed that no valid schedule exists. You must provide a short certificate proving this impossibility. Exactly one of the following two structural bottlenecks will apply, and you must output the corresponding certificate:

- `JOB i` (where $i \in J$): The system of constraints formed by rules 1, 2, and 3 is intrinsically inconsistent when restricted to the single job $i$. If multiple jobs fit this description, you may output any one of them.
- `LOAD c` (where $c \in \{1, 2\}$): The system of constraints formed by rules 1, 2, and the isolation rule for machine $c$ (rule 4 for $c=1$, rule 5 for $c=2$) is intrinsically inconsistent when applied to the entire set $J$. If both machines fit this description, you may output either one.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required cardinality of the pre-images for a job on machine 1 and machine 2, respectively. Jobs are implicitly numbered 1 to **j**.

## Output

Print a single line containing the certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, **T** = 100. For job 1, the domain restricts assigned time steps to $\{1, \dots, 100\}$. Rule 2 requires $M_1^{-1}(1)$ to be a set of 70 integers with a span of 69 (implying 70 consecutive integers) and $M_2^{-1}(1)$ to be a set of 60 integers with a span of 59. The sequential flow constraint requires all 60 integers in $M_2^{-1}(1)$ to be strictly greater than all 70 integers in $M_1^{-1}(1)$. Satisfying this ordering within a domain of 100 elements is mathematically impossible. Thus, `JOB 1` proves the inconsistency.

In Example 2, **T** = 150. The domain restricts assigned time steps to $\{1, \dots, 150\}$. For machine 1, rule 2 requires $M_1^{-1}(1), M_1^{-1}(2), M_1^{-1}(3), M_1^{-1}(4)$ to each be sets of 50 integers (each spanning 49, thus consecutive). Rule 4 requires these four sets to be mutually disjoint. No arrangement of four disjoint sets of size 50 can exist entirely within a domain of 150 elements. Thus, `LOAD 1` proves the inconsistency.
</STATEMENT>
<RATIONALE>
I replaced the standard scheduling interval formulation with a formal set-theoretic mapping definition. Instead of jobs having "start" and "completion" times, the schedule is defined by machine-state functions, and constraints are enforced on the pre-images of these functions (using cardinality and span to enforce contiguity). This forces the model to mathematically prove that the pre-image constraints imply the standard interval bounds, breaking simple heuristic pattern-matching of scheduling keywords.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement for a pre-image to have cardinality $p$ and span $p-1$ is mathematically identical to a contiguous block of length $p$; the strict inequality between pre-images is identical to sequential precedence, meaning the impossibility conditions ($p_1+p_2 > T$ and $\sum p_c > T$) remain exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still asks for a certificate of impossibility which requires checking simple sum inequalities in a single pass, keeping it in the same $O(N)$ infeasibility-checking class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "span" or "difference between maximum and minimum elements" if $p=1$, though mathematically $0 = 1-1$ is perfectly well-defined and handled correctly by the definitions.
</RISK>
