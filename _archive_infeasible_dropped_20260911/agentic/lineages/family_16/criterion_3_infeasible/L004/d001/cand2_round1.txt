<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory processes **j** jobs through exactly **two** machines. Every job is processed on machine 1 first and then on machine 2. For each job you are given its processing time on machine 1 and on machine 2. Each machine processes only one job at a time, and a job reaches machine 2 only after finishing on machine 1.

There is a required deadline **T**: every job must be completely finished by time **T**. 

For the inputs in this problem, no valid schedule exists to meet the deadline. You must output a short certificate proving the deadline is impossible. The proof must rely on the fundamental constraints of the system, ignoring complex interactions. You must output one of the following certificates:

- `JOB i` (where **i** is a 1-based job index): This certificate proves that the inherent sequential requirements of job **i** alone make it impossible to finish by **T**, even if it were the only job in the factory.
- `LOAD c` (where **c** is 1 or 2): This certificate proves that the total processing duration required by machine **c** guarantees it cannot complete its operations by **T**, even if the other machine operated instantaneously.

Exactly one such certificate will be valid for each test case, and you should print the one that holds.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2.

## Output

Print a single line containing the valid certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is the valid certificate because its own sequential requirements cannot be met within the deadline. In Example 2, no single job violates the deadline in isolation, but `LOAD 1` is the valid certificate because the first machine cannot complete its assigned volume of work within the deadline.
</STATEMENT>
<RATIONALE>
Removed the explicit formulas (`p1 + p2 > T` and `sum > T`) from the certificate descriptions and the example notes. The problem now describes the physical meaning of the certificates (a job failing in isolation, or a machine failing even if the other is instantaneous), forcing the model to deduce the corresponding arithmetic checks from the scheduling constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for the certificates are mathematically identical to the original; a job failing in isolation means its sequential times sum to more than T, and a machine failing in isolation means its total processing time across all jobs exceeds T.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity remains O(N) since the same linear scans and sums are required to check the two impossibility conditions.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "total processing duration required by machine c" as something other than the sum of all jobs' times on that machine, though the phrase "even if the other machine operated instantaneously" strongly implies the standard sum.
</RISK>
