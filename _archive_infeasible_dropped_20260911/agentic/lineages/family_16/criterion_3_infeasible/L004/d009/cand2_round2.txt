<STATEMENT>
# Problem C — Impossible Set Selection: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are given **j** jobs. For each job $k$ (where $k$ is a 1-based index from 1 to **j**), you must construct two sets of integers: $S_{1,k}$ (representing configuration 1) and $S_{2,k}$ (representing configuration 2). 

The number of elements in $S_{1,k}$ must exactly equal **p1**.
The number of elements in $S_{2,k}$ must exactly equal **p2**.

A valid construction must satisfy three rules:

- **Rule 1 (Domain Boundary):** Every integer in every set must be chosen from the exact range $1$ through $\mathbf{T}$ inclusive. In other words, $S_{1,k} \subseteq \{1, 2, \dots, \mathbf{T}\}$ and $S_{2,k} \subseteq \{1, 2, \dots, \mathbf{T}\}$ for all jobs $k$.
- **Rule 2 (Inter-Job Disjointness):** For a given configuration type $c \in \{1, 2\}$, no two jobs can share any integer in their sets. That is, for any two distinct jobs $x$ and $y$, the intersection of $S_{c,x}$ and $S_{c,y}$ must be empty.
- **Rule 3 (Internal Topology):** For every job $k$, the elements of $S_{1,k}$ and $S_{2,k}$ must satisfy a strict spacing requirement. If we arrange all elements of $S_{1,k}$ in ascending order, every element (except the last) must be exactly 1 less than the element immediately following it. The same must be true for the elements of $S_{2,k}$ when arranged in ascending order. Finally, the smallest element of $S_{2,k}$ must be exactly 1 greater than the largest element of $S_{1,k}$.

For all test cases provided in this problem, it is guaranteed that no valid construction can satisfy all three rules simultaneously. Your task is to certify this impossibility by identifying a localized contradiction. At least one of the following two types of certificates is guaranteed to be valid for the given input; print any one valid certificate. If multiple certificates are valid, any of them is accepted.

- **Job-specific contradiction:** There is a job **i** (1-based index) such that Rule 1 and Rule 3 cannot be simultaneously satisfied for job **i**, even if we completely ignore Rule 2 and all other jobs. Print `JOB i` for any such valid index **i**.
- **Configuration-specific contradiction:** There is a configuration type **c** (where **c** is 1 or 2) such that Rule 1 and Rule 2 cannot be simultaneously satisfied for configuration **c**, even if we completely ignore Rule 3 and the other configuration type. Print `LOAD c` for any such valid configuration **c**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required sizes of $S_{1,k}$ and $S_{2,k}$ respectively.

## Output

Print a single line containing any valid certificate of impossibility: either `JOB i` (where i is the job index) or `LOAD c` (where c is the configuration type). If multiple certificates are valid, any of them is accepted.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, consider job 1. The required sizes dictate that $|S_{1,1}| = 70$ and $|S_{2,1}| = 60$. By Rule 3, the elements of $S_{1,1}$ must have adjacent differences of exactly 1, meaning they span a sequence of 70 integers. Similarly, $S_{2,1}$ must span a sequence of 60 integers. Because the smallest element of $S_{2,1}$ is exactly 1 greater than the largest element of $S_{1,1}$, the combined span of both sets must cover exactly $70 + 60 = 130$ distinct integers. However, Rule 1 restricts all integers to the boundary $1$ through $100$, which can only accommodate at most 100 integers. Thus, Rule 1 and Rule 3 cannot be simultaneously satisfied for job 1. `JOB 1` is a valid certificate.

In Example 2, no single job violates the rules on its own. However, consider configuration type 1. Rule 2 requires the four $S_{1,k}$ sets (each of size 50) to be mutually disjoint across all jobs. This requires a total of $4 \times 50 = 200$ distinct integers. Since Rule 1 restricts all sets to the boundary $1$ through $150$, it is impossible to find 200 distinct integers. Thus, Rule 1 and Rule 2 cannot be simultaneously satisfied for configuration type 1, making `LOAD 1` a valid certificate.
</STATEMENT>
<RATIONALE>
The contiguity requirement (Rule 3) was rewritten from a global property ("the union forms a single contiguous block") to a set of local spacing constraints ("every element except the last must be exactly 1 less than the element following it"). This forces the model to logically reconstruct the total span of the sets to realize it equals `p1 + p2`, breaking simple keyword pattern matching. Additionally, the acceptance of any valid certificate is explicitly stated to resolve previous strictness issues.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical implications of the local spacing rules are identical to the original contiguous block requirement, meaning the exact same contradictions (`p1 + p2 > T` or `sum(p1) > T` or `sum(p2) > T`) apply and the output remains unchanged.
</PRESERVED_ANSWER>

</PRESERVED_CLASS>
