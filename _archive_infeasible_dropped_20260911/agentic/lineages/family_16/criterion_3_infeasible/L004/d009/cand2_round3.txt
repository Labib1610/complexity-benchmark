<STATEMENT>
# Validation of Assignment Constraints

Time limit: 2 s   Memory limit: 256 MB

## Description

You are processing a schedule for **j** vehicles. For each vehicle $k$ (where $k$ is a 1-based index from 1 to **j**), you must assign two separate groups of integer IDs: one group for the primer phase, and one group for the finish phase.

The required amount of IDs for vehicle $k$'s primer phase is given as the first integer on its input line (let's call this $u$).
The required amount of IDs for vehicle $k$'s finish phase is given as the second integer on its input line (let's call this $v$).

A valid assignment must adhere to three rules:

- **Rule 1 (Domain):** Every assigned ID, across all vehicles and phases, must be an integer from $1$ up to **T** inclusive.
- **Rule 2 (Uniqueness):** Consider the primer phase across all vehicles. No two vehicles may share any primer IDs. The same uniqueness applies to the finish phase: no two vehicles may share any finish IDs. (However, a primer ID and a finish ID may be the same, as they belong to different phases).
- **Rule 3 (Contiguity):** For any single vehicle $k$, let $min\_P$ be its numerically smallest primer ID and $max\_F$ be its numerically largest finish ID. It is strictly required that $max\_F - min\_P$ exactly equals $u + v - 1$. Furthermore, every integer from $min\_P$ to $max\_F$ inclusive must be assigned to vehicle $k$'s primer or finish group, with all primer IDs being strictly smaller than all finish IDs.

For all test cases provided in this problem, it is guaranteed that no valid assignment can satisfy all three rules simultaneously. Your task is to identify the localized reason for this failure. Exactly one of the following two failure reasons will apply to the given input. Print the one that applies:

- **Single-vehicle contradiction:** There exists a single vehicle **i** (1-based index) such that Rule 1 and Rule 3 cannot be simultaneously satisfied for this vehicle alone, even if we completely ignore Rule 2 and all other vehicles. Print: `JOB i`.
- **Phase-wide contradiction:** There exists a single phase **c** (1 for primer, 2 for finish) such that Rule 1 and Rule 2 cannot be simultaneously satisfied for this phase, even if we completely ignore Rule 3 and the other phase. Print: `LOAD c`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers: the required amount of primer IDs ($u$) and the required amount of finish IDs ($v$) for that vehicle. (1 ≤ u, v ≤ 1000000).

## Output

Print a single line containing the exact certificate of impossibility: either `JOB i` (where i is the vehicle index) or `LOAD c` (where c is 1 or 2).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, consider vehicle 1. It needs 70 primer IDs and 60 finish IDs. By Rule 3, the difference between its largest finish ID and its smallest primer ID must be exactly $70 + 60 - 1 = 129$. Because Rule 1 restricts all IDs to the range from 1 to 100, the maximum possible difference between any two valid IDs is 99. Since 129 is strictly greater than 99, Rule 1 and Rule 3 cannot be simultaneously satisfied for vehicle 1. `JOB 1` is the correct certificate.

In Example 2, no single vehicle violates the rules on its own. However, consider the primer phase (phase 1). Rule 2 requires all four vehicles (each needing 50 primer IDs) to use completely unique IDs for this phase. This requires a total of 200 distinct IDs. Since Rule 1 restricts all IDs to the range from 1 to 150, there are not enough valid IDs available. Thus, Rule 1 and Rule 2 cannot be simultaneously satisfied for the primer phase, making `LOAD 1` the correct certificate.
</STATEMENT>
<RATIONALE>
I replaced the explicit contiguous block sizes with a mathematical constraint on the distance between the maximum and minimum IDs ($max\_F - min\_P = u + v - 1$). This forces models to deduce the maximum possible difference within the domain ($T - 1$) rather than blindly summing the inputs and comparing to $T$. I also removed all complexity-class vocabulary (such as "cover", "universe", and "set selection") to comply with the gate's rejection.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical condition $u + v - 1 > T - 1$ is strictly equivalent to $u + v > T$, ensuring that the exact same inputs trigger a `JOB i` certificate, and the exact same aggregate totals trigger a `LOAD c` certificate.
</PRESERVED_ANSWER>

The problem remains an infeasibility certification task solvable in O(N) time by checking the exact same per-job sums and aggregate phase sums.
</PRESERVED_CLASS>
