<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A data center is tasked with processing a batch of **j** large datasets. The processing pipeline consists of two stages: extraction (Stage 1) and transformation (Stage 2). For each dataset $k$ (where $k$ is a 1-based index from 1 to **j**), extraction takes exactly $p_{1,k}$ seconds and transformation takes exactly $p_{2,k}$ seconds.

The data center operates strictly from time $0$ to time $\mathbf{T}$ seconds, after which it shuts down for maintenance. During this operational window, all processing must be completed. A dataset's transformation can only begin after its extraction is fully finished. Furthermore, the extraction server can process only one dataset at a time, and the transformation server can process only one dataset at a time.

For all test cases provided in this problem, it is guaranteed that the data center cannot successfully process all **j** datasets before the shutdown. System administrators have determined that the failure is always caused by one of two isolated fundamental bottlenecks. Exactly one of the following will be true, and your task is to output the corresponding diagnostic message:

- **Sequential bottleneck:** A specific dataset **i** would still be processing after the shutdown even if its extraction began exactly at time $0$ and its transformation followed immediately without interruption. When this occurs, output `JOB i`.
- **Throughput bottleneck:** A specific server **c** (1 for the extraction server, 2 for the transformation server) would still be operating after the shutdown even if it were kept constantly busy from time $0$ onwards processing its stage for the entire batch. When this occurs, output `LOAD c`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of a dataset on the extraction server and the transformation server, respectively.

## Output

Print a single line containing the correct diagnostic message: either `JOB i` (where i is the dataset index) or `LOAD c` (where c is the server number).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, consider dataset 1. Even if its extraction started exactly at time 0 and its transformation followed immediately without delay, the dataset would still be processing after the 100-second operational window closes. Thus, `JOB 1` is the correct message. 

In Example 2, no single dataset is too long to process on its own. However, consider the extraction server. Even if it were kept constantly busy from time 0 onwards, it would still be operating after the 150-second operational window closes because of the volume of extraction tasks it must complete. Thus, `LOAD 1` is the correct message.
</STATEMENT>
<RATIONALE>
I removed the explicit formal rules (Resource Isolation, Precedence, Deadline) and explicit mathematical contradiction conditions ("Rule 2 and Rule 3 cannot be simultaneously satisfied"). Instead, the impossibility certificates are defined by describing a hypothetical ideal timeline: an entity (a dataset or a server) would still be operating after the shutdown at time T even if it started at time 0 and ran continuously. This forces the model to deduce the mathematical bounds ($p_1+p_2 > T$ and $\sum p_c > T$) from the physical timeline description rather than pattern-matching explicit constraint formulas.
</RATIONALE>
<PRESERVED_ANSWER>
The logical conditions for the certificates are mathematically equivalent to the original problem: a dataset failing under ideal sequential processing means $p_1+p_2 > T$, and a server failing under ideal continuous processing means $\sum p > T$, ensuring all outputs remain identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains solvable in $O(N)$ time by iterating through the datasets to check $p_1+p_2 > T$ and accumulating the sums of $p_1$ and $p_2$ to check against $T$.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "constantly busy from time 0 onwards processing its stage for the entire batch" as implying the server can process them in parallel, though the preceding text explicitly states "the extraction server can process only one dataset at a time".
</RISK>
