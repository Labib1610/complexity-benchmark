# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders using two specialized workstations. Each order must first be processed at workstation 1 and subsequently at workstation 2. Each workstation can handle only one order at a time, and an order cannot begin at workstation 2 until its processing at workstation 1 is complete. For each order, you are given its required processing time at workstation 1 and workstation 2.

All orders must be fully completed by a strict deadline **T**. 

For all test cases provided in this problem, it is guaranteed that meeting the deadline **T** is impossible regardless of the schedule. Your job is not to search for a schedule; it is to prove impossibility by providing a short certificate checkable from the input. It is guaranteed that exactly one of the following two categories of impossibility will apply. Find and print any valid certificate of the applicable category:

- **Sequential path bottleneck:** A single order's end-to-end processing timeline strictly exceeds the deadline on its own. Because it must be processed at workstation 1 and then workstation 2, the combined duration of these two steps strictly exceeds **T**. Output `JOB i`, where `i` is the 1-based index of any order that independently violates the deadline.
- **Cumulative volume bottleneck:** A single workstation is assigned an aggregate processing workload that strictly exceeds the deadline. Since a workstation processes one order at a time, the sum of its required processing times across all orders strictly exceeds **T**. Output `LOAD c`, where `c` is the workstation number (1 or 2) that is over-allocated.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers: the processing times of an order on workstation 1 and workstation 2 respectively. Both times are between 1 and 1000000, inclusive.

## Output

Print a single line containing the certificate of impossibility: either `JOB i` (where i is the order index) or `LOAD c` (where c is the workstation number). If multiple valid certificates of the applicable category exist, any one is acceptable.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, even if the facility only had to process the first order, it would still fail to meet the 100-unit deadline because of the time it must spend sequentially across the two workstations (70 then 60, total 130). Thus, `JOB 1` proves the deadline is impossible. In Example 2, no single order violates the deadline on its own, but the first workstation is required to operate for a combined 200 time units overall. Since it processes tasks one at a time, it cannot finish within the 150-unit deadline, making `LOAD 1` the valid certificate.
