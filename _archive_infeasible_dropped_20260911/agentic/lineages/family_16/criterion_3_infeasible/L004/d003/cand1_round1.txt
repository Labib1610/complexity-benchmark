<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders using two specialized workstations. Each order must first be processed at workstation 1 and subsequently at workstation 2. Each workstation can handle only one order at a time, and an order cannot begin at workstation 2 until its processing at workstation 1 is complete. For each order, you are given its required processing time at workstation 1 ($p1$) and workstation 2 ($p2$).

All orders must be fully completed by a strict deadline **T**. 

For all test cases provided in this problem, it is guaranteed that meeting the deadline **T** is impossible regardless of the processing sequence. Your job is not to search for a schedule; it is to prove impossibility with a short certificate checkable from the input. To do this, you must identify the single entity whose fundamental mechanical requirement independently violates the deadline, even under idealized conditions. 

Specifically, you must determine if an order's unbroken sequential processing path exceeds the time limit (output `JOB i` where **i** is the 1-based order index), or if a specific workstation's aggregate processing volume across the entire batch exceeds the time limit (output `LOAD c` where **c** is the workstation number). It is guaranteed that exactly one such entity will strictly exceed **T**. Print the identifier of this entity.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of an order on workstation 1 and workstation 2.

## Output

Print a single line containing the certificate of impossibility: either `JOB i` (where i is the order index) or `LOAD c` (where c is the workstation number).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, even if the facility only had to process the first order, its sequential processing path requires 70 units on workstation 1 followed immediately by 60 units on workstation 2, totaling 130 units. This exceeds the 100-unit deadline, so `JOB 1` is the valid certificate. In Example 2, no single order violates the deadline on its own. However, workstation 1 has an aggregate processing volume of 200 units across the four orders. Since it processes tasks one at a time, its required active time alone exceeds the 150-unit deadline, making `LOAD 1` the valid certificate.
