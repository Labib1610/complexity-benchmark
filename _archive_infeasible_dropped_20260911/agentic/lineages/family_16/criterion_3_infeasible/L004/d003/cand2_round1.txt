# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders using two specialized workstations. Each order must first be processed at workstation 1 and subsequently at workstation 2. Each workstation can handle only one order at a time, and an order cannot begin at workstation 2 until its processing at workstation 1 is complete. For each order, you are given its required processing time at workstation 1 and workstation 2.

All orders must be fully completed by a strict deadline **T**. 

For all test cases provided in this problem, it is guaranteed that meeting the deadline **T** is impossible regardless of the processing sequence. Your job is not to search for a schedule; it is to prove impossibility with a short certificate. You must output a valid certificate that demonstrates this impossibility based on the physical constraints of the facility. A valid certificate takes one of two forms:

- `JOB i` (where **i** is the 1-based index of an order): This certifies that the uninterrupted sequential duration required to process this specific order across the two workstations strictly exceeds the deadline, making it impossible on its own.
- `LOAD c` (where **c** is the workstation number, 1 or 2): This certifies that the cumulative active time required by workstation **c** to complete its assigned phase for every order strictly exceeds the deadline, making it impossible for that workstation to finish in time even if it never sits idle.

It is guaranteed that exactly one valid certificate exists for each test case. Print the correct certificate.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers (1 ≤ p1, p2 ≤ 1000000): the processing times of an order on workstation 1 and workstation 2, respectively.

## Output

Print a single line containing the unique valid certificate of impossibility: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, even if the facility only had to process the first order, it would still fail to meet the 100-unit deadline because of the sequential time it must spend across the two workstations (70 then 60, totaling 130). Thus, `JOB 1` proves the deadline is impossible. 

In Example 2, no single order violates the deadline on its own, but the first workstation is required to operate for a combined 200 time units overall. Since it processes tasks one at a time, it cannot finish within the 150-unit deadline, making `LOAD 1` the valid certificate.

<RATIONALE>
Removed the explicit mathematical inequalities (`p1_i + p2_i > T` and sums `> T`) that allowed models to directly map text to conditional statements. Replaced them with operational descriptions ("uninterrupted sequential duration", "cumulative active time") that force models to deduce the underlying arithmetic from the physical constraints of the scenario.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for outputting `JOB i` or `LOAD c` are mathematically identical to the seed problem, just described through their physical meaning rather than algebraic formulas.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an $O(N)$ impossibility certification task, requiring only a single pass to check each job's sequential duration and accumulate the two workstations' total loads.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "uninterrupted sequential duration" as requiring them to consider idle time between the two processing steps, though the phrase "on its own" clarifies that this is the minimum possible time for a single isolated job.
</RISK>
