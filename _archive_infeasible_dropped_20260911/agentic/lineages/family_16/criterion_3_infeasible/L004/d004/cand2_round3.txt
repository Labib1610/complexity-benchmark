<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders using two specialized workstations. Each order must first be processed at workstation 1 and subsequently at workstation 2. Each workstation can handle only one order at a time, and an order cannot begin at workstation 2 until its processing at workstation 1 is complete. For each order, you are given its required processing time at workstation 1 ($p1$) and workstation 2 ($p2$).

All orders must be completely finished by time **T**. 

For all test cases provided in this problem, it is guaranteed that finishing all orders by time **T** is impossible regardless of the processing sequence. Your job is not to search for a schedule; it is to identify the isolated bottleneck that proves the deadline cannot be met. 

To provide a short, checkable certificate of impossibility, you must consider three hypothetical relaxations of the facility's constraints. The input guarantees that in exactly one of these relaxations, meeting the deadline **T** remains impossible. You must output the certificate corresponding to that unique relaxation:

- **Relaxation A (Single-Order Isolation):** Assume all orders except a specific order **i** (1-based index) are cancelled. The facility only needs to process order **i** through workstation 1 and then workstation 2. If this relaxed scenario cannot be completed by time **T**, the sequential requirement of order **i** is the bottleneck. Output: `JOB i`.
- **Relaxation B (Workstation 1 Isolation):** Assume workstation 1 must process its phase for all **j** orders one at a time, but order precedence and workstation 2 are entirely ignored. If this relaxed scenario cannot be completed by time **T**, workstation 1 is the bottleneck. Output: `LOAD 1`.
- **Relaxation C (Workstation 2 Isolation):** Assume workstation 2 must process its phase for all **j** orders one at a time, but order precedence and workstation 1 are entirely ignored. If this relaxed scenario cannot be completed by time **T**, workstation 2 is the bottleneck. Output: `LOAD 2`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of an order on workstation 1 and workstation 2.

## Output

Print a single line containing the certificate of impossibility: either `JOB i` (where i is the order index) or `LOAD c` (where c is the workstation number).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under **Relaxation A** for order 1, the facility only processes this single order. It must spend 70 time units on workstation 1 followed by 60 time units on workstation 2, requiring 130 time units. Since 130 strictly exceeds the deadline of 100, this relaxation is impossible, yielding `JOB 1`. (Relaxations B and C would require only 75 and 66 time units respectively, both of which are within the deadline).

In Example 2, under **Relaxation B**, workstation 1 must process its phase for all four orders. Since it can only handle one at a time, it must be active for a combined 200 time units. This exceeds the deadline of 150, making this relaxation impossible and yielding `LOAD 1`. No single order violates the deadline in isolation, and workstation 2 only needs 4 time units, so only Relaxation B fails.

<RATIONALE>
The direct numeric predicates (sum of p1/p2 or p1+p2) were replaced with the infeasibility of isolated, relaxed scheduling scenarios. To solve the problem, models can no longer pattern-match on phrases like "sequential duration" or "total processing volume"; they must analytically deduce the minimum makespan for each relaxation (which evaluates to exactly the seed's required lower bounds) and verify which one exceeds T. This addresses the expert's feedback by ensuring the cases are distinct hypothetical scenarios rather than overlapping constraint subsets of the full problem.
</RATIONALE>
<PRESERVED_ANSWER>
The minimum time to complete Relaxation A is exactly p1_i + p2_i; Relaxation B is exactly the sum of all p1; and Relaxation C is exactly the sum of all p2, meaning the same numeric conditions trigger the exact same outputs as the seed.
</PRESERVED_ANSWER>
