# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders using two specialized workstations. Each order must first be processed at workstation 1 and subsequently at workstation 2. Each workstation can handle only one order at a time, and an order cannot begin at workstation 2 until its processing at workstation 1 is complete. For each order, you are given its required processing time at workstation 1 ($p1$) and workstation 2 ($p2$).

All orders must be completely finished by time **T**. 

For all test cases provided in this problem, it is guaranteed that finishing by time **T** is impossible regardless of the processing sequence. Your job is not to search for a schedule; it is to prove impossibility with a short certificate checkable from the input. 

By isolating specific constraints, we can establish theoretical lower bounds on the total completion time. Consider the following isolated scenarios:
- **Isolated Order:** The facility processes only a single order **i**, ignoring all other orders.
- **Isolated Workstation 1:** Workstation 1 processes its required stages for all orders. (Recall it can handle only one order at a time). We assume workstation 2 takes zero time and all orders are instantly available.
- **Isolated Workstation 2:** Workstation 2 processes its required stages for all orders. (Recall it can handle only one order at a time). We assume workstation 1 takes zero time and all orders are instantly available.

The input guarantees that the minimum time required by at least one of these isolated scenarios strictly exceeds the deadline **T**. You must output a certificate identifying a scenario that fails to meet **T**:
- If the Isolated Order scenario for a specific order **i** (1-based index) requires a minimum time that strictly exceeds **T**, output `JOB i`.
- If the Isolated Workstation 1 scenario requires a minimum time that strictly exceeds **T**, output `LOAD 1`.
- If the Isolated Workstation 2 scenario requires a minimum time that strictly exceeds **T**, output `LOAD 2`.

If multiple scenarios or multiple orders exceed **T**, you may output any valid certificate.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of an order on workstation 1 and workstation 2.

## Output

Print a single line containing the certificate of impossibility: either `JOB i` (where i is the order index) or `LOAD c` (where c is the workstation number).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under the Isolated Order scenario for the first order, the facility must spend time sequentially across the two workstations (70 then 60, minimum time 130). This strictly exceeds the deadline of 100. Thus, `JOB 1` proves it is impossible. 

In Example 2, no single Isolated Order violates the time limit. However, under the Isolated Workstation 1 scenario, the first workstation is required to operate for a combined 200 time units. Since it processes orders one at a time, its minimum time is 200, which strictly exceeds the deadline of 150, making `LOAD 1` a valid certificate.
