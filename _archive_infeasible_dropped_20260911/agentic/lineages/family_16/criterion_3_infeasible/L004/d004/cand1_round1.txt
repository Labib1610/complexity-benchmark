# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders using two specialized workstations. For each order, you are given its required continuous processing time at workstation 1 ($p1$) and workstation 2 ($p2$).

A schedule assigns start times $S_{1,k}$ and $S_{2,k}$ for each order $k$ (1-indexed) such that:
1. $S_{1,k} \ge 0$ and $S_{2,k} \ge 0$.
2. $S_{2,k} \ge S_{1,k} + p_{1,k}$.
3. For any two distinct orders $x$ and $y$, their processing intervals on workstation 1, $[S_{1,x}, S_{1,x} + p_{1,x})$, do not intersect. The same applies to their intervals on workstation 2, $[S_{2,x}, S_{2,x} + p_{2,x})$.

A schedule successfully meets the deadline if all processing is completed by time **T**. Specifically:
- An order $k$ meets the deadline if $S_{1,k} + p_{1,k} \le T$ and $S_{2,k} + p_{2,k} \le T$.
- A workstation $c$ meets the deadline if $S_{c,k} + p_{c,k} \le T$ for all orders $k$.

For all test cases provided in this problem, it is guaranteed that no valid schedule can meet the deadline **T**. Your job is not to search for a schedule, but to prove this impossibility by identifying a minimal structural bottleneck. Exactly one of the following two types of bottleneck will be valid for the given input. Print the one that holds:

- An isolation witness: A single order **i** (1-based index) such that no schedule could meet the deadline for order **i**, even if the facility only had to process order **i** (ignoring all other orders). Print: `JOB i`.
- A relaxation witness: A single workstation **c** (where **c** is 1 or 2) such that no schedule could meet the deadline on workstation **c**, even if we completely dropped condition (2) for all orders. Print: `LOAD c`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of an order on workstation 1 and workstation 2.

## Output

Print a single line containing the certificate of impossibility: either `JOB i` (where i is the order index) or `LOAD c` (where c is the workstation number).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, even if the facility only had to process the first order, it would still fail to finish by time 100. The earliest possible start time on workstation 2 is constrained by the completion on workstation 1, pushing the final completion beyond the deadline. Thus, `JOB 1` is the valid isolation witness. 

In Example 2, no single order violates the time limit on its own. However, if we drop condition 2, workstation 1 still needs to process 4 orders of length 50 without intersecting intervals (condition 3). Since they cannot overlap, they cannot all be completed by time 150. Thus, `LOAD 1` is the valid relaxation witness.

<RATIONALE>
I removed the explicit wording that described the certificates as "sequential duration" and "total processing volume". Instead, I formalized the scheduling constraints mathematically and defined the certificates as specific relaxations of these constraints (ignoring other jobs vs ignoring the precedence constraint). This forces the model to mathematically derive that the isolation witness corresponds to `p1+p2 > T` and the relaxation witness corresponds to `sum(p) > T`.
</RATIONALE>

The isolation witness is valid if and only if p1+p2 > T, and the relaxation witness is valid if and only if the sum of processing times on a workstation exceeds T, which perfectly matches the original conditions.
</PRESERVED_ANSWER>
