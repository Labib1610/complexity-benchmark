**Solution Explanation**

For a single job `k`

* `|V_{k,1}| = p1_k`, `|V_{k,2}| = p2_k`
* All vertices of `V_{k,1}` must be smaller than all vertices of `V_{k,2}`.
* The induced subgraph of `V_{k,1} ∪ V_{k,2}` has to be connected.
  In a path graph a connected vertex set is a contiguous interval.
  Because the two loads are ordered, the interval consists of the
  `p1_k` leftmost vertices followed by the `p2_k` rightmost vertices,
  therefore it contains exactly `p1_k + p2_k` distinct vertices.

Hence **Constraint 1** (the host graph has exactly `T` vertices) and
**Constraint 3** can be satisfied for job `k` **iff**

```
p1_k + p2_k ≤ T
```

If for some job this inequality is violated, the whole instance is
impossible already for that job – we must output `JOB k`.

---

For a fixed load type (1 or 2) the sets of that load must be pairwise
disjoint (**Constraint 2**).  
Thus the total number of vertices needed for that load is the sum of the
required sizes:

```
total1 = Σ p1_k   (over all jobs)
total2 = Σ p2_k
```

These vertices must all lie inside the host graph of size `T`, therefore
the load can be feasible only if the corresponding total does not exceed
`T`.

If no single job already contradicts the constraints, the instance is
still impossible because one of the loads needs more vertices than the
host graph provides. The problem guarantees that exactly one of the two
certificate types is valid, so after the job check we can safely output
the load whose total exceeds `T`.

The algorithm is therefore:

```
read j, T
total1 = total2 = 0
for i = 1 .. j
        read p1, p2
        total1 += p1
        total2 += p2
        if p1 + p2 > T:
                print "JOB i" and exit
# no violating job
if total1 > T:   print "LOAD 1"
else:            print "LOAD 2"
```

`j ≤ 2·10⁵`, all operations are O(j) time and O(1) extra memory.

---

**Correctness Proof**

We prove that the algorithm always prints a correct certificate.

*Lemma 1*  
For any job `k` there exists a selection of `V_{k,1}, V_{k,2}` satisfying
Constraints 1 and 3 **iff** `p1_k + p2_k ≤ T`.

*Proof.*  
If `p1_k + p2_k ≤ T`, choose the interval `[1, p1_k + p2_k]` of the host
path. Let the first `p1_k` vertices be `V_{k,1}` and the remaining
`p2_k` vertices be `V_{k,2}`. The interval is connected, all vertices of
`V_{k,1}` are smaller than those of `V_{k,2}`, and it uses only vertices
inside the host graph of size `T`. Hence Constraints 1 and 3 hold.

Conversely, suppose a feasible selection exists.
Because the induced subgraph on `V_{k,1} ∪ V_{k,2}` is connected in a
path, it must be a contiguous interval of vertices.
All vertices of `V_{k,1}` are smaller than all vertices of `V_{k,2}`,
therefore the interval contains exactly `|V_{k,1}| + |V_{k,2}| =
p1_k + p2_k` distinct vertices.
All these vertices belong to the host graph of size `T`, so
`p1_k + p2_k ≤ T`. ∎



*Lemma 2*  
For a fixed load type `c ∈ {1,2}` there exists a selection of all
`V_{k,c}` satisfying Constraints 1 and 2 **iff**
`total_c = Σ_k p_{k,c} ≤ T`.

*Proof.*  
If `total_c ≤ T`, place the required sets consecutively along the path,
e.g. the first job uses vertices `1..p_{1,c}`, the second uses the next
`p_{2,c}` vertices, and so on. They are disjoint and lie inside the host
graph, satisfying Constraints 1 and 2.

If a feasible selection exists, the sets are pairwise disjoint, thus
contain `total_c` distinct vertices of the host graph, which has only
`T` vertices. Hence `total_c ≤ T`. ∎



*Lemma 3*  
If the algorithm prints `JOB i`, then the instance indeed cannot satisfy
all three constraints.

*Proof.*  
The algorithm prints `JOB i` only when `p1_i + p2_i > T`. By Lemma 1,
Constraints 1 and 3 are already impossible for job `i`, regardless of any
other jobs or of Constraint 2. Therefore the whole instance is impossible. ∎



*Lemma 4*  
If the algorithm prints `LOAD c`, then the instance indeed cannot satisfy
all three constraints.

*Proof.*  
The algorithm reaches this branch only after confirming that for every
job `k`, `p1_k + p2_k ≤ T`; thus by Lemma 1 each individual job can meet
Constraints 1 and 3.  
It then prints `LOAD c` because `total_c > T`. By Lemma 2,
Constraints 1 and 2 cannot be simultaneously satisfied for load `c`,
even ignoring Constraint 3. Hence the whole instance is impossible. ∎



*Theorem*  
The algorithm always outputs a correct certificate (`JOB i` or `LOAD c`)
for the given input.

*Proof.*  
Two cases.

1. There exists a job `i` with `p1_i + p2_i > T`.  
   The algorithm detects the first such job and outputs `JOB i`. By
   Lemma 3 this certificate is valid.

2. No job violates the inequality, i.e. for all `k`,
   `p1_k + p2_k ≤ T`.  
   Then by Lemma 1 each job can satisfy Constraints 1 and 3.
   The problem statement guarantees that the instance is still impossible,
   therefore some load must exceed the host size. Consequently either
   `total1 > T` or `total2 > T`. The algorithm outputs the corresponding
   `LOAD c`, which is valid by Lemma 4.

Exactly one of the two certificate types is valid by the problem guarantee,
and the algorithm outputs one of them. ∎

**Complexity Analysis**

The algorithm scans the `j` jobs once.

* Time: `O(j)`  
* Memory: `O(1)` (only a few integer counters)

Both satisfy the limits.

---

**Reference Implementation (Python 3)**

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    j = int(next(it))
    T = int(next(it))

    total1 = 0
    total2 = 0
    for idx in range(1, j + 1):
        p1 = int(next(it))
        p2 = int(next(it))
        total1 += p1
        total2 += p2
        if p1 + p2 > T:
            sys.stdout.write(f"JOB {idx}")
            return

    # no violating job
    if total1 > T:
        sys.stdout.write("LOAD 1")
    else:
        sys.stdout.write("LOAD 2")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above.
