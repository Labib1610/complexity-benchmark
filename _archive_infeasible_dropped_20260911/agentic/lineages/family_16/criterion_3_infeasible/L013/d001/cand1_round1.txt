# Problem C — Pipeline Admission Controller

Time limit: 2 s   Memory limit: 256 MB

## Description

You are implementing Phase 2 of a distributed task management system. The full pipeline consists of:
1. **Ingestion**: Receiving user requests and parsing them.
2. **Admission Control (Your Task)**: Quickly rejecting batches that are mathematically impossible to complete within the user's requested time window.
3. **Scheduling**: Finding the optimal execution order for accepted batches.
4. **Dispatch**: Sending the ordered instructions to the hardware.

You are responsible only for Phase 2. The pipeline routes a batch of **j** jobs to your module along with a maximum time window **T**. Each job requires a certain amount of time on Processor 1, and subsequently a certain amount of time on Processor 2. A job cannot begin on Processor 2 until it has completely finished on Processor 1. Processor 1 and Processor 2 each handle only one job at a time.

Every batch routed to your module in this environment has already been flagged as impossible to complete within **T**. Your program must not search for a schedule; its sole function is to generate a short rejection certificate that the Ingestion module can return to the user.

For the provided inputs, exactly one of the following two impossibility arguments applies. Print the corresponding certificate:

- **Sequential bottleneck**: A single job cannot complete within the time window due to its own sequential processing requirements across the two processors, even in an ideal scenario where it never has to wait for other jobs. Print `JOB i`, where **i** (1-based index) is such a job.
- **Processor saturation**: A single processor cannot finish its portion of the batch within the time window, simply because the continuous uninterrupted execution of all its assigned tasks would exceed the window length. Print `LOAD c`, where **c** is the overloaded processor (1 or 2).

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200,000, 1 ≤ T ≤ 1,000,000,000).
The next **j** lines each contain two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1,000,000): the required time for the job on Processor 1 and Processor 2, respectively.

## Output

Print a single line containing the certificate: either `JOB i` (for a sequential bottleneck) or `LOAD c` (for processor saturation).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 units on Processor 1 and 60 on Processor 2 in sequence. Even without queueing, its own execution requires 130 time units, which exceeds the 100 window. Thus, `JOB 1` is the correct certificate. 
In Example 2, no single job violates the window on its own. However, Processor 1 is assigned four tasks of 50 units each. Even executing them continuously, it requires 200 time units in total, exceeding the 150 window. Thus, `LOAD 1` is the correct certificate.
