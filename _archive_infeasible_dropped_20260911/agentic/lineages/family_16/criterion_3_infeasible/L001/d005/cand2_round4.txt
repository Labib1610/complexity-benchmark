<STATEMENT>
# Problem C — Impossibility Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory is tasked with completing **j** distinct manufactured items. The production of each item requires sequential processing through exactly **2** specialized machines: machine 1 must be fully completed for an item before its machine 2 processing can begin. You are provided with the required processing time on machine 1 and machine 2 for every item. Neither machine can process more than one item simultaneously.

The factory operates under a strict global deadline **T**. All operations across both machines for all items must be finalized by this time.

Formally, a valid schedule must assign a start time $S_{i,m}$ and an end time $E_{i,m}$ for each item $i \in \{1 \dots j\}$ on each machine $m \in \{1, 2\}$ such that:
1. **Duration:** $E_{i,m} - S_{i,m} = p_{i,m}$ (where $p_{i,m}$ is the required time for item $i$ on machine $m$).
2. **Sequential Dependency:** $S_{i,2} \ge E_{i,1}$ for all items $i$.
3. **Non-Overlap:** For any machine $m$, if $i \neq k$, the interval $[S_{i,m}, E_{i,m})$ does not intersect with $[S_{k,m}, E_{k,m})$.
4. **Global Window:** $S_{i,1} \ge 0$ and $E_{i,2} \le T$ for all items $i$.

In this specific problem, **no valid schedule exists** that can meet the deadline **T** for the given inputs. Instead of attempting to schedule the items, your task is to output a simple proof (a certificate) demonstrating why the deadline is structurally impossible to meet. 

It is guaranteed that the impossibility in each test case is caused by exactly one of the following two reasons. You must determine which reason applies and output the corresponding certificate. If the applicable reason offers multiple valid certificates, any single one is acceptable.

- **Individual Feasibility:** For a single item **i**, there exist no times $S_{i,1}, E_{i,1}, S_{i,2}, E_{i,2}$ that satisfy conditions 1, 2, and 4. (In other words, the item cannot be completed even if condition 3 is completely ignored for all items).
  Output format: `JOB i` (where **i** is the 1-based index of the item).

- **Machine Saturation:** For a single machine **c** (**c** $\in \{1, 2\}$), there exist no start and end times for all **j** items on machine **c** that satisfy conditions 1, 3, and the machine-specific global window ($S_{i,c} \ge 0$ and $E_{i,c} \le T$ for all $i$). (In other words, the machine cannot process all its assigned work within the deadline even if condition 2 is completely ignored).
  Output format: `LOAD c` (where **c** is exactly 1 or 2).

## Input

The first line specifies two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
The subsequent **j** lines each provide exactly **2** integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the processing time required for that item on machine 1 and machine 2, respectively. (Let $p_{i,1}$ and $p_{i,2}$ denote these values for the $i$-th item).

## Output

Output exactly one line containing a valid certificate from the applicable category: either `JOB i` or `LOAD c`. If printing `LOAD c`, then **c** must be exactly 1 or 2.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the first item requires a minimum of 130 time units from the start of its machine 1 operation to the end of its machine 2 operation. This violates the global window of 100, so `JOB 1` is a valid certificate.
In Example 2, machine 1 must process 4 items sequentially (due to the non-overlap condition). The combined duration of these operations is 200, which cannot fit within the global window of 150. Thus `LOAD 1` is a valid certificate.
</STATEMENT>
<RATIONALE>
The explicit formulas `p1 + p2 > T` and `sum(p) > T` have been removed from the problem description. Instead, the certificates are defined as the non-existence of a schedule when specific constraints are relaxed. The model must now deduce that relaxing non-overlap makes the necessary condition `p1 + p2 <= T`, and relaxing sequential dependency makes the necessary condition `sum(p_c) <= T`, forcing algorithmic reasoning rather than pattern matching on prose descriptions of aggregate loads.
</RATIONALE>
<PRESERVED_ANSWER>
The certificates are logically identical to the seed formulation: a single item cannot satisfy conditions 1, 2, and 4 if and only if `p1 + p2 > T`, and a single machine cannot satisfy conditions 1, 3, and the global window if and only if `sum(p_c) > T`.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an $O(n)$ impossibility certification task, as checking the relaxed structural conditions still requires exactly the same linear scan and sum operations as the original problem.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the formal schedule definition as implying they need to implement a full scheduling algorithm or interval packing solver, though the guarantee that exactly one of the relaxed reasons applies should steer a careful reader back to the $O(n)$ check.
</RISK>
