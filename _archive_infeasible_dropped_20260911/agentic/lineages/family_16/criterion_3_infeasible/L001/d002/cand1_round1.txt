<STATEMENT>
# Problem C — Impossible Time Limit: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system must assign non-negative start times $x_{i,c} \ge 0$ for each task $i \in \{1, \dots, j\}$ and stage $c \in \{1, 2\}$ such that:
1. $x_{i,1} + p_{i,1} \le x_{i,2}$ for all $i$ (a task's stage 1 precedes its stage 2).
2. $x_{i,c} + p_{i,c} \le T$ for all $i$ and $c$ (all processing must complete by the absolute deadline $T$).
3. For any $i \neq k$ and stage $c$, the intervals $[x_{i,c}, x_{i,c} + p_{i,c})$ and $[x_{k,c}, x_{k,c} + p_{k,c})$ do not intersect (each stage processes one task at a time).

For every input in this problem it is **guaranteed that no valid assignment of start times exists**. Your goal is not to search for an arrangement; it is to **prove** the time limit is impossible with a short certificate that can be checked directly against the input.

It is guaranteed that exactly one of the following two relaxations is already impossible. You must output a valid certificate of the applicable type. If multiple valid certificates of that type exist, you may output any one of them.

- **JOB i**: The relaxation restricted to the variables $x_{i,1}$ and $x_{i,2}$ (enforcing only constraints 1 and 2 for task $i$, and dropping constraint 3) has no valid assignment.
  Print: `JOB i` — where **i** (1-based) is the index of such a task.

- **LOAD c**: The relaxation restricted to the variables $x_{1,c}, \dots, x_{j,c}$ (enforcing only constraints 2 and 3 for stage $c$, and dropping constraint 1) has no valid assignment.
  Print: `LOAD c` — where **c** is 1 or 2, representing such a stage.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations $p_{i,1}$ and $p_{i,2}$ of task $i$ in stage 1 and stage 2.

## Output

Print a single line containing a valid certificate of the applicable type: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the relaxation for task 1 (dropping constraint 3) requires $x_{1,1} \ge 0$, $x_{1,1} + 70 \le x_{1,2}$, and $x_{1,2} + 60 \le 100$. This system of inequalities has no solution, so `JOB 1` proves the time limit is impossible. In Example 2, the relaxation for stage 1 (dropping constraint 1) requires four non-intersecting intervals of length 50 to all fit within $[0, 150]$. This is impossible, so `LOAD 1` is a valid certificate.
</STATEMENT>
<RATIONALE>
The previous wording explicitly narrated the bottleneck conditions ("A single task... cannot complete", "A single stage cannot process all of its assigned work"), allowing models to directly check $p_1+p_2 > T$ and $\sum p > T$ without understanding why. The rewrite formalizes the scheduling problem as a system of constraints and defines the certificates as mathematical relaxations. Models must now independently deduce that dropping the non-overlap constraint yields the $p_1+p_2 > T$ bound, and dropping the ordering constraint yields the $\sum p > T$ bound.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions for the two relaxations having no valid assignment exactly correspond to $p_{i,1} + p_{i,2} > T$ and $\sum_i p_{i,c} > T$, which are the identical conditions from the seed problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires an $O(N)$ scan to find a task with $p_1+p_2 > T$ or a stage with total load $> T$, keeping it in the INFEASIBLE certification class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "dropping constraint 3" as meaning they need to solve a complex LP, but the definitions are algebraically trivial to resolve once written out.
</RISK>
