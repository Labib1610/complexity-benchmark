<STATEMENT>
# Problem C — Infeasible System Certification

Time limit: 2 s
Memory limit: 256 MB

## Description

You are analyzing a scheduling system modeled by a set of variables and constraints. For $j$ items and $2$ phases, let $S_{i, c}$ and $E_{i, c}$ be the start time and end time of item $i$ in phase $c$ ($1 \le i \le j$, $c \in \{1, 2\}$).

A valid schedule must satisfy the following constraints:
1. **Duration:** $E_{i, c} - S_{i, c} = p_{i, c}$ for all $i$ and $c$, where $p_{i, c}$ is the given processing time.
2. **Sequence:** $S_{i, 2} \ge E_{i, 1}$ for all $i$.
3. **Deadline:** $E_{i, 2} \le T$ for all $i$, where $T$ is the global time limit.
4. **Non-negativity:** $S_{i, 1} \ge 0$ for all $i$.
5. **Mutual Exclusion:** For a given phase $c$, the processing intervals $[S_{i, c}, E_{i, c})$ and $[S_{k, c}, E_{k, c})$ do not overlap for any $i \neq k$.

For every input in this problem, it is guaranteed that the constraint system is unsatisfiable. Your goal is to output a short certificate that identifies a specific, trivial contradiction. It is guaranteed that you can always find a contradiction using one of two specific subsystems:

- **`JOB i`**: The subsystem consisting only of constraints 1, 2, 3, and 4 for a single item $i$ is already mathematically inconsistent.
- **`LOAD c`**: The subsystem consisting only of constraints 1 and 5 for a single phase $c$ (across all items), combined with the bounding facts that $S_{i, c} \ge 0$ and $E_{i, c} \le T$ for all $i$, is already mathematically inconsistent.

Output a valid certificate. If multiple certificates apply, you may output any one of them.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_{i, 1}$ and $p_{i, 2}$ ($1 \le p_{i, 1}, p_{i, 2} \le 1000000$): the required durations for item $i$ in phase 1 and phase 2.

## Output

Print a single line containing a valid certificate: either `JOB i` (where $i$ is the 1-based index) or `LOAD c` (where $c$ is 1 or 2).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the constraints for item 1 require $S_{1, 1} \ge 0$, $E_{1, 1} = S_{1, 1} + 70$, $S_{1, 2} \ge E_{1, 1}$, $E_{1, 2} = S_{1, 2} + 60$, and $E_{1, 2} \le 100$. This implies $130 \le 100$, which is a contradiction. Thus `JOB 1` is a valid certificate.

In Example 2, the `LOAD 1` certificate is valid because phase 1 requires four mutually exclusive intervals of length 50, all bounded between 0 and 150. This requires a total length of 200 to fit within a span of 150, which is a mathematical contradiction.
</STATEMENT>
<RATIONALE>
The previous statement explicitly told the models to check if a single task's sequence exceeded the time limit or if a stage's total work exceeded the time limit, directly handing them the `p1+p2 > T` and `sum > T` checks. I rewrote the problem as a formal constraint satisfaction system, defining the certificates as unsatisfiable cores of specific constraint subsets. This removes the explicit lower bounds from the text, forcing the models to independently deduce that "constraints 1,2,3,4 for item i are inconsistent" implies `p1+p2 > T` and that "constraints 1,5 bounded by 0 and T are inconsistent" implies interval packing where `sum > T`.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions for the subsystems to be inconsistent evaluate exactly to `p_i,1 + p_i,2 > T` and `sum(p_i,c) > T`, which are the exact same conditions for the original problem's certificates, meaning any valid original certificate remains perfectly valid here.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires an $O(n)$ check of individual sums and aggregate stage sums to identify the contradiction, preserving the INFEASIBLE certification complexity class.
</PRESERVED_CLASS>
<RISK>
Models might struggle to parse the phrase "bounding facts that S_{i,c} >= 0 and E_{i,c} <= T" as an explicit addition to the LOAD subsystem, though the phrasing "combined with the bounding facts" makes the inclusion logically unambiguous.
</RISK>
