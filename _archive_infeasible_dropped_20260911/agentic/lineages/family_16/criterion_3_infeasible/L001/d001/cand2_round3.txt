<STATEMENT>
# Problem C — Impossible Time Limit: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system executes **j** tasks. There are exactly **two** stages, indexed 1 and 2. Every task must be processed entirely in stage 1, and only after finishing stage 1, it is processed in stage 2. Each stage can handle only one task at a time. For each task, you are given its required processing duration in stage 1 and its required processing duration in stage 2.

There is a strict time limit **T**: every task must be completely finished by time **T**.

For every input in this problem, it is **guaranteed that the time limit cannot be met**, no matter how the tasks are ordered. Your goal is not to search for an arrangement; it is to **prove** the time limit is impossible by providing a short certificate. 

Exactly one of the following reasons always applies. Print the one that holds:

- **Sequential bottleneck.** A specific task cannot possibly complete both of its required operations within the time limit, even if it were the only task in the system, because its operations must run one after the other. 
  Print: `JOB i` — where **i** (1-based) is such a task.

- **Capacity bottleneck.** A specific stage cannot possibly complete all of its assigned work within the time limit, even if it were constantly active, because it processes tasks one at a time. 
  Print: `LOAD c` — where **c** is exactly 1 or 2 (the overloaded stage).

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations of a task in stage 1 and stage 2.

## Output

Print a single line: `JOB i` (if a task represents a sequential bottleneck) or `LOAD c` (if stage **c** represents a capacity bottleneck).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, task 1 cannot complete its operations within 100 time units because they must run in sequence, so `JOB 1` proves the time limit is impossible. In Example 2, no single task is a sequential bottleneck, but stage 1 must process more work in total than the 150 time units allow, so `LOAD 1` is the certificate.
</STATEMENT>
<RATIONALE>
I removed the explicit arithmetic formulas (`p1 + p2 > T` and `sum > T`) that allowed models to pattern-match the solution without understanding the system's constraints. Instead, the certificates are defined by the physical limitations of the execution model (sequential processing for a single task, and single-task capacity for a stage). This forces the model to deduce the mathematical conditions from the prose description of the bottlenecks. I also explicitly restored the bound of exactly "two" stages.
</RATIONALE>
<PRESERVED_ANSWER>
The definitions of the sequential and capacity bottlenecks mathematically equate to the exact same conditions (`p1+p2 > T` and `total > T`) as the original problem, ensuring identical output requirements.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an impossibility certification task where the algorithm verifies the provided simple mathematical conditions in linear time.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "even if it were the only task in the system" as implying they need to simulate the system dynamically, but the phrase "because its operations must run one after the other" firmly points to simple addition.
</RISK>
