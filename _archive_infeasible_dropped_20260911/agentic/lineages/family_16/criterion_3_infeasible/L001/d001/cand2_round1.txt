<STATEMENT>
# Problem C — Impossible Time Limit: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system executes **j** tasks through exactly **two** stages. Every task is executed in stage 1 first and then in stage 2. For each task you are given its duration in stage 1 and in stage 2. Each stage handles only one task at a time, and a task reaches stage 2 only after finishing in stage 1.

There is a required time limit **T**: every task must be completely finished by time **T**.

For every input in this problem it is **guaranteed that the time limit cannot be met**, no matter how the tasks are ordered. Your goal is not to search for an arrangement; it is to **prove** the time limit is impossible by identifying a single component of the system that inherently violates the deadline.

You must output a short certificate that demonstrates this impossibility without considering the full schedule or any overlapping delays. The test cases guarantee that exactly one of the following two types of certificates can be formed:

- **Isolated Task:** A specific task cannot complete within the deadline due to its own sequential execution requirements, even if it never has to wait for other tasks. Print `JOB i` where **i** (1-based) is this task.
- **Isolated Stage:** A specific stage cannot complete its assigned volume of work within the deadline, even if it runs continuously with no idle time waiting for the other stage. Print `LOAD c` where **c** is the stage number (1 or 2).

Print the single certificate that is valid for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations of a task in stage 1 and stage 2.

## Output

Print a single line: `JOB i` (where task **i** is an isolated task certificate) or `LOAD c` (where stage **c** is an isolated stage certificate).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, task 1 requires 130 time units of sequential execution, which exceeds the deadline of 100 even if it never waits. Thus `JOB 1` proves the time limit is impossible. In Example 2 no single task violates the deadline in isolation, but stage 1 is assigned 200 units of total work. Even running continuously, it cannot finish by time 150, so `LOAD 1` is the certificate.
</STATEMENT>
<RATIONALE>
The explicit arithmetic formulas (`p1 + p2 > T` and `sum > T`) have been removed from the problem statement and the notes. Instead, the problem now describes the certificates conceptually in terms of the execution model ("sequential execution requirements" and "assigned volume of work"). This forces the model to actually understand the constraints of the two-stage system to derive the arithmetic checks, rather than blindly pattern-matching the provided formulas.
</RATIONALE>

The conditions for outputting `JOB i` or `LOAD c` are logically identical to the original arithmetic rules, meaning the exact same outputs are required for all inputs.
</PRESERVED_ANSWER>
