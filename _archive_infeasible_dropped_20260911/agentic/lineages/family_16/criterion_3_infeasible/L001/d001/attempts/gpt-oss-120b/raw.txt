**Solution Explanation**

For every task we know the processing time in stage 1 (`p1`) and in stage 2 (`p2`).

* **Task bottleneck** – a single task cannot finish even if it is the only
  one that runs:

```
p1 + p2 > T
```

* **Stage bottleneck** – a whole stage cannot finish all its work within the
  limit, even if there is no waiting between the two stages:

```
 Σ p1  > T      (stage 1)
 Σ p2  > T      (stage 2)
```

The statement guarantees that *exactly one* of the two situations holds for the
given input. Therefore it is sufficient to:

1. Scan all tasks once.
2. While scanning, keep the total sums `sum1` and `sum2`.
3. If we meet a task with `p1 + p2 > T`, we can immediately output  
   `JOB i` (the first such task is enough) – this is the task bottleneck.
4. If the scan finishes without such a task, then a stage bottleneck must be
   present. According to the guarantee, only one stage exceeds `T`, so we output
   `LOAD 1` if `sum1 > T`, otherwise `LOAD 2`.

The algorithm is linear `O(j)` time and `O(1)` extra memory, easily fast for
`j ≤ 200 000`.

---

#### Correctness Proof  

We prove that the algorithm always outputs a valid certificate.

*Lemma 1*  
If the algorithm outputs `JOB i`, then task *i* is a task bottleneck.

*Proof.*  
The algorithm outputs `JOB i` only when it finds a task with
`p1_i + p2_i > T`. Even if this task runs alone, it needs more than `T` time,
hence it cannot be finished before the deadline. ∎



*Lemma 2*  
If the algorithm finishes scanning all tasks without finding a task with
`p1 + p2 > T`, then at least one stage has total load larger than `T`.

*Proof.*  
The problem guarantees that exactly one of the two bottleneck types holds.
Since no task violates `p1 + p2 ≤ T`, the task‑bottleneck type does **not**
hold. Therefore the stage‑bottleneck type must hold, i.e. either  
`Σ p1 > T` or `Σ p2 > T`. ∎



*Lemma 3*  
If the algorithm outputs `LOAD c`, then stage `c` is a stage bottleneck.

*Proof.*  
`LOAD c` is output only after the scan when no task bottleneck exists
(Lemma 2). The algorithm checks the two summed loads:
* if `sum1 > T` it outputs `LOAD 1`,
* else it outputs `LOAD 2`.  
Because at least one of the two sums exceeds `T` (Lemma 2), the chosen `c`
indeed satisfies `Σ p_c > T`. Hence stage `c` cannot finish all its work by the
deadline, even with zero waiting. ∎



*Theorem*  
The algorithm always prints a correct certificate (`JOB i` or `LOAD c`) for the
given input.

*Proof.*  
Two cases.

1. There exists a task with `p1 + p2 > T`.  
   The algorithm encounters the first such task, outputs `JOB i`.  
   By Lemma 1 this is a valid certificate.

2. No task violates `p1 + p2 > T`.  
   Then, by the problem guarantee, a stage bottleneck exists.
   The algorithm finishes the scan, and by Lemma 2 at least one stage load is
   larger than `T`. It outputs `LOAD c` for the stage whose load exceeds `T`,
   which is valid by Lemma 3.

In both cases the printed line is a correct certificate. ∎



---

#### Complexity Analysis  

The input is processed once.

*Time* – `O(j)` where `j` ≤ 200 000.  
*Memory* – `O(1)` besides the input buffer.

Both limits satisfy the constraints easily.

#### Reference Implementation (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    j, T = data[0], data[1]
    idx = 2
    sum1 = 0
    sum2 = 0
    # scan tasks
    for i in range(1, j + 1):
        p1 = data[idx]
        p2 = data[idx + 1]
        idx += 2
        sum1 += p1
        sum2 += p2
        if p1 + p2 > T:
            print(f"JOB {i}")
            return
    # no task bottleneck -> stage bottleneck
    if sum1 > T:
        print("LOAD 1")
    else:
        print("LOAD 2")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
