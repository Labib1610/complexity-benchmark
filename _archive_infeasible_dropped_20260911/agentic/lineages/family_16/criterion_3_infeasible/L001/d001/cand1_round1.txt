<STATEMENT>
# Problem C — Impossible Time Limit: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system executes **j** tasks through exactly **two** stages. Every task is executed in stage 1 first and then in stage 2. For each task you are given its duration in stage 1 and in stage 2. Each stage handles only one task at a time, and a task reaches stage 2 only after finishing in stage 1.

There is a required time limit **T**: every task must be completely finished by time **T**.

For every input in this problem it is **guaranteed that the time limit cannot be met**, no matter how the tasks are ordered. Your goal is not to search for an arrangement; it is to **prove** the time limit is impossible with a short certificate that isolates a single component of the system which fundamentally exceeds the time limit on its own.

You must output one of two certificate types:
- `JOB i` — where **i** (1-based) is a task whose inherent sequential execution requirements cannot be completed within **T**, even if it were the only task in the system.
- `LOAD c` — where **c** is 1 or 2, identifying a stage whose total volume of assigned work exceeds **T**, even if it could operate continuously without waiting for tasks from the other stage.

It is guaranteed that for each test case, exactly one valid certificate exists.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations of a task in stage 1 and stage 2.

## Output

Print a single line containing the valid certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, task 1 requires 70 time units in stage 1 followed by 60 in stage 2. This sequence alone requires more than 100 time units, making the deadline impossible. `JOB 1` is the valid certificate.
In Example 2, no single task exceeds the deadline on its own. However, stage 1 must process all 4 tasks sequentially. The total work assigned to stage 1 exceeds 150, making the deadline impossible. `LOAD 1` is the valid certificate.
</STATEMENT>
<RATIONALE>
Removed the explicit arithmetic formulas (`p1 + p2 > T` and `sum > T`) from the certificate descriptions. Models must now derive these checks by reasoning about the constraints of the execution model (sequential task execution and sequential stage processing) rather than directly transcribing provided formulas into code.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions that trigger a `JOB i` or `LOAD c` certificate remain mathematically identical, as the underlying execution model and time limit definitions are unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The solution still requires exactly the same linear-time pass to check individual task sums and aggregate stage sums, keeping it in the same complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "inherent sequential execution requirements" if they fail to link it to the previously stated rule that a task must finish stage 1 before starting stage 2.
</RISK>
