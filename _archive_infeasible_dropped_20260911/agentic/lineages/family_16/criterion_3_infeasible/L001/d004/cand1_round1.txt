<STATEMENT>
# Problem C — Impossibility Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory is tasked with completing **j** distinct manufactured items. The production of each item requires sequential processing through two specialized stages: stage 1 must be fully completed for an item before its stage 2 processing can begin. You are provided with the required processing time in stage 1 and stage 2 for every item. Neither stage can process more than one item simultaneously.

The factory operates under a strict global deadline **T**. All operations across both stages for all items must be finalized by this time.

In this specific problem, **no valid schedule exists** that can meet the deadline **T** for the given inputs. Instead of attempting to schedule the items, your task is to output a simple proof (a certificate) demonstrating why the deadline is structurally impossible to meet. 

It is guaranteed that the impossibility can be proven by isolating a specific constraint that fails on its own. You must output a valid certificate for one of the following two isolation cases. If multiple valid certificates exist, any single one is acceptable.

- **Isolated Item:** Output `JOB i` (where **i** is the 1-based index) if item **i** requires a minimum time that strictly exceeds **T**, even if it is the only item assigned to the factory.
- **Isolated Stage:** Output `LOAD c` (where **c** is 1 or 2) if stage **c** requires a minimum time that strictly exceeds **T**, even if the sequential dependency between stages is removed and items require zero time in the other stage (stage **c** still cannot process multiple items simultaneously).

## Input

The first line specifies two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
The subsequent **j** lines each provide two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the processing time required for that item in stage 1 and stage 2, respectively.

## Output

Output exactly one line containing a valid certificate from the applicable isolation case: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, if we isolate the first item, it must still pass sequentially through stage 1 and then stage 2. Its minimum completion time strictly exceeds the deadline of 100 on its own, so `JOB 1` correctly certifies the impossibility.
In Example 2, no individual item fails the deadline on its own. However, if we isolate stage 1 and remove the sequential dependency, stage 1 is still required to process all 4 items one at a time. Even without waiting for stage 2, the continuous operation of stage 1 requires a minimum time that strictly exceeds the 150 deadline, making `LOAD 1` a valid certificate.

<RATIONALE>
The explicit inequalities (`p1 + p2 > T` and `sum(pc) > T`) were removed. They are replaced with equivalent physical constraint relaxations ("isolated item" and "isolated stage"). This forces the model to mathematically deduce the minimum bounds from the described physical limits rather than directly transcribing provided formulas.
</RATIONALE>
<PRESERVED_ANSWER>
The condition for an isolated item failing matches exactly `p1 + p2 > T`, and the condition for an isolated stage failing despite no sequential dependencies matches exactly `sum(pc) > T`, so the accepted certificates are identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires verifying the exact same impossibility certificates in O(N) time, keeping it in the same class.
</PRESERVED_CLASS>
<RISK>
Models might misunderstand "minimum time" in the isolated stage case, though explicitly reminding them that stages cannot process multiple items simultaneously mitigates the risk of assuming parallel execution.
</RISK>
