<STATEMENT>
# Problem C — Impossibility Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders. Each order must be processed first in department 1, and then, immediately or later, in department 2. An order cannot start in department 2 until its department 1 processing is entirely finished. Each department can handle at most one order at any given moment. 

For each order, you are provided the exact time required in department 1 and the time required in department 2.

The facility operates under a strict deadline **T**: every single order must complete its processing in both departments by time **T**.

For all inputs provided, it is impossible to meet this deadline, regardless of how the orders are scheduled. You are not asked to explore schedules. Instead, you must prove the impossibility by outputting a certificate that directly verifies the failure. 

A certificate is valid if it matches one of these formats:
- `JOB i` — where **i** (1-based) is the index of an order whose own sequential processing requirement (the combined time it must spend in both departments) strictly exceeds the deadline **T**, even if it were the only order in the facility.
- `LOAD c` — where **c** is a department number (1 or 2) whose total active processing time (the sum of the times required by all **j** orders in that specific department) strictly exceeds the deadline **T**, making it impossible for that department to finish its workload in time.

You must output a valid certificate. If multiple such certificates exist, outputting any one of them is acceptable.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
The next **j** lines each contain two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing time required for the order in department 1 and department 2, respectively.

## Output

Print a single line containing a valid certificate: either `JOB i` (where **i** is the order index) or `LOAD c` (where **c** is the department number).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, order 1 needs 70 time units in department 1 and 60 time units in department 2. Because these must occur in sequence, this order alone requires 130 time units. This is strictly greater than the 100 time limit, proving the schedule is impossible. `JOB 1` is a valid certificate.

In Example 2, no single order takes more than 150 time units on its own. However, department 1 has to process 4 orders, each taking 50 time units. The total active time required from department 1 is 200 time units. Since 200 exceeds the 150 time limit, department 1 cannot finish before the deadline. `LOAD 1` is a valid certificate.
</STATEMENT>
<RATIONALE>
I removed the explicit guarantee that "exactly one of the following two categories applies". The seed explicitly promised an exhaustive dichotomy between the two bottleneck categories, which allowed models to use process-of-elimination logic (e.g., checking `JOB` and `LOAD 1`, then unconditionally outputting `LOAD 2` if they failed). By removing this meta-guarantee and presenting the certificates simply as valid formats to verify, models are forced to independently evaluate each condition.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions for `JOB i` ($p_1+p_2 > T$) and `LOAD c` ($\sum p_c > T$) are identical to the seed, ensuring the exact same certificates are valid for every input.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still only requires checking linear aggregates and per-item sums against a threshold, keeping the O(N) complexity class unchanged.
</PRESERVED_CLASS>
