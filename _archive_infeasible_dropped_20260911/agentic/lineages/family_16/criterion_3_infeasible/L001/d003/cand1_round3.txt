# Problem C — Impossibility Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** orders. Every order must go through exactly two stages in a strict sequence: it is first processed in Stage 1, and only after its Stage 1 work is fully completed can it be processed in Stage 2. An order may wait between stages if Stage 2 is currently processing another order. Each stage can process only one order at a time, and a stage's processing of an order cannot be interrupted.

There is a strict facility deadline **T**: every order must be completely finished in both stages by time **T**.

For every input in this problem, it is guaranteed that the deadline cannot be met, regardless of how the orders are scheduled. Your goal is not to search for a schedule; rather, you must prove that the deadline is impossible by providing a short certificate that can be verified directly against the input.

While a schedule might fail for complex reasons, it is guaranteed that for all test cases provided, the impossibility can be proven by pointing out a basic structural violation using one of the following two certificate types. If multiple valid certificates exist, you may output any one of them.

- **Sequential bottleneck:** An individual order **i** has a minimum required span (the sum of its durations in the two stages) that is strictly greater than the deadline **T**.
  Print: `JOB i` — where **i** (1-based) is the index of such an order.

- **Resource bottleneck:** An individual stage **c** (**c** $\in \{1, 2\}$) has a total committed active time (the sum of durations for all **j** orders in this stage) that is strictly greater than the deadline **T**.
  Print: `LOAD c` — where **c** is the stage number (1 or 2).

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing durations of an order in Stage 1 and Stage 2, respectively.

## Output

Print a single line containing a valid certificate: either `JOB i` (for a sequential bottleneck) or `LOAD c` (for a resource bottleneck).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, order 1 requires 70 units of time in Stage 1 and 60 units in Stage 2. Because it must be processed sequentially, its minimum required span is 130, which exceeds the 100 time limit even if it runs alone without waiting, so `JOB 1` proves the deadline is impossible. 
In Example 2, no single order exceeds 150 on its own, but Stage 1 must process 200 units of work in total (50 for each of the 4 orders). This total committed active time exceeds the 150 time limit, making it impossible for Stage 1 to finish by the deadline, so `LOAD 1` is a valid certificate.
