<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A data center must resolve **j** queries. Each query requires sequential execution: it must first complete a data retrieval phase on the storage array (Component 1), and subsequently complete an analysis phase on the compute node (Component 2). For each query, you are given the exact number of minutes required on Component 1, and the exact number of minutes required on Component 2. 

The system operates under strict concurrency limits:
- A query can only begin its Component 2 phase after its Component 1 phase is entirely complete.
- The storage array (Component 1) can process at most one query at any given moment.
- The compute node (Component 2) can process at most one query at any given moment.
- All queries must be completely finished by time **T**.

For every input in this problem, it is **guaranteed that the deadline cannot be met**, no matter how the system schedules the queries. Your task is not to search for a schedule; it is to **prove** the deadline is impossible by identifying a hypothetical relaxation of the system constraints that *still* fails to meet the deadline. 

It is guaranteed that exactly one of the following three relaxed scenarios will inevitably fail to finish by time **T** (while the remaining two could theoretically be completed by time **T** in their relaxed states). Output the certificate for the unique scenario that fails:

- **Relaxed Scenario A:** Both the storage array and the compute node are upgraded to infinitely scalable clusters, allowing unlimited concurrency (any number of queries can be processed simultaneously without sharing resources). However, the strict sequential requirement for each query remains: a query's compute phase still cannot start until its storage phase is entirely complete. Under this relaxation, if no schedule can meet the deadline **T**, it is because a specific query **i** (1-based index) cannot finish in time. Print `JOB i`.
- **Relaxed Scenario B:** The sequential dependency within every query is completely removed (a query's compute phase can be scheduled at any time, independently of its storage phase). Additionally, the compute node is upgraded to an infinitely scalable cluster, allowing unlimited concurrency. The storage array retains its original single-threaded limit (at most one query at a time), though preemption is now permitted (a storage phase can be paused and resumed later without penalty). If no schedule can meet the deadline **T** under these relaxed rules, print `LOAD 1`.
- **Relaxed Scenario C:** The sequential dependency within every query is completely removed. The storage array is upgraded to an infinitely scalable cluster, allowing unlimited concurrency. The compute node retains its original single-threaded limit (at most one query at a time), though preemption is now permitted. If no schedule can meet the deadline **T** under these relaxed rules, print `LOAD 2`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required minutes of the query on Component 1 and Component 2.

## Output

Print a single line containing the certificate:
- `JOB i` (where **i** is the 1-based query index for which Relaxed Scenario A fails)
- `LOAD c` (where **c** is 1 if Relaxed Scenario B fails, or 2 if Relaxed Scenario C fails)

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under Relaxed Scenario A, all queries can be processed concurrently. Queries 2 and 3 finish by times 4 and 7 respectively. However, due to its internal sequential dependency, query 1 requires 70 minutes on the storage array followed immediately by 60 minutes on the compute node. It finishes exactly at minute 130. Since this exceeds the deadline of 100, `JOB 1` proves the deadline is impossible.

In Example 2, no single query violates the deadline under Relaxed Scenario A (each requires at most 51 minutes). However, under Relaxed Scenario B, the compute phases can all finish concurrently by minute 1, but the storage array remains single-threaded. Processing all four storage phases requires a minimum of 200 minutes. Even with preemption and independent scheduling, the storage array cannot finish its workload by time 150, making `LOAD 1` the certificate.
</STATEMENT>
<RATIONALE>
I replaced the explicit arithmetic shortcuts ("0 minutes required", "all queries except i are cancelled") with functionally equivalent scheduling environments ("unlimited concurrency", "preemption permitted"). This forces the model to genuinely reason about the makespan of these relaxed systems to deduce that the minimum completion time is still just `p1 + p2`, `sum(p1)`, or `sum(p2)`, rather than pattern-matching the arithmetic directly from the text.
</RATIONALE>
<PRESERVED_ANSWER>
The relaxed scenarios are mathematically equivalent to the seed: infinite capacity with sequential dependency yields a makespan of max(p1+p2), while independent scheduling with one infinite and one single-threaded resource yields a makespan of max(sum(p), max(other_p)) which reduces to sum(p) since the problem guarantees exactly one scenario fails (meaning max(other_p) <= T).
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem can still be solved in O(N) time by checking if any job's p1+p2 > T, and evaluating sum(p1) > T and sum(p2) > T.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "preemption is now permitted" as implying a complex scheduling algorithm is required, though the lack of release dates mathematically guarantees the minimum makespan on a single machine is strictly the sum of processing times.
</RISK>
