# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A chef is preparing a banquet featuring **j** special recipes, tracked in the kitchen's order system as `JOB`s. The preparation follows a strict sequence: every `JOB` must first be baked in appliance 1 (the oven), and only after it has finished in the oven can it be transferred to be finished in appliance 2 (the broiler). For each `JOB`, you are provided with the duration it requires in appliance 1 and the duration it requires in appliance 2. Each appliance can process at most one `JOB` at any given time.

There is a strict time limit **T**: every `JOB` must be completely finished by time **T**.

For every input in this problem, it is guaranteed that the time limit cannot be met, no matter how the chef orders the preparation. Your task is not to search for a schedule, but to prove the time limit is impossible by outputting a short certificate that identifies a fundamental physical constraint violation.

The input guarantees that at least one of the following two types of certificates will be valid for the given test case:

- **Sequential Bottleneck:** Because a recipe must be processed in the oven and then the broiler in sequence, it requires a minimum total processing duration. If this duration for an individual recipe strictly exceeds the total time available until the deadline, no schedule could possibly complete it in time. To certify this, print `JOB i`, where **i** is the 1-based index of such a recipe.
- **Resource Exhaustion:** Because an appliance can only handle one recipe at a time, it must be active for at least the total duration of all recipes assigned to it. If the total active time required for a specific appliance strictly exceeds the total time available until the deadline, no schedule could possibly process all recipes on that appliance. To certify this, print `LOAD c`, where **c** is 1 (for the oven) or 2 (for the broiler).

If multiple certificates are valid (for instance, multiple recipes face a sequential bottleneck, or both appliances face resource exhaustion), you may print any one of them.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required time of a `JOB` in appliance 1 and appliance 2 respectively.

## Output

Print a single line containing a valid certificate: either `JOB i` (where recipe **i**'s sequential processing duration exceeds **T**) or `LOAD c` (where appliance **c**'s total required active time exceeds **T**).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, recipe 1 requires 70 units of time in the oven followed by 60 units in the broiler. The total sequential duration is 130, which is strictly greater than the deadline of 100. Thus, `JOB 1` is a valid certificate.
In Example 2, no single recipe's sequential duration exceeds 150. However, appliance 1 must process all 4 recipes, requiring a total active time of 50 + 50 + 50 + 50 = 200 units. Since this exceeds the deadline of 150, `LOAD 1` is a valid certificate.
</STATEMENT>
<RATIONALE>
The explicit inequalities (`p1+p2 > T` and `sum > T`) and the guarantee that exactly one reason applies were removed. They were replaced with an indirect description of the certificates based on the physical constraints of the appliances (sequential processing duration and total active time). This forces the model to derive the required mathematical checks from the text rather than pattern-matching the formulas. The G1/G3 issues from the previous attempt were resolved by explicitly allowing any valid certificate if multiple exist, rather than falsely claiming uniqueness.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for printing `JOB i` or `LOAD c` map exactly to the same inequalities (`p1+p2 > T` and `sum > T`) as the seed, meaning the same certificates remain valid.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains O(N) because finding a valid certificate still requires at most one pass over the input to check the per-job sums and accumulate the per-appliance totals.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "minimum total processing duration" as something other than the simple sum of the two appliance times, or "total active time required" as something other than the sum of all jobs for a single appliance, though the physical description strongly implies these sums.
</RISK>
