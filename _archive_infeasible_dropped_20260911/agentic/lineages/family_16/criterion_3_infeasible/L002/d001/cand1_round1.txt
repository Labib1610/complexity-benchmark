# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A chef is preparing a banquet featuring **j** special recipes, tracked in the kitchen's order system as `JOB`s. Every `JOB` must be baked in appliance 1 (the oven) first and then finished in appliance 2 (the broiler). For each `JOB` you are given its required time in appliance 1 and in appliance 2. Each appliance processes only one `JOB` at a time, and a `JOB` reaches appliance 2 only after finishing in appliance 1.

There is a strict time limit **T**: every `JOB` must be completely finished by time **T**.

For every input in this problem it is **guaranteed that the time limit cannot be met**, no matter how the chef orders the preparation. Your task is not to search for a schedule; it is to **prove** the time limit is impossible by identifying a specific bottleneck that makes it unachievable.

You must output a short certificate that isolates a portion of the requirements which intrinsically exceeds the available time **T**. The kitchen accepts two types of bottleneck certificates:

- `JOB i` (where **i** is a 1-based recipe index): This certificate proves that the physical routing of recipe **i** through the kitchen takes longer than the deadline allows, even in a hypothetical scenario where no other recipes exist.
- `LOAD c` (where **c** is 1 or 2): This certificate proves that appliance **c** is assigned a volume of work that cannot be completed by the deadline, even in a hypothetical scenario where recipes can be processed in any order and do not need to wait for the other appliance.

It is guaranteed that for every test case, exactly one valid certificate of the above types exists. Print that certificate.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required times of a `JOB` in appliance 1 and appliance 2.

## Output

Print a single line containing the valid certificate for the given input (`JOB i` or `LOAD c`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, recipe 1 requires 70 units of time in the oven and 60 in the broiler. Since it must pass through both in order, it requires 130 units of time from start to finish. This exceeds the 100-unit deadline, validating the `JOB 1` certificate.

In Example 2, no single recipe violates the deadline on its own. However, appliance 1 is required to operate for 50 units of time for each of the 4 recipes. This 200-unit operational requirement makes it impossible to finish everything by the 150-unit deadline, validating the `LOAD 1` certificate.
</STATEMENT>
<RATIONALE>
I removed the explicit mathematical conditions (`p1+p2 > T` and `sum > T`) for the certificates. Instead, I described the certificates in terms of the scheduling model (a recipe processed alone, or an appliance processing its share without dependencies), forcing the models to deduce the inequalities from the physical constraints of the problem rather than pattern-matching against a checklist.
</RATIONALE>
<PRESERVED_ANSWER>
The logical conditions for a certificate to be valid remain exactly the same (a single job's sequential time exceeding T, or an appliance's total load exceeding T), so the identical output will be produced for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires a linear scan over the jobs to check the per-job sum and accumulate the per-appliance sum, keeping it in the same O(n) feasibility certification class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "volume of work" or "physical routing" and fail to derive the exact inequalities, but the Note section's explanation of the examples strongly reinforces the intended mathematical meaning, reducing ambiguity.
</RISK>
