<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A chef is preparing a banquet featuring **j** special recipes, tracked in the kitchen's order system as `JOB`s. Each `JOB` has a strict two-stage preparation sequence: it must first be processed in appliance 1 (the oven) and subsequently in appliance 2 (the broiler). For each `JOB`, you are given the exact number of minutes it must continuously occupy appliance 1, and the exact number of minutes it must continuously occupy appliance 2. Each appliance can only accommodate one `JOB` at any given moment, and a `JOB` can only transition to the broiler after its oven phase is entirely complete.

The kitchen operates under a strict deadline: all processing for all recipes must be completely finished within a **T**-minute operational window.

For every input in this problem, it is guaranteed that the deadline cannot be met. Your task is to prove the deadline is impossible by printing a short certificate. 

A certificate is valid if it identifies a specific physical limitation that strictly exceeds the **T**-minute window. You must output a certificate matching one of the two forms below. At least one such certificate is guaranteed to be valid for every input; if multiple are valid, you may print any one of them.

- **Single-Recipe Sequence:** Print `JOB i` (where **i** is the 1-based index of the recipe) if recipe **i** inherently violates the deadline. This occurs if the minimum possible time elapsed from the moment recipe **i** enters the oven to the moment it exits the broiler strictly exceeds **T**.

- **Appliance Workload:** Print `LOAD c` (where **c** is 1 for the oven or 2 for the broiler) if appliance **c** inherently violates the deadline. Since an appliance processes strictly sequentially, this occurs if the absolute minimum time required for appliance **c** to completely process its specific phase for all **j** recipes strictly exceeds **T**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required minutes of the `JOB` in appliance 1 and appliance 2.

## Output

Print a single line containing a valid certificate: either `JOB i` (for a recipe whose sequence strictly exceeds the window) or `LOAD c` (for an appliance whose workload strictly exceeds the window).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, recipe 1 requires 70 minutes in the oven and 60 in the broiler. The minimum time elapsed from entering the oven to exiting the broiler is 130 minutes. Since 130 > 100, it cannot be completed within the 100-minute window, making `JOB 1` a valid certificate.

In Example 2, no single recipe's sequence exceeds 150 minutes. However, the oven must process 4 recipes at 50 minutes each. Because the oven cannot concurrently process multiple recipes, the absolute minimum time required for it to process all 4 recipes is 200 minutes. Since 200 > 150, this duration cannot be contained within the 150-minute window, making `LOAD 1` a valid certificate.
</STATEMENT>
<RATIONALE>
The explicit promise that "exactly one bottleneck applies" has been removed, replacing it with "at least one is guaranteed... if multiple are valid, you may print any one." This breaks the tautological shortcut where models check `JOB i`, then `LOAD 1`, and blindly default to `LOAD 2` without calculating the second appliance's sum. Furthermore, the arithmetic conditions are now described as physical minimums ("minimum possible time elapsed", "absolute minimum time required") rather than explicit summations, forcing genuine reasoning about the constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical definitions of the physical minimums perfectly correspond to $p_{i,1} + p_{i,2} > T$ and $\sum p_{k,c} > T$, ensuring all original valid certificates remain exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an INFEASIBLE certification task, requiring $O(j)$ time to verify the simple numeric bounds for jobs and appliances.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "minimum possible time elapsed" as an invitation to write a complex scheduling simulator, leading to Time Limit Exceeded, but the wording is unambiguous for a competent reader.
</RISK>
