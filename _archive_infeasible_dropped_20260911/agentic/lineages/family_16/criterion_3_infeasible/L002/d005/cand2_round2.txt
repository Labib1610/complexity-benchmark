# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A data center must process **j** queries. Each query requires sequential execution through a two-stage pipeline: a data retrieval phase on the storage array (Component 1), followed by an analysis phase on the compute node (Component 2). For each query, you are given the exact number of minutes required on Component 1, and the exact number of minutes required on Component 2.

The system operates under strict concurrency limits:
- A query can only begin its Component 2 phase after its Component 1 phase is entirely complete.
- The storage array (Component 1) can process at most one query at any given moment.
- The compute node (Component 2) can process at most one query at any given moment.
- All queries must be completely finished by time **T**.

For every input in this problem, it is **guaranteed that the deadline cannot be met**, no matter how the system schedules the queries. Your task is not to search for a schedule; it is to **prove** the deadline is impossible by outputting a short certificate.

It is guaranteed that exactly one of the two following structural bottlenecks is the reason for failure. Print a certificate demonstrating it:

- **Isolated Query Violation:** There is a query that cannot complete its pipeline within the deadline, even in a hypothetical scenario where it experiences zero wait time. Specifically, if a query begins data retrieval at time 0 and requires $p_1$ minutes, the maximum remaining time window available for it on the compute node is $T - p_1$ minutes. If its required analysis time $p_2$ strictly exceeds this available window, this query alone makes the schedule impossible.
  Print: `JOB i` — where **i** (1-based index) is any such query.

- **Resource Oversubscription:** A specific component is asked to perform an aggregate amount of work that cannot be completed by the deadline, even in a hypothetical scenario where the sequential dependency between components is removed and the component runs continuously from time 0 with no gaps. If the absolute minimum time required to execute all assigned phases on a single component strictly exceeds $T$, that component is oversubscribed.
  Print: `LOAD c` — where **c** is 1 (if the storage array is oversubscribed) or 2 (if the compute node is oversubscribed).

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required minutes of the query on Component 1 and Component 2.

## Output

Print a single line containing the certificate:
- `JOB i` (if the Isolated Query Violation applies)
- `LOAD c` (if the Resource Oversubscription applies)

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, if query 1 is processed with zero wait time, its data retrieval phase occupies the storage array for 70 minutes, leaving a maximum of 30 minutes before the deadline limit. Its analysis phase requires 60 minutes, which strictly exceeds the available 30-minute window, proving the deadline impossible. `JOB 1` is a valid certificate.

In Example 2, no single query violates the isolated deadline. However, the storage array is required to perform 50 minutes of data retrieval for each of the 4 queries. Even if the storage array operates continuously from time 0, it requires 200 minutes to complete its dedicated tasks. Since this strictly exceeds the 150-minute deadline, the storage array is oversubscribed. `LOAD 1` is a valid certificate.
