# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A chef is preparing a banquet featuring **j** special recipes, tracked in the kitchen's order system as `JOB`s. Every `JOB` requires time in appliance 1 (the oven) and then appliance 2 (the broiler). 

A valid schedule must assign each `JOB` **i** an oven start time $O_i$ and a broiler start time $B_i$ such that:
1. $O_i \ge 0$
2. $B_i \ge O_i + p_{1,i}$ (the broiler phase starts after the oven phase ends)
3. $B_i + p_{2,i} \le T$ (the broiler phase ends at or before the strict time limit **T**)
4. For any two distinct recipes **i** and **k**, their oven intervals $[O_i, O_i + p_{1,i})$ do not overlap.
5. For any two distinct recipes **i** and **k**, their broiler intervals $[B_i, B_i + p_{2,i})$ do not overlap.

For every input in this problem it is **guaranteed that the time limit cannot be met** (no valid schedule exists). Your task is not to search for a schedule; it is to **prove** the time limit is impossible with a short certificate that can be checked directly against the input.

Exactly one of the following structural bottlenecks is guaranteed to be the unique cause for every input. Print the certificate corresponding to the applicable reason:

- **Infeasible Path.** There is a recipe **i** for which constraints 1, 2, and 3 cannot be simultaneously satisfied, even if constraints 4 and 5 are completely ignored.
  Print: `JOB i` — where **i** (1-based) is this recipe.

- **Infeasible Allocation.** There is an appliance **c** (1 for the oven, 2 for the broiler) for which it is impossible to pack all recipes' intervals for that appliance non-overlappingly into the timeline $[0, T]$. Specifically, constraint 4 cannot be satisfied within $[0, T]$ for the oven, or constraint 5 cannot be satisfied within $[0, T]$ for the broiler, even if constraints 1, 2, and 3 are relaxed such that each interval is only required to be a valid subset of $[0, T]$ (meaning $O_i \ge 0$, $O_i + p_{1,i} \le T$, $B_i \ge 0$, and $B_i + p_{2,i} \le T$).
  Print: `LOAD c` — where **c** is the overloaded appliance.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers $p_1$ and $p_2$ (1 ≤ $p_1$, $p_2$ ≤ 1000000): the required times of a `JOB` in appliance 1 and appliance 2. (For the **i**-th `JOB`, these are denoted $p_{1,i}$ and $p_{2,i}$).

## Output

Print a single line: `JOB i` (where recipe **i** violates the individual path constraints) or `LOAD c` (where appliance **c** violates the allocation packing constraints).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for recipe 1 to satisfy constraints 1, 2, and 3, we would need $0 \le O_1$, $B_1 \ge O_1 + 70$, and $B_1 + 60 \le 100$. This implies $B_1 \ge 70$ and $B_1 \le 40$, which is a contradiction. Thus constraints 1, 2, and 3 cannot be satisfied for recipe 1, making `JOB 1` the certificate.

In Example 2, no single recipe violates constraints 1, 2, and 3 on its own. However, the oven requires four disjoint intervals of length 50. Packing these into the timeline $[0, 150]$ requires at least 200 units of time, which is impossible. Thus constraint 4 cannot be satisfied within $[0, 150]$, making `LOAD 1` the certificate.
