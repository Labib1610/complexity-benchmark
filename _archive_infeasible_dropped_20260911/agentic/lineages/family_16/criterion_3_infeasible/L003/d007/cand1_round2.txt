<METHOD_DESCRIPTION>Removes the explicit list of formal constraints (Duration, Sequential, Exclusivity) that allowed models to trivially map certificates to algebraic formulas. Describes physical bottlenecks directly instead, forcing models to deduce the underlying additive properties from the scenario.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are managing a two-stage processing pipeline for $j$ items. Each item $i$ must first pass through machine 1, requiring a continuous processing time of $p_{i,1}$. After it has fully completed machine 1, it must pass through machine 2, requiring a continuous processing time of $p_{i,2}$. 

The system operates under the following conditions:
- Neither machine can process more than one item at the same time.
- An item cannot start on machine 2 until it has completely finished on machine 1.
- All processing must begin at or after time 0 and finish at or before a strict global deadline $T$.

For every test case, you are guaranteed that no valid schedule exists that can process all $j$ items within the deadline $T$. Your task is to output a short certificate that identifies a reason for this impossibility.

Exactly one of the following two categories of failure witnesses is guaranteed to apply. Print a valid witness from the applicable category:

* `JOB i` (where $i$ is a 1-based index, $1 \le i \le j$): The intrinsic sequential requirements of item $i$ alone make it impossible to finish before the deadline, irrespective of any other items in the system.
* `LOAD c` (where $c \in \{1, 2\}$): The sheer volume of work assigned to machine $c$ makes it impossible to process everything before the deadline, even if we completely suspend the rule that items must finish machine 1 before starting machine 2.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_{i,1}$ and $p_{i,2}$ ($1 \le p_{i,1}, p_{i,2} \le 1000000$), representing the processing times for item $i$ on machine 1 and machine 2, respectively.

## Output

Print a single line containing either `JOB i` (where $i$ is the 1-based index of an item that independently violates the deadline) or `LOAD c` (where $c \in \{1, 2\}$ is the index of a machine that independently violates the deadline).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, item 1 cannot complete both stages within 100 units of time, because moving through machine 1 and then machine 2 requires strictly more time than the window allows. Thus `JOB 1` is a valid certificate.
In Example 2, machine 1 is assigned four items that each take 50 units of time. Running them one after another requires more time than the 150 units available before the deadline, even ignoring the existence of machine 2. Thus `LOAD 1` is a valid certificate.
</STATEMENT>
<RATIONALE>
I replaced the formal constraint lists (which trivially mapped to the algebraic checks `p1+p2 > T` and `sum > T`) with natural language descriptions of the physical bottlenecks in a scheduling scenario. This forces the model to deduce the additive properties from the semantic meaning of "intrinsic sequential requirements" and "sheer volume of work" rather than pattern-matching variable names.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for a valid JOB or LOAD certificate remain exactly `p1+p2 > T` and `sum(p_c) > T`, meaning the outputs for any input are strictly unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains INFEASIBLE, as finding a valid certificate still requires an O(N) scan to check individual job lengths and total machine loads.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "sheer volume of work" as including wait times, though explicitly suspending the sequential dependency rule mitigates this.
</RISK>
