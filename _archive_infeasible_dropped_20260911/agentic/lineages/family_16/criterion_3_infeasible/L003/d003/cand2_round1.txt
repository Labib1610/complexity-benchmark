<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system must process **j** tasks. For each task $i$, its primary phase occupies a time interval $[S_{1,i}, E_{1,i})$ and its secondary phase occupies $[S_{2,i}, E_{2,i})$. 

A valid schedule must satisfy the following rules for all tasks $i$:
1. $S_{1,i} \ge 0$ and $S_{2,i} \ge 0$
2. $E_{1,i} - S_{1,i} = p1_i$
3. $E_{2,i} - S_{2,i} = p2_i$
4. $S_{2,i} \ge E_{1,i}$
5. For any $u \neq v$, the intervals $[S_{1,u}, E_{1,u})$ and $[S_{1,v}, E_{1,v})$ do not intersect.
6. For any $u \neq v$, the intervals $[S_{2,u}, E_{2,u})$ and $[S_{2,v}, E_{2,v})$ do not intersect.
7. $E_{2,i} \le T$ (all tasks must complete by the absolute deadline **T**).

For every input in this problem, it is guaranteed that no valid schedule exists that can satisfy all seven rules simultaneously. Your task is to prove the deadline is impossible by outputting a short certificate that identifies a minimal subset of mutually contradictory rules.

Exactly one of the following underlying contradictions will always apply. Print the certificate for the one that holds:

* `JOB i` (where **i** is a 1-based index): Certifies that for task **i**, rules 1, 2, 3, 4, and 7 are mutually contradictory, even if rules 5 and 6 are entirely ignored.
* `LOAD c` (where **c** is either 1 or 2): Certifies that the rules for phase **c** are inherently contradictory. Specifically:
  - If **c** = 1: Rules 1, 2, 5, and the relaxed requirement $E_{1,i} \le T$ (which is strictly weaker than rules 4 and 7 combined) are mutually contradictory, even if rules 3, 4, and 6 are ignored.
  - If **c** = 2: Rules 1, 3, 6, and 7 are mutually contradictory, even if rules 2, 4, and 5 are ignored.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required interval lengths $p1_i$ and $p2_i$ for a task's primary and secondary phases.

## Output

Print a single line containing either `JOB i` (where task **i**'s isolated rules form the contradiction) or `LOAD c` (where the contradiction arises from phase **c**'s non-intersection rules).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is the correct certificate because applying rules 1, 2, 3, and 4 to task 1 forces its secondary phase completion time to strictly exceed the deadline of 100, contradicting rule 7. 
In Example 2, `LOAD 1` is the certificate because applying rules 1, 2, and 5 to the four tasks forces at least one primary phase completion time to strictly exceed 150, which contradicts the relaxed requirement $E_{1,i} \le 150$.
</STATEMENT>
<RATIONALE>
The previous statement explicitly described the required checks in terms of "its own sequential stage requirements" and "total volume of work", which models reliably mapped directly to `p1+p2 > T` and `sum > T`. This rewrite entirely removes those additive descriptions. Instead, it defines the system using strict mathematical interval constraints and defines the certificates as identifying specific subsets of mutually contradictory rules. To succeed, the model must now deduce that the non-intersection constraints over a fixed window imply a sum limit, and the sequential constraints for a single task imply an additive lower bound.
</RATIONALE>
<PRESERVED_ANSWER>
The contradictions defined for `JOB i`, `LOAD 1`, and `LOAD 2` are mathematically identical to testing $p1_i+p2_i > T$, $\sum p1_i > T$, and $\sum p2_i > T$ respectively, so the exact same certificates apply to all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains in the same complexity class because the underlying logic is identical; the three independent violations can still be found in $O(j)$ time by linearly scanning and summing the input values.
</PRESERVED_CLASS>
<RISK>
Models might struggle to parse the formal mathematical notation of intervals, but the rules themselves are standard and unambiguous formulations of scheduling constraints.
</RISK>
