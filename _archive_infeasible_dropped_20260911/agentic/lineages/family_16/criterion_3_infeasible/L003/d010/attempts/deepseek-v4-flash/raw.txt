We need to check two possible contradictions:

1. **JOB i**: For a single index, we need  
   - Primary: start \( s_1 \ge 0 \), end \( e_1 = s_1 + p_1 \le T \)  
   - Secondary: start \( s_2 \ge 0 \), end \( e_2 = s_2 + p_2 \le T \)  
   - Precedence: \( e_1 \le s_2 \)  

   This is possible iff \( p_1 + p_2 \le T \).  
   If \( p_1 + p_2 > T \), then `JOB i` is impossible.

2. **LOAD c**: For a class with \( n \) elements, each with parameter \( p_k \), we need to assign start \( s_k \ge 0 \), end \( e_k = s_k + p_k \le T \), and for any two distinct elements \( a, b \):  
   \[
   |(s_a + e_a) - (s_b + e_b)| \ge p_a + p_b
   \]
   Let \( m_k = s_k + e_k = 2s_k + p_k \).  
   Since \( s_k \ge 0 \) and \( e_k \le T \), we have:
   \[
   p_k \le m_k \le 2T - p_k
   \]
   Also, the separation condition means all \( m_k \) must be pairwise at least \( p_a + p_b \) apart.

   This is a scheduling problem: we need to place intervals \([p_k, 2T - p_k]\) on the real line such that the distance between any two chosen points is at least the sum of their \( p \)'s.

   A known necessary and sufficient condition for feasibility is:  
   Sort the \( p \)'s in non-decreasing order.  
   Let \( S_k = p_1 + p_2 + \dots + p_k \).  
   Feasible iff for all \( k \), \( S_k \le T + p_k \) (or equivalently \( S_k - p_k \le T \)).  
   Actually, the standard condition:  
   If we sort \( p_1 \le p_2 \le \dots \le p_n \), then we can place them greedily:  
   First element at \( m_1 = p_1 \).  
   Then \( m_k = m_{k-1} + p_{k-1} + p_k \).  
   This gives \( m_k = p_1 + 2p_2 + 2p_3 + \dots + 2p_{k-1} + p_k \).  
   We need \( m_k \le 2T - p_k \) for all \( k \).  
   That is:  
   \( p_1 + 2\sum_{i=2}^{k-1} p_i + p_k \le 2T - p_k \)  
   \(\Rightarrow p_1 + 2\sum_{i=2}^{k-1} p_i + 2p_k \le 2T\)  
   \(\Rightarrow p_1 + 2\sum_{i=2}^{k} p_i \le 2T\)  
   \(\Rightarrow \sum_{i=1}^k p_i + \sum_{i=2}^k p_i \le 2T\)  
   \(\Rightarrow S_k + (S_k - p_1) \le 2T\)  
   \(\Rightarrow 2S_k - p_1 \le 2T\)  
   \(\Rightarrow S_k \le T + p_1/2\) — but this is not integer-friendly.

   Actually, the known condition for this problem (from similar competitive programming tasks) is:  
   Sort \( p \) ascending.  
   Feasible iff for all \( k \),  
   \[
   \sum_{i=1}^k p_i \le T + p_k
   \]
   Let’s verify:  
   Greedy: place first at \( m_1 = p_1 \).  
   Then \( m_k = m_{k-1} + p_{k-1} + p_k \).  
   So \( m_k = p_1 + 2p_2 + \dots + 2p_{k-1} + p_k \).  
   Need \( m_k \le 2T - p_k \).  
   So \( p_1 + 2\sum_{i=2}^{k-1} p_i + p_k \le 2T - p_k \)  
   \(\Rightarrow p_1 + 2\sum_{i=2}^{k-1} p_i + 2p_k \le 2T\)  
   \(\Rightarrow p_1 + 2\sum_{i=2}^{k} p_i \le 2T\)  
   \(\Rightarrow \sum_{i=1}^k p_i + \sum_{i=2}^k p_i \le 2T\)  
   \(\Rightarrow S_k + (S_k - p_1) \le 2T\)  
   \(\Rightarrow 2S_k - p_1 \le 2T\)  
   \(\Rightarrow S_k \le T + p_1/2\) — not matching.

   Let’s test with example 2:  
   p = [50,50,50,50], T=150.  
   S1=50, S2=100, S3=150, S4=200.  
   Condition \( S_k \le T + p_k \):  
   k=1: 50 ≤ 200 ok  
   k=2: 100 ≤ 200 ok  
   k=3: 150 ≤ 200 ok  
   k=4: 200 ≤ 200 ok — but it’s impossible! So condition is wrong.

   Let’s derive properly.

   We need to place \( m_i \) such that:
   - \( p_i \le m_i \le 2T - p_i \)
   - \( |m_i - m_j| \ge p_i + p_j \)

   This is equivalent to:  
   Sort \( p \) ascending.  
   The minimal possible spread is achieved by placing them as close as possible:  
   \( m_1 = p_1 \)  
   \( m_2 = m_1 + p_1 + p_2 = 2p_1 + p_2 \)  
   \( m_3 = m_2 + p_2 + p_3 = 2p_1 + 2p_2 + p_3 \)  
   ...  
   \( m_k = 2\sum_{i=1}^{k-1} p_i + p_k \)

   We need \( m_k \le 2T - p_k \) for all k.  
   So:
   \[
   2\sum_{i=1}^{k-1} p_i + p_k \le 2T - p_k
   \]
   \[
   2\sum_{i=1}^{k-1} p_i + 2p_k \le 2T
   \]
   \[
   \sum_{i=1}^{k} p_i + \sum_{i=1}^{k-1} p_i \le 2T
   \]
   \[
   S_k + S_{k-1} \le 2T
   \]
   where \( S_0 = 0 \).

   So condition: For all k, \( S_k + S_{k-1} \le 2T \).

   Check example 2:  
   S0=0, S1=50, S2=100, S3=150, S4=200.  
   k=1: 50+0=50 ≤ 300 ok  
   k=2: 100+50=150 ≤ 300 ok  
   k=3: 150+100=250 ≤ 300 ok  
   k=4: 200+150=350 > 300 → impossible. Correct.

   So we can check LOAD 1 and LOAD 2 by sorting their p's and checking this condition.

Now, the problem says exactly one subset is contradictory. So we check:
- For each i, if p1+p2 > T → JOB i is impossible.
- For class 1: collect all p1's, sort, check condition.
- For class 2: collect all p2's, sort, check condition.

Exactly one will fail.

Implementation:

```python
import sys

def main():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    j = int(data[0])
    T = int(data[1])
    p1s = []
    p2s = []
    idx = 2
    for i in range(1, j+1):
        p1 = int(data[idx]); p2 = int(data[idx+1])
        idx += 2
        p1s.append(p1)
        p2s.append(p2)
        if p1 + p2 > T:
            print(f"JOB {i}")
            return

    # Check LOAD 1
    arr = sorted(p1s)
    S = 0
    prev = 0
    for k, val in enumerate(arr, start=1):
        S += val
        if S + prev > 2 * T:
            print("LOAD 1")
            return
        prev = S

    # Check LOAD 2
    arr = sorted(p2s)
    S = 0
    prev = 0
    for k, val in enumerate(arr, start=1):
        S += val
        if S + prev > 2 * T:
            print("LOAD 2")
            return
        prev = S

if __name__ == "__main__":
    main()
```
