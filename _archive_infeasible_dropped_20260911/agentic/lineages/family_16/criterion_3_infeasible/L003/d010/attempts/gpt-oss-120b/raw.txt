**Solution Explanation**

For every index `i` we have two elements  

* primary – parameter `p1[i]` (class 1)  
* secondary – parameter `p2[i]` (class 2)

All rules are linear, therefore feasibility can be expressed by simple
inequalities.

--------------------------------------------------------------------

#### 1.  When does a single index `i` contradict the rules `1,2,3,5` ?

Only the two elements of this index are considered.

```
end1 - start1 = p1                (span)
end2 - start2 = p2                (span)
0 ≤ start1 , start2
end1 , end2 ≤ T                    (bounds)
end1 ≤ start2                      (precedence)
```

From the span equations  

```
end1 = start1 + p1
end2 = start2 + p2
```

Insert them into the other constraints

```
0 ≤ start1 ≤ T - p1
0 ≤ start2 ≤ T - p2
start1 + p1 ≤ start2
```

A feasible `start1` must satisfy  

```
start1 ≤ T - p1                (1)
start1 ≤ T - p2 - p1           (2)
```

Thus a solution exists **iff**

```
p1 ≤ T            and            p1 + p2 ≤ T                (★)
```

If (★) is violated, the subset for this index is impossible, i.e. the
certificate is `JOB i`.

--------------------------------------------------------------------

#### 2.  When does a whole class contradict the rules `1,2,3,4` ?

Consider only class c (all primary elements for `c = 1`,
all secondary elements for `c = 2`).

For an element with parameter `p`

```
end = start + p
sum = start + end = 2·start + p
```

Bounds give  

```
0 ≤ start ≤ T - p          →   p ≤ sum ≤ 2·T - p          (interval I(p))
```

Separation between two elements `A , B` of the same class:

```
|sumA - sumB| ≥ pA + pB
```

If we order the elements by their `sum` values,
consecutive elements must differ by at least `pprev + pcur`.
Hence we can place them greedily:

```
sort all parameters p increasingly
prev_sum = -∞
for p in sorted list
        low  = p                     (left end of I(p))
        high = 2·T - p               (right end of I(p))
        need = max(low, prev_sum + pprev + p)   (if there is a previous)
        if need > high → impossible
        prev_sum = need
        pprev = p
```

If the loop finishes, the whole class is feasible; otherwise it is
contradictory and the certificate is `LOAD c`.

--------------------------------------------------------------------

#### 3.  Whole algorithm

* Scan all indices.
  * If `p1[i] > T` **or** `p1[i] + p2[i] > T` → output `JOB i`.
* No such index exists ⇒ the contradiction must be inside a class.
  * Test class 1 with the greedy procedure above.
    * If infeasible → `LOAD 1`.
  * Otherwise class 2 must be infeasible → `LOAD 2`.

The statement guarantees that exactly one of the two possibilities
occurs, therefore the answer is unique.

--------------------------------------------------------------------

#### 4.  Correctness Proof  

We prove that the algorithm always prints the required certificate.

---

##### Lemma 1  
For a fixed index `i` the rules `1,2,3,5` are feasible **iff**
`p1[i] ≤ T` and `p1[i] + p2[i] ≤ T`.

**Proof.**  
Derived in section&nbsp;1. The inequalities are necessary and sufficient
for the existence of `start1 , start2`. ∎



##### Lemma 2  
If for some index `i` condition of Lemma&nbsp;1 is violated,
the subset `JOB i` is contradictory.

**Proof.**  
Violation means the four rules cannot be satisfied for that index,
exactly the definition of a contradictory `JOB i`. ∎



##### Lemma 3  
For a fixed class `c` the greedy algorithm succeeds **iff**
there exist numbers `sum` for all its elements satisfying the bounds
`p ≤ sum ≤ 2T‑p` and the separation
`|sumA‑sumB| ≥ pA + pB`.

**Proof.**  
Sort the elements by the required `sum`.  
For the first element any value in its interval works; the algorithm
chooses the left end `p`.  
Assume the algorithm has placed the first `k‑1` elements respecting all
constraints, with the last placed value `prev_sum`.  
For element `k` any feasible `sum` must be at least `prev_sum + pprev + pk`
(because of separation) and also at least its own lower bound `pk`.  
The algorithm picks the smallest possible such value.
If this value exceeds the upper bound `2T‑pk`, no feasible `sum` exists for
element `k`, hence the whole system is impossible.
Conversely, if the algorithm never exceeds an upper bound, the constructed
values satisfy all constraints. ∎



##### Lemma 4  
If the greedy test for class `c` fails, the rule subset `LOAD c` is
contradictory.

**Proof.**  
Failure means no assignment of `sum` values exists, which by Lemma&nbsp;3
means the rules `1,2,3,4` cannot be satisfied for that class. ∎



##### Lemma 5  
If the greedy test for class `c` succeeds, the rule subset `LOAD c` is
feasible.

**Proof.**  
Directly from Lemma&nbsp;3: the algorithm provides a concrete feasible
assignment, therefore the subset is not contradictory. ∎



##### Theorem  
The algorithm outputs

* `JOB i` for the unique index whose subset `JOB i` is contradictory,
  or
* `LOAD c` for the unique class whose subset `LOAD c` is contradictory.

**Proof.**  

*If an index violates Lemma 1.*  
The algorithm detects the first such index and prints `JOB i`.  
By Lemma 2 this subset is contradictory.  
Because the statement guarantees uniqueness, no other index violates
Lemma 1 and the classes are feasible (Lemma 5), so the answer is correct.

*Otherwise all indices satisfy Lemma 1.*  
Hence every `JOB i` subset is feasible.  
The overall system is still contradictory, therefore one of the two
class subsets must be contradictory.  
The algorithm tests class 1; if it fails, Lemma 4 gives `LOAD 1`,
otherwise class 2 must fail and Lemma 4 gives `LOAD 2`.  
In both cases the printed certificate is the unique contradictory
subset. ∎



--------------------------------------------------------------------

#### 5.  Complexity Analysis  

*Scanning indices* – `O(j)` time.  
*Greedy test* for a class – sorting `j` numbers: `O(j log j)` time,
`O(j)` memory.  
Overall: `O(j log j)` time, `O(j)` additional memory, well within limits
(`j ≤ 2·10⁵`).

#### 6.  Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    T = int(next(it))
    p1 = [0] * n
    p2 = [0] * n
    for i in range(n):
        p1[i] = int(next(it))
        p2[i] = int(next(it))

    # 1) look for contradictory JOB
    for i in range(n):
        if p1[i] > T or p1[i] + p2[i] > T:
            sys.stdout.write(f"JOB {i+1}\n")
            return

    # no JOB fails -> contradiction is in a class
    def class_feasible(params):
        params.sort()
        prev_sum = None
        prev_p = None
        for p in params:
            low = p
            high = 2 * T - p
            if prev_sum is None:
                cur = low
            else:
                cur = max(low, prev_sum + prev_p + p)
            if cur > high:
                return False
            prev_sum = cur
            prev_p = p
        return True

    if not class_feasible(p1[:]):          # class 1
        sys.stdout.write("LOAD 1\n")
    else:
        # class 2 must be contradictory
        sys.stdout.write("LOAD 2\n")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
