<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system processes **j** jobs through exactly **two** sequential stages. Every job must clear stage 1 completely before it can enter stage 2. For each job you are given its required duration in stage 1 and in stage 2. A stage can only advance one job at any given moment.

There is a required time limit **T**: every job must be completely finished by time **T**.

For every input in this problem it is **guaranteed that the time limit cannot be met**, no matter how the jobs are ordered. Your task is not to search for a schedule; it is to **prove** the time limit is impossible by identifying a localized structural bottleneck that alone strictly exceeds the time limit.

Exactly one of the following bottlenecks will always apply. Print the one that holds:

- **Isolated path bottleneck.** A specific job requires a sequence of operations that cannot fit within the time limit, even if it were the only job in the system.
  Print: `JOB i` — where **i** (1-based) is a job whose isolated processing time exceeds **T**.

- **Stage capacity bottleneck.** A specific stage must perform an amount of work that cannot be completed by the deadline, even if jobs experienced no delays waiting for the other stage.
  Print: `LOAD c` — where **c** is 1 or 2, representing a stage whose total required active time exceeds **T**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations of a job in stage 1 and stage 2.

## Output

Print a single line: `JOB i` (a job whose isolated processing time exceeds T) or `LOAD c` (a stage c whose total required active time exceeds T).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 time units in stage 1 followed immediately by 60 time units in stage 2. Even ignoring all other jobs, its isolated processing time is 130, which strictly exceeds the limit of 100. Thus `JOB 1` proves the deadline is impossible.

In Example 2, no single job's isolated processing time exceeds 150. However, stage 1 must be active for 50, 50, 50, and 50 time units. Because a stage can only advance one job at any given moment, its total capacity requirement is 200, which strictly exceeds 150. Thus `LOAD 1` is the certificate.
</STATEMENT>
<RATIONALE>
Replaced the explicit summing formulas in the bullet points with physical descriptions of the bottlenecks (isolated processing path and stage capacity limits). This forces the model to reason about the system's mechanics to deduce that "isolated processing time" translates to `p1 + p2` and "total required active time" translates to the sum of a stage's durations, rather than just copying the formulas from the text.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions that trigger `JOB i` and `LOAD c` remain exactly `p1 + p2 > T` and `sum(p_c) > T`, ensuring identical outputs for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires an O(N) single-pass check to certify impossibility, keeping it in the same complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "isolated processing time" as just the maximum of the two stages rather than their sum, though the phrase "requires a sequence of operations" and the worked example strongly imply the sum.
</RISK>
