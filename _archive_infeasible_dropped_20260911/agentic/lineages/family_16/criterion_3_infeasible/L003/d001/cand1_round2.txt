# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system processes **j** jobs through exactly **two** sequential stages. Every job must clear stage 1 completely before it can enter stage 2. For each job you are given its required duration in stage 1 and in stage 2. A stage can only advance one job at any given moment.

There is a required time limit **T**: every job must be completely finished by time **T** (starting from time 0).

For every input in this problem, it is **guaranteed that the time limit cannot be met**, no matter how the jobs are scheduled. Your task is not to search for a schedule; it is to **prove** the time limit is impossible by identifying a structural bottleneck that trivially exceeds **T**.

You must output a certificate of impossibility using one of the following formats:

- `JOB i` : The inherent sequential work required for job **i** (1-based index) makes it impossible for this job to complete by time **T**, even if it were the only job in the entire system.
- `LOAD c` : The sheer volume of work assigned to stage **c** (**c** is 1 or 2) makes it impossible for the stage to process everything by time **T**, even if the stage never sits idle.

It is guaranteed that at least one such bottleneck exists. If there are multiple valid certificates (e.g., multiple jobs that cannot complete in time alone, or both stages are overloaded), you may print any one of them.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations of a job in stage 1 and stage 2.

## Output

Print a single line containing a valid certificate: either `JOB i` (where job **i** cannot finish by **T** alone) or `LOAD c` (where stage **c**'s total work exceeds **T**). If more than one valid certificate exists, print any one of them.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 units of time in stage 1 and 60 units in stage 2. Since it must clear stage 1 before entering stage 2, it requires at least 130 units of time from start to finish. This exceeds the limit of 100, so `JOB 1` is a valid certificate.

In Example 2, stage 1 must process four jobs, each taking 50 units of time. Since a stage can only process one job at a time, stage 1 requires at least 200 units of continuous operation. This exceeds the limit of 150, so `LOAD 1` is a valid certificate.
</STATEMENT>
<RATIONALE>
I removed the explicit arithmetic formulas (`p1 + p2 > T` and total load `> T`) that allowed models to pattern-match the solution without understanding the workflow. Instead, I described the physical meaning of the two failure modes (a single job's sequential path, or a single stage's total volume), forcing the models to deduce the inequalities from the mechanics of the two-stage system. I also clarified that any valid certificate may be printed, addressing previous ambiguities.
</RATIONALE>
<PRESERVED_ANSWER>
The definitions of valid `JOB i` and `LOAD c` certificates mathematically reduce to exactly `p1 + p2 > T` and `sum(p_c) > T`, ensuring any output valid for the seed remains valid here.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires a simple linear scan to check individual job totals and stage sums, keeping it in the same O(N) complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misunderstand "inherent sequential work" and fail to add `p1` and `p2`, but the definition is unambiguous given the description of the two stages and the explicit walkthrough in the Note.
</RISK>
