# Impossible Data Pipeline: Error Diagnosis

Time limit: 2 s   Memory limit: 256 MB

## Description

You are analyzing a data pipeline that processes **j** distinct data streams. The pipeline consists of two sequential network nodes, Node 1 and Node 2.
- A stream must completely finish transferring through Node 1 before it can begin transferring through Node 2.
- A node can only route one stream at a time.
- Once a stream begins at a node, it transfers continuously without interruption.
- Stream $i$ requires $p_{i,1}$ milliseconds at Node 1 and $p_{i,2}$ milliseconds at Node 2.
- The entire pipeline operates within a fixed session window of **T** milliseconds. All streams must be fully received by the end of Node 2 before the session expires.

The provided session configurations are mathematically impossible to fulfill. Your task is to output a diagnostic code that pinpoints a fundamental reason for the failure. The diagnostic code must be exactly one of the following formats:

* `JOB i` (where **i** is the 1-based index of the stream): The stream's own end-to-end latency floor (the absolute minimum time required to traverse both nodes sequentially) exceeds the session window, making it impossible even if it had exclusive access to the pipeline.
* `LOAD c` (where **c** is either 1 or 2): Node **c** is over-provisioned. The total aggregate transmission time required by all streams at this node exceeds the session window, making it impossible even if the node transmitted continuously with zero idle time and sequential dependencies were ignored.

The test data is designed such that every configuration fails due to exactly one of these two diagnostic categories. Output the valid diagnostic code. (If multiple streams or nodes satisfy a category, you may output any single valid code.)

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers $p_{i,1}$ and $p_{i,2}$ (1 ≤ $p_{i,1}$, $p_{i,2}$ ≤ 1000000): the required transmission milliseconds for stream $i$ at Node 1 and Node 2.

## Output

Print a single line containing a valid diagnostic code: either `JOB i` (where stream **i**'s latency floor exceeds the window) or `LOAD c` (where Node **c**'s aggregate time exceeds the window).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is correct because stream 1's end-to-end latency floor requires 70 milliseconds at Node 1 followed immediately by 60 milliseconds at Node 2, totaling 130 milliseconds. This strictly exceeds the 100-millisecond session window.

In Example 2, `LOAD 1` is correct because Node 1 must transmit 4 streams for 50 milliseconds each. This requires 200 milliseconds of continuous transmission time, which strictly exceeds the 150-millisecond session window.
