<STATEMENT>
# Impossible Schedule: Audit the Facility

Time limit: 2 s   Memory limit: 256 MB

## Description

You are auditing a cargo inspection facility that processes **j** containers. The facility has two strict processing stages: the X-ray scanner (Stage 1) and the Manual Search bay (Stage 2). 
Each container $i$ (for $1 \le i \le j$) requires exactly $p_{i,1}$ minutes of continuous processing in the X-ray scanner, followed immediately or later by $p_{i,2}$ minutes of continuous processing in the Manual Search bay.

The facility operates under the following strict physical and temporal rules:
- **Processing Durations:** Container $i$ occupies the X-ray scanner for $p_{i,1}$ uninterrupted minutes and the Manual bay for $p_{i,2}$ uninterrupted minutes.
- **Sequential Routing:** A container cannot begin its Manual Search until its X-ray scan has fully concluded.
- **Exclusive Access:** The X-ray scanner can process at most one container at any given time. Similarly, the Manual Search bay can process at most one container at any given time.
- **Operating Window:** The facility opens at minute 0. All operations for all containers must be completely finished by minute **T**, at which point the facility shuts down.

You are given a manifest of containers. It is guaranteed that for every test case, no valid schedule exists that satisfies all rules simultaneously. The facility manager needs an audit code explaining the primary reason for this impossibility.

To ensure standardized reporting, you must evaluate the following failure modes in order, and output the code for the highest-precedence mode that applies:

**Precedence 1: Isolated Container Failure**
Code: `JOB i` (where **i** is the 1-based index of the container).
Applies if container $i$ is fundamentally too long for the window. Even if we suspended the Exclusive Access rule—allowing container $i$ to be processed simultaneously with any other containers—it would still not finish by minute **T** due to its own Processing Durations and the Sequential Routing rule.
*(If multiple containers qualify, output the one with the smallest index $i$.)*

**Precedence 2: Isolated Stage Bottleneck**
Code: `LOAD c` (where **c** is either 1 or 2).
Applies if stage $c$ is fundamentally overburdened. Even if we suspended the Sequential Routing rule—allowing all containers to be available for stage $c$ at minute 0 regardless of their status in the other stage—stage $c$ alone could not finish processing everyone by minute **T** due to the Exclusive Access rule.
*(If both stages qualify, output `LOAD 1`.)*

**Precedence 3: Coupled Scheduling Conflict**
Code: `INTERLOCK`
Applies if the schedule is impossible under the full rules, but neither of the above isolated failures occur. The impossibility arises purely from the interaction between Sequential Routing and Exclusive Access across multiple containers.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required processing times of container $i$ in Stage 1 and Stage 2.

## Output

Print a single line containing the appropriate audit code: `JOB i`, `LOAD c`, or `INTERLOCK`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for container 1, the Sequential Routing rule dictates it must complete 70 minutes of X-ray followed by 60 minutes of Manual Search. Even without waiting for other containers (suspending Exclusive Access), this requires 70 + 60 = 130 minutes of continuous time. Since 130 > 100, it cannot meet the window. `JOB 1` applies.

In Example 2, for Stage 1, the Exclusive Access rule dictates it must process 4 containers for 50 minutes each, one at a time. This requires 4 × 50 = 200 minutes of active runtime. Since 200 > 150, `LOAD 1` applies. (No individual container exceeds the window alone, as 50 + 1 = 51 ≤ 150, so Precedence 1 does not apply).
</STATEMENT>
<RATIONALE>
I removed the explicit problem guarantee that only JOB or LOAD certificates apply by introducing a third `INTERLOCK` certificate for coupled contradictions. I redefined the JOB and LOAD certificates not as mathematical inequalities, but as physical "relaxations" (suspending specific facility rules). A model must deduce that suspending Exclusive Access reduces a container's constraint to `p1+p2 > T`, and suspending Sequential Routing reduces a stage's constraint to `sum(pc) > T`. Pattern-matching models will fail to translate the physical relaxations into the correct arithmetic or will attempt to implement a full scheduling solver for the `INTERLOCK` case.
</RATIONALE>
<PRESERVED_ANSWER>
The strict precedence order (JOB i, then LOAD c, then INTERLOCK) perfectly mirrors the conditional logic of the intended algorithm, ensuring identical outputs for all inputs where a JOB or LOAD violation exists (which the seed guarantees is all of them).
</PRESERVED_ANSWER>

The problem still requires only O(N) independent checks for the JOB and LOAD thresholds; the INTERLOCK condition never needs to be explicitly simulated because it acts solely as a logical fallback.
</PRESERVED_CLASS>
