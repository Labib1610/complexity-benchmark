# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are managing a manufacturing process with exactly 2 sequential machines, numbered 1 and 2. 
You are given a set of **j** jobs to process. Each job $i$ (for $1 \le i \le j$) requires a continuous processing block of $p_{i,1}$ hours on machine 1, and subsequently a continuous processing block of $p_{i,2}$ hours on machine 2.

A valid production schedule must satisfy all of the following rules:
- **Duration:** Job $i$ occupies machine 1 for exactly $p_{i,1}$ hours and machine 2 for exactly $p_{i,2}$ hours.
- **Sequential routing:** For every job $i$, its processing on machine 2 cannot begin until its processing on machine 1 has completely finished.
- **Exclusive access:** Each machine can process at most one job at any given time. Jobs cannot overlap on the same machine.
- **Global deadline:** All processing for all jobs across both machines must be completely finished by time $T$. No job can start before time 0.

For every test input provided to your program, it is guaranteed that no valid production schedule exists. Your task is to output a short certificate that identifies a localized reason for this impossibility.

You must evaluate the following failure conditions and output a corresponding certificate. If multiple valid certificates exist across or within the conditions below, you may output any one of them.

* **Single-Job Bottleneck:** Check if there is any individual job $i$ that cannot meet the deadline even if it had exclusive, uninterrupted access to both machines. If such a job exists, print `JOB i` (where **i** is a 1-based index).
* **Machine Overload:** Check if either machine is assigned a total volume of work that exceeds the deadline, even if we completely ignore the sequential routing dependencies between the two machines. If such a machine exists, print `LOAD c` (where **c** is either 1 or 2).
* **Coupled Contradiction:** If the impossibility is not caused by a single-job bottleneck or a single-machine overload, but rather by the complex sequential interactions of multiple jobs, print `COMPLEX`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times of job $i$ on machine 1 and machine 2 respectively.

## Output

Print a single line containing the applicable certificate: `JOB i`, `LOAD c`, or `COMPLEX`. 
If multiple valid certificates exist (e.g., multiple overloaded machines), you may print any one of them.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is the certificate because for job 1, the sequential routing requires it to spend 70 hours on machine 1 and then 60 hours on machine 2. The absolute minimum time to complete job 1 is $70 + 60 = 130$ hours, which strictly exceeds the global deadline of 100.
In Example 2, `LOAD 1` is the certificate because machine 1 is assigned 4 jobs, each requiring 50 hours. Because the machine has exclusive access (no overlap), it requires at least $4 \times 50 = 200$ hours to process all of them, which strictly exceeds the global deadline of 150.
