# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory processes j jobs through exactly two machines. Every job is processed on machine 1 first and then on machine 2. For each job you are given its processing time on machine 1 and on machine 2. Each machine processes only one job at a time, and a job reaches machine 2 only after finishing on machine 1.

There is a required deadline T: every job must be completely finished by time T.

While analyzing all possible orderings to find a valid schedule is a large task, for every input in this problem, no sequence of jobs can possibly meet the deadline. Your task is to output a certificate that proves the deadline is unattainable. Every input is guaranteed to succumb to exactly one of the following two categories of bottlenecks. Print the certificate for the category that applies:

- Sequential bottleneck: The minimal end-to-end processing duration of a specific job strictly exceeds T. Print: `JOB i` — where i (1-based) identifies such a job.
- Volume bottleneck: The aggregate active time required by a single machine to process all its assigned operations strictly exceeds T. Print: `LOAD c` — where c is a machine number (1 or 2) causing this bottleneck.

## Input

The first line contains two integers j and T (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next j lines contains two integers p1 and p2 (1 ≤ p1, p2 ≤ 1000000): the processing times of a job on machine 1 and machine 2.

## Output

Print a single line containing either `JOB i` (if the sequential bottleneck category applies) or `LOAD c` (if the volume bottleneck category applies), representing the valid certificate.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 + 60 = 130 time units from start to finish. Since 130 > 100, `JOB 1` proves the deadline is impossible. In Example 2, no single job's sequential duration exceeds 150, but machine 1 must process 50+50+50+50 = 200 units of work in total. Since 200 > 150, `LOAD 1` is the certificate.
</STATEMENT>
<RATIONALE>
I restored the exclusive reason-category guarantee exactly as required to fix the gate rejection. To prevent models from pattern-matching the explicit sum formulas, I replaced the direct mathematical descriptions (`p1 + p2 > T` and `total work > T`) with conceptual scheduling terms (`minimal end-to-end processing duration` and `aggregate active time`), forcing them to reason about what those terms mean in the context of the problem.
</RATIONALE>
<PRESERVED_ANSWER>
The criteria for outputting `JOB i` or `LOAD c` remain exactly equivalent to checking if a job's sum exceeds T or a machine's total load exceeds T, so the identical outputs are required.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an O(N) impossibility certification task where the solver must check local structural bottlenecks.
</PRESERVED_CLASS>
