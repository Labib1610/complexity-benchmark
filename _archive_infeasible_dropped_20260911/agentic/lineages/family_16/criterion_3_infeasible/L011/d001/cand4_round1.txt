# Problem C — Unreachable Sync: Rejection Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

A communications satellite must process $j$ data synchronization requests (referred to as `JOB`s in the system logs) over two distinct channels. Every `JOB` must first be uploaded via the Uplink (channel 1) and then downloaded via the Downlink (channel 2). For each `JOB`, you are given the time it takes to complete the upload on channel 1 and the time it takes to complete the download on channel 2. Each channel can transmit only one `JOB` at a time, and a `JOB` can only begin its download phase after its upload phase has fully concluded.

The satellite will only remain in line-of-sight for a strict time window of $T$ milliseconds. Every `JOB` must be completely finished before this window closes.

There are $j!$ possible permutations for ordering these transmissions. While analyzing all possible sequences to find a valid schedule is a large task, for every input provided in this problem, no valid transmission sequence can possibly fit within the window $T$. Your task is to output a rejection certificate that proves the time window is unattainable. Every input is guaranteed to satisfy exactly one of the following properties. Print the one that holds:

- A single request is too long. If some `JOB`'s upload and download durations add up to more than $T$, that `JOB` alone (channel 1 then channel 2, in sequence) cannot finish by $T$. Print: `JOB i` — where $i$ (1-based) is such a request.

- A channel is overloaded. A channel transmits its phase for all `JOB`s one at a time, so it requires at least the sum of all its assigned durations. If the total duration on channel 1 (or channel 2) exceeds $T$, the time window is impossible to meet. Print: `LOAD c` — where $c$ is 1 or 2 and the total duration on channel $c$ exceeds $T$.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the transmission times in milliseconds for a `JOB` on channel 1 and channel 2, respectively.

## Output

Print a single line: `JOB i` (a `JOB` whose $p_1 + p_2$ exceeds $T$) or `LOAD c` (a channel $c$ whose total load exceeds $T$).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, request 1 needs $70 + 60 = 130 > 100$ milliseconds in sequence, so `JOB 1` proves the window is impossible. In Example 2, no single request exceeds 150 milliseconds, but channel 1 must process $50+50+50+50 = 200 > 150$ milliseconds of transmissions in total, so `LOAD 1` is the certificate.
