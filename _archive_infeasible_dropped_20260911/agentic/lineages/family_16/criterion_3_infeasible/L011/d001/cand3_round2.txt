<STATEMENT>
# Problem C — Audit of an Impossible Timeline

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant processes j items through two sequential stages. Every item must first complete processing at stage 1, and only then can it be processed at stage 2. Each stage can only handle one item at a time. The duration required for each item at stage 1 and stage 2 is provided.

Management has set a strict timeline T, meaning all items must be entirely finished by time T.

Your task is to output a certificate that proves the optimal two-stage schedule cannot possibly meet the deadline. Based on the constraints of this process, an impossible deadline can be certified by identifying a structural bottleneck that prevents any sequence of items from finishing on time. You must evaluate the workload and print the failure code corresponding to the bottleneck:

- `JOB i` : if item i (1-based index) requires more sequential time than the timeline permits (its duration on stage 1 plus its duration on stage 2 is strictly greater than T).
- `LOAD c` : if stage c (where c is 1 or 2) is assigned more total active time than the timeline permits (the sum of durations of all items on stage c is strictly greater than T).

The test data guarantees that exactly one valid certificate exists for each scenario.

## Input

The first line contains two integers j and T (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next j lines contains two integers p1 and p2 (1 ≤ p1, p2 ≤ 1000000): the processing times of an item on stage 1 and stage 2.

## Output

Print a single line containing either `JOB i` (for an item whose p1 + p2 exceeds T) or `LOAD c` (for a stage c whose total load exceeds T).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, item 1 requires 70 + 60 = 130 > 100 time units sequentially, so `JOB 1` certifies the timeline is impossible. In Example 2, no single item exceeds 150, but stage 1 must process 50+50+50+50 = 200 > 150 units of work in total, so `LOAD 1` is the certificate.
</STATEMENT>
<RATIONALE>
Removed the explicit framing that exactly one of the two properties is guaranteed to hold as a direct alternative to analyzing all orderings. Instead, the task is framed as certifying the infeasibility of the optimal two-stage schedule by identifying a bottleneck. This forces the model to understand that the two provided conditions are sufficient certificates for infeasibility, rather than just blindly trusting a structural hint to skip scheduling logic.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for outputting `JOB i` and `LOAD c` are mathematically identical to the seed (`p1 + p2 > T` and `sum(pc) > T`), ensuring the exact same output for all test cases.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The solution still requires an O(N) scan to check individual job sums and total machine loads, keeping it in the same O(N) complexity class.
</PRESERVED_CLASS>
<RISK>
The phrase "optimal two-stage schedule" might cause models to attempt to simulate or compute the optimal schedule (e.g., using Johnson's rule) instead of just checking the certificate conditions.
</RISK>
