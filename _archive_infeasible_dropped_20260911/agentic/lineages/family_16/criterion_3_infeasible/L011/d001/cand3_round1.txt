<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory processes a set of jobs through exactly two machines. Every job is processed on machine 1 first and then on machine 2. Each machine processes only one job at a time, and a job reaches machine 2 only after its operation on machine 1 is complete.

There is a strict deadline $T$: every job must be completely finished by time $T$.

While analyzing all possible orderings to find a valid schedule is a large task, for every input in this problem, no sequence of jobs can possibly meet the deadline. Your task is to output a certificate that reflects the infeasibility of the optimal two-machine schedule.

You must issue a certificate reflecting the root cause of the infeasibility. Output the appropriate format:
- `JOB i` — if the $i$-th job (1-based) cannot be completed by the deadline even if it were the only job in the factory.
- `LOAD c` — if machine $c$ (1 or 2) cannot finish its required operations by the deadline even if there were no delays waiting for the other machine.

For every test case, it is guaranteed that exactly one such root cause will be present.

The factory's intake buffer stores a positive number of jobs $j$ up to a maximum equivalent to a full grid of 400 rows and 500 columns. The deadline $T$ is a positive integer up to the total number of milliseconds in exactly 11 days, 13 hours, 46 minutes, and 40 seconds. Each processing time is a positive integer at most the square of one thousand.

## Input

The first line contains two integers $j$ and $T$.
Each of the next $j$ lines contains two integers $p_1$ and $p_2$: the processing times of that job on machine 1 and machine 2.

## Output

Print a single line: `JOB i` (where $i$ is the 1-based index of the job) or `LOAD c` (where $c$ is the machine number, 1 or 2), depending on which certificate proves the schedule is impossible.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 time units on machine 1 and 60 on machine 2. Even if it were the only job in the factory, its sequential processing would take 130 time units, which exceeds the deadline of 100. Thus, `JOB 1` is the certificate.

In Example 2, no single job exceeds the deadline on its own. However, machine 1 must process 4 jobs for 50 time units each. Even with no delays, machine 1 requires 200 time units of continuous operation, which exceeds the 150 deadline. Thus, `LOAD 1` is the certificate.
</STATEMENT>
<RATIONALE>
Removed the explicit mathematical formulas (`p1 + p2 > T` and `sum > T`) that models were pattern-matching to solve the problem without understanding the scheduling domain. Replaced them with logical descriptions of the physical root causes of infeasibility ("only job in the factory" and "no delays waiting for the other machine"). Also indirected the numerical bounds using physical equivalents (e.g., milliseconds in 11 days...) to force extraction of the limits rather than reading bare inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
The logical condition of a job failing "even if it were the only job" mathematically evaluates to exactly `p1 + p2 > T`, and a machine failing "even if there were no delays" evaluates to exactly `sum(p_c) > T`, meaning the exact same outputs are required for every input.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires a linear scan to check individual job sums and aggregate machine sums, keeping it in the same O(N) impossibility certification class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "no delays waiting for the other machine" as implying overlapping processing, though the text explicitly states "Each machine processes only one job at a time", which resolves this ambiguity.
</RISK>
