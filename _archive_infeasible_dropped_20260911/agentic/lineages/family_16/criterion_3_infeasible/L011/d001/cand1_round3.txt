<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory processes $j$ jobs through exactly two machines. Every job is processed on machine 1 first and then on machine 2. For each job you are given its processing time on machine 1 and on machine 2. Each machine processes only one job at a time, and a job reaches machine 2 only after finishing on machine 1.

There is a required deadline $T$: every job must be completely finished by time $T$.

There are $j!$ possible permutations for scheduling these jobs. For every input in this problem, the optimal two-machine schedule is infeasible and no sequence of jobs can possibly meet the deadline. Your task is to output a certificate that reflects this infeasibility.

You must provide a certificate using one of the following formats:
- `JOB i` — where $i$ (1-based) is a specific job whose processing times on the two machines add up to more than $T$. If multiple jobs exceed $T$, you may print `JOB i` for any such job $i$.
- `LOAD c` — where $c \in \{1, 2\}$ is a specific machine whose total processing time across all jobs exceeds $T$. If both machines exceed $T$, you may print `LOAD c` for either overloaded machine $c$.

It is guaranteed that for every input, at least one such certificate is valid. Print one valid certificate line.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the processing times of a job on machine 1 and machine 2.

## Output

Print a single line: `JOB i` (for any job whose $p_1 + p_2$ exceeds $T$) or `LOAD c` (for any machine $c$ whose total load exceeds $T$).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 needs $70 + 60 = 130 > 100$ time units in sequence, so `JOB 1` proves the deadline is impossible. In Example 2 no single job exceeds 150, but machine 1 must process $50+50+50+50 = 200 > 150$ units of work in total, so `LOAD 1` is a valid certificate.
</STATEMENT>
<RATIONALE>
Removed the explicit guarantee that "exactly one" of the conditions holds, replacing it with a requirement to certify the infeasibility of the optimal two-machine schedule, while guaranteeing that at least one valid certificate of the specified forms exists. This prevents models from blindly assuming an either/or structure (e.g., exiting with `LOAD 2` without checking it if the other two conditions fail) and forces them to actually evaluate the conditions for validity. Multiplicity handling was made completely explicit to resolve previous ambiguity.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for `JOB i` and `LOAD c` are mathematically identical to the seed, and the explicit allowance to print *any* valid certificate ensures the reference solution's output remains perfectly valid for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an impossible-deadline certification task (co-NP style witness verification) where the solver must identify a local sequence or global load bottleneck.
</PRESERVED_CLASS>
