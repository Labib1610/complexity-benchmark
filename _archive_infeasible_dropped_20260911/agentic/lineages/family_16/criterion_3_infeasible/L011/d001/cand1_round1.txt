<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory processes $j$ jobs through exactly two machines. Every job is processed on machine 1 first and then on machine 2. For each job you are given its processing time on machine 1 and on machine 2. Each machine processes only one job at a time, and a job reaches machine 2 only after finishing on machine 1.

There is a required deadline $T$: every job must be completely finished by time $T$.

There are $j!$ possible permutations for scheduling these jobs. Your task is to evaluate the optimal two-machine schedule (the ordering that minimizes the maximum completion time). For every input in this problem, the optimal schedule will fail to meet the deadline $T$.

You must output a certificate that reflects the structural bottleneck causing this infeasibility. The certificate must be formatted as one of the following:

- `JOB i` — where $i$ (1-based) is a job whose minimum possible completion time across both machines, even if it were the only job in the factory, strictly exceeds $T$.
- `LOAD c` — where $c \in \{1, 2\}$ is a machine whose total required processing time for the entire batch of jobs strictly exceeds $T$.

(For all provided test cases, the optimal schedule's failure can be attributed to at least one of these specific bottleneck certificates. If multiple apply, output any valid one).

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the processing times of a job on machine 1 and machine 2.

## Output

Print a single line containing a valid certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 130 time units in isolation, which strictly exceeds the deadline of 100, so `JOB 1` proves the deadline is impossible. In Example 2, no single job exceeds 150 in isolation, but machine 1 requires 200 total time units of processing for the entire batch. Since 200 > 150, `LOAD 1` is the certificate.
</STATEMENT>
<RATIONALE>
Removed the explicit formulas `p1 + p2 > T` and `total work > T` as well as the explicit instruction to just "print the one that holds". Instead, the problem frames the task as evaluating the infeasibility of the optimal two-machine schedule and outputting a structural bottleneck certificate. The bottleneck conditions are rephrased into physical descriptions ("minimum possible completion time across both machines" and "total required processing time"), forcing models to deduce the mathematical inequalities rather than relying on surface pattern matching from the text.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for `JOB i` and `LOAD c` are mathematically identical to the original $p_1 + p_2 > T$ and $\sum p_c > T$, meaning the same certificates remain valid for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains INFEASIBLE (co-NP style impossibility certification) because the task is still to evaluate local structural bounds that prove the global deadline cannot be met.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "minimum possible completion time across both machines" as meaning they need to compute the makespan of the optimal schedule first, rather than just summing the two processing times for a single job, but the phrase "even if it were the only job in the factory" resolves this ambiguity.
</RISK>
