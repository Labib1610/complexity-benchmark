# Problem C — Impossible Window: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are evaluating a manufacturing process with $j$ custom projects. There are exactly two machines: a primary unit and a secondary unit. Every project must be processed on the primary unit first, and then on the secondary unit. Each project requires a specified duration on the primary unit and a specified duration on the secondary unit.

A schedule assigns each task to a continuous time interval. A valid schedule must satisfy four conditions:
1. **Precedence**: For each project, its testing on the secondary unit must start at or after the moment its assembly on the primary unit ends.
2. **Capacity 1**: The primary unit may process at most one task at a time.
3. **Capacity 2**: The secondary unit may process at most one task at a time.
4. **Deadline**: All intervals for all projects must be entirely contained within the strict operating window of $[0, T]$ minutes.

For every input, it is guaranteed that the operating window $[0, T]$ is too short to fulfill all projects. The impossibility is always caused by exactly one of two bottleneck categories. Your task is to verify the projects and output a certificate for the category that applies:

- **Category 1 (Single Project Bottleneck)**: This applies if the precedence and deadline constraints for some project $i$ alone are impossible to satisfy. This occurs exactly when project $i$'s total sequential time (primary duration plus secondary duration) strictly exceeds $T$. If this category applies, output `JOB i` (where $i$ is the 1-based index of any such project).
- **Category 2 (Unit Capacity Bottleneck)**: This applies if the capacity and deadline constraints for some unit $c$ alone are impossible to satisfy. This occurs exactly when the total sum of durations of all projects on unit $c$ strictly exceeds $T$. If this category applies, output `LOAD c` (where $c=1$ for the primary unit, or $c=2$ for the secondary unit, for any such overloaded unit).

It is guaranteed that exactly one of these two bottleneck categories is the true cause of impossibility. If there are multiple valid certificates within the applicable category (for example, multiple projects exceed $T$, or both units exceed $T$), you may output any one of them.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in minutes for the project's assembly on the primary unit and its testing on the secondary unit, respectively.

## Output

Print a single line containing either `JOB i` (if Category 1 applies and project $i$ is a valid certificate) or `LOAD c` (if Category 2 applies and unit $c$ is a valid certificate).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, project 1 requires 70 minutes on the primary unit and then 60 minutes on the secondary unit. Since $70 + 60 = 130 > 100$, project 1 alone cannot fit in the window. This falls under Category 1, making `JOB 1` a valid certificate. 

In Example 2, no single project's sequential time exceeds 150. However, the primary unit must process four tasks of 50 minutes each. Since $4 \times 50 = 200 > 150$, the primary unit alone cannot complete its workload within the window. This falls under Category 2, making `LOAD 1` a valid certificate.
