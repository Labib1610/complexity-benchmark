# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are evaluating a manufacturing process with $j$ custom projects. Each project requires assembly on the primary unit for a specified duration, and testing on the secondary unit for a specified duration. 

A schedule assigns each task to a continuous time interval. A valid schedule must satisfy four conditions:
1. **Precedence**: For each project, its secondary unit testing interval must start at or after the moment its primary unit assembly interval ends.
2. **Capacity 1**: No two primary unit assembly intervals may overlap in time.
3. **Capacity 2**: No two secondary unit testing intervals may overlap in time.
4. **Deadline**: All intervals must be entirely contained within the strict operating window of $[0, T]$ minutes.

In scheduling analysis, we define the *utilization* of any task as its duration divided by the operating window $T$. A system cannot be scheduled if any individual resource bottleneck has a utilization strictly greater than $1$.

For every input, it is guaranteed that the operating window is too short to fulfill all projects, no matter how they are scheduled. Furthermore, exactly one of the following three bottlenecks will have a utilization strictly greater than $1$. Your task is to verify the projects and output the code for the bottleneck that applies:

- `JOB i` (where $i$ is the 1-based index of a project): The sequential path for project $i$, whose utilization is exactly the utilization of its assembly task plus the utilization of its testing task.
- `LOAD 1`: The primary unit, whose utilization is exactly the sum of the utilizations of all assembly tasks across all $j$ projects.
- `LOAD 2`: The secondary unit, whose utilization is exactly the sum of the utilizations of all testing tasks across all $j$ projects.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in minutes for the project's assembly on the primary unit and its testing on the secondary unit, respectively.

## Output

Print a single line containing either `JOB i` (if project $i$'s sequential path utilization strictly exceeds 1) or `LOAD c` (where $c$ is 1 for the primary unit or 2 for the secondary unit, if that unit's capacity utilization strictly exceeds 1).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the first project requires 70 minutes on the primary unit and then 60 minutes on the secondary unit. Its sequential utilization is $70/100 + 60/100 = 1.3$. Since $1.3 > 1$, this makes `JOB 1` the valid bottleneck. 

In Example 2, no individual project's sequential utilization exceeds 1. However, the primary unit is assigned four assembly tasks of 50 minutes each. The primary unit's capacity utilization is $50/150 + 50/150 + 50/150 + 50/150 \approx 1.333$. Since this strictly exceeds 1, `LOAD 1` is the valid bottleneck.
