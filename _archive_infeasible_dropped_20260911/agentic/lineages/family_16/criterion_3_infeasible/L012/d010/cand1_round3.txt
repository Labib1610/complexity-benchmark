# Spaceship Power Allocation Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

You are the chief engineer of a spaceship managing $j$ critical subsystems. Each subsystem requires exactly 2 distinct energy bursts to reboot: a **Capacitor Charge** burst and a **System Initialization** burst. 

The reboot sequence is strictly governed by the following safety constraints:
1. **Precedence**: For any given subsystem, its System Initialization burst cannot begin until its Capacitor Charge burst has completely finished. (Equality at the boundary is allowed; the initialization can start at the exact millisecond the charge ends).
2. **Capacitor Grid Capacity**: The ship's capacitor grid can process at most 1 Capacitor Charge burst at any given moment.
3. **Initialization Grid Capacity**: The ship's initialization grid can process at most 1 System Initialization burst at any given moment.
4. **Time Limit**: All bursts across all subsystems must finish processing at or before the strict operating deadline of $T$ milliseconds.

The ship's computer has determined that no valid sequence of operations can satisfy all four constraints simultaneously. To isolate the bottleneck, you must conduct three diagnostic checks. The input data guarantees that exactly one of the three checks will reveal a minimum required time strictly greater than $T$. You must output the corresponding error code for the check that proves $T$ is impossible to meet:

- **Diagnostic Check 1 (Output `JOB i`)**: Evaluate whether any individual subsystem is inherently too long. For a specific subsystem $i$, calculate the minimum time required to process its Capacitor Charge burst and its System Initialization burst. Since these two bursts must follow the precedence constraint (Constraint 1), they cannot overlap. If this minimum time for subsystem $i$ strictly exceeds $T$, output `JOB i` where $i$ is the 1-based index of the subsystem. If multiple subsystems exceed $T$, outputting any such index $i$ is acceptable.
- **Diagnostic Check 2 (Output `LOAD 1`)**: Evaluate whether the Capacitor Grid is inherently overloaded. Consider only the Capacitor Charge bursts for all $j$ subsystems. By Constraint 2, the grid must process these sequentially. Calculate the absolute minimum time required to process this specific workload. If this minimum time strictly exceeds $T$, output `LOAD 1`.
- **Diagnostic Check 3 (Output `LOAD 2`)**: Evaluate whether the Initialization Grid is inherently overloaded. Consider only the System Initialization bursts for all $j$ subsystems. By Constraint 3, the grid must process these sequentially. Calculate the absolute minimum time required to process this specific workload. If this minimum time strictly exceeds $T$, output `LOAD 2`.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in milliseconds for the subsystem's **Capacitor Charge** burst and its **System Initialization** burst, respectively.

## Output

Print a single line containing either `JOB i` (if Diagnostic Check 1 yields a minimum time $> T$ for subsystem $i$), `LOAD 1` (if Diagnostic Check 2 yields a minimum time $> T$), or `LOAD 2` (if Diagnostic Check 3 yields a minimum time $> T$).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under Diagnostic Check 1 for subsystem 1, we evaluate its individual requirements. Subsystem 1 must complete its 70 ms Capacitor Charge followed immediately by its 60 ms System Initialization. The earliest possible time to complete both is 130 ms. Since 130 ms strictly exceeds the 100 ms Time Limit, `JOB 1` is a valid bottleneck proof.

In Example 2, no individual subsystem exceeds the 150 ms limit under Diagnostic Check 1. However, under Diagnostic Check 2, we evaluate the Capacitor Grid's total workload. We must process all four 50 ms Capacitor Charge bursts one at a time due to the capacitor grid's capacity limit. The earliest possible time to finish all these bursts is 200 ms. Since 200 ms strictly exceeds the 150 ms Time Limit, `LOAD 1` is the valid bottleneck proof. Finishing exactly at the deadline would be allowed, but 200 ms strictly exceeds it.
</STATEMENT>
<RATIONALE>
I removed the explicit "set duration to 0" and "ignore capacity" instructions that previously handed the models the `sum(p1)` and `sum(p2)` formulas on a silver platter. Instead, the problem asks for the minimum time to process the isolated workloads sequentially. Models must now deduce that the minimum time to process a set of items with a serial capacity limit is exactly their sum, forcing them to reason about the scheduling constraints rather than pattern-matching the arithmetic shortcut.
</RATIONALE>
<PRESERVED_ANSWER>
The three diagnostic checks mathematically evaluate to exactly $p_1+p_2 > T$, $\sum p_1 > T$, and $\sum p_2 > T$, which are the exact same boundary conditions as the original experiments.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The solution remains $O(N)$ because the checks still only require calculating the sum of the input arrays and the pairwise sums, which is identical to the seed problem's logic.
</PRESERVED_CLASS>
<RISK>
Some models might misinterpret "minimum time required to process this specific workload" as implying they need to schedule the tasks optimally across both grids, missing the fact that for a single isolated serial resource, the minimum time is simply the sum of all task durations.
</RISK>
