# Spaceship Power Allocation Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

You are the chief engineer of a spaceship managing $j$ critical subsystems. Each subsystem requires two distinct energy bursts to reboot: a **Capacitor Charge** burst and a **System Initialization** burst. 

The reboot sequence is strictly governed by the following safety constraints:
1. **Precedence**: For any given subsystem, its System Initialization burst cannot begin until its Capacitor Charge burst has completely finished.
2. **Capacitor Grid Capacity**: The ship's capacitor grid can process at most one Capacitor Charge burst at any given moment.
3. **Initialization Grid Capacity**: The ship's initialization grid can process at most one System Initialization burst at any given moment.
4. **Time Limit**: All bursts across all subsystems must be fully completed within a strict operating window of $T$ milliseconds, starting at time 0.

The ship's computer has determined that no valid sequence of operations can satisfy all four constraints simultaneously. To isolate the bottleneck, you must conduct three hypothetical scheduling experiments. The input data guarantees that exactly one of the three experiment types will yield a metric strictly greater than $T$. You must output the corresponding error code for the experiment that proves $T$ is impossible to meet:

- **Experiment Type 1 (Output `JOB i`)**: Find a valid schedule of all $j$ subsystems (respecting Constraints 1, 2, and 3) that minimizes the absolute completion time of a specific subsystem $i$'s System Initialization burst. If this best-case completion time for subsystem $i$ exceeds $T$, output `JOB i` where $i$ is the 1-based index of the subsystem. If multiple subsystems exceed $T$ under this experiment, outputting any such index $i$ is acceptable.
- **Experiment Type 2 (Output `LOAD 1`)**: Find a valid schedule of all $j$ subsystems (respecting Constraints 1, 2, and 3) that minimizes the absolute time when the capacitor grid completely finishes processing the last of its $j$ Capacitor Charge bursts. If this best-case completion time for the capacitor grid exceeds $T$, output `LOAD 1`.
- **Experiment Type 3 (Output `LOAD 2`)**: Find a valid schedule of all $j$ subsystems (respecting Constraints 1, 2, and 3) that minimizes the elapsed time between the moment the initialization grid starts its very first System Initialization burst and the moment it completely finishes its final System Initialization burst. If this best-case elapsed working window for the initialization grid exceeds $T$, output `LOAD 2`.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in milliseconds for the subsystem's **Capacitor Charge** burst and its **System Initialization** burst, respectively.

## Output

Print a single line containing either `JOB i` (if Experiment Type 1 yields a metric $> T$ for subsystem $i$), `LOAD 1` (if Experiment Type 2 yields a metric $> T$), or `LOAD 2` (if Experiment Type 3 yields a metric $> T$).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under Experiment Type 1 for subsystem 1, we want to minimize its completion time. We can schedule its 70 ms Capacitor Charge first (finishing at 70 ms), followed immediately by its 60 ms System Initialization (finishing at 130 ms). Even if we delay other subsystems to achieve this, the earliest subsystem 1 can finish is 130 ms. Since 130 ms strictly exceeds the 100 ms Time Limit, `JOB 1` is a valid bottleneck proof.

In Example 2, no individual subsystem exceeds the 150 ms limit under Experiment Type 1. However, under Experiment Type 2, the capacitor grid must process four 50 ms bursts serially. The earliest it can possibly finish all of them is 200 ms. Since 200 ms strictly exceeds the 150 ms Time Limit, `LOAD 1` is the valid bottleneck proof.

<RATIONALE>
Replaced the explicit "zero-duration" and "ignore-capacity" experiment descriptions with mathematically equivalent scheduling minimizations. This forces the model to deduce that the minimum completion time of a prioritized job is its sum of durations, the minimum completion time of the first machine is its total workload, and the minimum active window of the second machine is its total workload, without giving away the simple summations in the text.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematically optimal schedules for the three metrics evaluate exactly to $p_{i,1}+p_{i,2}$, $\sum p_{i,1}$, and $\sum p_{i,2}$, making the condition for each output identical to the seed.
</PRESERVED_ANSWER>
