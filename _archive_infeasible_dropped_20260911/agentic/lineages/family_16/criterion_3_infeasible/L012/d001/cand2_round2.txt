<STATEMENT>
# Problem C — Impossible Window: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are auditing $j$ data-transfer routines (referred to as "jobs"). Each job consists of transmitting a header via Channel 1, followed by transmitting its payload via Channel 2. A channel can only handle one transmission at a time, and a job's payload transmission cannot begin until its header transmission has completely finished.

There is a strict operational window of $T$ microseconds. All jobs must fully complete both of their transmissions within this window.

For every test case in this problem, it is guaranteed that the time window $T$ is impossible to meet, regardless of the schedule. Furthermore, exactly one of two fundamental bottlenecks is guaranteed to be the applicable reason; you must print the corresponding certificate. The impossibility may stem from a sequential bottleneck: if a specific job $i$ (1-based) is so lengthy that, even if it were the only job in the system, its required sequence of Channel 1 and Channel 2 transmissions cannot finish within $T$ microseconds, print `JOB i`. Alternatively, it may stem from a volume bottleneck: if a specific channel $c \in \{1, 2\}$ is assigned so much total work across all jobs that it would need to be active for strictly greater than $T$ microseconds, print `LOAD c`. Because a channel processes one transmission at a time and a job's payload cannot start until its header finishes, these bottlenecks flawlessly certify the impossibility. 

You are not asked to find a schedule; only output the valid certificate implied by the guaranteed condition.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in microseconds for the job's header on Channel 1 and its payload on Channel 2.

## Output

Print a single line containing the applicable certificate. For every test case, exactly one condition is guaranteed to be true: either a single job's sequential requirements exceed the window (print `JOB i`, where $i$ is its 1-based index) or a channel's total required time exceeds the window (print `LOAD c`, where $c \in \{1, 2\}$).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the first job requires 70 microseconds on Channel 1 and then 60 microseconds on Channel 2. Even if it were the only job, its sequential transmissions require 130 microseconds. Since 130 > 100, it cannot complete within the window, making `JOB 1` the valid certificate. 

In Example 2, no individual job requires more than 150 microseconds sequentially. However, Channel 1 must be active for all four headers, totaling 200 microseconds. Since a channel processes one transmission at a time and 200 > 150, `LOAD 1` is the valid certificate.
</STATEMENT>
<RATIONALE>
Removed the explicit mathematical inequalities (`p1 + p2 > T`, `sum > T`) and the explicit two-bullet characterization. Instead, the problem uses an indirect operational description ("its required sequence of Channel 1 and Channel 2 transmissions", "so much total work across all jobs"). This forces the model to synthesize the operational rules (sequential dependency for jobs, cumulative load for channels) into the correct algebraic checks, rather than just pattern-matching a given formula.
</RATIONALE>

The conditions for outputting `JOB i` or `LOAD c` are mathematically identical to the seed's `p1+p2 > T` and `sum > T`, and the guarantee that exactly one applies is strictly preserved.
</PRESERVED_ANSWER>
