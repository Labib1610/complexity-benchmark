**Solution Explanation**

For every subsystem `i`

* `p1[i]` – duration of the *Capacitor Charge* burst  
* `p2[i]` – duration of the *System Initialization* burst  

Four constraints exist, but we have to consider three *experiments* that
ignore some of them.

--------------------------------------------------------------------
### Experiment 1 – `JOB i`

Capacity limits of both grids are removed, therefore all bursts may run
in parallel, only the precedence *charge → init* for the same subsystem
remains.

For a fixed subsystem `i` the earliest finishing time is simply  

```
time_i = p1[i] + p2[i]
```

If `time_i > T` the experiment proves that the original problem is
impossible, and we must output `JOB i`.

--------------------------------------------------------------------
### Experiment 2 – `LOAD 1`

All initialization bursts are set to length `0` and the init‑grid limit is
removed.
Only the capacitor grid is still serial, and each job must finish its
charge before its (zero‑length) init.

All jobs are processed one after another on the single capacitor grid,
hence the makespan is the sum of all charge times

```
total_charge = Σ p1[i]
```

If `total_charge > T` we output `LOAD 1`.

--------------------------------------------------------------------
### Experiment 3 – `LOAD 2`

All charge bursts are set to length `0` and the charge‑grid limit is
removed.
Now only the init grid is serial, and every job is ready at time 0.
The makespan equals the sum of all initialization times

```
total_init = Σ p2[i]
```

If `total_init > T` we output `LOAD 2`.

--------------------------------------------------------------------
### Correctness Proof  

We prove that the algorithm prints the required answer.

---

#### Lemma 1  
In Experiment 1 the earliest possible finishing time of subsystem `i`
equals `p1[i] + p2[i]`.

*Proof.*  
All other subsystems may run completely in parallel because both grids
have unlimited capacity. The only restriction for subsystem `i` is that
its own charge must finish before its init starts, therefore they must
run consecutively and need exactly `p1[i] + p2[i]` time. ∎



#### Lemma 2  
In Experiment 2 the minimum makespan equals ` Σ p1[i]`.

*Proof.*  
All initialization bursts have length 0, thus they do not contribute to
the schedule length. The capacitor grid can handle only one charge at a
time, so the charges must be processed sequentially on a single machine.
Any ordering processes each charge once, giving total time
` Σ p1[i]`. No schedule can be shorter because the grid is busy during
the whole interval. ∎



#### Lemma 3  
In Experiment 3 the minimum makespan equals ` Σ p2[i]`.

*Proof.** Symmetric to Lemma 2, now the init grid is the only serial
resource, all charges are instantaneous, and every job is ready at time 0.
Hence the init bursts are processed one after another, total time
` Σ p2[i]`. ∎



#### Lemma 4  
If the algorithm outputs `JOB i` then Experiment 1 indeed exceeds `T`.

*Proof.*  
The algorithm outputs `JOB i` only when it has found an index with
`p1[i] + p2[i] > T`. By Lemma 1 this value is the optimum makespan of
Experiment 1 for subsystem `i`, therefore the optimum is larger than `T`. ∎



#### Lemma 5  
If the algorithm outputs `LOAD 1` then Experiment 2 exceeds `T`.

*Proof.*  
`LOAD 1` is printed only when no subsystem violates Lemma 1 and
` Σ p1[i] > T`. By Lemma 2 the optimum makespan of Experiment 2 equals that
sum, which is larger than `T`. ∎



#### Lemma 6  
If the algorithm outputs `LOAD 2` then Experiment 3 exceeds `T`.

*Proof.*  
Analogous to Lemma 5 using Lemma 3. ∎



#### Theorem  
The program always prints the correct required line.

*Proof.*  
Exactly one of the three experiments has optimum makespan greater than `T`
(guaranteed by the statement).

*Case 1.* Some subsystem satisfies `p1[i] + p2[i] > T`.  
The algorithm finds the first such `i` and prints `JOB i`. By Lemma 4
this is correct, and the other experiments cannot exceed `T` because only
one may.

*Case 2.* No subsystem violates `p1[i] + p2[i] > T`.  
Then Experiment 1 is not the failing one.
The algorithm checks ` Σ p1[i]`.  
If it is larger than `T`, it prints `LOAD 1`, which is correct by
Lemma 5.  
Otherwise ` Σ p1[i] ≤ T`. Because exactly one experiment fails,
necessarily ` Σ p2[i] > T`, and the algorithm prints `LOAD 2`,
correct by Lemma 6.

All possibilities are covered, thus the output is always correct. ∎

### Complexity Analysis

*Reading input:* `O(j)`  
*Scanning for a violating subsystem:* `O(j)`  
*Computing the two sums:* `O(j)`  

Total time `O(j)` ( ≤ 2·10⁵ ), memory `O(1)` besides the input values.

### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    j = int(next(it))
    T = int(next(it))

    p1 = []
    p2 = []

    # read all pairs, also look for a job that exceeds T alone
    job_index = -1
    for idx in range(1, j + 1):
        a = int(next(it))
        b = int(next(it))
        p1.append(a)
        p2.append(b)
        if job_index == -1 and a + b > T:
            job_index = idx  # 1‑based

    if job_index != -1:
        sys.stdout.write(f"JOB {job_index}")
        return

    total_p1 = sum(p1)
    if total_p1 > T:
        sys.stdout.write("LOAD 1")
        return

    total_p2 = sum(p2)
    # by problem guarantee this must be > T now
    sys.stdout.write("LOAD 2")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input/output format.
