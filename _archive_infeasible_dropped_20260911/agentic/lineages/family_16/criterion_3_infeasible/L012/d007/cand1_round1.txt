# Spaceship Power Allocation Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

You are the chief engineer of a spaceship managing $j$ critical subsystems. Each subsystem requires two power bursts to reboot: a **Capacitor Charge** burst and a **System Initialization** burst. 

The reboot sequence is subject to the following safety constraints:
1. **Precedence**: For any given subsystem, its System Initialization burst must start at or after the exact moment its Capacitor Charge burst finishes.
2. **Capacitor Grid Capacity**: The ship's capacitor grid can only handle one Capacitor Charge burst at a time. No two Capacitor Charge bursts may overlap.
3. **Initialization Grid Capacity**: The ship's initialization grid can only handle one System Initialization burst at a time. No two System Initialization bursts may overlap.
4. **Time Limit**: The entire reboot process for all bursts across all subsystems must be completely contained within a strict operating window of $[0, T]$ milliseconds.

The ship's computer has determined that the window $T$ is too short to reboot all subsystems. To isolate the exact bottleneck, the diagnostic system calculates the absolute minimum time required to process all subsystems under three hypothetical scenarios. Each scenario relaxes some of the safety constraints. The input data guarantees that exactly one of these scenarios will require a minimum time that strictly exceeds $T$. You must output the error code for the scenario that fails:

- **Scenario 1**: Constraints 2 and 3 are suspended, allowing unlimited simultaneous bursts on both grids. Constraint 1 (Precedence) remains strictly enforced. If the absolute minimum time to complete all bursts in this scenario strictly exceeds $T$, output `JOB i`, where $i$ is the 1-based index of the specific subsystem that prevents completion.
- **Scenario 2**: Constraints 1 and 3 are suspended. Only Constraint 2 (Capacitor Grid Capacity) remains enforced. If the absolute minimum time to complete all bursts in this scenario strictly exceeds $T$, output `LOAD 1`.
- **Scenario 3**: Constraints 1 and 2 are suspended. Only Constraint 3 (Initialization Grid Capacity) remains enforced. If the absolute minimum time to complete all bursts in this scenario strictly exceeds $T$, output `LOAD 2`.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in milliseconds for the subsystem's **Capacitor Charge** burst and its **System Initialization** burst, respectively.

## Output

Print a single line containing either `JOB i` (if Scenario 1 fails), `LOAD 1` (if Scenario 2 fails), or `LOAD 2` (if Scenario 3 fails).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, under Scenario 1, subsystems can be processed simultaneously but must still follow Precedence. The first subsystem requires 70 milliseconds for its Capacitor Charge and 60 milliseconds for its System Initialization sequentially, taking 130 milliseconds total. Since this strictly exceeds the window $T = 100$, Scenario 1 fails, making `JOB 1` the valid proof of impossibility. 

In Example 2, under Scenario 1, no individual subsystem prevents completion within $T = 150$. However, under Scenario 2, Precedence is ignored but the Capacitor Grid Capacity constraint is enforced. The grid must process four Capacitor Charge bursts of 50 milliseconds each without overlapping. The absolute minimum time required is $50 + 50 + 50 + 50 = 200$ milliseconds, which strictly exceeds $T = 150$. Thus, Scenario 2 fails, making `LOAD 1` the valid proof.
