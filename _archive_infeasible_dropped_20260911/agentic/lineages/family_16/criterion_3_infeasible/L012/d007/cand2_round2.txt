# Spaceship Power Allocation Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

You are the chief engineer of a spaceship managing $j$ critical subsystems. Each subsystem requires two power bursts to reboot: a **Capacitor Charge** burst and a **System Initialization** burst.

A valid reboot schedule must assign each subsystem $k \in \{1, \dots, j\}$ two time intervals, $I_{1,k}$ (for the Capacitor Charge) and $I_{2,k}$ (for the System Initialization), satisfying the following rules:
- **[Domain]**: All intervals must be completely contained within a strict operating window of $[0, T]$ milliseconds.
- **[Length]**: For each subsystem $k$, the duration of $I_{1,k}$ must be exactly $p_{1,k}$ milliseconds, and the duration of $I_{2,k}$ must be exactly $p_{2,k}$ milliseconds.
- **[Precedence]**: For each subsystem $k$, all points in time within $I_{1,k}$ must strictly precede all points in time within $I_{2,k}$. (The System Initialization cannot start until the Capacitor Charge is completely finished).
- **[Capacity 1]**: The ship's capacitor grid can only handle one burst at a time. The intervals $I_{1,1}, I_{1,2}, \dots, I_{1,j}$ must be pairwise disjoint.
- **[Capacity 2]**: The ship's initialization grid can only handle one burst at a time. The intervals $I_{2,1}, I_{2,2}, \dots, I_{2,j}$ must be pairwise disjoint.

The ship's computer has determined that the window $T$ is too short, meaning no valid schedule exists. You must output a certificate isolating a bottleneck. At least one of the following certificates is guaranteed to be valid for the given input; if multiple are valid, you may print any one of them:

- `JOB i` (where $i$ is the 1-based index of a qualifying subsystem): The **[Domain]**, **[Length]**, and **[Precedence]** rules are mutually contradictory for subsystem $i$ alone, even if all other subsystems are ignored.
- `LOAD 1`: The **[Domain]**, **[Length]**, and **[Capacity 1]** rules are mutually contradictory across all subsystems, even if all other rules are ignored.
- `LOAD 2`: The **[Domain]**, **[Length]**, and **[Capacity 2]** rules are mutually contradictory across all subsystems, even if all other rules are ignored.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in milliseconds for the subsystem's **Capacitor Charge** burst and its **System Initialization** burst, respectively.

## Output

Print a single line containing any valid certificate string: either `JOB i` (for a valid 1-based index $i$), `LOAD 1`, or `LOAD 2`, corresponding to a contradictory subset of rules as defined above.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for subsystem 1, the **[Length]** rule dictates interval sizes of 70 and 60. The **[Precedence]** rule forces the second to start after the first ends. It is impossible to place both intervals within the 100-millisecond **[Domain]** without violating one of these conditions, making `JOB 1` a valid proof of impossibility.

In Example 2, no individual subsystem is impossible to schedule on its own. However, the **[Capacity 1]** rule forces all four Capacitor Charge intervals to be disjoint. Finding four disjoint intervals of length 50 within a single 150-millisecond **[Domain]** is impossible, making `LOAD 1` a valid certificate.

The logical contradictions perfectly map to the original arithmetic checks: Domain+Length+Precedence is contradictory iff p1+p2 > T, Domain+Length+Capacity1 is contradictory iff sum(p1) > T, and Domain+Length+Capacity2 is contradictory iff sum(p2) > T.
