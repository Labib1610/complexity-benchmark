# Spaceship Power Allocation Certificate

Time limit: 2 s   Memory limit: 256 MB

## Description

You are the chief engineer of a spaceship managing $j$ critical subsystems. Each subsystem requires two distinct energy bursts to reboot: a **Capacitor Charge** burst and a **System Initialization** burst. 

The reboot sequence is strictly governed by the following safety constraints:
1. **Precedence**: For any given subsystem, its System Initialization burst cannot begin until its Capacitor Charge burst has completely finished.
2. **Capacitor Grid Capacity**: The ship's capacitor grid can process at most one Capacitor Charge burst at any given moment.
3. **Initialization Grid Capacity**: The ship's initialization grid can process at most one System Initialization burst at any given moment.
4. **Time Limit**: All bursts across all subsystems must be fully completed within a strict operating window of $T$ milliseconds.

The ship's computer has determined that no valid sequence of operations can satisfy all four constraints simultaneously. The input guarantees that exactly one of the following hypothetical relaxation scenarios retains a bottleneck that unavoidably violates Constraint 4. You must isolate the exact bottleneck by outputting the corresponding error code:

- `JOB i` (where $1 \le i \le j$ is the 1-based index of a subsystem): It is impossible to satisfy Constraint 4 even if we assume the capacitor grid and initialization grid can process infinitely many bursts simultaneously (effectively ignoring Constraints 2 and 3). Under this relaxation, the precedence constraint acting on subsystem $i$ alone forces a timeline that exceeds $T$.
- `LOAD 1`: It is impossible to satisfy Constraint 4 even if we assume every subsystem's System Initialization burst requires zero time and has no precedence constraints (effectively ignoring Constraints 1 and 3). Under this relaxation, the capacitor grid's capacity limit acting on all Capacitor Charge bursts forces a timeline that exceeds $T$.
- `LOAD 2`: It is impossible to satisfy Constraint 4 even if we assume every subsystem's Capacitor Charge burst requires zero time and has no precedence constraints (effectively ignoring Constraints 1 and 2). Under this relaxation, the initialization grid's capacity limit acting on all System Initialization bursts forces a timeline that exceeds $T$.

Input is guaranteed to be unschedulable, and exactly one of the listed certificate types is guaranteed to apply.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the duration in milliseconds for the subsystem's **Capacitor Charge** burst and its **System Initialization** burst, respectively.

## Output

Print a single line containing either `JOB i` (if the isolated subsystem $i$ scenario violates the time limit), `LOAD 1` (if the isolated Capacitor Charge scenario violates the time limit), or `LOAD 2` (if the isolated System Initialization scenario violates the time limit).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, if we relax the problem by ignoring grid capacities (Constraints 2 and 3), we still must complete subsystem 1's 70 ms Capacitor Charge and its 60 ms System Initialization. Due to Constraint 1 (Precedence), these cannot overlap. The absolute minimum time to complete both is 130 ms. This unavoidably violates the 100 ms Time Limit (Constraint 4). Thus, `JOB 1` is the valid proof.

In Example 2, no individual subsystem's sequential work exceeds the 150 ms limit. However, if we relax the problem by ignoring initialization and precedence constraints (Constraints 1 and 3), Constraint 2 dictates the four Capacitor Charge bursts cannot overlap. The minimum time to process all four 50 ms bursts one at a time is 200 ms, which unavoidably violates Constraint 4. Thus, `LOAD 1` is the valid proof.
</STATEMENT>
<RATIONALE>
The problem was reframed from "reducing to a subset of tasks" (which easily triggers simple sum logic) to "relaxing orthogonal constraints" on the full set of tasks. This forces models to deduce that a single active precedence constraint implies `p1+p2`, and a single active capacity constraint implies an aggregated sum of durations. The formal numeric bounds rejected in the previous attempt have been exactly restored to comply with strict contract checking.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for outputting `JOB i`, `LOAD 1`, and `LOAD 2` mathematically simplify to exactly $p_{1,i} + p_{2,i} > T$, $\sum p_1 > T$, and $\sum p_2 > T$, which perfectly matches the seed logic for all valid inputs.
</PRESERVED_ANSWER>
