# Accelerator Blueprint Validation

Time limit: 2 s   Memory limit: 256 MB

## Description

You are validating a blueprint for a dual-rail linear accelerator of length $T$ millimeters. The accelerator consists of an Upper Rail and a Lower Rail. The blueprint specifies the placement of $j$ distinct acceleration modules.

For each module $i$, the blueprint must allocate two continuous segments:
- A **Primary Magnetic Array** spanning $p_1$ millimeters on the Upper Rail.
- A **Secondary Magnetic Array** spanning $p_2$ millimeters on the Lower Rail.

The placement of these arrays is governed by the following physical laws:
1. **Phase Progression**: For any module $i$, the coordinate at which its Secondary Array begins on the Lower Rail must be greater than or equal to the coordinate at which its Primary Array ends on the Upper Rail.
2. **Upper Rail Integrity**: The $j$ Primary Arrays must not overlap with one another on the Upper Rail (sharing boundary endpoints is permitted).
3. **Lower Rail Integrity**: The $j$ Secondary Arrays must not overlap with one another on the Lower Rail (sharing boundary endpoints is permitted).
4. **Chamber Containment**: Every array must be positioned entirely within the accelerator's coordinate bounds from $0$ to $T$.

The simulation engine has rejected the blueprint because it is impossible to satisfy all constraints within length $T$. The input guarantees that the impossibility is caused by exactly one of the following three categories. You must output the corresponding diagnostic code:

- `JOB i` (where $i$ is the 1-based index of a module): Output this if the system formed exclusively by the **Phase Progression** and **Chamber Containment** constraints for module $i$'s two arrays is mathematically unsatisfiable on its own. (If multiple modules satisfy this, outputting `JOB i` for any such module is accepted).
- `LOAD 1`: Output this if the system formed exclusively by the **Upper Rail Integrity** and **Chamber Containment** constraints for all $j$ Primary Arrays is mathematically unsatisfiable on its own.
- `LOAD 2`: Output this if the system formed exclusively by the **Lower Rail Integrity** and **Chamber Containment** constraints for all $j$ Secondary Arrays is mathematically unsatisfiable on its own.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the span in millimeters of the module's Primary Array and Secondary Array, respectively.

## Output

Print a single line containing either `JOB i` (if module $i$'s isolated constraints are unsatisfiable), `LOAD 1` (if the Upper Rail's isolated constraints are unsatisfiable), or `LOAD 2` (if the Lower Rail's isolated constraints are unsatisfiable).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, module 1 requires a Primary Array of 70 mm and a Secondary Array of 60 mm. The constraints for module 1 require embedding a 70 mm segment and a subsequent 60 mm segment within the coordinate space $[0, 100]$. Because their combined length (70 + 60 = 130) exceeds the total available length of 100, this is mathematically impossible, making `JOB 1` a valid diagnostic code. 

In Example 2, no single module's isolated constraints are impossible. However, the Upper Rail must host four Primary Arrays of 50 mm each without overlapping. Because their total combined length (50 + 50 + 50 + 50 = 200) exceeds the available space of 150, embedding them into the coordinate space $[0, 150]$ is mathematically impossible, making `LOAD 1` the valid code.
