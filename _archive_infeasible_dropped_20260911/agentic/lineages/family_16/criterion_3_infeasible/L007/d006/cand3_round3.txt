# Problem C — Impossible Allocations: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A memory manager must allocate continuous blocks within a linear address space of length $T$ (spanning from coordinate $0$ to $T$) for $j$ processes.
Each process $i \in \{1 \dots j\}$ requires a primary block of length exactly $p_{i,1}$ and a secondary block of length exactly $p_{i,2}$.
A complete allocation is valid if it satisfies two rules:
1. **Sequential Address:** For every process $i$, the highest coordinate of its primary block must be less than or equal to the lowest coordinate of its secondary block.
2. **Isolation:** No two primary blocks can overlap. Similarly, no two secondary blocks can overlap. (Different blocks of the same type may touch exactly at their boundaries).

You are analyzing logs from failed systems where a valid complete allocation is mathematically impossible. For every provided test case, it is guaranteed that exactly one of the following independent impossibility conditions is met. Output the code for the one that applies:
- `JOB i` — The minimum possible distance from the lowest coordinate of process **i**'s primary block to the highest coordinate of its secondary block, assuming the Sequential Address rule is satisfied, strictly exceeds $T$.
- `LOAD c` — The minimum possible distance from the absolute lowest coordinate to the absolute highest coordinate occupied by the $j$ blocks of type **c** (where **c** $\in \{1, 2\}$ represents primary or secondary), assuming the Isolation rule is satisfied, strictly exceeds $T$.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required lengths for the primary and secondary blocks for that process, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` (where **i** is the 1-indexed process number) or `LOAD c` (where **c** $\in \{1, 2\}$).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```
</STATEMENT>
<RATIONALE>
The explicit scheduling framing (jobs, components, contiguity, causality) was replaced with a geometric memory allocation scenario. The independent impossibility conditions are now defined rigorously as the minimum bounding span of 1D segments under sequential and non-overlapping constraints, forcing the model to logically derive the `p1 + p2 > T` and `sum(p_c) > T` checks rather than pattern-matching them from standard CP phrasing.
</RATIONALE>
<PRESERVED_ANSWER>
The minimum bounding span for two sequential blocks of lengths p1 and p2 is exactly p1 + p2, and for j non-overlapping blocks it is their sum; strictly exceeding T is mathematically identical to the seed's impossibility conditions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an O(N) feasibility check (INFEASIBLE class) because the required bounding spans are still computed via simple sums of the input lengths.
</PRESERVED_CLASS>
