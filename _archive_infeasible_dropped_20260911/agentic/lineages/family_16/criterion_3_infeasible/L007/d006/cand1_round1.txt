<STATEMENT>
# Problem C — Impossible Domains: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system must assign an activation domain $D_{i,c} \subseteq [0, T]$ to each item $i \in \{1 \dots j\}$ and component $c \in \{1, 2\}$. 
A complete assignment is valid if it satisfies all of the following individual constraints:
1. **Contiguity:** For each specific item $i$ and component $c$, the domain $D_{i,c}$ must be a single contiguous closed interval of length exactly $p_{i,c}$.
2. **Causality:** For each specific item $i$, any $x \in D_{i,1}$ and $y \in D_{i,2}$ must satisfy $x \le y$.
3. **Exclusivity:** For each specific component $c$ and specific pair of distinct items $i \neq k$, the intersection $D_{i,c} \cap D_{k,c}$ must contain at most one real number.

You are analyzing logs from failed systems where a valid complete assignment is mathematically impossible. The system performs placement audits to find the minimum unsatisfiable core responsible for the failure. 

Let $S_{i} = \{D_{i,1}, D_{i,2}\}$ be the set of domains associated with item $i$.
Let $V_{c} = \{D_{1,c}, \dots, D_{j,c}\}$ be the set of domains associated with component $c$.

For every provided test case, exactly one of the following audits reveals an inherent impossibility. Output the code for the one that applies:
- `JOB i` — The audit isolating $S_{i}$ fails. It is impossible to assign the domains in $S_{i}$ within $[0, T]$ such that they satisfy all individual constraints that reference no domains outside of $S_{i}$.
- `LOAD c` — The audit isolating $V_{c}$ fails. It is impossible to assign the domains in $V_{c}$ within $[0, T]$ such that they satisfy all individual constraints that reference no domains outside of $V_{c}$.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required domain lengths $p_{i,1}$ and $p_{i,2}$ for the item at component 1 and component 2, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
Removed the explicit clauses ("even if we completely ignore Exclusivity", etc.) that spoon-fed the independent per-item and per-component tests to the models. Replaced them with a formal definition of constraint scopes applied to specific domain subsets ($S_i$ and $V_c$). This forces the model to logically deduce which constraints remain active for each audit, and derive the $p_1+p_2 > T$ and $\sum p > T$ impossibility conditions from first principles rather than relying on structural hints.
</RATIONALE>
<PRESERVED_ANSWER>
The subsets of constraints that exclusively reference $S_i$ and $V_c$ perfectly map to the original problem's isolated JOB (Contiguity + Causality) and LOAD (Contiguity + Exclusivity) conditions, so the exact same certificates are triggered for every input.
</PRESERVED_ANSWER>
