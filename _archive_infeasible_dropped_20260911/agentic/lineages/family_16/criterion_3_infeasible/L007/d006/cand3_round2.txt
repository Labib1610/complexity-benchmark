<STATEMENT>
# Problem C — Impossible Domains: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system must assign an activation domain $D_{i,c} \subseteq [0, T]$ to each task $i \in \{1 \dots j\}$ and track $c \in \{1, 2\}$. 
A complete assignment is valid if it satisfies three axioms:
1. **Contiguity:** Each domain $D_{i,c}$ must be a single contiguous closed interval of length exactly $p_{i,c}$.
2. **Precedence:** For every task $i$, if $x \in D_{i,1}$ and $y \in D_{i,2}$, then $x \le y$.
3. **Capacity:** For a fixed track $c$, and any two distinct tasks $i \neq k$, the intersection $D_{i,c} \cap D_{k,c}$ must contain at most one real number.

You are analyzing configurations where a valid complete assignment is mathematically impossible. A diagnostic audit always traces the failure to exactly one irreducible bottleneck: either a single task whose domains inherently cannot fit within the timeline under the Precedence and Contiguity rules alone, or a single track whose domains inherently cannot fit within the timeline under the Capacity and Contiguity rules alone.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required domain lengths $p_{i,1}$ and $p_{i,2}$ for the task on track 1 and track 2, respectively.

## Output

Print a single line containing the applicable bottleneck certificate:
- If the bottleneck is a single task, print `JOB i`, where **i** is the 1-indexed task number.
- If the bottleneck is a single track, print `LOAD c`, where **c** $\in \{1, 2\}$ is the track number.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```
</STATEMENT>
<RATIONALE>
The explicit bullet points and "even if we completely ignore" clauses were removed from the problem description. They are replaced by a single sentence that defines the failures as irreducible bottlenecks under specific subsets of rules ("Precedence and Contiguity rules alone" and "Capacity and Contiguity rules alone"). This removes the direct structural affordance that models were using to map the independent feasibility tests, forcing them to deduce the algebraic meaning of the rule subsets.
</RATIONALE>
<PRESERVED_ANSWER>
The bottleneck definitions mathematically reduce to exactly the same checks: a task failing under Precedence and Contiguity alone means $p_{i,1} + p_{i,2} > T$, and a track failing under Capacity and Contiguity alone means its total length exceeds $T$, strictly matching the seed's `JOB i` and `LOAD c` conditions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The conditions can still be checked in $O(N)$ time by iterating over the items to check the sum of their two domain lengths against $T$, and summing the lengths per track to check against $T$.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "inherently cannot fit" as allowing for complex packing configurations, though "under the [Rules] alone" strictly isolates the constraints to simple sums.
</RISK>
