<STATEMENT>
# Problem C — Impossible Board Layouts

Time limit: 2 s   Memory limit: 256 MB

## Description

You are analyzing a 1D block placement puzzle. The board is a line segment from $0$ to $T$.
There are $j$ pairs of blocks to be placed on the board. For each pair $i \in \{1 \dots j\}$, there is a red block of length $p_{i,1}$ and a blue block of length $p_{i,2}$.

A complete valid layout must satisfy three rules:
1. **Containment:** Every block must be placed contiguously within the board boundaries from $0$ to $T$.
2. **Precedence:** For every pair $i$, the red block must be placed completely to the left of its corresponding blue block (they may touch at boundaries but cannot overlap).
3. **Collision-free:** No two red blocks can overlap, and no two blue blocks can overlap (they may touch at boundaries).

You are given logs from impossible puzzles. For every provided test case, the puzzle cannot be solved, and you must output an error code demonstrating a specific localized reason why. The input guarantees that at least one such localized failure exists.

An automated inspector identifies the failure by checking for two types of geometric impossibilities:
- If, for some 1-based index $i$, it is physically impossible to construct a layout for the red block and blue block of pair $i$ that satisfies Containment and Precedence, the inspector outputs `JOB i`.
- If, for some color $c \in \{1, 2\}$ (where 1 is red and 2 is blue), it is physically impossible to construct a layout for all $j$ blocks of color $c$ that satisfies Containment and the Collision-free rule, the inspector outputs `LOAD c`.

Determine and print a valid error code for each test case. (If multiple such failures apply, any valid one of these forms will be accepted).

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the lengths of the red block and the blue block for pair $i$, respectively.

## Output

Print a single line containing the applicable error code: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```
</STATEMENT>
<RATIONALE>
Replaced the mathematical interval assignment framing with a physical 1D block placement puzzle. The explicit "even if we completely ignore" clauses were removed, and the impossibility conditions are now framed as geometric constraints (Containment + Precedence vs Containment + Collision-free). This forces the model to deduce the underlying sum inequalities (`p1+p2 > T` and `sum > T`) from the geometric rules rather than pattern-matching explicit algebraic relaxations.
</RATIONALE>
<PRESERVED_ANSWER>
The geometric impossibility of placing two sequential blocks within [0, T] exactly matches the original `JOB i` condition (p1+p2 > T), and the impossibility of placing non-overlapping blocks of the same color exactly matches the `LOAD c` condition (sum > T).
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an $O(j)$ feasibility check, as the required geometric deductions reduce to the exact same linear sum comparisons as the seed.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "physically impossible to construct a layout" as requiring a complex packing algorithm, though the 1D nature and simplified rules make the required sum checks mathematically equivalent and unambiguous.
</RISK>
