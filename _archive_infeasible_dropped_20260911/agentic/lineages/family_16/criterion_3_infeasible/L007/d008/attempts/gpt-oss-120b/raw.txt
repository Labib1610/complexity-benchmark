**Solution Explanation**

For each task `i` we have to choose two disjoint subsets  

* `S_{i,1}` of size `p[i][0]` (core 1)  
* `S_{i,2}` of size `p[i][1]` (core 2)

All numbers must belong to `{1,…,T}` and every number of core 1 must be **smaller**
than every number of core 2.

The statement guarantees that **exactly one** of the following reasons makes a
complete allocation impossible.

* **JOB i** – for this single task the two sets cannot be placed at all,
  ignoring all other tasks and the “different‑core‑exclusivity”.
* **LOAD c** – for this core the `j` sets of this core cannot be placed
  disjointly, ignoring the ordering between the two cores.

We only have to detect which of the two reasons occurs.



--------------------------------------------------------------------

#### 1.   When is a single job impossible?  

We may put the `p1` numbers of core 1 at the beginning of the interval,
e.g. `1 … p1`, and the `p2` numbers of core 2 right after them,
e.g. `p1+1 … p1+p2`.  
This uses exactly `p1 + p2` distinct integers, therefore

```
JOB i  ⇔  p1 + p2 > T
```

--------------------------------------------------------------------

#### 2.   When is a whole core impossible?  

If we forget the ordering constraint completely, the `j` sets of one core
only have to be pairwise disjoint subsets of `{1,…,T}`.
That is possible iff the total amount of needed slots does not exceed `T`:

```
LOAD 1  ⇔  Σ p[i][0] > T
LOAD 2  ⇔  Σ p[i][1] > T
```

--------------------------------------------------------------------

#### 3.   Overall algorithm  

* read `j, T`
* iterate over the `j` tasks  
  * accumulate `sum1`, `sum2` (total needed slots for core 1 / core 2)  
  * if `p1 + p2 > T` remember the first such index `bad_job`
* after the loop  

```
if bad_job exists:          print("JOB", bad_job)
elif sum1 > T:              print("LOAD 1")
else:                       print("LOAD 2")
```

The problem guarantees that exactly one of the three cases occurs,
so the algorithm always produces a correct certificate.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the required certificate.

---

##### Lemma 1  
For a task `i` a feasible pair of sets exists *iff* `p[i][0] + p[i][1] ≤ T`.

**Proof.**  
*If* `p1 + p2 ≤ T`, choose `S_{i,1} = {1,…,p1}` and  
`S_{i,2} = {p1+1,…,p1+p2}`. They are subsets of `[1,T]`,
disjoint, and `max S_{i,1}=p1 < p1+1 = min S_{i,2}` – a feasible pair.

*Only‑if*: any feasible pair uses `p1` distinct numbers for core 1 and
`p2` distinct numbers for core 2, all inside `[1,T]`, and the two groups are
disjoint. Hence at least `p1+p2` different integers of `[1,T]` are needed,
so `p1+p2 ≤ T`. ∎



##### Lemma 2  
For a fixed core `c` the `j` sets can be chosen pairwise disjoint
*iff* ` Σ_i p[i][c] ≤ T`.

**Proof.**  
*If* the sum ≤ T, enumerate the numbers `1…T` and give the first `p[1][c]`
to task 1, the next `p[2][c]` to task 2, and so on – all sets are disjoint
subsets of `[1,T]`.

*Only‑if*: any feasible family consists of ` Σ_i p[i][c]` distinct integers
from `[1,T]`, therefore that sum cannot exceed `T`. ∎



##### Lemma 3  
If the algorithm prints `JOB i`, then indeed task `i` is impossible
even when ignoring all other constraints.

**Proof.**  
The algorithm prints `JOB i` only when it has found `p[i][0]+p[i][1] > T`.  
By Lemma&nbsp;1 this inequality is exactly the condition that makes a single
task infeasible, irrespective of other tasks or core exclusivity. ∎



##### Lemma 4  
If the algorithm prints `LOAD c`, then core `c` is impossible
even when ignoring the ordering between the two cores.

**Proof.**  
The algorithm reaches this branch only after confirming that **no**
task violates Lemma&nbsp;1, i.e. every `p[i][0]+p[i][1] ≤ T`.  
Then it checks `sum_c = Σ_i p[i][c]`.  
If `sum_c > T` it prints `LOAD c`. By Lemma&nbsp;2 this inequality is
exactly the condition that makes the sets of core `c` impossible, regardless
of the other core. ∎



##### Lemma 5  
Exactly one of the three branches of the algorithm is taken.

**Proof.**  
The statement of the problem guarantees that exactly one of the two
certificates is valid.  
If a `JOB i` exists, Lemma&nbsp;1 gives `p[i][0]+p[i][1] > T`, therefore the
algorithm will find such an index and take the first branch.  
Otherwise all tasks satisfy `p[i][0]+p[i][1] ≤ T`. Then, by the guarantee,
 one of the cores must have total demand larger than `T`; consequently
the corresponding sum test succeeds and the algorithm takes the second or
third branch. ∎



##### Theorem  
The algorithm always outputs the correct certificate required by the
problem.

**Proof.**  
By Lemma&nbsp;5 the algorithm outputs exactly one line.
If it is `JOB i`, Lemma&nbsp;3 shows the certificate is correct.
If it is `LOAD c`, Lemma&nbsp;4 shows the certificate is correct.
Thus in all cases the produced answer is a valid certificate. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Reading* `j` lines and performing O(1) work per line:

```
Time   :  O(j)          ( ≤ 2·10⁵ )
Memory :  O(1)          ( only a few counters )
```

Both limits easily meet the required constraints.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    j = int(next(it))
    T = int(next(it))

    sum1 = 0
    sum2 = 0
    bad_job = 0  # 0 means none found yet

    for idx in range(1, j + 1):
        p1 = int(next(it))
        p2 = int(next(it))
        sum1 += p1
        sum2 += p2
        if not bad_job and p1 + p2 > T:
            bad_job = idx

    out = []
    if bad_job:
        out = f"JOB {bad_job}"
    elif sum1 > T:
        out = "LOAD 1"
    else:
        out = "LOAD 2"

    sys.stdout.write(out + "\n")

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
