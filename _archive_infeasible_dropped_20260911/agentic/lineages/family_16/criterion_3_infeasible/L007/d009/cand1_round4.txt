# Problem C — Injective Mapping Certification

Time limit: 2 s   Memory limit: 256 MB

## Description

A formal verification system is attempting to construct a valid family of injective functions. Let $j$ be the number of required entities. For each entity $i \in \{1 \dots j\}$, the system must construct two injective functions, $\phi_{i,1}$ and $\phi_{i,2}$.

The input specifies the exact domain for each function: the domain of $\phi_{i,1}$ is the set of integers $\{1, \dots, p_{i,1}\}$, and the domain of $\phi_{i,2}$ is the set of integers $\{1, \dots, p_{i,2}\}$. All constructed functions must be injective (mapping distinct inputs to distinct outputs).

The constructed functions must strictly satisfy three constraints:
1. **Codomain Bounding:** For all $i \in \{1 \dots j\}$ and $c \in \{1, 2\}$, every integer in the image (the set of all output values) of $\phi_{i,c}$ must be chosen from the discrete interval $[1, T]$.
2. **Image Supremum Precedence:** For every entity $i$, the maximum integer in the image of $\phi_{i,1}$ must be strictly less than the minimum integer in the image of $\phi_{i,2}$.
3. **Range Exclusivity:** For a fixed function index $c \in \{1, 2\}$, the functions cannot share any output values across different entities. Therefore, for any distinct entities $i \neq m$, the intersection of the image of $\phi_{i,c}$ and the image of $\phi_{m,c}$ must be empty.

You are analyzing logs from failed systems where a valid complete assignment of these functions is mathematically impossible. For every provided test case, exactly one of the following isolated conditions is inherently impossible to satisfy. Output the code for the one that applies:
- `JOB i` — It is mathematically impossible to find valid injective functions $\phi_{i,1}$ and $\phi_{i,2}$ for entity **i** (1-indexed) that simultaneously satisfy Codomain Bounding and Image Supremum Precedence, even if we completely ignore Range Exclusivity and all other entities.
- `LOAD c` — It is mathematically impossible to find injective functions $\phi_{1,c}, \dots, \phi_{j,c}$ for index **c** (where **c** $\in \{1, 2\}$) that simultaneously satisfy Codomain Bounding and Range Exclusivity, even if we completely ignore Image Supremum Precedence and the other function index.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required domain sizes $p_{i,1}$ and $p_{i,2}$ for the first and second functions of the entity, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
We replaced the discrete scheduler and time-slot allocations with the construction of injective functions. The model must now deduce that an injective function with a domain of size $p$ inherently requires an image of size $p$, and that the constraints on the images mathematically reduce to the exact same exact-cardinality pigeonhole checks, defeating models that rely on keyword-driven task-scheduling heuristics.
</RATIONALE>
<PRESERVED_ANSWER>
Because an injective function maps its domain of size $p$ to exactly $p$ distinct output values, the constraints on the images are mathematically isomorphic to the original set-cardinality constraints, meaning `JOB i` still requires $p_{i,1} + p_{i,2} > T$ and `LOAD c` still requires $\sum p_{i,c} > T$.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains solvable by the exact same $O(j)$ algorithm that checks the arithmetic sums against $T$.
</PRESERVED_CLASS>
<RISK>
Models might struggle with the mathematical terminology "injective" or "image", though both are explicitly defined in the text to prevent ambiguity.
</RISK>
