<STATEMENT>
# Problem C — Impossible Allocations: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A discrete scheduler must allocate time slots for $j$ tasks across two machines. The schedule is defined by a set of binary variables $X_{i,c}[t] \in \{0, 1\}$, where $i \in \{1 \dots j\}$ is the task, $c \in \{1, 2\}$ is the machine, and $t \in \{1 \dots T\}$ is the time slot.

The input specifies the exact processing requirements for each task. For each task $i$ and machine $c$, the total number of active time slots must be exactly $p_{i,c}$. That is:
$$ \sum_{t=1}^{T} X_{i,c}[t] = p_{i,c} $$

A valid schedule must satisfy two additional operational rules:
1. **Strict Phase Ordering:** For any task $i$, its processing on Machine 1 must strictly precede its processing on Machine 2. Formally, for any time slots $t_1$ and $t_2$, if $X_{i,1}[t_1] = 1$ and $X_{i,2}[t_2] = 1$, then it must be strictly true that $t_1 < t_2$.
2. **Machine Capacity:** A machine can process at most one task at any given time. Formally, for any machine $c$ and any time slot $t$, the sum of active variables across all tasks cannot exceed 1:
$$ \sum_{i=1}^{j} X_{i,c}[t] \le 1 $$

You are given configurations for which no valid complete schedule exists. Your task is to pinpoint an isolated reason for the failure. For each configuration, output a certificate identifying a specific constraint subsystem that is inherently unsatisfiable on its own. The valid certificates are:

- `JOB i` — Task **i** (1-indexed) cannot be scheduled. It is mathematically impossible to assign values to the variables $X_{i,1}[t]$ and $X_{i,2}[t]$ (for $t \in \{1 \dots T\}$) such that they satisfy both the processing requirements and the Strict Phase Ordering rule, even if we assume this task has exclusive use of both machines (completely ignoring the Machine Capacity rule and all other tasks).
- `LOAD c` — Machine **c** (where **c** $\in \{1, 2\}$) is over-subscribed. It is mathematically impossible to assign values to the variables $X_{1,c}[t], \dots, X_{j,c}[t]$ (for $t \in \{1 \dots T\}$) such that they satisfy both the processing requirements and the Machine Capacity rule, even if we completely ignore the Strict Phase Ordering rule and the variables for the other machine.

If multiple constraint subsystems are unsatisfiable, output the certificate for any one of them.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the following $j$ lines contains two integers $p_{i,1}$ and $p_{i,2}$ ($1 \le p_{i,1}, p_{i,2} \le 1000000$): the required number of active time slots for task $i$ on Machine 1 and Machine 2, respectively.

## Output

Print a single line containing a valid certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
Translated the set-theoretic scheduling constraints into an equivalent integer linear programming feasibility problem using binary indicator variables. This preserves the exact scheduling model and mathematical constraints while stripping away the specific "set intersection" and "max < min" phrasing that models were using as surface-level shortcuts to guess the sum inequalities. By explicitly resolving the selection ambiguity ("output the certificate for any one of them"), the text strictly adheres to the expert's feedback while forcing genuine structural deduction.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum number of 1s assignable under the strict phase ordering constraint is T (yielding p_{i,1} + p_{i,2} > T for JOB i), and under the machine capacity constraint is T (yielding sum(p_{i,c}) > T for LOAD c), exactly matching the original impossibility conditions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
Checking the sums for JOB and LOAD remains an O(N) operation, keeping the problem in the same complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the binary variable formulation as requiring an actual ILP solver or simulation, leading to Time Limit Exceeded if they fail to deduce the O(1) sum checks.
</RISK>
