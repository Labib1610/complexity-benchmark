# Problem C — Impossible Allocations: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A compiler is attempting to map $j$ distinct computational graphs into a linear execution pipeline of $T$ stages. For each graph $i$, the compiler must allocate a set of exactly $p_{i,1}$ distinct stages for its frontend operations, and a set of exactly $p_{i,2}$ distinct stages for its backend operations.

A valid allocation must satisfy three rules:
1. **Pipeline Bounds:** Every allocated stage must be an integer chosen from $1$ to $T$ inclusive.
2. **Sequential Dataflow:** For any single graph $i$, its frontend set and backend set must be disjoint. Furthermore, if we combine them and sort all $p_{i,1} + p_{i,2}$ allocated stages in ascending order, the first $p_{i,1}$ stages in the sorted list must be exactly the frontend set, and the remaining $p_{i,2}$ stages must be exactly the backend set.
3. **Hardware Exclusivity:** For a given phase $c \in \{1, 2\}$ (where phase 1 is frontend and phase 2 is backend), a pipeline stage can be assigned to at most one graph. In other words, the frontend sets of any two different graphs must be disjoint, and the backend sets of any two different graphs must be disjoint.

You are debugging logs from compilation failures where a valid allocation is mathematically impossible. For every provided test case, you are guaranteed that exactly one of the following isolated conditions is the root cause. Output the code for the one that applies:
- `JOB i` — Graph **i** (1-indexed) cannot be mapped. It is mathematically impossible to choose frontend and backend sets for this graph alone that satisfy Pipeline Bounds and Sequential Dataflow, even if we completely ignore all other graphs.
- `LOAD c` — Phase **c** (where **c** $\in \{1, 2\}$) is overloaded. It is mathematically impossible to assign sets of phase **c** stages across all graphs that satisfy Pipeline Bounds and Hardware Exclusivity, even if we completely ignore Sequential Dataflow and the other phase.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of frontend stages $p_{i,1}$ and backend stages $p_{i,2}$ for the graph, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
The explicit bounds and strict precedence inequalities were replaced with a sorting-based property. By defining the valid ordering as "sorting the combined sets places all frontend elements first," the problem forces the model to independently deduce that this implies strict mathematical precedence and requires $p_{i,1} + p_{i,2}$ distinct integers from the interval $[1, T]$. This disrupts pattern-matching on standard scheduling terminology.
</RATIONALE>
<PRESERVED_ANSWER>
The Sequential Dataflow rule is mathematically identical to strict supremum precedence (forcing $p_{i,1} + p_{i,2} \le T$), and Hardware Exclusivity is identical to core exclusivity (forcing $\sum p_{i,c} \le T$), ensuring the exact same impossibility triggers apply.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an $O(j)$ sequential feasibility check, requiring only basic sums and comparisons to identify the impossibility certificate.
</PRESERVED_CLASS>
