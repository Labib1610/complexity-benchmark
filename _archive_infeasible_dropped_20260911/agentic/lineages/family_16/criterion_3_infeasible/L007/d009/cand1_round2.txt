# Problem C — Impossible Allocations: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A telecom provider is attempting to allocate network resources on two separate optical fibers, Fiber 1 and Fiber 2. Let $j$ be the number of corporate clients requesting bandwidth. For each client $i \in \{1 \dots j\}$, the provider must allocate a set of distinct frequency channels on Fiber 1 and a set of distinct frequency channels on Fiber 2.

The input specifies the exact number of channels each client requires: client $i$ must receive exactly $p_{i,1}$ channels on Fiber 1, and exactly $p_{i,2}$ channels on Fiber 2.

A valid network allocation must strictly satisfy three constraints:
1. **Valid Channels:** Every channel assigned to any client on either fiber must be an integer chosen from the available discrete range $[1, T]$.
2. **Spectral Separation:** For every client $i$, their assigned channels must be spectrally separated between the two fibers. Specifically, there must exist some integer threshold $k_i$ such that every channel assigned to client $i$ on Fiber 1 is less than or equal to $k_i$, and every channel assigned to client $i$ on Fiber 2 is strictly greater than $k_i$.
3. **Channel Exclusivity:** On each fiber $c$ (where $c \in \{1, 2\}$), a single channel cannot be shared by multiple clients. Therefore, for any distinct clients $i \neq m$, their assigned sets of channels on Fiber $c$ must have an empty intersection.

You are analyzing logs from failed systems where a valid complete assignment of these channels is mathematically impossible. For every provided test case, exactly one of the following isolated conditions is inherently impossible to satisfy. Output the code for the one that applies:
- `JOB i` — It is mathematically impossible to find valid sets of channels for client **i** (1-indexed) that simultaneously satisfy Valid Channels and Spectral Separation, even if we completely ignore Channel Exclusivity and all other clients.
- `LOAD c` — It is mathematically impossible to find valid sets of channels for all clients on Fiber **c** (where **c** $\in \{1, 2\}$) that simultaneously satisfy Valid Channels and Channel Exclusivity, even if we completely ignore Spectral Separation and the other fiber.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of channels $p_{i,1}$ and $p_{i,2}$ for the first and second fiber allocations of the client, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
I changed the framing to telecom fiber allocation and replaced the "strict supremum precedence" rule with a "spectral separation" rule requiring an integer threshold $k_i$ that partitions the two sets of channels. This forces the model to mathematically deduce that the existence of such a threshold implies $p_{i,1} + p_{i,2} \leq T$, preventing simple pattern matching on "strictly precedes".
</RATIONALE>
<PRESERVED_ANSWER>
The "Spectral Separation" threshold condition is mathematically equivalent to the original strict precedence condition, and the "Channel Exclusivity" condition is exactly the original core exclusivity, meaning the precise same jobs and machines will trigger the certificates.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains INFEASIBLE (O(N) certification) because the core logic of checking $p_{i,1} + p_{i,2} > T$ and $\sum p_{i,c} > T$ is unchanged.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "integer threshold $k_i$" as a value they need to read from the input or output, though the wording "there must exist some integer threshold" makes it clear it is an existential mathematical condition.
</RISK>
