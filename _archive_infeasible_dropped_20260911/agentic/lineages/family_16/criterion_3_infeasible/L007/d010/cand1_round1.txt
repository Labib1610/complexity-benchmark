<STATEMENT>
# Problem C — Impossible Allocations: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are analyzing a system of linear constraints over binary vectors. There is a dimensionality $T$. You are given $j$ pairs of target weights $(p_{i,1}, p_{i,2})$ for $i = 1, \dots, j$.

For each index $i$, you must construct a component-1 binary vector $u_i = (u_{i,1}, u_{i,2}, \dots, u_{i,T}) \in \{0, 1\}^T$ and a component-2 binary vector $v_i = (v_{i,1}, v_{i,2}, \dots, v_{i,T}) \in \{0, 1\}^T$ such that:
1. The sum of the elements of $u_i$ is exactly $p_{i,1}$.
2. The sum of the elements of $v_i$ is exactly $p_{i,2}$.

The entire collection of vectors must satisfy three conditions:
- **Intra-Pair Orthogonality and Precedence:** For each $i$, there cannot exist any index $x$ where $u_{i,x} = 1$ and any index $y \le x$ where $v_{i,y} = 1$.
- **First-Component Sparsity:** The vector $U = \sum_{i=1}^j u_i$ must satisfy its $k$-th element $U_k \le 1$ for all $k \in \{1, \dots, T\}$.
- **Second-Component Sparsity:** The vector $V = \sum_{i=1}^j v_i$ must satisfy its $k$-th element $V_k \le 1$ for all $k \in \{1, \dots, T\}$.

You are analyzing systems where it is mathematically impossible to find any set of vectors $u_1 \dots u_j$ and $v_1 \dots v_j$ that satisfy all constraints. For every provided test case, you are guaranteed that exactly one of the following isolated conditions is the root cause of the impossibility. Output the code for the one that applies:
- `JOB i` — The requirements for index **i** (1-indexed) are impossible. It is mathematically impossible to construct even a single pair of vectors $u_i$ and $v_i$ that satisfy Intra-Pair Orthogonality and Precedence alongside their target weights, even if we completely ignore all other pairs and both Sparsity conditions.
- `LOAD c` — Component **c** (where **c** $\in \{1, 2\}$) is overloaded. It is mathematically impossible to construct the component **c** vectors across all $j$ items to satisfy its corresponding Sparsity condition alongside the target weights, even if we completely ignore the other component and the Precedence condition.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required sum of elements $p_{i,1}$ for $u_i$ and $p_{i,2}$ for $v_i$, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
Removed all scheduling and graph-mapping terminology (stages, pipelines, frontend, backend). Reformulated the problem into binary vector construction where sequential dataflow becomes an index-based precedence condition for non-zero elements, and hardware exclusivity becomes a bound on the sum of vectors. This forces the model to deduce that the index condition requires $p_1 + p_2 \le T$ distinct dimensions, and the sparsity condition limits the total weight to $T$.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that no $u_{i,x}=1$ can have an index greater than or equal to any $v_{i,y}=1$ strictly requires $p_{i,1}+p_{i,2} \le T$ for a single pair, mapping directly to `JOB i`, while the sparsity bounds on $U$ and $V$ strictly require the sum of weights for a given component across all pairs to be at most $T$, mapping directly to `LOAD c`.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The task still requires exactly the same three $O(N)$ aggregate checks (individual sum vs $T$, and two total sums vs $T$), preserving the INFEASIBLE complexity class.
</PRESERVED_CLASS>
