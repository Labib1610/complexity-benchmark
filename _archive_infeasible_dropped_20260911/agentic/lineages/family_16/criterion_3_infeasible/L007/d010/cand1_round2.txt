# Problem C — Impossible Allocations: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A hypervisor is attempting to map $j$ distinct virtual machines (VMs) into physical memory. The memory is divided into two separate banks, Bank 1 and Bank 2. Each bank provides exactly $T$ contiguous bytes of address space, from address $1$ up to $T$.

For each VM $i$, the hypervisor must allocate a single contiguous block of exactly $p_{i,1}$ bytes in Bank 1, and a single contiguous block of exactly $p_{i,2}$ bytes in Bank 2.

A valid memory mapping must satisfy three rules:
1. **Physical Bounds:** Every allocated block must fit entirely within the $1$ to $T$ address space of its respective bank.
2. **Sequential Addressing:** For any single VM $i$, every byte address in its Bank 1 block must be strictly less than every byte address in its Bank 2 block.
3. **Memory Isolation:** Within Bank 1, no two VMs can have overlapping blocks. Similarly, within Bank 2, no two VMs can have overlapping blocks.

You are debugging logs from allocation failures where a valid mapping is impossible. For every provided test case, you are guaranteed that exactly one of the following three isolated conditions is the root cause. Output the code for the condition that applies:
- `JOB i` — VM **i** (1-indexed) cannot be mapped. It is mathematically impossible to assign Bank 1 and Bank 2 blocks for this VM alone that satisfy Physical Bounds and Sequential Addressing, even if we completely ignore all other VMs.
- `LOAD 1` — Bank 1 is overloaded. It is mathematically impossible to assign Bank 1 blocks for all VMs that satisfy Physical Bounds and Memory Isolation, even if we completely ignore Bank 2 and the Sequential Addressing rule.
- `LOAD 2` — Bank 2 is overloaded. It is mathematically impossible to assign Bank 2 blocks for all VMs that satisfy Physical Bounds and Memory Isolation, even if we completely ignore Bank 1 and the Sequential Addressing rule.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of bytes in Bank 1 and Bank 2 for VM $i$, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` (where $i$ is the VM index), `LOAD 1`, or `LOAD 2`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
The scenario was shifted from discrete pipeline stages to contiguous memory blocks. While 1D contiguous packing introduces the concept of fragmentation, the specific isolated certificates requested manually bypass it, reducing exactly to the original single-job sum and total-load sum inequalities. Models must genuinely reason about the isolation guarantees to realize that simulation or fragmentation checks are unnecessary.
</RATIONALE>
<PRESERVED_ANSWER>
The isolated conditions mathematically evaluate to the exact same inequalities: a single VM's contiguous blocks require $p_{i,1}+p_{i,2} \le T$ to satisfy strict address precedence, and 1D contiguous packing without other constraints fits if and only if the sum of sizes is $\le T$.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an O(N) impossibility certification task because the test cases are guaranteed to be verifiable by checking the three isolated conditions.
</PRESERVED_CLASS>
