<STATEMENT>
# Problem C — Impossible Maneuvers: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A satellite network has $j$ scheduled orbital adjustments. Each adjustment $i$ requires exactly $p_{i,1}$ seconds of thrust from the primary engine, and exactly $p_{i,2}$ seconds of thrust from the secondary engine. The entire sequence of adjustments must be mapped to a discrete communication window consisting of $T$ integer timestamps.

A valid maneuver plan must assign each required second of thrust to a unique integer timestamp, satisfying three rules:
1. **Window Bounds:** Every assigned timestamp must be an integer chosen from $1$ to $T$ inclusive.
2. **Burn Precedence:** For any single adjustment $i$, its primary engine timestamps and secondary engine timestamps must be disjoint. Furthermore, no timestamp assigned to its primary engine may be greater than or equal to any timestamp assigned to its secondary engine.
3. **Engine Exclusivity:** For a given engine phase $c \in \{1, 2\}$ (where phase 1 is the primary engine and phase 2 is the secondary engine), a timestamp can be assigned to at most one adjustment. Thus, the primary engine sets of any two different adjustments must be disjoint, and the secondary engine sets of any two different adjustments must be disjoint.

For every provided test case, a valid maneuver plan is mathematically impossible. You are guaranteed that exactly one of the following conditions holds, serving as a certificate of impossibility. Output the code for the one that applies:
- `JOB i` — Adjustment **i** (1-indexed) is internally unsatisfiable. There does not exist any choice of primary and secondary timestamps for this adjustment alone that satisfies both Window Bounds and Burn Precedence.
- `LOAD c` — Phase **c** (where **c** $\in \{1, 2\}$) is overloaded. There does not exist any assignment of phase **c** timestamps across all adjustments that satisfies both Window Bounds and Engine Exclusivity.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of primary engine timestamps $p_{i,1}$ and secondary engine timestamps $p_{i,2}$ for the adjustment, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
Removed the explicit additive grouping of parameters ("sort all p_1 + p_2 stages") which acted as a massive affordance for models to sum the variables. Replaced it with a logically equivalent negated relational constraint ("no element in set A may be >= any element in set B"). This forces models to independently prove that the minimal span of these two disjoint sets within the bounds is exactly their sum, defeating models that rely on textual pattern matching.
</RATIONALE>
<PRESERVED_ANSWER>
The negated relational constraint mathematically requires all primary timestamps to be strictly less than all secondary timestamps, making the minimum possible maximum timestamp exactly p_1 + p_2, perfectly preserving the `JOB i` condition; the exclusivity rule requires summing phase requirements, preserving `LOAD c`.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the same co-NP style impossibility certification task, requiring checking whether a single job's sequential work or a single machine's total load exceeds the available time $T$.
</PRESERVED_CLASS>
<RISK>
Models might struggle to parse the negated relational constraint, but it is mathematically precise and unambiguous to a competent reader, posing no risk of misinterpretation.
</RISK>
