# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** distinct items. The production of each item involves exactly two sequential stages: it must first undergo preparation at stage 1, and upon completion, undergo finishing at stage 2. You are provided the duration required for each stage per item. Equipment at any stage can handle at most one item at any given moment.

The facility operates for a single shift of duration **T**. All items must be completely processed by time **T** (inclusive).

You are tasked with auditing production logs. For each log, the required production cannot possibly be completed within the shift, regardless of how the items are ordered. Your objective is to generate a concise certificate that definitively proves the impossibility of the schedule. 

A valid certificate isolates a violation of a physical constraint. One or more of the following violations may exist in a log:

- `JOB i` — The **i**-th item (1-indexed) requires a sequential chain of operations whose combined duration strictly exceeds the shift length.
- `LOAD c` — The equipment at stage **c** (where **c** is 1 or 2) is assigned a total active duration across all items that strictly exceeds the shift length.

If multiple certificates apply, you must resolve ties as follows: print `LOAD 2` if applicable; otherwise print `LOAD 1` if applicable; otherwise print `JOB i` for the smallest applicable **i**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration required for the item at stage 1 and stage 2, respectively.

## Output

Print a single line containing the applicable certificate, following the tie-breaking rules if multiple violations exist: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

The exclusivity guarantee ("exactly one of the following violations") was removed and replaced with a scenario where multiple violations may exist, alongside a strict tie-breaking hierarchy. This forces the model to actually evaluate all possible violations and apply the hierarchy, rather than using early returns for `JOB i` or inferring `LOAD 2` with a simple `else` statement. The inclusive deadline phrasing was also restored to address previous feedback.
