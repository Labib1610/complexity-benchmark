# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

An automated car detailing facility has been commissioned to service **j** vehicles (each referred to in the system logs as a `JOB`). The cleaning process for every vehicle consists of two sequential phases: it must first pass through the soap applicator (bay 1), and upon completion, pass through the high-pressure rinse arch (bay 2). You are provided the duration each vehicle must spend in each bay. Each bay can accommodate at most one vehicle at any given moment.

The facility is scheduled to operate for a single continuous block of **T** seconds. All vehicles must completely finish both phases before the facility closes.

You are tasked with auditing schedules from facilities that failed to service all vehicles. For each schedule, completing all vehicles within the **T** seconds is physically impossible, regardless of the order in which they are processed. Your objective is to generate a concise certificate that definitively proves the impossibility of the schedule.

The provided schedules are structurally guaranteed to exhibit exactly one of the following violations. You must output the unique applicable certificate:

- `JOB i` — The **i**-th vehicle (1-indexed) requires a sequential combination of soaping and rinsing whose combined duration strictly exceeds the facility's operating time **T**.
- `LOAD c` — Bay **c** (where **c** is 1 or 2) is assigned a total active duration across all **j** vehicles that strictly exceeds the facility's operating time **T**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration the vehicle must spend in bay 1 and bay 2, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

This forces the model to extract the mathematical conditions (sums of sequential phases vs. sums of individual bay times) from a new semantic domain, breaking shortcuts that relied on pattern-matching the standard "jobs and machines" scheduling vocabulary.
</RATIONALE>
