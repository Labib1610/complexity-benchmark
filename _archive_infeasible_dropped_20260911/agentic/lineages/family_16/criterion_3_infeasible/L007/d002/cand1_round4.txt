# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** distinct items. The production of each item involves exactly two sequential stages: it must first undergo preparation at stage 1, and upon completion, undergo finishing at stage 2. You are provided the duration required for each stage per item. Equipment at any stage can handle at most one item at any given moment.

The facility operates for a single shift of duration **T**. All items must be completely processed before the shift ends.

You are tasked with auditing production logs from failed facilities. For each log, the required production cannot possibly be completed within the shift, regardless of how the items are ordered. Your objective is to generate a concise certificate that definitively proves the impossibility of the schedule. 

A valid certificate isolates a violation of a physical constraint. The possible violations are:

- `JOB i` — The **i**-th item (1-indexed) requires a sequential chain of operations whose combined duration strictly exceeds the shift length.
- `LOAD c` — The equipment at stage **c** (where **c** is 1 or 2) is assigned a total active duration across all items that strictly exceeds the shift length.

Identify and print an applicable certificate for the given log.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration required for the item at stage 1 and stage 2, respectively.

## Output

Print a single line containing an applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
Removed the explicit guarantee that exactly one violation exists in every log, changing "the applicable certificate" to "an applicable certificate". This prevents models from safely using an `else` catch-all to infer a `LOAD 2` violation without checking its condition, forcing them to implement explicit verification for all constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The hidden test data still inherently contains exactly one valid certificate per log, so any valid certificate the model finds will perfectly match the original expected output.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an impossibility certification task where a single job's sequential work or a machine's serial load exceeds the time limit.
</PRESERVED_CLASS>
<RISK>
Models might assume multiple certificates could apply and attempt to implement self-imposed tie-breaking logic, though any valid certificate they output will be correct as it is unique in the test cases.
</RISK>
