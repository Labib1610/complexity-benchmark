# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** distinct items. The production of each item involves exactly two sequential stages: it must first undergo preparation at stage 1, and upon completion, undergo finishing at stage 2. You are provided the duration required for each stage per item. Equipment at any stage can handle at most one item at any given moment.

The facility operates for a single shift of duration **T**. All items must be completely processed before the shift ends.

You are tasked with auditing production logs from failed facilities. For every input, the required production cannot possibly be completed within the shift, regardless of how the items are ordered. Exactly one of the following reasons always applies. Your objective is to generate a concise certificate that definitively proves the impossibility of the schedule. You do not need to search for a schedule; only report the valid certificate implied by the physical constraints. Print the one that holds:

- `JOB i` — A single item **i** (1-indexed) dictates a continuous sequential occupation interval. Even if it transitions instantly from stage 1 to stage 2, the uninterrupted span of time needed to clear both of its stages is strictly greater than **T**.
- `LOAD c` — The machine-occupation ledger for stage **c** (where **c** is 1 or 2) necessitates an aggregate active time. If the equipment at stage **c** were to process its required tasks for all **j** items consecutively with zero idle time, the resulting span of active operation for that stage would be strictly greater than **T**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration required for the item at stage 1 and stage 2, respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

<RATIONALE>
Removed the explicit additive threshold checks (e.g., "combined duration strictly exceeds") and replaced them with an indirect physical audit formulation ("continuous sequential occupation interval" and "machine-occupation ledger"). This forces the model to deduce the mathematical sums from the physical scenario rather than pattern-matching the explicit inequalities. Added the "exactly one reason applies" guarantee and explicit strictness language to resolve previous ambiguity flags without restoring the forbidden formulas.
</RATIONALE>
<PRESERVED_ANSWER>
The textual definitions of the intervals mathematically evaluate to the exact same strict inequalities as the seed (`p1_i + p2_i > T` and `sum(p_c) > T`), ensuring the correct certificate remains identical for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an INFEASIBLE certificate-checking task, requiring a linear scan to verify if an individual item's total time or a machine's aggregate load exceeds the given threshold.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "uninterrupted span of time needed to clear both of its stages" as a non-additive property, though "strictly greater than T" makes the mathematical threshold clear to a careful reader.
</RISK>
