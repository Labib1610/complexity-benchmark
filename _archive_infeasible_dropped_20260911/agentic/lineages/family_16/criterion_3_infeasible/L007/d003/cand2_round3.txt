<STATEMENT>
# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** distinct items. The production of each item involves exactly two sequential stages: it must first undergo preparation at stage 1, and upon completion, undergo finishing at stage 2. You are provided the duration required for each stage per item. Equipment at any stage can handle at most one item at any given moment.

The facility operates for a single shift of duration **T**. All items must be completely processed before the shift ends.

You are tasked with auditing production logs from failed facilities. For each log, the required production cannot possibly be completed within the shift, regardless of how the items are ordered. Your objective is to generate a concise certificate that definitively proves the impossibility of the schedule. 

A valid certificate isolates a violation of a physical limitation. The possible violations are:

- `JOB i` — The **i**-th item (1-indexed) could not theoretically complete its two stages within the shift duration **T**, even in an ideal scenario where it is processed entirely alone.
- `LOAD c` — The equipment at stage **c** (where **c** is 1 or 2) could not theoretically complete its required operations on all items within the shift duration **T**, even in an ideal scenario where it operates non-stop.

Identify and print an applicable certificate for the given log.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration required for the item at stage 1 and stage 2, respectively.

## Output

Print a single line containing an applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```
</STATEMENT>
<RATIONALE>
Removed the explicit arithmetic descriptions ("combined duration", "total active duration") that allowed models to pattern-match the `p1 + p2 > T` and `sum(p_c) > T` threshold checks. Replaced them with an indirect physical audit formulation ("processed entirely alone" and "operates non-stop"). This forces the model to logically derive the minimum possible completion times under these ideal scenarios to construct the threshold checks, while remaining completely unambiguous.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that an item fails even if processed alone is mathematically identical to `p1 + p2 > T`, and the condition that equipment fails even if operating non-stop is mathematically identical to `sum(p_c) > T`, so the valid certificates for any input remain exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains INFEASIBLE (co-NP style certification) because it still requires finding a single item whose sequential processing time exceeds the deadline or a single machine whose total load exceeds the deadline.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "processed entirely alone" or "operates non-stop" as involving schedule-dependent delays, but the phrasing explicitly frames these as "ideal scenarios" to strictly bound the minimum possible time, which minimizes this risk.
</RISK>
