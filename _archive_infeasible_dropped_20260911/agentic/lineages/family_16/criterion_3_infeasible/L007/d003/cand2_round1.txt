# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes **j** distinct items. The production of each item involves exactly two sequential stages: it must first undergo preparation at stage 1, and upon completion, undergo finishing at stage 2. You are provided the duration required for each stage per item. Equipment at any stage can handle at most one item at any given moment.

The facility operates for a single shift of duration **T**. All items must be completely processed before the shift ends.

You are tasked with auditing production logs from failed facilities. For each log, the required production cannot possibly be completed within the shift, regardless of how the items are ordered. Your objective is to generate a concise certificate that definitively proves the impossibility of the schedule. 

A valid certificate isolates a violation of a physical constraint. The possible violations are:

- `JOB i` — A valid schedule requires an item's stage 2 processing interval to begin no earlier than the completion of its stage 1 processing interval. For the **i**-th item (1-indexed), no such pair of intervals of the required lengths can be placed entirely between time 0 and time **T**.
- `LOAD c` — A valid schedule requires that no two items are processed on the same equipment simultaneously. For the equipment at stage **c** (where **c** is 1 or 2), no set of mutually disjoint intervals of the required lengths for all items can be placed entirely between time 0 and time **T**.

Identify and print an applicable certificate for the given log.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration required for the item at stage 1 and stage 2, respectively.

## Output

Print a single line containing an applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```
</STATEMENT>
<RATIONALE>
I replaced the explicit arithmetic definitions of JOB and LOAD certificates ("combined duration strictly exceeds", "total active duration... strictly exceeds") with their underlying physical scheduling constraints. Models must now read the interval sequencing and mutual exclusion rules and deduce that they mathematically correspond to checking if the sum of durations exceeds T.
</RATIONALE>
<PRESERVED_ANSWER>
The physical interval constraints are mathematically identical to the arithmetic threshold checks: sequential intervals fit if and only if their sum is at most T, and disjoint intervals fit if and only if their sum is at most T.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains identical because the conditions can still be evaluated in O(N) time by streaming the input and maintaining sums.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "mutually disjoint intervals" as implying the items must be scheduled continuously without gaps, though mathematically both require the exact same sum condition.
</RISK>
