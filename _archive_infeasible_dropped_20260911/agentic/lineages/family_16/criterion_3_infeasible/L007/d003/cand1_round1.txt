# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant processes **j** distinct items during a single operating window of duration **T**. Every item must be fully processed before the window closes. Processing an item requires exactly two sequential steps: preparation at stage 1, followed immediately or eventually by finishing at stage 2. The plant's equipment can only handle one item at a time at any given stage. You are given the processing times for both stages of each item.

You are auditing records from plants that failed to meet their quotas. In every provided record, it is physically impossible to complete all items within the operating window, no matter what schedule is attempted. You must output a concise certificate that proves this impossibility.

A valid certificate demonstrates a fundamental bottleneck. The acceptable certificates are:

- `JOB i` — If the **i**-th item (1-indexed) were the only item in the plant and experienced zero wait time between its two steps, its completion time would still fall after the window closes.
- `LOAD c` — If the equipment at stage **c** (where **c** is 1 or 2) operated continuously without a single idle gap, the time required to complete its portion of the work for all items would exceed the window's duration.

Determine and output an applicable certificate for the given record.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
The next **j** lines each contain two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the processing times required for the item at stage 1 and stage 2, respectively.

## Output

Output a single line containing an applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

The previous statement explicitly handed the solver the mathematical thresholds (`combined duration strictly exceeds...`, `total active duration... strictly exceeds`). This rewrite replaces those explicit formulas with a physical audit framing: defining invalidity through the hypothetical scenarios of a single item with zero wait time, or a machine operating with zero idle gaps. Models must now deduce that these physical scenarios correspond to the scalar sums `p1 + p2 > T` and `sum(p_c) > T`.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for outputting a certificate remain mathematically identical: `JOB i` requires p1 + p2 > T, and `LOAD c` requires the sum of processing times at stage c to exceed T, so the identical outputs are valid.
</PRESERVED_ANSWER>
