<METHOD_DESCRIPTION>Transforms the continuous scheduling problem into assigning contiguous subsets of integers. The intra-job precedence constraint becomes a strict inequality between all elements of two sets. The machine capacity constraint becomes pairwise disjointness of sets. This preserves the exact same impossibility certificates but uses set theory and discrete math terminology instead of time, intervals, or scheduling.</METHOD_DESCRIPTION>

<STATEMENT>
# Impossible Domains: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are analyzing a discrete allocation system. The system must assign contiguous subsets of integers from the domain $U = \{1, 2, \dots, T\}$.

There are $j$ requests. Each request $i \in \{1 \dots j\}$ requires two contiguous sets of integers, $S_{i,1}$ and $S_{i,2}$.
The required size of $S_{i,1}$ is $p_{i,1}$, and the required size of $S_{i,2}$ is $p_{i,2}$.
Because the sets must be contiguous, if a set starts at integer $x$ and has size $k$, it consists exactly of the integers $\{x, x+1, \dots, x+k-1\}$. All elements of every assigned set must strictly belong to $U$.

A valid complete allocation must satisfy two rules:
1. **Separation:** For every request $i$, every integer in $S_{i,1}$ must be strictly less than every integer in $S_{i,2}$.
2. **Exclusivity:** For a fixed index $c \in \{1, 2\}$, the sets $S_{1,c}, S_{2,c}, \dots, S_{j,c}$ must be pairwise disjoint. (That is, no two requests can share an integer in their first sets, and no two requests can share an integer in their second sets).

You are given logs from failed systems where a valid complete allocation is mathematically impossible. For every provided test case, exactly one of the following reasons is guaranteed to be the cause of the failure. Output the code for the one that applies:
- `JOB i` — It is mathematically impossible to choose contiguous sets $S_{i,1}$ and $S_{i,2}$ within $U$ that satisfy the **Separation** rule for request **i** (1-indexed), even if we completely ignore the Exclusivity rule and all other requests.
- `LOAD c` — It is mathematically impossible to choose contiguous sets $S_{1,c}, \dots, S_{j,c}$ within $U$ that satisfy the **Exclusivity** rule for index **c** (where **c** $\in \{1, 2\}$), even if we completely ignore the Separation rule and the other index.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the following $j$ lines contains two integers $p_{i,1}$ and $p_{i,2}$ ($1 \le p_{i,1}, p_{i,2} \le 1000000$): the required sizes for $S_{i,1}$ and $S_{i,2}$ respectively.

## Output

Print a single line containing the applicable certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```
</STATEMENT>
<RATIONALE>
Changed the framing from continuous scheduling/signal processing to allocating contiguous subsets of integers. This removes interval-packing and temporal precedence keywords, forcing the model to independently deduce that "strictly less than" for contiguous sets implies a sum-of-sizes lower bound, and "pairwise disjoint" implies a total-size lower bound.
</RATIONALE>
<PRESERVED_ANSWER>
The impossibility of Separation for request i is algebraically identical to p_{i,1} + p_{i,2} > T, and the impossibility of Exclusivity for index c is identical to sum(p_{i,c}) > T, matching the original conditions perfectly.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires exactly the same O(j) sequential sum and per-component sum checks to identify the certificate.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "strictly belong to U" as allowing non-integers if not careful, but "subsets of integers from the domain U" makes it unambiguously discrete.
</RISK>
