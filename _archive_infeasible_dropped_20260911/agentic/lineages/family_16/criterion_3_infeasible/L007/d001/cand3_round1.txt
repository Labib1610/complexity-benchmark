# Problem C — SLA Breach Diagnostic

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud architecture processes a batch of **j** client requests. The infrastructure consists of two sequential tiers: a Frontend Gateway (Tier 1) and a Backend Database (Tier 2). Every request must be processed by Tier 1 before it can be handed off to Tier 2. A tier can only process one request at a time.

You are given a strict Service Level Agreement (SLA) window of **T** milliseconds. The entire batch must be completely resolved within this window. 

The provided batches are known to be invalid; it is mathematically impossible to process them within **T** milliseconds under any scheduling strategy. Your task is to output a diagnostic certificate explaining why the batch fails. Exactly one valid diagnostic certificate exists for each test case, corresponding to one of these two structural limits:

- **Sequential Path Violation**: A specific request cannot complete within the SLA even if it were the only request in the system. Because a request must clear Tier 1 and then Tier 2, its minimum end-to-end footprint is the combined duration it spends actively processing on both tiers. If this combined duration for a single request strictly exceeds the SLA window, output `JOB i`, where **i** is the 1-based index of this request.
- **Tier Saturation**: A tier's cumulative active time exceeds the SLA. Because a tier handles requests one by one, it must remain active for the total duration of all tasks assigned to it across the entire batch. If the sum of all Tier 1 durations, or the sum of all Tier 2 durations, strictly exceeds the SLA window, output `LOAD c`, where **c** is the saturated tier (1 or 2).

## Input

The first line provides two integers **j** and **T** (1 ≤ **j** ≤ 200,000, 1 ≤ **T** ≤ 1,000,000,000).
The subsequent **j** lines each contain two integers **p1** and **p2** (1 ≤ **p1**, **p2** ≤ 1,000,000), representing the milliseconds the request requires on Tier 1 and Tier 2, respectively.

## Output

Output a single line containing the diagnostic certificate: either `JOB i` or `LOAD c`. 

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the first request requires 70 milliseconds on Tier 1 and 60 milliseconds on Tier 2. Its combined sequential footprint is 130 milliseconds. Since 130 > 100, the SLA is breached by this request alone, yielding `JOB 1`. 

In Example 2, no individual request's combined footprint exceeds 150 milliseconds. However, Tier 1 is requested to be active for 50 + 50 + 50 + 50 = 200 milliseconds across the batch. Since 200 > 150, Tier 1 is saturated, yielding `LOAD 1`.
