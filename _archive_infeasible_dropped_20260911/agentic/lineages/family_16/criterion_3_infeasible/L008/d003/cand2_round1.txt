# Problem C — Telemetry Window: Diagnostic Code

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital satellite is scheduled to execute **j** observation jobs before the mission window closes at $t = \mathbf{T}$ milliseconds.

Each observation job consists of two strictly ordered phases:
1. The targeting gimbal (Subsystem 1) must be dedicated to the job for a continuous block of **p1** milliseconds.
2. Only after this gimbal block has fully concluded, the imaging sensor (Subsystem 2) must be dedicated to the job for a continuous block of **p2** milliseconds.

The hardware dictates that the gimbal's blocks cannot overlap with each other, and the sensor's blocks cannot overlap with each other.

Mission control has determined that no valid schedule exists that finishes all phases by $t = \mathbf{T}$. You must output a diagnostic code that demonstrates a fundamental timeline violation.

The diagnostic code must be one of the following:
- `JOB i` (where **i** is the 1-based job index). This asserts that a simulated timeline isolating observation **i**—starting its first phase at $t=0$ and immediately transitioning to its second phase—yields a final phase-end timestamp strictly greater than $\mathbf{T}$.
- `LOAD c` (where **c** is 1 or 2). This asserts that a simulated timeline consolidating all operations for Subsystem **c**—starting the first operation at $t=0$ and immediately transitioning to subsequent operations on that subsystem—yields a final subsystem occupied interval ending strictly after $t=\mathbf{T}$.

The telemetry data is guaranteed to trigger exactly one of these fundamental timeline violations. Print the corresponding code.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration of the gimbal block and the duration of the sensor block for that observation job.

## Output

Print a single line containing the valid diagnostic code (`JOB i` or `LOAD c`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is valid because a simulated timeline isolating observation 1 yields a first phase-end timestamp at $t=70$ and a final phase-end timestamp at $t=130$, which is strictly greater than the $100$ deadline.

In Example 2, `LOAD 1` is valid because a simulated timeline consolidating all operations for Subsystem 1 yields a final subsystem occupied interval ending at $t=200$, which is strictly after the $150$ deadline.
</STATEMENT>
<RATIONALE>
The previous wording explicitly framed the violation conditions using arithmetic terms like "cumulative active footprint" and "earliest possible conclusion," which let models directly map the text to `p1+p2>T` and `sum(p)>T` without understanding the schedule timeline. I replaced these with an indirect telemetry-timeline formulation, forcing models to infer that a "simulated timeline isolating observation i" requires computing the sum of its two phases, and "consolidating all operations for Subsystem c" requires computing the aggregate duration across all jobs for that subsystem.
</RATIONALE>
