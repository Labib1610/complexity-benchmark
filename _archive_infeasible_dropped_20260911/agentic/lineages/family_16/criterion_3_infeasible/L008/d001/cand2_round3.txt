# Problem C — Telemetry Window: Diagnostic Code

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital satellite is scheduled to execute **j** observation jobs before it passes out of communication range in exactly **T** milliseconds.

Each observation job requires two sequential phases:
1. First, the targeting gimbal (Subsystem 1) must orient to the correct coordinates. This takes **p1** milliseconds.
2. Afterward, the imaging sensor (Subsystem 2) must expose the frame. This takes **p2** milliseconds.

The satellite's hardware constraints dictate that:
- The targeting gimbal can only orient for one job at a time.
- The imaging sensor can only expose for one job at a time.
- For any given job, the imaging sensor cannot begin its exposure until the gimbal has completely finished orienting for that specific job.

Mission control has determined that completing all **j** jobs within the **T** millisecond window is impossible, regardless of the execution order. Your task is not to attempt a schedule, but to output a diagnostic code proving why the sequence cannot be completed. The certificate can be checked directly against the input.

Test data is constructed so that exactly one of the two following failure categories applies to any given test case. Print the code for the unique applicable reason:

- **Isolated Job Failure:** A single job is structurally impossible to complete within the communication window, even if it were the only job scheduled, due to the sequential dependency of its own phases.
  Print: `JOB i` — where **i** (1-based) is the index of such an observation job.

- **Subsystem Saturation:** A specific hardware subsystem lacks sufficient total uptime in the communication window to process its required phase for all scheduled jobs, even if we assume no idle time on that subsystem.
  Print: `LOAD c` — where **c** is the subsystem number (1 for the targeting gimbal, or 2 for the imaging sensor).

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the orientation time on Subsystem 1 and the exposure time on Subsystem 2 for that observation job.

## Output

Print a single line: the diagnostic code for the unique applicable reason category (`JOB i` or `LOAD c`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, observation job 1 requires 70 milliseconds of orientation followed sequentially by 60 milliseconds of exposure. The sequential nature of these phases means this job alone cannot complete within the 100-millisecond window, so `JOB 1` is the correct diagnostic code. In Example 2, every individual job can easily complete within 150 milliseconds. However, the targeting gimbal (Subsystem 1) requires four separate 50-millisecond orientations. Since it can only orient for one job at a time, it would need 200 milliseconds of active time, which exceeds the window. Thus, `LOAD 1` is the correct diagnostic code.
