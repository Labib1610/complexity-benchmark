# Problem C — Telemetry Window: Diagnostic Code

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital satellite is scheduled to execute **j** observation jobs before it passes out of communication range in exactly **T** milliseconds.

Each observation job requires two sequential phases:
1. First, the targeting gimbal (Subsystem 1) must orient to the correct coordinates. This takes **p1** milliseconds.
2. Afterward, the imaging sensor (Subsystem 2) must expose the frame. This takes **p2** milliseconds.

The satellite's hardware constraints dictate that:
- The targeting gimbal can only process one job at a time.
- The imaging sensor can only process one job at a time.
- For any given job, the imaging sensor cannot begin processing until the gimbal has completely finished processing that specific job.

Mission control has determined that completing all **j** jobs within the **T** millisecond window is impossible, regardless of the execution order. Your task is to output a diagnostic code that independently proves this impossibility.

A valid diagnostic code must be one of the following:
- `JOB i` (where **i** is a 1-based job index). This code certifies that even if no other jobs were scheduled, job **i** alone could not be completed within the time window.
- `LOAD c` (where **c** is 1 or 2). This code certifies that even if the other subsystem operated instantaneously, Subsystem **c** alone could not complete its required work for all jobs within the time window.

You are guaranteed that the provided telemetry data will support exactly one of these assertions. Print the valid code.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the orientation time on Subsystem 1 and the exposure time on Subsystem 2 for that observation job.

## Output

Print a single line containing the valid diagnostic code (`JOB i` or `LOAD c`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is valid because job 1 alone requires 70 milliseconds on Subsystem 1 followed by 60 milliseconds on Subsystem 2. This sequence cannot finish within 100 milliseconds.

In Example 2, `LOAD 1` is valid because Subsystem 1 must operate for 50+50+50+50 = 200 milliseconds in total. Even if Subsystem 2 took zero time, Subsystem 1 cannot finish within 150 milliseconds.

<RATIONALE>
Removed the explicit inequalities (p1+p2 > T, sum(p1) > T, sum(p2) > T) and replaced them with counterfactual scenarios ("even if no other jobs were scheduled", "even if the other subsystem operated instantaneously"). This forces the model to derive the mathematical bounds from the physical constraints of the subsystems rather than simply transcribing given formulas.
</RATIONALE>
<PRESERVED_ANSWER>
The counterfactual scenarios mathematically evaluate to the exact same inequalities as the original problem, ensuring the identical diagnostic code is valid for every input.
</PRESERVED_ANSWER>

<RISK>
Models might misinterpret "even if the other subsystem operated instantaneously" as implying a different scheduling overlap rule, though the note explicitly clarifies that the total serial operational time of the subsystem is what exceeds the window.
