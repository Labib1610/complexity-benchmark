<STATEMENT>
# Problem C — Telemetry Window: Diagnostic Code

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital satellite executes $j$ observation jobs within a mission window of $T$ seconds. 

For each job $k \in \{1 \dots j\}$, the telemetry system must allocate an instantaneous rate of gimbal processing $g_k(t) \ge 0$ and sensor processing $s_k(t) \ge 0$ at each moment $t \in [0, T]$. 

A physically valid execution must satisfy the following constraints:
1. **Completion:** For every job $k$, the total accumulated gimbal processing $\int_{0}^{T} g_k(t) dt$ must exactly equal $p1_k$, and the total accumulated sensor processing $\int_{0}^{T} s_k(t) dt$ must exactly equal $p2_k$.
2. **Phase Precedence:** For each job $k$, sensor processing cannot occur until gimbal processing is complete. Specifically, $s_k(t) = 0$ for any time $t$ where $\int_{0}^{t} g_k(\tau) d\tau < p1_k$.
3. **Gimbal Bandwidth:** At any time $t \in [0, T]$, the total gimbal processing rate across all jobs cannot exceed 1: $\sum_{k=1}^{j} g_k(t) \le 1$.
4. **Sensor Bandwidth:** At any time $t \in [0, T]$, the total sensor processing rate across all jobs cannot exceed 1: $\sum_{k=1}^{j} s_k(t) \le 1$.

Mission control has determined that no valid execution functions $g_k(t)$ and $s_k(t)$ can exist for the current schedule. You must output a diagnostic code that identifies a source of the failure. 

The telemetry data is guaranteed to trigger at least one of the following impossibility conditions. Print the corresponding code (if multiple apply, you may output any valid one):
- `JOB i` (where $i$ is the 1-based job index): It is mathematically impossible to define non-negative functions $g_i(t)$ and $s_i(t)$ for $t \in [0, T]$ such that:
  - $\int_0^T g_i(t) dt = p1_i$ and $\int_0^T s_i(t) dt = p2_i$
  - $s_i(t) = 0$ for any time $t$ where $\int_0^t g_i(\tau) d\tau < p1_i$
  - $g_i(t) \le 1$ and $s_i(t) \le 1$ for all $t \in [0, T]$
- `LOAD 1`: It is mathematically impossible to define non-negative functions $g_1(t) \dots g_j(t)$ for $t \in [0, T]$ such that $\int_0^T g_k(t) dt = p1_k$ for all $k \in \{1 \dots j\}$, and $\sum_{k=1}^j g_k(t) \le 1$ for all $t$.
- `LOAD 2`: It is mathematically impossible to define non-negative functions $s_1(t) \dots s_j(t)$ for $t \in [0, T]$ such that $\int_0^T s_k(t) dt = p2_k$ for all $k \in \{1 \dots j\}$, and $\sum_{k=1}^j s_k(t) \le 1$ for all $t$.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p1$ and $p2$ ($1 \le p1, p2 \le 1000000$): the required total gimbal processing and total sensor processing for that observation job.

## Output

Print a single line containing the valid diagnostic code (`JOB i` or `LOAD c`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is triggered because the conditions require $g_1(t) \le 1$, meaning the integral $\int_0^t g_1(\tau) d\tau$ can grow at a maximum rate of 1. It will take at least 70 seconds for this integral to reach 70. During this time, $s_1(t)$ must remain 0. This leaves at most $100 - 70 = 30$ seconds for sensor processing. Since $s_1(t) \le 1$, the maximum possible value for $\int_0^{100} s_1(t) dt$ is 30, making it impossible to reach the required $p2_1 = 60$.

In Example 2, `LOAD 1` is triggered because the required gimbal processing for all four jobs sums to $50 \times 4 = 200$. However, the maximum possible value for the integral of the sum $\int_0^{150} \sum_{k=1}^4 g_k(t) dt$ is $\int_0^{150} 1 dt = 150$. This contradiction makes it mathematically impossible to satisfy the conditions for the set of all jobs.

<RATIONALE>
The problem was rewritten to use instantaneous rate functions and integrals rather than the seed's cumulative processing functions. This breaks the specific wording patterns the LLMs were using to immediately extract the scalar inequalities. Furthermore, the diagnostic cases are now completely self-contained mathematical impossibility statements, resolving the expert's concern about ambiguity in partial rule application while forcing the solver to deduce the endpoint workload inequalities from the integral limits.
</RATIONALE>

The mathematical conditions for impossibility are perfectly equivalent because the maximum integral of a non-negative function bounded by 1 over an interval of length T is exactly T, meaning the same individual job limits and total load bottlenecks apply.
