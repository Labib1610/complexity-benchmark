# Problem C — Dual-Stage Pipeline Validation

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing facility processes a batch of $j$ jobs through a nonpreemptive two-stage pipeline within a strict operational deadline of $T$ seconds. 

The pipeline consists of Machine A (Stage 1) and Machine B (Stage 2). For each job $k \in \{1 \dots j\}$, the production requires exactly $p1_k$ seconds of continuous processing on Machine A, followed later by exactly $p2_k$ seconds of continuous processing on Machine B. Both machines can process at most one job at a time.

A schedule is defined by assigning two real-valued start times to each job $k$: $x_k$ (the time it begins on Machine A) and $y_k$ (the time it begins on Machine B). A schedule is physically executable if and only if it satisfies all of the following algebraic constraints:

1. **Machine A Bounds:** For all $k \in \{1 \dots j\}$, $0 \le x_k$ and $x_k + p1_k \le T$.
2. **Machine B Bounds:** For all $k \in \{1 \dots j\}$, $0 \le y_k$ and $y_k + p2_k \le T$.
3. **Sequential Flow:** For all $k \in \{1 \dots j\}$, $x_k + p1_k \le y_k$.
4. **Machine A Exclusivity:** For any two distinct jobs $u$ and $v$ in $\{1 \dots j\}$, $\max(x_u, x_v) \ge \min(x_u + p1_u, x_v + p1_v)$.
5. **Machine B Exclusivity:** For any two distinct jobs $u$ and $v$ in $\{1 \dots j\}$, $\max(y_u, y_v) \ge \min(y_u + p2_u, y_v + p2_v)$.

The facility's control system has determined that no physically executable schedule exists for the current batch of jobs. You must output a diagnostic code identifying the isolated source of this impossibility. 

The input data is guaranteed to trigger exactly one of the following isolated contradictions. Print the corresponding code:
- `JOB i` (where $i$ is the 1-based index of the job): It is mathematically impossible to assign start times $x_i$ and $y_i$ for job $i$ that simultaneously satisfy Constraints 1, 2, and 3 (assuming all other jobs are ignored and Constraints 4 and 5 are lifted). If multiple jobs satisfy this, you may output the code for any such job.
- `LOAD 1`: It is mathematically impossible to assign start times $x_1 \dots x_j$ for all $j$ jobs that simultaneously satisfy Constraints 1 and 4 (assuming Constraints 2, 3, and 5 are lifted, meaning jobs do not need to visit Machine B and precedence is ignored).
- `LOAD 2`: It is mathematically impossible to assign start times $y_1 \dots y_j$ for all $j$ jobs that simultaneously satisfy Constraints 2 and 5 (assuming Constraints 1, 3, and 4 are lifted, meaning jobs do not need to visit Machine A and precedence is ignored).

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p1$ and $p2$ ($1 \le p1, p2 \le 1000000$): the required processing times on Machine A and Machine B for that job.

## Output

Print a single line containing the valid diagnostic code (`JOB i`, `LOAD 1`, or `LOAD 2`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is triggered because Constraint 1 requires $x_1 \ge 0$, and Constraint 3 requires $y_1 \ge x_1 + 70$, which forces $y_1 \ge 70$. Constraint 2 requires $y_1 + 60 \le 100$, forcing $y_1 \le 40$. The bounds $y_1 \ge 70$ and $y_1 \le 40$ form a direct contradiction, making it impossible to satisfy Constraints 1, 2, and 3 for job 1.

In Example 2, `LOAD 1` is triggered because Constraint 1 requires $0 \le x_k \le 100$ for all four jobs. Constraint 4 requires that for any pair of jobs, the difference between their start times is at least 50. Sorting the four start times in ascending order, the constraints force the fourth job to start at least $3 \times 50 = 150$ seconds after the first job. Since the first job must start at $x \ge 0$, the fourth job must start at $x \ge 150$. However, Constraint 1 requires the fourth job to start at $x \le 150 - 50 = 100$. This contradiction makes it mathematically impossible to satisfy Constraints 1 and 4 simultaneously.
</STATEMENT>
<RATIONALE>
To satisfy the strict requirement of preserving the execution model (nonpreemptive two-machine scheduling), this rewrite keeps the exact physical framing of Machine A, Machine B, and non-overlapping start times. However, it removes the textual affordances ("overlap", "capacity", "sum") by defining the physical constraints as a strict system of algebraic inequalities. The non-overlapping requirement is obfuscated into the min/max inequality, forcing models to algebraically deduce that Constraint 4 over $j$ items implies a sum reduction, rather than relying on surface pattern matching.
</RATIONALE>
<PRESERVED_ANSWER>
The algebraic constraints are mathematically isomorphic to the original scheduling conditions, meaning `JOB i` still triggers if and only if p1+p2 > T, and the `LOAD` codes trigger if and only if the respective sums exceed T.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an O(N) impossibility certification where the solution is found by checking the linear feasibility bounds for individual jobs and the aggregate sums for the machines.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the min/max inequality as an $O(N^2)$ pairwise requirement to be simulated rather than a global structural bound, leading to Time Limit Exceeded, though the wording is mathematically unambiguous.
</RISK>
