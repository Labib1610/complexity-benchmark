<STATEMENT>
# Problem C — Non-Contiguous Pipeline Validation

Time limit: 2 s   Memory limit: 256 MB

## Description

A high-performance computing cluster must execute a batch of $j$ tasks within a strict time window of $T$ discrete clock cycles. The available cycles form a universal set $U = \{1, 2, \dots, T\}$.

Each task $k \in \{1 \dots j\}$ requires two disjoint allocations of cycles: a primary set of exactly $p1_k$ CPU cycles, and a secondary set of exactly $p2_k$ GPU cycles. Unlike traditional scheduling, a task's cycles do not need to be contiguous; they can be any arbitrary subsets of $U$.

A complete valid schedule must satisfy all of the following structural properties:

1. **Time Bound:** For all tasks, their assigned CPU and GPU cycle sets must be subsets of $U$.
2. **Strict Precedence:** For each task $k$, every CPU cycle assigned to it must be strictly earlier (numerically less) than every GPU cycle assigned to it.
3. **CPU Isolation:** The CPU can process at most one task per cycle, meaning the $j$ primary CPU cycle sets must be mutually disjoint.
4. **GPU Isolation:** The GPU can process at most one task per cycle, meaning the $j$ secondary GPU cycle sets must be mutually disjoint.

The cluster's pre-flight scheduler has determined that no valid schedule exists for the given batch. You must output a diagnostic code identifying a fundamental limit that has been breached. 

The input data is guaranteed to trigger at least one of the following isolated impossibilities. If multiple apply, you may output the code for any valid one:
- `JOB i` (where $i$ is the 1-based index of the task): It is mathematically impossible to assign the cycle sets for task $i$ to satisfy properties 1 and 2, even if it were the only task.
- `LOAD 1`: It is mathematically impossible to assign the CPU cycle sets for all $j$ tasks to satisfy properties 1 and 3.
- `LOAD 2`: It is mathematically impossible to assign the GPU cycle sets for all $j$ tasks to satisfy properties 1 and 4.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p1$ and $p2$ ($1 \le p1, p2 \le 1000000$): the required exact number of CPU cycles and GPU cycles for that task.

## Output

Print a single line containing a valid diagnostic code (`JOB i`, `LOAD 1`, or `LOAD 2`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is triggered because task 1 requires a set of 70 CPU cycles and a set of 60 GPU cycles. Property 2 requires every CPU cycle to be strictly earlier than every GPU cycle, which implies the two sets must be disjoint. Thus, task 1 requires at least $70 + 60 = 130$ distinct cycles. Since the available window $U$ only contains $T = 100$ cycles, it is impossible to construct these sets for task 1 even in isolation.

In Example 2, `LOAD 1` is triggered because there are four tasks, each requiring a set of 50 CPU cycles. Property 3 requires these four sets to be mutually disjoint, which means their union would require exactly $4 \times 50 = 200$ distinct cycles. Since the available window $U$ only contains $T = 150$ cycles, it is mathematically impossible to assign these CPU sets.
</STATEMENT>
<RATIONALE>
The problem was shifted from an explicit 1D geometric interval packing scenario to a discrete, non-contiguous subset scheduling model. This breaks the models' surface-level mapping of "sliders in a track" to geometric sum inequalities, forcing them to reason mathematically. Genuinely reasoning models will recognize that mutually disjoint subsets of a universe $U$ trivially imply that the sum of their sizes cannot exceed $|U|$, while pattern-matching models will attempt to simulate complex non-contiguous subset allocations and fail. The "exactly one" guarantee was also relaxed to "at least one" to fix a logical flaw identified in the expert review while maintaining the same output contract.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical requirements for disjoint subsets in a bounded universe of size $T$ perfectly reduce to the original lower bounds (`p1+p2 > T`, `sum(p1) > T`, `sum(p2) > T`), meaning the exact same inputs trigger the exact same diagnostic codes.
</PRESERVED_ANSWER>

The problem remains in the INFEASIBLE complexity class, as the intended solution is still an $O(N)$ certification of the violated capacity bounds.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "arbitrary subsets of U" as allowing overlapping cycles if they fail to read the strict isolation properties, but the isolation properties are explicitly defined as "mutually disjoint," which is standard and unambiguous.
</RISK>
