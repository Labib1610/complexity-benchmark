# Problem C — Kinematic Constraints Validation

Time limit: 2 s   Memory limit: 256 MB

## Description

A physics engine must validate a 1D kinematic configuration of $j$ mechanical linkages within a bounding track of length $T$. The track extends continuously from coordinate $0$ to coordinate $T$.

Each linkage $k \in \{1 \dots j\}$ consists of a primary component and a secondary component. The span parameters for these components are given as $p1_k$ and $p2_k$, respectively. 

To define a configuration, the engine must assign four real-valued anchor coordinates $A_k, B_k, C_k,$ and $D_k$ to each linkage $k$. A configuration is physically realizable if and only if it satisfies all of the following algebraic conditions:

1. **Primary Bounds:** For all $k \in \{1 \dots j\}$, $A_k \ge 0$ and $B_k \le T$.
2. **Secondary Bounds:** For all $k \in \{1 \dots j\}$, $C_k \ge 0$ and $D_k \le T$.
3. **Primary Span:** For all $k \in \{1 \dots j\}$, $B_k - A_k = p1_k$.
4. **Secondary Span:** For all $k \in \{1 \dots j\}$, $D_k - C_k = p2_k$.
5. **Sequence:** For all $k \in \{1 \dots j\}$, $B_k \le C_k$.
6. **Primary Separation:** For any two distinct linkages $u$ and $v$ in $\{1 \dots j\}$, their coordinates must satisfy: $|A_u - A_v| + |B_u - B_v| \ge p1_u + p1_v$.
7. **Secondary Separation:** For any two distinct linkages $u$ and $v$ in $\{1 \dots j\}$, their coordinates must satisfy: $|C_u - C_v| + |D_u - D_v| \ge p2_u + p2_v$.

The engine has determined that no physically realizable configuration exists for the current batch of linkages. You must output a diagnostic code identifying the isolated source of this impossibility. 

The input data is guaranteed to trigger exactly one of the following isolated contradictions. Print the corresponding code:
- `JOB i` (where $i$ is the 1-based index of the linkage): It is mathematically impossible to assign $A_i, B_i, C_i, D_i$ for linkage $i$ to simultaneously satisfy Constraints 1, 2, 3, 4, and 5 (assuming all other linkages are ignored and Constraints 6 and 7 are lifted). If multiple linkages satisfy this, you may output the code for any such linkage.
- `LOAD 1`: It is mathematically impossible to assign $A_k, B_k$ for all $j$ linkages to simultaneously satisfy Constraints 1, 3, and 6 (assuming Constraints 2, 4, 5, and 7 are lifted).
- `LOAD 2`: It is mathematically impossible to assign $C_k, D_k$ for all $j$ linkages to simultaneously satisfy Constraints 2, 4, and 7 (assuming Constraints 1, 3, 5, and 6 are lifted).

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p1$ and $p2$ ($1 \le p1, p2 \le 1000000$): the span parameters for the primary and secondary components of that linkage.

## Output

Print a single line containing the valid diagnostic code (`JOB i`, `LOAD 1`, or `LOAD 2`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is triggered because linkage 1 requires $B_1 - A_1 = 70$ and $D_1 - C_1 = 60$. Constraint 5 requires $B_1 \le C_1$. Combining these gives $A_1 + 70 \le D_1 - 60$, which simplifies to $D_1 - A_1 \ge 130$. However, Constraints 1 and 2 require $A_1 \ge 0$ and $D_1 \le 100$, meaning $D_1 - A_1 \le 100$. This forms a direct contradiction, making it impossible to satisfy Constraints 1 through 5 for linkage 1.

In Example 2, `LOAD 1` is triggered because there are four primary components, each with $p1_k = 50$. Constraint 6 requires that for any distinct $u$ and $v$, $|A_u - A_v| + |B_u - B_v| \ge 100$. Combined with $B_k - A_k = 50$ (Constraint 3), this mutual separation requirement strictly bounds how densely the coordinates can be packed. Satisfying these absolute value inequalities mutually for all four linkages would require a coordinate span of at least 200. Since Constraint 1 restricts all coordinates to the interval $[0, 150]$, it is mathematically impossible to satisfy Constraints 1, 3, and 6 simultaneously.

<RATIONALE>
Transformed the geometric "no overlap" constraints into an equivalent system of absolute value inequalities. This prevents models from pattern-matching the problem to 1D interval packing and directly taking the global sum shortcut, forcing them to either recognize the obscure mathematical equivalence or fail by attempting to simulate the pairwise constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The absolute value inequality $|A_u - A_v| + |B_u - B_v| \ge p1_u + p1_v$ is mathematically exactly equivalent to the intervals $[A_u, B_u]$ and $[A_v, B_v]$ being non-overlapping, meaning the exact same conditions trigger the exact same diagnostic codes.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying mathematical truth remains a set of global bounds on non-overlapping intervals, solvable in $O(N)$ by checking if single-job spans or cumulative subsystem sums exceed $T$.
</PRESERVED_CLASS>
<RISK>
Models might fail to understand the absolute value equivalence and attempt a brute-force $O(N^2)$ pairwise validation, which will result in a Time Limit Exceeded (TLE) error; this is the intended failure mode, but could be seen as the problem being "too mathematically obscure."
</RISK>
