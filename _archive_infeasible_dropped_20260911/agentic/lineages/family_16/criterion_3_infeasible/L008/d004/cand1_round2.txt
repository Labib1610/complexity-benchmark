<METHOD_NAME>Remaining Time Inequality</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the direct sum inequality (p1 + p2 > T) with an equivalent remaining-time inequality (T - p1 < p2) described purely in prose, forcing models to deduce the relationship algebraically rather than matching a known threshold pattern.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Problem C — Telemetry Window: Diagnostic Code

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital satellite is scheduled to execute **j** observation jobs before the mission window closes at $t = \mathbf{T}$ milliseconds.

Each observation job consists of two strictly ordered phases:
1. The targeting gimbal (Subsystem 1) must be dedicated to the job for a continuous block of **p1** milliseconds.
2. Only after this gimbal block has fully concluded, the imaging sensor (Subsystem 2) must be dedicated to the job for a continuous block of **p2** milliseconds.

The hardware dictates that the gimbal's blocks cannot overlap with each other, and the sensor's blocks cannot overlap with each other.

Mission control has determined that no valid schedule exists that finishes all phases by $t = \mathbf{T}$. You must output a diagnostic code that demonstrates a fundamental timeline violation.

The diagnostic code must evaluate to one of the following:
- `JOB i` (where **i** is the 1-based job index). This asserts that if job **i** were processed alone, its sensor phase would be forced to begin at a time that leaves strictly less than its required duration before the mission window closes at $t=\mathbf{T}$.
- `LOAD c` (where **c** is 1 or 2). This asserts that the total continuous uptime required by Subsystem **c** across all **j** jobs is strictly greater than the available window $t=\mathbf{T}$.

The telemetry data is guaranteed to trigger at least one of these fundamental timeline violations. If multiple valid violations exist (for example, multiple jobs violate the first condition, or both subsystems violate the second), you may print the corresponding code for any one of them.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration of the gimbal block and the duration of the sensor block for that observation job.

## Output

Print a single line containing a valid diagnostic code (`JOB i` or `LOAD c`).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, `JOB 1` is a valid diagnostic code because if observation 1 is processed alone, its gimbal phase finishes at 70 milliseconds. The sensor phase then has only $100 - 70 = 30$ milliseconds remaining before the window closes, which is strictly less than its required duration of 60 milliseconds.

In Example 2, `LOAD 1` is a valid diagnostic code because Subsystem 1 must process four non-overlapping blocks of 50 milliseconds each. This requires 200 milliseconds of total continuous uptime, which is strictly greater than the available window of 150.
</STATEMENT>
<RATIONALE>
The explicit sum threshold `p1 + p2 > T` was replaced with a prose description of remaining time `T - p1 < p2`. This forces models to parse the physical constraints of the timeline and deduce the algebraic relationship, rather than relying on surface pattern matching for a direct sum threshold.
</RATIONALE>
<PRESERVED_ANSWER>
The condition `T - p1 < p2` is algebraically identical to `p1 + p2 > T`, and the total uptime check remains identically `sum > T`, ensuring all valid inputs produce the exact same set of acceptable outputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires a single $O(N)$ pass to check independent conditions for each job and subsystem, preserving its original complexity class.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "its required duration before the mission window closes" as `T - p2 < p1` instead of `T - p1 < p2`, though the note explicitly walks through the correct arithmetic to eliminate this ambiguity.
</RISK>
