<STATEMENT>
# Problem C — Impossible Placement: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

You are given an empty grid consisting of 2 rows and **T** columns. The columns are indexed from $1$ to $T$ (left to right). You must place blocks for **j** distinct shapes into this grid. For each shape $i$, you must place exactly **p1** blocks into Row 1, and exactly **p2** blocks into Row 2.

To be valid, the placement must satisfy two structural properties:
1. **Partitioning:** For any given shape $i$, there must exist some vertical partition line drawn after column $k$ (where $0 \le k \le T$) such that all of shape $i$'s Row 1 blocks are placed in columns $\le k$, and all of its Row 2 blocks are placed in columns $> k$.
2. **Cell Capacity:** Any given cell in the grid can contain at most one block, regardless of which shape it belongs to.

Every provided configuration represents an impossible placement—there is no valid way to assign the blocks to the $T$ columns that satisfies all properties. Instead of attempting to generate the placement, your task is to identify the bottleneck that proves the configuration is unachievable, providing a short certificate.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Shape Bottleneck:** For some shape $i$, it is mathematically impossible to find any partition column $k$ ($0 \le k \le T$) that provides enough capacity—meaning the total number of Row 1 cells to the left of the partition is at least $p1$, and the total number of Row 2 cells to the right of the partition is at least $p2$. Output `JOB i` (where $i$ is the 1-based index of the shape).
- **Row 1 Overflow:** The aggregate count of Row 1 blocks required across all $j$ shapes strictly exceeds the $T$ cells available in Row 1. Output `LOAD 1`.
- **Row 2 Overflow:** The aggregate count of Row 2 blocks required across all $j$ shapes strictly exceeds the $T$ cells available in Row 2. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the number of Row 1 blocks and Row 2 blocks required for that shape.

## Output

Print a single line: `JOB i` (for a Shape Bottleneck) or `LOAD c` (for a Row Overflow, where **c** is 1 for Row 1 or 2 for Row 2).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, shape 1 requires 70 blocks in Row 1 and 60 blocks in Row 2. There is no partition column $k$ ($0 \le k \le 100$) that leaves at least 70 cells to its left and at least 60 cells to its right. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single shape breaks the Partitioning property. However, the shapes require 50, 50, 50, and 50 blocks in Row 1 respectively. The aggregate count of 200 Row 1 blocks strictly exceeds the 150 cells available in Row 1. Thus `LOAD 1` is the correct output.
</STATEMENT>
<RATIONALE>
The problem was reframed from a scheduling narrative (jobs, setups, teardowns) to an equivalent geometric partitioning task on a 2xT grid. The condition `p1 + p2 > T` is now expressed as the mathematical impossibility of finding a valid vertical partition column `k` that satisfies `k >= p1` and `T - k >= p2`. This forces the solver to reason algebraically to simplify the condition to O(1); models that rely on surface pattern matching may literally implement an O(T) loop to search for `k`, resulting in a Time Limit Exceeded error. The explicit numeric capacity checks are preserved to maintain the exact task character.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that no valid `k` exists mathematically simplifies exactly to `p1 + p2 > T`, and the aggregate count checks directly map to the total sum checks, preserving all answers identically.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains O(j) for validating the properties, as it still requires checking simple sums and algebraic inequalities for each item.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "total number of Row 1 cells to the left of the partition" as implying only empty/unused cells rather than the absolute grid dimension, though the phrasing avoids the word "available" to minimize this risk.
</RISK>
