<STATEMENT>
# Problem C — Impossible Allocation: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A central server must synchronize $j$ active databases over a strict window of $T$ seconds. For each database $i$, the server must transmit exactly $p1_i$ Delta chunks and exactly $p2_i$ Snapshot chunks. 

The server has one Delta channel and one Snapshot channel:
- Across all databases, the server can send at most one Delta chunk per second.
- Across all databases, the server can send at most one Snapshot chunk per second.

Additionally, the server enforces a strict data consistency protocol using a coupled recurrence tracker. For a schedule to be valid, it must satisfy the tracker for every database. For each database $i \in \{1, \dots, j\}$, a state pair $(X_i, Y_i)$ is initialized to $(1, 1)$. During each second $k$ from $1$ to $T$ (in chronological order), the server computes new values based on the chunks sent to database $i$ at second $k$:
- If second $k$ contains a Delta chunk for database $i$, the state is updated to:
  $X_{new} = -X_i + 2Y_i$
  $Y_{new} = -X_i + 2Y_i$
- Otherwise, if second $k$ contains a Snapshot chunk for database $i$, the state is updated to:
  $X_{new} = -X_i + 4Y_i$
  $Y_{new} = -X_i + 3Y_i$
- If second $k$ contains neither, the state remains unchanged ($X_{new} = X_i$, $Y_{new} = Y_i$).

After computing the new values, the state is permanently updated: $X_i \leftarrow X_{new}$, $Y_i \leftarrow Y_{new}$.

A schedule is valid only if, for all databases $i$, the final state $(X_i, Y_i)$ after second $T$ is exactly $(2 p2_i + 1, p2_i + 1)$.

Every provided configuration is mathematically impossible to complete. Your task is to identify the bottleneck that proves the configuration is unachievable.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **State Violation:** For some database $i$, it is mathematically impossible to schedule its $p1_i$ Delta chunks and $p2_i$ Snapshot chunks within $T$ seconds such that its final state $(X_i, Y_i)$ equals $(2 p2_i + 1, p2_i + 1)$ (even if it were the only database on the server). Output `JOB i` (where $i$ is the 1-based index of the database).
- **Delta Saturation:** It is impossible to schedule all required Delta chunks for all $j$ databases within $T$ seconds. Output `LOAD 1`.
- **Snapshot Saturation:** It is impossible to schedule all required Snapshot chunks for all $j$ databases within $T$ seconds. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of Delta chunks and Snapshot chunks respectively for database $i$.

## Output

Print a single line: `JOB i` (for a State Violation) or `LOAD c` (for a saturation failure, where **c** is 1 for Delta saturation or 2 for Snapshot saturation).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, database 1 requires 70 Delta chunks and 60 Snapshot chunks. To achieve the final state $(X_1, Y_1) = (121, 61)$, the recurrence relations place strict constraints on the ordering of the chunks. It can be shown that this requires more than 100 seconds to achieve. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single database violates the state tracker on its own. However, the sum of required Delta chunks across all 4 databases is 200. Since the server can only send 1 Delta chunk per second, it is impossible to schedule them all in $150$ seconds. Thus `LOAD 1` is the correct output.

<RATIONALE>
The explicit "set to 0" and "increase by 1" rules were replaced with a system of coupled linear equations. Under a change of basis, these equations are mathematically identical to the original tracker: the Delta update resets the hidden state, and the Snapshot update increments it. This forces models to derive the algebraic invariant to realize that $p1_i + p2_i > T$ remains the exact impossibility threshold.
</RATIONALE>

</PRESERVED_ANSWER>
