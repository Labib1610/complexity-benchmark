# Problem C — Impossible Allocation: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A scheduling system must process $j$ jobs within a strict time window of $T$ seconds, represented as the integer set $\{1, \dots, T\}$. Each job $i$ requires exactly $p1_i$ seconds of preparation and exactly $p2_i$ seconds of execution.

The schedule must assign two sets for each job $i$:
- A set $A_i \subset \{1, \dots, T\}$ consisting of exactly $p1_i$ distinct integers (the preparation seconds).
- A set $B_i \subset \{1, \dots, T\}$ consisting of exactly $p2_i$ distinct integers (the execution seconds).

The schedule is valid if and only if it satisfies all of the following constraints:
1. **Preparation Capacity:** Across all jobs, no two jobs can be in preparation during the same second. (For any $i \neq k$, $A_i \cap A_k = \emptyset$).
2. **Execution Capacity:** Across all jobs, no two jobs can be in execution during the same second. (For any $i \neq k$, $B_i \cap B_k = \emptyset$).
3. **Sequential Dependency:** For every job $i$, its preparation must be fully completed before its execution can begin. Mathematically, there must exist an integer split point $S_i$ such that every $x \in A_i$ satisfies $x \le S_i$, and every $y \in B_i$ satisfies $y > S_i$.

Every provided configuration is mathematically impossible to schedule. Your task is to identify the bottleneck that proves the configuration is unachievable.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Job Violation:** For some job $i$, it is mathematically impossible to find valid sets $A_i$ and $B_i$ within $\{1, \dots, T\}$ that satisfy its sequential dependency, even if it were the only job in the system. Output `JOB i` (where $i$ is the 1-based index of the job).
- **Preparation Saturation:** It is mathematically impossible to satisfy the Preparation Capacity constraint because the total number of preparation seconds required across all $j$ jobs exceeds $T$. Output `LOAD 1`.
- **Execution Saturation:** It is mathematically impossible to satisfy the Execution Capacity constraint because the total number of execution seconds required across all $j$ jobs exceeds $T$. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of preparation seconds and execution seconds respectively for job $i$ (i.e., $p1_i$ and $p2_i$).

## Output

Print a single line: `JOB i` (for a Job Violation) or `LOAD c` (for a saturation failure, where **c** is 1 for Preparation Saturation or 2 for Execution Saturation).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires a set $A_1$ of 70 distinct integers and a set $B_1$ of 60 distinct integers. To satisfy the sequential dependency, the split point $S_1$ must be at least 70 to accommodate $A_1$. Consequently, $B_1$ requires 60 distinct integers strictly greater than 70, pushing the maximum required integer to at least 130. Since the timeline only goes up to 100, this is impossible. Thus `JOB 1` is the correct certificate.

In Example 2, each job can individually be scheduled. However, the Preparation Capacity constraint requires finding mutually disjoint sets $A_1, A_2, A_3, A_4$. The total number of unique integers required for preparation is 200, which cannot fit into the 150-second window. Thus `LOAD 1` is the correct certificate.
