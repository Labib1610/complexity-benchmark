# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A software firm is rolling out an update comprising **j** independent components. The rollout involves two stages: compilation on a dedicated build machine (Stage 1), followed by validation on a dedicated testing machine (Stage 2). A machine handles exactly one component at a time. A component is eligible for the testing machine only when its compilation has completely finished.

The firm has allocated a strict release window of exactly **T** minutes. All components must be fully validated before this window closes.

Every provided scenario represents an impossible timeline—there is no valid scheduling order that can complete all components within the release window. Instead of scheduling, your task is to identify a bottleneck that proves the timeline is unachievable, providing a short certificate the system can verify.

Exactly one of the following bottleneck categories will always be present. Output the applicable certificate:

- **Component Delay.** To verify this bottleneck for a component, trace its hypothetical optimal path: it starts on the build machine at minute 0, and the testing machine begins processing it at the exact minute the build machine finishes it. If the minute the testing machine finishes it is strictly greater than **T**, the timeline is unachievable. Output `JOB i`, where **i** is the 1-based index of the component.
- **Machine Saturation.** To verify this bottleneck for a machine, trace its hypothetical continuous operation: it starts at minute 0 and processes its assigned stage for all components consecutively, starting each component the exact minute it finishes the previous one. If the minute it finishes its final component is strictly greater than **T**, the timeline is unachievable. Output `LOAD c`, where **c** is 1 for the build machine or 2 for the testing machine.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **E_1** and **E_2** (1 ≤ E_1, E_2 ≤ 1000000): the time required to compile the component on the build machine, and the time required to validate it on the testing machine.

## Output

Print a single line: `JOB i` (for a component bottleneck) or `LOAD c` (for a machine bottleneck).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, tracing the optimal path for component 1: it starts on the build machine at minute 0, the build machine finishes it at minute 70, the testing machine starts it at minute 70, and the testing machine finishes it at minute 130. Since 130 is strictly greater than the 100-minute window, `JOB 1` is the correct proof of impossibility. In Example 2, no single component finishes its optimal path after minute 150. However, tracing the continuous operation for the build machine (machine 1): it processes all components consecutively, starting at minute 0 and finishing its final component at minute 200. Since 200 is strictly greater than the 150-minute window, `LOAD 1` is the correct output.
