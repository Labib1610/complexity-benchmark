# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A software firm is rolling out an update comprising **j** independent components. The rollout involves two stages: compilation on a dedicated build machine (Stage 1), followed by validation on a dedicated testing machine (Stage 2). A machine handles exactly one component at a time. A component is eligible for the testing machine only when its compilation interval has entirely concluded.

The firm has allocated a strict release window of exactly **T** minutes. All operations must be fully completed by minute **T**.

Every provided scenario represents an impossible timeline—there is no valid scheduling of intervals that can complete all components within the release window. Instead of scheduling, your task is to identify a bottleneck that proves the timeline is unachievable, providing a short certificate the system can verify.

Exactly one of the following bottleneck certificates will be valid for each scenario. Output the applicable certificate:

- **Component Delay:** `JOB i` (where **i** is the 1-based index of the component). Valid if, for component **i**, there is no pair of time intervals $I_{comp}$ and $I_{val}$ (with lengths matching its required compilation and validation durations) such that $I_{comp}$ begins at or after minute 0, $I_{val}$ begins at or after the end time of $I_{comp}$, and the end time of $I_{val}$ is at most **T**.
- **Machine Saturation:** `LOAD c` (where **c**=1 for the build machine, **c**=2 for the testing machine). Valid if, for machine **c**, there is no set of mutually disjoint time intervals (one for each component's task on this machine, with lengths matching their required durations) such that every interval begins at or after minute 0 and the end time of the latest interval is at most **T**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the compilation duration and validation duration of a component.

## Output

Print a single line: `JOB i` (for a component bottleneck) or `LOAD c` (for a machine bottleneck).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, component 1 requires 70 minutes of compilation and 60 minutes of validation. It is impossible to place a 70-minute interval and a subsequent 60-minute interval within the timeframe from minute 0 to minute 100. Thus, `JOB 1` is the correct proof of impossibility.

In Example 2, the build machine must accommodate four compilation tasks of 50 minutes each. It is impossible to fit four mutually disjoint 50-minute intervals within the timeframe from minute 0 to minute 150. Thus, `LOAD 1` is the correct output.

The previous statement gave away the mathematical reduction by explicitly describing the verification process as checking continuous active blocks and priority scheduling lengths against T. The rewrite defines the certificates through the existential non-existence of valid interval assignments. Models can no longer pattern-match sentences to simple sums; they must logically deduce that the minimum possible end time for a chain of two intervals is their sum, and the minimum possible end time for a set of disjoint intervals is their total sum.
</RATIONALE>
<PRESERVED_ANSWER>
The condition for `JOB i` is mathematically identical to p1+p2 > T, and the condition for `LOAD c` is mathematically identical to sum(p_c) > T, so the exact same bottleneck will be identified for every input.
</PRESERVED_ANSWER>
