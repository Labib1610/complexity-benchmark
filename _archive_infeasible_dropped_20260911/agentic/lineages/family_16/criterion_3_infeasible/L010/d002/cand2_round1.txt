# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A software firm is rolling out an update comprising **j** independent components. The rollout involves two stages: compilation on a dedicated build machine (Stage 1), followed by validation on a dedicated testing machine (Stage 2). A machine handles exactly one component at a time. A component is eligible for the testing machine only when its compilation has completely finished.

The firm has allocated a strict release window of exactly **T** minutes. All components must be fully validated before this window closes.

Every provided scenario represents an impossible timeline—there is no valid scheduling order that can complete all components within the release window. Instead of scheduling, your task is to identify a bottleneck that proves the timeline is unachievable, providing a short certificate the system can verify.

Exactly one valid certificate will always be present in the input. Output the applicable certificate based on these verification rules:

- **Component Delay.** A certificate of the form `JOB i` (where **i** is the 1-based index of the component) is valid if the following isolated simulation fails: component **i** claims the build machine for a contiguous interval of its required duration starting at time 0, and then immediately claims the testing machine for a contiguous interval of its required duration. The certificate is valid if the component's testing interval ends strictly after time **T**.
- **Machine Saturation.** A certificate of the form `LOAD c` (where **c** is 1 for the build machine or 2 for the testing machine) is valid if the following isolated simulation fails: machine **c** processes all of its required tasks consecutively as a single unbroken sequence of intervals starting at time 0, ignoring the other stage. The certificate is valid if the final interval in this sequence ends strictly after time **T**.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required duration for Stage 1 and Stage 2 of a component, respectively.

## Output

Print a single line: `JOB i` (for a valid component bottleneck) or `LOAD c` (for a valid machine bottleneck).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, evaluating the `JOB 1` certificate involves simulating component 1: its Stage 1 interval is [0, 70], and its Stage 2 interval is [70, 130]. Since the endpoint 130 is strictly greater than the 100-minute window, `JOB 1` is a valid proof of impossibility. In Example 2, no single component's intervals extend past 150 minutes when simulated in isolation. However, evaluating the `LOAD 1` certificate involves simulating the build machine processing all tasks consecutively: the sequence of intervals spans [0, 200]. Since the endpoint 200 is strictly greater than the 150-minute window, `LOAD 1` is a valid certificate.
