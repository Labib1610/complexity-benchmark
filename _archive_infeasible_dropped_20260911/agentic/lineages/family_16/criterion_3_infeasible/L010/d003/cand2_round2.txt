# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

An engineering team is deploying a system consisting of **j** independent modules. The deployment pipeline has two sequential phases: compilation on a central build server (Phase 1) and subsequent verification on a central test server (Phase 2). Each server can process at most one module at any given moment. A module can only begin Phase 2 after its Phase 1 is completely finished.

The team has a strict deadline: the entire deployment must be completed by minute **T**.

You are given configurations that are inherently flawed. It is physically impossible to schedule the modules such that all work completes by minute **T**. Your task is not to attempt scheduling, but to output a precise certificate that proves the deadline cannot be met.

The test cases are constructed such that exactly one of the following two fundamental limits is breached. Identify which one it is and output the corresponding certificate:

- **Path Violation.** For any single module, its compilation and verification must occur strictly in sequence. If the combined duration of compilation and verification for a specific module strictly exceeds the deadline **T**, output `JOB i`, where **i** is the module's 1-based position in the input.
- **Volume Violation.** A server must process its assigned phase for all modules serially. If the total compilation time across all modules strictly exceeds the deadline **T**, output `LOAD 1`. If the total verification time across all modules strictly exceeds the deadline **T**, output `LOAD 2`.

## Input

The first line contains the number of modules **j** (1 ≤ j ≤ 200,000) and the deadline **T** (1 ≤ T ≤ 1,000,000,000).
Each of the subsequent **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1,000,000), representing the compilation time and the verification time for that module.

## Output

Print exactly one line containing the unique valid certificate: either `JOB i` or `LOAD c`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for module 1, its compilation and verification take 70 and 60 minutes respectively. The combined sequential duration is 130, which strictly exceeds the 100-minute deadline, making `JOB 1` the valid proof of impossibility. 

In Example 2, the total compilation time across all modules is 50 + 50 + 50 + 50 = 200, which strictly exceeds the 150-minute deadline. Thus `LOAD 1` is the correct output.
