# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A software firm is rolling out an update comprising **j** independent modules. The rollout involves two stages: compilation on a dedicated build machine (Stage 1), followed by validation on a dedicated testing machine (Stage 2). A machine handles exactly one module at a time. A module is eligible for the testing machine only when its compilation has completely finished.

The firm has allocated a strict release window of exactly **T** minutes. All modules must be fully validated before this window closes at minute **T**.

Every provided scenario represents an impossible timeline—there is no valid scheduling order that can complete all modules before the window closes at minute **T**. The impossibility can always be proven by identifying a specific structural violation. 

A valid schedule requires a module's compilation and validation phases to be executed as two sequential intervals. If it is mathematically impossible to fit these two sequential intervals for a specific module inside the window [0, **T**] with lengths equal to its required durations, this constitutes a module violation, and the certificate is `JOB i` (where **i** is the 1-based module index). 

Alternatively, a valid schedule requires a machine to execute its phase for all modules using non-overlapping intervals. If it is mathematically impossible to place one non-overlapping interval per module on a specific machine inside the window [0, **T**] with lengths equal to the required durations, this constitutes a machine violation, and the certificate is `LOAD c` (where **c** is 1 for the build machine or 2 for the testing machine).

You are guaranteed that for every input, exactly one such violation exists—either a single module violation or a single machine violation. Output the corresponding certificate.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the compilation duration and validation duration of a module.

## Output

Print a single line containing the unique valid certificate: `JOB i` (for a module violation) or `LOAD c` (for a machine violation).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for module 1, its compilation and validation take 70 and 60 minutes respectively. It is impossible to fit two sequential intervals of lengths 70 and 60 within the 100-minute window, making `JOB 1` the valid certificate. In Example 2, no single module requires sequential intervals exceeding 150 minutes in total, but the build machine requires intervals of lengths 50, 50, 50, and 50. It is impossible to place these four non-overlapping intervals inside the 150-minute window. Thus `LOAD 1` is the valid certificate.
