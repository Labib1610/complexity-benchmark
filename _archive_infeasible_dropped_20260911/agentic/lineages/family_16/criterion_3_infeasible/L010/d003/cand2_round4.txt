# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A software firm is deploying an update consisting of **j** independent modules. The deployment is a two-stage process: first, a module is built in a dedicated build environment (Stage 1); subsequently, it is validated in a dedicated testing environment (Stage 2). Each environment is capable of handling exactly one module at a time. A module becomes eligible for the testing environment only after its build process has entirely concluded.

The firm has designated a strict release window of exactly **T** minutes. All modules must be completely validated before this window expires at minute **T**.

Every provided test case represents an impossible timeline—there is no valid execution schedule that can finish all modules before the window closes. Your objective is not to attempt scheduling, but to output a short certificate proving why the timeline is unachievable. 

You are guaranteed that exactly one of the following fundamental limits is breached in each test case. Output the corresponding certificate:

- **Module Pipeline Violation.** A valid schedule requires a module's build and testing phases to occur as two chronological, non-overlapping periods within the release window. If it is mathematically impossible to fit these two sequential periods for a specific module inside the **T**-minute window given their required durations, output `JOB i`, where **i** is the 1-based index of the module.
- **Environment Capacity Violation.** A valid schedule requires an environment to execute its phase for all modules using disjoint periods within the release window. If it is mathematically impossible to pack one disjoint period per module into environment **c** inside the **T**-minute window given their required durations, output `LOAD c`, where **c** is 1 for the build environment or 2 for the testing environment.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required time in the build environment and the required time in the testing environment for that module.

## Output

Print a single line containing exactly one certificate: either `JOB i` (for a module pipeline violation) or `LOAD c` (for an environment capacity violation).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for module 1, the build and testing phases take 70 and 60 minutes respectively. It is physically impossible to fit two chronological periods of lengths 70 and 60 within the 100-minute window, making `JOB 1` the correct proof of impossibility. 
In Example 2, no single module requires sequential periods exceeding 150 minutes in total. However, the build environment requires processing periods of lengths 50, 50, 50, and 50. It is impossible to accommodate these four disjoint periods inside the 150-minute window. Thus `LOAD 1` is the correct output.
