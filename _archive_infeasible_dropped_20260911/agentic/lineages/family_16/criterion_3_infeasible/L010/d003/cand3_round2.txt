# Problem C — Impossible Deadline: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A tech company is deploying a major patch consisting of $j$ separate modules. The deployment process requires each module to undergo two sequential phases. First, it must be compiled on the primary build server. Once a module's compilation is fully complete, it is sent to the secondary QA server for automated validation. Both the build server and the QA server are strictly single-threaded; they can process exactly one module at a time. The entire patch deployment must be finished within a hard deadline of exactly $T$ minutes.

You are given deployment logs that represent impossible scenarios. No matter how the modules are ordered, they cannot all be completed within the $T$-minute deadline. Your task is to output a brief certificate that proves the schedule is impossible.

Based on the provided data, exactly one of the following two bottlenecks will always be present. You must print the corresponding certificate:

- **Module-Level Bottleneck:** Even without any queueing delays, a module's compilation and validation must occur as consecutive blocks of time. If the total uninterrupted time required to compile and then validate a specific module is strictly greater than the available window $T$, it is physically impossible for that module to finish in time. Output `JOB i`, where $i$ is the 1-based index of the module in the log.
- **Server-Level Bottleneck:** Because a server processes one module at a time, its total active processing time is the aggregate of the times required for all modules on that server. If the build server's aggregate compilation workload is strictly greater than the available $T$ minutes, it cannot finish its tasks. Similarly, if the QA server's aggregate validation workload is strictly greater than the available $T$ minutes, it cannot finish. Output `LOAD c`, replacing $c$ with 1 if the build server is the bottleneck, or 2 if the QA server is the bottleneck.

## Input

The first line contains two integers $j$ and $T$ (1 ≤ $j$ ≤ 200000, 1 ≤ $T$ ≤ 1000000000).
The following $j$ lines detail the deployment. Each line contains two integers $p_1$ and $p_2$ (1 ≤ $p_1, p_2$ ≤ 1000000), representing the compilation minutes and validation minutes required for that module, respectively.

## Output

Print a single line: `JOB i` if an individual module cannot be completed, or `LOAD c` if a server's total workload exceeds the deadline.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the first module requires 70 minutes of compilation and 60 minutes of validation. Since these must happen back-to-back, the module alone requires 130 minutes. This exceeds the 100-minute limit, so `JOB 1` is the correct proof.

In Example 2, no single module requires more than 150 minutes overall. However, the build server must perform four separate 50-minute compilations. Because the server is single-threaded, it needs 200 minutes of active time, which exceeds the 150-minute window. Thus, `LOAD 1` is the correct proof.
