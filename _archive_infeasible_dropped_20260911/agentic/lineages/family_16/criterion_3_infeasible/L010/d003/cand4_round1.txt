# Problem C — Impossible Ribbon: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant is decorating a continuous ribbon of material of length **T** millimeters. The order consists of **j** distinct designs. The decoration process involves two steps: applying a base layer, followed by a top layer.

For each design, the base layer occupies a continuous segment of length **p1** mm, and the top layer occupies a continuous segment of length **p2** mm. 

The placement of these segments must adhere to the following rules:
1. For any single design, its top layer segment must be positioned sequentially after its base layer segment on the ribbon.
2. All base layer segments for all designs share the same primary track, so they must be placed as non-overlapping segments.
3. All top layer segments for all designs share the same secondary track, so they must also be placed as non-overlapping segments.
4. All segments must fit entirely within the ribbon's span, from 0 to **T**.

Every provided order represents an impossible configuration—there is no valid arrangement of segments that can satisfy all constraints on a ribbon of length **T**. Instead of attempting to place them, your task is to identify a bottleneck that proves the configuration is unachievable, providing a short certificate the system can verify.

Exactly one of the following bottlenecks will always be present. Output the applicable certificate:

- **Design Spread.** A valid arrangement requires a design's base and top layers to be placed as two sequential segments within the ribbon. If it is mathematically impossible to fit these two sequential segments for a specific design inside the ribbon [0, **T**] with lengths equal to its required base and top layer lengths, output `JOB i`, where **i** is the 1-based index of the design.
- **Track Saturation.** A valid arrangement requires a track to contain its respective segments for all designs as non-overlapping segments within the ribbon. If it is mathematically impossible to place one non-overlapping segment per design on track **c** inside the ribbon [0, **T**] such that each segment's length equals the design's required length for that track, output `LOAD c`, where **c** is 1 for the primary track or 2 for the secondary track.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the base layer length and top layer length of a design.

## Output

Print a single line: `JOB i` (for a design bottleneck) or `LOAD c` (for a track bottleneck).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for design 1, its base and top layers require 70 mm and 60 mm respectively. It is impossible to fit two sequential segments of lengths 70 and 60 within the 100 mm ribbon, making `JOB 1` the correct proof of impossibility. In Example 2, no single design requires sequential segments exceeding 150 mm in total, but the primary track requires segments of lengths 50, 50, 50, and 50. It is impossible to place these four non-overlapping segments inside the 150 mm ribbon. Thus `LOAD 1` is the correct output.

<RATIONALE>
The problem was completely reframed from a time-based job scheduling domain into a spatial geometry domain (placing segments on a ribbon). This removes the typical affordances of "compilation", "validation", "machines", and "scheduling", forcing the model to deduce from the spatial constraints that "sequential segments" means `p1 + p2 > T` and "non-overlapping segments" means `sum(p1) > T` or `sum(p2) > T`.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions for the bottlenecks (p1 + p2 > T for a specific design, or sum(p) > T for a track) perfectly mirror the original component delay and machine saturation conditions, guaranteeing identical output for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires an O(N) scan to verify linear inequalities, keeping it strictly in the same certification complexity class.
</PRESERVED_CLASS>
