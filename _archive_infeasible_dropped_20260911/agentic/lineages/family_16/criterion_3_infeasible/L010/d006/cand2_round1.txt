<STATEMENT>
# Problem C — Impossible Protocol: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A cryptographic protocol operates on a state space represented by **T**-bit unsigned integers (bits are indexed from 0 to **T**-1, where 0 is the least significant bit). A session consists of **j** independent exchanges. For each exchange $i$ (from 1 to **j**), the protocol must generate two **T**-bit integers:
- A query mask $M_{Q,i}$ having a Hamming weight (number of set bits) of exactly **p1**.
- A reply mask $M_{R,i}$ having a Hamming weight of exactly **p2**.

A valid session must satisfy three security properties:
1. **Causality:** For any single exchange $i$, there must exist a bit-shift pivot $k$ (an integer where $0 \le k \le T$) such that applying a logical right shift of $k$ bits to the query mask yields zero (i.e., $M_{Q,i} \gg k = 0$), and applying a logical left shift of **T**$-k$ bits to the reply mask also yields zero within a **T**-bit register (i.e., $(M_{R,i} \ll (T-k)) \pmod{2^T} = 0$).
2. **Query Independence:** For any two distinct exchanges $x$ and $y$, their query masks must be mutually exclusive: $M_{Q,x} \ \& \ M_{Q,y} = 0$ (where $\&$ is the bitwise AND operator).
3. **Reply Independence:** For any two distinct exchanges $x$ and $y$, their reply masks must be mutually exclusive: $M_{R,x} \ \& \ M_{R,y} = 0$.

Every provided configuration represents an impossible session—there is no valid way to generate the masks that satisfies all properties for a **T**-bit register. Instead of attempting to generate them, your task is to identify the bottleneck that proves the configuration is unachievable, providing a short certificate the system can verify.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Causality Failure:** For some exchange $i$, there exist no **T**-bit integers $M_{Q,i}$ and $M_{R,i}$ with Hamming weights **p1** and **p2** that satisfy the Causality property. Output `JOB i` (where $i$ is the 1-based index of the exchange).
- **Query Collision:** There exist no **j** integers $M_{Q,1}, \dots, M_{Q,j}$ with the required Hamming weights that satisfy the Query Independence property. Output `LOAD 1`.
- **Reply Collision:** There exist no **j** integers $M_{R,1}, \dots, M_{R,j}$ with the required Hamming weights that satisfy the Reply Independence property. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required Hamming weights for the query mask and the reply mask of an exchange.

## Output

Print a single line: `JOB i` (for a causality bottleneck) or `LOAD c` (for a collision bottleneck, where **c** is 1 for query collision or 2 for reply collision).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for exchange 1, the query and reply masks require Hamming weights of 70 and 60 respectively. There exist no $100$-bit integers $M_{Q,1}$ and $M_{R,1}$ with these weights such that a pivot $k$ can shift $M_{Q,1}$ right to zero and $M_{R,1}$ left to zero within the 100-bit register, breaking the Causality property. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single exchange breaks Causality. However, the query masks require Hamming weights of 50, 50, 50, and 50. There exist no 4 integers of 150 bits with these weights such that their bitwise ANDs are mutually zero, breaking the Query Independence property. Thus `LOAD 1` is the correct output.
</STATEMENT>
<RATIONALE>
I replaced the explicit set operations (injective functions, disjoint images, max < min) with bitwise operations on $T$-bit integers. The cardinality checks are now obscured behind Hamming weights, bitwise ANDs equating to zero, and logical shifts overflowing a $T$-bit register. This forces the model to algebraically deduce that the shift conditions imply non-overlapping bit domains ($p1+p2 \le T$) and that mutually exclusive masks imply sum of weights $\le T$, defeating simple surface-level keyword matching for cardinality checks.
</RATIONALE>
<PRESERVED_ANSWER>
The logical shift conditions hold if and only if all $p1$ bits of the query mask are below a pivot $k$ and all $p2$ bits of the reply mask are at or above $k$, which is equivalent to $p1+p2 \le T$; mutually exclusive masks (bitwise AND is zero) require the sum of their Hamming weights to not exceed the total bits $T$, preserving the exact same bottleneck conditions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an INFEASIBLE certification task where the algorithm only needs to sequentially check if $p1+p2 > T$ for any job, or if the sum of $p1$ or sum of $p2$ exceeds $T$.
</PRESERVED_CLASS>
<RISK>
Models might get confused by the modulo $2^T$ notation for the left shift, although it is the standard mathematical definition of overflowing a fixed-width register.
</RISK>
