# Problem C — Impossible Schedule: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A computing cluster must execute an order of **j** distinct jobs by a strict deadline **T**. Each job requires two sequential stages: stage 1 on the primary processor, followed by stage 2 on the secondary processor.

Let $S_{i,1}$ and $S_{i,2}$ represent the start times of stage 1 and stage 2 for job $i$. The required processing durations are $d_{i,1}$ and $d_{i,2}$ respectively. A schedule is valid if and only if it satisfies the following system of constraints:

1. **Release:** $S_{i,1} \ge 0$ for all $i \in \{1, \dots, j\}$.
2. **Sequentiality:** $S_{i,2} \ge S_{i,1} + d_{i,1}$ for all $i \in \{1, \dots, j\}$.
3. **Deadline:** $S_{i,2} + d_{i,2} \le T$ for all $i \in \{1, \dots, j\}$.
4. **Primary Processor Mutual Exclusion:** For any two distinct jobs $i$ and $k$, either $S_{k,1} \ge S_{i,1} + d_{i,1}$ or $S_{i,1} \ge S_{k,1} + d_{k,1}$.
5. **Secondary Processor Mutual Exclusion:** For any two distinct jobs $i$ and $k$, either $S_{k,2} \ge S_{i,2} + d_{i,2}$ or $S_{i,2} \ge S_{k,2} + d_{k,2}$.

Every provided order represents an impossible schedule—there is no assignment of start times that can satisfy all constraints simultaneously. Rather than searching for a schedule, your task is to identify a bottleneck that proves the system is infeasible.

Exactly one of the following fundamental contradictions will always be present. Output the applicable certificate:

- **Direct Path Contradiction:** By chaining constraints 1, 2, and 3 for a single job $i$, it is a mathematical requirement that $d_{i,1} + d_{i,2} \le T$. If this necessary condition is violated for a specific job (meaning $d_{i,1} + d_{i,2} > T$), output `JOB i`, where $i$ is the 1-based index of the job.
- **Volume Contradiction:** By combining the non-overlap constraints with the release and deadline constraints for a single processor $c$, it is a mathematical requirement that the total processing time assigned to that processor cannot exceed the window **T**. Therefore, $\sum_{i=1}^j d_{i,c} \le T$. If this necessary condition is violated for processor $c$ (meaning the sum strictly exceeds **T**), output `LOAD c`, where $c$ is 1 for the primary processor or 2 for the secondary processor.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **d_1** and **d_2** (1 ≤ d_1, d_2 ≤ 1000000): the required processing duration for stage 1 and stage 2 of a job.

## Output

Print a single line: `JOB i` (for a direct path contradiction) or `LOAD c` (for a volume contradiction).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, for job 1, applying the direct path constraints requires $70 + 60 \le 100$, which is false ($130 > 100$). Thus `JOB 1` is the correct proof of infeasibility. 
In Example 2, no single job violates the direct path condition. However, applying the volume constraints to the primary processor requires $50 + 50 + 50 + 50 \le 150$. This is false ($200 > 150$), making `LOAD 1` the correct output.
