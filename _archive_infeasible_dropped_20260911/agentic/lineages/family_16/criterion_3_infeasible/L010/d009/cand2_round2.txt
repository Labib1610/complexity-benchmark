<STATEMENT>
# Problem C — Impossible Allocation: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A network router must process traffic over a strict window of $T$ timeslots. There are $j$ active data flows. For each flow $i$, the router must schedule exactly $p1_i$ Ingress packets and exactly $p2_i$ Egress packets. 

A valid schedule is defined mathematically by two globally injective functions, $f_{in}$ and $f_{out}$, which assign a unique timeslot to every required packet across all flows:
- $f_{in}: \{ (i, k) \mid 1 \le i \le j, 1 \le k \le p1_i \} \to \{1, 2, \dots, T\}$
- $f_{out}: \{ (i, k) \mid 1 \le i \le j, 1 \le k \le p2_i \} \to \{1, 2, \dots, T\}$

By definition of injectivity, these functions enforce that the router can process at most one Ingress packet per timeslot (across all flows) and at most one Egress packet per timeslot (across all flows).

Additionally, the router enforces a strict causal firewall. For a schedule to be valid, every flow $i \in \{1, \dots, j\}$ must satisfy the following strict inequality:
$$ \max_{1 \le k \le p1_i} f_{in}(i, k) < \min_{1 \le k \le p2_i} f_{out}(i, k) $$

Every provided configuration is mathematically impossible to route—there is no valid way to construct the schedule to accommodate all required packets while satisfying the firewall for all flows. Your task is to identify the bottleneck that proves the configuration is unachievable.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Causal Violation:** For some flow $i$, it is impossible to schedule its $p1_i$ Ingress and $p2_i$ Egress packets within $T$ timeslots without violating the causal firewall inequality (even if it were the only flow on the router). Output `JOB i` (where $i$ is the 1-based index of the flow).
- **Ingress Saturation:** It is impossible to construct the injective mapping $f_{in}$ to schedule all required Ingress packets for all $j$ flows within $T$ timeslots. Output `LOAD 1`.
- **Egress Saturation:** It is impossible to construct the injective mapping $f_{out}$ to schedule all required Egress packets for all $j$ flows within $T$ timeslots. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of Ingress packets and Egress packets respectively for flow $i$ (i.e., $p1_i$ and $p2_i$).

## Output

Print a single line: `JOB i` (for a causal violation) or `LOAD c` (for a saturation failure, where **c** is 1 for Ingress saturation or 2 for Egress saturation).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, flow 1 requires 70 Ingress packets and 60 Egress packets. To construct $f_{in}$ for flow 1, 70 distinct timeslots must be assigned from $\{1, \dots, 100\}$, meaning $\max_{k} f_{in}(1, k) \ge 70$. To construct $f_{out}$ for flow 1, 60 distinct timeslots must be assigned from $\{1, \dots, 100\}$, meaning $\min_{k} f_{out}(1, k) \le 41$. The causal firewall requires $\max f_{in} < \min f_{out}$, which would necessitate $70 < 41$, a mathematical contradiction. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single flow violates the causal firewall on its own. However, constructing $f_{in}$ requires mapping $\sum_{i=1}^4 50 = 200$ distinct items into the codomain $\{1, \dots, 150\}$. Because $200 > 150$, an injective function $f_{in}$ cannot exist. Thus `LOAD 1` is the correct output.
