# Problem C — Impossible Schedule: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A manufacturing plant must process a batch of $j$ jobs within a strict operational window of $T$ hours. The plant has exactly two machines: Machine 1 and Machine 2. For each job $i$, the plant must schedule exactly $p1_i$ hours of processing on Machine 1 and exactly $p2_i$ hours of processing on Machine 2.

A valid schedule must satisfy the following constraints:
- A machine can process at most one job at a time.
- For any job $i$, its processing on Machine 2 cannot begin until its processing on Machine 1 is completely finished.
- All processing for all jobs must begin at or after hour $0$ and finish at or before hour $T$.

Every provided configuration is mathematically impossible to schedule—there is no valid way to construct a schedule to accommodate all required hours for all jobs while satisfying the constraints. Your task is to identify the bottleneck that proves the configuration is unachievable.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Sequential Bottleneck:** For some job $i$, it is impossible to schedule its $p1_i$ hours on Machine 1 and $p2_i$ hours on Machine 2 within $T$ hours without violating the sequential dependency rule (even if it were the only job in the plant). Output `JOB i` (where $i$ is the 1-based index of the job).
- **Machine 1 Saturation:** It is impossible to schedule all required Machine 1 hours for all $j$ jobs within the $T$-hour window. Output `LOAD 1`.
- **Machine 2 Saturation:** It is impossible to schedule all required Machine 2 hours for all $j$ jobs within the $T$-hour window. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required processing hours on Machine 1 and Machine 2 respectively for job $i$ (i.e., $p1_i$ and $p2_i$).

## Output

Print a single line: `JOB i` (for a sequential bottleneck) or `LOAD c` (for a saturation failure, where **c** is 1 for Machine 1 saturation or 2 for Machine 2 saturation).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 hours on Machine 1 and 60 hours on Machine 2. Since Machine 2 cannot start until Machine 1 finishes, the absolute minimum time to complete this job is $70 + 60 = 130$ hours. It is impossible to schedule this within the $T=100$ hour window. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single job violates the sequential bottleneck on its own. However, the sum of required Machine 1 hours across all 4 jobs is 200. Since Machine 1 can only process 1 hour of work per hour, it is impossible to complete 200 hours of work in a $150$-hour window. Thus `LOAD 1` is the correct output.
