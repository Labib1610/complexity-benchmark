<STATEMENT>
# Vector Orientation Obstructions

Time limit: 2 s   Memory limit: 256 MB

## Description

You are analyzing a set of 2D vectors. There are two available pools of vectors:
- **Pool X** consists of $T$ distinct vectors, defined as $\vec{x}_u = (1, u)$ for $u = 1, 2, \dots, T$.
- **Pool Y** consists of $T$ distinct vectors, defined as $\vec{y}_v = (1, v)$ for $v = 1, 2, \dots, T$.

There are $j$ distinct vector fields to construct. For field $i$, you must select exactly $p1_i$ vectors from Pool X, and exactly $p2_i$ vectors from Pool Y. 
- A vector from Pool X can be selected for at most one field.
- A vector from Pool Y can be selected for at most one field.

To maintain the required curl of the field, each field $i$ must satisfy the **Orientation Rule**:
For *every* vector $\vec{a}$ selected from Pool X for field $i$, and *every* vector $\vec{b}$ selected from Pool Y for field $i$, the 2D cross product $\vec{a} \times \vec{b}$ must be strictly positive. 
*(Note: The 2D cross product of $(x_1, y_1)$ and $(x_2, y_2)$ is defined as $x_1 y_2 - y_1 x_2$.)*

Every provided configuration is mathematically impossible to construct—there is no valid way to select the vectors to accommodate all fields while satisfying the rules. Your task is to identify the bottleneck that proves the configuration is unachievable.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Curl Violation:** For some field $i$, it is impossible to select its $p1_i$ vectors from Pool X and $p2_i$ vectors from Pool Y to satisfy the Orientation Rule, even if it were the only field being constructed. Output `JOB i` (where $i$ is the 1-based index of the field).
- **Pool X Depletion:** It is impossible to select all required vectors from Pool X across all $j$ fields without reusing a vector. Output `LOAD 1`.
- **Pool Y Depletion:** It is impossible to select all required vectors from Pool Y across all $j$ fields without reusing a vector. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of vectors from Pool X and Pool Y respectively for field $i$.

## Output

Print a single line: `JOB i` (for a curl violation) or `LOAD c` (for a depletion failure, where **c** is 1 for Pool X depletion or 2 for Pool Y depletion).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, field 1 requires 70 vectors from Pool X and 60 vectors from Pool Y. It is impossible to select them from the available $T=100$ vectors such that every cross product is strictly positive. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single field violates the Orientation Rule on its own. However, the sum of required vectors from Pool X across all 4 fields is 200. Since Pool X only has 150 vectors, it is impossible to fulfill the requirements without reuse. Thus `LOAD 1` is the correct output.

<RATIONALE>
The 1D causal scheduling constraint (Ingress before Egress) was mapped to a 2D computational geometry orientation test. The model must now algebraically unpack the cross product condition ($\vec{a} \times \vec{b} = 1 \cdot v - u \cdot 1 = v - u > 0 \implies u < v$) to realize that indices from Pool X must be strictly smaller than indices from Pool Y, which forces the required index span to be $p1_i + p2_i \le T$. This prevents models from pattern-matching standard scheduling bounds while rewarding genuine mathematical reasoning.
</RATIONALE>
