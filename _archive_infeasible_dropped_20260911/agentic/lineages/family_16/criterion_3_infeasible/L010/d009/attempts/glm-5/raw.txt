Looking at this problem, I need to analyze the phase tracker mechanism carefully.

For a single database with p1 Delta chunks and p2 Snapshot chunks, the tracker V starts at 0. Each Snapshot increments V by 1, each Delta resets V to 0. The final value must equal p2.

**Key insight**: The last p2 Snapshot chunks must occur after the last Delta chunk (otherwise a Delta would reset V below p2). Additionally, between any two consecutive of these last p2 Snapshots, there can be no Delta chunks. So all p1 Delta chunks must come before the last p2 Snapshots, requiring at least p1 + p2 seconds.

But wait - could there be extra Snapshots before the last Delta? No, because p2 is the exact count required. So all p2 Snapshots must be the "last p2" ones, meaning all p1 Deltas must precede all p2 Snapshots. This requires p1 + p2 ≤ T.

Let me verify with Example 1: Database 1 has p1=70, p2=60, T=100. Since 70+60=130 > 100, it's a phase violation. ✓

For saturation: total Delta chunks = sum(p1_i) must be ≤ T, and total Snapshot chunks = sum(p2_i) must be ≤ T.

The problem guarantees exactly one condition is broken, so I check in order: phase violations first (for each database), then Delta saturation, then Snapshot saturation.

    data = sys.stdin.buffer.read().split()
    idx = 0

    T = int(data[idx]); idx += 1
    
    total_p1 = 0

        total_p1 += p1
        total_p2 += p2
        
        if p1 + p2 > T:
