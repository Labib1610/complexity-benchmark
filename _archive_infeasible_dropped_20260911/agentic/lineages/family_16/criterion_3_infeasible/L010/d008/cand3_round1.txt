# Problem C — Infeasible Execution: Trace It

Time limit: 2 s   Memory limit: 256 MB

## Description

A centralized cryptographic exchange operates a continuous execution window consisting of $T$ sequential micro-ticks, indexed 1 to $T$. There are $j$ institutional traders submitting transaction batches.

For each trader $i$, the exchange must execute exactly $p1_i$ distinct "Audit" operations and exactly $p2_i$ distinct "Reconciliation" operations. Each operation consumes exactly one micro-tick.

To prevent ledger corruption, the exchange's execution engine enforces three strict invariants:
1. **Causal Dependency:** For any individual trader, every Audit operation must be executed at a strictly earlier micro-tick than every Reconciliation operation belonging to that same trader.
2. **Audit Bandwidth:** The exchange can process a maximum of one Audit operation per micro-tick globally across all traders.
3. **Reconciliation Bandwidth:** The exchange can process a maximum of one Reconciliation operation per micro-tick globally across all traders.

*(Note: The engine supports full duplexing, meaning a single micro-tick can simultaneously process one Audit operation for trader A and one Reconciliation operation for trader B, provided invariants are maintained.)*

Every provided batch configuration is mathematically impossible to execute—there is no valid way to assign micro-ticks to satisfy all invariants. Your task is to analyze the configuration and output a certificate identifying the primary cause of failure. 

Because configurations can be highly defective, multiple invariants might be violated simultaneously. You must evaluate the configuration and report the **most severe bottleneck** according to the following strict audit hierarchy:

**Level 1 (Individual Insolvency):**
Evaluate each trader individually. A trader is structurally insolvent if there are not enough micro-ticks in the entire $T$-tick window to execute their required Audit and Reconciliation operations while satisfying the Causal Dependency invariant, even if they were the only trader on the exchange.
If one or more traders are insolvent, output `JOB i` for the insolvent trader with the smallest index $i$ (using 1-based indexing).

**Level 2 (Audit Network Exhaustion):**
If no individual trader is insolvent, evaluate the global Audit requirements. If the combined number of Audit operations required across all traders strictly exceeds the $T$ available micro-ticks, the network cannot support the Audit phase. Output `LOAD 1`.

**Level 3 (Reconciliation Network Exhaustion):**
If the configuration passes Level 1 and Level 2, evaluate the global Reconciliation requirements. If the combined number of Reconciliation operations required across all traders strictly exceeds $T$, output `LOAD 2`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of Audit operations and Reconciliation operations respectively for trader $i$.

## Output

Print a single line containing the certificate of the primary bottleneck: `JOB i` (for Level 1 insolvency), `LOAD 1` (for Level 2 exhaustion), or `LOAD 2` (for Level 3 exhaustion).

## Examples


### Example 2


### Example 3

**Input**


**Output**
```
JOB 1
```

<RATIONALE>
I redefined the subset allocation as scheduling operations over discrete time ticks, establishing constraints through causal dependency and bandwidth limits rather than bare inequalities. I explicitly removed the unique-failure guarantee from the text, introducing a strict evaluation hierarchy and a third example where multiple constraints fail simultaneously, forcing the model to implement the bottleneck prioritization logic rather than relying on a short-circuited heuristic.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions for Level 1 ($p1_i + p2_i > T$), Level 2 ($\sum p1_i > T$), and Level 3 ($\sum p2_i > T$) are strictly equivalent to the original Supremum-Infimum Separation, X-Orthogonality, and Y-Orthogonality axioms; since the hidden tests only contain exactly one failure, any correct implementation of the hierarchy will yield the exact same output.
</PRESERVED_ANSWER>
