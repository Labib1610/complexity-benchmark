<STATEMENT>
# Problem C — Impossible Schedule: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A factory must process a batch of $j$ jobs within a strict deadline of $T$ hours. The factory has two machines: Machine 1 and Machine 2. 

For each job $i$, it must first be processed on Machine 1 for an uninterrupted duration of $p1_i$ hours. Only after Machine 1 has completely finished job $i$ can it be processed on Machine 2 for an uninterrupted duration of $p2_i$ hours. Each machine can process at most one job at a time. Preemption is not allowed.

Every provided configuration is mathematically impossible to schedule—there is no valid way to order the jobs such that all jobs complete both stages within the $T$-hour deadline. Instead of attempting to find a schedule, your task is to identify a structural bottleneck that proves the configuration is unachievable. 

You are guaranteed that for every test case, at least one of the following physical bottlenecks applies. Output a short certificate for a bottleneck that applies. (If multiple bottlenecks apply, you may output any one of their valid certificates.)

- **Isolated Job Delay:** A specific job requires more time to complete its sequence of operations than the deadline allows, even if it is the only job in the factory and experiences zero wait time. Output `JOB i` (where $i$ is the 1-based index of the job).
- **Machine 1 Overload:** Machine 1 cannot complete its total required work for all jobs within the deadline, even if it operates continuously without a single moment of idle time. Output `LOAD 1`.
- **Machine 2 Overload:** Machine 2 cannot complete its total required work for all jobs within the deadline, even if it operates continuously without a single moment of idle time. Output `LOAD 2`.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required processing time for job $i$ on Machine 1 and Machine 2 respectively (i.e., $p1_i$ and $p2_i$).

## Output

Print a single line containing a valid certificate: `JOB i`, `LOAD 1`, or `LOAD 2`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job 1 requires 70 hours on Machine 1 followed by 60 hours on Machine 2. There is no way it can complete its sequence within the 100-hour deadline, even with no other jobs interfering. Thus `JOB 1` is a valid proof of impossibility. 

In Example 2, no single job exceeds the deadline. However, the four jobs require a total of 200 hours on Machine 1. Machine 1 cannot complete this work within the 150-hour deadline. Thus `LOAD 1` is a valid proof of impossibility.

<RATIONALE>
Removed the explicit scalar formulas and the exact-unique-failure guarantee, replacing them with physical impossibility conditions and an "at least one applies" guarantee. Models can no longer pattern-match the inequalities directly from the text and must deduce them from the described physical constraints of the scheduling model.
</RATIONALE>
<PRESERVED_ANSWER>
The certificates map exactly to the original sum and sequence bounds, and since the original dataset guarantees exactly one condition holds per input, allowing any valid certificate preserves the single correct output for all test cases.
</PRESERVED_ANSWER>

The problem remains an O(N) impossibility certification task where the intended solution is checking the three linear bounds.
