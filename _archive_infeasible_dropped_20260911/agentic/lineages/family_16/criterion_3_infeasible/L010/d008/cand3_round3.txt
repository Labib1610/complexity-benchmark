# Problem C — Memory Allocation Bottleneck

Time limit: 2 s   Memory limit: 256 MB

## Description

A distributed hypervisor manages a contiguous block of $T$ virtual memory pages, indexed $1$ through $T$. There are $j$ concurrent processes. Each process $i$ requires two distinct sets of pages:
- An input tensor $In_i$ consisting of exactly $p1_i$ distinct pages.
- An output tensor $Out_i$ consisting of exactly $p2_i$ distinct pages.

To avoid data corruption and ensure causal consistency, the hypervisor must enforce three allocation invariants:
1. **Causal Ordering:** For any single process $i$, every page allocated to its input tensor $In_i$ must have a strictly lower index than every page allocated to its output tensor $Out_i$.
2. **Input Isolation:** No two distinct processes may share any page in their input tensors (i.e., all $In$ sets are mutually disjoint).
3. **Output Isolation:** No two distinct processes may share any page in their output tensors (i.e., all $Out$ sets are mutually disjoint).

*(Note: A page may be shared between an input tensor of process $i$ and an output tensor of process $k$, provided this does not violate Causal Ordering for either individual process.)*

Every provided configuration is mathematically impossible to allocate—there is no valid way to assign the pages to satisfy all invariants simultaneously. Because a configuration could theoretically fail for multiple interacting reasons, you must identify the primary bottleneck that renders the configuration unachievable. 

Evaluate the configuration against the following foundational limits in strict diagnostic order, and output the certificate for the highest-priority limit that is broken:

- **Priority 1 (Input-Space Exhaustion):** It is impossible to embed $j$ mutually disjoint input tensors of the required sizes into the $T$ available pages. Output `LOAD 1`.
- **Priority 2 (Output-Space Exhaustion):** It is impossible to embed $j$ mutually disjoint output tensors of the required sizes into the $T$ available pages. Output `LOAD 2`.
- **Priority 3 (Causal Violation):** For some process $i$, it is impossible to embed its input and output tensors of the required sizes into the $T$ available pages such that Causal Ordering is maintained. Output `JOB i` (where $i$ is the 1-based index of the process). If multiple processes independently fail this, output the certificate for the process with the smallest index $i$.

## Input

The first line provides two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000), representing the number of processes and the total number of memory pages.
Each of the subsequent **j** lines contains two integers, **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), specifying the required number of pages for $In_i$ and $Out_i$ respectively.

## Output

Print a single line containing the certificate of the primary bottleneck: `LOAD 1`, `LOAD 2`, or `JOB i` (where `i` is the process index).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, process 1 needs 70 input pages and 60 output pages. To maintain Causal Ordering, all 70 input pages must have strictly lower indices than all 60 output pages. This requires at least 130 distinct pages, but only 100 are available, making it impossible. This is a Causal Violation. The total required input pages across all processes (75) and total output pages (66) do not exceed 100, so Priorities 1 and 2 are not triggered. The correct certificate is `JOB 1`.

In Example 2, no individual process violates Causal Ordering (e.g., 50 + 1 ≤ 150). However, the four processes require 50 input pages each. To satisfy Input Isolation, they must be mutually disjoint, requiring 200 pages in total. Since only 150 pages are available, it is impossible to embed them. This triggers Input-Space Exhaustion (Priority 1). The correct certificate is `LOAD 1`.
</STATEMENT>
<RATIONALE>
I translated the abstract subset-selection scenario into a memory-allocation narrative (virtual pages, input/output tensors) to preserve the exact mathematical structure (linearly ordered universe, disjoint subsets, strict index separation) while changing the vocabulary. To defeat models relying on the shortcut that exactly one requirement fails, I removed the explicit "exactly one failure" guarantee and replaced it with a strict diagnostic priority hierarchy. This forces models to logically evaluate the bottleneck priorities rather than assuming any first-found failure is sufficient.
</RATIONALE>
<PRESERVED_ANSWER>
The conditions for Priority 1, Priority 2, and Priority 3 are mathematically identical to the seed's X-Domain Exhaustion (sum of p1 > T), Y-Domain Exhaustion (sum of p2 > T), and Separation Failure (p1_i + p2_i > T), ensuring the exact same certificates are produced for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains an INFEASIBLE complexity class requiring O(j) scalar checks of subset size sums and individual size pairs against the limit T.
</PRESERVED_CLASS>
<RISK>
Models might interpret the priority checks as requiring them to simulate the entire allocation process to find interacting constraints, though the phrasing explicitly isolates the conditions to embedding specific disjoint sets or individual process tensors.
</RISK>
