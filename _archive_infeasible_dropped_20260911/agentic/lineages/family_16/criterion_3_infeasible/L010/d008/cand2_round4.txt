<STATEMENT>
# Problem C — Impossible Schedule: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system attempts to schedule a set of $j$ jobs. Each job $i$ consists of two consecutive phases: Phase 1 requires exactly $p1_i$ units of time, and Phase 2 requires exactly $p2_i$ units of time.

There are two specialized processors: Processor X and Processor Y.
- Phase 1 of every job must be executed exclusively on Processor X.
- Phase 2 of every job must be executed exclusively on Processor Y.
- For any single job $i$, its Phase 2 cannot begin until its Phase 1 has completely finished.
- Processor X can only process one job's Phase 1 at a time.
- Processor Y can only process one job's Phase 2 at a time.

All jobs must complete both of their phases within a strict global time window of $T$ units (from time $0$ to time $T$).

Every provided configuration is mathematically impossible to schedule. Your task is to identify the primary bottleneck that proves the schedule is unachievable, providing a short certificate.

There are three foundational structural constraints. For each, we can calculate the absolute minimum time window required to satisfy it independently:
- **Sequential Job Constraint:** The minimum time window required for a single job $i$ to run its Phase 1 and Phase 2 sequentially. The certificate is `JOB i` (where $i$ is the 1-based index of the job).
- **Processor X Workload:** The minimum time window required for Processor X to complete the total of all its assigned Phase 1 processing times. The certificate is `LOAD 1`.
- **Processor Y Workload:** The minimum time window required for Processor Y to complete the total of all its assigned Phase 2 processing times. The certificate is `LOAD 2`.

In the provided configurations, multiple constraints might demand a minimum time window strictly greater than $T$. You must output the certificate corresponding to the constraint that demands the **strictly largest minimum time window** overall. (If the largest demand is a Sequential Job Constraint, output `JOB i` for the specific job $i$ that maximizes this time).

You are guaranteed that for all provided inputs, there is a strictly unique maximum among these required minimum time windows.

## Input

The first line contains two integers $j$ and $T$ ($1 \le j \le 200000$, $1 \le T \le 1000000000$).
Each of the next $j$ lines contains two integers $p1_i$ and $p2_i$ ($1 \le p1_i, p2_i \le 1000000$): the time required for Phase 1 and Phase 2 of job $i$, respectively.

## Output

Print a single line: `JOB i` (if a sequential job constraint demands the largest time window), or `LOAD c` (where $c$ is 1 for Processor X workload or 2 for Processor Y workload).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, Job 1 requires a minimum time window of $70 + 60 = 130$. The Processor X workload requires $70 + 2 + 3 = 75$, and Processor Y requires $60 + 2 + 4 = 66$. The strictly largest minimum time window is $130$, which corresponds to Job 1. Thus, `JOB 1` is the correct certificate.

In Example 2, the Processor X workload requires a minimum time window of $50 + 50 + 50 + 50 = 200$. The Processor Y workload requires $4$, and the largest individual job requires $51$. The strictly largest minimum time window is $200$, corresponding to Processor X. Thus, `LOAD 1` is the correct output.

This forces models to abandon their shortcut of stopping at the first threshold violation and instead evaluate and compare all three conditions.
