<STATEMENT>
# Problem C — Impossible Matrix Schedule: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system attempts to construct two binary matrices, $M$ and $N$, both of dimensions $j \times T$ (where $j$ is the number of rows and $T$ is the number of columns). The $j$ rows correspond to distinct jobs, and the $T$ columns correspond to discrete sequential time steps. The columns are indexed $1$ to $T$.

For each job row $i$ (from $1$ to $j$), the system must place exactly $p1_i$ ones in matrix $M$ and exactly $p2_i$ ones in matrix $N$. All other entries in the matrices must be strictly zero.

A valid construction must satisfy three structural constraints:
1. **Job Index Precedence:** For any single job row $i$, if $M_{i, x} = 1$ and $N_{i, y} = 1$, then the column index $x$ must be strictly less than the column index $y$. 
2. **M-Column Sparsity:** Every column in matrix $M$ must contain at most one $1$ (i.e., the sum of the elements in any single column of $M$ cannot exceed $1$).
3. **N-Column Sparsity:** Every column in matrix $N$ must contain at most one $1$ (i.e., the sum of the elements in any single column of $N$ cannot exceed $1$).

*(Note: The two matrices are independent regarding column sparsity. A specific column index $c$ may contain a $1$ in both $M$ and $N$, provided this does not violate the Job Index Precedence constraint for their respective rows.)*

Every provided configuration is mathematically impossible to construct—there is no valid way to place the ones to satisfy all constraints. Instead of attempting to generate the matrices, your task is to identify the bottleneck that proves the configuration is unachievable, providing a short certificate.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Row Precedence Paradox:** For some job row $i$, there is no way to place $p1_i$ ones in $M$ and $p2_i$ ones in $N$ within $T$ columns such that the Job Index Precedence constraint is satisfied. Output `JOB i` (where $i$ is the 1-based index of the row).
- **M-Capacity Exhaustion:** There is no way to place the required number of ones across all rows in $M$ such that the M-Column Sparsity constraint is satisfied. Output `LOAD 1`.
- **N-Capacity Exhaustion:** There is no way to place the required number of ones across all rows in $N$ such that the N-Column Sparsity constraint is satisfied. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required number of ones for row $i$ in matrix $M$ and matrix $N$ respectively (i.e., $p1_i$ and $p2_i$).

## Output

Print a single line: `JOB i` (for a row precedence paradox) or `LOAD c` (for a capacity exhaustion, where **c** is 1 for M-capacity exhaustion or 2 for N-capacity exhaustion).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, job row 1 requires $p1_1 = 70$ ones in matrix $M$ and $p2_1 = 60$ ones in matrix $N$. There is no way to place these ones within 100 columns such that every $1$ in $M$ appears in a strictly earlier column than every $1$ in $N$, breaking the Job Index Precedence constraint. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single job row breaks the Job Index Precedence constraint. However, the rows require a total of 200 ones to be placed in matrix $M$. There is no way to place these across 150 columns while ensuring no column contains more than one $1$, breaking the M-Column Sparsity constraint. Thus `LOAD 1` is the correct output.
