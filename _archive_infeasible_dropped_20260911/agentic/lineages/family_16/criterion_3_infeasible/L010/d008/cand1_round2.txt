<STATEMENT>
# Problem C — Impossible Allocation: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A system must allocate integer memory addresses from the namespace $U = \{1, 2, \dots, M\}$. There are $N$ active processes. For each process $i$, the system must allocate two subsets of $U$: a read-set $R_i$ containing exactly $a_i$ addresses, and a write-set $W_i$ containing exactly $b_i$ addresses.

A valid memory assignment must satisfy three structural rules:
1. **Process-Level Ordering:** For any single process $i$, every address in its read-set $R_i$ must be strictly numerically smaller than every address in its write-set $W_i$.
2. **Read-Set Independence:** The total number of unique addresses present in the union of all read-sets $R_1, \dots, R_N$ must be exactly equal to the sum of their individual sizes, $\sum_{i=1}^N a_i$.
3. **Write-Set Independence:** The total number of unique addresses present in the union of all write-sets $W_1, \dots, W_N$ must be exactly equal to the sum of their individual sizes, $\sum_{i=1}^N b_i$.

*(Note: An address $u \in U$ may simultaneously belong to a read-set for process $i$ and a write-set for process $k$, provided this does not violate the ordering rule for their respective processes.)*

Every provided configuration is mathematically impossible to allocate—there is no valid way to assign the addresses to satisfy all rules. Instead of attempting to generate the assignments, your task is to identify the bottleneck that proves the configuration is unachievable, providing a short certificate.

Exactly one of the following foundational requirements is broken. Output the applicable certificate:

- **Ordering Failure:** For some process $i$, there do not exist any two subsets $R_i, W_i \subseteq U$ of the required sizes that satisfy the Process-Level Ordering rule. Output `JOB i` (where $i$ is the 1-based index of the process).
- **Read-Set Exhaustion:** There is no way to choose subsets $R_1, \dots, R_N \subseteq U$ of the required sizes that satisfy the Read-Set Independence rule. Output `LOAD 1`.
- **Write-Set Exhaustion:** There is no way to choose subsets $W_1, \dots, W_N \subseteq U$ of the required sizes that satisfy the Write-Set Independence rule. Output `LOAD 2`.

You are guaranteed that exactly one of these requirements will be broken for the given input.

## Input

The first line contains two integers **N** and **M** (1 ≤ N ≤ 200000, 1 ≤ M ≤ 1000000000).
Each of the next **N** lines contains two integers **a** and **b** (1 ≤ a, b ≤ 1000000): the required number of addresses for $R_i$ and $W_i$ respectively (i.e., $a_i$ and $b_i$).

## Output

Print a single line: `JOB i` (for an ordering failure) or `LOAD c` (for an exhaustion failure, where **c** is 1 for read-set exhaustion or 2 for write-set exhaustion).

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, process 1 requires a read-set of size $a_1 = 70$ and a write-set of size $b_1 = 60$. There is no way to select these from a namespace of 100 addresses such that every address in $R_1$ is strictly less than every address in $W_1$, breaking the Process-Level Ordering rule. Thus `JOB 1` is the correct proof of impossibility. 

In Example 2, no single process breaks the Ordering rule. However, the processes require $a_i = 50$ for all four processes. There is no way to select these read-sets (totaling 200 addresses) from a namespace of 150 addresses such that the number of unique addresses in their union is exactly 200, breaking the Read-Set Independence rule. Thus `LOAD 1` is the correct output.
