<STATEMENT>
# Problem C — Impossible Scheduling: Certify It

Time limit: 2 s   Memory limit: 256 MB

## Description

A computing cluster must process a batch of $j$ jobs. Each job $i$ consists of a task on Machine 1 requiring exactly $p1_i$ units of time, and a task on Machine 2 requiring exactly $p2_i$ units of time. 

Let $t_{1,i}$ be the start time of job $i$ on Machine 1, and $t_{2,i}$ be the start time of its task on Machine 2. A valid schedule must assign non-negative real numbers to all start times such that:
1. **Sequentiality:** $t_{2,i} \ge t_{1,i} + p1_i$ for all $i \in \{1 \dots j\}$.
2. **Deadline:** $t_{2,i} + p2_i \le T$ for all $i \in \{1 \dots j\}$.
3. **Machine 1 Capacity:** For any two distinct jobs $i$ and $k$, their Machine 1 processing intervals $[t_{1,i}, t_{1,i} + p1_i)$ and $[t_{1,k}, t_{1,k} + p1_k)$ must not intersect.
4. **Machine 2 Capacity:** For any two distinct jobs $i$ and $k$, their Machine 2 processing intervals $[t_{2,i}, t_{2,i} + p2_i)$ and $[t_{2,k}, t_{2,k} + p2_k)$ must not intersect.

Every provided configuration is mathematically impossible to schedule within the deadline $T$. Instead of attempting to schedule the jobs, your task is to identify the fundamental bottleneck that proves the schedule is impossible, and output its corresponding certificate.

A configuration may violate multiple foundational requirements. You must compute the **time deficit** for each potential violation, and output the certificate corresponding to the **strictly maximum deficit**. 

The deficits are defined as follows:
- **Local Constraint Deficit:** For each job $i$, its deficit is the amount by which its minimum possible completion time (implied by constraint 1 alone) exceeds the deadline $T$. If this is the maximum deficit, output `JOB i` (where $i$ is the 1-based index of the job).
- **Machine 1 Volume Deficit:** The deficit of Machine 1 is the amount by which the total active time required for Machine 1 across all jobs (implied by constraint 3) exceeds the available time window $[0, T]$. If this is the maximum deficit, output `LOAD 1`.
- **Machine 2 Volume Deficit:** The deficit of Machine 2 is the amount by which the total active time required for Machine 2 across all jobs (implied by constraint 4) exceeds the available time window $[0, T]$. If this is the maximum deficit, output `LOAD 2`.

If there is a tie for the maximum deficit, you must prioritize the certificates in the following order: `LOAD 1` (highest priority), then `LOAD 2`, then `JOB i`. If multiple jobs tie for the maximum deficit, prioritize the one with the smallest index $i$. (Note: The input guarantees that the maximum deficit is always strictly positive).

## Input

The first line contains two integers **j** and **T** (1 ≤ j ≤ 200000, 1 ≤ T ≤ 1000000000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the required processing time on Machine 1 and Machine 2 respectively for job $i$ (i.e., $p1_i$ and $p2_i$).

## Output

Print a single line containing the certificate of the bottleneck with the maximum time deficit: `JOB i`, `LOAD 1`, or `LOAD 2`.

## Examples

### Example 1

**Input**
```
3 100
70 60
2 2
3 4
```

**Output**
```
JOB 1
```

### Example 2

**Input**
```
4 150
50 1
50 1
50 1
50 1
```

**Output**
```
LOAD 1
```

## Note

In Example 1, the deficit for Machine 1 is $(70+2+3) - 100 = -25$. The deficit for Machine 2 is $(60+2+4) - 100 = -34$. The deficit for Job 1 is $(70+60) - 100 = 30$. Since Job 1 has the strictly maximum deficit (and it is positive), `JOB 1` is the correct proof of impossibility.

In Example 2, the deficit for Machine 1 is $(50+50+50+50) - 150 = 50$. The deficit for Machine 2 is $(1+1+1+1) - 150 = -146$. The deficit for each job is $(50+1) - 150 = -99$. The strictly maximum deficit belongs to Machine 1, so `LOAD 1` is the correct output.

<RATIONALE>
Reverted the problem domain back to the original scheduling formulation to satisfy the gate's strict requirement on task semantics. To break the models' shortcut (relying on the unique-failure guarantee to stop at the first violation), the problem now explicitly states multiple failures can occur and requires finding the "maximum deficit" with a strict tie-breaking priority. Models that pattern-match the old shortcut will fail if they blindly generate code that stops at the first failure without evaluating all deficits.
</RATIONALE>
<PRESERVED_ANSWER>
Because the original test cases guarantee exactly one requirement is broken, exactly one deficit will be positive while the others are ≤ 0, ensuring the "maximum deficit" always perfectly identifies the single true bottleneck.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains INFEASIBLE (solvable in O(N) time) because computing all deficits and finding the maximum requires a single linear scan of the input.
</PRESERVED_CLASS>
<RISK>
Models might find the problem easier to solve because the mathematical definitions of the deficits explicitly map to the required summations, though correctly implementing the maximum-finding logic with priority tie-breakers introduces new surface area for bugs.
</RISK>
