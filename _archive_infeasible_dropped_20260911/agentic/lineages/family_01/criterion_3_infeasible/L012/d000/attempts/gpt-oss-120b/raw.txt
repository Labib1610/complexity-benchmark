**Solution Explanation**

For every pair of workers `(u , v)` we know that they cannot work together.
We have to output three workers `a < b < c` such that all three pairs
`(a,b) , (a,c) , (b,c)` are forbidden.
Among all such triples we need the lexicographically smallest one
(minimum `a`, then minimum `b`, then minimum `c`).

The graph formed by the forbidden pairs is undirected.
The required triple is exactly a **triangle** in this graph.
`n ≤ 2000`, therefore a bitset of length `n` fits into a Python integer
(`2000` bits ≈ 250 bytes).

--------------------------------------------------------------------

#### 1.   Data representation  

* `adj[i]` – integer whose `j‑th` bit (`0`‑based) is `1` iff worker `i`
  cannot work with worker `j+1`.
* All edges are stored as ordered pairs `(a,b)` with `a < b`.
  The list is sorted – this gives the required order of trying pairs.

--------------------------------------------------------------------

#### 2.   Finding the smallest triangle  

For a fixed ordered edge `(a,b)` (`a < b`) a third vertex `c` must be a
common neighbour of `a` and `b` and also satisfy `c > b`
(because we need `a < b < c`).

```
common = adj[a] & adj[b]          # bits of vertices adjacent to both a and b
mask   = common >> b              # discard bits ≤ b
```

If `mask` is non‑zero, the least significant set bit of `mask`
corresponds to the smallest possible `c` for this pair.
The position of that bit is obtained by `lsb = mask & -mask`
and `idx = lsb.bit_length() - 1`.
Finally `c = b + idx + 1`.

Because we iterate edges in increasing `(a,b)` order and always pick the
smallest possible `c`, the first triangle we encounter is exactly the
lexicographically smallest one.

The algorithm stops as soon as a triangle is found – the problem guarantees
that at least one exists.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest
triple `a<b<c` forming a triangle.

---

##### Lemma 1  
For a fixed ordered edge `(a,b)` the algorithm, if it finds a vertex `c`,
outputs the smallest possible `c` such that `a<b<c` and `{a,b,c}` is a
triangle.

**Proof.**  
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to both
`a` and `b`.  
`mask = common >> b` removes all vertices `≤ b`.  
If `mask ≠ 0`, its least significant set bit corresponds to the smallest
remaining vertex, i.e. the smallest `c > b` belonging to `common`. ∎



##### Lemma 2  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
`(a,b)` is an input edge, therefore `a` and `b` are adjacent.
`c` is taken from `common = adj[a] & adj[b]`, hence `c` is adjacent to
both `a` and `b`.  Consequently all three edges exist. ∎



##### Lemma 3  
Let `T` be the set of all triangles in the graph.
The algorithm outputs the triangle with the smallest lexicographic
order among `T`.

**Proof.**  
Consider the ordered list of all edges `(a,b)` with `a<b`, sorted
lexicographically.
The algorithm scans this list sequentially.
For each scanned edge it either finds no suitable `c` or, by Lemma&nbsp;1,
the smallest possible `c` for that edge.
Therefore the first triangle encountered has the smallest possible first
element `a`.  
If several triangles share this `a`, the scan proceeds with increasing
`b`, so the first found among them has the smallest possible `b`.  
Finally, for that `(a,b)` the algorithm chooses the smallest feasible `c`
(Lemma&nbsp;1).  
Thus the produced triangle is lexicographically minimal among all
triangles. ∎



##### Theorem  
The program prints three integers `a b c` (`a<b<c`) such that each pair
cannot work together, and the printed triple is the lexicographically
smallest among all such triples.

**Proof.**  
By Lemma&nbsp;2 the printed triple forms a triangle, i.e. all three pairs
are forbidden.  
By Lemma&nbsp;3 this triangle is the lexicographically smallest one.
Therefore the output satisfies the specification. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets* – `O(m)` operations.  
*Scanning edges* – for each of the `m` edges we perform a constant‑time
bitwise `&`, a shift and a few integer operations: `O(m)`.  

Memory consumption: `n` integers of at most `n` bits → `O(n² / wordsize)`
≈ `2000·2000 / 64 ≈ 62 KB`, well within limits.

Overall:

```
Time   :  O(m)   ≤ 2·10⁵
Memory :  O(n)   ≤ 2000 integers
```

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    edges = []

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u > v:
            u, v = v, u
        edges.append((u, v))
        # set bits (0‑based)
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    edges.sort()                # lexicographic order of (a,b)

    for a, b in edges:
        common = adj[a] & adj[b]
        # keep only vertices > b
        mask = common >> b
        if mask:
            lsb = mask & -mask
            idx = lsb.bit_length() - 1   # position after shift
            c = b + idx + 1
            sys.stdout.write(f"{a} {b} {c}")
            return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
