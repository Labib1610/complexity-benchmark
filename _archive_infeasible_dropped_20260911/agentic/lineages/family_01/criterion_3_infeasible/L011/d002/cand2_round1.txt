# Problem C — Proof of Impossibility

Time limit: 2 s   Memory limit: 256 MB

The factory administration needs to divide its workforce into two non-overlapping shifts: day and night. However, HR has logged a list of incompatibilities. Each incompatibility record bars two specific employees from working the same shift.

It has been determined that creating a valid two-shift assignment for the entire workforce is impossible due to inherent contradictions in the log. To officially close the scheduling attempt, you must provide a specific proof of this impossibility by identifying a complete deadlock. A complete deadlock is formed by a set of three distinct incompatibility records from the log that collectively involve exactly three distinct employees. 

You must identify the three employees involved in such a deadlock.

## Input
The first line provides two integers $n$ and $m$. The workforce size $n$ ranges from 3 up to the facility's maximum of 2000. The number of logged incompatibility records $m$ is at least 3, and goes up to 200000 or the maximum possible number of distinct employee pairs, whichever is smaller.

Each of the subsequent $m$ lines contains two integers $u$ and $v$ — the ID numbers of the two employees in an incompatibility record. Employees are identified by numbers from 1 to $n$.

It is guaranteed that the log contains no duplicate records (each pair of employees is listed at most once), and that at least one complete deadlock exists.

## Output
Print three integers $a$, $b$, and $c$ on a single line with $a < b < c$, representing the ID numbers of the three employees in the deadlock. They must satisfy the condition that there are three records in the log that collectively involve only these three employees. If there are multiple valid groups of three employees, output the one with the smallest value for $a$; in case of a tie, the one with the smallest value for $b$; and if still tied, the one with the smallest value for $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I removed the sequential pair-wise description of the deadlock ("first is incompatible with second, second with third...") which models used to map directly to a "common neighbor" adjacency intersection. Instead, I defined the deadlock as a set of three records that collectively involve exactly three employees. This forces the model to deduce the structural equivalence to a triangle (3 edges on 3 vertices) before it can recognize the need for the intended bitset adjacency algorithm.
</RATIONALE>
<PRESERVED_ANSWER>
In a graph with no duplicate edges, any set of three edges that collectively span exactly three vertices must form a triangle, meaning exactly the same sets of employees are valid under both descriptions.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core task remains finding a 3-clique (triangle) in the provided incompatibility graph, preserving the original computational complexity and the viability of the intended $O(nm/64)$ bitset algorithm.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "collectively involve exactly three distinct employees" as a condition on the entire log rather than just the subset of three records, though the phrasing explicitly restricts the scope to "a set of three distinct incompatibility records".
</RISK>
