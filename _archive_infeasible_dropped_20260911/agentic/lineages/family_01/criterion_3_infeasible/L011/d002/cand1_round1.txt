# Problem C — Proof of Impossibility

Time limit: 2 s   Memory limit: 256 MB

The factory administration needs to divide its workforce into two non-overlapping shifts: day and night. However, HR has logged a list of mutual incompatibilities between specific workers. When an incompatibility is logged for a pair of workers, they are barred from working the same shift.

It has been determined that creating a valid two-shift assignment for the entire workforce is impossible due to inherent contradictions in the incompatibility log. To officially close the scheduling attempt, you must provide a specific proof of this impossibility. Specifically, you need to find three distinct employees who form a complete deadlock. A complete deadlock is a group of exactly three employees who, if they were the only employees to be scheduled, could not possibly be divided between the two shifts without violating at least one logged incompatibility between members of this specific group of three. The log is guaranteed to contain at least one such triad. You must identify one such triad of employees.

## Input
The first line provides two integers $n$ and $m$. The workforce size $n$ ranges from 3 up to the facility's maximum of 2000. The number of logged incompatibilities $m$ is at least 3, and goes up to 200000 or the maximum possible number of distinct employee pairs, whichever is smaller.

Each of the subsequent $m$ lines contains two integers $u$ and $v$ — the ID numbers of a pair of employees who are incompatible. Employees are identified by numbers from 1 to $n$.

It is guaranteed that at least one complete deadlock involving three employees exists in the log.

## Output
Print three integers $a$, $b$, and $c$ on a single line with $a < b < c$, representing the ID numbers of the three employees in the deadlock. They must form a complete deadlock as defined in the description. If there are multiple valid triads, output the one with the smallest value for $a$; in case of a tie, the one with the smallest value for $b$; and if still tied, the one with the smallest value for $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
Removed the explicit listing of the three required pairwise incompatibilities from both the description and the output sections, which directly handed the models the triangle/common-neighbor structure. Replaced it with the logical property that the three employees cannot be divided into two shifts without an internal violation. This forces the model to deduce via the pigeonhole principle that a group of 3 nodes is not 2-colorable if and only if all three possible edges are present, before it can recognize that a common-neighbor adjacency intersection is the correct algorithm.
</RATIONALE>
<PRESERVED_ANSWER>
Any three employees that cannot be split into two shifts without violating an internal incompatibility must have all three pairwise incompatibilities present, meaning the valid outputs remain exactly the triangles of the graph.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a 3-cycle (triangle) in an undirected graph, maintaining the exact same algorithmic complexity and intended bitset-intersection approach.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "could not possibly be divided" as a dynamic simulation or connectivity requirement, but the phrase strictly and unambiguously defines the lack of a valid 2-coloring for those 3 vertices.
</RISK>
