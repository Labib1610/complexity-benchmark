**Solution Explanation**

For every chemical we know the list of chemicals it reacts with.
A *deadlock* is a triangle – three vertices `a<b<c` such that all three
edges `{a,b}`, `{a,c}`, `{b,c}` are present.

`n ≤ 2000`, therefore a whole adjacency row fits into a 2000‑bit bitset.
In Python an integer can be used as such a bitset: bit *i* (0‑based) is
`1` iff the vertex `i` is adjacent to the current vertex.

--------------------------------------------------------------------

#### Data structures
* `adj[i]` – integer, bitset of neighbours of vertex `i` (0‑based).
* `nbr[i]` – list of neighbours of `i` sorted increasingly (for the
  outer loops).

--------------------------------------------------------------------

#### Algorithm
```
read n,m
build adj[] and nbr[]
for a = 0 … n-1
        for each b in nbr[a] with b > a          # a<b
                common = adj[a] & adj[b]        # vertices adjacent to both
                # we need a vertex c > b
                shifted = common >> (b+1)      # delete bits ≤ b
                if shifted != 0:
                        # lowest set bit = first possible c
                        lsb = shifted & -shifted
                        c = (b+1) + (lsb.bit_length() - 1)
                        output a+1, b+1, c+1
                        terminate
```

*Why does it give the lexicographically smallest triangle?*  
The outermost loop increases `a`. For a fixed `a` the inner loop scans
`b` in increasing order, and the first `c` we find is the smallest
possible because we take the lowest set bit after `b`.  
Thus the first triangle discovered is exactly the one with minimal
`a`, then minimal `b`, then minimal `c`.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the required triangle.

---

**Lemma 1**  
For any vertices `a<b`, `common = adj[a] & adj[b]` contains exactly the
vertices adjacent to both `a` and `b`.

*Proof.* By definition `adj[x]` has a `1` at position `v` iff `{x,v}`
is an edge. Bitwise AND keeps a `1` at `v` only if both operands have a
`1`, i.e. both edges `{a,v}` and `{b,v}` exist. ∎



**Lemma 2**  
`shifted = common >> (b+1)` has a `1` at position `k` (0‑based) iff
vertex `c = b+1+k` satisfies `c>b` and is adjacent to both `a` and `b`.

*Proof.* Right shift discards the lowest `b+1` bits, i.e. all vertices
`≤ b`. The remaining bits keep their relative order, therefore a `1` at
position `k` corresponds to vertex `c = b+1+k` with the required
properties. ∎



**Lemma 3**  
If `shifted ≠ 0`, the vertex `c` computed by the algorithm is the
smallest vertex `>b` that is adjacent to both `a` and `b`.

*Proof.* `lsb = shifted & -shifted` isolates the least significant `1`,
i.e. the smallest `k` with a `1`. Consequently `c = b+1+k` is the smallest
vertex larger than `b` belonging to `common`. By Lemma&nbsp;2 this `c`
is adjacent to both `a` and `b`. ∎



**Lemma 4**  
When the algorithm prints `(a,b,c)`, the three edges
`{a,b}`, `{a,c}`, `{b,c}` are all present.

*Proof.* `b` is taken from `nbr[a]`, therefore `{a,b}` is an edge.
By Lemma&nbsp;1 vertex `c` belongs to `common = adj[a] & adj[b]`,
hence `{a,c}` and `{b,c}` are edges. ∎



**Lemma 5**  
The first printed triangle is lexicographically minimal among all
triangles.

*Proof.* The outer loop enumerates `a` increasingly.
For a fixed `a`, the inner loop enumerates `b>a` increasingly.
For each pair `(a,b)` Lemma&nbsp;3 yields the smallest possible `c>b`.
Therefore any triangle discovered later has either a larger `a`,
or the same `a` and larger `b`, or the same `a,b` and larger `c`. ∎



**Theorem**  
The algorithm always outputs three distinct integers `a<b<c` that form
a triangle, and this triangle is the lexicographically smallest one in
the graph.

*Proof.* Existence of at least one triangle is guaranteed by the
statement. The loops eventually examine the pair `(a,b)` belonging to
the smallest triangle; Lemma&nbsp;3 then finds its `c`, so the algorithm
will print a triangle. By Lemma&nbsp;4 the printed vertices indeed form
a triangle, and by Lemma&nbsp;5 it is the lexicographically smallest
possible. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

`adj[a] & adj[b]` is a bitwise AND on at most 2000 bits → `O(1)` in Python
(because integer operations are word‑wise).  
The loops iterate over every edge exactly once (`b` is a neighbour of
`a` with `b>a`). Hence

*Time*: `O(m)`  
*Memory*: `O(n + m)` for the adjacency bitsets and neighbour lists  
(`n ≤ 2000`, `m ≤ 200 000` well within limits).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n          # bitset
    nbr = [[] for _ in range(n)]

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        if u == v:
            continue
        # store undirected edge
        adj[u] |= 1 << v
        adj[v] |= 1 << u
        if v > u:
            nbr[u].append(v)
        else:
            nbr[v].append(u)

    # ensure neighbour lists are sorted (they already are because we added in input order,
    # but sorting guarantees correctness)
    for lst in nbr:
        lst.sort()

    for a in range(n):
        mask_a = adj[a]
        for b in nbr[a]:          # b > a
            # common neighbours of a and b
            common = mask_a & adj[b]
            # keep only vertices > b
            shifted = common >> (b + 1)
            if shifted:
                lsb = shifted & -shifted
                # position of lsb (0‑based)
                k = lsb.bit_length() - 1
                c = b + 1 + k
                # output 1‑based
                sys.stdout.write(f"{a+1} {b+1} {c+1}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
