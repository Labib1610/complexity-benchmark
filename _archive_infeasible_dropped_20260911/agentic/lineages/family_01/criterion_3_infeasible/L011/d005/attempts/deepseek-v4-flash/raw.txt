We can model each sequence as a bitmask of length `m`, but since `m` can be up to 200,000, we need a more efficient approach.

The key observation:  
Each operation sets the same position `k` to 1 for two sequences.  
So for two sequences to have a positive dot product, they must share at least one position where both are 1.  
That means they must appear together in at least one operation.

Thus, the problem reduces to:  
We have a graph with `n` vertices (sequences). Each operation adds an edge between `u` and `v`.  
We need to find a triangle (3 mutually connected vertices) with the smallest lexicographic order.

Since `m` can be up to 200,000 and `n` up to 2000, we can use an adjacency matrix (n×n boolean) to check edges in O(1).  
We iterate over all triples `(a, b, c)` in lexicographic order and check if all three edges exist.

Complexity: O(n³) = 8e9 in worst case — too slow.  
We need a better method.

We can use the fact that `n ≤ 2000`, so we can store adjacency as bitsets (Python integers) and use bit operations to find triangles faster.

Algorithm:
- Build adjacency bitset for each vertex.
- For each `a` from 1 to n:
  - For each `b > a` that is connected to `a`:
    - Compute `common = adj[a] & adj[b]`
    - If `common` has any bit set beyond `b`, pick the smallest such `c`.
    - This gives the lexicographically smallest triangle starting with `a, b`.

This is efficient because we only iterate over edges, and bit operations are fast.

Let's implement it.

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * (n + 1)
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u] |= (1 << (v - 1))
        adj[v] |= (1 << (u - 1))
    
    for a in range(1, n + 1):
        # iterate over neighbors b > a
        mask_b = adj[a] >> a  # shift to ignore bits <= a
        while mask_b:
            # get lowest set bit
            lsb = mask_b & -mask_b
            b = a + (lsb.bit_length())  # because we shifted by a
            # Actually careful: after shifting by a, bit position 0 corresponds to vertex a+1
            # Let's do it differently:
            # We'll iterate over bits directly
            break
        # Better: iterate over b in neighbors of a with b > a
        for b in range(a + 1, n + 1):
            if (adj[a] >> (b - 1)) & 1:
                common = adj[a] & adj[b]
                # find smallest c > b
                # clear bits <= b
                common &= ~((1 << b) - 1)
                if common:
                    c = (common & -common).bit_length()  # 1-indexed
                    print(a, b, c)
                    return

if __name__ == "__main__":
    solve()
```
