**Solution Explanation**

For every operation `k` we set the `k`‑th bit of exactly two sequences `u , v`
to `1`.  
Therefore each bit corresponds to an *undirected edge* `{u,v}` of a simple
graph `G` with `n` vertices and `m` edges.

--------------------------------------------------------------------

#### 1.   From the statement to a graph property  

For a vertex `i`

```
W(S_i) = degree(i)                (number of incident edges)
```

For two different vertices `i , j`

```
common(i,j) = 1  if edge {i,j} exists
               0  otherwise
d(S_i,S_j) = degree(i) + degree(j) – 2·common(i,j)
```

For three distinct vertices `a<b<c`

```
d(a,b)+d(b,c)+d(c,a)
 = 2·(deg(a)+deg(b)+deg(c)) – 2·(common(ab)+common(bc)+common(ca))
```

The required equality is  

```
d(a,b)+d(b,c)+d(c,a) = 2·(deg(a)+deg(b)+deg(c)) – 6
```

Hence  

```
2·(common(ab)+common(bc)+common(ca)) = 6
⇒ common(ab)+common(bc)+common(ca) = 3
```

`common` is `0` or `1`, therefore the sum is `3` **iff all three edges are
present** – i.e. `{a,b,c}` is a triangle of `G`.

So the whole problem is:

*find the lexicographically smallest triangle in an undirected simple graph
with `n ≤ 2000` vertices and `m ≤ 200 000` edges.*

--------------------------------------------------------------------

#### 2.   Finding the smallest triangle  

`n = 2000` fits into a 64‑bit word array, but Python integers are arbitrary
precision and support fast bit operations.  
For every vertex `v` we store a bitset `mask[v]` (`int`) whose `i`‑th bit is
`1` iff edge `{v,i}` exists.

Algorithm (0‑based indices)

```
for a = 0 … n-1:
    for each neighbour b of a with b > a:
        common = mask[a] & mask[b]          # vertices adjacent to both a and b
        # we need a vertex c > b
        common >>= (b+1)                    # delete bits ≤ b
        if common != 0:
            low = common & -common           # lowest set bit
            c = (low.bit_length() - 1) + (b+1)
            output a+1, b+1, c+1 and stop
```

Why does it give the lexicographically smallest triangle?

* the outer loop increases `a` – the first vertex is minimal,
* inside, neighbours `b` are examined in increasing order,
* for a fixed pair `(a,b)` we take the smallest possible `c > b`.

Thus the first triangle found is exactly the required one.

Complexities  

*building masks* – `O(m)`  
*search* – each edge `{a,b}` is processed once, the work per edge is a few
bit operations (`&`, shift, `& -`).  
Overall `O(m)` time, `O(n)` memory (the `n` integer masks).

Both limits are easily satisfied (`n ≤ 2000`, `m ≤ 200 000`).

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triple
`(a,b,c)` that satisfies the condition of the problem.

---

##### Lemma 1  
For any three distinct vertices `x,y,z` the condition  

```
d(S_x,S_y)+d(S_y,S_z)+d(S_z,S_x) = 2·(W(S_x)+W(S_y)+W(S_z)) – 6
```

holds **iff** the edges `{x,y}`, `{y,z}`, `{z,x}` all exist in `G`.

**Proof.**  
From the derivation in Section&nbsp;1  

```
d(x,y)+d(y,z)+d(z,x) = 2·(deg(x)+deg(y)+deg(z)) – 2·(e_xy+e_yz+e_zx)
```

where `e_uv = 1` if edge `{u,v}` exists, else `0`.  
Equality with the right‑hand side of the statement forces  

```
2·(e_xy+e_yz+e_zx) = 6  ⇒  e_xy+e_yz+e_zx = 3 .
```

Since each `e_uv` is at most `1`, the sum can be `3` only when all three are
`1`. ∎



##### Lemma 2  
When the algorithm terminates with vertices `(a,b,c)`,
the three edges `{a,b}`, `{b,c}`, `{c,a}` are present in `G`.

**Proof.**  
The outer loop guarantees `a<b`.  
The inner loop iterates only over neighbours `b` of `a`, therefore edge
`{a,b}` exists.  
`common = mask[a] & mask[b]` contains exactly the vertices adjacent to **both**
`a` and `b`. After shifting right by `b+1` we keep only vertices `> b`.  
If the shifted value is non‑zero, its lowest set bit corresponds to a vertex
`c>b` that is adjacent to both `a` and `b`. Hence edges `{a,c}` and `{b,c}`
exist. ∎



##### Lemma 3  
The triple `(a,b,c)` output by the algorithm is the lexicographically smallest
triangle of `G`.

**Proof.**  
Consider any triangle `{x,y,z}` with `x<y<z`.  
During the execution:

* When `a = x` the outer loop reaches `x` before any larger vertex.
* Inside, neighbours `b` of `x` are examined in increasing order, so `b = y`
  is processed before any `b' > y`.
* For this pair `(x,y)` the bitset `mask[x] & mask[y]` contains `z`. After the
  shift, `z` is still present, thus the algorithm will find a `c ≤ z`.
  Because `z` is the smallest vertex > `y` adjacent to both, the algorithm
  actually obtains `c = z`.

Consequently the algorithm discovers the triangle `(x,y,z)` at the moment
`a = x`. Since no triangle with a smaller first vertex can exist, the first
triangle found is lexicographically minimal. ∎



##### Lemma 4  
If the algorithm finishes without output, the graph contains no triangle.

**Proof.**  
Assume a triangle exists, say `{p,q,r}` with `p<q<r`. By Lemma&nbsp;2 the
algorithm would output a triangle when processing `a=p`, `b=q`. Hence the
algorithm cannot finish without output. Contradiction. ∎



##### Theorem  
The program prints three integers `a<b<c` that satisfy the equation of the
statement, and among all such triples it prints the lexicographically
smallest one.

**Proof.**  
By Lemma&nbsp;1 a triple satisfies the equation exactly when it forms a
triangle.  
If the program outputs `(a,b,c)`, Lemma&nbsp;2 shows it is a triangle, thus
the equation holds. Lemma&nbsp;3 guarantees it is the lexicographically
smallest triangle, therefore the smallest valid triple.  
If the program did not output anything, Lemma&nbsp;4 would imply the graph
has no triangle, contradicting the problem guarantee that a resonance exists.
Hence the program always outputs the required triple. ∎

#### 4.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    masks = [0] * n          # bitset of neighbours
    neigh = [[] for _ in range(n)]

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        masks[u] |= 1 << v
        masks[v] |= 1 << u
        neigh[u].append(v)
        neigh[v].append(u)

    # ensure neighbour lists are sorted for increasing order
    for lst in neigh:
        lst.sort()

    for a in range(n):
        ma = masks[a]
        for b in neigh[a]:
            if b <= a:
                continue
            common = ma & masks[b]
            # keep only vertices > b
            common >>= (b + 1)
            if common:
                low = common & -common          # lowest set bit
                c = (low.bit_length() - 1) + (b + 1)
                # output 1‑based indices
                sys.stdout.write(f"{a+1} {b+1} {c+1}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
