<STATEMENT>
# Problem C — Sequence Resonance

Time limit: 2 s   Memory limit: 256 MB

You are analyzing a system of $n$ sequences, denoted $S_1, S_2, \ldots, S_n$. Each sequence has a length of exactly $m$ bits, and all bits are initially set to $0$.

The system's configuration is defined by a list of $m$ operations. For each $k$ from $1$ to $m$, the $k$-th operation specifies two distinct sequence indices $u$ and $v$. This operation modifies the $k$-th position of the sequences by setting $S_u[k] = 1$ and $S_v[k] = 1$. The $k$-th position of all other sequences remains $0$.

Let $W(S_i)$ denote the Hamming weight of sequence $S_i$, which is the total number of $1$s in $S_i$. 
Let $d(S_i, S_j)$ denote the Hamming distance between $S_i$ and $S_j$, which is the number of positions $k$ where $S_i[k] \neq S_j[k]$.

Your task is to find a "resonance" among the sequences. A resonance is formed by three distinct sequence indices $a$, $b$, and $c$ (with $a < b < c$) such that their pairwise Hamming distances satisfy the following equation:

$d(S_a, S_b) + d(S_b, S_c) + d(S_c, S_a) = 2 \left( W(S_a) + W(S_b) + W(S_c) \right) - 6$

## Input
The first line contains two integers $n$ and $m$. The integer $n$ ($3 \le n \le 2000$) defines the number of sequences. The integer $m$ ($3 \le m \le 200000$) defines the length of each sequence and the number of operations. It is guaranteed that $m \le n(n-1)/2$.

Each of the following $m$ lines corresponds to an operation. For $k$ from $1$ to $m$, the $k$-th of these lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating the sequences modified in operation $k$. No two operations will specify the exact same pair of indices $\{u, v\}$.

It is guaranteed that at least one valid resonance exists.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, with $a < b < c$. These integers must form a valid resonance as described above. 

If there are multiple valid trios, output the one that is lexicographically smallest. This means you should output the trio with the smallest value for $a$; if there is a tie, choose the one with the smallest value for $b$; and if a tie remains, choose the one with the smallest value for $c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<RATIONALE>
The surviving models succeeded by evaluating the original pointwise sum for the possible values (0, 1, 2) and noticing that only a value of 2 contributes heavily, directly deducing that exactly 3 pointwise intersections are required. To defeat this, the explicit sum over $k$ is completely removed. The condition is rephrased as a global geometric property using Hamming weight and Hamming distance. Models must now algebraically expand the definition of Hamming distance ($d(x,y) = W(x) + W(y) - 2|x \cap y|$) and simplify the equation to discover it requires exactly 3 shared operations (a triangle). Blindly simulating the metric will result in a Time Limit Exceeded.
</RATIONALE>
<PRESERVED_ANSWER>
By definition, $d(S_i, S_j) = W(S_i) + W(S_j) - 2 C(i,j)$, where $C(i,j)$ is the number of shared $1$s. Substituting this into the new equation algebraically simplifies exactly to $C(a,b) + C(b,c) + C(c,a) = 3$, which, given the input constraints, strictly requires $a,b,c$ to form a triangle, identical to the original problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem remains finding a triangle in an undirected graph, which is achieved optimally in $O(n \cdot m / 64)$ or $O(m \sqrt{m})$ time, preserving the complexity class.
</PRESERVED_CLASS>
