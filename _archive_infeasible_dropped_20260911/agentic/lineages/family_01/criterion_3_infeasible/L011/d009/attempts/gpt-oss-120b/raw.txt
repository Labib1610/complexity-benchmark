**Solution Explanation**

For every operation `k` we set the `k`‑th bit of exactly two sequences.
The pair of indices `(u , v)` of this operation is an *edge* of an
undirected simple graph `G` with vertices `1 … n`.

```
edge (u , v)  ⇔  the k‑th bit of Su and Sv is 1
```

For a pair of vertices `i , j`

* if the edge `{i , j}` exists, the two sequences have a common `1`
  at this position → contribution `3`
* otherwise the two sequences differ at this position → contribution `1`

All `m` positions give a base value `1`, therefore  

```
F(Si , Sj) = m                     (no edge i‑j)
F(Si , Sj) = m + 2                 (edge i‑j exists)
```

For a triple `{a , b , c}`

```
F(a,b)+F(b,c)+F(c,a) = 3·m + 2·( #edges among a,b,c )
```

The required sum `3·m + 6` means that the three edges
`ab , bc , ca` must all be present – the vertices form a **triangle**.

Thus the problem is reduced to:

> In the given simple graph ( `n ≤ 2000 , m ≤ 200 000` ) find the
> lexicographically smallest triangle `(a,b,c)` with `a<b<c`.
> It is guaranteed that at least one triangle exists.

--------------------------------------------------------------------

#### 1.   Data structure – bitset per vertex  

`n ≤ 2000`, therefore a 2000‑bit integer fits easily into a Python `int`.
For every vertex `v` we store

```
adj[v]  – integer whose (u‑1)-th bit is 1  ⇔  edge (v , u) exists
```

All edges are inserted in `O(m)` time.

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle  

We enumerate the first two vertices of the triangle in lexicographic order:

```
for a = 1 … n
    for b = a+1 … n
        if edge a‑b does not exist: continue
        common = adj[a] & adj[b]          # vertices adjacent to both a and b
        # we need a vertex c > b
        common >>= b                      # delete bits 0 … b‑1
        if common != 0:
               c = smallest vertex in common
               output a b c
```

* `adj[a] & adj[b]` gives all common neighbours of `a` and `b`.
* Shifting right by `b` removes vertices `≤ b`; the lowest set bit now
  corresponds to the smallest possible `c`.
* The index of the lowest set bit is obtained by `lsb = common & -common`
  and `c = b + 1 + (lsb.bit_length() - 1)`.

The double loop runs at most `n·(n‑1)/2 ≤ 2·10⁶` iterations,
each iteration performs only a few integer operations – easily fast enough.

Because `a` grows first, then `b`, and we always pick the smallest possible
`c`, the first triangle we encounter is the lexicographically smallest one.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

##### Lemma 1  
For any two vertices `i , j`  
`F(Si , Sj) = m + 2·[ edge (i , j) exists ]`.

**Proof.**  
All `m` positions contribute `1`.  
If the edge `(i , j)` exists, the corresponding position contributes `3`
instead of `1`, i.e. an extra `2`. No other position gives a different
contribution. ∎



##### Lemma 2  
A triple `{a,b,c}` satisfies  
`F(a,b)+F(b,c)+F(c,a) = 3·m + 6`  
iff the three edges `ab , bc , ca` are all present (the vertices form a
triangle).

**Proof.**  
By Lemma&nbsp;1 each pair contributes `m` plus `2` if the edge exists.
Hence the total sum equals `3·m + 2·( number of present edges among the three
pairs )`.  
Equality with `3·m+6` forces the number of present edges to be `3`. ∎



##### Lemma 3  
When the algorithm examines a pair `(a,b)` (`a<b`) that is an edge,
`common = (adj[a] & adj[b]) >> b` is non‑zero **iff** there exists a vertex
`c>b` adjacent to both `a` and `b`. In that case the smallest such `c` is
recovered from the lowest set bit of `common`.

**Proof.**  
`adj[a] & adj[b]` contains exactly the vertices adjacent to *both* `a` and
`b`. Shifting right by `b` discards bits for vertices `≤ b`; the remaining
bits correspond one‑to‑one to vertices `> b`. Therefore the integer is
non‑zero exactly when such a vertex exists. The lowest set bit after the
shift corresponds to the smallest vertex `c>b`. ∎



##### Lemma 4  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The algorithm outputs only after confirming:
* edge `ab` exists (the inner loop continues only in this case);
* `common` after the shift is non‑zero, i.e. there exists a vertex `c>b`
  adjacent to both `a` and `b` (Lemma&nbsp;3).

Thus edges `ab , ac , bc` are present – a triangle. ∎



##### Lemma 5  
Let `T* = (a*,b*,c*)` be the lexicographically smallest triangle.
The algorithm will output `T*`.

**Proof.**  
Consider the outer loops. They enumerate all ordered pairs `(a,b)` with
`1 ≤ a < b ≤ n` in increasing lexicographic order.
Since `T*` is a triangle, its first two vertices `(a*,b*)` appear in this
order. When the algorithm reaches this pair, edge `a*b*` exists, so the
inner test passes. By Lemma&nbsp;3 the algorithm finds the smallest vertex
`c > b*` adjacent to both `a*` and `b*`. Because `c*` is adjacent to both and
`c* > b*`, the smallest such vertex is exactly `c*`. Consequently the
algorithm outputs `(a*,b*,c*)` and terminates before any later pair is
examined. ∎



##### Lemma 6  
The algorithm never outputs a triple that is not the lexicographically
smallest triangle.

**Proof.**  
Assume it outputs `(a,b,c)` and there exists a smaller triangle
`(a',b',c')` lexicographically. Then either `a' < a`, or `a'=a` and
`b' < b`, or `a'=a , b'=b` and `c' < c`.  
The outer loops would encounter the pair `(a',b')` (or `(a,b)`) before
`(a,b)`. At that moment, by Lemma&nbsp;3 the algorithm would have found a
common neighbour `c'` (or a smaller `c`) and would have terminated earlier,
contradiction. ∎



##### Theorem  
The algorithm always terminates and prints the lexicographically smallest
triple of distinct indices `(a,b,c)` that satisfies  

`F(Sa,Sb)+F(Sb,Sc)+F(Sc,Sa)=3m+6`.

**Proof.**  
Existence of at least one triangle is guaranteed, therefore the double
loop will eventually meet the first edge of the smallest triangle and,
by Lemma&nbsp;5, output it. Lemma&nbsp;4 shows the output is indeed a triangle,
and Lemma&nbsp;6 guarantees it is the lexicographically smallest one. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets* : `O(m)` time, `O(n)` memory (each vertex stores one
integer of ≤ 2000 bits).

*Searching* : at most `n·(n‑1)/2 ≤ 2·10⁶` iterations, each `O(1)` work.  
Time `O(n²) ≤ 2·10⁶` operations → well below the 2 s limit.

Memory consumption: `O(n)` integers ≈ `2000·(2000/8) ≈ 0.5 MB`, far below the
limit.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)

    # adjacency as bitsets, 1‑based vertices, bit (v-1) corresponds to vertex v
    adj = [0] * (n + 1)

    for _ in range(m):
        u = next(it)
        v = next(it)
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    for a in range(1, n + 1):
        # iterate b > a
        # we can test edge existence by checking the bit
        bits_a = adj[a]
        for b in range(a + 1, n + 1):
            if not (bits_a >> (b - 1)) & 1:
                continue          # no edge a‑b
            # common neighbours of a and b
            common = adj[a] & adj[b]
            # keep only vertices > b
            common >>= b
            if common:
                # lowest set bit gives smallest c > b
                lsb = common & -common
                pos = lsb.bit_length() - 1   # position after the shift
                c = b + 1 + pos
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
