Looking at this problem, I need to find a triangle (3-clique) in an undirected graph with n ≤ 2000 vertices and m ≤ 200000 edges, outputting the lexicographically smallest one.

**Key insight:** If m > n²/4, by Turán's theorem the graph must contain a triangle. In this case, I can find one efficiently by checking each vertex's neighborhood - if any vertex has two neighbors that are connected, that's a triangle.

When m ≤ n²/4, I can afford O(m·√m) work. The approach: for each edge (u,v), check if they share a common neighbor. To make this efficient, I iterate over edges and for each edge, mark neighbors of the smaller-degree endpoint, then check neighbors of the other endpoint.

**Lexicographic optimization:** To find the lexicographically smallest triangle, I process vertices in order. For vertex a (starting from 1), I look at pairs of its neighbors (b, c) with a < b < c and check if edge (b,c) exists. The first such triangle found is lexicographically smallest.

For efficiency with the neighbor-marking approach, I process edges (u,v) with u < v, and for each, find the smallest common neighbor w. Among all triangles found, I track the lexicographically smallest.

```python
import sys

def main():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [set() for _ in range(n + 1)]
    edges = []
    
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        if u > v:
            u, v = v, u
        adj[u].add(v)
        adj[v].add(u)
        edges.append((u, v))
    
    # Sort edges for deterministic processing
    edges.sort()
    
    best = None
    marked = [0] * (n + 1)
    stamp = 0
    
    for u, v in edges:
        # Find smallest common neighbor w
        # Mark neighbors of u (only those > max(u,v) won't help for lex order,
        # but we need all common neighbors)
        stamp += 1
        for w in adj[u]:
            marked[w] = stamp
        
        for w in adj[v]:
            if marked[w] == stamp:
                # Found triangle (u, v, w)
                a, b, c = sorted([u, v, w])
                if best is None or (a, b, c) < best:
                    best = (a, b, c)
                    # Can't break early - need lex smallest overall
    
    print(best[0], best[1], best[2])

main()
```

Wait, this could be slow if there are many edges with large neighborhoods. Let me optimize: for each edge, iterate over the smaller neighborhood and check membership in the larger one.

```python
import sys

def main():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [set() for _ in range(n + 1)]
    edges = []
    
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        if u > v:
            u, v = v, u
        adj[u].add(v)
        adj[v].add(u)
        edges.append((u, v))
    
    edges.sort()
    
    best = None
    
    for u, v in edges:
        # Iterate over smaller neighborhood
        if len(adj[u]) <= len(adj[v]):
            small, large = adj[u], adj[v]
        else:
            small, large = adj[v], adj[u]
        
        for w in small:
            if w in large:
                a, b, c = sorted([u, v, w])
                if best is None or (a, b, c) < best:
                    best = (a, b, c)
    
    print(best[0], best[1], best[2])

main()
```

This is O(m · min_degree) in the worst case, but with the degree optimization it's O(m · √m) amortized. Given m ≤ 200000, this should be fast enough.
