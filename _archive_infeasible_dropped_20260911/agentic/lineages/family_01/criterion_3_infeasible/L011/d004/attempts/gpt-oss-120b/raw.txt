**Solution Explanation**

For every unordered pair `{u , v}` with `F(u,v)=1` we have an undirected edge
`u – v`.  
The task is to output the lexicographically smallest triangle
`a < b < c` – three vertices that are pairwise adjacent.

`n ≤ 2000`, therefore a *bitset* of length `n` fits into a single Python
integer (`2000` bits ≈ 250 bytes).  
With bitsets the intersection of two neighbour sets is a single
`&` operation, i.e. **O(1)**.

--------------------------------------------------------------------

#### Data structures

* `adj[i]` – integer whose `j‑th` bit (`j` 0‑based) is `1` iff vertex `i+1`
  is adjacent to vertex `j+1`.  
  (`adj[i]` never contains the bit of `i` itself because `F(x,x)=0`.)

* `nbr[i]` – list of neighbours of vertex `i+1` **greater** than `i+1`,
  sorted increasingly.  
  Only neighbours `> i` are stored because during the search we always need
  `a < b`.

--------------------------------------------------------------------

#### Algorithm
```
for a = 1 … n
        for each b in nbr[a]               # b > a, edge a–b exists
                common = adj[a] & adj[b]   # vertices adjacent to both
                # we need a vertex c > b
                x = common >> b            # discard bits ≤ b
                if x != 0:                 # at least one common neighbour
                        low = x & -x        # lowest set bit of x
                        k = low.bit_length() - 1   # its index (0‑based)
                        c = b + 1 + k
                        output a b c and stop
```

*Why does the first found triangle satisfy the required order?*

* `a` grows from `1` upwards – the first triangle uses the smallest possible
  `a`.
* For a fixed `a`, `b` iterates increasingly – the first triangle for this
  `a` uses the smallest possible `b`.
* For a fixed pair `(a,b)` we take the smallest `c > b` (the lowest set bit
  after shifting).  

Thus the algorithm returns the lexicographically smallest triangle.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

##### Lemma 1  
For any vertices `a < b`, `common = adj[a] & adj[b]` contains exactly the
vertices adjacent to **both** `a` and `b`.

**Proof.** By definition `adj[a]` has a `1`‑bit precisely for neighbours of `a`,
similarly for `adj[b]`. Bitwise `&` keeps a `1` only where both operands have `1`,
hence exactly the common neighbours. ∎



##### Lemma 2  
After `x = common >> b`, the lowest set bit of `x` corresponds to the smallest
vertex `c` such that `c > b` and `c` is adjacent to both `a` and `b`.

**Proof.** Shifting right by `b` discards bits `0 … b‑1`, i.e. vertices
`1 … b`. The new bit `0` now represents vertex `b+1`, bit `1` → `b+2`, etc.
Therefore any set bit of `x` corresponds to a common neighbour larger than `b`.
The lowest set bit is the smallest such vertex. ∎



##### Lemma 3  
When the algorithm prints `(a,b,c)`, the three vertices form a triangle:
`F(a,b)=F(a,c)=F(b,c)=1`.

**Proof.** The outer loops guarantee that edges `a–b` and `a–c` exist
(`b` is taken from `nbr[a]`, `c` is a neighbour of `a` because `c` belongs to
`adj[a]`).  
From Lemma&nbsp;1, `c` belongs to `common = adj[a] & adj[b]`, therefore `c` is
also adjacent to `b`. Hence all three edges are present. ∎



##### Lemma 4  
If the algorithm stops at the first printed triangle `(a,b,c)`,
there is **no** triangle `(a',b',c')` with lexicographically smaller
triple.

**Proof.** Assume a smaller triangle exists.

*If `a' < a`*: the outermost loop would have examined `a'` before `a`,
and because the triangle exists, the inner loops would have found a
triangle (maybe with different `b',c'`) and stopped earlier – contradiction.

*If `a' = a` and `b' < b`*: while processing vertex `a` the inner loop iterates
`b` in increasing order, thus `b'` would be examined before `b` and the
algorithm would have stopped at that earlier triangle – contradiction.

*If `a' = a`, `b' = b` and `c' < c`*: for this pair `(a,b)` the algorithm
chooses the smallest possible `c` larger than `b` (Lemma&nbsp;2). Hence
`c'` cannot be smaller – contradiction. ∎



##### Lemma 5  
If a triangle exists in the graph, the algorithm will eventually print one.

**Proof.** Let `(a,b,c)` be any triangle with `a<b<c`.  
When the outer loop reaches this `a`, `b` is in `nbr[a]`.  
Consequently the inner loop processes this `b`.  
By Lemma&nbsp;1, `c` belongs to `common`. After shifting, `c` appears in `x`,
so `x != 0` and the algorithm prints a triangle (maybe an even smaller one,
but at least one). ∎



##### Theorem  
The algorithm terminates and outputs the lexicographically smallest
triangle of the given graph.

**Proof.** By Lemma&nbsp;5 a triangle will be found, therefore the algorithm
terminates. By Lemma&nbsp;3 the printed triple is indeed a triangle.
Lemma&nbsp;4 shows that no lexicographically smaller triangle can exist.
Thus the output is exactly the required smallest triangle. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency bitsets*: `O(m)`  
*Neighbour lists*: also `O(m)`.

Main loops: each unordered edge `{a,b}` with `a<b` is examined once.
For each such edge we perform a constant‑time bitwise `&` and a few integer
operations.  
Number of examined edges = `m` ≤ 200 000.

```
Time   :  O(m)          ( ≤ 2·10⁵ operations, easily < 2 s )
Memory :  n integers of ≤ 2000 bits  →  O(n)  (≈ 250 KB)  + neighbour lists O(m)
```

Both limits satisfy the problem constraints.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based, adj[i] bit j (0‑based) => vertex j+1
    nbr = [[] for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u == v:
            continue
        # set bits
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)
        if u < v:
            nbr[u].append(v)
        else:
            nbr[v].append(u)

    # neighbours are already collected only > vertex, but need sorted
    for lst in nbr:
        lst.sort()

    for a in range(1, n + 1):
        for b in nbr[a]:                 # b > a, edge a-b exists
            common = adj[a] & adj[b]
            # discard vertices <= b
            x = common >> b
            if x:
                low = x & -x
                k = low.bit_length() - 1   # index of lowest set bit
                c = b + 1 + k
                # output lexicographically smallest triangle
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
