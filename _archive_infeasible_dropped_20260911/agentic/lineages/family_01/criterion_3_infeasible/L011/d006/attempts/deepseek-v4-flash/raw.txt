We can model each operation as an edge in a graph between two vertices.  
For a triple of vertices \(a < b < c\), the condition given in the problem is equivalent to saying that among the three sequences, for each position \(k\), the values must not cancel out in a way that reduces the sum of absolute values by more than 6.  

In fact, the condition simplifies to:  
The three vertices must form a triangle in the graph (all three edges present).  
This is because each operation contributes \(+1\) and \(-1\) to two different sequences. If all three pairs are connected, then for each position, the three values are either \((1, -1, 0)\) in some order, and the sum of absolute values is 2, while the absolute sum is also 2, so no loss. If one edge is missing, then for some position, two of the sequences have \(+1\) and \(-1\), and the third has 0, giving a loss of 2. The total loss of 6 means all three edges are missing? Actually, let’s check:  

For a triple, the loss is \(2 \times\) (number of missing edges among the three pairs).  
We need loss = 6, so number of missing edges = 3, meaning no edges among them.  
Wait, that contradicts the example. Let’s re-evaluate.

Actually, the condition is:  
\[
\sum |S_a+S_b+S_c| = \sum (|S_a|+|S_b|+|S_c|) - 6
\]
The RHS is the sum of absolute values minus 6.  
For each position, if the three values are \((1,-1,0)\), then \(|1-1+0|=0\) while sum of abs = 2, so loss = 2.  
If the three values are \((1,1,-1)\), then \(|1+1-1|=1\) while sum of abs = 3, loss = 2.  
If the three values are \((1,1,1)\) or \((-1,-1,-1)\), then loss = 0.  
If the three values are \((1,-1,1)\) etc., loss = 2.  

So each position where the three sequences are not all the same sign gives a loss of 2.  
We need total loss = 6, so exactly 3 positions have loss 2, and all other positions have loss 0.  

Now, each operation connects two vertices. For a given triple, a position has loss 2 if the operation involves exactly two of the three vertices (so one of them is 0).  
If the operation involves all three? Impossible, since each operation only involves two vertices.  
If the operation involves none of the three, all values are 0, loss 0.  
If the operation involves exactly one of the three, then one is \(\pm1\), others 0, sum abs = 1, abs sum = 1, loss 0.  
If the operation involves exactly two of the three, then we have \((1,-1,0)\), loss 2.  

So loss = 2 × (number of operations that involve exactly two of the three vertices).  
We need loss = 6 ⇒ exactly 3 such operations.  

Now, each operation is an edge. For a triple, the number of edges that have exactly two endpoints in the triple is:  
- If the triple forms a triangle (3 edges among them), then each of those 3 edges has both endpoints in the triple, so they are not "exactly two" — they are "exactly two" actually, because both endpoints are in the triple, so yes, they count. Wait: "exactly two" means the edge has both endpoints in the triple, and the third vertex is not an endpoint. So yes, all 3 edges of the triangle count.  
- If the triple has only 2 edges, then those 2 edges count, plus any edge from the third vertex to one of the other two? No, that would be an edge with one endpoint in the triple and one outside, which doesn't count. So only the 2 internal edges count.  
- If the triple has 1 edge, only that 1 counts.  
- If 0 edges, 0 count.  

So loss = 2 × (number of edges among the triple).  
We need loss = 6 ⇒ number of edges among the triple = 3.  
That means the triple must form a triangle (all three edges present).  

So the problem reduces to: Find the lexicographically smallest triangle in an undirected graph with \(n\) vertices and \(m\) edges.  

Given constraints \(n \le 2000\), \(m \le 200000\), we can do this efficiently.  

We can iterate over \(a\) from 1 to n, then \(b > a\), and check if edge (a,b) exists. If yes, then for each \(c > b\) that is adjacent to both a and b, we have a triangle. To find the smallest c, we can precompute adjacency sets and for each pair (a,b), intersect their neighbor sets and pick the smallest > b.  

Complexity: O(n^2) pairs, each intersection O(degree) worst-case, but with bitsets we can do it fast. Since n ≤ 2000, we can use Python integers as bitsets for adjacency.  

Implementation:  
- Read n, m.  
- Build adjacency bitsets: adj[i] is an integer with bit j set if edge (i,j) exists.  
- For a from 1 to n:  
  - For b from a+1 to n:  
    - If adj[a] has bit b:  
      - common = adj[a] & adj[b]  
      - Remove bits ≤ b (we want c > b)  
      - If common != 0, find smallest set bit > b → that's c.  
      - Output and exit.  

We need 1-indexed.  

Let's implement.  

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * (n + 1)
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u] |= (1 << v)
        adj[v] |= (1 << u)
    
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if (adj[a] >> b) & 1:
                common = adj[a] & adj[b]
                # remove bits <= b
                mask = ((1 << (b + 1)) - 1)
                common &= ~mask
                if common:
                    # find lowest set bit
                    c = (common & -common).bit_length() - 1
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
