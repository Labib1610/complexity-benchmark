**Solution Explanation**

For every chemical we know the set of chemicals it reacts with.
We have to output the lexicographically smallest triple  

```
a < b < c
```

such that every two of them react – i.e. a triangle in the undirected
graph of reactions.

`n ≤ 2000`, therefore a *bitset* of length `n` fits into a Python integer
(2000 bits ≈ 250 bytes).  
With bitsets the intersection of two neighbour sets is a single
`&` operation and we can test in *O(1)* whether a common neighbour exists.



--------------------------------------------------------------------

#### Data structures
* `adj_bits[v]` – integer, bit *i* (`0‑based`) is `1` iff vertex `i+1`
  reacts with `v`.
* `adj_list[v]` – sorted list of neighbours of `v`.  
  Used to iterate over possible `b` in increasing order.

--------------------------------------------------------------------

#### Algorithm
```
read n, m
build adj_bits and adj_list
for a = 1 … n
        for b in adj_list[a] (already sorted)
                if b <= a: continue          # keep a < b
                common = adj_bits[a] & adj_bits[b]   # vertices adjacent to both
                # we need a vertex c > b
                mask = common >> b          # drop bits ≤ b
                if mask != 0:
                        low = mask & -mask   # lowest set bit
                        pos = low.bit_length() - 1   # its index (0‑based)
                        c = b + 1 + pos
                        output a b c
                        exit
```

*Why does the first found triple equal the lexicographically smallest?*  

The outer loop increases `a`.  
For a fixed `a` the inner loop scans `b` in increasing order.
For a fixed pair `(a,b)` we take the smallest possible `c > b`
(the lowest set bit after shifting).  
Thus triples are examined in exactly lexicographic order, and the first
valid one is the answer.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest
triangle.

---

**Lemma 1**  
For any vertices `a` and `b` the expression  

```
mask = (adj_bits[a] & adj_bits[b]) >> b
```

has a set bit at position `p` (`0‑based) iff vertex `c = b+1+p`
is adjacent to both `a` and `b` and `c > b`.

*Proof.*  
`adj_bits[a] & adj_bits[b]` has exactly the bits of vertices adjacent to
both `a` and `b`. Shifting right by `b` discards bits `0 … b-1`,
i.e. vertices `1 … b`. The remaining bit at position `p` corresponds to
vertex `b+1+p`. ∎



**Lemma 2**  
If `mask != 0` then the algorithm computes `c` equal to the smallest
vertex `> b` adjacent to both `a` and `b`.

*Proof.*  
`low = mask & -mask` isolates the lowest set bit of `mask`. Its index
`pos` is the smallest `p` with a set bit. By Lemma&nbsp;1 the corresponding
vertex is `c = b+1+pos`, which is the smallest vertex `> b` adjacent to
both `a` and `b`. ∎



**Lemma 3**  
When the algorithm prints a triple `(a,b,c)`, it is a triangle
(`a<b<c` and all three edges exist).

*Proof.*  
`a<b` by the loop condition. `c>b` by construction (`c = b+1+pos`).  
`b` is taken from `adj_list[a]`, therefore edge `(a,b)` exists.
By Lemma&nbsp;2, `c` is adjacent to both `a` and `b`. Hence all three
edges are present. ∎



**Lemma 4**  
The algorithm examines all possible triangles in lexicographic order.

*Proof.*  
The outer loop enumerates `a` increasingly.
For a fixed `a`, the inner loop enumerates `b` increasingly among
neighbours of `a` with `b>a`.  
For each pair `(a,b)` the algorithm, if possible, chooses the smallest
`c>b`.  
Therefore the sequence of examined triples is exactly the lexicographic
order of all triples `a<b<c`. ∎



**Theorem**  
The algorithm outputs the lexicographically smallest triple of chemicals
that form a triangle.

*Proof.*  
By Lemma&nbsp;3 any printed triple is a triangle.
By Lemma&nbsp;4 the first triangle encountered during the enumeration is
the lexicographically smallest one.
The algorithm stops at the first such triangle, thus outputs exactly that
triple. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building structures*: `O(m)`  
*Main loops*: at most `O(n^2)` iterations (worst case complete graph),
each does only constant‑time bit operations.  
With `n ≤ 2000` this is well below the limits.

Memory: `n+1` integers of ≤ 2000 bits → ≤ 250 KB, plus adjacency lists,
overall far under 256 MB.

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj_bits = [0] * (n + 1)
    adj_list = [[] for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        # set bits (0‑based)
        adj_bits[u] |= 1 << (v - 1)
        adj_bits[v] |= 1 << (u - 1)
        adj_list[u].append(v)
        adj_list[v].append(u)

    for lst in adj_list:
        lst.sort()

    out = []
    for a in range(1, n + 1):
        bits_a = adj_bits[a]
        for b in adj_list[a]:
            if b <= a:
                continue
            common = bits_a & adj_bits[b]
            mask = common >> b          # keep only vertices > b
            if mask:
                low = mask & -mask
                pos = low.bit_length() - 1
                c = b + 1 + pos
                out = [a, b, c]
                sys.stdout.write(f"{a} {b} {c}\n")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
