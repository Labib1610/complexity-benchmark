 We need to find a triangle (three mutually connected nodes) in an undirected graph, and output the lexicographically smallest one.

A straightforward approach:  
- Store edges in an adjacency set for O(1) lookups.  
- Iterate over all triples `(a, b, c)` in increasing order, and check if all three edges exist.  
- Since we want the lexicographically smallest, we can break as soon as we find one.

Given constraints:  
- n up to 2000, m up to 200,000.  
- Checking all triples naively is O(n³) which is too slow for n=2000 (8 billion checks).  

We can optimize:  
- For each `a` from 1 to n, for each `b > a` that is connected to `a`, for each `c > b` that is connected to both `a` and `b`.  
- This is still potentially O(n³) in worst case, but with early exit and adjacency sets, it will be fast enough for typical cases.  
- Since we only need the first triangle in lexicographic order, we can stop early.

Let's implement:

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n + 1)]
for _ in range(m):
    u, v = map(int, input().split())
    adj[u].add(v)
    adj[v].add(u)

for a in range(1, n + 1):
    for b in sorted(adj[a]):
        if b <= a:
            continue
        for c in sorted(adj[b]):
            if c <= b:
                continue
            if c in adj[a]:
                print(a, b, c)
                exit()
```
