**Solution Explanation**

For three chemicals `a < b < c`

* `a` reacts with `b`
* `c` reacts with `a`
* `c` reacts with `b`

All three edges are present – the three vertices form a **triangle**.
The task is therefore:

*find the lexicographically smallest triangle*  
(`a` minimal, then `b`, then `c`).

`n ≤ 2000`, `m ≤ 2·10⁵`.  
`n` is small enough to try every unordered pair `(a,b)` – at most `n·(n‑1)/2 ≈ 2·10⁶` pairs.
For a fixed pair we have to know whether there is a vertex `c > b`
adjacent to **both** `a` and `b`.  
With a bitset representation this test is `O(1)`.



--------------------------------------------------------------------

#### Data structure – bitset adjacency

For every vertex `v` we store an integer `adj[v]` whose binary representation
has a `1` at position `u‑1` (`0`‑based) iff the edge `v‑u` exists.

```
adj[v] : bit i (0‑based) == 1   ⇔   edge (v , i+1) exists
```

`n ≤ 2000`, therefore one Python `int` (unlimited length) is enough
(≈ 2000 bits ≈ 250 bytes).

* building the bitsets: `O(m)`



--------------------------------------------------------------------

#### Searching the smallest triangle

```
for a = 1 … n
    for b = a+1 … n
        if edge (a,b) exists:
            common = adj[a] & adj[b]          # vertices adjacent to both
            # we need c > b, i.e. bits with index ≥ b
            shifted = common >> b              # drop bits ≤ b
            if shifted != 0:
                # lowest set bit gives the smallest possible c
                low = shifted & -shifted
                c = (low.bit_length()) + b      # convert to vertex number
                output a b c and finish
```

* `common` – intersection of neighbours of `a` and `b`.
* `shifted` removes vertices `≤ b`.  
  If it is non‑zero, the least set bit corresponds to the smallest admissible `c`.
* `low.bit_length()` returns the position (1‑based) of that bit inside `shifted`,
  therefore the real vertex number is `b + that_position`.

The outer loops enumerate pairs `(a,b)` in lexicographic order,
and inside we immediately take the smallest possible `c`.  
Consequently the first triangle we encounter is the required answer.

Complexities  

*Time* : `O(n²)` pair loops, each iteration `O(1)` → ≤ 4·10⁶ operations.  
*Memory* : `n` integers → `O(n)` (≈ 0.5 MiB).

Both are far below the limits.



--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

##### Lemma 1  
For any vertices `a < b`, after the test `if edge (a,b) exists`,
`shifted = (adj[a] & adj[b]) >> b` contains a `1` at position `k‑1`
iff vertex `c = b + k` is adjacent to **both** `a` and `b`.

**Proof.**  
`adj[a] & adj[b]` has a `1` exactly at positions of vertices adjacent to both.
Shifting right by `b` removes bits for vertices `1 … b`.  
Thus bit `k‑1` of `shifted` corresponds to vertex `b + k`. ∎



##### Lemma 2  
If `shifted ≠ 0` then `c = b + (low.bit_length())` (where `low = shifted & -shifted`)
is the smallest vertex `c > b` adjacent to both `a` and `b`.

**Proof.**  
`low` isolates the least significant `1` of `shifted`.  
Its position (1‑based) inside `shifted` is `low.bit_length()`.  
All bits of `shifted` with smaller index are zero, therefore no vertex
`b + k` with `k` smaller exists. ∎



##### Lemma 3  
When the algorithm prints a triple `(a,b,c)`, the three edges
`(a,b) , (a,c) , (b,c)` are present, i.e. the triple is a triangle.

**Proof.**  
The algorithm prints only after confirming the edge `(a,b)` exists.
By Lemma&nbsp;1 vertex `c` is adjacent to both `a` and `b`. ∎



##### Lemma 4  
The first printed triple is the lexicographically smallest triangle.

**Proof.**  
Pairs `(a,b)` are examined in increasing `a`, then increasing `b`.
For a fixed pair the algorithm (Lemma&nbsp;2) chooses the smallest possible `c`.
Therefore any triangle with a smaller `a` would have been found earlier,
and with the same `a` but smaller `b` also earlier.
If a triangle has the same `a,b` but smaller `c`, the algorithm would have
chosen that `c`. Hence the first printed triangle is minimal in the
lexicographic order. ∎



##### Theorem  
The algorithm always outputs three integers `a < b < c` that form a triangle,
and this triple is the lexicographically smallest among all such triples.

**Proof.**  
Existence of at least one required triple is guaranteed by the statement,
so some iteration will have `shifted ≠ 0` and the algorithm will print.
By Lemma&nbsp;3 the printed triple is a triangle.
By Lemma&nbsp;4 it is the lexicographically smallest triangle.
∎

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    for a in range(1, n + 1):
        a_mask = adj[a]
        for b in range(a + 1, n + 1):
            if not (a_mask >> (b - 1)) & 1:   # edge (a,b) missing
                continue
            common = a_mask & adj[b]
            shifted = common >> b               # keep only vertices > b
            if shifted:
                low = shifted & -shifted
                c = low.bit_length() + b
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```
