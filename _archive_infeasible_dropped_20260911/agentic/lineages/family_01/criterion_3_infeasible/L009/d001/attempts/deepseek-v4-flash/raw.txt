We can solve this by checking all triples in increasing order and stopping at the first valid one.  
Since \( n \leq 2000 \), checking all triples naively would be \( O(n^3) \), which is too slow.  

Instead, we can use an adjacency matrix (or set) and iterate over pairs, checking for a common neighbor.  
We want the lexicographically smallest triple, so we iterate \( x \) from 1 to \( n \), then \( y \) from \( x+1 \) to \( n \), and check if there is a \( z > y \) that connects to both.  

We can store adjacency as a set for fast lookup.  

Here’s the implementation:  

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for x in range(1, n + 1):
        for y in range(x + 1, n + 1):
            if y in adj[x]:
                # find smallest z > y connected to both x and y
                common = adj[x] & adj[y]
                for z in sorted(common):
                    if z > y:
                        print(x, y, z)
                        return

if __name__ == "__main__":
    main()
```
