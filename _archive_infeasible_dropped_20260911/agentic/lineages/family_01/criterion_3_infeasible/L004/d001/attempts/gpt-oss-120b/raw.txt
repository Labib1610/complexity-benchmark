**Solution Explanation**

For every worker we store the set of workers that are incompatible with him.
A triangle `a < b < c` exists iff  

* `b` is in the incompatibility set of `a`,
* `c` is in the incompatibility set of `a`,
* `c` is in the incompatibility set of `b`.

The required triangle is the lexicographically smallest one, i.e. the smallest
possible `a`, then the smallest possible `b`, then the smallest possible `c`.

--------------------------------------------------------------------

#### 1.   Data structure – bitset

`n ≤ 2000`, therefore a 2000‑bit integer fits easily into a Python `int`.
Bit *i* (0‑based) of the integer belonging to vertex `v` is `1`
iff vertex `i+1` is incompatible with `v`.

```
adj[v]  – integer bitset of neighbours of vertex v (0‑based)
```

All operations we need (`intersection`, `test if an edge exists`,
`find smallest set bit`) are single‑word bit operations and are O(1).

--------------------------------------------------------------------

#### 2.   Searching the lexicographically smallest triangle

```
for a = 0 … n-1:
    for b = a+1 … n-1:
        if edge (a,b) does not exist: continue
        common = adj[a] & adj[b]          # vertices adjacent to both a and b
        # we need c > b, therefore delete bits 0 … b
        common &= ~((1 << (b+1)) - 1)
        if common != 0:
            low = common & -common        # lowest set bit
            c = low.bit_length() - 1      # index of that bit
            output a+1, b+1, c+1 and stop
```

*The loops iterate `a` then `b` in increasing order, and we always pick the
smallest possible `c` (the lowest set bit).  
Consequently the first triangle we encounter is exactly the lexicographically
smallest one.*

The outer loops run at most `n·(n-1)/2 ≤ 2·10⁶` iterations, each iteration does
only a few integer operations – easily fast enough.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triangle.

---

##### Lemma 1  
For any pair of vertices `a < b` the variable `common` after masking contains
exactly the vertices `c` such that `c > b` and edges `(a,c)` and `(b,c)` exist.

**Proof.**  
`adj[a] & adj[b]` is the set of vertices adjacent to **both** `a` and `b`.  
Mask `~((1 << (b+1)) - 1)` has zeros on bits `0 … b` and ones elsewhere,
so `common &= mask` removes all vertices `c ≤ b`. ∎



##### Lemma 2  
If `common` is non‑zero, `low = common & -common` corresponds to the smallest
vertex `c` (i.e. the smallest index) contained in `common`.

**Proof.**  
For a positive integer, `x & -x` isolates its lowest set bit.  
Thus `low` has a single `1` at the position of the smallest index present in
`common`. Converting that bit to an index (`bit_length()-1`) yields that
smallest vertex. ∎



##### Lemma 3  
When the algorithm prints a triple `(a,b,c)`, it is a triangle
(`a<b<c` and all three edges exist).

**Proof.**  
`b` is iterated only if edge `(a,b)` exists (explicit test).  
By Lemma&nbsp;1 every vertex represented in `common` is adjacent to both `a` and
`b` and larger than `b`.  
By Lemma&nbsp;2 `c` is taken from `common`, therefore edges `(a,c)` and `(b,c)`
exist and `c>b`. ∎



##### Lemma 4  
Let `T` be the set of all triangles. The algorithm outputs the triangle with
minimum lexicographic order among `T`.

**Proof.**  
Consider the outer loops. They enumerate all ordered pairs `(a,b)` with
`a<b` in lexicographic order.  
For a fixed `(a,b)` the algorithm, if possible, outputs the smallest feasible
`c` (Lemma&nbsp;2).  
Hence the first printed triangle is the one with the smallest `(a,b)` for which
any triangle exists, and among those the smallest `c`.  
That is exactly the lexicographically smallest triangle in `T`. ∎



##### Theorem  
The algorithm always terminates and prints three integers `a<b<c` forming a
triangle, and this triangle is the lexicographically smallest among all
triangles in the given graph.

**Proof.**  
The input guarantees at least one triangle, therefore some iteration will have
`common ≠ 0` and the algorithm will print and stop.  
Termination follows because the loops are finite.  
Correctness of the printed triple follows from Lemma&nbsp;3, and its
lexicographic minimality from Lemma&nbsp;4. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets*: `O(m)`  
*Main loops*: at most `n·(n-1)/2 ≤ 2·10⁶` iterations, each does a constant‑time
bitwise `&`, a mask, and a few integer operations → `O(n²)` time.  

Memory: `n` integers, each ≤ `2ⁿ` → `O(n)` bits ≈ `2000·2000 / 8 ≈ 0.5 MB`.

Both limits satisfy the problem constraints.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n          # bitset for each vertex, 0‑based
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(n):
        mask_a = adj[a]
        for b in range(a + 1, n):
            # edge (a,b) ?
            if not (mask_a >> b) & 1:
                continue
            common = mask_a & adj[b]
            # keep only vertices > b
            common &= ~((1 << (b + 1)) - 1)
            if common:
                low = common & -common
                c = low.bit_length() - 1
                # output 1‑based and ordered
                sys.stdout.write(f"{a+1} {b+1} {c+1}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
