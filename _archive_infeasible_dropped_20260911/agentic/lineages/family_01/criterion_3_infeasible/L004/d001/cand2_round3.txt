<STATEMENT>
# Problem C — Proof of Impossibility

Time limit: 2 s   Memory limit: 256 MB

The factory's automated rostering system operates in three stages. In the first stage, it gathers pairwise scheduling conflicts into a centralized database. The factory employs a number of workers, each assigned a sequential integer ID starting from 1. The maximum possible headcount is strictly capped at two thousand workers, though the factory must have a minimum of three to operate.

The database records these conflicts. Due to storage constraints, the system can hold a maximum of two hundred thousand conflict records, and naturally will not hold more than the maximum possible number of unique pairs among the current headcount. A minimum of three conflict records is required to trigger the second stage.

In the second stage—which is the component you must implement—the system must process a roster that is already known to be hopeless. The factory has only two shifts, 1 and 2. Your job is not to assign shifts; rather, it is to generate a certificate of impossibility to pass to the third stage. The third stage will then consume this certificate to automatically trigger an expansion request for a third shift.

To construct the certificate, you must process the raw conflict records into directed dependencies. For any given conflicting pair, a dependency arc must be formed pointing from the worker with the smaller ID to the worker with the larger ID. 

A valid certificate of impossibility consists of exactly three distinct workers $a$, $b$, and $c$, strictly ordered such that $a < b < c$, where the dependencies $a \to b$, $a \to c$, and $b \to c$ all exist. 

You must output the IDs of the three workers forming this certificate. If multiple valid certificates exist, you must output the one that is lexicographically smallest (smallest $a$; ties broken by smallest $b$; then smallest $c$).

### Input
The first line contains two integers: the current headcount and the total number of conflict records.
Each of the subsequent lines contains two integers $u$ and $v$ — a conflicting pair.
It is guaranteed that at least one valid certificate exists.

### Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$ such that the dependencies $a \to b$, $a \to c$, and $b \to c$ are all present. Output the lexicographically smallest such certificate (smallest $a$; ties broken by smallest $b$; then smallest $c$).

### Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

### Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

The rewrite shifts the presentation of the conflicts from implied undirected pairs to explicitly normalized directed dependencies, requiring the model to reason about the directed structure rather than blindly applying an undirected graph template. Additionally, all numeric bounds for variables $n$ and $m$ have been removed from the input section and are instead stated indirectly as physical and storage limits in the descriptive text, fulfilling strategy S07.
</RATIONALE>
<PRESERVED_ANSWER>
Because any undirected triangle inherently has exactly three vertices that can be ordered strictly as $a < b < c$, and the dependency arcs are explicitly defined to point from smaller to larger IDs, the set of valid certificates exactly matches the set of undirected triangles from the seed problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core computational task remains finding a 3-chromatic substructure (a triangle) in an unweighted graph, keeping the time complexity and certificate-style structure perfectly intact.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "dependency arc" as implying they need to run a topological sort or cycle detection, but the explicit definition of the required $a \to b$, $a \to c$, $b \to c$ structure resolves this for careful readers.
</RISK>
