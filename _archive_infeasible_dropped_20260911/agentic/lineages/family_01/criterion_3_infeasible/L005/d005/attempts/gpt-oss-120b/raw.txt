**Solution Explanation**

For a triple `{a,b,c}` let  

* `L_x` – degree of vertex `x` (number of logs containing `x`);
* `e` – number of logs whose both ends are inside the triple  
  (`e = 0 … 3`);
* `Y` – number of logs with exactly one end in the triple;
* `X` – number of logs with none of the three vertices.

```
L_a + L_b + L_c = 2·e + Y                (each internal edge counted twice)
m                = e + Y + X
```

The required condition is  

```
L_a + L_b + L_c + X = m + 3
```

Insert the two equalities:

```
2·e + Y + X = (e + Y + X) + 3   →   e = 3
```

So the three vertices must be **pairwise connected**, i.e. they form a
triangle.  
The task is therefore:

*find the lexicographically smallest triangle in the given undirected
graph*.

--------------------------------------------------------------------

#### 1.   Data structure – bitsets

`n ≤ 2000`, therefore a 2000‑bit bitset fits into a Python integer.
For every vertex `v` we store

```
mask[v] = bitset of neighbours w with w > v
```

Only neighbours with larger index are stored – this guarantees the
ordering `a < b < c` automatically.

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle

We iterate `a = 1 … n`.  
For the current `a` we enumerate all `b` that are neighbours of `a`
(`b > a`) in increasing order.
For a fixed pair `(a,b)` the vertices that are neighbours of **both**
`a` and `b` and larger than `b` are exactly

```
common = mask[a] & mask[b]
```

If `common` is non‑zero, its least significant set bit gives the smallest
possible `c`.  
The first triple we encounter while iterating `a` then `b` is the
lexicographically smallest triangle, and we can output it immediately.

All operations are bitwise on Python integers – extremely fast.
The total work is `O( Σ deg(v) ) = O(m)` for enumerating the `b`s and a
constant‑time bitwise `AND` for each pair.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest
triangle.

---

##### Lemma 1  
For any vertices `a < b`, `common = mask[a] & mask[b]` contains exactly
the vertices `c` such that `a<b<c` and edges `(a,c)` and `(b,c)` exist.

**Proof.**  
`mask[a]` contains all neighbours of `a` larger than `a`; similarly for
`mask[b]`. Their intersection therefore contains precisely those vertices
that are neighbours of both `a` and `b` and are larger than both, i.e.
larger than `b`. ∎



##### Lemma 2  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The algorithm outputs a triple only when `common` is non‑empty.
By Lemma&nbsp;1 every `c` in `common` is adjacent to both `a` and `b`.
The outer loop guarantees that edge `(a,b)` exists (otherwise `b` would
not be enumerated). Hence all three edges are present – a triangle. ∎



##### Lemma 3  
Let `T` be the set of all triangles. The algorithm outputs the triangle
with the smallest lexicographic order.

**Proof.**  
Consider the nested loops:

* outer loop processes `a` in increasing order;
* for a fixed `a`, inner enumeration processes `b` in increasing order;
* for a fixed pair `(a,b)`, the least set bit of `common` yields the
  smallest possible `c`.

Therefore the algorithm examines triangles in exactly the lexicographic
order of their vertex triples. The first triangle encountered is the
lexicographically smallest one. ∎



##### Lemma 4  
The input is guaranteed to contain at least one triangle, so the
algorithm will find one.

**Proof.**  
The statement of the problem guarantees existence of a triple satisfying
the original condition, which we proved is equivalent to being a
triangle. Hence at least one triangle exists, and the loops will eventually
reach it. ∎



##### Theorem  
The algorithm always prints three integers `a<b<c` that form a triangle
and are lexicographically minimal among all such triples.

**Proof.**  
By Lemma&nbsp;4 a triangle exists. The algorithm scans all possible
pairs `(a,b)` and, by Lemma&nbsp;1, correctly detects all candidate `c`s.
When it outputs a triple, Lemma&nbsp;2 ensures it is a triangle.
By Lemma&nbsp;3 the first output triangle is the lexicographically
smallest one. Hence the printed triple satisfies all requirements. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building masks*: `O(m)` time, `O(n)` integers (≈ 2000 bits each) → `O(n)` memory.  
*Search*: each edge `(a,b)` with `a<b` is examined once, constant work per
edge → `O(m)` time.  

Overall  

```
Time   :  O(m)   ≤ 2·10^5   (well below 2 s)
Memory :  O(n)   ≤ 2000 integers  (negligible)
```

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    # mask[v]: bitset of neighbours w with w > v
    mask = [0] * (n + 1)

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u > v:
            u, v = v, u
        # now u < v
        mask[u] |= 1 << v

    for a in range(1, n + 1):
        bits = mask[a]
        while bits:
            lsb = bits & -bits
            b = lsb.bit_length() - 1   # neighbour > a
            bits ^= lsb

            common = mask[a] & mask[b]   # vertices > b adjacent to both
            if common:
                lsb2 = common & -common
                c = lsb2.bit_length() - 1
                # a < b < c automatically
                print(a, b, c)
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
