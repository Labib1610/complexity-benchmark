We can solve this by iterating over all triples and checking the condition efficiently.  
Since \( n \leq 2000 \), checking all triples directly is \( O(n^3) \) which is too slow.  

Instead, we can use the fact that the condition can be rewritten.  
For a triple \((a,b,c)\):

\[
\text{edges involving at least one of them} = D_a + D_b + D_c - 3
\]

Let’s denote:
- \( e_{ab} \) = 1 if edge between a and b, else 0.
- The number of edges involving at least one of a,b,c is:
  \[
  D_a + D_b + D_c - (e_{ab} + e_{ac} + e_{bc})
  \]
  because edges inside the triple are counted twice in the sum of degrees.

So the condition becomes:
\[
D_a + D_b + D_c - (e_{ab} + e_{ac} + e_{bc}) = D_a + D_b + D_c - 3
\]
which simplifies to:
\[
e_{ab} + e_{ac} + e_{bc} = 3
\]
That means the triple must form a triangle.

So the problem reduces to: find the lexicographically smallest triangle in the graph.

We can do this by:
- Storing adjacency as a set for O(1) edge checks.
- Iterating over all pairs (a,b) with a < b, and for each, checking c > b such that edges (a,c) and (b,c) exist.

Complexity: \( O(n^2) \) pairs, each check O(1) with sets, so \( O(n^2) \) total, which is fine for \( n \leq 2000 \).

Here’s the implementation:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(n):
        for b in range(a+1, n):
            if b not in adj[a]:
                continue
            for c in range(b+1, n):
                if c in adj[a] and c in adj[b]:
                    print(a+1, b+1, c+1)
                    return

if __name__ == "__main__":
    solve()
```
