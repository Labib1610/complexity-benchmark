<METHOD_NAME>Set-Theoretic Filtering Trap</METHOD_NAME>
<METHOD_DESCRIPTION>Rephrases the explicit mutual-edge condition of a clique as a set-theoretic filter counting operation. Models that pattern-match will literally implement the filter over all subsets of size 3, resulting in an O(n^3) or worse algorithm that exceeds the time limit. Models that genuinely reason about algorithmic structure will deduce that a 3-vertex subset containing exactly 3 edges is simply a triangle, and will correctly implement an efficient O(m * degree) or bitset-based search.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem C — Justifying the Roster Failure

Time limit: 2 s
Memory limit: 256 MB

The management wants to assign all personnel to two distinct working periods. They have collected a list of incompatibility logs, each indicating that two specific individuals are in conflict and cannot share a working period. 

However, management will only formally declare the two-period assignment impossible if they can pinpoint a specific failing group. They require a group of exactly three individuals $\{a, b, c\}$ that certifies this impossibility.

A candidate subset of exactly three distinct individuals $T = \{a, b, c\}$ is considered a certifying group if it satisfies the following density condition: when the provided incompatibility logs are filtered to keep only those logs where both individuals belong to $T$, exactly three logs remain.

The management guarantees that the provided records contain at least one such group of three individuals. Your task is to identify one such group.

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n(n-1)/2, 2 \cdot 10^5)$), representing the number of personnel and the total number of incompatibility logs, respectively. Personnel are numbered from 1 to $n$.

Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), indicating an incompatibility log involving individual $u$ and individual $v$. All logs are distinct (no pair of individuals is listed more than once).

It is guaranteed that at least one such group of three individuals exists.

## Output
Print three integers $a$, $b$, and $c$ on a single line, satisfying $a < b < c$, representing the three individuals in the group.

If there are multiple such groups, output the one that comes first lexicographically (minimize $a$; in case of a tie, minimize $b$; and finally minimize $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I replaced the explicit mutual conflict condition ("a and b, a and c, b and c are in conflict") with a set-theoretic filter ("when logs are filtered to keep only those where both individuals are in T, exactly 3 remain"). This forces the model to deduce that a 3-element subset with exactly 3 edges is a triangle. Models that rely on surface pattern matching will implement the filter literally in O(n^3) or O(n^3 * m) and fail by Time Limit Exceeded, while models that reason about the structure will recognize the triangle property and use efficient edge iteration or bitset intersections.
</RATIONALE>
<PRESERVED_ANSWER>
Because the input contains no duplicate logs, the maximum possible number of logs strictly within any 3-person subset is 3; therefore, requiring exactly 3 logs to remain is mathematically identical to requiring all three pairs to be present.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the detection of a triangle (K3) in an undirected graph, which is solvable in polynomial time using adjacency bitsets or by intersecting neighbor lists.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "both individuals belong to T" as applying to the entire set of logs collectively rather than evaluating each log individually, though the phrasing "keep only those logs where..." strongly implies a per-log filter.
</RISK>
