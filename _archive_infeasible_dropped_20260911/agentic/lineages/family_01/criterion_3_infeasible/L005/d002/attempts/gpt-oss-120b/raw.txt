**Solution Explanation**

For three persons `a<b<c` we have to decide whether *every* 2‑colouring of the three
places forces a monochromatic edge that is present in the given list.
For three vertices this happens **iff** the three edges  
`(a,b) , (a,c) , (b,c)` are all present – i.e. the three vertices form a
*triangle* in the graph.

So the task is:

*find the lexicographically smallest triangle in an undirected simple graph*.

--------------------------------------------------------------------

#### 1.   Data structure – bitsets

`n ≤ 2000`, therefore a 2000‑bit bitset fits into a single Python integer.
For every vertex `v` we store

```
adj[v]  – integer whose i‑th bit (0‑based) is 1  ⇔  edge (v, i+1) exists
```

All vertices are numbered from `1`, we keep the bit for vertex `x`
at position `x‑1`.

With bitsets we can intersect neighbour sets of two vertices in O(1)
machine operations.

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle

We iterate `a` from `1` to `n`.
For each `a` we iterate `b` from `a+1` to `n` **only if the edge (a,b) exists**.
The common neighbours of `a` and `b` are

```
common = adj[a] & adj[b]          # integer
```

A vertex `c` that together with `a,b` forms a triangle must satisfy `c>b`,
otherwise the triple would have been examined earlier.
Therefore we discard bits `≤ b`:

```
mask = common >> b                 # shift removes bits 0 … b‑1
```

If `mask` is non‑zero, the least set bit gives the smallest possible `c`
(`c = b + 1 + index_of_lowest_bit`).  
Because we scan `a` increasingly, then `b` increasingly, the first triangle
found is exactly the lexicographically smallest one.

The index of the lowest set bit of a positive integer `x` can be obtained by

```
low = (x & -x).bit_length() - 1
```

(the expression `x & -x` isolates the lowest set bit).

When a triangle is found we output it and terminate.

The algorithm runs in  

* `O(n²)` iterations of the outer loops (`n ≤ 2000` → at most 2 000 000),
* each iteration does only a few integer operations,
* memory consumption `O(n)` integers (≈ 2000·256 B).

Both limits are far below the given constraints.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest
triangle.

---

##### Lemma 1  
A set `{a,b,c}` with `a<b<c` is a failing subset (as defined in the statement)
iff the three edges `(a,b) , (a,c) , (b,c)` are all present in the input graph.

**Proof.**  
If the three edges are present, the induced subgraph is a triangle, which is
not bipartite, i.e. it cannot be 2‑coloured without a monochromatic edge.
Conversely, if at least one of the three edges is missing, colour the two
endpoints of the missing edge with different colours and the third vertex
arbitrarily – then no monochromatic edge exists. ∎



##### Lemma 2  
When the algorithm examines a pair `(a,b)` (`a<b`) it finds the smallest
`c>b` such that `{a,b,c}` is a triangle, if any exists.

**Proof.**  
`common = adj[a] & adj[b]` contains exactly the vertices adjacent to **both**
`a` and `b`. After shifting right by `b`, the lowest set bit of `mask`
corresponds to the smallest vertex index `c` with `c>b` that belongs to
`common`. Hence the algorithm returns the smallest possible `c`. ∎



##### Lemma 3  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The algorithm outputs a triple only after confirming that the edge `(a,b)`
exists (the inner loop iterates only over neighbours of `a`) and that
`c` is taken from `common = adj[a] & adj[b]`. By definition of `common`,
both edges `(a,c)` and `(b,c)` exist. Thus all three edges are present. ∎



##### Lemma 4  
The first triangle found by the algorithm is the lexicographically smallest
triangle in the whole graph.

**Proof.**  
The outer loop enumerates `a` in increasing order.
For a fixed `a`, the inner loop enumerates `b` in increasing order among
neighbours of `a` that are larger than `a`.  
By Lemma&nbsp;2, for this pair the algorithm obtains the smallest possible
`c>b`. Therefore triples are examined in the exact order of increasing
lexicographic tuple `(a,b,c)`. The first one that satisfies the triangle
condition (Lemma&nbsp;3) is consequently the minimal one. ∎



##### Theorem  
The algorithm always prints three integers `a<b<c` that form a failing
subset, and among all such subsets it prints the lexicographically smallest
one.

**Proof.**  
Existence: the statement guarantees at least one failing subset, i.e. at
least one triangle. The algorithm scans all pairs `(a,b)` and for each pair
checks all possible `c`; therefore it will eventually encounter a triangle
and output it.

Correctness of the output: by Lemma&nbsp;3 the printed triple is a triangle,
hence a failing subset by Lemma&nbsp;1.

Minimality: by Lemma&nbsp;4 the first triangle found is the lexicographically
smallest triangle, and the algorithm stops exactly at that moment. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Time*  
The double loop runs over all ordered pairs `a<b`. In the worst case (`m`
≈ `n(n-1)/2`) this is `n(n-1)/2 ≤ 2·10⁶` iterations.
Each iteration performs a constant number of integer bit operations,
so the total running time is `O(n²)` ≤ `2·10⁶` operations, well inside 2 s.

*Memory*  
`adj` stores `n` integers, each using at most `n` bits → `O(n)` memory,
≈ 2000 · 256 B ≈ 0.5 MiB, far below the limit.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based, bit i‑1 corresponds to vertex i
    edges = []                  # list of (u,v) with u<v for iteration

    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        if u > v:
            u, v = v, u
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)
        edges.append((u, v))

    # For fast neighbour iteration per a, build list of neighbours > a
    neigh = [[] for _ in range(n + 1)]
    for u, v in edges:
        neigh[u].append(v)
        neigh[v].append(u)

    for a in range(1, n + 1):
        # consider neighbours b > a
        for b in neigh[a]:
            if b <= a:
                continue
            # common neighbours of a and b
            common = adj[a] & adj[b]
            # discard vertices <= b
            mask = common >> b
            if mask:
                # lowest set bit
                low = (mask & -mask).bit_length() - 1
                c = b + 1 + low
                # we have a<b<c and triangle exists
                print(a, b, c)
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
