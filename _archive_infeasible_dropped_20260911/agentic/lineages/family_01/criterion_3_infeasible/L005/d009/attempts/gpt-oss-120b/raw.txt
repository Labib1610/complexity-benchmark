**Solution Explanation**

For three edges `e1 , e2 , e3` write down all their six endpoints.
The required parity condition says that every vertex occurs an **even**
number of times.
With three edges the total number of occurrences is `6`, therefore each
vertex can appear `0 , 2` or `4` times.
A vertex cannot appear `4` times (it would have to be incident to four
different edges) and it cannot appear `6` times.
Consequently the only possible distribution is

```
exactly three different vertices, each of them appears twice
```

i.e. the three edges are the three sides of a triangle.

So the whole problem is:

> *find the lexicographically smallest triangle (a<b<c) in the given
> undirected simple graph.*  
> At least one triangle is guaranteed to exist.



--------------------------------------------------------------------

#### 1.   Data representation  

`n ≤ 2000`, therefore a vertex adjacency list can be stored as a bitset
inside a single Python integer (`int` has arbitrary length).

```
adj[v]  – integer, bit i is 1  ⇔  edge (v,i) exists
nbr[v]  – normal list of neighbours, kept sorted
```

All edges are inserted in `O(1)` time.

--------------------------------------------------------------------

#### 2.   Searching the smallest triangle  

We iterate over the smallest vertex `a` of the triangle,
then over the second smallest vertex `b`,
and finally we look for the smallest possible third vertex `c`.

```
for a = 0 … n-1
        for every neighbour b of a with b > a   (in increasing order)
                common = adj[a] & adj[b]          # vertices adjacent to both
                # we need a vertex c > b
                mask = common >> (b+1)            # delete bits ≤ b
                if mask != 0 :                    # at least one candidate
                        low = mask & -mask        # lowest set bit
                        offset = low.bit_length() - 1
                        c = b + 1 + offset
                        answer = (a+1,b+1,c+1)    # back to 1‑based numbering
                        print and stop
```

*Why does this give the lexicographically smallest triangle?*

* the outer loop fixes the smallest vertex `a`.  
  The first `a` for which a triangle exists is the minimal possible `a`.
* for this `a` the inner loop checks neighbours `b` in increasing order,
  therefore the first `b` that participates in a triangle is the minimal
  possible `b` for this `a`.
* for a fixed `(a,b)` we take the smallest `c > b` that is adjacent to both,
  i.e. the minimal possible `c`.

Thus the first triple we output is exactly the lexicographically smallest
`(a,b,c)`.

All operations inside the loops are bitwise integer operations on
~2000‑bit numbers – they are performed in constant (very small) time.
The whole algorithm works in `O(m)` time, `m ≤ 2·10⁵`,
and uses `O(n)` additional memory.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm always prints the required triple.

---

##### Lemma 1  
A set of three edges satisfies the parity condition *iff* the three
edges form a triangle.

**Proof.**  
Each edge contributes `1` to the parity count of each of its two
endpoints, therefore the total number of endpoint occurrences is `6`.
All vertices must appear an even number of times, consequently each
vertex appears `0` or `2` times.  
With three edges a vertex can be incident to at most three edges, hence
the only possible distribution is *three* vertices, each incident to
*exactly two* edges. The only graph with three edges and three vertices of
degree `2` is a triangle. ∎



##### Lemma 2  
When the algorithm reaches a pair of vertices `(a,b)` (`a<b`) that belong
to at least one triangle, it outputs the triangle whose third vertex `c`
is the smallest possible among all triangles containing `(a,b)`.

**Proof.**  
`common = adj[a] & adj[b]` is exactly the set of vertices adjacent to both
`a` and `b`.  
`mask = common >> (b+1)` removes all vertices `≤ b`.  
If `mask ≠ 0`, its least significant set bit corresponds (after shifting back)
to the smallest vertex `c > b` that is adjacent to both `a` and `b`.  
Consequently the algorithm outputs the triangle `(a,b,c)` with minimal `c`. ∎



##### Lemma 3  
Let `T = (a₀,b₀,c₀)` be the lexicographically smallest triangle in the
graph (`a₀<b₀<c₀`).  
The algorithm will output `T`.

**Proof.**  
Consider the outermost loop.  
All vertices `< a₀` cannot be the smallest vertex of any triangle,
otherwise that triangle would be lexicographically smaller than `T`.  
Hence when the algorithm reaches `a = a₀` the first triangle it can meet
has smallest vertex `a₀`.

Inside this iteration, neighbours `b` are examined in increasing order.
Any neighbour `b < b₀` together with `a₀` cannot belong to a triangle,
otherwise the triangle `(a₀,b,…)` would be lexicographically smaller than `T`.
Thus the first neighbour examined that participates in a triangle is
`b = b₀`.

By Lemma&nbsp;2 the algorithm now returns the triangle with the smallest
possible third vertex `c`.  
All triangles with vertices `(a₀,b₀,⋯)` have `c ≥ c₀`, and the triangle
with `c = c₀` exists (it is `T`).  
Therefore the algorithm outputs `(a₀,b₀,c₀) = T`. ∎



##### Lemma 4  
If the algorithm prints a triple `(a,b,c)` then `(a,b,c)` is a triangle.

**Proof.**  
The algorithm prints only after it has found a vertex `c` that belongs to
`common = adj[a] & adj[b]`.  
Thus edges `(a,b)`, `(a,c)` and `(b,c)` all exist, i.e. the three vertices
form a triangle. ∎



##### Theorem  
The algorithm always terminates and prints the lexicographically smallest
triple of distinct vertices that satisfies the required parity condition.

**Proof.**  
Termination: the outer loops iterate over finitely many vertices and
edges, and inside they perform only constant‑time operations.  

Existence of output: the statement guarantees at least one triangle,
hence there exists at least one pair `(a,b)` for which `common` contains a
vertex `c>b`. The algorithm will eventually encounter such a pair and will
print a triangle (Lemma&nbsp;4).

By Lemma&nbsp;3 the printed triangle is the lexicographically smallest
triangle, and by Lemma&nbsp;1 this triangle is exactly a set of three
edges obeying the parity condition. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency structures* : `O(m)` time, `O(n)` memory.  
*Main loops*                       : each edge `(a,b)` is examined once,
                                     all operations are bitwise on at most
                                     2000‑bit integers → `O(1)`.  
Total time                         : `O(m) ≤ 2·10⁵`.  
Memory usage                       : adjacency bitsets (`n` integers)  
                                     + neighbour lists (`2m` integers) → `O(n+m)`.

Both limits satisfy the required limits easily.

--------------------------------------------------------------------

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * n                # bitsets
    nbr = [[] for _ in range(n)]  # neighbour lists

    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u
        nbr[u].append(v)
        nbr[v].append(u)

    for lst in nbr:
        lst.sort()

    for a in range(n):
        for b in nbr[a]:
            if b <= a:
                continue
            common = adj[a] & adj[b]
            # keep only vertices with index > b
            mask = common >> (b + 1)
            if mask:
                low = mask & -mask                 # lowest set bit
                offset = low.bit_length() - 1
                c = b + 1 + offset
                # output 1‑based indices
                sys.stdout.write(f"{a+1} {b+1} {c+1}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
