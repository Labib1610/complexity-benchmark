<METHOD_NAME>Permutation-Based Pairwise Coverage</METHOD_NAME>
<METHOD_DESCRIPTION>Instead of defining a clique by stating that all items must be mutually connected, this method requires a property to hold across all permutations of the subset. By stating that the first two elements of every permutation must be connected, it logically enforces that all pairs are connected, but masks this behind sequence-validation terminology. Models relying on pattern-matching will fail to recognize the triangle-finding problem and either implement a naive O(n^3) permutation check that times out, or fail to apply the necessary bitset intersection optimization.</METHOD_DESCRIPTION>

<STATEMENT>
# Processor Instruction Scheduling

## Time and Memory Limits
Time limit: 2 s
Memory limit: 256 MB

## Description
A modern CPU architecture supports $n$ distinct instruction types, numbered $1$ to $n$. During hardware validation, engineers identified $m$ unordered pairs of instructions that can be safely "pipelined" (executed back-to-back without stalling).

To certify a specific optimization module, you must find a "Pipelined Trio". A Pipelined Trio is a set of exactly three distinct instruction types that is completely robust to reordering. 

Specifically, a set of three distinct instruction types is a Pipelined Trio if and only if it satisfies the following condition:
For all 6 possible ways to arrange these three instruction types into a linear sequence, the first instruction in that specific sequence can be safely pipelined with the second instruction in that sequence.

You must systematically evaluate the pipelining data to find a Pipelined Trio. If there are multiple valid Pipelined Trios, you must report the trio whose instruction numbers form the lexicographically smallest sequence when sorted in ascending order. (A sequence $a_1 < b_1 < c_1$ is lexicographically smaller than $a_2 < b_2 < c_2$ if $a_1 < a_2$; or if $a_1 = a_2$ and $b_1 < b_2$; or if $a_1 = a_2$ and $b_1 = b_2$ and $c_1 < c_2$).

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n \cdot (n-1)/2, 2\cdot 10^5)$), indicating the total number of instruction types and the total number of pipelined pairs.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing that instruction type $u$ and instruction type $v$ can be pipelined. This relationship is symmetric. It is guaranteed that at least one Pipelined Trio exists.

## Output
Output a single line containing three integers $a$, $b$, and $c$, ordered such that $a < b < c$, representing the instruction numbers in the chosen Pipelined Trio. Among all valid Pipelined Trios, output the lexicographically smallest one (smallest $a$; if tied, smallest $b$; if tied, smallest $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I completely reframed the scenario from committee vetoes to CPU instruction pipelining. Crucially, I replaced the direct indicator sum with a permutation-based requirement: for all 6 sequences of the three instructions, the first can be pipelined with the second. This forces the model to logically deduce that this condition is equivalent to a triangle (a 3-clique); models that fail to make this deduction and write literal translations will TLE on the $O(n^3)$ permutations.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that the first two elements of all 6 permutations of a 3-element set must be connected perfectly covers all 3 possible pairs, making the valid sets mathematically identical to the deadlocked trios in the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to finding a lexicographically smallest 3-clique (triangle) in an undirected graph, preserving its INFEASIBLE complexity class.
</PRESERVED_CLASS>
<RISK>
A reader might wonder if the sequence check implies that the second and third instructions must also be pipelined, though the text explicitly restricts the condition to "the first instruction... with the second instruction".
</RISK>
