**Solution Explanation**

For the given undirected graph we have to output three different vertices  
`a < b < c` which form a triangle (three pairwise adjacent vertices).  
If several triangles exist we output the lexicographically smallest one,
i.e. the one with the smallest possible `a`; if several have the same `a`,
the one with the smallest `b`, and finally the smallest `c`.

The constraints are  

* `n ≤ 2000`
* `m ≤ 200 000`

so an `O(n·m)` algorithm is far too slow, but an `O(m·√m)` or
`O(m·log n)` algorithm easily fits into the limits.



--------------------------------------------------------------------

#### 1.  Ordering vertices by degree  

For every vertex we store its adjacency list.
To speed up the triangle search we orient every undirected edge
`u – v` from the vertex with **smaller degree** to the vertex with
larger degree (ties are broken by the vertex number).
The oriented graph is a *directed acyclic* graph – every directed edge
goes from a “smaller” vertex to a “larger” one.

Why is this useful?
If we look for a triangle `x – y – z – x`,
at least one of its three edges is oriented from the smallest
vertex (according to the ordering) to a larger one.
Consequently, for every vertex `x` we only have to consider its **outgoing**
neighbours – the number of outgoing edges of a vertex is at most
`√(2m)` (standard property of this orientation).

--------------------------------------------------------------------

#### 2.  Finding the smallest triangle  

We iterate `a` from `1` to `n` (the required lexicographic order).

For the current `a`

```
for each b in out[a]:
        mark b as reachable from a
for each b in out[a]:
        for each c in out[b]:
                if c is marked:
                        triangle (a,b,c) found
```

The first triangle discovered in this way is automatically the
lexicographically smallest one, because

* `a` grows increasingly,
* for a fixed `a` the inner loops enumerate `b` and `c` in increasing order
  (the adjacency lists are stored sorted).

The total work is  

```
 Σ  out-degree(a)          (first loop)   +
 Σ  out-degree(a)·out-degree(b)   (second nested loops)
```

which is `O(m·√m)` and well below the limits for `n ≤ 2000`.

--------------------------------------------------------------------

#### 3.  Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

##### Lemma 1  
For every vertex `v` the number of outgoing edges `|out[v]|` is at most
`√(2m)`.

**Proof.**  
If `deg(v) ≤ √(2m)` then all its edges are outgoing, so `|out[v]| ≤ √(2m)`.  
Otherwise `deg(v) > √(2m)`. An edge `v – u` is outgoing from `v`
only if `deg(v) < deg(u)` or (`deg(v) = deg(u)` and `v < u`).
Thus every outgoing neighbour `u` has degree at least `deg(v) > √(2m)`.
There are at most `2m / √(2m) = √(2m)` such vertices, otherwise the sum of
their degrees would exceed `2m`. ∎



##### Lemma 2  
If a triangle `{x,y,z}` exists, then during the iteration with `a = min(x,y,z)`
the algorithm will discover this triangle.

**Proof.**  
Let `a = min(x,y,z)`. Because of the orientation rule,
all edges incident to `a` are oriented **outward** from `a`
(because the other two vertices have degree ≥ `deg(a)` and larger index
if degrees are equal). Hence `b` and `c` (the other two vertices of the
triangle) belong to `out[a]`.

When the algorithm processes `a`, it marks all vertices of `out[a]`,
therefore both `b` and `c` become marked.
Later it iterates over each `b ∈ out[a]` and over each `c ∈ out[b]`.
Since the edge `b – c` belongs to the triangle, it is oriented either
`b → c` or `c → b`. In the first case `c ∈ out[b]` and the algorithm
detects the triangle; in the second case the symmetric situation
(`b ∈ out[c]`) will be examined when the outer loop reaches `b`,
still inside the same outer iteration for `a`. Thus the triangle is found
while processing `a`. ∎



##### Lemma 3  
The first triangle reported by the algorithm is the lexicographically
smallest triangle of the graph.

**Proof.**  
The outer loop examines vertices `a` in increasing order.
By Lemma&nbsp;2 any triangle whose smallest vertex equals the current `a`
will be found before the algorithm proceeds to a larger `a`.
Consequently no triangle with a smaller first element can be missed.

Assume several triangles share the same smallest vertex `a`.
Inside the processing of `a` the algorithm iterates `b` over the sorted
list `out[a]`. Hence the first examined `b` is the smallest possible
second vertex of any triangle with this `a`.  
For this fixed `b` the inner loop iterates `c` over the sorted list
`out[b]`; the first `c` that is also marked is the smallest possible third
vertex. Therefore the first triangle discovered for this `a` has the
minimal possible `(b,c)` pair, i.e. it is lexicographically minimal among
all triangles whose smallest vertex is `a`.

Combining the two arguments, the very first triangle output by the
algorithm is the globally lexicographically smallest triangle. ∎



##### Lemma 4  
If the algorithm outputs a triple `(a,b,c)`, then `{a,b,c}` is a triangle.

**Proof.**  
The algorithm outputs a triple only when it finds a vertex `c`
that is marked (meaning `c ∈ out[a]`) **and** also belongs to `out[b]`.
Thus edges `a–b`, `a–c`, and `b–c` all exist in the original undirected
graph, i.e. the three vertices form a triangle. ∎



##### Theorem  
The algorithm always terminates and prints the lexicographically smallest
triangle of the given graph.

**Proof.**  
Termination follows because the loops iterate over finite adjacency lists.
By Lemma&nbsp;4 any printed triple is a triangle.
By Lemma&nbsp;3 the first printed triangle is the lexicographically smallest
one. The problem statement guarantees at least one triangle, therefore the
algorithm will indeed print a triple before finishing. ∎



--------------------------------------------------------------------

#### 4.  Complexity Analysis  

*Building the orientation* – `O(m)` time, `O(n+m)` memory.  
*Triangle search* – `O(m·√m)` time (Lemma&nbsp;1) and `O(n)` extra memory for
the temporary marking array.  
With `n ≤ 2000` and `m ≤ 200 000` this easily satisfies the limits
(≈ 9·10⁶ elementary operations in the worst case).

--------------------------------------------------------------------

#### 5.  Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    deg = [0] * (n + 1)
    edges = []
    for _ in range(m):
        u = int(next(it)); v = int(next(it))
        deg[u] += 1
        deg[v] += 1
        edges.append((u, v))

    # orient edges from smaller (deg, id) to larger
    out = [[] for _ in range(n + 1)]
    for u, v in edges:
        if deg[u] < deg[v] or (deg[u] == deg[v] and u < v):
            out[u].append(v)
        else:
            out[v].append(u)

    # sort adjacency lists to guarantee lexicographic order
    for lst in out:
        lst.sort()

    marked = [0] * (n + 1)
    cur_mark = 1

    for a in range(1, n + 1):
        # mark all out-neighbours of a
        for b in out[a]:
            marked[b] = cur_mark

        for b in out[a]:
            for c in out[b]:
                if marked[c] == cur_mark:
                    # triangle found, output sorted
                    tri = sorted((a, b, c))
                    print(tri[0], tri[1], tri[2])
                    return
        cur_mark += 1   # reuse array without clearing

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
