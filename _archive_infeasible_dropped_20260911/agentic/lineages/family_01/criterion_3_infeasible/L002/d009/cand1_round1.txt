<STATEMENT>
# Committee Deadlock Resolution

## Time and Memory Limits
Time limit: 2 s
Memory limit: 256 MB

## Description
A selection panel is evaluating a roster of candidates, numbered $1$ to $n$. During the vetting process, the panel recorded mutual vetoes. Each veto is an unordered pair of distinct candidates who cannot be placed on the same committee.

To formally document a scheduling failure, you must locate a specific obstruction: a deadlocked trio. A trio is defined as a set of exactly three distinct candidates. 

For any candidate $x$ in a trio, let their *internal conflict set* be the collection of other candidates within that same trio who have a recorded mutual veto with $x$. A trio is considered deadlocked if it satisfies both of the following requirements:
1. Every candidate in the trio has a non-empty internal conflict set.
2. No two candidates in the trio have the exact same internal conflict set.

You must systematically evaluate the vetoes to find a deadlocked trio. If there are multiple deadlocked trios, you must report the trio whose candidate numbers form the lexicographically smallest sequence when sorted in ascending order. (A sequence $a_1 < b_1 < c_1$ is lexicographically smaller than $a_2 < b_2 < c_2$ if $a_1 < a_2$; or if $a_1 = a_2$ and $b_1 < b_2$; or if $a_1 = a_2$ and $b_1 = b_2$ and $c_1 < c_2$).

## Input
The first line contains two integers $n$ and $m$, indicating the candidate headcount and the log size. The bounds are $3 \le n \le 2000$ and $3 \le m \le \min(n(n-1)/2, 200000)$.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing a mutual veto between candidate $u$ and candidate $v$. It is guaranteed that at least one deadlocked trio exists.

## Output
Output a single line containing three integers $a$, $b$, and $c$, ordered such that $a < b < c$, representing the candidate numbers in the chosen trio. Among all valid deadlocked trios, output the lexicographically smallest one (smallest $a$; if tied, smallest $b$; if tied, smallest $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```

<METHOD_NAME>Neighborhood Equality Obfuscation</METHOD_NAME>
<METHOD_DESCRIPTION>Replaced the bipartiteness/2-coloring condition with a structurally equivalent condition based on induced neighborhood sets. A 3-vertex subgraph is a triangle if and only if every vertex has degree >= 1 and no two vertices have identical neighborhoods within the subgraph. This prevents models from immediately recognizing the triangle requirement via the word "partition" or "sets".</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>
<RATIONALE>
The surviving models succeeded by recognizing that partitioning a 3-vertex graph into two independent sets is impossible if and only if it is a triangle, allowing them to search for triangles directly. I removed the partition framing entirely. Instead, the condition is now defined via the distinctness of the candidates' internal conflict sets. This forces the model to either mathematically deduce that this new condition is also uniquely satisfied by a triangle, or implement it literally and likely face a Time Limit Exceeded on $O(N^3)$ operations.
</RATIONALE>
<PRESERVED_ANSWER>
The new condition requires that in a 3-vertex subgraph, all vertices have degree $\ge 1$ and no two vertices have the same neighborhood, which is mathematically true only for the complete graph $K_3$ (a triangle), meaning it identifies exactly the same deadlocked trios as the original partition condition.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the search for a lexicographically smallest triangle in an undirected graph, preserving its $O(nm/64)$ certificate-finding complexity class.
</PRESERVED_CLASS>
