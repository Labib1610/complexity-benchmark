<STATEMENT>
# Committee Deadlock Resolution

## Time and Memory Limits
Time limit: 2 s
Memory limit: 256 MB

## Description
A selection panel is evaluating a roster of candidates, numbered $1$ to $n$. During the vetting process, the panel recorded mutual vetoes. Each mutual veto is a unique unordered pair of distinct candidates who cannot be placed on the same committee. 

To track these conflicts, the panel assigns a unique event identifier to each recorded mutual veto. For each candidate, we define their *veto portfolio* as the set of event identifiers for all mutual vetoes in which they are involved.

To formally document a scheduling failure, you must locate a specific obstruction: a deadlocked trio. A trio is defined as a set of exactly three distinct candidates. For any trio of candidates, we can examine the event identifiers shared by at least two members of the trio. Specifically, if the candidates in the trio are $x$, $y$, and $z$, with portfolios $P_x$, $P_y$, and $P_z$, we define their *shared portfolio* as:
$$(P_x \cap P_y) \cup (P_y \cap P_z) \cup (P_z \cap P_x)$$

A trio is considered deadlocked if its shared portfolio contains exactly 3 event identifiers.

You must systematically evaluate the vetoes to find a deadlocked trio. If there are multiple deadlocked trios, you must report the trio whose candidate numbers form the lexicographically smallest sequence when sorted in ascending order. (A sequence $a_1 < b_1 < c_1$ is lexicographically smaller than $a_2 < b_2 < c_2$ if $a_1 < a_2$; or if $a_1 = a_2$ and $b_1 < b_2$; or if $a_1 = a_2$ and $b_1 = b_2$ and $c_1 < c_2$).

## Input
The first line contains two integers $n$ and $m$, indicating the candidate headcount and the log size. The headcount $n$ starts from a minimum of 3 and reaches up to the interview limit of 2000. The log size $m$ is at least 3 and is bounded by the database capacity of 200,000 entries, or the maximum possible number of unique pairs for $n$ candidates, whichever is more restrictive.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing a mutual veto between candidate $u$ and candidate $v$. It is guaranteed that at least one deadlocked trio exists.

## Output
Output a single line containing three integers $a$, $b$, and $c$, ordered such that $a < b < c$, representing the candidate numbers in the chosen trio. Among all valid deadlocked trios, output the lexicographically smallest one (smallest $a$; if tied, smallest $b$; if tied, smallest $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I replaced the vertex-centric subset condition with an edge-incidence set intersection condition. A literal code translation of this definition requires intersecting sets of size $m$ (up to 200,000) for every possible pair or trio, which will trivially exceed the 2-second time limit or 256MB memory limit. To pass, the model must logically deduce that the intersection of two incidence sets yields at most the single edge between them, allowing the condition to be reduced back to standard adjacency-matrix triangle finding.
</RATIONALE>
<PRESERVED_ANSWER>
The shared portfolio of a trio contains exactly the event identifiers of the mutual vetoes between members of the trio; since there are at most 3 such vetoes, the portfolio has size 3 if and only if all three pairwise vetoes exist, making the condition perfectly equivalent to the original triangle requirement.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem remains finding a triangle (K3) in an undirected graph, which preserves the certificate-style infeasibility class and the intended O(n*m/64) bitset algorithm.
</PRESERVED_CLASS>
<RISK>
Models might be confused about whether the event identifiers are 1-indexed integers or some other data type, though this shouldn't matter since they only need to reason about set sizes and intersections, not the actual values of the identifiers.
</RISK>
<METHOD_NAME>
Edge-Incidence Set Intersection
</METHOD_NAME>
<METHOD_DESCRIPTION>
Replaces vertex adjacency with the intersection of edge-incidence sets (portfolios of event identifiers). A literal implementation requires O(n^3 * m) time or O(n^2 * m) memory, which will TLE or MLE. To achieve the required O(n * m / 64) time and O(n^2) memory, the model must mathematically deduce that the intersection of two incidence sets yields at most the single edge between them, reducing the condition back to standard triangle finding.
</METHOD_DESCRIPTION>
<METHOD_NOVEL>
yes
</METHOD_NOVEL>
