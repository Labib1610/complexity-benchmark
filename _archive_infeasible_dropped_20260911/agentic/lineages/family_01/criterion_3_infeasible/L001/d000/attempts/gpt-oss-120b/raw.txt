**Solution Explanation**

For every worker we keep the set of his conflicts as a bitset  
(`int` in Python).  
Bit `i‑1` of the integer of worker `v` tells whether `v` conflicts with
worker `i`.

```
adj[v]  – integer, bit (i-1) = 1  ⇔  (v , i) is a conflict edge
```

For a pair of workers `a , b` the bitwise *and* `adj[a] & adj[b]`
contains exactly the workers that conflict with **both** `a` and `b`.

The required triple has to be *lexicographically* minimal,
i.e. smallest possible `a`; for this `a` the smallest possible `b`,
and then the smallest possible `c`.

--------------------------------------------------------------------

#### Algorithm
```
read n , m
adj[1…n] = 0
neigh[1…n] = empty list

for each edge (u , v):
        set the bits in both adjacencies
        store v in neigh[u] and u in neigh[v]

for a = 1 … n:
        sort neigh[a] increasingly          # needed for lexicographic order
        for b in neigh[a] (in this order):
                if b <= a:   continue       # we only need a < b
                common = adj[a] & adj[b]    # workers adjacent to both a and b
                # we need c > b, i.e. bits with index ≥ b
                mask   = full_mask ^ ((1 << b) - 1)     # bits 0 … b‑1 cleared
                cand   = common & mask
                if cand != 0:                # at least one suitable c exists
                        lowest = cand & -cand            # lowest set bit
                        c = lowest.bit_length()          # 1‑based index of that bit
                        output a, b, c
                        terminate
```

*Why does it work?*

* `adj[a] & adj[b]` are exactly the workers that are neighbours of **both**
  `a` and `b`.  
  Intersecting two adjacency sets is `O(1)` because they are single integers.

* The mask removes all vertices `≤ b`.  
  If something remains, its lowest set bit corresponds to the smallest vertex
  `c > b` that forms a triangle with `a , b`.

* The outer loops enumerate pairs `(a,b)` in strict lexicographic order:
  `a` grows, and for a fixed `a` the neighbours `b` are processed increasingly.
  The first triangle found therefore has the smallest possible `(a,b,c)`.

*The algorithm stops at the first triangle, which is exactly the required one.*

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triple
`(a,b,c)` that forms a triangle.

---

##### Lemma 1  
For any vertices `x` and `y`, `adj[x] & adj[y]` contains exactly the vertices
that are adjacent to *both* `x` and `y`.

**Proof.**  
Bit `i‑1` of `adj[x]` is `1` iff edge `(x,i)` exists, similarly for `adj[y]`.  
The bitwise *and* is `1` precisely when both bits are `1`, i.e. when both
edges `(x,i)` and `(y,i)` exist. ∎



##### Lemma 2  
For a fixed ordered pair `(a,b)` with `a<b`, after applying the mask,
`cand = (adj[a] & adj[b]) & mask` contains exactly the vertices `c` such that  

* `c > b` and  
* edges `(a,c)` and `(b,c)` exist.

**Proof.**  
By Lemma&nbsp;1 `adj[a] & adj[b]` are all common neighbours of `a` and `b`.  
`mask` has `0` on bits `0 … b‑1` and `1` elsewhere, therefore the *and* removes
every vertex `c ≤ b` and keeps every vertex `c > b`. ∎



##### Lemma 3  
If `cand ≠ 0`, the vertex `c` obtained from the lowest set bit of `cand`
is the smallest vertex `c > b` that together with `a,b` forms a triangle.

**Proof.**  
All vertices represented in `cand` satisfy the conditions of Lemma&nbsp;2.
The lowest set bit corresponds to the smallest index among them,
hence to the smallest such vertex `c`. ∎



##### Lemma 4  
When the algorithm prints a triple `(a,b,c)`, it is a triangle
(`a‑b`, `a‑c`, `b‑c` are all edges) and satisfies `a<b<c`.

**Proof.**  
`b` is taken from `neigh[a]`, therefore edge `(a,b)` exists and we skip
the case `b ≤ a`, so `a<b`.  
`cand` is non‑empty, hence by Lemma&nbsp;2 there exists at least one vertex
`c>b` adjacent to both `a` and `b`.  
The algorithm chooses the smallest such `c` (Lemma&nbsp;3), so edges
`(a,c)` and `(b,c)` exist, and `c>b`. ∎



##### Lemma 5  
Let `T* = (a*,b*,c*)` be the lexicographically smallest triangle in the
graph. The algorithm will output `T*`.

**Proof.**  
Consider the outer loop iteration with `a = a*`.  
All `b` with an edge to `a*` and `b > a*` are examined in increasing order.
When `b = b*` is processed, Lemma&nbsp;2 guarantees that `cand` contains
exactly the common neighbours larger than `b*`.  
Since `(a*,b*,c*)` is a triangle, `c*` belongs to `cand`; therefore `cand ≠ 0`.
The algorithm outputs the smallest such `c`, which must be `c*` because any
other candidate would be larger and would give a lexicographically larger
triple.  

All earlier pairs `(a,b)` with `a < a*` or `a = a* , b < b*` cannot yield a
triangle, otherwise `T*` would not be lexicographically minimal.
Thus the first printed triangle is exactly `T*`. ∎



##### Theorem  
The algorithm terminates and prints the lexicographically smallest triple
`(a,b,c)` such that all three pairs are conflicting workers.

**Proof.**  
The loops iterate over a finite number of ordered pairs; the inner test may
output and terminate. Because the input guarantees at least one triangle,
by Lemma&nbsp;5 such an output will certainly happen.  
By Lemma&nbsp;4 the printed triple is a triangle, and by Lemma&nbsp;5 it is the
lexicographically smallest one. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building the structure*  
`O(m)` – each edge updates two integers and two adjacency lists.

*Search*  
For each ordered pair `(a,b)` where `a<b` and edge `(a,b)` exists
(the number of such pairs is `m`), we perform only constant‑time
bit operations.  
Hence `O(m)` time.

`n ≤ 2000`, `m ≤ 2·10⁵`, well inside the limits.

Memory consumption:  
`adj` – `n+1` Python integers, each about `n` bits ⇒ at most `2000·2000 ≈ 4·10⁶` bits ≈ 0.5 MiB.  
Neighbour lists – `2m` integers ≤ `4·10⁵`.  
Total far below 256 MB.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # bitsets, 1‑based indexing
    neigh = [[] for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        # set bits (v-1) and (u-1)
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)
        neigh[u].append(v)
        neigh[v].append(u)

    full_mask = (1 << n) - 1

    for a in range(1, n + 1):
        neigh[a].sort()
        a_mask = adj[a]
        for b in neigh[a]:
            if b <= a:
                continue
            common = a_mask & adj[b]
            # keep only vertices > b
            mask = full_mask ^ ((1 << b) - 1)   # clear bits 0..b-1
            cand = common & mask
            if cand:
                lowest = cand & -cand
                c = lowest.bit_length()          # 1‑based vertex number
                print(a, b, c)
                return

if __name__ == "__main__":
    solve()
```
