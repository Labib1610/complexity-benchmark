**Solution Explanation**

For every person we know the list of people with whom he/she has a conflict.
The conflicts form an undirected graph  

`V = {1 … n}` , `E = {(u , v) | u` and `v` dispute}`.

A schedule for two shifts would be a proper 2‑colouring of the graph.
The statement guarantees that the input graph always contains a triangle
(three pairwise adjacent vertices).  
We have to output *the lexicographically smallest* triangle
`a < b < c`.

--------------------------------------------------------------------

#### 1.   Observations  

* `n ≤ 2000`.  An adjacency **bitset** of length `n` fits easily into a
  Python integer (≈ 2000 bits ≈ 250 bytes).  
  Bitwise operations on Python integers are performed in C and are
  extremely fast.

* For a fixed edge `(a , b)` the vertices that close a triangle with it
  are exactly the vertices belonging to the intersection  

  `N(a) ∩ N(b)` (common neighbours of `a` and `b`).

* If we examine edges in the order  

  `a = 1 … n` (outer loop)  
  `b` – neighbours of `a` in increasing order, `b > a` (inner loop)  

  and for each edge pick the *smallest* possible `c > b`,
  the first triangle we meet is exactly the lexicographically smallest
  one required by the statement.

--------------------------------------------------------------------

#### 2.   Data structures  

* `bits[v]` – Python `int`, bit `i` (`0‑based`) is set **iff**
  vertex `i+1` is a neighbour of `v`.  
  Setting a bit: `bits[u] |= 1 << (v-1)`.

* `adj[v]` – list of all neighbours of `v`, sorted increasingly.
  Needed only to iterate `b` in the correct order.

Both structures need `O(n + m)` memory.

--------------------------------------------------------------------

#### 3.   Algorithm  

```
read n, m
bits = [0] * (n+1)
adj  = [[] for _ in range(n+1)]

for each edge (u, v):
        bits[u] |= 1 << (v-1)
        bits[v] |= 1 << (u-1)
        adj[u].append(v)
        adj[v].append(u)

for each v: sort adj[v]

for a = 1 .. n:
        for b in adj[a]:               # neighbours of a, increasing
                if b <= a: continue    # need a < b
                common = bits[a] & bits[b]          # N(a) ∩ N(b)
                shifted = common >> b               # delete vertices ≤ b
                if shifted:
                        # lowest set bit of shifted
                        low = (shifted & -shifted).bit_length() - 1
                        c = low + b + 1            # back to original label
                        output a, b, c and finish
```

*`shifted`* contains exactly the common neighbours whose numbers are
greater than `b`.  
If it is non‑zero, the least significant set bit gives the smallest such
`c`.  
The whole outer search stops at the first found triangle,
which is the lexicographically smallest one because of the enumeration
order proven above.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triangle.

---

##### Lemma 1  
For any edge `{a,b}` (`a<b`) the algorithm computes exactly the set  
`{ c | c > b  and  {a,c}∈E and {b,c}∈E }`.

**Proof.**  
`common = bits[a] & bits[b]` has a 1‑bit exactly at positions `c-1`
where `c` is adjacent to *both* `a` and `b`.  
`shifted = common >> b` discards the `b` lowest bits, i.e. all vertices
`c ≤ b`.  
Thus the set bits of `shifted` correspond precisely to vertices `c > b`
adjacent to both `a` and `b`. ∎



##### Lemma 2  
If `shifted` is non‑zero, the vertex  

`c = (index of least significant set bit of shifted) + b + 1`

is the smallest vertex `c > b` that together with `{a,b}` forms a triangle.

**Proof.**  
`shifted` contains a 1‑bit for each feasible `c` (Lemma&nbsp;1) and the
bits are ordered by increasing vertex number.
The least significant set bit therefore corresponds to the smallest such
`c`.  Adding `b` (the amount of right shift) and `1` (conversion from
0‑based index to vertex label) yields exactly that vertex. ∎



##### Lemma 3  
When the algorithm prints a triple `(a,b,c)`, the three edges
`{a,b}`, `{a,c}`, `{b,c}` are all present in the input graph.

**Proof.**  
`b` is a neighbour of `a` by the way the inner loop iterates `adj[a]`.
`c` is obtained from `shifted`, which by Lemma&nbsp;1 is a common neighbour
of `a` and `b`.  Hence both `{a,c}` and `{b,c}` belong to `E`. ∎



##### Lemma 4  
Let `(a₀,b₀,c₀)` be the first triple printed by the algorithm.
For every triangle `(a,b,c)` with `a < b < c` we have  
`(a₀,b₀,c₀) ≤_lex (a,b,c)`.

**Proof.**  
The outer loop enumerates `a` increasingly; the inner loop enumerates for
that `a` all `b > a` increasingly.
Consequently, the algorithm examines all possible pairs `(a,b)` in
lexicographic order of `(a,b)`.

For a fixed pair `(a,b)` Lemma&nbsp;2 shows that the algorithm, if any,
selects the smallest feasible `c`.  
Therefore, the first printed triangle corresponds to the smallest pair
`(a,b)` for which a triangle exists, and within that pair the smallest `c`.
No triangle can be lexicographically smaller. ∎



##### Theorem  
The algorithm always terminates and outputs the lexicographically smallest
triple `a<b<c` such that the three edges are present in the input graph.

**Proof.**  
The input guarantees at least one triangle, so there exists a pair
`(a,b)` with `a<b` for which `shifted` becomes non‑zero.
When the algorithm reaches the *first* such pair in its ordered scan,
Lemma&nbsp;2 yields a concrete `c` and the algorithm prints the triple
and stops. Hence it terminates.

By Lemma&nbsp;3 the printed triple is indeed a triangle.
By Lemma&nbsp;4 no other triangle is lexicographically smaller.
Thus the output satisfies the specification. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Building the structures* : `O(n + m)` time, `O(n + m)` memory.  

*Main loop* : one iteration per directed edge `a<b`, i.e. `m` times.
Each iteration performs a constant number of bitwise operations on
integers of length `n ≤ 2000` bits – `O(1)` in Python.
Therefore total time `O(m) ≤ 2·10⁵`.  

Overall  

* **Time**   `O(n + m)`   ( ≤ 2·10⁵ operations, far below the limit )  
* **Memory** `O(n + m)`   ( ≤ a few MB, well inside the limit )

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    bits = [0] * (n + 1)          # adjacency bitsets
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        # set bits (0‑based inside the integer)
        bits[u] |= 1 << (v - 1)
        bits[v] |= 1 << (u - 1)
        adj[u].append(v)
        adj[v].append(u)

    for v in range(1, n + 1):
        adj[v].sort()

    out = []
    for a in range(1, n + 1):
        ba = bits[a]
        for b in adj[a]:
            if b <= a:
                continue            # need a < b
            common = ba & bits[b]   # N(a) ∩ N(b)
            shifted = common >> b   # discard vertices ≤ b
            if shifted:
                # index of least significant 1‑bit
                low = (shifted & -shifted).bit_length() - 1
                c = low + b + 1     # back to original vertex number
                out = [a, b, c]
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
