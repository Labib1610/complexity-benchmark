We can solve this by checking each possible triple, but that would be too slow for large inputs. Instead, we can use the fact that we only need to find the lexicographically smallest triangle in an undirected graph.

A more efficient approach:  
- For each vertex `a` from 1 to n, look at its neighbors.  
- For each pair of neighbors `(b, c)` with `b < c`, check if there is an edge between `b` and `c`.  
- The first such triple found (in increasing order of `a`, then `b`, then `c`) is the answer.

We can store the adjacency as a set for O(1) edge lookup.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        neighbors = sorted(adj[a])
        for i in range(len(neighbors)):
            b = neighbors[i]
            for j in range(i + 1, len(neighbors)):
                c = neighbors[j]
                if c in adj[b]:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
