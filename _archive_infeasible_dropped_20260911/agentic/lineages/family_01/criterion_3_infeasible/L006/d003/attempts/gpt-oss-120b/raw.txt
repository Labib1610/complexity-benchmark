**Solution Explanation**

For three different vertices `a < b < c` we need all three edges  
`(a,b) , (a,c) , (b,c)` – i.e. a *triangle* in the undirected graph.
The task is to output the lexicographically smallest triangle.
`n ≤ 2000`, therefore a bitset of length `n` fits into a Python integer
(2000 bits ≈ 250 bytes).

--------------------------------------------------------------------

#### Data structures
* `adj[i]` – integer whose `j‑th` bit (`j = 0 … n‑1`) is `1`
  iff there is an edge between vertices `i` and `j+1`.
* `edge_set` – a `set` of ordered pairs `(u,v)` (`u < v`) to test
  existence of an edge in `O(1)` (used only while building the bitsets).

--------------------------------------------------------------------

#### Algorithm
```
read n, m
adj = [0] * (n+1)          # 1‑based
for each edge (u,v):
        if u > v: swap
        adj[u] |= 1 << (v-1)
        adj[v] |= 1 << (u-1)

for a = 1 .. n:
        for b = a+1 .. n:
                if edge (a,b) not present: continue
                common = adj[a] & adj[b]          # vertices adjacent to both
                # discard vertices ≤ b, we need c > b
                mask = (1 << b) - 1               # bits 0 … b-1 are 1
                common &= ~mask
                if common != 0:
                        low = common & -common    # lowest set bit
                        c_idx = low.bit_length() - 1
                        c = c_idx + 1
                        output a b c and finish
```

The first triangle found by the double loop is automatically the
lexicographically smallest one, because `a` grows first, then `b`,
and we always pick the smallest possible `c`.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

**Lemma 1**  
For any vertices `a` and `b` the integer `common = adj[a] & adj[b]`
has a set bit at position `c-1` (`c` 1‑based) **iff**
edges `(a,c)` and `(b,c)` both exist.

*Proof.*  
`adj[a]` has bit `c-1` set ⇔ edge `(a,c)` exists.  
`adj[b]` has bit `c-1` set ⇔ edge `(b,c)` exists.  
The bitwise AND is set exactly when both are set. ∎



**Lemma 2**  
After `common &= ~mask` (where `mask` has bits `0 … b-1` set) the remaining
set bits correspond precisely to vertices `c` with `c > b` that are adjacent
to both `a` and `b`.

*Proof.*  
`~mask` has zeros for indices `0 … b-1` and ones elsewhere.
ANDing clears all bits ≤ `b-1` and leaves higher bits unchanged.
By Lemma&nbsp;1 the higher bits represent vertices adjacent to both `a` and `b`. ∎



**Lemma 3**  
If `common != 0` after the masking step, `c = (common & -common).bit_length()`
is the smallest vertex `c > b` that together with `a,b` forms a triangle.

*Proof.*  
`common & -common` isolates the lowest set bit of `common`.  
Its index is the smallest `c-1` present, i.e. the smallest `c`. ∎



**Lemma 4**  
When the algorithm prints a triple `(a,b,c)`, it is a triangle.

*Proof.*  
The outer loops guarantee that edge `(a,b)` exists (checked via the set).  
By Lemma&nbsp;2 and Lemma&nbsp;3, `c` satisfies that edges `(a,c)` and `(b,c)`
exist. Hence all three edges are present – a triangle. ∎



**Lemma 5**  
The first printed triangle is the lexicographically smallest triangle.

*Proof.*  
The loops enumerate pairs `(a,b)` in increasing lexicographic order:
`a` from `1` to `n`, for each `a` `b` from `a+1` upwards.
For a fixed `(a,b)` Lemma&nbsp;3 chooses the smallest possible `c`.
Therefore any triangle with a smaller `a` would have been examined earlier,
and with the same `a` but smaller `b` also earlier.
Thus the first found triangle is the minimal one. ∎



**Theorem**  
The algorithm always outputs the lexicographically smallest triple
`a < b < c` that forms a triangle, and such a triple exists by the problem
statement.

*Proof.*  
Existence follows from the guarantee.  
When the algorithm encounters the first pair `(a,b)` belonging to any
triangle, Lemma&nbsp;2‑3 produce the smallest compatible `c`,
so a triangle is printed (Lemma&nbsp;4).  
By Lemma&nbsp;5 this triangle is the lexicographically smallest among all
triangles. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Building adjacency bitsets*: `O(m)` operations.  
*Main double loop*: at most `n·(n-1)/2 ≤ 2·10⁶` iterations.
Each iteration performs a constant‑time bitwise AND and a few integer
operations (`O(1)` because the integers have at most 2000 bits, i.e. a few
machine words).  
Hence total time `O(n² + m) ≤ 2·10⁶`, well within the 2 s limit.

Memory: `adj` stores `n+1` integers, each ≤ 2ⁿ, i.e. about `n·250 bytes`
≈ 0.5 MB, far below the limit.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    edge_set = set()

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        if u > v:
            u, v = v, u
        edge_set.add((u, v))
        adj[u] |= 1 << (v - 1)
        adj[v] |= 1 << (u - 1)

    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if (a, b) not in edge_set:
                continue
            common = adj[a] & adj[b]
            # clear bits for vertices <= b
            mask = (1 << b) - 1          # bits 0..b-1 are 1
            common &= ~mask
            if common:
                low = common & -common
                c_idx = low.bit_length() - 1
                c = c_idx + 1
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
