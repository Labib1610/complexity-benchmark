<STATEMENT>
# Problem C — Triadic Resonance

Time limit: 2 s
Memory limit: 256 MB

You are analyzing a system of $n$ acoustic frequencies, labeled $1$ through $n$. Through experimentation, you have discovered $m$ unique "harmonious pairs" of frequencies. Each harmonious pair consists of two distinct frequencies that resonate stably together. Order within a pair does not matter.

We are looking for a "perfect triad". A perfect triad is defined by a set of exactly three distinct frequencies, $S = \{a, b, c\}$. To evaluate whether $S$ is a perfect triad, you filter the entire list of $m$ harmonious pairs, retaining only those pairs where both frequencies belong to $S$. If the size of this filtered list is exactly 3, then $S$ is a perfect triad.

Your task is to find a perfect triad and output its frequencies in ascending order ($a < b < c$). If multiple such triads exist, you must output the one that is lexicographically smallest (i.e., the one with the smallest $a$; in case of ties, the smallest $b$; and then the smallest $c$).

## Input
The first line contains two integers $n$ and $m$. The value of $n$ is an integer between the number of observable spatial dimensions and the year commonly associated with the Y2K bug, inclusive. The value of $m$ is at least 3, and at most two hundred thousand (or the maximum possible number of unique pairs among $n$ frequencies, if that is strictly less).
Each of the following $m$ lines contains two integers $u$ and $v$ — a harmonious pair of frequencies. No pair is listed more than once.
It is guaranteed that the data contains at least one perfect triad.

## Output
Print three integers $a$, $b$, and $c$ on a single line, separated by spaces, representing the frequencies of the lexicographically smallest perfect triad, such that $a < b < c$.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
I completely removed the directed/ordered "forward trail" phrasing that spoon-fed the optimized triangle-finding algorithm. Instead, the condition is framed as filtering the entire list of pairs by a 3-element subset and checking if exactly 3 pairs remain. This forces the model to deduce that this implies all three internal pairs are present (a 3-clique), otherwise it will likely write a literal translation of the filter which operates in $O(n^3 m)$ time and fails the 2s time limit.
</RATIONALE>
<PRESERVED_ANSWER>
A 3-element set $S$ has at most 3 distinct unordered pairs; requiring the filtered list of unique input pairs to have size 3 is mathematically equivalent to requiring all three pairs (a,b), (b,c), and (a,c) to exist in the input, preserving the exact same condition as the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying problem remains finding a triangle (3-clique) in an undirected graph, which shares the exact same complexity class as the seed.
</PRESERVED_CLASS>
<RISK>
Models might interpret "observable spatial dimensions" as 4 (if they erroneously include time, though "spatial" explicitly excludes it), but this only affects the lower bound of $n$ which is not critical for algorithmic correctness on standard test cases.
</RISK>
