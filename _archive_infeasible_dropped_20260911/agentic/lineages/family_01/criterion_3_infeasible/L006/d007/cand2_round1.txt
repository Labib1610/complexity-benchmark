<STATEMENT>
# Problem C — Cross-Referenced Flags

Time limit: 2 s
Memory limit: 256 MB

You are auditing a strict access-control system containing $n$ user profiles, numbered $1$ to $n$. Each profile maintains exactly $n$ boolean permission flags, which are all initially set to `false`.

The system logs $m$ mutual authorizations. Each authorization is a pair $(u, v)$, which updates the system by setting flag $v$ in profile $u$ to `true`, and setting flag $u$ in profile $v$ to `true`.

A critical security vulnerability occurs if there is a "tri-level escalation". This happens when three distinct profile IDs $a$, $b$, and $c$ (with $a < b < c$) satisfy the following state:
1. In profile $a$, flag $b$ and flag $c$ are both `true`.
2. In profile $b$, flag $c$ is `true`.

Because authorizations are mutual, this configuration creates a closed loop of permissions among the three profiles.

You must identify the profiles involved in this vulnerability. It is guaranteed that the log produces at least one such configuration.

## Input
The first line contains two integers $n$ and $m$ ($3 \le n \le 2000$, $3 \le m \le \min(n(n-1)/2, 200000)$).
Each of the next $m$ lines contains two integers $u$ and $v$ — a pair of profiles that mutually authorized each other.
It is guaranteed that at least one tri-level escalation exists.

## Output
Print three integers $a$, $b$, and $c$ on one line with $a < b < c$, representing the IDs of the three profiles. Output the lexicographically smallest such combination (smallest $a$; ties broken by smallest $b$; then smallest $c$).

## Example 1
Input:
```
4 5
1 2
1 3
2 3
2 4
3 4
```
Output:
```
1 2 3
```

## Example 2
Input:
```
5 6
1 2
1 4
2 4
3 4
3 5
4 5
```
Output:
```
1 2 4
```
</STATEMENT>
<RATIONALE>
The problem was completely reframed from a relational graph scenario ("forward audit trails" between "suppliers") to an object-property scenario ("profiles" containing "boolean flags"). This removes all graph-theoretic and relational vocabulary, preventing models from relying on surface-level pattern matching to trigger standard graph algorithms. Models must now genuinely simulate or reason about the boolean state conditions to realize it structurally maps to finding a 3-clique, which also naturally hints at the optimal bitset implementation.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that profile $a$ has flags $b$ and $c$, and profile $b$ has flag $c$ (with symmetric updates) is mathematically identical to the existence of undirected edges $(a,b)$, $(a,c)$, and $(b,c)$, ensuring the exact same combinations are found.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a 3-clique (triangle) in an undirected graph disguised as a symmetric boolean matrix, leaving the INFEASIBLE complexity class and optimal $O(nm/64)$ bitset algorithm entirely unchanged.
</PRESERVED_CLASS>
<RISK>
A reader might incorrectly assume that "flag b and flag c are both true" implies that *only* those flags are true, though standard programming parlance interprets this as a minimum required state rather than an exclusive one.
</RISK>
