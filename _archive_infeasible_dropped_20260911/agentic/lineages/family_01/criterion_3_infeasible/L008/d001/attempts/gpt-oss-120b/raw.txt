**Solution Explanation**

For every employee we know the set of employees that must work on a different shift.
The required triple `{a,b,c}` is exactly a *triangle* in this undirected graph:
all three edges `{a,b}`, `{a,c}`, `{b,c}` are present.

The graph has  

* `n ≤ 2000` vertices  
* `m ≤ 2·10⁵` edges  

and it is guaranteed that at least one triangle exists.
We have to output the lexicographically smallest sorted triple
`a < b < c`.

--------------------------------------------------------------------

#### 1.   Bitset representation  

`n = 2000` fits into a 2000‑bit integer.
For a vertex `v` we store an integer `bits[v]` whose `i`‑th bit (`i = 0 … n‑1`)
is `1` iff vertex `i+1` is adjacent to `v`.

```text
bits[v]  = Σ  (1 << (u-1))   over all neighbours u of v
```

All set operations become fast bit operations (`&`, `|`, `~`).

--------------------------------------------------------------------

#### 2.   Searching triangles in lexicographic order  

We iterate `a` from `1` to `n`.  
For a fixed `a` we look at neighbours `b` with `b > a` (sorted order).

For the pair `{a,b}` the common neighbours are

```
common = bits[a] & bits[b]
```

Only a vertex `c` larger than `b` can give a sorted triple `a < b < c`,
therefore we delete all bits `≤ b`:

```
mask   = (1 << b) - 1          # bits 0 … b-1 are 1
common = common & ~mask
```

If `common` is non‑zero, the lowest set bit gives the smallest possible `c`
(because we already iterate `a` and `b` in increasing order).  
The position of the lowest set bit is obtained by `common & -common`
and `bit_length()`.

The first triple we encounter is exactly the required minimal one,
so we can output it immediately and terminate.

The whole algorithm touches each edge once, all operations are O(1) on
Python integers, therefore the total complexity is `O(m)` and the memory
consumption is `O(n)` integers (`≈ 2000·256 bits`).

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triangle.

---

##### Lemma 1  
For any vertices `a < b`, after masking `common = bits[a] & bits[b]` with
`~((1<<b)-1)`, the set bits of `common` are exactly the vertices `c` such that
`c > b` and `{a,b,c}` is a triangle.

**Proof.**  
`bits[a] & bits[b]` contains precisely the vertices adjacent to **both**
`a` and `b`. Masking removes all vertices `≤ b`. The remaining bits correspond
to vertices `c > b` adjacent to both `a` and `b`, i.e. to triangles
`a,b,c`. ∎



##### Lemma 2  
When the algorithm processes a pair `(a,b)` (with `a<b`) it finds the
smallest possible `c` that together with `a,b` forms a triangle.

**Proof.**  
By Lemma&nbsp;1 the set bits of `common` are exactly the admissible `c`.
`common & -common` extracts the least significant set bit, i.e. the smallest
`c`. ∎



##### Lemma 3  
Let `T = (a,b,c)` be the first triangle output by the algorithm.
Then there is no triangle `(a',b',c')` with
`a' < a`, or `a'=a` and `b' < b`, or `a'=a, b'=b` and `c' < c`.

**Proof.**  
The outer loop enumerates `a` in increasing order, the inner loop enumerates
`b` (neighbours of `a`) in increasing order, and for each pair the algorithm
chooses the smallest possible `c` (Lemma&nbsp;2).  
Therefore any triangle with a smaller `a` would have been examined earlier,
any triangle with the same `a` but smaller `b` would have been examined in the
same outer iteration earlier, and with the same `a,b` but smaller `c` would
have been found by the same pair earlier. Since none of those happened,
no such triangle exists. ∎



##### Lemma 4  
The algorithm always outputs a triangle.

**Proof.**  
The statement of the problem guarantees that at least one triangle exists.
Consider the lexicographically smallest triangle `(a*,b*,c*)`.
When the outer loop reaches `a = a*`, the inner loop will eventually consider
`b = b*` (because `b*` is a neighbour of `a*`).  
At that moment `common` contains `c*` (Lemma&nbsp;1), so it is non‑empty and
the algorithm outputs a triangle. ∎



##### Theorem  
The algorithm outputs exactly the lexicographically smallest triple
`a < b < c` that forms a triangle.

**Proof.**  
By Lemma&nbsp;4 the algorithm outputs some triangle `T`.  
By Lemma&nbsp;3 no triangle is lexicographically smaller than `T`.  
Thus `T` is the lexicographically smallest triangle, which is exactly the
required output. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*Building adjacency bitsets* : `O(m)` time, `O(n)` memory.  
*Main loops* : each edge `{a,b}` with `a<b` is examined once → `O(m)` time.  
All operations on the bitsets are constant‑time on Python's arbitrary length
integers.

```
Time   :  O(m)   ≤ 2·10⁵
Memory :  O(n)   ≤ 2000 integers  (≈ 250 KB)
```

Both limits satisfy the problem constraints.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    bits = [0] * (n + 1)          # 1‑based
    neigh = [[] for _ in range(n + 1)]

    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        bits[u] |= 1 << (v - 1)
        bits[v] |= 1 << (u - 1)
        neigh[u].append(v)
        neigh[v].append(u)

    for lst in neigh:
        lst.sort()

    for a in range(1, n + 1):
        ba = bits[a]
        for b in neigh[a]:
            if b <= a:
                continue
            common = ba & bits[b]
            # delete vertices <= b
            mask = (1 << b) - 1          # bits 0 .. b-1 are 1
            common &= ~mask
            if common:
                low = common & -common    # lowest set bit
                c = low.bit_length()      # because bits are 0‑based, gives c
                # c is already > b
                sys.stdout.write(f"{a} {b} {c}\n")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
