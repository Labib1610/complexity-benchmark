We can solve this by checking each possible triple in lexicographic order and testing if all three edges exist. Since \(n \le 2000\), checking all triples naively would be \(O(n^3)\), which is too slow. Instead, we can use an adjacency matrix and iterate over pairs, then check for a common neighbor.

Here’s the approach:

- Store edges in a boolean adjacency matrix.
- Iterate `a` from 1 to n, `b` from a+1 to n.
- If edge (a,b) exists, then for each `c` from b+1 to n, check if edges (a,c) and (b,c) exist.
- The first such triple found is lexicographically smallest.

This is \(O(n^3)\) in the worst case, but with early exit and \(n \le 2000\), it may still be too slow in Python.  
We can optimize by using bitsets: represent each vertex’s neighbors as an integer bitmask, then for each pair (a,b), compute `mask[a] & mask[b]` and pick the smallest set bit greater than b.

Let’s implement that.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [0] * (n + 1)
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if (adj[a] >> b) & 1:
                common = adj[a] & adj[b]
                # remove bits <= b
                common &= ~((1 << (b + 1)) - 1)
                if common:
                    c = (common & -common).bit_length() - 1
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
