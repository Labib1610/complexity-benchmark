**Solution Explanation**

For every worker we know the workers he/she conflicts with.
The conflicts form an undirected simple graph `G = (V,E)`  
(`|V| = n ≤ 2000`, `|E| = m ≤ 2·10⁵`).

A required triple is a *triangle* – three vertices `a<b<c` such that all three
edges `{a,b}`, `{a,c}`, `{b,c}` belong to `E`.
The input guarantees that at least one triangle exists.
We have to output the lexicographically smallest one
(first smallest `a`, then `b`, then `c`).

--------------------------------------------------------------------

#### 1.  Observations  

* `n` is only 2000 – we can store the whole adjacency matrix.
* Bit operations on Python integers are extremely fast.
  With a bitset we can test the whole neighbourhood of a vertex in **O(1)**
  time.
* To obtain the lexicographically smallest triangle we may simply try all
  possible pairs `(a,b)` in increasing order and, for each pair,
  look for the smallest possible `c`.

--------------------------------------------------------------------

#### 2.  Data structures  

* `adj_bit[v]` – an integer whose binary representation has a `1` at position
  `u` (`0 ≤ u < n`) iff `{v,u}` is an edge.
* `adj_list[v]` – sorted list of neighbours of `v`.  
  Needed only to iterate `b` in increasing order.

Both structures are built while reading the input.

--------------------------------------------------------------------

#### 3.  Algorithm  

```
for a = 0 … n-1:
        for b in adj_list[a] (in increasing order):
                if b <= a: continue          # we need a < b
                common = adj_bit[a] & adj_bit[b]          # vertices adjacent to both a and b
                # delete vertices ≤ b, we need c > b
                mask = (1 << (b+1)) - 1          # bits 0 … b are 1
                common = common & ~mask
                if common != 0:                  # at least one suitable c exists
                        low = common & -common   # lowest set bit
                        c = low.bit_length() - 1 # its index (0‑based)
                        output a+1, b+1, c+1
                        terminate
```

*The first printed triple is the answer* because the outer loops enumerate
pairs `(a,b)` exactly in lexicographic order, and for a fixed pair we take the
smallest possible `c`.

--------------------------------------------------------------------

#### 4.  Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triangle.

---

##### Lemma 1  
For a fixed pair of vertices `a<b`, after the line  
`common = adj_bit[a] & adj_bit[b]` the set represented by `common`
is exactly the set `{ v | {a,v}∈E and {b,v}∈E }`.

**Proof.**  
`adj_bit[a]` has a `1` at position `v` iff `{a,v}` is an edge, similarly for
`adj_bit[b]`. Bitwise AND keeps a `1` only when both bits are `1`. ∎



##### Lemma 2  
After masking with `~mask` (`mask = (1 << (b+1)) - 1`) the integer `common`
contains a `1` at position `c` **iff** `c>b` and `{a,c}` and `{b,c}` are edges.

**Proof.**  
`mask` has `1`s exactly at positions `0 … b`.  
`~mask` therefore has `0`s at those positions and `1`s elsewhere.
Bitwise AND with `~mask` clears all bits `≤ b` and leaves bits `> b`
unchanged. By Lemma&nbsp;1 the unchanged bits correspond precisely to vertices
adjacent to both `a` and `b`. ∎



##### Lemma 3  
If `common` (after masking) is non‑zero, `low = common & -common` isolates the
least significant `1`‑bit, and `c = low.bit_length()‑1` is the smallest vertex
`c>b` that together with `a,b` forms a triangle.

**Proof.**  
`common & -common` is a standard trick returning a power of two equal to the
lowest set bit. Its index is obtained by `bit_length()‑1`. Because all bits
`≤ b` are cleared, the remaining bits are all `> b`; the lowest of them is the
smallest such `c`. ∎



##### Lemma 4  
When the algorithm prints a triple `(a,b,c)`, it is a triangle
(`a<b<c` and all three edges exist).

**Proof.**  
`a<b` by the loop condition.  
`c>b` because we removed all bits `≤ b`.  
By Lemma&nbsp;2, `c` is adjacent to both `a` and `b`.  
Edge `{a,b}` exists because `b` is taken from `adj_list[a]`. ∎



##### Lemma 5  
Let `T` be the set of all triangles of the graph.
The algorithm outputs the lexicographically smallest element of `T`.

**Proof.**  
Consider the enumeration order of pairs `(a,b)`:

* `a` increases from `0` to `n‑1`.
* For a fixed `a`, `b` runs through `adj_list[a]` in increasing order,
  skipping `b≤a`.

Thus pairs are visited in strictly increasing lexicographic order.
For a visited pair `(a,b)` the algorithm, by Lemma&nbsp;3, finds the smallest
`c>b` that together with `a,b` forms a triangle, if any exists.
Consequently the first printed triple is the smallest triple among all
triangles whose first two vertices are the first pair `(a,b)` that belongs to
some triangle. No triangle with a smaller `a` exists (otherwise its pair would
have been examined earlier). If several triangles share the same `a`,
none has a smaller `b` (otherwise that pair would have been examined earlier).
Finally, for the chosen `(a,b)` we output the smallest possible `c`. ∎



##### Theorem  
The algorithm always terminates and prints exactly the lexicographically
smallest triple of workers that pairwise conflict.

**Proof.**  
The input guarantees at least one triangle, i.e. `T` is non‑empty.
During the double loop every pair `(a,b)` with `a<b` and `{a,b}∈E` is examined,
hence some iteration will encounter a pair belonging to a triangle.
At that iteration `common` (after masking) is non‑zero, the algorithm prints a
triple and returns, so it terminates.

By Lemma&nbsp;4 the printed triple is a triangle.
By Lemma&nbsp;5 it is the lexicographically smallest triangle.
∎



--------------------------------------------------------------------

#### 5.  Complexity Analysis  

*Building the structures* – `O(m)` time, `O(n + m)` memory.  
*Main loops* – each edge `{a,b}` with `a<b` is processed once.
All operations inside the loop are O(1) bit operations on Python integers.
Hence total time `O(m) ≤ 2·10⁵`.  

Memory consumption:  
`adj_bit` – `n` integers, each ≤ `2ⁿ` → `O(n)` bits ≈ 2000·2000/8 ≈ 0.5 MiB.  
`adj_list` – `2m` integers → `O(m)` ≤ 4·10⁵ integers ≈ 3 MiB.  
Overall well below the limits.

#### 6.  Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)

    adj_bit = [0] * n
    adj_list = [[] for _ in range(n)]

    for _ in range(m):
        u = next(it) - 1
        v = next(it) - 1
        adj_bit[u] |= 1 << v
        adj_bit[v] |= 1 << u
        adj_list[u].append(v)
        adj_list[v].append(u)

    for lst in adj_list:
        lst.sort()

    for a in range(n):
        a_bits = adj_bit[a]
        for b in adj_list[a]:
            if b <= a:
                continue
            common = a_bits & adj_bit[b]
            # delete vertices <= b
            mask = (1 << (b + 1)) - 1
            common &= ~mask
            if common:
                low = common & -common          # lowest set bit
                c = low.bit_length() - 1
                # output 1‑based indices
                sys.stdout.write(f"{a+1} {b+1} {c+1}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
