 We need to find the lexicographically smallest triangle in an undirected graph.  
A direct brute force over all triples would be O(n³), which is too slow for n up to 2000.  

We can instead iterate over the smallest vertex `a` in the triangle, then try to find two neighbors `b` and `c` of `a` such that `b < c` and there is an edge between `b` and `c`.  
To make it efficient, we can store adjacency as sets for O(1) edge lookup.  

We iterate `a` from 1 to n, and for each `a`, we look at its neighbors in increasing order. For each pair of neighbors `(b, c)` with `b < c`, we check if `c` is in `adj[b]`. The first such found gives the lexicographically smallest triple because we check `a` in increasing order, and for each `a`, we check `b` in increasing order, and for each `b`, we check `c` in increasing order.  

Here’s the implementation:  

```python
n, m = map(int, input().split())
adj = [set() for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    adj[u].add(v)
    adj[v].add(u)

for a in range(1, n + 1):
    neighbors = sorted(adj[a])
    for i in range(len(neighbors)):
        b = neighbors[i]
        if b <= a:
            continue
        for j in range(i + 1, len(neighbors)):
            c = neighbors[j]
            if c in adj[b]:
                print(a, b, c)
                exit()
```
