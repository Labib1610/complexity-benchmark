We can solve this by checking all triples in lexicographical order and stopping at the first valid triangle.  
Since \( n \leq 2000 \), a naive triple loop would be \( O(n^3) \), which is too slow.  
Instead, we can iterate over possible smallest vertex \( a \), then over possible \( b > a \), and check if there exists a \( c > b \) connected to both \( a \) and \( b \).  

We can store adjacency as a set for fast lookups.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in range(a + 1, n + 1):
            if b in adj[a]:
                # find smallest c > b connected to both a and b
                for c in range(b + 1, n + 1):
                    if c in adj[a] and c in adj[b]:
                        print(a, b, c)
                        return

if __name__ == "__main__":
    main()
```
