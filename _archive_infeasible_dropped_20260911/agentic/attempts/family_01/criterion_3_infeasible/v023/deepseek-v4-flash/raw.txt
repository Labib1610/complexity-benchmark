We need to find the lexicographically smallest triangle in an undirected graph.

A direct approach:  
- Store edges in a set for O(1) lookup.  
- Iterate over all triples in sorted order and check if all three edges exist.  
- Since n ≤ 2000, O(n³) is too slow (8×10⁹).  

We can do better:  
- For each vertex `a` from 1 to n, consider its neighbors.  
- For each pair of neighbors `b, c` (with b < c), check if edge (b, c) exists.  
- The first found triple in this order is lexicographically smallest because we iterate `a` in increasing order, then `b` in increasing order, then `c` in increasing order.

Complexity: O(m * degree) worst-case, but with m ≤ 2×10⁵ it's fine.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    edges = set()
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        edges.add((u, v))
        edges.add((v, u))
        adj[u].append(v)
        adj[v].append(u)
    
    for a in range(1, n + 1):
        adj[a].sort()
        for i in range(len(adj[a])):
            b = adj[a][i]
            if b <= a:
                continue
            for j in range(i + 1, len(adj[a])):
                c = adj[a][j]
                if c <= b:
                    continue
                if (b, c) in edges:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    main()
```
