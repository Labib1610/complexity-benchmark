We need to find a triangle (3-clique) in an undirected graph, with lexicographically smallest vertex triple.

A direct brute force over all triples is O(n³), which is too slow for n = 2000.  
We can instead iterate over each possible smallest vertex `a`, then try to find the smallest `b > a` such that there exists a `c > b` connected to both `a` and `b`.

We can store adjacency as sets for fast intersection checks.

Here’s the implementation:

```python
import sys

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        for b in sorted(adj[a]):
            if b <= a:
                continue
            # find smallest c > b connected to both a and b
            common = adj[a] & adj[b]
            for c in sorted(common):
                if c > b:
                    print(a, b, c)
                    return

if __name__ == "__main__":
    solve()
```
