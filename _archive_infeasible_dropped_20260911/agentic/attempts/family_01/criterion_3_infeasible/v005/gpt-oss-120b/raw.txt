**Solution Explanation**

For every worker we store the set of his conflicting workers as a bitset.
`bit i` ( `1 ≤ i ≤ n` ) is `1` iff the worker conflicts with worker `i`.

```
adj[v]  – integer, bit i = 1  ⇔  (v , i) is a conflict edge
```

`n ≤ 2000`, therefore one integer (≈ 2000 bits) is enough for every vertex.

--------------------------------------------------------------------

#### Finding the lexicographically smallest triangle  

We have to output the smallest triple `(a,b,c)` with `a<b<c` and all three
edges present.

```
for a = 1 … n
    for b = a+1 … n
        if edge (a,b) exists
            common = adj[a] & adj[b]          # vertices adjacent to both a and b
            # we need the smallest c > b
            common >>= b                      # delete bits ≤ b
            if common != 0:
                low = common & -common        # lowest set bit
                offset = low.bit_length() - 1
                c = b + 1 + offset
                output a b c and finish
```

*Why does this give the lexicographically smallest triangle?*  
The outer loops enumerate `(a,b)` in increasing order (`a` first, then `b`).
For a fixed `(a,b)` we take the smallest possible `c > b`.  
Hence the first triangle we encounter is exactly the lexicographically
smallest one.

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triple
`(a,b,c)` forming a triangle.

---

##### Lemma 1  
For any vertices `a<b`, after `common = adj[a] & adj[b]` and
`common >>= b`, the set bits of `common` correspond exactly to vertices
`c` such that `c>b` and edges `(a,c)` and `(b,c)` exist.

**Proof.**  
`adj[a] & adj[b]` contains exactly the vertices adjacent to **both** `a`
and `b`. Shifting right by `b` removes bits `1 … b`. Therefore the remaining
bits correspond precisely to vertices `c>b` adjacent to both `a` and `b`. ∎



##### Lemma 2  
If `common != 0` after the shift, `c = b+1+offset` computed by the algorithm
is the smallest vertex `c>b` that together with `a,b` forms a triangle.

**Proof.**  
`common` is a positive integer, its lowest set bit `low = common & -common`
represents the smallest index `k` (0‑based) where a bit is `1`.  
Thus `k = offset` is the smallest integer such that bit `k` of `common` is `1`,
i.e. the smallest `c' = b+1+k` satisfying the condition of Lemma&nbsp;1.
Therefore `c` is the smallest possible `c`. ∎



##### Lemma 3  
When the algorithm prints a triple `(a,b,c)`, it is a triangle.

**Proof.**  
The algorithm prints only after confirming that edge `(a,b)` exists
(`(adj[a]>>b)&1 == 1`) and after finding `c` as in Lemma&nbsp;2.
By Lemma&nbsp;2, `c` is adjacent to both `a` and `b`. Hence all three edges
exist, i.e. `(a,b,c)` is a triangle. ∎



##### Lemma 4  
Let `(a\*,b\*,c\*)` be the first triple printed by the algorithm.
Then no triangle `(a',b',c')` with lexicographically smaller order exists.

**Proof.**  
The outer loops enumerate all ordered pairs `(a,b)` with `a<b` in increasing
lexicographic order.  
Consider any triangle `(a',b',c')`. Its pair `(a',b')` will be examined at
some iteration. If `(a',b')` is lexicographically smaller than `(a\*,b\*)`,
the algorithm would have processed it earlier.  
During that iteration, by Lemma&nbsp;2 the algorithm would have found the
smallest possible `c'` (which is exactly the `c'` of the triangle) and would
have printed it, contradicting that `(a\*,b\*,c\*)` is the first output.
Therefore no triangle with a smaller `(a,b)` exists.

If a triangle has the same `(a,b) = (a\*,b\*)` but a smaller `c`,
Lemma&nbsp;2 guarantees the algorithm would have chosen the smallest such `c`,
so `c\*` is already minimal. ∎



##### Theorem  
The algorithm outputs the lexicographically smallest triple
`(a,b,c)` (`a<b<c`) such that all three pairwise conflicts are present.

**Proof.**  
By Lemma&nbsp;3 the printed triple is a triangle.
By Lemma&nbsp;4 no triangle with a smaller lexicographic order exists.
Thus the printed triple is exactly the required answer. ∎

#### Complexity Analysis  

*Building adjacency bitsets*: `O(m)` operations.  
*Main loops*: at most `n·(n-1)/2 ≤ 2·10⁶` iterations.
All operations inside are O(1) bitwise integer ops.

```
Time   : O(n² + m)   ≤ 2·10⁶ + 2·10⁵  well below the limit.
Memory : O(n) integers ≈ 2000·(2000/8) bytes ≈ 0.5 MB.
```

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [0] * (n + 1)          # 1‑based
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(1, n - 1):
        mask_a = adj[a]
        for b in range(a + 1, n):
            if (mask_a >> b) & 1 == 0:
                continue          # edge (a,b) missing
            common = mask_a & adj[b]
            # keep only vertices > b
            common >>= b
            if common:
                low = common & -common          # lowest set bit
                offset = low.bit_length() - 1   # position of that bit
                c = b + 1 + offset
                sys.stdout.write(f"{a} {b} {c}")
                return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
