We can solve this by checking all triples, but with up to n=2000, brute-force checking all triples is too slow (O(n³)). Instead, we can iterate over each pair (a, b) where a < b, and look for the smallest c > b such that edges (a, c) and (b, c) also exist, using a set for fast neighbor lookups. This gives O(m * degree) in worst case, but with m ≤ 2e5 it's acceptable. We must also follow the lexicographic order requirement.

Here's the implementation:

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    m = int(data[1])
    adj = [set() for _ in range(n + 1)]
    idx = 2
    for _ in range(m):
        u = int(data[idx]); v = int(data[idx+1])
        adj[u].add(v)
        adj[v].add(u)
        idx += 2

    # Precompute sorted neighbor lists for each node
    sorted_adj = [sorted(adj[i]) for i in range(n + 1)]

    found = False
    for a in range(1, n + 1):
        for b in sorted_adj[a]:
            if b <= a:
                continue
            # Look for smallest c > b such that both a-c and b-c exist
            for c in sorted_adj[a]:
                if c <= b:
                    continue
                if c in adj[b]:
                    print(a, b, c)
                    found = True
                    break
            if found:
                break
        if found:
            break

if __name__ == "__main__":
    main()
```
