Looking at this problem, I need to find a triangle (3-clique) in an undirected graph, outputting the lexicographically smallest one.

**Approach:**
- For each vertex `a` in increasing order, I look for two neighbors `b` and `c` (both > `a`) that are also connected to each other.
- To check if two neighbors of `a` are connected efficiently, I maintain a set of neighbors for each vertex.
- For each `a`, iterate over pairs of neighbors `(b, c)` with `a < b < c` and check if edge `(b, c)` exists.

**Complexity analysis:**
- The sum of degrees squared could be large in general, but with `m ≤ 2·10^5`, the worst case is a star graph where one vertex has degree `m`. However, a star has no triangles, so we'd scan all pairs of its neighbors (O(m²) ≈ 4·10^10) which is too slow.

**Optimization:** If a vertex `a` has degree `d`, checking all pairs takes O(d²). To bound this, I limit the degree: if `d > √(2m)`, then `a` has many neighbors. But a vertex with degree `d` is part of a triangle if any two of its neighbors are adjacent. 

Actually, a cleaner bound: the sum of `d²` over all vertices is at most `2m · max_degree`. In the worst case (star graph), this is `2m · m = 4·10^10`, too slow.

**Better approach:** Use the fact that we want lexicographically smallest. For each `a`, sort neighbors > `a`. For the check, instead of O(d²) pairs, note that if `a` is in a triangle, we just need to find one. But we need the lex smallest, so we need to find the smallest `b`, then smallest `c`.

For a given `a` with neighbors sorted, for each `b` (in order), check if any neighbor `c > b` of `a` is also a neighbor of `b`. This is O(d) set lookups per `b`, so O(d²) total per `a` in the worst case, but with early termination.

Given constraints (n ≤ 2000, m ≤ 2·10^5), and that a triangle is guaranteed, the early termination helps. With n=2000, even O(n·d²) where d is bounded by the point where we find a triangle should be acceptable in practice, especially since we process `a` in order and stop at the first triangle found.

Let me implement with adjacency sets and early termination:

```python
import sys

def solve():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    adj = [set() for _ in range(n + 1)]
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(1, n + 1):
        neighbors = sorted(x for x in adj[a] if x > a)
        na = adj[a]
        for i in range(len(neighbors)):
            b = neighbors[i]
            nb = adj[b]
            for j in range(i + 1, len(neighbors)):
                c = neighbors[j]
                if c in nb:
                    print(a, b, c)
                    return

solve()
```

This processes `a` in increasing order, `b` in increasing order among neighbors > `a`, and `c` in increasing order among neighbors > `b` of `a`. The first triangle found is lexicographically smallest. Early termination when found keeps it efficient.
