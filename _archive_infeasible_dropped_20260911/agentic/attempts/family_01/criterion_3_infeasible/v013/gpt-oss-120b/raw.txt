**Solution Explanation**

For every operator `v` we store the set of operators that share a tool with `v`.
`n ≤ 2000`, therefore a set can be stored as a bit mask of `n` bits –
a Python integer works perfectly.

```
mask[v]  – integer, bit (u‑1) is 1  ⇔  (v , u) is a record
```

A triangle `a < b < c` exists iff

```
(b is neighbour of a)  and  (c is neighbour of a)  and  (c is neighbour of b)
```

For a fixed pair `(a , b)` the common neighbours are

```
common = mask[a] & mask[b]
```

Only vertices larger than `b` may become the third vertex, therefore we
delete all bits `≤ b`.

```
common &= ~((1 << b) - 1)          # keep only vertices > b
```

If `common` is non‑zero, the least set bit gives the smallest possible `c`
(because we scan `a` and `b` in increasing order).  
The index of the least set bit is obtained by

```
low = common & -common            # isolate lowest 1‑bit
c   = low.bit_length()            # 1‑based vertex number
```

Scanning all pairs `(a , b)` with `a = 1 … n`, `b = a+1 … n`
in this order guarantees that the first triangle we output is the
lexicographically smallest one.

The algorithm runs in  

*`O(n²)`* time – at most `~2·10⁶` iterations, each doing only a few integer
operations, and  

*`O(n)`* memory for the masks.

Both limits satisfy the constraints.

#### Correctness Proof  

We prove that the algorithm outputs exactly the lexicographically smallest
triangle.

---

**Lemma 1**  
For any vertices `a < b`, after the statement  

```
common = mask[a] & mask[b]
common &= ~((1 << b) - 1)
```

`common` contains exactly the vertices `c` such that `c > b` and
edges `(a,c)` and `(b,c)` are present.

*Proof.*  
`mask[a] & mask[b]` keeps precisely the vertices adjacent to **both**
`a` and `b`.  
`(1 << b) - 1` has bits `0 … b-1` set; its bitwise complement has bits
`b … n-1` set.  AND‑ing with this complement removes all vertices `≤ b`
and keeps all `> b`. ∎



**Lemma 2**  
If `common` is non‑zero, `c = (common & -common).bit_length()` is the
smallest vertex `c > b` that together with `a , b` forms a triangle.

*Proof.*  
`common & -common` isolates the least significant 1‑bit of `common`,
i.e. the smallest index among the remaining vertices.
`bit_length()` returns that index (1‑based). By Lemma&nbsp;1 this vertex
is adjacent to both `a` and `b`, and no smaller vertex `> b` has this
property. ∎



**Lemma 3**  
When the algorithm prints a triple `(a,b,c)`, it is a triangle
(`a<b<c` and all three edges exist).

*Proof.*  
The outer loops guarantee `a<b`.  
The inner `if` checks that edge `(a,b)` exists (`mask[a]` contains `b`).  
By Lemma&nbsp;2 the obtained `c` satisfies `c>b` and edges `(a,c)` and
`(b,c)` exist. Hence all three edges are present. ∎



**Lemma 4**  
Let `T` be the lexicographically smallest triangle in the graph.
The algorithm will output `T`.

*Proof.*  
Consider the moment the outer loops reach `a = T₁` (the smallest vertex of
`T`).  
All earlier `a` are `< T₁`; no triangle can start with a smaller first
vertex, otherwise it would be lexicographically smaller than `T`.  
For this `a`, the inner loop iterates `b` increasingly.
When `b = T₂` (the second vertex of `T`) the edge `(a,b)` exists, so the
algorithm examines this pair.  
By Lemma&nbsp;1 the set `common` contains exactly the vertices `c` that
complete a triangle with `a,b`. Since `T₃` is such a vertex and all
vertices `> b` smaller than `T₃` cannot form a triangle (otherwise a
lexicographically smaller triangle would exist), Lemma&nbsp;2 yields
`c = T₃`. The algorithm prints `(a,b,c) = T` and terminates. ∎



**Theorem**  
The algorithm always outputs the lexicographically smallest triple
`a<b<c` that forms a triangle.

*Proof.*  
By Lemma&nbsp;3 any printed triple is a triangle.
By Lemma&nbsp;4 the first printed triangle is exactly the lexicographically
smallest one. Since the algorithm stops after printing, the output
satisfies the specification. ∎



---

#### Complexity Analysis  

*Memory*: `n+1` integers, each ≤ `2ⁿ`, i.e. `O(n)`.

*Time*:  
The double loop runs `∑_{a=1}^{n} (n-a) = n(n-1)/2 = O(n²)` iterations.
Each iteration performs a constant number of bit operations on integers of
size `n ≤ 2000` bits, which is `O(1)` in Python.  
Hence total time `O(n²) ≤ 4·10⁶` operations, well within the limits.

#### Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    masks = [0] * (n + 1)          # 1‑based
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        masks[u] |= 1 << (v - 1)
        masks[v] |= 1 << (u - 1)

    for a in range(1, n + 1):
        mask_a = masks[a]
        for b in range(a + 1, n + 1):
            if (mask_a >> (b - 1)) & 1:          # edge (a,b) exists
                common = mask_a & masks[b]
                # keep only vertices > b
                common &= ~((1 << b) - 1)
                if common:
                    low = common & -common
                    c = low.bit_length()        # 1‑based index
                    print(a, b, c)
                    return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and
conforms to the required input‑output format.
