We can solve this by checking each possible triple in lexicographic order, but that would be too slow for \( n = 2000 \).  
Instead, we can use an adjacency matrix and check triples efficiently.

Here’s the approach:

- Store the graph as a set of neighbors for each node.
- Iterate over `a` from 1 to n.
- For each `a`, iterate over `b > a` that is connected to `a`.
- For each such `b`, check if there is a `c > b` that is connected to both `a` and `b`.
- The first such triple found will be lexicographically smallest.

We can speed up the neighbor check using sets.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
    
    for a in range(n):
        for b in adj[a]:
            if b > a:
                common = adj[a] & adj[b]
                for c in common:
                    if c > b:
                        print(a + 1, b + 1, c + 1)
                        return

if __name__ == "__main__":
    main()
```
