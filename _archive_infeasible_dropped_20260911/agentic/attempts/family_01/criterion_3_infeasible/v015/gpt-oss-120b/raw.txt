**Solution Explanation**

For every worker we know the workers he/she cannot share a shift with.
The pairs form an undirected graph :

* vertices – workers `1 … n`
* edges    – forbidden pairs  

A triple `a<b<c` that cannot be placed into two shifts is exactly a **triangle**
(3‑clique) of this graph: all three edges `{a,b}`, `{b,c}`, `{a,c}` are present.

The task is therefore:

*find the lexicographically smallest triangle in an undirected graph
with `n ≤ 2000` vertices and up to `2·10⁵` edges*.



--------------------------------------------------------------------

#### 1.   Representation – adjacency bitsets  

`n ≤ 2000`, therefore a vertex can be represented by a 2000‑bit integer.
For vertex `v` we store  

```
adj[v]  –  integer whose i‑th bit = 1  ⇔  edge (v,i) exists
```

Memory consumption: `n` integers, each ≤ `2ⁿ`, i.e. < 0.5 MiB.

Building the structure (edges are 1‑based in the input):

```
adj = [0] * n
for each (u,v):
        u -= 1 ; v -= 1                     # to 0‑based
        adj[u] |= 1 << v
        adj[v] |= 1 << u
```

--------------------------------------------------------------------

#### 2.   Searching triangles in lexicographic order  

We iterate `a` from smallest to largest, inside it `b>a`, inside it we look
for the smallest possible `c>b`.

```
for a = 0 … n-1:
        for b = a+1 … n-1:
                if edge a‑b exists:
                        common = adj[a] & adj[b]          # vertices adjacent to both
                        # we need a vertex c > b
                        common_shifted = common >> (b+1)
                        if common_shifted != 0:
                                # lowest set bit = smallest c
                                lsb = common_shifted & -common_shifted
                                rel = lsb.bit_length() - 1          # position inside shifted mask
                                c = b + 1 + rel
                                output a+1, b+1, c+1
                                return
```

Explanation of the bit operations  

* `adj[a] & adj[b]` – all vertices adjacent to **both** `a` and `b`.
* `>> (b+1)`   – remove bits `0 … b`, because we need `c>b`.
* `x & -x` isolates the lowest set bit of a positive integer `x`.
* `bit_length() - 1` converts that isolated bit into its index
  (0‑based inside the shifted mask).

The three nested loops exactly follow the lexicographic order:
the first found triple is the required answer.

Complexity  

*Outer loops* – at most `n·(n‑1)/2 ≤ 2·10⁶` iterations.  
Each iteration performs only a few integer operations on 2000‑bit numbers,
which is far below the time limit.

Memory – `O(n)` integers (≈0.5 MiB).

The problem guarantees existence of at least one triangle, so the algorithm
always terminates with an answer.



--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm outputs the lexicographically smallest triple
`a<b<c` that forms a triangle.

---

##### Lemma 1  
For any vertices `a<b`, the expression  

```
common = adj[a] & adj[b]
candidates = common >> (b+1)
```

contains exactly those vertices `c` with `c>b` that are adjacent to **both**
`a` and `b`.

**Proof.**  
`adj[a]` has a `1` at position `c` iff edge `(a,c)` exists.
Similarly for `adj[b]`.  
Bitwise `&` keeps a `1` at position `c` iff **both** edges exist,
i.e. `c` is adjacent to `a` **and** to `b`.  
Shifting right by `b+1` discards bits `0 … b`; the remaining bits correspond
to vertices with index `>b`. ∎



##### Lemma 2  
If `candidates` is non‑zero, the vertex  

```
c = b+1 + ( (candidates & -candidates).bit_length() - 1 )
```

is the smallest vertex `c>b` adjacent to both `a` and `b`.

**Proof.**  
`candidates & -candidates` isolates the least significant `1` of `candidates`,
i.e. the smallest index inside the shifted mask.  
`bit_length()-1` converts it to that index `rel`.  
Adding `b+1` restores the original vertex number. ∎



##### Lemma 3  
When the algorithm prints a triple `(a,b,c)`, the three edges
`(a,b)`, `(a,c)`, `(b,c)` are all present.

**Proof.**  
The outer test `if (adj[a] >> b) & 1` guarantees edge `(a,b)`.  
`c` is obtained from `common = adj[a] & adj[b]`, therefore `c` belongs to
`common` and is adjacent to both `a` and `b`. ∎



##### Lemma 4  
The algorithm prints the **lexicographically smallest** triangle.

**Proof.**  
The outermost loop enumerates `a` in increasing order.
For a fixed `a`, the middle loop enumerates `b>a` in increasing order.
For a fixed pair `(a,b)`, Lemma&nbsp;2 yields the smallest possible `c>b`.
Consequently the first printed triple is the smallest one in the total order
by `(a,b,c)`. ∎



##### Lemma 5  
If the graph contains any triangle, the algorithm will eventually print one.

**Proof.**  
Take the lexicographically smallest triangle `(a₀,b₀,c₀)`.
During the execution the outer loops will reach exactly this pair `(a₀,b₀)`,
because `a₀` and then `b₀` are iterated over all possible values.
For this pair, by Lemma&nbsp;1 `c₀` belongs to `common`,
hence `candidates` is non‑zero and Lemma&nbsp;2 will select `c=c₀`.
Thus the algorithm prints a triple (the one from Lemma&nbsp;4). ∎



##### Theorem  
The algorithm always terminates and outputs the lexicographically smallest
triple `a<b<c` such that every pair among them is a restricted pair.

**Proof.**  
Termination follows from the finite double loop and immediate return after
printing.  
Existence of a printed triple is guaranteed by Lemma&nbsp;5 (the input
contains at least one triangle).  
By Lemma&nbsp;3 the printed triple is indeed a triangle.
By Lemma&nbsp;4 it is the lexicographically smallest triangle.
∎

#### 4.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)

    adj = [0] * n                # adjacency bitsets, 0‑based vertices

    for _ in range(m):
        u = next(it) - 1
        v = next(it) - 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    for a in range(n):
        mask_a = adj[a]
        for b in range(a + 1, n):
            if (mask_a >> b) & 1:          # edge a‑b exists
                common = mask_a & adj[b]   # vertices adjacent to both
                # keep only vertices with index > b
                cand = common >> (b + 1)
                if cand:
                    lsb = cand & -cand                     # lowest set bit
                    rel = lsb.bit_length() - 1
                    c = b + 1 + rel
                    # output 1‑based, ordered a<b<c
                    sys.stdout.write(f"{a+1} {b+1} {c+1}")
                    return

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input/output format.
