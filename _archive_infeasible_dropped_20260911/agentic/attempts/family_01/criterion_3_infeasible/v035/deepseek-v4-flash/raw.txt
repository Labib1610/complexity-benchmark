We can solve this by representing the graph and looking for a triangle.  
Since `n` can be up to 2000 and `m` up to 200,000, we should avoid an O(n³) search.  

A method:  
- Store adjacency sets for each vertex.  
- Iterate over all edges, check if two endpoints share a common neighbor with ID greater than the larger endpoint to avoid duplicates and to find lexicographically smallest.

```python
import sys

def main():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    adj = [set() for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)
    
    # find lexicographically smallest triangle
    for a in range(1, n + 1):
        for b in sorted(adj[a]):
            if b <= a:
                continue
            # look for c > b in intersection of adj[a] and adj[b]
            # iterate over the smaller set for efficiency
            if len(adj[a]) < len(adj[b]):
                for c in adj[a]:
                    if c > b and c in adj[b]:
                        print(a, b, c)
                        return
            else:
                for c in adj[b]:
                    if c > b and c in adj[a]:
                        print(a, b, c)
                        return

if __name__ == "__main__":
    main()
```
