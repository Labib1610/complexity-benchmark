## What every family file does

Each file `09`–`23` fills exactly one family by writing, for all three criteria:
- `statement.md`  — the problem the model sees (NEVER names the complexity class)
- `reference.py`  — a deterministic Python 3 solution (stdin → stdout)
- `tests/NN.in` + `tests/NN.out` — test cases, with `.out` GENERATED by running the reference
- `validator.py`  — only when `judge: custom` (any-valid-answer problems)

The `meta.yaml` for each criterion is **already filled** (class, intended algorithm, reduction notes). Do not overwrite the `class`, `intended_algorithm`, or `reduction_note` fields. You MAY adjust `judge`, `time_limit_s`, and add `validator.py` where a problem accepts multiple valid answers.

## The fixed procedure for every family (do this each time)

1. **Read** the family's existing `meta.yaml` files to confirm class labels and intended algorithms.
2. **Write the three statements** per `conventions/statement_schema.md`:
   - Plain task description, bounds allowed, at least one worked example each.
   - LEAKAGE RULE: no "NP-complete / polynomial / tree / bipartite / DAG / 2-SAT" as labels, no difficulty hints. Describe structure operationally (e.g. say "each point belongs to exactly one parent and there are no cycles among parents" instead of "the graph is a tree").
3. **Write the three references**: deterministic, match the `intended_algorithm` in meta.yaml, read all stdin, write only the answer. Pin any tie-break the statement promises (e.g. lexicographically smallest) so `judge: exact` has a unique target.
4. **Create test inputs** `tests/01.in`, `02.in`, … : start with the statement's examples, then add small edge cases (minimal sizes, the boundary that triggers infeasibility, empty-constraint cases). Keep them small.
5. **Generate every `.out` by running the reference** on its `.in`. Never hand-write outputs.
6. **Validate**: `python -m harness.reference_check dataset/family_XX_<slug>` and fix every flag (reference mismatch, missing `.out`, leakage term). Re-run until clean.
7. **Report**: show the family tree, the clean reference-check output, and confirm no leakage. Then stop and wait for the next file.

## Important reminders

- Match the Family 1 shape EXACTLY. Family 1 is your reference implementation; open it whenever unsure.
- For the INFEASIBLE criterion: the correct output is a specific sentinel or certificate defined in the statement. A model that returns a confident wrong non-null answer must be judged WRONG_ANSWER — that is the failure mode we measure, so make the expected output crisp.
- Keep references fast enough to pass their own `time_limit_s`. If a reference for a large-bound P problem is slow in Python, use fast I/O (`sys.stdin.buffer.read().split()`).
- Each file is self-contained. After finishing a family, the dataset for that family must pass reference_check before you move on.
