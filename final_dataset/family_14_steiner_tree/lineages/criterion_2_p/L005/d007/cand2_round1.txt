<METHOD_NAME>Inverted Cut-Property Framing</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the objective of 'finding the minimum cost to connect a subset of nodes' with 'finding the sum of costs of edges that, if removed individually, would disconnect the subset'. This mathematically corresponds to the exact same set of edges (the minimal Steiner tree on a tree). Naive implementation of the new objective yields an O(N^2) algorithm which will time out, forcing the model to recognize the underlying tree structure and optimize to O(N) via subtree counting to succeed.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>
<STATEMENT>
# System Redundancy

Time limit: 2 s   Memory limit: 256 MB

## Description

We are analyzing a system of **n** variables, numbered 1 through **n**. A specific subset of **t** variables are designated as *control variables*.

You are provided with a maximal set of **m** equality constraints. Each constraint specifies that two variables **u** and **v** must be equal, and has an associated verification cost **w**. 

It is guaranteed that if all **m** constraints are enforced simultaneously, all **n** variables are forced to take the exact same value. Furthermore, the set of constraints is minimal in achieving this: if we were to drop exactly one constraint from this set of **m**, the variables would no longer be forced to be completely uniform. Instead, the variables would naturally partition into exactly two independent groups. Variables within the same group would still be forced to be equal to each other, but the two groups would be allowed to take on different values from each other.

We define a constraint as *structurally critical* if dropping it (while keeping all other **m** - 1 constraints enforced) allows at least two control variables to take on different values from each other (which occurs if and only if they end up in different groups). If **t** = 1, this is naturally impossible.

Your objective is to determine the sum of the verification costs of all structurally critical constraints.

## Input

The first line provides three integers **n**, **m**, and **t** (1 ≤ **n** ≤ 200000, **m** = **n** - 1, 1 ≤ **t** ≤ **n**).

The second line provides **t** distinct integers representing the identifiers of the control variables.

The subsequent **m** lines each contain three integers **u**, **v**, and **w**. These values describe a constraint specifying that variable **u** and variable **v** must be equal (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), with a verification cost of **w** (1 ≤ **w** ≤ 1000000). It is guaranteed that the full set of **m** constraints forces all **n** variables to be equal.

## Output

Print a single integer indicating the sum of the verification costs of all structurally critical constraints.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the control variables are 1 and 4.
- If we drop the constraint between 1 and 2, the remaining constraints force {2, 3, 4} to be equal, while {1} becomes an independent group. Since control variables 1 and 4 are in different groups, they can take different values. Thus, this constraint is structurally critical (cost 5).
- Dropping the constraint between 2 and 3 allows {1, 2} and {3, 4} to be independent groups, separating the control variables (cost 1). 
- Dropping the constraint between 3 and 4 allows {1, 2, 3} and {4} to be independent, again separating the control variables (cost 2).
All three constraints are structurally critical, so the total sum is 5 + 1 + 2 = 8.

In Example 2, there is only **t** = 1 control variable (variable 3). It is impossible for a single variable to take on different values from itself. Therefore, no constraints are structurally critical, requiring a total cost of 0.
</STATEMENT>
<RATIONALE>
The problem was completely inverted from a minimization objective ("find the minimum cost to connect a subset") to a summation objective ("find the sum of costs of edges that, if removed individually, would disconnect the subset"). This hides the Steiner tree pattern. Naively implementing the exact instructions (removing each constraint and checking groups) yields an O(N^2) algorithm that will fail the generous 2s time limit for N=200,000. To pass, the model must recognize the implicit tree structure and independently derive the O(N) subtree-counting optimization.
</RATIONALE>
<PRESERVED_ANSWER>
Because the original graph is a tree, the minimal connected subgraph containing the target nodes is exactly the union of all simple paths between them; an edge belongs to this union if and only if removing it separates at least two target nodes into different components, making the sum of structurally critical constraints mathematically identical to the minimum Steiner tree weight.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains P (specifically O(N)), as the optimal solution still involves structurally rooting the tree and performing a single post-order traversal to count target variables in each subtree.
</PRESERVED_CLASS>
<RISK>
The phrase "take on different values" could theoretically be misinterpreted as requiring the variables to be different rather than allowing them to be different, but the parenthetical "(which occurs if and only if they end up in different groups)" strictly anchors it to the topological cut property, eliminating ambiguity.
</RISK>
