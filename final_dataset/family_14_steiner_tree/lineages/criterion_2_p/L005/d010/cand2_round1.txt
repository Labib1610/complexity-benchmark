<STATEMENT>
# Critical Component Isolation Analysis

Time limit: 2 s   Memory limit: 256 MB

## Description

You are evaluating a system of **n** components, numbered $1$ to **n**. You are given a set of **t** specific components, designated as the *critical components*.

You are provided with a catalog of **m** bidirectional dependencies. Each dependency exists between a pair of components (**u**, **v**) and has an associated risk factor **w**. The system is fully integrated, meaning the full catalog of **m** dependencies ties all **n** components into a single interdependent structure with no redundancy (it is guaranteed that **m** = **n** - 1). Because of this exact structure, if you were to hypothetically remove any single dependency from the full system, the **n** components would be cleanly partitioned into exactly two disjoint groups, such that no remaining dependencies link a component in one group to a component in the other.

Your task is to identify a specific subset of these **m** dependencies based on the following exact criterion:
A dependency must be included in your subset if and only if its hypothetical removal from the full system would cause the **t** critical components to be distributed across *both* of the resulting disjoint groups (meaning neither group ends up containing all **t** critical components).

Calculate and output the sum of the risk factors of all dependencies that meet this criterion.

## Input

The first line provides three integers **n**, **m**, and **t** (1 ≤ **n** ≤ 200000, **m** = **n** - 1, 1 ≤ **t** ≤ **n**).

The second line provides **t** distinct integers representing the critical components.

The subsequent **m** lines each contain three integers **u**, **v**, and **w**. These values describe a dependency between component **u** and component **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**) with a risk factor of **w** (1 ≤ **w** ≤ 1000000). It is guaranteed that the full set of **m** dependencies integrates all **n** components such that removing any single dependency always partitions the components into exactly two disjoint independent groups.

## Output

Print a single integer indicating the sum of the risk factors of all dependencies that satisfy the inclusion criterion.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the critical components are 1 and 4.
- Removing the dependency (1, 2) splits the system into group {1} and group {2, 3, 4}. The critical components (1 and 4) are separated into different groups. This dependency meets the criterion.
- Removing the dependency (2, 3) splits the system into group {1, 2} and group {3, 4}. The critical components are separated. This dependency meets the criterion.
- Removing the dependency (3, 4) splits the system into group {1, 2, 3} and group {4}. The critical components are separated. This dependency meets the criterion.
All three dependencies are included. The sum of their risk factors is 5 + 1 + 2 = 8.

In Example 2, there is only 1 critical component (component 3). When any dependency is hypothetically removed, the single critical component will entirely belong to one of the two resulting groups. It is impossible for it to be distributed across both groups. Therefore, no dependencies meet the criterion, and the sum is 0.

<RATIONALE>
The problem has been completely reframed from an optimization task ("find the minimum cost to connect via paths") to a deterministic filtering task ("sum the weights of dependencies whose removal partitions the target set"). This removes all graph, tree, path, and minimization vocabulary. Models relying on surface patterns will likely simulate the removal in O(N^2) and fail via Time Limit Exceeded, while models that genuinely reason will recognize that this definition is mathematically isomorphic to the invariant used in O(N) subtree counting.
</RATIONALE>
<PRESERVED_ANSWER>
In a tree, an edge lies on a path between two target vertices if and only if removing that edge separates the target set into two non-empty components; therefore, the exact same subset of edges is selected and their sum is identical.
</PRESERVED_ANSWER>

The complexity class remains unchanged because the exact same O(N) algorithm (rooting the tree and counting critical components in subtrees to determine if an edge splits the set) perfectly satisfies the new inclusion criterion.
</PRESERVED_CLASS>
