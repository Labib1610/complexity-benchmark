<METHOD_DESCRIPTION>Instead of asking for the minimum subgraph connecting a set of vertices, the problem defines "essential" edges as those lying on the unique path between at least one pair of priority vertices, and asks for the sum of their costs. This breaks the standard "Steiner tree on tree" pattern matching while mathematically defining the exact same set of edges.</METHOD_DESCRIPTION>

<STATEMENT>
# Priority Site Connectivity

Time limit: 2 s   Memory limit: 256 MB

## Description

An infrastructure project defines **n** substations, indexed from 1 to **n**. You are provided with a list of **t** substations designated as priority locations. There are also **m** proposed communication lines, each connecting a pair of substations for a specific resource cost. 

The proposed lines are arranged such that a signal can be routed between any two substations via exactly one unique sequence of lines.

A proposed line is considered *essential* if it is part of the unique sequence of lines connecting at least one pair of priority substations. If **t** is 1, there are no valid pairs, and thus no lines are essential.

Your task is to calculate the sum of the resource costs of all essential lines, counting each essential line exactly once. This value represents the minimum total resource cost required to activate a subset of lines such that all priority substations can communicate with one another, either directly or by relaying through other substations.

## Input

The first line contains three integers **n**, **m**, and **t**. The constraints are 1 ≤ **n** ≤ 200000, **m** = **n** - 1, and 1 ≤ **t** ≤ **n**.

The second line contains **t** distinct integers: the indices of the priority substations.

The following **m** lines each contain three integers **u**, **v**, and **w**. These specify a proposed line between substation **u** and substation **v** (with 1 ≤ **u**, **v** ≤ **n** and **u** ≠ **v**) having a resource cost of **w** (1 ≤ **w** ≤ 1000000).

## Output

Print a single integer representing the minimum total resource cost required to link all priority substations.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1 the priority substations 1 and 4 are joined only through 2 and 3, so all three lines (5+1+2 = 8) are needed. In Example 2 there is one priority substation, so no lines are needed.
</STATEMENT>
<RATIONALE>
The problem was reframed to ask for the sum of edges that lie on the path between any pair of priority vertices. This breaks the direct "Steiner tree on tree" pattern matching by presenting it as a path-union problem, while explicitly tying it back to the original optimization objective to satisfy the strict checker constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The union of paths between all pairs of priority vertices in a tree is exactly the minimal subtree connecting them, so the sum of their costs is identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying graph is still a tree and the required edges are identical, so it remains solvable in O(n) time using post-order traversal or leaf pruning.
</PRESERVED_CLASS>
<RISK>
Models might misunderstand "counting each essential line exactly once" if they attempt to sum paths naively, though this is a desired failure mode rather than an ambiguity in the statement.
</RISK>
