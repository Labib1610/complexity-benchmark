# Phase 3: Synchronization Energy

Time limit: 2 s
Memory limit: 256 MB

## Description

The facility's emergency response protocol consists of four automated phases. You are responsible for programming Phase 3.

- **Phase 1 (Detection)**: The system initializes $n$ hardware modules (numbered $1$ to $n$) and a fixed infrastructure of $m$ bidirectional power relays. To save on material costs while ensuring full coverage, the relays are arranged to form a minimally connected network: all modules are linked into a single grid, but there are no redundant relays that would provide alternate routes between any two modules.
- **Phase 2 (Flagging)**: A diagnostic scan identifies exactly $t$ modules that require immediate synchronization.
- **Phase 3 (Synchronization - Your Task)**: The central system must activate a subset of the relays. The chosen relays must form a single, contiguous active grid that allows all $t$ flagged modules to communicate with one another (unflagged modules may also be included in this active grid). Each relay requires a specific energy expenditure to activate. The system must calculate the absolute minimum total energy required to achieve this.
- **Phase 4 (Purge)**: The synchronized modules execute a distributed memory purge.

Given the infrastructure layout and the list of flagged modules from Phase 2, calculate the minimum total energy expenditure required to complete Phase 3.

## Input

The first line contains three integers $n$, $m$, and $t$ ($1 \le t \le n$, $1 \le n \le 200000$, $m = n - 1$).
The second line contains $t$ distinct integers: the identifiers of the flagged modules.
Each of the next $m$ lines contains three integers $u$, $v$, and $w$ ($1 \le u, v \le n$, $u \neq v$, $1 \le w \le 1000000$): a relay connecting module $u$ to module $v$ requiring $w$ units of energy to activate. The relays form the infrastructure described in Phase 1.

## Output

Print a single integer: the minimum total energy required to link all flagged modules.

<RATIONALE>
The direct statement that "between any two modules there is exactly one valid sequence of relays" was removed. Instead, the problem now describes the network as "minimally connected" with "no redundant relays that would provide alternate routes." This forces the model to deduce the tree structure from these physical properties rather than relying on explicit combinatorial phrasing, requiring it to reason about the topology to realize that pruning empty subtrees is the optimal and only way to form the minimal network.
</RATIONALE>
<PRESERVED_ANSWER>
The problem still asks for the minimum weight of a connected subgraph containing a specific set of vertices in the exact same input graph, so the optimal cost remains identical for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying graph is still a tree where we must find the minimum weight subtree spanning a set of terminal nodes, which is solvable in O(n) time by pruning leaves that do not contain any terminals.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "no alternate routes between any two modules" if they fail to link it to the definition of a tree, but to a human reader, a connected graph with no alternate paths between any pair of nodes unambiguously defines a tree.
</RISK>
