# Permutation Orbit Cost

Time limit: 2 s
Memory limit: 256 MB

## Description

You are analyzing the symmetric group $S_n$ acting on a set of **n** positions, numbered 1 to **n**. Initially, you have the trivial subgroup containing only the identity permutation.

You are provided with a list of **m** available generators. Each generator is a transposition that swaps the elements at position **u** and position **v**. Enabling a generator includes it in your active generating set and incurs a cost of **w**. 
The full list of available transpositions forms a minimal generating set for $S_n$. Consequently, there are exactly **m** = **n** − 1 available transpositions, and if you were to enable all of them, the resulting generated subgroup would be the entire symmetric group, meaning its natural action would have a single orbit covering all **n** positions.

Your objective is to enable a subset of these transpositions such that the subgroup they generate satisfies a specific condition: a given list of **t** target positions must all belong to the same orbit. (Two positions are in the same orbit if there exists some permutation in the generated subgroup that maps one position to the other). You do not care about the orbit structure of the remaining positions, though some may end up in the target orbit as a mathematical consequence of your chosen subset.

What is the minimum total cost (the sum of the costs of the enabled transpositions) required to ensure all **t** target positions are in the same orbit?

## Input

The first line contains three integers **n**, **m**, and **t**. The number of positions is **n** (1 ≤ **n** ≤ 200000). The number of available transpositions **m** is always exactly **n** − 1. The number of target positions is **t** (1 ≤ **t** ≤ **n**).
The second line contains **t** distinct integers: the identifiers of the target positions.
Each of the next **m** lines contains three integers **u**, **v**, and **w**. These denote an available transposition between position **u** and position **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), which costs **w** to enable (1 ≤ **w** ≤ 1000000).

## Output

Print a single integer: the minimum total cost required.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

<RATIONALE>
The problem was reframed from enforcing equality constraints to finding a minimum-cost subset of transpositions that places a set of target positions in the same orbit. This forces the model to deduce that a minimal generating set of transpositions corresponds to a tree, and that orbits correspond to connected components, requiring genuine structural reasoning rather than pattern matching on "variables equal".
</RATIONALE>
<PRESERVED_ANSWER>
The subset of transpositions placing the targets in the same orbit matches exactly the subset of edges connecting the targets in the tree, so the minimum cost is identical for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying structure remains finding the unique minimal spanning subtree for a set of vertices in a given tree, which is solvable in linear time.
</PRESERVED_CLASS>
<RISK>
Models or readers lacking background in basic abstract algebra might find "minimal generating set for $S_n$" or "orbit" confusing, though these are standard concepts unambiguously defined in the text.
</RISK>
