This strips away graph-algorithm affordances like "subtree", "pruning", or "leaves", forcing the model to re-derive the tree-pruning logic from first principles of the connectivity constraint.</METHOD_DESCRIPTION>

<STATEMENT>
# Emergency Pressurization

Time limit: 2 s   Memory limit: 256 MB

## Description

An orbital station is composed of **n** modules, identified by integers from 1 to **n**. These modules are physically linked by **m** structural corridors. The architecture of the station guarantees that the entire facility is fully contiguous, and that there is exactly one unique sequence of corridors connecting any pair of modules without retracing steps.

Due to a reactor failure, the station must operate on emergency power. There are **t** critical modules that house essential life-support systems. You must determine the emergency state of each corridor. Each corridor $i$ must be assigned a state $x_i \in \{0, 1\}$, where $x_i = 1$ means the corridor is kept pressurized, and $x_i = 0$ means it is depressurized and impassable.

A corridor $i$ requires a continuous power draw of **w**$_i$ to remain pressurized. Your objective is to minimize the total power draw, which is calculated as the sum of **w**$_i \times x_i$ over all **m** corridors.

This minimization is subject to a strict functional connectivity constraint: for every pair of critical modules, there must exist at least one sequence of corridors connecting them such that every corridor in the sequence has been assigned the state $x_i = 1$. Non-critical modules may freely be included in these sequences to serve as transit nodes.

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ **t** ≤ **n**, 1 ≤ **n** ≤ 200000, **m** = **n** − 1). The given corridors strictly satisfy the unique connectivity guarantee described above.
The second line contains **t** distinct integers: the identifiers of the critical modules.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**, 1 ≤ **w** ≤ 1000000), representing a corridor linking module **u** and module **v** that requires **w** units of power to pressurize.

## Output

Print a single integer: the minimum total power draw required to keep all critical modules functionally interconnected.

</STATEMENT>
<RATIONALE>
The problem objective is recast from "choosing a collection of corridors to keep pressurized" into an integer linear programming (ILP) style format where each corridor is assigned a binary state $x_i \in \{0, 1\}$. The total cost is represented as a sum of products, and the connectivity requirement is framed as a pairwise reachability constraint over the $x_i = 1$ edges. This removes standard graph terminology and affordances ("subnetwork", "pruning", "minimal subtree") while mathematically demanding the exact same properties.
</RATIONALE>
<PRESERVED_ANSWER>
Minimizing the sum of weights for a subset of edges such that all critical nodes remain connected in a tree is mathematically identical to finding the minimum weight subtree spanning those nodes, yielding the exact same output.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains the Steiner tree problem on a tree, which is solvable in polynomial $O(n)$ time using standard traversals.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the $x_i \in \{0, 1\}$ framing as an NP-hard general ILP if they fail to recognize the structural guarantees implicitly provided by $m = n - 1$ and the unique path constraint, though the text is perfectly unambiguous.
</RISK>
