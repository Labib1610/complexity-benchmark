<STATEMENT>
# Facility Linkage

Time limit: 2 s   Memory limit: 256 MB

## Description

A facility consists of $n$ distinct locations. Certain pairs of locations can be linked via dedicated infrastructure segments, each with an associated activation cost. A specific subset of these locations, numbering $t$ in total, are designated as critical. All critical locations must be able to communicate with one another, either directly or by relaying through other linked locations.

The provided infrastructure segments connect all locations in the facility. To minimize initial construction, the network is built such that removing any single segment partitions the facility into disconnected zones. You must select a subset of the available segments to activate such that all critical locations are mutually reachable, while minimizing the sum of the activation costs.

## Input

The first line contains three integers $n$, $m$, and $t$. The facility can be as small as a single location, and its database supports a maximum capacity of 200,000 locations. The inventory of segments $m$ is exactly the number of locations minus one. The critical location headcount $t$ requires at least one location and can encompass the entire facility.

The second line provides $t$ distinct integers: the identifiers of the critical locations.

Each of the subsequent $m$ lines contains three integers $u$, $v$, and $w$. These represent an infrastructure segment joining location $u$ and location $v$. The identifiers $u$ and $v$ are distinct valid location numbers (from 1 to $n$). The activation cost $w$ has a base hardware cost of at least 1 and a maximum theoretical limit of 1,000,000.

## Output

Print a single integer: the minimum total activation cost required to ensure all critical locations are connected.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the critical locations 1 and 4 can only communicate by relaying through 2 and 3, so all three segments (costs 5, 1, and 2, totaling 8) must be activated. In Example 2, there is only one critical location, so no segments need to be activated.
</STATEMENT>
<RATIONALE>
I removed the explicit mention of "exactly one possible route" and replaced it with a mechanical description of a tree ("removing any single segment partitions the facility"). This forces the model to deduce the tree structure from the graph's bridge properties rather than matching the "unique route" keyword. I also applied the S07 strategy by replacing bare inequalities with scenario-based constraints (e.g., "maximum capacity of 200,000 locations").
</RATIONALE>
<PRESERVED_ANSWER>
The underlying graph and the objective to find the minimum cost to connect a subset of nodes remain identical, so the required subset of edges and total cost are unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The graph is still a tree (connected, and every edge is a bridge), so finding the minimum connected subgraph spanning the critical nodes is still solvable in linear time using tree traversal.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "removing any single segment partitions the facility" as a property to be checked dynamically rather than a guaranteed property of the input graph, though "the network is built such that" should clarify it is a given guarantee.
</RISK>
