# Permutation Puzzle Simplification

Time limit: 2 s   Memory limit: 256 MB

## Description

You are analyzing a mechanical puzzle consisting of **n** registers, numbered 1 to **n**, each initially holding a distinct value. The puzzle includes a set of allowed swap operations. Each operation allows you to exchange the values held in register **u** and register **v**, and has an associated fatigue cost of **w**.

A subset of registers **S** is considered *fully permutable* if, by applying a sequence of only those swap operations that exchange two registers both located within **S**, you can arrange the values currently held in **S** into any arbitrary permutation. (A subset containing exactly one register is inherently fully permutable). Initially, the full set of **n** registers is fully permutable. Furthermore, the puzzle uses a minimal generating set of swaps: it contains the absolute minimum number of swap operations required to make all **n** registers fully permutable.

You may simplify the puzzle by performing a sequence of register lock-downs. In a single step, you permanently lock exactly one register. Locking a register completely disables any swap operation that involves it. However, your lock-down sequence must satisfy two strict safety regulations:
1. You may never lock any of the **t** *target registers*, as they are required for the puzzle's final state.
2. After every individual lock-down step, the subset of remaining unlocked registers must still be *fully permutable*. If locking a register would restrict the remaining unlocked registers such that not all permutations of their values can be achieved, that register cannot be locked at that time.

You can stop the lock-down process at any point, including making no lock-downs at all. Your objective is to determine the minimum possible total fatigue cost of the swap operations that remain enabled in the puzzle when you finish.

## Input

The first line provides three integers **n**, **m**, and **t** (1 ≤ t ≤ n, 1 ≤ n ≤ 200000, **m** equals the absolute minimum number of swaps needed to make **n** registers fully permutable).
The second line provides **t** distinct integers representing the indices of the target registers.
Each of the subsequent **m** lines provides three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), indicating a swap operation between register **u** and register **v** with a fatigue cost of **w**.

## Output

Output a single integer representing the minimum possible total fatigue cost of the remaining swap operations after a valid sequence of lock-downs.

<RATIONALE>
The problem was disguised by mapping graph connectivity to permutation group generation. A set of transpositions (swaps) generates the full symmetric group on a set of elements if and only if the transposition graph is connected. Consequently, a "minimal generating set" of swaps implies the graph is a tree (forcing $m = n - 1$). The model must now genuinely recognize this isomorphism to deduce that it is solving a Steiner tree problem via leaf pruning, rather than relying on explicit graph terminology or the explicit $m=n-1$ bound.
</RATIONALE>
<PRESERVED_ANSWER>
The condition "fully permutable" is mathematically identical to the vertices being connected, and a "minimal generating set" ensures the initial structure is a tree, meaning the valid lock-downs perfectly mirror the allowed variable eliminations in the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying structure remains exactly finding the minimal connected subtree spanning a set of target nodes in a tree, which is solvable in $O(N)$ time.
</PRESERVED_CLASS>
