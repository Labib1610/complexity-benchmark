<STATEMENT>
# Problem B — Activating the Primary Network

Time limit: 2 s   Memory limit: 256 MB

## Description

A vast research complex comprises a certain number of outposts **n**, identified sequentially from 1 to **n**. The complex's registry system is designed to handle up to exactly 200,000 outposts. You are given a ledger of **m** potential bidirectional fiber-optic connections that can be powered on between specific pairs of outposts. The total count of these potential connections **m** is always exactly one less than the total number of outposts **n** in the complex. Each connection requires a certain power draw **w** to activate, which is at least 1 and never exceeds 1,000,000.

A select committee of **t** outposts are designated as **primary** hubs. This committee could be as small as a single outpost, or it could include every outpost in the complex. Your goal is to select a subset of the potential fiber-optic connections to power on, ensuring that every primary hub can exchange data with every other primary hub (data may seamlessly route through any powered-on intermediate outposts). Calculate the absolute minimum total power draw necessary to achieve this. You are guaranteed that the provided connections are sufficient to link all primary hubs together.

## Input

The first line contains three integers **n**, **m**, and **t**: the number of outposts, the number of potential connections, and the number of primary hubs.
The second line contains **t** distinct integers: the identifiers of the primary hubs.
Each of the next **m** lines describes a potential connection with three integers **u**, **v**, and **w**: the two outposts it connects (where **u** ≠ **v**), and the power draw **w** required.

## Output

Print a single integer: the absolute minimum total power draw required to fully connect all primary hubs.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the primary hubs 1 and 4 can only communicate if the connections between (1,2), (2,3), and (3,4) are all powered on. The total power draw is 5 + 1 + 2 = 8.
In Example 2, there is only one primary hub, so no connections need to be powered on.
In Example 3, primary hubs 1, 2, and 3 must all be connected. Powering on the connection between 1 and 2 drawing 4 units, and the connection between 2 and 3 drawing 5 units achieves this for a total draw of 9.
</STATEMENT>
<RATIONALE>
The explicit guarantee that the network is fully connected (and thus a tree) was removed, leaving only the guarantee that the primary hubs can be linked. To succeed, a model must either deduce that a graph with $m = n - 1$ must be a tree to be tractable at $n=200,000$, or blindly assume it. Models that pattern-match this to a general Steiner Tree problem will attempt an NP-hard algorithm and fail on the time limit. Numeric bounds were also integrated into the scenario text (Strategy S07).
</RATIONALE>
<PRESERVED_ANSWER>
The actual test cases are unchanged (they are still trees), so the minimum cost to connect the primary hubs remains exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
Because the underlying inputs are always trees, finding the minimal connecting subgraph is still solvable in O(n) polynomial time, keeping it in P.
</PRESERVED_CLASS>
<RISK>
Models might assume the graph is disconnected and contains cycles, leading them to write a general Steiner Tree algorithm. This is intentional and not an ambiguity in the task, but rather a trap for models that fail to reason about tractability.
</RISK>
