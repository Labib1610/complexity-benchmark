<STATEMENT>
# Core Synchronization Network

Time limit: 2 s   Memory limit: 256 MB

## Description

A distributed computing cluster consists of $n$ processing modules, numbered $1$ to $n$. These modules are linked by $m$ bidirectional data buses. The cluster's architecture ensures that all modules are interlinked in a single contiguous network. To reduce hardware redundancy, the total number of buses $m$ is strictly fixed at exactly $n - 1$, meaning there is exactly one unique sequence of buses between any two processing modules.

A specific subset of $t$ modules are designated as core modules. These core modules must be able to synchronize and exchange data with one another.

Initially, all data buses are in a dormant state. Before synchronization can occur, you must select a set of buses to activate. Activating the bus between module $u$ and module $v$ incurs a one-time calibration cost of $w$. Once a bus is activated, data can flow across it in either direction without any additional cost. Buses that remain dormant cannot transmit data.

Your task is to determine the minimum possible total calibration cost required to activate a set of buses such that all $t$ core modules can successfully exchange data with each other, possibly routing through other non-core modules. If $t=1$, the minimum total calibration cost is 0.

## Input

The first line provides three integers: $n$, $m$, and $t$. The facility's blueprint supports up to two hundred thousand modules ($1 \le n \le 200000$). The number of buses $m$ is always $n - 1$. The number of core modules $t$ can range from a single module up to the entire cluster ($1 \le t \le n$).

The second line contains exactly $t$ distinct integers representing the IDs of the core modules.

Following this, there are $m$ lines, each detailing a single data bus with three integers: $u$, $v$, and $w$ ($1 \le u, v \le n$, $u \neq v$). The calibration cost $w$ for activating any single bus is at least one and does not exceed one million units ($1 \le w \le 1000000$). 

## Output

Print a single integer: the minimum total calibration cost required.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the core modules are 1 and 4. To allow them to exchange data, the buses between 1 and 2 (cost 5), 2 and 3 (cost 1), and 3 and 4 (cost 2) must be activated. The total cost is 5 + 1 + 2 = 8.
In Example 2, there is only one core module (module 3). Since no data exchange with other core modules is needed, no buses need to be activated. The minimum possible total cost is 0.
</STATEMENT>
<RATIONALE>
The problem was reframed from a routing/tour scenario to a network synchronization requirement. This breaks the pattern-matching affordance where models associate "visiting all required stations" on an $n-1$ edge network directly with computing the weight of a minimal spanning subtree. The underlying logic remains identical.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that all core modules must be able to exchange data across activated buses is mathematically identical to finding the minimal connected subgraph containing all core modules, which inherently costs the same as the original valid tour.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class is unchanged because the graph structure remains a weighted network with exactly $n-1$ edges and a single simple path between any pair of nodes, meaning the required optimal structure is still a uniquely determined minimal subtree.
</PRESERVED_CLASS>
