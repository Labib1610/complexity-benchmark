# Subsystem Calibration

Time limit: 2 s   Memory limit: 256 MB

## Description

A computing cluster contains a number of distinct processing modules, numbered sequentially starting from 1. These are connected by bidirectional data buses. The architecture guarantees that all modules are part of a single contiguous network, and the total number of buses is strictly fixed at exactly one less than the number of modules.

A specific subset of these modules are designated as core modules. 

Initially, all buses are uncalibrated and cannot transmit data. You must select a set of buses to calibrate. Calibrating the bus between module $u$ and module $v$ requires a one-time calibration time of $w$. Once calibrated, a bus can transmit data in both directions. Buses that are not calibrated cannot be used.

Your task is to determine the minimum possible total calibration time required to calibrate a set of buses such that all core modules can communicate with each other. This means there must be a path of calibrated buses between any two core modules, possibly routing through other non-core modules. If there is only a single core module, it is considered trivially connected to itself.

## Input

The first line provides three integers: the total number of processing modules, the number of data buses, and the number of core modules. The facility's power grid can support up to 200,000 processing modules. The number of data buses is always exactly the number of modules minus one. The number of core modules can range from a single module up to the entire deployed cluster.

The second line contains the distinct integer IDs of the core modules.

Following this, there are as many lines as there are buses, each detailing a single data bus with three integers: the IDs of the two distinct modules it connects, and its calibration time. The calibration time for any single bus is at least 1 microsecond and is capped by the protocol's maximum allowed delay of 1,000,000 microseconds.

## Output

Print a single integer: the minimum total calibration time required.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the core modules are 1 and 4. To connect module 1 and module 4, the sequence of buses between them must be calibrated. This consists of the bus between 1 and 2 (time 5), the bus between 2 and 3 (time 1), and the bus between 3 and 4 (time 2). The total calibration time is 5 + 1 + 2 = 8.
In Example 2, there is only one core module (module 3). Since a single module is trivially connected to itself, no buses need to be calibrated. The minimum possible total time is 0.

<RATIONALE>
I removed the explicit mention of "unique sequence of belts" which spoon-fed the tree property and its implications to the models. I also adjusted the numeric bounds to be described indirectly through the scenario (S07), and refined the objective to simply connecting the required modules, removing the ambiguous "starting location" choice that caused task drift in previous attempts.
</RATIONALE>
<PRESERVED_ANSWER>
Connecting all designated modules in a tree requires exactly the edges of the minimal subtree containing them, which is mathematically identical to the minimum edges needed for a tour starting from an optimally chosen node.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains finding the weight of the minimal subtree connecting a set of vertices, which is solvable in O(n) time on trees.
</PRESERVED_CLASS>
<RISK>
Models might assume the network is not a tree if they fail to deduce it from the $m = n - 1$ and "contiguous network" constraints.
</RISK>
