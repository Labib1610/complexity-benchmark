<STATEMENT>
# Protocol Compilation

Time limit: 2 s   Memory limit: 256 MB

## Description

A secure communication framework utilizes **n** distinct cryptographic keys. There are **m** bidirectional translation protocols, each enabling direct conversion between a specific pair of keys. The framework is completely integrated, meaning any key can ultimately be translated into any other key through some sequence of protocols.

Among the keys, **t** of them are designated as *master keys*. To guarantee seamless high-level operations, you must select a subset of translation protocols to pre-compile. 

Because the framework has exactly **n** keys and **m** = **n** − 1 protocols with no isolated segments, there is exactly one sequence of protocols connecting any two keys. The security requirement states that for every possible pair of master keys, every single protocol in the sequence between them must be included in your pre-compiled subset. Each protocol is pre-compiled at most once and its memory cost is paid only once, even if it serves multiple pairs of master keys.

Pre-compiling the protocol that converts between key **u** and key **v** requires **w** bytes of dedicated memory.

Determine the minimum total memory required to pre-compile a subset of protocols that satisfies this strict security requirement.

## Input

The first line contains three integers **n**, **m**, and **t**. The framework supports up to 200000 keys (1 ≤ **n** ≤ 200000). The number of master keys **t** is between 1 and **n**. To enforce strict hierarchical security, the number of translation protocols **m** is exactly one less than the number of keys (**m** = **n** − 1).

The second line contains **t** distinct integers: the identifiers of the master keys.

Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), representing a translation protocol between key **u** and key **v**. Pre-compiling this protocol consumes **w** bytes of memory (1 ≤ **w** ≤ 1000000). The protocols form the completely integrated framework described above.

## Output

Print a single integer: the minimum total memory required to pre-compile the necessary protocols.

## Examples

### Example 1

**Input**
```
4 3 2
1 4
1 2 5
2 3 1
3 4 2
```

**Output**
```
8
```

### Example 2

**Input**
```
5 4 1
3
1 2 4
2 3 6
3 4 2
4 5 9
```

**Output**
```
0
```

### Example 3

**Input**
```
3 2 3
1 2 3
1 2 4
2 3 5
```

**Output**
```
9
```

## Note

In Example 1, the master keys 1 and 4 have a fundamental sequence passing through keys 2 and 3. Therefore, all three protocols in this sequence (consuming 5, 1, and 2 bytes) must be pre-compiled, for a total of 8 bytes.
In Example 2, there is only one master key, meaning there are no pairs of master keys. Thus, 0 protocols need to be pre-compiled.

The scenario was entirely replaced with a cryptographic protocol compilation setting. To break the pattern matching of "connect all special nodes" -> "Steiner tree on tree" -> "leaf pruning", the requirement is reframed as ensuring the unique path between every possible pair of master keys is fully included in the selected subset. This forces the model to mathematically realize that the union of all paths between terminals in a tree is equivalent to the minimal spanning subtree, rather than relying on surface-level keyword triggers.
