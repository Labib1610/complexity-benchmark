<STATEMENT>
# Problem A — Establishing Equivalences

Time limit: 5 s   Memory limit: 256 MB

## Description

You are auditing a ledger of **n** corporate accounts, indexed from 1 to n. There are **m** available bilateral audit procedures you can commission. Commissioning a specific procedure to compare two accounts requires a known fee.

Each commissioned procedure provides a binding certificate that the two specified accounts hold identical balances. These certificates can be combined using the transitive property of equality: if you hold a certificate proving account A equals account B, and another proving account B equals account C, it is legally established that account A equals account C.

Among all the accounts, a specific subset of **t** accounts are flagged for regulatory review. 

Your objective is to commission a set of procedures such that the resulting certificates are sufficient to legally establish that every flagged account holds exactly the same balance as every other flagged account. You may commission procedures involving unflagged accounts; their equivalences can be used as intermediate logical steps in your deductions.

Calculate the minimum possible total fee required to commission a valid set of procedures that establishes this mutual equivalence among all flagged accounts.

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2).
The second line contains **t** distinct integers: the identifiers of the flagged accounts.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000): a potential audit procedure comparing account u and account v that requires a fee of w.
The potential procedures are sufficient to allow all flagged accounts to be proven identical.

## Output

Print a single integer: the minimum total fee of the commissioned procedures required to legally establish that all **t** flagged accounts are mutually equivalent.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, commissioning the procedures between account 4 and each of the three flagged accounts (fees 1+1+1 = 3) successfully establishes that all flagged accounts are identical. This is more efficient than only commissioning procedures directly between the flagged accounts (which would require a fee of at least 4). In Example 3, there is only one flagged account, which is trivially equivalent to itself, so no procedures need to be commissioned.
</STATEMENT>
<RATIONALE>
The explicit graph-connectivity phrasing ("sequence of active links", "merges into a single database") was replaced with a logical deduction scenario based on the transitive property of equality. This removes the spatial and network keywords that trigger standard Steiner Tree templates, forcing the model to recognize that establishing mutual equivalence among a subset of variables via pairwise relations is structurally identical to finding a minimum-cost connected subgraph containing those terminals.
</RATIONALE>
<PRESERVED_ANSWER>
The cost to legally establish equivalence among the $t$ accounts using transitive pairwise relations is exactly the minimum cost to form a connected component containing those $t$ nodes in the corresponding graph, which is identical to the original Steiner Tree formulation.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains Exact Steiner Tree on graphs (NP-complete), as the underlying mathematical structure of finding a minimum-weight edge subset that connects a given set of terminal vertices has not changed.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "legally establish that every flagged account holds exactly the same balance" as requiring all $n$ accounts to be proven equal, though the wording explicitly restricts the mutual equivalence requirement to the flagged accounts.
</RISK>
