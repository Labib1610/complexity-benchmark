# Problem A — Secure Key Recovery Protocol

Time limit: 5 s
Memory limit: 256 MB

## Description

You are designing a secure recovery protocol for a distributed system. The system uses a set of independent random cryptographic keys, indexed from $1$ to $n$.

Within this system, there is a specific target set $T$ containing $t$ distinct critical keys.

You are provided with a pool of $m$ available pairwise combinations. Each combination allows you to securely compute and publish the bitwise XOR of two specific keys, $u$ and $v$. Publishing this combination incurs a computational cost $w$.

Your objective is to select a subset of these combinations to publish, such that an operator who possesses *any single* key from the target set $T$ can use the published XOR values to uniquely determine the exact values of *all other* keys in the target set $T$. 

(Note that the operator does not know any key initially, except for the single critical key they are given. They must be able to chain the published XOR values to derive the others. Keys not in $T$ may be involved in the published combinations and can be safely used as intermediate stepping stones.)

Find the minimum possible total sum of the costs of the selected combinations.

## Input

The first line provides three integers **n**, **m**, and **t**. These represent the total number of keys, the number of available combinations, and the number of critical keys, respectively. (It is guaranteed that **t** is between $1$ and the number of years in a decade, inclusive; **n** is between $1$ and the square of the maximum possible value of **t**, inclusive; and **m** is between $0$ and the maximum possible number of unique pairs of keys, inclusive).

The second line lists **t** distinct integers representing the indices of the critical keys in the target set $T$.

Following this, there are **m** lines. Each line provides three integers **u**, **v**, and **w** ($1 \le \mathbf{u}, \mathbf{v} \le \mathbf{n}$, $\mathbf{u} \neq \mathbf{v}$), indicating that the XOR of key **u** and key **v** can be published for a cost of **w** (where **w** is a strictly positive integer not exceeding one million).

It is guaranteed that the available combinations provide at least one valid way to satisfy the conditions.

## Output

Output a single integer representing the minimum possible total sum of the costs of the selected combinations.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, the critical keys are 1, 2, and 3. We can select the combinations (1, 4), (2, 4), and (3, 4), which incurs a total cost of 1 + 1 + 1 = 3.
- If an operator holds key 1, they can compute key 4 since the XOR of 1 and 4 is published (i.e., $K_4 = K_1 \oplus (K_1 \oplus K_4)$).
- Using the derived key 4, they can then compute key 2 (using the XOR of 2 and 4) and key 3 (using the XOR of 3 and 4).
- Thus, holding only key 1 allows the exact determination of all other critical keys.
- By symmetry, holding only key 2 or only key 3 also allows determining all other critical keys.
This selection is valid and optimal. (Selecting combinations only among the critical keys, such as (1, 2) and (2, 3), would incur a cost of at least 4).

In Example 3, the target set $T = \{1\}$ has only one critical key. We can select an empty set of combinations.
- The requirement states that an operator holding any single critical key must be able to determine all *other* critical keys in the target set.
- Since there are no other critical keys besides key 1, this requirement is vacuously satisfied without publishing any combinations.
Thus, zero combinations need to be selected, resulting in a cost of 0.

<RATIONALE>
Removed all group-theoretic terminology and replaced it with a cryptographic key-recovery narrative over GF(2). Because independent random keys can only be determined through XOR chaining if a path exists between them, this perfectly preserves the connectivity requirement while disguising it as a linear algebra/logic problem. Furthermore, the bounds are stated indirectly (S07), preventing models from using simple regex to extract `t <= 10` and map it to their Steiner Tree DP templates.
</RATIONALE>
