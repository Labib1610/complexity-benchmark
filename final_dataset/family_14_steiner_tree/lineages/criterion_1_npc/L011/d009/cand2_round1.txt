<METHOD_NAME>Implicit Arborescence Framing</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit algebraic tree conditions (dimension $|S|-1$, cardinality $|S|-1$) with a set of local directed-graph rules (exactly one root, out-degree 1, well-foundedness) framed as software module dependencies. This removes the surface-level formulas that models use to trigger Steiner Tree templates, forcing them to genuinely deduce that the local rules mandate an acyclic connected structure.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem A — Dependency Resolution Minimization

Time limit: 5 s
Memory limit: 256 MB

## Description

You are refactoring a software system consisting of $n$ modules, numbered 1 to $n$. 

You are given a target set $T$ containing $t$ core modules that must be integrated. Additionally, there is a pool of $m$ available bidirectional adapters. An adapter between module $u$ and module $v$ incurs a specific implementation cost $w$ if selected.

Your objective is to select a subset of adapters $C$ and assign a dependency direction to each to form a valid architecture. When you select an adapter between $u$ and $v$, you must declare either that $u$ depends on $v$, or that $v$ depends on $u$.

For any chosen subset $C$, we define its *active module set* $S$ as the union of the core set $T$ and the set of all modules that are involved in at least one selected adapter.

Your chosen architecture is considered valid if and only if it satisfies all of the following structural design rules:
1. **System Kernel:** Exactly one module in $S$ has no dependencies (it does not depend on any other module).
2. **Strict Hierarchy:** Every other module in $S$ depends on exactly one other module in $S$.
3. **Well-Foundedness:** For any module in $S$, recursively following its chain of dependencies must eventually terminate at the System Kernel.
4. **No Dead Weight:** For every module $k \in S$ that is not in the core set $T$, module $k$ must be involved in at least two selected adapters (counting both the module it depends on, and any modules that depend on it).

Your task is to find a valid architecture that minimizes the total sum of the costs of the selected adapters.

## Input

The first line provides three integers **n**, **m**, and **t** (1 ≤ **t** ≤ 10, 1 ≤ **n** ≤ 100, 0 ≤ **m** ≤ **n**·(**n**−1)/2).  
The second line lists **t** distinct integers representing the modules in the core set $T$.  
Following this, there are **m** lines. Each line provides three integers **u**, **v**, and **w** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**, 1 ≤ **w** ≤ 1000000), indicating that an adapter between module **u** and module **v** is available for a cost of **w**.  
It is guaranteed that the available adapters provide at least one valid way to satisfy the conditions.

## Output

Output a single integer representing the minimum possible total cost of a valid architecture.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, we can select adapters between (1,4), (2,4), and (3,4), which incurs a total cost of 1 + 1 + 1 = 3. 
We assign the dependencies so that module 1 depends on 4, module 2 depends on 4, and module 3 depends on 4.
- The core set is $T = \{1, 2, 3\}$.
- The selected adapters involve modules 1, 2, 3, and 4. Thus, the active module set is $S = \{1, 2, 3, 4\}$.
- **System Kernel:** Module 4 has no dependencies.
- **Strict Hierarchy:** Modules 1, 2, and 3 each depend on exactly one module (module 4).
- **Well-Foundedness:** Following the dependency chain from 1, 2, or 3 immediately reaches the kernel (module 4).
- **No Dead Weight:** The only module in $S$ not in $T$ is 4. It is involved in 3 selected adapters, satisfying the requirement of being involved in at least 2.
This architecture is valid and optimal. Selecting adapters only among the core modules would incur a cost of at least 4.

In Example 3, the core set $T = \{1\}$ has only one module. We can select zero adapters.
- The active module set is $S = \{1\}$.
- **System Kernel:** Module 1 has no dependencies.
- **Strict Hierarchy:** There are no other modules in $S$, so this is vacuously satisfied.
- **Well-Foundedness:** Module 1 is already the kernel.
- **No Dead Weight:** There are no modules in $S$ outside of $T$, so this requirement is vacuously satisfied.
Thus, zero adapters need to be selected, resulting in a cost of 0.
</STATEMENT>
<RATIONALE>
The explicit algebraic tree formulas (`|S|-1`) have been replaced with a set of local dependency rules that define an arborescence (a directed tree). By removing the explicit cardinality and dimension indicators, models can no longer trigger their Steiner Tree templates via surface pattern matching, and must instead genuinely deduce that the local hierarchy rules enforce a globally connected, acyclic structure.
</RATIONALE>
<PRESERVED_ANSWER>
Any valid dependency architecture mathematically corresponds to an arborescence on the active set $S$, meaning the underlying undirected selected adapters form a tree spanning $S$; because the costs are symmetric and any undirected tree can be oriented into a valid arborescence, the minimum cost is identical to the original undirected Steiner Tree.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains a minimum-weight tree covering a target set (Steiner Tree), maintaining its NP-complete complexity.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "involved in at least two selected adapters" as requiring two distinct dependency targets, but the parenthetical explicitly clarifies this counts both inbound and outbound connections, matching the original undirected degree requirement.
</RISK>
