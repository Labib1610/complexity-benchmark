# Problem A — Synchronization Core

Time limit: 5 s
Memory limit: 256 MB

## Description

You are analyzing a system of **n** binary variables, identified by integers from 1 to **n**. You can deploy *synchronization constraints* between specific pairs of variables. There are **m** possible constraints available. Deploying a constraint between variable **u** and variable **v** incurs a one-time cost of **w**. A deployed constraint enforces that **u** and **v** must hold the same boolean value. 

A subset of variables **S** is defined as *strictly unified* if every possible boolean assignment to the variables in **S** that satisfies all deployed constraints completely contained within **S** (i.e., constraints where both constrained variables belong to **S**) results in all variables in **S** sharing the exact same boolean value. 

A new system requirement dictates that a specific group of **t** *core variables* must all be included in the same strictly unified subset.

You may include any number of other auxiliary variables in this subset if deploying constraints to them helps reduce the overall cost. Your task is to select a set of constraints to deploy such that there exists at least one strictly unified subset containing all **t** core variables, while keeping the total cost of the deployed constraints to the absolute minimum.

## Input

The first line provides three integers **n**, **m**, and **t** (1 ≤ **t** ≤ 10, 1 ≤ **n** ≤ 100, 0 ≤ **m** ≤ **n**·(**n**−1)/2).  
The second line lists **t** distinct integers representing the identifiers of the core variables.  
Following this, there are **m** lines. Each line provides three integers **u**, **v**, and **w** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**, 1 ≤ **w** ≤ 1000000), indicating that a synchronization constraint can be deployed between variable **u** and variable **v** for a cost of **w**.  
It is guaranteed that the available constraints provide at least one valid way to satisfy the system requirement.

## Output

Output a single integer representing the minimum possible total cost required to satisfy the system requirement.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, deploying the constraints between variable 4 and variables 1, 2, and 3 requires a total cost of 1 + 1 + 1 = 3. Consider the subset **S** = {1, 2, 3, 4}. The deployed constraints completely contained within **S** enforce that variable 4 must hold the same value as variables 1, 2, and 3. Any boolean assignment to the variables in **S** that satisfies these three constraints must assign the exact same value to all four variables. Because every satisfying assignment results in all variables in **S** sharing the exact same value, **S** is strictly unified. This subset successfully contains the core variables 1, 2, and 3. Utilizing variable 4 in the subset is more cost-effective than deploying constraints exclusively among the core variables, which would incur a cost of at least 4.

In Example 3, only one variable is designated as core. A subset consisting of just this single variable (**S** = {1}) vacuously satisfies the condition for being strictly unified: any boolean assignment to a single-variable set trivially results in all variables in the set sharing the same value, as there is only one variable. Thus, zero constraints need to be deployed, resulting in a cost of 0.

I changed the problem domain from networking and cohesive enclaves (which strongly hints at graph cuts and connectivity) to boolean variables and synchronization constraints. The cut condition for connectivity is replaced by its logical isomorphism: a subset of variables is "connected" if and only if every satisfying assignment to its internal equivalence constraints forces all variables to take the identical value. This forces the model to recognize that the boolean constraint satisfaction problem is actually a graph connectivity problem, preventing surface-level pattern matching to Steiner Tree.
