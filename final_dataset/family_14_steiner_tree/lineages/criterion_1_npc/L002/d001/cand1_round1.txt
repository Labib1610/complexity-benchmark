<STATEMENT>
# Problem A — Grid Management Upgrade

Time limit: 5 s
Memory limit: 256 MB

## Description
A regional energy provider is modernizing its grid management software. The new system must process telemetry from legacy equipment that operates across $n$ distinct data schemas (numbered 1 to $n$).

To facilitate data exchange, third-party vendors offer $m$ bidirectional translation modules. Each module enables direct, two-way conversion between a specific pair of schemas and requires a one-time licensing fee.

The provider has identified $t$ specific schemas as mission-critical. Your objective is to determine the most cost-effective combination of translation modules to license so that data can be converted from any mission-critical schema to any other mission-critical schema. You may chain multiple modules together to achieve this, and you are permitted to license modules that convert to or from non-critical schemas if using them as intermediate steps lowers the overall licensing fee.

Write a program to calculate the minimum total licensing fee required to achieve full interoperability among all $t$ mission-critical schemas.

## Input
The first line contains three integers $n$, $m$, and $t$ ($1 \le t \le 10$, $1 \le n \le 100$, $0 \le m \le n(n-1)/2$).
The second line contains $t$ distinct integers: the IDs of the mission-critical schemas.
Each of the next $m$ lines contains three integers $u$, $v$, and $w$ ($1 \le u, v \le n$, $u \neq v$, $1 \le w \le 1000000$), representing an available translation module between schema $u$ and schema $v$ that has a licensing fee of $w$.
It is guaranteed that licensing all available modules would successfully make all mission-critical schemas interoperable.

## Output
Print a single integer: the minimum total licensing fee to ensure all mission-critical schemas can exchange data.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note
In Example 1, chaining conversions through the non-critical schema 4 (which costs 1+1+1 = 3) is cheaper than licensing the modules that directly convert between the three mission-critical schemas (which would cost 4). 
In Example 3, there is only one mission-critical schema, so no modules need to be licensed.

<RATIONALE>
The problem was reframed from a physical network of substations and fiber links to a software architecture problem involving data schemas and translation modules, while remaining within the grid management domain. This removes obvious spatial graph terminology ("corridors", "passive relays") to prevent models from instantly pattern-matching the scenario to the Steiner Tree problem, forcing them to deduce the underlying undirected graph structure from the concept of bidirectional data conversion.
</RATIONALE>
<PRESERVED_ANSWER>
The task is still to find a subset of items (edges) with minimum total cost that connects a specific subset of elements (terminals), meaning the mathematical objective and optimal configurations remain identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem is still exactly the Steiner Tree problem on graphs, preserving its NP-complete complexity.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "chaining modules" as requiring directed paths, but the description explicitly states the modules are "bidirectional" and enable "two-way conversion," making the undirected nature clear.
</RISK>
