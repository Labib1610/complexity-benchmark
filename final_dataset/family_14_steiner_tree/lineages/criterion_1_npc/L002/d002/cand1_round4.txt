<STATEMENT>
# Problem A — Legacy Archive Integration

Time limit: 5 s
Memory limit: 256 MB

## Description
A national library is integrating its digital repositories. The archives contain documents in $n$ different file formats. The library's indexing server allocates exactly 100 memory slots for format profiles, so the total number of formats $n$ will never exceed this capacity, and there is always at least 1 format.

To allow seamless viewing, external developers offer $m$ bidirectional format converters. Each converter allows two-way transformation between a specific pair of formats. The number of available converters $m$ can be as low as 0, and at most provides one converter for every unique pair among the $n$ formats, which is $n(n-1)/2$.

The library has designated $t$ specific formats as essential for public access. The public access portal features 10 display channels, setting an absolute maximum for the number of essential formats $t$ (with a minimum of 1). 

Each converter has a one-time purchase price $w$. The procurement policy restricts any single software purchase price $w$ to a maximum of 1000000, and prices are strictly positive (at least 1).

You must find the minimum total purchase price to buy a set of converters such that a document in any essential format can be transformed into any other essential format. You may chain multiple converters. You are allowed to purchase converters for non-essential formats if using them as intermediate steps results in a lower total price.

## Input
The first line contains the three integers $n$, $m$, and $t$.
The second line contains $t$ distinct integers, representing the IDs of the essential formats.
Each of the following $m$ lines contains three integers $u$, $v$, and $w$, denoting a bidirectional converter between format $u$ and format $v$ ($u \neq v$, with both between 1 and $n$) available for a purchase price of $w$.
The available converters are guaranteed to be sufficient to connect all essential formats if all were purchased.

## Output
Print a single integer: the minimum total purchase price to ensure all essential formats can be transformed into one another.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note
In Example 1, chaining transformations through the non-essential format 4 (which costs 1+1+1 = 3) is cheaper than purchasing the converters that directly transform between the three essential formats (which would cost 4). 
In Example 3, there is only one essential format, so no converters need to be purchased.

I replaced the explicit mathematical inequalities for variable bounds with scenario-based physical limits (e.g., 10 display channels for $t \le 10$, 100 memory slots for $n \le 100$) while preserving the exact numerical digits. This forces the model to read and comprehend the prose to derive the constraints, preventing it from relying on a quick scan of an isolated input section to realize $t$ is small enough for an exponential-time Steiner tree DP.
</RATIONALE>
