<STATEMENT>
# Problem A — System State Unification

Time limit: 5 s   Memory limit: 256 MB

## Description

You are analyzing a system consisting of **n** independent state variables, numbered 1 through **n**. Initially, each variable holds a distinct integer value corresponding to its index (i.e., variable $i$ holds the value $i$).

You are given a catalog of **m** available transformation rules. The $j$-th rule is defined by a pair of values $(u_j, v_j)$ and has a one-time licensing fee of $w_j$.
If you pay the fee to activate a rule, it becomes permanently available. An active rule $(u, v)$ allows you to perform the following operation: choose any variable in the system that currently holds the value $u$ and change its value to $v$, or choose any variable that currently holds the value $v$ and change its value to $u$. 
Once a rule is activated, you may apply it an unlimited number of times, in any sequence, to any variables.

You have a specific list of **t** target variables. Your objective is to pay the minimum total licensing fee to activate a subset of rules such that, through some valid sequence of rule applications, it is possible to reach a state where all **t** target variables hold the exact same value.

Determine the absolute minimum total licensing fee required.

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2).
The second line contains **t** distinct integers representing the indices of the target variables.
The next **m** lines each provide three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), indicating that a rule between value **u** and value **v** can be activated for a fee of **w**.
It is guaranteed that it is possible to unify the target variables using the available rules.

## Output

Output a single integer representing the minimum total licensing fee required.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, you can activate the rules (1, 4), (2, 4), and (3, 4) for a total fee of 1 + 1 + 1 = 3. 
You can then apply the first rule to change variable 1's value from 1 to 4. 
Apply the second rule to change variable 2's value from 2 to 4. 
Apply the third rule to change variable 3's value from 3 to 4. 
Now, target variables 1, 2, and 3 all hold the value 4. This is cheaper than activating rules directly between 1, 2, and 3.

In Example 3, there is only one target variable, which trivially already holds the same value as itself. No rules need to be activated, so the cost is 0.
</STATEMENT>
<RATIONALE>
I transformed the problem from a standard graph connectivity format into a state-space unification puzzle. Instead of connecting nodes with edges, the solver must activate transformation rules to change the values of independent variables until a target subset holds the same value. This forces the model to deduce that "making variables hold the same value via symmetric rules" is isomorphic to "finding a single connected component containing their initial values", and that minimizing the one-time activation cost of these rules is exactly the Minimum Steiner Tree problem. Models relying on surface pattern matching may misinterpret this as a shortest-path sum problem or a state-space BFS and fail.
</RATIONALE>
<PRESERVED_ANSWER>
Every valid sequence of rule applications that unifies the target variables requires a path from each target's initial value to the final common value within the network of activated rules, making the minimum cost exactly equal to the minimum Steiner tree connecting the target indices.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains the Minimum Steiner Tree problem on an undirected graph, which is NP-complete, as the variables, target indices, and transformation rules perfectly map to nodes, terminals, and edges.
</PRESERVED_CLASS>
<RISK>
A reader might wonder if applying a rule to a variable affects other variables holding the same value, but the phrasing "choose any variable... and change its value" clarifies that the operation applies to a single variable at a time.
</RISK>
