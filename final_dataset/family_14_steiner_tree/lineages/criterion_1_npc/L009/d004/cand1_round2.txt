# Problem A — Core Subset Integration

Time limit: 5 s   Memory limit: 256 MB

## Description

You are given a finite collection $V$ consisting of $n$ distinct elements, labeled 1 through $n$. A specific subset $T \subseteq V$ containing exactly $t$ elements is designated as the core subset.

You are also provided with a list of $m$ available pairings. Each pairing links two distinct elements from $V$ and requires a specific cost to activate. 

Your task is to select a subset of these pairings to activate such that the core subset is fully integrated. The core subset is considered fully integrated if, for every pair of core elements $a, b \in T$, there exists a sequence of elements $v_0, v_1, \dots, v_k$ in $V$ satisfying:
- $v_0 = a$
- $v_k = b$
- For every integer $i$ from $0$ to $k-1$, the selected subset of pairings includes a pairing that links $v_i$ and $v_{i+1}$.

Elements in $V$ that do not belong to $T$ are strictly optional. They are not required to be integrated, but they may freely appear in the sequences to link core elements if their inclusion results in a lower total activation cost.

Determine the minimum total cost to activate a subset of pairings that fully integrates the core subset.

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2, 1 ≤ t ≤ 10). The integer **t** is the number of elements in the core subset.
The second line provides **t** distinct integers representing the labels of the core elements.
The subsequent **m** lines each contain three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), describing an available pairing that links element **u** and element **v** with an activation cost of **w**.
It is guaranteed that it is possible to fully integrate all core elements using the available pairings.

## Output

Print a single integer: the minimum total cost to activate a valid subset of pairings that fully integrates the core subset.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, integrating the core subset by utilizing the optional element 4 (which incurs a cost of 1+1+1 = 3) is strictly cheaper than activating pairings directly between the three core elements (which would incur a cost of 4). In Example 3, there is only a single core element, which trivially satisfies the sequence condition with zero activated pairings.

The problem has been rewritten using abstract set-theoretic language instead of network or infrastructure analogies. By replacing graph terminology (edges, paths, nodes, connected) with formal definitions (pairings, sequences of elements, integrated subsets), models that rely on surface pattern matching to trigger Steiner Tree dynamic programming templates will fail to map the prompt to their training data, forcing them to genuinely parse the sequence constraint.
</RATIONALE>
