**Solution Explanation**

For every constraint we choose, the two involved settings must obtain the same value.
All chosen constraints together form an *undirected* graph.
In any feasible system state the values are constant inside each connected component of this
graph.

The security requirement is:

*all critical settings belong to one connected component.*

So we have to select a set of edges of minimum total cost that connects the given
`t ( ≤ 10 )` terminal vertices – the classic **Steiner Tree** problem in an undirected
graph with `n ≤ 100`.

The Steiner Tree problem is NP‑hard in general, but for a small number of terminals it
can be solved by the well known DP over subsets (Dreyfus‑Wagner algorithm).

--------------------------------------------------------------------

#### 1.   Graph

```
vertices : 1 … n
edges    : undirected, weight w
```

--------------------------------------------------------------------

#### 2.   DP definition  

```
mask  – bitmask of terminals already connected (0 … (1<<t)-1)
v     – vertex where the (partial) tree ends
dp[mask][v] = minimum total cost of a tree
              that connects exactly the terminals of 'mask'
              and whose vertices are a connected subgraph that contains v
```

The answer we need is  

```
min_v dp[ALL][v]          (ALL = (1<<t)-1)
```

--------------------------------------------------------------------

#### 3.   Initialisation  

For each terminal `i` (its vertex is `term[i]`)

```
dp[1<<i][ term[i] ] = 0
dp[1<<i][ other vertices ] = INF
```

--------------------------------------------------------------------

#### 4.   Transitions  

Two kinds of transitions are required.

*4.1   Merging two already built sub‑trees*  

For a fixed `mask` and a proper non‑empty submask `sub` :

```
dp[mask][v] = min( dp[sub][v] + dp[mask ^ sub][v] )
```

Both sub‑trees end in the same vertex `v`, therefore their union is also a tree
ending in `v`.

*4.2   Extending a tree through an edge*  

After the merging step the values `dp[mask][*]` are only correct for the vertices
where the tree currently ends.  
We have to propagate them through the graph: for every edge `u‑v` with weight `w`

```
dp[mask][v]  ≤ dp[mask][u] + w
dp[mask][u]  ≤ dp[mask][v] + w
```

This is exactly a single‑source shortest‑paths problem with many sources
(the current values `dp[mask][*]`).  
We run Dijkstra (or a simple SPFA because the graph is tiny) for each `mask`.

--------------------------------------------------------------------

#### 5.   Algorithm  

```
read input
build adjacency list
if t == 1 : answer = 0

FULL = (1<<t) - 1
dp = [ [INF]*n for _ in range(1<<t) ]

# initialise singletons
for i, vertex in enumerate(terminals):
        dp[1<<i][vertex-1] = 0          # 0‑based indices

for mask from 1 to FULL:
        # 1) combine smaller masks
        sub = (mask-1) & mask
        while sub:
                other = mask ^ sub
                for v in 0..n-1:
                        cand = dp[sub][v] + dp[other][v]
                        if cand < dp[mask][v]:
                                dp[mask][v] = cand
                sub = (sub-1) & mask

        # 2) run Dijkstra to spread through edges
        heap = [(dp[mask][v], v) for v in range(n) if dp[mask][v] < INF]
        heapify(heap)
        while heap:
                d, u = heappop(heap)
                if d != dp[mask][u]: continue
                for (v, w) in adj[u]:
                        nd = d + w
                        if nd < dp[mask][v]:
                                dp[mask][v] = nd
                                heappush(heap, (nd, v))

answer = min(dp[FULL])
print(answer)
```

Complexities  

*Number of masks* : `2^t ≤ 1024`  
*Merge step* : for each mask we iterate over all its proper submasks → `O(3^t)`  
*Dijkstra* : `O( 2^t * (m log n) )`  

With `t ≤ 10`, `n ≤ 100`, `m ≤ 4950` this easily fits into the limits.

--------------------------------------------------------------------

#### 6.   Correctness Proof  

We prove that the algorithm outputs the minimum possible total cost.

---

##### Lemma 1  
For any mask and vertex `v`, after the Dijkstra step finishes,
`dp[mask][v]` equals the minimum cost of a tree that

* connects exactly the terminals of `mask`,
* is a connected subgraph,
* contains vertex `v`.

**Proof.**  
Induction over the Dijkstra process.

*Base*: before Dijkstra, `dp[mask][v]` may be `INF` or a value obtained from the
merge step. In the latter case there exists a tree satisfying the three
properties with that cost (the two sub‑trees merged at `v`). So the invariant
holds.

*Step*: when we relax an edge `u‑v` with weight `w`,
we consider a tree `T` that satisfies the properties for `u` with cost `dp[mask][u]`.
Adding edge `u‑v` yields a tree satisfying the properties for `v` with cost
`dp[mask][u] + w`. If this is cheaper than the current `dp[mask][v]` we replace it.
Thus the value always stays the minimum over all such trees.
When the heap is empty, no further improvement is possible, i.e. the minimum
has been reached. ∎



##### Lemma 2  
After processing a mask, for every vertex `v` the value `dp[mask][v]` is the
minimum possible cost of any tree that connects exactly the terminals of `mask`
and contains `v`.

**Proof.**  
The algorithm processes masks in increasing order.
Assume the statement holds for all proper submasks of `mask`.  
During the *merge* step we consider every partition of `mask` into two non‑empty
subsets `sub` and `mask\sub`. By induction hypothesis `dp[sub][v]` and
`dp[mask\sub][v]` are optimal for their respective subsets, therefore their sum
is the optimal cost of a tree that connects all terminals of `mask` **and**
has `v` as a common vertex of the two sub‑trees. Taking the minimum over all
partitions yields the optimal cost among all trees that can be expressed as a
union of two smaller optimal trees meeting at `v`.  
Any optimal tree for `mask` either can be split this way (if it has a vertex
whose removal separates the terminals) or already appears after the Dijkstra
propagation of a smaller mask (the case where the tree is a simple path from a
terminal to `v`). Hence after the merge step the value is at most optimal.
The subsequent Dijkstra step (Lemma&nbsp;1) can only improve it, never worsen it,
and finally yields the true optimum. ∎



##### Lemma 3  
For the full mask `ALL`, `min_v dp[ALL][v]` equals the minimum total cost of a
set of edges that makes all terminals belong to one connected component.

**Proof.**  
Any feasible set of edges that connects all terminals forms a connected
subgraph `H`. Choose any vertex `v` of `H`; the edges of `H` constitute a tree
(not necessarily a tree, but we can extract a spanning tree of the same
connected component) that connects all terminals and contains `v`. Its cost is
at least `dp[ALL][v]` by Lemma&nbsp;2, therefore the optimum over `v` is a lower
bound on the answer.

Conversely, let `v*` be a vertex attaining `min_v dp[ALL][v]`. By Lemma&nbsp;2 there
exists a tree `T` of cost `dp[ALL][v*]` that connects all terminals and contains
`v*`. Using exactly the edges of `T` satisfies the requirement, so the optimum
cannot be larger. ∎



##### Theorem  
The algorithm outputs the minimum possible total implementation cost that
guarantees all critical settings have the same value.

**Proof.**  
If `t = 1` the requirement is vacuous, the algorithm outputs `0`, which is optimal.
Otherwise, by Lemma&nbsp;3 the value printed (`min_v dp[ALL][v]`) equals the minimum
cost of a set of edges that connects all terminals. Such a set exactly enforces
that all critical settings belong to one equality component, which is precisely
the security objective. Hence the algorithm is optimal. ∎

#### 7.   Reference Implementation  (Python 3)

```python
import sys
import heapq

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    t = int(next(it))
    terminals = [int(next(it)) - 1 for _ in range(t)]

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        w = int(next(it))
        adj[u].append((v, w))
        adj[v].append((u, w))

    if t == 1:
        print(0)
        return

    INF = 10**18
    FULL = (1 << t) - 1
    dp = [[INF] * n for _ in range(1 << t)]

    for i, v in enumerate(terminals):
        dp[1 << i][v] = 0

    # process masks in increasing order
    for mask in range(1, FULL + 1):
        # combine submasks
        sub = (mask - 1) & mask
        while sub:
            other = mask ^ sub
            # only need to consider each unordered pair once; both sub and other will appear
            for v in range(n):
                cand = dp[sub][v] + dp[other][v]
                if cand < dp[mask][v]:
                    dp[mask][v] = cand
            sub = (sub - 1) & mask

        # Dijkstra to propagate through edges
        heap = [(dp[mask][v], v) for v in range(n) if dp[mask][v] < INF]
        heapq.heapify(heap)
        while heap:
            d, u = heapq.heappop(heap)
            if d != dp[mask][u]:
                continue
            for v, w in adj[u]:
                nd = d + w
                if nd < dp[mask][v]:
                    dp[mask][v] = nd
                    heapq.heappush(heap, (nd, v))

    answer = min(dp[FULL])
    print(answer)


if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms to
the required input‑output format.
