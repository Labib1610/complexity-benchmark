# Problem A — Decentralized Ledger Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

A financial consortium oversees a network of **n** distinct data repositories, labeled 1 through **n**. To facilitate communication, there are **m** proposed integration procedures available. Each procedure lists an initiating repository **u** and a receiving repository **v**, and incurs a fixed implementation overhead.

Implementing a procedure establishes a communication channel for **u** to push its ledger updates to **v**. Because the consortium enforces a strict parity protocol, establishing this channel automatically allows **v** to push its own updates back to **u** at no extra cost. Consequently, implementing a procedure ensures that the two repositories are completely synchronized.

The repositories are divided into two categories: exactly **t** of them are designated as critical vaults, while the rest are standard vaults. Any repository (critical or standard) will automatically forward any updates it receives to all other repositories it is synchronized with.

Your task is to select a subset of the **m** proposed procedures to implement so that all critical vaults are fully integrated. Specifically, a ledger update originating at any critical vault must successfully propagate to every other critical vault, either directly or by cascading through standard vaults acting as intermediaries. Find the lowest possible sum of implementation overheads required to meet this condition. 

## Input

The first line provides three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2).
The second line contains **t** distinct integers representing the labels of the critical vaults.
The following **m** lines each contain three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), describing a proposed procedure from initiating repository **u** to receiving repository **v** that costs **w** to implement.
It is guaranteed that the provided procedures are sufficient to fully integrate all critical vaults.

## Output

Print a single integer representing the minimum total implementation overhead needed to fully integrate all critical vaults.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, implementing procedures through the standard vault 4 (overhead 1+1+1 = 3) is cheaper than integrating the three critical vaults without using repository 4 (which would cost 2+2 = 4). In Example 3, there is only one critical vault, so no procedures are needed and the minimum total overhead is 0.

<RATIONALE>
Removed the explicit "bilateral" and "two-way" keywords that allowed models to instantly map the input to an undirected graph. Instead, the input is framed as a directed proposal (from an initiating repository to a receiving one) where the symmetric effect is a consequence of a strict parity protocol. This forces the model to read and comprehend the protocol rules to deduce that the underlying network is undirected, rather than relying on surface pattern matching.
</RATIONALE>
<PRESERVED_ANSWER>
The parity protocol ensures that every implemented procedure allows updates to flow in both directions at no extra cost, making the underlying network logically undirected just like the seed problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding the minimum-cost connected subgraph that spans a specific subset of nodes, which is the exact definition of the undirected Steiner Tree problem.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret the parity protocol as meaning the reverse channel requires a separate implementation cost, though the phrase "at no extra cost" is explicitly included to prevent this.
</RISK>
