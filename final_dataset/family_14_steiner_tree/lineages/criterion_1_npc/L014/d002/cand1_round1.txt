# Problem A — Decentralized Ledger Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

A financial consortium manages an ecosystem of **n** distinct data repositories, labeled uniquely from 1 to **n**. To ensure consistency, the consortium can implement bilateral "state-binding agreements". There are **m** proposed agreements available. Each agreement strictly couples the databases of two specific repositories, guaranteeing their records remain permanently identical. Establishing an agreement incurs a known implementation overhead.

The identical-state guarantee provided by these agreements is transitive: if repository A is bound to B, and B is bound to C, then A, B, and C will all share the exact same records, regardless of whether a direct agreement exists between A and C.

Among the **n** repositories, a specific subset of **t** repositories are designated as primary ledgers. The remaining repositories are auxiliary. Compliance regulations mandate that all **t** primary ledgers must share a single, unified state. You must select a subset of the **m** proposed agreements to implement so that this mandate is fulfilled. You are permitted to select agreements that involve auxiliary repositories to help establish the necessary transitive bindings between the primary ledgers.

Your goal is to satisfy the compliance mandate while keeping the sum of the implementation overheads as low as possible. Determine this minimum total overhead.

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2).
The second line contains **t** distinct integers: the labels of the primary ledgers.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000): indicating a proposed state-binding agreement between repository **u** and repository **v** with an implementation overhead of **w**.
It is guaranteed that the listed proposed agreements are sufficient to guarantee a unified state for all primary ledgers.

## Output

Print a single integer: the minimum total implementation overhead required to guarantee that all primary ledgers share a unified state.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, implementing agreements that bind the three primary ledgers to the auxiliary repository 4 (overhead 1+1+1 = 3) is cheaper than directly binding the three primary ledgers to each other (which would cost 2+2 = 4). In Example 3, there is only one primary ledger, so it trivially shares a state with itself and no agreements need to be implemented.

The previous wording used standard network routing terminology ("channels," "relay," "exchange," "chain"), which models immediately mapped to the Steiner tree problem on a graph. To break this surface-level pattern matching while preserving the scenario domain, the mechanics were rewritten to use equivalence relations ("state-binding agreements," "permanently identical," "transitive"). This forces the model to independently deduce that transitive bilateral equalities form connected components, and that minimizing the cost of binding a subset of variables is mathematically identical to finding a minimum Steiner tree.
</RATIONALE>
<PRESERVED_ANSWER>
The cost of binding repositories into a transitive equivalence class is exactly the sum of the chosen pairwise agreement overheads, which mathematically mirrors the sum of edge weights in a connected subgraph linking the same vertices.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains the Steiner Tree problem on graphs, which is NP-complete, as the objective is still to find the minimum-weight set of edges (agreements) that connects a specific subset of vertices (primary ledgers).
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "transitive" as implying that a single agreement automatically creates multiple direct links with no extra cost, though the phrase "regardless of whether a direct agreement exists" clarifies that the shared state is what propagates, not the agreements themselves.
</RISK>
