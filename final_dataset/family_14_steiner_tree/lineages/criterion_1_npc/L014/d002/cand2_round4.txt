<STATEMENT>
# System of Equivalencies

Time limit: 5 s
Memory limit: 256 MB

## Description

A formal verification tool is analyzing a system with $n$ distinct integer variables, indexed from 1 to $n$. The tool can apply $m$ possible equivalence constraints. Each constraint forces two specific variables to have the exact same value. Applying the constraint between variable $u$ and variable $v$ requires $w$ units of computational overhead.

The goal of the verification step is to prove that a specific subset of $t$ variables (called the *critical variables*) must all share the same value. To do this, you must select a subset of the $m$ available equivalence constraints to apply. 

The applied constraints will propagate: if the selected constraints force $A = B$ and $B = C$, then $A = C$ is implicitly established. You may apply constraints involving any of the $n$ variables; non-critical variables can be constrained to help chain equivalencies between critical variables.

You must choose a set of constraints to apply such that, by the laws of transitivity, all $t$ critical variables are forced to be equal to each other. Your objective is to satisfy this condition while minimizing the total computational overhead of the applied constraints. 

## Input

The first line contains three integers $n$, $m$, and $t$ ($1 \le t \le 10$, $1 \le n \le 100$, $0 \le m \le n(n-1)/2$).
The second line contains $t$ distinct integers: the indices of the critical variables.
Each of the next $m$ lines contains three integers $u$, $v$, and $w$ ($1 \le u, v \le n$, $u \neq v$, $1 \le w \le 1000000$): indicating an available equivalence constraint between variable $u$ and variable $v$ with an overhead of $w$.
It is guaranteed that applying all $m$ constraints would successfully force all critical variables to be equal.

## Output

Print a single integer: the minimum total overhead required to force all critical variables to be equal.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, applying constraints between variables (1,4), (2,4), and (3,4) costs 1+1+1 = 3. This forces variable 1 = 4, 2 = 4, and 3 = 4, which transitively ensures critical variables 1, 2, and 3 are all equal. This is cheaper than directly forcing 1 = 2 and 2 = 3 (which would cost 2+2 = 4). In Example 3, there is only one critical variable, so no constraints need to be applied.
