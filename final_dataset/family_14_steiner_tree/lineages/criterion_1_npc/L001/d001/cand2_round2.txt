<STATEMENT>
# Connecting the Primary Hubs

Time limit: 5 s   Memory limit: 256 MB

## Description

A complex contains n operational hubs (identified 1 through n). Certain pairs of hubs can be bridged by a conduit at a specific expense. A subset of t hubs are designated as primary hubs. All primary hubs must be united into a single communicating network using the conduits you select (either directly or through intermediate hubs). You may route the network through the remaining hubs if it decreases the total expense, or you may bypass them entirely.

Determine a selection of conduits that unites all primary hubs at the minimum possible total expense. Output this minimum total expense.

## Input

The first line provides three integers n, m, and t. The total number of operational hubs n is between 1 and 100, limited by the site's grid capacity. The number of available conduits m is between 0 and n(n-1)/2. The number of primary hubs t is between 1 and 10, strictly capped by the availability of primary transceivers.
The second line lists t distinct integers: the identifiers of the primary hubs.
The subsequent m lines each contain three integers u, v, and w. These indicate a conduit bridging hub u and hub v (where u and v are distinct identifiers between 1 and n) for an expense of w. The expense w is between 1 and 1000000, limited by the maximum grant.
The provided conduits are guaranteed to be sufficient to unite all primary hubs.

## Output

Print a single integer: the minimum total expense required to unite all primary hubs.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, routing the network through the optional intermediate hub 4 (expenses 1+1+1 = 3) is cheaper than bridging the three primary hubs directly (which would cost 4). In Example 3 there is only one primary hub, so no conduit is needed.

<RATIONALE>
I replaced all standard graph terminology with a scenario about connecting "primary hubs" using "conduits". The explicit mathematical inequalities for the bounds were removed and instead embedded into prose as physical constraints (such as site grid capacity and transceiver availability). This prevents models from simply pattern-matching the bare `1 <= t <= 10` inequality to recognize the small terminal set, forcing them to actually read the narrative to extract the constraints and deduce the viability of exponential-time dynamic programming.
</RATIONALE>
