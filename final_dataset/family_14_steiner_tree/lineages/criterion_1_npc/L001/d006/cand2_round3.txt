<STATEMENT>
# Problem A — Variable Equality Enforcement

Time limit: 5 s   Memory limit: 256 MB

## Description

You are analyzing a system of **n** variables, indexed from 1 to **n**.

You are provided with a list of **m** available equality constraints. An equality constraint between variable $u$ and variable $v$ enforces that $u$ and $v$ must take the exact same value. Selecting this specific constraint to be active incurs a one-time configuration cost of $w$.

You are given one set of **t** target variables: $c_1, c_2, \dots, c_t$.
Your objective is to select a subset of the available equality constraints to activate such that, by logical deduction, all **t** target variables are forced to be equal to each other. 

Non-target variables may be used as intermediates to chain equalities together, or they may be ignored entirely. Selecting constraints involving non-target variables is completely valid and often results in a lower total configuration cost.

Determine the minimum total configuration cost required to ensure that all **t** target variables are logically forced to be equal. (If $t=1$, no constraints need to be activated and the minimum cost is 0).

## Input

The first line contains three integers **n**, **m**, and **t** (1 ≤ t ≤ 10, 1 ≤ n ≤ 100, 0 ≤ m ≤ n·(n−1)/2), representing the total number of variables, the number of available equality constraints, and the number of target variables. `m` may be 0; in that case, the block of constraint lines is empty.
The second line contains **t** distinct integers $c_1, c_2, \dots, c_t$: the identifiers of the target variables. The order of these identifiers does not matter.
Each of the next **m** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v ≤ n, u ≠ v, 1 ≤ w ≤ 1000000), indicating that an equality constraint can be activated between variable u and variable v at a cost of w.
It is guaranteed that for every input, there exists a selection of listed constraints that makes all target variables equal.

## Output

Print a single integer: the minimum total configuration cost to activate a set of equality constraints that satisfies the requirement.

## Examples

### Example 1

**Input**
```
4 6 3
1 2 3
1 4 1
2 4 1
3 4 1
1 2 2
2 3 2
1 3 2
```

**Output**
```
3
```

### Example 2

**Input**
```
4 4 3
1 2 3
1 2 1
2 3 1
1 4 10
3 4 10
```

**Output**
```
2
```

### Example 3

**Input**
```
3 2 1
1
1 2 5
2 3 5
```

**Output**
```
0
```

## Note

In Example 1, the target variables are 1, 2, and 3. You can activate equality constraints between (1,4), (2,4), and (3,4) for a total cost of 1+1+1 = 3. Because variable 1 is forced equal to 4, and 2 is forced equal to 4, they must be equal to each other. Similarly, 3 is forced equal to 4, so all three target variables are forced to be equal. Alternatively, activating equality constraints for (1,2) and (2,3) directly would cost 2+2 = 4. The minimum cost is 3. 

In Example 3, there is only one target variable ($t=1$), so no constraints are needed and the minimum cost is 0.
</STATEMENT>
<RATIONALE>
The problem has been reframed from merging groups to enforcing equality constraints among variables. This disrupts the model's ability to pattern-match the scenario directly to Steiner Tree over a graph, forcing it to deduce that transitive equality constraints form a connected subgraph containing the target variables.
</RATIONALE>
<PRESERVED_ANSWER>
Finding a minimum-cost set of equality constraints to make a subset of variables equal is mathematically identical to finding a minimum-weight connected subgraph that spans a specific subset of vertices.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the Node-Weighted (or Edge-Weighted) Steiner Tree problem, which is NP-complete, as the underlying graph topology and optimization objective are unchanged.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "equality constraints" as an assignment problem rather than a connectivity problem, though the explicit note about logical deduction and chaining should prevent this.
</RISK>
