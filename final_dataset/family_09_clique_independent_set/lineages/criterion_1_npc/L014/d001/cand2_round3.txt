<STATEMENT>
# Problem A — Workable Roster

Time limit: 5 s   Memory limit: 256 MB

## Description

You are forming a roster of exactly **k** crew members from a pool of **n** candidates (numbered 1 to n). You are given **m** incompatibility records. Each record pairs two distinct candidates who refuse to work together. 

A roster is considered **workable** if no two candidates on the roster have an incompatibility record. (Any two candidates without a specific incompatibility record can work together).

Given a target roster size **k**, decide whether a workable roster of exactly **k** candidates exists, and if so, report one.

## Input

The first line contains three integers **n**, **m**, and **k** (1 ≤ n ≤ 46, 0 ≤ m ≤ n·(n−1)/2, 1 ≤ k ≤ n).
Each of the next **m** lines contains two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v): an incompatibility record between candidate **u** and candidate **v**. No record is listed twice, and the order of candidates in a record does not matter.

## Output

If a workable roster of exactly **k** candidates exists, print `YES` on the first line, then on the second line print **k** distinct candidate numbers forming such a roster, separated by spaces. Any roster in which no two candidates share an incompatibility record is accepted.

If no such roster exists, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

## Note

A workable roster requires that no two chosen candidates are incompatible. In Example 2, candidates 1, 3, and 5 have no incompatibility records among them. In Example 1, no three of the four candidates are mutually compatible.
</STATEMENT>
<RATIONALE>
Changed the framing from a social network to crew scheduling with incompatibilities to avoid standard "friends/strangers" graph tropes. Kept the exact bounds in inequality form to satisfy the strict bounding constraints, and maintained the original acceptance criteria (allowing any valid roster) because adding a new tie-break rule would violate the hard I/O contract constraints.
</RATIONALE>
<PRESERVED_ANSWER>
The problem still requires finding a set of k elements where no two elements share a listed pairwise relationship, meaning any valid independent set for the given graph remains correct.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The task is structurally identical to finding an Independent Set of size k, which is NP-complete.
</PRESERVED_CLASS>
