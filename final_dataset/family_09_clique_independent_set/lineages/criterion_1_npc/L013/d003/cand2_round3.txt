<STATEMENT>
# Problem A — Secure Audit Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

A financial institution has **n** accounts, numbered 1 through **n**. The auditing team must select exactly **k** distinct accounts to audit.

The institution's database contains **m** reconciliation channels. Each channel bridges exactly two specific accounts. 
To prevent database corruption, a strict safety protocol must be followed: a selection of accounts is valid if and only if for every two distinct selected accounts **a** and **b**, the pair (**a**, **b**) is not among the **m** listed channels. If any channel has both of its bridged accounts selected for the audit, the system will deadlock.

Given the **n** accounts and the configurations of the **m** reconciliation channels, determine whether it is possible to select exactly **k** accounts that satisfy this condition. If a valid selection is possible, you must provide one such selection of accounts.

## Input

The first line of the input contains three integers **n**, **m**, and **k**.
The institution's high-security tier maps each account to a distinct chromosome of a standard human diploid cell. Consequently, the number of accounts **n** is at least 1 and at most the total number of chromosomes in such a cell.
The number of channels **m** is a non-negative integer that will not exceed the maximum possible number of unique pairs of these accounts.
The target audit size **k** is an integer between 1 and **n** inclusive.

The next **m** lines each contain two integers **u** and **v** (between 1 and **n**, with **u** ≠ **v**), representing the two accounts bridged by a specific reconciliation channel.
The order of the two accounts on a line does not matter, and no channel's pair of accounts is listed more than once.

## Output

If a valid selection of exactly **k** distinct accounts can be found such that no two selected accounts are bridged by a channel, print `YES` on the first line. On the second line, print **k** distinct integers representing the account numbers to audit, separated by spaces. If there are multiple valid selections, any one will be accepted.

If no such selection is possible, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```
</STATEMENT>
<RATIONALE>
The explicit bounds `1 ≤ n ≤ 46` were replaced with an indirect physical limit (the 46 chromosomes of a standard human diploid cell) to fulfill Strategy S07. This removes the bare inequality that models use as a pattern-matching shortcut to justify simple recursive search, while preserving the exact mathematical bound. The problem description was also tightened to rigorously define the forbidden-pair condition without using performance hints or ambiguous scheduling terminology.
</RATIONALE>
<PRESERVED_ANSWER>
The problem still requires finding a set of exactly k accounts such that no two chosen accounts share a reconciliation channel, which perfectly matches the original independent set requirement.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying structure remains exactly the Independent Set problem on a graph with n vertices and m edges, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models could theoretically misremember the number of chromosomes in a human diploid cell, though 46 is a universally known biological constant heavily represented in training data.
</RISK>
