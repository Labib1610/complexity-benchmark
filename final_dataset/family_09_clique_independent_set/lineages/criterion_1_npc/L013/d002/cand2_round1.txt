# Problem A — Privacy Zones and Surveillance

Time limit: 5 s   Memory limit: 256 MB

## Description

A city administration is planning its surveillance network. There are **n** junctions, numbered 1 through **n**. Due to local regulations, the administration must select exactly **k** distinct junctions to be designated as "privacy zones", which will be completely free of surveillance. The remaining **n** − **k** junctions will each have a surveillance tower installed.

The city's road network includes **m** high-traffic avenues. Each avenue directly connects exactly two specific junctions. Safety protocols dictate that every high-traffic avenue must be monitored by at least one surveillance tower. An avenue is considered safely monitored if a tower is installed at one or both of its connecting endpoints. 

Given the **n** junctions and the endpoints of the **m** high-traffic avenues, determine whether it is possible to select exactly **k** junctions to be privacy zones such that every high-traffic avenue is safely monitored. If a valid selection is possible, you must provide one valid set of privacy zones.

## Input

The first line of the input contains three integers **n**, **m**, and **k** (1 ≤ **n** ≤ 46, 0 ≤ **m** ≤ **n**·(**n**−1)/2, 1 ≤ **k** ≤ **n**).
The next **m** lines each contain two integers **u** and **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), representing the two junctions connected by a specific high-traffic avenue.
The order of the two junctions on a line does not matter, and no avenue's pair of junctions is listed more than once.

## Output

If a valid configuration of exactly **k** privacy zones can be established, print `YES` on the first line. On the second line, print **k** distinct integers representing the junction numbers chosen as privacy zones, separated by spaces. If there are multiple valid selections, any one will be accepted.

If no such selection is possible, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

<RATIONALE>
The seed problem explicitly framed the constraints as direct conflicts ("no hardware lock is requested by more than one executing process"), which models trivially map to finding an Independent Set. This rewrite inverts the narrative structure: instead of avoiding conflicts among the $k$ chosen items, the goal is to ensure "coverage" by the $n-k$ unchosen items. To succeed, the model must deduce that requiring at least one tower per avenue (Vertex Cover of size $n-k$) is mathematically identical to forbidding both endpoints from being privacy zones (Independent Set of size $k$).
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that every avenue has at least one tower (from the $n-k$ junctions not chosen) means no avenue can have zero towers, which ensures no two chosen privacy zones share an avenue, preserving the exact independent set logic and output space.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to finding an Independent Set of size $k$ (or a Vertex Cover of size $n-k$), which is a classic NP-complete problem.
</PRESERVED_CLASS>
