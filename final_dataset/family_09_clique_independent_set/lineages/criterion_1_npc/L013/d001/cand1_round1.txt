# Problem A — Stable Payload Deployment

Time limit: 5 s   Memory limit: 256 MB

## Description

A software system contains **n** available modules, numbered 1 through **n**. Through automated integration testing, the system has identified **m** isolation constraints. Each constraint specifies two modules that share a restricted resource.

Your objective is to assemble a stable deployment payload consisting of exactly **k** distinct modules. The system architecture evaluates stability by checking the payload against the list of isolation constraints. A payload is considered stable if, for every single one of the **m** constraints, the payload includes at most one of the two specified modules. There are no other rules restricting the payload composition.

Given the exact configuration of the **n** modules and the **m** constraints, determine whether a stable payload of exactly **k** modules can be successfully assembled. If such a payload can be formed, you must also provide one valid selection of modules.

## Input

The first line of the input contains three integers **n**, **m**, and **k** (1 ≤ **n** ≤ 46, 0 ≤ **m** ≤ **n**·(**n**−1)/2, 1 ≤ **k** ≤ **n**).
The next **m** lines each contain two integers **u** and **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), representing the two modules involved in an isolation constraint.
The constraints apply symmetrically, and no constraint is listed more than once for the same pair of modules.

## Output

If a stable deployment payload of exactly **k** modules can be assembled, print `YES` on the first line. On the second line, print **k** distinct integers representing the module numbers in the payload, separated by spaces. If there are multiple valid payloads, any one will be accepted.

If no such payload can be assembled, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

<RATIONALE>
The description was subtly shifted from a graph-theory framing ("no two modules selected form a collision") to a constraint-satisfaction framing ("for every constraint, the payload includes at most one of the two specified modules"). This removes the direct wording that triggers pattern matching for the Independent Set problem on graphs, forcing the model to deduce the underlying structure from the constraints themselves.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that at most one module per constraint can be selected is logically identical to the condition that no two selected modules form a collision, preserving all valid payloads.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to finding an Independent Set of size k, keeping it firmly in NP-complete.
</PRESERVED_CLASS>
<RISK>
None. The phrase "at most one of the two specified modules" is a mathematically precise and unambiguous requirement.
</RISK>
