<STATEMENT>
# Problem A — Reagent Formulation

Time limit: 5 s
Memory limit: 256 MB

## Description

A biochemical research facility is preparing a composite solution. The inventory holds $n$ candidate reagents, which are indexed using integers starting from 1 up to $n$.

Due to chemical volatility, certain reagents will react destructively if they are mixed together. The facility's database logs $m$ specific neutralization risks. Each risk identifies exactly two reagents that cannot both be present in the final solution.

Your task is to determine whether it is possible to identify exactly $n-k$ reagents to be excluded from the final mixture, such that the remaining $k$ reagents are completely stable. To achieve stability, for every one of the $m$ neutralization risks, at least one of the two reagents involved must be among the excluded ones. 

The physical constraints of the mixing apparatus dictate the limits of the inputs. The apparatus has 48 loading bays, but exactly 2 bays are permanently reserved for pH buffers. The number of candidate reagents $n$ is bounded by the remaining capacity, meaning $n$ is at most 46 (and at least 1). The number of known risks $m$ can be as low as 0 and as high as the theoretical maximum of $n(n-1)/2$. The requested mixture size $k$ will be at least 1 and at most $n$.

## Input

The first line provides three space-separated integers representing the scenario parameters: $n$, $m$, and $k$. 
Following this, there are $m$ lines. Each line specifies two integers $u$ and $v$ ($1 \le u, v \le n$, where $u \neq v$), indicating a pair of reagents that constitute a neutralization risk. Each risk is listed at most once.

## Output

If a stable mixture of exactly $k$ reagents can be formulated, print `YES` on the first line. On the second line, output the $k$ distinct integer indices of the chosen reagents that are **kept** for the mixture (i.e., not excluded), separated by spaces. The evaluation system will accept any valid group that meets all the stability criteria.

If no such mixture is possible, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

<RATIONALE>
I changed the framing from selecting an independent set of size k to excluding a vertex cover of size n-k. This forces the model to recognize the duality between keeping a stable set and excluding at least one element from every conflicting pair, disrupting simple pattern matching. I also embedded the maximum bound of 46 into a scenario about 48 loading bays with 2 reserved, satisfying the indirect bounds strategy while explicitly stating the derived numbers to pass the automated gate.
</RATIONALE>
<PRESERVED_ANSWER>
The answer remains unchanged because excluding n-k items such that every conflict has at least one excluded item is mathematically identical to keeping k items with no internal conflicts.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The complexity class remains NP-complete as it is the exact same problem (Independent Set / Vertex Cover) on the same graph structure.
</PRESERVED_CLASS>
<RISK>
The model might output the excluded items instead of the kept items if it misreads the output instructions, though the bolded "kept" and explicit count "k" mitigate this.
</RISK>
