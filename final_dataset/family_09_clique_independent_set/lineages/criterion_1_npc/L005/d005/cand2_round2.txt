<METHOD_NAME>Incidence Matrix Projection</METHOD_NAME>
<METHOD_DESCRIPTION>Translates a graph problem into a linear algebra constraint satisfaction problem. Vertices become elements of a binary vector, edges become sparse constraint vectors, and the independent set condition becomes a dot-product upper bound. This strips away all graph terminology, preventing LLMs from triggering graph-specific heuristics like "order vertices by degree descending" which are necessary to prune the search space efficiently.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Problem A — Sparse Vector Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

You are tasked with finding a specific binary vector **x** = ($x_1, x_2, \dots, x_n$) of length **n**, where each element $x_i \in \{0, 1\}$.

The vector must satisfy two conditions:
1. The Hamming weight of **x** (the total number of elements equal to 1) must be exactly **k**.
2. You are given a set of **m** sparse constraint vectors $v_1, v_2, \dots, v_m$, each of length **n**. Every constraint vector $v_j$ contains exactly two 1s, with all other elements being 0. For every $j$ from 1 to **m**, the dot product **x** $\cdot$ $v_j$ must be at most 1.

Given **n**, **m**, **k**, and the positions of the 1s for each constraint vector, determine if a valid vector **x** exists. If it does, report one such vector by listing the indices where $x_i = 1$.

## Input

The first line contains three integers **n**, **m**, and **k** (1 ≤ n ≤ 46, 0 ≤ m ≤ n·(n−1)/2, 1 ≤ k ≤ n).
Each of the next **m** lines contains two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v), representing the 1-based indices of the two 1s in that constraint vector. The input will never list the same pair of indices more than once.

## Output

If a valid binary vector **x** exists, print `YES` on the first line. On the second line, print the **k** distinct 1-based indices where $x_i = 1$, separated by spaces. If multiple valid vectors exist, any of them will be accepted. Print only the **k** chosen indices.

If no such vector exists, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

## Note

In Example 2, setting $x_1 = 1, x_3 = 1, x_5 = 1$ (and $x_2 = 0, x_4 = 0$) results in a Hamming weight of 3. The first constraint vector has 1s at positions 1 and 2; the dot product is $1 \cdot 1 + 0 \cdot 1 = 1$, which is $\le 1$. The second constraint vector has 1s at positions 3 and 4; the dot product is $1 \cdot 1 + 0 \cdot 1 = 1$, which is $\le 1$. Thus, the vector is valid.
In Example 1, any binary vector of length 4 with a Hamming weight of 3 will result in a dot product of 2 for at least one of the given constraint vectors, making it impossible to satisfy all conditions.
</STATEMENT>
<RATIONALE>
The problem was reframed from selecting conflict-free jobs to finding a binary vector that satisfies a set of dot-product constraints. This completely removes graph terminology (vertices, edges, cliques, conflicts) while mathematically preserving the exact independent set structure (via the edge-incidence matrix). This forces the model to recognize the underlying graph structure independently if it wants to apply essential graph-specific pruning heuristics (like sorting by degree).
</RATIONALE>
<PRESERVED_ANSWER>
The condition that the dot product of the binary vector `x` and a constraint vector (with 1s at `u` and `v`) is at most 1 is algebraically equivalent to `x_u + x_v <= 1`, which perfectly matches the original constraint that jobs `u` and `v` cannot both be selected.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the Independent Set problem on a graph with `n` vertices and `m` edges, which is NP-complete, simply represented through its edge-incidence matrix.
</PRESERVED_CLASS>
