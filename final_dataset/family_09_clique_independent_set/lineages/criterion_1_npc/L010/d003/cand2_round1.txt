<STATEMENT>
# Problem A — Module Configuration Constraints

Time limit: 5 s   Memory limit: 256 MB

## Description

A software system consists of **n** modules (labeled 1 to **n**). You are evaluating the system for a specific deployment that requires activating exactly **k** modules.

The system is supported by **m** exclusive hardware interfaces. Each interface is shared by exactly two distinct modules. 
When a module is activated, it emits a control signal to every interface it shares. Each interface has a strict hardware capacity of one control signal. If an interface receives signals from both of the modules that share it, its capacity is exceeded and it experiences a critical overload. 

A deployment is considered safe if you activate exactly **k** modules and zero interfaces experience an overload.

Determine if there is a safe deployment. If such a deployment is possible, you must identify one valid set of modules to activate.

## Input

The first line contains three integers **n**, **m**, and **k** (1 ≤ **n** ≤ 46, 0 ≤ **m** ≤ **n**·(**n**−1)/2, 1 ≤ **k** ≤ **n**).
Each of the next **m** lines contains two integers **u** and **v** (1 ≤ **u**, **v** ≤ **n**, **u** ≠ **v**), representing an exclusive hardware interface shared by module **u** and module **v**. No interface is listed more than once.

## Output

If a safe deployment of exactly **k** modules can be formed, output `YES` on the first line. On the second line, output the **k** distinct module labels that make up this deployment, separated by spaces. If multiple valid deployments exist, print any one of them (in any order).

If no such deployment can be formed, output `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

## Note

In Example 2, evaluating the interfaces shows that activating modules 1, 3, and 5 causes no overloads. Interface (1, 2) receives a signal only from module 1, and interface (3, 4) receives a signal only from module 3. Thus, the deployment is safe. In Example 1, any selection of three modules will cause at least one interface to receive signals from both of its shared modules, triggering an overload. Therefore, no safe deployment of size 3 exists.
</STATEMENT>
<RATIONALE>
Removed the direct definition of safety as "at most one of the two modules" being selected. Replaced it with a physical description of signal capacities where an interface overloads if it receives signals from both of its shared modules. This forces the model to deduce the pairwise mutual exclusion property rather than having it explicitly handed to it, preventing immediate pattern matching to standard graph/independent-set wording.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that an interface overloads if both modules are activated is logically identical to the original constraint that at most one module of the pair can be chosen, ensuring all safe deployments remain exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires finding a set of exactly k vertices such that no two share an edge, which is the NP-complete Independent Set problem.
</PRESERVED_CLASS>
