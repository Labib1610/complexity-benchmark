# Problem A — Phonotactic Constraints

Time limit: 5 s   Memory limit: 256 MB

## Description

A linguist is constructing a synthetic language featuring **n** distinct phonemes (labeled 1 to **n**). There are **m** phonotactic constraints between certain pairs of phonemes. A constraint between phoneme **u** and phoneme **v** means they are considered unpronounceable when both are present in the language's core inventory, so they cannot both be chosen.

A valid core inventory is exactly a set of phonemes where no phonotactic constraint exists between any two chosen phonemes.

You are given a target inventory size **k**. Determine if there is a valid core inventory containing exactly **k** phonemes. If such an inventory can be formed, you must identify one.

## Input

The first line contains three integers **n**, **m**, and **k** (1 ≤ n ≤ 46, 0 ≤ m ≤ n·(n−1)/2, 1 ≤ k ≤ n).
Each of the next **m** lines contains two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v), representing a phonotactic constraint between phoneme **u** and phoneme **v**. No constraint pair is listed more than once.

## Output

If a valid core inventory of exactly **k** phonemes can be formed, output `YES` on the first line. On the second line, output the **k** distinct phoneme labels that make up this inventory, separated by spaces. If multiple valid inventories exist, print any one of them (in any order).

If no such inventory can be formed, output `NO`.

## Examples

### Example 1

**Input**
```
4 4 3
1 2
1 3
2 3
3 4
```

**Output**
```
NO
```

### Example 2

**Input**
```
5 2 3
1 2
3 4
```

**Output**
```
YES
1 3 5
```

### Example 3

**Input**
```
3 3 1
1 2
2 3
1 3
```

**Output**
```
YES
1
```

## Note

In Example 2, phonemes 1, 3, and 5 have no phonotactic constraints among them. In Example 1, no three of the four phonemes are mutually free of constraints.

Changed the scenario from monitoring devices with mutual conflicts to a linguistic setting involving phonemes and phonotactic constraints. This removes any semantic cues that might trigger memorized templates for "devices/conflicts" while forcing the model to recognize the underlying independent set structure purely from the logical constraints of the new domain.
</RATIONALE>
<PRESERVED_ANSWER>
The entities and forbidden pairs map one-to-one to the original devices and conflicts, so any valid selection of $k$ items in the new scenario corresponds exactly to a valid selection in the original.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the Independent Set problem on a graph with $n$ vertices and $m$ edges, which is NP-complete.
</PRESERVED_CLASS>
