# Pipeline Stage 2: Safe Batch Selection

Time limit: 2 s
Memory limit: 256 MB

## Description

In our automated deployment pipeline, deploying microservices to the testing environment occurs in three consecutive stages. You are responsible only for building the software for Stage 2.

**Stage 1: Conflict Analysis.**
A static analysis tool examines the **n** available microservices, which are assigned sequential IDs starting from 1. The maximum possible value for **n** is dictated by our legacy registry's capacity, which is exactly 100,000. There is always at least one microservice.

The tool identifies **m** pairs of microservices that share a mutable database table, logging them as conflicting pairs. The conflict report can be empty, but its maximum length is strictly capped at 400,000 entries. The conflict relationship is symmetric. 

By architectural design, every microservice is deployed as either a "transmitter" or a "receiver". A conflict is strictly an incompatibility between a transmitter and a receiver. A transmitter will never conflict with another transmitter, and a receiver will never conflict with another receiver. The specific role (transmitter or receiver) of each microservice is omitted from the report.

**Stage 2: Safe Batch Selection (Your Task).**
The deployment coordinator receives the list of microservices and the conflict report. It must select exactly **k** distinct microservices to form a "safe batch." The target size **k** is at least 1 and will not exceed **n**. 

A batch is safe if absolutely no two microservices within it are listed as conflicting. You must determine if such a batch can be formed. If multiple valid safe batches of size **k** are possible, any one of them is accepted.

**Stage 3: Integration Testing.**
The safe batch produced by Stage 2 is deployed to an isolated cluster for performance testing.

## Input

The first line contains three integers **n**, **m**, and **k**. Their valid ranges are exactly as established by the system limits described above.
The following **m** lines provide the conflict data. Each line contains two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v), representing a conflicting pair of microservices. No pair is listed more than once.

## Output

If a safe batch of exactly **k** microservices can be formed, print `YES` on the first line. On the second line, print the **k** distinct microservice numbers that form this batch, separated by spaces. If multiple safe batches of size **k** exist, any of them is accepted.

If it is impossible to form a safe batch of size **k**, print `NO`.

## Examples

### Example 1

**Input**
```
4 4 2
1 3
1 4
2 3
2 4
```

**Output**
```
YES
1 2
```

### Example 2

**Input**
```
5 0 5
```

**Output**
```
YES
1 2 3 4 5
```

### Example 3

**Input**
```
4 4 3
1 3
1 4
2 3
2 4
```

**Output**
```
NO
```
