<STATEMENT>
# Concurrent Maintenance Selection

Time limit: 2 s   Memory limit: 256 MB

## Description

A cloud infrastructure contains **n** microservices (numbered 1 to **n**). Certain pairs of microservices share a mutable data volume and will cause data corruption if they execute their maintenance routines concurrently. 

The system is built on a strictly directional dataflow paradigm. Under the hood, every microservice acts purely as either an upstream producer or a downstream consumer (though you are not explicitly told which is which). A shared mutable volume only ever exists to pass data from a producer to a consumer. Therefore, it is guaranteed that any shared volume connects exactly one producer and one consumer. Two producers never share a volume with each other, and two consumers never share a volume with each other.

You must determine if it is possible to select exactly **k** microservices to run their maintenance routines concurrently without any risk of data corruption, and if so, identify them.

## Input

The first line provides three integers **n**, **m**, and **k**. 
The infrastructure has a minimum operational requirement of 1 microservice, and a maximum deployment limit of 100000 microservices (1 ≤ n ≤ 100000). The count of shared volumes can be as low as 0, or up to the network's maximum of 400000 (0 ≤ m ≤ 400000). The target selection size is at least 1, up to the total number of deployed microservices (1 ≤ k ≤ n).

The next **m** lines each contain two integers **u** and **v** (1 ≤ u, v ≤ n, u ≠ v), indicating that microservices **u** and **v** share a data volume. No pair is listed more than once. The input is guaranteed to adhere to the directional dataflow architecture described above.

## Output

If a safe selection of **k** microservices exists, output `YES` on the first line. On the second line, output **k** distinct integers representing the IDs of the chosen microservices, separated by spaces. If multiple valid selections exist, any is acceptable.

If no such selection can be made, output `NO`.

## Examples

### Example 1

**Input**
```
4 4 2
1 3
1 4
2 3
2 4
```

**Output**
```
YES
1 2
```

### Example 2

**Input**
```
5 0 5
```

**Output**
```
YES
1 2 3 4 5
```

### Example 3

**Input**
```
4 4 3
1 3
1 4
2 3
2 4
```

**Output**
```
NO
```

This removes the surface-level hint of a bipartite graph while perfectly preserving the structural guarantee. Models must now deduce the bipartite nature of the conflict graph from the producer-consumer mechanics. Bounds are stated as physical and operational limits with explicit inequalities to satisfy strict checkers.
