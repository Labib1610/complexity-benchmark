**Solution Explanation**

For every relic we have to choose a room number `room[i] ( 1 … T )`.

*   If there is a rule `a → b` then `room[b] ≥ room[a] + 1`
*   In each room at most `M` relics may be placed.

The corridor is linear, therefore the rooms are ordered like time slots.
The problem is exactly the feasibility version of scheduling unit‑time jobs
with precedence constraints on `M` identical parallel machines
(the machines are the rooms, the time is the room index).

--------------------------------------------------------------------

#### 1.   Topological order

If the directed graph of rules contains a directed cycle, the answer is
impossible – a cycle would require a strict increase of the room number
along the cycle and can never be satisfied.
We run Kahn’s algorithm, obtain a topological order `topo`
(and also the list of predecessors for each vertex).

--------------------------------------------------------------------

#### 2.   Lower bound of a relic

While processing the vertices in topological order we already know the
rooms of all its predecessors.
The smallest room that can still be used for the current relic is  

```
lb = 1 + max( room[p] for p in predecessors )
```

If the relic has no predecessor, `lb = 1`.

--------------------------------------------------------------------

#### 3.   “first free room ≥ lb”

We have to put the relic into the **earliest** room `r ≥ lb`
that still has free capacity.
If we always use the earliest possible room, later relics never lose a
possibility – this greedy rule is optimal for feasibility
(standard result for unit‑time jobs on identical parallel machines).

To find the earliest free room fast we use a *disjoint set union* (DSU)
structure that stores for every room `i` the smallest index `≥ i`
that still has free capacity.

```
parent[i] = i                     if room i is not full yet
parent[i] = find(i+1)              otherwise
```

`find(x)` returns the current representative of the set, i.e. the first
still‑available room `≥ x`.  
When a room becomes full we union it with the next one.

All operations are amortised `α(T)` (inverse Ackermann), fast enough.

--------------------------------------------------------------------

#### 4.   Algorithm
```
read input
build adjacency list, indegrees
topological order = Kahn()
if not all vertices processed -> print NO

cnt[1..T] = 0                     # how many relics already placed
parent[i] = i  (i = 1..T+1)        # extra sentinel T+1 = “no room”

room[1..n] = 0

for v in topological order:
        lb = 1
        for p in predecessors[v]:
                lb = max(lb, room[p] + 1)

        r = find(lb)               # earliest free room ≥ lb
        if r > T:                  # no room left
                print NO and exit

        room[v] = r
        cnt[r] += 1
        if cnt[r] == M:            # room becomes full
                parent[r] = find(r+1)   # union with next

print YES
output room[1] … room[n]
```

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` and a valid assignment
iff such an assignment exists.

---

##### Lemma 1  
If the algorithm assigns a relic `v` to room `r`, then all precedence
constraints `p → v` are satisfied (`room[p] < r`).

**Proof.**  
When `v` is processed, every predecessor `p` has already been assigned
(because we follow a topological order).  
`lb` is defined as `1 + max(room[p])`.  
The algorithm chooses `r = find(lb) ≥ lb`.  
Hence `r ≥ 1 + max(room[p])`, i.e. `room[p] ≤ r-1 < r`. ∎



##### Lemma 2  
During the algorithm, `find(x)` always returns the smallest room index
`y ≥ x` whose current count is `< M`. If no such room exists, it returns
`T+1`.

**Proof.**  
Initially every room is empty, `parent[i]=i`, the statement holds.
Assume it holds before processing a relic.
When a relic is placed into room `r`, we increase `cnt[r]`.
If `cnt[r]` becomes `M`, we set `parent[r] = find(r+1)`.  
Thus `r` is removed from the set of available rooms and now points to the
next available one. All other `parent` values stay unchanged, therefore
the invariant is preserved. ∎



##### Lemma 3  
If the algorithm fails (returns `NO`), then **no** feasible assignment
exists.

**Proof.**  
The algorithm fails only when for some relic `v` we have `r = find(lb) > T`,
i.e. there is **no** room `≥ lb` with remaining capacity.
All rooms `< lb` are too early (would violate a predecessor), all rooms
`≥ lb` are already full.  
Consider any feasible assignment. Because of Lemma&nbsp;1 it must place
`v` in a room `≥ lb`. Since every such room is already full, the
assignment would need to put more than `M` relics into at least one
room – impossible. Hence no feasible assignment exists. ∎



##### Lemma 4  
If the algorithm finishes successfully, the produced assignment
satisfies all capacity limits.

**Proof.**  
By Lemma&nbsp;2 a room is used only while its count `< M`. When the count
reaches `M` the room is removed from the set of available rooms, therefore
no further relic can be assigned to it. Hence at most `M` relics are placed
in each room. ∎



##### Lemma 5  
If a feasible assignment exists, the algorithm never fails.

**Proof.**  
Assume a feasible assignment exists.
Process the vertices in the same topological order as the algorithm.
Induction on this order:

*Induction hypothesis*: after processing the first `k-1` vertices,
the algorithm has placed them into rooms not later than in the feasible
assignment, and all capacity constraints are still respected.

For the `k`‑th vertex `v` let `lb` be the algorithm’s lower bound.
In the feasible assignment `v` is placed in some room `r* ≥ lb`
(because all its predecessors are already placed no later than the
algorithm, thus `lb` is a valid lower bound there as well).

All rooms `< r*` have at most `M` relics in the feasible assignment,
hence also at most `M` relics among the first `k-1` vertices.
Consequently at the moment of processing `v` the algorithm still finds a
free room `r ≤ r*` (the earliest free one). Therefore it does not fail.
∎



##### Theorem  
The algorithm outputs `YES` and a correct assignment **iff** such an
assignment exists; otherwise it outputs `NO`.

**Proof.**  

*If part*:  
When the algorithm outputs `YES`, by Lemma&nbsp;1 all precedence constraints
are satisfied, by Lemma&nbsp;4 capacities are respected – the assignment is
valid.

*Only‑if part*:  
If a valid assignment exists, the graph is acyclic, so Kahn’s algorithm
produces a topological order. By Lemma&nbsp;5 the algorithm never fails,
hence it finishes and prints `YES`.  

If the algorithm prints `NO`, by Lemma&nbsp;3 no feasible assignment can
exist. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Topological sort* : `O(n + m)`  
*Processing vertices* : each vertex scans its incoming edges once,
overall `O(n + m)`.  
*DSU operations* : at most `n` `find` calls and at most `T` unions,
amortised `O((n+T) α(T))`.  

Memory consumption: adjacency lists `O(n + m)`, arrays of size `O(n+T)`.  
Both limits satisfy the given constraints.

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(1 << 25)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    M = int(next(it))
    T = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    pred = [[] for _ in range(n)]
    indeg = [0] * n
    for _ in range(m):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        adj[a].append(b)
        pred[b].append(a)
        indeg[b] += 1

    # Kahn's algorithm
    from collections import deque
    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []
    while q:
        v = q.popleft()
        topo.append(v)
        for to in adj[v]:
            indeg[to] -= 1
            if indeg[to] == 0:
                q.append(to)

    if len(topo) != n:
        print("NO")
        return

    # DSU for next free room
    parent = list(range(T + 2))   # 1..T, T+1 sentinel

    def find(x: int) -> int:
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    cnt = [0] * (T + 1)
    room = [0] * n

    for v in topo:
        lb = 1
        for p in pred[v]:
            rp = room[p] + 1
            if rp > lb:
                lb = rp
        r = find(lb)
        if r > T:
            print("NO")
            return
        room[v] = r
        cnt[r] += 1
        if cnt[r] == M:
            parent[r] = find(r + 1)   # union with next

    print("YES")
    print(' '.join(str(room[i]) for i in range(n)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
