**Solution Explanation**

For every injection we have  

* a *release day* `L[i]` – the earliest day it may be given (all its
  predecessors must be earlier),  
* a *deadline* `R[i]` – the latest day it may be given (all its successors
  must be later).

Both are integers in `[1,T]`.  
If we can put every injection on a day `d[i]` with `L[i] ≤ d[i] ≤ R[i]`
and at most `M` injections on each day, the answer is **YES**,
otherwise **NO**.

The problem becomes the classic “unit‑length jobs with release times and
deadlines on `M` identical machines”.  
It is solvable greedily:

```
for day = 1 .. T
        insert into a priority queue all jobs with L ≤ day
        (key = R, smallest deadline first)
        take up to M jobs from the queue whose R ≥ day
        assign them to the current day
```

If at some day the queue contains a job with `R < day` the schedule is
impossible.

The only remaining work is to compute the intervals `[L[i],R[i]]`.

--------------------------------------------------------------------

#### 1.   Computing earliest possible day `L[i]`

The precedence graph is a DAG (otherwise the answer is obviously **NO**).
A topological order is obtained by Kahn’s algorithm.
Processing vertices in that order

```
L[i] = 1 + max{ L[p] | p → i }          (0 if no predecessor)
```

`L[i]` is the length of the longest directed path ending in `i`
plus one, i.e. the earliest day respecting all strict “earlier” constraints.

--------------------------------------------------------------------

#### 2.   Computing latest possible day `R[i]`

We run the same algorithm on the reversed graph.
Processing vertices in reverse topological order

```
R[i] = T - max{ (T - R[s]) | i → s }    (or simply)
R[i] = min{ R[s] - 1 | i → s }          (T if no successor)
```

`R[i]` is the latest day that still leaves at least one day for every
successor.

If for some vertex `L[i] > R[i]` the instance is impossible.

--------------------------------------------------------------------

#### 3.   Greedy scheduling with a priority queue

All vertices are sorted by `L`.  
During the scan over days we maintain a min‑heap ordered by `R`.

```
ptr = 0                                 # index in the sorted list
for day = 1 .. T
        while ptr < n and L[order[ptr]] <= day:
                push (R[order[ptr]], order[ptr]) into heap
                ptr += 1
        repeat up to M times:
                if heap empty: break
                (r, v) = pop heap
                if r < day:               # missed its deadline
                        impossible
                assign day to v
```

If after the last day the heap is not empty, some jobs could not be placed
→ impossible.

The algorithm is `O((n+m) + T log n)` and uses `O(n+m)` memory,
well inside the limits.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints **YES** and a valid schedule iff such a
schedule exists.

---

##### Lemma 1  
For every injection `i` the value `L[i]` computed in section&nbsp;1 is the
smallest day on which `i` can be placed in any feasible schedule.
Analogously `R[i]` from section&nbsp;2 is the largest feasible day.

**Proof.**  
`L[i] = 1 + max L[p]` over all predecessors `p`.  
All predecessors must be on strictly earlier days, therefore any feasible
day for `i` is at least `1 + max day(p)`. The induction base (sources) gives
`L = 1`. The construction shows that day `L[i]` itself is attainable
(by placing each predecessor on its own earliest day). Same argument
backwards for `R[i]`. ∎



##### Lemma 2  
If the greedy scheduling algorithm assigns a day to every injection,
the obtained assignment respects all precedence constraints.

**Proof.**  
Consider an edge `a → b`. By Lemma&nbsp;1 we have `L[b] ≥ L[a] + 1`.
When day `d = day(a)` is processed, `a` is already in the heap
(because `L[a] ≤ d`). It is removed and fixed on that day.
Vertex `b` cannot be taken before day `L[b]`, i.e. at the earliest on day
`d+1`. Hence `day(a) < day(b)`. ∎



##### Lemma 3  
If the greedy algorithm fails (either a job with `R < current day` appears
in the heap or the heap is non‑empty after day `T`), then **no** feasible
schedule exists.

**Proof.**  
The algorithm always keeps in the heap exactly the jobs whose release
time has passed but are not yet scheduled.
When a job with `R < day` is at the top, every unscheduled job has deadline
≥ that `R`. All of them must be placed on some day ≥ `day`, which is already
later than their deadline – impossible.  
If after day `T` the heap still contains jobs, each of them has `L ≤ T`,
so they could only be placed on days `1..T`, all of which are already full
(`M` jobs per day). Hence no schedule fits. ∎



##### Lemma 4  
If a feasible schedule exists, the greedy algorithm succeeds.

**Proof.**  
Consider the days from `1` to `T`.  
Induction on the day number: assume that up to day `d‑1` the algorithm has
chosen a subset of jobs that can be extended to a full feasible schedule.
On day `d` the algorithm sees all jobs with `L ≤ d`. Among them it picks up
to `M` jobs with smallest deadlines `R`.  
Take any optimal feasible schedule `S`. Replace on day `d` the jobs of `S`
by the jobs chosen by the algorithm (they are a subset of the jobs
available to `S` because they have earlier or equal deadlines). This
exchange does not violate any deadline (the algorithm never picks a job
with later deadline than a job it discards) and does not affect feasibility
of the remaining unscheduled jobs (their release times are unchanged and
their deadlines are not earlier than the discarded ones). Thus after the
exchange a feasible schedule still exists for the remaining jobs.
By induction the algorithm never gets stuck and finally schedules all
jobs. ∎



##### Lemma 5  
The schedule produced by the algorithm satisfies the daily capacity `M`.

**Proof.**  
The algorithm assigns at most `M` jobs on each day by construction
(the inner loop runs at most `M` times). ∎



##### Theorem  
The program outputs **YES** and a list of days exactly when a feasible
assignment exists; otherwise it outputs **NO**.

**Proof.**  

*If the program prints **YES**:*  
All jobs received a day, capacity is respected (Lemma&nbsp;5) and
precedences hold (Lemma&nbsp;2). Hence the assignment is feasible.

*If a feasible assignment exists:*  
`L[i] ≤ R[i]` for all `i` (otherwise impossible).  
By Lemma&nbsp;4 the greedy scheduler never fails, therefore the program
assigns a day to every job and prints **YES**.

Thus the output is correct in both directions. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Topological sorting & computing `L` and `R`*: `O(n + m)` time, `O(n + m)` memory.  
*Greedy scheduling*: each vertex is inserted and removed once from the heap  
  `O(n log n)` operations, plus `T` iterations (`T ≤ 10^5` in typical limits).  
Overall time `O((n+m) + T log n)`, memory `O(n + m)`.

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
import heapq

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    M = int(next(it))
    T = int(next(it))
    m = int(next(it))

    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]
    indeg = [0] * n
    outdeg = [0] * n
    for _ in range(m):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        g[a].append(b)
        rg[b].append(a)
        indeg[b] += 1
        outdeg[a] += 1

    # topological order
    from collections import deque
    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []
    while q:
        v = q.popleft()
        topo.append(v)
        for to in g[v]:
            indeg[to] -= 1
            if indeg[to] == 0:
                q.append(to)
    if len(topo) != n:
        print("NO")
        return

    # earliest L
    L = [1] * n
    for v in topo:
        mx = 0
        for p in rg[v]:
            if L[p] > mx:
                mx = L[p]
        L[v] = mx + 1

    # latest R
    R = [T] * n
    for v in reversed(topo):
        mn = T + 1
        for to in g[v]:
            if R[to] - 1 < mn:
                mn = R[to] - 1
        if mn <= T:
            R[v] = mn
        else:
            R[v] = T

    for i in range(n):
        if L[i] > R[i] or L[i] > T or R[i] < 1:
            print("NO")
            return

    # sort vertices by L
    order = list(range(n))
    order.sort(key=lambda x: L[x])

    assign = [0] * n
    heap = []          # (R, vertex)
    ptr = 0
    for day in range(1, T + 1):
        while ptr < n and L[order[ptr]] <= day:
            v = order[ptr]
            heapq.heappush(heap, (R[v], v))
            ptr += 1
        cnt = 0
        while cnt < M and heap:
            r, v = heapq.heappop(heap)
            if r < day:
                print("NO")
                return
            assign[v] = day
            cnt += 1

    if any(a == 0 for a in assign):
        print("NO")
        return

    print("YES")
    print(' '.join(map(str, assign)))

if __name__ == "__main__":
    solve()
```

and conforms to the required input‑output format.
