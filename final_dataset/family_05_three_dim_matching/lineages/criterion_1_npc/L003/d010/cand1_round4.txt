<METHOD_DESCRIPTION>Removes the asymmetric "stage i gets frequency i" wording. Instead, presents all three parameters symmetrically: choose k items such that no two share a frequency, no two share an amplitude, and no two share a phase. This prevents models from immediately hardcoding a loop over stages 1 to k and partitioning the input by frequency, forcing them to realize the symmetry or write a generic 3D matching solver which they might fail to optimize properly.</METHOD_DESCRIPTION>

<STATEMENT>
# Quantum Resonance Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

You are designing a quantum resonance core which requires exactly **k** distinct modules.

You are provided with a catalog of **t** available modules. Each module is characterized by exactly 3 parameters: Frequency, Amplitude, and Phase. All parameter values are integers between 1 and **k**.

To achieve perfect stability, you must select exactly **k** modules from the catalog such that all the following conditions are met:
1. No two selected modules share the same Frequency parameter.
2. No two selected modules share the same Amplitude parameter.
3. No two selected modules share the same Phase parameter.

Determine if such a stable core can be formed by selecting exactly **k** modules from the catalog.

## Input

The first line provides two integers, **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k³). Here, **k** represents the number of modules required, and **t** is the total number of available modules in the catalog.

The next **t** lines each contain three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), representing the Frequency, Amplitude, and Phase parameters of a module in the catalog. Every module listed in the input is distinct. You may choose only among these listed modules, and each module from the catalog may be selected at most once.

## Output

If a perfectly stable core can be formed, output `YES` on the initial line. Following this, output **k** lines each containing three integers `x y z`, specifying the modules used for your core. If several valid selections exist, supplying any one of them is sufficient. The modules may be printed in any sequence.

If it is impossible to find **k** modules satisfying the condition, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, the two available modules are `1 1 1` and `2 1 2`. We need to select exactly 2 modules. However, both of these modules have an Amplitude of 1. This violates the rule that no two selected modules may share the same Amplitude parameter. Thus, it is impossible to form a stable core.
</STATEMENT>
<RATIONALE>
The asymmetric constraint assigning Frequency `i` to stage `i` was replaced with a symmetric constraint requiring all selected modules to have distinct Frequencies. This prevents solvers from trivially treating Frequency as a fixed stage index and forces them to recognize that selecting `k` values from `1..k` without duplicates naturally covers all values.
</RATIONALE>
<PRESERVED_ANSWER>
Selecting exactly `k` modules with distinct values in `1..k` for a parameter is mathematically identical to requiring every value from `1..k` to appear exactly once, preserving all valid subsets.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, asking for `k` disjoint triples from a subset of `k × k × k`.
</PRESERVED_CLASS>
