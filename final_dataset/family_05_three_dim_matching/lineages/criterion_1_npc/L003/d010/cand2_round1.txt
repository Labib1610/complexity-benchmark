<METHOD_NAME>Pigeonhole XOR Obfuscation</METHOD_NAME>
<METHOD_DESCRIPTION>Conceals an exact-cover/3D-matching constraint by converting the distinctness requirement into a target state of an array updated via bitwise XOR. Because there are exactly k operations and k indices, the only way to avoid leaving any index at 0 (which would fail the target state) is to hit every index exactly once. Models that literally translate the XOR operations will write a simulation-based backtracking search without early pruning, leading to TLE, whereas models that mathematically deduce the pigeonhole constraint will recover the exact-cover structure.</METHOD_DESCRIPTION>

<STATEMENT>
# Quantum State Preparation

Time limit: 5 s   Memory limit: 256 MB

## Description

You are tasked with preparing a specific quantum state using a sequence of exactly **k** operations. The quantum system consists of three independent registers: the Alpha register, the Beta register, and the Gamma register. Each register contains **k** elements, indexed from 1 to **k**.

Initially, all elements in all three registers hold the value 0.

You are provided with a catalog of **t** available quantum operations. Each operation is characterized by three target indices: $x$, $y$, and $z$, all integers between 1 and **k**.
When you apply an operation characterized by $(x, y, z)$, the system undergoes the following transformations using bitwise XOR ($\oplus$):
- The $x$-th element of the Alpha register is updated: $\text{Alpha}[x] \leftarrow \text{Alpha}[x] \oplus x$
- The $y$-th element of the Beta register is updated: $\text{Beta}[y] \leftarrow \text{Beta}[y] \oplus y$
- The $z$-th element of the Gamma register is updated: $\text{Gamma}[z] \leftarrow \text{Gamma}[z] \oplus z$

All other elements in the registers remain unchanged by this operation. Because bitwise XOR is commutative and associative, the order in which the chosen operations are applied does not matter.

To achieve the target resonance, you must select exactly **k** distinct operations from the catalog and apply them to the system. Each operation from the catalog may be selected at most once. 

Your goal is to choose a set of exactly **k** operations such that, after all of them have been applied, the registers satisfy the following conditions for every index $i$ from 1 to **k**:
- $\text{Alpha}[i] = i$
- $\text{Beta}[i] = i$
- $\text{Gamma}[i] = i$

Determine if such a set of **k** operations can be selected from the catalog.

## Input

The first line provides two integers, **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k³). Here, **k** represents the number of elements in each register (and thus the number of operations required), and **t** is the total number of available operations in the catalog.

The next **t** lines each contain three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), representing the target indices of an operation in the catalog. Every operation listed in the input is distinct. You may choose only among these listed operations, and each may be selected at most once.

## Output

If a valid set of **k** operations can be chosen, output `YES` on the initial line. Following this, output **k** lines each containing three integers `x y z`, specifying the operations used. If several valid selections exist, supplying any one of them is sufficient. The operations may be printed in any sequence.

If it is impossible to find **k** operations satisfying the condition, output `NO`.

## Note

In Example 2, there are 2 available operations: `1 1 1` and `2 1 2`. 
Because exactly **k** = 2 operations must be selected, you must choose both of them.
Applying `1 1 1`:
- Alpha[1] becomes $0 \oplus 1 = 1$
- Beta[1] becomes $0 \oplus 1 = 1$
- Gamma[1] becomes $0 \oplus 1 = 1$

Applying `2 1 2`:
- Alpha[2] becomes $0 \oplus 2 = 2$
- Beta[1] becomes $1 \oplus 1 = 0$
- Gamma[2] becomes $0 \oplus 2 = 2$

After both operations, the Beta register has elements Beta[1] = 0 and Beta[2] = 0. This fails the requirement that Beta[$i$] = $i$ for all $i$ (we needed Beta[1] = 1 and Beta[2] = 2). Thus, it is impossible to form the target state.
</STATEMENT>
<RATIONALE>
I removed the explicit distinctness constraints and the "stage assignment" framing, replacing them with a state-preparation scenario using bitwise XOR. Because there are exactly $k$ operations and $k$ elements per register, the only way to avoid leaving any element at 0 (which fails the $A[i]=i$ target) is to hit every element exactly once. This forces models to either deduce the pigeonhole principle to recover the exact-cover formulation, or write a naive XOR simulation search that will Time Limit Exceed due to lack of early pruning.
</RATIONALE>
<PRESERVED_ANSWER>
Since an element updated 0 times remains 0 (invalid), and updating any element 3 or more times requires subtracting operations from other elements (leaving them at 0), every index must be hit exactly once; thus the valid sets of operations are exactly the valid 3D matchings from the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, as the XOR state requirement is mathematically isomorphic to an exact cover constraint over the three dimensions.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the XOR operation as applying to the entire register rather than a specific index, though the wording "The x-th element of the Alpha register... Alpha[x]" is highly explicit.
</RISK>
