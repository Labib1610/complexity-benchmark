<STATEMENT>
# Quantum Resonance Selection

Time limit: 5 s   Memory limit: 256 MB

## Description

You are designing a quantum resonance core. The system's dimensional order is **k**, meaning the core requires exactly **k** modules to achieve stability.

You are provided with a catalog of **t** available modules. Each module is characterized by exactly 3 parameters: Frequency, Amplitude, and Phase. All parameter values are integers between 1 and **k**.

To achieve perfect stability, you must select exactly **k** modules from the catalog such that the following three conditions are met:
1. The Frequency values of the **k** selected modules must include every integer from 1 to **k** exactly once.
2. The Amplitude values of the **k** selected modules must include every integer from 1 to **k** exactly once.
3. The Phase values of the **k** selected modules must include every integer from 1 to **k** exactly once.

Determine if such a stable core can be formed by selecting exactly **k** modules from the catalog.

## Input

The first line provides two integers, **k** and **t**. The integer **k** represents the dimensional order of the core (and thus the number of modules required), and **t** is the total number of available modules in the catalog.
The dimensional order **k** is guaranteed to be at least 1 and at most the total number of players on the pitch at the start of a standard association football match. The catalog size **t** will be between 0 and the cube of the dimensional order, inclusive.

The next **t** lines each contain three integers **x**, **y**, and **z** (positive integers up to **k**), representing the Frequency, Amplitude, and Phase parameters of a module in the catalog. Every module listed in the input is distinct. You may choose only among these listed modules, and each module from the catalog may be selected at most once.

## Output

If a perfectly stable core can be formed, output `YES` on the initial line. Following this, output **k** lines each containing three integers `x y z`, specifying the modules used for your core. If several valid selections exist, supplying any one of them is sufficient. The modules may be printed in any sequence.

If it is impossible to find **k** modules satisfying the condition, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, the two available modules are `1 1 1` and `2 1 2`. We need to select 2 modules. The only possible selection is choosing both modules. Their Frequency values are 1 and 2, which includes every integer from 1 to 2 exactly once. Their Phase values are 1 and 2, which also includes every integer from 1 to 2 exactly once. However, both of these modules have an Amplitude of 1. The Amplitude values are 1 and 1, which fails the requirement to include every integer from 1 to 2 exactly once. Thus, it is impossible to form a stable core.
</STATEMENT>
<RATIONALE>
I reformulated the constraints so that all three parameters (Frequency, Amplitude, Phase) are treated symmetrically, requiring each to include every integer from 1 to k exactly once. This removes the explicit "stage i gets Frequency i" framing that previously allowed models to trivially partition the search space by frequency. S07 is also used to express the upper bound of k indirectly.
</RATIONALE>
<PRESERVED_ANSWER>
Selecting exactly k modules where each parameter includes exactly all integers from 1 to k is mathematically equivalent to assigning one module per frequency 1..k while ensuring no duplicate amplitudes or phases.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to 3-Dimensional Matching, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might fail to parse the association football reference for the bound of 22, but deriving it requires only basic general knowledge and does not introduce algorithmic ambiguity.
</RISK>
