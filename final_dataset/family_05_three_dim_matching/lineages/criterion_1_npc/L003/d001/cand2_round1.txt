# Problem A — Pipeline Hardware Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

A manufacturing facility relies on a three-stage automated pipeline to produce custom hardware.

**Stage 1: Material Preparation.** Silicon wafers are prepped and moved to the active floor.

**Stage 2: Pipeline Hardware Synchronization.** The facility contains exactly **k** robotic arms, **k** optical sensors, and **k** control modules, each indexed from 1 to **k**. A functional production track must integrate exactly one arm, one sensor, and one module. Because of strict calibration tolerances, only specific combinations of `(arm, sensor, module)` can successfully operate together. The synchronization stage must establish exactly **k** parallel production tracks such that every single robotic arm, optical sensor, and control module in the facility is allocated to exactly one track.

**Stage 3: Quality Assurance.** The synchronized tracks pass their output to the testing bay for diagnostics.

Your system handles Stage 2. Given the batch size **k** and a log of viable hardware combinations from the latest calibration cycle, determine whether it is possible to successfully establish the **k** parallel tracks. If it is possible, provide the track assignments so the pipeline can advance to Stage 3.

## Input

The first line provides two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k), representing the number of available units for each hardware category and the total number of viable combinations, respectively.
The following **t** lines each contain three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k), indicating that robotic arm **x**, optical sensor **y**, and control module **z** can be integrated into a functional track. No combination is duplicated in the log.

## Output

If the facility can successfully establish **k** parallel tracks, output `YES` on the first line. Following this, output **k** lines detailing the hardware assignments for each established track, where each line contains three integers `x y z` representing the arm, sensor, and module used. 

If there are multiple ways to successfully allocate the hardware, transmitting any one valid allocation will satisfy the synchronization requirement. The testing bay evaluates each track independently, so the order in which the tracks are listed in your output is immaterial.

If it is impossible to establish the required parallel tracks, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable combinations rely on optical sensor 1. Consequently, optical sensor 2 remains unallocated, making it impossible to establish 2 complete tracks.
