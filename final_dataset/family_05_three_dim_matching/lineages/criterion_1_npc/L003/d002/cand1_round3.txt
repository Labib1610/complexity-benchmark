# Problem A — Pipeline Hardware Allocation

Time limit: 5 s   Memory limit: 256 MB

## Description

A manufacturing facility builds custom fluid networks through an automated assembly process.

The facility houses exactly **k** Pumps, **k** Filters, and **k** Valves. Inside each equipment category, the items are labeled with integer IDs starting from 1 up to **k**.

A functional fluid pipeline is formed by linking together exactly one Pump, one Filter, and one Valve. However, due to complex pressure dependencies, a pipeline can only operate safely if its specific combination of (Pump, Filter, Valve) is explicitly listed as a tested blueprint. 

Your objective is to safely operate all the facility's hardware simultaneously. To do this, you must construct a set of pipelines from the tested blueprints. A valid operation plan must utilize the entire inventory: all **k** Pumps, all **k** Filters, and all **k** Valves must be active. Because physical components cannot be duplicated, any chosen blueprint consumes its three specific parts, making them unavailable for others.

Given the quantity **k** and the list of tested blueprints, determine if the facility can successfully achieve a full deployment of all its equipment. If so, output the blueprints to be activated.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k).

Then, **t** lines follow. Each line consists of three integers **x**, **y**, and **z** (1 ≤ x, y, z ≤ k). These represent the IDs of a Pump, Filter, and Valve, respectively, that form a tested blueprint. All listed blueprints are unique (no combination is listed more than once).

## Output

If a full deployment is possible, print `YES` on the first line. On the following **k** lines, print three integers `x y z` per line, representing the equipment used in each activated pipeline. Any valid deployment where all equipment is fully utilized without overlap will be accepted. You may print the chosen pipelines in any order.

If there is no way to achieve a full deployment, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both tested blueprints require Filter 1. This means Filter 2 cannot be deployed, making it impossible to achieve a full deployment of all equipment.

Removed the textbook exact cover phrasing ("choose exactly k configurations... such that every individual... is incorporated into exactly one track") which models were pattern-matching to trigger Dancing Links or 3D Matching algorithms. Replaced it with physical scenario constraints ("utilize the entire inventory", "components cannot be duplicated"). This forces models to derive the exact cover requirement from the logic of component consumption rather than keyword matching.
</RATIONALE>

The requirement to use all components exactly once from a set of allowed triples is mathematically identical to the original problem, ensuring the same output for any given input.
