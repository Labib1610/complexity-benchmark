# Problem A — Drone Assembly Protocol

Time limit: 5 s   Memory limit: 256 MB

## Description

A robotics facility is manufacturing a fleet of autonomous drones. The assembly line must deliver exactly **k** functional units. The facility is stocked with exactly **k** items in each of three distinct hardware categories:

- **k** chassis frameworks (labeled 1 through k)
- **k** navigation modules (labeled 1 through k)
- **k** imaging sensors (labeled 1 through k)

Each drone requires exactly one chassis, one navigation module, and one imaging sensor. However, due to power routing and data-bus limitations, only specific combinations of these three components can be successfully wired together. You are given a comprehensive registry of all viable integration sets `(c, n, i)`.

To eliminate waste and fulfill the production quota, the final assembly plan must utilize every single chassis, every navigation module, and every imaging sensor in exactly one assembled unit. You must select exactly **k** viable integration sets from the registry so that no hardware component from any category is left unused or installed in multiple drones.

Determine if a complete assembly plan can be formed, and if so, output the integration sets to be utilized.

*Note on test data:* The evaluation suite contains dense configurations deliberately constructed to maximize fruitless exploration. The integration sets are arranged so that any procedure that sequentially assigns chassis frameworks from 1 to k, testing available registry options in the exact sequence they are provided, will be forced into a prohibitive number of dead-end paths before it can finish exploring the search space.

## Input

The first line provides two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k), representing the quantity of items in each hardware category and the total count of viable integration sets in the registry.
Each of the subsequent **t** lines contains three integers **c**, **n**, and **i** (1 ≤ c, n, i ≤ k), specifying a viable integration set made up of chassis **c**, navigation module **n**, and imaging sensor **i**. No integration set is listed more than once.

## Output

If a valid assembly plan for **k** drones can be formed, print `YES` on the first line. Following that, print **k** lines, each containing three integers `c n i` to represent a selected integration set. Any valid selection that incorporates every chassis, navigation module, and imaging sensor exactly once will be considered correct. The selected sets can be printed in any order.

If no valid assembly plan can be formed, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable integration sets require navigation module 1. Consequently, navigation module 2 can never be utilized, making a valid assembly plan impossible.

I explicitly replaced the vague adversarial-order note with a direct warning that a naive, fixed-order sequential assignment of chassis frameworks will encounter a prohibitive number of dead-end paths. This removes the affordance of relying on a simple fixed-order backtracking template and forces the model to reason about search space pruning, requiring it to implement a dynamic variable ordering heuristic (like MRV) or a more sophisticated exact cover approach.
