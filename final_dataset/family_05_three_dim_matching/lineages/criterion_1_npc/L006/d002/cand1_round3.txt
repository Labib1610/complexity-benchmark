# Problem A — Network Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

You are configuring a telecommunications system. The system operates using three distinct types of signal parameters: Uplink IDs, Downlink IDs, and Sideband IDs. Each type of ID is assigned an integer value from 1 to `k`.

You are provided with a catalog of `t` available transceiver modules. Each module is hardware-locked to a specific combination of one Uplink ID (`u`), one Downlink ID (`d`), and one Sideband ID (`s`). No two available modules share the exact same combination of all three IDs.

You must select exactly `k` modules from the catalog to form a complete network. To prevent any signal interference, the selected modules must satisfy the following strict non-interference conditions:
- No two chosen modules may share the same Uplink ID.
- No two chosen modules may share the same Downlink ID.
- No two chosen modules may share the same Sideband ID.

Equivalently, across the `k` chosen modules, the Uplink IDs must form a permutation of 1 to `k`, the Downlink IDs must form a permutation of 1 to `k`, and the Sideband IDs must form a permutation of 1 to `k`.

Determine whether such a selection is possible, and if so, report one valid set of `k` modules.

## Input

The first line contains two integers `k` and `t`. The parameter `k` represents the number of distinct IDs for each signal type; the system requires a minimum of 1 ID and is restricted by a physical hardware limit of 22 IDs. The parameter `t` represents the total inventory of available modules, ranging from a minimum of 0 up to the theoretical maximum of `k·k·k`.

Each of the next `t` lines contains three integers `u`, `d`, and `s`. These represent the Uplink ID, Downlink ID, and Sideband ID of a single available module. Every ID is a valid integer starting from 1 up to `k`. No module configuration is listed more than once.

## Output

If a valid set of exactly `k` modules exists, print `YES` on the first line, then print `k` lines, each containing the three IDs `u d s` of one chosen module. Any valid selection is accepted, and the modules may be printed in any order.

If no such set exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both available modules share the same Downlink ID (1). Choosing both would violate the condition that no two chosen modules may share the same Downlink ID, so it is impossible to choose 2 valid modules.
</STATEMENT>
<RATIONALE>
I reframed the scenario into selecting telecommunications modules with three ID types, replacing explicit inequality bounds with physical hardware limits and inventory capacities (Strategy S07). This hides the small value of `k` from simple pattern matching, preventing models from blindly triggering bitmask DP templates just by seeing the bare inequality `k <= 22`. I also explicitly clarified that the choices must form permutations to prevent any semantic drift regarding the exact-cover requirement.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement to select exactly `k` modules with no shared IDs across each of the three dimensions perfectly mirrors the original requirement to select `k` struts with no shared coordinates, leaving the valid sets identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, which is NP-complete, as it still asks to find a perfect 3-dimensional matching in a given set of triplets.
</PRESERVED_CLASS>
<RISK>
Models might struggle to parse the text-based bounds for `k` and `t`, though the phrasing "physical hardware limit of 22" and "theoretical maximum of k·k·k" is precise and unambiguous.
</RISK>
