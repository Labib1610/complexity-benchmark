# Problem A — Architectural Harmony

Time limit: 5 s   Memory limit: 256 MB

## Description

You are designing a structural framework within a 3D architectural space. The space is defined by a 3D grid of discrete locations. The number of valid coordinates along each axis is given by the project's integer scale factor, **k**. A project must have a scale factor of at least one. The maximum scale factor is limited by the city's strict zoning laws, which cap the total number of possible grid locations in the space at exactly 10,648. Since the grid is a perfect cube, the scale factor **k** cannot exceed the cube root of this limit.

You are provided with a catalog of **t** available support struts. The number of provided struts can be anything from zero up to the total number of grid locations in the space. Each strut is designed to be installed at a specific location, given by its axis indices (**x**, **y**, **z**). These indices are strictly positive integers that cannot exceed the scale factor. No two available struts in the catalog are designed for the exact same location.

You must select a subset of exactly **k** struts from the catalog to form a stable framework. To ensure proper load distribution, the framework must satisfy a strict non-alignment condition:
- No two chosen struts may share the same **x**-index.
- No two chosen struts may share the same **y**-index.
- No two chosen struts may share the same **z**-index.

Determine whether it is possible to select a stable framework of exactly **k** struts from the catalog, and if so, report one valid selection.

## Input

The first line contains two integers **k** and **t**: the scale factor, and the number of available struts in the catalog. 
Each of the following **t** lines contains three integers **x**, **y**, and **z**, representing an available strut at those axis indices. No location is listed more than once.

## Output

If a stable framework of exactly **k** struts can be formed, print `YES` on the first line. Then, output **k** lines, each containing the three indices `x y z` of one chosen strut. Any valid selection is accepted, and the chosen struts may be printed in any order.

If no such framework can be formed, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both available struts share the same **y**-index (1). Choosing both would violate the non-alignment condition, so it is impossible to choose 2 valid struts.

<RATIONALE>
Removed the explicit numerical inequalities (e.g., `1 <= k <= 22`) from the Input section and embedded them into the natural language scenario of the Description. By stating that the maximum volume is 10,648 and `k` is its cube root, the model must read the text and perform arithmetic to derive `k <= 22`. This prevents surface-level pattern matchers from immediately recognizing a small `k` and appropriately triggering bitmask dynamic programming.
</RATIONALE>
<PRESERVED_ANSWER>
The problem still requires finding a subset of exactly `k` tuples from `t` available 3D coordinates such that no two tuples share any axis index, which is mathematically identical to the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, which is an NP-complete problem, since it asks for a perfect 3D matching of size `k` within a bounded grid.
</PRESERVED_CLASS>
<RISK>
Models might struggle to correctly parse "cube root of this limit" to establish the bound of 22, though the integer 10,648 is unambiguously 22^3.
</RISK>
