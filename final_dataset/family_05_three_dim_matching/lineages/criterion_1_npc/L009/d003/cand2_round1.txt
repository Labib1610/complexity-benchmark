<STATEMENT>
# Problem A — Data Synchronization

Time limit: 5 s   Memory limit: 256 MB

## Description

A distributed database needs to synchronize records across three distinct clusters. You are provided with a log of **t** successful past sync events. Each event is described by a triplet of integers `(x, y, z)`, representing the local transaction IDs in the first, second, and third clusters respectively.

You must extract a batch of exactly **k** events from the log to form a complete synchronization cycle. A batch of **k** events is considered a complete cycle if it satisfies the following property:
If you take the **k** chosen events and isolate their first transaction IDs, sorting these **k** integers must result exactly in the contiguous sequence 1, 2, ..., **k**. 
Simultaneously, if you isolate and sort their second transaction IDs, they must also form the sequence 1, 2, ..., **k**. 
Finally, if you isolate and sort their third transaction IDs, they must similarly form the sequence 1, 2, ..., **k**.

Determine whether such a batch of exactly **k** events can be extracted from the log, and if so, report one valid batch.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the required sequence length and the number of events in the log.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), representing a logged event. No event is listed more than once.

## Output

If a complete synchronization cycle of **k** events exists, print `YES` on the first line, then print **k** lines, each containing the three transaction IDs `x y z` of one chosen event. Any valid cycle is accepted; the events may be printed in any order.

If no valid cycle exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both logged events have a second transaction ID of 1. If we select both to form a batch of 2 events, isolating and sorting their second IDs yields the sequence `1, 1`, which is not the required sequence `1, 2`. Since exactly 2 events must be selected and only 2 are available, it is impossible to form a complete cycle.
</STATEMENT>
<RATIONALE>
I transformed the scenario from assigning operators/apparatuses/shifts to selecting a batch of synchronization events. To defeat the exact-cover pattern matching, I replaced the "no two interfere" (set packing) phrasing with a property about sorted sequences: the $k$ chosen events must contain first, second, and third IDs that, when sorted, form the sequence $1 \dots k$. This forces the model to mathematically deduce that this sequence property is equivalent to a uniqueness/exact-cover constraint before it can apply standard algorithms like DLX.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that $k$ integers bounded by $1 \dots k$ sort exactly to $1 \dots k$ is logically identical to requiring them to be mutually distinct, meaning the valid subsets of triplets are exactly the same as in the original problem.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, which is NP-Complete, because the structural constraints on the selected triplets are mathematically unchanged.
</PRESERVED_CLASS>
<RISK>
The phrase "isolate their first transaction IDs" could be seen as slightly informal, though the subsequent explanation of sorting the $k$ integers makes the mechanical meaning unambiguous.
</RISK>
