<STATEMENT>
# Problem A — Crew Assembly

Time limit: 5 s
Memory limit: 256 MB

## Description

A facility is finalizing a deployment protocol. The protocol involves three distinct pools of resources:
- operators, sequentially numbered starting from 1 up to the deployment size **k**,
- apparatuses, sequentially numbered starting from 1 up to the deployment size **k**,
- shifts, sequentially numbered starting from 1 up to the deployment size **k**.

A deployment unit is formed by linking one operator, one apparatus, and one shift. You are provided with a catalog of tested links `(x, y, z)`.

Your task is to activate a subset of these tested links such that every operator, every apparatus, and every shift is assigned to exactly one active link. Determine whether such a configuration is possible, and if so, report the chosen links.

The deployment size **k** requires at least one of each resource, and is strictly capped by the transport shuttle's maximum capacity of 22 seats per resource category. The number of tested links **t** in the catalog can range from none at all up to the absolute theoretical maximum where every operator is tested with every apparatus on every shift.

## Input

The first line contains two integers **k** and **t**: the deployment size and the number of tested links in the catalog.
Each of the next **t** lines contains three integers **x**, **y**, **z**, representing a tested link. The values correspond to the assigned operator, apparatus, and shift, which are guaranteed to be within their active 1-indexed pools of size **k**. No link is listed more than once in the catalog. 

## Output

If a valid configuration exists, print `YES` on the first line, then print the members `x y z` of each chosen link, one per line. Any valid configuration is accepted; the links may be printed in any order.

If no valid configuration exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both tested links use apparatus 1. Since every resource must be assigned to exactly one active link, activating both would assign apparatus 1 twice, while activating only one would leave an operator and apparatus 2 unassigned. Thus, it is impossible to form a valid configuration.
</STATEMENT>
<RATIONALE>
Changed the problem's criteria from "select exactly k combinations such that every element appears at least once" to "select a subset of combinations such that every element appears exactly once". This forces models to deduce the 'exactly k' property from the exact cover constraints rather than pattern-matching the explicit loop bound. Bare inequalities were replaced with physical limits (e.g., shuttle capacity) per S07.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement to cover 3k items exactly once using combinations of 3 items from distinct sets ensures that any valid subset must contain exactly k combinations, matching the seed's original criteria perfectly.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching (an NP-complete problem), as it asks to find a perfect 3-uniform hypergraph matching over three disjoint sets.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "exactly one active link" as applying to only one category rather than all three, though the phrasing "every operator, every apparatus, and every shift" makes the joint requirement highly unambiguous.
</RISK>
