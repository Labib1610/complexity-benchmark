<STATEMENT>
# Problem A — Crew Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

A facility needs to launch a deployment plan involving three categories of assets:
- operators, identified by integers 1 through **k**,
- apparatuses, identified by integers 1 through **k**,
- shifts, identified by integers 1 through **k**.

A deployment unit consists of one operator, one apparatus, and one shift. You are provided with a catalog of allowed combinations `(x, y, z)`.

Your task is to select exactly **k** of these allowed combinations to form the final deployment plan. The plan is considered fully operational if and only if the selected combinations distribute the assets perfectly: every operator from 1 to **k**, every apparatus from 1 to **k**, and every shift from 1 to **k** must be included in exactly one of the chosen combinations.

Determine whether such a plan can be formed, and if so, report one valid set of **k** combinations.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the group size and the number of allowed combinations.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), representing an allowed combination. No combination is listed more than once.

## Output

If a valid deployment plan of **k** combinations exists, print `YES` on the first line, then print **k** lines, each containing the three members `x y z` of one chosen combination. Any valid plan is accepted; the combinations may be printed in any order.

If no valid plan exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both allowed combinations use apparatus 1. Since exactly 2 combinations must be selected and they must together distribute the assets perfectly, apparatus 2 cannot be included, making it impossible to form a valid plan.
</STATEMENT>
<RATIONALE>
Changed the condition from "appears at least once" for each category to a strict "included in exactly one" across all assets, removing the per-operator framing that cued a sequential assignment shortcut. This forces the model to recognize the exact-partitioning structure directly rather than relying on the implied pigeonhole principle. Explicit bounds were restored to ensure strict compliance with the I/O contract.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement of choosing exactly k combinations that include every item exactly once is mathematically equivalent to choosing k combinations that include every item at least once, so all valid answers are identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, merely with its condition stated as a strict partitioning rather than a coverage bound.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "distribute the assets perfectly" as an additional unknown constraint, though the colon immediately and explicitly defines what it means.
</RISK>
