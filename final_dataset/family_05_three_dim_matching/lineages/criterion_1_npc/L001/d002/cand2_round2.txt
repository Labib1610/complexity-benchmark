# Problem A — Crew Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

An operation requires coordinating three distinct pools of resources. Each pool contains exactly **k** elements:
- Technicians: **k** individuals, identified by integers 1 through k,
- Consoles: **k** workstations, identified by integers 1 through k,
- Sectors: **k** locations, identified by integers 1 through k.

A deployment unit is formed by linking exactly one technician to operate exactly one console within exactly one sector. Due to certification and availability constraints, only specific configurations of (technician, console, sector) are authorized. You will receive a catalog of these authorized configurations.

Your task is to formulate a comprehensive operational roster consisting of exactly **k** authorized configurations chosen from the catalog. To ensure strict non-overlap, no two selected configurations may share the same technician, the same console, or the same sector. Consequently, a valid roster will utilize every technician, every console, and every sector exactly once.

Determine if such a roster can be formulated. If it can, provide one valid set of configurations.

## Input

The first line provides two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k). Here, **k** represents the headcount of each resource pool (limited by the facility's maximum capacity of 22), and **t** is the number of authorized configurations in the catalog, which can range from an empty catalog of 0 up to the theoretical maximum of k·k·k.

The following **t** lines each contain three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), describing an authorized configuration consisting of technician **x**, console **y**, and sector **z**. No configuration appears more than once in the catalog.

## Output

If a valid roster of **k** configurations can be formulated, output `YES` on the first line. Following this, output **k** lines, each containing three integers `x y z` corresponding to a chosen configuration. Any valid roster that assigns every technician, every console, and every sector exactly once is acceptable. The configurations may be printed in any order.

If no such roster can be formulated, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both authorized configurations require console 1, meaning console 2 can never be utilized in the roster.

<RATIONALE>
The terminology was shifted from "time slots" to "sectors" to remove the chronological affordance that led models to conceptually "group by time slot" and process the problem iteratively over time. The exact-once framing was adjusted to emphasize mutual exclusion ("no two selected configurations may share..."), forcing models to recognize the symmetric 3-dimensional matching structure rather than relying on standard assignment problem templates. The exact numeric bounds were restored in formal notation to satisfy the strict I/O parser, while still being contextualized via capacity limits.
</RATIONALE>
