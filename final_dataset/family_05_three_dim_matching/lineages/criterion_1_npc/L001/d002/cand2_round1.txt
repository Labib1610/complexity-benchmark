<STATEMENT>
# Problem A — Crew Assembly

Time limit: 5 s   Memory limit: 256 MB

## Description

An operation requires coordinating three distinct pools of resources. Each pool contains exactly **k** elements:
- Personnel: **k** specialists, identified by integers 1 through k,
- Equipment: **k** machines, identified by integers 1 through k,
- Schedule: **k** time slots, identified by integers 1 through k.

A deployment unit is formed by assigning exactly one specialist to operate exactly one machine during exactly one time slot. Due to certification and availability constraints, only specific configurations of (specialist, machine, time slot) are authorized. You will receive a catalog of these authorized configurations.

Your task is to formulate a comprehensive operational roster. This roster is formed by selecting exactly **k** authorized configurations from the catalog. To ensure proper distribution of resources and avoid conflicts, no two selected configurations may feature the same specialist, no two may feature the same machine, and no two may occur in the same time slot.

Determine if such a roster can be formulated. If it can, provide one valid set of configurations.

## Input

The first line provides two integers **k** and **t**. The pool size **k** represents the headcount of specialists, which is at least 1 and cannot exceed the facility's maximum capacity of 22 individuals. The total number of authorized configurations **t** ranges from an empty catalog (0) up to the absolute limit where every possible combination of one specialist, one machine, and one time slot is authorized.

The following **t** lines each contain three integers **x**, **y**, **z**, representing a specialist, machine, and time slot respectively. These identifiers will always be valid elements of their respective pools (from 1 up to **k**). No configuration appears more than once in the catalog.

## Output

If a valid roster of **k** configurations can be formulated, output `YES` on the first line. Following this, output **k** lines, each containing three integers `x y z` corresponding to a chosen configuration. Any valid roster meeting the non-overlap criteria is acceptable. The configurations may be printed in any order.

If no such roster can be formulated, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both authorized configurations require machine 1. Since a valid roster of 2 configurations cannot feature the same machine twice, it is impossible to formulate.
</STATEMENT>
<RATIONALE>
Removed the explicit instruction to "utilize every time slot exactly once" and replaced it with a mutual exclusion constraint: "no two selected configurations may feature the same time slot". This forces the model to deduce that selecting exactly $k$ non-overlapping configurations from pools of size $k$ is mathematically equivalent to an exact cover, preventing it from blindly anchoring its search loops on time slots. Additionally, numeric bounds were rewritten as physical capacities (e.g., maximum headcount of 22, and the absolute limit of combinations) to satisfy S07.
</RATIONALE>
<PRESERVED_ANSWER>
Selecting exactly $k$ configurations where no resource is reused among pools of exactly $k$ elements logically guarantees that every element is used exactly once, preserving the exact same valid subsets as before.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains 3-Dimensional Matching (an NP-complete problem), as it still requires finding a perfect matching in a 3-uniform hypergraph.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the bounds if they fail to translate "every possible combination of one specialist, one machine, and one time slot" into $k^3$, but the phrasing is a direct mathematical definition of the Cartesian product size.
</RISK>
