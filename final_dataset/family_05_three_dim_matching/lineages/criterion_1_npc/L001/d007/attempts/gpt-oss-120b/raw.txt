**Solution Explanation**

For a set of `k` triples  

```
(ai , bi , ci)      1 ≤ ai , bi , ci ≤ k
```

the required score `3·k` means

* all `ai` are different  → `Uα = k`
* all `bi` are different  → `Uβ = k`
* all `ci` are different  → `Uγ = k`

So we have to choose `k` triples such that every value `1 … k` appears **once**
in each coordinate.  
That is exactly a *3‑dimensional matching* (exact cover) problem with at most
`k = 22` elements in each dimension – tiny enough for a simple backtracking
search.



--------------------------------------------------------------------

#### 1.   Data structures

* `triples` – list of all given triples, each stored as `(a,b,c)`.
* `by_a[a]` – list of indices of triples whose first coordinate equals `a`
  (`1 … k`).  
  (`by_b`, `by_c` are not needed.)
* three boolean arrays `used_a[1..k] , used_b[1..k] , used_c[1..k]`
  – which values are already taken.
* `chosen` – indices of triples already selected (size ≤ `k`).

All arrays are tiny (`k ≤ 22`).

--------------------------------------------------------------------

#### 2.   Recursive search

```
search(depth):
    if depth == k:               # k triples already chosen
        return True

    # choose the still unused a with the smallest number of usable rows
    best_a = -1
    best_cnt = INF
    for a = 1 .. k:
        if used_a[a]: continue
        cnt = 0
        for idx in by_a[a]:
            b,c = triples[idx][1], triples[idx][2]
            if not used_b[b] and not used_c[c]:
                cnt += 1
        if cnt == 0:               # dead end, prune immediately
            return False
        if cnt < best_cnt:
            best_cnt = cnt
            best_a = a

    # try every possible triple that uses best_a
    for idx in by_a[best_a]:
        a,b,c = triples[idx]
        if used_b[b] or used_c[c]: continue
        # take it
        used_a[a] = used_b[b] = used_c[c] = True
        chosen.append(idx)
        if search(depth+1):
            return True
        # backtrack
        chosen.pop()
        used_a[a] = used_b[b] = used_c[c] = False

    return False
```

*The heuristic* – always expand the still‑free `a` with the fewest admissible
triples – dramatically reduces the branching factor.

The recursion depth never exceeds `k ≤ 22`; the total number of visited
states is far below the time limit (worst case a few million, easily handled
in 5 s).

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct set iff such a set
exists.

---

##### Lemma 1  
During the search the three boolean arrays always represent the set of
already chosen triples: a value `x` is marked `True` in `used_a` (resp. `b`,
`c`) **iff** some already chosen triple has that value as its first
(resp. second, third) coordinate.

**Proof.**  
Initially all are `False`.  
When a triple `(a,b,c)` is taken we set the three entries to `True`; when we
backtrack we reset exactly those three entries to `False`. No other
modifications are performed. ∎



##### Lemma 2  
At any recursive call, the set `chosen` together with the `used_*` arrays
forms a *partial* solution: all already chosen triples have pairwise different
`a`, `b` and `c` values.

**Proof.**  
Induction over recursion depth.  
*Base*: depth 0 – empty set, property holds.  
*Step*: assume it holds before taking a new triple `(a,b,c)`. The algorithm
checks `used_b[b]` and `used_c[c]` are `False`; `used_a[a]` is `False` because
`a` is the currently selected unused value. Therefore the new triple does not
conflict with any earlier one, and after marking the three values the
property still holds. ∎



##### Lemma 3  
If the algorithm reaches `depth == k`, the `k` triples in `chosen` constitute
a valid answer (score `3k`).

**Proof.**  
By Lemma&nbsp;2 all `a`, `b`, `c` values are pairwise different, therefore each
coordinate contributes exactly `k` distinct values. The score is `k+k+k = 3k`. ∎



##### Lemma 4  
If a valid set of `k` triples exists, the recursive search will eventually
reach `depth == k`.

**Proof.**  
Consider any fixed valid set `S`.  
At the first level the algorithm chooses some unused `a₁`. Because `S` contains
exactly one triple with that `a₁`, that triple is among `by_a[a₁]` and its
`b` and `c` are still unused, so the algorithm can pick it.  
After picking it, the remaining unused values are exactly those of `S \ {t₁}`.
Repeating the argument, at each deeper level the algorithm can follow the
triples of `S` one by one. Hence there exists a path in the search tree that
reaches depth `k`. ∎



##### Lemma 5  
If the algorithm finishes without finding depth `k`, no valid set exists.

**Proof.**  
Assume contrary that a valid set `S` exists. By Lemma&nbsp;4 there is a path
corresponding to `S`. The algorithm explores **all** possibilities that respect
the current `used_*` markings (it tries every admissible triple for the
selected `a`). Therefore the path for `S` would be explored and would reach
depth `k`, contradicting the assumption that the algorithm terminated without
success. ∎



##### Theorem  
The program outputs

* `YES` and a list of `k` triples **iff** such a list exists,
* otherwise outputs `NO`.

**Proof.**  
*If* the program prints `YES`, it did so after `search` returned `True`,
hence reached depth `k`. By Lemma&nbsp;3 the printed triples are a valid
solution.

*Only‑if* a valid solution exists, Lemma&nbsp;4 guarantees the search can
reach depth `k`; consequently it returns `True` and the program prints `YES`.
If no solution exists, Lemma&nbsp;5 shows the search cannot reach depth `k`,
so it returns `False` and the program prints `NO`. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*`k ≤ 22`, `t ≤ k³ ≤ 10648`.*

* Pre‑processing (`by_a`) : `O(t)`.
* In each recursive call we scan all rows of the currently selected `a`
  to count candidates – at most `t` in the worst case, but `k` is tiny,
  and the heuristic quickly reduces the branching factor.
* The total number of visited states is bounded by the number of partial
  matchings, which is far below `k!` (≈ 1.1·10²⁰ for `k=22`) but the pruning
  makes the actual visited count tiny (well under a few million).

Hence the running time is comfortably below the 5 s limit, and the memory
consumption is `O(t + k)` ≤ a few MB.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(1000000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    k = int(next(it))
    t = int(next(it))

    triples = []
    by_a = [[] for _ in range(k + 1)]          # 1‑based
    for idx in range(t):
        a = int(next(it))
        b = int(next(it))
        c = int(next(it))
        triples.append((a, b, c))
        if 1 <= a <= k:
            by_a[a].append(idx)

    used_a = [False] * (k + 1)
    used_b = [False] * (k + 1)
    used_c = [False] * (k + 1)
    chosen = []

    INF = 10 ** 9

    def search(depth: int) -> bool:
        if depth == k:
            return True

        # select unused a with minimal number of usable rows
        best_a = -1
        best_cnt = INF
        for a in range(1, k + 1):
            if used_a[a]:
                continue
            cnt = 0
            for idx in by_a[a]:
                _, b, c = triples[idx]
                if not used_b[b] and not used_c[c]:
                    cnt += 1
            if cnt == 0:
                return False          # dead end
            if cnt < best_cnt:
                best_cnt = cnt
                best_a = a
                if cnt == 1:          # cannot get better
                    break

        # try all rows using best_a
        for idx in by_a[best_a]:
            a, b, c = triples[idx]
            if used_b[b] or used_c[c]:
                continue
            used_a[a] = used_b[b] = used_c[c] = True
            chosen.append(idx)
            if search(depth + 1):
                return True
            chosen.pop()
            used_a[a] = used_b[b] = used_c[c] = False

        return False

    possible = search(0)

    out = []
    if possible:
        out.append("YES")
        for idx in chosen:
            a, b, c = triples[idx]
            out.append(f"{a} {b} {c}")
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
