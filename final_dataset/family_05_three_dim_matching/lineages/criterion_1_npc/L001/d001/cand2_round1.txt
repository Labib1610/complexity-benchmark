<STATEMENT>
# Problem A — Mission Roster

Time limit: 5 s   Memory limit: 256 MB

## Description

A space station requires a complete mission schedule. There are three distinct pools, each containing exactly **k** items:
- **k** specialists, identified by integers 1 through **k**,
- **k** machines, identified by integers 1 through **k**,
- **k** time slots, identified by integers 1 through **k**.

A crew deployment consists of exactly one specialist, one machine, and one time slot. You are provided with a list of authorized configurations. Each configuration is given as a triplet `(x, y, z)` indicating that specialist `x` is certified to operate machine `y` during time slot `z`. 

To complete the mission roster, you must select exactly **k** configurations from the authorized list so that each specialist, each machine, and each time slot is scheduled in **exactly one** deployed crew. Note that the authorized configurations may be presented in an order designed to defeat greedy assignment strategies; careful planning is required.

Determine if a complete mission roster can be assembled. If it can, output one valid deployment schedule.

## Input

The first line contains two integers **k** and **t**: the group size and the number of authorized configurations. The group size **k** is at least 1 and at most the total capacity of two 11-bed sleeping modules. The value **t** is at least 0 and at most the theoretical maximum where every specialist is authorized for every machine in every time slot.

Each of the subsequent **t** lines contains three integers **x**, **y**, and **z** (between 1 and **k** inclusive), representing one authorized configuration. No configuration is listed more than once.

## Output

If a valid roster of **k** deployments exists, print `YES` on the first line. Then, print **k** lines, each containing the three integers `x y z` of a selected deployment. Any roster where every specialist, machine, and time slot is used exactly once is accepted. The deployments may be printed in any order.

If no such roster can be formed, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both authorized configurations require machine 1, meaning machine 2 can never be utilized in the roster.
</STATEMENT>
<RATIONALE>
The explicit numeric bounds (`k <= 22` and `t <= k^3`) were replaced with indirect physical limits (two 11-bed modules and a theoretical maximum combination phrase). This forces the model to deduce the instance size through reading comprehension, removing the surface-level pattern match of small numbers that typically triggers exponential search heuristics. An explicit warning about adversarial ordering was also added to discourage simple greedy algorithms.
</RATIONALE>
<PRESERVED_ANSWER>
The structural requirement to select exactly k non-overlapping triplets from the given list remains functionally identical, ensuring all valid inputs produce the same output as the seed.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still asks for a perfect matching in a tripartite hypergraph, which is exactly the NP-complete 3-Dimensional Matching problem.
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "two 11-bed sleeping modules" as a limit of 11 if it assumes the modules are split among different groups, though "total capacity" strongly implies 22.
</RISK>
