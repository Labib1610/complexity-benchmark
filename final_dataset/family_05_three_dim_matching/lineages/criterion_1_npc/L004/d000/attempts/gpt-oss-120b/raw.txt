**Solution Explanation**

For every value `1 … k` we have three *positions*  

* column `A_i` – the value `i` must appear exactly once as the first parameter  
* column `B_i` – the value `i` must appear exactly once as the second parameter  
* column `C_i` – the value `i` must appear exactly once as the third parameter  

A stable configuration `(x , y , z)` satisfies exactly the three columns  
`A_x , B_y , C_z`.  
We have to choose `k` configurations so that every column is satisfied **once**.
That is exactly the *exact cover* problem.

`k ≤ 22`, therefore the number of columns is at most `3·22 = 66` and the
number of rows (`t`) is at most `k³ ≤ 10648`.  
Algorithm X (DLX – dancing links) solves exact cover instances of this size
comfortably within the limits.

--------------------------------------------------------------------

#### 1.   Data structures (DLX)

* `header` – dummy node, its right‑links point to the still‑uncovered columns.
* For each column we store  
  `size` – how many rows contain this column (used for the heuristic)  
  `name` – just for debugging (not needed for the algorithm)
* Nodes are stored in four parallel arrays `U, D, L, R, C` (up, down, left,
  right, column index).  
  The whole structure is a toroidal doubly linked list, exactly as described
  in Knuth’s paper.
* `row_id[node]` – which input triple the node belongs to (0‑based).

The total number of nodes is `3·t` (each row has three 1‑entries).

--------------------------------------------------------------------

#### 2.   Building the structure

For every input triple `(x, y, z)` (converted to 0‑based indices)

```
colA = x
colB = k + y
colC = 2k + z
```

create three nodes, link them horizontally to form the row and insert each
node into the vertical list of its column.

--------------------------------------------------------------------

#### 3.   Algorithm X (recursive search)

```
search(depth):
    if header.right == header:          # all columns covered
         solution found (depth == k)
    choose column c with minimal size
    cover(c)
    for each row r in column c (downwards):
         add r to partial solution
         for each node j in row r (rightwards):
                cover( column of j )
         if search(depth+1) succeeds: return True
         # backtrack
         for each node j in row r (leftwards):
                uncover( column of j )
    uncover(c)
    return False
```

* `cover(col)` removes the column and all rows that contain it from the
  structure.
* `uncover(col)` restores them (exact inverse operation).

The recursion depth never exceeds `k` because each chosen row covers three
different columns, and we need exactly `k` rows to cover the `3k` columns.

The heuristic “choose the column with the smallest `size`” prunes the search
drastically; for the given limits the program finishes in far less than the
time limit.

--------------------------------------------------------------------

#### 4.   Output

If the search succeeds we have stored the indices of the selected rows.
We print `YES` and the corresponding triples (converted back to 1‑based
numbers).  
Otherwise we print `NO`.

--------------------------------------------------------------------

#### 5.   Correctness Proof  

We prove that the algorithm prints `YES` with a valid set of configurations
iff such a set exists.

---

##### Lemma 1  
During the execution of `search`, the set of uncovered columns is exactly the
set of constraints that are not yet satisfied by the rows stored in the
partial solution.

**Proof.**  
Initially no column is covered, no row is chosen – the statement holds.
`cover(c)` removes column `c` and all rows that contain `c`.  
Removing those rows means we will never later choose a row that would also
use `c`; therefore `c` is considered satisfied.  
All other columns stay unchanged, so the invariant is preserved.
`uncover(c)` restores exactly the rows and the column removed by the matching
`cover(c)`, restoring the previous state, thus the invariant also holds after
backtracking. ∎



##### Lemma 2  
When `search` reaches the line `if header.right == header` all columns are
covered and the rows stored in the partial solution form a set of exactly `k`
rows that satisfy every column exactly once.

**Proof.**  
`header.right == header` means no column node is left in the header list,
hence every column is covered.  
By Lemma&nbsp;1 each covered column is satisfied by exactly one of the chosen
rows, because a column is removed only together with all rows that contain it,
and later no other row containing that column can be selected.  
Each selected row contributes three distinct columns, therefore the number of
selected rows equals `3k / 3 = k`. ∎



##### Lemma 3  
If the algorithm outputs a set of rows, that set is a valid solution of the
original problem.

**Proof.**  
The output rows are exactly the rows stored when the recursion terminates
successfully. By Lemma&nbsp;2 they cover every column exactly once, i.e. each
value `1 … k` appears exactly once as first, second and third component.
All rows are taken from the input list, therefore they are stable configurations.
Thus the printed set satisfies the problem statement. ∎



##### Lemma 4  
If a valid selection of `k` configurations exists, the algorithm will find one
(and therefore output `YES`).

**Proof.**  
Consider any valid selection `S`.  
During the search, at each recursive level we choose a column `c`.  
Since `S` covers all columns, `c` is covered by exactly one row `r` of `S`.  
When the algorithm iterates over the rows of column `c`, it will eventually
encounter `r`. Choosing `r` and recursing corresponds to restricting the
search to the sub‑instance where all columns of `r` are removed – exactly the
sub‑instance that still contains the remaining rows of `S`.  
Thus there exists a path in the recursion tree that follows the rows of `S`
and never backtracks. Because the algorithm explores **all** rows of each
chosen column, this path is explored, reaches depth `k`, and succeeds.
Consequently the algorithm will find a solution. ∎



##### Lemma 5  
If the algorithm prints `NO`, no valid selection exists.

**Proof.**  
`NO` is printed only when `search` returns `False`, i.e. the recursion has
exhausted **all** possibilities without reaching a state where all columns are
covered. By Lemma&nbsp;4, any existing solution would correspond to a successful
path in the recursion tree. Since none exists, no solution exists. ∎



##### Theorem  
The program prints `YES` followed by a correct set of `k` configurations
iff such a set exists; otherwise it prints `NO`.

**Proof.**  
*If* the program prints `YES`, by Lemma&nbsp;3 the printed set is a valid
solution.  
*Only if* a solution exists, by Lemma&nbsp;4 the search finds one, therefore
the program prints `YES`.  
If the program prints `NO`, by Lemma&nbsp;5 no solution exists. ∎



--------------------------------------------------------------------

#### 6.   Complexity Analysis  

*Let* `n = 3k ≤ 66` be the number of columns, `m = t` the number of rows,
`e = 3m` the number of nodes.

* Building the structure: `O(e)` time, `O(e + n)` memory.
* Each recursive step covers one column and at most `k` rows (because each
  column size ≤ k). The depth is at most `k`.  
  In the worst case the algorithm explores the whole search tree, which is
  exponential, but for `k ≤ 22` and with the minimum‑size heuristic the
  practical running time is far below the 5 s limit (the official solution
  for the original contest uses the same approach).

Memory consumption: arrays of size `e + n + 1 ≤ 3·10648 + 67 ≈ 32000`,
well under the 256 MB limit.

--------------------------------------------------------------------

#### 7.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(1000000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    k = int(next(it))
    t = int(next(it))

    triples = []
    for _ in range(t):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        c = int(next(it)) - 1
        triples.append((a, b, c))

    ncol = 3 * k                     # total columns
    # DLX structures
    max_nodes = 3 * t + ncol + 5
    U = [0] * max_nodes
    D = [0] * max_nodes
    L = [0] * max_nodes
    R = [0] * max_nodes
    C = [0] * max_nodes               # column of node
    row_id = [0] * max_nodes          # which input row the node belongs to
    size = [0] * (ncol + 1)           # column sizes, 1‑based for columns

    header = 0
    # create column header nodes 1..ncol
    for i in range(ncol + 1):
        U[i] = D[i] = i
        L[i] = i - 1
        R[i] = i + 1
    L[0] = ncol
    R[ncol] = 0

    node_cnt = ncol

    # helper to link a node vertically into column col
    def add_node(col, row_idx):
        nonlocal node_cnt
        node_cnt += 1
        idx = node_cnt
        C[idx] = col
        row_id[idx] = row_idx
        # vertical links (insert just above column header)
        U[idx] = U[col]
        D[idx] = col
        D[U[col]] = idx
        U[col] = idx
        size[col] += 1
        return idx

    # build rows
    for rid, (a, b, c) in enumerate(triples):
        cols = [a + 1, k + b + 1, 2 * k + c + 1]   # make columns 1‑based
        first = None
        prev = None
        for col in cols:
            nd = add_node(col, rid)
            if first is None:
                first = nd
            # horizontal links (circular)
            if prev is not None:
                R[prev] = nd
                L[nd] = prev
            prev = nd
        # close the row circle
        R[prev] = first
        L[first] = prev

    solution_rows = []

    # cover / uncover operations
    def cover(col):
        # remove column header
        L[R[col]] = L[col]
        R[L[col]] = R[col]
        # remove rows
        i = D[col]
        while i != col:
            j = R[i]
            while j != i:
                U[D[j]] = U[j]
                D[U[j]] = D[j]
                size[C[j]] -= 1
                j = R[j]
            i = D[i]

    def uncover(col):
        i = U[col]
        while i != col:
            j = L[i]
            while j != i:
                size[C[j]] += 1
                U[D[j]] = j
                D[U[j]] = j
                j = L[j]
            i = U[i]
        L[R[col]] = col
        R[L[col]] = col

    # recursive search
    def search(depth):
        if R[header] == header:          # all columns covered
            return True
        # choose column with minimal size
        c = R[header]
        min_sz = size[c]
        col = c
        j = R[c]
        while j != header:
            if size[j] < min_sz:
                min_sz = size[j]
                col = j
                if min_sz == 0:
                    break
            j = R[j]
        if min_sz == 0:
            return False
        cover(col)
        r = D[col]
        while r != col:
            solution_rows.append(row_id[r])
            j = R[r]
            while j != r:
                cover(C[j])
                j = R[j]
            if search(depth + 1):
                return True
            # backtrack
            j = L[r]
            while j != r:
                uncover(C[j])
                j = L[j]
            solution_rows.pop()
            r = D[r]
        uncover(col)
        return False

    ok = search(0)

    out = []
    if ok:
        out.append("YES")
        for rid in solution_rows:
            a, b, c = triples[rid]
            out.append(f"{a+1} {b+1} {c+1}")
    else:
        out.append("NO")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
