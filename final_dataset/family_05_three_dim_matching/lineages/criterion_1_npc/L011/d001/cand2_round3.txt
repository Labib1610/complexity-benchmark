<STATEMENT>
# Problem A — Orthogonal Projections

Time limit: 5 s   Memory limit: 256 MB

## Description

You are analyzing a three-dimensional logical grid. The grid forms a perfect cube with a side length of **k**, where **k** is at most 22. The coordinates along each of the three axes (X, Y, and Z) are indexed strictly from 1 to **k**.

You are provided with a list of **t** active cells within this grid. The total count of these active cells can range from zero up to the full volume of the grid. Each active cell is specified by its coordinates `(x, y, z)`.

Your task is to isolate a subset of exactly **k** active cells from the given list such that their orthogonal projections completely cover all three axes without any overlap. This means no two selected cells may share the same X-coordinate, the same Y-coordinate, or the same Z-coordinate. Consequently, the **k** chosen cells must collectively utilize every index from 1 to **k** exactly once on the X-axis, exactly once on the Y-axis, and exactly once on the Z-axis.

Determine if such a non-overlapping selection exists. If it does, report one valid set of **k** cells.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the size of the grid along each dimension and the number of active cells.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), representing an active cell at X-coordinate **x**, Y-coordinate **y**, and Z-coordinate **z**. All listed active cells are distinct.

## Output

If a valid selection of **k** cells exists, print `YES` on the first line. Then, print **k** lines, each containing the three integers `x y z` of one selected cell. Any valid selection that perfectly covers all coordinate indices exactly once is accepted; the chosen cells may be printed in any order.

If no such selection is possible, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both active cells have a Y-coordinate of 1. This means the Y-coordinate 2 can never be covered, making a valid selection impossible.
</STATEMENT>
<RATIONALE>
I reframed the problem from a resource-assignment scenario (operators, terminals, shifts) into a geometric selection task (choosing active cells in a 3D grid). This removes the intuitive "group by operator" affordance, forcing the model to independently recognize the exact 3-dimensional matching structure from the geometric constraints. I also moved the textual description of the bounds into the narrative to apply strategy S07, while retaining the strict numeric inequalities in the input section to satisfy the autograder.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical conditions are identical: selecting exactly k triples from a given set such that each index from 1 to k appears exactly once in each of the three positions, meaning the correct output for any input is exactly the same.
</PRESERVED_ANSWER>

The problem remains exactly 3-Dimensional Matching, which is a classic NP-complete problem.
</PRESERVED_CLASS>
