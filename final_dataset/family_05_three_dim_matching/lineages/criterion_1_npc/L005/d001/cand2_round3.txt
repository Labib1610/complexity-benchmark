# Problem A — Cloud Provisioning

Time limit: 5 s   Memory limit: 256 MB

## Description

A cloud infrastructure team must deploy a set of isolated instances. The number of instances required is a positive integer up to twenty-two. Each instance must be built with exactly one compute node, one container image, and one database shard. The available inventory provides compute nodes, container images, and database shards. For each of these three resource types, the inventory size is exactly equal to the number of instances required (the items are numbered starting from one up to the inventory size). 

Because of architecture differences and network policies, only specific combinations of a compute node, a container image, and a database shard will successfully initialize. You are provided with the complete list of viable configurations. Only triples explicitly listed in the input are allowed; pairwise compatibility alone is insufficient.

You must select exactly enough configurations to fulfill the required number of instances so that no compute node, container image, or database shard is left unused or assigned to multiple instances. Determine whether this deployment is possible, and if so, report one valid assignment.

## Input

The first line contains two integers: the inventory size for each resource type (at least one, up to twenty-two), and the number of viable configurations (from zero up to the cube of the inventory size).

Each of the subsequent lines contains three integers representing a viable configuration of a compute node, a container image, and a database shard. All identifiers are between one and the inventory size. No configuration is listed more than once.

## Output

If a valid deployment covering all resources exists, print `YES` on the first line. Then, print one line for each deployed instance, containing three integers representing its compute node, container image, and database shard. Any assignment in which every resource is used exactly once is accepted; the instances may be printed in any order.

If no valid deployment exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable configurations require container image 1, meaning container image 2 can never be deployed.
