<STATEMENT>
# Problem A — Optical Switch Configuration

Time limit: 5 s   Memory limit: 256 MB

## Description

An optical network switch routes data. The hardware operates with a scale factor of **k**, meaning it is equipped with input ports numbered 1 to **k**, output ports numbered 1 to **k**, and optical frequencies numbered 1 to **k**.

Due to hardware limitations, only certain transmission pathways are physically viable. You are provided with a catalog of **t** viable pathways. Each pathway is defined by a triplet `(u, v, w)`, representing a connection from input port `u` to output port `v` operating on frequency `w`.

Your task is to activate a selection of exactly **k** distinct pathways from the provided catalog to achieve full network capacity. To ensure stable operation without interference, the combined footprint of your activated selection must be perfectly balanced across the hardware. Specifically, a configuration of **k** pathways is valid if and only if the chosen pathways collectively utilize exactly **k** distinct input ports, exactly **k** distinct output ports, and exactly **k** distinct optical frequencies.

Determine whether such a full-capacity routing configuration is possible, and if so, output one valid set of **k** activated pathways.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the scale factor of the switch, and the number of viable pathways in the catalog.
Each of the following **t** lines contains three integers **u**, **v**, and **w** (1 ≤ u, v, w ≤ k), representing a viable pathway connecting input port **u** to output port **v** using frequency **w**. No pathway is listed more than once.

## Output

If a valid configuration of exactly **k** pathways exists, print `YES` on the first line. Then, print **k** lines, each containing the three integers `u v w` of an activated pathway. Any configuration that meets all requirements is accepted; the pathways may be printed in any order.

If no such configuration exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable pathways connect to output port 1. Activating a selection of exactly 2 pathways from the catalog would result in only 1 distinct output port being utilized. This violates the requirement that exactly 2 distinct output ports must be utilized across the configuration. Therefore, no valid configuration exists.
</STATEMENT>
<RATIONALE>
Replaced the pairwise mutual exclusion constraints ("no two pathways share an input port") with a global set property ("the k chosen pathways collectively utilize exactly k distinct input ports"). This removes the explicit framing of making one independent choice per input port, forcing the models to deduce the underlying 3-dimensional matching structure and the optimal depth-first search strategy themselves.
</RATIONALE>
<PRESERVED_ANSWER>
Selecting exactly k items that collectively contain exactly k distinct values for a given attribute is mathematically equivalent to selecting k items such that no two share the same value for that attribute, leaving all valid configurations unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, asking for a subset of size k from a set of triples such that all coordinates in each of the three dimensions are distinct.
</PRESERVED_CLASS>
