<STATEMENT>
# Problem A — Optical Switch Configuration

Time limit: 5 s   Memory limit: 256 MB

## Description

An optical network switch routes data using specific transmission pathways. Each pathway is defined by an array of three operational parameters. The switch operates at a scale factor **k**. The parameters for any pathway are integer values ranging from 1 to **k**.

Due to hardware limitations, only certain specific transmission pathways are physically viable. You are provided with a list of **t** viable pathways. Each pathway is defined by a triplet `(u, v, w)`, representing its three operational parameters.

To achieve full capacity, you must activate a subset of exactly **k** pathways from the provided list. To ensure stable operation, the activated subset must satisfy a global diversity requirement. Specifically, an activated subset of **k** pathways is considered stable if and only if:
- The first parameters of the chosen pathways yield exactly **k** unique values.
- The second parameters of the chosen pathways yield exactly **k** unique values.
- The third parameters of the chosen pathways yield exactly **k** unique values.

Determine whether such a stable full-capacity configuration is possible, and if so, output one valid set of **k** activated pathways.

## Input

The first line contains two integers **k** and **t**: the scale factor of the switch, and the number of viable pathways in the list. The scale factor requires at least 1 component and is constrained by the maximum of 22 available hardware pins. The number of pathways can range from an empty list up to the theoretical maximum where all combinations of parameters are viable.

Each of the following **t** lines contains three integers **u**, **v**, and **w** (between 1 and **k** inclusive), representing the three operational parameters of a viable pathway. No pathway is listed more than once.

## Output

If a stable configuration of exactly **k** pathways exists, print `YES` on the first line. Then, print **k** lines, each containing the three integers `u v w` of an activated pathway. Any configuration that meets all requirements is accepted; the pathways may be printed in any order.

If no such configuration exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both viable pathways have a second parameter of 1. If we activate exactly 2 pathways from the list (which means choosing both), the second parameters of the chosen pathways would yield only 1 unique value. This violates the requirement that they must yield exactly 2 unique values. Therefore, no valid configuration exists.
</STATEMENT>
<RATIONALE>
The problem was reframed to hide the explicit 3-Dimensional Matching structure. Instead of stating that no two pathways can share an input, output, or frequency (which prompts models to iterate over one dimension and assign pathways), the constraint is now a global set-size property: the chosen subset of `k` pathways must yield exactly `k` unique values for each parameter. This forces models to derive the perfect matching property themselves rather than relying on surface-level pattern matching. Numeric bounds were also replaced with physical descriptions (e.g., 22 hardware pins) per strategy S07.
</RATIONALE>
<PRESERVED_ANSWER>
The condition that `k` pathways yield exactly `k` unique values for a parameter ranging from 1 to `k` is mathematically identical to requiring that no two pathways share a parameter, preserving all valid subsets.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Dimensional Matching, a known NP-complete problem, as the underlying combinatorial requirements are unchanged.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "yield exactly k unique values" as applying to the entire triplet rather than each parameter individually, though the bullet points explicitly separate the first, second, and third parameters.
</RISK>
