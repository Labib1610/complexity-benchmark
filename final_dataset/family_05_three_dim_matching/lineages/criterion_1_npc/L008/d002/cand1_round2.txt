# Problem A — Concurrent Operation Scheduling

Time limit: 5 s   Memory limit: 256 MB

## Description

You are deploying a distributed service that must run **k** concurrent operations. To support this, your data center provides **k** available processors, **k** memory banks, and **k** data buses. Each hardware unit is assigned a unique ID from 1 to **k**. The system architecture dictates that the number of concurrent operations (**k**) is at least 1 and at most 22.

A hardware configuration is defined by three IDs: one processor, one memory bank, and one data bus. You have a log of **t** verified configurations that are known to be stable. Depending on previous testing, this log might be completely empty (0 configurations), or it might contain every theoretically possible triplet up to k·k·k.

Your goal is to select exactly **k** configurations from the log to run the operations simultaneously. To avoid resource conflicts, the chosen subset of configurations must be completely independent. Specifically, no two selected configurations can use the same processor, no two can use the same memory bank, and no two can use the same data bus.

Determine if such a conflict-free selection of exactly **k** configurations exists, and if so, report the configurations you have chosen.

## Input

The first line contains two integers **k** and **t**: the number of concurrent operations to schedule and the number of verified configurations in the log. The values of **k** and **t** adhere to the system limits described above.
Each of the next **t** lines contains three integers **x**, **y**, and **z**. These represent a verified configuration using processor **x**, memory bank **y**, and data bus **z**. Each ID **x**, **y**, and **z** corresponds to a valid hardware unit, meaning it is guaranteed to be at least 1 and at most **k**. No configuration appears more than once in the log.

## Output

If it is possible to find exactly **k** configurations that do not conflict, output `YES` on the first line. Then, output **k** lines, each containing the three integers `x y z` of a selected configuration. Any valid selection of configurations is accepted. The chosen configurations can be printed in any order.

If no such selection of configurations exists, output `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both verified configurations require memory bank 1, meaning memory bank 2 can never be utilized in any chosen configuration.
</STATEMENT>
<RATIONALE>
The explicit "exact cover" wording ("every item is consumed exactly once") was replaced with an equivalent independent set framing ("no two selected configurations can use the same item", plus a strict size requirement of exactly `k`). This forces models to deduce that a size-`k` independent set across `k` items implies a perfect matching/exact cover, defeating surface-level pattern matching that triggers Dancing Links templates. The numeric bounds were integrated into the narrative as physical constraints to satisfy Strategy S07 while using the exact digits to pass the automated gate.
</RATIONALE>
<PRESERVED_ANSWER>
Selecting exactly `k` configurations such that no two share a processor, memory bank, or data bus guarantees that all `k` processors, memory banks, and data buses are used exactly once, which is mathematically identical to the seed's exact cover requirement.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains 3-Dimensional Matching (an NP-complete problem), as it still requires finding a perfect 3-partite matching among the given triplets.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "no two selected configurations can use the same processor" as a global restriction rather than a pairwise one, though "no two" is standard combinatorial phrasing for pairwise disjointness.
</RISK>
