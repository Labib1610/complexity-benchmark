<STATEMENT>
# Problem A — Balanced Route Deployment

Time limit: 5 s   Memory limit: 256 MB

## Description

You are tasked with deploying a balanced data processing network. The architecture relies on three distinct layers: origins, processing nodes, and endpoints. There are exactly **k** components in each layer, indexed from 1 to **k**.

You are provided a list of **t** supported pathways. A pathway is a specific triplet consisting of an origin, a processing node, and an endpoint.

To bring the network online, you must activate a set of pathways such that:
- Every origin is utilized by exactly one active pathway.
- To prevent signal collision, no processing node may be present in more than one active pathway.
- To prevent data corruption, no endpoint may be present in more than one active pathway.
- The total number of active pathways is exactly **k**.

These constraints ensure a perfectly balanced load across the network. Determine if such a configuration is possible, and if so, report the pathways to activate.

## Input

The first line contains two integers **k** and **t**. A network must have at least 1 component per layer, up to the physical chassis limit of 22 components. The inventory of supported pathways can be entirely empty (0) or contain up to every possible combination (**k** · **k** · **k**).

Each of the next **t** lines contains three integers **x**, **y**, **z** (where each component index is from 1 to **k** inclusive), representing a supported pathway consisting of origin **x**, processing node **y**, and endpoint **z**. No pathway is listed more than once.

## Output

If a valid configuration exists, print `YES` on the first line, then print exactly **k** lines, each containing the three integers `x y z` of one activated pathway. Any valid configuration is accepted; the pathways may be printed in any order.

If no such configuration exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, both supported pathways require processing node 1. Activating both would cause a signal collision, but activating only one fails the requirement for exactly **k** pathways. Thus, no valid configuration is possible.

<RATIONALE>
Removed the explicit "every origin, processing node, and endpoint is used exactly once" terminology, which triggers exact-cover/3D-matching templates. Replaced it with logically equivalent rules using "exactly one" for origins but "at most one" for nodes and endpoints, forcing the model to deduce the perfect matching via the pigeonhole principle. Bounds were integrated into the physical constraints of the network scenario to satisfy the indirect-bounds strategy while retaining exact numerical limits.
</RATIONALE>

The constraints that k pathways are chosen, covering all k origins exactly once, with no overlap on the k nodes or k endpoints, mathematically forces a perfect 3-dimensional matching, keeping all valid outputs identical.
</PRESERVED_ANSWER>
