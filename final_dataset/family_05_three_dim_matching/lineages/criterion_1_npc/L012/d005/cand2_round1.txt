# Problem A — Resonance Calibration

Time limit: 5 s   Memory limit: 256 MB

## Description

A geological scanner operates in a subterranean grid. Every location in the grid is defined by a depth **x**, a latitude **y**, and a longitude **z**, each taking an integer value from 1 up to the grid's bounding dimension **k**.

The scanner has identified **t** resonance pockets at specific `(x, y, z)` locations. 

To calibrate the system, you must load a subset of the identified pockets into the scanner's memory bank. The memory bank has exactly **k** slots, and every slot must be filled with a distinct pocket from the identified list.

Once loaded, the scanner evaluates the harmonic frequencies emitted by the chosen subset. Each loaded pocket `(x, y, z)` emits a specific energy signature in three independent spatial bands:
- Its depth energy is $4^x$.
- Its latitude energy is $4^y$.
- Its longitude energy is $4^z$.

To achieve perfect calibration and prevent harmonic feedback, the total aggregated energy in each spatial band must match the system's ideal resonance threshold. The calibration is successful if and only if:
- The sum of the depth energies of the **k** loaded pockets is exactly $(4^{k+1} - 4) / 3$.
- The sum of the latitude energies of the **k** loaded pockets is exactly $(4^{k+1} - 4) / 3$.
- The sum of the longitude energies of the **k** loaded pockets is exactly $(4^{k+1} - 4) / 3$.

Determine whether a successful calibration is possible, and if so, report one valid selection of resonance pockets.

## Input

The first line contains two integers **k** and **t** (1 ≤ k ≤ 22, 0 ≤ t ≤ k·k·k): the grid dimension and the number of identified resonance pockets.
Each of the next **t** lines contains three integers **x**, **y**, **z** (1 ≤ x, y, z ≤ k), the coordinates of a resonance pocket. No location is listed more than once.

## Output

If a valid calibration configuration of exactly **k** pockets exists, print `YES` on the first line. Then, print **k** lines, each containing the three coordinates `x y z` of one selected pocket. Any valid selection is accepted, and the pockets may be printed in any order.

If no valid selection exists, print `NO`.

## Examples

### Example 1

**Input**
```
2 3
1 1 1
1 2 2
2 2 2
```

**Output**
```
YES
1 1 1
2 2 2
```

### Example 2

**Input**
```
2 2
1 1 1
2 1 2
```

**Output**
```
NO
```

### Example 3

**Input**
```
1 1
1 1 1
```

**Output**
```
YES
1 1 1
```

## Note

In Example 2, the grid dimension is 2, so the memory bank requires exactly 2 pockets. The identified pockets are `(1, 1, 1)` and `(2, 1, 2)`. If both are loaded, we evaluate the aggregated energies. The latitude energies are $4^1 = 4$ and $4^1 = 4$. Their sum is $4 + 4 = 8$. However, the required threshold for $k=2$ is $(4^{2+1} - 4) / 3 = 20$. Since 8 does not equal 20, the calibration fails. Thus, a successful calibration is impossible.
</STATEMENT>
<RATIONALE>
Changed the pairwise inequality check into a global condition requiring the sum of $4^x$ (and $4^y$, $4^z$) for the selected pockets to equal $(4^{k+1}-4)/3$. This forces the model to mathematically deduce that the only way to achieve this sum with exactly $k$ terms in base 4 is if the coordinates form a permutation of $1..k$, breaking the shortcut of algebraically simplifying the original inequalities.
</RATIONALE>
<PRESERVED_ANSWER>
Because the only way for exactly $k$ powers of 4 to sum to $(4^{k+1}-4)/3$ (which has exactly $k$ ones in base 4) is if they are exactly $4^1, 4^2, \dots, 4^k$, this condition is logically equivalent to requiring all selected pockets to have distinct coordinates in each dimension, preserving all valid selections.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The core problem remains selecting $k$ triplets from a given list such that they exactly cover the domains $X, Y, Z$ of size $k$, which is exactly the NP-complete 3-Dimensional Matching problem.
</PRESERVED_CLASS>
<RISK>
Models might simulate the arithmetic directly and risk integer overflow if they don't use 64-bit integers, though $4^{23}$ safely fits within standard 64-bit signed integers in most competitive programming languages.
</RISK>
