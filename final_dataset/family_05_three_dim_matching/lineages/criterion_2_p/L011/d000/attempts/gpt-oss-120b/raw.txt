**Solution Explanation**

For every driver `x` all listed plans use the same truck `y`.  
Therefore the truck is *forced* by the driver and does not influence the
choice of plans – we only have to decide which route `z` each driver will
take.

So the problem becomes:

*Drivers* `1 … k` and *routes* `1 … k`.  
For driver `x` we have an edge to route `z` iff the plan `(x , truck[x] , z)`
is given.  
We have to choose exactly one edge incident to every driver and to every
route – i.e. a **perfect matching** in this bipartite graph.

If such a matching exists we output the corresponding plans
(`truck[x]` is known from any input line of driver `x`);
otherwise we output `NO`.

The classic Hopcroft‑Karp algorithm finds a maximum matching in  
`O(E·√V)` time, which is easily fast enough for `k ≤ 1200` and
`E ≤ k·k ≤ 1.44·10⁶`.

--------------------------------------------------------------------

#### Algorithm
```
read k, t
truck[1…k] = 0
adj[1…k] = empty lists
for each of the t lines (x, y, z):
        if truck[x] == 0: truck[x] = y          # first occurrence fixes the truck
        add edge x → z (store also the whole triple for later output)

run Hopcroft‑Karp on the bipartite graph (left = drivers, right = routes)
let matchL[x] = matched route of driver x   (0 = unmatched)
let matchR[z] = matched driver of route z

if any driver is unmatched:
        print "NO"
else:
        print "YES"
        for x = 1 … k:
                z = matchL[x]
                output x, truck[x], z
```

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm prints `YES` and a correct schedule
iff such a schedule exists.

---

##### Lemma 1  
For each driver `x` all input plans have the same truck, therefore the
value `truck[x]` stored by the algorithm equals the truck that must be used
with driver `x` in any feasible schedule.

**Proof.** The statement is given in the problem statement.
The algorithm stores the first seen truck for `x`; all later lines have the
same value, so the stored one is the unique possible truck. ∎



##### Lemma 2  
A set of `k` plans uses every driver, every truck and every route exactly
once **iff** the corresponding edges form a perfect matching between drivers
and routes.

**Proof.**  
*If* the plans form such a set, each driver appears once, each route appears
once, and by Lemma&nbsp;1 each driver is paired with its forced truck.
Thus each driver is incident to exactly one chosen edge and each route to
exactly one – a perfect matching.

*Only‑if* we have a perfect matching `M`. For every driver `x` the matching
contains exactly one edge `x–z`. The plan `(x, truck[x], z)` exists because
edges were created only from existing plans. Collecting those `k` plans uses
each driver once (by construction), each route once (matching property) and
each truck once (each driver has a distinct truck). ∎



##### Lemma 3  
Hopcroft‑Karp returns a matching of maximum cardinality.

**Proof.** Standard property of the Hopcroft‑Karp algorithm. ∎



##### Lemma 4  
If the algorithm prints `YES`, the printed `k` plans constitute a valid
schedule.

**Proof.** `YES` is printed only when every driver is matched, i.e. the
matching size is `k`. By Lemma&nbsp;2 the corresponding plans use each driver,
truck and route exactly once, hence they form a valid schedule. ∎



##### Lemma 5  
If a valid schedule exists, the algorithm prints `YES`.

**Proof.** From a valid schedule we obtain a perfect matching
(Lemma&nbsp;2). Its size is `k`. By Lemma&nbsp;3 the algorithm’s matching is
maximum, therefore its size is at least `k`. Since there are only `k` drivers,
the size equals `k` and all drivers are matched, so the algorithm prints
`YES`. ∎



##### Theorem  
The algorithm outputs `YES` and a correct set of `k` plans
iff such a set exists; otherwise it outputs `NO`.

**Proof.** Directly from Lemma&nbsp;4 (soundness) and Lemma&nbsp;5 (completeness). ∎



--------------------------------------------------------------------

#### Complexity Analysis  

* `E` – number of plans (`t`), `V = 2k`.
* Hopcroft‑Karp: `O(E·√V) = O(t·√k)`.
* All other work is linear in `t + k`.

With `k ≤ 1200` and `t ≤ k²` this is well below the limits
(≈ 1.5·10⁶·35 ≈ 5·10⁷ elementary operations).

Memory consumption: adjacency lists store each edge once → `O(t)`,
plus arrays of size `O(k)`. Fits into 256 MB.

#### Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    k = int(next(it))
    t = int(next(it))

    truck = [0] * (k + 1)          # truck[x]
    adj = [[] for _ in range(k + 1)]   # edges from driver to route
    # store triples for output
    edge_info = dict()            # (x, z) -> (x, y, z)

    for _ in range(t):
        x = int(next(it)); y = int(next(it)); z = int(next(it))
        if truck[x] == 0:
            truck[x] = y
        # add edge
        adj[x].append(z)
        edge_info[(x, z)] = (x, y, z)

    # Hopcroft‑Karp
    INF = 10 ** 9
    pairU = [0] * (k + 1)   # driver -> route
    pairV = [0] * (k + 1)   # route -> driver
    dist = [0] * (k + 1)

    def bfs() -> bool:
        q = deque()
        for u in range(1, k + 1):
            if pairU[u] == 0:
                dist[u] = 0
                q.append(u)
            else:
                dist[u] = INF
        dist[0] = INF
        while q:
            u = q.popleft()
            if dist[u] < dist[0]:
                for v in adj[u]:
                    if pairV[v] == 0:
                        if dist[0] == INF:
                            dist[0] = dist[u] + 1
                    elif dist[pairV[v]] == INF:
                        dist[pairV[v]] = dist[u] + 1
                        q.append(pairV[v])
        return dist[0] != INF

    def dfs(u: int) -> bool:
        if u == 0:
            return True
        for v in adj[u]:
            if pairV[v] == 0 or (dist[pairV[v]] == dist[u] + 1 and dfs(pairV[v])):
                pairU[u] = v
                pairV[v] = u
                return True
        dist[u] = INF
        return False

    matching = 0
    while bfs():
        for u in range(1, k + 1):
            if pairU[u] == 0 and dfs(u):
                matching += 1

    if matching != k:
        sys.stdout.write("NO")
        return

    out_lines = ["YES"]
    for x in range(1, k + 1):
        z = pairU[x]
        # retrieve stored triple (x, truck[x], z)
        _, y, _ = edge_info[(x, z)]
        out_lines.append(f"{x} {y} {z}")
    sys.stdout.write("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```

and conforms to the required input‑output format.
