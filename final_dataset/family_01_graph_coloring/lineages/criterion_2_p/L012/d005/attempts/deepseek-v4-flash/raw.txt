We are given a graph with \( n \) nodes and \( m \) edges. Each node must be assigned a value \( s_i \in \{1,2\} \). The condition for each node \( i \) is:

\[
\sum_{j \in N(i)} s_j = k_i \cdot (3 - s_i)
\]

where \( N(i)) is the set of neighbors of \( i \), and \( k_i = |N(i)| \).

Let’s analyze the condition. If \( s_i = 1 \), then \( 3 - s_i = 2 \), so the sum of neighbors’ values must be \( 2k_i \). Since each neighbor’s value is at most 2, this forces all neighbors to have value 2. If \( s_i =  2 \), then \( 3 - s_i =  ​1 \), so the sum of neighbors’ values must be \( k_i \). Since each neighbor’s value is at least 1, this forces all neighbors to have value 1.

Thus the rule is equivalent to:

- If a node is assigned 1, then all its neighbors must be assigned 2.
- If a node is assigned 2, then all its neighbors must be assigned 1.

This is exactly a proper 2-coloring of the graph (bipartite condition). Indeed, if we map 1 → 0 and 2 → 1, then the condition says adjacent nodes must have different colors. So the graph must be bipartite. If it is not bipartite, answer is NO.

If it is bipartite, there are exactly two possible colorings (up to swapping the two colors). However, the problem asks for the sequence that minimizes the sum \( \sum s_i \cdot 3^{n-i} \). Since \( s_i \in \{1,2\} \), this is like a binary number where 1 is smaller than 2. To minimize the sum, we want earlier positions (smaller index) to be as small as possible. So we need to choose the coloring that assigns 1 to as many early-index nodes as possible, with priority from index 1 upward.

This is a classic lexicographic minimization: we want the smallest binary string (with 1<2) among all valid colorings. Since the graph is bipartite, we can try both color assignments for node 1 (either 1 or 2), and for each, propagate the coloring via BFS/DFS. If a conflict occurs, that assignment is invalid. Among the valid ones, pick the one that is lexicographically smaller (i.e., compare the sequences directly). Since the graph may be disconnected, we must handle each component independently, but the lexicographic order is global. The standard approach: process nodes in order 1..n. For each uncolored node, try assigning it color 1 first, then propagate; if that leads to a valid coloring for the whole component, keep it; otherwise assign color 2. This greedy works because the choice for the earliest uncolored node dominates all later choices.

Implementation details:

- Use adjacency list.
- Color array: 0 = uncolored, 1 = color1 (value1), 2 = color2 (value2).
- For each node i from 1 to n:
  - If already colored, skip.
  - Try color1: set color[i]=1, BFS/DFS to propagate: for each neighbor, if uncolored, set opposite; if colored, check consistency. If conflict, revert (set all nodes visited in this attempt to 0) and try color2. If color2 also conflicts, output NO.
  - If color1 works, keep it; else use color2.

But careful: When trying color1, we might color some nodes that were already colored from previous components? No, because we only start on uncolored nodes. So the component is entirely uncolored before we start. So we can just do BFS/DFS and if conflict, we need to undo the colors we set in this attempt. We can collect visited nodes during the attempt and reset them if conflict.

Complexity: O(n+m).

Let’s verify with examples.



Example1: graph is a cycle 1-2-3-4-1. Bipartite. Try node1=1 → forces 2=2,3=1,4=2. Valid. Sequence: 1 2 1 2. That’s minimal.

Example2: triangle, not bipartite → NO.

Edge cases: isolated nodes: condition trivially satisfied (k=0, sum=0, RHS=0). They can be either 1 or2. Greedy will assign 1 because it’s smallest.
