**Solution Explanation**

For every commodity `i` we have to choose a price tier `p[i] ∈ {1,2}`.
For each dependency (edge) `{u,v}` the two conditions are

* at least one endpoint has tier 1,
* at least one endpoint has tier 2.

Both are satisfied **iff** the two endpoints obtain *different* tiers.
So the whole problem is exactly the problem of 2‑colouring a graph
(colour 1 ↔ tier 1, colour 2 ↔ tier 2).

--------------------------------------------------------------------

#### 1.   Graph view  

* vertices – commodities `1 … n`
* undirected edges – given dependencies  

The task is to colour the vertices with two colours so that every edge
connects vertices of different colours.  
If this is impossible we output `NO`.

--------------------------------------------------------------------

#### 2.   Lexicographically smallest assignment  

The graph may consist of several connected components.
Inside one component there are exactly two colourings – they are each
other’s colour swap.

The whole sequence `p[1] … p[n]` is compared lexicographically,
i.e. first `p[1]`, then `p[2]`, …  
Therefore the first (smallest index) vertex of a component decides which
orientation is better:

*If the smallest indexed vertex of a component gets colour 1,
the whole sequence is lexicographically smaller than if it got colour 2.*

Hence for every component we simply colour it **so that its smallest
vertex receives colour 1**.  
If we start a BFS/DFS from that vertex and give it colour 0 (later
translated to tier 1) this rule is automatically satisfied.

Isolated vertices have no edges, any tier works – we give them tier 1.

--------------------------------------------------------------------

#### 3.   Algorithm  

```
read n, m
build adjacency list

colour[1…n] = -1          # -1 = not visited yet

for v = 1 … n (in increasing order):
        if colour[v] == -1:          # new component, v is its smallest vertex
                colour[v] = 0        # colour 0 will become tier 1
                queue ← {v}
                while queue not empty:
                        x = pop queue
                        for each neighbour y of x:
                                if colour[y] == -1:
                                        colour[y] = colour[x] ^ 1   # opposite colour
                                        push y into queue
                                else if colour[y] == colour[x]:
                                        # edge connects equal colours → not bipartite
                                        print "NO" and exit

# all components processed without conflict
print "YES"
output (colour[i] + 1) for i = 1 … n   # translate 0→1, 1→2
```

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a lexicographically smallest
valid assignment iff such an assignment exists.

---

##### Lemma 1  
During the BFS of a component the algorithm assigns opposite colours to
the two endpoints of every processed edge.

**Proof.**  
When an edge `x – y` is examined:

* If `y` is uncoloured, the algorithm sets `colour[y] = colour[x] ^ 1`,
  i.e. opposite colour.
* If `y` is already coloured, the algorithm checks `colour[y] != colour[x]`;
  otherwise it aborts with `NO`. ∎



##### Lemma 2  
If the algorithm finishes without aborting, the obtained colouring satisfies
the two conditions for **every** dependency.

**Proof.**  
By Lemma&nbsp;1 each edge connects vertices of different colours.
Mapping colour 0 → tier 1, colour 1 → tier 2 gives for every edge one
endpoint tier 1 and the other tier 2, i.e. both required conditions. ∎



##### Lemma 3  
If the algorithm aborts (detects an edge whose endpoints have equal colour)
then **no** assignment satisfying the conditions exists.

**Proof.**  
An edge `u‑v` with `colour[u] = colour[v]` means that in the current
partial colouring `u` and `v` are forced to have the same tier.
Any valid assignment must colour the whole component consistently with
the already decided colours (otherwise a previously inspected edge would
be violated). Hence `u` and `v` would still receive the same tier, which
contradicts the requirement that an edge must have both tiers present.
Thus a valid assignment does not exist. ∎



##### Lemma 4  
For each connected component the algorithm outputs a colouring in which the
smallest‑indexed vertex of the component receives tier 1.

**Proof.**  
When the outer loop reaches a vertex `v` that is still uncoloured,
`v` is the smallest index of its component (all smaller indices belong to
already processed components). The algorithm colours `v` with `0`,
which later becomes tier 1. All other vertices of the component receive
colours relative to `v`, therefore `v` stays tier 1. ∎



##### Lemma 5  
Among all valid assignments, the one produced by the algorithm is
lexicographically smallest.

**Proof.**  
Consider the components in order of their smallest vertex.
By Lemma&nbsp;4 the algorithm gives each of those vertices tier 1.
Any other valid assignment must give each such vertex either tier 1
(same) or tier 2.  
If for the first component where the two assignments differ the other
assignment gives tier 2, its whole sequence is lexicographically larger,
because earlier positions coincide and at that position `2 > 1`.  
Thus no other valid assignment can be lexicographically smaller. ∎



##### Theorem  
The algorithm outputs  

*`NO`* iff no assignment satisfying all dependencies exists,  

*`YES`* and a sequence `p[1]…p[n]` otherwise, and this sequence is the
lexicographically smallest possible.

**Proof.**  

*If the algorithm prints `NO`*: by Lemma&nbsp;3 a valid assignment cannot
exist.

*If the algorithm prints `YES`*: it terminated without conflict, therefore
by Lemma&nbsp;2 the produced assignment satisfies all dependencies.
Lemma&nbsp;5 shows it is lexicographically minimal among all satisfying
assignments.

*Conversely*, if a satisfying assignment exists, the graph is bipartite.
BFS never meets an edge whose endpoints have the same colour, so the
algorithm never aborts and prints `YES`. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Building adjacency list* – `O(n + m)` memory and time.  
*BFS over all components* – each vertex and each edge processed once:  
`O(n + m)` time, `O(n)` additional memory for the colour array and the
queue.

Overall: **time `O(n + m)`**, **memory `O(n + m)`**, well inside the limits
(`n, m ≤ 2·10⁵`).

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
from collections import deque

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    it = iter(data)
    n = next(it)
    m = next(it)

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = next(it); v = next(it)
        adj[u].append(v)
        adj[v].append(u)

    colour = [-1] * (n + 1)          # -1 = unvisited, 0 or 1 otherwise

    for start in range(1, n + 1):
        if colour[start] != -1:
            continue
        # start a new component, give smallest vertex colour 0 (-> tier 1)
        colour[start] = 0
        q = deque([start])
        while q:
            x = q.popleft()
            cx = colour[x]
            for y in adj[x]:
                if colour[y] == -1:
                    colour[y] = cx ^ 1
                    q.append(y)
                elif colour[y] == cx:
                    # not bipartite
                    sys.stdout.write("NO")
                    return

    # all good
    sys.stdout.write("YES\n")
    out = ' '.join(str(colour[i] + 1) for i in range(1, n + 1))
    sys.stdout.write(out)

if __name__ == "__main__":
    solve()
```

conforms to the required input‑output format.
