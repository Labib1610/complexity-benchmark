# Module 2: State Assignment

Time limit: 1 s   Memory limit: 256 MB

The data reconciliation process consists of three distinct modules executed in sequence. First, the analytics engine scans past records to compile a list of cross-dependencies between database entries.

Your task is to implement the second module: the state assignment processor. This processor receives the list of cross-dependencies and must assign a numeric state of either `1` or `2` to each of the $n$ entries. To maintain data integrity, for every cross-dependency identified between entry $u$ and entry $v$, the bitwise XOR of their assigned states must evaluate to exactly 3.

If it is impossible to assign states to all entries satisfying this condition, the processor must abort the workflow. Furthermore, whenever multiple valid assignments are possible, the compliance protocol requires the processor to output the one that yields the lexicographically smallest sequence of states (where the sequence is formed by the states assigned to entries $1$ through $n$). It is permitted for all entries to receive the same state if no cross-dependencies force otherwise; both states do not need to be present in the final assignment.

Finally, the output of your module is fed into the third module, which uses these state designations to finalize the reconciliation schedule.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 2\cdot 10^5$, $0 \le m \le 2\cdot 10^5$), representing the number of database entries and the number of cross-dependencies identified by the first module.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$) — a pair of entries linked by a cross-dependency.

## Output
If the state assignment processor cannot find any valid assignment, output a single line with `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $s_1 \dots s_n$ (each either `1` or `2`), representing the state assigned to each entry from $1$ to $n$. This sequence must be the lexicographically smallest valid assignment.

## Example 1
Input:
```
4 4
1 2
2 3
3 4
1 4
```
Output:
```
YES
1 2 1 2
```

## Example 2
Input:
```
3 3
1 2
1 3
2 3
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
Changed the physical constraints of "working together" into an algebraic constraint where the "bitwise XOR of states must exactly equal 3". This forces models to logically deduce that `1 ^ 2 == 3` means adjacent elements must take opposite values, preventing simple keyword matching on "incompatible" and "two blocks" which easily triggers bipartite graph templates. Also explicitly clarified that both states do not need to be present to resolve an ambiguity in the seed.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that the bitwise XOR of two values from {1, 2} equals 3 is mathematically identical to requiring the two values to be different, perfectly preserving the original incompatibility constraint and lexicographically smallest resolution.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to finding a valid 2-coloring of an undirected graph and choosing the lexicographically smallest coloring, which is solvable in O(n+m) time using Breadth-First Search (or Depth-First Search).
</PRESERVED_CLASS>
