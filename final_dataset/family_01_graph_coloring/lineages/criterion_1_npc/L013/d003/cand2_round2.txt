# Routine Placement Protocol

Time limit: 2 s   Memory limit: 256 MB

A software system consists of $n$ routines. Profiling has revealed $m$ pairs of routines that exhibit critical interference when executed in the same tier. To ensure system stability, safety protocols dictate that the two routines in any identified interference pair must never be assigned to the same tier.

The execution framework is partitioned into a front-end tier (identified as tier 1), a middle-ware tier (identified as tier 2), and a back-end tier (identified as tier 3).

The interference constraints can form complex, interlocking dependencies. The system's hardware architecture accommodates a physical capacity of up to 40 routines, requiring at least 1 to be active. The number of interference pairs can range from 0 up to the maximum possible combination of pairs. Your solution must correctly process any configuration of constraints within these limits, verifying whether an allocation is possible or not.

You must determine whether it is feasible to allocate every routine to exactly one of these three tiers without violating the interference protocols. If a valid allocation is possible, you must provide one. You only need to supply one valid allocation, even if multiple are possible.

## Input
The first line contains two integers $n$ and $m$ — the total number of routines and the number of interference pairs ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$).
Each of the subsequent $m$ lines contains two integers $u$ and $v$, indicating that routine $u$ and routine $v$ must be allocated to different tiers.

## Output
If it is impossible to allocate all routines to the tiers without violating the interference protocols, print a single line containing `NO`.
If it is possible, print `YES` on the first line. On the second line, print $n$ integers $e_1, e_2, \dots, e_n$ separated by spaces, where each $e_i \in \{1, 2, 3\}$ indicates the tier assigned to routine $i$. You only need to supply one valid allocation, even if multiple are possible.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
