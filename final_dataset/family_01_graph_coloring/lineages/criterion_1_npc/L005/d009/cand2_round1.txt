<STATEMENT>
# Problem A — Distributed Shard Routing

Time limit: 2 s   Memory limit: 256 MB

You are configuring a distributed database with $n$ storage nodes. To ensure stable load distribution, each node must be assigned to exactly one of 3 available data shards. The shards are identified by the integer IDs 1, 2, and 3.

Each shard ID applies a specific hardware filter to a 3-channel diagnostic signal. The diagnostic signal consists of channels A, B, and C, and always originates with the values `[1, 1, 1]`.
- Shard 1 zeroes out channel A, and multiplies the current value of channel B by 2.
- Shard 2 zeroes out channel B, and multiplies the current value of channel C by 2.
- Shard 3 zeroes out channel C, and multiplies the current value of channel A by 2.

You are given a list of $m$ high-frequency query patterns. Each pattern represents a directional payload transfer from a specific node $u$ to a specific node $v$. 
During a transfer, the router tests compatibility by sending a diagnostic signal `[1, 1, 1]` sequentially through the two nodes. Node $u$ applies its assigned shard's filter to the signal first, and then node $v$ applies its assigned shard's filter to the resulting signal.

A routing collision occurs if the sum of the three channels in the final signal is strictly greater than 3. 

To maintain system stability, you must assign a shard ID (1, 2, or 3) to each of the $n$ nodes such that strictly zero collisions occur among all $m$ given query patterns. 

## Input
The first line contains two integers $n$ and $m$ — the number of storage nodes and the number of directional payload transfers ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$).
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing a transfer from node $u$ to node $v$. Nodes are indexed from 1 to $n$.

## Output
If no such assignment is possible, output NO on a single line.
Otherwise, output YES on the first line. On the second line, output $n$ integers $c_1 \ c_2 \dots c_n$ (each being 1, 2, or 3), where $c_i$ is the shard ID assigned to node $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I replaced the single modulo-arithmetic equation with a sequential, asymmetric state transformation that mimics a network simulation. Applying two identical filters yields a final channel sum of 5, while any two distinct filters yield a sum of 2, making the threshold "> 3" logically equivalent to testing equality. By framing the interactions as directional and the operations as non-commutative, models are heavily discouraged from mapping the problem to undirected graph coloring, which breaks their reliance on degree-ordering heuristics (like DSATUR) and forces a naive backtracking approach that will TLE.
</RATIONALE>
<PRESERVED_ANSWER>
The condition exactly evaluates to whether the two assigned shard IDs are identical (sum 5 vs sum 2), preserving the identical constraint logic and therefore the exact same valid outputs for all possible inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains isomorphic to Graph 3-Coloring, keeping it firmly NP-complete.
</PRESERVED_CLASS>
