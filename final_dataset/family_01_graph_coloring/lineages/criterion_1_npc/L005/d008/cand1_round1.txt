<STATEMENT>
# Problem A — Distributed Shard Routing

Time limit: 2 s   Memory limit: 256 MB

You are configuring a distributed database. To ensure stable load distribution, each storage node must be assigned to exactly one of 3 available data shards, identified by the integer IDs 1, 2, and 3.

The facility has exactly 4 server racks, each capable of holding 10 storage nodes, setting a hard physical limit on the total number of nodes. Testing requires at least 1 node to be active in the system.

You are given a list of high-frequency query patterns. Each pattern involves a specific pair of nodes $(u, v)$ that are frequently accessed together. The number of such patterns can range from zero up to the theoretical maximum of one pattern for every possible unique pair of distinct nodes.

To prevent routing bottlenecks, the hash-based router evaluates these pairs using a functional resonance check. For any given node $i$, its assigned shard ID $c_i$ defines its continuous basis function $f_i(x) = x^{c_i}$. 

For each high-frequency pair of nodes $(u, v)$, the router computes their overlap integral over the unit interval:
$$I_{u,v} = \int_{0}^{1} f_u(x) f_v(x) \, dx$$

A routing collision occurs if the overlap integral $I_{u,v}$ exactly equals $\frac{1}{2 c_u + 1}$ or if it exactly equals $\frac{1}{2 c_v + 1}$. 

To maintain system stability, you must assign a shard ID (1, 2, or 3) to each node such that strictly zero collisions occur among all given query patterns.

## Input
The first line contains two integers $n$ and $m$ — the number of storage nodes and the number of high-frequency query patterns. The limits on these values are determined by the physical capacities and theoretical maximums described above.
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing a pair of nodes involved in a high-frequency query pattern. Nodes are indexed from 1 to $n$.

## Output
If no such assignment is possible, output NO on a single line.
Otherwise, output YES on the first line. On the second line, output $n$ integers $c_1 \ c_2 \dots c_n$ (each being 1, 2, or 3), where $c_i$ is the shard ID assigned to node $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2

```
3 4
```
Output:
```
NO
```

<RATIONALE>
The explicit subset-cardinality equality check has been replaced with a calculus-based overlap condition, and the numeric bounds have been moved into the scenario text (S07). To succeed, the model must symbolically evaluate the definite integral to $1/(c_u + c_v + 1)$ and realize that it equals $1/(2c_u + 1)$ if and only if $c_u = c_v$, thereby deducing the hidden inequality constraint. Models that attempt to translate the problem literally and compute the integral numerically at each leaf of a search tree will fail due to time limits or floating-point precision issues.
</RATIONALE>
<PRESERVED_ANSWER>
The overlap integral evaluates to $1/(c_u + c_v + 1)$, which equals $1/(2c_u + 1)$ or $1/(2c_v + 1)$ if and only if $c_u = c_v$; thus strictly zero collisions enforces $c_u \neq c_v$ for all given pairs, exactly preserving the valid assignments.
</PRESERVED_ANSWER>
