<STATEMENT>
# Problem A — Microservice Initialization Phases

Time limit: 2 s   Memory limit: 256 MB

You are migrating a legacy system consisting of $n$ microservices. To manage the rollout safely, each microservice must be assigned to exactly one of 3 deployment phases. These phases are identified by the integers 1, 2, and 3.

You are given a list of $m$ interacting pairs of microservices. To ensure proper data handoff, these interacting pairs require sequential deployment. When two interacting microservices are deployed, the one in the earlier phase prepares the environment for the one in the later phase. 

Because the data flow direction between any interacting pair can be configured dynamically, it does not matter which of the two microservices is deployed first. However, to guarantee a clear initialization sequence, the phase assignment must ensure that for every given pair $(u, v)$, one of the two microservices receives a strictly greater phase number than the other.

Your task is to assign a phase (1, 2, or 3) to each of the $n$ microservices such that this condition holds for all $m$ interacting pairs.

## Input
The first line contains two integers $n$ and $m$ — the number of microservices and the number of interacting pairs ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$).
Each of the subsequent $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), representing a pair of microservices that interact. Microservices are indexed from 1 to $n$.

## Output
If no such assignment is possible, output NO on a single line.
Otherwise, output YES on the first line. On the second line, output $n$ integers $c_1 \ c_2 \dots c_n$ (each being 1, 2, or 3), where $c_i$ is the phase number assigned to microservice $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
Removed explicit "not equal" or set cardinality phrasing. Replaced it with a sequencing scenario where, for each given pair, one component must receive a strictly greater phase number than the other. This disguises the symmetric inequality (graph coloring) constraint as a local ordering requirement, forcing the model to deduce that this simply means the assigned integers cannot be equal.
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that one phase number must be strictly greater than the other is mathematically identical to requiring that the two phase numbers are not equal, preserving all valid assignments exactly.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to 3-coloring a graph, as each node must be assigned a value from {1, 2, 3} such that no two adjacent nodes share the same value.
</PRESERVED_CLASS>
<RISK>
None. The phrase "one of the two microservices receives a strictly greater phase number than the other" is mathematically unambiguous and maps directly to strict inequality.
</RISK>
