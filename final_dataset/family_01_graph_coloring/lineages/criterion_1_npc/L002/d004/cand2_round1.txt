# Trace Verification Protocol

Time limit: 2 s   Memory limit: 256 MB

You are implementing a security module for an array of $n$ quantum registers. Each register $i$ (from 1 to $n$) must be initialized with a state value $S[i]$ chosen from the set $\{1, 2, 3\}$.

The system's integrity is governed by a set of $m$ pairwise entanglement tests. Each test specifies two 1-based indices $u$ and $v$. For the array to be valid, every test must pass the following Trace Verification Protocol:

1. Initialize a $3 \times 3$ identity matrix $G$. Let its rows and columns be indexed 1, 2, and 3.
2. Swap row 1 and row $S[u]$ of the matrix $G$. (Note: if $S[u] = 1$, this operation leaves the matrix unchanged).
3. In the resulting matrix $G$, swap column 1 and column $S[v]$.
4. Calculate the trace of $G$ (the sum of the elements on its main diagonal).
5. The test passes if and only if the trace of $G$ is strictly less than 3.

Your task is to determine whether there exists at least one valid initialization sequence of length $n$ that passes all $m$ tests simultaneously. The test suites include highly restrictive test configurations. Naive left-to-right sequence generation will fail to complete within the time limit; you must ensure your search is efficient.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$). 
The following $m$ lines each contain two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), indicating a pair of registers that must undergo the verification test. 

## Output
If no sequence of states can pass all tests, output `NO` on a single line.
If a valid sequence exists, output `YES` on the first line. On the second line, output $n$ integers representing the valid sequence $S[1], S[2], \dots, S[n]$. If there are multiple valid sequences, any of them will be accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
I replaced the explicit inequality constraint (`S[u] != S[v]`) with a matrix trace protocol. The operations (swapping rows and columns of an identity matrix) correspond to multiplying permutation matrices, where the trace strictly equals 3 if and only if the two sequence values are identical. This forces the model to either mathematically prove the equivalence to inequality (which is difficult for LLMs) or implement the matrix operations literally, which strips away graph-specific optimizations and introduces a massive constant factor overhead, causing a TLE on hard instances.
</RATIONALE>
<PRESERVED_ANSWER>
The trace of the modified identity matrix is 3 if and only if S[u] equals S[v], meaning the condition "trace < 3" is mathematically identical to "S[u] != S[v]", keeping all valid and invalid sequences exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly 3-Coloring on a graph defined by the input pairs, preserving its NP-complete complexity.
</PRESERVED_CLASS>
