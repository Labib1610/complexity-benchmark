<STATEMENT>
# Assembly Sequencing

Time limit: 2 s   Memory limit: 256 MB

You are configuring the production schedule for a high-precision manufacturing plant. The daily production cycle is divided into exactly three sequential operational blocks (labeled 1, 2, and 3, in chronological order). 

There are $n$ distinct manufacturing tasks that must be executed. You must assign each task to exactly one of the three operational blocks. 

You are given a list of $m$ resource conflicts. Each conflict indicates that two specific tasks require the same critical robotic arm. Because a robotic arm lacks the capacity to process tasks concurrently, any two tasks that share an arm must be temporally separated. Specifically, for every given pair of tasks that share an arm, one task in the pair must be assigned to a strictly earlier operational block than the other.

Your objective is to determine if all $n$ tasks can be scheduled into the three operational blocks without violating any resource conflicts. If a valid schedule exists, output it.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — the number of manufacturing tasks and the number of resource conflicts.
Each of the next $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \ne v$), representing a pair of tasks that share a robotic arm.

## Output
If there is no valid way to schedule the tasks, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $b_1, b_2, \dots, b_n$ (each in {1, 2, 3}), where $b_i$ is the operational block assigned to task $i$. If there are multiple valid schedules, any valid schedule is accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The problem was completely reframed from frequency assignment to manufacturing scheduling. To break the model's recognition of the "not equal" constraint that screams Graph 3-Coloring, the mutual exclusion constraint was reworded as a temporal precedence constraint: "one task in the pair must be assigned to a strictly earlier operational block than the other". This logically enforces $b_u \neq b_v$ without using equality/inequality vocabulary, forcing the model to either deduce the graph structure or attempt to solve it as a generic scheduling/CSP problem without graph-specific heuristics (like degree ordering).
</RATIONALE>
<PRESERVED_ANSWER>
The requirement that one task must be in a strictly earlier block than the other is mathematically identical to requiring that their assigned blocks (1, 2, or 3) are not equal, preserving the exact same valid assignments as the original interference constraint.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem still requires assigning each of $n$ elements to one of 3 states such that no two conflicting elements share the same state, which is exactly Graph 3-Coloring (NP-complete).
</PRESERVED_CLASS>
<RISK>
A model might misinterpret "one task in the pair must be assigned to a strictly earlier operational block" as a directed constraint (e.g., $u$ must precede $v$ based on input order), though the phrasing "one task ... than the other" is inherently symmetric in standard English.
</RISK>
