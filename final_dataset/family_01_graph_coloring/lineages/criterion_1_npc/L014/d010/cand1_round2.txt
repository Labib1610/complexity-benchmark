# Task Scheduling Compatibility

Time limit: 2 s
Memory limit: 256 MB

You are given $n$ tasks, numbered 1 to $n$, and a set of $m$ dependencies between them. Your task is to assign a configuration parameter to each task. The available parameter options for any task are 1, 2, and 3.

For each dependency $(u, w)$, the parameters assigned to task $u$ and task $w$ (let's call them $x$ and $y$ respectively) must be compatible. The compatibility is determined by a defined check.

For a dependency between task $u$ and task $w$, the system first calculates a scheduling weight for each task:
$W_u = 100 \cdot x + u$
$W_w = 100 \cdot y + w$

Then, it calculates two cross-evaluation scores:
$S_u = \max(W_u, W_w) \cdot x + \min(W_u, W_w) \cdot y$
$S_w = \max(W_u, W_w) \cdot y + \min(W_u, W_w) \cdot x$

If $S_u$ is exactly equal to $S_w$, the assigned parameters cause a scheduling conflict and are incompatible for this dependency. 

To be fully valid, every dependency must connect two tasks that do not cause a scheduling conflict. You are provided with the number of tasks and the exact pairs that share a dependency. You must output a fully valid parameter assignment for all tasks, or indicate if it is impossible.

## Input
The first line contains two integers $n$ and $m$ — the number of tasks and the number of dependencies ($1 \le n \le 40$, $0 \le m \le n \cdot (n-1)/2$).
Each of the following $m$ lines contains two distinct integers $u$ and $w$ ($1 \le u, w \le n$, $u \neq w$), representing a pair of tasks connected by a dependency. It is guaranteed that each unordered pair of tasks appears at most once in the input.

## Output
If no valid parameter assignment can be found, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $a_1, a_2, \dots, a_n$ (where each $a_i \in \{1, 2, 3\}$), representing the parameter assigned to task $i$. Any valid assignment will be accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

Replaced the symmetric polynomial with a max/min cross-evaluation where the variables $u$ and $w$ do not algebraically cancel out in the equality test. This forces the model to logically prove that the weights $W_u$ and $W_w$ can never be equal (using the numeric bounds of $u$ and $w$) rather than relying on simple algebraic cancellation, breaking the exact shortcut identified in the trace.
</RATIONALE>
<PRESERVED_ANSWER>
Because $W_u$ and $W_w$ can never be equal given the bounds, $\max(W_u, W_w) > \min(W_u, W_w)$ is strictly true, meaning $S_u = S_w$ if and only if $x = y$, preserving the exact same valid assignments as the seed.
</PRESERVED_ANSWER>
