**Solution Explanation**

For every component we have to choose a voltage `1 , 2 , 3`.
For every data link `(u , v)` the two ends must obtain *different* voltages.
The problem is exactly the **graph 3‑colouring** problem:

* vertices – components  
* edges    – data links  
* colours  – voltages `1,2,3`

`n ≤ 40`, therefore an exponential backtracking search with good pruning
solves the task easily.



--------------------------------------------------------------------

#### 1.   Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices)  
* `colour[v]` – current colour of `v` (`0` = not coloured yet)  
* `allowed[v]` – bit mask of still possible colours for `v`  
  bit `0` → colour `1`, bit `1` → colour `2`, bit `2` → colour `3`  
  initially `allowed[v] = 0b111 = 7` for every vertex  

* `order` – vertices sorted by decreasing degree  
  (most constrained first → strong pruning)

--------------------------------------------------------------------

#### 2.   Backtracking  

Recursive function `dfs(pos)` colours the vertex `order[pos]`.

```
if pos == n :   all vertices coloured → success
v = order[pos]
for each colour c that is still allowed for v
        assign c to v
        for every still uncoloured neighbour u of v
                delete colour c from allowed[u]
                if allowed[u] becomes empty → conflict, stop this branch
        recurse to dfs(pos+1)
        if recursion succeeded → propagate success
        undo all changes (restore allowed masks, colour[v]=0)
return failure
```

*The only information that changes during the search are the
`allowed` masks of the still uncoloured neighbours of the currently
coloured vertex.  
All other vertices keep their masks, therefore we only have to store
the previous mask of a neighbour to be able to restore it when backtracking.*

The recursion depth is at most `n = 40`, far below Python’s recursion limit.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
During the execution of `dfs` the invariant holds:

> For every vertex `x` that is still uncoloured,
> `allowed[x]` contains exactly the colours that are **not** used by any
> already coloured neighbour of `x`.

**Proof.**  
Initially no vertex is coloured, `allowed[x] = {1,2,3}` – the invariant
holds.

Assume the invariant holds before a recursive step.
We colour a vertex `v` with colour `c`.  
For each uncoloured neighbour `u` we delete `c` from `allowed[u]`.
All other vertices keep their masks unchanged.
Thus after the update `allowed[u]` contains precisely the colours not used
by coloured neighbours (the new coloured neighbour `v` uses colour `c`,
all older coloured neighbours are unchanged). ∎



##### Lemma 2  
When the algorithm tries a colour `c` for a vertex `v`,
all previously coloured vertices keep pairwise different colours
(and also differ from `c` on the edges incident to `v`).

**Proof.**  
The algorithm only tries a colour `c` that is present in `allowed[v]`.
By Lemma&nbsp;1 this means that none of the already coloured neighbours of `v`
uses colour `c`.  
All earlier colour choices were made in the same way, therefore every
edge whose both ends are already coloured connects vertices with different
colours. ∎



##### Lemma 3  
If the algorithm reaches `pos == n` (all vertices coloured) the obtained
colouring is a valid solution of the original problem.

**Proof.**  
By Lemma&nbsp;2 every edge connects vertices with different colours.
All colours belong to `{1,2,3}` by construction. ∎



##### Lemma 4  
If a partial assignment can be extended to a full proper 3‑colouring,
the recursive search will never discard the branch that contains this
extension.

**Proof.**  
Consider a step where the algorithm colours vertex `v` with colour `c`.
If the current partial assignment is extendable, then there exists a full
proper colouring extending it; in that colouring `v` has some colour
`c*`.  
Because the full colouring is proper, `c*` is not used by any already
coloured neighbour of `v`. By Lemma&nbsp;1 `c*` is therefore present in
`allowed[v]`, i.e. the algorithm will try it (maybe later among other
colours).  
When it tries `c*`, the update of neighbours removes exactly the colour
`c*` from their allowed sets. In the full proper colouring none of those
neighbours uses `c*`, so their allowed sets stay non‑empty.
Consequently the algorithm does **not** backtrack because of a conflict
while following this branch. ∎



##### Lemma 5  
If the algorithm outputs `NO`, the graph is not 3‑colourable.

**Proof.**  
`NO` is printed only if the initial call `dfs(0)` returns failure,
i.e. every possible colour choice for the first vertex leads to a
recursive call that finally fails.
Assume for contradiction that a proper 3‑colouring exists.
Follow the recursion along the colours used by this colouring:
by Lemma&nbsp;4 the branch that respects the colouring is never pruned,
hence the recursion would finally succeed – contradiction. ∎



##### Lemma 6  
If the algorithm outputs `YES` together with a colour list,
the list is a proper 3‑colouring.

**Proof.**  
`YES` is printed only after `dfs` returned success, which happens only
when `pos == n`. By Lemma&nbsp;3 the obtained assignment is proper. ∎



##### Theorem  
The program prints  

* `YES` and a correct voltage assignment **iff** such an assignment exists,  
* otherwise prints `NO`.

**Proof.**  
*If* part – existence ⇒ algorithm finds it:  
By Lemma&nbsp;4 the branch representing any existing proper colouring is never
discarded, therefore the recursion eventually reaches `pos == n` and
returns success. By Lemma&nbsp;6 the printed assignment is correct.

*Only‑if* part – algorithm prints `YES` ⇒ assignment exists:  
Lemma&nbsp;6 guarantees the printed assignment is proper, hence a solution
exists.

If the algorithm prints `NO`, Lemma&nbsp;5 shows that no proper 3‑colouring
exists. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

`n ≤ 40`.

*Each recursive level* tries at most 3 colours and for each colour scans the
neighbour list of the current vertex (size ≤ n‑1).  
All other operations are `O(1)`.

Worst‑case time: `O( 3^n * n )` – exponential, unavoidable for an NP‑complete
problem.  
For `n = 40` the strong pruning (degree ordering, early conflict detection)
keeps the actual running time far below the limit (well under a second
for all test cases).

Memory consumption:

* adjacency lists – `O(n + m)` ≤ `O(n^2)` ≤ 1600 integers  
* arrays `colour`, `allowed` – `O(n)`  

Overall `O(n + m)` ≤ a few kilobytes, far below the 256 MB limit.

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        if u == v:
            continue
        adj[u].append(v)
        adj[v].append(u)

    # order vertices by decreasing degree (stronger constraints first)
    order = sorted(range(n), key=lambda x: -len(adj[x]))

    colour = [0] * n               # 0 = uncoloured, else 1..3
    allowed = [7] * n               # bitmask 0b111 : all three colours possible

    # depth‑first search with backtracking
    def dfs(pos: int) -> bool:
        if pos == n:
            return True
        v = order[pos]
        mask = allowed[v]
        while mask:
            low = mask & -mask
            c = low.bit_length()          # colour number 1..3
            mask ^= low

            colour[v] = c
            bit = 1 << (c - 1)
            changed = []                   # (vertex, previous_allowed)

            conflict = False
            for u in adj[v]:
                if colour[u] == 0:          # only affect still uncoloured neighbours
                    if allowed[u] & bit:
                        prev = allowed[u]
                        allowed[u] = prev & ~bit
                        changed.append((u, prev))
                        if allowed[u] == 0:
                            conflict = True
                            break
            if not conflict:
                if dfs(pos + 1):
                    return True

            # undo changes
            for u, prev in changed:
                allowed[u] = prev
            colour[v] = 0
        return False

    if dfs(0):
        out = ['YES', ' '.join(str(colour[i]) for i in range(n))]
        sys.stdout.write('\n'.join(out))
    else:
        sys.stdout.write('NO')

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input / output format.
