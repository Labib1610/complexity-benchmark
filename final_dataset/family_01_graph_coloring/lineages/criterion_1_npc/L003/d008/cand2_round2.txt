<METHOD_NAME>Constraint Mapping via Arithmetic Properties</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit "different modes" constraint with an arithmetic property on the assigned values (their product cannot be a perfect square). Since the allowed values are 1, 2, 3, the only way their product is a perfect square is if they are equal. This prevents models from immediately triggering graph coloring heuristics, forcing them to reason about the arithmetic constraint instead.</METHOD_DESCRIPTION>
<METHOD_NOVEL>yes</METHOD_NOVEL>

<STATEMENT>
# Antenna Alignment

Time limit: 2 s   Memory limit: 256 MB

You are deploying a network of $n$ communication antennas. Each antenna must be configured with a power setting, chosen from the values 1, 2, and 3. Every antenna must receive exactly one setting.

There are $m$ pairs of antennas that are in direct line-of-sight of each other. If two antennas in line-of-sight operate on settings whose product is a perfect square, their signals will create a standing wave resonance and cause a network failure. Therefore, to ensure stable communication, any two antennas that are in line-of-sight must be assigned settings such that their product is strictly not a perfect square.

You must determine whether it is possible to assign a valid power setting to all $n$ antennas such that no two line-of-sight antennas trigger this resonance failure. To ensure the evaluation is robust, test cases may be adversarially selected hard resonance network configurations, including both difficult satisfiable and unsatisfiable instances.

## Input
The first line contains two integers $n$ and $m$ — the number of antennas and the number of line-of-sight pairs ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$). The antennas are indexed from $1$ to $n$.
Each of the subsequent $m$ lines contains two distinct integers $u$ and $v$ ($1 \le u, v \le n$), indicating that antenna $u$ and antenna $v$ are in line-of-sight. Every listed pair represents a strict resonance constraint.

## Output
If a safe configuration is impossible, output a single line containing NO.
If a valid configuration exists, output YES on the first line. On the second line, output $n$ space-separated integers $p_1, p_2, \dots, p_n$ (where each $p_i \in \{1, 2, 3\}$), representing the setting assigned to antenna $i$. Any valid configuration will be accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The explicit requirement that line-of-sight antennas must have "different" settings was replaced with the mathematical requirement that the product of their settings must not be a perfect square. For the allowed values of 1, 2, and 3, the only way a product of two values forms a perfect square is if the values are identical. This forces the model to deduce the non-equality constraint rather than immediately matching the problem to graph coloring.
</RATIONALE>
<PRESERVED_ANSWER>
The product of two numbers chosen from {1, 2, 3} is a perfect square if and only if the numbers are equal, meaning the constraint is mathematically identical to requiring different values.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to graph 3-coloring, which is NP-complete.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "perfect square" if they fail to restrict the domain to {1, 2, 3}, but the problem statement explicitly bounds the settings to these values.
</RISK>
