<METHOD_NAME>ALGEBRAIC_EQUALITY_OBFUSCATION</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the explicit inequality constraint ("must be different") with an algebraically equivalent condition over the domain {1, 2, 3}: "the product of the two values must not be a perfect square". This prevents surface-level pattern matching from recognizing the problem as Graph 3-Coloring, thereby disabling the degree-ordered backtracking heuristics the remaining models rely on to pass adversarial test cases.</METHOD_DESCRIPTION>

<STATEMENT>
# Antenna Alignment

Time limit: 2 s   Memory limit: 256 MB

You are deploying a network of communication antennas. The hardware controller has a strict capacity limit, supporting up to a maximum of 40 antenna slots. Thus, you will deploy a number of antennas ranging from 1 up to this hardware limit. 

Each antenna must be configured with a power setting, chosen from the integer values 1, 2, or 3. 

Certain pairs of antennas are in direct line-of-sight. If two antennas in line-of-sight are configured such that the product of their power settings yields a perfect square (the square of an integer), their signals will enter a resonance loop and cause a network failure. To ensure stable communication, any two antennas that share a line-of-sight must be assigned power settings whose product is strictly not a perfect square. 

The number of line-of-sight pairs can be anything from zero up to the theoretical maximum where every antenna has a line-of-sight to every other antenna.

You must determine whether it is possible to assign a valid power setting to all antennas such that no resonance loops occur.

## Input
The first line contains two integers $n$ and $m$ — the number of antennas and the number of line-of-sight pairs. The number of antennas $n$ respects the hardware limit (between 1 and 40 inclusive). The number of pairs $m$ is between 0 and the maximum possible number of distinct antenna pairs. The antennas are indexed from $1$ to $n$.
Each of the subsequent $m$ lines contains two distinct integers $u$ and $v$ ($1 \le u, v \le n$), indicating that antenna $u$ and antenna $v$ are in line-of-sight. Every listed pair represents a strict resonance constraint.

## Output
If a safe configuration is impossible, output a single line containing NO.
If a valid configuration exists, output YES on the first line. On the second line, output $n$ space-separated integers $p_1, p_2, \dots, p_n$ (where each $p_i \in \{1, 2, 3\}$), representing the power setting assigned to antenna $i$. Any valid configuration will be accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
I replaced the explicit "must be different" constraint with an algebraically equivalent condition: "the product of the two power settings must not be a perfect square". Since the domain is restricted to {1, 2, 3}, the product of two values is a perfect square (1, 4, or 9) if and only if the two values are identical. This prevents models from recognizing the problem as Graph 3-Coloring via surface pattern matching, forcing them to either genuinely deduce the equivalence or write a generic constraint solver that lacks the degree-ordering heuristics needed to pass the adversarial test cases.
</RATIONALE>
<PRESERVED_ANSWER>
The condition "product is not a perfect square" for values in {1, 2, 3} is mathematically identical to "values are different", meaning the exact same assignments are valid and the output remains unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The underlying constraint network is completely unmodified, meaning the problem remains exactly equivalent to Graph 3-Coloring and stays in the same NP-complete complexity class.
</PRESERVED_CLASS>
<RISK>
Models might theoretically fail to understand that 1 is a perfect square, though the explicit definition "the square of an integer" makes it mathematically unambiguous.
</RISK>
