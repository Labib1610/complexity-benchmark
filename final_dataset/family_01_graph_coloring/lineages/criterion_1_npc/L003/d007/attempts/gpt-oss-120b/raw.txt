**Solution Explanation**

The problem asks for a proper 3‑coloring of an undirected graph with  
`n ≤ 40`. This is a classic NP‑complete problem, but for such a small
`n` a well‑pruned depth‑first search (backtracking) is fast enough.

--------------------------------------------------------------------

#### 1.  Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices).  
* `order` – vertices sorted by decreasing degree, the usual heuristic for
  graph coloring (the most constrained vertex is colored first).  
* `color[v]` – current colour of vertex `v` (`0` = uncoloured,
  otherwise `1,2,3`).  

--------------------------------------------------------------------

#### 2.  Backtracking  

```
dfs(pos):
    if pos == n:               # all vertices coloured
        return True
    v = order[pos]             # vertex to colour now
    for c in (1,2,3):
        if no neighbour of v already has colour c:
            color[v] = c
            if dfs(pos+1):
                return True
            color[v] = 0       # undo
    return False               # none of the three colours works
```

The test *“no neighbour already has colour c”* is `O(deg(v))`.  
Because `n` is tiny, this simple test is sufficient.

The ordering by degree dramatically reduces the search tree:
high‑degree vertices are fixed early, cutting many branches.

--------------------------------------------------------------------

#### 3.  Correctness Proof  

We prove that the algorithm outputs **YES** with a correct coloring
iff such a coloring exists.

---

##### Lemma 1  
During the execution of `dfs(pos)` the partial assignment stored in
`color` is always proper: no two already coloured adjacent vertices share
the same colour.

**Proof.**  
A colour `c` is assigned to a vertex `v` only after checking that none
of its neighbours currently has colour `c`. All previously coloured
vertices keep their colours, therefore after the assignment the property
holds. ∎



##### Lemma 2  
If `dfs(pos)` returns `True`, the array `color` is a proper 3‑coloring of
the whole graph.

**Proof.**  
`True` is returned only when `pos == n`, i.e. every vertex received a
colour. By Lemma&nbsp;1 the partial assignment is proper at every step,
hence also after the last step. All vertices are coloured, so the whole
graph is properly coloured. ∎



##### Lemma 3  
If a proper 3‑coloring exists, `dfs(0)` eventually returns `True`.

**Proof.**  
Consider any fixed proper coloring `C`. The recursion explores **all**
possibilities of assigning colours to vertices in the order `order`,
because for each vertex it tries the three colours one after another.
Whenever the recursion chooses a colour that coincides with `C` for the
current vertex, the check against neighbours succeeds (since `C` is
proper). Therefore the branch that follows exactly the colours of `C`
is never pruned and reaches depth `n`, where it returns `True`. ∎



##### Lemma 4  
If `dfs(0)` returns `False`, no proper 3‑coloring exists.

**Proof.**  
`False` means that every branch of the search tree was explored and each
ended in a dead‑end where the current vertex could not be coloured
without violating propriety. Suppose a proper coloring existed.
By Lemma&nbsp;3 the branch following that coloring would have succeeded,
contradiction. Hence no proper coloring exists. ∎



##### Theorem  
The program prints  

* “YES” and a valid assignment **iff** a valid assignment exists,  
* otherwise prints “NO”.

**Proof.**  
If the program prints “YES”, it did so because `dfs(0)` returned `True`.
By Lemma&nbsp;2 the printed assignment is a proper 3‑coloring, therefore a
solution exists.

If the program prints “NO”, `dfs(0)` returned `False`. By Lemma&nbsp;4
no proper 3‑coloring exists, so the correct answer is “NO”. ∎



--------------------------------------------------------------------

#### 4.  Complexity Analysis  

*Let `Δ` be the maximum degree.*

* Each recursive step checks at most `Δ` neighbours → `O(Δ)`.
* In the worst case the algorithm explores `3^n` nodes, but the degree
  ordering and early pruning make the practical number tiny for `n ≤ 40`.
* Memory consumption: `O(n + m)` for the adjacency lists and `O(n)` for
  the colour array.

Both limits easily satisfy the given constraints (2 s, 256 MiB).

--------------------------------------------------------------------

#### 5.  Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        adj[u].append(v)
        adj[v].append(u)

    # order vertices by decreasing degree
    order = sorted(range(n), key=lambda x: -len(adj[x]))
    color = [0] * n  # 0 = uncoloured, else 1..3

    # fast neighbour colour test
    def can_use(v: int, c: int) -> bool:
        for nb in adj[v]:
            if color[nb] == c:
                return False
        return True

    def dfs(pos: int) -> bool:
        if pos == n:
            return True
        v = order[pos]
        for c in (1, 2, 3):
            if can_use(v, c):
                color[v] = c
                if dfs(pos + 1):
                    return True
                color[v] = 0
        return False

    if dfs(0):
        out = ['YES', ' '.join(str(color[i]) for i in range(n))]
        sys.stdout.write('\n'.join(out))
    else:
        sys.stdout.write('NO')

if __name__ == "__main__":
    solve()
```

conforms to the required input‑output format.
