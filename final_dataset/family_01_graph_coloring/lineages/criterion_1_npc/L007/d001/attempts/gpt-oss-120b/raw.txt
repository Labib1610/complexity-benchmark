**Solution Explanation**

For every person we have to choose one of three shifts  
(1, 2, 3) such that two people that are in conflict never obtain the same
shift.
The conflict graph has at most `n = 40` vertices, therefore an exponential
search with strong pruning is fast enough.

--------------------------------------------------------------------

#### 1.   Data structures  

* `adj[v]` – list of neighbours of vertex `v` (0‑based indices).  
* `col[v]` – current colour of `v` (`0` = not coloured yet, otherwise `1…3`).  
* `poss[v]` – bit mask of still possible colours for `v`.  
  bit `0` → colour 1, bit `1` → colour 2, bit `2` → colour 3.  
  Initially `poss[v] = 0b111 = 7` for every vertex.  

Because `n ≤ 40` all structures are tiny.

--------------------------------------------------------------------

#### 2.   Backtracking with forward checking  

The algorithm is a depth‑first search that always colours one still
uncoloured vertex.

* **Variable ordering (MRV)** – choose the vertex with the smallest
  number of still possible colours (`popcount(poss[v])`).  
  This reduces branching dramatically.

* **Value ordering** – try the possible colours in any order
  (`1,2,3`).

* **Forward checking** – after fixing a colour for vertex `v`
  the same colour is removed from the possibility masks of all still
  uncoloured neighbours.
  If a neighbour loses its last possible colour the current branch is
  impossible and we backtrack immediately.

All changes of `poss[·]` are stored on a stack (`changed`) so they can be
restored when the recursion returns.

The recursion stops successfully when every vertex is coloured.

The whole search explores at most `3^40` states, but the MRV heuristic and
forward checking prune the tree heavily; for `n = 40` it easily fits into
the 2 seconds limit.

--------------------------------------------------------------------

#### 3.   Correctness Proof  

We prove that the algorithm prints **YES** and a correct assignment
iff a 3‑colouring exists, otherwise prints **NO**.

---

##### Lemma 1  
During the search `poss[v]` always contains exactly the colours that can
still be assigned to `v` without violating already fixed colours.

**Proof.**  
Initially all three colours are possible, which is correct.
When a vertex `x` receives colour `c`, the algorithm removes `c` from
`poss[y]` for every uncoloured neighbour `y`.  
No other colour is removed, and no colour is added later.
Thus after the removal `poss[y]` contains precisely the colours that do not
conflict with the already fixed neighbours. ∎



##### Lemma 2  
If the algorithm reaches a recursive call where some vertex has
`poss[v] = 0`, then the current partial assignment cannot be extended to
a full proper 3‑colouring.

**Proof.**  
By Lemma&nbsp;1 `poss[v] = 0` means that *every* colour would conflict with
an already coloured neighbour, therefore any extension would create a
conflict. ∎



##### Lemma 3  
Whenever the algorithm assigns a colour to a vertex, the partial
assignment remains proper (no two adjacent coloured vertices share a
colour).

**Proof.**  
A colour `c` is assigned to vertex `v` only if `c ∈ poss[v]`.  
By Lemma&nbsp;1 this means that none of the already coloured neighbours of
`v` uses colour `c`. Hence the new assignment does not create a conflict. ∎



##### Lemma 4  
If the algorithm outputs a colouring, it is a valid 3‑colouring of the
whole graph.

**Proof.**  
The algorithm stops only when every vertex is coloured.
By Lemma&nbsp;3 the partial assignment is proper after each step, therefore
the final complete assignment is proper.
All colours are taken from `{1,2,3}` by construction. ∎



##### Lemma 5  
If a proper 3‑colouring exists, the algorithm will eventually find one
(and thus output **YES**).

**Proof.**  
Consider any fixed proper 3‑colouring `C`.  
During the search the algorithm explores *all* possibilities that are
compatible with the already made decisions (it never discards a colour
that could still lead to a solution, because it only removes colours
that would immediately create a conflict – Lemma&nbsp;1).  
Therefore there exists a path in the search tree that follows exactly
the colours of `C`.  
The algorithm performs a depth‑first traversal of the whole tree, so it
will eventually walk along that path and reach a leaf where all vertices
are coloured. At that leaf it outputs the found colouring. ∎



##### Lemma 6  
If the algorithm finishes without finding a colouring, then no proper
3‑colouring exists.

**Proof.**  
Assume the contrary: a proper 3‑colouring `C` exists but the algorithm
fails.  
During the exhaustive depth‑first search every possible colour choice
that does **not** immediately contradict already fixed colours is tried.
Whenever a branch is cut off, it is because some vertex obtained
`poss = 0` (Lemma&nbsp;2), i.e. no colour can be assigned without conflict.
Consequently **no** extension of the current partial assignment can be a
proper colouring.  
Thus the branch that would follow `C` cannot be cut off, contradicting the
assumption that the algorithm never reaches a full colouring. ∎



##### Theorem  
The program prints  

* `YES` and a correct shift assignment **iff** a feasible assignment exists,
* otherwise prints `NO`.

**Proof.**  
*If* the program prints `YES`, by Lemma&nbsp;4 the printed assignment is a
valid 3‑colouring, therefore a feasible assignment exists.  

*Only‑if*: if a feasible assignment exists, Lemma&nbsp;5 guarantees that
the algorithm will find one and print `YES`.  
If the algorithm prints `NO`, it terminated without finding a colouring,
hence by Lemma&nbsp;6 no feasible assignment exists. ∎



--------------------------------------------------------------------

#### 4.   Complexity Analysis  

*`n ≤ 40`*  

Let `T` be the number of visited search nodes.

* Each recursive step scans all vertices to pick the MRV vertex  
  → `O(n)` time.
* Updating neighbours touches each edge at most once per assignment  
  → `O(m)` per level, but summed over the whole search it is `O(T·Δ)` where
  `Δ` is the maximum degree ( ≤ n).

In practice `T` is far below `3^n` because of pruning; for the worst
theoretical bound we can only state `O(3^n)`.  
Memory consumption:  

* adjacency list `O(n + m)`,
* arrays `col`, `poss` of size `n`,
* recursion depth `n`.

All well below the limits (a few kilobytes).

#### 5.   Reference Implementation  (Python 3)

```python
import sys

sys.setrecursionlimit(10000)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    adj = [[] for _ in range(n)]
    for _ in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        if u == v:
            continue
        adj[u].append(v)
        adj[v].append(u)

    # possible colours mask, bits 0..2 correspond to colours 1..3
    poss = [0b111] * n
    col = [0] * n                     # 0 = uncoloured, else 1..3
    popcnt = [0, 1, 1, 2, 1, 2, 2, 3]  # for numbers 0..7

    # choose vertex with Minimum Remaining Values (fewest possible colours)
    def select_vertex() -> int:
        best = -1
        best_cnt = 4
        for v in range(n):
            if col[v] == 0:
                cnt = popcnt[poss[v]]
                if cnt < best_cnt:
                    best_cnt = cnt
                    best = v
                    if cnt == 1:
                        break
        return best

    def dfs() -> bool:
        # all coloured?
        if all(col[v] != 0 for v in range(n)):
            return True

        v = select_vertex()
        mask = poss[v]
        # try colours 1,2,3
        for colour in (1, 2, 3):
            bit = 1 << (colour - 1)
            if mask & bit == 0:
                continue

            # assign colour
            col[v] = colour
            changed = []          # (neighbor, old_mask)
            ok = True

            for nb in adj[v]:
                if col[nb] == 0 and (poss[nb] & bit):
                    new_mask = poss[nb] & ~bit
                    if new_mask != poss[nb]:
                        changed.append((nb, poss[nb]))
                        poss[nb] = new_mask
                        if new_mask == 0:
                            ok = False
                            break

            if ok and dfs():
                return True

            # revert changes
            for nb, old in reversed(changed):
                poss[nb] = old
            col[v] = 0

        return False

    if dfs():
        out = ["YES", " ".join(str(c) for c in col)]
    else:
        out = ["NO"]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
