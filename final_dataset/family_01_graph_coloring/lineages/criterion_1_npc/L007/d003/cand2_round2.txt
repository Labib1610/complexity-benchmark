# Problem A — Trichrome Shifts

Time limit: 2 s   Memory limit: 256 MB

A manufacturing facility operates continuously across three distinct shifts, designated as 1, 2, and 3. The facility employs $n$ personnel.

Certain pairs of personnel have complex operational dependencies. You are provided with $m$ dependency records, each specifying two individuals $u$ and $v$. 

To prevent critical workflow failures, the shift scheduling must satisfy a specific set of ordered compatibility rules. For every recorded dependency pair $(u, v)$ (in the exact order provided in the input), their assigned shifts $s_u$ and $s_v$ must satisfy ALL of the following:
- If $s_u = s_v$, their combined shift intensity $(s_u \times s_v)$ must be strictly greater than 10.
- If $s_u < s_v$, their forward transition gap $(s_v - s_u)$ must be strictly less than 3.
- If $s_u > s_v$, their backward recovery sum $(s_u + s_v)$ must be strictly greater than 2.

Your task is to allocate each person to exactly one of the three shifts such that every dependency record satisfies these safety conditions, or to determine that no such allocation exists.

## Input
The first line provides two integers $n$ and $m$ — the total number of personnel and the number of dependency records ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$).
Each of the subsequent $m$ lines provides two integers $u$ and $v$, representing a pair of personnel whose assigned shifts must satisfy the compatibility rules above.

## Output
If there is no valid shift allocation, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $s_1, s_2, \dots, s_n$ (where each $s_i \in \{1, 2, 3\}$), with $s_i$ representing the shift assigned to person $i$. Any valid allocation is accepted.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```

<RATIONALE>
The previous version used a single arithmetic expression `(s_u^2 + s_v^2) % (s_u + s_v) > 0` which models easily simplified to the symmetric disequality `s_u != s_v`, allowing them to recognize the problem as standard graph 3-coloring and apply highly optimized solvers (like MRV/degree ordering). I replaced this with a set of three ordered, conditional rules (handling `<`, `>`, and `=`) that mathematically still evaluate to `s_u != s_v` for the domain {1,2,3}, but appear as asymmetric directed constraints. This forces the model to implement the custom rules literally, breaking the pattern match to undirected graph coloring and causing optimized solvers to be bypassed in favor of naive backtracking, which will TLE.
</RATIONALE>
<PRESERVED_ANSWER>
The three conditional rules are constructed such that they are always satisfied when s_u ≠ s_v (since max gap is 2 < 3, and min sum is 3 > 2) and always fail when s_u = s_v (since max product is 9, which is not > 10), making them logically identical to the original symmetric condition.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to finding a valid 3-coloring for a given graph, which is NP-complete.
</PRESERVED_CLASS>
