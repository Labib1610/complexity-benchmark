<METHOD_NAME>XOR-Addition Partial Order Disguise</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the divisibility rule with the algebraic condition `(c_u XOR c_v) + c_u = c_v`. For values in {1, 2, 3}, this condition creates a 2-cycle if the values are equal, and forms a strictly bipartite DAG (edges only from 1 and 2 to 3) if they are distinct. This perfectly preserves the exact set of valid assignments (proper 3-colorings) without using divisibility or hinting at coloring. Models that fail to recognize the equivalence will fall back to naive cycle-checking backtracking instead of optimized DSATUR, leading to a Time Limit Exceeded on N=40.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem A — Harmonic Resonance

Time limit: 2 s
Memory limit: 256 MB

You are configuring a network of $n$ signal emitters. Each emitter must be assigned a base frequency multiplier, which must be exactly 1, 2, or 3.

The network is tested under $m$ interference conditions. Each condition involves a specific pair of emitters. When a pair of emitters $u$ and $v$ interact, they may form directed transmission channels based on their assigned multipliers. 

Specifically, for each interacting pair $u$ and $v$:
- A directed channel forms from $u$ to $v$ if $(c_u \oplus c_v) + c_u = c_v$.
- A directed channel forms from $v$ to $u$ if $(c_u \oplus c_v) + c_v = c_u$.
Here, $\oplus$ denotes the bitwise XOR operation. (If both conditions are met, channels form in both directions simultaneously).

To avoid destructive structural feedback, the resulting network of transmission channels must never form any directed cycles (a path of one or more channels that starts and ends at the same emitter, following the direction of the channels).

Your task is to determine whether it is possible to assign a frequency multiplier $c_i \in \{1, 2, 3\}$ to every emitter $i$ (from $1$ to $n$) such that the network contains no directed cycles among the $m$ specified interacting pairs. If it is possible, provide a valid assignment.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$) — the number of emitters and the number of interacting pairs.
Each of the following $m$ lines contains two integers $u$ and $v$ ($1 \le u, v \le n$, $u \neq v$), representing that emitter $u$ and emitter $v$ interact. It is guaranteed that each unordered pair $\{u, v\}$ appears at most once in the input.

## Output
If there is no valid assignment, output `NO` on a single line.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $c_1, c_2, \dots, c_n$, where each $c_i \in \{1, 2, 3\}$ is the frequency multiplier assigned to emitter $i$. If multiple valid assignments exist, you may output any of them.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
</STATEMENT>
<RATIONALE>
The problem was previously solved by models recognizing that the divisibility rule on {1, 2, 3} creates an acyclic orientation for distinct values and a 2-cycle for equal values, immediately mapping it to 3-coloring and applying optimized coloring algorithms like DSATUR. I replaced the divisibility rule with the condition `(c_u XOR c_v) + c_u = c_v`. This evaluates to exactly the same logical outcomes (equal values create 2-cycles, distinct values create a depth-1 DAG with edges pointing only to 3) but obfuscates the relationship behind a cryptographic-looking bitwise operation. Models must now either mathematically prove this equivalence or fall back to naive cycle-checking search, which will TLE on N=40. I also restored the exact numeric bounds to the Input section to satisfy the strict I/O contract check.
</RATIONALE>
<PRESERVED_ANSWER>
The XOR-addition condition creates a 2-cycle if and only if adjacent emitters map to the same value, and forms a strictly bipartite DAG (with max path length 1) when all interacting pairs are assigned distinct values, meaning the set of cycle-free assignments remains exactly the set of proper 3-colorings.
</PRESERVED_ANSWER>
