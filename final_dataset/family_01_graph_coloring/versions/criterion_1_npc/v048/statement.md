# Communication Band Configuration

Time limit: 2 s
Memory limit: 256 MB

The automated coordination system of a large facility runs a daily three-phase workflow to manage its $n$ field agents (numbered 1 through $n$). 

In the initial data-gathering phase, proximity sensors track the agents and output a log of $m$ agent pairs who operate close enough to risk electronic interference. 

Your software module is responsible for the intermediate configuration phase. You must assign each agent exactly one of three available communication bands, designated by the integers 1, 2, and 3. To ensure clear transmissions, the assignment rules dictate that no two agents identified as a proximity pair in the initial phase can be assigned the same communication band. 

Once your module completes its assignment, the final phase of the workflow automatically broadcasts the configuration to the agents' devices. If your module determines that no valid assignment of the three bands can satisfy the interference constraints, it must signal a failure so the entire process can be aborted.

## Input
The first line contains two integers $n$ and $m$ — the number of agents and the number of proximity pairs generated by the first phase ($1 \le n \le 40$, $0 \le m \le n(n-1)/2$).
Each of the subsequent $m$ lines contains two integers $u$ and $v$ — a pair of agents who operate in close proximity.

## Output
If the configuration phase cannot be completed successfully, output a single line containing `NO`.
Otherwise, output `YES` on the first line. On the second line, output $n$ integers $b_1, b_2, \dots, b_n$ (where each $b_i \in \{1, 2, 3\}$), representing the communication band assigned to agent $i$. If multiple valid band configurations exist, any of them will be accepted by the broadcast phase.

## Example 1
Input:
```
4 5
1 2
1 3
2 3
1 4
2 4
```
Output:
```
YES
1 2 3 3
```

## Example 2
Input:
```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```
Output:
```
NO
```
