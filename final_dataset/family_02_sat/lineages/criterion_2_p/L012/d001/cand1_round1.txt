# Problem B — Paired Window Constraints

Time limit: 1 s   Memory limit: 256 MB

## Description

The system configuration pipeline operates in three stages. First, a parser transforms complex user requirements into a standardized intermediate format concerning $n$ binary switches, each to be set ON or OFF before the run. This format consists of $m$ acceptance rules. Every rule names exactly two switch-conditions. A rule passes when at least one of its two conditions is met. A condition consists of a switch identifier and the required polarity (either positive for ON, or negative for OFF) that satisfies it.

In the second stage—which your program must implement—you evaluate this intermediate format. Your task is to determine whether a single global ON/OFF setting of all $n$ switches exists that satisfies every rule simultaneously. If a valid configuration exists, report one. Otherwise, report that the rules are mutually contradictory.

Finally, in the third stage, a downstream controller will read your output and physically actuate the switches.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 10^5$, $0 \le m \le 2 \cdot 10^5$).
Each of the next $m$ lines contains two non-zero signed integers $l_1$ and $l_2$, with $|l_i| \le n$. These represent the two conditions for a rule. A positive integer $x$ means switch $x$ must be ON, and a negative integer $-x$ means switch $x$ must be OFF. For the rule to pass, at least one of the two stated conditions must hold.

## Output
If no valid assignment exists, print a single line `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ (each in $\{0, 1\}$) forming any valid assignment, where $1$ denotes ON and $0$ denotes OFF.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid assignments may exist; any one is accepted. The same condition may appear in multiple rules.
