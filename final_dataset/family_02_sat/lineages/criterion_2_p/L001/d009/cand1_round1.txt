<METHOD_NAME>Bitwise Parity-and-Mask Obfuscation</METHOD_NAME>
<METHOD_DESCRIPTION>Replaces the sequential arithmetic evaluation with a two-stage bitwise XOR and AND masking sequence. This defeats models that rely on simple inequality thresholds to recognize boolean logic, forcing them to symbolically evaluate the bitwise operations across all cases to realize it encodes a 2-SAT clause.</METHOD_DESCRIPTION>

<STATEMENT>
# Problem B — Logistics Safeguards

Time limit: 1 s   Memory limit: 256 MB

## Description

Management of a logistics network must finalize the operational schedule for its $n$ transit hubs. Every hub $i$ must be assigned a phase state $s_i \in \{0, 1\}$.

Safety inspectors have completed $m$ vulnerability assessments. Each assessment provides two non-zero integer parameters $l_1$ and $l_2$. 

For each assessment, a two-stage parity-and-mask sequence is executed.
In the first stage, each parameter $v \in \{l_1, l_2\}$ generates a diagnostic byte $K_v$. The generation uses a base mask $M_v$:
- $M_v = 165$ if $v > 0$
- $M_v = 90$ if $v < 0$

It also uses a phase byte $P_v$, determined by the designated hub $|v|$'s phase state $s_{|v|}$:
- $P_v = 255$ if $s_{|v|} = 1$
- $P_v = 0$ if $s_{|v|} = 0$

The diagnostic byte is computed as the bitwise XOR (denoted $\oplus$) of the base mask and the phase byte: $K_v = M_v \oplus P_v$.

In the second stage, the two diagnostic bytes $K_{l_1}$ and $K_{l_2}$ are combined and masked against the critical threshold $165$. The final parity check value $C$ is computed using bitwise AND operations (denoted $\&$):
$C = K_{l_1} \ \& \ K_{l_2} \ \& \ 165$

An assessment is considered *stable* if its final parity check value $C$ is exactly $0$. A critical failure occurs if there is at least one assessment that is not stable (i.e., $C > 0$). 

Your task is to determine whether it is possible to assign a phase state $s_i \in \{0, 1\}$ to every hub such that zero critical failures occur (i.e., all $m$ assessments are stable). If such a schedule can be formed, you must provide one.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 10^5$, $0 \le m \le 2 \cdot 10^5$). For clarity, $n$ is up to 100000 and $m$ is up to 200000.

Each of the following $m$ lines provides two non-zero integers $l_1$ and $l_2$ ($1 \le |l_i| \le n$), representing the two parameters of a vulnerability assessment. 

Note that $l_1$ and $l_2$ in an assessment may refer to the same hub, with the same or opposite signs. A hub may appear in any number of assessments, and identical assessments may repeat.

## Output
If no safe schedule is possible, print a single line NO.

Otherwise, print YES on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ (each being 0 or 1, representing the phase state $s_i$ for hub $i$) that form a valid schedule. Multiple valid schedules may exist; any one is accepted.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

<RATIONALE>
The previous version used a sequential arithmetic update (`2Z + 1` evaluated against a threshold of `3`) which models easily mapped to the four states of a boolean truth table. I removed this numerical recurrence affordance entirely, replacing it with a bitwise XOR and AND masking system using the constants 165 (`10100101`) and 90 (`01011010`). This forces the model to symbolically execute the bitwise operations across all branches rather than relying on a simple arithmetic inequality shortcut.
</RATIONALE>
<PRESERVED_ANSWER>
The bitwise logic functions identically to the original boolean triggers: $K_v = 165$ precisely when the corresponding literal is falsified, and the final AND operation results in $C=165 > 0$ if and only if both literals are falsified, preserving the exact same stability constraints.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to 2-SAT, as each assessment still enforces that at least one of two boolean literals must be true, which can be solved in linear time using strongly connected components on an implication graph.
</PRESERVED_CLASS>
