**Solution Explanation**

For every microservice `i` we have a Boolean variable  

* `x_i = 1` – the service is *upgraded*  
* `x_i = 0` – the service stays *legacy*

Each policy contains two literals `l1 , l2`.  
A literal is

* `+i`  →  `x_i` must be true
* `-i`  →  `x_i` must be false (`¬x_i`)

The policy is satisfied iff at least one of its literals is true, i.e.

```
(l1) OR (l2)
```

Thus the whole problem is exactly the classic **2‑SAT** problem.
We have to decide whether a conjunction of such 2‑clauses is satisfiable and,
if it is, output one satisfying assignment.



--------------------------------------------------------------------

#### 1.   Implication graph

For a clause `(a ∨ b)` we add the two implications  

```
¬a → b
¬b → a
```

If we can reach `b` from `¬a` and also `¬b` from `a`, then setting `a = false`
forces `b = true`, etc.

We build a directed graph with `2·n` vertices – one for each literal:

```
vertex 2·(i-1)     :  x_i   (true)
vertex 2·(i-1) + 1 : ¬x_i   (false)
```

`neg(v) = v ^ 1` flips the last bit, i.e. gives the opposite literal.

For every input clause we translate the two integers to vertices
and insert the two edges described above.

The graph size:  

* vertices ≤ 2·10⁵  
* edges    ≤ 2·m ≤ 4·10⁵ – easily fits into memory.



--------------------------------------------------------------------

#### 2.   Strongly Connected Components (SCC)

A well‑known property of 2‑SAT:

*The formula is unsatisfiable **iff** for some variable `i`
  the vertices of `x_i` and `¬x_i` belong to the same SCC.*

Why? Inside one SCC every vertex reaches every other, therefore
`x_i → ¬x_i` and `¬x_i → x_i`, forcing both truth values simultaneously –
impossible.

We compute SCCs with Kosaraju’s algorithm (two DFS passes).  
Both passes are written iteratively to avoid recursion limits.



--------------------------------------------------------------------

#### 3.   Constructing an assignment

Kosaraju processes SCCs in reverse topological order.
If component `C1` is discovered **after** component `C2` in the second pass,
then there is **no** path from `C1` to `C2`.

Hence we can assign

```
x_i = 1   if   comp[ true(i) ]  >  comp[ false(i) ]
x_i = 0   otherwise
```

(the larger component number means it appears earlier in the topological order).

The obtained assignment satisfies all clauses.



--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints `YES` and a correct configuration
iff such a configuration exists.

---

##### Lemma 1  
For every clause `(a ∨ b)` the added edges `¬a → b` and `¬b → a`
are logically equivalent to the clause.

**Proof.**  
If `a` is true, the clause is satisfied regardless of `b`.  
If `a` is false (`¬a` true) the edge forces `b` to be true, otherwise the
implication would be violated. Symmetrically for `b`. ∎



##### Lemma 2  
If a variable `x_i` and its negation belong to the same SCC,
the formula is unsatisfiable.

**Proof.**  
Inside an SCC each vertex reaches every other, therefore
`x_i → ¬x_i` and `¬x_i → x_i`. Any assignment would have to make both
`x_i` and `¬x_i` true, impossible. ∎



##### Lemma 3  
If for every `i` the two literals are in different SCCs,
the assignment defined by  
`x_i = 1` iff `comp[x_i] > comp[¬x_i]` satisfies all clauses.

**Proof.**  
Consider any edge `u → v` of the implication graph.
If `comp[u] > comp[v]` then `u` is assigned **false** (because its component
appears later) and the implication is vacuously true.
If `comp[u] < comp[v]` then `u` is true, therefore `v` must also be true.
But `comp[u] < comp[v]` means there is no path from `v` back to `u`,
so `v` cannot be forced false elsewhere. Hence the implication holds.
Since every clause is equivalent to its two implications (Lemma&nbsp;1),
all clauses are satisfied. ∎



##### Lemma 4  
If the algorithm outputs `YES` and an assignment, that assignment is valid.

**Proof.**  
`YES` is printed only when for every variable the two literals lie in different
SCCs (otherwise `NO`). By Lemma&nbsp;3 the constructed assignment satisfies all
implications, therefore all original clauses. ∎



##### Lemma 5  
If a satisfying assignment exists, the algorithm never prints `NO`.

**Proof.**  
Assume a satisfying assignment exists.
If some variable had its two literals in the same SCC, Lemma&nbsp;2 would make
the formula unsatisfiable – contradiction. Hence all literals are in distinct
SCCs, the algorithm will not trigger the `NO` case and will output `YES`. ∎



##### Theorem  
The program prints `NO` **iff** the given set of policies is unsatisfiable;
otherwise it prints `YES` followed by a configuration that satisfies all
policies.

**Proof.**  
*If* part: when the program prints `NO`, some variable’s literals share an SCC.
By Lemma&nbsp;2 the formula is unsatisfiable.

*Only‑if* part: when the formula is satisfiable, Lemma&nbsp;5 guarantees the
program does not print `NO`. It prints `YES` and, by Lemma&nbsp;4, the
produced assignment is valid. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Building the graph* : `O(n + m)` vertices, `O(m)` edges.  
*Kosaraju* : two DFS traversals → `O(V + E) = O(n + m)`.  
*Assignment* : `O(n)`.

Memory consumption: adjacency lists for forward and reverse graph,
each storing `2·m` integers → `O(n + m)` ≤ about 5 · 10⁵ integers
(~4 MB).

Both limits satisfy the problem constraints.



--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    N = 2 * n                     # number of vertices
    g = [[] for _ in range(N)]    # forward graph
    rg = [[] for _ in range(N)]   # reverse graph

    def lit_to_idx(x: int) -> int:
        """positive -> true vertex, negative -> false vertex"""
        if x > 0:
            v = x - 1
            return 2 * v          # true
        else:
            v = -x - 1
            return 2 * v + 1      # false

    for _ in range(m):
        a = int(next(it))
        b = int(next(it))
        A = lit_to_idx(a)
        B = lit_to_idx(b)
        NA = A ^ 1
        NB = B ^ 1
        # ¬A -> B
        g[NA].append(B)
        rg[B].append(NA)
        # ¬B -> A
        g[NB].append(A)
        rg[A].append(NB)

    sys.setrecursionlimit(1 << 25)

    # first pass: order by finish time
    visited = [False] * N
    order = []

    for v in range(N):
        if not visited[v]:
            stack = [(v, 0)]
            while stack:
                node, state = stack.pop()
                if state == 0:
                    if visited[node]:
                        continue
                    visited[node] = True
                    stack.append((node, 1))
                    for to in g[node]:
                        if not visited[to]:
                            stack.append((to, 0))
                else:
                    order.append(node)

    # second pass: assign components
    comp = [-1] * N
    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            stack = [v]
            comp[v] = cid
            while stack:
                node = stack.pop()
                for to in rg[node]:
                    if comp[to] == -1:
                        comp[to] = cid
                        stack.append(to)
            cid += 1

    # check for contradictions
    assignment = [0] * n
    for i in range(n):
        t = 2 * i
        f = t ^ 1
        if comp[t] == comp[f]:
            print("NO")
            return
        assignment[i] = 1 if comp[t] > comp[f] else 0

    # output
    out = ["YES", " ".join(map(str, assignment))]
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
