<STATEMENT>
# Phase 3: Deployment Planner

Time limit: 1 s   Memory limit: 256 MB

## Description
You are managing the deployment of $n$ microservices. Each microservice must be allocated to exactly one of two environments: the Primary Environment (represented by 1) or the Secondary Environment (represented by 0).

The architecture includes $m$ fallback rules to ensure reliability. Each rule defines two target deployment states. A target state is represented by a non-zero integer $v$. The absolute value $|v|$ identifies the microservice. A positive $v$ means the target is for microservice $|v|$ to be in the Primary Environment. A negative $v$ means the target is for microservice $|v|$ to be in the Secondary Environment.

These rules act as operational fallbacks. If the system's allocation fails to achieve the first target state of a rule, it is strictly obligated to achieve the second target state. Symmetrically, if it fails to achieve the second target state, it must achieve the first. A rule is satisfied if at least one of its two target states is achieved. Your task is to determine whether there exists a global allocation—assigning every microservice to either the Primary or Secondary environment—such that all fallback rules are satisfied.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 10^5$, $0 \le m \le 2 \cdot 10^5$), representing the number of microservices and the number of fallback rules.

Each of the following $m$ lines provides a rule as two non-zero integers $l_1$ and $l_2$ ($1 \le |l_i| \le n$). The absolute value $|l_i|$ identifies the microservice. A positive $l_i$ specifies the Primary Environment for microservice $|l_i|$; a negative $l_i$ specifies the Secondary Environment for microservice $|l_i|$.

## Output
If no valid global allocation exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ separated by spaces. Print $s_i = 1$ if microservice $i$ is allocated to the Primary Environment, and $s_i = 0$ if it is allocated to the Secondary Environment. Any valid allocation is accepted.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid allocations may exist; any one is accepted. The same microservice ID may appear in multiple rules, and even within the same rule (for example, a rule given as `3 3` simply means the system cannot fail to match this target, effectively mandating that specific state). If $m = 0$, any allocation is valid.
</STATEMENT>
<RATIONALE>
Replaced the explicit disjunctive logic ("fails to match both") with operational fallback rules that describe two-way implications (failing the first forces the second, and vice versa). This removes the direct translation to 2-CNF clauses that models rely on for recognizing 2-SAT, forcing them to derive the graph structure from the fallback semantics.
</RATIONALE>
<PRESERVED_ANSWER>
The operational fallback semantics (failing one target forces the other, and at least one must be achieved) are logically equivalent to the original disjunction, so the set of valid allocations remains identical.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem is still exactly 2-SAT, solvable in linear time using Kosaraju's or Tarjan's algorithm on the implication graph.
</PRESERVED_CLASS>

None.
