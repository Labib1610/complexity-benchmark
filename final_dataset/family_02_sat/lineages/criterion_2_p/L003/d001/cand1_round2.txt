<STATEMENT>
# Phase 3: Deployment Planner

Time limit: 1 s   Memory limit: 256 MB

## Description

The continuous integration pipeline for our cloud infrastructure operates in four distinct phases:
1. **Manifest Aggregation**: Developers submit compatibility requirements for their microservices.
2. **Policy Compilation**: The orchestrator breaks down all requirements into a flat list of failover routing rules covering the microservices. Each rule bridges exactly two potential endpoints. An endpoint is defined by a specific microservice being present in a specific target zone. Every microservice must be deployed in exactly one zone: either Zone 1 (primary) or Zone 0 (secondary). To maintain connectivity, the final deployment must satisfy every rule by matching at least one of the two endpoints specified in each rule.
3. **Deployment Planning (Your Task)**: You must process the compiled rules and determine if there exists a global deployment configuration that satisfies every rule simultaneously. If such a configuration exists, you must output it so the pipeline can proceed. Otherwise, you must halt the pipeline.
4. **Rollout Execution**: The system reads your configuration and physically deploys the specified versions.

Write the program for Phase 3. The input is guaranteed to be the output of Phase 2. 

## Input
The first line contains two integers $n$ and $m$. The cluster requires at least $1$ microservice and has a physical limit of $10^5$ microservices, establishing the range for $n$. The rule engine's memory buffer accommodates up to $2 \cdot 10^5$ rules, so $m$ may range from $0$ up to this maximum.

Each of the following $m$ lines provides a rule as two non-zero integers $l_1$ and $l_2$. Since these map to microservice IDs, their absolute values are at most $n$. If an integer is greater than $0$, the specified endpoint requires that microservice to be in Zone 1. If an integer is less than $0$, the specified endpoint requires that microservice to be in Zone 0. 

## Output
If no valid global deployment configuration exists, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ separated by spaces, each being $0$ or $1$. Print $s_i = 1$ if microservice $i$ is deployed in Zone 1, and $s_i = 0$ if it is deployed in Zone 0, forming any valid configuration.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid configurations may exist; any one is accepted. The two endpoints in a single rule may refer to the same microservice (as seen in Example 2). The same microservice ID may appear in multiple rules.
