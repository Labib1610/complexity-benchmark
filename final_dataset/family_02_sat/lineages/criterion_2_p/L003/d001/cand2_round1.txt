<STATEMENT>
# Drone Telemetry Network

Time limit: 1 s   Memory limit: 256 MB

## Description

You are configuring a network of $n$ surveillance drones. Each drone must be assigned to exactly one flight tier: Upper or Lower.

The network contains $m$ ground checkpoints. To maintain continuous data flow, every checkpoint must establish a connection with the aerial fleet. Due to terrain and signal constraints, each checkpoint has exactly two potential relays it can use. A relay is defined by a specific drone flying in a specific tier. A checkpoint successfully connects if the fleet configuration makes at least one of its two potential relays active.

You must determine if there is a fleet-wide tier assignment (each drone placed in exactly one tier) that allows every single checkpoint to connect simultaneously.

## Input
The first line contains two integers $n$ and $m$ ($1 \le n \le 10^5$, $0 \le m \le 2 \cdot 10^5$), representing the number of drones and the number of checkpoints.
Each of the following $m$ lines describes the two potential relays for a checkpoint as two non-zero integers $r_1$ and $r_2$ ($|r_i| \le n$).
The absolute value of each integer indicates the drone ID. A positive integer means the relay is active if that drone is in the Upper tier. A negative integer means the relay is active if that drone is in the Lower tier.

## Output
If no valid fleet configuration exists to connect all checkpoints, print a single line containing `NO`.
Otherwise, print `YES` on the first line. On the second line, print $n$ integers $s_1, s_2, \dots, s_n$ separated by spaces. Print $s_i = 1$ if drone $i$ is assigned to the Upper tier, and $s_i = 0$ if it is assigned to the Lower tier, forming any valid configuration.

## Example 1
Input:
```
2 2
1 2
-1 -2
```
Output:
```
YES
1 0
```

## Example 2
Input:
```
1 2
1 1
-1 -1
```
Output:
```
NO
```

## Note
Multiple valid configurations may exist; any one is accepted. The same drone ID may appear in the relay options for multiple checkpoints.
</STATEMENT>
<RATIONALE>
The problem was completely reframed from a software deployment scenario to a physical drone telemetry network. Terms heavily associated with satisfiability problems (policies, states, fulfilled, legacy) were replaced with domain-specific mechanics (drones, tiers, checkpoints, relays). This forces the model to independently recognise that "at least one of two potential relays" translates to a boolean disjunction, rather than relying on familiar software configuration tropes.
</RATIONALE>

The entities and their constraints map 1:1 (microservices to drones, upgraded/legacy to Upper/Lower, policies to checkpoints), so the identical set of boolean assignments remains valid for any given input.
</PRESERVED_ANSWER>
