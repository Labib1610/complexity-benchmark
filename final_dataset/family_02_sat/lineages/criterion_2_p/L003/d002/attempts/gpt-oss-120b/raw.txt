**Solution Explanation**

For every microservice `i` we have a Boolean variable  

```
xi = 1   … microservice i is placed in the Primary environment
xi = 0   … microservice i is placed in the Secondary environment
```

A protocol (clause) contains two *literals* `l1 , l2`.

* `l =  v (v>0)` means `xv` must be `1`
* `l = -v (v>0)` means `xv` must be `0`

The protocol is *breached* only when **both** literals are false.
Therefore a feasible deployment must satisfy the Boolean formula

```
(l1  OR  l2)  AND  (l3 OR l4)  AND …                (1)
```

Exactly the classic **2‑SAT** problem.

--------------------------------------------------------------------

#### 1.   Implication graph

For a literal `l` we denote by `¬l` its negation.
The clause `(a OR b)` is equivalent to the two implications

```
¬a  →  b
¬b  →  a
```

If we build a directed graph whose vertices are all literals
(`xi = 0` and `xi = 1` for every `i`) and insert the two edges for each
clause, any assignment that respects all implications satisfies (1).

Vertex coding (0‑based)

```
variable i (1 … n)
    false (xi = 0) : 2*(i-1)
    true  (xi = 1) : 2*(i-1) + 1
negation of a vertex v : v ^ 1          (flips the last bit)
```

--------------------------------------------------------------------

#### 2.   Strongly connected components

In the implication graph, if a literal and its negation belong to the
same strongly connected component (SCC) they imply each other, i.e.
both must be true – impossible.  
Hence the formula is **unsatisfiable** iff for some `i`

```
SCC( xi = 0 ) == SCC( xi = 1 )
```

Otherwise a satisfying assignment exists and can be obtained from the
topological order of the SCC‑condensation DAG:

*process SCCs in reverse topological order* (the order produced by the
second pass of Kosaraju).  
If the component of `xi = 1` appears **after** the component of `xi = 0`,
we set `xi = 1`; otherwise `xi = 0`.

--------------------------------------------------------------------

#### 3.   Algorithm
```
read n , m
create adjacency lists G (2*n vertices) and GR (reversed graph)

for each clause (l1 , l2):
        a = vertex(l1)          # as described above
        b = vertex(l2)
        add edge (a^1) → b   to G   and b → (a^1) to GR
        add edge (b^1) → a   to G   and a → (b^1) to GR

# Kosaraju
DFS1 on G, store vertices in order of finishing time
DFS2 on GR, processing vertices in reverse order, assign component id

for i = 1 … n:
        if comp[false(i)] == comp[true(i)]:  print "NO" and exit

print "YES"
for i = 1 … n:
        ans[i] = 1 if comp[true(i)] > comp[false(i)] else 0
print ans
```

Both DFS passes are linear, `O(n + m)`.  
Memory consumption is `O(n + m)`.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm prints **YES** and a correct assignment
iff such an assignment exists.

---

##### Lemma 1  
For every clause `(a OR b)` the two added edges
`¬a → b` and `¬b → a` are logically equivalent to the clause.

**Proof.**  
If `a` is true, the clause is satisfied regardless of `b`.  
If `a` is false (`¬a` true) the edge forces `b` to be true, otherwise the
implication would be violated. Symmetrically for `b`.  
Thus the only way to violate both implications is to make `a` and `b`
false simultaneously, i.e. to falsify the clause. ∎



##### Lemma 2  
If a literal `p` and its negation `¬p` belong to the same SCC,
the formula is unsatisfiable.

**Proof.**  
Inside an SCC there is a directed path `p → … → ¬p` and also
`¬p → … → p`. By following the edges we obtain the implications
`p ⇒ ¬p` and `¬p ⇒ p`. Hence any assignment must satisfy both
`p = true` and `p = false`, impossible. ∎



##### Lemma 3  
Assume no variable has its two literals in the same SCC.
Let `comp(v)` be the component number assigned by the second Kosaraju pass
(the order of processing is reverse topological).  
Define the assignment  

```
xi = 1  iff  comp(true(i)) > comp(false(i))
```

Then every implication edge `u → v` is satisfied.

**Proof.**  
In the condensation DAG edges go from a component to a *different*
component that appears **earlier** in the second pass (because we
process vertices in reverse finishing order). Therefore

```
edge u → v   ⇒   comp(u) > comp(v)
```

If `u` is true in the assignment, then `comp(u) > comp(v)` implies
`comp(v) < comp(u)`. By construction a variable is set to true only
when its true‑literal component is larger than its false‑literal component.
Consequently `comp(v) < comp(u)` forces `v` to be true as well (or at
least not false). Hence the implication holds. ∎



##### Lemma 4  
The assignment defined in Lemma&nbsp;3 satisfies every clause.

**Proof.**  
Take a clause `(a OR b)`. By Lemma&nbsp;1 it is equivalent to the two
implications `¬a → b` and `¬b → a`. Lemma&nbsp;3 guarantees that all
implications are satisfied, therefore at least one of `a , b` is true,
i.e. the clause holds. ∎



##### Lemma 5  
If the algorithm outputs **YES** and the assignment `ans`,
`ans` satisfies all clauses.

**Proof.**  
The algorithm outputs **YES** only when for every variable the two
literals lie in different SCCs, thus the preconditions of Lemma&nbsp;3
and Lemma&nbsp;4 are met. The printed assignment is exactly the one
constructed in Lemma&nbsp;3, therefore all clauses are satisfied. ∎



##### Lemma 6  
If the algorithm outputs **NO**, the formula is unsatisfiable.

**Proof.**  
The algorithm prints **NO** precisely when for some variable `i`
`comp(false(i)) == comp(true(i))`. By Lemma&nbsp;2 this makes the
formula unsatisfiable. ∎



##### Theorem  
The algorithm prints **YES** and a correct deployment plan
iff such a plan exists; otherwise it prints **NO**.

**Proof.**  

*If part*:  
Assume a feasible deployment exists. Then the corresponding Boolean
assignment satisfies all clauses, hence all implications, therefore no
literal can imply its own negation. Consequently no variable has its two
literals in the same SCC. The algorithm will not output **NO**.
By Lemma&nbsp;5 the assignment it prints is also feasible, so it outputs
**YES**.

*Only‑if part*:  
If the algorithm prints **YES**, Lemma&nbsp;5 guarantees the printed
assignment satisfies all clauses, i.e. a feasible deployment exists.

If the algorithm prints **NO**, Lemma&nbsp;6 shows the formula is
unsatisfiable, thus no feasible deployment exists.

Both directions hold, completing the proof. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Vertices* : `2·n`  
*Edges*    : `2·m` (two per clause)

```
Time   :  O( n + m )
Memory :  O( n + m )
```

Both respect the limits (`n ≤ 10⁵ , m ≤ 2·10⁵`).

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys
sys.setrecursionlimit(1 << 25)

def solve() -> None:
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    N = 2 * n                     # number of vertices
    g = [[] for _ in range(N)]   # forward graph
    rg = [[] for _ in range(N)]  # reversed graph

    def lit_to_idx(v: int) -> int:
        """map literal to vertex index"""
        var = abs(v) - 1
        if v > 0:                 # true literal
            return var * 2 + 1
        else:                     # false literal
            return var * 2

    for _ in range(m):
        l1 = int(next(it))
        l2 = int(next(it))
        a = lit_to_idx(l1)
        b = lit_to_idx(l2)
        na = a ^ 1                 # negation
        nb = b ^ 1
        # ¬a -> b
        g[na].append(b)
        rg[b].append(na)
        # ¬b -> a
        g[nb].append(a)
        rg[a].append(nb)

    # ---------- Kosaraju ----------
    visited = [False] * N
    order = []

    def dfs1(v: int):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for v in range(N):
        if not visited[v]:
            dfs1(v)

    comp = [-1] * N
    cur = 0

    def dfs2(v: int, label: int):
        comp[v] = label
        for to in rg[v]:
            if comp[to] == -1:
                dfs2(to, label)

    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cur)
            cur += 1

    # ---------- check satisfiability ----------
    for i in range(n):
        if comp[2 * i] == comp[2 * i + 1]:
            print("NO")
            return

    # ---------- build assignment ----------
    ans = [0] * n
    for i in range(n):
        # true component larger => true
        ans[i] = 1 if comp[2 * i + 1] > comp[2 * i] else 0

    print("YES")
    print(' '.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input‑output format.
