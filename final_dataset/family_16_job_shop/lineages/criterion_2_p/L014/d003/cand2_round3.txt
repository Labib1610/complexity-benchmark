# Problem B — Two-Stage Resolution

Time limit: 1 s
Memory limit: 256 MB

## Description

A digital pipeline must resolve a collection of **j** tasks. Each task requires a primary operation lasting **p1** microseconds, followed by a secondary operation lasting **p2** microseconds. You must choose a permutation of the **j** tasks to form a single initial sequence. Each task must appear exactly once in this sequence.

The pipeline operates with two independent execution units, Node 1 and Node 2, following these rules:
- Whenever Node 1 is unoccupied and the initial sequence is not empty, Node 1 immediately removes the task at the front of the sequence. It spends **p1** microseconds executing the primary operation for this task, after which the task is placed into a transit queue.
- Whenever Node 2 is unoccupied and there is at least one task in the transit queue, Node 2 immediately takes the task that has been in the transit queue for the longest time. It spends **p2** microseconds executing the secondary operation for this task, after which the task is fully resolved.
- Once either Node 1 or Node 2 begins working on a task, it works continuously until that specific operation is finished.

Your objective is to determine the optimal arrangement of the initial sequence that minimizes the exact microsecond at which the final task is fully resolved by Node 2. Report this minimum possible resolution time.

## Input

The first line contains a single integer **j**. The value of **j** is at least 1 and at most the number of meters in 200 kilometers.
Each of the next **j** lines contains two integers **p1** and **p2**: the primary operation duration and the secondary operation duration of a task. These durations are at least 1 and at most the number of grams in exactly one metric tonne (1000 kilograms).

## Output

Print a single integer: the smallest possible time at which all tasks are fully resolved.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one task. Node 1 takes it at time 0 and finishes the primary operation at time 5, placing it in the transit queue. Node 2 immediately takes it and finishes the secondary operation at time 5 + 3 = 8.

<RATIONALE>
The explicit flow-shop terminology (mixer/froster, baking) was replaced with a neutral digital pipeline featuring two execution nodes. This removes the semantic triggers that let LLMs instantly recognize the classic two-machine scheduling problem, forcing them to derive the optimal sequence rules from the event-based mechanics. Additionally, numeric bounds were rewritten using physical conversions (S07), requiring the model to deduce the exact limits dynamically rather than pattern-matching bare inequalities.
</RATIONALE>
