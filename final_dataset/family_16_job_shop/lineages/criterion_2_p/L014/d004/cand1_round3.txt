<STATEMENT>
# Problem B — Two-Segment Routing

Time limit: 1 s
Memory limit: 256 MB

## Description

A network routing grid must be constructed using **j** vertical columns. Each column consists of exactly two cells: an upper cell and a lower cell. Each column has a required traversal time of **p1** microseconds for its upper cell, and **p2** microseconds for its lower cell.

You must choose a single sequence in which to arrange all **j** columns from left to right.
Once arranged, a signal travels from the top-left cell to the bottom-right cell. A valid path only moves right (to the next column in the same row) or down (from the upper cell to the lower cell of the same column).
Specifically, a path travels through the upper cells from the first column up to some column $k$, moves down to the lower cell of column $k$, and then travels through the lower cells from column $k$ to the last column.

These rules are equivalently captured by the following definitions. Let the chosen permutation of columns be $S = (S_1, S_2, \dots, S_j)$.
For the $i$-th column in the sequence, let $A_i$ be its upper cell time, and $B_i$ be its lower cell time (corresponding to its **p1** and **p2** values).

For any column $k$ ($1 \le k \le j$), the traversal time of the path that moves down at column $k$ is:
$$ P(k) = \sum_{i=1}^k A_i + \sum_{i=k}^j B_i $$

The overall grid completion time for the sequence $S$ is the maximum path time among all possible downward moves:
$$ \max_{1 \le k \le j} P(k) $$

Your objective is to determine the optimal permutation $S$ that minimizes this grid completion time. Report this minimum possible time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the upper cell time and the lower cell time of a column.

## Output

Print a single integer: the smallest possible grid completion time.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one column. The path must move through its upper cell and then its lower cell, taking 5 + 3 = 8 microseconds.
</STATEMENT>
<RATIONALE>
The problem was reframed from a two-machine flow-shop schedule to finding a column permutation that minimizes the maximum path sum in a 2xN grid. This is mathematically identical (the makespan of a 2-machine flow-shop equals the longest path in its 2xN dependency grid), but completely removes the "machine processing" vocabulary that triggers LLMs to instantly apply Johnson's rule. Models must now either independently derive Johnson's rule for the grid path formulation or fail.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum path sum in a 2xN grid is an exact mathematical identity to the makespan of a 2-machine flow-shop with the same weights, so identically optimal permutations will produce identical minimal costs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the 2-machine flow-shop scheduling problem (solvable in O(N log N) via Johnson's rule), just described geometrically.
</PRESERVED_CLASS>
<RISK>
None. The formula explicitly defines the path sum and the maximization objective, leaving no ambiguity about how the score of a permutation is calculated.
</RISK>
