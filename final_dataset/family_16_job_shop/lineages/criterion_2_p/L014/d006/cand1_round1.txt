<STATEMENT>
# Problem B — Drone Track Routing

Time limit: 1 s
Memory limit: 256 MB

## Description

You are designing flight itineraries for two automated drones, the Scout and the Hauler. There are **j** distinct checkpoints. Each drone must visit all **j** checkpoints exactly once. Crucially, the Scout and the Hauler may follow completely independent itineraries—they are not required to visit the checkpoints in the same sequence.

The Scout drone begins its itinerary at time 0. It visits its checkpoints one after another. At each checkpoint, the Scout performs an inspection. For a checkpoint given in the input with parameters **p1** and **p2**, the Scout's inspection takes exactly **p1** microseconds. Travel time between checkpoints is instantaneous (0 microseconds), so the Scout continuously moves to its next checkpoint and begins its inspection as soon as the current one finishes.

The Hauler drone also begins at time 0 and visits the checkpoints in the exact order of its own chosen itinerary. At each checkpoint, the Hauler performs an extraction taking exactly **p2** microseconds. The Hauler's operation is strictly constrained:
- It can only begin its extraction at a checkpoint after the Scout has completely finished its inspection at that exact same checkpoint.
- It processes its itinerary strictly one checkpoint at a time: it cannot begin extraction at the next checkpoint in its itinerary until it has fully completed extraction at the current one.
- If the Hauler is ready to extract at a checkpoint but the Scout has not yet finished inspecting it, the Hauler must wait.
- Travel time for the Hauler is also instantaneous.

Your objective is to determine an itinerary for the Scout and an itinerary for the Hauler that minimize the time at which the Hauler completely finishes its extraction at the final checkpoint in its itinerary. Report this minimum possible completion time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000) representing a checkpoint. **p1** is the time required for the Scout's inspection, and **p2** is the time required for the Hauler's extraction.

## Output

Print a single integer: the minimum possible time at which the Hauler finishes its final extraction.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one checkpoint. The Scout drone begins at time 0 and finishes its inspection at time 5. The Hauler drone's itinerary also consists of this single checkpoint. It must wait until time 5 to begin, and finishes its extraction at time 5 + 3 = 8.
</STATEMENT>
<RATIONALE>
Changed the problem to explicitly allow the two drones to follow independent sequences. This forces the model to realize (or fail to realize) that for a two-machine flow shop, the optimal permutation schedule is always as good as any schedule with different sequences. Models relying on text pattern matching for "permutation flow shop" will be thrown off and attempt to optimize two separate sequences, typically leading to incorrect heuristics or TLE.
</RATIONALE>
<PRESERVED_ANSWER>
Mathematical permutation dominance in F2||Cmax guarantees that the minimum completion time over all pairs of independent sequences is exactly equal to the minimum completion time when both sequences are restricted to be identical, so the optimal answer for any input is completely unchanged.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains solvable in O(j log j) using Johnson's rule, because the optimal answer is still found by computing the optimal permutation schedule.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "completely independent itineraries" as implying the Hauler does not need to wait for the Scout, but the bullet point "can only begin its extraction at a checkpoint after the Scout has completely finished its inspection at that exact same checkpoint" unambiguously preserves the dependency.
</RISK>
