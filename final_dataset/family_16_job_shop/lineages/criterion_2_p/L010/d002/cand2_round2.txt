<STATEMENT>
# Pipeline Optimization

Time limit: 1 s   Memory limit: 256 MB

## Description

You are configuring a two-stage data pipeline to process a batch of $j$ independent elements. You must arrange the $j$ elements into a single sequence (a permutation of the given elements). Both stages of the pipeline will process the elements in this exact chosen sequence.

Each element requires a primary processing duration, $p_1$, and a secondary processing duration, $p_2$. For the element placed at position $k$ in your sequence ($1 \le k \le j$), let $p_1(k)$ and $p_2(k)$ denote its respective durations.

You must assign a primary start time $S_k$ and a secondary start time $A_k$ for each position $k$. To be valid, the timeline must satisfy the following rules:
- The primary stage processes elements one after another, handling at most one element at a time: $S_{k+1} \ge S_k + p_1(k)$ for $1 \le k < j$.
- The secondary stage processes elements one after another, handling at most one element at a time: $A_{k+1} \ge A_k + p_2(k)$ for $1 \le k < j$.
- An element's secondary processing cannot begin until its own primary processing is fully complete: $A_k \ge S_k + p_1(k)$ for $1 \le k \le j$.

Set the start time of the first element on the primary stage to zero ($S_1 = 0$). Your goal is to find a sequence of the $j$ elements and a valid timeline that minimizes the finish time of the last element on the secondary stage, which is given by $A_j + p_2(j)$. Report this smallest possible final finish time.

## Input

The first line contains a single integer $j$ ($1 \le j \le 200000$).
Each of the next $j$ lines contains two integers $p_1$ and $p_2$ ($1 \le p_1, p_2 \le 1000000$): the primary processing duration and secondary processing duration of an element.

## Output

Print a single integer: the smallest possible finish time of the last element on the secondary stage.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one element with $p_1 = 5$ and $p_2 = 3$. We set $S_1 = 0$, so its primary processing completes at 5. We then set $A_1 = 5$, and its secondary processing completes at $5 + 3 = 8$.
</STATEMENT>
<RATIONALE>
The problem was rewritten to remove the explicit "Two-Stage Assembly" title and the "preparation/assembly" manufacturing narrative, replacing it with a generic data pipeline scenario. By presenting the precedence rules as both natural language constraints and explicit state-transition inequalities, the problem forces models to reason about the underlying mathematical structure of the scheduling task rather than relying on keyword matching for the canonical two-machine flow-shop problem.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical formulation (including sequence permutation, start times, and non-overlapping/precedence inequalities) is completely identical to the seed, so the optimal schedule and its final finish time remain exactly the same for all inputs.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem is mathematically isomorphic to the standard two-machine permutation flow-shop scheduling problem, which can be solved optimally in $O(n \log n)$ time using Johnson's rule.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the natural language phrase "processes elements one after another" as requiring strict equality without idle time, but the explicit inequalities ($\ge$) immediately clarify that idle time is permitted.
</RISK>
