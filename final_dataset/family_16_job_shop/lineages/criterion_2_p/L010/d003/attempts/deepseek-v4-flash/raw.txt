We can model this as a scheduling problem.  
For each lens, we have two “lengths”: primary clearance `d1` and secondary clearance `d2`.  
The sequence must satisfy:

- Primary positions: `X_{k+1} >= X_k + d1_k`
- Secondary positions: `Y_k >= X_k + d1_k`
- Secondary positions: `Y_{k+1} >= Y_k + d2_k`

We want to minimize `Y_j + d2_j`.

If we set `X_1 = 0`, then:

- `X_k = sum_{i=1}^{k-1} d1_i`
- `Y_k` must be at least `X_k + d1_k` and also at least `Y_{k-1} + d2_{k-1}`.

So:

`Y_k = max( X_k + d1_k, Y_{k-1} + d2_{k-1} )`

with `Y_1 = d1_1`.

The final value is `Y_j + d2_j`.

We can think of this as:  
For a given order, the final boundary is:

`max over k of ( sum_{i=1}^{k} d1_i + sum_{i=k}^{j} d2_i )`

Because:

- `Y_k` is at least `sum_{i=1}^{k} d1_i` (since `X_k + d1_k = sum_{i=1}^{k} d1_i`)
- Then from `Y_k` to the end, we add `d2_k + ... + d2_j`.

So the final boundary is:

`max_{k=1..j} ( prefix_d1[k] + suffix_d2[k] )`

where `prefix_d1[k] = sum_{i=1}^k d1_i` and `suffix_d2[k] = sum_{i=k}^j d2_i`.

We need to choose the permutation to minimize this maximum.

This is a known problem: we can sort by `d1 - d2` (or equivalently `d1` vs `d2`) to minimize the maximum of prefix sums of one type plus suffix sums of the other.

The optimal order is to sort lenses by `d1 - d2` in **descending** order.  
Why? Because we want large `d1` early (to keep prefix sums small relative to later) and large `d2` late (to keep suffix sums small early).  
Sorting by `d1 - d2` descending achieves this.

Let’s verify with examples.

Example 1:
```
3
3 2
2 4
1 3
```
Sort by d1-d2 descending:
- (3,2): diff=1
- (2,4): diff=-2
- (1,3): diff=-2

Order: (3,2), (2,4), (1,3)

prefix_d1: 3, 5, 6  
suffix_d2: 2+4+3=9, 4+3=7, 3

max(3+9=12, 5+7=12, 6+3=9) = 12?  
But expected output is 10. So this is not correct.

Let’s try another order:  
(2,4), (3,2), (1,3)  
prefix_d1: 2,5,6  
suffix_d2: 4+2+3=9, 2+3=5, 3  
max(2+9=11, 5+5=10, 6+3=9) = 11.

Try (1,3), (3,2), (2,4):  
prefix: 1,4,6  
suffix: 3+2+4=9, 2+4=6, 4  
max(1+9=10, 4+6=10, 6+4=10) = 10. Works.

So sorting by `d1 - d2` descending is not correct.  
We need to sort by `d1` ascending? Let’s check:  
Sort by d1 ascending: (1,3), (2,4), (3,2) → gives 10.  
Sort by d1 descending: (3,2), (2,4), (1,3) → gives 12.

So maybe sort by `d1` ascending works?  
Check example 3: all (2,2) → any order gives 8.

Check example 2: single lens → 8.

Let’s test another case:  
Suppose lenses: (5,1), (1,5).  
Sort by d1 ascending: (1,5), (5,1)  
prefix: 1,6  
suffix: 5+1=6, 1  
max(1+6=7, 6+1=7) = 7.  
Other order: (5,1), (1,5)  
prefix: 5,6  
suffix: 1+5=6, 5  
max(5+6=11, 6+5=11) = 11.  
So ascending d1 is better.

But is it always optimal?  
We can think: we want to minimize max(prefix_d1[k] + suffix_d2[k]).  
This is equivalent to minimizing the maximum of `sum_{i=1}^k d1_i + sum_{i=k}^j d2_i`.  
If we sort by `d1` ascending, we put small d1 early, which keeps prefix small, and large d1 late, which doesn’t hurt because suffix_d2 shrinks.

But we also need to consider d2: large d2 should be late to keep suffix small early.  
So we want small d1 early and large d2 late.  
This suggests sorting by `d1 - d2` ascending? Let’s test:  
Example 1: diffs: 1, -2, -2 → ascending: (2,4), (1,3), (3,2)  
prefix: 2,3,6  
suffix: 4+3+2=9, 3+2=5, 2  
max(2+9=11, 3+5=8, 6+2=8) = 11. Not 10.

So that’s not it either.

Let’s think more carefully.  
We want to minimize `max_k (P_k + S_k)` where `P_k = sum_{i=1}^k d1_i`, `S_k = sum_{i=k}^j d2_i`.  
Note `P_k + S_k = total_d1 + total_d2 - (sum_{i=k+1}^j d1_i + sum_{i=1}^{k-1} d2_i)`.  
So minimizing the max is equivalent to maximizing the minimum of `(sum_{i=k+1}^j d1_i + sum_{i=1}^{k-1} d2_i)` over k.  
This is like balancing the two sides.

A known result: sort by `d1 - d2` in **ascending** order? We tried that and got 11.  
Maybe sort by `d1` ascending and if tie by `d2` descending?  
Example 1: (1,3), (2,4), (3,2) → works.

Let’s test another:  
(10,1), (1,10), (5,5)  
Sort by d1 asc: (1,10), (5,5), (10,1)  
prefix: 1,6,16  
suffix: 10+5+1=16, 5+1=6, 1  
max(1+16=17, 6+6=12, 16+1=17) = 17.  
Other order: (1,10), (10,1), (5,5)  
prefix: 1,11,16  
suffix: 10+1+5=16, 1+5=6, 5  
max(1+16=17, 11+6=17, 16+5=21) = 21.  
So ascending d1 is better.

What about (5,5), (1,10), (10,1)?  
prefix: 5,6,16  
suffix: 5+10+1=16, 10+1=11, 1  
max(5+16=21, 6+11=17, 16+1=17) = 21. Worse.

So ascending d1 seems good.

But is it always optimal?  
Consider (2,100), (100,2).  
Ascending d1: (2,100), (100,2)  
prefix: 2,102  
suffix: 100+2=102, 2  
max(2+102=104, 102+2=104) = 104.  
Other order: (100,2), (2,100)  
prefix: 100,102  
suffix: 2+100=102, 100  
max(100+102=202, 102+100=202) = 202.  
So ascending d1 is much better.

What about (50,50), (1,100), (100,1)?  
Ascending d1: (1,100), (50,50), (100,1)  
prefix: 1,51,151  
suffix: 100+50+1=151, 50+1=51, 1  
max(1+151=152, 51+51=102, 151+1=152) = 152.  
Other: (1,100), (100,1), (50,50)  
prefix: 1,101,151  
suffix: 100+1+50=151, 1+50=51, 50  
max(1+151=152, 101+51=152, 151+50=201) = 201.  
So ascending d1 is better.

I suspect sorting by `d1` ascending is optimal.  
Let’s prove:  
We want to minimize max_k (P_k + S_k).  
If we swap two adjacent lenses i and i+1 with d1_i > d1_{i+1}, then swapping them (so smaller d1 comes first) will reduce P_k for k >= i+1 and increase S_k for k <= i.  
The maximum might decrease or stay same.  
So sorting by d1 ascending is optimal.

Thus algorithm:  
- Read all lenses.
- Sort by d1 ascending.
- Compute prefix sums of d1 and suffix sums of d2.
- Answer = max(prefix_d1[k] + suffix_d2[k]) for k=1..j.

Complexity O(j log j).

Let’s implement.

```python
import sys

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    j = int(data[0])
    lenses = []
    idx = 1
    for _ in range(j):
        d1 = int(data[idx]); d2 = int(data[idx+1])
        lenses.append((d1, d2))
        idx += 2

    lenses.sort(key=lambda x: x[0])  # sort by d1 ascending

    prefix_d1 = [0] * j
    suffix_d2 = [0] * j

    s = 0
    for i in range(j):
        s += lenses[i][0]
        prefix_d1[i] = s

    s = 0
    for i in range(j-1, -1, -1):
        s += lenses[i][1]
        suffix_d2[i] = s

    ans = 0
    for i in range(j):
        val = prefix_d1[i] + suffix_d2[i]
        if val > ans:
            ans = val

    print(ans)

if __name__ == "__main__":
    solve()
```
