We can solve this by sorting the components with a custom comparator.  
The key is to compare two components `(a1, a2)` and `(b1, b2)` to decide which should come first to minimize the final `Y`.

If we place `A` before `B`, the final `Y` after both is:

```
max(max(X + a1, Y) + a2 + b1, Y + a2) + b2
```

But a simpler known greedy rule for this type of problem is:

Sort by `min(p1, p2)` in a specific way:  
- If `p1 < p2`, sort by `p1` ascending.  
- Else sort by `p2` descending.

This is a known optimal ordering for minimizing the makespan in two-machine flow shop with this recurrence.

Here’s the implementation:

```python
import sys

def solve():
    input = sys.stdin.readline
    j = int(input())
    comps = []
    for _ in range(j):
        p1, p2 = map(int, input().split())
        comps.append((p1, p2))
    
    # Sort using the Johnson's rule variant
    comps.sort(key=lambda x: (x[0] < x[1], x[0] if x[0] < x[1] else -x[1]))
    
    X = 0
    Y = 0
    for p1, p2 in comps:
        X += p1
        Y = max(X, Y) + p2
    print(Y)

if __name__ == "__main__":
    solve()
```
