<STATEMENT>
# Subsystem Queue

Time limit: 1 s   Memory limit: 256 MB

## Description

An operating system must execute a batch of **j** processes. You must arrange these processes into a single queue.

Two independent subsystems, the Fetcher and the Executor, both sequentially handle every process in this exact queue from the first to the last.
- The Fetcher handles processes one by one, moving to the next immediately after finishing the current one.
- The Executor also handles processes one by one in the exact same sequence. It begins handling a process as soon as it has finished its own work on the previous process AND the Fetcher has finished its work on the current process. If the Fetcher is still working on the current process, the Executor sits idle until the Fetcher finishes it.

For each process, you are given the time it takes the Fetcher to handle it, and the time it takes the Executor to handle it.

By choosing the optimal arrangement of processes in the queue, what is the earliest possible time the Executor can finish handling the final process?

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the duration of the process for the Fetcher and the Executor, respectively.

## Output

Print a single integer: the earliest possible time the Executor completes the final process in the queue.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, the single process takes 5 for the Fetcher, then 3 for the Executor, finishing at time 8.

The original statement explicitly framed the problem as scheduling "two phases" in the "same chosen order", which perfectly matches the textbook description of the two-machine flow-shop problem and trivially triggers Johnson's rule. By reframing the problem around a single queue traversed by two separate pointers (Fetcher and Executor) with a lag constraint, the explicit "Phase A/Phase B" scheduling terminology is removed. Models must now deduce the flow-shop sequence from the traversal mechanics.
