# Canal Routing

Time limit: 1 s   Memory limit: 256 MB

## Description

A fleet of **j** cargo ships needs to pass through a major canal. The canal features exactly two sequential bottlenecks: Lock Alpha and Lock Beta.

You must arrange the **j** ships into a single initial sequence. The fleet will then pass through the canal following these mechanics:

- Lock Alpha accommodates only one ship at a time. It takes a given ship its specified Alpha duration to clear Lock Alpha. As soon as a ship clears Lock Alpha, the next ship in the sequence immediately enters it.
- Upon clearing Lock Alpha, a ship immediately enters the intermediate basin and approaches Lock Beta.
- The intermediate basin is spacious enough to hold any number of waiting ships, but ships cannot maneuver to overtake one another. Consequently, ships arrive at and queue for Lock Beta in the exact same order they cleared Lock Alpha.
- Lock Beta accommodates only one ship at a time. It takes a given ship its specified Beta duration to clear Lock Beta. If Lock Beta is occupied, arriving ships wait in the basin until it is their turn.

Determine the initial sequence of ships that minimizes the total time required for the entire fleet to completely clear the canal (i.e., the moment the final ship finishes clearing Lock Beta). Output this minimum possible time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **a** and **b** (1 ≤ a, b ≤ 1000000): the Alpha duration and Beta duration for a ship.

## Output

Print a single integer: the smallest possible time at which all ships have cleared Lock Beta.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, the single ship takes 5 time units to clear Lock Alpha, then immediately takes 3 time units to clear Lock Beta, finishing at time 8.

<RATIONALE>
Removed explicit mentions of "two stages" and "same chosen order", replacing them with a physical canal scenario where non-overtaking mechanics enforce a strict FIFO queue between two bottlenecks. This forces the model to independently deduce that the two locks act as a standard two-machine flow-shop before applying Johnson's rule.
</RATIONALE>
<PRESERVED_ANSWER>
The mathematical model of the canal mechanics is strictly identical to the original two-stage pipeline, so the minimal completion time for any input remains exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem is still equivalent to the 2-machine flow-shop scheduling makespan problem, which is optimally solved in O(j log j) time using Johnson's algorithm.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret "spacious enough to hold any number of waiting ships" as allowing ships to be processed simultaneously in the basin, but the text explicitly states the time is spent waiting for Lock Beta, which only accommodates one ship at a time.
</RISK>
