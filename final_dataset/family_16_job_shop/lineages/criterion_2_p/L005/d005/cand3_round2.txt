<STATEMENT>
# Problem B — Grid Path Arrangement

Time limit: 1 s   Memory limit: 256 MB

## Description

You are given a set of **j** rectangular tiles. Each tile is divided into a top half and a bottom half, and each half contains an integer value. For each tile, you are given its top value, **t1**, and its bottom value, **t2**.

You must arrange all **j** tiles in a single horizontal row from left to right. This arrangement forms a grid with 2 rows and **j** columns. The top halves of the tiles form the top row, and the bottom halves form the bottom row.

Consider a path through this grid that starts at the top-left cell (the top half of the first tile) and ends at the bottom-right cell (the bottom half of the last tile). A valid path can only step to the right (to the next cell in the same row) or down (from the top half of a tile to its bottom half). Because there are only two rows, any valid path will travel right along the top row, step down at exactly one tile, and then travel right along the bottom row until the end.

The *cost* of a path is defined as the sum of all the values in the cells it visits. For any chosen arrangement of the tiles, there are exactly **j** valid paths, corresponding to the **j** possible tiles where the downward step can occur. The *score* of an arrangement is the maximum cost among all its **j** valid paths.

Your task is to determine the optimal left-to-right ordering of the tiles that minimizes this score.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains exactly 2 integers **t1** and **t2** (1 ≤ t1, t2 ≤ 1000000): the top value and the bottom value of a tile.

## Output

Print a single integer: the smallest possible score (the minimum possible maximum path cost) achievable by ordering the tiles optimally.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, the single tile has a top value of 5 and a bottom value of 3. There is only one valid path, which visits the top cell and then steps down to the bottom cell, yielding a cost of 5 + 3 = 8.

<RATIONALE>
I replaced the two-machine flow-shop scheduling scenario with an isomorphic grid-path problem. By asking to minimize the maximum path sum in a 2xN grid formed by arranging pairs, the edit removes all temporal scheduling terminology (vessels, locks, durations, waiting) that models use to pattern-match Johnson's rule, forcing them to recognize the mathematical structure of the prefix/suffix sum bottleneck themselves.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum path sum in a 2xN grid where moves are restricted to right and down is mathematically identical to the makespan recurrence of a 2-machine permutation flow shop, so the optimal order yields the exact same minimized value for all inputs.
</PRESERVED_ANSWER>
