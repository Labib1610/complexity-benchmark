# Problem B — Visual Effects Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

A studio is rendering **j** visual effects into a final reel. You must choose the sequence in which these effects are arranged.

Each effect requires a geometry processing cost **p1** and a lighting processing cost **p2**.

During the final render, the system evaluates the pipeline's bottleneck. If the transition from geometry to lighting occurs at the **k**-th effect in your sequence (where 1 ≤ k ≤ j), the pipeline delay is calculated as:
- The sum of the geometry costs of the first **k** effects in your sequence, PLUS
- The sum of the lighting costs of all effects from position **k** to position **j** in your sequence.

The system automatically incurs the worst-case delay. This means the total processing time of your chosen sequence will be the **maximum** pipeline delay across all **j** possible transition points **k**.

Choose the sequence of the effects to make this total processing time as small as possible. Report that smallest possible processing time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the geometry and lighting processing costs of an effect.

## Output

Print a single integer: the smallest possible total processing time.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one effect, so the transition point must be at the 1st effect (k = 1). The geometry sum is 5 and the lighting sum is 3, resulting in a total processing time of 8.
</STATEMENT>
<RATIONALE>
The original problem explicitly described a two-machine flow-shop scheduling scenario (two dedicated processors, fixed sequence, completion time), which allowed models to immediately map it to Johnson's rule by surface pattern matching. I removed the processors and replaced them with an explicit mathematical definition of the makespan (the maximum over $k$ of the prefix sum of $p_1$ plus the suffix sum of $p_2$). Models must now independently deduce that this minimax prefix/suffix sum structure is mathematically equivalent to the two-machine flow-shop makespan before they can apply the intended sorting algorithm.
</RATIONALE>
<PRESERVED_ANSWER>
The maximum over all split points $k$ of the geometry prefix sum and lighting suffix sum is mathematically identical to the completion time of a two-machine flow-shop, so the optimal sequence and its objective value remain exactly the same.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem is still equivalent to minimizing the makespan of a two-machine flow-shop, which is solved optimally in $O(n \log n)$ time using Johnson's rule.
</PRESERVED_CLASS>
