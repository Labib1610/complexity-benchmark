# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to process **j** sectors. For each sector, you are given a first parameter **p1** and a second parameter **p2**.

You must arrange the **j** sectors into a single linear sequence. As the expedition processes your sequence sector by sector, it maintains two running totals: `alpha` (initially 0) and `beta` (initially 0).

For each sector in your sequence, the following updates occur in this exact order:
1. `alpha` is increased by **p1**.
2. `beta` is updated to the maximum of its current value and the new value of `alpha`.
3. `beta` is then increased by **p2**.

After all **j** sectors have been processed, the overall completion metric is the final value of `beta`.

Determine the sequence of sectors that minimizes this overall completion metric. Report that smallest possible metric.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the first and second parameters for a sector, respectively.

## Output

Print a single integer: the smallest possible overall completion metric.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
- Processing the third sector (1, 3):
  1. `alpha` increases by 1 to 1.
  2. `beta` becomes max(0, 1) = 1.
  3. `beta` increases by 3 to 4.
- Processing the second sector (2, 4):
  1. `alpha` increases by 2 to 3.
  2. `beta` becomes max(4, 3) = 4.
  3. `beta` increases by 4 to 8.
- Processing the first sector (3, 2):
  1. `alpha` increases by 3 to 6.
  2. `beta` becomes max(8, 6) = 8.
  3. `beta` increases by 2 to 10.
The final value of `beta` is 10, which is the smallest possible overall completion metric.

In Example 2, processing the single sector (5, 3):
1. `alpha` increases by 5 to 5.
2. `beta` becomes max(0, 5) = 5.
3. `beta` increases by 3 to 8.
The overall completion metric is 8.

<RATIONALE>
The models were using the "battery" and "unmet requirement" semantics to heuristically deduce that they needed to group sectors by net energy gain ($p_2 - p_1 \ge 0$). By mapping the entire state machine to the mathematically identical 2-machine flow shop makespan recurrence, the concepts of "gain", "loss", and "battery" are entirely removed. The models must now either recognize the abstract DP structure or derive the exchange argument mathematically.
</RATIONALE>
<PRESERVED_ANSWER>
The original battery logic computed the final cost as the sum of all $p_1 + p_2$ minus the total energy allocated; this is mathematically identical to the completion time of the last job on the second machine in a standard flow shop, which is exactly what the new `alpha` and `beta` recurrence computes.
</PRESERVED_ANSWER>

The problem remains exactly equivalent to finding the optimal schedule for a 2-machine flow shop to minimize makespan, which is solvable in $O(N \log N)$ time using Johnson's rule.
