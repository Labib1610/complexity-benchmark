# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to process **j** sectors. For each sector, you are given a primary coefficient **p1** and a secondary coefficient **p2**.

You must arrange the **j** sectors into a single linear sequence. As the expedition processes your sequence sector by sector, it maintains a `primary tracker` (initially 0) and a `secondary tracker` (initially 0).

For each sector in your sequence, the following steps occur in this exact order:
1. The expedition calculates a `baseline` equal to the current `secondary tracker` minus **p1**.
2. The expedition calculates a `threshold` equal to the current `primary tracker` plus **p1**.
3. A `target value` is determined as the larger of the `baseline` and the `threshold`.
4. The `primary tracker` is increased by **p1**.
5. The `secondary tracker` is updated to exactly the `target value` plus twice the value of **p2**.

After all **j** sectors have been processed, the overall completion metric is exactly half of the sum of the final `primary tracker` and the final `secondary tracker`.

Determine the sequence of sectors that minimizes this overall completion metric. Report that smallest possible metric.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the primary and secondary coefficients for a sector, respectively.

## Output

Print a single integer: the smallest possible overall completion metric.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
- Processing the third sector (1, 3): The baseline is 0 - 1 = -1. The threshold is 0 + 1 = 1. The target is max(-1, 1) = 1. The primary tracker becomes 0 + 1 = 1. The secondary tracker becomes 1 + 2 * 3 = 7.
- Processing the second sector (2, 4): The baseline is 7 - 2 = 5. The threshold is 1 + 2 = 3. The target is max(5, 3) = 5. The primary tracker becomes 1 + 2 = 3. The secondary tracker becomes 5 + 2 * 4 = 13.
- Processing the first sector (3, 2): The baseline is 13 - 3 = 10. The threshold is 3 + 3 = 6. The target is max(10, 6) = 10. The primary tracker becomes 3 + 3 = 6. The secondary tracker becomes 10 + 2 * 2 = 14.
The final primary tracker is 6 and the secondary tracker is 14. Their sum is 20, and half of this sum is 10, which is the overall completion metric.

In Example 2, processing the single sector (5, 3):
- The baseline is 0 - 5 = -5. The threshold is 0 + 5 = 5. The target is max(-5, 5) = 5. The primary tracker becomes 0 + 5 = 5. The secondary tracker becomes 5 + 2 * 3 = 11.
The final primary tracker is 5 and the secondary tracker is 11. Their sum is 16, and half of this sum is 8, which is the overall completion metric.

<RATIONALE>
The previous state transition based on a clamped battery allowed models to immediately deduce that minimizing the cost was equivalent to maximizing the total energy covered by the battery (since the sum of p1+p2 is constant). I replaced the state variables entirely with two cross-coupled trackers that algebraically evaluate to exactly the same final metric. This removes the "allocated energy" affordance, forcing models to perform a genuine algebraic adjacent exchange to discover the optimal sorting rule.
</RATIONALE>
<PRESERVED_ANSWER>
The new primary tracker exactly computes the prefix sum of p1, and the new secondary tracker algebraically simplifies to `2 * cost - prefix_sum(p1)`, making half of their final sum mathematically guaranteed to equal the original accumulated cost for every possible sequence.
</PRESERVED_ANSWER>
