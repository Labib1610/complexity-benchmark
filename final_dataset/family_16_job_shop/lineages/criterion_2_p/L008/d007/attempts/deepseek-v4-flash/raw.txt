We can model the process and find the optimal ordering.

Let’s denote:

- \( P \) = primary tracker  
- \( S \) = secondary tracker  

For a sector with coefficients \((p_1, p_2)\):

1. baseline = \( S - p_1 \)  
2. threshold = \( P + p_1 \)  
3. target = \(\max(\text{baseline}, \text{threshold})\)  
4. \( P \leftarrow P + p_1 \)  
5. \( S \leftarrow \text{target} + 2 p_2 \)

We want to minimize final \((P + S)/2\).

---

### Key observation

The update for \( S \) is:

\[
S_{\text{new}} = \max(S - p_1, P + p_1) + 2p_2
\]

And \( P_{\text{new}} = P + p_1 \).

We can think of the state as \((P, S)\).  
The final metric is \((P + S)/2\).

---

### Reformulation

Let’s define:

\[
D = S - P
\]

Initially \( D = 0 \).

For a sector:

- baseline = \( S - p_1 = P + D - p_1 \)  
- threshold = \( P + p_1 \)  
- target = \(\max(P + D - p_1, P + p_1)\)  
- \( P_{\text{new}} = P + p_1 \)  
- \( S_{\text{new}} = \max(P + D - p_1, P + p_1) + 2p_2 \)

Then:

\[
D_{\text{new}} = S_{\text{new}} - P_{\text{new}} = \max(P + D - p_1, P + p_1) + 2p_2 - (P + p_1)
\]

Simplify:

\[
D_{\text{new}} = \max(D - p_1, p_1) + 2p_2 - p_1
\]

So:

\[
D_{\text{new}} = \max(D - p_1, p_1) + 2p_2 - p_1
\]

This is independent of \( P \)!  
So the evolution of \( D \) depends only on the order of sectors, not on \( P \).

---

### Final metric

We have:

\[
P_{\text{final}} = \sum p_1
\]

\[
S_{\text{final}} = P_{\text{final}} + D_{\text{final}}
\]

So:

\[
\frac{P_{\text{final}} + S_{\text{final}}}{2} = \frac{P_{\text{final}} + (P_{\text{final}} + D_{\text{final}})}{2} = P_{\text{final}} + \frac{D_{\text{final}}}{2}
\]

Since \( P_{\text{final}} \) is fixed (sum of all \( p_1 \)), minimizing the metric is equivalent to minimizing \( D_{\text{final}} \).

---

### Minimizing \( D_{\text{final}} \)

We have:

\[
D_{\text{new}} = \max(D - p_1, p_1) + 2p_2 - p_1
\]

We can rewrite:

\[
D_{\text{new}} = 
\begin{cases}
D - p_1 + 2p_2 - p_1 = D + 2p_2 - 2p_1, & \text{if } D \ge 2p_1 \\
p_1 + 2p_2 - p_1 = 2p_2, & \text{if } D < 2p_1
\end{cases}
\]

So:

- If \( D \ge 2p_1 \), \( D \) increases by \( 2(p_2 - p_1) \).
- If \( D < 2p_1 \), \( D \) becomes \( 2p_2 \).

---

### Greedy strategy

We want to keep \( D \) as small as possible.  
Notice that if \( D < 2p_1 \), the new \( D \) is \( 2p_2 \), which might be large or small.

We can think:  
- If \( p_2 < p_1 \), then \( 2p_2 < 2p_1 \), so after reset, \( D \) is smaller than the threshold for that sector.  
- If \( p_2 \ge p_1 \), then \( 2p_2 \ge 2p_1 \), so after reset, \( D \) is at least the threshold.

---

### Sorting rule

We can sort sectors by \( p_1 - p_2 \) descending? Let’s test.

Consider two sectors A and B.  
We want to decide order that minimizes final \( D \).

Let’s denote \( a_1, a_2 \) for A, \( b_1, b_2 \) for B.

Start with \( D \).

**Order A then B:**

After A:  
If \( D < 2a_1 \), \( D_A = 2a_2 \)  
Else \( D_A = D + 2(a_2 - a_1) \)

After B:  
If \( D_A < 2b_1 \), \( D_{AB} = 2b_2 \)  
Else \( D_{AB} = D_A + 2(b_2 - b_1) \)

**Order B then A:**

After B:  
If \( D < 2b_1 \), \( D_B = 2b_2 \)  
Else \( D_B = D + 2(b_2 - b_1) \)

After A:  
If \( D_B < 2a_1 \), \( D_{BA} = 2a_2 \)  
Else \( D_{BA} = D_B + 2(a_2 - a_1) \)

We want to compare \( D_{AB} \) and \( D_{BA} \).

---

### Known result

This is similar to a scheduling problem with two-state transitions.  
The optimal order is to sort by \( p_1 - p_2 \) **descending** (or equivalently \( p_2 - p_1 \) ascending).  
Let’s verify with examples.

---

### Example 1

Sectors:  
(3,2): \( p_1 - p_2 = 1 \)  
(2,4): \( p_1 - p_2 = -2 \)  
(1,3): \( p_1 - p_2 = -2 \)

Sort descending by \( p_1 - p_2 \):  
(3,2), then (2,4), then (1,3) — but the optimal was (1,3), (2,4), (3,2).  
So that’s not correct.

Maybe sort by \( p_2 \) descending?  
(2,4), (1,3), (3,2) — not optimal either.

---

### Let’s derive properly

We want to minimize final \( D \).  
The transition is:

If \( D < 2p_1 \): \( D \leftarrow 2p_2 \)  
Else: \( D \leftarrow D + 2(p_2 - p_1) \)

We can think of \( D \) as a "level".  
If \( D \) is small, a sector resets it to \( 2p_2 \).  
If \( D \) is large, it just adds \( 2(p_2 - p_1) \).

We want to keep \( D \) small.  
So we should process sectors with small \( p_2 \) first when \( D \) is small, to avoid large resets.  
But also, if \( p_2 - p_1 \) is negative, processing it when \( D \) is large reduces \( D \).

---

### Greedy by \( p_2 \) ascending?

Test example 1:  
Sort by \( p_2 \) ascending: (3,2), (1,3), (2,4)  
Start D=0  
(3,2): D<6 → D=4  
(1,3): D<2? No, D=4≥2 → D=4+2*(3-1)=8  
(2,4): D<4? No, D=8≥4 → D=8+2*(4-2)=12  
Final D=12 → metric = sum p1=6 + 12/2=12 → not 10.

---

### Another approach

We can think of the process as:  
The final \( D \) is determined by the last sector that "resets" \( D \) to \( 2p_2 \).  
After that, all subsequent sectors just add \( 2(p_2 - p_1) \).

So if we choose a sector \( k \) as the last reset, then:

\[
D_{\text{final}} = 2p_{2k} + \sum_{i \text{ after } k} 2(p_{2i} - p_{1i})
\]

We want to minimize this.

We can choose any sector as the last reset, and order the rest after it in a way that minimizes the sum of \( p_2 - p_1 \) (since it's added).  
But we also need to ensure that before the last reset, all previous sectors don't reset (i.e., their \( D \) stays above their \( 2p_1 \) threshold).  
That means for all sectors before the last reset, we need \( D \) to be large enough.

---

### Key insight

If we sort sectors by \( p_1 - p_2 \) **ascending** (i.e., most negative first), then processing them in that order will keep \( D \) large (because negative \( p_2 - p_1 \) reduces \( D \), but we want to avoid resets).  
Actually, if we process sectors with \( p_2 - p_1 < 0 \) first, they reduce \( D \), which might cause resets later.  
We want to avoid resets after the last reset.

---

### Known solution pattern

This problem is known: sort by \( p_1 - p_2 \) descending? Let’s test with example 1.

Sort by \( p_1 - p_2 \) descending: (3,2), (2,4), (1,3)  
Start D=0  
(3,2): D<6 → D=4  
(2,4): D<4? No, D=4≥4 → D=4+2*(4-2)=8  
(1,3): D<2? No, D=8≥2 → D=8+2*(3-1)=12  
Final D=12 → metric=12 → not 10.

Sort by \( p_1 - p_2 \) ascending: (2,4), (1,3), (3,2)  
Start D=0  
(2,4): D<4 → D=8  
(1,3): D<2? No, D=8≥2 → D=8+4=12  
(3,2): D<6? No, D=12≥6 → D=12-2=10  
Final D=10 → metric=6+5=11 → not 10.

---

### Let’s brute force small to find pattern

We can write a brute force for small j to see optimal order.

But given time, I recall this is a known problem:  
The optimal order is to sort by \( p_1 - p_2 \) **descending**? No, we saw not.

Actually, the correct sorting is by \( p_1 + p_2 \) descending? Let’s test.

Example 1:  
(3,2): sum=5  
(2,4): sum=6  
(1,3): sum=4  
Sort descending: (2,4), (3,2), (1,3)  
Start D=0  
(2,4): D<4 → D=8  
(3,2): D<6? No, D=8≥6 → D=8-2=6  
(1,3): D<2? No, D=6≥2 → D=6+4=10  
Final D=10 → metric=6+5=11 → not 10.

Sort ascending: (1,3), (3,2), (2,4)  
Start D=0  
(1,3): D<2 → D=6  
(3,2): D<6? No, D=6≥6 → D=6-2=4  
(2,4): D<4? No, D=4≥4 → D=4+4=8  
Final D=8 → metric=6+4=10 → matches!

So sorting by \( p_1 + p_2 \) ascending works for example 1.

(2,2): D<4 → D=4  
(2,2): D<4? No, D=4≥4 → D=4+0=4  
(2,2): D<4? No, D=4≥4 → D=4+0=4

### Test example 2

### So sorting by \( p_1 + p_2 \) ascending seems correct.

Let’s verify with another random small case by brute force mentally.

Suppose sectors: (1,100), (100,1)  
Sort by sum ascending: (1,100) sum=101, (100,1) sum=101 — tie, any order.

Order (1,100) then (100,1):  
Start D=0  
(1,100): D<2 → D=200  
(100,1): D<200? No, D=200≥200 → D=200+2*(1-100)=200-198=2  
Final D=2, sum p1=101 → metric=101+1=102.

Order (100,1) then (1,100):  
Start D=0  
(100,1): D<200 → D=2  
(1,100): D<2? No, D=2≥2 → D=2+2*(100-1)=2+198=200  
Final D=200, sum p1=101 → metric=101+100=201.

So first order is better. Sorting by sum ascending gives (1,100) first (sum=101) and (100,1) second (sum=101) — tie, but we need to break ties correctly.  
If tie, we should put the one with smaller \( p_1 \) first? Here (1,100) has smaller p1, and it gave better result.  
So tie-break by \( p_1 \) ascending.

---

### So algorithm:

1. Read sectors.
2. Sort by \( (p_1 + p_2, p_1) \) ascending.
3. Simulate the process to compute final D.
4. Answer = sum(p1) + D/2.

Since D is always even (because updates add multiples of 2), answer is integer.

---

### Complexity

O(j log j) for sorting, j up to 200k, fine.

---

### Implementation

```python
import sys

def solve():
    input = sys.stdin.readline
    j = int(input())
    sectors = []
    total_p1 = 0
    for _ in range(j):
        p1, p2 = map(int, input().split())
        sectors.append((p1, p2))
        total_p1 += p1
    
    # Sort by (p1+p2, p1) ascending
    sectors.sort(key=lambda x: (x[0] + x[1], x[0]))
    
    D = 0
    for p1, p2 in sectors:
        if D < 2 * p1:
            D = 2 * p2
        else:
            D = D + 2 * (p2 - p1)
    
    ans = total_p1 + D // 2
    print(ans)

if __name__ == "__main__":
    solve()
```
