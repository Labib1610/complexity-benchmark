# Problem B — Anomaly Containment Grid

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition has encountered **j** distinct spatial anomalies. You must configure the containment grid by assigning a permanent, unique integer tag from 1 to **j** to each anomaly. 

The anomalies undergo a sequence of state transitions driven by the grid's automated protocols. Each anomaly starts in State 0 (Dormant). For each anomaly, you are given the time it takes to complete its primary and secondary reactions, denoted as **p1** and **p2**.

The grid continuously monitors the anomalies and applies the following event triggers:
- **Primary Trigger:** If no anomaly is currently in State 1 (Resonating), and there is at least one anomaly in State 0, the grid selects the State 0 anomaly with the lowest tag. That anomaly instantly transitions to State 1. It remains in State 1 for exactly its **p1** duration, after which it instantly transitions to State 2 (Volatile).
- **Secondary Trigger:** If no anomaly is currently in State 3 (Stabilizing), and there is at least one anomaly in State 2, the grid selects the State 2 anomaly with the lowest tag. That anomaly instantly transitions to State 3. It remains in State 3 for exactly its **p2** duration, after which it instantly transitions to State 4 (Archived).

Both triggers operate independently and instantaneously whenever their conditions are met. Once an anomaly enters State 1 or State 3, its timer cannot be paused or interrupted. 

Determine the tag assignment that minimizes the time at which all **j** anomalies have reached State 4. Report this minimum possible completion time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the State 1 duration and the State 3 duration for that anomaly.

## Output

Print a single integer: the smallest possible time at which all anomalies reach State 4.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, the single anomaly enters State 1 for 5 seconds, immediately enters State 2, and since no anomaly is in State 3, it instantly enters State 3 for 3 seconds. It reaches State 4 at time 8.
</STATEMENT>
<RATIONALE>
Removed the explicit framing of two agents ("Radar Rover" and "Sampling Rover") processing items in sequence. Replaced it with an event-driven state transition system where the concurrency limit of 1 on specific states implicitly creates the two-machine bottleneck. This forces models to logically map the state triggers to a flow-shop scheduling problem rather than pattern-matching the standard two-machine description.
</RATIONALE>
<PRESERVED_ANSWER>
The state transitions mathematically mirror the original two-machine flow shop: State 1 and State 3 act as the two machines, State 2 acts as the buffer, and the "lowest tag" rule enforces the exact same priority processing order, meaning the optimal tag assignment yields the identical minimal completion time.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains equivalent to the two-machine flow shop makespan minimization, which is solvable in O(j log j) using Johnson's rule.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the "lowest tag" selection as applying dynamically in a way that allows overtaking, but since anomalies finish State 1 in tag order, they become available for State 3 in that exact same order, meaning the lowest tag available is always the one that arrived first; thus the mechanics are unambiguous and identical to the seed.
</RISK>
