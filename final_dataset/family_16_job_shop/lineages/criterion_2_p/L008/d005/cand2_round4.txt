# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given a surface scan requirement **p1** and a deep core yield **p2**.

You must arrange the **j** sectors into a single linear sequence. The expedition processes your sequence sector by sector, maintaining a `data cache` (initially 0) and tracking the `total elapsed time` (initially 0).

For each sector in your sequence, the following steps occur in this exact order:
1. The sector requires **p1** units of data to unlock its surface. If the current `data cache` is strictly less than **p1**, the expedition must manually compute the shortfall. Manually computing takes 1 hour per unit of data shortfall. This shortfall amount is added to the `total elapsed time`, and the `data cache` is completely depleted (becomes 0). 
   If the `data cache` is greater than or equal to **p1**, the surface is unlocked instantly (0 hours), and the `data cache` is simply reduced by **p1**.
2. Once the surface is unlocked, the expedition extracts the deep core. This extraction takes exactly **p2** hours, which is added to the `total elapsed time`. As a direct byproduct, the extraction also generates **p2** units of data, which are added to the `data cache`.

Determine the sequence of sectors that minimizes the final `total elapsed time` after all **j** sectors are processed. Report that smallest possible total elapsed time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the surface scan requirement and deep core yield for a sector, respectively.

## Output

Print a single integer: the smallest possible total elapsed time.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence is the third sector, then the second, then the first.
- Processing the third sector (1, 3): The cache (0) is less than p1 (1). The shortfall is 1. The `total elapsed time` increases by 1 (becoming 1), and the cache becomes 0. Then extraction takes 3 hours (time becomes 4) and yields 3 units of data (cache becomes 3).
- Processing the second sector (2, 4): The cache (3) is greater than or equal to p1 (2). The surface is unlocked instantly (time remains 4), and the cache is reduced by 2 (becoming 1). Then extraction takes 4 hours (time becomes 8) and yields 4 units of data (cache becomes 5).
- Processing the first sector (3, 2): The cache (5) is greater than or equal to p1 (3). The surface is unlocked instantly (time remains 8), and the cache is reduced by 3 (becoming 2). Then extraction takes 2 hours (time becomes 10) and yields 2 units of data (cache becomes 4).
The final `total elapsed time` is 10.

In Example 2, processing the single sector (5, 3):
- The cache (0) is less than p1 (5). The shortfall is 5. The `total elapsed time` increases by 5 (becoming 5), and the cache becomes 0. Then extraction takes 3 hours (time becomes 8) and yields 3 units of data (cache becomes 3).
The final `total elapsed time` is 8.

<RATIONALE>
The explicit terminal metric separated `sum(p2)` from the `idle delay`, which exposed the standard two-machine flow shop wait-time formula. This edit merges the two components into a single `total elapsed time` tracker updated step-by-step. The buffer's negative check is rephrased as computing a resource shortfall. Models must now deduce that minimizing this integrated resource-time ledger is mathematically identical to Johnson's rule, preventing simple pattern matching on the greedy exchange.
</RATIONALE>
<PRESERVED_ANSWER>
The state updates are mathematically identical: a shortfall added to time and depleting the cache is exactly equivalent to accumulating negative buffer values into idle delay, while adding p2 to both time and cache natively bakes the sum of p2 into the final metric.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly the two-machine flow shop scheduling problem, optimally solvable in O(n log n) using Johnson's rule.
</PRESERVED_CLASS>
<RISK>
Models might misinterpret the "takes 1 hour per unit of data shortfall" as a variable rate rather than a direct 1:1 addition, though the example traces make the exact arithmetic completely explicit.
</RISK>
