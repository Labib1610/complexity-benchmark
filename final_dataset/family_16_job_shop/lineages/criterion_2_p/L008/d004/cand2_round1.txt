# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given a surface scan duration and a deep core extraction duration.

You must arrange the **j** sectors into a single linear sequence. 

Once your sequence is chosen, the expedition's total operation time is evaluated based on a "pivot" sector. If the sector at position $k$ (where $1 \le k \le j$) in your sequence is chosen as the pivot, the cost is calculated as the sum of:
- The surface scan durations of all sectors from position $1$ to position $k$, inclusive.
- The deep core extraction durations of all sectors from position $k$ to position $j$, inclusive.

The actual pivot will always be the position $k$ that results in the *maximum* possible cost for your chosen sequence. We call this maximum cost the sequence's *peak cost*.

Determine the sequence of sectors that minimizes this peak cost. Report the smallest possible peak cost.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations for a sector's surface scan and deep core extraction, respectively.

## Output

Print a single integer: the smallest possible peak cost among all valid sequences.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, one optimal sequence places the sectors in the following order: the 3rd sector, then the 2nd sector, then the 1st sector. 
Their durations $(p1, p2)$ in this order are $(1, 3)$, $(2, 4)$, and $(3, 2)$.
- If the pivot is position 1: cost = $1 + (3 + 4 + 2) = 10$.
- If the pivot is position 2: cost = $(1 + 2) + (4 + 2) = 9$.
- If the pivot is position 3: cost = $(1 + 2 + 3) + 2 = 8$.
The peak cost for this sequence is $\max(10, 9, 8) = 10$. No other sequence achieves a peak cost strictly less than 10.

<RATIONALE>
I completely removed the description of parallel serialized tracks and dependency waiting times. Instead, I presented the exact mathematical equivalent of the 2-machine flow-shop makespan: minimizing the maximum of the prefix sum of the first stage and the suffix sum of the second stage. This forces the model to either genuinely derive the adjacent-swap comparator (which leads to Johnson's rule) or fail, bypassing superficial keyword triggers.
</RATIONALE>
<PRESERVED_ANSWER>
The makespan of a 2-machine permutation flow-shop is mathematically identical to the maximum over all k of the sum of the first operation's times up to k and the second operation's times from k onwards.
</PRESERVED_ANSWER>
