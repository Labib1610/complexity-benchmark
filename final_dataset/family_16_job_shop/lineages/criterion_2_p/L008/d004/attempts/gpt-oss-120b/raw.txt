**Solution Explanation**

For a sector `i`

* `p1[i]` – amount subtracted from the buffer  
* `p2[i]` – amount added to the buffer  

During the whole expedition we keep

* `buf` – current buffer (initially `0`)
* `idle` – total idle delay (initially `0`)

Processing a sector

```
buf -= p1[i]
if buf < 0:
        idle += -buf          # the deficit
        buf = 0
buf += p2[i]
```

After all sectors the required value is  

```
answer = idle + Σ p2[i]                (1)
```

--------------------------------------------------------------------

#### 1.   Observations

* `idle` is increased **only** when the buffer before a sector is smaller than its `p1`.
  The increase equals `p1 - buf_before`.

* After a sector the buffer becomes  

```
buf_after = max(0, buf_before - p1) + p2                (2)
```

  So a sector changes the buffer by `+p2` and possibly a *negative* part `-p1`.

* A sector with `p1 ≤ p2` never makes the buffer smaller than it was before
  (it is “non‑decreasing”).  
  A sector with `p1 > p2` *decreases* the buffer (it is “decreasing”).

* While the buffer is small we would like to **avoid** a decreasing sector,
  because it would create a deficit.
  While the buffer is large we would like to **use** decreasing sectors,
  because their negative effect can be absorbed.

Therefore an optimal order is

```
1. all non‑decreasing sectors (p1 ≤ p2)   – they build the buffer,
2. all decreasing sectors   (p1 >  p2)   – they consume the buffer.
```

--------------------------------------------------------------------

#### 2.   Order inside the two groups  

*Group 1 – `p1 ≤ p2`*  

For two such sectors `A` and `B` (`p1A ≤ p2A`, `p1B ≤ p2B`) we compare the
idle delay when they are processed in the two possible orders.
Assume the buffer before the first of them is `x`.

```
order A,B :   idle = max(0, p1A - x)                + max(0, p1B - (max(0,x-p1A)+p2A))
order B,A :   idle = max(0, p1B - x)                + max(0, p1A - (max(0,x-p1B)+p2B))
```

Because `p2A ≥ p1A` and `p2B ≥ p1B`, the second term of the first line is never
larger than the second term of the second line **iff** `p1A ≤ p1B`.
Consequently the optimal order inside this group is **increasing `p1`**.

*Group 2 – `p1 > p2`*  

Now both sectors decrease the buffer. The same exchange argument shows that
the order with the **larger `p2` first** never gives a larger idle delay.
Thus inside this group we sort **decreasing `p2`**.

--------------------------------------------------------------------

#### 3.   Algorithm
```
read all sectors
group1 = sectors with p1 ≤ p2
group2 = sectors with p1 >  p2

sort group1 by   p1  increasing
sort group2 by   p2  decreasing

process sectors in the concatenated order
        (group1 followed by group2) exactly as the statement describes
obtain idle
answer = idle + sum(p2 of all sectors)
print answer
```

`j ≤ 2·10⁵`, sorting is `O(j log j)`, the simulation is `O(j)`.  
Memory consumption is `O(j)`.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the minimal possible metric.

---

##### Lemma 1  
In an optimal sequence all sectors with `p1 ≤ p2` appear before any sector
with `p1 > p2`.

**Proof.**  
Take an optimal sequence and locate the first decreasing sector `D`
(`p1D > p2D`). If there is a non‑decreasing sector `N` (`p1N ≤ p2N`) after `D`,
swap `D` and `N`.  
Because `N` never reduces the buffer, after the swap the buffer just before
`D` is **not smaller** than before the swap, therefore the deficit caused by
`D` does not increase, while the deficit caused by `N` cannot increase either
(`N` never creates a deficit).  
Thus the total idle delay does not grow, contradicting the optimality unless
no such `N` exists. ∎



##### Lemma 2  
Among sectors with `p1 ≤ p2` the order of increasing `p1` minimises the idle
delay.

**Proof.**  
Consider two consecutive sectors `A,B` of this group with `p1A > p1B`.
Let the buffer before `A` be `x`.  
Idle contributed by the pair in order `A,B` is  

```
I_AB = max(0, p1A - x) + max(0, p1B - (max(0,x-p1A)+p2A))
```

Because `p2A ≥ p1A`, the second term is `0` whenever the first term is `0`,
otherwise it is at most `p1B - (x-p1A)`.  
If we exchange them, the idle becomes  

```
I_BA = max(0, p1B - x) + max(0, p1A - (max(0,x-p1B)+p2B))
```

Since `p2B ≥ p1B`, the second term of `I_BA` is **at least** the second term of
`I_AB`. Moreover `max(0, p1A - x) ≥ max(0, p1B - x)`. Hence `I_AB ≤ I_BA`.  
Therefore putting the smaller `p1` first never worsens the result, and by
repeated exchanges we obtain the optimal order – increasing `p1`. ∎



##### Lemma 3  
Among sectors with `p1 > p2` the order of decreasing `p2` minimises the idle
delay.

**Proof.**  
Analogous to Lemma&nbsp;2, now both sectors decrease the buffer.
For two consecutive sectors `A,B` with `p2A < p2B` we compare the two orders.
A direct calculation (or the same exchange argument) shows that the idle
delay of order `B,A` is not larger than that of `A,B`.  
Consequently sorting by decreasing `p2` is optimal for this group. ∎



##### Lemma 4  
The sequence produced by the algorithm (group 1 sorted by `p1`,
then group 2 sorted by `p2`) yields the minimum possible idle delay.

**Proof.**  
By Lemma&nbsp;1 any optimal sequence can be transformed into a sequence where
all group 1 sectors precede all group 2 sectors without increasing idle.
Inside each group we can further reorder according to Lemma&nbsp;2 and
Lemma&nbsp;3 without increasing idle.  
Thus there exists an optimal sequence exactly equal to the algorithm’s
sequence. ∎



##### Theorem  
The algorithm outputs the smallest possible overall completion metric.

**Proof.**  
The algorithm computes the idle delay of the sequence described in
Lemma&nbsp;4, which is minimal.  
The final answer adds the constant `Σ p2[i]` (independent of the order) to
that idle delay, therefore the printed value is the minimal possible metric. ∎

#### 5.   Complexity Analysis  

*Sorting* : `O(j log j)`  
*Simulation*: `O(j)`  
*Memory*   : `O(j)` for storing the sectors.

Both limits satisfy the given constraints (`j ≤ 200 000`).

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    group1 = []          # p1 <= p2
    group2 = []          # p1 >  p2
    total_p2 = 0
    for _ in range(n):
        p1 = int(next(it)); p2 = int(next(it))
        total_p2 += p2
        if p1 <= p2:
            group1.append((p1, p2))
        else:
            group2.append((p1, p2))

    group1.sort(key=lambda x: x[0])          # increasing p1
    group2.sort(key=lambda x: -x[1])         # decreasing p2

    buf = 0
    idle = 0
    for p1, p2 in group1:
        buf -= p1
        if buf < 0:
            idle += -buf
            buf = 0
        buf += p2
    for p1, p2 in group2:
        buf -= p1
        if buf < 0:
            idle += -buf
            buf = 0
        buf += p2

    print(idle + total_p2)

if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
