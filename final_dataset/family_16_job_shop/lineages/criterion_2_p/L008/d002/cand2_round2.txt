# Problem B — Expedition Pipeline

Time limit: 1 s   Memory limit: 256 MB

## Description

An expedition needs to survey **j** distinct sectors. For each sector, you are given its mapping duration **p1** and its drilling duration **p2**. 

You must arrange all **j** sectors into a single itinerary from first to last. The expedition uses a Radar Rover for mapping and a Sampling Rover for drilling, which both follow your chosen itinerary sequentially. 

To determine the exact time the expedition finishes, we track the Sampling Rover's "backlog"—the number of hours of drilling it still needs to complete at the exact moment the Radar Rover departs a sector. Because the Sampling Rover can only drill a sector after it has been fully mapped, the backlog updates sector by sector:
- Initially, before the first sector, the backlog is 0.
- For each sector in your itinerary, the Radar Rover spends **p1** hours mapping it. During these **p1** hours, the Sampling Rover works continuously, reducing its existing backlog by up to **p1** hours (the backlog cannot drop below 0).
- Immediately after the Radar Rover finishes mapping the sector, it moves on, and the sector's drilling duration **p2** is added to the Sampling Rover's backlog.

After all **j** sectors are mapped, the Radar Rover's job is done. The total expedition time is the sum of all **p1** durations (the total time the Radar Rover was working) plus the final backlog (the remaining time the Sampling Rover needs to finish the newly accumulated drilling).

Determine the itinerary that minimizes this total expedition time, and report that smallest possible time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the durations for a sector with the Radar Rover and the Sampling Rover.

## Output

Print a single integer: the smallest possible total expedition time.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, for the itinerary ordering the input sectors as the 3rd, then 2nd, then 1st:
- 3rd sector (1, 3): The Radar Rover works for 1 hour. The backlog drops to 0, then 3 is added. Backlog = 3.
- 2nd sector (2, 4): The Radar Rover works for 2 hours. The backlog reduces by 2 (to 1), then 4 is added. Backlog = 5.
- 1st sector (3, 2): The Radar Rover works for 3 hours. The backlog reduces by 3 (to 2), then 2 is added. Backlog = 4.
The total time is the sum of mapping times (1 + 2 + 3 = 6) plus the final backlog (4), which equals 10.

In Example 2, for the single sector (5, 3): the Radar Rover works for 5 hours. The initial backlog of 0 remains 0, then the drilling duration 3 is added. The total time is the mapping time (5) plus the final backlog (3), finishing at 8.

This explicitly preserves the two-stage machine rules as requested by the expert, while forcing models to genuinely recognize that minimizing the final backlog is equivalent to Johnson's rule rather than pattern-matching the "machine 1 then machine 2" template.
