<STATEMENT>
# Server Queue Calibration

Time limit: 1 s   Memory limit: 256 MB

## Description

You are configuring a sequential processing queue for **j** data packets. You must choose a single sequence in which to order these packets from position 1 to $j$.

Each packet has two properties: an *arrival delay* (**p1**) and a *processing duration* (**p2**).

The packets are fed into a single processing unit one by one according to your chosen sequence. The unit can process only one packet at a time, and it processes waiting packets in the exact order they arrived.

The timeline of the system progresses sequentially through your ordered packets as follows:
For each packet in your sequence:
1. First, an *arrival delay* phase occurs, lasting exactly **p1** seconds. During this phase, the processing unit continuously works on any previously queued packets. If the unit finishes all queued packets before the phase ends, it remains idle for the remainder of these **p1** seconds.
2. Immediately after this delay phase ends, the new packet arrives at the unit and is added to the queue. This instantly adds exactly its *processing duration* (**p2**) in seconds to the unit's remaining workload.

At the very beginning, the queue is empty and the processing unit is idle.

The total completion time is defined as the total continuous time elapsed from the start of the first packet's arrival delay phase until the processing unit finishes processing the final ($j$-th) packet.

Your objective is to find an arrangement sequence of the **j** packets that minimizes this total completion time. Output this minimum possible total completion time.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the arrival delay and the processing duration of a packet, respectively.

## Output

Print a single integer: the minimum possible completion time of the final packet.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, an optimal sequence is to order the packets as: (1 3), then (2 4), then (3 2).
- First packet (1 3): The system waits for 1 second (arrival delay). The unit is idle. Then the packet arrives, adding 3 seconds to the queue workload.
- Second packet (2 4): The system waits for 2 seconds. During this time, the unit processes 2 seconds of the previous 3-second workload, leaving 1 second. Then the packet arrives, adding 4 seconds. The queue workload is now 1 + 4 = 5 seconds.
- Third packet (3 2): The system waits for 3 seconds. The unit processes 3 seconds of the 5-second workload, leaving 2 seconds. Then the packet arrives, adding 2 seconds. The queue workload is now 2 + 2 = 4 seconds.

The total time spent in arrival delay phases is 1 + 2 + 3 = 6 seconds. After the final packet arrives, the unit needs 4 more seconds to finish the remaining workload. The total completion time is 6 + 4 = 10, which is the minimum possible completion time.

I replaced the explicit cumulative sum formulation of absolute arrival times with a step-by-step state update perspective. The timeline is now described as a sequence of phases where the processing unit reduces its workload backlog by `p1` (down to a minimum of 0) and then increases it by `p2`. This structurally obscures the equivalence to a two-machine flow shop, forcing the model to analyze the recurrence mathematically rather than pattern-matching the cumulative release times to Johnson's rule.
</RATIONALE>
