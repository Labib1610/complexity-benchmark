We need to minimize the completion time of the last packet.  
The arrival time of the k-th packet in the chosen order is the sum of p1 of all packets up to that point.  
The processing start time is the maximum of its arrival time and the finish time of the previous packet.  
The finish time is start time + p2.

We can think of this as a scheduling problem: we have jobs with release times (arrival times) and processing times.  
The release time of job i depends on the sum of p1 of all jobs before it.  
We want to minimize the makespan (completion time of the last job).

A known optimal strategy for minimizing makespan with release times and processing times when release times are controllable (by ordering) is to sort by p1 ascending? Let’s check.

If we sort by p1 ascending, the arrival times are as small as possible early, which tends to reduce idle time.  
But we also have p2 to consider.  
Actually, the optimal order is to sort by p1 ascending, and if p1 equal, sort by p2 descending? Let’s test with examples.

Example 1:  
(3,2), (2,4), (1,3)  
Sort by p1 ascending: (1,3), (2,4), (3,2) → matches the optimal given.  
Completion:  
t=1 start, finish 4  
t=3 arrival, wait until 4, finish 8  
t=6 arrival, wait until 8, finish 10 → 10.

Example 3: all equal p1=2, p2=2 → any order gives 8.

So sorting by p1 ascending seems correct.  
But is there a case where sorting by p1 ascending is not optimal?  
Consider:  
(1, 100), (2, 1)  
Sort by p1: (1,100) then (2,1):  
t=1 start, finish 101  
t=3 arrival, wait until 101, finish 102 → 102.  
If we swap: (2,1) then (1,100):  
t=2 start, finish 3  
t=3 arrival, start at 3, finish 103 → 103.  
So p1 ascending is better.

What about p1 equal?  
(2,5), (2,1)  
Sort by p1 ascending (both equal), then by p2 descending: (2,5) then (2,1):  
t=2 start, finish 7  
t=4 arrival, wait until 7, finish 8 → 8.  
If we put (2,1) first:  
t=2 start, finish 3  
t=4 arrival, start at 4, finish 9 → 9.  
So p2 descending when p1 equal is better.

Thus the optimal order is: sort by p1 ascending, and if p1 equal, sort by p2 descending.

Now we just simulate the process to get the final completion time.

Complexity: O(j log j) for sorting, O(j) for simulation, which is fine for j ≤ 200000.

Let’s implement.

```python
import sys

def main():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    j = int(data[0])
    packets = []
    idx = 1
    for _ in range(j):
        p1 = int(data[idx])
        p2 = int(data[idx+1])
        packets.append((p1, p2))
        idx += 2
    
    # Sort by p1 ascending, then p2 descending
    packets.sort(key=lambda x: (x[0], -x[1]))
    
    time = 0
    arrival = 0
    for p1, p2 in packets:
        arrival += p1
        if time < arrival:
            time = arrival
        time += p2
    
    print(time)

if __name__ == "__main__":
    main()
```
