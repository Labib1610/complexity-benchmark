**Solution Explanation**

For every job we know the processing time on machine 1 (`p1`) and on
machine 2 (`p2`).  
All jobs have to be processed on machine 1 first, then on machine 2,
and both machines must follow the same order of jobs.
We have to minimise the finishing time of the last job on machine 2
(the *makespan*).

--------------------------------------------------------------------

#### 1.   Johnson’s rule for two‑machine flow shop  

For two machines the optimal order is known:

* split the jobs into two groups  

```
A = { jobs with p1 ≤ p2 }
B = { jobs with p1 >  p2 }
```

* sort `A` by increasing `p1`
* sort `B` by decreasing `p2`
* the optimal sequence is `A` followed by `B`

*Proof sketch*  
Consider any two jobs `i` and `j`.  
If `p1_i ≤ p2_i` and `p1_j ≤ p2_j` then putting the one with the
smaller `p1` first never makes the makespan larger.
If `p1_i > p2_i` and `p1_j > p2_j` then putting the one with the larger
`p2` first never makes the makespan larger.
If the jobs belong to different groups the rule forces the
`A`‑job before the `B`‑job, which can be shown to be optimal as well.
Repeating these pairwise improvements yields exactly the described order. ∎



--------------------------------------------------------------------

#### 2.   Computing the makespan of a given order  

```
time1 = 0          # moment when machine 1 finishes current job
time2 = 0          # moment when machine 2 finishes current job
for each job (p1,p2) in the order:
        time1 += p1                # job finishes on machine 1
        time2 = max(time2, time1)  # it may have to wait for machine 2
        time2 += p2                # processing on machine 2
answer = time2
```

All numbers fit into 64‑bit (`≤ 2·10^11`).

--------------------------------------------------------------------

#### 3.   Algorithm  

```
read n and all (p1,p2)
A = [] , B = []
for each job:
        if p1 ≤ p2:  A.append((p1,p2))
        else:        B.append((p1,p2))

sort A by p1 ascending
sort B by p2 descending
order = A + B

simulate as described and output the final time2
```

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the minimal possible finishing time.

---

##### Lemma 1  
The sequence `order = A (sorted by p1) followed by B (sorted by p2 descending)`
is optimal for the two‑machine flow shop.

**Proof.** This is exactly Johnson’s rule, proved optimal in Section 1. ∎



##### Lemma 2  
For a fixed processing order the simulation computes the exact makespan.

**Proof.**  
`time1` is the completion moment of the last processed job on machine 1,
hence after adding `p1` it equals the finish time of the current job on
machine 1.  
Machine 2 can start this job only after both it is ready (`time1`) and
machine 2 itself is free (`time2`). The `max` implements this waiting.
Adding `p2` yields the finish moment of the current job on machine 2.
Induction over the jobs shows that after the loop `time2` equals the
completion time of the last job on machine 2, i.e. the makespan. ∎



##### Lemma 3  
The algorithm outputs the makespan of the optimal order.

**Proof.**  
By Lemma 1 the constructed `order` is optimal.
By Lemma 2 the simulation returns the makespan of this order.
Therefore the printed value equals the minimal possible finishing time. ∎



##### Theorem  
`solve()` prints the smallest possible time at which all jobs are finished.

**Proof.** Directly from Lemma 3. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis  

*Partition & reading*: `O(n)`  
*Sorting*: `O(n log n)`  
*Simulation*: `O(n)`  

Memory consumption: storing all jobs → `O(n)` ( ≤ 200 000 pairs).

Both limits satisfy the problem constraints.

#### 6.   Reference Implementation  (Python 3)

```python
import sys

def solve() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    n = data[0]
    jobs = [(data[i], data[i + 1]) for i in range(1, 2 * n + 1, 2)]

    a = []  # p1 <= p2
    b = []  # p1 >  p2
    for p1, p2 in jobs:
        if p1 <= p2:
            a.append((p1, p2))
        else:
            b.append((p1, p2))

    a.sort(key=lambda x: x[0])          # increasing p1
    b.sort(key=lambda x: -x[1])         # decreasing p2
    order = a + b

    time1 = 0
    time2 = 0
    for p1, p2 in order:
        time1 += p1
        if time2 < time1:
            time2 = time1
        time2 += p2

    print(time2)


if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above and conforms
to the required input‑output format.
