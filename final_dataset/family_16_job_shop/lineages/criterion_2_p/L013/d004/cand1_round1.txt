<METHOD_DESCRIPTION>
Reframed the explicit prefix/suffix sum (which is the algebraic signature of a 2-machine flow shop makespan) into a minimax problem finding the maximum weight path in a 2xN grid. This completely hides the scheduling structure and forces models to either recognize the grid-path equivalence to Johnson's rule or derive the optimal sorting comparator from scratch.
</METHOD_DESCRIPTION>

yes

<STATEMENT>
# Grid Path Vulnerability

Time limit: 1 s   Memory limit: 256 MB

## Description

You are given **j** rectangular tiles. Each tile has an upper value and a lower value. You must arrange all **j** tiles in a single horizontal sequence from left to right. This arrangement forms a grid with exactly 2 rows and **j** columns. The orientation of the tiles is fixed: their upper values must remain in the top row and their lower values in the bottom row. You only choose their left-to-right order.

Consider a token that starts at the top-left cell of this grid and must travel to the bottom-right cell. In a single step, the token may only move to the adjacent cell directly to its right, or to the adjacent cell directly below it. The *score* of a path is the sum of the values in all the cells it visits (including the starting and ending cells).

For any chosen sequence of tiles, we define its *vulnerability* as the maximum possible score a token could achieve among all valid paths through the grid. 

Your objective is to find an arrangement sequence for the **j** tiles that minimizes this vulnerability. Output the minimum possible vulnerability.

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the next **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000): the upper value and the lower value of a tile, respectively.

## Output

Print a single integer: the minimum possible vulnerability.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 2, there is only one tile. The grid has 2 rows and 1 column. The only valid path starts at the top cell (5), moves down to the bottom cell (3), and ends there. The total score is 5 + 3 = 8. Since there is only one arrangement, the minimum possible vulnerability is 8.
</STATEMENT>
<RATIONALE>
Replaced the explicit algebraic formula `max(prefix_sum(p1) + suffix_sum(p2))` with a mathematically identical 2D grid path traversal. This removes the direct signature of the 2-machine flow shop makespan, forcing the model to independently deduce the equivalence between grid-path minimaxing and Johnson's rule.
</RATIONALE>
<PRESERVED_ANSWER>
Because any valid path in a 2-row grid must move right along the top row to some column `k`, move down, and move right along the bottom row to the end, the path sum is exactly the prefix sum of the top row plus the suffix sum of the bottom row, perfectly preserving the original objective function.
</PRESERVED_ANSWER>
<PRESERVED_CLASS>
The problem remains exactly equivalent to a 2-machine flow shop scheduling problem, which is optimally solved in O(N log N) time using Johnson's rule, keeping it in the P complexity class.
</PRESERVED_CLASS>
