# Problem B — Mutex Lock Sequencing

Time limit: 1 s   Memory limit: 256 MB

## Description

You are optimizing a software routine that launches a sequence of **j** threads. Each thread requires exclusive access to two resources in a specific order: first an Alpha Mutex, then a Beta Mutex.

You must design a single initialization sequence (an ordering of the **j** threads). Both the Alpha Mutex and the Beta Mutex will grant access to the threads in this exact same order.

The timing of the threads is governed by these rules:
1. The Alpha Mutex grants access to the threads continuously, one after another in your chosen initialization sequence, starting at microsecond 0. 
2. The Beta Mutex grants access to the threads one after another in the exact same initialization sequence.
3. For any given thread, it cannot acquire the Beta Mutex until two conditions are met:
   - The thread has fully completed its time holding the Alpha Mutex.
   - The Beta Mutex has been fully released by the previous thread in the initialization sequence (this applies to all threads after the first).
4. A thread acquires the Beta Mutex at the earliest possible microsecond that satisfies the conditions above.

Your task is to find an initialization sequence of the **j** threads that minimizes the total routine time—specifically, the microsecond when the final thread in your sequence releases the Beta Mutex.

What is the lowest possible completion time?

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the time (in microseconds) the thread holds the Alpha Mutex and the Beta Mutex, respectively.

## Output

Print a single integer: the lowest possible completion time when the last thread releases the Beta Mutex.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, if we order the initialization sequence as the 3rd thread, then the 2nd thread, then the 1st thread from the input:
- The 3rd thread holds the Alpha Mutex for 1 (releases at microsecond 1). It holds the Beta Mutex for 3, acquiring it at 1 and releasing it at 4.
- The 2nd thread holds the Alpha Mutex for 2 (releases at 1+2=3). It holds the Beta Mutex for 4. It must wait until it has released the Alpha Mutex (microsecond 3) and the previous thread releases the Beta Mutex (microsecond 4). It acquires the Beta Mutex at 4 and releases it at 4+4=8.
- The 1st thread holds the Alpha Mutex for 3 (releases at 3+3=6). It holds the Beta Mutex for 2. It must wait until it has released the Alpha Mutex (microsecond 6) and the previous thread releases the Beta Mutex (microsecond 8). It acquires the Beta Mutex at 8 and releases it at 8+2=10.
The final release time is 10. This is the minimum possible time across all valid initialization sequences.

In Example 2, there is only one thread. It releases the Alpha Mutex at 5. It acquires the Beta Mutex at 5 and releases it at 5 + 3 = 8.

The explicit input bounds were retained exactly as requested to ensure strict contract compliance.
