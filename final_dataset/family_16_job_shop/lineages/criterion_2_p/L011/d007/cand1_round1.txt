<STATEMENT>
# Problem B — Phase Calibration

Time limit: 1 s   Memory limit: 256 MB

## Description

You are calibrating a phase generator by applying a sequence of **j** distinct pulses. 

The generator tracks two internal values throughout the calibration: the Base Phase and the Peak Phase. Both values start at exactly 0. 

You must select an order in which to apply all **j** pulses exactly once. When a pulse with parameters **p1** and **p2** is applied, the internal values update according to the following exact sequence of steps:
1. The Base Phase is increased by **p1**.
2. If the Base Phase is currently strictly greater than the Peak Phase, the Peak Phase is instantly updated to equal the Base Phase.
3. The Peak Phase is increased by **p2**.

Your task is to find an ordering of the **j** pulses that minimizes the final value of the Peak Phase after the entire sequence has been applied.

What is the minimum possible final value of the Peak Phase?

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the two parameters for one of the pulses.

## Output

Print a single integer: the minimum possible final value of the Peak Phase.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, if we order the pulses as the 3rd pulse, then the 2nd pulse, then the 1st pulse from the input:

- **Apply 3rd pulse (1, 3):**
  Base Phase increases by 1 (now 1).
  Base Phase (1) > Peak Phase (0), so Peak Phase is updated to 1.
  Peak Phase increases by 3 (now 4).

- **Apply 2nd pulse (2, 4):**
  Base Phase increases by 2 (now 3).
  Base Phase (3) is not greater than Peak Phase (4), so Peak Phase remains 4.
  Peak Phase increases by 4 (now 8).

- **Apply 1st pulse (3, 2):**
  Base Phase increases by 3 (now 6).
  Base Phase (6) is not greater than Peak Phase (8), so Peak Phase remains 8.
  Peak Phase increases by 2 (now 10).

The final Peak Phase is 10. This is the minimum possible final value across all valid orderings.

In Example 2, there is only one pulse. The Base Phase becomes 5. The Peak Phase is updated to 5, then increases by 3 to reach a final value of 8.

<RATIONALE>
The rewrite completely removes the scheduling context (workers, tasks, execution timeline) that previously allowed models to recognize the problem as a 2-machine flow-shop and apply Johnson's rule. The pipeline logic is recast as a purely algebraic sequence of state updates with a conditional threshold, forcing models to deduce the optimal structural ordering from the mathematical mechanics alone.
</RATIONALE>
<PRESERVED_ANSWER>
The sequence of Base Phase updates tracks the cumulative sum of `p1`, and the conditional update to Peak Phase mirrors the wait-time logic of the second machine (`max(Base, Peak) + p2`), meaning the final Peak Phase is mathematically identical to the flow-shop makespan.
</PRESERVED_ANSWER>
