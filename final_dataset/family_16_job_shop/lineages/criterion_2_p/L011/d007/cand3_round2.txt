# Problem B — Toll Switch Journey

Time limit: 1 s   Memory limit: 256 MB

## Description

You are planning a journey through a set of **j** checkpoints. Each checkpoint has two associated costs: a daytime toll and a nighttime toll.
You must choose a single sequence in which to visit all **j** checkpoints.

During your journey, you will begin by traveling during the day. At some checkpoint **k** (where 1 ≤ **k** ≤ **j**), you will switch to traveling at night. You must make this switch exactly once.
- For all checkpoints visited before the switch (positions 1 to **k**-1 in your sequence), you pay only the daytime toll.
- At the checkpoint where you switch (position **k**), you pay both the daytime toll and the nighttime toll.
- For all checkpoints visited after the switch (positions **k**+1 to **j**), you pay only the nighttime toll.

You do not get to choose the switch point **k**. An adversary will observe your chosen sequence of checkpoints and select the switch point **k** that maximizes the total toll you must pay.

Your task is to find an ordering of the **j** checkpoints that minimizes the total toll you will pay, assuming the adversary plays optimally to maximize it.

What is the minimum possible total toll you can be forced to pay?

## Input

The first line contains a single integer **j** (1 ≤ j ≤ 200000).
Each of the following **j** lines contains two integers **p1** and **p2** (1 ≤ p1, p2 ≤ 1000000), representing the daytime toll and nighttime toll for a checkpoint, respectively.

## Output

Print a single integer: the minimum possible total toll you can be forced to pay.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1
5 3
```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2
2 2
2 2
```

**Output**
```
8
```

## Note

In Example 1, if we order the checkpoints as the 3rd checkpoint, then the 2nd checkpoint, then the 1st checkpoint from the input:
- The daytime tolls in this order are 1, 2, 3.
- The nighttime tolls in this order are 3, 4, 2.

The adversary can choose any switch point **k** (1, 2, or 3):
- If **k** = 1: you pay daytime at 1, and nighttime at 1, 2, 3. Total = 1 + (3 + 4 + 2) = 10.
- If **k** = 2: you pay daytime at 1, 2, and nighttime at 2, 3. Total = (1 + 2) + (4 + 2) = 9.
- If **k** = 3: you pay daytime at 1, 2, 3, and nighttime at 3. Total = (1 + 2 + 3) + 2 = 8.
The adversary wants to maximize the total, so they will choose **k** = 1, resulting in a toll of 10.
This is the minimum possible total toll across all valid orderings of the checkpoints.

<RATIONALE>
I transformed the two-machine flow shop scheduling problem into a min-max game on a sequence of tolls. The makespan of a two-machine flow shop is mathematically identical to the maximum over $k$ of the prefix sum of the first processing times plus the suffix sum of the second processing times. By framing this as an adversary choosing a switch point to maximize toll costs, the underlying flow shop structure is completely disguised. Models relying on scheduling keywords or typical flow-shop descriptions will fail to recognize the applicability of Johnson's rule.
</RATIONALE>
