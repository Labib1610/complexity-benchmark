# Problem B — Thread Synchronization Queue

Time limit: 1 s   Memory limit: 256 MB

## Description

You are optimizing the execution queue for a batch of **j** computational threads. Each thread requires sequential access to two exclusive system resources: the Alpha Mutex and the Beta Mutex.

You must arrange the **j** threads into a single strict execution queue. The system will then process the threads based on your queue order according to the following rules:

1. The Alpha Mutex is granted to the threads strictly in your queue order. The first thread in the queue acquires it at microsecond 0. As soon as a thread completely finishes its required time with the Alpha Mutex and releases it, the next thread in the queue immediately acquires it. 
2. The Beta Mutex is also granted to the threads strictly in your queue order.
3. A thread can only acquire the Beta Mutex when both of these conditions are met:
   - The thread has fully completed its time with the Alpha Mutex and released it.
   - The Beta Mutex is currently free (meaning the previous thread in the queue has finished its time with the Beta Mutex and released it. For the first thread in the queue, the Beta Mutex is free initially).
4. A thread acquires the Beta Mutex at the earliest possible microsecond that both conditions are true.

The system architecture supports a queue size of at least one thread, up to a strict memory limit of exactly two hundred thousand threads. The hold times for each thread on the Alpha Mutex and Beta Mutex are measured in microseconds. Hardware constraints dictate that a mutex must be held for at least one microsecond, while the operating system enforces a maximum hold time of exactly one million microseconds per mutex.

Your objective is to find a queue ordering of the **j** threads that minimizes the total execution time—specifically, the exact microsecond when the final thread in your queue releases the Beta Mutex.

## Input

The first line contains a single integer **j**, representing the number of threads in the batch.
Each of the subsequent **j** lines corresponds to a thread and contains two integers, **a** and **b**. These represent the microseconds the thread must hold the Alpha Mutex and the Beta Mutex, respectively.

## Output

Print a single integer: the minimum possible microsecond when the final thread in the queue releases the Beta Mutex.

## Examples

### Example 1

**Input**
```
3
3 2
2 4
1 3
```

**Output**
```
10
```

### Example 2

**Input**
```
1

```

**Output**
```
8
```

### Example 3

**Input**
```
3
2 2

2 2
```

**Output**
```
8
```

## Note

In Example 1, if you order the threads in the queue as the 3rd thread from the input, then the 2nd thread, then the 1st thread:
- The 3rd thread holds the Alpha Mutex for 1 microsecond (releasing it at microsecond 1). It immediately acquires the Beta Mutex and holds it for 3 microseconds, releasing it at 4.
- The 2nd thread acquires the Alpha Mutex at microsecond 1 and holds it for 2 microseconds (releasing it at 1+2=3). It requires the Beta Mutex for 4 microseconds. It must wait until it has released the Alpha Mutex (microsecond 3) and the previous thread has released the Beta Mutex (microsecond 4). It acquires the Beta Mutex at 4 and releases it at 4+4=8.
- The 1st thread acquires the Alpha Mutex at microsecond 3 and holds it for 3 microseconds (releasing it at 3+3=6). It requires the Beta Mutex for 2 microseconds. It waits for its Alpha release (microsecond 6) and the previous Beta release (microsecond 8). It acquires the Beta Mutex at 8 and releases it at 8+2=10.
The final release time is 10. This is the minimum possible time across all valid queue orderings.

In Example 2, with only one thread, it releases the Alpha Mutex at microsecond 5. It immediately acquires the Beta Mutex at 5 and releases it at 5 + 3 = 8.
