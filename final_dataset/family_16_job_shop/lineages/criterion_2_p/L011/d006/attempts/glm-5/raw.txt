Looking at this problem, I need to find an ordering of operations (each with prepare time p1 and finalize time p2) that minimizes the total completion time.

Let me analyze the structure. If I order operations as 1, 2, ..., n, then:
- Prepare worker finishes operation i at time P_i = p1_1 + p1_2 + ... + p1_i
- Finalize worker starts operation i at max(P_i, F_{i-1}) where F_0 = 0
- Finalize worker finishes operation i at F_i = max(P_i, F_{i-1}) + p2_i

The key insight: if the finalize worker is never idle (always backlogged), then F_n = sum(p1) + p2_last. This happens when the prepare tasks are "front-loaded" enough.

If finalize is never idle, we want the last operation to have minimal p2. But we also need to ensure no idle gaps.

Let me think about when idle gaps occur. A gap occurs at operation i if P_i > F_{i-1}, meaning prepare hasn't finished yet.

**Strategy:** Sort by p2 in descending order. This puts small p2 values at the end. The idea is that operations with large p2 early create a "buffer" that keeps the finalize worker busy while prepare catches up, minimizing idle time and ensuring the last (smallest) p2 is at the end.

Let me verify with Example 1: operations (3,2), (2,4), (1,3). Sorted by p2 desc: (2,4), (1,3), (3,2).
- P_1 = 2, F_1 = 2+4 = 6
- P_2 = 3, F_2 = max(3,6)+3 = 9
- P_3 = 6, F_3 = max(6,9)+2 = 11

But the answer is 10. So pure descending sort doesn't work here.

Let me reconsider. The optimal in Example 1 is order (1,3), (2,4), (3,2):
- P_1 = 1, F_1 = 1+3 = 4
- P_2 = 3, F_2 = max(3,4)+4 = 8
- P_3 = 6, F_3 = max(6,8)+2 = 10 ✓

So the first operation has p1=1 (small), which lets finalize start early and build a buffer.

This is the classic "two-machine flow shop" problem (Johnson's rule). Johnson's rule: partition into two sets - S1 where p1 ≤ p2, S2 where p1 > p2. Sort S1 by p1 ascending, sort S2 by p2 descending. Concatenate S1 + S2.

Let me verify:
- (3,2): p1>p2, S2
- (2,4): p1≤p2, S1
- (1,3): p1≤p2, S1

S1 sorted by p1 asc: (1,3), (2,4). S2 sorted by p2 desc: (3,2).
Order: (1,3), (2,4), (3,2) → gives 10 ✓

Example 3: all (2,2), p1=p2, all in S1. Order doesn't matter.
- F_1 = 4, F_2 = max(4,4)+2 = 6, F_3 = max(6,6)+2 = 8 ✓

Example 2: (5,3), p1>p2, S2. F_1 = 5+3 = 8 ✓

Johnson's rule works. Let me implement it efficiently.

```python
import sys

def main():
    input_data = sys.stdin.buffer.read().split()
    n = int(input_data[0])
    idx = 1
    S1 = []  # p1 <= p2, sort by p1 asc
    S2 = []  # p1 > p2, sort by p2 desc
    for _ in range(n):
        p1 = int(input_data[idx]); p2 = int(input_data[idx+1])
        idx += 2
        if p1 <= p2:
            S1.append((p1, p2))
        else:
            S2.append((p1, p2))
    S1.sort(key=lambda x: x[0])
    S2.sort(key=lambda x: x[1], reverse=True)
    order = S1 + S2
    prep_time = 0
    fin_time = 0
    for p1, p2 in order:
        prep_time += p1
        if prep_time > fin_time:
            fin_time = prep_time + p2
        else:
            fin_time += p2
    print(fin_time)

main()
```
