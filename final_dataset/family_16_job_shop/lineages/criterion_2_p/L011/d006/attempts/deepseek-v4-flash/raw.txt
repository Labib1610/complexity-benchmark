We can think of this as a scheduling problem.  
We have two workers: one for preparation and one for finalization.  
The finalization of an operation can only start after both its preparation is done and the previous finalization is done.  

To minimize the total time, we should order operations so that long preparation tasks are done early, while long finalization tasks are done later.  
A known optimal strategy is to sort by **preparation time descending** (or equivalently, by finalization time ascending).  

Here’s the reasoning:  
- If we put a job with a long preparation early, the finalization worker can work on other jobs while this one is being prepared.  
- If we put a job with a long finalization early, it will block the finalization worker unnecessarily.  

So the optimal order is: **sort by preparation time in descending order**.  

We simulate the process:  
- `prep_end` = cumulative preparation time  
- `final_end` = time when finalization worker finishes current job  
For each job in sorted order:  
  - `prep_end += p1`  
  - `final_end = max(final_end, prep_end) + p2`  

The answer is `final_end` after processing all jobs.  

```python
n = int(input())
jobs = [tuple(map(int, input().split())) for _ in range(n)]

# Sort by preparation time descending
jobs.sort(key=lambda x: -x[0])

prep_end = 0
final_end = 0

for p1, p2 in jobs:
    prep_end += p1
    final_end = max(final_end, prep_end) + p2

print(final_end)
```
